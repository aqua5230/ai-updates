Grok Build 1.0.59

發布日期：2026-10-14

繁體中文

新功能

複製回覆內容保留原始定位字元，程式碼區塊標註語言與檔名

當你在對話結束後整理 Grok 生成的內容，想把程式碼或整段說明貼到自己的編輯器時，複製功能帶來了更乾淨的操作體驗。

如同在電子筆記中剪貼參考資料，標籤清楚標記出每段摘錄的來源格式，無論切換成精簡視窗還是全螢幕檢視，底部的操作列都能整齊排版，貼到其他文件時也保留了原本的段落縮排。

已完成的回覆中，每個程式碼區塊下方現在都會顯示 [Copy] 複製按鈕，並標明該段程式碼所屬的語言或檔案名稱。如果你在精簡模式與全螢幕模式之間切換，程式碼區塊、表格與圖表底部的複製列現在都能正確顯示，不會再出現版面錯位。複製整個程式碼區塊或整篇回覆時，內容會維持原有的定位字元（tab），不再被自動替換成空格。

問題修復

PowerShell 掛鉤支援讀取輸入變數，回傳中斷指令確實終止對話

當你撰寫自動化指令來介入 AI 對話流程時，自訂掛鉤（hook，特定事件發生時被觸發的小程式）現在具備更穩定的執行彈性。

好比在自動化生產線設置檢驗站，感測器遇到非標準格式的進料時先亮黃燈警示並繼續運作，而當品檢員送出停機訊號時，輸送帶也能確實立刻停止。

過去在進階 PowerShell 行內掛鉤中，如果程式碼讀取了 $input 變數，整個掛鉤會直接失敗。現在它會印出警告訊息並維持執行。當掛鉤回傳 continue: false 時，AI 現在會依指示確實停止該輪對話，不再像以前那樣直接忽略中斷訊號。這確保了前置檢查未通過時，後續的推理動作不會擅自繼續進行。

問題修復

儀表板空指令改顯示用法說明，預覽貼上支援 Esc 與換列取消

在儀表板檢視專案或輸入指令時，介面現在能妥善防範誤觸所帶來的非預期動作。

彷彿操作精密儀器的控制面板，空按循環按鈕只會跳出使用教學而不會直接啟動新排程，若在準備貼上資料的中途切換選單或按下取消鍵，儀表板也會主動提示已中止任務，避免指令在背景默默送出。

在儀表板中，如果你輸入了 /loop 循環指令卻沒有附帶提示詞，現在只會顯示該指令的使用方法，不會再開啟一個新的工作階段（session）。當你在快速預覽視窗中等待貼上剪貼簿內容時，只要把焦點移動到其他資料列或按下 Esc 鍵，該筆待送出的回覆就會立刻取消，並跳出浮動通知告知狀態，不再滯留並於稍後意外送出。

新功能

`grok --resume` 支援任意分隔符，找舊工作階段不再需要精確符號

當你想接續之前的對話進度，在終端機喚回舊的工作階段（session）時，標題搜尋不再要求字元完全一致。

就像在音樂播放器中搜尋歌名，以前只要把單字之間的空格打成連字號就找不到曲目，現在搜尋功能會自動忽略符號差異，隨手輸入片段詞彙就能立即找出收藏的歌曲。

現在執行 grok --resume <title> 時，指令會自動忽略標題單字之間的連接符號。即使原本的紀錄名稱是「Fix login bug」，你只要輸入 grok --resume fix-login-bug，甚至用底線分隔單字，都能順利找到並重啟該次工作階段。這省去了每次接續專案前，都得先翻找歷史紀錄確認精確標題大小寫與空格格式的麻煩。

問題修復

`grok worktree rm` 修正錯誤提示，無法強制移除時不再建議 `-f`

當你使用指令清理專案工作樹（worktree，Git 讓同一專案平行開多份副本的功能）時，終端機不再給出無效的排錯建議。

正如前往快遞櫃檯寄送物品，如果物件本身因體積超標而無法收件，人員便不會再建議你改買特快專遞方案，避免你多跑一趟流程卻依然被退件。

過去執行 grok worktree rm 移除工作樹時，如果遇到了受保護或無法直接刪除的狀態，錯誤訊息往往會建議加上 -f 參數強制移除；但實際上即便你真的補上 -f，指令仍然會拒絕刪除該工作樹。現在這項不實用的提示已經移除，只有在 -f 確實能發揮強制刪除效果時，終端機才會提示該選項。

English

FEATURE

Copying responses preserves original tab characters, while code blocks label language and file names

When organizing Grok-generated content after a conversation to paste code or full explanations into your editor, the copy features deliver a cleaner workflow.

Think of clipping reference notes into a digital notebook: tags clearly mark the source format of each excerpt, the bottom action bar stays neatly arranged whether switching between compact and full-screen views, and original paragraph indentations remain intact when pasted into other documents.

In completed responses, every code block now displays a [Copy] button below it, labeling the language or file name for that code. If you switch between compact mode and full-screen mode, the copy bar at the bottom of code blocks, tables, and charts renders correctly without layout misalignment. When copying an entire code block or a full response, content preserves its original tab characters instead of being automatically replaced with spaces.

BUGFIX

PowerShell hooks support reading input variables, reliably ending conversations on abort commands

When writing automated commands to intervene in AI conversation flows, custom hooks (small programs triggered by specific events) now offer more reliable execution flexibility.

Picture an inspection station on an automated assembly line: sensors flash a yellow warning light and keep running when encountering non-standard feeds, while the conveyor belt reliably stops immediately when quality inspectors send an abort signal.

Previously in advanced PowerShell inline hooks, if code read the $input variable, the entire hook failed outright. It now prints a warning message and continues executing. When a hook returns continue: false, the AI reliably stops that turn of conversation as instructed, rather than ignoring the abort signal as before. This ensures that subsequent reasoning steps will not proceed unauthorized if pre-checks fail.

BUGFIX

Dashboard empty commands now display usage instructions, while preview paste supports cancellation via Esc or switching rows

When viewing projects or entering commands in the dashboard, the interface now properly guards against unintended actions caused by accidental triggers.

A control panel on precision equipment provides a fitting parallel: pressing a loop button with no arguments only displays a tutorial rather than launching a fresh schedule, and switching menus or hitting cancel midway through pasting data prompts an alert that the task was aborted before commands can silently send in the background.

In the dashboard, entering the /loop command without an accompanying prompt now only displays usage instructions for that command, instead of opening a new session. When waiting to paste clipboard content in the quick preview window, simply moving focus to another row or pressing the Esc key immediately cancels that pending response and triggers a toast notification with the status, rather than lingering to send unexpectedly later.

FEATURE

`grok --resume` supports arbitrary delimiters, eliminating the need for exact symbols when finding past sessions

When resuming past conversation progress and recalling old sessions in the terminal, title searches no longer demand character-for-character precision.

Like searching for song titles in a music player, where typing a hyphen instead of a space between words once yielded no tracks, the search feature now ignores punctuation differences so entering word fragments immediately locates saved songs.

Now when running grok --resume <title>, the command automatically ignores joining symbols between title words. Even if the original recorded name is "Fix login bug", typing grok --resume fix-login-bug or separating words with underscores will successfully locate and restart that session. This saves the hassle of digging through history before resuming a project just to confirm exact title casing and spacing.

BUGFIX

`grok worktree rm` fixes error hints, no longer suggesting `-f` when force removal is impossible

When using commands to clean up project worktrees (a Git feature for running multiple parallel copies of the same project), the terminal no longer offers ineffective troubleshooting advice.

Just as visiting a courier counter to ship a package means staff will not suggest switching to express delivery if an oversized parcel cannot be accepted at all, you are spared an extra trip that still ends in rejection.

Previously, when running grok worktree rm to remove a worktree that was protected or could not be directly deleted, error messages often recommended adding the -f flag for force removal. In reality, even if you supplied -f, the command still refused to delete the worktree. This unhelpful hint has now been removed, and the terminal suggests the option only when -f can genuinely carry out a forced deletion.
