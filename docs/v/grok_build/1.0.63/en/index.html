Grok Build 1.0.63

Released: 2026-10-17

Release notes

FEATURE

Memory Always Uses a Concise Index, and the Command Lists Topics Sorted by Read Frequency

When you have accumulated a large volume of project notes over long-term conversations, you want to keep track of the key information the AI remembers at any time.

Step into a library with a popular book display: previously, the catalog required an extra toggle to condense and finding a topic meant browsing line by line; now the shelves keep only book titles and call numbers, and the most frequently read books can be seen right as you walk in.

Memory now always uses the concise MEMORY.md index that records only topic titles and paths. The [memory_v2] compact_index_enabled setting previously used in the configuration file to enable the concise index no longer has an effect. When you type /memory in the terminal to view it, the list is directly sorted by how frequently Grok reads each topic. When organizing information or planning a travel itinerary in daily work, simply enter /memory to browse the most frequently referenced core notes first.

FEATURE

Rex Terminal Reports Each Session and Subagent Independently, Supporting Main Status Only Display

When using Rex terminal to handle multiple tasks simultaneously, you often need to check the operational status of all background assistants at any time.

Picture a building's central monitoring room that keeps an independent record for each duty and each patrolling guard, with the option to report only the main status.

Rex terminal support now reports each open session and each running subagent as its own record, making it easy for you to track what each one is doing in real time. If you prefer to avoid clutter and only report the overall primary status, you can turn off child reporting in the configuration file:

[ui.notifications.program_status]
children = false

After saving, status notifications will keep only the main status and no longer list all individual subagents.

BUGFIX

Worktree Operations Add Clear Guidance, Prompting Repairs for Missing Directories and Proactively Explaining Non-Git Environments

When frequently switching between multiple branches or organizing project copies, directory states for worktrees can sometimes become abnormal due to being moved. Worktrees (a Git feature for opening multiple copies of the same project in parallel) supported by Grok now provide clearer explanations for common abnormal situations.

Flip through the inspection log at an equipment rental desk: previously, applying for registration in an unsupported area gave no explanation and left you bewildered, and the checklist offered no recovery method when a case was missing or the main storage relocated; now unfulfilled attempts clearly state the reason, and missing folders or changed locations proactively include repair steps.

When you run grok -w or press the shortcut key Ctrl+W in a non-Git project directory, the screen clearly explains that no worktree was created because you are not currently in a Git repository. If a worktree folder you previously created has been deleted, or the source repository moved, running grok worktree list and grok worktree show will clearly mark this abnormal record with a hint on how to repair the worktree.

FEATURE

Command Hooks Support an Argument List, Running Directly Without a Shell and Automatically Filling Variables

When writing automated workflows to intercept specific events, passing arguments directly through the command line is often safer and cleaner than invoking a command interpreter. Grok's command hooks (small programs triggered when specific events occur) now officially support configuring an args list in settings.

Take a direct express shuttle to a designated destination: packages are handed straight to designated programs for delivery without passing through a transfer station, and reserved fields on each package label are filled in with this trip's data before departure.

After setting args, Grok executes command directly as a single standalone program with no shell interpretation. If an argument contains hook variables such as $GROK_SESSION_ID, the actual value of the current session is automatically substituted at runtime. When you want to send information to external logs at the end of a conversation, simply configure args in the hook settings to pass clean arguments directly.

BUGFIX

Plan Review Interface Automatically Preserves Typed Text and Waits for Pending Prompts and Windows to Close

When concentrating on typing in the chat box or filling out feedback, the last thing you want is a confirmation pop-up disrupting your thoughts.

When a manager brings documents for sign-off, the draft you are currently writing is kept as approval notes rather than turning your written words into an approval stamp; if the sign-off arrives only after a task milestone, it waits until you close the open conversations or editing interfaces before presenting the papers.

When a plan review screen pops up while you are typing, the text you just entered is fully preserved in the review notes, so typed characters no longer accidentally trigger plan shortcuts such as approve. At the end of a turn, if the screen still has an open /feedback dialog, question prompt, tool prompt waiting for your response, or queued prompt edit, the plan review screen will faithfully wait until you close those windows before opening.

FEATURE

The Fork Command Preserves the Model and Effort of the Parent Session

When conducting an in-depth exploration into a complex architecture, you may want to branch into another line of thought midway to validate different ideas.

In a laboratory dividing a sample into another test tube for a control experiment, the branch tube preserves the reagents and temperature settings specified for the parent sample, continuing the test under both conditions.

If Grok was initially started by specifying a model with -m or setting thinking effort with --effort, running the /fork command now preserves the model and effort settings from the parent session. When you launch a custom model in the terminal and are halfway through intensive debugging, simply running /fork allows you to immediately continue the conversation under the original settings without manually readjusting parameters.

BUGFIX

Custom Models Connecting to MCP over Chat Completions No Longer Fail Turns Due to Tool Schema Errors

When connecting your own language model to a compatible interface, you often pair it with various extensions to expand file reading or search capabilities.

Connect to an external docking station with an adapter: connector specification issues that previously caused disruptions might halt operations; with this issue resolved, you are no longer cut off for the same reason.

Custom models use Chat Completions endpoints (the interface where models receive chat requests). When connecting to MCP (a protocol that connects AI to external tools) servers, turns no longer fail due to tool schema errors.

BUGFIX

Narrower Terminals Automatically Hide Live Status, Keeping Agent Names Intact in Workflow Run Views

On small laptop screens or when splitting the terminal into multiple small panes, horizontal display width is often quite limited.

Glance up at an electronic departures board on a narrow train platform: previously, the display crammed in detailed progress descriptions and abruptly cut train service names in half; now, when space is constrained, live status text collapses automatically to ensure every train's name is displayed in full.

When viewing workflow run views in a narrower terminal window, the screen now automatically hides the live status text for each agent. This prevents status descriptions from crowding the layout and pushing agent names off the screen, allowing you to clearly identify each running agent at a glance even in narrow windows.
