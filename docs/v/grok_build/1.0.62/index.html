Grok Build 1.0.62

發布日期：2026-10-16

繁體中文

問題修復

無頭模式等待背景工作接續對話，逾時中斷改回傳錯誤

當你寫腳本透過指令列自動處理任務時，最怕背景工作還沒做完程式就提早離場。使用 grok -p 啟動無頭模式（沒有終端機畫面的執行模式）時，若已完成的背景工作觸發了接續對話，現在會耐心等待該輪對話結束後才退出。

如同自助洗衣機的運轉流程，以前主行程一結束就立刻切斷電源，不管追加的防皺運轉跑完了沒有；現在機器會等接續動作徹底收尾才關機，要是設定的時間上限強行中斷了未完工項，面板更會亮起錯誤紅燈而不是回報順利完成。

如果加上 --background-wait-timeout 參數且因逾時停止了待處理工作，程式結束時會回傳錯誤代碼，不再誤報為成功執行。

新功能

儀表板冷啟動恢復工作階段，保持浮層開啟並支援按鍵返回

你在儀表板翻找過去的歷史紀錄時，可能會想先點進某個舊存檔看看進度。在儀表板浮層中針對未預載的存檔執行冷啟動 /resume 時，介面現在會讓浮動面板保持附著開啟。

彷彿在電子導覽機前點選歷史路徑，以前只要觸控未預載的深層檔案，選單面板就會冷不防關閉脫離，讓人想反悔返回都無從按起；現在清單畫面會持續固定在視野中，隨時都能按上一頁安全退回。

如此一來，載入舊工作階段時不會丟失操作畫面，你可以隨時按下向左方向鍵（Left）或 Ctrl+\ 順利退出，返回原本的清單繼續瀏覽。

問題修復

選取帶參數斜線指令按 Enter 直接執行，不再殘留空格

在終端機輸入框使用斜線指令時，大家常會透過選單挑選想跑的動作。當你在提示詞撰寫區反白選取帶有可選參數的斜線指令並按下 Enter 鍵時，現在會立刻執行該指令。以前輸入框（composer，撰寫提示詞的文字區）只會在指令後面留下一格多餘的空格，停在原地等待你再次確認。

好比在車載導航螢幕上選取附帶途經點的路線，以前按下確認鈕，畫面只會在輸入欄末端留下一格空白等候；現在一按便直接開始指引，不再卡在輸入框等待多餘的操作。

這樣不必在選好指令後還得手動多敲一次鍵，命令一選定就能順暢送出。

問題修復

多項 CLI 指令支援管道提早關閉與串流限制，避免輸出異常崩潰

平時在終端機串接多道指令過濾資料時，下游工具提早結束往往會引發非預期的中斷。包含 grok models、列出工作階段的 grok sessions 與 grok export 等指令，當輸出管道提早關閉（例如串接 head 只取前幾行）或輸出裝置已滿時，現在都不再發生當機。

就像工廠輸送帶上的分裝包裝線，以前只要下游集貨箱裝滿或接收閘門提早關閉，傳送機械便會當場卡死並引發整條產線警報；現在機台一旦察覺出口無法收件，就會平順停止輸出並安穩關機。

grok update 與 grok login 兩項指令在標準輸出（stdout）或標準錯誤關閉且無法寫入時，現在同樣能安全結束，確保批次腳本不再因串流截斷而崩潰。

English

BUGFIX

Headless mode waits for background follow-up turns and exits with error on timeout

When scripting automated tasks through the command line, the biggest risk is a process exiting prematurely before background work finishes. When launching headless mode (an execution mode with no terminal screen) with grok -p, if completed background tasks trigger follow-up conversation turns, the runner now waits patiently for that turn to conclude before exiting.

Like the cycle of a laundromat washing machine, the power previously cut off the moment the main cycle finished, regardless of whether the extra anti-wrinkle cycle had completed; now the machine shuts down only after follow-up actions wrap up completely, and if a configured time limit forcibly stops unfinished work, the panel flashes a red error light instead of reporting a successful run.

If you provide the --background-wait-timeout option and pending work is stopped due to a timeout, the program now exits with an error code instead of falsely reporting success.

FEATURE

Dashboard cold boot resumes sessions while keeping popover open with keyboard back navigation

When browsing past history in the dashboard, you might want to open an older saved state to inspect its progress. Triggering a cold /resume on an unloaded session from the dashboard popover now keeps the floating panel open and attached.

At a digital directory kiosk, tapping an unloaded deep record previously caused the menu panel to snap shut and detach unexpectedly, leaving no way to step back; now the list display stays anchored in view so you can safely return at any moment.

This way, you never lose your context when loading an older session, and you can press the Left arrow key (Left) or Ctrl+\ at any time to exit cleanly and return to the list.

BUGFIX

Selecting slash commands with arguments and pressing Enter executes immediately without trailing spaces

When using slash commands in the terminal input box, users often pick actions from the menu. Selecting a slash command with optional arguments in the prompt area and pressing Enter now executes that command immediately. Previously, the composer (the text area for writing prompts) only appended an extra space after the command, sitting idle while waiting for your confirmation.

On an in-car navigation screen, selecting a route with waypoints and hitting confirm previously only left a blank space at the end of the input field; now a single press starts guidance immediately instead of stalling for redundant input.

You no longer need to press an extra key manually after choosing a command, allowing selected actions to submit smoothly.

BUGFIX

Multiple CLI commands handle early pipe closures and stream limits without crashing

When piping multiple commands in the terminal to filter data, a downstream tool exiting early often triggers unexpected disruptions. Commands including grok models, grok sessions for listing sessions, and grok export no longer crash when their output pipe closes early (such as when piped into head for the first few lines) or when the output device fills up.

In a factory conveyor packaging line, if a downstream collection bin filled up or a receiving gate closed early, the transport machinery previously jammed on the spot and triggered plant-wide alarms; now the equipment halts output smoothly and shuts down safely as soon as it detects that the exit cannot accept packages.

grok update and grok login now also exit safely when standard output (stdout) or standard error is closed and unwritable, ensuring batch scripts no longer crash due to truncated streams.
