Grok Build 1.0.50

Released: 2026-10-06

Release notes

BUGFIX

Stabilizing Parallel Working Copies with Git Mode Preserving Uncommitted Changes

When you want to branch off to try new ideas without disrupting ongoing work, it is the perfect time to use worktrees (a Git feature that lets you run multiple parallel copies of the same project).

Picture setting up a spare prep counter in a kitchen: moving half-finished dishes used to risk misplacing ingredients or getting stuck, but switching to a new counter in Git mode preserves uncommitted changes, and having two prep tables will not cause them to clash.

When creating a worktree in Git mode using -w, it now preserves current uncommitted changes and is compatible with repositories that use separate git directories. Running it in a non-Git repository or an empty Git repository now displays a clear error. Copies created with the --worktree-ref flag will no longer mistakenly include incorrect submodule content or raw LFS pointer text. If you launch two creations simultaneously with the same label, both copies will complete smoothly without throwing an already-exists error. When creation fails, the home page and all paths also consistently print a clear reason.

FEATURE

Strict Safeguards for Removing Worktrees to Avoid Accidental Deletion of Same-Named Files

When organizing a project and preparing to clean up unused branch copies, the biggest fear is running a command that wipes out unsaved work.

Think of cleaning out shared lockers: previously, similar locker numbers could cause the entire box to be cleared, but now, as long as personal belongings remain inside or another locker shares the same name on a different floor, the attendant will stop immediately and refuse to clear it.

When running grok worktree rm to delete a worktree without adding the -f force flag, the command immediately reports an error and refuses deletion if that worktree is in use or has unsaved changes. It also will not accidentally delete other unrelated folders that merely happen to share the same name. When specifying deletion by label, if that label exists across multiple repositories simultaneously, the command actively refuses execution to prevent deleting the wrong target. After running the /fork --worktree command, the image and log paths reported by the terminal now reliably point to real local files.

BUGFIX

File Write and Directory Navigation Safeguards with Isolated Discarding for Same-Named Files

When working with project files in the terminal, the greatest concern is disk or path anomalies wiping out or corrupting existing files. If writing to a file fails, it now completely preserves the original content instead of leaving behind a blank, empty file. When switching directories with grok --cwd a, the command stays securely inside directory a rather than mysteriously running inside a duplicated, nested a/a. When discarding file changes in the interface, it only reverts the files you explicitly checked, never affecting other files with similar names. When a session's working directory is deleted externally or does not exist, entering a prompt immediately reports failure with a clear message, rather than delaying errors or recreating that working directory on its own. Terminal tool calls will neither fail nor overflow even if the workspace directory is missing or the tool output volume is massive. Previously, moved directories or interrupted writes easily left blank files or touched similarly named files; now, every file operation comes with explicit stop-loss and protection mechanisms.

FEATURE

Click Top Header to Copy Full Branch Names as Dashboard Fully Displays Worktrees

When you need to send an active branch name to a colleague or paste it into release notes, clicking directly in the interface saves the time of manually querying it via commands.

A display tag has been swapped for a magnetic strip: narrow windows display abbreviations to keep the layout tidy, yet a single click still picks up the complete original name.

Clicking the Git branch name in the top header directly copies the full branch name. Even in narrow terminal windows, long branch names are automatically abbreviated, but clicking still copies the entire name. The dashboard now indicates the worktree to which each session belongs, displays the selected -m model in the input box for creating new agents, and allows freely toggling worktree mode within the folder picker. File conflicts encountered during Git merges or rebases are also listed directly in the changes list, making it easy to see at a glance which files require conflict resolution.

FEATURE

Compact Mode Collapses Dock Without Sending Queued Prompts on Tab Close

If you want to focus on the current conversation within limited terminal screen space, switching to compact mode quickly frees up your view.

Following the storage logic of a folding desk: collapsing the sidebar on tall screens previously broke internal spacing, but tucking away the dock now keeps the screen cleanly spaced, and shortcut keys calling drawer functions remain completely unobstructed.

Compact mode now automatically collapses summary information and maintains reasonable internal padding in taller terminal windows. It also actively hides the dock or task panel, matching the exact effect of manually pressing Ctrl+G. When you use Ctrl+G to hide the dock, the queue panel and the Ctrl+; shortcut that summons queued items continue to pop up and operate normally. The command palette and model selector opened with Ctrl+P have been adjusted to match the width of the settings window. After closing a tab that is executing a task, queued prompts are no longer sent to the model.

FEATURE

Export Formats Supported for Tables with Live Previews Tracking Server Status

When the model organizes large comparison datasets in the terminal, you no longer need to struggle with mouse selections before manually pasting into a spreadsheet. Exported tables now include dedicated copy buttons to export directly in TSV, CSV, or Markdown format, making it easy to paste straight into Excel or various spreadsheet applications. Pinned live preview items now clearly indicate whether a running application is actually detected behind the URL. The timestamp feature can now be adjusted via the settings interface or by running /timestamps, offering three display modes: off, minimal, and on. In the /usage and /session-info windows, excessively long error messages wrap automatically instead of being cut off by window borders. Redundant dash symbols have also been removed from status messages and subagent lists, producing a cleaner visual layout. Previously, copying terminal tables required time to re-split columns, and long messages were frequently clipped by windows; now, every output integrates directly with daily tools and renders completely.

BUGFIX

View History Summaries Without Scrolling as Slash Commands Accept Mixed Case

When conversation turns accumulate and trigger background compaction, you can now see the condensed summary of the active project conversation at a single glance.

Much like a calibrated teleprompter, where condensed summary text was once pushed into blind spots below the screen, compiled key messages now scroll into visible view, and control commands will not fail from an accidental Caps Lock.

Conversation summaries are now fully visible on screen out of the box without requiring manual scrolling. If a turn includes compacted messages, it scrolls into a visible position once the turn ends, rather than remaining hidden below the window bottom. Slash commands are fully case-insensitive, executing normally whether you type /COMPACT or /Compact. When running /context to view context, the interface no longer displays auto-compaction thresholds that the agent never reported. When tool calls are triggered mid-explanation, the terminal stops needlessly redrawing the pager.

FEATURE

Diagnostics Accurately Pinpoint Faulty Configurations as Feedback Faithfully Reports Delivery Status

When environmental configuration issues prevent tools from starting normally, precise self-diagnosis spares you the pain of repeatedly scouring configuration files. When running the grok doctor health check command, the tool now pinpoints the configuration files or settings obstructing startup, instead of blindly reporting zero anomalies. When running the grok doctor fix auto-repair command, the confirmation dialog defaults focus to the Cancel button, preventing users from accidentally modifying existing shell or tmux configuration files due to quick keystrokes. If a workflow file fails to parse, the error report explicitly lists the filename and detailed parse error message, instead of leaving behind a vague "unknown workflow". Drafts saved by the model in the background now faithfully display their actual titles in the /feedback window. Submitting feedback also accurately reports delivery success or failure, without prematurely displaying thank-you prompts or stacking duplicate prefixes. Previously, resolving configuration conflicts meant guessing and debugging; now, clear and transparent status feedback accompanies everything from startup checks to feedback submissions.

BUGFIX

Targeted Interruption for Specific Responses While Marking Cancelled Tool States Correctly

When multiple tasks advance concurrently in the background and you spot an error in one direction, you need to halt it precisely without disturbing other operating processes.

Like an independent emergency brake on a factory assembly line: pulling the lever previously risked halting entire rows of equipment, but now it brakes only the designated station and properly stamps unfinished processes as voided rather than approved.

When issuing a targeted cancellation request, it now halts only the specific response explicitly designated by the client, without affecting other ongoing work. In conversation turns cancelled midway through, tool calls that have not yet received responses are properly recorded as cancelled, rather than erroneously marked as successful. When choosing to let the program continue running, commands running inside background subagents are safely preserved without unintended interruption. Pressing Ctrl+\ or numbers with modifier keys also no longer triggers buttons on permission panels or cancellation confirmation cards.

BUGFIX

Permission Rules Gain Fault Tolerance with Native Tool Names Managed Directly

When setting up access allowlists for command-line tools, a minor typo in a configuration file should not bring down the entire protection mechanism. Permission rules now directly support native tool names such as run_terminal_command and Shell, allowing control rules to align directly with underlying tool calls. When a terminal command matches rules set by the permission manager, the terminal faithfully prompts for confirmation or grants direct access. Even if a managed permission configuration file contains isolated invalid keys, remaining valid rules still load and take effect normally. An invalid syntax rule within a section will no longer invalidate all other rules across that block. The grep search tool now strictly honors read denial rules that start with ./ relative paths. Previously, a single typo in a configuration file could paralyze every allowlist and safeguard; with standalone fault tolerance now in place, day-to-day security controls are far more dependable.

FEATURE

Sessions Over 4MB Stay Connected, Stream Drops Automatically Retry

When you have in-depth, multi-turn architecture discussions with a model, the biggest worry is that conversations grow too long, causing connections to drop without warning or return incomplete answers.

In a long-distance phone system with auto-redial, calls used to get abruptly severed whenever conversations ran too long or lines lagged, but now dropped streams reconnect automatically while retries from different processes stagger their wait times to prevent collisions.

Even when conversation content exceeds 4 MiB, ultra-long sessions maintain a stable connection; if a model call stalls halfway through, it retries automatically before marking the turn as failed. If a Chat Completions stream disconnects abruptly without a finish reason, it automatically retries instead of leaving incomplete fragments behind; retry backoff intervals are jittered across processes. Request payload sizes now strictly observe the limit configured in max_request_bytes; switching models directly with /model preserves your previously configured reasoning effort instead of reverting to the new model's default.

FEATURE

Rewind Cursor Lands Accurately at Prompt End, Scheduler Supports Chinese Time Intervals

When you need to undo your previous question and make minor adjustments, the rewind command quickly returns you to the earlier turn.

Upgrading a tape rewinder with digital bookmarks illustrates this behavior: rewind used to leave the cursor in the wrong position, but now the cursor rests conveniently at the very end of the restored prompt for immediate typing, and scheduled checks accept intervals in Chinese.

When running /rewind to restore conversation history, the input cursor lands precisely at the end of the restored prompt, letting you backspace immediately or continue adding text; creating new sessions with persistent rewind checkpoints enabled also no longer crashes unexpectedly. The /loop command and the scheduler_create tool now directly support non-English time intervals, such as entering 5分 to create recurring tasks without crashing the session. Disabling a specific scheduler tool through the --disallowed-tools startup flag still allows all remaining enabled scheduler tools to load and start normally during launch.

FEATURE

Terminal Clearly Shows Execution Status, Headless Mode Supports Piped Input

When running tasks in the background or piping them into scripts, clear status indications and quiet input streams are essential. Terminal commands display "Running …" while executing and "Ran …" when finished; if a background session is waiting for approval, the window title displays "Action Required" for prompt handling. When running grok in headless mode (operating without a terminal window), it reads prompts directly from piped standard input without attempting to launch an interactive interface. Setting [features] title_refresh = false in requirements.toml disables title refreshes even when GROK_TITLE_REFRESH is present; pinning [cli] use_leader = false as an administrator prevents starting a leader process even if the --leader flag is passed. Background tasks previously left users unsure where work stalled, but status is now immediately clear and script processing is quieter and more reliable.

FEATURE

Config Supports Concurrent Multi-Window Writes, Notification Hooks Control Memory Usage

When you open multiple terminal windows to adjust preferences, saving simultaneously risks overwriting and corrupting global settings. When multiple windows modify settings simultaneously, permissions lists and MCP (a protocol connecting AI to external tools) server settings in config.toml are no longer lost or corrupted. Custom notification hooks (small programs triggered by specific events) configured under [[ui.notifications.hooks]] faithfully execute their specified commands upon matching events. Even when executed command hooks print massive output text, memory usage no longer spikes abnormally. Log output written to files, or environments where the NO_COLOR variable is active, keeps text in a clean plain-text format, preventing hard-to-read ANSI color codes from leaking in. Editing preferences across multiple windows previously risked corrupting files, and high hook output caused memory spikes, but underlying file writes and log handling are now far more reliable.

FEATURE

Tool Search Supports Same-Named Servers, Memory Retrieval Compatible with CJK

When attaching multiple external services and knowledge bases to an agent, accurate tool discovery and memory retrieval are critical for smooth operation. When multiple MCP (a protocol connecting AI to external tools) servers offer tools with identical names, running search_tool lists all matching tools without dropping options from any server. The web_fetch tool proactively declines downloads before loading oversized files into memory, preventing memory exhaustion. The memory_get tool strictly enforces file size limits, no longer returning oversized files that exceed thresholds; the memory_search tool now accurately matches Chinese, Japanese, and Korean words across lengthy notes. Attaching multiple servers previously risked missing identically named tools, and querying Chinese notes often came up empty, but tool discovery is now thorough and large files are properly prevented from overflowing memory.

BUGFIX

Image Generation Rejects Invalid Files, Preserves Transparency and Camera Orientation

When asking a model to generate creative illustrations or process photo albums, inverted image orientations or broken transparency cutouts can ruin the result.

Professional photo labs inspect and process prints with similar rigor: format conversions previously turned transparent backgrounds solid black and flattened portrait selfies sideways, but re-encoding now rotates images upright using orientation tags and promptly rejects corrupted fake files.

When invoking image generation, if the model returns content that is not a valid image file, the tool proactively rejects it instead of forcibly saving invalid data as a .jpg file. When re-encoding images, the conversion routine automatically reads and preserves rotation orientation recorded in EXIF tags, keeping portrait photos upright. Images with transparent backgrounds remain in PNG format after re-encoding, preventing transparent areas from turning solid black.

FEATURE

Terminal Preserves Indentation Tabs, Bundled ripgrep Ready for Immediate Use

When having models run terminal commands to analyze code, formatting indentation and efficient search determine debugging accuracy.

Giving engineers a dedicated precision gauge and high-speed detector reflects this upgrade: returned output previously flattened indentation, but tab characters are now preserved in full and a full-text search engine can be called at any time even in minimal containers.

Tab characters contained in terminal command output are now preserved intact when passed to the model, rather than being stripped away or breaking alignment. The bundled ripgrep search utility is now directly accessible to all commands in the terminal environment, making it immediately usable even inside minimal container images without extra installations. Terminal tool documentation now clearly states the true output truncation limit; the file search tool grep also strictly honors relative globbing patterns from the current session directory.
