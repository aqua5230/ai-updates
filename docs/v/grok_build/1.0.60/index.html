Grok Build 1.0.60

發布日期：2026-10-15

繁體中文

問題修復

grok --resume 依更新時間排序工作階段，找不到本機紀錄時即刻回報

當你累積了大量對話想重新接續先前的工作進度，只憑模糊印象輸入名稱往往難以精準定位。

如同在圖書館櫃檯查詢借閱紀錄，以前一旦館內找不到藏書，館方電腦便主動發起外館調閱並要求重新刷卡驗證；現在螢幕直接按最後更新時間由近到遠條列項目，若沒有相符紀錄還會提示相近名稱，找不到時立即告知結果。

執行 grok --resume <title> 恢復對話時，列出的相符工作階段會依據最後更新時間由新到舊排序，並清楚附上各自的最近更新時間。要是輸入的名稱完全沒有符合的紀錄，命令列會主動推薦相似的標題供你挑選。 當指定的標題在本地電腦中完全不存在時，命令列現在會立即回報未找到，而不是嘗試發起遠端還原程序並要求你登入帳號。

新功能

全螢幕 Markdown 檢視器按 Shift+Y 複製游標所在的程式碼區塊

閱讀長篇技術文件或檢視終端機輸出時，切換到全螢幕檢視器能讓排版更為乾淨，但想取用其中的範例段落往往需要額外步驟。

彷彿拿著手持掃描器在貨架間盤點，以前想記錄規格得拿出紙筆沿著邊界逐字謄寫，現在光點只要對準商品標籤扣下按鍵，整組資料便立刻收進隨身清單。

在全螢幕 Markdown 檢視器中，現在只要將游標移動到目標程式碼上方，按下快捷鍵 Shift+Y，就會複製游標所在的整個程式碼區塊。如此一來，閱讀長篇文件時便能直接擷取所需的指令或程式碼片段，不必再特地動用滑鼠手動框選。

問題修復

從儀表板開啟工作階段時，按 Esc 聚焦回捲歷程而非退回儀表板

從儀表板開啟特定工作階段準備輸入指令時，要是想先檢閱先前的上下文，直覺按鍵往往可能帶來非預期的畫面切換。

跟參觀特展展示台一樣，以前在互動導覽的第一道題目按下返回鍵，畫面會冷不防退回接待大廳；現在只會把檢視游標移到上方的過往解說板，與獨立參觀時的行為完全相同。

以前從儀表板開啟工作階段後，若在第一個提問處按下 Esc，畫面會直接關閉並退回儀表板。現在按下 Esc 時，焦點會切換到上方儲存的回捲歷程（scrollback，可往上捲動查看歷史輸出的區域）。這樣的一致行為與直接在終端機啟動的獨立工作階段相同，避免你為了查看先前的對話而中斷手頭上的流程。

English

BUGFIX

grok --resume sorts sessions by update time and immediately reports when local records are missing

When you have accumulated many conversations and want to resume earlier progress, typing a name from vague memory often makes precise targeting difficult.

Think of checking borrowing records at a library counter. Previously, whenever a book was missing from the collection, the computer initiated an interlibrary loan and required card reverification; now, the screen lists items from newest to oldest by last update time, suggests similar names if no record matches, and reports the result immediately when nothing is found.

When running grok --resume <title> to resume a conversation, matching sessions are listed in order from newest to oldest based on their last update time, clearly displaying their respective recent update times. If the entered name has no matching records at all, the command line recommends similar titles for you to choose from. When the specified title does not exist at all on the local machine, the command line now immediately reports that it was not found, instead of attempting to initiate a remote restore process and asking you to log in.

FEATURE

Full-screen Markdown viewer copies the code block under the cursor with Shift+Y

When reading long technical documents or inspecting terminal output, switching to a full-screen viewer keeps the layout cleaner, but grabbing example passages often takes extra steps.

Picture taking inventory among store shelves with a handheld scanner. Previously, recording specifications meant pulling out pen and paper to transcribe character by character along the margins; now, aiming the light beam at a product label and pressing a button instantly pulls the whole dataset into a portable list.

In the full-screen Markdown viewer, moving the cursor over target code and pressing Shift+Y now copies the entire code block beneath the cursor. Reading long documents this way lets you capture needed commands or snippets directly without reaching for a mouse to highlight them manually.

BUGFIX

Pressing Esc focuses scrollback instead of returning to dashboard when opening a session

When opening a session from the dashboard to enter commands, intuitive keystrokes can often trigger unexpected view switches if you want to inspect earlier context first.

Like visiting a special exhibition booth, pressing back at the first question of an interactive guide used to kick you back to the reception hall without warning; now, it only shifts the viewing cursor up to the previous display board, behaving exactly like a self-guided tour.

Previously, after opening a session from the dashboard, pressing Esc at the first prompt would close the view and return directly to the dashboard. Now, pressing Esc shifts focus to the saved scrollback (the buffer area for scrolling up to inspect past output). This consistent behavior matches standalone sessions started directly in the terminal, preventing interruptions to your workflow when you only want to review prior dialogue.
