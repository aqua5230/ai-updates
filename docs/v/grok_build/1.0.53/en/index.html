Grok Build 1.0.53

Released: 2026-10-12

Release notes

FEATURE

Safeguards tighten for long tasks and workflows, pausing idle goals and protecting approval keystrokes

When automated tasks run continuously, accidental interruptions or background idling can disrupt schedules.

Picture an automated building safety system where flicking a switch previously cut off operations immediately, whereas the control panel now asks for a second confirmation to prevent unfinished routines from stalling.

Exiting when it would terminate an active workflow now raises a warning and requires a second quit confirmation. When /goal continues three consecutive times without calling any tools, it automatically pauses, and entering /goal resume resumes execution. If approval requests are pending, entering /fork is rejected to ensure keystrokes continue responding to prompts. /workflow stop and /workflow pause no longer pick instances through loose fuzzy matching. Running with -p in headless mode (execution without a visual terminal interface) prints rejected approval requests to stderr. The workflow view lists agents outside declaration phases and counts only finished ones toward done.

FEATURE

Session listings skip corrupted directories, preserving usage across multi-window writes

When switching across multiple windows or terminal environments, preserving conversation logs and execution states is vital for continuity. Previously, if a single session directory was unreadable, grok sessions list and /resume would abort entirely. They now automatically skip faulty directories, letting remaining valid records list and resume normally. When two windows write to the same session simultaneously, usage records for every turn are now fully preserved instead of overwriting each other. Persistent shells still execute your typed commands as usual even if restoring prior state fails. When creating a worktree (a Git feature that keeps multiple parallel copies of the same project) from a project subfolder, grok worktree list and grok worktree show correctly report from the repository root.

FEATURE

Plugin and hook loading errors gain visibility, with config checks warning on non-boolean values

Clear error diagnostics save substantial troubleshooting time when customizing extensions or adjusting environment parameters. Running /hooks now clearly lists errors encountered while loading inline hooks (small programs triggered when a specific event occurs) and plugins. Hooks you manually disable remain disabled even if the file recording disabled entries cannot be read. When installing plugins on Linux, interrupting grok plugin install mid-copy no longer leaves corrupted folders that block reinstallation. When known [features] keys in config.toml contain non-boolean values, grok inspect issues a warning. Entering /docs directly opens your exact typed guide or picker. Simply running grok --help and grok --version no longer automatically creates a .grok folder.

FEATURE

Wrapped terminal commands join automatically, with monochrome diffs marking changes using plus and minus signs

Layout details directly shape workflow smoothness when reviewing long terminal output and comparing code.

Think of copying a long serial number from a multi-column receipt, where wrapped lines previously required manually deleting stray breaks after cutting, whereas selecting wrapped text now automatically joins into continuous text ready to paste directly.

Shell commands displayed across wrapped lines in tool and background task rows automatically restore to a single line when copied. Wrapped URLs in tool headers can now be clicked on any line to navigate to the complete address. When editing multiple files simultaneously, the view explicitly notes how many other files this edit touches. When color output is disabled, edit diffs mark deleted and added lines with - and +. If reading a directory listing fails, the list automatically expands to show the reason for failure.

FEATURE

Input focus and feedback drafts gain protections, with instant submissions bypassing background cards

When typing responses or feedback in the terminal, sudden popups stealing cursor focus are especially disruptive.

Like filling out forms at a post office counter where a chiming ticket or an arriving clerk previously whisked away your paperwork, the desk now reserves your writing space so you can finish the task at hand unhurriedly.

When entering /feedback, the feedback window stays open even if permission prompts, questions, or external tool notices arrive in the background. When loading feedback drafts, remaining valid drafts still load normally even if a single draft is corrupted. Typing @ to mention files reuses a cached file list until directory structures change before rescanning, making suggestions appear faster. Attempting to edit a queued command (such as /compact) displays a prompt and rejects the action, fully preserving your newly typed text. Pressing Ctrl+Enter to submit immediately no longer accidentally answers stop subagent panels or external tool prompt cards.

FEATURE

External tools support parallel input prompts, with launch flags enforcing interactive terminal permissions

Expanding AI capabilities through external tools demands precise permission boundaries and clear interactive prompts. The --tools and --disallowed-tools lists configured at launch now take effect inside the interactive terminal interface as well. When models make parallel calls through MCP (Model Context Protocol, a protocol for connecting AI to external tools) to multiple tools requiring input, each call displays its own prompt. When configuring stdio MCP servers, a leading tilde ~ in commands and arguments is expanded. ~ now automatically expands into your home directory without manually typing absolute paths, and parallel calls display their own distinct prompt cards.
