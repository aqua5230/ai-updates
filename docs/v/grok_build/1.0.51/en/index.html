Grok Build 1.0.51

Released: 2026-10-09

Release notes

FEATURE

Background workflows gain real-time control, preserving revision comments upon plan approval

When assigning long-running automated tasks, you can now directly track real-time activity for background operations.

Picture a dedicated control console added to a factory floor: tasks once dispatched no longer just run unmonitored to completion, as every conveyor belt can be paused at the press of a button, and notes attached midway stay preserved until final inspection.

Typing /workflow lists, stops, or resumes background workflows (ordered sequences of automated tasks), which also appear synchronously alongside stop buttons in the task panel. Running /workflow stop or /workflow resume accurately targets the currently active workflow. Comments left during plan revision runs are fully preserved and submitted when approving the plan. If a background command discovers its working directory is missing, it immediately reports failure without flipping back to a running state due to lingering subsequent output.

FEATURE

Headless mode reliably waits for goal outcomes, stabilizing background task pauses and resumes

When running scripts to batch-process project goals in the background, you no longer have to guess whether tasks completed cleanly.

Stepping into a laundromat, you no longer have to wonder if laundry finished after pressing start, because the screen now waits until spin-drying completes before issuing a receipt; pressing pause halts the water, and opening the door mid-cycle allows washing to resume once closed.

When running grok -p in headless mode (execution without a terminal window), the process waits for background goals to fully finish and reports the final outcome. Supplying the --background-wait-timeout flag automatically terminates the goal when the deadline expires, without printing extraneous pause notices upon completion. Pressing Ctrl+C pauses an active goal, allowing you to resume its progress directly when reopening the conversation. If goal features are disabled in settings, headless mode treats an entered /goal command as a standard text query.

FEATURE

Worktrees support Jujutsu repositories, avoiding stalls on special files and missing directories

When switching branches across complex projects, managing separate copies now avoids path pitfalls.

Repotting a plant no longer stalls when soil carries stones or labels drift out of place, allowing seedlings to take firm root even when moved to a new style of pot or when original soil is missing.

grok worktree (a feature enabling parallel copies of a project) supports Jujutsu repositories. Creating a copy no longer hangs even when named pipes or sockets are present. When GROK_HOME is set to a symlink (a shortcut file pointing to another location), copies created with -w maintain active tracking. If the original launch folder was deleted, grok -w falls back to the root directory with a helpful notice. Running grok -p --output-format json reports the directory used, clarifying name collisions. Both grok sessions list and /resume display sessions started from the same subdirectory while hiding adjacent submodule records.

FEATURE

Worktree cleanup protects against accidental deletion, accelerating launches with many copies

When cleaning up retired parallel development copies, safeguards and scanning efficiency both see tangible improvements.

Like a warehouse clerk auditing vacated lockers, automated deregistration prevents losing track of inventory after manual removals or unstable connections, while residual empty boxes are cleared out cleanly and inventory checks run much faster.

Running grok worktree rm or gc (a maintenance command that cleans up discarded copies) cleans up properly and restores registered names even after manually deleting folders or rebuilding the database. Untracked content that consists only of empty folders is permitted for deletion. Without the -f flag, the copy is preserved if checks for unsaved changes fail or time out. Running grok worktree list now displays unfinished copies left behind by interruptions. All grok worktree commands skip loading model directories at startup. Opening the /resume picker is also noticeably smoother when managing large numbers of copies.

FEATURE

Slash command and skill completion update promptly, protecting input cursors and hidden commands

When quickly typing commands or referencing files in the prompt box, automatic suggestions no longer disrupt your typing flow.

Think of an attentive restaurant server by your table: rather than placing orders whenever dishes are mentioned in passing or blocking the menu with an outdated bill, requests are jotted down only when addressed in the opening sentence, and order revisions never obscure words you are currently writing.

Only slash commands positioned at the very beginning of a message now trigger a skill (a functional module granting specific capabilities to the model). Entering undocumented commands like /cd manually executes the intended command instead of getting intercepted by similarly named skills. When project skills change, the autocomplete menu for slash commands updates instantly, accurately displaying filenames under the commands/ directory and applying proper project tags in nested projects. Completion popups no longer hide characters trailing the cursor. When rapidly entering filenames, @ file completion no longer mistakenly applies stale results from previous searches.

FEATURE

Review cards identify trigger sources, preventing accidental keystrokes on permission prompts

When tools request file deletion, web searches, or rewrites, confirmation panels now clearly identify the origin of each check.

At a bank teller counter, receipts now carry official department stamps instead of leaving internal review rules unnamed, and bumping an ink pad with an elbow during stamping is never mistaken for payment approval.

When a hook (a script triggered by specific events) requests confirmation for web searches or file deletions, the review card displays its name. Tool calls from MCP (Model Context Protocol, an interface connecting AI to external tools) also prompt with explicit names. File write review cards display the existing content about to be overwritten. When permission prompts, questions, or MCP cards appear, keystrokes from typing, arrow keys, Enter, or Ctrl+Enter will no longer trigger unintended selections. Custom commands located outside the configuration directory, such as my-guard, are automatically located and executed from PATH. Loading errors in the /hooks list can also be expanded and inspected directly.

FEATURE

Oversized prompts automatically offload to files, keeping image drags and long pastes uninterrupted

When pasting massive code blocks or screenshots into prompts, input channels no longer freeze the interface from data overload.

Much like shipping an oversized parcel through the post office, overweight mail is automatically boxed and diverted to freight instead of bouncing or jamming mail slots, and attaching fragile stickers no longer tears packages.

When pasting exceptionally long questions or prompts, the system offloads them into separate files for delivery instead of cramming them into conversation strings. In terminal environments lacking bracketed paste support, long text no longer stalls around 1 KB and reads through completely. You can now drag and drop images directly from file managers into terminal windows as attachments. Pasting images alongside skill commands like /pr-workflow delivers the images faithfully to the model. Images from external tools undergo format verification so corrupted files do not crash the session, which continues running smoothly even when writing large files or capturing multiple screenshots.

FEATURE

Terminal shortcuts and dialogs get refreshed, streamlining search scrolling and multi-select choices

When navigating menus inside cramped terminal windows, key responsiveness and screen layout become significantly smoother.

Operating a folding toolbox in a cramped workshop feels much smoother when organizers scale to fit overhead clearance, top and bottom drawers can be reached directly, and pulling the power switch instantly cuts electricity.

In tmux (a terminal multiplexer that splits windows into panes) with extended keys enabled, Shift+Enter, Ctrl+., Ctrl+/, and Ctrl+[ / ] are now recognized. When browsing /feedback drafts, pressing G, Home, or End jumps directly to the first or last entry. For multi-select questions, number keys toggle multiple choices before submitting. Running /find continues counting matches accurately during streaming output and scrolls directly to wrapped lines containing results. Pressing Ctrl+C while dialogs are open still cancels the turn. In terminals with limited vertical height, dialogs such as /feedback preserve readability, and delivery failure states wrap cleanly within the dialog box.

FEATURE

Dashboard session pins persist across restarts, supporting quoted paths and safe deletions

When frequently inspecting and switching between multiple project sessions, panel ordering and operational safeguards are far more dependable.

Imagine a magnetic bulletin board on an office wall: pinned routine notices return neatly to their original spots after rebooting instead of scrambling when lights go out, and discarded slips leave no sticky residue behind when torn away.

Pinned sessions in the dashboard (an overview panel managing all conversation tasks) now strictly preserve their original pinning order even after restarting. Closing a session clears the item completely instead of leaving it stranded in the inactive list. Entering /exit from the detail view closes only the currently viewed session. During Peek previews, moving focus with arrow keys before pressing number keys no longer assigns tasks to unintended agents. Executing /cd or using the location picker now permits paths containing quotes or escaped characters. Entering /delete with trailing characters returns an immediate error instead of accidentally deleting the active session.

FEATURE

Resending edited messages preserves workspace files, clarifying login steps and halting turns on logout

When repeatedly refining requirements throughout long conversations, code files and account states receive more comprehensive protection.

Revising blueprints at an architectural firm no longer knocks over finished models on the desk when rewriting an earlier draft, because resubmissions update only the drawings while freshly laid brick walls remain intact.

Canceling and re-editing submitted messages during long sessions no longer mistakenly reverts files in the workspace. Logging out immediately halts active turns in local sessions. Login failures provide clear next steps instead of dumping raw errors. If grok -p has no saved login credentials, it automatically executes the configured authentication command (auth_provider_command). Opening a session falls back to the Auto model when failing to retrieve the model list. Running /compact (a command condensing conversation history to free space) on an empty session also no longer resets reported context window values.

FEATURE

Tool Permission Flags Align with Model Names, Memory Simplifies to a Toggle, and Density Controls Are Added

When fine-tuning models from the command line, configuration options and tool permissions become more intuitive.

A mixing console aligns its knobs with screen labels, while switches return to simple on-off toggles.

--disallowed-tools accepts the exact names seen by the model (such as run_terminal_command or spawn_subagent). Headless mode adds --allowed-tools as an alias for --allow. /density and the Tool call density setting control the level of detail in tool calls. --system-prompt automatically appends rules from --append-system-prompt. Memory is simplified into a straightforward toggle, requiring only the enabled key under [memory] in configuration files. The command line removes the /share command and session sharing features.
