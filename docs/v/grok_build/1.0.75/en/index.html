Grok Build 1.0.75

Released: 2026-11-04

Release notes

BUGFIX

Project hooks and skill settings operate independently, with warnings when permission files fail to parse

When switching development across multiple repositories, manual settings that fail silently often cause unexpected confusion. If permission rules fail to load, such as when syntax does not parse or .claude/settings.json is not valid JSON, a warning notification now appears immediately when opening a session instead of being silently skipped. Disabling a project hook in /hooks applies only to the current repository, without disabling hooks (small programs triggered by specific events) of the same name in other repositories. Turning an individual skill on or off in the Skills tab saves only [skills].disabled to config.toml, so managed skill folders and ignore lists distributed by an organization keep applying. Previously, misconfigured rules were baffling and disabling a project tool could inadvertently affect other workspaces; now issues surface immediately and plugin settings for each project remain isolated.

BUGFIX

Dashboard tracks background agents, stops runs anytime, and highlights controls on hover

When assigning background agents to handle multiple tasks at once, tracking real progress in real time and being able to halt runs at any moment is essential.

Picture a dispatcher at a central monitoring console: the screens display only equipment actively running, and hitting an emergency stop cuts operations instantly without waiting to clear inspection slips.

Workflow status lines now clearly say how many agents are still running instead of listing the total number created. When an approval card pops up for a background task, clicking the stop button in the dock (an action bar pinned along the screen edge) stops that background run immediately instead of forcing you to answer the card first. Dashboard rows stay in Working while a session has background subagents or workflow runs going, and stopping the row there completely ends all related tasks. A question card's Enter:submit button, the dashboard session popup's [✗], and collapsed workflow rows also highlight prominently when hovered by the mouse pointer.

BUGFIX

Rejecting changes preserves manual saves, preventing your own edits from being overwritten

Tinkering with files while waiting for a model to generate code comes with the worry that rejecting a suggestion will wipe away your own work.

Think of asking a contractor to sketch proposals onto a blueprint: even if you reject the remodeling concept altogether, the outlet marks you penciled in beforehand remain intact.

Previously, if Grok missed detecting a manual save, rejecting a change would overwrite the edits you had already stored. Now, even when Grok misses a save event, choosing to reject a change keeps all edits you saved to the file yourself completely intact.

BUGFIX

Exporting to unread named pipes fails immediately, and deleting sessions during background writes avoids "Directory not empty"

Resuming past sessions across directories or piping conversations outward was often blocked by folder paths and background writes.

Much like flipping through a portable index binder, opening a tab from any desk leads straight back to the specific drawer where the dossier was originally filed.

Now, wherever you launch your terminal from, running grok --resume <id> automatically switches to open in the folder where the session (records of conversation and state during work) was recorded, instead of refusing outright. When using /export to send a conversation to a named pipe (a channel that passes data between programs via a file path) that nothing is reading, Grok fails right away instead of freezing until killed. When cleaning up history with grok sessions delete, it no longer fails with "Directory not empty" even while other background processes are still writing into that session folder.

FEATURE

Prompts support boundary jumps and selection, while typing in scrollback auto-focuses

When editing lengthy prompts or reviewing message history, constantly switching cursor and input focus often interrupts your train of thought. Pressing Cmd+Up/Cmd+Down or Ctrl+Home/Ctrl+End now jumps directly to the start or end of the prompt, and adding Shift selects from the current cursor to the prompt start or end. Pressing Left on an empty prompt opens the dashboard from any session or welcome screen. In scrollback, pressing Ctrl+L adds a selected message or highlighted text to the prompt as a quote, while extensions now open via /plugins instead. Typing a digit or symbol while scrollback has focus, with vim keys (a mode using letter keys for navigation and editing) turned off, moves focus to the prompt and types it there, just as letters already do; ? still opens the command palette. When Ctrl+Enter arrives as plain Enter, the footer send indicator displays Enter Enter, with tmux (a terminal multiplexer) under default settings being one example.

BUGFIX

Compact terminals adaptively streamline UI, while special characters and legacy consoles display cleanly

Shrinking windows or operating in legacy consoles often makes crowded text and missing character glyphs painful to read. In narrow screens, footer and status bars automatically drop or shorten items, preventing buttons from overlapping or being cut off. Opening a rewind (restoring a conversation to an earlier step) confirmation dialog on a short terminal, or shrinking the terminal while that window remains open, no longer crashes Grok. Emoji and keycap symbols are measured precisely to the terminal's actual rendering width, so rows no longer overflow their borders or lose their trailing …. When generated media paths contain Chinese or Japanese characters or Windows formats, file names remain intact and fit row widths. On older Windows consoles such as cmd.exe and PowerShell, symbols in list rows use compatible characters instead of rendering as broken empty boxes. Terminals with 16 colors display paste labels and tool accents in the muted gray used by other secondary text, and paste label brackets no longer vanish under the light theme.

FEATURE

Tool output truncation aligns with code cells, while quote layout and queued notes display fully

Clear and disciplined formatting helps you quickly grasp key details when reading quoted dialogue or inspecting lengthy tool output. When output from Fetch, Web Search, or MCP (a protocol connecting AI to external tools) is cut off, the bottom displays an indicator row matching code cells to show remaining lines and your viewer key. A single hidden line reads +1 line. Notes above a queued prompt showing a model switch result or a ready worktree (a feature enabling parallel working copies for a project) stay on screen when execution starts, instead of scrolling out of view. Inside conversation quotes, every line of a code block stays neatly beneath the quote bars, copying a quote turns reference links into inline links, and lines following multi-line math are numbered correctly. Clicking a link or local file that cannot open in the current environment, such as over an SSH connection with no display, clearly explains why instead of doing nothing.
