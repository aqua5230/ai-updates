Grok Build 1.0.54

發布日期：2026-10-12

繁體中文

問題修復

/resume 支援指定識別碼或標題，啟動恢復時提示詞自動排程送出

想接續先前中斷的工作進度時，終端機現在能更快鎖定歷史紀錄並妥善處理輸入內容。

就像向飯店櫃檯調閱住宿名冊，櫃檯人員只要依姓名或編號就能過濾出特定紀錄；即使舊帳本少數頁面破損，櫃檯也會保留備份並搶救出完整資料，不會影響新住客登記。

現在輸入 /resume 可以加上選填的工作階段識別碼或標題，直接開啟過濾為相符項目的選單。若在啟動並恢復工作階段時送出提示詞，內容會先進入佇列排程，等載入完成後自動送出，不再停留在輸入框。對斜線指令按下立即送出快捷鍵 Ctrl+Enter，會依指令形式執行或排入佇列，不再被當成一般提示詞送出。即使工作階段清單損毀，也不會阻止新工作階段登記，Grok 會保留備份、搶救能讀取的資料列，並發出警告提醒你。

問題修復

工作樹分支獨立在專屬路徑執行，終端指令不再誤改原始目錄

當你想在不干擾主要程式碼的情況下嘗試實驗性改動，Git 工作樹（讓同一專案平行開多份副本的功能）能幫你建立獨立分支。

如同從原生盆栽剪下枝條移到獨立花盆培育，園丁在分盆修剪或施肥時，修剪動作都不會碰傷原本母株的根葉。

現在當你執行 grok -w -r 或在對話中輸入 /fork 分支出工作樹，終端機不僅會顯示工作樹路徑，所有操作也會切實切換至該路徑下執行。以往在分支出工作樹後執行 Shell 指令，指令往往會誤改到原本的檢出目錄；現在路徑明確切換後，終端機指令不再更動原始目錄。當你為了重構特定模組而分支出工作樹時，可以在獨立路徑下放手執行編譯與修改指令，確保原始專案內容維持原狀。

新功能

記憶搜尋顯示長行相符片段，/memory 與技能設定支援符號連結

查閱儲存的記憶紀錄或設定自訂技能時，檔案捷徑與長文字行不再導致檢視中斷。進行記憶搜尋時，若命中內容位於非常長的文字行中，現在會直接顯示包含關鍵字的相符片段，不再於命中位置前就把整行截斷。在終端機輸入 /memory 檢視筆記時，若目錄中含有符號連結（指向另一個位置的捷徑檔），清單會直接略過該筆記，不再使整份清單讀取失敗。在技能設定中，[skills].ignore 忽略清單在比對符號連結的 SKILL.md 說明檔時，會依存放該檔案的資料夾名稱進行比對。以前只要筆記中夾帶捷徑或關鍵字落在長行末端，查詢便會整份報錯或看不見內文；現在檢索與忽略設定都能精準掌握目標。

問題修復

修復終端文字排版與二進位亂碼，支援折行網址與面板點擊

在終端機檢視各類輸出與操作卡片時，文字排版與超連結點擊都獲得了細緻修正。貼上帶有 Windows 換行符號的文字時，內容會轉為標準換行送給模型；Markdown 圖片語法不再殘留孤立的驚嘆號，非數學公式的金額符號也會保持純文字。寫入核准卡片若遇到二進位或無法讀取的檔案，會明確標示為無法讀取，不再顯示整片亂碼；檔案讀取失敗時，卡片也能展開顯示具體的失敗原因。執行失敗的 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）工具列，錯誤訊息會依螢幕寬度自動折行並保留原本換行。herdr 面板內的連結現在可以直接點擊；Shell 指令說明中折行的長網址，每一行也都能點開完整連結。以前常因為符號誤判成公式、遇到無法讀取的檔案就跳出亂碼，或是網址斷行而無法點擊；現在介面輸出更為整潔易讀。

新功能

長對話與大段貼上釋放記憶體，閒置處理器耗用與啟動速度最佳化

長時間執行對話或貼入龐大資料時，背景資源的佔用情況直接影響操作流暢度。

好比圖書館閱覽桌的管理規定，讀者看完的厚重參考書只要推入還書箱便能清出桌面，塗改草稿也不會無止境堆在抽屜裡佔用空間。

在長時間運作的工作階段中，當冗長的回覆內容捲出螢幕之外後，Grok 佔用的記憶體會相應減少。在含有大段貼上內容的提示詞中打字反應更快，提示詞的復原歷史紀錄也加上了上限，確保已刪除的貼上內容不再停留在記憶體中。停留在閒置歡迎畫面時的處理器使用率已經降低；若環境變數 TMUX 指向已停止運作的 tmux 伺服器，啟動速度也比以往更快。

English

BUGFIX

/resume Supports Specifying IDs or Titles, Auto-Queuing Prompts During Session Resumption

When you want to pick up where you left off, the terminal can now locate historical records faster and handle input more smoothly.

Picture requesting guest logs at a hotel front desk: the clerk filters specific records simply by name or room number; even if a few pages of an old ledger are torn, the desk keeps a backup and recovers all readable data without holding up new guest registrations.

Now, typing /resume accepts an optional session ID or title to directly open a menu filtered to matching entries. If you submit a prompt while a session is booting and resuming, the content enters a queue and sends automatically once loading completes, rather than remaining stuck in the input box. Pressing the immediate-send shortcut Ctrl+Enter on a slash command now executes or queues it according to command rules, rather than sending it as a plain prompt. Even if the session catalog is corrupted, it will not prevent new sessions from registering, as Grok preserves backups, salvages readable rows, and displays warnings to alert you.

BUGFIX

Worktree Branches Run in Dedicated Paths, Preventing Terminal Commands from Modifying Original Directories

When you want to try experimental changes without disrupting primary code, Git worktrees (a feature allowing parallel copies of the same project) help you set up isolated branches.

Think of clipping cuttings from a potted plant to nurture in a separate pot: pruning or fertilizing in the new container never harms the roots or leaves of the parent plant.

Now when you run grok -w -r or enter /fork in conversation to fork a worktree, the terminal not only displays the worktree path, but also switches all operations directly into that path. In the past, running Shell commands after forking a worktree often accidentally modified the original checkout directory; with explicit path switching now in place, terminal commands no longer touch the original directory. When you fork a worktree to refactor a specific module, you can freely run build and modification commands under the isolated path while keeping your original project untouched.

FEATURE

Memory Search Displays Snippets for Long Lines, While /memory and Skill Settings Support Symlinks

When checking saved memory logs or configuring custom skills, file shortcuts and long text lines no longer disrupt your view. During memory searches, if a match falls inside an extremely long line of text, the terminal now directly displays the matching snippet containing your keyword, rather than truncating the entire line before the hit. When viewing notes by entering /memory in the terminal, if a directory contains symlinks (shortcut files pointing to another location), the list cleanly skips that note rather than failing to load entirely. In skill configurations, the [skills].ignore list matches symlinked SKILL.md instruction files against the name of the folder storing the file. Previously, queries would throw errors or hide content whenever notes contained shortcuts or keywords landed at the end of long lines; now both retrieval and ignore settings accurately locate targets.

BUGFIX

Fixing Terminal Text Formatting and Binary Garble, with Wrapped URL and Pane Link Clicking Support

When viewing terminal outputs and action cards, text formatting and hyperlink interactions have received meticulous fixes. Pasting text with Windows line endings now normalizes newlines before sending to the model; Markdown image syntax no longer leaves behind orphaned exclamation marks, and currency signs not intended as math formulas remain plain text. Write approval cards now explicitly mark binary or unreadable files as unreadable instead of rendering screens of garbled characters; if reading a file fails, the card can expand to reveal the specific failure cause. When an MCP (a protocol allowing AI to connect with external tools) tool run fails, the error message wraps to the terminal width while preserving original line breaks. Links inside herdr panes can now be clicked directly; for long URLs wrapped across lines in Shell command help, clicking any line opens the complete link. Previously, symbols were often misread as formulas, unreadable files dumped garbled text, and wrapped URLs broke clickable links; interface output is now noticeably cleaner and easier to read.

FEATURE

Memory Freed in Long Conversations and Large Pastes, with Idle CPU Usage and Startup Speed Optimized

During extended sessions or after pasting large amounts of data, background resource usage directly impacts operational smoothness.

Much like library reading desk rules, returning heavy reference books to drop boxes clears the table immediately, and scribbled draft papers never pile up endlessly in drawers to waste space.

In long-running sessions, memory held by Grok decreases as lengthy responses scroll past the screen view. Typing is more responsive in prompts with large pasted blocks, and prompt undo history now has a cap to ensure deleted paste content no longer lingers in memory. CPU utilization while idling on the welcome screen has been reduced; if the TMUX environment variable points to a stopped tmux server, startup is also faster than before.
