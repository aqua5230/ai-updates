Grok Build 1.0.73

發布日期：2026-10-28

繁體中文

新功能

自動更新遇啟動失敗即停止重試，提示執行 grok update

如果新下載的版本在你的電腦上啟動失敗，過往開啟工具時容易被卡在重複嘗試的流程中。以前即使新版本在當前環境有重大問題而無法開啟，自動更新依然會在每次啟動時不斷嘗試套用，反覆遭遇啟動挫折。

宛如社區管線檢測發現閥門故障時立刻掛上維修警示，在原廠送達新零件前不再反覆送電硬推，改請住戶手動查看檢驗單。

現在只要新版本在本機啟動失敗，自動更新便會停止重試，直到官方發布更新的版本為止。每次啟動時終端機都會明確提示你執行 grok update 查明失敗原因。

新功能

設定支援預設多行模式，按 Enter 直接換行不搶送出

每次撰寫長篇提示詞時，最怕才按一下換行鍵就把尚未完成的半成品直接送了出去。

恰似在多功能筆記本裡切換書寫格式，以前每次翻開新頁面都預設是便條紙，隨手敲一下就撕下送出；現在把格式固定為長文信紙，按下按鍵只是順暢跳到下一行繼續落筆。

現在你在 /settings 啟用 Start in multiline 選項，或是在設定檔的 [ui] 區段加入 multiline_default 設定，未來開啟新工作階段（session，對話互動的獨立階段）與儀表板時，都會預設進入多行模式。在這個模式下，按下 Enter 鍵只會插入換行符號。

新功能

挑選器支援快速鍵翻頁跳轉，新增 Gruvbox 深色主題

翻閱長度驚人的功能清單或挑選器時，光靠上下方向鍵一步步挪動往往相當耗時。

好比在圖書館的密集書庫查閱目錄，以前遇上厚厚的索引本只能單頁逐行翻找，現在既能按分頁鍵整段跳頁或直達卷首卷尾，書架還換上了護眼的暖色系陳列。

現在於 /skills 與各類挑選器（pickers，彈出式選項清單）中，你可以直接使用 Page Up 與 Page Down 上下翻頁，或是按下 Home 與 End 鍵直接跳到首項或末項。輸入 /theme 切換外觀時，清單內也新增了 gruvbox-dark-hard 復古高對比深色主題供你選用。

問題修復

`--restore-code` 遇失敗保留工作區檔案，精準鎖定專屬儲藏

執行程式碼還原若中途出錯，工作區裡尚未提交與未追蹤的檔案最需要得到妥善保留。

猶如維修師傅整理零件抽屜，以前只要零件卡榫安裝失敗，隨手擱在桌上的散裝零件就會被整批掃進雜物箱；現在桌面的散件原封不動，抽屜也加了專屬標籤，就算隔壁工作檯重新調動工具箱也不會拿錯。

使用 --restore-code 還原程式碼時，若還原過程失敗，你尚未提交與未追蹤的檔案現在會穩妥保留在工作樹（Git 讓同一專案平行開多份副本的功能）中，不會被收進儲藏。即使其他平行工作區在此期間更動了儲藏（stash，Git 暫時收起未提交修改的功能）清單，--restore-code 也能精準辨識並還原專屬於自己的儲藏紀錄。若切換分支後執行的結帳後掛鉤（post-checkout hook，切換分支後自動觸發的小程式）發生錯誤，你的修改也會安全保留在儲藏內。

問題修復

Windows 退出徹底結束處理程序，修復 Shift 與 AZERTY 快捷鍵

在 Windows 平台使用命令列時，關閉軟體或輸入特殊組合鍵容易遇到卡頓與無回應的狀況。以前在命令列退出 Grok 時，雖然視窗畫面已復原，但背景中的 grok.exe 處理程序有時並未結束，導致命令列停留在無提示字元的等待狀態。

像借用會議室開完會，以前雖然關了燈，投影機卻還卡在運轉而無法交還場地，現在離開時會連同所有設備徹底關閉。

現在只要終端機畫面完成復原，grok.exe 就會立刻結束執行，將控制權正常交還給終端機。在鍵盤操作上，以前按住 Shift 鍵輸入的符號快捷鍵，或是 AZERTY 鍵盤上的數字鍵快捷鍵經常無法觸發，現在這些按鍵組合在 Windows 上都能正常識別運作。

新功能

佇列面板顯示排隊圖片標籤，連續立即發送不誤標取消

面對排入佇列的大量提示詞，若想連續插隊執行，介面狀態與終端機畫面現在銜接得更加穩定。

就像在得來速車道連續調整點單順序，以前服務鈴一催促，原本進行中的餐點會被廣播誤報為顧客退訂，監視螢幕還會晃動；現在換單順暢銜接，取餐螢幕清楚標示附餐圖示，施工指引也一直留在看板上。

在佇列面板中，排隊等待處理的圖片現在會與輸入框一致，顯示為綠色標籤晶片（chips），方便辨識隨附的圖檔。 當佇列中的提示詞開始執行時，建立工作樹（Git 讓同一專案平行開多份副本的功能）的提示訊息會持續保留在螢幕上，不會被新啟動的任務清空。 連續多次點擊「立即發送」插隊時，被中途停止的輪次不再被標示為使用者取消，對話紀錄檢視畫面也不會突然跳動。

新功能

對話檢視支援輸入自動轉向，完善折行排版並釋放圖片快取

瀏覽過往的對話紀錄與執行過程時，游標選取、文字折行與終端機的資源釋放細節已修復完備。 當焦點停在對話紀錄時，鍵入任何文字（包含非 ASCII 的中文字元）都會直接導向提示詞輸入框，且不會影響等待審核的卡片或計畫。 載入工作階段（session，對話互動的獨立階段）若發生錯誤，終端機會顯示完整原因，不再把過長訊息的中間段落截斷省略。 內含豎線 | 但非 Markdown 表格的文字行，現在會像一般文字正常折行，不再於終端機邊緣被硬生生切斷。 在對話紀錄中選取文字時，即使上方有項目被移除，選取的游標列仍會穩定停留在同一列。 採用 Kitty 圖像協定的終端機，在 Grok 隱藏圖片後會立即釋放終端機內的影像記憶體，不再持續佔用快取空間。

English

FEATURE

Automatic updates stop retrying after launch failures and prompt to run grok update

If a newly downloaded version fails to start on your computer, launching the tool previously risked trapping you in repeated attempts. Automatic updates used to persistently attempt to apply a new version at every launch even when major issues in the current environment prevented it from opening, running into repeated startup frustration.

Picture a community pipeline inspection hanging a maintenance warning the moment a valve fails: instead of repeatedly forcing power through before replacement parts arrive from the factory, it asks residents to check the inspection slip manually.

Now, as long as a new version fails to launch on this machine, automatic updates stop retrying until an even newer version is officially released. Every time you launch, the terminal clearly prompts you to run grok update to see why it failed.

FEATURE

Settings add default multiline mode so pressing Enter inserts a newline without sending

When composing long prompts, nothing is more frustrating than pressing the newline key only to accidentally send an unfinished draft.

Think of switching writing formats in a multi-purpose notebook: opening a new page previously defaulted to sticky notes where a single tap tore it off and sent it away, but now the format is locked to stationery paper so pressing a key smoothly advances to the next line to keep writing.

When you enable the Start in multiline option in /settings or add the multiline_default setting under the [ui] section in your configuration file, launching new sessions (independent stages of conversational interaction) and the dashboard will now enter multiline mode by default. In this mode, pressing Enter only inserts a newline.

FEATURE

Pickers support paging shortcuts and introduce the Gruvbox dark theme

Scrolling through extensive feature lists or pickers using only the up and down arrow keys to move step by step can often take considerable time.

Imagine searching a catalog in dense library stacks: where a thick index previously required flipping page by page and line by line, you can now jump full pages or skip straight to the beginning or end, and the shelves even feature an eye-friendly warm color scheme.

In /skills and various pickers (pop-up option lists), you can now use Page Up and Page Down to flip pages up and down, or press Home and End to jump directly to the first or last entry. When entering /theme to switch appearances, the list also adds a retro high-contrast gruvbox-dark-hard dark theme for you to choose.

BUGFIX

`--restore-code` keeps workspace files on failure and targets its own stash

When an error occurs during code restoration, uncommitted and untracked files in the workspace need proper preservation above all.

Consider a mechanic organizing a parts drawer: if a latch failed to install, loose pieces left on the workbench used to be swept wholesale into a junk bin, but now the workbench pieces stay untouched and the drawer gets a dedicated tag so rearranging toolboxes at an adjacent bench will not mix them up.

When restoring code with --restore-code, if the restoration process fails, your uncommitted and untracked files now safely remain in the working tree (Git's feature for opening multiple parallel copies of the same project) instead of being stashed. Even if other parallel workspaces modify the stash (Git's feature for temporarily shelving uncommitted changes) list in the meantime, --restore-code accurately identifies and restores its own dedicated stash record. If a post-checkout hook (a small program automatically triggered after switching branches) fails after the checkout, your changes will also remain safely stashed.

BUGFIX

Windows exits end processes cleanly and fix Shift and AZERTY shortcuts

When using the command line on Windows, closing the application or entering special key combinations could easily encounter stalls and unresponsiveness. Previously, when quitting Grok from the command line, even though the terminal window was restored, the background grok.exe process sometimes failed to end, leaving the shell waiting without a prompt.

Like leaving a borrowed conference room after a meeting: turning off the lights previously left the projector running so the room could not be handed back, but now departing shuts down every piece of equipment completely.

Now, as soon as the terminal screen finishes restoring, grok.exe terminates immediately to return control properly to the shell. For keyboard input, shortcuts typed with Shift-held symbols or AZERTY digit keys often failed to trigger, but these key combinations are now recognized and function normally on Windows.

FEATURE

Queue pane displays queued image chips and successive Send nows avoid false cancellation labels

When managing many queued prompts and jumping the queue repeatedly, the interface state and terminal display now stay much more stable.

A drive-thru lane smoothly adjusts orders in succession: whenever an intercom chime previously rushed the queue, an in-progress meal would be mistakenly announced as cancelled by the customer while the monitoring screen jittered, but order swaps now transition cleanly, pickup screens clearly display side-item icons, and construction signs stay right on the board.

In the queue pane, queued images waiting to be processed now appear as green chips, matching the prompt input box, making it easy to identify attached image files. When a queued prompt starts executing, notes about creating a working tree (Git's feature for opening multiple parallel copies of the same project) stay on screen instead of being cleared by newly launched tasks. When clicking "Send now" several times in a row to jump the queue, stopped turns are no longer labeled "Turn cancelled by user", and the transcript view no longer jumps abruptly.

FEATURE

Transcript view redirects typed input, refines line wrapping, and frees image caches

When browsing past transcripts and execution history, cursor selection, text wrapping, and terminal resource cleanup details have been thoroughly polished. Typing any text while the transcript has focus (including non-ASCII Chinese characters) directs the input straight to the prompt, leaving any pending card or plan approval as it is. When an error occurs loading a session (an independent stage of conversational interaction), the terminal shows the complete reason instead of cutting out the middle of a long message. Lines containing a vertical bar | that are not a Markdown table now wrap like normal text instead of being cut off at the terminal edge. When selecting text in the transcript, the selected row stays steadily on the same row even when an entry above it is removed. For terminals using the Kitty graphics protocol, images Grok hides are freed immediately in the terminal, so they no longer consume cache memory.
