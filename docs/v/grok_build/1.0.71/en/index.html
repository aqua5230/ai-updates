Grok Build 1.0.71

Released: 2026-10-26

Release notes

FEATURE

Prompt experimentally supports Vim mode with state-dependent cursor appearance

Developers who rely on keyboard shortcuts to navigate quickly can now run Vim commands directly inside the terminal prompt.

Much like turning a professional camera focus ring, you previously had to crawl through long texts with arrow keys step by step; now switching modes lets you jump across whole sections or undo changes using counts and motion commands.

Adding the specified setting to the config.toml configuration file enables this experimental feature:

[keys]
vim = "all"

The prompt supports Insert mode and Normal mode. You can use Vim motions, operators, counts, and undo functionality. The prompt's info line clearly marks whether the current mode is NORMAL or INSERT. In Normal mode the cursor is a block, while in Insert mode it switches to a bar. Through ui.cursor_blink, you can configure whether the cursors blink. If you switch to Minimal mode, the info row starts with the prompt's vim mode, and NORMAL is displayed in bold.

FEATURE

Support single Ctrl+C quick exit when no unfinished work remains

When you want to leave a terminal conversation quickly, you often have to press the interrupt command twice to exit.

Picture a power switch fitted with a safety cover: wrapping up work once required toggling two confirmation buttons in a row; now, as long as the desk is clear with no unfinished processes, flipping the main switch once shuts off power cleanly.

Setting ui.single_ctrl_c_quit = true now lets a single Ctrl+C quit directly when no draft or unfinished work would be lost. This toggle can also be found under Editor in /settings. If you keep the default setting, the tool still asks for a second Ctrl+C press for confirmation. When you simply want to clear the window quickly without unsaved progress, a single keystroke immediately closes the session.

BUGFIX

Hooks support failing closed to stop subsequent operations upon unexpected errors

When using custom commands to guard workflows, if a checker program unexpectedly crashes, commands that should have been blocked might slip through.

Think of a pinch-prevention safety gate on an automated assembly line: if a detection sensor suddenly lost power or timed out, the conveyor belt still rolled blindly forward; now, the moment the sensor circuit loses its signal, the entire barrier snaps shut and forces a full shutdown.

Hooks (small programs triggered by specific events) now officially accept the "failClosed": true setting:

{
  "failClosed": true
}

When such hooks time out or crash, the tool call is denied or the prompt is blocked instead of blindly going ahead. Once this property is enabled in the configuration file, subsequent operations will not advance on their own if a hook check is interrupted.

FEATURE

Unified image chip styling and hover previews with cleanup for rejected image notices

When attaching images to collaborate with AI in a conversation, the terminal introduces several refinements to how images are presented and managed. Image chips in the prompt use the same green as sent images in the transcript. Hovering an image chip in the transcript now directly shows the image that was sent, or why it was not attached. Image chips in your messages stay whole on one row when the message wraps, without breaking in the middle anymore. Inline images display in Noctty on Windows. Images the server rejects are removed from the conversation. This resolves an issue where rejected images caused the notice that images were left out to repeat, and grow, on every later turn.

BUGFIX

Clearer formatting for Q&A and drafts with fix for reopening slash menus

When interacting with the agent through questions and answers or reviewing execution logs in the terminal, several interface layouts and popup behaviors have been cleaned up. Answers to the agent's questions show one row per question and answer, and end in … only when the text is cut. Feedback draft rows show the draft's state: drafted, declined, cancelled or failed. A slash menu closed with Esc no longer reopens by itself when the command list refreshes, such as right after startup. When a turn fails, error messages no longer repeat a generic "Request failed:" prefix before the error.
