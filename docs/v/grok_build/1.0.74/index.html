Grok Build 1.0.74

發布日期：2026-11-02

繁體中文

新功能

@ 檔案選擇器支援工作區外路徑與原地編輯

你在對話提示框輸入 @ 挑選檔案時，經常需要引用專案資料夾以外的設定檔或參考資料。

宛如在通訊錄搜尋聯絡人，以前只能挑選同部門成員且點選後無法更動，現在不僅能跨部門翻找名冊，選取後還能隨時退格重選。

現在只要在 @ 後方輸入 /、~/ 或 ../ 開頭的路徑，選單就會直接列出該目錄下的檔案清單。如果不需要這項行為，可以在設定中加入：

[ui]
at_picker_outside_workspace = false

已經挑選進提示框的 @ 檔案也能直接在原地修改。在標記結尾按下 Backspace，選單會沿著原本路徑再次展開；按下鍵盤的 Left 或 Right 方向鍵，則能把游標移入路徑文字之中直接編輯。

新功能

終端輸入支援換行與捷徑補齊，審查卡片提供攔截說明

在終端機輸入提示詞與處理互動卡片時，各項按鍵行為現在更符合操作預期。在 VS Code 或其他採用 Kitty 鍵盤協定的 xterm.js 終端機中，按下 Shift+Enter 現在會正常插入換行符號。 使用 ! 模式輸入外部指令時，按下 Tab 鍵補齊功能現在會列出透過符號連結（symlink，指向另一個位置的捷徑檔）安裝的指令，例如 Homebrew、npm、rustup 與 Debian alternatives 的二進位執行檔。 當介面跳出指令審查卡片時，若自動審查攔截了指令或無法審查，卡片會清楚標註狀態，按下 Ctrl+F 還能查看審查者的詳細說明。 面對提問卡片時，按下 Ctrl+Y 不再於尚未回答時關閉卡片；輸入答案時，它會貼回先前用 Ctrl+K 剪下的文字。

新功能

回覆引用支援乾淨複製，補齊程式碼與登入網址面板

整理對話紀錄中的程式碼與文字引用時，複製內容的操作變得更加順手。

好比在閱覽室整理摘錄，以前遇到無效連結或正在動筆時摘錄夾常會卡死，現在隨時都能把乾淨引文收進筆記。

回覆中的引用文字新增 [Copy] 按鈕，點擊後能直接複製為不帶 > 標記的 Markdown 格式。 當下方開著排隊中的提示詞準備編輯時，點擊紀錄裡的程式碼 [Copy] 會確實複製，不再出現複製無效或意外關閉編輯框的情況。 輸入 /mcps 時，若瀏覽器無法自動開啟 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器的登入網址，面板會直接顯示網址，方便按 c 或 [copy the url] 複製。

問題修復

支援普通點擊跳轉子代理，空格路徑完整連結不截斷

在終端介面點選檔案路徑與代理連結時，跳轉與開啟機制變得更穩定。

恰似整修社區告示牌上的跳轉指引，以前按壓特殊開關常無反應，點開附件還會殘留廢棄底片；現在普通點選就能直通完整目標，也不再留下任何多餘行程。

具名子代理的連結現在只要普通點擊即可開啟。當你從 macOS 透過 SSH 連線操作，複合點擊訊號無法順利傳遞給 Grok 時，依然能順利點開子代理畫面。 從終端介面開啟連結與檔案時，修復了每次點擊都會在背景殘留殭屍行程的問題。 行內程式碼若包含帶空格的路徑，例如 ~/Library/Application Support/...，只要檔案存在就會將整串路徑建為連結，不再於第一個空格處中斷。

問題修復

子代理訊息改為靠左條列，快取損壞自動修復並補齊流程紀錄

追蹤背景任務、工作流程與多個代理之間的協作時，排版與除錯資訊更為完整。子代理之間的對話訊息改為靠左條列顯示在標註發送者與接收者的項目符號下方，取代了過往置中排列的版面。 當內建技能、代理或工作流程在本機的快取（cache，把算過／查過的結果暫存起來直接用）清單遺失或損壞時，Grok 會主動重新整理，不再持續保留過期內容或導致每次同步都失敗。 對話紀錄裡的工作流程執行紀錄，結尾現在會直接顯示回傳的執行成果，不再只有單獨一個冒號。輸入 /tasks 時會清楚顯示任務執行的具體時間；若查詢未知的任務 ID，清單也會保留該列並標示錯誤訊息。

問題修復

恢復對話僅讀取指定紀錄，修復耗時顯示與損毀容錯

重新載入過往對話時，舊紀錄的容錯能力與讀取速度皆有改善。

跟從存檔庫調閱歷史卷宗一樣，以前遇到破損頁面就整份報廢，翻找時還得整庫清點；現在直取目標檔案，部分墨跡模糊也能正常翻開。

執行 grok --resume <id> 時只讀取指定紀錄，不再掃描整個儲存庫，開啟速度加快。 恢復對話後，背景指令的完成狀態會標在原輪次中，並顯示實際執行時間，不再出現約 0.0s。 歷史紀錄若含未知的推論強度或損壞位元組，工作階段會以預設強度運作並提示一次，並排除損毀行。 使用 grok -p --resume 載入失敗會顯示具體原因而非固定報錯；加上 --output-format json 時，開啟前失敗會印出單一 JSON 錯誤。

問題修復

上下文視窗容量持續鎖定，分頁即時顯示並修復登出狀態

切換對話分頁與調整模型容量時，各項工作階段的狀態維持皆有加強。透過 /context-window 挑選較大的上下文視窗後，該設定現在會持續鎖定生效。即便對話長時間閒置、遇到請求限流等錯誤，在主動重啟之前都不會提早觸發內容壓縮。 使用 /new 開啟新分頁時，介面在新對話回覆前就會立刻顯示剛切換過去的上下文視窗大小。 執行 grok logout 登出後，即使背景有另一個 Grok 實體正在更新登入憑據，也不會在下次啟動時被自動重新登入，確保登出狀態持久有效。 如果刪除工作階段失敗，介面只會印出一次「Could not delete session」前綴提示，讓後續的具體錯誤原因能完整呈現，不再遭到切除。

問題修復

更新下載檢驗失敗保留原檔，加固沙盒防護與退出流程

升級版本或在隔離環境維護時，安裝與更新流程有了更健全的防護。

就像為大樓更新門禁，以前送來空包裹或檢驗失敗時舊閘門會直接被拆除，現在必須確認新零件無誤才允許替換。

在 Linux 與 macOS 執行 grok update --force-reinstall 或指定現有版本時，若下載未通過檢查會保留既有執行檔，不再直接刪除。 若代理伺服器或快取（cache，把算過／查過的結果暫存起來直接用）傳回空檔，安裝程式會保留原本檔案，不再誤報成功。 在歡迎畫面按 Ctrl+U 結束安裝時，會在正常時限內退出，不再於顯示「Update installed」後卡死。 透過設定或 --sandbox 指定沙盒時，未受限狀態下仍可跑 grok update；處於隔離沙盒時則不再自動更新，改為提示手動執行。

問題修復

Windows 替換檔案前驗證執行，修復舊版符號與編碼略過

在 Windows 環境下安裝與操作時，多項系統相容性問題已獲得排解。Windows 安裝程式在替換 grok.exe 與 agent.exe 之前，會先驗證下載檔案能否正常執行；若下載內容有誤（如代理伺服器傳回封鎖頁面），會完整保留現有檔案。 在傳統的 cmd.exe 或 Windows PowerShell 主控台（console，命令列視窗）中，工作流程、儀表板、意見回饋與擴充套件對話框的狀態圖示與箭頭，會改以 >、•、√ 或 x 顯示，不再呈現為空白方框。 部分 Windows 編輯器存檔時會附帶 UTF-8 位元組順序記號，現在含有此標記的自訂代理檔案都能正常載入，不再被直接略過。 當啟動出錯、切換 /minimal 或 /fullscreen，或是收到終止訊號時，Grok 會徹底退出，不再偶爾掛起。

問題修復

命令列非 UTF-8 引數容錯啟動，無頭模式中止輸出結尾紀錄

在自動化腳本或特殊系統編碼環境中執行時，啟動與非正常中斷的處置具備了完整防護。傳入無效的非 UTF-8 命令列引數不再導致 Grok 在啟動時崩潰。例如 --cwd 這類路徑參數能正常接收，而 -p 等文字參數則會顯示用法錯誤提示，不再直接閃退。 系統環境變數中若含有非 UTF-8 位元組，現在也不會再阻礙 Grok 正常啟動。 在無頭模式（headless，沒有終端機視窗／視覺介面的執行模式）下執行時，若被 Ctrl-C 或 SIGTERM 訊號中止，json、streaming-json 或 streaming-messages-json 串流會補上一筆結尾紀錄保留成果，不再直接中斷。

問題修復

修復單行長文字貼上凍結，解決打字延遲與沙盒卡死

在終端機輸入提示詞或貼上大量資料時，介面卡頓與凍結問題已經修復。將日誌、JSON 或 base64 等超長單行文字貼入提示框時，終端介面不再凍結數秒。 在原生 Windows 或不支援括號貼上的終端機中，貼上內容常轉為連續按鍵輸入；在開啟規劃模式提示時，這類長貼上不再導致輸入框卡住數秒。 當未安裝 ffmpeg 且 PATH 包含較慢的目錄時（例如 WSL 環境下的 Windows 磁碟機），打字不再延遲。 在 macOS 上，當終端介面在阻擋視窗伺服器的沙盒中執行時，介面也不再陷入凍結。

新功能

長對話自動釋放排版記憶體，降低檔案監控與重繪 CPU 負擔

處理大型專案或展開長篇對話時，記憶體與處理器資源的消耗得到有效控制。在長時間工作階段中，已經滾動到螢幕遠方的已完成 Markdown 區塊會主動釋放渲染好的排版版面，有效減少記憶體佔用；當你搜尋歷史訊息時，文字搜尋依然能順利找到它們。 在 Linux 系統的大型程式碼庫中，檔案監控功能修復了啟動後持續佔用單一 CPU 核心約一分鐘的問題。 當子代理在背景運作時，終端介面現在只針對畫面上的即時動畫進行重繪，減少子代理運作時的 CPU 消耗。

新功能

補齊對話框省略符號，統一狀態燈號與搜尋醒目色彩

在終端介面瀏覽各項面板、設定對話框與狀態提示時，畫面呈現更加精準一致。意見回饋若送出失敗，訊息會優先說明處理結果，隨後列出失敗原因並引導輸入 /feedback 重新發送。 當對話框的分頁標籤、快捷鍵說明或設定列超出寬度時，結尾會以 … 省略號收尾，不再直接被硬生生截斷。 搜尋提示詞歷史紀錄時，相符字母會以一致的顏色醒目標示，/ 與 @ 選單邊框計數也同步淡化。 儀表板在串流回覆時標頭會顯示 Responding，頁尾按鍵提示維持全小寫規範的 new agent。 工作流程標記與啟動中的 MCP 伺服器皆套用主題執行中色彩；精簡模式下登入失敗訊息也改以錯誤顏色顯示。

English

FEATURE

@ File Picker Supports Outside-Workspace Paths and In-Place Editing

When picking files with @ in the prompt, you often need to reference configuration files or documentation outside the project folder.

Browsing contacts in an address book once meant being restricted to your own department without any way to alter selections, but you can now search across departments and backspace to choose again at any time.

Now, typing a path starting with /, ~/ or ../ after @ lists files directly from that directory. If you do not need this behavior, add the following to your configuration:

[ui]
at_picker_outside_workspace = false

Picked @ files in the prompt can also be edited directly in place. Pressing Backspace at the end of a token reopens the picker on its original path; pressing Left or Right arrow keys places the cursor inside the path text for direct editing.

FEATURE

Terminal Input Supports Newlines and Symlink Completion, with Explanations on Approval Cards

Key behavior now aligns more closely with expectations when typing prompts and interacting with cards in the terminal. In VS Code and other xterm.js-based terminals using the Kitty keyboard protocol, pressing Shift+Enter now properly inserts a newline. In ! mode, Tab completion now lists commands installed as symlinks (shortcut files pointing to another location), such as Homebrew, npm, rustup, and Debian alternatives binaries. When a shell approval card pops up, the card clearly displays status when Auto-review blocked a command or could not review it, and pressing Ctrl+F shows the reviewer's detailed explanation. On question cards, pressing Ctrl+Y no longer closes the card without an answer. While typing an answer, it pastes back text previously cut with Ctrl+K.

FEATURE

Clean Copying for Reply Quotes, Reliable Code Copying, and a Sign-In URL Panel

Copying content is now much smoother when managing code and quotations in the transcript.

Like sorting excerpts in a reading room, where clippings previously froze whenever you hit an invalid reference or started writing, clean quotations can now be collected into your notes at any time.

Quotations in replies gain a [Copy] button that copies the text directly as Markdown without its > markers. Clicking [Copy] on a code block in the transcript copies reliably while a queued prompt is open for editing, rather than failing to copy or unexpectedly closing the editor. When running /mcps, if the browser cannot automatically open an MCP (Model Context Protocol, a protocol for connecting AI to external tools) server's sign-in URL, the panel displays the URL directly so you can copy it with c or [copy the url].

BUGFIX

Plain Clicks Open Subagents, and Spaced Paths Form Complete Links Without Truncation

Navigation and opening mechanisms are more reliable when clicking file paths and agent links in the terminal interface.

A renovated community noticeboard guides navigation smoothly: while pressing special switches once failed to respond and opening attachments left discarded films behind, a standard click now reaches the full target without lingering processes.

Links to named subagents now open on a plain click. Even when connecting from macOS over SSH where modified clicks fail to reach Grok, you can still open subagent views smoothly. Opening links and files from the terminal interface fixes an issue where every click left behind a zombie process in the background. When inline code contains paths with spaces, such as ~/Library/Application Support/..., the entire string links to the destination as long as the file exists, instead of truncating at the first space.

BUGFIX

Subagent Messages Left-Aligned, Corrupt Caches Auto-Repaired, and Workflow Logs Completed

Layout and debugging information are more comprehensive when tracking background tasks, workflows, and multi-agent collaboration. Messages between subagents now appear as left-aligned rows beneath the bullet marking the sender and recipient, replacing the previous centered layout. When the local cache (temporary storage for computed or fetched results) manifest for built-in skills, agents, or workflows is missing or corrupt, Grok refreshes it automatically instead of staying outdated or failing every sync. Workflow run lines in the transcript now end with the returned result rather than a bare colon. Entering /tasks clearly displays the specific time the task ran. Querying an unknown task ID keeps the row in place with its error message.

BUGFIX

Resuming Sessions Reads Only Target Records, Fixing Duration Display and Corruption Handling

Tolerance for legacy transcripts and loading performance are both improved when reloading previous conversations.

Just as pulling historical files from an archive once meant auditing every shelf and discarding entire folders over a torn page, you can now retrieve the target file directly even if parts of the ink are damaged.

Running grok --resume <id> reads only the specified session instead of scanning the entire store, opening much faster. After resuming a session, background command completion is recorded in the turn that ran it, showing the actual execution time rather than about 0.0s. Sessions whose history contains an unrecognized reasoning effort or unreadable bytes run at the model's default effort with a single notice, leaving corrupted lines out of the transcript. When loading fails under grok -p --resume, the interface displays the specific reason instead of a fixed error message. With --output-format json, failures before opening print a single JSON error.

BUGFIX

Context Window Capacity Remains Locked, Tabs Update Instantly, and Logout Persistence Fixed

State persistence across sessions is strengthened when switching conversation tabs and adjusting model capacity. After selecting a larger context window via /context-window, that setting remains locked in effect. Even if a session sits idle for an extended period or encounters errors like rate limits, compaction will not trigger early before you restart. Opening a new tab with /new immediately displays the context window size you just switched to before the new conversation replies. After running grok logout, you will not be signed back in automatically on the next launch even if another running Grok instance refreshes credentials in the background, ensuring sign-out persists. If deleting a session fails, the interface prints the "Could not delete session" prefix only once, allowing the specific failure reason to display fully without truncation.

BUGFIX

Update Download Verification Failures Retain Original Binaries, Hardening Sandbox and Exit Flows

Installation and update flows offer sturdier safeguards when upgrading versions or maintaining isolated environments.

Upgrading access controls for a building once meant the old gate was dismantled even when an empty package arrived or inspections failed, whereas replacement is now permitted only after verifying the new hardware.

When running grok update --force-reinstall or targeting the installed version on Linux and macOS, existing executables are retained if downloads fail their checks, rather than being deleted directly. If a proxy or cache (temporary storage for computed or fetched results) returns an empty file, the installer keeps the original file instead of falsely reporting success. Pressing Ctrl+U on the welcome screen to finish installation exits within the normal deadline, rather than hanging after displaying "Update installed". When configuring a sandbox via settings or --sandbox, running grok update remains permitted in unconfined states; once confined in an isolated sandbox, Grok stops updating automatically and prompts you to run it manually instead.

BUGFIX

Windows Verifies Execution Before Replacing Files, Fixing Legacy Symbols and Encoding Skips

Multiple system compatibility issues have been resolved when installing and operating on Windows. Before replacing grok.exe and agent.exe, the Windows installer verifies that the downloaded build runs properly. If the download is invalid (such as when a proxy returns a blocked page), it keeps existing files intact. On legacy consoles (command-line windows) such as cmd.exe and Windows PowerShell, status icons and selection arrows in workflow views, dashboards, feedback dialogs, and extensions dialogs now display as >, •, √, or x instead of empty boxes. Some Windows editors save files with a UTF-8 byte order mark. Custom agent files containing this mark now load normally instead of being skipped. Grok exits cleanly instead of occasionally hanging after startup errors, switching with /minimal or /fullscreen, or receiving termination signals.

BUGFIX

Non-UTF-8 Command-Line Arguments Tolerated at Startup, and Headless Termination Adds Closing Record

Startup and abnormal termination handling are now fully protected when running in automation scripts or environments with specialized system encodings. Passing invalid non-UTF-8 command-line arguments no longer crashes Grok at startup. Path arguments such as --cwd are accepted properly, while text arguments such as -p display usage error messages instead of crashing instantly. System environment variables containing non-UTF-8 bytes also no longer prevent Grok from starting normally. When running in headless mode (an execution mode without a terminal window or visual interface), runs stopped by Ctrl-C or SIGTERM signals end their json, streaming-json, or streaming-messages-json streams with a closing record that preserves the run outcome, instead of cutting off abruptly.

BUGFIX

Fix Freezes on Long Single-Line Pastes, Resolve Typing Lag and Sandbox Hangs

When entering prompts or pasting large amounts of data in the terminal, interface stutter and freeze issues have been resolved. Pasting very long single-line text such as logs, JSON, or base64 into the prompt box no longer freezes the terminal interface for seconds. On native Windows or in terminals without bracketed paste support, pasted content often arrives as a sequence of keystrokes. When the plan-mode tip is enabled, these long pastes no longer cause the prompt box to freeze for seconds. Typing no longer lags when ffmpeg is not installed and PATH contains slow directories (such as Windows drives under WSL). On macOS, when the terminal interface runs inside a sandbox that blocks the window server, the UI no longer freezes.

FEATURE

Release Layout Memory in Long Sessions, Reduce CPU Load from File Watching and Repaints

When handling large projects or holding long conversations, memory and processor resource usage are kept under control. In long sessions, finished Markdown blocks that have scrolled far off screen proactively release their rendered layouts, effectively reducing memory usage. When you search message history, text search still finds them smoothly. In large repositories on Linux, file watching fixes an issue where a single CPU core remained busy for about a minute after startup. When subagents run in the background, the terminal interface now repaints only for on-screen animations, reducing CPU consumption while subagents are active.

FEATURE

Add Dialog Ellipsis Marks, Unify Status Indicators and Search Highlight Colors

Browsing panels, settings dialogs, and status prompts in the terminal interface now provides a more precise and consistent visual presentation. If feedback fails to send, the message leads with the outcome, then lists the failure reason and guides you to enter /feedback to retry. When dialog tab labels, shortcut descriptions, or settings rows exceed their width, they end in an ellipsis … instead of being abruptly cut off. When searching prompt history, matching letters are highlighted in a consistent color, and the counts on the / and @ menu borders are dimmed as well. While a reply streams, the dashboard peek header displays Responding, and the footer key hint keeps the all-lowercase convention of new agent. Running markers in workflow views and starting MCP servers both use the theme's running color. In minimal mode, "Sign-in failed" messages also appear in the error color.

`@` paths outside the workspace: an `@` path that starts with `/`, `~/` or `../` lists files from that folder; set `[ui] at_picker_outside_workspace = false` to turn it off
Picked `@` files in the prompt can be edited in place: `Backspace` at the end of one reopens the picker on its path, and `Left` or `Right` puts the cursor inside it to change the path
Original changelog終端輸入支援換行與捷徑補齊，審查卡片提供攔截說明
Shift+Enter inserts a newline in VS Code and other xterm.js-based terminals that use the Kitty keyboard protocol
Shell approval cards say when Auto-review blocked a command or could not review it, and `Ctrl+F` shows the reviewer's explanation
`!` mode Tab completion offers commands installed as symlinks, such as Homebrew, npm, rustup and Debian alternatives binaries
`Ctrl+Y` on a question card no longer closes it without an answer; while you type an answer, it pastes back text cut with `Ctrl+K`
Original changelog回覆引用支援乾淨複製，補齊程式碼與登入網址面板
`/mcps`: when a browser cannot open an MCP server's sign-in URL, the URL shows in a panel you can copy with `c` or the `[copy the url]` button
Quotes in replies get a `[Copy]` button that copies the whole quote as Markdown without its `>` markers
A code block `[Copy]` in the transcript copies while a queued prompt is open for editing, instead of copying nothing or closing the edit
Original changelog支援普通點擊跳轉子代理，空格路徑完整連結不截斷
Named subagent links open on a plain click, so they work over SSH from macOS where a modified click cannot reach Grok
Opening links and files from the TUI no longer leaves a zombie process behind for each click
File paths with spaces in inline code, such as `~/Library/Application Support/...`, link to the whole path when it exists instead of stopping at the first space
Original changelog子代理訊息改為靠左條列，快取損壞自動修復並補齊流程紀錄
Messages between subagents appear as left-aligned rows under the bullet that name the sender and recipient, replacing the centered rows
Built-in skills, agents and workflows are refreshed when their local cache's manifest is missing or corrupt, instead of staying outdated or failing every sync
Workflow run lines in the transcript end with what the run returned instead of a bare colon, `/tasks` shows the time it was taken, and polling an unknown task id leaves a row with its error
Original changelog恢復對話僅讀取指定紀錄，修復耗時顯示與損毀容錯
Resumed sessions show a background command's completion in the turn that ran it, with its real run time instead of about 0.0s
`grok -p --resume` shows why a session could not load instead of always "Session does not exist", and with `--output-format json` a resume, continue or fork that fails before the session opens prints one JSON error
Sessions with an unrecognized reasoning effort or unreadable bytes in their history resume instead of failing: the session runs at the model's default effort and says so once, and the unreadable lines are left out of the transcript
`grok --resume <id>` opens much faster on large session stores, reading only the resumed session instead of every session
Original changelog上下文視窗容量持續鎖定，分頁即時顯示並修復登出狀態
`/new` tabs show the context window you just switched to before the new session replies
`grok logout` stays signed out when another running Grok refreshes its sign-in, instead of signing you back in on the next launch
A failed session delete shows the "Could not delete session" prefix once, so the reason is no longer cut off
A larger context window picked with `/context-window` stays in effect, so compaction no longer starts early after the session sits idle, after a failed request such as a rate limit, or until you restart
Original changelog更新下載檢驗失敗保留原檔，加固沙盒防護與退出流程
`grok update` still runs when `--sandbox` or config sets a sandbox profile, unless Grok is already running confined
Grok running confined in a sandbox never starts an update on its own and tells you to run `grok update` instead
Quitting to install an update with `Ctrl+U` on the welcome screen exits within the usual exit deadline instead of sometimes hanging after "Update installed"
`grok update --force-reinstall`, or `grok update --version` with the installed version, keeps your working `grok` on Linux and macOS when the download fails its checks, instead of deleting it
Installers keep the installed `grok` when a proxy or cache returns an empty download, instead of replacing it with an empty file and reporting success
Original changelogWindows 替換檔案前驗證執行，修復舊版符號與編碼略過
Windows: Grok exits fully after a startup error, a `/minimal` or `/fullscreen` switch, or a signal, instead of sometimes hanging
Windows installers check that the downloaded build runs before replacing `grok.exe` and `agent.exe`, and keep the existing install when it does not, such as when a proxy serves a blocked-download page
Windows: on older consoles such as plain `cmd.exe` and Windows PowerShell windows, status marks and selection arrows in workflow views, the dashboard, and the feedback and extensions dialogs show as `>`, `•`, `√` or `x` instead of empty boxes
Custom agent files saved with a UTF-8 byte order mark, as some Windows editors write them, load instead of being skipped
Original changelog命令列非 UTF-8 引數容錯啟動，無頭模式中止輸出結尾紀錄
Command-line arguments that are not valid UTF-8 no longer crash `grok` at startup: paths such as `--cwd` accept them, and text such as `-p` gets a usage error
Environment variables with non-UTF-8 bytes no longer stop Grok from starting
Headless runs stopped by Ctrl-C or SIGTERM end their `json`, `streaming-json` or `streaming-messages-json` output with a closing record that keeps the run's outcome, instead of cutting off the stream
Original changelog修復單行長文字貼上凍結，解決打字延遲與沙盒卡死
macOS: the TUI no longer freezes when it runs inside a sandbox that blocks the window server
Typing no longer lags when ffmpeg is not installed and `PATH` holds slow directories, such as Windows drives under WSL
Long pastes that arrive as keystrokes, such as pastes on native Windows or in terminals without bracketed paste, no longer freeze the prompt for seconds while the plan-mode tip is on
Pasting long single-line text such as logs, JSON or base64 into the prompt no longer freezes the TUI for seconds
Original changelog長對話自動釋放排版記憶體，降低檔案監控與重繪 CPU 負擔
Long sessions use less memory: finished Markdown blocks far off screen release their rendered layout, and search still finds their text
File watching on Linux no longer keeps a CPU core busy for about a minute after startup in large repositories
Lower CPU use while subagents run: the TUI repaints only for animations on screen
Original changelog補齊對話框省略符號，統一狀態燈號與搜尋醒目色彩
Feedback that cannot be sent leads with the outcome, such as "Could not send feedback. Saved to Drafts.", then gives the reason and says to retry from `/feedback`
Dialog tab labels, shortcuts and settings rows that do not fit end in `…` instead of being cut off
Prompt history search highlights matched letters in the same color as other fuzzy lists, and the counts on the `/` and `@` menu borders are dimmed like other border captions
Dashboard: the peek header reads `Responding` while a reply streams, and the `Esc` footer hint reads `new agent` like the other lowercase hints
Running markers in workflow views and MCP servers that are still starting use the theme's running color, like other progress indicators
Minimal mode: "Sign-in failed" shows in the error color instead of the warning color
