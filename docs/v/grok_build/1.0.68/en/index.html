Grok Build 1.0.68

Released: 2026-10-22

Release notes

BUGFIX

Creating Worktrees Lists Uncopied Files, and Fails Cleanly When Running out of Disk Space

When you branch out in an existing project to experiment with new features, the biggest worry while creating copies is missing files without realizing it. When running worktree create (a Git feature that maintains multiple parallel copies of the same project) or fork, the command now lists all files that could not be copied along with any mode changes that were lost in the process.

Picture asking a print shop to duplicate a full set of engineering blueprints: in the past, if paper ran out or binding failed on a few pages, the shop often quietly pulled those pages out and delivered the job as if nothing went wrong; now, running out of paper halts the machine immediately to report the error, listing every uncopied blueprint and cut annotation page by page on an inventory sheet.

In the past, if worktree create encountered tracked files that could not be copied or ran out of disk space, it quietly fell back to a fallback mechanism and kept running, leading you to believe the whole environment had been replicated intact. Now, whenever it cannot copy tracked files or runs out of disk space, the process terminates cleanly with an error instead of silently falling back, ensuring that you always know the exact state of your files.

FEATURE

Vim Navigation Consolidated into One Setting, Keeping Old Settings and Toggle Commands Compatible

People who prefer moving the cursor without arrow keys often rely on familiar keystrokes to define their navigation rhythm in the terminal. Vim navigation is now consolidated into a single setting, [keys] vim, which you can set to off to disable it or nav to enable navigation.

Like rewiring a lighting panel in an old house, where the living room and hallway previously used different switch models, the wall is now unified with a single toggle button while the original pull-cord switch in the corner still delivers power normally.

Besides editing your configuration file manually, you can also type /vim-mode directly in the chat interface to toggle this feature quickly. If you previously configured the older [ui] vim_mode in your settings, there is no need to rush to change it after upgrading, as the older setting continues to work seamlessly. You can configure it directly in your configuration file:

[keys]
vim = "nav" # Can be set to "off" or "nav"

This immediately enables Vim navigation mode according to your preference.

FEATURE

Prompts Gain Terminal Color Bands, and Mode Switches Highlight Names in Dedicated Colors

When a terminal accumulates a long thread of questions and answers, quickly scrolling makes it hard to spot where each command begins at a glance. The terminal theme now draws a subtle band behind your input prompts using the color information reported by your terminal.

Shading the question margins in a multi-page binder restores clarity: while black-and-white text previously made section breaks easy to miss, each question now stands out with a soft background tint, and flipping to different topic tabs reveals matching tab colors.

When switching between different working modes, the mode-switch toast (a brief notification temporarily displayed on screen) updates in tandem. The mode names in the notification, including Agent, Plan, and Ask, now appear directly in each mode's dedicated color. Together, these two visual refinements make it easy to identify your current operating state and the boundaries between prompts at a single glance, whether you are switching modes or reviewing past conversations.

FEATURE

Dashboard Directory Picker Opens Unfocused by Default, and Model Picks Retain Context Settings

When preparing to launch a new task on the console dashboard, smooth transitions and inherited settings save plenty of repetitive checks. The dashboard now includes two workflow improvements: first, pressing Ctrl+L on the dashboard to open the change-directory picker leaves the path input field unfocused by default, matching the /resume search interface.

Think of operating a multifunction printer touchscreen: opening a menu previously forced an active cursor over options, and choosing a paper size meant re-selecting it for the next document; now, menus remain in browsing state by default, and customized settings carry straight into the next print job.

The second adjustment focuses on model selection. Previously, after selecting a specific model on the dashboard and adjusting its context window size, spawning and launching the next session often reset the customized window range. The dashboard now remembers your selected context window size and preserves it when spawning the next session, removing the need to re-select it every time you start a new conversation.

FEATURE

Transcripts Clearly Mark Image Delivery Status, Preserved Across Rewinds and Resumes

When you frequently send screenshots and reference images during a conversation, reviewing history requires knowing the actual delivery status of each attachment. Image placeholders in the transcript now clearly indicate whether the actual image file was sent or only plain text was typed.

Flipping through an engineering inspection logbook with attached photos illustrates the change: during past reviews, one could not tell whether an entry included actual photographs or merely written descriptions, and reopened cases often jumbled revoked attachment marks; today, the log clearly distinguishes photos from text, and retracing records correctly preserves even struck-through images.

When you use Send Now prompts or rewind specific conversation turns, the transcript correctly restores and marks all images originally sent. Even when resuming a previous session, image placeholders show the correct sent or struck-through state, giving you a clear view of image context across every turn.

BUGFIX

Running Sessions Remain Uninterrupted When Software Updates Delete Binaries

When you have an AI running a lengthy task, such as organizing a massive batch of files or refactoring code, the worst disruption is an update interrupting your progress halfway through. In the past, updates deleted older binaries (compiled program files that run directly). Running Grok sessions (continuous sequences of conversation and tasks) broke as a result.

A moving train suffers immediately if its old locomotive is uncoupled mid-journey, abruptly stalling the cars behind it.

This issue has been resolved: running Grok sessions are no longer broken when an update deletes their binary.
