zh-TW

`gh pr edit` 指定審核者，不用每次都先抓一輪組織團隊名單

你用 gh pr edit 幫一份 PR（pull request，你送出等人審核、準備合併的一份程式碼修改）指定審核者，如果只是加某個人，不是加某個團隊，以前這個指令還是會先跑去組織裡把整份團隊名單抓一遍，不管你用不用得到。就像去檔案庫辦事，只有真的要用到某份檔案才去調閱它，不會每次進門都先把整個檔案庫翻一遍。現在 gh pr edit 只有你真的要指定某個團隊當審核者時，才會去抓這份名單，其餘情況直接跳過這一步。對你來說，差別在於單純加個人當審核者的操作，不會再被一趟用不到的名單查詢拖慢。

快取筆數、轉圈指示器、派工倉庫、登入通道，四處小毛病一次修好

這幾個小毛病都出在不會特別留意的地方。清快取（cache，算過的結果先存著、下次直接拿）時，gh cache delete 回報的刪除筆數以前會算錯。不管你只給 key，還是 key 再加上 ref（git 參照，標出這份快取屬於哪個分支），現在數字都對得上。gh agent-task create 加 --follow 看進度，以前跑完那個轉圈指示器不會自己停，現在結束就跟著收掉。同樣是這個指令，以前派工可能送到上游倉庫（upstream repo，你這份倉庫的來源），而不是你設定的預設倉庫，現在會送對。另外，auth login 與 auth refresh 改走 UNIX socket（同一台電腦裡程式互傳資料的通道，不繞網路）。像搬完家才發現的幾件小事：箱數少算了、玄關燈忘了關、一封信還寄到舊地址、電話線也沒接上新插孔，這次一併收拾。

en

`gh pr edit` no longer fetches your org's whole team list just to add a reviewer

You use gh pr edit to set reviewers on a PR — a pull request, the code change you've submitted and are waiting on someone to review before it merges. Add just one person, not a team, and until now the command would still go fetch your entire org's team list first, whether you needed it or not. It's like visiting an archive: you only pull a specific record when you actually need it, you don't flip through the whole archive every time you walk in the door. Now gh pr edit only fetches that list when you're actually naming a team as a reviewer, and skips the step the rest of the time. For you, that means adding a single person as a reviewer no longer gets slowed down by a team lookup you never needed.

Cache delete counts, the spinner, task-dispatch repo, and login — four small fixes at once

These are the kind of small bugs you'd never notice unless you hit them directly. When you clear the cache — results stored earlier so you don't have to recompute them — gh cache delete used to report the wrong number of deleted entries; now the count is right whether you pass just a key or a key plus a ref, the git reference marking which branch a cache entry belongs to. Run gh agent-task create with --follow to watch progress, and the spinner used to keep spinning after the run finished; now it stops right when the task does. That same command used to sometimes dispatch work to the upstream repo — the repo yours was forked from — instead of your configured default repo; now it goes to the right one. And auth login and auth refresh now talk over a UNIX socket instead of the network. It's like the handful of things you only notice after you've finished moving house: you miscounted the boxes, forgot to turn off the hallway light, a letter still went to the old address, and the phone line never got hooked up to the new jack — this round cleans up all four.

zh-CN

`gh pr edit` 指定审核者，不用每次都先抓一遍组织团队名单

你用 gh pr edit 给一份 PR（pull request，你提交出去等人审核、准备合并的一份代码修改）指定审核者，如果只是加某个人，不是加某个团队，以前这个命令还是会先跑去组织里把整份团队名单抓一遍，不管你用不用得到。就像去档案库办事，只有真的要用到某份档案才去调阅它，不会每次进门都先把整个档案库翻一遍。现在 gh pr edit 只有你真的要指定某个团队当审核者时，才会去抓这份名单，其余情况直接跳过这一步。对你来说，差别在于单纯加个人当审核者的操作，不会再被一趟用不到的名单查询拖慢。

缓存条数、转圈指示器、派工仓库、登录通道，四处小毛病一次修好

这几个小毛病都出在不太会特别留意的地方。清缓存（cache，算过的结果先存着，下次直接拿）时，gh cache delete 报告的删除条数以前会算错。不管你只给 key，还是 key 再加上 ref（git 引用，标出这份缓存属于哪个分支），现在数字都对得上。gh agent-task create 加 --follow 看进度，以前跑完那个转圈指示器不会自己停，现在结束就跟着收掉。同样是这个命令，以前派工可能送到上游仓库（upstream repo，你这份仓库的来源），而不是你设定的默认仓库，现在会送对。另外，auth login 与 auth refresh 改走 UNIX socket（同一台电脑里程序互传数据的通道，不绕网络）。像搬完家才发现的几件小事：箱数少算了、玄关灯忘了关、一封信还寄到旧地址、电话线也没接上新插孔，这次一并收拾。

ja

`gh pr edit` でレビュアーを指定するとき、毎回組織のチーム一覧を取りに行かなくてよくなった

gh pr edit で PR（pull request、レビューを経てマージされるのを待つ、送り出したコードの変更）にレビュアーを指定するとき、追加するのが個人一人だけでチームでなくても、これまでは組織のチーム一覧をまるごと取りに行っていた。使うかどうかは関係なかった。資料室に用があるとき、実際に必要な一件だけを取りに行くのであって、入るたびに資料室全体をめくり返すわけではないのと同じだ。今の gh pr edit は、実際にチームをレビュアーに指定するときだけこの一覧を取りに行き、それ以外はこの手順を飛ばす。使う側から見ると、個人一人だけをレビュアーに加える操作が、使いもしない一覧取得に足を引っ張られなくなったということだ。

キャッシュの件数、くるくる回るインジケーター、タスクの送信先リポジトリ、ログイン経路、四つの小さな不具合をまとめて直した

どれも普段は気づかないところに潜んでいた不具合だ。キャッシュ（cache、一度計算した結果をためておいて次はそのまま使う仕組み）を消すとき、gh cache delete が報告する削除件数はこれまで数え間違えていた。key だけを渡した場合でも、key に ref（git の参照情報、そのキャッシュがどのブランチのものかを示す）を添えた場合でも、今は数が合う。gh agent-task create に --follow を付けて進捗を見ると、これまでは実行が終わってもくるくる回るインジケーターが自分では止まらなかったが、今は終わると同時に消える。同じコマンドでは、これまで作業の送信先が設定した既定のリポジトリではなく upstream repo（自分のリポジトリの元になったリポジトリ）に向かうことがあったが、今は正しい方に届く。ほかにも、auth login と auth refresh は UNIX socket（同じマシンの中でプログラム同士がデータをやり取りする通路で、ネットワークを経由しない）を使うようになった。引っ越しを終えてから気づく細かな見落としのようなものだ。箱の数を数え間違えていた、玄関の電気を消し忘れていた、手紙が旧住所にまだ届いていた、電話線も新しいジャックにつながっていなかった。今回はその四つをまとめて片付けた。

ko

`gh pr edit`에서 리뷰어를 지정할 때, 매번 조직 팀 목록부터 긁어오지 않아도 된다

gh pr edit로 PR(pull request, 리뷰를 거쳐 병합되기를 기다리는, 제출한 코드 변경 사항)에 리뷰어를 지정할 때, 추가하는 대상이 팀이 아니라 개인 한 명뿐이어도 예전에는 이 명령이 조직의 팀 목록 전체를 먼저 긁어왔다. 실제로 쓰든 안 쓰든 상관없이 그랬다. 자료실에 볼일이 있을 때 실제로 필요한 문서 한 건만 꺼내러 가지, 들어갈 때마다 자료실 전체를 뒤지지는 않는 것과 같다. 이제 gh pr edit는 실제로 팀을 리뷰어로 지정할 때만 이 목록을 가져오고, 나머지 경우에는 이 단계를 건너뛴다. 사용자 입장에서 달라지는 점은, 개인 한 명만 리뷰어로 추가하는 작업이 더는 쓸모없는 목록 조회에 발목 잡히지 않는다는 것이다.

캐시 삭제 건수, 빙글빙글 도는 표시기, 작업 전송 저장소, 로그인 경로, 소소한 문제 네 가지를 한 번에 고쳤다

다들 평소에는 딱히 눈에 띄지 않는 곳에서 벌어지던 문제다. 캐시(cache, 계산해 둔 결과를 저장해 두었다가 다음에 바로 꺼내 쓰는 방식)를 지울 때 gh cache delete가 보고하는 삭제 건수가 예전에는 잘못 계산됐다. key만 넘기든, key에 ref(그 캐시가 어느 브랜치에 속하는지 나타내는 git 참조)를 더해 넘기든, 이제는 숫자가 맞는다. gh agent-task create에 --follow를 붙여 진행 상황을 보면, 예전에는 작업이 끝나도 빙글빙글 도는 표시기가 저절로 멈추지 않았는데 이제는 끝나는 순간 함께 사라진다. 같은 명령에서 예전에는 작업을 설정해 둔 기본 저장소가 아니라 upstream repo(자신의 저장소가 갈라져 나온 원본 저장소)로 보내는 일이 있었는데 이제는 제대로 된 쪽으로 간다. 그 밖에 auth login과 auth refresh는 UNIX socket(같은 컴퓨터 안에서 프로그램끼리 데이터를 주고받는 통로로, 네트워크를 거치지 않는다)을 쓰도록 바뀌었다. 이사를 마치고 나서야 알아차리는 자잘한 일들과 같다. 상자 개수를 잘못 셌다, 현관 등을 끄는 걸 잊었다, 편지가 아직 옛 주소로 오고 있었다, 전화선도 새 잭에 연결되지 않았다. 이번에 그 네 가지를 한꺼번에 정리했다.
