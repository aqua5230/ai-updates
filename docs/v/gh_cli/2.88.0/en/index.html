GitHub CLI 2.88.0

Released: 2026-03-10

Release notes

FEATURE

Create and view collaboration items with clearer people and choices

You can now create a pull request and ask reviewers based on their login, or search for them in the interactive picker.

Pull request and issue views show friendlier display names for every participant, and closing a duplicate issue can point back to the original with --duplicate-of. It is like labelling office tasks with names and a link to the original sheet, so the next person does not have to guess who is who or which copy matters.

FEATURE

Filter diffs, read data, and launch Copilot more smoothly

You can now hide files you do not want to inspect from a pull request diff with --exclude.

JSON output for pull request files adds changeType, and listing or viewing agent tasks can also return JSON for other tools to read. When gh launches Copilot CLI, it sets the COPILOT_GH environment variable so Copilot knows who started it. It is like sorting a stack of proofs: remove the pages you do not need, then add labels for the next helper.

FEATURE

Get more control over cloning, merge messages, and code history

When you use gh repo clone to copy a remote project to your computer, --no-upstream lets you avoid setting an upstream.

Editing a repository can now set the commit message for a squash merge, which combines several changes into one. gh browse also adds --blame to open a line-by-line history showing who changed a line and when. It is like moving house with the option not to leave a forwarding address, labelling one whole box, and checking which roommate packed an item.

BUGFIX

Hit fewer errors and garbled results when editing or exporting data

You should hit fewer rough edges when editing and exporting data.

gh project item-edit no longer errors for a Draft Issue with only a title or body; a failed extension install now shows owner/repo instead of raw internal data; and assignee databaseId values in --json output no longer stay at zero. Color codes in JSON and diffs, port-forwarding number conversion, --remote with a repository argument, and an unnecessary API call for issue comments were also fixed. It is like repairing a form so its fields, labels, and delivery tubes all return to the right place.

FEATURE

Keep issue lists, project settings, and maintenance work steadier

You get clearer guardrails around issue lists and project setup.

Pull-request-only search qualifiers are rejected in gh issue list, project issue creation explains scope errors more clearly, and repeatedly starting an issue development branch with the same name no longer corrupts .git/config. The release also simplifies repeated scope handling and feature checks, precompiles Content-Type matching, and updates Go requirements, install prefixes, per-platform licenses, a monthly promotion workflow, and dependencies. It is like having the office filter out the wrong forms first, then arranging keys and repair manuals so routine work is less likely to jam.
