GitHub CLI 2.103.0

Released: 2026-10-21

Release notes

FEATURE

`gh` can sign in with auto-refreshing credentials (preview)

Normally, signing in to GitHub with gh gives you a token (the pass that proves who you are) that never expires. You can now opt into expiring OAuth credentials instead: gh stores a short-lived access token alongside a rotating refresh token (a credential used only to get a new pass). The access token is refreshed automatically whenever needed, so you stay signed in without authenticating again.

An office swapped its permanent badges for temporary ones reissued every day: you used to keep one badge until you left the company, and now it renews daily while you still just tap in each morning.

This is a preview you have to opt into. To use it for a single sign-in, run:

gh auth login --expiring

To prefer expiring credentials for every sign-in, run:

gh config set expiring_credentials enabled
FEATURE

Living with expiring `gh` credentials: status, git and scripts

Once expiring credentials are on, you may want to know how long yours has left. gh auth status shows whether a credential is refreshable and when the current access token expires, and both gh auth status and gh auth token refresh the access token automatically when needed. Expiring tokens are available on github.com and GHE.com; on hosts that do not issue them, gh falls back to a regular non-expiring token. If git talks to GitHub over HTTPS, the advice is to use git 2.46 or newer and run gh auth setup-git so gh acts as git's credential helper (the program that hands git its sign-in details). That way git does not cache the credential past its lifetime.

Treat it like fresh milk: you could once stock up a crate and drink it slowly, and now you buy it as you need it.

So scripts and extensions should not store the output of gh auth token; run it again each time a token is needed. Tokens supplied through GH_TOKEN or GITHUB_TOKEN are never refreshed.

FEATURE

New `gh issue artifact` manages issue artifacts from the terminal (private preview)

When planning a new feature, you may want to hang the plan, a flow chart or a web prototype right on a GitHub issue (the thread that tracks a task or problem). gh issue artifact brings issue artifacts to the command line with six commands, list, view, create, edit, download and delete, for example:

# Create a Markdown document with an attached image
gh issue artifact create 142 signin-plan.md --attach ./signin-flow.png

# Create an HTML document
gh issue artifact create 142 menu-prototype.html

# List or view artifacts
gh issue artifact list 142
gh issue artifact view 142 2

# Update a document or restore an earlier version
gh issue artifact edit 142 2 --body-file signin-plan-v2.md
gh issue artifact edit 142 2 --restore-version 5

Give every work ticket its own folder that holds the plan and the prototype and remembers every version, so rolling back to version 5 is easy.

Artifacts can also be addressed by their GitHub URLs, and Markdown documents take image and video attachments with --attach. This is a private preview: only users and organizations enrolled can use it, and the commands work only for repositories in the preview; access instructions are in the official preview announcement discussion.
