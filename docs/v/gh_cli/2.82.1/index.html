不支援的 GitHub 主機也能順利修改拉取請求

你在不支援 V1 projects（第一代專案功能）的 GitHub 主機上使用 gh pr edit 修改拉取請求時，gh CLI 不會再先嘗試抓取這些主機不支援的專案資料，因此編輯動作能順利進行。它處理的是主機能力不同造成的多餘請求，不是替主機新增 V1 projects。就像在分店修改訂單，分店沒有某種舊型櫃位時，店員會直接替你處理訂單，不再先跑去找那個櫃位。

更新建置與格式辨識等底層依賴版本

你安裝 gh CLI 後，程式使用的幾個底層依賴（組成程式的外部零件）已更新到較新的版本：github/codeql-action 從 3 升到 4；github.com/sigstore/sigstore-go 從 1.1.0 升到 1.1.3；github.com/gabriel-vasile/mimetype 從 1.4.9 升到 1.4.10；actions/attest-build-provenance 從 2.4.0 升到 3.0.0。這些是版本替換本身，原始紀錄沒有宣稱額外功能或效能改變。就像維修工具箱，把幾個外部零件換成指定的新批次，工具箱的用途不變，但裡面的零件版本已對上新標籤。

en

Edit pull requests without fetching unsupported V1 projects

When you use gh pr edit to edit a pull request on a GitHub host that does not support V1 projects, gh CLI no longer tries to fetch those unsupported project records first. The edit can proceed without that unnecessary request. This handles the host's existing capability difference; it does not add V1 projects to the host. It's like changing an order at a branch that has no old service counter: the clerk handles the order directly instead of sending you to look for a counter that is not there.

Update build, signing, and MIME detection dependencies

After installing gh CLI, several dependencies (external components that the program is built from) are on newer versions: github/codeql-action moves from 3 to 4; github.com/sigstore/sigstore-go from 1.1.0 to 1.1.3; github.com/gabriel-vasile/mimetype from 1.4.9 to 1.4.10; and actions/attest-build-provenance from 2.4.0 to 3.0.0. These entries record version replacements only; the release notes do not claim extra features or performance changes. It's like replacing a few parts in a repair kit with specified newer batches: the kit's purpose stays the same, while the part labels are brought up to date.
