AI_UPDATES.LOG

GitHub CLI 2.97.0

發布日期：2026-07-31

繁體中文

用名稱改 Project 項目，清單欄位也看得到名字

你在 GitHub Project（把工作拆成卡片和欄位的管理看板）裡找待辦事項，不必先翻出那串難記的 ID 了。gh project item-edit 現在能依名稱找到項目；像整理「修登入頁」這張卡時，可直接用它的名字指定對象。gh project item-list 也能把具名欄位列出來，清單不再只像一排沒有標籤的抽屜。搜尋某個儲存庫時，gh search --repo 會提示 OWNER/REPO 格式，文件也把依名稱編輯列為主要做法。

`gh skill` 接上 Grok，代理清單換成 Devin

想讓 AI 代理幫忙檢視程式碼時，gh skill 的選項更新了。它新增 Grok 的 skill host 支援，也把代理清單中的 Windsurf 換成 Devin；選擇畫面過長的標籤換行問題一併修好。專案還加入 code review agent skill，也就是給代理做程式碼審查用的操作說明。像替工具箱添了新轉接頭，現在能接 Grok；舊的 Windsurf 插槽則改標 Devin，拿取時不會再被斷行的標籤絆住。

驗證缺根憑證不再卡死，macOS 解鎖多等一分鐘

開啟 GitHub CLI 時，驗證器需要的 trusted root（用來確認信任鏈起點的根憑證）若缺失，初始化失敗現在會被妥善處理，不會讓這一步變成死結。macOS 的 keyring（存放登入金鑰的地方）若跳出互動式解鎖提示，等待時間也從 3 秒延到 60 秒。這版還補上 macOS keyring 的安全文件。像進大樓時保全發現名冊少一頁，會改走可處理的流程；而你正翻包找門禁卡，櫃台願意多等一分鐘。

專案自動流程整理：分流 issue、部署與依賴更新

這張卡講的是 gh 專案自己的後勤，不是你今天要輸入的新指令。團隊新增 pull request 範本、用代理分流 issue 的 workflow，也新增 Dependabot 的分流流程；issue 分流 workflow 改用 Actions token 做 Copilot 推論，並更新到 gh-aw v0.83.1。部署 workflow 加強，網站部署用的 SITE_DEPLOY_PAT 改由 gh-cli-site-deployer App 取代。CodeQL 的 Dependabot 更新會分組處理，Go 與多個函式庫、Actions 也陸續升版；無效的 CODEOWNERS 規則與程式、文件、註解的錯字一併清掉。像倉庫後場重新排班：分貨、交接、補貨都各自有路走，前台的 CLI 使用方式沒有因此多一道手續。

English

Edit Project items by name and see named fields in lists

When you are looking for a task in a GitHub Project, you no longer have to dig up its hard-to-remember ID first. gh project item-edit can now resolve an item by name, so you can target a card such as “Fix login page” by its name. gh project item-list can show named field columns too, rather than a row of unlabeled drawers. gh search --repo now hints at the OWNER/REPO format, and the docs present name-based editing as the main Project flow.

`gh skill` adds Grok and swaps Windsurf for Devin

If you use AI agents to review code, gh skill has refreshed its choices. It adds support for Grok as a skill host and replaces Windsurf with Devin in its agent list; labels that wrapped awkwardly in the picker have also been fixed. The project now includes a code-review agent skill: instructions for an agent doing code review. Think of a toolbox gaining a new adapter for Grok while the old Windsurf slot is relabeled Devin, with no wrapped label getting in the way.

Missing verifier roots no longer halt setup; macOS keyring access gets a minute

When GitHub CLI starts, verifier initialization can fail because a trusted root—the root certificate at the start of a chain of trust—is missing. That failure is now handled gracefully instead of becoming a dead end. On macOS, an interactive keyring access prompt now gets 60 seconds rather than 3 seconds. This release also adds security documentation for the macOS keyring. It is like a guard finding a page missing from a visitor list and following a workable procedure, while the desk gives you a full minute to find your access card.

Project automation tidied: issue triage, deployment, and dependency updates

This card is about the gh project's own backstage work, not a new command for you to type today. The team adds a pull-request template, an agentic issue-triage workflow, and a Dependabot-triage workflow; the issue-triage workflow uses the Actions token for Copilot inference and is refreshed to gh-aw v0.83.1. The deployment workflow is hardened, and SITE_DEPLOY_PAT is replaced by the gh-cli-site-deployer App. CodeQL Dependabot updates are grouped, while Go, libraries, and Actions receive updates; a dead CODEOWNERS rule and typos in code, docs, and comments are removed. It is like reorganizing a warehouse back room: sorting, handoffs, and restocking each get their own route, without adding a step to the CLI counter.
