GitHub CLI 2.93.0

Released: 2026-05-27

Release notes

FEATURE

Authentication and API checks get more accurate

This batch fixes a handful of accuracy issues around authentication and API checks.

Secrets (sensitive values like API keys) used to be scoped only to a user or a repository; now an agent (an automated bot, for example) can also use secrets under an application identity. Looking up a PR (pull request) by number used to take a "number-only" shortcut that skipped API validation, which could return inaccurate results; that shortcut is gone, so every lookup is validated now. Hitting a 401 (unauthorized) error used to just print an unhelpful error; now it prints "run gh auth refresh" to tell you exactly what to do. When gh copilot fails to run, it now hints you to run the copilot command directly to troubleshoot, instead of just showing an error. It's like an ATM that no longer just flashes an error code when a withdrawal fails, but tells you directly what to do next.

FEATURE

Supply-chain security tightens up; releases get locked

This batch strengthens supply-chain security (making sure the software you download hasn't been tampered with).

gh release verify (the command that checks a release's integrity) now derives the right digest algorithm (the hashing method used to verify content hasn't changed) from the length of the ref (version tag), making verification more accurate. The CLI's own build pipeline switched its verification action from actions/attest-build-provenance to actions/attest (another official GitHub-hosted attestation action). In the project's own GitHub Actions (automation scripts), first-party actions (ones GitHub itself maintains) are now pinned by SHA (a fixed version hash), so they can't silently change content if the upstream action gets updated. Docs also now note that starting with v2.93.0, GitHub Releases become immutable (locked after publishing — no more edits). It's like sealing a shipment before it leaves the factory and using an inspector who only checks a fixed batch number, so the goods can't be swapped mid-transit.

BUGFIX

Install docs and a small Windows glitch fixed

This batch is installation-docs and small polish fixes.

The official install command docs were updated; some Linux distros (the dnf family) had an unnecessary --repo gh-cli in their install commands, which is now removed; on Windows, running certain commands used to flash a tzutil console window in the background — that flicker is fixed; and a duplicated word plus a grammar typo in the docs were also corrected. The rest is extended PR-screening process work, telemetry (usage-reporting statistics) adjustments, and dependency version bumps that don't affect day-to-day use. It's like proofreading a manual to remove extra filler words and typos in one pass — everything just reads cleaner now.
