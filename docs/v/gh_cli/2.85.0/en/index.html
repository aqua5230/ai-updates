GitHub CLI 2.85.0

Released: 2026-01-14

Release notes

FEATURE

Browse straight to Actions

When you want to inspect GitHub Actions—the service that runs automated tests, builds, or deployments—from the terminal, gh browse now has an --actions flag.

A flag is an option added to a command to change what it opens, and this one sends the browse command to the Actions page instead of making you start on a repository page and switch tabs. The notes only add this shortcut; they do not claim to change what workflows do or produce. Like adding a direct elevator button for the parking garage: same destination, fewer buttons.

FEATURE

Use a Git remote name to choose the default repository

When setting the default repository with gh repo set-default, you can now name a Git remote, such as origin.

That helps people who already gave one codebase several remote destinations choose the default by the label they recognize. The notes do not say the command will create or rewrite any remotes for you. It is like choosing an existing “work” or “personal” label in an address book instead of copying the full address again.

FEATURE

Unexpected project data no longer makes the tool stop abruptly

When working with GitHub project data, null project items—places where an item exists but has no readable value—will no longer trigger a panic, an abrupt program stop when it cannot handle an error.

This is a repair to an existing path, not a new project-management feature. The same release also corrected the Debian CLI package link in the installation guide, sending readers to the right place. Like a clerk skipping a blank box on a form and continuing, while the sign at the entrance is pointed the right way.

FEATURE

Release tooling and underlying dependencies received maintenance

You do not need to change any everyday command, but this release updated OAuth, signing, build verification, and several Go dependencies.

It also maintained CI, the automated checking and packaging process: GoReleaser was upgraded, Azure Code Signing details changed, build jobs gained tags, and Windows temporary-tag creation received an explicit shell. Extension workflow templates also update actions/checkout. The notes do not claim a new terminal feature, so this is best read as ongoing care for the release factory. Like maintaining a warehouse’s sealers, sorting rules, and spare parts while the kinds of parcels it sends remain the same.
