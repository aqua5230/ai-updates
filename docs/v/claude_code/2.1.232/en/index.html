Claude Code 2.1.232

Released: 2026-08-13

Release notes

FEATURE

Forked subagents keep the context and work in the background

When a long conversation needs another agent, a subagent_type: "fork" subagent now starts with the full conversation and prompt cache, rather than needing the background repeated.

In interactive sessions, non-teammate agents also start in the background by default. It is like handing a colleague a notebook already marked at the right page, then letting them work at the next desk instead of taking over yours.

FEATURE

Cross-session messages can go straight to a session name

With several Claude sessions on one machine, type @ and a session name in the prompt to send it a SendMessage.

A bare name that exactly matches one live session no longer needs a ref confirmation. Duplicate names receive a name-word-word variant. /config also adds Dialog expiry and Messages from your other sessions, where inbound cross-session messages can be accepted, held, or refused.

FEATURE

GitLab credentials are redacted and GitLab repositories work in marketplaces

GitLab is now safer and easier to use as a plugin source.

The listed GitLab token families are redacted, and routable glpat- and gldt- tokens are fully redacted. The glab CLI config store gets the same sandbox and credential-path protection as gh. Plugin marketplaces can clone bare gitlab.com repository URLs, including nested subgroups, and authentication-failure hints name the real Git host.

FEATURE

Plugin marketplace settings get friendlier names and installs refresh first

Marketplace settings now accept additionalMarketplaces for extraKnownMarketplaces and allowedMarketplaces for strictKnownMarketplaces.

A URL-typed blockedMarketplaces policy entry still blocks a bare repository URL when the CLI treats it as a Git clone. /plugin install plugin@marketplace refreshes the marketplace first, so newly published plugins do not require a manual marketplace update.

FEATURE

Gateway validates Desktop settings and policies before it starts

Gateway now accepts every released Desktop setting in the desktop: overlay and validates it against Desktop's schema at boot; unknown or invalid keys fail boot.

Empty managed.policies[].match.groups or admin.admin_groups, and malformed email_domain values, also fail boot instead of silently matching nobody or granting admin access.

FEATURE

Fable 5 returns to Advisor with a corrected consent message

Organizations with Fable access can again choose Fable 5 in /advisor, with usage-credits consent set through /model fable.

The consent message for interactive --advisor fable launches no longer tells you to run /model fable in an interactive session that has just exited.

FEATURE

Commands that can redirect file access now require permission approval

Permission checks now cover routes that can redirect file access.

PowerShell parameters that write variables can no longer silently overwrite $PSDefaultParameterValues and redirect later commands. Git Bash writes through Cygwin-style symlinks on Windows require approval, and Bash input redirections (< file) are permission-checked on every platform.

BUGFIX

Nested Git repositories now earn trust separately

A Git repository inside another Git repository no longer inherits trust from its parent directory.

Each repository now needs its own trust confirmation. Trusting the outer project still means trusting that project; it does not automatically extend to a separate project inside it.

BUGFIX

MCP connections stop waiting so long for a broken server reply

When an MCP server does not answer, or gives a malformed reply to the protocol-version probe, a connection no longer waits through the full 30-second connect timeout.

MCP is the protocol that connects AI to external tools. It is like ringing a doorbell and getting either silence or an unreadable note; you find out sooner that this door cannot be used now.

FEATURE

Remote Control reconnects to the right conversation and restores its history

Remote Control sessions started from Claude Desktop or an IDE now reattach to the existing claude.

ai session when resumed, rather than appearing new each time. Newly attached clients remain reachable while idle, and bridge-session history is restored after its worker restarts. If the original session was deleted from claude.ai or the app, resuming starts a replacement instead of reporting a login problem.

FEATURE

Remote Control reconnects after a blip and explains who has control

After a network blip, Remote Control keeps reconnecting for about 30 minutes and no longer drops after a few blips spread across an hour.

Resuming does not silently take control from another Claude Code on the same machine; run /remote-control there to move it. The terminal now says whether another device took over, another app ended, or deleted the session, and stops suggesting a reconnect that would undo that state.

BUGFIX

Cloud login and rejected voice connections now show the reason

When managed settings fail to load, Cloud gateway /login no longer exits silently or leaves an unresponsive terminal after “Press Enter to continue”; it shows the reason.

On native builds, voice mode no longer stays on “listening…” when the voice service rejects its connection; that rejection appears immediately.

BUGFIX

Cloud connections reload rotated certificates and recover from idle timeouts

After an mTLS client certificate rotation, Claude Code now reloads the certificate and key on connection errors instead of requiring a restart.

Bedrock, Vertex, and gateway deployments recover from stream idle timeout errors rather than failing the request. Malformed AWS or Vertex region values no longer build request URLs and fall back to the default region.

BUGFIX

Truncated text no longer widens overlays or leaves a garbled character

A content-sized overlay no longer renders one column too wide when its text is truncated, and text truncated at the start no longer collapses to an ellipsis.

A long shell-command or agent-description preview cut mid-emoji also no longer leaves a stray garbled character. These are fixes for displaying only part of a string without distorting what remains.

BUGFIX

A plugin marketplace no longer disappears during simultaneous startup writes

A startup race caused by concurrent writes to known_marketplaces.json could silently unregister a plugin marketplace.

That race is fixed, so a registered marketplace no longer disappears when startup work writes the file at the same time.

BUGFIX

Update and TUI can restart while surviving work is running

/update and /tui no longer refuse to restart just because work that survives the relaunch is running.

That work is not being stopped; the update or text interface can restart while it continues to survive the relaunch.

BUGFIX

Usage-limit guidance now recommends only available slash commands

In SDK and remote sessions, usage-limit guidance no longer suggests slash commands that are unavailable in that environment.

It does not change the limit or add commands; it makes the guidance point only to actions that the current session can actually use.

BUGFIX

Remote Control no longer inherits a cloud session’s transcript or credentials

A Remote Control session hosted by a bridge inside a cloud session no longer inherits that cloud session’s transcript or credentials.

The bridge can still host Remote Control, but the hosted session does not receive the cloud session’s conversation record or login proof.

FEATURE

Long streaming and pasted images no longer block responsiveness

Fullscreen streaming stays responsive in long sessions because each update no longer re-normalizes the whole conversation.

Pasted and clipboard images are read without blocking the event loop, the main loop that processes interface and input events. Incoming content no longer has to stop the rest of the interface to be handled.

FEATURE

Managed-settings approval shows endpoints and separates higher-risk overrides

The managed-settings approval dialog now shows endpoint URLs and explains telemetry-only changes more clearly.

Routine OpenTelemetry options are skipped, while server-managed sandbox binary overrides still need approval: sandbox.bwrapPath, sandbox.socatPath, and sandbox.ripgrep. It distinguishes routine telemetry settings from changes that replace a sandbox tool.

BUGFIX

Feedback, bug reports, and higher-effort code review no longer hold up the turn

/feedback and /bug now open immediately even while Claude is responding.

/code-review at high, xhigh, and max effort now runs in a background agent like other effort levels. One action opens the reporting form without waiting; the other moves the longer review work off the interactive conversation.

FEATURE

Finished agents are tidier and custom-agent nudges are gone

Completed background subagents now hide immediately in the agent panel with a /tasks footer hint, and “↓ N more” moved left.

The resume message for a completed background agent is shorter. The startup tip about creating custom subagents and the matching /powerup nudge are removed. These changes tidy status information rather than change how agents work.

FEATURE

Cowork stops inlining external imports from user memory

Cowork sessions no longer inline external @-imports from user-scope memory files.

This is about external imports being expanded into the current session, not about Cowork ceasing to read the memory file itself. Referenced external content no longer automatically enters the session through that route.

FEATURE

Sandbox paths trust only approved sources and reject planted directories

The auto-generated cross-session messaging socket directory in shared /tmp now refuses a planted symlink or another user’s directory.

The Linux filesystem sandbox is hardened against a protected-path bypass. sandbox.ripgrep is honored only from user, managed, and --settings settings; project settings cannot override the sandbox’s ripgrep binary.
