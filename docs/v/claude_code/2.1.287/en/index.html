Claude Code 2.1.287

Released: 2026-10-01

Release notes

FEATURE

Claude Mods deep module architecture launches, with a built-in close-watch reminder assistant

When you're heads-down rushing work and worried about missing key details, the new module extension capability comes in handy.

Claude Mods lets plugins modify deeper layers of how the system works. It ships with a built-in module called You should know, which runs a dedicated assistant agent alongside you to help keep watch, proactively flagging details either side might have missed. In official sessions with telemetry enabled, type /plugin enable cc-plugin-you-should-know@builtin in Claude's interactive interface to enable it.

It's like having a seasoned sous-chef standing beside you while you stir-fry—never grabbing the wok, but tapping your shoulder in time when the seasoning runs heavy or the heat runs too high.
FEATURE

Agent list supports name filtering, and collapsed sections can be opened directly

When you have dozens of sessions running in the background and can't find a specific task, the agent list now supports quick search.

In the agents view, type n:<keyword> to match both session names and task content at once. Even if matching items are hidden inside collapsed sections, the filter lists them all, and pressing Enter opens the first search result directly.

Picture using a quick index machine among a library's densely packed shelves: enter a title code and it automatically unfolds the collapsed bookcase and points out where the first book sits.
FEATURE

Telemetry events gain a prompt field, compatible with nested-key monitoring backends

When managing cloud monitoring and trace records, certain backends may fail to parse field names containing dots.

In the OpenTelemetry (an open standard for collecting logs and performance data) user_prompt event, a new field named prompt_text has been added, containing a full copy of prompt. When your log backend splits dotted key names into layers of nested structure, reading this new field won't error out. If you mask or filter sensitive prompts, remember to handle this new field as well.

Think of attaching name tags in different languages to the same piece of luggage, so transfer stations used to all kinds of scanning equipment can identify it smoothly.
FEATURE

Extension tools support URL interactive elicitation, making login authorization smoother

When an external tool needs to guide you to a specific web page to complete login, it can now pop up a URL prompt directly.

This version supports the URL elicitation feature from the 2025-11-25 protocol version of MCP (Model Context Protocol, the protocol that lets AI connect to external tools).

Like a clerk at the service counter handing you a guidance card printed with a dedicated URL—open it to complete login authorization, instead of hunting around for the activation page yourself as before.

After updating, if a particular server can't connect, just add {"bareElicitationCapability": true} to that MCP server's configuration block to restore compatibility.

FEATURE

Windows command tool speedup, with clearer pipeline redirection and tool-disable notices

Running commands or chaining pipelines on Windows is now smoother, with clearer error messages.

When denying authorization for the Bash tool also shuts down PowerShell, a warning is now issued at startup, avoiding the predicament of having no usable terminal tool at all. Interactive mode no longer unexpectedly hangs or crashes when it encounters piped input or redirection—it clearly explains why and then exits; if you use piped input, switch to -p mode instead. The system also removed the redundant subprocess (an independent process branched off from the main program) before command execution, improving command speed.

Just as a car dashboard lights up immediately when both power switches are off, you confirm your equipment is complete before setting out—and the throttle feels lighter too.
FEATURE

Self-hosted environments get a built-in GitHub interface command, working even without the CLI installed

When you run automation on your team's self-hosted runners and need to access data from GitHub, you're spared the hassle of manually installing tools.

On macOS and Linux, sessions using officially hosted Git now have gh api built in. Even if the host doesn't have the related command package preinstalled, the system can access remote resources directly through the REST interface.

It's like a carry-on suitcase with a universal network adapter built in for business trips—even in a meeting room without dedicated equipment, you can connect right away.
BUGFIX

Remote control connections are more stable, fixing sleep interruptions and retry stalls

When you run tasks via remote control or in agent environments, connections are now more stable and reliable.

In remote sessions where the organization allows it but there's no dedicated user account, fast mode now stays on properly. When a remote control connection hits an unresponsive state, it now automatically gives up and retries after thirty seconds, instead of waiting idly for minutes. Running claude remote-control through an HTTP proxy server can now complete registration; previously, when registration failed, it showed a misleading organization permission error. Running tasks also won't be interrupted when a Mac goes idle and sleeps.

Like a long-distance line that proactively redials within half a minute when it hits static, it won't easily drop when facing a switchboard transfer or a brief standby.
BUGFIX

Event hook counts are precise, fixing repeated wake-ups and cloud sync

When you set up automated checks in a project or sync plugins in the cloud, event hook execution is cleaner and more accurate.

A hook (a small program triggered when a specific event occurs) configured for asynchronous wake-up that lacks its script file now reports the error only once, instead of repeatedly waking up and sending notifications. The plugin sync startup hook now runs successfully in new cloud sessions, and execution records no longer count internal callbacks—set one and it faithfully shows one.

Think of a doorbell circuit fault lighting up a single repair indicator on the panel instead of ringing all day, with the counter no longer tallying internal self-checks as visitors.
BUGFIX

SDK tool heartbeat and streaming fixes—urgent messages no longer interrupt background searches

When you automate execution through the SDK (the software package for programmatically connecting to Claude) or command mode, data streaming and background operations are more stable.

When the model's reply stream stalls, tool heartbeat signals still arrive on schedule. After switching models mid-reply, claude -p and SDK sessions no longer repeatedly trigger the fallback mechanism on every subsequent message. When using --output-format stream-json or the SDK and running a context: fork skill via /<skill>, each turn of the skill now streams output too. Urgent messages sent out of queue won't interrupt a web query running in the background.

Picture an urgent courier delivery arriving at the mailroom: the staff on duty takes it immediately, but doesn't unplug the fax machine that's mid-reception.
BUGFIX

Enterprise cloud model check fixes, with more precise guardrail blocks and header validation

When enterprises rent models through cloud channels, startup checks and safety guardrail responses are clearer and more stable.

The model list check at startup no longer misses managed settings, so the menu fully shows all available models. If a safety guardrail block is triggered during a thinking reply, the guardrail's explanatory text now displays clearly instead of a generic system error. When experimental features are turned off, session title and prompt hook requests thoroughly remove the format the cloud gateway rejects. In CLAUDE_CODE_SKIP_*_AUTH checks, if ANTHROPIC_CUSTOM_HEADERS specifies Authorization more than once, the authorization header sent by the model availability check now matches the actual request. When Amazon Bedrock rejects a model ID, the Claude apps gateway shows developers on screen which model is unavailable, and the gateway log records the ID actually sent.

Like an office building's access system precisely checking the approved list when a visitor swaps badges, it clearly states the reason when a restricted area is hit, rather than flashing a vague fault light.
FEATURE

Model switching preserves thinking depth; 1M context on by default in the cloud

When switching between models or calling in an advisor, your settings and history are properly preserved.

When you sign in with claude.ai and pick Fable in /model, the saved default model follows the latest version; switching between Opus 5.5 and Sonnet 5.5 no longer rewrites tool history and loses your earlier deep thinking. Opus 4.7 and above, plus Fable, default to 1M context on Bedrock, Vertex, Foundry, and the Claude apps gateway with no [1m] suffix needed, and setting CLAUDE_CODE_DISABLE_1M_CONTEXT=1 keeps you at 200K. /advisor now supports Sonnet 5.5 advising Opus 4.7 and 4.8, and flags pairings the API won't accept ahead of time. When a safety flag triggers a model switch, the thinking effort you originally specified is kept too.

A doctor hands over diagnostic notes to a colleague, and the new consultation keeps the originally planned depth without starting the story over.
FEATURE

Terminal command safeguards upgraded, sensitive file writes strictly intercepted

When you let the AI loose on batch-cleaning directories or running all kinds of system scripts, potentially dangerous operations are now gated more rigorously.

Running a dangerous rm against / or your home directory while the same command redirects output to ~ or a wildcard path no longer slips past the confirmation prompt; the permission menu also now explains things in plain language instead of internal codes. Bash commands inside the Linux sandbox no longer inherit handles already opened by the Claude Code executable. Writing to sensitive locations or outside the working directory through a symlink (a shortcut file pointing to another location) committed to the repository now shows the final destination and waits for human approval. Even with an allow rule covering the entire Bash tool or hooks permitted to run, files that Claude Code's file tools flat-out refuse to write (Anthropic's personal data store, host credential files) will only trigger a confirmation for shell writes, never silent execution.

A building upgrades its security desk: even with an all-access badge, entering the core server room still requires signing in person.
BUGFIX

Conversation compaction no longer double-loads settings; mid-session project additions take effect immediately

When an over-long conversation triggers automatic compaction or you resume earlier progress, project settings stay accurate.

After resuming a session or running conversation compaction (the mechanism that automatically condenses long conversations to save space), a folder's CLAUDE.md is no longer loaded twice, and the post-compaction commit-attribution reminder no longer shows up in tool results. A cloud session restarting mid-compaction no longer loses the first half of the conversation, and repositories added mid-session in cloud and SDK sessions now have their skills and plugins loaded, with CLAUDE.md no longer loading late only after you switch directories.

Condensing the minutes of a long meeting doesn't photocopy the opening rules twice, and a new agenda item handed in midway gets slipped into the folder right away.
FEATURE

Smoother background agent management, with command queuing and permission prompts

When you dispatch multiple background agents to handle tasks in parallel, list viewing and command interaction feel much smoother.

After a background task finishes and its worktree (Git's feature for running multiple parallel copies of the same project) is cleaned up, the session can still be reopened from the management list without trouble. Prompts awaiting approval in the background are now clearly listed. Agent replies are now delivered in a sequential queue, and slash commands typed while a turn is in progress (except /stop, which interrupts immediately) run in order once the current turn completes.

A manager reviews field staff progress: records stay retrievable after a temporary desk is torn down, documents awaiting sign-off are clearly marked, and newly assigned items join the queue to be handled the moment the current work wraps up.
FEATURE

Terminal scrolling no longer crashes; key pasting and permission prompts improved

When scrolling through long conversations or reviewing permissions, the terminal's visual feedback and interaction details are more stable.

Holding a scroll key under heavy system load no longer crashes the full-screen interface unexpectedly; with --include-partial-messages, truncated replies no longer send message_stop too late or drop it, so apps no longer misread them as still in progress. Animations truly stop when reduced motion is enabled, and the "how long ago" time no longer jumps around while you type a note on the /rewind confirmation screen. The light theme boosts contrast for the input box border and history arrows. Right-click paste on Windows and Linux, and middle-click paste on Linux, now take effect on button release, so moving the pointer away before releasing cancels; multiple pending prompts are ordered oldest to newest instead of abruptly covering the current screen, though prompts with countdown timers still appear on top.

Flipping through a heavy ledger, the pages glide without sticking; slips awaiting sign-off are stacked in arrival order, with time-limited ones placed on top.
FEATURE

Tighter MCP tool permission checks, plus protocol switching and prompt layout polish

When you connect external extension tools or run background automation, tool permissions and prompt layout are more consistent.

Organization-set permission ceilings for MCP (Model Context Protocol, the protocol that lets AI connect to external tools) tools previously failed for tools named __proto__; they are no longer ignored. When an MCP server changes the protocol version it supports, connector tool calls no longer occasionally run twice, nor keep failing until restart; headless mode (running without a visual interface) sessions no longer misread a single rejection as needing re-authentication. Prompt screens for tool calls and retained messages now share a unified dashed border for tidier visual layout.

An outside vendor moves in and badge permissions are strictly controlled; after the access protocol changes there's no need to re-register, and every window's sign-off slips follow one format.
FEATURE

Reduced load for large MCP payloads, with deferred tool loading and independent retries

When external tools return huge payloads or you connect multiple servers, resource consumption and the loading process are steadier.

When MCP results are stored as single-line JSON (a text-based data format), Claude is no longer wrongly told to page through them with Read's offset and limit, since that approach can't split one long line. Handling oversized data now saves memory and session storage, and no extra uploads happen just to count tokens (the text units AI processes and bills by). In headless mode, if a remote server's first connection temporarily fails during multi-server startup, each one retries individually without waiting on the slowest connection. When a server is configured with alwaysLoad: false, its tools defer loading until tool search.

Bulk freight arriving at the warehouse takes up less space, and a delayed truck can retry entry on its own off to the side without blocking the others.
BUGFIX

Screen reader search and menu fixes, more precise key guidance (part 1)

When operating the terminal with screen-reading software, the search box cursor position and menu key guidance are now more accurate.

The cursor in search boxes and login verification-code fields no longer drifts away from the character being typed. When rewinding a conversation you can press Enter to confirm without typing an extra note, and the interface no longer shows invalid Tab or arrow-key hints; empty menus or search boxes receiving keys no longer wrongly display "Select with numbers". When the previous screen is taller than the window, the top content of subsequent review prompts, settings-change lists, and the rejected-plan line all read out in full.

An accessible audio guide locks precisely onto the current input position, announces only valid keys, and no longer skips the opening paragraph when the page turns.
FEATURE

Screen readers now read file diffs in full, with less animation interference (part 2)

When reviewing code changes and background progress through screen-reading software, spoken interference drops noticeably and content is more complete.

File-edit review prompts and other diff screens now fully read out added, deleted, or modified lines. Send progress and form validation no longer retrigger speech with every animation frame, and the agent list's time updates are throttled to keep speech from jumping wildly. Extra pauses at line starts when printing text have been removed for smoother reading rhythm; setting CLAUDE_AX_PREPARK_MS=50 restores the original pause.

A live meeting transcriber reads out each revision sentence by sentence, no longer cutting in every second to announce the time, so listeners can stay focused to the end.
BUGFIX

Deep-review upload guidance fixed; no more wrong settings advice

When you use the /ultrareview command to upload code for deep review, error guidance is more precise.

If an upload breaks because a .gitattributes file in a particular encoding can't be parsed, the system no longer suggests modifying unrelated paths. When an upload is rejected, it also no longer wrongly directs you to copy project setting variables into your personal global settings.

An inspector whose part fails spec points straight at the offending dimension, no longer misdirecting you to amend the factory certificate or check unrelated lists.
BUGFIX

Clearer sign-in credential failure messages, no more vague codes

When your claude.

ai sign-in credentials are revoked, the system now states directly that your sign-in credentials are no longer valid. Previously, when your sign-in was revoked, the terminal only showed a vague API Error: 401, leaving you puzzled. Now the system clearly marks it as "OAuth token revoked." In -p command mode, error messages also begin with "Failed to authenticate." Where you once wondered whether the network or a server had failed, you can now tell at a glance that you need to sign in again.

FEATURE

Built-in commands smoother to use, settings menu supports left-right paging and keyboard switching

When adjusting settings or reporting issues in the terminal, the built-in commands interact and report errors more clearly.

The /config settings list supports cycling values in both directions with the left and right arrow keys, wraps automatically in narrow windows, and supports shortcut keys for quick paging; /memory also lets you toggle switches like auto-memory directly with the arrow keys. Typing a /skill name mid-message is now recognized correctly, including the disable-model-invocation type; the issue-report command no longer fills recent errors directly into the public template, but lists them fully on a confirmation screen. When Claude in Chrome cannot connect to Chrome, it no longer falsely reports a JSON parsing error; when /desktop times out or produces too much output while launching the desktop app, the error message states the cause.

A remote-control panel now has fine-tuning arrow keys and a quick page button, making operation crisper; when the device fails, the screen also tells you what went wrong.
FEATURE

Plugin marketplace supports plain HTTP sources, dependency installs and more reliable caching

When you install or update custom plugins, the package management flow is smoother and more reliable.

Repositories hosted over plain HTTP now support installing plugins with claude plugin marketplace add --sparse and git-subdir. Plugins downloaded at startup no longer corrupt the session's cache files (which temporarily store looked-up results for direct reuse) due to a simultaneous reload. When the marketplace misbehaves, it explains the cause and next steps in plain language, the list flags uninstalled dependencies, and updating a plugin retries any unfinished installs.

Following an app store's package list, missing pieces or interrupted installs used to be hard to spot; now missing pieces are flagged, and updates retry the unfinished installs.
FEATURE

Remote file transfers support disk streaming, auto-retry on failure with relaxed wait time

When Claude sends you files from the cloud or a remotely controlled session, file transfers become more stable and reliable.

The wait time for remote uploads has been relaxed to thirty-five seconds; upload timeouts, network errors, or server responses of 502, 503, or 504 trigger one retry. When a temporary problem occurs, it proactively reminds you that you can request the file again in a few minutes. Large files are now streamed directly from disk instead of filling up memory, and when a size limit is exceeded, the server's specific cap is clearly listed.

A post office shipping a large parcel now loads it onto the truck gradually via a conveyor belt instead of hauling it all at once, and a brief traffic jam on the road triggers automatic redelivery.
BUGFIX

Oversized images auto-resized for sending, multi-attachment transfer limit fixed

When you attach many files or high-resolution images in a conversation, everything sends smoothly with nothing dropped.

In remote sessions, sending a PNG, JPEG, or WebP image over eight thousand pixels on a side used to fail; now a scaled-down copy is sent instead. Sending seventeen to twenty attachments at once from the app now delivers every file, no longer stopping at the first sixteen. If the server rejects files over the limit, it also clearly explains the specific reason.

Shipping a giant poster, the courier automatically folds it or rolls it into a standard tube, and a whole batch of parcels gets fully counted onto the truck.

Downloading a large file on your computer, you minimize it to the background while progress keeps ticking live on a small status card, and the main screen stays free for editing other documents.

After a reload, it no longer launches duplicate processes, but marks the session as already open elsewhere. The browser extension's default connection toggle now also applies to editor sessions; once connected, it still asks before performing browser actions.

A meeting-room booking system walks you into the already-open discussion room, no longer issuing duplicate access cards, and the board outside the door shows the latest usage status.

Viewing tool input and output in remote or subsystem environments no longer times out just because the editor tab appears slightly late. Choosing /usage and /context from the menu also runs properly. Saving settings no longer falsely reports a timeout when the reply data is large, and when a plugin management list operation fails, the reason is listed.

BUGFIX

[Cloud sessions] GitHub fetch and push failures in cloud sessions fixed

When you have just connected to a cloud environment and are ready to sync progress with a remote repository, the flow no longer breaks for no reason.

In cloud sessions, GitHub would occasionally briefly reject a freshly issued access token (an authorization token used to confirm your identity), causing fetch or push operations on your code to fail.

With a newly issued access card entering a building, the gate would occasionally refuse entry for a moment when you swiped; now you are no longer stuck outside.

After the fix, running fetch and push in a cloud session is no longer interrupted by GitHub briefly rejecting a new token.

For organizations with many channels, the spending-limit list in the admin console can now list recently created and private channels.

[Code Review] Code review feedback now shown in full, and pushing again automatically restarts the review

When you open a pull request and wait for the AI to review your changes, or when you submit updates based on feedback, the review process now gives clearer and more reliable responses.

Suggestions and the reasons behind flags in the review report no longer get cut off mid-sentence; every comment appears as a complete sentence. If the review of a previous commit failed twice, pushing new code will still trigger a review of the latest commit instead of skipping it. If a discussion thread is locked, the card clearly states that nothing ran or was published because of the lock, and that you were not charged anything.

Imagine a senior proofreader who writes out every comment in full while marking up a manuscript, never leaving a sentence half-finished; the moment the author hands in a revised draft, the review starts over right away, and if the file is locked, the proofreader clearly explains that no charge was made.
