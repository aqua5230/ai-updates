Claude Code 2.1.225

發布日期：2026-08-08

zh-TW

額度用完時，原因與恢復時間說清楚

公司替 Claude Code 設了使用上限，做到一半跳出「額度已滿」時，最煩的是不知道誰設的、何時能再做。現在透過 gateway（閘道，替公司統一管控連線的中介服務）使用時，警告會直接列出上限金額、重設時間，以及管理者留下的訊息。像停車場出口的看板，從前只亮紅燈；現在會寫清楚今日上限、幾點重新開放，還附上管理室交代。這項支援需要 gateway 升到 2.1.225。

進陌生資料夾前，agents 也會先問你

你把下載來的專案交給 claude agents 處理前，現在會先看到工作區信任提示。工作區信任（workspace trust，確認這個資料夾可放心讓工具在裡面工作的確認）原本已在 claude 指令裡出現，這次讓 agents 的行為跟上。它像進陌生人家裡修東西：先問主人能不能進門，再開始翻工具箱；確認過的資料夾才繼續。遇到網路抓下來、還沒看過內容的專案時，這道提醒尤其有用。

登入短暫失靈，不再把長期憑證換掉

沒有畫面的 headless（無頭模式，沒有終端機視窗的執行方式）工作跑到一半，碰上一個暫時的 401 錯誤，以前可能被換成短命登入 token（授權令牌，用來證明登入身分的通行碼），得重啟才救得回來。macOS 的 MCP OAuth 伺服器也會在鑰匙圈讀取逾時後，突然連發 401，像從沒登入過。現在兩種狀況都修正了。這像交通卡讀卡器一時失靈，卻把你的月票剪成單次票；它現在不會亂換卡。

自動模式被拒後，會換路而非原地重試

自動模式（auto mode，Claude 自己執行操作、逐步少問一次的模式）要請權限卻被安全篩選器拒絕時，操作仍會被擋下；這次拒絕不計入連續受阻次數，模型會收到往下做的提示，改往其他可繼續做的步驟前進，不再重試。像自助結帳機刷不過某張折價券，店員仍不讓它通過，但也不會讓機器一直重刷同一張；它會改成繼續處理購物籃裡的其他東西。

跨工作階段訊息不再無聲停在半路

你在沒有畫面的 headless（無頭模式，沒有終端機視窗的執行方式）環境，或 Claude Code 剛啟動時傳跨工作階段訊息，過去訊息可能停在佇列裡，既不提醒也不會過期。現在這個問題修好了，不必再像盯著一直沒叫號的號碼牌那樣等著。跨工作階段訊息是不同 Claude 工作階段之間的傳話；它該送達、該告知時就會有明確結果，而非悄悄停住。

遠端控制重連後，不再把舊進度越堆越多

用 Remote Control（遠端控制，從另一台裝置查看或接手 Claude 工作）接續超長對話時，先前壓縮過的聊天記錄可能讓恢復失敗；網頁工作階段還會被誤判卡住，每次重連又重送更多舊事件。現在這兩處都修正。它像接續播放清單：以前播放器既找不到停下的位置，又把已播曲目一首首重放；現在能從原處接回，也不會讓舊內容越疊越厚。

遠端控制收到的照片，直接交給 Claude 看

你在 Claude app 附上一張照片給 Remote Control（遠端控制，從另一台裝置查看或接手 Claude 工作）的工作階段時，Claude 現在直接收到照片，不必再用另一個工具從磁碟讀檔。要它看截圖、收據或白板照片時，這條路少了一次繞行。像把相片交到對方面前，而不是先放進倉庫，再請對方拿鑰匙去找；照片仍是同一張，只是交接方式改得更直接。

agents 不會因滑過別的專案就走錯資料夾

agents 清單裡把滑鼠移到另一個專案的工作階段上，下一個 agent 以前可能改在那個專案的資料夾啟動，現在不會了。另一邊，claude self-hosted-runner 的 --base-dir 若無法建立或寫入，過去會先註冊、每個工作階段才失敗；現在啟動時就明白報錯並退出。像派車中心不再因瞄到隔壁訂單就把司機派錯地址，車庫門打不開也會在出車前說清楚，不會每趟才拋錨。

VS Code Focus 視圖不再把待辦與答案藏掉

在 VS Code 的 Focus view（專注檢視，把對話內容折疊整理的畫面）裡追 Claude 的進度時，最新待辦、未回答問題的脈絡，甚至已解決的答案，之前可能被折起來看不見。現在它們會留在眼前；只有純思考內容會折疊，並標成「Thought for Ns」，等該輪結束再收回。像整理收納盒：行動清單和結論放在最上層，草稿筆記才暫時收到盒底。

可直接傳話給其他機器上的遠端工作階段

想請另一台機器上的 Remote Control 工作階段幫忙，現在 SendMessage 可依名稱直接開啟對話，不必等對方先傳話。ListAgents 會把它顯示成 name [ref]，方便辨認遠端對象。你確認過的遠端收件人，也不會因本機剛好有同名工作階段、而且清單查不到遠端時，被偷偷換成那一個。像依取件編號交付物品：先用名稱和編號認出指定對象；即使遇到同名者，已確認的對象也不會被換掉。

en

Usage-limit warnings now explain the cap and reset time

If your company sets a Claude Code spending limit, hitting it halfway through work used to leave you guessing who set it and when work could resume. When you connect through a gateway, the warning now names the cap, reset time, and operator message. It is like a parking-lot exit sign that once showed only red; now it says today's limit, when entry reopens, and what management wants you to know. The gateway must be on 2.1.225.

Agents now ask before working in an untrusted folder

Before handing a downloaded project to claude agents, you now get a workspace-trust prompt. Workspace trust is a confirmation that a folder is safe for tools to work in. Claude already asked this question; agents now behave the same way. It is like repairing something in a stranger's home: ask before entering, then open the toolbox. This matters most for projects fetched from the internet that you have not inspected yet.

Brief 401 errors no longer replace durable login credentials

A headless job can run without a terminal window. During one, a temporary 401 error used to replace a long-lived CLAUDE_CODE_OAUTH_TOKEN with a short-lived login token, breaking the job until restart. On macOS, MCP OAuth servers could also emit a burst of 401s after a Keychain read timed out. Both cases are fixed. It was like a transit-card reader briefly failing and then cutting your monthly pass into a one-trip ticket; it no longer swaps the card.

Auto mode moves on after a blocked action instead of retrying

When auto mode asks for permission and a safety filter refuses that check, the action still stays blocked. The refusal no longer counts toward the consecutive-block limit, and the model is told to move on rather than retry. Think of a self-checkout that cannot accept one coupon: staff still reject it, but do not make the machine scan the same coupon forever; it continues with the rest of the basket.

Cross-session messages no longer disappear into a silent queue

Send a message between Claude sessions from a headless environment, or during startup, and it could previously sit in a queue with neither notice nor expiry. That is fixed. A cross-session message is a handoff between separate Claude sessions; it should now produce an outcome rather than resemble a letter wedged silently inside a mailbox. You no longer need to wonder whether it is waiting forever.

Remote Control reconnects stop piling up old progress

With Remote Control, you can inspect or take over Claude work from another device. Resuming a huge conversation after its history was compacted could fail, while web sessions could be falsely called stuck and resend an ever-growing backlog on each reconnect. Both are fixed. It was like rejoining an online meeting where the host lost the first half of the notes and replayed every old slide; now the meeting resumes where it stopped without piling up history.

Remote Control now hands app photos directly to Claude

Attach a photo in the Claude app to a Remote Control session and Claude now receives it directly, rather than fetching it from disk with a separate tool call. When you ask it to inspect a screenshot, receipt, or whiteboard photo, the handoff has one less detour. It is like handing someone a picture instead of storing it in a warehouse and asking them to fetch it with a key: same photo, more direct delivery.

Agents keep the right folder, and runners fail early on bad paths

Hovering over a session from another project in the agents list could previously change the folder where the next agent started. It no longer does. Separately, if claude self-hosted-runner cannot create or write its --base-dir, it now exits with a clear startup error instead of registering and failing every session. It is like dispatch no longer sending a driver to a neighbor's address after glancing at their order, and reporting a locked garage before every trip breaks down.

VS Code Focus keeps current work and answers visible

When following Claude in VS Code's Focus view, the newest to-do list, context for a pending question, and settled answers could be folded away. They now stay visible. Only thinking-only sections fold, show “Thought for Ns,” and collapse again once that turn finishes. Think of folded meeting notes: the action list and conclusion remain on top, while rough scratch work goes inside the pages.

SendMessage can reach named Remote Control sessions on other machines

Want help from a Remote Control session on another machine? SendMessage can now start a conversation with it by name; you no longer have to wait for it to write first. ListAgents shows it as name [ref]. A Remote Control recipient you already confirmed also cannot be silently replaced by a same-named local session if its remote list cannot be checked. It is registered mail: find the addressed recipient first, and do not hand the confirmed letter to a namesake.

远程控制重连后，不再把旧进度越堆越多

用 Remote Control（远程控制，从另一台设备查看或接手 Claude 工作）接续超长对话时，先前压缩过的聊天记录可能让恢复失败；网页会话还会被误判卡住，每次重连又重送更多旧事件。现在这两处都修正。它像线上会议断线再进来：以前主持人既找不到前半段笔记，又把之前的投影片一张张重播；现在会议能接回原处，也不会让旧内容越叠越厚。

利用上限の警告が、上限とリセット時刻を説明する

会社が Claude Code に利用上限を設け、作業の途中で上限到達と出たとき、誰が決めたのか、いつ再開できるのか分からないのは困る。gateway（ゲートウェイ、会社が接続をまとめて管理する仲介サービス）経由なら、警告に上限額、リセット時刻、管理者のメッセージが直接表示される。赤ランプだけだった駐車場の出口掲示板に、今日の上限、再開時刻、管理室からの伝言まで出るようなものだ。この機能には gateway 2.1.225 が必要である。

信頼していないフォルダでは agents も先に確認する

ダウンロードしたプロジェクトを claude agents に渡す前に、ワークスペースの信頼確認が出るようになった。ワークスペースの信頼とは、そのフォルダ内でツールを動かしてよいか確かめる確認である。claude コマンドにはすでにあった挙動に agents もそろった。知らない家で修理を始める前に、まず中へ入ってよいか尋ねるようなものだ。ネットから取ったばかりで中身を見ていないプロジェクトで役立つ。

一時的な 401 で長期ログイン情報を置き換えなくなった

画面なしで動く headless（ヘッドレス、端末ウィンドウを出さない実行方式）の作業中、一時的な 401 エラーによって長期の CLAUDE_CODE_OAUTH_TOKEN が短命なログイン token（認証トークン、ログインを証明する通行証）へ置き換わり、再起動まで壊れることがあった。macOS の MCP OAuth サーバーも、キーチェーン読み取りのタイムアウト後に 401 を連発することがあった。どちらも修正済みである。交通系ICカードの読み取り機が一瞬壊れたからと月間パスを一回券に替えてしまうような扱いは、もう起きない。

自動モードは拒否後に同じ操作を繰り返さず先へ進む

自動モード（auto mode、Claude が操作を自分で進め、確認を減らすモード）が権限を求め、安全フィルターがその確認を拒否した場合、操作自体は引き続き拒否される。ただし、その拒否を連続ブロック回数に数えて同じ操作を繰り返すことはなくなった。モデルには先へ進むよう伝えられる。セルフレジで一枚のクーポンが通らなくても、店員は通さない一方で同じ券を延々と読ませず、残りの商品を処理させるようなものだ。

セッション間メッセージが無言で待機し続けなくなった

画面なしで動く headless（ヘッドレス、端末ウィンドウを出さない実行方式）環境や Claude Code の起動中にセッション間メッセージを送ると、以前は通知も期限もないままキューに置かれることがあった。この問題は修正された。セッション間メッセージは別々の Claude セッションへの伝言である。郵便受けの隙間に挟まって黙ったままの手紙ではなく、送達か通知か、はっきりした結果が得られる。

Remote Control の再接続で古い進捗が積み上がらなくなった

Remote Control（リモートコントロール、別の端末から Claude の作業を見たり引き継いだりする機能）で非常に長い会話を再開すると、圧縮済みの履歴が原因で復帰できないことがあった。Web のセッションも停止中と誤判定され、再接続のたびに古いイベントを増やして送り直していた。どちらも修正済みである。オンライン会議へ戻ったとき、司会者が前半のメモを失い、古いスライドを全部また流すような状態はなくなる。

Remote Control の写真を Claude へ直接渡せる

Claude アプリから Remote Control（リモートコントロール、別の端末から Claude の作業を見たり引き継いだりする機能）のセッションへ写真を添付すると、Claude は別ツールでディスクから読むのではなく、その写真を直接受け取る。スクリーンショット、レシート、ホワイトボードの写真を見せるとき、受け渡しが一段短くなる。写真を倉庫に置いて鍵で取りに行かせるのではなく、相手の手へ渡すようなものだ。

agents は別プロジェクトに触れても作業先を取り違えない

agents の一覧で別プロジェクトのセッションにカーソルを置くと、次の agent がその別プロジェクトのフォルダで始まることがあったが、もう起きない。また claude self-hosted-runner は --base-dir を作成または書き込みできない場合、登録後に各セッションで失敗する代わり、起動時に明確なエラーを出して終了する。隣の注文をちらりと見て運転手を別住所へ送る配車や、車庫が開かないことを出発後まで黙る状況がなくなる。

VS Code の Focus 表示が最新の作業と答えを隠さない

VS Code の Focus view（フォーカス表示、会話を折りたたんで整理する画面）で Claude の進捗を追うと、最新の TODO、未回答の質問の文脈、解決済みの答えまで折りたたまれることがあった。今はそれらが見えたままになる。思考だけの部分だけが折りたたまれ、「Thought for Ns」と表示され、そのターンの完了後に再び閉じる。会議メモを折るなら、行動項目と結論は一番上に残し、下書きだけを内側にしまうようなものだ。

SendMessage で別の端末の Remote Control セッションへ直接送れる

別の端末にある Remote Control のセッションへ頼みたいとき、SendMessage は名前で直接会話を始められるようになった。相手から先にメッセージが来るのを待つ必要はない。ListAgents では name [ref] と表示され、遠隔の相手を見分けられる。確認済みの遠隔受信者も、遠隔側の一覧を確認できないときに同名のローカルセッションへ勝手に差し替わることはない。書留郵便で宛先を確かめ、同姓同名の住人へ渡さないようなものだ。

사용 한도 경고가 한도와 초기화 시점을 알려 준다

회사에서 Claude Code 사용 한도를 걸어 두고 작업 중간에 한도 도달 경고가 뜨면, 누가 정했는지와 언제 다시 할 수 있는지가 답답하다. 이제 gateway(게이트웨이, 회사가 연결을 한데 관리하는 중개 서비스)를 거치면 경고가 한도 금액, 초기화 시점, 관리자의 메시지를 바로 보여 준다. 빨간불만 켜지던 주차장 출구 전광판에 오늘 한도와 재개 시각, 관리실 안내까지 적히는 셈이다. 이 기능을 쓰려면 gateway가 2.1.225여야 한다.

신뢰하지 않는 폴더에서는 agents도 먼저 묻는다

내려받은 프로젝트를 claude agents에 맡기기 전, 이제 작업 공간 신뢰 확인이 먼저 나온다. 작업 공간 신뢰란 그 폴더 안에서 도구가 일해도 되는지 확인하는 절차다. claude 명령에는 이미 있던 동작을 agents도 따르게 됐다. 낯선 집에서 수리를 시작하기 전에 들어가도 되는지 묻는 것과 같다. 인터넷에서 받아 아직 내용을 살피지 않은 프로젝트에서 특히 쓸모 있다.

잠깐의 401 오류가 장기 로그인 정보를 바꾸지 않는다

화면 없이 도는 headless(헤드리스, 터미널 창 없이 실행하는 방식) 작업은 일시적인 401 오류를 만날 수 있다. 예전에는 이때 오래 쓰는 CLAUDE_CODE_OAUTH_TOKEN이 짧게 사는 로그인 token(인증 토큰, 로그인 신분을 증명하는 통행증)으로 바뀌어 재시작 전까지 작업이 깨졌다. macOS의 MCP OAuth 서버도 키체인 읽기가 시간 초과된 뒤 401을 연달아 냈다. 두 문제 모두 고쳤다. 교통카드 단말기가 잠시 고장 났다고 월 정기권을 한 번짜리 표로 바꾸던 일이 사라진 셈이다。

자동 모드는 거부된 작업을 되풀이하지 않고 다음으로 넘어간다

자동 모드(auto mode, Claude가 작업을 스스로 진행해 확인을 덜 묻는 방식)가 권한을 요청했는데 안전 필터가 이를 거부하면 작업은 계속 막힌다. 다만 이 거부를 연속 차단 횟수에 넣어 같은 작업을 되풀이하지 않게 됐다. 모델은 다음으로 넘어가라는 안내를 받는다. 셀프 계산대에서 쿠폰 한 장이 안 읽혀도 직원이 통과시키지는 않지만, 같은 쿠폰을 끝없이 찍게 하지 않고 장바구니의 나머지를 처리하게 하는 것과 같다.

세션 간 메시지가 알림 없이 멈춰 있지 않는다

화면 없이 도는 headless(헤드리스, 터미널 창 없이 실행하는 방식) 환경이나 Claude Code가 막 시작할 때 세션 간 메시지를 보내면, 예전에는 알림도 만료도 없이 대기열에 머물 수 있었다. 이 문제를 고쳤다. 세션 간 메시지는 서로 다른 Claude 세션에 전하는 말이다. 이제는 우편함 틈에 끼어 말없이 남은 편지처럼 머물지 않고, 전달이나 알림이라는 분명한 결과를 낸다.

Remote Control 재연결 때 오래된 진행 상황이 쌓이지 않는다

Remote Control(원격 제어, 다른 기기에서 Claude 작업을 보거나 이어받는 기능)로 아주 긴 대화를 다시 열면, 압축된 기록 때문에 복구가 깨질 수 있었다. 웹 세션은 멈춘 것으로 잘못 판단돼 재연결할 때마다 오래된 이벤트를 점점 더 많이 다시 보냈다. 두 문제를 고쳤다. 온라인 회의에 다시 들어왔더니 진행자가 앞부분 메모를 잃고 예전 슬라이드를 모두 다시 틀던 상황이 사라진 셈이다.

Remote Control의 사진을 Claude에게 바로 건넨다

Claude 앱에서 Remote Control(원격 제어, 다른 기기에서 Claude 작업을 보거나 이어받는 기능) 세션에 사진을 붙이면 Claude가 이제 별도 도구로 디스크에서 읽지 않고 사진을 직접 받는다. 스크린샷, 영수증, 화이트보드 사진을 보게 할 때 전달 과정이 한 단계 줄어든다. 사진을 창고에 넣고 열쇠로 찾아오게 하는 대신 상대 손에 건네는 것과 같다.

agents는 다른 프로젝트를 훑어도 작업 폴더를 잘못 고르지 않는다

agents 목록에서 다른 프로젝트의 세션에 마우스를 올리면 다음 agent가 그 프로젝트 폴더에서 시작하던 문제가 사라졌다. 또 claude self-hosted-runner가 --base-dir를 만들거나 쓸 수 없으면, 등록한 뒤 매 세션마다 실패하는 대신 시작할 때 분명한 오류를 내고 끝낸다. 배차 센터가 옆 주문을 흘끗 보고 기사를 다른 주소로 보내거나, 차고 문이 안 열린다는 사실을 출발 뒤에야 알리던 일이 없어진 셈이다.

VS Code Focus 보기가 최신 할 일과 답을 숨기지 않는다

VS Code의 Focus view(집중 보기, 대화를 접어 정리하는 화면)에서 Claude의 진행을 따라갈 때 최신 할 일, 답을 기다리는 질문의 맥락, 이미 해결된 답까지 접혀 보이지 않을 수 있었다. 이제 이들은 보이는 채로 남는다. 생각만 담긴 부분만 접히고 “Thought for Ns”라고 보이며, 해당 차례가 끝나면 다시 접힌다. 회의록을 접을 때 행동 목록과 결론은 위에 남기고 초안 메모만 안쪽에 넣는 것과 같다.

SendMessage로 다른 기기의 Remote Control 세션에 바로 보낼 수 있다

다른 기기의 Remote Control 세션에 도움을 청하고 싶다면 SendMessage가 이제 이름으로 대화를 바로 시작한다. 상대가 먼저 메시지를 보낼 때까지 기다릴 필요가 없다. ListAgents는 이를 name [ref]로 보여 준다. 이미 확인한 원격 수신자도 원격 목록을 확인할 수 없다는 이유로 같은 이름의 로컬 세션으로 몰래 바뀌지 않는다. 등기우편에서 주소를 확인하고 동명이인에게 편지를 넘기지 않는 것과 같다.
