Claude Code 2.1.325

Released: 2026-11-13

Release notes

FEATURE

Sandboxed Bash Commands Now Follow the Normal Permission Flow

When Claude Code runs Bash commands inside a sandbox (an isolated security environment for running code), they used to pass automatically, but now they follow the normal permission flow by default.

Moving into a building with upgraded security means even work on your own balcony goes through standard management approval, and skipping that check requires signing a separate consent form.

To keep the previous behavior of running without prompts, add this to your settings file:

{
  "sandbox": {
    "autoAllowBashIfSandboxed": true
  }
}

If your organization enables the sandbox through managed settings, this toggle must be placed in your highest-ranking managed settings source to take effect.

BUGFIX

Sandbox Blocks Writes to Updater Folders, Worktrees, and Added Directories

When commands run inside a sandbox (an isolated security environment), the folders they can access are now more tightly restricted. Previously, sandboxed commands could still write to the native updater's download folder in some cases, and that gap is now fixed. For projects using a worktree (a Git feature that lets you open parallel copies of the same project), the Bash sandbox previously failed to fully protect the settings files inside. The same protection now covers any hooks (small programs triggered by specific events) inside them as well. For a linked worktree, its shared Git folder is now fully protected as well. When you work with added directories, the sandbox now follows the same approach as the launch folder and refuses sandboxed writes to .claude settings, skills, agents, custom commands, and hooks inside them.

FEATURE

Sandbox Helpers and Local Tools No Longer Receive Sign-In Credentials or Passphrases

When Claude Code runs searches in the background or keeps the sandbox running, those internal helpers previously carried your sensitive authentication data in their environment variables.

Picture handing a plumber your entire keyring along with the safe combination just to fix a pipe, instead of giving them only the keycard needed for that visit.

Now, programs that the sandbox starts for its own use, such as its network bridge, no longer have Claude Code's sign-in tokens (authorization credentials) and API keys in their environment. When ripgrep for code search, local Git commands, and the sandbox runtime's helper programs start up, they also no longer put the mTLS client key's passphrase into their environment.

BUGFIX

Fixed Permission Rules Missed After Directory Changes, Case Differences, and Restarts

After you set up deny or ask permission rules, they could unexpectedly fail to apply under several common operations. Relative path rules like Read(./.env) previously stopped protecting the project as soon as cd was run to change directories; this is now fixed, and they also apply in added directories. Deny or ask rules starting with mcp__plugin_*_ previously missed a plugin's MCP (Model Context Protocol, a protocol that connects AI to external tools) server or tool when spelled in a different letter case, and now match regardless of case. In self-hosted runner and claude remote-control sessions, permission approvals arriving after Claude Code restarts previously missed deny rules, and now have them applied. When starting from certain subfolders of a repository, a committed .claude/settings.local.json will no longer be mistaken for your personal settings file.

BUGFIX

Bash Permission Checks Close Compound Command Prompt and Matching Gaps

When guarding terminal commands with permission lists, three types of Bash check gaps previously allowed controls to be bypassed. First, some deny and ask rules did not apply to certain Bash commands, which is now fixed. Second, for compound commands chaining multiple commands together, some could previously run without asking; those compound commands that previously skipped prompts now ask for permission first. Third, a Bash allow rule written to permit only one specific program could end up running a different program under certain conditions, and this matching issue has also been fixed.

FEATURE

Read-Only Git Commands Now Ask First in Untrusted Non-Project Repositories

When you ask Claude to check the code history of another project on your computer, even running a read-only Git command like git status will now prompt for your approval first if that repository does not belong to the current project or a directory you have trusted.

Think of browsing folders in someone else's study: before, promising not to touch anything let you open the drawers right away, whereas now there is a polite check at the door so you cannot enter without saying hello first.

If you regularly need to inspect across directories and want to skip prompting every time, name that folder with the --add-dir flag at startup instead of putting it in the additionalDirectories setting.

FEATURE

Scheduled Tasks, /loop, and Always Allow Rules Tighten Automatic Approval

When setting up scheduled tasks or running jobs repeatedly with /loop, if a skill declares allowed-tools or hooks (small programs triggered by specific events), it will now ask you before running. To let it run unattended, add the corresponding Skill(name) entry to permissions.allow in your settings. Clicking "Always allow" in Desktop, IDE, and SDK hosts has also changed: saving a rule alone is offered only when that rule would actually let the command pass next time.

Like issuing passcards for an unattended night shift on a production line, a casual pass used to carry over automatically, whereas now the line pauses for your sign-off if the permission is not enough to clear it on its own.
BUGFIX

Fixed Artifact Read Permissions and Confirmation Bypasses for Public Content

When working with artifacts (interactive output panels), permission checks previously tended to block where they should be lenient and let things slip where they should be strict. Now, when reading an artifact you created or its data, Claude no longer repeatedly asks you for permission. In cloud sessions, deny and ask permission rules as well as hooks (small programs triggered by specific events) set for the Artifact tool have also been fixed so they are no longer skipped. If an artifact or page is visible to people outside your organization, previously setting an allow rule, approving uploads earlier, or selecting "don't ask again" for Artifact could let some subagents modify it, upload files, or publish pages without confirmation; now all of these external-facing actions ask you first. Under auto mode, approval also covers only that single change instead of judging only the first edit and approving subsequent changes automatically.

FEATURE

Cloud and Self-Hosted Runners Adjust Startup Conditions, Connection Responses, and Symlink Limits

When running tasks on cloud environments and self-hosted runners, this release adjusts several connection and startup boundaries. Self-hosted runner sessions attached to multiple repositories can now use a repository added mid-session. When a session folder or repository path is a symlink (a shortcut file pointing to another location), self-hosted runners will refuse it. An exception is a path checked out by a checkout hook (a small program triggered by specific events). Claude Code on the web, cloud scheduled tasks, and Cowork cloud sessions still start even when sandbox.failIfUnavailable is set, because the hosted container has no command sandbox. Requests for settings, permission rules, hooks, or status over a cloud or self-hosted connection now return less or are refused, while the rules actually applied remain unchanged. Spend limit and shared budget errors in cloud sessions and under Remote Control also no longer display "ask your admin to raise it".

BUGFIX

Fixed Cloud Connector False Failures, Auto-Answered Prompts, and Slack Tips

When connecting external service connectors in cloud sessions, errors previously occurred during loading and URL matching. When a plugin listed an Atlassian, Asana, or Sentry connector at a different URL, Claude would falsely report that it had failed even though it was working, which is now fixed. Approval prompts for connector tools were previously answered automatically while plugins were still loading, and will no longer decide for you ahead of time. If your organization's policy already denies cloud sessions, Slack app recommendation tips will no longer appear either.

FEATURE

Sandboxes and worktrees add Git block notes, special-layout compatibility, and disallowed commands

Running Git inside a sandbox or isolated copy can hit environment limits that stop certain commands.

A crew working on a borrowed soundstage gets a clear list of which gear they can touch and which lights stay off-limits, so they are never left staring at a locked cabinet.

When a sandboxed git checkout, git stash, or autostash pull cannot update protected files such as those in .claude, Claude now receives a note. In a bare repository's worktree (a Git feature for opening multiple parallel copies of a project), a --separate-git-dir checkout, or an Android repo checkout, /security-review and inline Git commands in skills no longer stop with an error. Isolated worktree sessions or agents now refuse git bisect run, git maintenance register|start, and scalar setup commands, and report which commands still work.

BUGFIX

Fix worktree creation hooks, missing sparse-clone files, and container trust rules

This release fixes several environment edge cases around creating and mounting isolated copies. On the first --worktree run in a new home directory, a WorktreeCreate hook (a small program triggered by specific events) from a plugin in CLAUDE_CODE_PLUGIN_SEED_DIR is no longer skipped. On older Git versions such as 2.34, using worktree.sparsePaths as well as sparse plugin and marketplace clones no longer leaves out repository root files. If a WorktreeCreate hook path goes through a symlink (a shortcut file pointing to another location) inside the project, EnterWorktree refuses it, so have the hook print the real path. When running -p and the SDK in a worktree (a Git feature for opening multiple parallel copies of a project) or submodule mounted into a container, allow rules in .claude/settings.local.json apply only after the folder is trusted.

FEATURE

Plugin marketplaces add security warnings, full commit pins, and proxy tunneling

Security prompts and connection rules have been updated for installing extensions from plugin marketplaces. Add-marketplace confirmations, plugin recommendation prompts, and plugin install warnings now clearly state that plugins can run code on your computer with access to your files and shell. When accessing a private marketplace hits HTTPS authentication failed, the message now notes that Git's terminal prompts and askpass programs are disabled, and it also appears with newer Git versions. A marketplace's ref field now accepts the full ID of any commit on a branch or tag, though older clients cannot clone such a pin and will fail to load it. When ALL_PROXY is the only proxy set, marketplace and plugin downloads now use a CONNECT tunnel, so a proxy that refuses that tunnel fails them.

FEATURE

Plugins unpack under plugins directory, skip unsafe paths, and enforce organization locks

Managed settings' strictPluginOnlyCustomization lock on agents and skills now takes effect in sessions that are already running. Plugins from a managed remote marketplace enabled in prependPlugins or appendPlugins count as the organization's plugins, while pluginDigests is deprecated and ignored. Plugin MCP (Model Context Protocol, a protocol that lets AI connect to external tools) bundles .mcpb and .dxt now unpack under the plugins directory, allowing read-only plugin folders to load. They no longer write to .mcpb-cache (a temporary cache directory), and bundles fetched by URL download again once. Plugin loading now skips unsafe paths and links, and claude plugin validate reports them. .claude/skills folders in --plugin-dir plugins no longer load from a session started above them; start in the plugin folder instead.

BUGFIX

Fix MCP server reconnection, auth refresh, and connection state after folder moves

MCP (Model Context Protocol, a protocol that lets AI connect to external tools) servers used to get stuck in the wrong state when switching or reconnecting. After moving a folder or starting from a pre-warmed session, Claude Desktop and SDK sessions no longer mislabel or omit local .mcp.json servers or fail to connect WebSocket ones. /mcp also no longer keeps listing a plugin's server after a plugin reload removes it while connecting. After a token (authorization credential) refresh is briefly refused, a server no longer stays stuck on "needs authentication". Its mcp_tool hooks (small programs triggered by specific events) are no longer skipped either. In headless mode (running without a terminal window or visual interface), prompts during a connection replacement are no longer cancelled without asking, and SDK tool calls no longer answer "Not connected" after reconnecting.

FEATURE

Background MCP task questions wait for your draft, and Esc means answer later

Interaction is smoother when a background MCP (Model Context Protocol, a protocol that lets AI connect to external tools) task needs your decision. If you are typing a message, the task's question no longer opens over your draft and instead waits until you send or clear it, while the spinner and turn timer keep running. Pressing Esc on the question prompt now means "answer later", sending nothing to the server and keeping the question in /tasks. Tasks no longer get stuck after closing a question with Esc or asking it again; the footer now notes that your input is needed, and pressing Enter in /tasks shows the question again. Background tasks also resume updating when another call to the same server loses the connection and a later call reconnects. When a task is waiting for your answer, Claude is now notified and can point you to /tasks.

BUGFIX

Fix /login and desktop sign-in cancellation overwrites and false success pages

When sign-in is interrupted or blocked, updated state handling and prompts give clear feedback at every step.

At a hotel check-in desk, canceling a new registration no longer demagnetizes your existing room key, a failed check-in no longer flashes a green welcome light, privacy changes ask you first, and any block points straight to the card causing trouble.

In /login, choosing "Sign in with your Console account" and pressing Esc right after the browser step no longer replaces your existing login. When sign-in fails or is canceled, the browser also no longer displays a misleading sign-in success page. If running /login will change your privacy settings, it now asks for your permission first. When claude --desktop fails to sign in with a Claude account, the error message now names the specific API key, provider, or setting blocking it.

FEATURE

Clean up auth lock files and speed up keyless Console startup

Authentication lock files used to pile up or slow down startup. Leftover .oauth_refresh.lock.owner.tmp.* temporary files no longer accumulate in the config directory, and short commands such as claude auth status no longer leave a lock behind on a Console profile that makes the next session hang for about a minute. When starting with a keyless Console sign-in or another Anthropic profile login, a token (authorization credential) that is still valid is read directly without waiting for the credentials lock. If you run claude -p in a clean environment with no cached account data, it now waits to fetch that data before sending its first request, so a first run can start a few seconds later.

FEATURE

Background sessions stop billing shell API keys and refuse cross-account moves

Billing and account boundaries are now enforced more strictly when moving tasks to the background.

Separate tabs at a group dinner keep everyone's charges apart, so you never accidentally swipe the host's card at the next table, cannot force a bill onto another party, and will not cancel food already on the stove just by ringing the exit bell twice.

Background sessions started on your claude.ai login no longer accidentally use and bill an API key or token (authorization credential) from the shell that started the background service. Moves of a session to another sign-in in the background are now refused with a message explaining what works instead. If a move to the background was refused, pressing a second Enter in the exit dialog no longer stops background work. When a background session cannot use its own API key or token, the shown messages no longer suggest adding the key to settings.

BUGFIX

Fix false organization restrictions, Bedrock permissions, and cloud credential compatibility

Several false errors and missed checks around organization permissions and cloud credentials are now fixed. Under keyless Console sign-in, /fast no longer claims fast mode is disabled by your organization without asking the server, and /model no longer reports an organization restriction when network issues prevent checking. When the allowedProviders setting does not allow Amazon Bedrock, counting tokens (text units AI uses for processing and billing) no longer sends the conversation to Bedrock. AWS credential_process helpers and Google Cloud default credentials also work properly when started without a HOME environment variable. Once Claude Desktop includes this version, third-party deployments will no longer stay stuck on "Stopping" during a token renewal.

FEATURE

Subagents Keep Their Own Models, Permission Isolation, and Output-Limit Retries

When you dispatch subagents to work in parallel, the main session's model and permissions used to get mixed together with theirs.

When a kitchen sends prep cooks to work in parallel, each brings their own recipe and pots, measures portions with their own bowl, and if a report runs too long and gets cut off, they are asked to summarize and resubmit the whole thing.

Now, even when the global model is set to opusplan or haiku, subagents with their own dedicated model are no longer switched to the plan-mode model, and subagents on a different model now size file reads and MCP (Model Context Protocol, a protocol for connecting AI to external tools) results using their own model. After a subagent's plan is approved, the main session no longer reverts unexpectedly to an earlier permission mode. allowed-tools grants from a slash command also no longer leak to background agents woken during or after its turn. If a subagent is cut off mid-response at the output token (a unit of text AI processes and bills by) limit, it is now asked to provide the whole answer again more briefly instead of returning only the second half.

BUGFIX

Third-Party Gateways and Custom Model IDs Compact Properly and Apply Context Limits

When connecting to models through a third-party gateway or Foundry, context lengths and model IDs used to run into compatibility issues. Previously, many sessions that filled up with conversation would not auto-compact and instead stopped with a context length error on every turn; this is now fixed. A saved sonnet[1m] model setting on a new install is also no longer rewritten to a model ID the API rejects. The CLAUDE_CODE_MAX_CONTEXT_TOKENS environment variable can now also set the full context window token (a unit of text AI processes and bills by) limit for unrecognized model IDs starting with claude-, such as a gateway's claude-sonnet-latest.

BUGFIX

Code Mode Fixes Worktree Paths, Approval Notes, and Resume Waiting

When running scripts in Code Mode, wrong paths, dropped messages, or premature execution used to happen easily. Scripts now properly stay inside the worktree (a Git feature for opening multiple parallel copies of the same project) you entered with EnterWorktree, instead of writing paths starting with ~ into the project. When encountering an MCP (Model Context Protocol, a protocol for connecting AI to external tools) server whose sign-in has expired, the /mcp screen also no longer keeps showing it as connected. Extra notes typed when selecting "Yes" at a permission dialog or plan approval now reliably reach Claude, and when you resume a session that ended mid-way through a Code Mode script, it waits for your next prompt instead of starting work on its own.

BUGFIX

Fill Missing Mid-Turn and Merged-Queue OpenTelemetry user_prompt Events

If you have OpenTelemetry enabled to collect telemetry logs, two message-sending scenarios previously missed recording prompt text. When you sent a message mid-turn while Claude was running tool calls, the user_prompt event used to be missing; it is now included with delivery.mode: "mid_turn" and the running turn's prompt.id. In VS Code, when multiple queued messages merged into one turn, or when one message included an image, the user_prompt event previously left out the earlier messages' text; it now records them in full.

BUGFIX

Fix Terminal Focus View, Scroll Overlaps, and Narrow-Screen Layout Glitches

Several terminal display and scroll-alignment issues are cleaned up in this release. In focus view, a scheduled task's subsequent reply no longer hides the answer you just received. When fullscreen is off, a background subagent's view no longer drops your original prompt. Long options in lists and permission prompts are no longer partly overwritten when they wrap, and first-run screens on narrow terminals no longer lose lines. Startup warnings about permission rules and the "N MCP servers need authentication" notice (Model Context Protocol, a protocol for connecting AI to external tools) are also no longer recorded as seen when scrolled out of view. If an agent's name or the working folder contains control characters or a line break, the welcome header no longer prints raw control characters or splits across two lines.

BUGFIX

Terminal and IDE Add Guidance Prompts and Fix Quick Launch Shortcut Display

On-screen reminders when hitting a snag or opening your environment are now more concrete and clear. Once Claude has read or edited a Jupyter notebook, the spinner tip in VS Code and similar integrated terminals now reminds you to re-run the notebook cell. If a request is blocked by your organization's policy, a line of next-step advice now appears below the error telling you to run /rewind to change the message or /clear to continue. When Claude tries to run a command that only you can run and triggers a red error, a dim line below it now explains that the command only runs when you type it at the prompt. On Windows and Linux, the IDE welcome dialog no longer mistakenly shows the Mac-only Cmd+Esc shortcut for Quick Launch.

BUGFIX

Fix claude purge, Empty Plugin Eval Output Path, and -p Terminal Output

Running several standalone CLI commands directly in the terminal used to hang or write to the wrong place when there was no interactive interface or when given special arguments. Running claude purge without a terminal to read keys from no longer hangs silently, and its project picker and -i prompts no longer ignore the keyboard when stdin (standard input, the data stream fed into a program from a pipe or file) is piped. Running claude plugin eval --output-dir '' with an empty path no longer writes the report into the current folder and instead exits with an error. Plain text output from claude -p on a terminal also no longer includes control sequences other than text styling, while pipes and file output remain unchanged.

BUGFIX

Fix /stats Day Count, Empty /insights Reports, and Feedback Upload Scope

When viewing usage stats or reporting issues, counts and data scopes across several slash commands have been corrected. The Active days total shown by /stats used to be one day too high, and that offset is now fixed. When using /insights, if no session qualifies for analysis, it no longer falsely reports that a report is ready, and two fields in the generated HTML report that were previously written without escaping are now fixed as well. When sending feedback via /feedback and /bug, before uploading other session logs alongside it, it now verifies that they were recorded by the currently signed-in account or organization.

FEATURE

/voice Shows What Locks Voice Mode and Guides Microphone Switching

When voice mode (/voice) does not respond or refuses to toggle, it now tells you directly where it is stuck.

Imagine trying to switch audio before a video call and seeing on screen whether the main switchboard locked the toggle or which menu lets you pick a different microphone, instead of blindly clicking every button.

Previously, even when managed settings, --settings, or the project's .claude/settings.json or .claude/settings.local.json kept voice mode locked, /voice still falsely reported that it had changed; it now states clearly which setting holds it. On macOS and Windows, when the "No audio detected" message appears, it now also specifies where to pick your microphone.

BUGFIX

Invalid Teammate Mode Values Trigger Warnings and New Sub-Sessions Start in Original Folder

Configuring multi-agent collaboration and the starting point for new views is handled more clearly in this release.

Suppose a team dispatches members to help out: everyone meets at the project site gate to start together, rather than starting from the convenience store the previous colleague detoured to.

If teammateMode in settings has an unrecognized value, it used to be silently ignored; now claude -p, the startup warning, and claude doctor all list it as a skipped entry (still not applied). Opening tmux and iTerm2 teammates, or starting a new session from the agents view with ←, also no longer starts in the directory where the shell last ran cd, and instead starts in the original session's folder.

BUGFIX

Plans fall back to the default folder when unwritable, keeping important files out of the scratchpad

This release lowers the risk of losing hard-won plans or generated files because they were saved to the wrong place.

Just as a bakery wraps fresh loaves in a standard paper bag with an explanatory note when the requested gift box is too small, it also reminds apprentices not to leave a customer's finished item on a sample tray that will soon be dumped out.

When an approved plan edit cannot be written to your custom plansDirectory folder, it is no longer lost; instead, it is saved back to the default plans folder with a warning explaining where it went and why. Claude's built-in instructions have also been updated so it avoids placing files you will still need later inside a temporary scratchpad (a draft folder that can be cleared).

BUGFIX

Windows fixes PATH permission stalls and /resume drive-letter case issues

Three path and permission issues that affected starting up or continuing older conversations on Windows have been fixed. If an entry in the PATH environment variable sits under a folder your account cannot open, startup could previously stall for about a second, which no longer happens. When using /resume to restore a session whose recorded drive-letter case or slash direction differed from the current one, it previously refused to open or hid the session, and that is now fixed. Running /resume inside a session also no longer drops a project's saved trust state when the recorded drive-letter case differs.

BUGFIX

Linux fixes sandboxed Bash file creation failures under symlinked home directories

On Linux, you might place your working directory under allowRead (folders permitted for reading). If that folder sits inside denyRead (paths blocked from reading), sandboxed Bash commands previously failed with a bwrap: Can't create file error. For example, you could run into this under a home directory using a symlink (a shortcut file pointing to another location). This error is now fixed.

FEATURE

Remote Control disconnects before /resume or /teleport on shared sessions

When you use Remote Control to watch a session that has a share link and type /resume or /teleport to switch conversations, the flow now includes an extra safeguard.

Switching a live TV broadcast to another external feed used to risk crossing signals if cut directly, so the old public signal is now dropped first and reconnected only when needed.

Both commands now disconnect the remote session first whenever the connected session has a share link or its share-link status cannot be checked; to regain control, simply run /remote-control again.

FEATURE

claude remote-control returns exit codes 4 and 69 by stop reason for restarts

When claude remote-control is run under a background service manager on a server, its stop reasons are now clearly distinguished.

Rather than flashing the same red warning light for every appliance panel fault, where a technician could not tell a power trip from a loose part, distinct codes now light up so an automated maintenance unit knows right away when to reboot.

It exits with status code 4 when it stops on its own and 69 when it fails to register, allowing the service manager to restart it accordingly, while single-session runs still exit with 0.

FEATURE

Account email check extends to scripts, file writes, web fetches, and MCP calls

If a person or tool tries to send your login email as an external identifier mid-task, only some channels blocked it before.

Before a mountaineering team sets off, checking packs, water bottles, and contact sheets catches any personal ID card accidentally slipped inside and pulls it out on the spot so private data does not head up the mountain with the group.

Now, whether in scripts run by a command, file writes, web fetch requests, or calls made through MCP (Model Context Protocol, a protocol that connects AI to external tools), any attempt to use your email as a client identity is refused.

FEATURE

Terminal slows prompt suggestion refreshes after 8 consecutive background or scheduled turns

When you step away from your desk and let the program run several rounds on its own in the background, nobody is watching the screen, yet it used to keep preparing what you should type next.

An empty showroom automatically dims its lights after sitting idle for a while to save wasted electricity, then snaps back to full brightness the moment you push the door open and step inside.

Now, whenever 8 turns in a row are started by background or scheduled tasks, prompt suggestions in the terminal refresh less often to save usage until you press any key or return to the terminal.

FEATURE

/cost and budget caps include mod complete and classify call billing

When your workflow includes a custom mod (an add-on module) and you want to control spending with /cost or --max-budget-usd, past totals left out the module's calls.

Much as a main utility meter used to leave out the water used by an automatic yard sprinkler, connecting that branch pipe back to the main meter for billing ensures the monthly bill and limit alerts finally add up.

Now, cost and token (the text unit AI processes and bills by) metrics include $.model.complete and $.model.classify calls made by a mod. /cost, $.session.usage(), and the --max-budget-usd cap all count them together.

FEATURE

Bundled dataviz skill improves static chart and ordered part-to-whole advice

When turning survey numbers into an easy-to-read proportion chart for a presentation, exports are sometimes non-interactive and groups sometimes have an inherent order, so past chart-picking guidance often missed the mark.

Picking a display rack for a customer used to mean putting everything on a round platter regardless of whether items followed a size sequence, whereas ordered items are now arranged from smallest to largest in a clear stepped display.

This update improves chart recommendations in the bundled dataviz skill (the built-in data visualization skill) for static image scenarios, and strengthens how it handles items with a natural order such as age bands.

BUGFIX

When connected to the network, if the program receives a response compressed with zstd (a compression technology used to shrink data size), it must decode the data back into a usable form. A security issue in this decoding process has now been fixed.

BUGFIX

Fix resumed sessions occasionally losing recent turns after an unexpected exit

If Claude Code stopped without a clean exit because of a crash or force-quit, resuming that session later could occasionally leave the last few turns missing. This is now fixed, so resuming a session after an unclean exit no longer drops recent conversation turns.

BUGFIX

Prevent shell commands from falling back to the launch directory when the working directory is deleted

If you delete the original project folder mid-conversation, subsequent terminal commands used to quietly keep running in a different location. When developers called applyFlagSettings() through the Agent SDK to configure flags, including even a single invalid value used to silently wipe out all settings saved by earlier calls. Now, any call that would cause this is refused with an error instead of overwriting the existing settings.

BUGFIX

When the requested code changes have already been submitted and only need your own approval, the list used to still show that it was waiting for you to type, making you think another instruction was needed. Fix brief-mode sessions like Dispatch sending duplicate replies

When going back and forth with AI in the compact interface, the screen would sometimes inexplicably pop up an identical block of text even after the answer was already shown. This release fixes the issue where brief-mode sessions such as Dispatch sent the same reply again in the same turn.

BUGFIX

Fix /teleport picking the wrong stash in unusual Git states and stop with instructions

When running /teleport to move a session to another environment, if the repository happened to be in certain unusual Git states, the way it chose a stash used to go wrong. Now, when this happens, it stops first and clearly tells you what to do next.

Update untrusted folder, OS block, and marketplace prompts in VS Code

The VS Code extension updated several messages for settings failures and security blocks to better match actual usage. When organization settings fail to load, the message no longer tells you to run a command again, and instead says "try again" to match the tab's Retry link. When opening an untrusted folder, the note now explains why the extension is off and how to turn it back on; when the operating system refuses to run Claude Code, the error message also notes that your IT team can add the blocked program to the allowlist. The marketplace confirmation button in the install link has also been changed to "Trust marketplace and continue".

FEATURE

Web cloud sessions raise MCP tool search description limit to 16,384 characters

When starting a new remote task in your browser and looking up how an external tool works, overly long manuals used to get cut off halfway (truncated past 4,096 characters).

Previously, mailing an equipment manual to a remote assistant meant capping it at four pages and cutting off key instructions, whereas raising the page limit now lets you hand over the entire handbook at once.

Now the limit for MCP (Model Context Protocol, a standard that lets AI connect to external tools) descriptions loaded through tool search in web cloud sessions has been raised to 16,384 characters, matching Claude Code sessions in other environments.

BUGFIX

Claude Tag fixes missing cards for Slack links when sign-in expires

When you paste an artifact link into a Slack workspace not managed by your organization and the poster's Claude sign-in happens to be expired, no preview card used to appear in the conversation.

Even when a recommended reading list on a magazine's back cover expires, a bookstore still places a plain white title card on the shelf so browsers know the book exists.

This Claude Tag display issue has been fixed, and a plain card now appears in the same situation.
