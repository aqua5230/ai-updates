Claude Code 2.1.325

Released: 2026-11-13

Release notes

FEATURE

Sandboxed Bash now follows normal permissions by default

Running Bash commands directly inside a sandbox (an isolated execution environment) no longer bypasses prompts automatically and now follows your normal permission rules. To keep running them without prompts, add this configuration to your settings file.

{"sandbox": {"autoAllowBashIfSandboxed": true}}

If you enable the sandbox through administrator-managed settings, you must also add the same setting in your highest-ranking managed source. That way, commands will continue running without prompts.

Like entering a library's private reading room, borrowing used to skip sign-out upon entry, whereas normal borrowing rules now decide whether you need to sign; to keep skipping sign-out, you must enable that permission separately.
FEATURE

Sandbox strengthens protection for added directories and updater folder

Write restrictions for commands running inside the sandbox are now stricter. In addition to the launch folder, .claude settings, skills, agents, commands, and hooks (small programs triggered by specific events) in directories you add are now all blocked from being modified by the sandbox. When a sandboxed git checkout, git stash, or pull with autostash cannot update protected files such as those in .claude, Claude now receives a note explaining why. In some cases, sandboxed commands could previously write to the native updater's download folder, and this bug has now been fixed. The Bash sandbox previously failed to fully protect the settings and hooks of a worktree (a Git feature for opening multiple parallel copies of the same project). Along with the shared .git folder of a linked worktree, both protection gaps have now been closed.

FEATURE

Sandbox and built-in utilities no longer carry account keys

Programs that the sandbox starts for its own operation, such as its network bridge, no longer have Claude Code's sign-in tokens (authorization credentials) and API keys in their execution environment. The file search tool ripgrep, local Git commands, and the sandbox runtime's helper programs also no longer launch with the mTLS client key's passphrase for mutual authentication certificates.

Picture dropping off photos at a print shop: you used to leave the whole album and film canister with the clerk, whereas now you only send over the specific files to print.
BUGFIX

Fix Linux sandbox file creation failure under allowed-read folders

On Linux, the working directory may sit under an allowRead folder inside a denyRead restriction. Previously, running sandboxed Bash commands in this situation would fail with a bwrap: Can't create file error message. For example, accessing your home directory through a symlink (a shortcut file pointing to another location) could trigger this directory layout. This issue is now fixed.

FEATURE

Read-only Git in untrusted external repositories now asks first

When Claude tries to run read-only Git commands in a Git repository outside the current project that you have not trusted yet, it now prompts for confirmation before running. To run these cross-repository read-only queries without confirming every time, you must explicitly pass the path with --add-dir at startup. Listing it only in the additionalDirectories setting does not skip the prompt automatically.

Think of sampling testers at an airport duty-free shop: before, you could spray freely as long as you didn't take anything, whereas now a clerk asks before you step into an unregistered counter unless you already claimed a sample pass.
FEATURE

Stricter permission checks for scheduled tasks and permanent allows

Before running scheduled tasks or the /loop command, Claude now pauses to ask you if a skill declares allowed-tools or hooks. To let such skills run unattended, add the corresponding Skill(name) entry to the allow list in your settings file.

{"permissions": {"allow": ["Skill(name)"]}}

In Desktop, IDE, and SDK hosts, the "Always allow" option has also tightened when it appears. The UI now offers this option only when saving that single rule will actually allow the command again next time, so scheduled tasks that previously relied on such rules may now pause for your confirmation.

A gym's auto-renewal desk used to charge and activate your pass whenever a record was on file, but now it pauses if contract terms changed or signatures are missing until you confirm in person.
BUGFIX

Fix missed Bash permission rules and wrong program execution

Fixed an issue where previously configured Bash deny and ask rules failed to apply to certain commands. Some compound Bash commands used to bypass permission checks and run directly, and these commands now show a confirmation prompt first. Also closed a gap where a Bash allow rule could actually execute a different program than the one named in the rule.

BUGFIX

Fix missed permission rules after changing directories or restarting

Relative deny and ask permission rules such as Read(./.env) previously stopped covering the original project after running cd to switch directories. This issue is fixed, and these rules now also apply in added directories. Rules starting with mcp__plugin_*_ match a plugin's MCP (Model Context Protocol, a protocol that lets AI connect to external tools) server or tool. Previously, differing letter case in the name would cause a miss, and this issue is now fixed. In self-hosted runners and claude remote-control sessions, a permission approval can sometimes arrive after Claude Code restarts. Previously, existing deny rules were not applied in that situation, and this gap is now fixed.

BUGFIX

Strict trust verification for project-local permission settings

Fixed a bug where a committed .claude/settings.local.json file in a repository was mistakenly treated as a personal settings file. Previously, when starting Claude Code from certain subfolders of a repository, this version-controlled file could be applied as the user's own settings. Permission checks are now stricter when running tasks via the -p flag or the SDK inside a worktree or submodule mounted into a container. The folder must now be trusted first before allow rules in .claude/settings.local.json take effect.

An access badge brought by a contractor used to grant access to certain floors right away, but now the owner must first confirm they trust the badge before access actually opens.
BUGFIX

Fix slash command tool grants leaking to background agents

When a slash command temporarily allows specific tools through allowed-tools, those temporary permissions previously carried over to agents woken during or after that turn. This issue is now fixed, and background agents no longer inherit that extra grant.

BUGFIX

Fix permission mode reverting after approving a subagent's plan

When you approve a subagent to carry out its planned steps, the current session could occasionally revert to an earlier setting. That issue is now fixed, so the session keeps the permission mode it should have.

BUGFIX

Adjust Artifact permission prompts and external content safeguards

Claude no longer asks for permission before reading an Artifact you created or the data inside it. Fixed an issue where deny and ask permission rules and hooks configured for the Artifact tool occasionally failed to apply in cloud sessions. Permission checks are now stricter for Artifacts visible to people outside your organization. Even if an allow rule is set or uploads were approved earlier, a subagent must ask you first before modifying such an external Artifact or uploading files to it. Even if you selected "don't ask again" for Artifact, publishing an external page will not skip confirmation. In auto mode, only the first change to an external Artifact used to be reviewed; now each approval covers only that single change, and subsequent edits are evaluated again.

BUGFIX

Fix security issue when decoding zstd-compressed responses

Claude Code previously had a security issue when decoding zstd-compressed responses. That vulnerability is now fixed, and updating to this version removes the risk.

FEATURE

Block select Git commands and symlink hooks in isolated worktrees

Several Git commands are now blocked inside an isolated worktree session or agent. This includes git bisect run, git maintenance register|start, and scalar's setup commands, and when blocked, the output tells you which commands still work. When calling EnterWorktree, if the path provided by a WorktreeCreate hook passes through a symlink inside the project, it is rejected. Have the hook print the real path instead.

When you sublet a studio, the landlord only lets you use your assigned workbench—tools on the banned list and shortcut detours are off-limits.
BUGFIX

Fix issues across Git checkouts and sparse clones

If you work in bare-repository worktrees, --separate-git-dir checkouts, or Android repo checkouts, you might have run into errors before. /security-review and inline Git commands in skills used to stop with an error, and that issue is now fixed. On the first run with --worktree in a new home directory, Claude Code previously skipped hooks in CLAUDE_CODE_PLUGIN_SEED_DIR. Now WorktreeCreate hooks from plugins trigger normally on that first run. On older Git versions such as 2.34, setting worktree.sparsePaths previously left out files in the repository root. The same issue affected sparse clones for plugins and marketplaces, and both are now fixed.

BUGFIX

Fix /teleport stash handling in unusual Git states

Running /teleport in certain unusual Git states previously made the wrong choice when handling stashed changes. That issue is now fixed, so it stops and tells you what to do next.

FEATURE

Warn clearly about code execution in plugin marketplace and install prompts

About to install a promising plugin? Across the add-marketplace confirmation screen, plugin recommendation prompts, and the plugin install warning, the text now explicitly states that plugins can run code on your computer and access your files and shell.

Downloading a browser extension used to mean just clicking OK, but now the store shows the permission list upfront so you can see what data it can access before deciding whether to install it.
FEATURE

Support specific commit pinning and proxy downloads for plugin marketplaces

When a private plugin marketplace shows an HTTPS authentication failed error, it now explains that Git's terminal prompts and askpass programs are disabled. Newer versions of Git now display this message properly as well. The marketplace ref field now accepts the full commit ID of any commit on a branch or tag; however, older clients before this version cannot clone this kind of pin, so a marketplace pinned this way fails to load there. When ALL_PROXY is the only proxy configured in the environment, plugin marketplace and plugin downloads now use a CONNECT tunnel; if the proxy server refuses CONNECT connections, the download fails.

FEATURE

Adjust plugin bundle unpacking and safe loading rules

Plugin .mcpb and .dxt MCP bundles no longer unpack into .mcpb-cache inside the plugin's own folder, and are placed under the plugins directory instead so read-only plugin folders can still load. Bundles fetched by URL will download again once after updating. When loading a plugin, certain unsafe paths and links inside its folder are automatically skipped, and running claude plugin validate reports them as well. For plugins loaded with --plugin-dir, nested .claude/skills folders inside them no longer load from sessions started in a parent directory. To use those skills, start Claude Code directly inside the plugin folder.

BUGFIX

Fix claude plugin eval error on empty output path

Running claude plugin eval --output-dir '' with an empty output path previously wrote the report directly into the current working folder by mistake. That issue is now fixed, and an empty path argument now exits with an error.

BUGFIX

Updates to managed remote plugins and customization locks

Plugins from a remote marketplace declared and enabled in managed settings, when listed under prependPlugins or appendPlugins, are now treated as the organization's own plugins. The pluginDigests setting is deprecated and ignored even if configured. The strictPluginOnlyCustomization rule, which organizations use to restrict agents and skills to plugins only, previously did not take effect immediately in sessions that were already running. This is now fixed, so sessions already in progress are subject to the same lock.

A company updates its badge whitelist and rules so approved contractor tools are recognized, while employees who have already badged in and are working at their desks immediately fall under the new policy as well.
FEATURE

Improved part-to-whole advice in the bundled dataviz skill

When creating static charts or presenting grouped data with a natural order such as age bands, the bundled dataviz skill now gives more fitting advice on showing part-to-whole proportions.

BUGFIX

Fixes for stale MCP server lists and reconnection auth issues

In Claude Desktop or SDK sessions, connection lists could break whenever a folder moved or started pre-warmed. A folder's own .mcp.json and local MCP servers were previously mislabeled or omitted, and WebSocket servers failed to connect; these issues are now fixed. When a plugin reloads and removes an MCP server while it is connecting, the /mcp list previously kept the old entry and now clears it. If a token refresh was briefly refused, an MCP server previously stayed stuck in "needs authentication" and skipped mcp_tool hooks; this is now fixed. During a tool call in headless mode (execution without a terminal window), MCP elicitation requests were previously cancelled without asking if the connection was replaced; this issue is now fixed. MCP tool calls from an SDK host previously sometimes returned "Not connected" even after a prior call had reconnected; this is now fixed.

FEATURE

Improved deferring background MCP task prompts and /tasks flow

Pressing Esc on a question from a background MCP task now sets it to "answer later", sending nothing to the server and keeping the question waiting in /tasks. Claude is also notified when a task is waiting for your reply and can point you to /tasks. If you are in the middle of typing a message, a background MCP task's question no longer opens over your input box; it waits until you send or clear the draft, while the spinner and turn timer keep running. Closing a question with Esc or asking it again previously left an MCP task stuck; the footer now indicates that your input is needed, and pressing Enter in /tasks brings the question back up. Background MCP tasks previously stopped updating progress when another call to the same server lost its connection and a later call reconnected; this issue is also fixed.

After checking in at a clinic and stepping aside to fill out paperwork, the queue screen used to cover the form in your hands, whereas now it waits until you finish writing before calling you and keeps your number.
BUGFIX

Updated /login privacy prompt and fixed sign-in failure states

When signing in via /login, you are now asked for permission before your privacy settings are changed. Choosing "Sign in with your Console account" in /login and pressing Esc right after the browser step previously overwrote your existing sign-in state. The issue where the browser occasionally showed the sign-in success page when sign-in failed or was canceled is also fixed. When signing in to a Claude account with claude --desktop is blocked, the error message now names the specific API key, provider, or setting preventing sign-in.

FEATURE

Faster Console sign-in startup and lock file cleanup

When launching with a keyless Console account or another Anthropic profile, a token that has not expired is now read directly without waiting for the credentials lock. Running short commands like claude auth status previously left a lock behind on a Console profile, causing the next session to hang for about a minute; this is now fixed. Temporary .oauth_refresh.lock.owner.tmp.* lock files that previously piled up in the config directory are no longer left behind.

BUGFIX

Fixed cloud credential loading without a HOME variable

AWS credential_process helpers and Google Cloud default credentials previously failed when starting without a HOME environment variable set. This issue is now fixed.

FEATURE

claude -p waits for account data when uncached

When running single-prompt mode in a clean environment with no saved login record, it now waits for user data to finish loading before sending the first request. This means an initial claude -p run without an account cache can start a few seconds later than before.

BUGFIX

Fixed false organization restrictions in /fast and /model

Under keyless Console sign-in, Claude Code had not actually checked with the server yet, yet /fast previously reported "Fast mode has been disabled by your organization". When unable to verify over the network, such as when offline, /model also previously claimed that your organization restricted a model. Both issues of falsely reporting restrictions without checking are now fixed.

FEATURE

Account email check covers scripts and network calls

Scripts run by commands, file writes, web fetches, and MCP calls are now also covered by the account email check, preventing your email from being sent as a client identity.

BUGFIX

Fix /feedback and /bug uploading other accounts' sessions

When using /feedback or /bug to report an issue with other session records attached, content from other accounts could previously be included. This issue is fixed, and now only sessions recorded by the currently signed-in account or the same organization are uploaded.

FEATURE

Isolate background session billing and block account switches

Background sessions started with a claude.ai account previously could mistakenly use and bill an API key or token from the shell that started the background service, and this issue is fixed. While a session is running in the background, more cases that could switch to another signed-in account are now refused, and the screen tells you what works instead. If you press Enter again in the exit dialog after a background move is refused, it also no longer stops background work by mistake. When a background session cannot use its own API key or token, the prompt message no longer misleads you into writing the key into the config file.

Imagine a night-shift colleague taking over a project and accidentally charging the credit card left by the earlier shift—now the two accounts are clearly separated so charges never mix.
FEATURE

claude remote-control exit codes and disconnect

The remote control tool claude remote-control has adjusted its exit codes so a service manager can automatically restart it for you. It returns status code 4 when stopping on its own, still returns 0 for a single session, and returns 69 when it fails to register. While connected via Remote Control, if the currently connected session has a share link or whether it has one cannot be confirmed, running /resume or /teleport disconnects first. To reconnect after switching, just run /remote-control again.

Just as a remote control pairing with a host disconnects first if the lock changed or its status is unclear, a failed restart also sends a clear signal so the caretaker can reboot it automatically.
FEATURE

Cloud and remote budget errors drop admin raise prompt

If you hit spend limit or shared budget errors in web or remote sessions, the error message shown on screen is now shorter. The previous prompt line telling you to contact an admin to raise the limit, "ask your admin to raise it", has been removed from cloud and Remote Control environments.

BUGFIX

Adjust cloud sandbox limits and fix connector errors

Hosted containers have no command sandbox, yet this no longer blocks Claude Code on the web, cloud scheduled tasks, or Cowork cloud sessions. Even when sandbox.failIfUnavailable is set, these cloud environments now start up smoothly. In cloud sessions, when a plugin listed a working Atlassian, Asana, or Sentry connector under a different URL, Claude previously reported a connection failure by mistake. Approval prompts for connector tools were also answered automatically while plugins were still loading, and both issues are now fixed.

FEATURE

Self-hosted runners tighten path checks and remote query limits

Querying settings, permission rules, hooks, or status over a cloud or self-hosted session connection now returns less information or is refused outright, though the rules actually applied inside the session remain unchanged. Self-hosted runners now refuse tasks whose session folder or repository path is a symbolic link, except for checkout paths created by a checkout hook. If a self-hosted runner session had multiple repositories attached, a new repository added mid-session was previously unusable, and this issue is now fixed.

BUGFIX

Fix subagent model switching and truncated reply handling

In environments where the model is set to opusplan or haiku, subagents with their own specified model were previously switched to the plan-mode model, and this issue is now fixed. Subagents using a different model also previously sized file reads and MCP results using the main session's model by mistake, and that issue is resolved as well. When a subagent's reply is cut off at the output token (a unit of text processed by AI) limit, it no longer returns just the trailing fragment, and instead is asked to provide a shorter complete answer again.

Suppose an assistant runs over time during a presentation and gets buzzed off the stage: before, only the last three pages of notes were handed over, whereas now they are asked to condense the whole talk onto one page.
BUGFIX

Improve context length handling for third-party gateways and Foundry

When holding long conversations through an enterprise self-hosted or external proxy service, Claude Code previously did not compact content automatically. That caused many third-party gateway and Foundry sessions to stop with a context length error on every turn, and it is now fixed. The environment variable CLAUDE_CODE_MAX_CONTEXT_TOKENS now also applies to unrecognized model IDs whose names start with claude-. For example, a gateway's custom claude-sonnet-latest can also use this variable to set its context window limit.

Labeling capacity on a new suitcase used to fail whenever the model was missing from the catalog, but now any model starting with the specified brand prefix can still receive a capacity limit.
BUGFIX

Fix new installs overwriting the sonnet[1m] model setting

When setting up an environment on another computer while carrying over an old configuration, previously saved preferences could sometimes be automatically replaced with a name the API rejects. This issue of rewriting a saved sonnet[1m] setting to a name the API rejects is now fixed.

BUGFIX

Fix Bedrock token counting bypassing organization model limits

When the managed setting allowedProviders does not allow Amazon Bedrock, the token counting step previously still sent the conversation to Bedrock. This issue is fixed, and the provider restriction is now properly enforced.

FEATURE

/cost and budget limits now count mod model calls

When you load an extension and run automated tasks in a session, the cost of text generation and classification triggered inside the extension is now included in the total. That means model usage from these mods is counted toward the /cost command and the --max-budget-usd budget limit, and is reflected in cost and token metrics.

BUGFIX

Fix worktree and resume issues in Code Mode scripts

When running scripts in Code Mode, a worktree entered via EnterWorktree used to be ignored, and ~ paths were mistakenly written into the project. An issue where /mcp still showed an MCP server as connected after its sign-in expired is also fixed. Extra text typed along with Yes at a permission prompt or plan approval previously failed to reach Claude in Code Mode, and now gets through. If a session ended while running a Code Mode script, resuming that session used to make Claude start working on its own; now it stops and waits for your next instruction before starting.

BUGFIX

Fix invalid Agent SDK setting clearing earlier settings

For developers integrating the Agent SDK: passing an invalid value to the flag settings interface used to silently wipe out all settings saved by earlier calls. This is now fixed—any call that would cause this now returns an error and refuses to apply.

BUGFIX

Fix missing OpenTelemetry prompt events and merged text

For admins and developers configuring OpenTelemetry telemetry: user messages sent while a tool is still running used to miss a prompt event record. That event is now recorded properly, marked as delivered mid-turn and tied to the currently running turn. Also fixed an issue where prompt events dropped the text of earlier messages when multiple queued messages in VS Code merged into a single turn, or when one of them included an image.

FEATURE

Show cell re-run tip after Jupyter notebook edits

When you ask Claude to read or write a Jupyter notebook in VS Code or other integrated terminals, there is now a helpful reminder on screen. Once Claude has read or edited a notebook file, the tip bar next to the spinner now reminds you that you can re-run the cell.

FEATURE

Show next steps for org blocks and user-only commands

When your organization's policy blocks a request, an extra line now appears below the error message telling you how to proceed: run /rewind and edit your original message, or run /clear to start fresh. If Claude tries to run a command that only you can run, a dim note now appears under the red error message reminding you that the command only runs when you type it yourself at the input prompt.

FEATURE

Refresh terminal prompt suggestions less after background turns

When automated or scheduled tasks run quietly in the background for a while and you are not watching the screen, the next-step suggestions beside the input box no longer need to keep refreshing. After 8 turns in a row, prompt suggestions in the terminal automatically refresh less often to save usage until you press any key or switch back to the terminal.

If nobody is watching TV in the living room, the remote menu used to keep reloading the program guide, whereas now it refreshes less often to save power and returns to its normal rate once you walk back or press a key.
FEATURE

Remind Claude to keep important files out of temp folder

When you ask Claude to write or organize files you will still need later, it now avoids the temporary scratchpad folder that can be cleared at any time. This reminder has been added to Claude's built-in instructions so your work does not end up in the wrong place.

FEATURE

Start teammates and new sessions in current directory

You can press ← to open the agents view and start a new session from there. Newly opened environments used to end up in whichever path the shell last ran cd into. Now teammates launched via tmux or iTerm2, as well as new sessions created from the agents view, all start in the current session's folder.

BUGFIX

Fix commands running in launch folder after directory deletion

If the folder you were working in was accidentally removed, the shell used to quietly fall back to the original launch location and keep running. Now the command fails right away with a message, and you can re-issue it afterward.

BUGFIX

Fix approved plan edits not being saved

If the plans folder could not be written to, your recent edits were lost as soon as you approved the plan. Now, when writing to plansDirectory fails like this, the plan is saved to the default plans folder instead, and a warning explains where it was saved and why.

BUGFIX

Fix recent turns lost when resuming after an unclean exit

If your terminal suddenly crashed or was force-closed, the last few turns of your conversation could occasionally go missing when you picked up where you left off. This is now fixed, so resuming a session that did not exit cleanly no longer drops recent turns.

BUGFIX

Fix PRs showing as waiting for input when only your review is needed

When all changes in a pull request were finished and it only needed your own approval or merge, the screen used to stay stuck in a waiting state. This false "waiting for input" status is now fixed, and the session status displays normally.

BUGFIX

Fix brief-mode sessions resending the same reply

When chatting with Claude in a compact interface like Dispatch, the exact same reply could sometimes appear again even after the turn had already answered. This issue where brief-mode sessions sent duplicate replies is now fixed, so they will not be sent twice.

BUGFIX

Fix terminal display overlap and narrow-window wrapping

In focus view, if a scheduled task replied after Claude had already answered your prompt, the original reply to you used to get hidden. With fullscreen off, the prompt could also occasionally go missing in a background subagent view, and both display issues are now fixed. Long options in lists and permission prompts used to partly overwrite each other when wrapping, and first-run screens on narrow terminals would lose a few lines; both layout issues are now fixed. Startup warnings about permission rules and the "N MCP servers need authentication" notice used to be marked as read even when scrolled out of view. This issue where they were mistakenly marked as seen is now fixed. When an agent's name or the working folder contained control characters or line breaks, the welcome header used to print garbled control characters or split across multiple lines; this is now fixed as well.

BUGFIX

Fix claude -p printing extra control sequences to terminals

When using single-command mode to print plain-text output directly on screen, the output used to include extra garbled sequences beyond text styling. This issue where claude -p printed extra control sequences to a terminal is now fixed so only styling controls remain, while output sent to pipes or files stays unchanged.

FEATURE

Improve /voice settings-lock and microphone selection prompts

When managed settings, the --settings flag, or project configuration files kept voice mode locked, running /voice used to falsely report that the mode had switched. These configuration files include .claude/settings.json and .claude/settings.local.json. Now, when voice mode is locked, /voice tells you directly which setting is holding it in place. If you see the "No audio detected" message from /voice on macOS or Windows, the screen now points you directly to where you can pick your microphone.

A walkie-talkie with a company-locked channel or an unplugged headset used to just keep claiming it switched or had no sound, whereas now it tells you who locked it and where to pick your microphone.
BUGFIX

Fix /stats day overcounting and /insights report bugs

When running /stats to view statistics, the active days total used to be counted one day too high; this is now fixed. When no sessions qualified for analysis, /insights used to still announce that a report was ready, and two values written into its HTML report were not escaped first; both bugs are now fixed.

BUGFIX

Fix claude purge hanging without a terminal or with piped input

Running claude purge in an environment without a terminal to read keystrokes from used to hang silently. When content was piped into standard input, the project picker and -i prompts would also ignore keyboard input; both interactive issues are now fixed.

BUGFIX

Fix missing warning for invalid teammateMode settings

If teammateMode in a settings file had an unrecognized value, it used to be silently ignored without any warning. Now claude -p, the startup warning, and claude doctor all list it as a skipped entry, while still not applying the invalid value.

BUGFIX

Fixed IDE welcome dialog shortcut on Windows and Linux

Opening the IDE welcome dialog on Windows and Linux used to show Cmd+Esc as the shortcut hint for Quick Launch by mistake. That display bug is now fixed.

BUGFIX

Fixed Slack tips appearing when your organization denies cloud sessions

Even when your company did not allow cloud environments, Slack app tips used to pop up on screen. That issue is fixed, and those tips no longer appear when organization policy denies cloud sessions.

BUGFIX

Fixed desktop third-party deployments hanging on "Stopping"

When you opened Claude Desktop in a self-hosted enterprise environment and tried to end a conversation, the screen used to stay stuck until a token renewal finished. Once that third-party deployment includes this version, the issue of hanging on "Stopping" is resolved.

BUGFIX

Fixed Windows startup stall from inaccessible PATH folders

On Windows, whenever an entry in the PATH environment variable sat under a folder your account could not open, Claude Code could stall for about a second at startup. This issue is fixed, so it will no longer hang for that reason.

BUGFIX

Fixed Windows /resume path case and trust issues

Using /resume on Windows to restore an old session used to fail with a refusal or hide the session if its recorded folder path had a different drive-letter case or slash direction. That is now fixed, so those sessions can be found and restored normally. Similarly, running /resume inside a Windows session when the path's drive-letter case differed used to also drop the project's saved trust state, which will no longer happen.

FEATURE

VS Code input box now suggests your next prompt

After asking Claude to edit code in VS Code, wondering whether to add tests or check the diff next? The input box now surfaces a suggested next prompt at the same moments the terminal does, and pressing Tab accepts it right away.

At a conveyor-belt sushi bar, you used to stare at the belt wondering what plate to pick next, whereas now the chef slides a matching next dish right in front of you based on what you just ordered so you can grab it.

If you find the suggestions distracting, add this line to Claude Code's settings.json to turn them off:

{"promptSuggestionEnabled": false}
FEATURE

Improved VS Code sign-in flow and error guidance

The VS Code extension now includes a Console sign-in method that creates no API key, so you do not have to generate an extra key just to log in. When signing in to an MCP server from the panel in SSH, WSL, or container windows, the screen now includes a field where you can paste the redirect URL directly. Sign-in options already blocked by the managed allowedProviders setting used to still appear on the sign-in screen, which is now fixed. If your browser reports a connection error for localhost, the sign-in card now tells you directly how to resolve it.

BUGFIX

Fixed VS Code model check mark and effort cap

After Claude Code restarted on another model or switched models over Remote Control, the model picker in VS Code used to leave its check mark on the old model. That display bug is now fixed. The effort selector also used to list options above the cap set by your organization or the maxEffortLevel setting, and it now stops showing levels above that limit.

FEATURE

Improved VS Code safety prompts and block messages

When a safety check triggers a permission prompt for MCP tools in VS Code, the dialog now explains why Claude Code needs to ask you. The message when organization settings fail to load no longer tells you to run a command again, and instead asks you to "try again" to match the tab's "Retry" link. When you open an untrusted folder, the notification now clearly explains why the extension is disabled and how to turn it back on. If your operating system blocks Claude Code from running, the error message now lets you know that your IT team can allow the blocked program. When opening the plugin marketplace through an install link, the confirmation button text now reads "Trust marketplace and continue".

BUGFIX

Fixed web MCP tool descriptions cutting off at 4,096 chars

When loading MCP tool descriptions through tool search in new cloud sessions, anything past 4,096 characters used to get cut off. This limit issue for MCP tool descriptions on the web is now fixed, raising the cap to 16,384 characters to match Claude Code in other environments.

BUGFIX

Fix missing card for Slack Artifact links when sign-in expires

A colleague pastes an Artifact link in a Slack workspace not managed by their organization while the poster's Claude sign-in has expired. Previously, no preview block would appear in the chat at all. This issue with pasting Artifact links in a Slack workspace not managed by the organization is fixed, and a plain card now appears.
