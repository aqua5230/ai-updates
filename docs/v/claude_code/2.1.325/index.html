Claude Code 2.1.325

發布日期：2026-11-13

繁體中文

新功能

沙盒 Bash 預設改走一般權限流程

平常在沙盒（隔離執行環境）裡直接跑 Bash 指令，現在不會再自動放行，而是照平時的權限規則來決定。 如果想維持不跳出詢問直接執行，請在設定檔加入下面這段設定。

{"sandbox": {"autoAllowBashIfSandboxed": true}}

如果你是用管理員統一控管的設定來開啟沙盒，也必須在優先順序最高的那份管理設定來源加上同一組設定。這樣指令才會繼續免詢問執行。

跟進圖書館的獨立閱覽室一樣，以前進門就免登記借閱，現在改按一般借閱規則決定是否要登記；想維持免登記借閱，得另外開通權限。
新功能

沙盒加強保護外加目錄與更新資料夾

在沙盒裡執行的指令，寫入限制現在變得更嚴格。除了原本的啟動資料夾，你額外加入的目錄裡，.claude 底下的設定、技能、代理、指令與 hooks（掛鉤，特定事件發生時被觸發的小程式）現在也一律禁止被沙盒改寫。 當沙盒裡的 git checkout、git stash 或附帶自動暫存的 pull 沒辦法更新 .claude 等受保護檔案時，Claude 現在會收到一則提示說明原因。 某些情況下沙盒指令曾能寫入原生更新程式的下載資料夾，這個漏洞已經修好。 Bash 沙盒過去沒能完整保護 worktree（工作樹，Git 讓同一專案平行開多份副本的功能）的設定與 hooks。連同連結 worktree 共用的 .git 資料夾，這兩項防護缺口現在也已經補上。

新功能

沙盒與內建小工具不再帶入帳號金鑰

沙盒為了自身運作而啟動的程式，例如網路橋接工具，執行環境裡不再帶有 Claude Code 的登入 token（授權令牌）與 API 金鑰。 檔案搜尋工具 ripgrep、本機 Git 指令以及沙盒執行期的輔助程式，啟動時也不會再帶著雙向驗證憑證的 mTLS 金鑰密碼。

如同去沖印店洗照片，以前整本相簿連同底片盒都留給店員，現在只把要洗的那幾張檔案傳過去。
問題修復

修正 Linux 沙盒在允許讀取目錄下建檔失敗

在 Linux 環境裡，工作目錄可能位於 denyRead 限制內的 allowRead 資料夾底下。這種情況過去執行沙盒 Bash 指令會中斷，跳出 bwrap: Can't create file 錯誤訊息。例如透過符號連結（指向另一個位置的捷徑檔）存取家目錄，就可能遇到上述目錄關係。現在這個問題已經修好。

新功能

在非專案的外部儲存庫跑唯讀 Git 改先詢問

Claude 想在目前專案以外、而且你還沒信任過的 Git 儲存庫裡執行唯讀 Git 指令，現在會先跳出確認才執行。 如果想讓這類跨儲存庫的唯讀查詢不用每次確認，啟動時必須用 --add-dir 參數明確指定該路徑。只寫在設定檔的 additionalDirectories 裡並不會自動免問。

像在機場免稅店試用展示品，以前只要不帶走就能直接試噴，現在跨進未登記的專櫃前，店員會先問過你，除非你早有領取試用券。
新功能

排程任務與永久允許的權限判斷變嚴謹

排程任務與 /loop 指令在執行前，如果遇到本身宣告了 allowed-tools 或 hooks 的技能，現在會先停下來詢問你。想讓這類技能在無人值守時自動跑，要把對應的 Skill(name) 加進設定檔的允許清單。

{"permissions": {"allow": ["Skill(name)"]}}

在桌面版、IDE 與 SDK 宿主環境裡，「Always allow」永遠允許選項也調整了出現條件。只有當存下來的單一規則真的能讓該指令下次直接放行時，畫面才會提供這個選項，因此過去依賴這類規則的排程任務現在可能會停下來等你確認。

好比辦健身房的自動續約，以前櫃檯只要有紀錄就會直接扣款開通，現在合約條款有變動或沒簽齊就會先暫停，等你親自到場確認後才繼續。
問題修復

修正 Bash 權限規則漏判與錯執行程式

先前設定好的 Bash 拒絕與詢問規則，遇到特定指令曾發生沒有套用的情況，這個問題已經修好。 部分組合在一起的複合 Bash 指令過去會繞過權限檢查直接執行，現在這類指令都會先跳出詢問視窗等你確認。 過去還有一種情況會讓 Bash 允許規則實際執行到與規則名稱不同的程式，這個漏洞也已經補上。

問題修復

修正權限規則在切換目錄與重啟後的漏判

像是 Read(./.env) 這類使用相對路徑的拒絕與詢問權限規則，過去只要執行過 cd 切換目錄就不再覆蓋原本專案。這個問題已經修好，現在這些規則在額外加入的目錄裡也會生效。 以 mcp__plugin_*_ 開頭的規則會比對外掛的 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器或工具。過去名稱大小寫不同就會漏判，這個問題已經修好。 在自託管執行器與 claude remote-control 工作階段中，有時權限核准會在 Claude Code 重啟後才送達。過去這類情況不會套用先前設定的拒絕規則，這個漏洞現在也已經修好。

問題修復

專案本機權限設定檔改為嚴格驗證信任

把儲存庫裡已提交的 .claude/settings.local.json 誤當成個人設定檔的漏洞已經修好。過去從儲存庫某些子資料夾啟動 Claude Code 時，這份已進版控的檔案曾會被當作使用者自己的設定套用。 當你透過 -p 參數或 SDK，在掛載進容器的 worktree 或子模組裡執行任務時，權限檢查變得更嚴謹。現在必須先確認信任該資料夾，.claude/settings.local.json 裡的允許規則才會生效。

外包人員帶來的門禁卡，以前進到某些樓層就直接放行，現在得先由屋主確認信任這張卡，門禁才會真正開通。
問題修復

修正斜線指令授權外洩給背景代理

當某個指令透過 allowed-tools 暫時放行特定工具時，這份臨時權限過去會一路延續到同一回合或之後才被喚醒的代理。現在這個問題已經修好，背景代理不會再繼承這項額外授權。

問題修復

修正核准子代理計畫後權限模式倒退

當你點頭讓子代理執行它擬好的步驟時，目前的工作階段過去偶爾會退回更早之前的設定。這個問題已經修好，現在工作階段會維持應有的權限模式。

問題修復

調整 Artifact 權限詢問與對外內容把關

讀取你自己建立的 Artifact 或裡面的資料，Claude 過去還會跳出權限詢問，現在已經不用再確認。 雲端工作階段裡針對 Artifact 工具設定的拒絕、詢問規則與 hooks，過去偶爾沒有套用的問題也已經修好。 針對組織外部人員看得到的 Artifact，權限把關現在更嚴密。即使先前設了允許規則或曾核准上傳，子代理想修改這類外部 Artifact 或上傳檔案前都必須先詢問你。就算你對 Artifact 勾過「不要再問」，發佈外部頁面時也不會略過確認。 在自動模式下，過去只會審核對外 Artifact 的第一次修改；現在每次放行都只涵蓋當下那一次更動，後續修改會重新判斷。

問題修復

修正 zstd 壓縮回應解碼的安全漏洞

Claude Code 解碼採用 zstd 壓縮格式的回應內容，過去存在一項安全問題。這個漏洞已經修好，更新到這個版本後就能排除這項風險。

新功能

隔離 worktree 禁用部分 Git 指令與捷徑掛鉤

在隔離的 worktree 工作階段或代理裡，現在禁止執行幾項 Git 指令。這包括 git bisect run、git maintenance register|start 與 scalar 的初始設定，被擋下時畫面還會告訴你哪些指令仍能使用。 呼叫 EnterWorktree 時，如果 WorktreeCreate 掛鉤提供的路徑經過專案裡的符號連結，它就會直接拒絕。請讓該掛鉤改印出真實路徑。

分租一間工作室時，房東只准你用分給自己的工作桌，列在禁用清單上的工具或繞道捷徑都不放行。
問題修復

修正多種 Git 檢出與稀疏複製的異常

如果你在純儲存庫 worktree、--separate-git-dir 或 Android repo 檢出環境下工作，以前可能會卡關。/security-review 與技能內嵌的 Git 指令過去會報錯停住，這個問題現在已經修好。 在新家目錄首次以 --worktree 啟動時，Claude Code 過去會跳過 CLAUDE_CODE_PLUGIN_SEED_DIR 裡的掛鉤。現在外掛帶的 WorktreeCreate 掛鉤在第一次執行就能正常觸發。 在像 2.34 這類較舊的 Git 版本上，設定 worktree.sparsePaths 過去會漏掉儲存庫根目錄的檔案。外掛與市集的稀疏複製也有同樣問題，現在都已經修好。

問題修復

修正 /teleport 在特殊 Git 狀態的暫存判斷

在部分不尋常的 Git 狀態下執行 /teleport，過去處理暫存變動的判斷容易出錯。這個問題已經修好，現在遇到這類狀況會停下來並告訴你接下來該怎麼處理。

新功能

外掛市集與安裝提示明確警告可執行程式碼

看到一個好用的外掛準備點安裝嗎？無論是在新增外掛市集的確認畫面、推薦外掛的提示，還是外掛安裝警告上，現在都會明確寫出外掛可以在你的電腦上執行程式碼，而且能存取你的檔案與終端機殼層。

拿下載瀏覽器擴充功能來說，以前只按確定，現在店家會先亮出權限清單，讓你看清楚它看得到哪些資料再決定要不要裝。
新功能

外掛市集支援特定 commit 鎖定與代理下載

私人外掛市集如果跳出 HTTPS authentication failed 錯誤，現在會說明 Git 的終端機互動提示與密碼輸入程式已被停用。較新版本的 Git 現在也會正常顯示這則訊息。 市集的 ref 欄位現在支援填入分支或標籤上任一筆提交的完整 commit ID；不過這個版本之前的舊用戶端無法複製這種鎖定方式，遇到時該市集會無法載入。 當環境只設定了 ALL_PROXY 作為代理時，外掛市集與外掛下載會改走 CONNECT 通道；如果代理伺服器拒絕 CONNECT 連線，下載就會直接失敗。

新功能

調整外掛套件解壓與安全載入規則

外掛的 .mcpb 與 .dxt MCP 套件包，不再解壓到外掛自己目錄底下的 .mcpb-cache，而是改放在外掛總目錄裡，讓唯讀的外掛資料夾也能載入。若是透過網址抓下來的套件，更新後會再重新下載一次。 載入外掛時會自動跳過資料夾內部分不安全的路徑與連結，執行 claude plugin validate 時也會把這些項目回報出來。 用 --plugin-dir 掛載的外掛，其內部的 .claude/skills 巢狀技能資料夾，現在不會從上層目錄啟動的工作階段載入。要使用這些技能時，請直接在外掛資料夾內啟動 Claude Code。

問題修復

修正 claude plugin eval 空輸出路徑的錯誤

執行 claude plugin eval --output-dir '' 且輸出路徑留空，過去會誤把報告直接寫進目前的工作資料夾。這個問題已經修好，現在遇到空路徑參數會直接報錯結束。

問題修復

組織管理設定的遠端外掛與自訂鎖定規則更新

管理設定已宣告並啟用的遠端市集，其中列在 prependPlugins 或 appendPlugins 的外掛，現在會被認定為組織自己的外掛。原本的 pluginDigests 設定已經棄用，設定了也會被忽略。 組織用來鎖定代理與技能只能來自外掛的 strictPluginOnlyCustomization 規定，過去對於已經啟動中的工作階段不會立即生效。這個問題已經修好，現在跑一半的工作階段同樣會受這道鎖定限制。

公司更新了門禁白名單與規範，不僅認列特約廠商的工具，連已經刷卡進場正在辦公的員工也會立刻套用新規定。
新功能

改進內建資料視覺化技能的比例圖表建議

製作靜態圖表或呈現年齡區間這類具有自然順序的分組資料，你都能從內建的 dataviz 技能得到更貼切的整體與部分比例呈現建議。

問題修復

修正 MCP 伺服器清單殘留與重連認證異常

在 Claude Desktop 或 SDK 工作階段裡，只要資料夾搬家或預熱啟動，連線清單就容易出錯。資料夾本身的 .mcp.json 與本機 MCP 伺服器過去會誤標或漏列，WebSocket 伺服器也連不上，這些問題已修好。 外掛在 MCP 伺服器連線時重載並移除它，/mcp 清單過去會留著舊項目，現在會清掉。 更新授權令牌若短暫遭拒，MCP 伺服器過去會卡在「needs authentication」並跳過 mcp_tool hooks，現已修好。 在 headless（無頭模式，沒有終端機視窗的執行模式）呼叫工具期間，若連線被替換，MCP 資訊徵詢請求過去會未經詢問就被取消，這個問題已經修好。 從 SDK 宿主發出的 MCP 工具呼叫，即使前一次已重連，過去有時仍會報錯「Not connected」，現已修好。

新功能

改善背景 MCP 任務提問延後與 /tasks 流程

背景執行的 MCP 任務跳出問題，按 Esc 鍵現在改為「稍後回答」，不會傳任何內容給伺服器，問題會留在 /tasks 裡等你。當任務還在等你的回覆時，Claude 也會收到通知，並引導你去 /tasks 處理。 如果你正打字寫訊息到一半，背景 MCP 任務的問題現在不會突然蓋在輸入框上，而是等你送出或清空草稿才打開，期間等待動畫與回合碼錶會照常計時。 先前用 Esc 關閉或重新發問曾讓 MCP 任務卡死；現在頁尾會提示需要你輸入，進 /tasks 按 Enter 就能再叫出問題。 同一部伺服器的另一次呼叫斷線後再連回來時，背景 MCP 任務過去會停止更新進度，這個問題也已經修好。

診間掛號後先去旁邊填資料時，以前叫號機常直接蓋掉你手上那份表格，現在會等你寫完才繼續叫號並保留你的號碼。
問題修復

調整 /login 隱私確認與修正登入失敗畫面

透過 /login 登入，如果要改動你的隱私設定，現在會先跳出詢問取得你的同意。 在 /login 點選「Sign in with your Console account」用主控台帳號登入，若在瀏覽器步驟剛結束就按 Esc 取消，過去會覆蓋掉原本的登入狀態。瀏覽器在登入失敗或取消時偶爾還顯示成功頁面的問題，現在也都已經修好。 用 claude --desktop 登入 Claude 帳號卻被擋下時，錯誤訊息現在會直接點名是哪一組 API 金鑰、服務提供者或設定卡住了登入。

新功能

加速主控台登入啟動並清理殘留鎖定檔

當你用免金鑰的 Console 帳號或其他 Anthropic 設定檔開啟工具時，只要手上的授權令牌還沒過期，現在會直接讀取，不必再排隊等憑證鎖定解除。 先前執行 claude auth status 這類短指令後，主控台設定檔曾會留下一道鎖定，害下一個工作階段卡住約一分鐘，這個問題已經修好。 設定目錄裡過去會越積越多的 .oauth_refresh.lock.owner.tmp.* 暫存鎖定檔，現在也不會再殘留。

問題修復

修正無 HOME 環境變數時雲端憑證讀取失敗

未設定 HOME 環境變數啟動時，AWS 的 credential_process 輔助程式與 Google Cloud 預設憑證曾無法正常運作。這個問題已經修好。

新功能

無快取下執行 claude -p 會先等帳號資料

當你在全新、還沒存過登入紀錄的環境裡跑單次指令模式時，現在發送第一筆請求前會先等用戶資訊載入完成。這代表在沒有帳號快取（把查過的結果暫存起來直接用）的情況下，執行 claude -p 的初次啟動可能會比以前晚幾秒。

修正 /fast 與 /model 誤報組織限制

使用免金鑰的 Console 主控台登入時，Claude Code 其實還沒問過伺服器。過去 /fast 卻會直接報錯「Fast mode has been disabled by your organization」。 遇到斷網等無法連線確認的狀況時，/model 過去也會誤稱組織限制了某個模型。這兩項未經確認就誤報限制的問題都已經修好。

帳號 Email 身分檢查涵蓋腳本與連線

指令執行的腳本、寫入檔案、抓取網頁與 MCP 呼叫，現在也都會受帳號 Email 檢查把關，不讓你的 Email 被當成用戶端身分送出。

FEATURE

Sandboxed Bash now follows normal permissions by default

Running Bash commands directly inside a sandbox (an isolated execution environment) no longer bypasses prompts automatically and now follows your normal permission rules. To keep running them without prompts, add this configuration to your settings file.

{"sandbox": {"autoAllowBashIfSandboxed": true}}

If you enable the sandbox through administrator-managed settings, you must also add the same setting in your highest-ranking managed source. That way, commands will continue running without prompts.

Like entering a library's private reading room, borrowing used to skip sign-out upon entry, whereas normal borrowing rules now decide whether you need to sign; to keep skipping sign-out, you must enable that permission separately.
FEATURE

Sandbox strengthens protection for added directories and updater folder

Write restrictions for commands running inside the sandbox are now stricter. In addition to the launch folder, .claude settings, skills, agents, commands, and hooks (small programs triggered by specific events) in directories you add are now all blocked from being modified by the sandbox. When a sandboxed git checkout, git stash, or pull with autostash cannot update protected files such as those in .claude, Claude now receives a note explaining why. In some cases, sandboxed commands could previously write to the native updater's download folder, and this bug has now been fixed. The Bash sandbox previously failed to fully protect the settings and hooks of a worktree (a Git feature for opening multiple parallel copies of the same project). Along with the shared .git folder of a linked worktree, both protection gaps have now been closed.

FEATURE

Sandbox and built-in utilities no longer carry account keys

Programs that the sandbox starts for its own operation, such as its network bridge, no longer have Claude Code's sign-in tokens (authorization credentials) and API keys in their execution environment. The file search tool ripgrep, local Git commands, and the sandbox runtime's helper programs also no longer launch with the mTLS client key's passphrase for mutual authentication certificates.

Picture dropping off photos at a print shop: you used to leave the whole album and film canister with the clerk, whereas now you only send over the specific files to print.
BUGFIX

Fix Linux sandbox file creation failure under allowed-read folders

On Linux, the working directory may sit under an allowRead folder inside a denyRead restriction. Previously, running sandboxed Bash commands in this situation would fail with a bwrap: Can't create file error message. For example, accessing your home directory through a symlink (a shortcut file pointing to another location) could trigger this directory layout. This issue is now fixed.

Read-only Git in untrusted external repositories now asks first

When Claude tries to run read-only Git commands in a Git repository outside the current project that you have not trusted yet, it now prompts for confirmation before running. To run these cross-repository read-only queries without confirming every time, you must explicitly pass the path with --add-dir at startup. Listing it only in the additionalDirectories setting does not skip the prompt automatically.

Think of sampling testers at an airport duty-free shop: before, you could spray freely as long as you didn't take anything, whereas now a clerk asks before you step into an unregistered counter unless you already claimed a sample pass.
FEATURE

Stricter permission checks for scheduled tasks and permanent allows

Before running scheduled tasks or the /loop command, Claude now pauses to ask you if a skill declares allowed-tools or hooks. To let such skills run unattended, add the corresponding Skill(name) entry to the allow list in your settings file.

{"permissions": {"allow": ["Skill(name)"]}}

In Desktop, IDE, and SDK hosts, the "Always allow" option has also tightened when it appears. The UI now offers this option only when saving that single rule will actually allow the command again next time, so scheduled tasks that previously relied on such rules may now pause for your confirmation.

A gym's auto-renewal desk used to charge and activate your pass whenever a record was on file, but now it pauses if contract terms changed or signatures are missing until you confirm in person.

If you find the suggestions distracting, add this line to Claude Code's settings.json to turn them off:

{"promptSuggestionEnabled": false}
FEATURE

Improved VS Code sign-in flow and error guidance

The VS Code extension now includes a Console sign-in method that creates no API key, so you do not have to generate an extra key just to log in. Sign-in options already blocked by the managed allowedProviders setting used to still appear on the sign-in screen, which is now fixed. If your browser reports a connection error for localhost, the sign-in card now tells you directly how to resolve it.

BUGFIX

After Claude Code restarted on another model or switched models over Remote Control, the model picker in VS Code used to leave its check mark on the old model. That display bug is now fixed. FEATURE

Improved VS Code safety prompts and block messages

When a safety check triggers a permission prompt for MCP tools in VS Code, the dialog now explains why Claude Code needs to ask you. If your operating system blocks Claude Code from running, the error message now lets you know that your IT team can allow the blocked program. BUGFIX

Fixed web MCP tool descriptions cutting off at 4,096 chars

When loading MCP tool descriptions through tool search in new cloud sessions, anything past 4,096 characters used to get cut off. This limit issue for MCP tool descriptions on the web is now fixed, raising the cap to 16,384 characters to match Claude Code in other environments.

BUGFIX

A colleague pastes an Artifact link in a Slack workspace not managed by their organization while the poster's Claude sign-in has expired. Previously, no preview block would appear in the chat at all. This issue with pasting Artifact links in a Slack workspace not managed by the organization is fixed, and a plain card now appears.
