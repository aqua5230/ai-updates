Claude Code 2.1.284

Released: 2026-09-28

Release notes

FEATURE

Claude Sonnet 5.5 Launches with Default 1M Token Context Window

When you call Claude in the terminal to work on massive projects, you can now use the latest flagship model.

The Anthropic API officially upgrades the default Sonnet to Claude Sonnet 5.5 (claude-sonnet-5-5). The new model features a context window of one million tokens (text units for AI processing and billing). Pricing is two dollars per million tokens for input, ten dollars for output, and zero point two dollars for cache reads. When using Claude for Desktop behind an enterprise gateway, the gateway automatically annotates the one-million context option for desktop clients.

Picture a library rolling out a new cart capable of holding an entire collection of books: lengthy volumes that previously could not fit are now carried all at once, and the lending system proactively lists the large-capacity specification.
FEATURE

Auto Mode Eases External Read Prompts and Becomes Default When Unconfigured

If you often need AI to inspect configuration files outside your project, operations are now more flexible.

When reading files outside the project directory in auto mode (an execution mode where Claude runs tasks while minimizing interruptions), a new prompt option "Allow once, ask again next time" lets you permit a single read without losing future gatekeeping control. Sessions in the terminal and VS Code now start in auto mode by default across all plans and providers when permissions are unconfigured. You can override this default behavior at any time using the permissions.defaultMode configuration key.

A guardhouse now keeps a single-use pass on hand: instead of being forced to grant full clearance or halt every single time, it can approve only this one read while the front gate maintains default patrol mode.
FEATURE

Effort Controls Support Keybindings with Ultracode as Independent Toggle

When fine-tuning the model's reasoning depth, you are no longer locked into fixed key combinations.

Slider keys for /effort are now customizable, allowing you to freely bind actions like effortSlider:decreaseEffort, increaseEffort, and toggleUltracode in keybindings.json. Ultracode (an independently toggleable mode) can now be enabled via the Tab key or /effort ultracode on. It is no longer forced to the xhigh reasoning level and continues operating under any effort setting.

Think of a camera splitting shutter speed and night mode into separate dials: switching to night mode previously locked the shutter, whereas any exposure setting can now be freely paired with night enhancement.
FEATURE

Usage Limits Display Spend Progress and Waiting Countdowns Stop Spamming

When checking usage or hitting quota limits, the interface now clearly explains spending and waiting progress.

When the enterprise gateway runs this version or newer, /usage and statusLine (the bar displayed at the bottom of the terminal) show spend amounts; rate_limits.spend_limit also adds used_usd, limit_usd, and period fields. Subscribers on claude.ai can find /rate-limit-options in /help and the command menu. When encountering rate limits or rejected logins, /usage, /extra-usage, and IDE usage views back off before retrying. Rate limit status, countdown timers, and the /usage-credits option are consolidated into a single block beneath the prompt input, eliminating repeated screen clutter. A turn that hits limits again after you type during a wait remains governed by the auto-continuation setting. Prompts for the top Max tier no longer suggest upgrading, and when /usage-credits is available, both prompts and /upgrade redirect to it.

FEATURE

MCP Tools Support Reconnecting All and Session Resumption Waits Before Erroring

If an external tool you connected to Claude Code can't connect or asks you to sign in again, run /mcp reconnect all in the terminal to retry every MCP (a protocol that lets AI reach external tools) server that isn't connected, all at once.

When you resume an old conversation and a tool is still connecting, the call no longer fails right away with "No such tool available" but waits up to ten seconds. If your organization's managed settings only allow plugins to provide MCP servers, claude mcp add no longer reports success while saving a server that never loads; it refuses and explains what to do. When Elicitation or ElicitationResult hooks (small programs that run when specific events happen) return {"decision":"block"}, the MCP request is now declined instead of ignored, and if a Claude in Chrome tool is called without its prefix, the error names the tool to call. In non-interactive mode (no chat screen), a server that is still connecting and is named by --allowedTools or an mcp_tool hook still gets up to two seconds on the first turn, even when CLAUDE_CODE_MCP_STARTUP_WAIT_MS is 0.

FEATURE

Enterprise Gateway Supports Certificate Auth and Telemetry Forwards to Google Cloud

When identity providers issue certificates instead of client secrets, private_key_jwt authentication is now supported.

The telemetry.forward_to destination can be configured with auth: { google: {} } to forward telemetry directly to its OTLP endpoint using the gateway's Google Cloud credentials. When identity providers include multiple groups, the gateway can accept 256 KiB headers rather than returning 431. A warning is displayed when availableModels is empty or omits startup models while model or enforceAvailableModels is unspecified. Any ANTHROPIC_FOUNDRY_RESOURCE that is not a pure resource name is rejected. When login is required (forceLoginMethod or forceLoginOrgUUID) but an API key, token, or apiKeyHelper is also configured, credential locations and removal instructions are listed.

BUGFIX

Plugin Settings Controls Fixed with Duplicate Marketplace Warnings Added

When you install or adjust plugins, the yes/no options on the /plugin settings screen are now a two-way choice instead of free text; number fields refuse invalid input, and the left and right arrow keys change a field's value instead of jumping to another tab.

When you add a plugin marketplace (a place where plugins are collected) that replaces one with the same name from a different source, the screen now says so and how to undo it. If a first install fails because a dependency's version range can't be met, it no longer leaves the plugin recorded as enabled. On older git (before 2.39), updating a marketplace that uses sparsePaths (fetching only some folders) no longer replaces a working local copy with an empty one. On Windows, plugin bin/ folders that don't exist are no longer added to PATH (the list of places the system looks for programs), and entries already there aren't added twice. When your organization's managed settings turn on allowManagedPermissionRulesOnly, plugins can no longer pre-approve tools on their own, except plugins from an official Anthropic source or one the managed settings vouch for.

FEATURE

Corrupted Streams Retry or Report Interruption and Oversized Conversations Recompress

During unstable network connections or overly long conversations, error handling now delivers clearer outcomes.

When a stream (content displayed simultaneously as it generates) is corrupted, Claude retries or reports an interrupted response instead of showing low-level parsing errors or inserting undefined into the answer. If server overload or errors occur after thinking blocks complete, the request also retries. When a conversation exceeds length limits even after compaction, Claude Code compacts it a second time at the cost of retaining fewer recent turns. If a connection drops mid-response, retries share their budget with other retries for that request, failing fast on persistently broken connections. When a session's specified model is unavailable with no fallback configured, the interface displays an unavailability notice alongside a learn-more link.

FEATURE

Terminal Fullscreen Scrolling Stabilizes and Dialog Labels Support Word Wrapping

When viewing terminal transcripts in narrow windows or fullscreen mode, interface text layouts no longer misalign.

Pressing [ to write conversations to scrollback in fullscreen transcript mode (conversation transcript view) on macOS and Linux no longer erases terminal output above the session. Scrolling up through history no longer jumps abruptly when responses finish generating. Labels in /config and /plugin wrap on word boundaries if they exceed window width. Detail columns in /tasks, /copy, and /hooks render as single columns when space permits and align right when space is tight. Pressing the Down arrow in Shell mode no longer mistakenly selects hidden elements to block character deletion. The /model list no longer erroneously displays +1 model when scrolled to the very bottom. /keybindings no longer maps Backspace or Delete to invalid footer actions, and rebinding footer:close no longer accidentally inputs x when pressing the close key on agent panels.

BUGFIX

Vim Mode Repeats Fast Typing Accurately and Cursor Avoids Image Placeholders

Users accustomed to terminal Vim mode will find repeating changes after rapid typing more accurate.

When typing quickly over SSH or tmux sessions, or pasting text without bracketed paste (a mechanism marking paste boundaries), pressing . reliably repeats the previous change. Actions such as pressing Esc right after cw and then pressing . without entering text also return correctly to normal mode. After executing dd on the last line or yy at the end of the prompt input, the cursor no longer lands on the opening bracket of image placeholders, preventing subsequent r or x keystrokes from corrupting or deleting images.

Like a mechanical keyboard recording consecutive keystrokes, combinations that previously dropped inputs during rapid typing are now faithfully replayed, and the cursor avoids resting on spots where a single touch could damage images.
FEATURE

Accidental Activation Prevention for Remote Control, Active Trust Prompts for Untrusted Directories

Connection security is strengthened when controlling the terminal remotely from a phone or another device.

When the terminal window regains focus, the remote activation prompt restarts the safety delay to prevent accidental confirmation from keystrokes. Running claude remote-control in an untrusted directory directly shows a trust confirmation rather than abruptly exiting. Photos sent from mobile devices and pulled back into the prompt box for editing are no longer lost, and photos without captions no longer move the cursor by one space. After launching in the home directory, switching renderers or updating no longer repeatedly pops up the trust dialog.

A smart door lock requires confirmation upon waking: touching the panel previously risked instantly opening the lock, but lighting up the screen now provides a buffer time, and unfamiliar visitors trigger an active confirmation prompt on screen.
FEATURE

Clear Categorization for Artifact Lists, Private-Path Writes No Longer Misreported

When generating or managing artifacts (standalone web pages, charts, or document files generated by AI) in a project, the interface and prompts are now clearer.

The /artifacts view adopts clean category tabs for All, Mine, and Shared. When generating an artifact page, Claude writes design plans directly into the page itself and applies your pre-named title. Writing to a viewer-private data/users/ subtree in the database no longer incorrectly claims all viewers can see it, and as_level adds a view tier. When the Artifact tool receives claude.ai chat or project links, artifacts in chat, or standalone artifact IDs, it requests the correct link or content instead of abruptly aborting. Files on network shares can only be published if they reside on mapped network drives added with --add-dir.

FEATURE

Authorization Prompts for External Rules, Sanitized Hidden Markers in Auto-Memory

System defenses are now more comprehensive when linking external project configurations or building long-term conversation memory.

Symlinking external rules into .claude/rules or linking external .claude directories now prompts for external import authorization instead of silently skipping them. When reading auto-memory files, invisible characters and forged tags hidden in content are neutralized and filtered. When Sonnet safety protections flag a message, the notification explains the reason and provides an option to edit and retry. If a session pins Opus models via ANTHROPIC_DEFAULT_OPUS_MODEL or modelOverrides while using the Anthropic API, safety-related model switches are determined by the API based on the safety flag type.

Just as building security screens incoming mail: packages forwarded through shortcuts previously slipped past inspection, but security now requests clearance first and intercepts any hidden notes slipped inside.
FEATURE

Explore Subagents Inherit Custom Models, Visible Real-Time Progress for Auto-Loops

Several bottlenecks have been fixed when using subagents or automated loops.

When a session uses a model ID unrecognized by Claude Code via the Claude API (such as custom models behind proxy servers), Explore subagents inherit that model instead of switching to Opus. Sessions that do not provide SendMessage are no longer prompted to use it to message other sessions. When /loop paces itself, every progress update and stop outcome is printed as visible text. Launching /ultrareview from a worktree created by Claude Desktop on macOS or Linux can upload the worktree. When the Agent SDK encounters images with malformed source fields, it replaces them with explanatory text, and malformed document blocks no longer cause subsequent turns to fail. /recap rejects requests forwarded from chat threads, scheduled tasks, or webhooks, but remains fully usable directly in terminals, Claude apps, remote control, -p, or SDK hosts.

FEATURE

Hook Logs Capture Standard Error Output, Streamlined Config Schema Accelerates Startup

Logs now preserve more actionable clues when developing custom automation scripts or troubleshooting issues.

When a hook fails, debug logs record standard error output even if normal output was produced simultaneously, and status codes are captured even without output. Running Bash inside Linux sandboxes from a write-restricted working directory that contains read-restricted folders no longer fails to start. The monitor event row displays printed event output and no longer repeats unchanged waiting messages. Workflow tools improve isolation against async script hook failures; startup builds only config schemas referenced by configuration files, reducing memory usage and speeding up launch. /claude-api hillclimb no longer spends evaluation rounds on imperceptibly small prompt rewordings, and an extra page requested alongside report.html is generated as one offline, standalone local file.

FEATURE

[VSCode] Message Timestamps Supported, Plugin List Displays Loading Errors

When using Claude Code in the VS Code editor, you can opt to show timestamps above each prompt and response, with date dividers appearing only when days change.

The Show Message Timestamps setting is disabled by default. Plugin management list rows display loading errors and notes, with popups providing options to disable or uninstall plugins and copy error details. An independent Ultracode toggle is added below the thinking slider, and model badges indicate active states across all effort levels. Typing /model and pressing Enter opens the model selection list, and custom /mcp, /config, and /settings commands are no longer obscured by extension dialogs. File links containing non-ASCII characters, spaces, or parentheses can now be opened normally.

FEATURE

[VSCode] Reloading Retains Conversation History, Multi-Agent Messaging Drops No Text

Workflows remain uninterrupted when restarting the extension or collaborating across multiple agents in VS Code.

Running Reload Claude from the Memory dialog ensures active file edits are saved first, and conversation tabs automatically reconnect to original chats after the extension restarts. If a restored tab is already opened by another process, a prompt asks how to proceed. Expanded blocks in focus views no longer collapse unexpectedly while subagents are working or when the first step is trimmed from view. Messages from other agents, sessions, or channels remain fully intact after refreshes, and uncredited agent messages no longer display as raw XML tags. Background agents continue running stably when pressing Escape while no turn is actively executing.

Similar to closing and reopening a conference room door: ongoing file edits are saved before reconnecting to the discussion, messages from others remain intact, and background colleagues do not stop working just because you pressed Escape.
FEATURE

[VSCode] Feedback Reports Stored Locally, Compacting Large Attachments Avoids Errors

Reporting and compaction are more reliable when using VS Code on specific cloud platforms or attaching large text files.

Submitting /feedback in cloud environments such as Vertex, Bedrock, or Foundry stores report contents directly on the local machine. When conversations include large plain-text file attachments, conversation compaction handles heavy content smoothly without throwing prompt-too-long errors. The login flow no longer delays upon reloading windows while waiting for the Python extension. Plugin installation links no longer overwrite existing marketplaces sharing the same name. CLAUDE_CONFIG_DIR in claudeCode.environmentVariables takes effect only when set to an absolute path, passing through to terminals in continuing sessions.

When a customer feedback form fails to submit over the network, the system saves the report in a local folder instead: previously submitting triggered an outright rejection, but the local machine now safely preserves the feedback.
FEATURE

[Claude Tag] Channels Support Latest Model Families, Clearer Standby and Login Prompts

Bot responses and status notifications are clearer when tagging @Claude for team collaboration in Slack channels.

Individual threads, channel defaults, and direct messages can select model families like Opus (latest) to stay aligned with the newest release in that family. When environments decline to launch, Claude posts a single notice to contact administrators and retries upon subsequent mentions, while unlinked members receive a direct message login prompt on every mention. Self-hosted setups clarify whether runners are starting, should be retried later, or will not start. Adding channel admins provides clear explanations when a channel's Slack workspace cannot be verified as connected to the organization; adding repositories requests a GitHub login if the current session cannot confirm admin permissions. Repository previews and PR creation buttons display properly even when GitHub Enterprise hostnames include underscores.

FEATURE

[Claude Tag] Organization Quotas Included in Analytics Charts, Review Publishing Adds Retries

Enterprise administrators gain a more complete data view when tracking team spending and reviewing code.

Forecast analytics charts now break down expenditures and percentage utilization counted against the organization quota. The Notify Members Now control in administrative settings reaches every claimed workspace across an Enterprise Grid in a single click, reaching broader member sets in large workspaces. Channel access listings display automatically linked connectors, repositories, and plugins alongside their respective origins. Interacting with edit or duplicate controls for cloud scheduled tasks while offline prompts an offline notice rather than indicating ongoing loading. When Code Review encounters pending unsubmitted reviews under its GitHub App on a pull request, it retries publishing completed reviews rather than giving up immediately.

Imagine corporate financial statements consolidating regional budget consumption into a unified chart: previously, unsubmitted reviews under the Code Review GitHub App could block completed reviews from publishing, but quota usage is now clearly visible and review publishing retries automatically.
