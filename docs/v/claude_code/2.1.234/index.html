替每個專案的對話紀錄取短名

像檔案館替各專案卷宗編短檔號，櫃位仍在原處，翻找時不用讀完整串名稱。同一台主機替每個工作階段各放一個設定資料夾時，對話紀錄的專案資料夾名稱不必再拖得很長。新增的環境變數（environment variable，程式啟動時讀取的外部設定）CLAUDE_CODE_PROJECT_DIR_NAME 可替每個專案的 transcript 資料夾指定短名。在啟動 Claude Code 的主機環境設定 CLAUDE_CODE_PROJECT_DIR_NAME=project-a，讓專案 transcript 資料夾使用 project-a。原本分開存放的設定方式不變，只是資料夾名稱更好辨認。

選取文字可用按鍵清掉，Esc 不再誤清

這像桌上多了一把只用來擦掉螢光筆記號的橡皮擦，而離開按鈕不會順手把整段標記抹掉。在程式裡反白一段文字後，現在可把按鍵綁定到 selection:clear，專門取消這個文字選取；agents view 也能用。全螢幕模式用滑鼠反白時，Esc 則不會再把選取範圍清掉，它照常只負責中斷或關閉。你可以在按鍵設定中把 selection:clear 指給想用的按鍵。

GitLab 合併請求狀態直接顯示

像球場計分板隨時亮出比賽狀態，不必離場另外查詢。專案連到 GitLab，而且 glab CLI 已完成登入時，頁尾與狀態列（statusline，終端機最底下的即時資訊）會顯示合併請求的 MR !N。草稿、等待中與綠色狀態也會一起顯示，不必先離開目前工作去查網頁。這只適用於有 GitLab remote 的 repository，並需要已驗證的 glab。

用量額度重設後可自動接著工作

像暫停的播放器在可播放時接著播；不想它自動播放，就把那個選項關掉。工作做到 claude.ai 用量限制剛好卡住時，額度重設後，Claude Code 現在會自動延續原本的工作階段。若你不想自動繼續，可開 /config，關掉「Continue automatically at usage limit」。選擇權留在你手上：保留設定就等待額度重設後接續，關閉後則由你決定何時再開始。

帳號信箱只用來辨識你

像櫃檯核對證件後把證件還給你，不會拿著它去別的店家登記。帳號 email 現在被明確限制為辨識你本人之用。除非你提出要求，Claude 不會把它送往無關的服務。這講的是帳號信箱的使用界線，不是要你另外開啟某個設定；當對話需要知道你是誰時可使用，和外部不相干服務之間則不自行傳遞，也不會因為系統自行選擇而交給外部；這正是它的限制。

Windows 特殊路徑在核准前先擋下

像行李分揀系統先剔除標籤格式異常的行李，不讓它進入後續運送流程。遠端讀檔、還原工作階段、載入 CLAUDE.md、workflow script 與上傳檔案，現在都拒絕 Windows NT-namespace 的 \??\ 路徑。這些原本仍在核准前可進行的檔案存取點，因此特別補上防線，用來降低 NTLM credential leak 的風險。它不是一般檔案路徑都不能讀，而是針對這種特殊命名空間格式。

長對話裡的權限回答不再失憶

像長途接力時把已蓋章的通行單一路傳下去，不會跑到中途又要求同一張單重新審核。很長的對話被 compact 之後，auto mode 不會再反覆重查並拒絕 sandboxed command 的網路存取。背景 subagent 跳出工具權限詢問時，這個工作階段的允許或拒絕回答也不會再遺失。前者處理對話壓縮後的網路權限，後者保住你對背景代理的選擇。

異常 API 回應不再直接當機，錯誤更好查

像實驗儀器標出缺少的讀值，卻不讓整場測試停擺，還會留下可追查的紀錄。經由第三方 gateway 的非串流備援回應，若 thinking block 少了 thinking 欄位，或 text block 少了 text 欄位，Claude Code 不再因此當機。碰上「API returned an empty or malformed response」時，錯誤訊息也會交代收到的 content type、body kind、size、request ID，以及原本 streaming request 為何失敗。

Markdown 顯示更快，也更像對話內容

像排版員把一頁講義的分隔線、特殊字元和手寫筆記一併排正，讀起來不再卡住或擠成一團。少見 Unicode 字元序列的訊息不會再讓 markdown rendering 慢到難以使用，--- horizontal rule 也不再黏到下一行。你自己輸入的 prompt 現在同樣會用 markdown 顯示，包含 highlighted code block、inline code 與 list，和回覆的呈現方式一致。這些改動都在整理對話文字如何被畫出來。

代理訊息與清單不再把長名稱看錯

從 ListAgents 複製 recipient 後，即使 session name 剛好到 200-character cap，或塞了很多 emoji，SendMessage 也不會再拒收。帳號的 session list 太長而無法完整檢查時，SendMessage 和 ListAgents 現在會明說，不能再把沒看見的工作階段當成不存在。像圖書館員查閱很長的索引，既能依完整條目找書，也會標出尚未核對的卷冊。

Git remote 會辨識正確主機

git remote 的網址帶有特殊 userinfo 時，repository detection 過去可能讀錯 host，讓連結指向錯誤主機，也讓依 repository 而定的行為套用到不對的地方。現在它會抓到正確的 host，連結與依 repository 區分的行為也回到該去的位置。像導航讀到地址中的特殊註記時，仍能辨認目的地，不會把註記當成城市。

MCP 診斷不再露出機密

檢查 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）diagnostic 時，畫面不再印出已解析的 secret。scope conflict warning 會保留設定中的 ${VAR} 形式；connection failure detail 則只顯示 server origin。像檢驗報告保留欄位名稱與檢體來源，卻不把檢體內容攤在走廊給人看。

市集來源白名單會核對真正連線主機

strictKnownMarketplaces 的 allowlist 現在不會接受一個看似允許、但 Git 實際連線主機不同的 SCP-style git marketplace source。這是修正來源檢查與真正連線位置不一致的問題；設定了嚴格白名單時，檢查對象會對準 Git 真正要連去的 host。像航空管制核對飛機實際使用的呼號是否在許可名單上，而不只看飛行計畫表的名稱。

登入連結與登入提醒各自送到對的人

全螢幕複製 /login 的 OAuth URL 等 modal 文字時，不會再遺失字元。當 Anthropic profile credential 已過期，且 claude.ai login 會優先處理時，畫面會指向 /login。若 /login 後仍設定 CLAUDE_CODE_OAUTH_TOKEN，舊 token 的提醒只會給你看，不會漏進 Claude 自動延續的 turn。像自助入口螢幕給你完整通行碼，把過期憑證帶到正確的登入入口，提醒只留在你的螢幕上。

執行中仍可開設定對話，佇列指令也不走樣

Claude 正在工作時，/permissions 的規則修改會套用到目前 turn 的剩餘部分；/add-dir <path> 也能使用。全螢幕 TUI 中，/add-dir、/autocompact、/theme、/help、/config、/advisor 可在中途開啟。正在跑 ! shell command 時開 /permissions 等 dialog 不會在指令結束後被關掉；佇列中的 ! 指令經上箭頭編輯，也不會被當 plain text 送給 model。像直播導播台在播出中仍能調整設定，排隊片段也不會被當成旁白播出。

佇列訊息不再搶進歷史，也不黏住 shell 模式

還在 queued 的訊息不會再提早重現於 prompt history。選取 queued message 時按 Esc，現在不會中斷目前 turn；在中途送出後，! mode 也不會殘留黏住。這三項都在分清楚「尚未送出」和「已送去執行」的界線，避免操作佇列時干擾正在進行的工作。像餐廳叫號單仍掛在等候板時，不會先跑進已完成紀錄，也不會把取消鈴誤當成叫停整間廚房。

全螢幕重啟不再遺失限制規則

新的 fullscreen renderer 提示被接受後重啟 session 時，permission mode、tool allow/deny rule、model 與 effort flag 不會再遺失。/tui 若發現目前 session 有它無法帶過重啟的 --allowed-tools 或 --disallowed-tools restriction，現在會拒絕切換並說明原因。它不再假裝重啟後還保有其實帶不走的限制。像搬家交接清單，確認受限制物品也能完整帶走才換房；帶不走時，交接人會先說明不能搬。

權限提問會對準正確範圍與正確回答

某個目錄先被看見、後來才在那裡出現 repository 時，trust prompt 現在會帶出 repository-wide scope warning。IDE 的 diff tab 剛好在 permission re-prompt 期間關閉，也不會把上一題的 input 套給新題目。前者補回你該知道的信任範圍，後者確保每次提問只收自己的回答。像簽核表補上整份合約適用範圍，並在換一張表單時不把上一張的簽名誤蓋過去。

遠端控制傳檔、切帳號與跨裝置資訊更可靠

Claude Code Desktop 或 VS Code 主持的 Remote Control session 傳給使用者的檔案，現在會 upload，因此在 phone 和 web 開啟時不再只看到 empty card。這台電腦登入不同 claude.ai account 或 organization 時，正在執行的 session 會在幾秒內停止並說明原因，不再拖到 HTTP 404。permission mode 的改變會同步給 phone 和 claude.ai/code，後者也會收到 model；phone 或 claude.ai/code 選的 effort 會套用到 terminal、Desktop、VS Code 主持的 session，並發布給連線 client。像遠端會議室把檔案送到每位與會者手中；換了門禁身分就結束舊會議，螢幕同步顯示規則。

權限預覽既不外送也不遮住關鍵內容

permission preview 現在只 relay 給通過 inbound trust gate 的 channel server，也尊重 server 明確表示不提供 permission capability 的選擇。relay 時的 credential masking 不會再把 command、path 或 destination 一起遮掉，讓 approver 看不見該核准什麼；過大的 private-key block 則會用完整強度 redaction。provider API token 即使緊接 shell delimiter，也會被 mask。像保全只把申請單交給已驗證的窗口，該遮住的密碼遮住，收件地址與申請內容卻仍讓核准者看清。

Desktop 跨工作階段訊息不再悄悄遺失

Claude Desktop 的 inter-session message 在接收端把 cross-session messaging 讀成 disabled 時，過去會被悄悄丟掉，送出端的 query 便長時間停在「thinking」。現在接收 session 不會再因為這個讀取錯誤而丟訊息。修的是訊息傳遞的錯誤判讀，讓送出端不會因為收件端其實沒收到而一直等待。像電話總機不再把誤判為被攔截的通話直接掛斷，來電者也不用對著沒有回音的線路等候。

自動產生的工作階段名稱更像標籤

自動產生的 session title 現在偏向短而具體的名稱，例如「Login button bug」，不再只是把你的請求整句重述成「Fix the login button on mobile」。名稱仍是自動生成，但用途從重複一遍對話內容，改為替之後回看時提供更快辨識的標籤。像電影院場次表只寫片名，不重播整段預告；短名讓你一眼認出要找的那場。

內建 claude-api 技能載入少花上下文

載入內建 claude-api skill 時，context cost 已從約 200k+ tokens 降到約 25k tokens。做法是 reference doc 改成按需要才載入，而不是一開始全塞進 context。token（AI 處理與計費的文字單位）這裡指模型讀取文字所用的量；技能仍可用，只是先帶進對話的參考資料變少。像出門先帶常用工具箱，等真的需要某份說明書才去抽取，而非把整個倉庫都搬上車。

目標遇到不可復原錯誤會清楚收尾，也會追問背景工作

turn 因 revoked auth、exhausted credit balance 或 context overflow 這類不可復原錯誤結束時，/goal 會自行清掉並通知你，不再保持 armed 狀態。background task 讓 goal 等了 30+ minutes 時，Claude 會去 check in，不再無限等待；若不想要這個動作，可設定 CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0。像待辦清單發現任務已因無法修復的原因中止，就把它標示結束；等候太久的委託則主動問一次進度。

setup-token 多打一個參數也會被攔下

執行 claude setup-token 時，預期之外的 extra argument 不會再被靜靜忽略，現在會直接拒絕。這可避免你以為多打的內容被採用，實際卻完全沒有作用；指令接受或拒絕的範圍會明白表現出來。要設定 token 時，請只輸入此命令預期的參數。像門禁掃描器收到多出的一張卡，會當場報錯，不把它假裝算進通行紀錄。

工具畫面少掉重複標籤，重點更容易看

auto mode 原本每個 Agent tool call 下方都重複顯示「Allowed by auto mode classifier」，這行現在移除了。正在執行的 tool header 裡，elapsed-time counter 也調暗，不再和粗體 count 搶視線。兩者都不是功能權限改變，而是把已經呈現的工具活動資訊整理得更不擁擠。像儀表板拿掉每格都重複的核准貼紙，並把次要的時間字淡化，眼睛自然先看到真正需要注意的數字。

代理團隊沿用領隊模型

/config 裡的「Default teammate model」設定已移除。agent-team 的 teammate 現在會沿用 leader 的 model，只有在 spawn 時明確指定才會用另一個。這是既有選擇規則的調整，不是新增另一個預設模型。像同一組樂團照指揮選定的曲譜演奏，只有開演前特別指派的樂手才拿不同版本。

背景通知沿用同一種標記格式

背景工作在兩個 turn 之間送來 notification 時，model 現在會在 <system-reminder> tags 內收到，與 turn 中途送達的格式一致。這項調整統一通知的外框，讓不同時點送達的內容採用同一種標記。背景工作仍是在兩個 turn 之間送達；改的是 model 收到它時所看見的外層格式。像舞台監督無論在演出中或換場時遞提示卡，都放進同樣的提示套。

Mantle 啟動少做一次不必做的探查

Mantle 啟動時，如果 main-loop model 已經選好，現在會略過 admin-pin availability probe。原本那個 probe 是在確認 admin-pin 是否可用；既然主迴圈模型已有選擇，這個條件下就不再進行該項啟動檢查。此項是縮減啟動流程裡不需要的探查，沒有新增一個管理 PIN 設定。像出門前既然已拿到指定鑰匙，就不用再回頭逐一檢查另一串備用鑰匙。

唯讀設定檔不再讓 Windows 啟動卡住

Windows 上的 ~/.claude.json 若是 read-only，Claude Code 啟動時不會再卡在 repeated rename retry。問題出在反覆嘗試重新命名這個設定檔；現在遇到唯讀狀態時，啟動流程不會因此停滯。這不表示程式會改寫唯讀檔，而是避免無法改名時一直卡在重試。像門鎖住的檔案櫃不能搬動時，工作人員不再一直拉著把手不放，而會讓其他開門準備繼續走。

連續 shell 指令會合在正確的執行紀錄裡

連續執行 shell command 時，如果中間穿插 todo 或 task update，畫面過去可能把同一串操作拆成多個「Ran 1 shell command」列。現在不會因為這些更新插進來，就把連續指令的執行紀錄切碎。todo 與 task 的更新仍會出現，只是不再改變你看到的 shell command 分組。像會議紀錄裡插入待辦提醒後，仍把同一位講者連續說的話收在同一段，不會每插一張便條就另開一段。

Claude Desktop の inter-session message は、受信 session が cross-session messaging を disabled と読み違えても黙って捨てられず、送信側の query が “thinking” のまま残らない。電話交換台が遮断中と読み違えた通話を切らないようなものである。

自動セッション名を役立つラベルにする

自動生成 session title は “Login button bug” のように短く具体的になり、依頼文をそのまま文で繰り返さない。映画館の上映表が作品名を示し、予告編全体を流さないようなものである。

内蔵 claude-api skill の context 消費を減らす

内蔵 claude-api skill の読み込みは reference doc を必要時に読むことで、context cost が約 200k+ tokens から約 25k tokens になった。最初に工具箱を持ち、説明書は必要時だけ取りに行くようなものである。

goal は失敗 turn を片付け待機作業を確認する

revoked auth、exhausted credit balance、context overflow などの回復不能 error で turn が終わると /goal は通知して自ら解除する。background task が 30+ minutes 待たせると Claude は check in し、不要なら CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0 にする。回復不能の仕事を完了扱いにし、待たせすぎた依頼の進捗を聞くようなものである。

setup-token は余分な引数を拒否する

claude setup-token は予期しない extra argument を黙って無視せず拒否する。入退室用の読み取り機が余分なカードを受け取ると、その場でエラーにし、通行記録に含めたふりをしないようなものである。

ツール表示の余計な情報を減らす

auto mode は各 Agent tool call の下に “Allowed by auto mode classifier” を繰り返し出さない。実行中 tool header の elapsed-time counter も太字 count と競わないよう暗くなる。計器板の重複札を取り、二次的な時計を薄くするようなものである。

チームは leader model を継承する

/config の “Default teammate model” は削除され、agent-team teammate は spawn で指定しない限り leader の model を使う。楽団が指揮者の選んだ楽譜を使い、開始前に別の譜面を指定された奏者だけが例外になるようなものである。

背景通知は通常のタグで届く

turn 間に届く background task notification は、turn 中の配信と同じく model に <system-reminder> tags 内で届く。舞台監督が場面中でも場面の合間でも、同じ封筒に注意書きを入れるようなものである。

Mantle は不要な起動 probe を省く

Mantle は起動時、main-loop model が既に選ばれていれば admin-pin availability probe を省く。必要な鍵を既に持つなら予備鍵を全て確かめないようなものである。

読み取り専用設定で Windows 起動が止まらない

Windows では ~/.claude.json が read-only でも、起動が repeated rename retry で止まらない。動かせない鍵付き書庫の取っ手を延々と引かないようなものである。

連続 shell command を正しい実行記録にまとめる

連続する shell command は、途中に todo または task update が入っても複数の “Ran 1 shell command” 行に分割されない。途中にメモを挟んでも同じ話者の連続発言を一段落に収めるようなものである。

프로젝트별 대화 기록에 짧은 이름을 붙인다

문서 보관소에서 프로젝트별 기록에 짧은 관리 번호를 붙이고 선반 위치는 그대로 두는 일과 같다.세션마다 설정 디렉터리를 따로 두는 호스트에서는 CLAUDE_CODE_PROJECT_DIR_NAME으로 프로젝트별 transcript 디렉터리의 짧은 이름을 정할 수 있다. Claude Code를 시작하는 호스트에서 CLAUDE_CODE_PROJECT_DIR_NAME=project-a로 설정하면 프로젝트 transcript 디렉터리는 project-a를 쓴다.

선택 영역을 의도적으로 지운다

나가기 버튼이 형광 표시까지 지우지 않고 전용 지우개를 두는 것과 같다.selection:clear을 키에 연결하면 agents view에서도 앱 안의 글자 선택을 지울 수 있다. 전체 화면의 Esc는 마우스 선택을 지우지 않고 기존처럼 중단하거나 닫는다.

GitLab 병합 요청 상태를 표시한다

경기장 전광판이 경기 상태를 그때그때 보여 주는 것과 같다.GitLab remote가 있고 glab CLI에 인증된 저장소에서는 바닥글과 statusline에 MR !N 및 초안, 대기, 녹색 상태가 표시된다.

사용량 한도가 재설정되면 자동으로 이어 간다

재생할 수 있게 된 플레이어가 멈춘 자리에서 다시 재생되는 것과 같다.claude.ai 사용량 한도가 재설정되면 Claude Code가 세션을 자동으로 계속할 수 있다. 원하지 않으면 /config의 “Continue automatically at usage limit”을 끄면 된다.

계정 이메일은 본인 식별에만 쓴다

창구가 신분증을 확인한 뒤 돌려주고 다른 가게에 가져가지 않는 것과 같다.Claude는 계정 email을 본인 식별에만 쓰며, 요청하지 않는 한 관련 없는 서비스에 보내지 않도록 지시받는다.

위험한 Windows 네임스페이스 경로를 미리 거절한다

공항 수하물 분류기가 라벨 형식이 이상한 짐을 이후 운송 과정에 보내기 전에 골라내는 것과 같다.원격 파일 읽기, 세션 복원, CLAUDE.md include, workflow script, 파일 업로드는 이제 Windows NT-namespace \??\ 경로를 거절한다. 승인 전 파일 접근의 NTLM credential leak 위험을 낮춘다.

긴 세션에서도 권한 응답을 지킨다

도장이 찍힌 통행증을 릴레이로 계속 넘기는 것과 같다.긴 대화가 compact된 뒤에도 auto mode는 sandboxed command의 네트워크 접근을 반복 확인해 거절하지 않는다. background subagent 권한 질문에 대한 세션 범위 허용과 거절도 사라지지 않는다.

비정상 API 응답으로 멈추지 않고 이유를 보인다

실험 장비가 빠진 측정값을 표시해도 시험 전체를 멈추지 않는 것과 같다.서드파티 gateway의 비스트리밍 대체 응답에 thinking 또는 text 필드가 없어도 Claude Code가 멈추지 않는다. 비어 있거나 잘못된 API 응답 오류는 content type, body kind, size, request ID와 streaming 실패 이유를 보인다.

Markdown을 빠르고 일관되게 표시한다

편집자가 특수 문자와 구분선과 메모를 함께 가지런히 놓는 것과 같다.드문 Unicode 시퀀스로 markdown rendering이 극도로 느려지지 않고 ---도 다음 줄과 붙지 않는다. 사용자의 prompt도 code block, inline code, list를 포함해 답변처럼 markdown으로 표시된다.

긴 세션 이름과 목록을 제대로 다룬다

ListAgents에서 복사한 recipient는 session name이 200-character cap에 닿거나 emoji가 많아도 SendMessage가 거절하지 않는다. session list를 완전히 확인할 수 없을 만큼 길면 두 명령이 이를 알린다. 사서가 긴 목록을 쓰면서 아직 확인하지 못한 권을 밝히는 것과 같다.

Git remote의 올바른 host를 찾는다

특이한 userinfo가 있는 git remote에서도 repository detection이 host를 잘못 읽지 않아 link와 repository별 동작이 올바른 host를 쓴다. 주소 안에 특이한 메모가 있어도 내비게이션이 실제 목적지를 알아보는 것과 같다.

MCP diagnostic이 secret을 드러내지 않는다

MCP diagnostic은 해석된 secret을 출력하지 않는다. scope conflict warning은 설정된 ${VAR}를 보이고 connection failure 세부 정보는 server origin만 보인다. 검사 보고서가 항목 이름과 검체 출처는 남기되 검체 자체는 드러내지 않는 것과 같다.

마켓플레이스 허용 목록은 실제 Git 호스트를 확인한다

strictKnownMarketplaces allowlist는 Git이 실제로 연결할 host와 다른 SCP-style git marketplace source를 받아들이지 않는다. 항공 관제가 비행 계획서의 이름만 보지 않고 항공기가 실제로 쓰는 호출 부호를 허용 목록과 대조하는 것과 같다.

로그인 정보를 알맞은 대상에게 보낸다

전체 화면에서 /login OAuth URL 같은 modal text를 복사해도 글자가 빠지지 않는다. 만료된 profile credential은 claude.ai login이 우선될 때 /login을 가리키며 오래된 CLAUDE_CODE_OAUTH_TOKEN 알림은 사용자에게만 보이고 자동 재개 turn에는 들어가지 않는다. 무인 출입 화면이 온전한 코드를 보여 주고 만료된 credential을 올바른 로그인으로 안내하며 알림은 본인 화면에만 남기는 것과 같다.

실행 중 조작과 대기 shell command를 제대로 다룬다

Claude가 작업 중이어도 /permissions 변경은 현재 turn의 나머지에 적용되고 /add-dir <path>도 쓸 수 있다. 전체 화면 TUI dialog를 중간에 열 수 있으며 실행 중인 ! command가 끝나도 닫히지 않고 편집한 대기 ! command도 plain text가 되지 않는다. 생방송 조정실이 방송 중 설정을 바꿔도 대기 영상이 내레이션이 되지 않게 하는 것과 같다.

대기 입력을 대기 상태로 유지한다

queued message는 대기 중에 prompt history에 다시 나타나지 않는다. 선택한 queued message에서 Esc를 눌러도 turn이 중단되지 않으며 중간 submit 뒤 ! mode도 남지 않는다. 대기 표를 처리 전 완료 기록으로 옮기지 않는 것과 같다.

전체 화면 재시작에서 제한을 잃지 않는다

“Try the new fullscreen renderer?”를 받은 뒤 session을 재시작해도 permission mode, tool rule, model, effort flag가 사라지지 않는다. /tui는 --allowed-tools 또는 --disallowed-tools restriction을 재시작에 가져갈 수 없으면 이유를 밝히고 전환을 거절한다. 이사 인계에서 제한된 물건까지 모두 넘길 수 있는지 확인한 뒤 방을 옮기는 것과 같다.

권한 확인의 범위와 답을 혼동하지 않는다

directory를 먼저 본 뒤 나중에 repository가 생긴 경우에도 trust prompt가 repository-wide scope warning을 보인다. permission re-prompt 중 IDE diff tab이 닫혀도 이전 input을 새 prompt에 쓰지 않는다. 계약 범위를 보태고 새 서류에 옛 서명을 옮기지 않는 것과 같다.

Remote Control 전송과 동기화를 제대로 한다

Claude Code Desktop 또는 VS Code가 주최한 Remote Control session의 파일은 upload되어 phone과 web에서 열린다. 이 컴퓨터가 다른 account 또는 organization에 로그인하면 session은 몇 초 안에 이유를 알리고 멈춘다. Desktop 또는 VS Code가 호스트하는 session은 permission mode 업데이트를 phone 및 claude.ai/code에, model 업데이트를 claude.ai/code에 보낸다. phone 또는 claude.ai/code에서 고른 effort는 terminal 및 Desktop/VS Code가 호스트하는 session에 적용되며, session은 effort level을 연결된 client에 게시한다. 원격 회의에서 자료를 모두에게 전달하고 모든 화면의 규칙을 맞추는 것과 같다.

권한 미리보기를 알맞게 전달하고 승인 내용을 지킨다

permission preview는 inbound trust gate를 통과한 channel server에만 relay되고 permission capability opt-out도 존중한다. masking은 approver에게 command, path, destination을 가리지 않으며 큰 private-key block은 redaction하고 provider API token은 shell delimiter 바로 뒤에 있어도 redaction한다. 인증된 창구에만 신청서를 주고 비밀은 가리되 승인 내용은 보이게 하는 것과 같다.

Desktop 세션 간 메시지를 잃지 않는다

Claude Desktop inter-session message는 수신 session이 cross-session messaging을 disabled로 잘못 읽어도 조용히 버려지지 않아 보내는 쪽 query가 “thinking”에 머물지 않는다. 전화 교환대가 막힌 통화로 잘못 읽은 연결을 끊지 않는 것과 같다.

자동 세션 제목을 쓸모 있는 라벨로 만든다

자동 생성 session title은 “Login button bug”처럼 짧고 구체적인 이름을 쓰며 요청 문장을 그대로 되풀이하지 않는다. 영화관 상영표가 영화 제목만 보여 주고 예고편 전체를 다시 틀지 않는 것과 같다.

내장 claude-api skill의 context 소비를 줄인다

내장 claude-api skill을 불러오는 context cost는 reference doc을 필요할 때 불러와 약 200k+ tokens에서 약 25k tokens로 줄었다. 먼저 공구함을 들고 설명서는 필요할 때 가져오는 것과 같다.

goal은 실패한 turn을 정리하고 대기 작업을 확인한다

revoked auth, exhausted credit balance, context overflow 같은 복구 불가능 error로 turn이 끝나면 /goal은 알리고 스스로 해제된다. background task가 30+ minutes 기다리게 하면 Claude가 check in하며 원하지 않으면 CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0으로 둔다. 복구 불가능한 일을 종료 표시하고 너무 오래 기다린 의뢰의 진행을 묻는 것과 같다.

setup-token은 뜻밖의 인자를 거절한다

claude setup-token은 뜻밖의 extra argument를 조용히 무시하지 않고 거절한다. 출입 통제 스캐너가 여분의 카드를 받으면 즉시 오류를 알리고, 그것을 출입 기록에 넣은 척하지 않는 것과 같다.

도구 화면의 불필요한 정보를 줄인다

auto mode는 모든 Agent tool call 아래에 “Allowed by auto mode classifier”를 반복해 보이지 않는다. 실행 중 tool header의 elapsed-time counter도 굵은 count와 경쟁하지 않게 흐려진다. 계기판의 중복 승인 표지를 빼고 보조 시계를 옅게 하는 것과 같다.

팀은 leader model을 따른다

/config의 “Default teammate model” 설정은 사라졌고 agent-team teammate는 spawn에서 지정하지 않는 한 leader의 model을 쓴다. 오케스트라가 지휘자가 고른 악보를 쓰고 시작 전에 다른 파트를 지정받은 연주자만 예외가 되는 것과 같다.

background notification이 같은 tag로 온다

turn 사이에 도착하는 background task notification은 turn 중 전달과 마찬가지로 model에 <system-reminder> tags 안에서 도착한다. 무대 감독이 장면 중이든 장면 사이든 같은 봉투에 안내문을 넣는 것과 같다.

Mantle은 불필요한 시작 probe를 건너뛴다

Mantle은 시작할 때 main-loop model이 이미 선택되어 있으면 admin-pin availability probe를 건너뛴다. 필요한 열쇠를 이미 들었으면 예비 열쇠를 모두 확인하지 않는 것과 같다.

읽기 전용 설정이 Windows 시작을 멈추지 않는다

Windows에서 ~/.claude.json이 read-only여도 시작이 repeated rename retry에서 멈추지 않는다. 움직일 수 없는 잠긴 서류장의 손잡이를 끝없이 당기지 않는 것과 같다.

연속 shell command를 올바른 실행 기록에 묶는다

연속 shell command는 사이에 todo 또는 task update가 들어와도 여러 “Ran 1 shell command” 행으로 나뉘지 않는다. 중간에 메모가 있어도 같은 화자의 이어진 말을 한 단락에 두는 것과 같다.
