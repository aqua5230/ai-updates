Claude Code 2.1.234

Released: 2026-08-17

Release notes

FEATURE

Short names for project transcripts

It is like an archive giving each project file a short reference code while leaving it on the same shelf.

Hosts that give each session its own config directory can set CLAUDE_CODE_PROJECT_DIR_NAME to choose a short per-project transcript directory name.

On the host that starts Claude Code, set CLAUDE_CODE_PROJECT_DIR_NAME=project-a so the project's transcript directory uses project-a.

FEATURE

Clear selections deliberately

It is a dedicated eraser, not an exit button that wipes your highlight.

Bind a key to selection:clear to clear an in-app text selection, including in agents view.

In fullscreen, Esc keeps a mouse selection highlighted while still interrupting or dismissing.

FEATURE

GitLab merge-request status at a glance

It is like a stadium scoreboard showing a match’s state as it changes.

Repositories with a GitLab remote and authenticated glab now show MR !N and draft, pending, or green status in the footer and statusline.

FEATURE

Resume when a usage limit resets

It is like resuming a paused player when playback becomes available.

Claude Code can now continue your session when a claude.

ai usage limit resets. Turn it off in /config under “Continue automatically at usage limit.”

FEATURE

Your account email stays for identification

It is like a clerk checking an ID and handing it back.

Claude is instructed to use your account email only to identify you, and not send it to unrelated services unless you ask.

FEATURE

Block risky Windows namespace paths early

It is like a baggage-sorting system removing luggage with a malformed tag before it enters the delivery line.

Remote reads, session restore, CLAUDE.

md includes, workflow scripts, and uploads now reject Windows NT-namespace \??\ paths, hardening remaining pre-approval access against NTLM credential leaks.

BUGFIX

Permissions stay put in long sessions

It is like passing the stamped pass along a relay.

After a long conversation is compacted, auto mode no longer repeatedly rechecks and denies sandboxed commands’ network access.

Session-scoped allow and deny answers also persist for background subagent permission prompts.

FEATURE

API response failures no longer fail silently

It is like a lab instrument flagging incomplete readings without stopping the whole test.

A non-streaming fallback response with a missing thinking or text field no longer crashes Claude Code.

Empty or malformed API errors now report content type, body kind, size, request ID, and why streaming failed.

FEATURE

Markdown renders cleanly and consistently

It is like a typesetter aligning special characters, rules, and notes together.

Unusual Unicode sequences no longer make markdown rendering extremely slow, and --- no longer runs into the next line.

Your prompts now render markdown like replies, including code blocks, inline code, and lists.

FEATURE

Agent messaging handles long session lists

SendMessage accepts recipients copied from ListAgents even at the 200-character session-name cap or with many emoji.

Both commands now say when the session list was too long to check completely.

It is like a librarian using a long catalogue entry while marking the volumes not yet checked.
BUGFIX

Git remote detection finds the right host

Repository detection now reads unusual git-remote userinfo without choosing the wrong host, so links and repository-specific behavior use the right host.

It is like navigation recognizing the real destination despite an unusual note in the address.
BUGFIX

MCP diagnostics keep secrets out of view

MCP diagnostics no longer print resolved secrets: scope-conflict warnings show configured ${VAR}, and connection-failure details show only the server origin.

It is like a medical report retaining the field names and specimen origin without exposing the sample itself.
BUGFIX

Marketplace allowlists check the real Git host

strictKnownMarketplaces allowlists no longer accept an SCP-style Git marketplace source whose host differs from where Git will actually connect.

It is like air traffic control checking an aircraft's actual call sign against an approved list, not only the name on its flight plan.
FEATURE

Login links and reminders reach the right place

Fullscreen copying keeps all characters in modal text such as a /login OAuth URL.

Expired profile credentials point to /login when a claude.ai login would take precedence, and stale CLAUDE_CODE_OAUTH_TOKEN reminders appear only to you, not Claude’s resumed turn.

It is like a self-service entry screen giving you the complete code, directing an expired credential to the right login, and keeping the reminder on your screen.
FEATURE

Mid-turn controls and queued shell commands behave

While Claude works, /permissions changes apply to the rest of the turn and /add-dir <path> works.

Fullscreen TUI dialogs can open mid-turn; dialogs survive a running ! command, and edited queued ! commands stay shell commands.

It is like a live control room changing settings during a broadcast without turning queued clips into narration.
BUGFIX

Queued input stays queued

Queued messages no longer reappear in prompt history while queued; Esc on a selected queued message does not interrupt the turn, and ! mode no longer sticks after a mid-turn submit.

It is like keeping a waiting ticket on the board until it is served.
BUGFIX

Fullscreen restarts keep restrictions honest

Restarting after “Try the new fullscreen renderer?” preserves permission mode, tool rules, model, and effort flags.

/tui declines a switch when it cannot carry --allowed-tools or --disallowed-tools restrictions through restart.

It is like a moving inventory that switches rooms only after every restricted item can be handed over.
BUGFIX

Permission prompts keep their scope and answer

Trust prompts now include the repository-wide scope warning when a repository appeared after its directory was first seen.

Closing an IDE diff tab during a re-prompt no longer applies the previous input to the new prompt.

It is like adding the contract scope and never copying an old signature to a new form.
FEATURE

Remote Control stays in sync and stops safely

Remote Control files from Desktop or VS Code now upload for phone and web.

Signing this computer into another account or organization stops the session within seconds with a reason. Sessions hosted by Desktop or VS Code send permission-mode updates to phone and claude.ai/code, and model updates to claude.ai/code. Effort chosen on a phone or claude.ai/code applies to terminal and Desktop/VS Code-hosted sessions; the session also publishes its effort level to connected clients.

It is like a remote meeting that actually hands out the file and updates every screen’s rules.
BUGFIX

Permission previews share less and show approvers enough

Permission previews relay only to trusted channel servers and honor permission-capability opt-out.

Masking no longer hides commands, paths, or destinations from approvers, while large private keys remain redacted and provider API tokens remain redacted even when immediately followed by shell delimiters.

It is like giving a request to a verified desk with secrets covered but the approval details visible.
BUGFIX

Desktop cross-session messages arrive

Claude Desktop inter-session messages are no longer silently dropped when the recipient reads cross-session messaging as disabled, leaving the sender stuck “thinking.

”

It is like a telephone switchboard no longer disconnecting a call it misread as blocked.
FEATURE

Auto session titles become useful labels

Auto-generated session titles now favor short, specific names such as “Login button bug” instead of restating the request as a sentence.

It is like a cinema schedule showing a film title, not replaying the whole trailer.
FEATURE

The built-in claude-api skill uses less context

Loading the built-in claude-api skill now costs about 25k tokens instead of about 200k+ by loading reference docs on demand.

It is like taking the toolbox first and fetching a manual only when needed.
FEATURE

Goals clear failed turns and check on waiting work

/goal clears itself with notice after unrecoverable errors.

When background tasks keep it waiting 30+ minutes, Claude checks in; set CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0 to opt out.

It is like closing an irrecoverably failed task and asking for progress on one that waits too long.
FEATURE

setup-token rejects stray arguments

claude setup-token now rejects unexpected extra arguments instead of silently ignoring them.

It is like an access-control scanner receiving an extra card: it flags the error immediately rather than pretending it belongs in the entry log.
FEATURE

Tool activity has less visual noise

Auto mode no longer repeats “Allowed by auto mode classifier” below every Agent tool call, and the running tool header dims its elapsed-time counter beside bold counts.

It is like removing duplicate approval stickers and fading a secondary clock on a dashboard.
FEATURE

Teams inherit the leader model

The /config “Default teammate model” setting is gone: agent-team teammates use the leader’s model unless spawn names one.

It is like an orchestra using the conductor’s chosen score unless a player is assigned a different part before starting.
FEATURE

Background notifications use the usual tags

Between-turn background task notifications now reach the model inside <system-reminder> tags, matching mid-turn delivery.

It is like a stage manager putting reminders in the same sleeve whether they arrive during a scene or between scenes.
FEATURE

Mantle skips an unnecessary startup probe

At startup, Mantle skips the admin-pin availability probe when a main-loop model is already selected.

It is like not checking every spare key once you already have the required one.
FEATURE

Read-only settings no longer stall Windows startup

On Windows, startup no longer stalls on repeated rename retries when ~/.claude.json is read-only.

It is like not endlessly tugging a locked filing cabinet that cannot be moved.
BUGFIX

Consecutive shell commands keep one accurate record

Consecutive shell commands no longer split into multiple “Ran 1 shell command” rows when todo or task updates occur between them.

It is like keeping one speaker’s continuous remarks in one paragraph despite inserted notes.
