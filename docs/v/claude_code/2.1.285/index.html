Claude Code 2.1.285

發布日期：2026-09-29

繁體中文

新功能

終端機指令直開桌面版，直接接續既有對話

在黑底白字命令列工作到一半想換到視窗介面，現在只要一行指令就能切換。

你在終端機使用 Claude Code 時，輸入 claude --desktop 就能直接在當前目錄啟動桌面版應用程式。若是想接續剛剛聊到一半的工作階段，只要加上 --continue 或指定代碼 --resume <id>，系統就會把既有對話完整搬進視窗中。

如同把隨身口袋筆記本的草稿，直接攤開到寬敞的辦公桌上繼續寫，排版與脈絡完全不受中斷。
新功能

外掛安裝支援預先設定，MCP 伺服器即裝即用

安裝擴充外掛時如果每次都要事後手動翻找選單填寫參數，流程往往被打斷。

現在透過 claude plugin configure <外掛名稱> 指令，你可以直接查看該外掛的所有設定項與未填欄位，也能搭配 --values-stdin 從標準輸入（stdin）一次灌入數值。安裝打包好 MCP（讓 AI 連接外部工具的協定）伺服器的外掛時，支援在 claude plugin install --config 後方直接加上 <伺服器>.<鍵>=<值> 帶入參數。過去如果外掛內建的伺服器缺少設定，系統常會默默跳過執行；現在不論在安裝提示或外掛清單中，都會主動提醒你前往設定。

宛如買新家電時隨箱附上客製化組裝單，在拆箱當下就把零件卡入定位，不必開機後再到處找螺絲起子設定。
新功能

外掛辨識更加嚴謹，SSH 與市集網址驗證更清楚

管理社群外掛時，名稱的細微差異可能讓安裝或開關動到別的外掛。

以前透過 SSH 下載外掛或市集清單，會忽略環境變數 GIT_SSH 與 Git 設定 core.sshCommand 指定的程式，現在會套用。兩個外掛的識別名稱若只差 .、-、@，或在 macOS、Windows 上只差大小寫，安裝時可能誤用已安裝外掛的快取（把查過的結果暫存起來直接用）或資料資料夾；現在會拒絕安裝。以完整的 name@marketplace 名稱啟用或停用外掛，也不會改到另一種大小寫的設定。外掛、市集及目前版本庫遠端的 Git 網址都會接受更完整的檢查；市集網址被拒時，畫面會說明原因。

新功能

企業政策集中管控，專案設定不得覆寫安全沙盒

公司要限制 Claude Code 可走哪些 API 供應管道時，管理員可在集中管理設定用 allowedProviders 指定範圍。

專案設定不能放寬或關閉管理員要求的沙盒（限制程式可存取範圍的環境），也不能替換受管理封鎖清單保護的代理伺服器、擴大嚴格允許清單，或重新開放被禁止讀取的檔案。透過 ANTHROPIC_AUTH_TOKEN 登入 Anthropic API 的工作階段，現在會載入組織政策。團隊、企業，以及無法判定登入方案的工作階段，若啟動時未能載入政策，會先暫停 WebFetch。作業系統拒讀管理設定檔時，Claude Code 會警告並在沒有該檔政策的情況下啟動；其他讀取錯誤或檔案無法解析，則會停止工作階段。

公司大樓若已規定哪些門要上鎖，各部門不能自行拆鎖；守門人還沒拿到通行名單時，也會先暫停放行。
新功能

支援停用網頁擷取，網址安全檢查錯誤回報更精準

當你不希望 Claude Code 自行抓取網頁資料，可用環境變數 CLAUDE_CODE_DISABLE_WEB_FETCH 關閉 WebFetch（網頁擷取工具）。

網址安全檢查的錯誤訊息也修正了：過去網域檢查遇到速率限制（短時間請求太多而被暫時限制），可能被誤報為網路問題或企業政策封鎖；現在會顯示請求頻率受限。

就像把某一項服務的開關關掉，旁邊的故障燈也會分清楚是使用次數受限，還是連線出了問題。
新功能

子代理完整繼承父層權限，背景執行回報不灌水

讓子代理（代理人分派的子工作單元）協助處理任務時，結果與權限現在更容易掌握。

使用 CLAUDE_CODE_FORK_SUBAGENT=1 執行 claude -p，子代理再呼叫 Agent 時會在前台執行，因而拿得到下一層代理人的結果。使用 claude -p --permission-prompt-tool 時，背景子代理的權限請求會交給指定的審批工具，不再自動被拒。分支子代理會繼承工作階段中父層的權限模式，包括計畫模式與 dontAsk，也不能自行離開計畫模式。自動模式下，背景子代理回報後不再要求第二次回覆；子代理把報告交回呼叫者，也會直接結束。

調查小組的成員帶著同一份授權出門，查完交回報告就收工，不必再補一封沒人需要的回信。
新功能

自動模式支援第三方平台，指令執行預設更俐落

若你串接其他模型供應商，或關閉了遙測（傳回使用狀況的診斷資料），現在也會收到切換權限的一次性提示。

這項提示會在使用者設定為其他模式時出現；自動模式（讓 Claude 依權限設定連續執行的模式）是可選的新預設。在這些環境下執行 claude -p 或 Python Agent SDK（供程式呼叫代理人的工具組）工作階段時，若未設定權限模式，會像互動式工作階段一樣直接以自動模式啟動，亦可用 --permission-mode 覆寫。

同一套作業流程搬到另一個工作地點，原本的預設選項仍會出現；沒有選定模式的工作，則照既定預設開始。
新功能

背景命令設定逾時上限，工作階段管理與切換更順手

把 Bash 或 PowerShell 命令放到背景執行時，現在預設 30 分鐘後停止，最長可設為 2 小時；命令因逾時停止，Claude 會收到通知。

/tasks 會把 Claude Code 自己執行的背景工作收在「System tasks」一列，按 Enter 可展開。背景中的工作階段現在可用 /resume 或 claude --resume 開啟；使用 claude --resume <id> "prompt" 時，附帶文字才會送成下一輪對話。背景工作階段，以及由 Claude Code 工具啟動的工作階段，不能開啟自動記憶，但仍可將它關閉。從 claude agents 回覆等待權限的背景工作階段，也不會意外核准待審命令。

新功能

遠端控制訊息不遺漏，插話提問能掌握進行中進度

從其他裝置透過遠端控制送出訊息和附件時，檔案若因網路錯誤、逾時或伺服器錯誤下載失敗，現在最多會重試兩次。

排隊訊息會等 Claude 開始處理才標為已讀；終端機若先關閉，未處理的訊息會在下次恢復工作階段時送達。在 Claude Desktop 等應用程式託管的工作階段，使用 /btw 問旁支問題，現在能看到正在進行的回合，不再只看到上一輪。遠端控制客戶端也不能執行 /claude-api。

像寄件追蹤會等包裹真正交到收件人手上才標記送達；還在途中，就留待下次配送。
新功能

Chrome 連線辨識主機名稱，設定指引更明確

讓 AI 操作瀏覽器進行網頁自動化時，跨電腦連線的管理介面變得更容易辨識。

本機端程式現在會主動向瀏覽器回報電腦名稱，多台裝置連線時不再只顯示籠統的序號標籤。在終端機輸入 /config chrome=true 時，系統會引導你開啟設定面板完成配置，而輸入 chrome=false 則可直接關閉連線。同時，遠端控制的說明文件也修正了參數預設值說明：遠端衍生出的工作階段預設不會開啟瀏覽器控制，除非在啟動時明確附上 --chrome 參數。

就像藍牙耳機連線清單能清楚顯示筆電與手機的專屬裝置名，不再全部顯示為未知名稱，讓人一眼就能確認連線對象。
問題修復

雲端工作階段全面修復，環境載入與工具快取更順暢

在雲端接續一段壓縮過的對話時，現在可以更新該工作階段先前讀取或發布的工件檔案。

建立雲端工作階段或使用 /remote-env，也不再只看得到最新 20 個環境。若在雲端環境變數中設定 MCP_DISCOVERY_CACHE=1，重啟後會重用連接器的工具清單；其他 MCP（讓 AI 連接外部工具的協定）伺服器不再快取，並在啟動時連線。開場回覆的短暫延遲、還沒上傳檔案就誤報上傳資料夾遺失，也已修正。按下排程的「立即執行」時，若在啟動前被拒，畫面會顯示與該排程失敗通知相同的說明，不再露出內部錯誤文字。

新功能

MCP 指令列輸出過濾跳脫字元，安全隱藏外掛設定值

在終端機管理 MCP（讓 AI 連接外部工具的協定）伺服器時，名稱或設定值裡的換行、終端機跳脫字元，現在不會弄亂 claude mcp list、claude mcp get 的輸出，也不會弄亂 remove、login、logout 找不到項目時的錯誤訊息。

claude mcp list 會列出 WebSocket 伺服器的網址與連線狀態。標準輸入輸出伺服器的設定若省略 type，claude mcp get 仍會顯示 Type、Command、Args、Environment。外掛提供的這類伺服器則會隱藏命令、參數及環境變數值，只顯示變數名稱。

清冊能列出每台設備及狀態，也會把不能公開的設定值遮住；設備名稱裡的特殊字元不會打亂整張表。
新功能

MCP 工具關閉即刻生效，自訂工具延遲載入更精準

在 SDK 或 -p 工作階段中，若中途新增 MCP（讓 AI 連接外部工具的協定）伺服器、之後再關閉，所屬工具現在會跟著移除，不再殘留給模型使用。

工具若以 _meta['anthropic/alwaysLoad'] 設為 false，即使所屬的 --mcp-config、Agent SDK 或外掛伺服器設為 alwaysLoad，它仍會延遲載入。雲端工作階段與自架 Runner 也把 widgets 及 widgets_ 等相近名稱保留給系統；自訂伺服器若用了這些名稱，必須改名才能載入。

工具箱中途加進一件工具又拿走後，清單會跟著更新；標明稍後再取用的工具，也不會因整箱打開就先搬出來。
新功能

工件編輯發布一步到位，對話倒帶嚴防誤覆寫

請 AI 撰寫文件、網頁或產生展示工件（artifact）時，產出與發布的流程變得更快且安全。

現在編輯或建立頁面時，系統會在同一步驟中主動建議發布，並精簡了後續提示文字以節省 Token（AI 處理與計費的文字單位）。為防止檔案內容被意外覆蓋，當先前讀取中斷、檔案外部變更、或使用者利用雙擊 Esc 倒帶對話時，系統會強制重新讀取最新原始檔後才允許發布。同時修復了伺服器短暫異常重試時，誤將成功發布判定為工作階段衝突的問題。

就像交件前先重看一次最新稿，免得拿舊版蓋掉剛改好的段落。
問題修復

工件清單關閉不中斷連結，目錄外檔案發布更受控

管理各項已產生的展示工件清單時，權限防護與版本關聯現在更加可靠。

在 /artifacts 面板中按下叉號關閉單一項目，不會再解除原始檔案與工件的關聯，下次發布同一個檔案時依然會正確更新版本而非重複新建。即使事先勾選了免詢問許可，若工件檔案位於工作目錄之外，系統仍會先向你確認，除非事先透過 --add-dir 將該目錄加入允許清單。此外，在自動模式下讀取他人建立的工件或上傳資源時，系統會確實進行安全審查，不再因為你在其他模式下曾批准過就跳過檢查。

新功能

Ultrareview 支援部分複製快照，要求 Git 2.31 以上版本

在 macOS 或 Linux 用 /ultrareview 上傳本機版本庫時，現在要求 Git 2.31 以上。

使用部分複製（只取回部分版本庫資料）的專案，在符合版本要求時會以工作樹快照上傳，不再退回舊方法。舊版 Git 若遇到工作樹缺少檔案的部分複製，會拒絕上傳並說明原因，不會先抓缺少的檔案；未使用 --filter 複製的版本庫仍可上傳。上傳時不納入符號引用（指向其他分支的別名）；目前分支若是符號引用，會拒絕上傳並說明原因；使用 --separate-git-dir 分離 Git 目錄的版本庫，也會拒絕上傳，不再用舊方法上傳。

寄送資料前先核對版本和清單；資料齊全就打包，缺了必要檔案則當場告知，不會自行補抓。
問題修復

Ultrareview 跨平台檔案上傳修復，敏感憑證防護更周全

用 /ultrareview 上傳版本庫時，幾種特殊檔名與路徑不再出錯。

WSL（在 Windows 中執行 Linux 的環境）的 Linux 磁碟區上，已變更檔案的名稱若含冒號，或以點號、空格結尾，不再讓上傳遭拒。macOS、Linux 上，某些特殊檔名造成的上傳變慢已修正；檔案或資料夾名稱帶有多個備份、編輯器標記時，憑證檔檢查也不再漏看。像 server:8443.key 這種副檔名前含冒號的憑證檔，其未提交變更不再混入上傳。專案資料夾暫時讀不到時誤報 core.worktree is set 的錯誤訊息、macOS 與 Linux 上 Git 工作樹（同一版本庫的另一份工作目錄）設定了 core.longpaths 而無法上傳，以及 Windows 上版本庫位於個人資料夾時誤傳連結工作樹，也已修正。

新功能

程式碼審查流程放寬，GitHub 組織選單滾動載入

設定自動修復 Pull Request 或排程審查時，GitHub 整合與規則套用提示更加明確。

即使開啟 disableWorkflows，程式碼審查與 /ultrareview 仍會執行；但若執行審查的機器由管理員自行設定此鍵，則不在此限。在「新增存放庫」對話框中，組織清單現在支援向下捲動載入更多項目，不再只顯示前面幾筆。當專案自訂的 REVIEW.md 規則因為拉取請求規模過大或身為符號連結（指向另一個位置的捷徑檔）而未能套用時，檢查報告中會主動加註說明。此外，/autofix-pr 與 /schedule 不會再對尚未完成狀態檢查的存放庫誤報未安裝 GitHub App。

新功能

API 請求共享重試額度，非串流備援定時發送存活訊號

網路不穩、串流一再失敗時，會改走非串流備援（不逐段接收，改等完整回覆）；以前備援另有一套重試，同一個請求最多會重送 21 次，現在與原請求共用次數。

可用環境變數 CLAUDE_CODE_NONSTREAMING_TIMEOUT_RETRIES 限制備援請求逾時後的重送次數。若 API 的輸出內容過濾器封鎖回覆，畫面會立即顯示該錯誤，不再反覆重送數分鐘。開啟部分訊息時，Anthropic API、Claude Platform on AWS 與閘道的非串流備援期間，每 30 秒會送出一次 ping 事件。

電話改用另一條線撥出時，仍共用原本的重撥次數；若對方明確拒接，就直接顯示原因。
新功能

雲端模型支援同級自動降級，啟動狀態快取一整天

透過 Bedrock 或 Vertex AI 使用 Claude Code 時，若管理員移除預設模型的存取權，工作階段、對話標題與摘要會改用同級較舊的可用模型，不再直接失敗。

兩者的啟動檢查也會記住帳號不能用的模型，最長一天，免得每次啟動都重查。Bedrock、Vertex AI、Mantle 的啟動檢查會帶上與一般請求一致的標頭，並表明請求來自 Claude Code。Bedrock、Mantle、Claude Platform on AWS 若使用非預設連接埠，簽名的 Host 標頭會包含連接埠。Bedrock 串流若遇到模型逾時或服務不可用，畫面會顯示錯誤訊息，不再是一整段原始 JSON。

新功能

自訂伺服器啟用百萬視野，對話中途換模型限制即時生效

透過自訂 ANTHROPIC_BASE_URL 連線時，Opus 4.7 以上、Sonnet 5 以上與 Fable 等支援百萬上下文的模型，現在會使用 1M 上下文視窗（模型一次可處理的文字容量）。

若閘道只支援 200K，可執行 /autocompact 200k 調整壓縮門檻。工作階段中途透過 set_model 請求切換模型，例如 Agent SDK 的 setModel，新模型的輸出 token（AI 處理文字的計量單位）上限和自動壓縮視窗會立即生效。若伺服器以客戶端未預期的另一個備援模型回覆拒絕訊息，/cost 與 SDK 的 modelUsage 會記到實際回覆所用的模型。

換了容量不同的記憶卡後，相機會立刻依新容量計算剩餘張數，不再沿用舊卡的數字。
新功能

長對話畫面不再微幅卡頓，歷史紀錄展開與退出更滑順

在對話累積了大量檔案搜尋與程式碼改動時，終端機畫面的操作反應更為靈敏。
