Claude Code 2.1.285

Released: 2026-09-29

Release notes

FEATURE

Launch Desktop App Directly from Terminal to Resume Existing Sessions

If you want to switch to a windowed interface in the middle of working on the command line, you can now do so with a single command.

When using Claude Code in the terminal, entering claude --desktop launches the desktop application directly in the current directory. If you want to continue a session you were just having, simply add --continue or specify an ID with --resume <id>, and the system brings the entire existing conversation into the window.

Think of spreading drafts from a pocket notebook onto a spacious desk to keep writing, leaving the layout and context completely uninterrupted.
FEATURE

Preconfigure Plugins on Install for Ready-to-Use MCP Servers

Having to manually hunt through menus to fill in parameters after installing an extension plugin often interrupts your workflow.

You can now use the claude plugin configure <plugin-name> command to directly view all configuration items and unfilled fields for that plugin, or pass values all at once from standard input using --values-stdin. When installing plugins that package MCP servers, you can pass parameters directly after claude plugin install --config with <server>.<key>=<value>. Previously, if a plugin's built-in server was missing configuration, the system would often silently skip running it; now, both install prompts and the plugin list will proactively remind you to configure it.

Picture unboxing a new appliance that comes with a customized assembly guide, letting you snap parts into place immediately rather than searching for a screwdriver after powering it on.
FEATURE

Stricter Plugin Identification with Clearer SSH and Marketplace URL Validation

Subtle name differences when managing community plugins could cause installations or toggles to affect the wrong plugin.

Downloading plugins or marketplace listings over SSH previously ignored the programs specified by the GIT_SSH environment variable and the Git config core.sshCommand, but they are now applied. If two plugin identifiers differ only by ., -, or @, or only by casing on macOS and Windows, installation previously risked misusing an installed plugin's cache or data directory; installation is now rejected. Enabling or disabling plugins using the full name@marketplace identifier will also no longer modify settings for a differently cased variant. Git URLs for plugins, marketplaces, and the current repository remotes undergo more thorough checks, and the interface explains the reason when a marketplace URL is rejected.

FEATURE

Centralized Enterprise Policy Controls Block Project Overrides of Security Sandboxes

When a company needs to restrict which API providers Claude Code can use, administrators can specify the scope in managed settings using allowedProviders.

Project settings cannot relax or disable admin-mandated sandboxes, replace proxy servers protected by managed blocklists, expand strict allowlists, or reopen files barred from reading. Sessions authenticated to the Anthropic API via ANTHROPIC_AUTH_TOKEN now load organization policies. Team, Enterprise, and sessions with unresolvable subscription tiers pause WebFetch if policies fail to load at startup. If the operating system denies read access to managed configuration files, Claude Code warns and starts without policies from that file; other read errors or unparseable files will halt the session.

When a corporate building specifies which doors must be locked, individual departments cannot remove the locks, and guards pause entry until they receive the approved access list.
FEATURE

Support Disabling Web Fetch and Clarify URL Security Check Errors

When you do not want Claude Code to fetch web data on its own, you can disable WebFetch using the CLAUDE_CODE_DISABLE_WEB_FETCH environment variable.

Error messages for URL security checks have also been corrected: previously, when domain checks hit rate limits, they could be misreported as network issues or enterprise policy blocks; now, rate limiting is accurately displayed.

A master switch turns off an individual service, while the diagnostic light clearly distinguishes between request limits and connection failures.
FEATURE

Subagents Fully Inherit Parent Permissions and Streamline Background Reporting

When using subagents to assist with tasks, managing results and permissions is now easier.

Running claude -p with CLAUDE_CODE_FORK_SUBAGENT=1 executes further Agent calls from subagents in the foreground, allowing them to capture results from nested agents. With claude -p --permission-prompt-tool, permission requests from background subagents are routed to the specified prompt tool instead of being automatically rejected. Forked subagents inherit the parent's permission mode in the session, including plan mode and dontAsk, and cannot exit plan mode on their own. In auto mode, background subagents no longer prompt for a second turn after reporting, and subagents finish immediately once returning reports to their callers.

Members of an investigation squad head out under the same authorization and wrap up once submitting their report, without sending an unneeded follow-up note.
FEATURE

Auto Mode Expands to Third-Party Providers with Streamlined Command Defaults

If you connect other model providers or disable telemetry, you will now also receive a one-time prompt to switch permissions.

This prompt appears when the user is configured in other modes, offering auto mode as an optional new default. Running claude -p or Python Agent SDK sessions in these environments without a specified permission mode will start directly in auto mode just like interactive sessions, which can still be overridden using --permission-mode.

Relocating the same workflow to another workplace keeps the original default prompt available, while unconfigured jobs start automatically under the standard default.
FEATURE

Enforce Background Command Timeouts and Improve Session Management

Background Bash or PowerShell commands now stop after a 30-minute default timeout, configurable up to 2 hours, and Claude receives a notification if a command halts due to timeout.

/tasks groups Claude Code's own background work under a "System tasks" row that expands when pressing Enter. Background sessions can now be opened with /resume or claude --resume, and accompanying text is submitted as the next conversation turn only when using claude --resume <id> "prompt". Background sessions and sessions launched by Claude Code tools cannot enable auto-memory, though it can still be turned off. Responding to a background session awaiting permissions from claude agents will also avoid accidentally approving pending commands.

FEATURE

Reliable Remote Control Messaging and Mid-Turn Visibility for Side Questions

When sending messages and attachments from other devices via remote control, file downloads that fail due to network errors, timeouts, or server errors are now retried up to twice.

Queued messages are marked as read only when Claude starts processing them; if the terminal closes early, unprocessed messages are delivered upon resuming the session next time. In sessions hosted by applications such as Claude Desktop, asking side questions with /btw now shows the turn currently in progress instead of only the previous turn. Remote control clients are also prohibited from running /claude-api.

Package tracking marks an item delivered only when handed to the recipient; anything still en route waits for the next delivery attempt.
FEATURE

Identify Hostnames for Chrome Connections with Clearer Configuration Guidance

Managing browser automation across computers is now easier to identify.

The local client proactively reports its computer hostname to the browser, replacing generic numeric labels when multiple devices connect. Entering /config chrome=true in the terminal guides you to open the settings panel to complete configuration, while entering chrome=false disables the connection directly. Additionally, documentation for remote control clarifies default flag behavior: remote spawned sessions do not enable browser control by default unless started with the explicit --chrome flag.

Bluetooth pairing lists clearly display dedicated names for laptops and phones rather than unknown identifiers, making connected devices instantly recognizable.
BUGFIX

Cloud Sessions Receive Full Fixes, Smoothing Environment Loading and Tool Caching

When resuming a compacted conversation in the cloud, you can now update artifact files previously read or published during that session.

Creating cloud sessions or running /remote-env is no longer restricted to viewing only the 20 most recent environments. If MCP_DISCOVERY_CACHE=1 is set in cloud environment variables, restarts reuse the connector tool list, while other MCP servers are no longer cached and connect upon startup. Brief delays on opening responses and false warnings about missing upload folders before files are uploaded have also been resolved. When clicking "Run now" on a schedule and getting rejected before startup, the screen displays the same explanation found in schedule failure notifications rather than exposing raw internal error text.

FEATURE

MCP CLI Output Filters Escape Characters and Safely Conceals Plugin Values

When managing MCP servers in the terminal, newlines and terminal escape characters within names or configuration values no longer scramble the output of claude mcp list and claude mcp get, nor do they garble not-found error messages for remove, login, and logout.

Running claude mcp list now displays URLs and connection states for WebSocket servers. If type is omitted in stdio server configurations, claude mcp get still displays Type, Command, Args, and Environment. For stdio servers provided by plugins, commands, arguments, and environment variable values are concealed, revealing only variable names.

A device roster displays equipment and statuses while obscuring sensitive configurations, ensuring special characters in names do not scramble the list.
FEATURE

MCP Tool Removal Takes Immediate Effect with Accurate Lazy Loading

In SDK or -p sessions, if an MCP server is added mid-session and subsequently closed, its associated tools are now removed immediately rather than lingering for the model to use.

If a tool sets _meta['anthropic/alwaysLoad'] to false, it still lazy-loads even if its parent --mcp-config, Agent SDK, or plugin server is configured with alwaysLoad. Cloud sessions and self-hosted runners also reserve widgets and related names like widgets_ for system use, requiring custom servers using those names to be renamed before loading.

Updating a toolkit manifest reflects mid-task additions and removals, while items labeled for later use stay stored even when the whole box opens.
FEATURE

Artifact Publishing Streamlines into One Step with Rewind Overwrite Protection

When asking AI to write documents, web pages, or generate display artifacts, creation and publishing are now faster and more secure.

When editing or creating pages, the system proactively suggests publishing in the same step and streamlines subsequent prompt text to save tokens. To prevent file contents from being accidentally overwritten, the system forces a re-read of the latest source file before allowing publication whenever a prior read was interrupted, the file changed externally, or the user rewound the conversation by double-pressing Esc. A bug where transient server retries misidentified successful publications as session conflicts has also been resolved.

Just as an editor rereads the latest draft before submission, this prevents an outdated copy from overwriting freshly revised paragraphs.
BUGFIX

Closing Artifact Items Preserves Links and Controls External File Publishing

Permission safeguards and version associations are now more reliable when managing lists of generated display artifacts.

Clicking the close icon on an individual entry in the /artifacts popover no longer disassociates the source file from the artifact, ensuring that publishing the same file again properly updates its version instead of creating a duplicate. Even if permission prompts were bypassed beforehand, the system still asks for confirmation if an artifact file resides outside the working directory, unless that directory was explicitly allowlisted via --add-dir. Furthermore, reading artifacts created by others or uploaded resources in auto mode strictly enforces security reviews without skipping checks just because approval was granted in another mode.

FEATURE

Ultrareview Supports Partial Clone Snapshots and Requires Git 2.31 or Later

Uploading a local repository with /ultrareview on macOS or Linux now requires Git 2.

31 or later. Projects using partial clones upload as worktree snapshots when meeting the version requirement rather than falling back to legacy methods. Older Git versions encountering partial clones missing worktree files reject the upload with an explanation instead of fetching missing files first, while repositories cloned without --filter can still upload. Symbolic references are excluded during uploads. If the current branch is a symbolic reference, the upload is rejected with an explanation; repositories that separate their Git directory via --separate-git-dir are also rejected instead of being uploaded with the older method.

Before shipping materials, one checks the version and manifest, packing complete sets while flagging missing files on the spot instead of fetching them unasked.
BUGFIX

Ultrareview Fixes Cross-Platform Uploads and Bolsters Sensitive Credential Protection

Several special filenames and paths no longer cause errors when uploading repositories using /ultrareview.

On WSL Linux volumes, modified filenames containing colons or ending with dots or spaces no longer trigger upload rejections. Slow uploads caused by certain special filenames on macOS and Linux have been resolved, and credential file checks no longer overlook files or directories containing multiple backup or editor markers. Uncommitted changes to credential files with colons before extensions, such as server:8443.key, are no longer mistakenly included in uploads. False core.worktree is set errors when project folders are temporarily unreadable, upload failures on macOS and Linux when Git worktrees configure core.longpaths, and erroneous uploads of linked worktrees when repositories reside in user profile folders on Windows have all been fixed.

FEATURE

Code Review Workflow Relaxes Constraints as GitHub Organization Lists Add Infinite Scroll

GitHub integration and rule application feedback are clearer when configuring automated pull request fixes or scheduled reviews.

Code reviews and /ultrareview still run even with disableWorkflows enabled, unless the machine executing the review was configured with this key by an administrator. In the "Add repository" dialog, the organization list now supports scrolling down to load more entries instead of only showing the initial few. When custom project REVIEW.md rules cannot be applied because a pull request is too large or REVIEW.md is a symlink, the check report proactively adds an explanatory note. In addition, /autofix-pr and /schedule no longer falsely report that the GitHub App is not installed for repositories with in-progress status checks.

FEATURE

API Requests Share Retry Quotas as Non-Streaming Fallbacks Send Periodic Keepalives

When unstable network conditions cause repeated streaming failures, requests switch to a non-streaming fallback.

Previously, fallbacks maintained a separate retry pool that could re-send the same request up to 21 times, but they now share retry counts with the original request. The environment variable CLAUDE_CODE_NONSTREAMING_TIMEOUT_RETRIES can limit retries when fallback requests time out. If an API output content filter blocks a response, the screen immediately displays the error instead of endlessly retrying for minutes. When partial messages are enabled, non-streaming fallbacks across the Anthropic API, Claude Platform on AWS, and gateways emit a ping event every 30 seconds.

Switching a phone call to a secondary line still counts against the original redial quota, showing the reason immediately if the recipient explicitly declines.
FEATURE

Cloud Models Support Same-Tier Automatic Downgrades and Cache Startup States for a Day

When using Claude Code via Bedrock or Vertex AI, if an administrator removes access to the default model, sessions, conversation titles, and summaries automatically fall back to an older available model in the same tier instead of failing outright.

Startup checks for both platforms also remember inaccessible models for up to a day, avoiding repeated lookups on every launch. Startup checks for Bedrock, Vertex AI, and Mantle attach headers consistent with standard requests and identify the traffic as originating from Claude Code. When using non-default ports, Bedrock, Mantle, and Claude Platform on AWS include the port in the signed Host header. If Bedrock streaming encounters model timeouts or service unavailability, the screen displays a clean error message rather than a raw JSON dump.

FEATURE

Custom Servers Enable Million-Token Context, Mid-Session Model Switches Apply Limits Instantly

When connecting through a custom ANTHROPIC_BASE_URL, models supporting million-token context—such as Opus 4.

7 and above, Sonnet 5 and above, and Fable—now use a 1M context window. If a gateway only supports 200K, you can run /autocompact 200k to adjust the compression threshold. When switching models mid-session via a set_model request, such as setModel in the Agent SDK, the new model's output token limits and automatic compact window take effect immediately. If the server responds with a rejection using an unexpected fallback model, /cost and the SDK's modelUsage attribute the usage to the model that actually responded.

After inserting a memory card with a different capacity, a camera recalculates remaining shots immediately rather than sticking to the old number.
FEATURE

Long Conversations Stay Responsive Without Minor Stutter, Expanding and Exiting History Runs Smoother

Terminal interactions remain responsive even when conversations accumulate numerous file searches and code modifications.

In long conversations, the occasional one-second stutter in non-fullscreen mode has been fixed and no longer recurs after running /clear or compacting history. Per-turn computational performance is improved when configuring large numbers of permission denial rules and external tools. In fullscreen mode, pressing Ctrl+O to open a history containing hundreds of file reads or searches no longer freezes the screen momentarily, and exiting history in non-fullscreen mode is also smoother. Tools that are still running when history opens append their results in real time upon completion. Additionally, HTML whitespace entities used in table indentation render properly as spaces instead of printing raw entity strings on screen.

BUGFIX

URL Passwords Masked Reliably, Malformed History Records Fixed

When viewing logs or transcripts, URL passwords containing @ or encoded as %40 are now fully masked without exposing partial or full passwords.

After editing in an external editor via Ctrl+G in Vim mode, returning to NORMAL mode and pressing x or r will not corrupt paste markers at the end of the prompt text. Saved session transcripts containing missing fields or malformed compact markers and resurrection entries will no longer fail compaction or session resumption, drop history, or crash outright.

While organizing records, passwords stay completely covered, and encountering damaged bookmarks no longer discards the entire reading history.
BUGFIX

Hooks No Longer Hang on Background Subprocesses, Cancellation Intercepts Commands Promptly

When extending workflows via hooks, if a background process launched by a synchronous hook keeps its output pipe open, Claude Code now proceeds shortly after the hook itself exits instead of waiting indefinitely.

Commands or hooks canceled while preparing to launch will no longer run to completion. Upon exiting plan mode, both hooks and SDK permission callbacks can read the plan written in the same turn. If agent(), parallel(), or pipeline() calls in a workflow fail, even if awaited later or unawaited entirely, they are no longer treated as unhandled Promise rejections that terminate background sessions.

Pressing a stop button on a workflow takes effect before work begins, and an error in one outsourced task no longer halts the entire pipeline.
FEATURE

Smarter Sandbox Allow Rules, Upgraded Permission Checks and System Variable Protections

When executing inline scripts like python3 -c or node -e, the sandbox no longer prompts for approval simply because content contains an = character.

Allow rules in .claude/settings.local.json are no longer blocked when Git trace2 is configured outside a repository. If the PowerShell command parser fails to start, permission checks do not skip deny and ask rules, nor do they cache the failure. When approving an Edit from the IDE diff view or modifying the edit during approval, edits targeting devices like /dev/null now complete properly. Windows project and local settings can no longer use env to configure variables related to ALLUSERSPROFILE, SystemDrive, or CommonProgramFiles, requiring user or managed settings instead.

BUGFIX

Fixes for Authentication and CLI Commands, Expanded Image Preview and Conversion Support

During daily login and session resumption, the terminal no longer hangs after the browser indicates a successful login, and two sessions simultaneously claiming a stale lock from a crash will no longer occasionally fail authentication.

CLAUDE_CODE_RESUME_INTERRUPTED_TURN will not rerun turns that ended due to --max-turns. When aliases place options before claude attach, logs, stop, respawn, or rm, command names are no longer mistaken for new prompt text. Fetching remote data via worktrees or /teleport fails fast instead of hanging the terminal when encountering SSH key passphrase or new host confirmation prompts. When Claude sends BMP, HEIC, HEIF, AVIF, or TIFF images, the Claude app now displays previews if Claude Code can convert them.

BUGFIX

Evaluation Tools Prevent Symlink Traversal, Truncated Responses Scored Separately

When evaluating models with /claude-api, the evaluation runner and report generator now prevent writes from traversing pre-existing symlinks or hard links placed at output file paths.

Responses truncated upon hitting the max_tokens limit, which were previously blended into average scores, are now flagged as truncated and computed separately. This distinction makes it easy to separate complete responses from unfinished outputs when reviewing results.

A report card flags unfinished exams and tallies them separately so evaluators know which answers were complete.
FEATURE

VS Code Adds Proactive Problem Diagnostics, Visual Configuration Forms for Plugin Management

When working on projects in the VS Code sidebar, Claude can now inspect errors and warnings in the Problems panel at any time without waiting for a file edit to finish.

When managing plugins, installing plugins with custom options prompts for unconfigured fields, which can later be edited via the gear icon. If an operation fails, popups explain why and only present actionable fixes when available. Prompts now ask for confirmation before removing marketplaces or disabling plugins enabled in shared project .claude/settings.json files. If reloading the window interrupts a conversation, the restored tab indicates at the bottom that no further responses will follow.

A dashboard checks current errors on demand, while configuration forms collect required options and request confirmation before major changes.
FEATURE

VS Code Warns on Multi-Window Collisions, Restored Conversations No Longer Open Blank

Session state is now better protected when opening multiple editor windows or browsing past history.

When attempting to open a conversation already running in another window or application, the system asks for confirmation instead of opening duplicate copies without warning. Clicking entries in the conversation history list will not overwrite an ongoing live conversation. Tabs reloaded after an extension restart no longer remain blank, displaying recovery instructions instead. If a conversation becomes permanently unrecoverable, an error message explains the cause and provides an option to start a new chat.

FEATURE

VS Code Prevents Dropped Messages During Replies, Tab Names Update on Conversation Renames

In VS Code, messages sent while Claude is replying no longer disappear after reopening a session.

Renaming a conversation via /rename, a SessionStart hook, or claude.ai updates the editor tab label immediately with the new title. After switching accounts, the "Web" tab in the session list displays sessions for the current account rather than stale records from the previous account. Going back during login and reselecting the same sign-in method allows you to leave the authorization code screen and proceed normally.

BUGFIX

VS Code Chat Fixes Eliminate Command Menu and Shortcut Conflicts

Pressing Enter after typing a slash command in the VS Code chat panel now runs the selected command instead of drifting to unrelated fuzzy search results or becoming unresponsive.

Pressing Esc after clicking an item in the command menu now closes only the menu without aborting the active turn. Text following references to Claude Code or IDE tags is no longer truncated, and the panel no longer hangs when long sessions prune the oldest history entries. After a window reload, reasons for hook blocks or stopped questions are preserved. Restored tabs will not mistakenly rerun interrupted turns if VS Code launched with CLAUDE_CODE_RESUME_INTERRUPTED_TURN set while Continue After Reload is disabled.

FEATURE

VS Code Subagent Map Delivers Accurate Info and Eliminates 10-Minute File Edit Freezes

Several issues with the agent map and file operations are fixed when orchestrating multiple agents for complex tasks in VS Code.

The agent map now accurately displays the actual model running for each subagent instead of mislabeling it with the session model. Real-time messages sent to running agents and latest logs appear fully, preventing lost conversations during concurrent multi-agent runs. When the editor becomes unresponsive due to autosave before file tools execute, operations no longer hang for 10 minutes on each read, write, or edit before skipping. In addition, uninstalling project plugins from the plugin management interface accurately removes only the targeted plugin without accidentally deleting other installations or failing.

FEATURE

Enterprise Plans Enable Direct Messaging and Preserve Slack Fallback Model Notes

When using Claude Tag in enterprise messaging software, members on Enterprise Standard Chat or Usage-Based Chat seats with Cowork can now message Claude directly one-on-one without needing a separate Claude Code seat.

The admin Default model setting and channel Configure page now list only the models your organization has permission to use, preventing failed saves or session creation errors. When Claude responds in Slack using a fallback model, the message displays a note below indicating the active model and reason, and editing the message later no longer erases this annotation.

An internal company directory allows eligible colleagues to contact the same point person directly; the dropdown only lists enabled accounts, and revising a message later never wipes out the original note.
