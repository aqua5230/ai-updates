Claude Code 2.1.259

Released: 2026-09-02

Release notes

FEATURE

Organizations can roll out managed MCP servers, and startup halts if managed config is corrupt

Administrators can now distribute HTTP or SSE MCP servers (Model Context Protocol, which connects AI to external tools) to every user via the managedMcpServers setting, using the same format as .mcp.json while skipping local commands:

{
  "managedMcpServers": {
    "company-docs": {"url": "https://mcp.internal.example.com/sse", "type": "sse"}
  }
}

allowedMcpServers now governs only user-added servers; to block managed-mcp.json servers after upgrading, use deniedMcpServers instead.

If the managed settings file, a drop-in file, the MDM plist, or the HKLM value fails to parse, Claude Code now refuses to start and names the source. Additionally, forceRemoteSettingsRefresh now properly triggers at startup even after a policy helper configured by MDM or managed settings has already run.

It is like a company issuing standard equipment: if the manifest is torn or unreadable, the guard stops everyone at the gate to verify rather than letting unchecked gear through.
FEATURE

Unattended hosts get a prompt-suppression flag to auto-deny blocking prompts

An automated mailroom, when presented with registered mail needing a physical signature, immediately turns it away while clearing normal parcels through, never letting the counter stall in endless waiting.

For unattended headless servers — environments running without a visible terminal window — you can run the full command:

claude --permission-prompts none

This flag is built for automated pipelines on unattended machines.

Whenever an action would pop up a prompt asking for confirmation, it is automatically denied on the spot, while the active permission mode (including auto mode) continues making decisions in the background. Running scheduled jobs or CI pipelines in a session no longer risks a single unprompted action freezing the entire workflow indefinitely.

FEATURE

GitLab merge requests are recognized natively with footer badge refreshes

When you manage merge requests in GitLab repositories via the command line, the terminal now natively recognizes commands like glab mr create, merge, close, reopen, note, and update.

Running these commands formats the merge request number as MR !N inside the collapsed tool summary and immediately refreshes the footer MR badge. This allows you to track code review and merge progress from the command line without switching back and forth to your browser.

It is like a parcel scanner getting upgraded barcode logic: the moment a specific tracking code is scanned, a dedicated label prints out and the bottom status bar on the receipt updates in real time.
FEATURE

Running the GitHub App installer inside GitLab repos now points to GitLab CI docs

Running /install-github-app inside a GitLab repository no longer fails silently with invalid requests or vague errors.

The output now clearly explains that the command is GitHub-only and directly links to the official GitLab CI/CD documentation for setting up your automation pipeline. This provides cross-platform engineering teams with the right alternative steps and configuration guidance right away.

It is like asking a metro ticketing machine for high-speed rail schedules: it politely informs you that it only sells subway tickets, while displaying a map guiding you to the high-speed rail transfer portal.
BUGFIX

Bash Read deny rules tighten around option values, git operands, and chained commands

Building security scanners have been upgraded with deeper inspection: whether contraband is hidden inside secret pockets, written into parcel metadata, or packed into crates for bulk shipping, guards catch it and request manual verification.

Bash Read() deny rules previously had loopholes when handling hidden file paths.

Passing denied files as option values (such as --ignore-revs-file=.env, -f.env, or @file), as file operands in git diff and git grep, or chained in compound commands like cd DIR && cat FILE previously slipped past security checks; all of these paths are now strictly intercepted. Furthermore, running grep -r or cp -r over a directory containing a denied file now explicitly prompts for permission.

BUGFIX

Worktree isolation accommodates non-standard git probe messages from hook-created trees

When running with worktree isolation — the Git feature that lets you maintain multiple parallel checkouts of the same project — parallel working copies created by automation pipelines now enjoy broader compatibility.

If your project provisions worktrees automatically via hooks (scripts triggered when specific lifecycle events occur), certain environments where underlying git rev-parse probe calls failed with messages other than "not a git repository" previously caused Claude Code to misjudge and reject the directory. This probe handling has been fixed so hook-created isolated workspaces load smoothly.

It is like an airtight laboratory chamber: as long as safety valves are engaged through certified lines, an unusual status code on a secondary gauge will not trigger a lockdown that locks the entire workstation out.
BUGFIX

Worktree isolation relaxes checks on pipelines and launcher scripts outside the main repo

It is like sorting packages inside a bonded warehouse: as long as items cannot cross over into the main customs area outside, any internal repackaging or routing proceeds without setting off security alarms.

Command execution constraints under worktree isolation — which creates isolated duplicate copies of a repository — have been reasonably relaxed.

Previously, running common Bash loops, xargs pipelines, or wrapper commands from launcher scripts inside isolated sessions was overly restricted and rejected. As long as these commands cannot reach the main checkout directory, they are now permitted to run freely, streamlining routine automated batch workflows.

BUGFIX

Concurrent sessions no longer overwrite settings, improving resumes and repo detection

Running multiple sessions at once no longer causes background processes to silently revert each other's updates to ~/.claude.json, protecting workspace trust, MCP servers, and project state from getting lost during concurrency.

Furthermore, --resume no longer crashes and --continue no longer opens a blank chat when a saved session contains an attachment missing its payload; repository detection will not drop a known repo identity after a transient git probe failure; and background GitHub connection checks for claude.ai users are now remembered across app restarts.

It is like multiple assistants sharing a single briefcase: writing updates no longer erases each other's notes, and finding an empty sheet or hitting a temporary network glitch will not wipe project details from memory.
FEATURE

Remote control stops background agents reliably, and workflow outputs gain syntax coloring

Hitting Stop in remote-control sessions now reliably terminates background agents and workflows, keeping killed tasks visible and stoppable until their underlying processes completely exit.

Resuming a workflow while a previously stopped run is still exiting no longer spawns duplicate agent instances. When a paused remote or scheduled session approves a connector tool permission prompt, execution resumes smoothly. Under /workflows, agent detail views now pretty-print JSON results with syntax highlighting and line breaks, tucking lengthy outputs behind an expand toggle, while nested background subagent results are retained inside parent transcripts.

When a dispatch center manages autonomous fleets, hitting the emergency brake brings every vehicle to a full halt under live monitoring, resuming never dispatches duplicate vehicles, and logs are cleanly archived in color.
BUGFIX

Custom commands support frontmatter models, and Vertex IDs respect token context caps

Frontmatter model: declarations inside custom commands and skills now apply properly in interactive sessions.

When running in auto mode, requesting a model that is not supported will retain the current session's model instead of breaking the turn. Furthermore, CLAUDE_CODE_MAX_CONTEXT_TOKENS now respects Vertex-style model IDs carrying @YYYYMMDD date suffixes, even for version tags that Claude Code does not natively recognize out of the box.

It is like a specialist dispatch system: requesting a specific technician assigns them directly, encountering an unsupported craft keeps the original crew, and every expert is held to strict limits on briefing notes.
BUGFIX

Thinking processes are not rejected repeatedly, and prompt caches persist across token refreshes

Like scrap paper in an examination hall: when your badge is renewed or a proctor pauses the clock, your prior formulas and reasoning remain intact on the desk rather than being wiped clean before the next question.

If a model's thinking reasoning is rejected during a conversation, subsequent turns will no longer be repeatedly rejected in a loop.

In sessions with telemetry disabled, refreshing an OAuth token no longer unexpectedly invalidates the prompt cache. In addition, triggering a blocking Stop hook preserves the previous turn's reasoning and prevents prompt cache misses on supported models.

FEATURE

MCP server disconnects report errors immediately, and session starts speed up by 50 ms

When an MCP server (Model Context Protocol, which connects AI to external tools) disconnects while enumerating available tools at startup, Claude Code now reports the error clearly instead of showing as connected with zero tools.

In remote claude.ai sessions, closing a browser-hosted MCP server tab will no longer leave you waiting 60 seconds at the start of each turn. Furthermore, headless and SDK sessions now begin their first turn up to 50 ms sooner once MCP servers finish connecting.

It is like a restaurant ordering system linked to cloud kitchens: if a kitchen goes offline, it immediately alerts staff instead of showing a blank menu, inactive branches will not stall the queue, and orders dispatch 50 ms faster once lines are connected.
FEATURE

Fullscreen mode avoids blank renders, and text measurement reuse accelerates terminals

An auditorium projector upgraded its typesetting engine: no matter how long the text is or how panes are resized, the display never goes blank, rendering the latest captions and edits clearly.

Engaging in lengthy conversations with hundreds of tool calls in fullscreen mode no longer causes the display to go blank.

Resizing the terminal or rendering lengthy responses for the first time now reuses text measurement data to improve rendering performance. Shell command live output previews no longer hide the newest lines when earlier text wraps. Additionally, a bug where the file edit permission dialog occasionally truncated modified lines without warning has been fixed.

FEATURE

Plugin validation supports structured JSON, and cloud metrics restore missing user attributes

In plugin tooling and observability integrations, running claude plugin validate --json now outputs a machine-readable JSON validation report.

When installing plugins, GitHub marketplace URLs containing trailing slashes or dangling ? and # fragments now correctly resolve to usable .git clone URLs. Publishing Artifacts in sessions continued from older versions no longer fails on an "unexpected parameter note" error. In addition, OpenTelemetry metrics and events emitted from cloud sessions now restore the previously missing user.email, organization.id, and user.account_uuid attributes.

It is like a quality inspection checkpoint introducing structured data exports: whether parcel labels carry trailing smudges or system handovers resume from older tickets, everything is parsed and tagged with client and organization metadata.
FEATURE

[VSCode] Active quick filter and status menu added to session sidebar

Adding quick filter tabs to the top of an inbox lets you instantly isolate ongoing or pending threads without scrolling through endless rows.

The VS Code extension's session list sidebar now features upgraded filtering controls.

A new Active quick filter button lets you instantly view ongoing sessions, alongside a dedicated status filter menu offering categories like Needs input (waiting for user response), Working (in progress), and Completed. This helps you quickly zero in on conversations requiring immediate attention when juggling multiple tasks.
