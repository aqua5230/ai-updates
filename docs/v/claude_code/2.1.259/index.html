リモート操作時のバックグラウンド停止を徹底、ワークフロー結果をカラーで見やすく整形

リモートコントロールセッションで停止を実行した際、バックグラウンドエージェントとワークフローが確実に終了するようになり、終了処理中のタスクもプロセスが完全に落ちるまで表示され再停止を受け付ける。前回の停止処理中にワークフローを再開しても重複したエージェントが生成されることはない。一時停止中のリモートセッションや定期実行セッションでコネクターツールの承認を行った場合も正常に処理が再開される。/workflows の詳細画面では JSON の実行結果が構文強調と改行で見やすく整形され、長い出力は展開ボタンの裏に折りたたまれるほか、入れ子のサブエージェントの結果も親の記録に保持される。管制センターが自動運転車を一斉停止させる際、非常ブレーキで確実に停車させて計器を維持し、再発進時に同じ便を二重発進させず、運行日誌をカラーで整理整頓して保管するようなものだ。

カスタムコマンドのモデル指定が対話で有効化、Vertex 形式のコンテキスト上限も適用

カスタムコマンドやスキルの先頭に指定した model: 設定が、対話型セッションで意図通りに反映されるようになった。オートモードで非対応のモデルが指定された場合でも、現在のセッションのモデルを維持して処理を続行し、不意の中断を防ぐ。また、@YYYYMMDD 形式の日付サフィックスが付いた Vertex スタイルのモデル ID に対しても、Claude Code が未認識のバージョンであっても環境変数 CLAUDE_CODE_MAX_CONTEXT_TOKENS によるトークン上限が正常に適用される。専門作業の割り当てシステムにおいて、特定の技術者を指名した場合は確実に配置し、未対応の工法では現行チームを維持した上で、各員の作業メモの長さを一律に制限するようなものだ。

思考プロセスの連続拒否を解消、トークン更新時もプロンプトキャッシュを維持

試験会場の下書き用紙のように、受験票の更新や監督官による一時中断があっても、これまでの計算式や推論の記録は机上にそのまま残り、次の問題でゼロからやり直す必要がないようなものだ。対話中にモデルの思考プロセスが一度拒否された場合でも、その後のターンで連続して拒否され続ける問題が解消された。テレメトリを無効化したセッションにおいて、OAuth 認証トークンが更新された際にプロンプトキャッシュ（cache、計算済みの結果を一時保存して再利用する仕組み）が破棄される現象も修正された。さらに、ブロック動作を行う Stop フック（hook、特定イベントの発生時に起動されるスクリプト）が作動した後も直前の推論過程が保持され、一部のモデルでキャッシュ未ヒットによる再計算が発生するのを防ぐ。

MCP サーバー切断時のエラー報告を改善、接続完了後の起動が最大 50ms 高速化

起動時に MCP（Model Context Protocol、AI が外部ツールに接続するためのプロトコル）サーバーがツール一覧の取得中に切断された際、ツールが 0 個のまま接続中と表示されるのではなく、エラーが明確に報告されるようになった。claude.ai のリモートセッションにおいてブラウザ管理の MCP サーバー画面が閉じられた後も、各ターンの開始時に 60 秒間待たされることがなくなる。また、ヘッドレス（headless、ターミナルの画面がない実行形態）や SDK セッションの起動時、MCP サーバーの接続が完了次第、最初のターンが最大 50 ミリ秒早く開始される。注文システムが外部厨房と通信する際、回線が切れたらメニューが 0 件になるのではなく即座に故障を知らせ、切断された店舗に引きずられず、接続完了後は 50 ミリ秒早く注文が通るようなものだ。

全画面表示での空白化を解消、テキスト計測の再利用で描画性能を向上

講堂の大型スクリーンが文字描画エンジンを強化し、文章がどれほど長くても画面を伸縮しても突然白紙にならず、最新の字幕や修正内容が鮮明に投影されるようなものだ。全画面モードで数百回のツール呼び出しを伴う長い会話を行った際、画面が真っ白になる現象が発生しなくなった。ターミナルのリサイズ時や長い回答の初回描画時に文字の計測結果を再利用することで、描画パフォーマンスが向上している。実行中シェルコマンドのリアルタイムプレビューにおいて、手前の行が折り返された際に最新の出力行が隠れる不具合も解消された。ファイル編集の権限確認ダイアログで変更行が予告なく途切れて表示されていた問題も修正されている。

プラグイン検証で構造化 JSON 出力に対応、クラウド指標の欠落属性を補完

プラグイン管理と可観測性の統合において、claude plugin validate --json を実行することで機械可読な構造化レポートを出力できるようになった。プラグイン導入時、末尾にスラッシュや余分な ?・# が付いた GitHub マーケットプレイスの URL からも正しい .git クローン先を解析できる。旧バージョンから引き継いだセッションで Artifact を公開する際、「unexpected parameter note」エラーで失敗する問題も解消された。さらに、クラウドセッションから送信される OpenTelemetry の指標やイベントに、従来欠落していた user.email、organization.id、user.account_uuid の 3 属性が追加された。品質検査場が構造化データ出力に対応し、荷物のラベルに余計な記号が付いていても古い伝票の引き継ぎであっても、正しく解析して顧客と組織の属性を揃えて記録するようなものだ。

[VSCode] サイドバーにクイックフィルターを追加、セッションを状態別に分類

受信トレイの先頭にクイックタグを追加し、対応中や返信待ちをクリックするだけでメールを絞り込め、長い一覧を下まで探さずに済むようなものだ。VS Code 拡張機能のサイドバーにあるセッション一覧に絞り込み機能が追加された。進行中の項目を素早く抽出できる Active クイックフィルターボタンが新設されたほか、ユーザーの入力を待つ Needs input、実行中の Working、完了済みの Completed といった状態別フィルターメニューが加わった。複数のタスクを並行して進めている場合でも、すぐに対応が必要な対話を素早く見つけられる。

조직 관리자는 managedMcpServers 설정을 통해 HTTP 또는 SSE 기반 MCP(Model Context Protocol, AI가 외부 도구에 연결하기 위한 프로토콜) 서버를 모든 사용자에게 일괄 배포할 수 있으며, 서식은 .mcp.json과 같고 로컬 명령어는 건너뛴다.

{
  "managedMcpServers": {
    "company-docs": {"url": "https://mcp.internal.example.com/sse", "type": "sse"}
  }
}

allowedMcpServers는 사용자가 추가한 서버만 관리하도록 바뀌었으며, 업그레이드 후 managed-mcp.json 서버를 차단하려면 deniedMcpServers를 써야 한다. 관리 설정 파일, drop-in 파일, MDM plist 또는 HKLM 값의 구문 분석에 실패하면 Claude Code는 시작을 거부하고 출처를 밝힌다. MDM이나 관리 설정 파일로 지정한 policy helper가 실행된 뒤에도 forceRemoteSettingsRefresh 강제 새로고침이 올바르게 작동하도록 고쳐졌다. 총무팀이 공용 비품을 배포할 때 목록에 훼손이나 누락이 있으면 경비원이 정문에서 가로막고 확인하며 대충 들여보내지 않는 것과 같다.

무인 호스트용 권한 플래그 추가, 확인 필요한 동작은 자동 거부해 멈춤 방지

무인 자동 수납함에서 본인 서명이 필요한 등기 우편을 마주쳤을 때 규정대로 즉시 수취를 거부해 반송하고, 서명이 필요 없는 택배는 정상 통과시켜 창구가 마냥 멈춰 서지 않게 하는 것과 같다. 관리자 없이 돌아가는 헤드리스(headless, 터미널 창이 없는 실행 방식) 서버를 위해 다음 명령어로 실행할 수 있다.

claude --permission-prompts none

이 새 플래그는 무인 호스트의 자동화 파이프라인을 전담한다. 확인 대화상자를 띄워야 하는 동작을 마주치면 시스템이 자동으로 거부하며, 현재 활성화된 권한 모드(오토 모드 포함)는 백그라운드에서 자율 결정을 계속 내린다. 서버 스케줄러나 CI 파이프라인에서 세션을 실행할 때, 미승인 동작 하나 때문에 전체 작업이 하염없이 멈추는 문제를 방지한다.

GitLab 병합 요청 자동 인식, 터미널 상태 표시줄 배지 실시간 갱신

GitLab 프로젝트에서 명령줄 도구로 병합 요청을 관리할 때 터미널이 glab mr create, merge, close, reopen, note, update 등의 명령을 기본으로 인식한다. 해당 명령을 실행하면 접힌 도구 요약에 MR !N 형식으로 병합 요청 번호가 표시되고, 터미널 맨 아래 상태 표시줄의 MR 배지도 함께 새로고침된다. 브라우저 창을 번갈아 확인하지 않고도 명령줄에서 코드 검토와 병합 진행 상황을 간편하게 파악할 수 있다. 택배 추적기가 전용 바코드 인식을 지원해 특정 송장을 찍자마자 전용 라벨을 인쇄하고 영수증 맨 아래 상태 칸을 실시간으로 갱신하는 것과 같다.

GitLab 저장소에서 GitHub 앱 설치 명령 실행 시 대체 문서 안내

GitLab 저장소 안에서 /install-github-app 명령을 실행할 때 무효한 요청을 보내거나 모호한 오류를 내뿜지 않는다. 해당 명령이 GitHub 전용임을 명확히 설명하고, 자동화 파이프라인 구성을 위한 공식 GitLab CI/CD 문서 링크를 곧바로 안내한다. 여러 플랫폼을 함께 다루는 개발 팀도 명령어를 시험해 보는 과정에서 올바른 대안과 설정 가이드를 즉시 얻을 수 있다. 지하철 발권기에서 고속철도 시간표를 물었을 때 이곳은 지하철 전용 창구임을 안내하고 고속철도 환승 웹페이지로 가는 약도를 함께 띄워 주는 것과 같다.

Bash Read 거부 규칙 대폭 강화, 숨은 파일 경로의 보안 허점 차단

건물 보안 검색대의 투시 성능이 향상되어 금지 물품이 가방 비밀 주머니에 숨겨져 있든, 택배 옵션 값에 적혀 있든, 상자에 한데 담겨 운반되든 보안 요원이 정확히 잡아내 확인을 요구하는 것과 같다. 이전에는 Bash의 Read() 파일 읽기 거부 규칙에 보안 허점이 존재했다. 옵션 값(--ignore-revs-file=.env, -f.env, @file 등)으로 민감한 파일을 넘기거나 git diff, git grep의 대상 파일로 지정하거나 cd DIR && cat FILE 형태의 복합 명령어로 묶었을 때 감시망을 벗어나는 일이 있었으나, 이제 모두 차단 범위에 들어왔다. 거부 대상 파일이 포함된 폴더에 grep -r이나 cp -r을 실행할 때도 권한 확인을 거치도록 변경되었다.

훅으로 만든 워크트리 호환성 개선, 비표준 Git 탐색 오류 메시지 수용

워크트리(worktree, Git에서 한 프로젝트의 복제본을 병렬로 여러 개 여는 기능) 격리 환경을 사용할 때 자동화 파이프라인이 생성한 작업 영역의 호환성이 향상되었다. 훅(hook, 특정 이벤트가 일어났을 때 실행되는 스크립트)으로 워크트리를 자동 생성하는 프로젝트의 경우, 일부 환경에서 하부 git rev-parse 명령어가 "not a git repository" 외의 사용자 지정 오류를 반환하면 시스템이 잘못 판단하여 로드를 거부하던 문제가 해결되었다. 실험실 격리 부스에서 안전 밸브가 정상 배관을 통해 열렸다면 측정 장비가 생소한 코드를 띄우더라도 출입 시스템이 작업대를 차단하지 않는 것과 같다.

워크트리 격리 환경의 명령어 제약 완화, 메인 저장소 미접근 파이프라인 허용

보세 창고 안에서 물품을 정리할 때 화물이 세관 밖 본 창고로 흘러 들어가지 않는다는 점만 확인되면 내부에서 어떻게 분류하고 운반하든 경보가 울리지 않는 것과 같다. 워크트리(worktree, Git에서 한 프로젝트의 복제본을 병렬로 여러 개 여는 기능) 격리 환경에서 명령어를 실행할 때 적용되던 과도한 검증이 완화되었다. 이전에는 격리 세션에서 일상적인 Bash 반복문이나 xargs 파이프라인, 래퍼 스크립트로 감싼 명령어를 실행할 때 시스템이 지나치게 방어적으로 작동하여 거부하는 경우가 있었다. 메인 체크아웃 디렉터리에 접근할 위험이 없는 명령어는 정상적으로 실행되도록 변경되어 일상적인 배치 작업이 원활해졌다.

다중 세션 병렬 실행 시 설정 덮어쓰기 방지, 대화 재개 및 저장소 인식 안정화

여러 세션을 동시에 실행할 때 백그라운드에서 전역 설정 파일 ~/.claude.json의 변경 사항을 서로 되돌려 버리던 문제가 해결되어 작업 영역 신뢰, MCP 및 프로젝트 상태가 유실되지 않는다. 또한 저장된 세션에 내용물이 없는 첨부 항목이 포함되어 있을 때 --resume이 실패하거나 --continue가 빈 대화창을 열던 오류가 수정되어 매끄럽게 이어갈 수 있다. 일시적인 Git 확인 실패로 저장소 식별 정보를 잃어버리는 현상이 없어졌으며, claude.ai 사용자를 위한 백그라운드 GitHub 연결 확인 결과도 재시작 후까지 유지된다. 여러 비서가 하나의 서류 가방을 함께 쓸 때 각자 작성한 메모를 서로 덮어쓰지 않고, 빈 쪽지나 일시적 통신 오류를 만나도 프로젝트를 곧바로 알아보고 업무를 이어가는 것과 같다.

원격 제어 시 백그라운드 에이전트 종료 보장, 워크플로 결과 구문 강조 서식 적용

원격 제어 세션에서 중지를 누르면 백그라운드 에이전트와 워크플로가 확실하게 종료되며, 종료 중인 작업도 프로세스가 완전히 끝날 때까지 화면에 남아 다시 중지할 수 있다. 이전 실행이 완전히 종료되기 전에 워크플로를 재개하더라도 복제 에이전트가 중복 생성되지 않는다. 일시 중지된 원격 및 예약 세션에서 커넥터 도구 권한을 승인했을 때도 작업이 올바르게 이어진다. /workflows의 에이전트 상세 화면에서는 JSON 결과가 구문 강조 및 줄바꿈으로 깔끔하게 서식화되고 긴 내용은 펼치기 버튼 뒤로 접히며, 중첩 백그라운드 서브에이전트 결과도 부모 기록에 온전히 보존된다. 관제 센터에서 자동 운행 차량을 세울 때 비상 브레이크로 확실히 정차시키고 계기판 감시를 유지하며, 재출발 시 같은 차를 두 대 보내지 않고 운행 기록을 컬러로 깔끔하게 정리해 보관하는 것과 같다.

사용자 정의 명령의 프런트매터 모델 지정 적용, Vertex 모델 컨텍스트 상한 정상 반영

사용자 정의 명령 및 스킬 머리말에 지정한 model: 설정이 대화형 세션에서 정상 작동한다. 오토 모드에서 지원되지 않는 모델을 마주치더라도 현재 세션의 모델을 유지하여 작업이 중단되지 않도록 방지한다. 아울러 @YYYYMMDD 날짜 접미사가 붙은 Vertex 형식의 모델 ID의 경우, Claude Code가 자체적으로 알지 못하는 버전이더라도 환경 변수 CLAUDE_CODE_MAX_CONTEXT_TOKENS에 설정된 토큰 상한이 올바르게 적용된다. 전문 작업 배정 시스템에서 특정 기술자를 지정하면 해당 인력을 투입하고, 지원되지 않는 공법일 때는 기존 인력을 유지하며, 각 전문가의 작업 메모 길이를 엄격히 제한하는 것과 같다.

생각 과정 반복 거부 문제 수정, 토큰 갱신 시에도 프롬프트 캐시 유지

시험장의 연습장처럼 수험표를 바꾸거나 감독관이 잠시 멈추더라도 기존에 적어 둔 수식과 추론 기록이 그대로 보존되어 다음 문제에서 처음부터 다시 계산하지 않는 것과 같다. 대화 도중 모델의 생각 과정이 한 번 거부되었더라도 이후 턴에서 계속해서 거부되는 악순환이 해결되었다. 텔레메트리가 비활성화된 세션에서 OAuth 인증 토큰을 갱신할 때 프롬프트 캐시(cache, 이미 계산한 결과를 임시 저장해 재사용하는 기능)가 유실되던 문제도 수정되었다. 차단형 Stop 훅(hook, 특정 이벤트가 일어났을 때 실행되는 스크립트)이 실행된 뒤에도 직전 턴의 추론 맥락이 유지되어 특정 모델에서 캐시 미스로 인한 불필요한 재계산이 발생하지 않는다.

MCP 서버 연결 끊김 시 즉시 오류 보고, 연결 완료 후 첫 턴 시작 최대 50ms 단축

시작 시 MCP(Model Context Protocol, AI가 외부 도구에 연결하기 위한 프로토콜) 서버가 도구 목록을 조회하는 도중 연결이 끊기면 도구가 0개인 연결 상태로 표시되는 대신 오류가 명확하게 보고된다. claude.ai 원격 세션에서 브라우저 기반 MCP 서버 탭이 닫혔을 때 각 턴 시작마다 60초 동안 지연되던 문제도 해결되었다. 헤드리스(headless, 터미널 창이 없는 실행 방식) 및 SDK 세션 시작 시 MCP 서버 연결이 완료되면 첫 턴이 최대 50ms 빠르게 시작된다. 주문 시스템이 배달 주방과 연동될 때 주방 통신이 끊기면 메뉴가 0개로 나오는 대신 고장을 알리고, 오프라인 지점 때문에 주문이 밀리지 않으며, 연결이 완료되면 접수 속도가 50ms 빨라지는 것과 같다.

전체 화면 긴 대화 시 빈 화면 오류 해결, 텍스트 측정 재사용으로 렌더링 가속

강당의 대형 빔프로젝터가 조판 엔진을 개선하여 본문이 아무리 길거나 화면 창을 조절해도 화면이 하얗게 비지 않고 최신 자막과 수정 내역을 선명히 띄워 주는 것과 같다. 전체 화면 모드에서 수백 번의 도구 호출을 수반하는 긴 대화를 나눌 때 화면이 빈 대화로 나타나던 문제가 해결되었다. 터미널 창 크기를 조절하거나 긴 응답을 처음 렌더링할 때 텍스트 측정값을 재사용하여 반응 속도를 높였다. 실행 중인 셸 명령어의 실시간 출력 미리보기가 앞 줄의 자동 줄바꿈 때문에 최신 출력 줄을 가려 버리던 현상도 개선되었다. 파일 편집 권한 대화상자에서 변경 내용이 아무런 표시 없이 잘려 보이던 문제도 수정되었다.

플러그인 검증 시 구조화 JSON 지원, 클라우드 메트릭 누락 속성 복원

플러그인 관리 및 모니터링 연동 측면에서 claude plugin validate --json 실행 시 프로그램이 파싱할 수 있는 구조화된 검증 보고서를 출력할 수 있다. 플러그인 설치 시 끝에 슬래시나 불필요한 ?, #이 붙은 GitHub 마켓플레이스 URL에서도 올바른 .git 클론 주소를 정상적으로 해석한다. 이전 버전에서 이어받은 세션에서 Artifact를 게시할 때 "unexpected parameter note" 오류로 실패하던 문제도 해결되었다. 아울러 클라우드 세션에서 전송되는 OpenTelemetry 메트릭 및 이벤트에 누락되었던 user.email, organization.id, user.account_uuid 속성이 채워졌다. 품질 검사소가 구조화 데이터 내보내기를 도입하여 화물 라벨에 잡음 기호가 묻어 있거나 이전 접수 건을 이어받더라도 정확히 파싱해 고객과 조직 식별 정보를 온전히 남기는 것과 같다.

[VSCode] 사이드바에 퀵 필터 추가, 상태별로 세션을 손쉽게 분류

받은편지함 맨 위에 빠른 필터 탭을 추가하여 진행 중이나 답장 대기 항목을 누르기만 하면 긴 목록을 일일이 뒤지지 않고도 메일을 걸러낼 수 있는 것과 같다. VS Code 확장의 사이드바 세션 목록에 필터링 기능이 도입되었다. 진행 중인 작업을 빠르게 추려낼 수 있는 Active 퀵 필터 버튼이 추가되었으며, 사용자 입력을 기다리는 Needs input, 작업 중인 Working, 완료된 Completed 등의 상태 필터 메뉴가 마련되었다. 여러 작업을 동시에 진행할 때 즉각적인 조치가 필요한 대화를 빠르게 찾아낼 수 있다.
