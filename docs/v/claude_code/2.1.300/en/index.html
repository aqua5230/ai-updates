Claude Code 2.1.300

Released: 2026-10-14

Release notes

FEATURE

AWS Platform Adds Advisor Command to Bring In Experts for Suggestions

If you want a second opinion on Claude on AWS, you no longer need to switch between multiple chat windows.

The platform has added an advisor feature.

Picture a project conference room with an expert seat on standby: where a single assistant previously answered alone, you can now actively invite an advisor into the discussion.

Normally, no advisor runs quietly in the background until you explicitly enter /advisor, pass the --advisor flag at startup, or specify advisorModel in your configuration to launch one. If your team never uses this tool, you can disable it entirely using the environment variable CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1.

FEATURE

Mods Expand Interface Capabilities with Virtual Text and History Change Hooks

Developing custom extension mods gives you more flexible control over input boxes and screen rendering.

Think of placing reference grid paper beneath a transparent writing board: previously, you could only see physical ink, but now traceless guide text can surface and you can lift the layer at any time to inspect records.

Virtual text attributes let you display hint text inside the input box without ever polluting drafts or submitted prompts. An interface inspection function lets you review the activity history of a specific agent directly on the main screen, and passing an empty object returns you to the prior view. Text components now support right-to-left writing settings, displaying text direction correctly and aligning text to the right in Windows and VS Code terminals. A newly added input change hook triggers when retrieving history, clearing, undoing, or when plugins populate text. This also fixes an issue where entering a newline failed to trigger the edit hook.

FEATURE

Hooks Support Workflow Rewrites with Strict Validation for Inputs and Plugin Keys

When managing agent startup workflows through hooks, the biggest concern is external logic corrupting parameters or leaking secret keys.

A document exchange gate operated under strict limits: previously, it could only reject documents outright, but now a secretary can revise recipients and contents while automatically checking confidential seals before stamping approval.

Agent spawn hooks previously could only reject workflow agents, but they can now directly rewrite their prompts and models. When a hook returns updated inputs before tool execution or permission requests, the system filters unknown fields just like standard inputs, and inputs rejected by tools immediately block the call. Agent hooks now respect configured models, resolve aliases correctly, and cannot be overridden by subagents. If no model is found, they fall back to the caller's fallback model. When sharing modules, built-in skills actively scan for secret keys before opening files and ask for confirmation before scanning folders outside the project. Prompts rewritten or discarded by hooks, as well as module hot-reload notes, are no longer mistakenly logged to telemetry, session title requests, or conversation logs.

BUGFIX

Agent Lists and Task Views Fixed to Keep Sessions Open

Assigning multiple agents to work in parallel makes tracking progress and reviewing conversations more reliable.

Previously, subagents that had just replied would quickly vanish from the task list after completing their work, leaving you with no way to revisit the conversation; they are now properly preserved.

Like a library circulation catalog, where cards were once pulled immediately upon returning books and left readers unable to trace sources, every checkout record and hierarchical directory entry now stays neatly inside its slot.

When inspecting subagents, completed parent agents no longer drop from the top breadcrumb path, keeping hierarchical relationships clear. When typing quickly, if text contained arrow-key names, the agent screen previously misinterpreted them as keypresses, shifting the preview or even clearing drafts; this issue has been resolved. Agent commands no longer stall the entire update flow when encountering individual requests with incomplete data. Managed agent sessions within skills are now fully preserved unless you explicitly request archiving or deletion.

BUGFIX

Background Services Terminate Reliably Without Leaving Orphaned Processes

Running tests or builds in the background makes you worry about frozen terminals or leftover orphaned processes when exiting.

A building security guard conducts closing rounds: previously, if warehouse machinery was still running when lights went out, the back door was easily left unlocked, but now strict countdowns cut the main power directly to ensure a complete shutdown.

Previously, if background commands were still running when exiting the program, session-end hooks were sometimes skipped. Now, if a command does not close within 1.5 seconds after receiving a stop notification upon exit, the system forcibly terminates it. Stopping a daemon no longer creates the illusion that a frozen background service has stopped, and it returns error code 1 if cleanup fails. Stopping daemons when telemetry is disabled also no longer exits silently while leaving sessions stranded on the list. Executing background commands no longer polls output files repeatedly or falls into sleep. When background sessions resume workflows, they now resume execution through the workflow tool approval mechanism.

BUGFIX

Worktree Fixes Branch Resolution to Prevent Opening Wrong Versions on Tag Collisions

Large projects often require creating multiple Git worktrees to handle different features, and switching versions is now far more accurate.

Duplicating research booklets in an archive mirrors this challenge: previously, catalog cards with similar call numbers led to grabbing the wrong pages, but now each booklet maps precisely to the correct original chapter.

Previously, if a branch or tag name resembled a commit hash, launching a worktree could check out the wrong version and display another branch name in the status; this identification issue is now resolved. In projects adopting modern storage backends, bugs causing abnormal branch name display and failures when reopening worktrees have been fixed. In worktrees for bare repositories unable to fetch the remote default branch, the system falls back to using the currently checked-out version as the baseline. When launching a worktree, corresponding plugin creation and removal hooks now run reliably.

BUGFIX

Remote Control Reconnection and Diff Views Fixed with Dead Sandbox Flags Removed

Connecting back to your computer from the web or desktop apps now offers better connection stability and file comparison for remote control.

Monitoring a storefront through a remote surveillance feed captures this improvement: previously, transient signal interference cut the display completely, and shelf reorganizations treated removed cabinets as regular moves, but now the screen faithfully reflects the floor.

When encountering brief credential issues, the server no longer abandons connection renewals immediately; it retries automatically and prompts you to log in again only when necessary. When a single computer hosts multiple connections simultaneously, active sessions are no longer mistakenly marked as stopped. Diff views across web and desktop clients now accurately distinguish between deleted and renamed files instead of labeling them all as modified, and conflict states display correctly. A previously ineffective sandbox command-line parameter has been removed; if you need sandbox protection, set sandbox.enabled to true in your configuration file.

BUGFIX

MCP Tool Fault Tolerance and Auto-Search Fixed to Survive Reconnections

Integrating external services poses risks when brief network reconnections or formatting errors interrupt an entire conversation.

When auto tool search is enabled, if an MCP (Model Context Protocol) server reconnects halfway through, search previously shut down without warning; it now remains active after the fix.

Working through a multi-port docking station reflects this resilience: previously, if an external device wobbled and reconnected, the entire row of shortcuts would break, but the host now continues running smoothly even when individual slots experience signal anomalies.

When rejected external tool definitions trigger errors, subsequent turns transmit the tool without parameters, preventing every turn from getting stuck on 400 errors. For servers that finish connecting after session compaction, tools and descriptions update immediately. Resuming conversation history also avoids repeatedly searching for previously loaded deferred tools.

BUGFIX

Session Compaction and Record Retention Fixed to Protect Conversations Across Reboots

Deep, lengthy conversations and headless executions rely on scheduled summaries to prevent context from exceeding capacity limits.

In headless mode or within the Agent SDK, if compaction triggered when answers hit length limits or during retries, reconnecting could drop recent pending messages or summaries; these scenarios have been thoroughly fixed.

Binding bulky meeting transcripts into executive summaries follows a similar discipline: previously, a single paper jam during binding scattered key surrounding pages, but every concise summary and critical page reference is now securely stapled in place.

When abnormal terminations truncate the final line of a conversation log, reopening no longer loses the very next log entry. Conversations containing unusual newline characters no longer cause branch commands to lose messages or cleanup commands to skip subprojects. Shrinking the auto-compaction window no longer causes compaction commands to emit false high-quota warnings. Local session logs now record system prompts and tool parameters for every request, allowing precise reproduction.

BUGFIX

Cloud Sessions Fix Freezes to Let Agents Resume After Container Resets

Long-running cloud tasks face risks when server reboots or policy fetch failures freeze progress for minutes at a time.

Previously, if organization policies could not be retrieved, cloud sessions stalled for 5 minutes per turn; they now terminate the turn immediately and state the reason clearly.

Renting a video conference system for a remote office presents the same reality: previously, a brief line switch froze screens for several minutes or looped audio playback, but connection hurdles are now flagged with immediate reasons and handed off smoothly.

When a session's own network configuration blocks the host, it reports this truthfully instead of misidentifying the cause as organization policy restrictions. After cloud containers are replaced, background agents that resumed once are no longer falsely reported as permanently lost, continuing execution normally. A bug where restarting during long responses caused completed messages to run a second time has also been resolved. Finally, command descriptions in the slash menu no longer vanish after sending a second message in a cloud conversation.

BUGFIX

Cowork Cloud Fixes Phantom File Writes, Improves Web Scraping and Permission Flexibility

When delegating tasks in the Cowork cloud environment, the system previously could misreport unreceived local files as successfully saved.

Writing or editing files in the cloud with a specified local path used to show success even if the file never reached the machine; this false confirmation is now fixed.

Entrusting documents to a field clerk once meant signed files could sit tucked inside a personal drawer while being reported as delivered to your desk, but now each file transfer confirms its actual delivery.

The web scraping tool now explicitly explains the failure reason when encountering a freshly failed URL, rather than blindly fetching the same page again. When organizations disable allow-always, connector tool approval prompts previously missed the allow-for-this-task option, a regression that has been resolved. In cloud hooks, when an approval attempt tries to alter the mode, that modification is skipped while keeping the remaining approved items intact.

BUGFIX

Enterprise Gateways Tighten Policy Controls, Fixing Proxies and Residual Login Credentials

For enterprise environments navigating corporate security inspections and gateway controls, login credential and connection policy management is now much tighter.

Stepping into a corporate badge office once meant rejected visitors might still walk away holding an old keycard, but now a failed check revokes the card and reclaims access immediately.

When a login was previously rejected by a rule enforcing specific organizations, authorization tokens for the rejected organization used to linger; they are now wiped clean upon rejection. Behind proxy servers that perform TLS inspection through the operating system credential store, feature flags and staged rollouts update normally instead of getting stuck on older versions. Sessions in managed environments now ignore custom certificates and TLS variables in configuration files, preventing corporate policies from being overridden. The desktop Code tab applies managed settings when a gateway is specified, requiring a reachable gateway at launch. When encountering policy keys unsupported on desktop, gateway commands now name the offending key and abort on startup rather than merely issuing a warning.

FEATURE

Telemetry Records Break Down Cache Lifespans, Enabling Compression by Default on Large Requests

Monitoring API request costs and debugging traces now provides visibility into cache lifespans while conserving bandwidth through compression.

A revised shipping invoice mirrors how oversized parcels previously hogged truck space with only a total weight stamp, whereas cargo is now vacuum-compressed to save room while manifests note specific shelf lives for room-temperature and frozen goods.

Large requests sent to the API now enable gzip compression by default to accelerate transfers, which remains effective even if telemetry is disabled; setting CLAUDE_CODE_GZIP_REQUEST_BODIES=0 disables it. Telemetry traces introduce breakdown fields for cache lifespan, explicitly separating 5-minute and 1-hour write units. Trace spans now populate standard generative AI attributes, including provider name, conversation ID, tool name, and error type. A bug was resolved where tool execution results omitted commit hashes during quiet commits in new-style repositories.

FEATURE

Artifact Tool Supports Single-Turn Publishing, Improving Draft and Document Paths

Asking Claude to write long reports or modify code deliverables is now cleaner and faster as Artifact generation and refinement improve.

Standing before a typesetting bench once required proofreaders to restart an entire submission cycle for a single typo, whereas stamping and publishing now happen in the same revision alongside a full filing cabinet path clearly marked on the margin.

When modifying an artifact, minor updates and republishing can now be merged in a single call, while larger edits can also be republished directly within the same response without staged delays. Detailed status lines during artifact tool execution previously displayed unprintable path codes when receiving input, but now clearly indicate waiting and running states just like terminal commands. Files recorded in session scratchpads now use full absolute paths instead of confusing standalone filenames or relative paths. When referencing PDF documents in a conversation, the model receives clearer prompts, reducing instances where it hallucinates answers before reading the content.

BUGFIX

Terminal Text Contrast and Menu Descriptions Fixed, Eliminating Duplicate Startup Calls

Display details across various terminals and integrated editor panels now render dim text clearly without duplicate startup checks.

Under dark ANSI themes and 16-color terminals, secondary dim text previously appeared identical to standard text, making hierarchy hard to discern; contrast has now been adjusted.

Switching to clearer dashboard lighting reveals how low-contrast dark screens once blurred every gauge together, whereas secondary labels now feature proper grayscale tiers and starting the car no longer triggers two duplicate engine self-checks.

When launching in the integrated terminal of VS Code, Cursor, or Devin Desktop, extension check commands previously ran 2 times, but are now streamlined to launch only 1 time. Option labels in the sandbox menu have been changed from misleading names to more intuitive command names. Documentation introducing restricted mode arguments was corrected after erroneously listing removed tools.

BUGFIX

Self-Hosted Runners Fix Output Freezes, Preserving Health Checks and Polling

Running automated tasks on self-hosted servers risks silent runner freezes whenever logs go unread.

Previously, when output remained unread, runners and dispatchers stopped polling, health checks disconnected, and processes could not be shut down via signals.

Piles of paper on an automated printer tray used to halt the entire machine whenever uncollected, but it now actively shreds older sheets while retaining the freshest pages to keep printing.

Logs now retain the latest 256 KiB and track the count of discarded messages, excluding Windows systems, keeping services continuously operational.

BUGFIX

VS Code Adds Option to Disable Auto-Attaching Selected Text, Fixing Drag-and-Drop and Menus

Asking questions in VS Code can now prevent editor-selected text from being automatically inserted into the input box.

The new claudeCode.attachSelection setting disables automatic attachment when set to false.

Jotting reminders on a notepad used to capture every passage your pen grazed across a page while misplacing dropped photos, whereas it now accurately records only the notes you intend to leave.

Holding Shift while dragging files into the input box on Windows no longer inserts unreadable drive paths, correctly generating references relative to the working directory instead. Dragging files across WSL, remote SSH, or container environments is no longer unresponsive. Pressing the up arrow to recall previous slash commands and hitting Enter no longer drops original arguments. Editing previously bookmarked prompts is no longer obstructed by unexpected file menu popups. Pressing Ctrl+Alt+F across File Explorer, other tree views, or the debug console on Windows and Linux now opens search instead of erroneously toggling Focus view.

BUGFIX

VS Code Intelligently Toggles Thinking and Quota States, Fixing Multi-Window Locks

Switching models or reloading windows in VS Code risks requests getting trapped in retry loops once quotas run out.

Fast mode previously stayed on when quota was exhausted, causing requests to be repeatedly rejected and retried, but now displays an error prompt and turns off automatically.

Gauges on a smart desk once kept pressing deduct buttons despite insufficient prepaid card balances and mistook previous visitors for remaining after reboots, but they now recognize account statuses instantly and clear stale locks cleanly.

For models that always perform deep thinking, the interface no longer displays a redundant thinking toggle. Conversation font size changes now apply immediately to diff views and plan previews without requiring a window reload, and are no longer overridden by theme changes. Reloading tabs or clicking to resume a session no longer loses branch conversations moved to worktrees. The system now calls tools directly when checking sessions in other windows, avoiding redundant processes from frequent path searches. After a crash and reboot, the system no longer falsely reports conversations as open elsewhere when process IDs are reused by other software.

FEATURE

Slack Supports Cross-Organization Channels, Adding Ephemeral Approval Cards and Audio Clip Reading

Slack workspaces support cross-enterprise shared channels, enabling cross-company collaboration and authorization checks without switching tools.

Administrators can now allow Claude to respond in shared Slack Connect channels, an option disabled by default for privacy; existing channel permission bundles also remain effective after upgrading to cross-organization channels.

Joining a cross-company joint project meeting used to make an assistant clam up whenever outside contractors were present and loudly shout rejections when reviewing documents, but the assistant now quietly offers sign-off sheets while blending into multilateral discussions.

When a connector tool requires authorization, an ephemeral card visible only to you appears in the thread to allow once or deny instead of throwing an error, while others only see that the system awaits your decision. Audio clip support is added, enabling Claude to read contents whenever Slack generates a transcript. A bug was fixed where other bots tagging Claude under messages sent by Claude itself went unanswered.

BUGFIX

Code Review Supports Triggers from Private Members, Linking Status Notes to Permission Settings

Summoning Claude to review code in pull requests now lets private members trigger the review workflow smoothly.

Developers with write access whose GitHub organization membership was kept private previously found @claude review comments frequently ignored; the system now recognizes permissions accurately and launches reviews.

Entering a high-security research facility once meant guards rejected requests unless badges hung visibly on chests, but verifying an access badge now initiates clearance and closed checkpoints directly name which supervisor can open the door.

When repository review functionality is paused, comments no longer direct administrators to irrelevant settings landing pages, clearly naming authorized personnel instead and linking directly to the Git provider settings page.
