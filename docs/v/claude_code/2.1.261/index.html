技能診斷指令上線，揪出閒置技能與脈絡佔用

整理工具包就像教練定期盤點健身房器材，長期沒人碰又佔走走道的啞鈴就該清出場地。 當你為 Claude 掛載了五花八門的技能，對話脈絡（context）的容量很快就會吃緊。現在只要輸入 /skill-doctor，畫面就會列出目前載入的所有技能中，哪些從頭到尾都沒被呼叫過，以及它們個別佔用了多少 token（AI 處理與計費的文字單位）。當你發現某些擴充根本沒派上用場卻平白吃掉容量，就能依照診斷結果把它們卸載，替重要的對話釋出更多空間。

指令輸出上限拉高至 128K，支援由檔案讀取子代理提示詞

跑大型建置或查詢長篇日誌時，終端機輸出常因超過預設長度而被截斷存成外置檔案。現在你在設定檔中加入 bashOutputMaxChars 或 taskOutputMaxChars，就能把終端機指令與背景任務直接回傳給 Claude 的內嵌字數上限拉高，最高支援到 128K 字元：

{
  "bashOutputMaxChars": 131072,
  "taskOutputMaxChars": 131072
}

此外，當你要指派給子代理的系統提示詞（system prompt）過於龐大、無法塞進單行指令列時，也可以改用 --append-subagent-system-prompt-file <路徑> 直接從檔案載入。這有如把貨運小貨車升級成大型貨櫃車，長篇清單不用再拆箱分裝成小紙條，整批資料都能直接載進車廂。

終端機輸入手感翻修，對齊 Bash 快捷鍵與修復漏字

終端機裡的文字輸入與編輯體驗迎來了一批修復。當你快速連打、長按按鍵重複輸入或是整段貼上文字時，字元不再會偶發性掉字或前後順序顛倒；而在輸入框內嵌的 [Image #N] 圖片標籤前，緊鄰的前一個字元現在也能順利按退格鍵刪除。同時，輸入列的單字跳轉與刪除快捷鍵全面對齊 Bash 行為：按 Ctrl+W 會往回刪除到前一個空格，Alt+F 與 Alt+D 會精準停在單字結尾，標點符號也會被視為單字分界，而舊有的 keybindingFlavor 設定則不再產生作用。這就像換上一支書寫順暢的鋼珠筆，不管寫得多快都不會斷水卡墨，修改詞句時的橡皮擦也能精準擦到邊界。

收緊危險刪檔防護，自動模式禁止未授權圖表上傳

把整份講義印在公開影印店的取件網址上，店員會當成講義已經送出店外；碎紙單就算寫在引號裡或用代號，也一樣要再確認才准動手。 針對高風險的刪除指令，危險 rm 安全提示現在擴大攔截範圍，即使 rm -rf 寫在雙引號包覆的 sh -c 腳本內，或是帶有位置參數（positional parameters，如指令後方代入的變數代號），都會確實跳出確認提示。若連結把內容打包進公開圖表繪製網站的 URL，自動模式會視為上傳到該站，除非你主動要求，否則不再自動放行。

遠端操控同步修復，狀態顯示與離線佇列精準更新

透過手機或瀏覽器使用遠端操控（Remote Control）時，多項跨裝置狀態同步問題已全面修正。現在終端機切換權限模式，或是行動端連入終端機工作階段時，不會再顯示過期的權限狀態；從手機停止運作或執行 /clear 指令後，按鈕與旋轉載入圖示會即時歸位，不再卡在忙碌中。使用 /teleport 拉取的工作階段不會再重複附加到雲端對話紀錄，自訂的精力等級（effort level）也能正確呈現在網頁上。在 Windows 企業代理伺服器環境下的事件串流已修復，若向另一台離線機器的工作階段發送 SendMessage，系統也會明確告知訊息已進入佇列等候重連。這有如拿著對講機指揮總部作業，雙方的狀態訊號隨時同步，發給離線人員的留言也會妥善留在收件箱中等待簽收。

企業閘道管理強化，組織政策診斷與登入規範更清楚

門牌後黏了樓層號要拆出真門號；門牌讀不出來就拒收，紙本與電子改同一套格式。 /status 與 claude doctor 新增組織政策行，代理攔阻政策載入失敗會標原因。受信任代理在 X-Forwarded-For 附加通訊埠時，閘道會修正客戶端 IP；有 access list 時無法判讀的項目回 403。閘道曾叫 Desktop 用 JSON 匯出 OpenTelemetry，CLI 用 protobuf 時只收 protobuf 的收集器會拒收 Desktop 資料，已對齊。載入受管設定遭拒時改說該組織可能未啟用服務，而非叫你重登入。forceLoginMethod: "gateway" 鎖定時忽略殘留 API key 或 claude.ai 登入並要求 /login；Bedrock、Vertex AI 與 Foundry 工作階段不受影響。

雲端驗證流程加速，清楚顯示模型名稱且連線不卡死

設定 Bedrock 時，若 AWS 憑證（credential，證明你是合法使用者的金鑰）輔助程式無回應，引導精靈不會再無限期卡住，而是會在逾時後印出明確錯誤，並修正了在安全檢驗代理伺服器後的檢查失敗。gcpAuthRefresh 在憑證仍有效、只是檢查稍慢時，不會再於啟動時打開瀏覽器；設定 GOOGLE_APPLICATION_CREDENTIALS 也不會再反覆搜尋專案或啟動額外行程。啟動時抓 claude.ai 連接器若逾時，整個工作階段都會看不見它們，CLI 改在背景重試。/model 選單與 VS Code 模型膠囊在辨識得出時，會顯示名稱而非 Bedrock、Vertex AI 或 LLM gateway 的原始 ID。這好比拿著跨國貴賓卡登機，櫃台能直接辨識你的身分並快速放行，遇到連線延遲也會在後台自動補驗，不必每次都把你叫去重辦手續。

工作階段恢復不掉訊，多代理協作快取與外掛同步修復

中斷後重新接續工作階段時，系統現在能更忠實還原當時的上下文。以前恢復工作階段時，平行工具呼叫旁的掛鉤（hook，特定事件發生時被觸發的小程式）輸出常會遺失，現在已能完整保留；使用 claude -p --resume 若遇到紀錄檔內的工作階段識別碼損壞，也會自動配發新識別碼安全重啟。在多代理協作中，隊友代理在第二輪不會再重複廣播初始技能，確保前綴完整並命中快取（cache，把查過的結果暫存起來直接用）；背景代理若無法喚醒，也不會再陷入迴圈空轉消耗 CPU。此外，剛送出提示詞立刻按下停止現在能確實中斷執行，雲端工作階段強制啟用已同步的外掛時，也不會再錯誤降級至市集備援版本。這就像接力賽交棒，跑者換人時能精準接過寫滿備忘的交接棒，不用重新宣告身分，遇到突發狀況也能立刻煞車。

終端機進度指示精準回報，文字串流加速且計量不浪費

月台資訊看板在列車還在進站時不能亮「已離站」，轉乘等候的倒數也要跟公告上限同一套，不能自己再加一輪。 在 iTerm2、Ghostty 或 ConEmu 等終端機中，進度指示器以前會在背景工作流程或代理仍在運作時提早把工作階段標記為完成，現在已修正為如實反映背景狀態。文字串流輸出時，排版引擎不再對已繪製完成的區塊重複運算，大幅提升了長篇回覆的顯示流暢度，也修復了容器方向切換時區塊高度異常的罕見錯誤。當你執行 /context 查看容量，若遠端計量服務無法連線，系統會改用本機演算法估算 token（AI 處理與計費的文字單位），不再額外呼叫小型模型浪費資源。遇到 API 無回應標頭時，重試會等到 API_TIMEOUT_MS（預設 10 分鐘）為止，不再另等 3 分鐘，提示訊息會說明可改 API_TIMEOUT_MS。

跨工具協作修復，自動掛載目錄與用量查詢更穩定

掛載在 /net automount 網路目錄下執行 /add-dir 加入子資料夾時，系統不再會誤報找不到路徑；當同一台電腦安裝多個版本時，高版本的功能旗標也不會再錯誤干擾舊版本。當用量端點被限流，或剛啟動就打開時，/usage 與 VS Code 用量面板不再丟掉特定模型的每週額度列。桌面版與網頁版在僅監聽產物（artifact）更新時，狀態也不會再錯誤卡在忙碌中。此外，桌面版 Cowork 工作階段中透過 Chrome 擴充上傳檔案的錯誤已排除，背景執行的指令若輸出外掛安裝提示，也能正確被系統辨識，不會把原始的 <claude-code-hint> 標籤洩漏到對話框裡。這宛如在多工工地整頓各組機具，圖紙路徑標註清晰，讓不同的協作工具各司其職且不互相打架。

[VSCode] 介面內建樣式精靈，直接新增與管理 MCP 伺服器

在 VS Code 擴充套件中自訂輸出風格與工具整合變得更加直覺。Output styles 選單新增了「建立自訂樣式」引導流程，能帶你一步步撰寫自訂輸出樣式檔，完成後立刻列在選單中隨選即用。針對 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器管理，對話框中現在直接提供了新增表單與刪除按鈕，你再也不用手動切出編輯器去修改設定檔，就能在介面內隨時加入或卸載各類外部工具伺服器。這如同在畫架旁直接加裝模組化置物盒，想換筆刷或顏料伸手就能裝上，不必每次都離開座位去工具箱翻找。

[VSCode] 工作階段清單標示強化，支援封存與分頁修復

管理多個工作階段就像整理辦公室公文夾，哪些案件正在其他部門借閱中、哪些該歸檔，都該有清楚的視覺標記。 工作階段清單現在為終端機、其他視窗或桌面版開啟中的工作階段標上空心圓圈，不再看起來像已關閉；右鍵選單加入了「封存工作階段」（Archive session）功能，解除封存也有了專屬圖示。隨視窗還原的分頁在重新命名時，輸入框會正確帶出當前名稱而非一片空白；清單中已摺疊的分類在面板載入時不會再短暫閃爍展開，修正背景分頁識別碼時選取列的高亮也不會卡死。透過快速鍵或連結重新開啟分頁時，Claude 分頁也會精準回到既有的編輯器分組中。

[VSCode] 提問與授權提示支援摺疊，排隊對話框不再殘留文字

互動介面上的各類提示卡片迎來了更流暢的操作體驗。權限與提問對話框現在新增了摺疊按鈕，讓你不用關閉提示就能瀏覽後方遮住的對話內容，提示旁的空白區域也能直接滾動對話歷史。連續排隊的授權對話框不會再殘留上一個提示打進去的文字，也避免了因連點而誤觸授權；焦點檢視（Focus view）中已結束的工具呼叫不再錯誤顯示為執行中。以 Claude.ai 或主控台（Console）帳號登入時，重載面板後等待回答的問題卡片會正常重現；使用 /btw 插話提問時，先前工作階段的歷史紀錄也不會再因視窗重載或設定檔出錯而被洗掉。這如同在服務櫃台前加裝透明活動板，既能隨時掀開查看底下的文件明細，叫號處理業務時也不會把上一位顧客留下的便條紙混進下一張表單。

[VSCode] 雲端工作階段遷移修復，分組與多視窗同步更穩定

跨裝置切換開發環境就像在不同會議室之間移動白板，任何未完的討論都該原樣帶入新空間。 從網頁版傳送（teleport）工作階段至本機時，若雲端關閉時恰好有提問中斷，系統不會再將其誤判為拒絕；將網頁工作階段加入分組時，也不會再同時出現在兩個群組中。清單開的分頁重載後不跳回舊工作階段；Web 開的分頁重載後不重跑 teleport、不留白。設定「Enable Remote Control for all sessions」會立刻套用到其他 VS Code 視窗。Open 篩選器能對上從 claude.ai 續接、分頁仍記在 web session 的項目，篩選選單區塊加上螢幕報讀標籤。「Start new session in this group」在 New conversation 後不再丟掉群組；sidebar 未讀清單載入前就結束的工作階段，不再缺未讀點。

[VSCode] 模型選單整併為單一清單，用量指示與登入防護修復

模型選擇器與側邊欄狀態管理在此次更新中進行了整頓。模型選單現在改為平整的單一清單，舊有名稱寫法統一排在最後，且能即時隱藏公司已停用的模型。若設定了停用登入提示，介面就不會再於未登入時強行跳出登入畫面；當某個面板切換至第三方模型供應商時，其他面板也不會再殘留官方專屬功能。新視窗側邊欄的用量計量表現在一開就能正常顯示，不再漏掉零用量上限；此外外掛安裝連結能正確喚起確認對話框，分頁標籤在執行中不會再誤亮未讀徽章，封存的工作階段也能順利加入分組。這好比餐廳重新整理總菜單，下架品項一目了然，服務生也不會拿著舊通行證向已免檢的客人反覆查驗身分。

Skill diagnostic command introduced to spot unused skills and context consumption

Organizing your toolkit is like a coach taking inventory of gym equipment: dumbbells that remain untouched for a long time and block the aisles should be cleared off the floor. When you load various skills into Claude, conversation context capacity can quickly become strained. Simply typing /skill-doctor now displays which of all currently loaded skills have never been invoked, as well as how many tokens each consumes. Once you discover extensions sitting unused while eating up capacity, you can prune them based on the diagnostic results to free up room for important conversations.

Command output limit raised to 128K, supporting subagent prompt loading from files

When running large builds or querying lengthy logs, terminal output is often truncated and saved to an external file because it exceeds the default length. Now, by adding bashOutputMaxChars or taskOutputMaxChars to your configuration file, you can raise the inline character limit for terminal commands and background tasks returned directly to Claude, supporting up to 128K characters:

{
  "bashOutputMaxChars": 131072,
  "taskOutputMaxChars": 131072
}

Additionally, when a system prompt assigned to a subagent is too large to fit on a single command line, you can use --append-subagent-system-prompt-file <path> to load it directly from a file. This is like upgrading from a delivery van to a large freight container truck: instead of unboxing a long manifest into small paper slips, the entire shipment can be loaded directly into the cargo hold.

Terminal input experience revamped, aligning with Bash shortcuts and fixing dropped characters

The text input and editing experience in the terminal has received a batch of fixes. Characters no longer occasionally drop or swap order when typing rapidly, holding down a key to repeat input, or pasting text blocks. The character immediately preceding an inline [Image #N] image chip in the input box can now also be smoothly removed using the Backspace key. Meanwhile, word navigation and deletion shortcuts in the prompt input fully align with Bash behavior: pressing Ctrl+W deletes backward to the previous whitespace, Alt+F and Alt+D stop precisely at word endings, punctuation is treated as a word boundary, and the legacy keybindingFlavor setting no longer has any effect. This is like switching to a smooth-writing rollerball pen that never skips or blobs no matter how fast you write, while an eraser cleanly wipes up to the boundary when modifying words.

Dangerous file deletion safeguards tightened, auto mode blocks unauthorized diagram uploads

Printing an entire handout onto the pickup URL of a public copy shop makes the clerk treat the handout as already sent outside; shredding orders must also be re-confirmed before executing, even if written inside quotes or using aliases. For high-risk deletion commands, the dangerous-rm safety prompt has expanded its interception scope: a confirmation prompt now reliably pops up even if rm -rf is inside a double-quoted sh -c script or involves positional parameters. If a link packages content into the URL of a public diagram rendering site, auto mode treats it as an upload to that site and will no longer auto-approve it unless you explicitly requested it.

Remote Control sync fixes: accurate status displays and offline queue updates

When using Remote Control from a phone or browser, multiple cross-device status synchronization issues have been thoroughly resolved. Switching permission modes in the terminal or attaching to a terminal session from a mobile device no longer displays a stale permission status. After stopping a run or executing a /clear command from a phone, buttons and loading spinners now reset immediately instead of remaining stuck in a busy state. Sessions pulled via /teleport are no longer redundantly appended to cloud conversation history, and custom effort levels now reflect correctly on the web. Event streaming under Windows enterprise proxy environments has been fixed, and sending SendMessage to a session on an offline machine now clearly informs you that the message is queued awaiting reconnection. This is like directing headquarters operations via walkie-talkie: status signals remain synchronized on both ends, while messages sent to offline personnel stay safely in their inbox waiting for acknowledgement.

Enterprise gateway management enhanced with clearer organization policy diagnostics and login rules

When a floor number is attached behind a house number, the true address must be parsed out; if the address is unreadable, it is rejected, while paper and electronic formats are unified into the same standard. /status and claude doctor add an Organization policy line that marks the reason when proxy blocking causes policy loading to fail. When a trusted proxy appends a port to X-Forwarded-For, the gateway corrects the client IP, and unreadable entries return 403 when an access list is configured. The gateway previously told Desktop to export OpenTelemetry as JSON while the CLI used protobuf, causing protobuf-only collectors to reject Desktop data; these have now been aligned. When loading managed settings is denied, the message now states that the organization may not have enabled the service instead of advising a re-login. When locked by forceLoginMethod: "gateway", leftover API keys or claude.ai logins are ignored to require /login, while Bedrock, Vertex AI, and Foundry sessions remain unaffected.

Cloud authentication accelerated, clearly displaying model names and preventing connection hangs

During Bedrock setup, if an AWS credential helper fails to respond, the setup wizard no longer hangs indefinitely but prints a clear error upon timeout, while also fixing check failures behind TLS-inspecting proxies. gcpAuthRefresh no longer opens a browser at startup when Google credentials are still valid but checks are slightly slow, and configuring GOOGLE_APPLICATION_CREDENTIALS avoids repeatedly searching for projects or spawning extra processes. When fetching claude.ai connectors at startup times out, which previously made them invisible for the entire session, the CLI now retries in the background. The /model picker and VS Code model pill now display recognizable model names instead of raw Bedrock, Vertex AI, or LLM gateway IDs when identified. This is like boarding with an international VIP card: the counter immediately recognizes your identity for quick clearance, while background verification runs automatically during connection delays instead of repeatedly calling you over to reapply.

Session resume preserves context, fixing multi-agent collaboration cache and plugin syncing

When resuming an interrupted session, the system now more faithfully restores the context from that point. Previously, hook outputs around parallel tool calls were often lost when resuming a session, but they are now fully preserved. Running claude -p --resume with a corrupted session ID in the transcript will automatically assign a fresh session ID for a safe restart. In multi-agent collaboration, teammate agents no longer re-broadcast initial skills on the second turn, ensuring prefix integrity and hitting the cache. If a background agent fails to wake up, it no longer enters a tight loop burning CPU. Furthermore, clicking stop right after sending a prompt now reliably halts execution, and cloud sessions force-enabling synced plugins will no longer erroneously fall back to marketplace clones. This is like passing the baton in a relay race: the next runner smoothly takes the note-covered baton without re-announcing their identity, and can brake immediately if an unexpected event occurs.

Terminal progress indicator reports accurately, accelerating text streaming and avoiding wasted metering

A platform information board must not display "Departed" while the train is still pulling into the station, and transfer wait countdowns must follow the posted ceiling rather than adding an extra round on their own. In terminals like iTerm2, Ghostty, or ConEmu, the progress indicator previously marked sessions as finished prematurely while background workflows or agents were still running; it has now been fixed to faithfully reflect background status. During text streaming, the layout engine no longer recalculates already-rendered blocks, significantly improving rendering smoothness for long responses and fixing a rare glitch where block height corrupted when containers switched directions. When running /context to check capacity, if the remote token-counting API is unavailable, the system switches to local estimation instead of making extra small-model requests. When the API sends no response headers, retries wait up to API_TIMEOUT_MS (10 minutes by default) instead of adding another 3 minutes, with messages explaining that API_TIMEOUT_MS can be adjusted.

Cross-tool collaboration fixes: automount directory handling and usage queries stabilized

When running /add-dir to add a subdirectory while mounted under a /net automount directory, the system no longer falsely reports that the path could not be resolved. On machines with multiple versions installed, feature flags gated to newer versions no longer mistakenly affect older versions. When the usage endpoint is rate-limited or accessed immediately after startup, /usage and the VS Code usage panel no longer drop weekly limit rows for specific models. Desktop and web sessions no longer stay incorrectly busy when only watching artifacts for updates. In addition, file upload failures via the Chrome extension in Desktop Cowork sessions have been resolved, and plugin install hints output by background commands are now properly recognized without leaking raw <claude-code-hint> tags into the conversation. This is like organizing equipment across a multi-trade construction site: blueprints and pathways are clearly marked so that different collaborating tools work in harmony without clashing.

[VSCode] Built-in style walkthrough added, directly create and manage MCP servers

Customizing output styles and tool integrations in the VS Code extension has become much more intuitive. The Output styles menu adds a "Build a custom style" walkthrough that guides you step-by-step to write a custom output style file and lists it immediately for instant use. For MCP server management, the dialog now provides an Add server form and Remove button directly, allowing you to add or remove external tool servers inside the IDE without manually switching out to edit configuration files. This is like attaching a modular organizer right beside your easel: whenever you want to swap brushes or paints, you can reach out and attach them without leaving your seat to rummage through a toolbox.

[VSCode] Session list indicators enhanced, supporting archiving and tab fixes

Managing multiple sessions is like organizing office folders: which cases are currently on loan to other departments and which should be archived must have clear visual markers. The session list now marks sessions open in a terminal, another window, or Claude Desktop with a hollow ring so they no longer appear closed. The right-click menu adds "Archive session", while Unarchive gets its own icon. When renaming a tab restored with the window, the input box correctly populates with the current name instead of opening blank. Collapsed sections in the list no longer briefly flash expanded when the panel loads, and the active-row highlight no longer freezes when correcting an unfocused tab's session ID. Reopening tabs via shortcuts or links now accurately places Claude tabs back into their existing editor group.

[VSCode] Question and permission prompts support folding, queued dialogs no longer retain text

Interactive prompt cards now offer a smoother operational experience. Permission and question prompts add a fold button so you can view underlying conversation content without dismissing the prompt, while the blank space beside the prompt can directly scroll conversation history. Successive queued permission dialogs no longer retain text typed into the previous prompt, preventing accidental approvals from rapid double-clicking. Completed tool calls in Focus view no longer mistakenly show as running. When signed in with a Claude.ai or Console account, pending question cards reappear properly after reloading the panel. When asking side questions with /btw, previous session history is no longer overwritten by window reloads or configuration errors. This is like installing a transparent movable flap at a service counter: you can lift it anytime to inspect document details underneath, and calling the next ticket will not mix notes left by the previous customer into the next form.

[VSCode] Cloud session migration fixes: grouping and multi-window sync stabilized

Switching development environments across devices is like moving a whiteboard between conference rooms: any unfinished discussion should be brought intact into the new space. When teleporting a session from the web to a local machine, questions interrupted as the cloud session shuts down are no longer misinterpreted as declined. Adding a web session to a group will no longer cause it to appear in two groups simultaneously. Tabs opened from the list do not jump back to older sessions after reloading, while tabs opened from web sessions do not re-run teleport or stay blank after reloads. Setting "Enable Remote Control for all sessions" applies immediately to other VS Code windows. The Open filter properly matches items continued from claude.ai whose tabs remain recorded under web sessions, with filter menu sections labeled for screen readers. "Start new session in this group" no longer loses its group after New conversation, and sessions ending before the sidebar unread list loads no longer miss their unread dot.

[VSCode] Model menu consolidated into flat list, usage indicators and login guards fixed

The model picker and sidebar state management have been overhauled in this update. The model menu is now a flat single list where legacy spellings are placed last, while immediately hiding models disabled by an organization. If the Disable Login Prompt setting is enabled, the interface no longer forces a sign-in screen when not logged in. When one panel switches to a third-party model provider, other panels no longer retain official-only features. The sidebar usage meter in a new window renders properly right upon opening without missing a 0% usage limit. Furthermore, plugin install links correctly trigger confirmation dialogs, tab badges no longer mistakenly illuminate unread during a running turn, and archived sessions can be successfully added to groups. This is like a restaurant reorganizing its master menu: discontinued items are clear at a glance, and servers will not repeatedly challenge exempt guests using outdated access passes.
