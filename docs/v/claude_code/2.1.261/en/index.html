Claude Code 2.1.261

Released: 2026-09-04

Release notes

FEATURE

Skill diagnostic command introduced to spot unused skills and context consumption

Organizing your toolkit is like a coach taking inventory of gym equipment: dumbbells that remain untouched for a long time and block the aisles should be cleared off the floor.

When you load various skills into Claude, conversation context capacity can quickly become strained.

Simply typing /skill-doctor now displays which of all currently loaded skills have never been invoked, as well as how many tokens each consumes. Once you discover extensions sitting unused while eating up capacity, you can prune them based on the diagnostic results to free up room for important conversations.

FEATURE

Command output limit raised to 128K, supporting subagent prompt loading from files

When running large builds or querying lengthy logs, terminal output is often truncated and saved to an external file because it exceeds the default length.

Now, by adding bashOutputMaxChars or taskOutputMaxChars to your configuration file, you can raise the inline character limit for terminal commands and background tasks returned directly to Claude, supporting up to 128K characters:

{
  "bashOutputMaxChars": 131072,
  "taskOutputMaxChars": 131072
}

Additionally, when a system prompt assigned to a subagent is too large to fit on a single command line, you can use --append-subagent-system-prompt-file <path> to load it directly from a file.

This is like upgrading from a delivery van to a large freight container truck: instead of unboxing a long manifest into small paper slips, the entire shipment can be loaded directly into the cargo hold.
BUGFIX

Terminal input experience revamped, aligning with Bash shortcuts and fixing dropped characters

The text input and editing experience in the terminal has received a batch of fixes.

Characters no longer occasionally drop or swap order when typing rapidly, holding down a key to repeat input, or pasting text blocks. The character immediately preceding an inline [Image #N] image chip in the input box can now also be smoothly removed using the Backspace key. Meanwhile, word navigation and deletion shortcuts in the prompt input fully align with Bash behavior: pressing Ctrl+W deletes backward to the previous whitespace, Alt+F and Alt+D stop precisely at word endings, punctuation is treated as a word boundary, and the legacy keybindingFlavor setting no longer has any effect.

This is like switching to a smooth-writing rollerball pen that never skips or blobs no matter how fast you write, while an eraser cleanly wipes up to the boundary when modifying words.
FEATURE

Dangerous file deletion safeguards tightened, auto mode blocks unauthorized diagram uploads

Printing an entire handout onto the pickup URL of a public copy shop makes the clerk treat the handout as already sent outside; shredding orders must also be re-confirmed before executing, even if written inside quotes or using aliases.

For high-risk deletion commands, the dangerous-rm safety prompt has expanded its interception scope: a confirmation prompt now reliably pops up even if rm -rf is inside a double-quoted sh -c script or involves positional parameters.

If a link packages content into the URL of a public diagram rendering site, auto mode treats it as an upload to that site and will no longer auto-approve it unless you explicitly requested it.

BUGFIX

Remote Control sync fixes: accurate status displays and offline queue updates

When using Remote Control from a phone or browser, multiple cross-device status synchronization issues have been thoroughly resolved.

Switching permission modes in the terminal or attaching to a terminal session from a mobile device no longer displays a stale permission status. After stopping a run or executing a /clear command from a phone, buttons and loading spinners now reset immediately instead of remaining stuck in a busy state. Sessions pulled via /teleport are no longer redundantly appended to cloud conversation history, and custom effort levels now reflect correctly on the web. Event streaming under Windows enterprise proxy environments has been fixed, and sending SendMessage to a session on an offline machine now clearly informs you that the message is queued awaiting reconnection.

This is like directing headquarters operations via walkie-talkie: status signals remain synchronized on both ends, while messages sent to offline personnel stay safely in their inbox waiting for acknowledgement.
FEATURE

Enterprise gateway management enhanced with clearer organization policy diagnostics and login rules

When a floor number is attached behind a house number, the true address must be parsed out; if the address is unreadable, it is rejected, while paper and electronic formats are unified into the same standard.

/status and claude doctor add an Organization policy line that marks the reason when proxy blocking causes policy loading to fail.

When a trusted proxy appends a port to X-Forwarded-For, the gateway corrects the client IP, and unreadable entries return 403 when an access list is configured. The gateway previously told Desktop to export OpenTelemetry as JSON while the CLI used protobuf, causing protobuf-only collectors to reject Desktop data; these have now been aligned. When loading managed settings is denied, the message now states that the organization may not have enabled the service instead of advising a re-login. When locked by forceLoginMethod: "gateway", leftover API keys or claude.ai logins are ignored to require /login, while Bedrock, Vertex AI, and Foundry sessions remain unaffected.

FEATURE

Cloud authentication accelerated, clearly displaying model names and preventing connection hangs

During Bedrock setup, if an AWS credential helper fails to respond, the setup wizard no longer hangs indefinitely but prints a clear error upon timeout, while also fixing check failures behind TLS-inspecting proxies.

gcpAuthRefresh no longer opens a browser at startup when Google credentials are still valid but checks are slightly slow, and configuring GOOGLE_APPLICATION_CREDENTIALS avoids repeatedly searching for projects or spawning extra processes. When fetching claude.ai connectors at startup times out, which previously made them invisible for the entire session, the CLI now retries in the background. The /model picker and VS Code model pill now display recognizable model names instead of raw Bedrock, Vertex AI, or LLM gateway IDs when identified.

This is like boarding with an international VIP card: the counter immediately recognizes your identity for quick clearance, while background verification runs automatically during connection delays instead of repeatedly calling you over to reapply.
BUGFIX

Session resume preserves context, fixing multi-agent collaboration cache and plugin syncing

When resuming an interrupted session, the system now more faithfully restores the context from that point.

Previously, hook outputs around parallel tool calls were often lost when resuming a session, but they are now fully preserved. Running claude -p --resume with a corrupted session ID in the transcript will automatically assign a fresh session ID for a safe restart. In multi-agent collaboration, teammate agents no longer re-broadcast initial skills on the second turn, ensuring prefix integrity and hitting the cache. If a background agent fails to wake up, it no longer enters a tight loop burning CPU. Furthermore, clicking stop right after sending a prompt now reliably halts execution, and cloud sessions force-enabling synced plugins will no longer erroneously fall back to marketplace clones.

This is like passing the baton in a relay race: the next runner smoothly takes the note-covered baton without re-announcing their identity, and can brake immediately if an unexpected event occurs.
FEATURE

Terminal progress indicator reports accurately, accelerating text streaming and avoiding wasted metering

A platform information board must not display "Departed" while the train is still pulling into the station, and transfer wait countdowns must follow the posted ceiling rather than adding an extra round on their own.

In terminals like iTerm2, Ghostty, or ConEmu, the progress indicator previously marked sessions as finished prematurely while background workflows or agents were still running; it has now been fixed to faithfully reflect background status.

During text streaming, the layout engine no longer recalculates already-rendered blocks, significantly improving rendering smoothness for long responses and fixing a rare glitch where block height corrupted when containers switched directions. When running /context to check capacity, if the remote token-counting API is unavailable, the system switches to local estimation instead of making extra small-model requests. When the API sends no response headers, retries wait up to API_TIMEOUT_MS (10 minutes by default) instead of adding another 3 minutes, with messages explaining that API_TIMEOUT_MS can be adjusted.

BUGFIX

Cross-tool collaboration fixes: automount directory handling and usage queries stabilized

When running /add-dir to add a subdirectory while mounted under a /net automount directory, the system no longer falsely reports that the path could not be resolved.

On machines with multiple versions installed, feature flags gated to newer versions no longer mistakenly affect older versions. When the usage endpoint is rate-limited or accessed immediately after startup, /usage and the VS Code usage panel no longer drop weekly limit rows for specific models. Desktop and web sessions no longer stay incorrectly busy when only watching artifacts for updates. In addition, file upload failures via the Chrome extension in Desktop Cowork sessions have been resolved, and plugin install hints output by background commands are now properly recognized without leaking raw <claude-code-hint> tags into the conversation.

This is like organizing equipment across a multi-trade construction site: blueprints and pathways are clearly marked so that different collaborating tools work in harmony without clashing.
FEATURE

[VSCode] Built-in style walkthrough added, directly create and manage MCP servers

Customizing output styles and tool integrations in the VS Code extension has become much more intuitive.

The Output styles menu adds a "Build a custom style" walkthrough that guides you step-by-step to write a custom output style file and lists it immediately for instant use. For MCP server management, the dialog now provides an Add server form and Remove button directly, allowing you to add or remove external tool servers inside the IDE without manually switching out to edit configuration files.

This is like attaching a modular organizer right beside your easel: whenever you want to swap brushes or paints, you can reach out and attach them without leaving your seat to rummage through a toolbox.
BUGFIX

[VSCode] Session list indicators enhanced, supporting archiving and tab fixes

Managing multiple sessions is like organizing office folders: which cases are currently on loan to other departments and which should be archived must have clear visual markers.

The session list now marks sessions open in a terminal, another window, or Claude Desktop with a hollow ring so they no longer appear closed.

The right-click menu adds "Archive session", while Unarchive gets its own icon. When renaming a tab restored with the window, the input box correctly populates with the current name instead of opening blank. Collapsed sections in the list no longer briefly flash expanded when the panel loads, and the active-row highlight no longer freezes when correcting an unfocused tab's session ID. Reopening tabs via shortcuts or links now accurately places Claude tabs back into their existing editor group.

FEATURE

[VSCode] Question and permission prompts support folding, queued dialogs no longer retain text

Interactive prompt cards now offer a smoother operational experience.

Permission and question prompts add a fold button so you can view underlying conversation content without dismissing the prompt, while the blank space beside the prompt can directly scroll conversation history. Successive queued permission dialogs no longer retain text typed into the previous prompt, preventing accidental approvals from rapid double-clicking. Completed tool calls in Focus view no longer mistakenly show as running. When signed in with a Claude.ai or Console account, pending question cards reappear properly after reloading the panel. When asking side questions with /btw, previous session history is no longer overwritten by window reloads or configuration errors.

This is like installing a transparent movable flap at a service counter: you can lift it anytime to inspect document details underneath, and calling the next ticket will not mix notes left by the previous customer into the next form.
BUGFIX

[VSCode] Cloud session migration fixes: grouping and multi-window sync stabilized

Switching development environments across devices is like moving a whiteboard between conference rooms: any unfinished discussion should be brought intact into the new space.

When teleporting a session from the web to a local machine, questions interrupted as the cloud session shuts down are no longer misinterpreted as declined.

Adding a web session to a group will no longer cause it to appear in two groups simultaneously. Tabs opened from the list do not jump back to older sessions after reloading, while tabs opened from web sessions do not re-run teleport or stay blank after reloads. Setting "Enable Remote Control for all sessions" applies immediately to other VS Code windows. The Open filter properly matches items continued from claude.ai whose tabs remain recorded under web sessions, with filter menu sections labeled for screen readers. "Start new session in this group" no longer loses its group after New conversation, and sessions ending before the sidebar unread list loads no longer miss their unread dot.

BUGFIX

[VSCode] Model menu consolidated into flat list, usage indicators and login guards fixed

The model picker and sidebar state management have been overhauled in this update.

The model menu is now a flat single list where legacy spellings are placed last, while immediately hiding models disabled by an organization. If the Disable Login Prompt setting is enabled, the interface no longer forces a sign-in screen when not logged in. When one panel switches to a third-party model provider, other panels no longer retain official-only features. The sidebar usage meter in a new window renders properly right upon opening without missing a 0% usage limit. Furthermore, plugin install links correctly trigger confirmation dialogs, tab badges no longer mistakenly illuminate unread during a running turn, and archived sessions can be successfully added to groups.

This is like a restaurant reorganizing its master menu: discontinued items are clear at a glance, and servers will not repeatedly challenge exempt guests using outdated access passes.
