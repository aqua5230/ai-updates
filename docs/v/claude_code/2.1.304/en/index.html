Claude Code 2.1.304

Released: 2026-10-19

Release notes

FEATURE

Auto Mode Adds Guided Setup, and Session Logs Stop Accumulating Classifier Context

If you want to let Claude execute tasks automatically but worry it will not understand your project architecture, a new tool can now help build its background context first. Running the /auto-mode-setup command reads your current project and recent sessions (the lifecycle of a conversational interaction), guiding you through teaching auto mode about your execution environment. This feature also supports Bedrock, Vertex, Foundry, Claude app gateways, and sessions with telemetry disabled. While auto mode is running, safety classifier context is no longer rewritten with every request, significantly reducing log file size.

Think of a new assistant reading a handover manual thoroughly upon onboarding; subsequent paperwork no longer requires stapling the thick rulebook behind every single sign-off sheet.
FEATURE

`/claude-api` Adds Agent Security Verification and Prioritizes Dedicated CLI on AWS

When managing autonomous agents in the cloud, you often need to confirm whether current configurations comply with official security standards. Running /claude-api managed-agents-secure now audits managed agent settings item by item against Anthropic's published security guidelines without modifying any existing configuration. In Claude Platform environments on AWS, the /claude-api skill directly invokes the ant command-line tool instead of falling back to software packages or transfer commands.

An inspector tours a server room with an official fire safety checklist, checking fire exits and extinguishers item by item without moving any equipment, and reporting updates directly over a dedicated radio.
FEATURE

Artifacts Support Independent Tab Links, and Deletion Confirmations Use Number Keys to Prevent Accidents

When asking Claude to produce artifacts containing multiple views, you often need precise control over the location and link for each screen. Requesting artifact links now prompts Claude to explicitly list full URLs for every tab view, while noting that switching views will not update the browser address bar. When deleting artifacts via /artifacts, the confirmation prompt now uses a numbered menu: pressing 1 or Enter keeps the artifact, while pressing 2 confirms deletion, with familiar y, n, and Esc keys remaining compatible.

Flipping through an exhibition guide with bookmarked sections reveals the exact code for each display hall, while tearing out a page requires matching a numbered stub to prevent mistakes.
FEATURE

Resume Prompts Warn of Usage Impact on Long Conversations, and Usage Queries Display Cooldown End Times

When planning to resume a lengthy paused conversation, it is often hard to gauge how much quota loading historical context will consume. Pro and Max plans now introduce a usage warning: if resuming an inactive conversation would take up a significant share of your 5-hour limit, the terminal displays a confirmation prompt. You can choose to resume directly or start a clean new conversation, after which Claude will proactively look back whenever you mention earlier context. When checking /usage hits a data rate limit, the interface clearly shows when the restriction ends; Opus 5.5's research preview label in the /fast window title has also been officially removed.

Before restarting an engine, the dashboard warns that the planned trip will consume most remaining fuel, and a gas pump displays a countdown timer when it shuts off.
FEATURE

Extensions Support Strict Human Authorization, with Precise Read-Only Flags and Configuration Tier Control

When writing extensions to intercept tool calls, controlling authorization boundaries for sensitive operations is critical. Modules add a decider: "person" property to tool.check, restricting approvals exclusively to permission confirmation dialogs or host callbacks; without an available human to ask, requests are denied directly with the module's reason. The event parameter also adds e.isReadOnly to flag whether a tool is read-only. If an earlier plugin bypasses your module hooks (small programs triggered by specific events), the log explicitly records the plugin and event names. The settings.read hook in modules can now read every configuration layer and override merged values, locking organizational settings as an inviolable ceiling. Plugin validation commands also no longer print text guessing hook locations.

A high-security checkpoint deploys dual defense lines, requiring security personnel to stamp dangerous operations in person while executive authorization ceilings block unauthorized escalations.
FEATURE

Module Reload Failures Retain Older Tools, and Clicks on Duplicate Buttons Register Accurately

Adjusting custom modules during a conversation can easily disrupt workflows if a syntax error occurs. Previously, a failed module reload cleared out working older tools and commands by mistake; now, reload failures preserve existing versions intact while the terminal clearly displays reload status. When multiple buttons share identical labels without a specified key, click events are no longer lost after rerendering. On enterprise or managed devices, sharing modules via the plugin-authoring skill no longer hangs on secrets scanning. Prompts activating in-session modules have switched to plain text, remaining visible across turns and clearly reporting loaded content upon activation.

Much like an orchestra changing sheet music, musicians keep playing from older scores when new prints contain errors without breaking the melody, and duplicate keystrokes still produce clear feedback.
FEATURE

Skill Reloads Transmit Only Changes, and Single Sources Face Hook Limits

When a project loads numerous custom skills, frequent updates can easily flood conversation context with redundant descriptions. Previously, every plugin reload resent the entire skill inventory; running /reload-skills now transmits only added or modified entries, while conversation compaction reliably resends a fresh full inventory. To prevent plugins from expanding indefinitely, a single source can register at most 1,024 hooks and 16,384 matching characters per session (the lifecycle of a conversational interaction). A skill's single-fire hook no longer deletes identical hooks from other skills upon triggering, and skills cannot obtain default authorization tools if policy bans local skill hooks.

Like a library updating its catalog, staff print supplementary slips only for new arrivals, while capping the number of display stands each private sponsor can place.
FEATURE

Multiple Subagents Run More Smoothly in Parallel, Eliminating Memory Loss When Messaged Immediately After Tasks

When dispatching multiple subagents across large projects, information transfer between agents is critical. Responsiveness and processing throughput when running multiple subagents concurrently have improved significantly. Previously, messaging or resuming a subagent immediately after it finished a task sometimes caused it to forget its most recent output; this cache loss issue is now resolved. In headless mode (an execution mode without terminal windows or visual interfaces), plugins can no longer spawn subagents to bypass turn limits or stop commands. When an agent team approves a shutdown request in the main session, it no longer accidentally terminates the entire tool process, and tool interception timeouts no longer overwrite existing rejection reasons.

Relay runners sprint along their respective lanes, taking on new tasks at the baton pass while carrying forward previous momentum, and the referee logging arrivals never whistles to abort the entire race.
FEATURE

Conversation Compaction Summaries List Past Tool Names, and Low Disk Space No Longer Discards History

When conversations exceed model capacity and trigger automatic compaction, a clear summary helps you quickly grasp prior decisions. Pressing Ctrl+O to view transcripts now displays a compaction summary that explicitly lists the names of all previously called tools. The CLAUDE_CODE_AUTO_COMPACT_WINDOW environment variable officially supports k and M unit suffixes, issuing proactive warnings if values fall out of range or are ignored. Previously, local log cleaners could drop conversations while trimming files under low disk space; this issue has been eliminated. Aborting mid-compaction after the model rejects an oversized conversation no longer throws prompt-too-long errors, and jumping with shortcut keys in transcript views no longer drifts.

A recording secretary binds lengthy proceedings into a concise memorandum, listing every previously presented slide on the cover, while tight filing cabinet space never causes a single voucher to slip out.
BUGFIX

External Drive Deletions Prompt Safety Confirmations, and Detached Worktrees Are Protected Upon Exit

When organizing files or testing project branches, operational boundaries are highly sensitive. Running rm -r on external drives or top-level directories such as /Volumes, /media, or WSL /mnt/c now triggers a safety confirmation prompt, matching the behavior for system directories. When using claude --worktree in a detached state or on a different branch, ending a session no longer arbitrarily deletes worktrees (Git's feature for running multiple parallel copies of the same project), keeping unpushed commits safe. When modifying files outside the working directory, paths now display as ~/ or absolute paths instead of lengthy relative notation. Linux sandbox paths containing square brackets no longer trigger errors, and Windows invokes git.exe directly to reduce latency.

Operating heavy machinery sounds a warning buzzer when backing up toward cargo containers, and latching pins lock in place whenever a detached trailer holds goods.
FEATURE

Remote Control removes account restrictions, while custom proxy gateways automatically retry with compatibility

Connecting to Claude through different terminals or custom server gateways often leads to communication disruptions due to minor differences in environment parameters. Previously, Remote Control (a connection mechanism syncing the desktop client with the terminal) permanently withheld desktop history when logging in with a different account from the terminal, but this restriction has now been officially removed. Desktop remote connections now launch smoothly even when telemetry is disabled under paid plans. When a custom language model gateway reports unsupported context management fields, the client automatically strips incompatible fields and resends the request. Custom ANTHROPIC_BASE_URL settings enable tool search by default, and automatically fall back to retry upon protocol rejections. Telemetry tracking configurations assigned by the server after login are no longer ignored throughout the entire session.

A roaming traveler’s device automatically detects local bandwidth during cross-border communication, falling back to basic packets for retransmission upon format mismatches, while switching to a temporary number never locks roaming history.
FEATURE

Model switching and interruptions no longer queue or stutter, while one-hour recurring schedules accurately hit the cache

When rushing to switch models or press interrupt during a conversation, any waiting feels sluggish. Across the SDK and desktop app, switching models, sending new messages, or issuing interrupt signals are no longer stalled behind context checks. If reading tools get stuck on idle pipes or devices disguised as images, pressing interrupt breaks free immediately. Scheduled /loop recurring wakeups set at the one-hour ceiling had their trigger timing fixed, preventing them from narrowly missing the one-hour cache expiration and avoiding full conversation re-reads upon waking. First-response speeds when resuming large conversations are noticeably faster, alongside improved memory consumption.

Picture a professional audio mixing console where pressing mute instantly cuts signals without waiting for background self-checks, while automated timed playback directly retrieves pre-warmed master tapes.
BUGFIX

Help text aligns with real parameter behavior, and terminal input notes are no longer cut off by ellipses

Typing commands and choosing response options in text terminals can be confusing when the interface display does not match underlying behavior. When running claude --help, descriptions for multiple options and update commands—including --tools, --resume, and --debug—have been recalibrated to reflect actual operation. When environment variables are set to auto or left unspecified, /effort and the effort indicator next to the input box no longer display guessed values on their own. In narrow windows under 100 columns wide, entering notes in the preview menu no longer cuts off text with ellipses. In the agent list, pressing Ctrl+C before releasing the mouse button will no longer clear selected text without copying it.

Imagine reading a product manual on an e-paper device where chapter titles match physical buttons one by one, and handwritten notes in small screen sidebars never have corner text cropped off.
FEATURE

Startup keys instantly sync organization policies, and desktop terminals fully inherit profile environment variables

When configuring team keys or switching project settings, failures to apply updated policies and system variables immediately often trigger permission errors. Previously, entering keys at launch or switching custom credentials in /config required waiting for an hourly routine check before organization policies updated. That sync now refreshes immediately. Running Bash commands within the desktop Code tab now fully inherits exported environment variables from profile files such as ~/.zshrc on macOS and Linux. After network disconnections, /privacy-settings no longer offers inapplicable privacy options, and Terms of Service reminders are never omitted. When loading configurations with claude -p, alerts focus strictly on critical errors that obstruct startup.

Consider a new security badge that instantly grants access to every floor at the turnstile, while personal lockers in the office already hold every necessary tool.
FEATURE

Cloud scheduling eliminates waiting for unapproved URLs, and initial conversation turns skip local tool startup stalls

Scheduling tasks into unattended cloud sessions often causes severe stalls when encountering steps that require manual authorization. In Cowork scheduled cloud sessions, subagents fetching URLs without approvals no longer wait five minutes repeatedly for each agent. During the first turn of a new conversation, unless explicitly declared as required, startup no longer waits for local standard input MCP (Model Context Protocol, a protocol allowing AI to connect to external tools) servers synced from the web, speeding up launches. Selecting directory plugin skills from the slash menu now executes them smoothly as commands, and tagging folders in the prompt input no longer drops names. If a self-hosted runner cannot find a repository, it clearly presents the project name and point of contact.

An unmanned weather station at night skips probes that lose signal instead of idling, while powering on equipment no longer requires pre-warming disconnected sensors.
FEATURE

VS Code background agents present cleanly in status lines, and startup hook runtimes no longer count toward timeouts

Collaborating with Claude inside VS Code often causes conversation context to get buried under large volumes of background task output. Background subagents now appear as a single line of progress text below the agent card rather than flooding trivial steps into the chat window, with full logs accessible under /tasks. Conversation panels across cloud platforms and custom gateways now also support interface rendering for modules. Execution time for SessionStart command hooks (programs triggered by specific events) is no longer counted toward the one-minute timeout limit, expanding up to 10 minutes to prevent startup failures from subprocess initialization timeouts. Closing sessions midway through startup immediately terminates processes, module drawings no longer vanish when open for extended periods, and past conversations list correctly under custom packaged executables.

Staging in a theater production reports backstage scenery shifts through side lights without disrupting the main stage, while lowering the curtain cleanly terminates rehearsal processes.
FEATURE

Shared channels proactively prompt for new threads mid-task, and commands run outside threads provide private guidance

Tagging Claude for collaboration in enterprise messaging apps can easily disrupt active conversations when channel properties change. Previously, if a channel was converted to an Enterprise Grid cross-workspace shared channel midway through a task, Claude would suddenly fall silent. Now it actively leaves a prompt guiding you to mention it again in a new thread to resume work. When someone runs the @Claude !fork branching command directly outside a thread, Claude no longer stays quiet, but sends an ephemeral message clearly explaining that this command can only be executed inside a thread. This ensures operational feedback remains consistently transparent during cross-group communication.

When a neighborhood meeting transitions into a cross-building seminar, the host puts up signs directing participants to the new venue, and ballots miscast in hallways are returned with guidance toward the correct ballot box.
FEATURE

Code review introduces three depth tiers, supporting automated organization-wide GitHub coverage

Rolling out automated code review across teams often calls for flexible review depth based on project importance. The code review feature now introduces a tiered system: team owners can select Fast, Standard (default), or In-depth checks for the entire organization, or customize distinct tiers for specific core projects. The administration console adds an automatic review option that brings all repositories under a GitHub organization into management at once, automatically including newly created projects to eliminate manual configuration overhead. If pull requests arrive immediately after enabling the review feature, the system no longer silently drops them, instead automatically rescheduling and completing the check.

Quality inspection centers establish sampling mechanisms across production lines, quickly weighing daily goods while deeply scanning precision instruments, automatically cataloging new assembly lines, and promptly inspecting samples submitted right as shifts begin.
