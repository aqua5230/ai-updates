工作階段出錯自動彙整草稿，快速檢視送出回報

在工作階段遇到錯誤或異常時，Claude 現在會透過 SendFeedback 工具主動替你整理一份回報草稿。你可以使用 /feedback 指令檢視內容、確認無誤後再送出，省去手動複製錯誤訊息與描述問題的繁瑣步驟。若不需要這項輔助，也能在個人設定加入 {"feedbackDrafts": false} 隨時關閉草稿功能。這如同實驗紀錄系統在測試失敗時自動彙整觀測結果成報告草稿，等研究人員檢視無誤後才正式提交。

載入提示支援自訂輪播，企業可配置專屬公告檔

企業想在載入等待時向團隊成員展示專屬指引，可在個人設定檔 ~/.claude/settings.json 加入 spinnerTipsOverride。這好比公司大廳的動態看板，除了播放總部預設宣導，還能插入內部通知。可直接貼上：

{"spinnerTipsOverride": {"label": "團隊提示", "tipsFile": "~/.claude/team-tips.json"}}

其中 tipsFile 指向獨立提示檔，label 是顯示名稱；提示項目可包含 {id, text, cooldownSessions, priority}，並會與內建提示輪播。

Bash 權限確認增設指引，可直接切換至自動模式

當終端機跳出 Bash 指令執行權限的確認提示時，介面現在會附上引導至自動模式的說明提示。自助洗衣店的螢幕除了讓你確認這次洗程，也會提示可改用自動方案，並提供「同意並切換為自動模式」按鍵；按一下便同時開啟本次洗程與自動選擇。你只要按一下按鍵，就能選擇「Yes, and switch to auto mode」，在允許當前指令執行的同時直接切換至自動模式，省去後續反覆手動確認的繁瑣操作。

新增成本調校指令，五大槓桿逐項分析 API 支出

想替專案節省 API 開銷的使用者，現在可以使用 /claude-api cost-optimize 指令分析現有專案的支出結構。該功能會依序帶你檢視快取（把算過或查過的結果暫存起來直接用）、批次處理、運算深度以及模型選擇等成本槓桿。系統也會協助評估 token（AI 處理與計費的文字單位）的精簡策略，並以單次一個具體量測改動的方式逐步調校。這就像請一位專業精算師逐筆審查帳單，按部就班調整各項用量槓桿，每次微調都量測實際節省成效。

API 技能涵蓋管理端點，支援成員、金鑰與加密配置

管理企業級 API 資源的使用者，現在能透過更新後的 /claude-api 技能直接操作 Admin API 的各項管理功能。這如同活動統籌坐在同一張後台總表前，能集中處理參加名單、邀請、場地、器材編號與用量報表，也能安排合作團隊的身分串接和自管保險箱密碼。該支援涵蓋組織成員名冊、邀請函發送、工作空間劃分、API 金鑰管理與速率限制用量報告。此外也納入了工作負載身分識別同盟（WIF）的配置。針對安全加密，系統也一併支援客戶託管加密金鑰（CMEK）等進階選項。

修復選單快速連按時序，不再誤觸游標上一行選項

在選單中快速切換選項時，系統不再因為按鍵反應落後而選錯上一行。過去在歷史搜尋、/config、/mcp、/skills、背景任務列表以及 /model 介面中，如果以極快速度連按方向鍵與 Enter 鍵，游標會誤觸剛才游標上方的那一列；現在按鍵時序已修正，確保選定的就是眼前停留的項目。這像電梯按鈕消除了判定延遲，快速連按時會準確停在你最終按下的樓層，不再因按太快而誤停在上一層。

子代理遭遇模型 404 自動切換備援，回傳詳細錯誤代碼

當子代理在首次呼叫模型時遭遇 404 找不到模型的錯誤，系統不再讓它直接死當。這好比客服總機發現主要分機無法接通時，會依序轉接備援分機；若全都失敗，仍會留下故障類型、狀態碼、案件 ID 與分機名稱。現在子代理會依序使用當前工作階段設定的備援模型鏈繼續嘗試，而且回傳給父代理的錯誤訊息中，會完整包含錯誤類型、狀態碼、請求 ID（request id）以及目標模型名稱，方便排查問題。

海量錯誤輸出不再塞爆對話，防止工作階段卡死

掛鉤（hook，特定事件發生時被觸發的小程式）或背景代理若噴出數 MB 的海量錯誤訊息，過去會直接塞爆對話紀錄，導致工作階段卡死在「Prompt is too long」而無法繼續輸入。現在系統已修正溢位處理機制，防止過量的錯誤輸出癱瘓對話。宛如水壩設有溢洪道，暴雨帶來大量水流時先導走多餘水量，不讓整座水庫堵塞而影響正常供水。

kitty 終端協定支援非拉丁鍵盤，Ctrl 快捷鍵正常觸發

在支援 kitty 協定的終端機中，使用非拉丁鍵盤配置（例如西里爾字母）的使用者，現在按下 Ctrl 快捷鍵組合也能正常觸發功能。過去在切換為非拉丁輸入法時，Ctrl 按鍵訊號無法被正確辨識；修復後無論目前的輸入語言為何，組合鍵都能精確送達。好比多語鍵盤的翻譯晶片修復了解碼邏輯，不論切換到哪種字母排列，只要按住控制鍵，系統都能認出底層標準的快捷指令。

滑鼠分段回報不再插入亂碼，過濾殘留跳脫字元

滑鼠回報資料若在跳脫字元前綴剛送出時被切成兩段讀取，過去會導致像 <35;150;7M 這樣的殘留字串被當成文字硬生生塞進提示輸入框裡。這如同電報機修好了斷句機制，就算控制訊號在中途稍微停頓，也不會把座標數據誤當成正文印在紙上。現在系統修正了終端機輸入串流的解析邏輯，即便滑鼠封包被拆成多次讀取，也能完整辨識並過濾掉控制碼。

沙盒清理保留外部捷徑，防止設定檔符號連結遭誤刪

使用 nix/home-manager 或 GNU stow 等工具管理設定檔的使用者，不再需要擔心個人設定檔被意外刪除。過去當 Bash 沙盒在指令執行完畢進行清理時，若指向外部的符號連結（symlink，指向另一個位置的捷徑檔）~/.claude/settings.json 被重導至沙盒可寫入區域之外，清理程序會將該連結檔案直接刪除；現在沙盒已修正保護邏輯。此舉如同打掃人員清理置物箱時，認得貼在外面的捷徑標籤，不會把屋主辛苦用工具管理的設定檔連根拔除。

Zed 鍵盤設定改為合併寫入，完整保留既有按鍵綁定

在 Zed 編輯器設定終端機快捷鍵時，執行 /terminal-setup 指令不再粗暴地洗掉你既有的全部按鍵綁定。這如同圖書館登記借閱時，管理員只在你的卡片空白處加蓋新章，而不是把寫滿個人備忘的整張借書證撕掉換新。過去該指令會直接覆寫整個 keymap.json 檔案；現在它懂得將所需的快捷鍵合併進現有設定中，完整保留你原先自訂的其他按鍵組合。

改名失敗明確提示同步狀態，不再靜默確認

使用 /rename 指令重新命名當前對話時，若內部工作階段註冊表（session registry）因故無法同步更新，系統不再假裝一切成功並默默確認。現在它會明確顯示提示訊息，告知其他工作階段可能暫時仍會顯示舊名稱，讓資訊維持透明。這宛如戶政事務所改名時，若分局系統連線延遲，辦事員會主動提醒你其他窗口可能暫時還掛著舊名字，避免產生誤會。

代理對話摘要依循專屬提示詞，不再套用預設模板

以 --agent 參數啟動自訂代理工作階段時，執行 /compact 壓縮指令或點選「Summarize from here」整理脈絡時，系統過去會錯誤套用預設的系統提示詞來產生摘要。現在摘要程序已修正為嚴格依循該對話專屬的自訂系統提示詞，確保代理的角色定位與特殊規則在濃縮後依然完整維持。像隨身秘書整理會議精華時，全程依照該專案的特約指引記錄，不會突然套用總公司的制式格式。

背景代理終端終止即時報錯，按 Enter 鍵可重新啟動

在 claude agents 列表中檢視背景工作階段時，若終端機宿主處理程序意外終止，該列過去會永遠卡在「opening…」狀態。這好比航班動態看板，當班機因故取消時，看板會在幾秒內亮出原因並提供重定班機選項，不再永遠卡在登機中。現在系統會在數秒內將該列標記為失敗並清楚顯示具體原因，你只需按下 Enter 鍵就能直接重新啟動該工作階段。

輸出檔無法寫入時限制記憶體，檔案加註遺失段落

當掛鉤（hook，特定事件發生時被觸發的小程式）或背景任務的輸出檔案因權限等原因無法寫入磁碟時，系統過去會在記憶體中無限累積暫存資料導致記憶體暴增。現在記憶體限制已獲得控制，且日後輸出檔案恢復可寫時，檔案內會明確加註哪一段輸出內容已遺失。正如印表機卡紙時不再把列印佇列無限堆在快取記憶體直到當機，而是適時捨棄並在補紙後的第一頁清楚印上斷印標記。

SSH 安裝 GitHub 應用程式改善，複製狀態與網址顯示更明確

在遠端 SSH 連線環境下執行 /install-github-app 指令時，登入體驗變得更加可靠。複製快捷鍵現在會如實說明登入網址是如何複製的，不再盲目宣稱複製成功；當遠端伺服器無法自動開啟本機瀏覽器時，登入網址也會第一時間直接印在畫面上供你手動點擊。這好比遠端電話辦公時，系統不再含糊回報文件已送到桌面，而是明確告知傳遞管道並立即把登入網址顯示在畫面上。

前景指令移轉背景執行收尾，不再誤報 code -1 錯誤

由前景轉移至背景工作階段執行的 Shell 指令，在執行完畢時不再跳出內部錯誤紀錄或誤導人的 [exited with code -1] 退出碼。這像接力賽把跑者移交給後援隊伍後，跑者抵達終點能順利繳回號碼牌，不會被計分板誤記為違規棄權或拋出錯誤碼。現在指令在背景順利收尾時能正確回報真實狀態，避免造成執行失敗的假象。

多範圍安裝外掛保護快取，避免中斷運作中工作階段

當你在不同範圍重複安裝同一個未標註版號的市集外掛時，系統過去會直接刪除並重建既有的快取目錄。這往往會干擾到正在使用該外掛的工作階段；現在快取（把算過或查過的結果暫存起來直接用）處理邏輯已獲得修正，第二個範圍的安裝動作不會再中斷運作中的程式。這就如同在同一棟大樓為第二間辦公室裝設相同設備時，工人不會拔掉走廊正在運轉的共用電源，確保第一間辦公室照常運作。

遠端遙控同步工作樹差異，連線端即時掌握修改進度

透過 /remote-control 指令開啟遠端控制工作階段時，已連線的用戶端現在能正確收到目前工作樹的修改差異（working-tree diff）。像遠端視訊會議中主講人順利同步投影畫面，遠端與會者能即時看見最新修改的文件對照，掌握工作進度。過去這些變更資訊未被同步傳遞給連線端；修正後遠端操作者能即時檢視檔案的具體改動，大幅提升遠端協作的透明度。

自託管執行器延後回報運作狀態，防止提早發出等待通知

自託管執行器（self-hosted runner）的工作階段過去在 Claude Code 尚未正式啟動前，就會提早回報為「running」運作中狀態，導致 Claude 桌面應用程式過早發出「Claude is waiting for your input」的提示通知。現在狀態回報時機已修正，只有在主程式真正啟動並就緒後才會發送通知。如同劇場在布景與燈光尚未就緒時不亮起開演燈，避免前台過早通知觀眾可以入場。

受管閘道登入修復端點檢查，離線環境順利完成初次設定

在由管理員統一派發的受管設定（managed settings）中，若指定透過 Claude 應用程式閘道登入，而環境對外無法連線至 Anthropic 預設端點，初次啟動設定過去會直接報錯並退出。就像博物館正門關閉時，導覽人員仍能循指定服務通道帶新訪客到報到桌，不會取消入場手續。現在系統已修正連線判斷邏輯，優先依循閘道設定順利完成初次設定，保障封閉網路環境的可用性。

雲端工作階段修復權限切換時序，送出訊息不再閃退舊模式

在網頁版、桌面版或行動應用程式中使用雲端工作階段時，若在剛送出訊息的瞬間立即切換權限模式，介面過去有時會因為非同步傳輸的順序衝突，而跳回先前顯示的舊模式。現在狀態同步順序已獲得修復，無論你送出訊息後多快切換權限，模式切換都能精確反映當下的最新選擇，不再遺失設定。這如同影像編輯器在按下儲存的同時切換工具，工具列仍保留剛選好的工具，不會跳回上一個。

雲端容器重啟主動回報進度，清楚列出受影響背景任務

當雲端工作階段在回合之間發生容器重啟，而背後的代理程式、Shell 指令或監控程序仍在執行時，系統過去在重啟後會陷入無聲無息的沉默狀態，讓你誤以為任務仍在背景順暢運作。現在工作階段在恢復連線後，會主動向你回報受影響的中斷工作項目與遺失進度，確保執行狀況一目了然。宛如雲端主機中途重開後，復工的助理會主動遞上中斷清單，清楚交代哪些背景作業受到影響，不再假裝沒事發生。

外掛市集強化字元防護，拒絕隱形字元並安全跳脫輸出

外掛市集的安全防護機制獲得全面強化。這好比市集招牌經過嚴格安檢，禁止懸掛夾帶隱形墨水或控制指令的看板，確保公告文字安全無害。系統現在會主動拒絕包含控制字元或隱形字元的外掛名稱，防止惡意命名欺騙；同時，在 /plugin 與 claude plugin 的輸出結果中，來自市集的說明文字也全面經過跳脫安全處理，避免終端機被惡意格式字串攻擊。

外部工具連線失敗明確通報，防止誤判工具不存在

在 Bedrock、Vertex、Foundry 平台或停用遙測的工作階段中，當設定的 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器連線失敗時，系統現在會明確告知 Claude 連線失敗的事實，避免 Claude 誤以為該工具根本不存在。這相當於通訊官向指揮官明確回報線路故障，讓指揮官清楚設備只是暫時連不上，而不是誤認倉庫裡從未配發該項工具。

Sonnet 5 放寬自動壓縮門檻，百萬上下文支援至 967K

使用 Sonnet 5 模型並開啟 1M 上下文視窗的使用者，系統現在將預設自動壓縮門檻調整為完整的 1M 容量。工作階段觸發自動壓縮的時機由原本約 934K token（AI 處理與計費的文字單位）延後至約 967K token，讓長對話能容納更多未壓縮的歷史紀錄。好比把記事本的翻頁警戒線往後推移，充分利用完整的百萬空間，寫到約 967K 單位時才啟動濃縮。

跨工作階段訊息預設單行摺疊，按 Ctrl+O 可展開全文

在多個工作階段之間傳遞的對等訊息，現在預設會摺疊為單行預覽格式 Message from @<sender>: <first line>。當你需要檢視完整內容時，只需按下 Ctrl+O 即可立即展開全部內文，保持主對話畫面的整潔清爽。這彷彿活頁講義先只露出章節標題與第一行，桌面保持整齊；需要細讀時再用快捷鍵攤開整頁。

終端機過濾特殊路徑超連結，可疑目標自動降級純文字

終端機在渲染 Markdown 格式的超連結時加入了更嚴格的安全防護限制。若連結目標指向遠端網路路徑、自動掛載路徑、含有特殊控制字元或以隱形字元開頭，系統會將其自動降級為不可點擊的純文字顯示，防止終端機誤觸潛在的惡意路徑或觸發非預期的網路連線行為。正如門禁把來源可疑或夾帶隱藏符號的感應卡降為普通紙卡，不能刷開門，避免有人誤用。

PR 狀態標籤增設一分鐘快取，視窗重焦略過重複查詢

終端機底部的 Pull Request 標籤現在具備了更聰明的快取（把算過或查過的結果暫存起來直接用）機制。當你切換視窗重新回到終端機時，如果距離上一次檢查的時間不到一分鐘，系統會略過向 GitHub 重新查詢的動作，減少多餘的網路請求並避免介面卡頓。好比手錶在切換視窗時不會每秒向衛星校時，只要上一分鐘內才核對過，就直接顯示既有資訊以節省資源。

自訂認證啟動即關閉遙測，全程落實企業隱私規範

在受管設定強制使用閘道登入或配置自訂 OAuth 的企業環境下，遙測分析資料收集功能現在從程式啟動時起便會一直保持關閉狀態。系統不再等到使用者完成登入驗證後才停用收集，從最初初始化階段就徹底保障企業內部環境的隱私與合規要求，因此不會在登入前留下分析資料。這如同重視隱私的會議室在開門時就關閉錄音設備，不必等訪客完成簽到才停錄。

閘道登入攜帶身分參數，明確標記客戶端來源與版號

透過應用程式閘道進行登入請求時，系統現在會在驗證流程中明確標註客戶端身分。這像舞台器材貼上所屬劇團與版號標籤，控制台一看便知道來源並套用對應規則。具體包含在裝置授權參數中帶上 surface=claude_code，並在 HTTP 標頭的 User-Agent 註明 claude-code/<version> 版號，方便後端閘道精確識別並套用存取政策。

受管設定無法讀取即刻終止，防止安全管制遭繞過

在啟用組織登入強制管制的環境下，若系統在啟動時無法讀取管理員設定的受管設定（managed settings），程式現在會直接退出並中止執行，即便本機或使用者層級的 Windows 登錄檔中存在相關設定也不會放行，嚴格防範安全防護被繞過。中央食譜讀不到時，廚房便不開火；即使爐旁放著場地或個人的筆記，也不拿來替代正式做法。

tipsFile points to a separate tips file, and label is its display name. Tip entries can include {id, text, cooldownSessions, priority} and rotate alongside built-in tips.

Like moving the review bookmark further back in a massive notebook, allowing you to fill up to about 967K units of notes before initiating a summary pass.

You can press Ctrl+O at any time to expand and read the full body without cluttering your main stream. Like loose-leaf study notes that show only a chapter heading and first line until you use a shortcut to open the full page.

Terminal hyperlinks rendered from Markdown now enforce safer formatting rules. Link targets that point to network or automounter paths, contain control characters, or lead with invisible characters are automatically rendered as plain text rather than clickable links. Like access control that downgrades a suspicious keycard or one with hidden symbols to an ordinary paper card that cannot open a door.

Prompt PR badge skips refocus checks when data is under a minute old

The pull request badge in the prompt footer now optimizes its GitHub network calls. When refocusing your terminal window, it skips the GitHub re-check if the previous check occurred under a minute ago, saving bandwidth and keeping your prompt snappy. Like a watch that doesn't ping satellites every second you glance at it, relying on a check performed less than a minute ago to conserve battery.

Analytics remain completely off from startup for gateway and OAuth setups

Telemetry and analytics now remain disabled starting from process startup, rather than waiting until after login, whenever managed settings enforce gateway login or a custom OAuth deployment is active. Like a privacy-conscious meeting room that switches its recording equipment off as the door opens, rather than waiting for a visitor to finish checking in.

Claude apps gateway sign-ins explicitly identify Claude Code clients

Gateway sign-in requests for Claude apps now explicitly identify Claude Code to the authorization server. Like stage equipment labelled with its theater company and version, so the control desk can identify its source and apply the matching rules. Requests include a surface=claude_code parameter during device authorization and specify a claude-code/<version> User-Agent header.

Organization enforcement exits on unreadable managed settings

Enforcement of organization sign-in policies now immediately exits at startup if the administrator's managed settings cannot be read. Even if host-supplied or per-user Windows registry settings exist, the tool will refuse to launch without verified administrative policies, closing potential security bypasses. If the central recipe cannot be read, the kitchen does not start cooking; notes left by the venue or an individual beside the stove cannot replace the official instructions.
