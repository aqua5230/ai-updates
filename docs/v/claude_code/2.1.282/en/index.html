Claude Code 2.1.282

Released: 2026-09-24

Release notes

FEATURE

New maxProseWidth setting automatically limits line width on wide screens

Reading long explanations in a wide or full-screen terminal (the text interface where you type commands) often means your eyes have to sweep back and forth across the entire screen.

The new maxProseWidth setting key caps plain-text explanations at a comfortable line width, while tables and code blocks that need the width still expand to full width.

Think of reading exhibit placards in a museum hall: the text summaries sit on columns of a moderate width, while oversized architectural drawings and panoramic models still unfold at full size, so you no longer get dizzy taking it all in.
FEATURE

Telemetry setting safeguards: project-exported variables are ignored with a clear startup notice

When you take over someone else's project folder, if its config files quietly include telemetry (a mechanism that collects operational data and sends it back to a server) variables, your data could leak without your knowledge.

Project and local config files now ignore OpenTelemetry variables that enable exporting, set endpoints, or capture content, such as CLAUDE_CODE_ENABLE_TELEMETRY and OTEL_LOG_*. The startup screen, /status, and claude doctor list the telemetry variables ignored in project config files, as well as the variables that keep telemetry off.

Like an apartment building's management committee that forbids residents from installing their own public surveillance: even if the lease handbook sneaks in a recording clause, the access-control system simply ignores it and lights up a warning in the guard room.
FEATURE

Chrome browser features can now be enabled in managed-MCP-only mode

When an enterprise locks down managed-mcp.json tool settings in a managed environment, trying to pair it with claude --chrome to let the AI operate a browser used to be blocked outright.

A new managed setting key, allowClaudeInChromeWithManagedMcp, has been added. Once an enterprise admin turns it on, Chrome browser connectivity can coexist with the dedicated tool settings. If the browser feature is blocked by a security policy, the error message shown in the terminal now names this setting as the one that hasn't been enabled.

Picture a company-issued laptop with a locked software installation list: once headquarters issues a special pass, a specific browser tool is permitted to run alongside the dedicated software.
FEATURE

Application gateway gains a fault-tolerance grace period for database failover

When a server-deployed application gateway (an intermediary server that forwards network requests) hits a brief database restart or a primary-replica switchover, health checks often report errors immediately.

The gateway configuration now adds a store.readiness_grace_seconds parameter. During a brief Postgres database interruption, such as a database failover, the health-check endpoint /readyz can temporarily stay in the ready state.

Like a building's generator kicking in its uninterruptible power supply during the brief gap of a grid switchover, the alarm doesn't declare the whole building dark over a momentary voltage flicker.
BUGFIX

Fixes for session resume and extended-thinking record retention

Several issues that could cause lost thinking context and failed requests during long conversations or when continuing old sessions have been fixed.

When resuming a session (the conversational cycle of interaction between you and the AI) with --continue or --resume, earlier messages no longer lose their prior extended thinking due to rewriting and resending. When resuming a conversation, removing previously mentioned built-in tools via --tools no longer drops thinking records either. Running /model, /rename, /artifacts, or other immediately executed slash commands while Claude is working no longer interrupts thinking records. Conversation history containing search results the API cannot decrypt no longer triggers a 400 error, which could occur on turns answered through a third-party gateway. When a redacted_thinking thinking block contains invalid data, Claude Code discards the thinking blocks in the conversation and retries once. Hitting a safety switch while thinking is off but effort is set to maximum no longer errors either.

BUGFIX

Fixes for model-switch prompts, usage purchase, and compaction fallback

Several fallback and prompt mechanisms for switching models and summarizing long conversations have been corrected.

When a summarization request is rejected during long-conversation compaction, it now automatically retries with a fallback model (the alternative that takes over when the primary option fails). In SDK-hosted sessions such as Claude Desktop, an unanswered usage-purchase prompt no longer switches models on its own and instead simply ends that turn; remote-control clients also see the model-switch notification. Entering a full Fable model ID with /model when the plan requires usage that hasn't been enabled now properly pops up the usage-purchase prompt instead of stalling on an API error. Safety-interception messages from Bedrock and Bedrock Mantle now include the request ID and message ID. Unregistered new models on Vertex AI can still provide web search, and the desktop app now prompts you to pick a different model when it encounters an unknown one.

BUGFIX

Fixes for simultaneous multi-window sign-in and credential refresh

When signing in with multiple editor windows open on the same computer, credential updates no longer conflict and jam.

If a previous process is closed or force-killed partway through refreshing credentials (the sign-in proof that verifies your identity), other windows no longer get stuck for up to a minute on a sign-in error saying another process is refreshing. Sessions that start at the same time and happen to hit a sign-in refresh now also automatically retry fetching the organization's security policy.

Like several people sharing one locker: if the person ahead walks away mid-swipe, the sensor lock doesn't stay deadlocked for a full minute—the next person can step up, swipe again, and open the door smoothly.
FEATURE

Managed settings and sandbox protection policies now enforced strictly

When enterprise admins distribute organizational security policies, the settings-parsing logic has become more reliable.

If a managed lockdown key such as disableClaudeAiConnectors or allowManagedPermissionRulesOnly is given a mistyped boolean value, the security lockdown is still enforced and the key is named at startup. If the permissions, autoMode, worktree (a Git feature that lets one project have multiple parallel copies), or attribution blocks contain invalid fields, the remaining valid settings still apply normally. Under any of the following conditions, sandbox.excludedCommands ignores entries from project and local settings:

Managed settings or --settings set allowUnsandboxedCommands: false
Managed settings set allowManagedDomainsOnly: true

If Windows or WSL administrator policies (HKLM, managed-settings.json) exist but are invalid or unreadable, the user-modifiable HKCU and WSL /etc/claude-code settings will not be applied.

BUGFIX

Fixes for rules-file loading paths and permission matching

Permission checks at project startup and command execution are now safer and stricter.

At startup, CLAUDE.md and rules in macOS /Network are no longer read via repository symlinks (shortcut files that point to another location) using .. or /.vol-style paths, and rule links pointing to /home are no longer listed. Bash permission rules containing a mid-pattern wildcard :* in config files now fully take effect, with a matching-rule notice at startup. Under managed allowManagedPermissionRulesOnly, skills and commands from repository, user, and --add-dir sources, as well as plugin manifests in skill directories, can no longer pre-approve tools on their own via allowed-tools. After a background work unit of a remote session restarts, commands approved on the restored permission prompt no longer run twice, and the display of special characters in authorization prompts has also been improved.

FEATURE

Permission rules and same-name plugin handling for cloud-synced skills

If your extensions happen to use the names anthropic-skills or claude-ai, the loading results may differ from before.

The allow rules Skill(anthropic-skills:*) and Skill(claude-ai:*) cover only skills synced from the claude.ai cloud, not plugins or other skills that merely share the name. Local skill folders, command files, and workflow commands under these two namespaces are no longer loaded; same-name plugins still load, but they yield when their name collides with a synced skill. MCP (Model Context Protocol, the protocol that lets AI connect to external tools) servers configured with these names no longer list skills or prompts, though their tools remain usable; to restore the listing, rename the server in the MCP settings.

When two rosters hit a same-named entry, one yields the name but keeps the rest of its content: same-name plugins now yield to cloud-synced skills, yet the plugins still load.
FEATURE

Auto mode now defaults to the server-side classifier on direct API connections

This default change affects you if you connect to Claude directly through the Anthropic API with telemetry turned off.

When using auto mode (the mode where Claude runs tools on its own without asking step by step), tool actions are now judged by the server-side classifier by default. If you don't want this server-side default, set the environment variable CLAUDE_CODE_AUTO_MODE_SERVER=0 to opt out.

A shop reroutes its default orders through a central counter: orders sent under the default now take the new path, and customers can still cancel that default.
BUGFIX

Fixes for terminal rendering, CJK line wrapping, and layout

Rendering issues in the terminal interface across various window sizes and output situations have been fixed across the board.

Launching in fullscreen no longer shows a brief flash of a blank screen. In normal window mode, when running a command deletes the prompt line at the same time and the screen shrinks but is still taller than the terminal height, output no longer shifts out of place or scrambles. In code diffs, when CJK characters or emoji wrap and redraw, the last column no longer leaves behind stale old characters. For projects with a SessionStart hook (a small program triggered when a specific event happens), the example hint text no longer flickers away at startup. In screen-reader mode, in lists inside quotes, and in long lists, when a code block sits at the start of a list item or at the start inside a quote, the blank line at the top of the block is no longer wrongly deleted.

BUGFIX

Fixes for terminal paste, shortcut hints, and quota reporting

Input handling and tool error reporting in the terminal are now clearer and more accurate.

When Bash and PowerShell hit a full disk quota (the storage space limit), they no longer return only the vague Exit code 1 and leave huge files in the temp folder; they now state clearly that space ran out. When tool argument validation fails, all invalid arguments for that call are now listed at once instead of reporting just one each time. When pasting multi-line text during a session (the conversation cycle between you and the AI), if paste mode resets midway, the lines are no longer sent one by one as commands. When a history prompt containing Tab characters is recalled, the cursor no longer stops at a non-final position. The send hint on older Windows Terminal versions now shows ctrl+x ctrl+s. When reading a PDF fails, paths with special characters display properly, and folder names resembling password or invalid no longer mislead about the cause of the error.

BUGFIX

Mid-command cancel protection and plugin uninstall fixes

Cancel handling and error safeguards when running commands and managing plugins have been corrected.

After you cancel, /install-github-app no longer keeps pushing the branch or saving the key; it stops immediately and reports the progress already completed. When running /feedback, /bug, or /share on platforms like Bedrock and Vertex, canceling midway through saving no longer force-writes the report file. When uninstalling a plugin, if the config file still enables that plugin or can't be read, the system stops the uninstall and points out that file, instead of falsely reporting success or deleting settings. If the plugin list can't be read after uninstalling, your saved options and secret information are still kept, and the uninstall tells you this data was preserved. claude remote-control --debug no longer errors out over an unrecognized argument.

BUGFIX

Fixes for skills panel search, input cursor, and shortcut hints

Several details of interacting with terminal menus and list windows have been fixed.

In fullscreen, the /feedback draft list now shows a scrollbar on mouse hover. In /skills, keys typed right after / no longer move the skills list and instead go into the search box. As you keep typing keywords, the typing cursor no longer jumps back to the list body, avoiding a hidden cursor and misplaced input-method text. Outside fullscreen, the /skills and /mcp lists are no longer two columns narrower. The key hints at the bottom of the agents panel no longer wrap onto two lines with custom long shortcuts, and the collapse hint respects your custom key settings. If you unbind the shortcut for stopping all agents in keybindings.json, the extra separator no longer appears at the bottom of the /tasks dialog.

BUGFIX

Fixes for Vim mode editing commands and cursor positioning

When using Vim keyboard mode in the terminal input box, several editing commands have been corrected to standard behavior.

The >> indent command no longer adds indentation to blank lines, r with a count no longer corrupts text when it exceeds the line length, 2J no longer merges one extra line, and repeated deletes and indents on the last line (like 2dd or 2>>) no longer shift oddly or delete the final line by mistake. After deleting with dd, dj, or dG, or pasting whole lines with p/P, the cursor lands on the first non-blank character; yy yanking no longer moves the cursor unexpectedly, and pressing Esc after an emoji no longer gets stuck inside the character. Using . to repeat x, s, p, d, or c now correctly recognizes a preceding count; when the previous line is wrapped, whole-line editing commands like p/P, o, O, J, >>, and << no longer act on the wrong line. When recalling a prompt from history or pulling it back from the queue, the cursor in normal mode lands precisely on the final character so x can delete it directly.

FEATURE

Faster resume of very long sessions and artifacts panel improvements

Continuing very long conversations and managing artifact files is now smoother.

Loading speed when resuming a huge session (the conversation cycle between you and the AI) is significantly faster, including long conversation histories that have never been compacted. On Windows, if a conversation can't be resumed because of a file read failure (EBADF), the error message now lists possible causes and troubleshooting suggestions in detail. When publishing an artifact, version labels longer than 60 characters are automatically shortened to avoid publish failures. The /artifacts panel layout has been overhauled: titles line up neatly in a single column, and descriptions that don't fit are omitted as a whole item instead of being cut off mid-word; the list also supports PgUp/PgDn, Home/End, mouse wheel, and click actions.

FEATURE

Claude API guidance updates and interface visual tweaks

The built-in claude-api skill has been updated with the latest rules for model billing and managed agent resource management.

The skill documentation adds a link explaining refusals in billing: refusing before output counts toward rate limits, while refusing mid-stream is billed as usual. The docs recommend using ant apply to bring Managed Agents managed resources under version control. On the visual side, the ultracode styling of /effort and the input box has been simplified to a clean, plain look, removing the ripples, border decorations, and keyword shimmer; the spinning indicator for dynamic-workflows has also been removed. The mascot Clawd's feet in the terminal startup banner have been repositioned below the corners of its body.

BUGFIX

VS Code extension long-reply streaming performance and connection UI fixes

Several issues in the VS Code extension around long conversations and window integration have been fixed.

When generating long replies, the panel no longer re-parses the entire text on every character update, improving the laggy stutter where reply content couldn't keep up with the stream. When the message input box grows tall enough to show a scrollbar, the voice input microphone button no longer covers the scrollbar. For a remote-control session (the conversation cycle between you and the AI) started locally, you can now open the local conversation from the Web list item, unless the session is running elsewhere. After the extension host restarts, if the sign-in screen in an editor tab gets stuck, an "unresponsive" notification is shown.

FEATURE

Cloud session repository connection and schedule management improvements

When managing cloud tasks across platforms, several interface operations have been strengthened for viewing associated codebases or confirming recurring schedule times.

The GitHub connector settings page now shows the GitHub App's installation and connection status, with steps to connect, install, or reconnect. When a repository is hosted on a non-GitHub Git server, the cloud session's repository menu adds shortcuts to open the repository and open the version comparison page. A running session (the conversation cycle between you and the AI) that already has one repository can now attach repositories from different GitHub owners, including sessions started from Slack, making it easy to compare against upstream projects. Fixed an issue where the next run time of an hourly recurring schedule in a half-hour time zone was off by 30 minutes. Accounts with large numbers of scheduled check reminders now load the Routines page and the sidebar schedule list noticeably faster.

BUGFIX

Slack Enterprise Grid Channel Sharing and Permission Setup Fixes

When teams collaborate across departments using Slack's multi-workspace architecture, they often run into situations where the bot fails to auto-join new channels or cannot reply properly.

With an org-wide enterprise installation, channel auto-join rules configured for a single workspace are no longer ignored, and Claude joins qualifying new channels as expected. In channels shared between different workspaces of the same organization, Claude no longer stays silent just because its version setting comes from another workspace. If a channel is shared with a workspace that has not installed Claude yet, the prompt message now clearly states which workspace needs the installation, instead of only reporting that the channel cannot be checked. After disconnecting a GitHub organization, removing that authorization from a permission bundle now saves successfully. When a legacy Slack app connects to GitHub Enterprise Server, the progress card now correctly shows the repository name and provides a working Create PR button.

BUGFIX

Slack Message Layout, Model Migration, and Usage Display Fixes

Model switching and message rendering in Slack internal conversations received several improvements.

When the older model a thread was using goes offline, the thread migrates directly to an available model, instead of retrying with the slower fallback model on every reply and popping up a notice. File descriptions Claude uploads to Slack now support table formatting, consistent with regular replies. The Agents & tools list no longer mistakes a thread's first message for its name, and later renames sync as well. After a session's cloud work unit restarts, the cost and token (the text unit AI processes and bills by) counts at the bottom of replies no longer inflate severalfold. Plan, table, and detail border cards in replies now default to a wide layout, and newly connected Slack workspaces also follow changes to the current default model.
