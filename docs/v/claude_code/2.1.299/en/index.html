Claude Code 2.1.299

Released: 2026-10-14

Release notes

FEATURE

Automatic Idle Compaction in Terminal Preserves Prompt Cache for Long Conversations

When you have a long conversation with Claude and step away, the terminal now manages your cache in the background. If a conversation exceeds 200,000 tokens and remains idle for around 54 minutes, it automatically compacts the conversation history before the one-hour prompt cache expires, preventing the next message from incurring the full processing cost again. This feature requires v2.1.290 or later. You can set the environment variable CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS to adjust the trigger threshold, or disable it by adding {"idleCompaction": false} to ~/.claude/settings.json.

Picture a library reading desk: previously, if a reader stepped away for too long, staff would return all the books to the stacks to be reshelved, but now a dedicated assistant writes down key notes before the time limit, letting you resume work with the summary the moment you return.
FEATURE

File Mentions Support Path-Only Mode to Save Space During Document Reads

When mentioning files with @ in a conversation, you can now have Claude receive only the file path instead of stuffing the full document content into the prompt. Simply set the environment variable CLAUDE_CODE_DISABLE_FILE_MENTIONS, and Claude will instead use its own file tools to read the target path. When you mention a PDF file in a message, the system no longer retains the raw bytes of the entire document in the session history, cutting down on memory and disk consumption. In addition, an issue where the Read tool failed to read specific page ranges of PDFs when running without root privileges in Linux remote sessions has been fixed.

Think of handing a reading list to a research assistant: previously, you would stuff a thick stack of original manuscripts into their briefcase every time you spoke, but now you only provide library call numbers so they can pull the specified chapters from the shelf when needed.
FEATURE

Agent View Adds Parameter Menus with Transparent Safe Mode Status

When managing background agent sessions, you can now use /effort and /fast directly in the agent view to set the default thinking depth and speed for new sessions. Entering /model, /effort, or /fast on its own also opens a menu for direct selection. For background sessions launched with --safe-mode, the preview panel in the agent view now displays an extra line clearly indicating that safe mode is active, and sessions will no longer silently drop out of safe mode when resumed or restarted. In addition, background prompts in bare mode no longer mislead you into omitting --bare when reopening, guiding you instead to use /stop and claude --resume to exit the mode. Previously, reopening background tools risked losing protection settings, but now state remains intact throughout.

FEATURE

Usage Monitoring Adds High-Consumption Alerts and Calibrates Percentage Metrics

When checking resource usage, /usage now warns you in advance during several scenarios that consume significant quota. Alerts appear on screen when you configure maximum thinking depth, run automated workflows, enable persistent context, or receive heavy tool output, helping prevent rapid quota exhaustion. At the same time, a calculation bug that occasionally produced absurd figures exceeding 100 percent in /usage, quota exhaustion warnings, and the status line at the bottom of the terminal across both the terminal and VS Code has now been corrected.

Like a car dashboard fuel gauge that flashes consumption warnings when the driver steps hard on the accelerator or engages all-wheel drive, the needle now stays accurately pinned within full scale rather than shooting past the gauge limits.
BUGFIX

Self-Hosted Runners Gain Graceful Shutdown with Connectivity and Credential Fixes

When operating self-hosted runners, the scheduler can now use the --shutdown-drain-sec flag to specify a grace period in seconds after receiving a SIGTERM signal. The runner immediately halts polling for new tasks and preserves this duration to allow active polls and hooks to complete cleanly. Meanwhile, MCP servers loaded via external wrapper files are no longer unexpectedly terminated if connector configurations change during execution. When a host lacks Git credentials, setup and doctor now provide clearer instructions. Sessions that emit output before their first turn previously missed setting a retirement timer and ignored --retire-at, causing delayed shutdowns; this timer now operates properly. Additionally, MCP requests in both cloud and self-hosted environments no longer follow proxy HTTP redirects.

FEATURE

Application Gateways Support Custom Attribution and Strictly Block Blacklisted Models

When routing Claude Desktop or terminal sessions through enterprise application gateways, you can now manage attribution signatures with greater flexibility. If you prefer not to display the attribution block in gateway sessions or the Code tab of Claude Desktop, setting the environment variable CLAUDE_CODE_ATTRIBUTION_HEADER=0 in your gateway policy disables it entirely. The attribution block itself also gains custom fields. For security management, gateways previously could inadvertently expose blocked models when applying exact-match or blacklist policies. The gateway now strictly excludes these prohibited models from its catalog and rejects matching requests by returning a 400 error. Permission enforcement previously risked leaking blocked entries, but list verification is now airtight.

BUGFIX

Custom Gateway Timeouts Relaxed to Prevent Third-Party Key Leakage

When connecting custom API gateway servers, the system now provides more resilient handling for long-lived connections and API key isolation. Streaming responses routed through the ANTHROPIC_BASE_URL environment variable now have their data timeout extended from 180 seconds to 300 seconds, reducing the likelihood of long thinking processes getting cut off midstream. In the past, custom gateway sessions nearing 200,000 tokens were often mistakenly flagged as exceeding length limits and aborted; requests are now dispatched normally. On the security front, requests to official servers for managed settings, feature flags, profile data, or feedback previously suffered from a vulnerability that forwarded third-party gateway keys to official endpoints; those requests now strictly isolate third-party keys and transmit only the valid official keys when required.

FEATURE

When developing and rendering module interfaces, layout flexibility is now substantially improved. On terminal displays, dimColor muted text is no longer conflated with standard text under dark ANSI themes and 16-color terminals. When a module triggers a re-render via $.ui.invalidate, updated contents are now reliably delivered to Claude on the subsequent turn. Furthermore, when asserting UI trees in the plugin test framework, root nodes are now strictly labeled with their owning plugin name.

FEATURE

Module Hooks Expand Context Fields to Support Media and Identity Access

Enterprise-managed extension modules now receive richer contextual details from hooks. Inside the prompt.submit hook, you can access raw image and document attachments from prompts directly through $.prompt.media. Calling $.session.identity() retrieves the session login method, organization, and email address. For skill invocations, the skill.prompt hook now receives the skill frontmatter configuration data, source, plugin name, and file path. In addition, the session.append hook introduces a queue entry point, separating queued transcript items from dispatched content. The turn.start hook no longer listens exclusively to the main loop, allowing it to recognize and monitor subagent or teammate turns via the presence of e.agentId.

BUGFIX

When running automation scripts in headless mode, module lifecycles are now shielded by stricter safeguards. Previously, if a module automatically submitted prompts at the end of each turn, it could bypass --max-turns limits, budget constraints, or abort signals and keep running; these constraints are now enforced. When administrators remotely disable a module, active sessions unload it immediately at turn boundaries. If fixes are saved immediately after a hot-reload failure, hot reloading now triggers updates properly, and re-saving untouched files no longer sparks redundant reloads. Furthermore, issues where cross-file function imports rejected object passing, module hooks asynchronously awaiting external operations entered endless loops, and modules were created at specific paths without confirmation have all been thoroughly resolved.

BUGFIX

Plugin Hook Defense-in-Depth Arrives to Block Object Tampering

A new defense-in-depth mechanism is now in place when plugins pass complex data structures. Plugin hooks and workflow scripts now uniformly cap the nesting depth of returned objects at 28,000 levels, preventing malicious or abnormal structures from degrading the system. When a plugin hook fails to receive or return results due to an exception, actions with intercept permissions are directly blocked from running rather than allowed through. If a tool has already run, its output is also forcibly withheld. When retrieving an individual property triggers an error, the system no longer rejects the entire object and instead only removes the offending key. Additionally, internal data passing no longer silently strips prototype keys, ensuring tool security checks cannot be bypassed. When a module makes a network request and receives a no-content status code, it also no longer misreports header length limits as exceeded.

FEATURE

Testing accuracy has improved significantly when writing automated tests and evaluations for plugins. When an evaluation encounters errors such as API access denials, the test is immediately scored 0 and exits with status code 1, rather than passing by chance. During test runs, if a service method called by a module does not respond within 10 seconds, the test directly fails just like a regular session. Validation errors when type declaration files are located at specific paths, along with telemetry events falsely reporting no hooks, have also been fixed.
