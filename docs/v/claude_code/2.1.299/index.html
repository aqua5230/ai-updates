Claude Code 2.1.299

發布日期：2026-10-14

繁體中文

新功能

終端機閒置自動壓縮，長對話不再耗盡提示快取

當你跟 Claude 進行長對話並暫離時，終端機現在會在背景幫你顧好快取（cache，把查過的結果暫存起來直接用）。若對話超過 20 萬個 token（AI 處理與計費的文字單位）且閒置約 54 分鐘，它會在滿一小時的提示快取過期前自動壓縮對話歷史，避免下一則訊息重新耗費完整處理成本。這項功能需要 v2.1.290 或更新版本。你可以設定環境變數 CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS 調整觸發門檻，若想停用，可在 ~/.claude/settings.json 加入 {"idleCompaction": false}。

彷彿圖書館的閱覽桌，以前讀者離開太久書籍會整批被館員推回倉庫重排，現在專屬助理會在逾期前把重點摘記好，讓你回來時翻開摘要就能立刻動工。
新功能

檔案提及支援僅給路徑，文件讀取更省空間

你在對話裡用 @ 標註檔案時，現在能讓 Claude 只接收檔案路徑而非把整份文件內容直接塞進提示詞。只要設定環境變數 CLAUDE_CODE_DISABLE_FILE_MENTIONS，Claude 就會改用自身的檔案工具讀取目標路徑。當你在訊息裡提及 PDF 檔案時，系統不再把整份文件的原始位元組留在工作階段紀錄中，減少記憶體與磁碟空間消耗。另外，在 Linux 遠端工作階段中以非最高權限執行時，Read 工具讀取 PDF 指定頁面範圍失敗的問題也已修好。

宛如跟研究助理交代待讀清單，以前每次開口都把厚重的整疊原稿直接塞進對方公事包，現在只給圖書館索書號，等他需要時再自己去書架翻閱指定章節。
新功能

代理檢視新增參數選單，安全模式狀態更透明

管理背景執行的代理工作階段時，現在能在代理檢視裡直接用 /effort 與 /fast 決定新工作階段預設使用的思考深度與速度。直接單獨輸入 /model、/effort 或 /fast 也會跳出選單供你直接挑選。針對帶有 --safe-mode 啟動的背景工作階段，代理檢視的預覽面板現在會多出一行提示清楚顯示處於安全模式，且在工作階段被喚醒或重啟時，也不會再發生無預警脫離安全模式的情況。此外，極簡模式（bare mode）的背景提示不再誤導你重開時省略 --bare，而是改為指引你使用 /stop 與 claude --resume 來退出模式。以前背景工具重開可能遺失防護設定，現在狀態始終維持原貌。

新功能

用量監控新增高消耗警示，百分比數值校準完畢

查詢用量時，現在 /usage 能提前在幾種特別吃額度的情況下發出提醒。當你開啟最高思考深度、執行自動化工作流程、啟用常駐上下文，或是工具回傳大量資料時，畫面都會亮出提醒避免額度驟減。同時，先前在終端機與 VS Code 裡的 /usage、額度即將用盡警示，以及顯示在終端機最底下的狀態列（status line）中，偶爾會出現已用額度超過百分之一百的荒謬數字，這個計算異常已經修正。

如同汽車儀表板的油耗提示，在車主重踩油門或開啟四輪傳動時主動閃爍耗油警報，並且指針刻度準確固定在滿格範圍內，不再出現指針衝破極限刻度的怪異現象。
問題修復

自架執行器支援緩衝關機，修復連線與憑證回報

維運自架執行器（self-hosted runner）時，調度程式現在能透過 --shutdown-drain-sec 參數設定收到 SIGTERM 結束訊號後的緩衝秒數。執行器會立刻停止輪詢新任務，並保留這段秒數讓進行中的輪詢與掛鉤（hook，特定事件發生時被觸發的小程式）順利跑完。同時，在執行期間如果連線器設定異動，透過外部包裝檔帶入的 MCP（讓 AI 連接外部工具的協定）伺服器不再被意外關閉。在主機缺少 Git 登入資訊時，setup 與 doctor 會給出更清楚的指引。工作階段若在首輪前就輸出內容，先前會漏設釋放計時器而忽略 --retire-at 導致延遲關機，現在計時器能正常運作。此外，雲端與自架環境中的 MCP 請求不再跟隨代理伺服器的 HTTP 轉址。

新功能

應用閘道支援自訂標註，嚴格阻絕黑名單模型

透過企業應用閘道串接 Claude Desktop 或終端機工作階段時，現在能更自由地管控簽章標註。如果不想在 Claude Desktop 的 Code 分頁或閘道工作階段中看見歸屬區塊，只要在閘道策略的環境變數設定 CLAUDE_CODE_ATTRIBUTION_HEADER=0 即可完全關閉。歸屬區塊本身也新增了自訂欄位。在安全管理方面，閘道先前在套用精確比對或是黑名單策略時，可能誤將被封鎖的模型對外開放。現在閘道會確實把這些違規模型從清單中排除，若收到請求則直接回傳 400 錯誤拒絕連線。以前權限控管容易出現漏網之魚，現在名單檢驗滴水不漏。

問題修復

自訂閘道連線逾時放寬，防止第三方金鑰洩漏

串接自訂 API 閘道伺服器時，系統現在能更穩固地處理長連線與金鑰隔離。透過環境變數 ANTHROPIC_BASE_URL 轉發串流回覆時，等待資料抵達的逾時限制從 180 秒放寬至 300 秒，減少長思考過程被中途掐斷的機率。過去當自訂閘道的工作階段對話逼近 20 萬個 token（AI 處理與計費的文字單位）時，容易誤判為長度過長而直接中斷，現在會正常送出請求。在安全性部分，先前向官方伺服器請求受控設定、功能旗標、個人資料或意見回饋時，曾發生誤將第三方閘道的金鑰一起送往官方伺服器的漏洞；現在這些請求已確實將第三方金鑰隔離，僅在必要時發送正確的官方金鑰。

新功能

模組介面排版元件升級，色彩與邊框精準繪製

開發與執行擴充模組的介面時，排版彈性現在提高許多。模組的 Text 元件新增了 size、weight、mono 與 tabular 屬性，Box 元件也支援從 xs 到 xl 的具名間距級距，舊有的 bold 則改由 weight 取代。在終端機顯示上，dimColor 淡色文字在暗色 ANSI 主題與 16 色終端機下不再與一般文字混淆。在 VS Code 或文字模式 claude -p 等無法繪製面板的環境中，$.ui.open 不會再虛報面板已放置成功。模組透過 $.ui.invalidate 觸發重繪後，更新後的內容現在會在下一輪確實送交 Claude。此外，在外掛測試框架中比對介面樹狀結構時，根節點現已強制標記所屬外掛名稱。

新功能

模組掛鉤擴充資料欄位，支援讀取媒體與身分

受企業管控的擴充模組現在能從掛鉤（hook，特定事件發生時被觸發的小程式）中獲得更多上下文細節。在 prompt.submit 掛鉤中，你可以透過 $.prompt.media 直接讀取提示詞夾帶的圖片或文件原始資料。呼叫 $.session.identity() 則能獲取工作階段的登入方式、組織與電子郵件。針對技能呼叫，skill.prompt 掛鉤現在會收到該技能的前置設定資料、來源、外掛名稱與檔案路徑。此外，session.append 掛鉤新增了佇列入口，讓記錄在對話歷程中的佇列項目能與實際發送的內容做出區隔。而 turn.start 掛鉤不再只監聽主迴圈，也能藉由是否存在 e.agentId 來識別並監聽子代理或隊友的執行回合。

問題修復

模組生命週期嚴格受控，修正背景無限迴圈

在無頭模式（headless，沒有視覺介面的執行模式）下執行自動化腳本時，模組的生命週期現在受到更嚴密的防護。以往若有模組在每回合結束時自動提交提示詞，曾發生無視 --max-turns 上限、預算限制或中斷訊號而持續運行的問題，現在這些限制會被強制遵守。當管理者從遠端停用模組時，進行中的工作階段會在回合交替時立刻卸載該模組。模組熱重載在重載失敗後若立刻存入修正，現在能正確觸發更新，且重複儲存未更動的檔案不再引發無謂重載。此外，跨檔案匯入函式傳遞物件被拒絕、模組掛鉤非同步等待外部作業引發無限重複執行，以及在特定路徑未經確認建立模組等異常，均已徹底修復。

問題修復

外掛掛鉤深度防護上線，嚴密阻絕物件竄改

擴充外掛傳遞複雜資料結構時，系統建立了全新的深度防禦機制。外掛掛鉤與工作流程腳本現在統一將傳回物件的巢狀層級上限收緊至 28,000 層，避免惡意或異常結構拖垮系統。當外掛掛鉤因異常無法接收或回傳結果時，原本具有攔截權限的動作將直接被拒絕執行而非放行；若工具已先行運作，其輸出結果也會被強制扣留。針對個別屬性取值引發錯誤時，系統不再整份拒絕物件，僅剔除出錯的鍵值。此外，內部資料傳遞不再偷偷抹除原型鍵值，確保工具安全檢查不被繞過；模組發起網路請求收到無內容的回應碼時，也不再因標頭長度誤判超標。

新功能

外掛評估支援排除工具，錯誤測試即刻判定不及格

在為外掛撰寫自動化測試與評估時，測試工具的精準度獲得了顯著改善。執行 claude plugin eval 時，現在能透過 --disallow-tools 參數或測試案例裡的 disallowed_tools 欄位，將特定的內建工具排除在評估流程之外。當評估過程遭遇 API 拒絕存取等錯誤時，該測試會直接判定為 0 分並以狀態碼 1 結束，不再僥倖判定為通過。在測試執行期間，若模組呼叫的服務方法在 10 秒內未給予回應，測試會比照工作階段直接判定失敗。同時，掛鉤的執行時間預算不再被背景持續呼叫所凍結。型別宣告檔位於特定路徑時驗證報錯，以及遙測事件誤報沒有掛鉤的問題也已一併修復。

新功能

企業受控設定加強防護，嚴防外掛竄改環境路徑

在受企業統一管轄的開發環境中，受控策略與外部模組的隔離更加嚴格。當組織集中管理 Claude Code 時，/plugin 指令與外掛驗證工具現在會主動列出哪些模組掛鉤會被略過。系統修補了沙盒環境中的指令得以寫入 --plugin-dir 資料夾的安全漏洞，防止外部未經驗證的程式碼藉由沙盒外重新載入而取得高權限執行。此外，使用者自行安裝的模組不再能透過設定環境變數影響企業受控命令的執行前綴，組織定義的權限規則與 MCP（讓 AI 連接外部工具的協定）工具名稱也不再被本機模組覆蓋。透過本機裝置管理設定的強制登入組織與驗證方式，現在始終享有最高優先權。

新功能

外掛製作流程指引更新，多終端安裝即刻同步

開發與分享擴充外掛時，跨視窗同步與發布流程現在更加直覺。當你使用技能製作模組並準備發布時，Claude 現在會在建立 GitHub 儲存庫之前，先向你確認要設為公開還是私人專案，並且會主動檢查即將推送的檔案內容是否妥當。在多個終端機視窗並行作業的情境下，先前在另一個終端機剛剛安裝的新外掛，在當前視窗執行 /reload-plugins 時可能會抓不到，現在這項同步問題已經修復。

跟在共用工作室協作一樣，同伴剛剛在工具架上擺出新工具，你一轉頭就能順手取用，不必再特地走出大門重開一次工作室。
問題修復

沙盒符號連結漏洞修補，路徑通配比對更精準

使用沙盒機制隔離執行指令時，系統修補了多項利用捷徑繞過管制的漏洞。在 macOS 上，沙盒指令過去曾藉由符號連結（symlink，指向另一個位置的捷徑檔）找到目標真實路徑，進而讀寫被明確禁用的目錄，現在這類捷徑穿透已被阻斷。當沙盒允許讀寫的起始目錄在執行中被替換成符號連結時，權限規則會立即重新檢查。針對包含大括號、括號或反斜線等特殊字元的資料夾路徑，設定檔檢查與底層沙盒對萬用字元的解讀現在已完全一致。在 Linux 環境下，若指令在展開萬用字元讀取規則時耗時較長，使用者也能正常按下 Esc 或 Ctrl-C 隨時中斷操作。

問題修復

沙盒跨平台相容修復，設定無法儲存時明確報錯

在不同作業系統上啟動沙盒時，邊界環境的設定儲存與目錄權限修復完畢。在 WSL2（Windows 上的 Linux 子系統）環境下，當沙盒具備 Windows 磁碟的寫入權限時，過去曾因目錄建立失敗報錯而卡住，現在已能正常執行。在 Linux 系統上，沙盒指令結束後若在設定目錄留下空白檔案，先前會導致登入狀態、伺服器清單與專案信任紀錄看起來全部丟失，這項顯示異常已修復。另外，若專案資料夾本身為唯讀而無法寫入設定，輸入 /sandbox 過去會虛報成功，現在會誠實告知設定未變更以及具體原因。以前遇到權限受阻時容易讓人摸不著頭緒，現在所有狀態都如實呈現。

問題修復

外部工具伺服器命名防護，權限比對不再混淆

當你替專案配置多個擴充服務並設定存取規則時，不再會因為特殊字元或縮寫而套用到錯誤目標。在設定檔中若 MCP（讓 AI 連接外部工具的協定）伺服器恰好命名為 constructor、prototype 或 toString 等 JavaScript 保留關鍵字，過去會無法連線或在自動授權模式下反覆跳出確認視窗，現在已恢復正常。同時，權限規則對名稱的匹配不再寬鬆放行：例如規則 mcp__a 過去會誤讓名稱為 a__b 或 a_ 的伺服器一同通過，現在僅嚴格允許名稱完全吻合的目標，若要涵蓋全部工具必須寫成完整名稱 mcp__<server>__*。若伺服器名稱本身包含雙底線，詢問與阻擋規則現在也能正確生效，不再因為底線切割而失效。

問題修復

外部協定支援新版協商，長文字描述不再截斷

透過網路連接外部工具時，通訊連線與資料傳遞的完整性獲得顯著提升。在雲端工作階段與遠端連線中，連線器預設將自動協商最新的 2026-07-28 協定版本。官方第一方伺服器的工具說明與指示文字，原本在超過 4,096 個字元時會被無情切斷，現在會完整傳遞給 Claude。進行身分驗證或更新 token（授權令牌）時，系統現在會如實送出自訂的標頭資訊，避免企業反向代理伺服器阻擋。針對 HTTP 連線收到通知時伺服器未結尾導致連線卡死 30 秒、背景重新連線導致工具呼叫重複執行或失敗，以及未經驗證的 HTTP 轉址問題，均已在此次更新中一併排除。

問題修復

外部設定解析修正，未授權伺服器不再暗中啟動

管理外部工具的設定清單時，格式驗證與啟動防護更加安全。現在當專案中的 .mcp.json 內容為空時，claude mcp list、claude doctor 與 /status 不再把它誤報為無效設定。如果設定檔裡的啟用清單只填寫單一伺服器名稱字串，整份檔案也不會再被忽略。在安全防護方面，當被安全性策略阻擋的伺服器遭到查詢或動態載入時，系統現在會在連線前就直接標記為受阻，絕不再暗中將其啟動或建立連線。此外，執行 claude mcp add 加入指令時，若指令結尾包含 --background，系統不會再誤把新增指令本身當成背景工作階段執行。以前設定檔格式稍微精簡就容易失效，現在容錯率高且安全把關嚴密。

問題修復

遠端遙控佇列穩定提升，慢速網路不再畫面凍結

從網頁端使用遠端遙控（Remote Control）操控本機終端機時，連線佇列的傳輸韌性更加穩固。在網路連線不穩或頻寬較慢的環境下，大量事件資料無法及時上傳時曾導致網頁畫面完全凍結，現在這類卡死狀況已經修復。當整批排隊等待的提示詞中有一則發送失敗時，同批次的其他提示詞不再會無故被整批丟棄。若使用者手動按下停止（Stop）中斷了下一則提示詞的檢查，前一則已經順利通過檢查的提示詞也能如實保留在歷史紀錄中。另外，使用方向鍵停留在佇列訊息上方時，介面現在會明確解釋停留原因。執行清除重置後再恢復舊工作階段，也不會再發生錯連到清除後新工作階段的靈異現象。

問題修復

遠端傳送大檔正常送達，相片本機存檔不卡關
