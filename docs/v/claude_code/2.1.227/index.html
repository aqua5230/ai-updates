AI_UPDATES.LOG

Claude Code 2.1.227

發布日期：2026-08-10

繁體中文

登入過期時，Max 使用者不再被誤催開啟用量額度

你明明訂了 Max 方案，剛開啟工作階段卻被催著替 Fable 開啟用量額度，感覺像進電影院時會員資料一時讀不到，售票員便誤以為你不是會員，要求你改辦一般票。問題出在登入 token（證明你已登入的數位令牌）過期時：功能旗標（feature flags，用來分批開啟功能的開關）檢查漏看了你的訂閱層級。現在即使一開始遇到過期 token，這項檢查也會帶上方案資訊，不會再錯誤提示 Max 用戶替 Fable 啟用 usage credits。

GitHub 雲端執行器不再拒跑所有 Bash 指令

你把專案交給 GitHub 自動跑檢查，卻發現 Bash（在終端機執行指令的常用工具）每一條都失敗，像工地門口明明有施工名單，警衛卻把整班工人全攔下來。這次問題出現在 GitHub-hosted runner（GitHub 提供、替你執行自動化工作的雲端電腦）搭配 claude-code-action，而且設定了 allowed_non_write_users 時；這個設定是允許沒有寫入權限者執行的名單。現在這組設定下的 Bash 指令能正常執行，原本的允許名單不再反而讓工作完全停擺。

倒帶到對話起點後，/tui 不再把舊對話叫回來

想把對話徹底倒回第一句以前、從空白重來時，最怕明明擦掉的內容又冒回畫面。先前若你把對話 rewind（倒回先前狀態）到第一則訊息之前，再輸入 /tui 開啟文字介面，舊對話可能被帶回來，像擦乾淨白板後按了開關，昨天的字又浮現。現在 /tui 會尊重你倒帶的位置：已倒到起點前的對話維持在那裡，不再被介面重新叫回。這是修正既有行為，不是新增一種刪除方式。

斜線指令選單更好認：只標選中項、保留表情符號

指令很多時，你靠選單找 / 指令，畫面不該把每個相關項目都染成同一種藍色。現在藍色只標出目前選到的那一列；搜尋命中的字元改用粗體，讓你仍能看出名稱本來的顏色。名稱含 emoji（表情符號）或重音字母時，字形也會完整保留，不再被選單弄得面目全非。它像車站的電子看板：亮的是你眼前要搭的那班車，符合搜尋的字則加粗，外國站名與圖示仍照原樣顯示。這是 slash-command menu（輸入 / 後出現的指令清單）的閱讀調整，不改變指令本身。

找不到檔案或檢查 @ 提及時，畫面少卡一下

輸入檔案名稱卻找不到、或在對話裡加上 @ 提及內容時，介面原本可能在背後檢查的空檔頓一下。這次減少了 event loop（程式用來輪流處理畫面與工作事件的節奏）在兩種檢查上的停滯：找不到檔案時產生建議，以及檢查 @ 提及內容的大小。像接線生本來要先停下來翻兩本簿子，才繼續接下一通電話；現在較少卡在那一步，畫面和其他工作有更多機會繼續往前。更新說的是效能改善，並沒有改變找不到檔案時的建議內容或 @ 提及的大小檢查規則。

English

Expired logins no longer nudge Max users toward usage credits

You may be on a Max plan yet get nudged to enable usage credits for Fable when a session opens. That was like a cinema clerk unable to read a member record and mistakenly asking a member to buy a regular ticket. If your login token had expired, feature flags were checked without your subscription tier. Those checks now include it, so Max users are no longer wrongly prompted to enable usage credits for Fable.

GitHub-hosted runners can execute Bash again

If GitHub is running checks for your project and every Bash command fails, the automation has become a worksite where the guard blocks every worker despite a valid list. This affected claude-code-action on GitHub-hosted runners when allowed_non_write_users was set—the list that permits users without write access. Bash commands now run normally with that setup, so the permission list no longer stops all work.

/tui no longer resurrects a conversation rewound to its start

When you rewind a conversation to before its first message to start from a blank slate, erased words should stay erased. Previously, opening the text interface with /tui could bring that conversation back, like yesterday's writing reappearing after you wiped a whiteboard and flipped a switch. /tui now respects the rewind point: a conversation rewound before its start stays there instead of being revived by the interface. This fixes existing behavior; it does not add a new way to delete chats.

Slash-command menu makes the selection—and every name—clearer

When a command list is long, a slash-command menu should not paint every matching item the same blue. Blue now marks only the row you selected, while matched characters are bold so each command name keeps its own color. Names containing emoji or accented characters also keep their glyphs intact. Think of a station board: your train is lit, matching letters are bold, and foreign station names and icons remain legible. This improves how the menu reads; it does not change the commands themselves.

Fewer pauses while checking missing-file suggestions and @-mentions

When a file name cannot be found or you add an @-mention in a conversation, the interface could pause while checking in the background. This release cuts event-loop stalls in two places: generating missing-file suggestions and checking the size of an @-mention. It is like a switchboard operator who no longer has to stop as often to search two ledgers before taking the next call. The screen and other work get more chances to keep moving. This is a performance improvement, not a change to suggestion contents or @-mention size rules.
