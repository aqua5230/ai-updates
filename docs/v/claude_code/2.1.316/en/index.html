Claude Code 2.1.316

Released: 2026-10-31

Release notes

FEATURE

Slack Cross-Channel Canvases Allow Continued Edits, Participation Setting Renamed

When collaborating across organizations or sharing canvases across channels in Slack, you may have encountered unanswered replies or Claude refusing to edit. Previously, once a canvas Claude created in a channel was shared to another channel or a direct message, it refused to edit or append content from that channel; this support has now been restored. In Slack Connect threads where both organizations have enabled Claude, untagged replies no longer go unanswered when forwarded to the other organization's app. The live checklist for cloud scheduled tasks can now directly update top-level messages posted during that run, preventing progress from staying half-done. On a channel's Configure page and in Claude Tag admin settings, the Respond automatically switch has been changed to a "How Claude participates" menu.

FEATURE

Cloud Sessions Support MCP Form Completion, Secret Management and Path Display Refined

When switching between cloud sessions in a browser to work on projects, interactive prompts and environment permissions now offer clearer feedback. Now, when an MCP (a protocol connecting AI to external tools) server requests a form, a card pops up in the interface for you to fill in or decline instead of the request being canceled without warning. When switching back to a cloud or Remote Control session while messages are still updating, the screen displays "Catching up…". Enterprise members can now add and delete network secrets in their personal cloud environments, rather than being restricted to view-only access. In a cloud session's Files pane search, a bug where folders appeared as ../.. paths after Claude changed directory has been fixed, and paths now show from the project root. The note explaining what the Changes pane leaves out has also been moved into a badge beside the branch name.

BUGFIX

VSCode Panel Supports Gateway Sign-In, Thinking Rainbow Effect and UI Controls Fixed

When collaborating on code with Claude in the VSCode sidebar, signing in to internal services and fine-tuning thinking effort now have more complete interface support. The chat panel can now sign in directly to an enterprise Claude apps gateway without opening a separate terminal. Entering ultrathink in a conversation runs that turn at xhigh effort and displays a rainbow effect in the chat box. When model settings carry the [1m] tag, the Effort slider, Ultracode switch, and model name are restored. When a configuration file contains errors, saved /btw question history will no longer be wiped accidentally. If manual approval of edits was previously specified, reloading the editor will no longer mistakenly revert to Auto mode.

FEATURE

Code Review Adopts Structured Cards, Analytics Page Adds Severity Charts

When submitting code for Claude to review project quality, the resulting review summaries and analytical statistics are now immediately clear. Starting /code-review from the Code tab in Claude Desktop or on the web now displays a structured findings card in cloud and claude remote-control sessions instead of a plain-text list. The findings-by-severity card on the analytics page shows the period's total findings, a daily chart stacked by severity, and counts for each severity level. When /ultrareview, a cloud session, or a cloud agent finds no GitHub remote, the message guides you to create a repository at https://github.com/new; in addition, /ultrareview no longer recommends a command that gh rejects.

BUGFIX

Bash Tool Retains Aliases and Functions, Background Commands No Longer Linger on Exit

When having Claude run scripts through the terminal, compatibility with a custom shell (an environment for running commands) has been improved. On macOS or Linux, when Claude Code exits on its own because credentials are refused or a cloud session is archived, it no longer leaves running commands behind. The Bash tool no longer garbles or loses aliases containing line breaks—except in Git Bash—and functions whose names start with a dash are now fixed. Scripts that export SHELLOPTS no longer stall right after their first command. In Windows Git Bash, when an rc startup file sets both errexit and pipefail while defining only winpty aliases or none at all, aliases and functions are no longer lost. When commands in PowerShell hooks (small programs triggered by specific events) start with a type cast, param, using, or an attribute, they also properly block execution on exit code 2.

BUGFIX

Auto Mode Permission Rules Prevent Accidental Overwrites, Interruption Status and Server Verdicts Fixed

When having Claude run tasks continuously in auto mode, permission lists and reasons for interruptions should never leave you guessing. When a managed autoMode.allow list omits "$defaults", built-in exceptions are no longer reintroduced by a host app's --settings, a first rule added in /permissions, or /auto-mode-setup; nor is the built-in rule on scheduled-task prompts removed because of this. Cloud sessions and scheduled tasks are now properly marked as failed when auto mode stops a turn because the server returned no safety verdict. While a background agent is still running, claude -p text output also explains why auto mode stopped a turn. In sessions started by a host application through a proxy or an LLM (large language model) gateway with experimental features turned off, the CLAUDE_CODE_AUTO_MODE_SERVER=1 environment variable is no longer ignored.

FEATURE

Certificate Errors Detail Actionable Fixes, Retaining Cross-Certificates for Private CAs

When tools send requests across an enterprise intranet or managed network, connection verification failures no longer throw a vague line of code.

Just like customs inspecting visa stamps in a passport, if an intermediate verification stamp is missing, the system points out exactly which checkpoint was skipped instead of coldly shutting the gate.

Now when an SSL certificate error occurs, the terminal directly analyzes likely causes, such as a server omitting an intermediate certificate, and provides specific remediation instructions. For architectures requiring internal private certificates, you can enable the CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP environment variable to retain cross-certificates that certify each other in a loop. In addition, network requests will no longer hang indefinitely if compressed data returned by a server is cut off or corrupted midway.

FEATURE

Gateway Supports Pooled Group Budgets, Layered Policies and Bedrock Guardrail Tagging Released

When managing team spend and permissions, the Claude apps gateway has new options. The pooled_budget field on the spend limits admin API can set a monthly shared budget for a group on top of each member's individual limit. Setting managed.policy_mode: layered applies all matching policies, merging each over the ones listed below it. On Bedrock upstreams, guardrail.input_tagging adds prompt attack filter tags; all_messages_and_system also tags the system prompt. Every model named in a request is checked against availableModels, deniedModels, and models; if blocked, a 400 error is returned naming the relevant field. When a gateway is required, running claude auth login in a terminal shows the gateway sign-in prompt. Managed settings fetched from the Anthropic API for Team and Enterprise accounts apply without confirmation, and any stored copy that fails verification is rejected.

BUGFIX

Opus 4.8 Fast Mode Slated for Deprecation, Three Model Aliases Restore Fallback

When switching between different Claude model versions across multiple cloud platforms, version migration and fault tolerance now have clear guidance. Fast mode for Opus 4.8 has been deprecated as of October 30, 2026, and will be removed on November 30, 2026; once removed, fast mode requests will return an error rather than falling back to standard Opus 4.8, requiring migration to Opus 5.5 to maintain speedups. On Vertex AI and Amazon Bedrock, the sonnet, opus, and haiku model aliases now switch to a compatible older version to provide fallback if the newest release is not yet available to your account or region, rather than failing mid-session. Entering an unrecognized model with /model <id> now triggers a warning that auto-compact will assume a 200K context window (the conversation volume it can hold).

FEATURE

Subagents Support Default Effort Settings, Deep Thinking Keyword Can Be Disabled

When dispatching background subagents (helpers that handle branching project tasks) to investigate a codebase, thinking depth and model inheritance can now be finely controlled. If a team prefers not to trigger extra high-intensity reasoning, the ultrathink keyword can be disabled directly via the CLAUDE_CODE_DISABLE_ULTRATHINK environment variable. For subagents spawned in the background, CLAUDE_CODE_SUBAGENT_EFFORT is used only when no other source specifies an effort level, replacing the default behavior of inheriting the main session's effort. Helpers that inherit a parent subagent's dedicated model will also stay locked to that assigned model after being awakened by a background notification or new message, rather than unexpectedly reverting to the main conversation model.

BUGFIX

Fixes for self-hosted runners and plugin environments, with improved SDK and Artifact rule loading

When hosting your own execution environments or writing plugin integrations, cross-machine state and rule displays no longer encounter unexplained errors. After a self-hosted runner session moves to a new machine, the on/off switch state of an MCP (a protocol that connects AI to external tools) server is no longer lost. After pressing Stop and replacing the process, it also no longer answers old messages sent while Claude was working. When a plugin credential environment variable is set to a switch value such as 1, the CLAUDE_PLUGIN_ROOT and server URL received by headersHelper scripts are no longer corrupted. With CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1, the SDK (software development kit) register_repo_root request can now load CLAUDE.md from outside the working directory. The Artifact tool no longer displays artifact database access rules at the self level as question marks, and now quotes those rules back when refusing a republish that would drop them.

BUGFIX

Invisible character cleaning in prompt input, with fixes for interface hints and survey submissions

When entering prompts and viewing hints in daily command-line use, multiple interface details that affect typing rhythm have been improved. Previously, copying text from web pages that contained invisible characters often required pressing Enter twice to send. Plain prompts now clean these characters and send on the first Enter press, while commands still retain the review confirmation step. The voice input hint no longer uses up its quota of three showings in a single session, and an empty keycap no longer appears when push-to-talk is unbound. During first-run startup in narrow terminal windows, security notes and terminal setup explanations no longer drop words. If /clear or /resume was run while a conversation was still being saved, resuming the conversation now also restores the original task plan. After typing 1 or 0 in the Enterprise survey, answers are no longer submitted due to a short pause, and now require pressing Enter to confirm.

PERF

Restricted sessions no longer upload files outside directories, with diff and search performance improvements

When comparing code changes or searching files across large projects, file upload scope and responsiveness are now more reliable.

A factory security checkpoint strictly checks the entry and exit list: even with a special pass, confidential documents outside designated work areas are strictly barred from being carried out the gate.

Previously in --restricted sessions, files outside working directories were not supposed to be uploaded even when covered by a Read allow rule. This upload restriction has now been fixed. When entering /diff in large repositories to inspect changes, each refresh usually runs one fewer full-repository Git command, and refresh intervals are automatically spaced out when Git responds slowly. For Windows users, Grep and Glob search tools no longer freeze the screen indefinitely when a search process is killed at timeout but fails to exit cleanly.
