Claude Code 2.1.281

發布日期：2026-09-23

繁體中文

新功能

Claude 應用程式閘道支援 Bedrock 角色切換與安全護欄

企業在雲端集中控管模型流量時，閘道在上游設定中新增了 assume_role 欄位。

這讓閘道能透過 STS 取得臨時憑證呼叫 Amazon Bedrock，甚至跨到其他 AWS 帳號，並支援為每位開發者提供獨立的工作階段。同時上游也支援配置 guardrail: {id, version}，強制所有請求通過指定的安全護欄檢查。

如同總部派出專車前往各分部載貨時，能換上該廠區的專屬通行證，且出發前一律通過安檢門過濾違規物品。
新功能

Claude 應用程式閘道擴充桌面端原則與固定遙測標籤

公司統一配置開發環境時，閘道的桌面端原則區塊新增了多項控管鍵。

管理者能設定禁止讀取工作目錄外的檔案（blockReadsOutsideWorkingDirectories）。同時也支援強制停用略過權限模式（disableBypassPermissionsMode）。閘道設定檔還可透過 telemetry.resource_attributes 為登入與工作階段加上固定遙測標籤。若受管 MCP 伺服器的路徑包含目前桌面端不支援的開頭格式，閘道會直接拒絕啟動以確保安全。

新功能

新增 attribution 設定，可隱藏提交與 PR 的署名資訊

想要讓程式碼版本庫的歷史紀錄保持純淨，現在可以在設定檔中加入 "attribution": false 來關閉所有 Commit 與 Pull Request 的工具署名。

若是團隊多人共用設定檔，請務必保留完整的大括號物件格式，避免舊版 CLI 遇到未知格式時直接略過整份設定檔。

跟寄出公文時拿掉編輯軟體的浮水印一樣，讓產出的紀錄完全只保留你的工作成果。
{
  "attribution": false
}
新功能

MCP 支援 URL 模式引導，伺服器可請求開啟瀏覽器流程

當外部服務需要你透過網頁完成登入或授權時，採用 2026-07-28 協定版本的 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器現在能主動要求 Claude Code 開啟瀏覽器畫面。

如果伺服器本身無法確認後續的完成狀態，終端機也不會留下一直卡住的等待對話框。

好比點餐機顯示網頁付款連結，手機直接跳出結帳畫面，櫃檯螢幕不會一直轉圈等待。
新功能

立即發送改將執行中工具轉入背景，不再中斷對話輪次

當你發現 Claude 還在執行耗時的指令，但你手邊已經想好後續的追問或新任務時，只要按下快捷鍵（Ctrl+Enter 或 Ctrl+X Ctrl+S），正在跑的工具就會被平順轉移至背景默默運作。

你不需要等它完全跑完，也不會因為搶先輸入而把先前的對話輪次強行中斷，讓工作節奏更為順暢。

彷彿在廚房燉湯的同時走進客廳交代同事下一份報表，瓦斯爐照常慢火細熬，你也不用站在爐邊乾等。
效能優化

自動模式審查擴及唯讀指令，並提供權限節省推薦

想要放手讓工具自動執行任務，自動模式（auto mode）在啟用伺服器端分類器時，現在連唯讀與沙盒內的指令也會經過伺服器審查，只要被標記有疑慮就會主動阻擋。

直接連線 Anthropic API 的使用者能透過環境變數 CLAUDE_CODE_AUTO_MODE_SERVER=1 加入審查。此外在終端機輸入 /insights 能估算自動模式近期為你的工作階段省下了多少次手動確認。

新功能

自動模式改進重啟快取複用與拒絕意圖理解

在中斷後重新接續工作階段（session）時，自動模式的權限分類器現在會直接重複使用先前的 Prompt 快取。

這項機制把算過或查過的結果暫存起來直接使用，省下重複計算的等待時間。此外當你拒絕某個危險動作時，Claude 現在會理解你拒絕的是「該項結果」而不只是那一行特定字眼，不會換個同義指令又重複嘗試相同的操作。

像吩咐管家不要買某款點心，他明白你的意思是別吃那道甜品，而不是換一間超商再去買回來。
新功能

加強刪除指令防護，新增變數路徑檢查與自動逾時拒絕

當工具在自動模式或略過權限模式下準備執行帶有變數替換的刪除指令時（例如 rm -rf "$(pwd)"），現在一律會停下來向你確認，不再直接放行。

如果目標路徑是變數接頂層目錄或純反斜線，安全防護也會主動攔截。在無人看守的工作階段中，確認視窗等待 2 分鐘後會自動拒絕並附上改寫提示，避免整台工作站因為等待使用者按鍵而永久卡死。

新功能

自託管執行器改用檔案傳遞系統提示詞，並加強指令檔統計

在自動化流水線中自建執行器時，極長的系統提示詞現在能改用 --system-prompt-file 傳遞私有檔案路徑，解決文字過長導致啟動失敗的問題。

同時啟動時的提示詞大小警告會將 @ 引入的所有關聯說明檔案一併合計。而在無頭模式（沒有終端機視覺畫面的模式）下，透過 --add-dir 額外掛載的資料夾也不會再把規則檔案重複傳送給模型。

問題修復

修復恢復工作階段時格式變更導致先前推理遺失的問題

接續先前未完成的對話時，多項恢復工作階段（session）的邏輯獲得了徹底修正。

以前平行工具呼叫、MCP 重新連線或中斷載入時，容易重複傳送格式變形的對話紀錄，導致 API 丟失先前的推理脈絡。現在超大工作階段不會再只恢復最後幾則訊息，在權限確認中途重啟也不會破壞快取暫存，而在工具執行中斷時手動恢復更不會偷塞隱藏訊息。這些損壞的歷史紀錄在啟動時都會自動修復完成。

新功能

改善長工作階段與已壓縮對話的恢復速度與快取還原

處理大型專案與長篇對話時，工作階段（session）的載入效率獲得了顯著提升。

重新打開讀取過大量檔案的紀錄時，還原檔案快取（把先前讀過的檔案內容暫存起來直接使用）的速度明顯加快，且內容與先前讀取時完全相符。在 Agent SDK 與桌面端中恢復已經過壓縮的超長對話也更加順暢。若開頭的第一則提示詞極長導致超出長度上限，系統現在會將該則提示詞獨立進行摘要修復，確保對話能正常接續。

問題修復

修復串流中斷與代理伺服器提早關閉連線時的重試與狀態遺失

連線經過企業代理伺服器或閘道時，串流傳輸的容錯機制更加健全。

以前串流連線正常關閉時可能被誤判為已完成回應，重複事件甚至會導致工具被重複執行兩次；現在中途掉包時會妥善保留已抵達的部分內容與搜尋結果。此外修復了 API 請求重試期間介面當機、斷線後重複發送空白請求，以及結尾附帶純用量資訊時遺失結束原因的錯誤，確保工作階段（session）的連線穩定可靠。

問題修復

修復 API 重試循環、限流等待與 HTML 錯誤頁面解析

遇到模型輸出截斷與工具呼叫解析失敗交替出現時，對話輪次不再無視最大輪數限制無休止重試。

重試看門狗機制在工作階段遭遇伺服器錯誤時不會再無限制靜默等待。快速模式收到 Retry-After: 0 時也不會緊接著瘋狂重發。此外代理伺服器回傳 HTML 格式的 429 或 502 錯誤頁面時，終端機會正確提取狀態碼，不再整段印出原始標記語法。

問題修復

修復工具回傳超大圖片、過長名稱與記憶體讀取失敗的卡住問題

呼叫外部工具處理多媒體或繁重工作時，多項邊界情況的穩定度獲得了加強。

當執行的工具回傳超大尺寸圖片時，修復了導致同批次其他工具無人回應且持續空轉的問題。同時解決了模型呼叫超過 200 字元的工具名稱造成對話永久卡死、系統檔案描述符耗盡時因無法讀取記憶體用量而誤報工具失敗，以及讀取或提及大於 3 MB 的 PDF 檔案時延遲甚至背景渲染無法中斷的情況。

問題修復

修復檔案工具包含空字元路徑與重複參數名稱時的處理錯誤

在程式碼編輯過程中呼叫各類檔案處理工具時，多項參數驗證邏輯得到了修正。

在使用讀取、寫入或編輯檔案工具時，如果路徑中意外混入了空字元（null byte），現在會明確回報工具執行失敗，不再直接中斷整個對話輪次。此外寫入工具在收到以不同參數名稱傳入但內容與路徑完全相同的呼叫時，也不會再直接拒絕執行。

宛如郵差看到寫錯格式的信封時會退件說明原因，而不是直接罷工回家。
問題修復

修復沙盒排除指令比對錯誤，並指引本機網路連接埠綁定

在 macOS 沙盒環境中開發時，如果本機開發伺服器無法綁定通訊埠，Claude 現在會主動引導設定 sandbox.network.allowLocalBinding。

同時修復了沙盒排除指令無法正確比對特定 Git 指令與帶有標籤的提交訊息、自訂暫存路徑時沙盒內無法寫入的問題，以及權限規則中包含空字元被誤展開為萬用字元與存取特定網路掛載路徑的安全性問題。

問題修復

修復 MCP 伺服器重複連線、掛鉤等待與無頭模式握手停滯

在無頭模式（沒有終端機視覺畫面的模式）下與主機端 MCP 伺服器連線時，若主機在握手中途無回應，遠端工作階段現在最多只會等待數秒便自動恢復。

同時掛鉤（hook，特定事件發生時被觸發的小程式）遇到阻塞事件時會確實等待伺服器連線。並修復了相同伺服器因網址大小寫或結尾斜線不同而連線兩次，以及另一個行程登入後狀態列未同步的問題，進一步提升連接工具時的可靠度。

效能優化

過濾 MCP 應用程式介面資源，並改善附件重複下載與螢幕報讀

在終端機中透過 @ 提及或列出 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）資源時，清單會主動略過純 UI 專用的應用程式資源，避免干擾主要提示詞。

在遠端控制連線中，工作階段內已下載過的附件會直接重複利用連線與暫存檔，不再浪費頻寬重複抓取。而在使用螢幕報讀軟體瀏覽 /mcp 清單時，停用的伺服器狀態會明確朗讀為關閉而非等待中。

問題修復

Plugin 新增 MCP 驗證檢查，並修復專案範圍管理指令

開發或安裝擴充外掛時，執行 claude plugin validate 現在會主動檢查 .mcp.json 中被略過的項目、未宣告的使用者設定變數與不安全網址，且不再將隱私權或支援網址誤判為未知欄位。

同時修復了解除安裝專案範圍外掛時誤報啟用中、更新時省略 --scope 誤用使用者範圍，以及從含有市集檔案的目錄載入外掛時載入空白外掛的問題。

新功能

Plugin 錯誤時顯示所屬名稱，加強掛鉤路徑與市集快取

在外掛生態系中除錯與管理套件時，錯誤回報機制變得更加明確。

當外掛中的掛鉤（hook，特定事件發生時被觸發的小程式）執行失敗時，錯誤訊息現在會明確點名是哪一個外掛出問題。驗證工具也會在指令未替路徑加上雙引號時發出警告，避免路徑含有空白字元時壞掉。此外市集在連線失敗並保留本機副本時不會誤記為已重新整理，解除安裝時若檔案因其他外掛使用而保留也會清楚說明。

問題修復

改進 Plugin 清單排版與捲動，修復市集更新與錯誤頁面確認

在終端機打開 /plugin 管理介面時，已安裝外掛清單現在會依狀態、名稱、類型與詳細資訊分欄整齊對齊，方便你一眼看清各個套件的狀態。

滑鼠滾輪能正確捲動清單內容而不影響底層畫面。同時修復了連按 Enter 觸發兩次更新或解除安裝、按住 y 鍵瞬間誤加市集，以及錯誤分頁在排除所有問題後沒有顯示確認提示的狀況，讓管理與瀏覽擴充套件時的操作更加順暢安定。

新功能

工作階段成品收納為底部按鈕，並改進頁面文案與壓縮上傳

對話中產生的所有成品現在會在輸入框下方整合為單一膠囊按鈕（例如 ⧉ name）。

點擊該按鈕即可打開 /artifacts 清單查看本次工作階段的所有產出。成品設計技能現在會要求 Claude 生成更精準直白的說明文字；在慢速網路發布較大成品時會自動啟用壓縮傳輸，並允許載入外部公開腳本，在遠端控制工作階段中也不會再遺失成品工具。

問題修復

修復雲端與遠端工作階段的背景代理回報、定時任務與重試迴圈

遠端執行長任務時，修復了背景代理剛完成就遇到工作單元重啟導致結果未告知 Claude 的問題。

同時排程任務與 /loop 在派送失敗時不會再每秒無休止重試導致程式結束。修復了權限確認重疊時介面卡在待核准狀態、定時輪次在第一個工具呼叫前遺失開頭通知，以及遠端控制在組織原則載入中誤報已停用的情況，保障長時無人值守任務順利推進。

問題修復

修復 macOS 鑰匙圈鎖定時遺失憑證，並最佳化互動式啟動耗時

在 macOS 睡眠喚醒或登入鑰匙圈鎖定時，寫入新憑證不再會意外遺失既有的 MCP 授權令牌（token，用來驗證身分的授權憑據）或刪除項目。

雲端身分更新背景程序結束時會確實釋放通訊埠。啟動時也將 Git 讀取與模型升級檢查移至首格畫面渲染之後，並停止對無法成功的原則請求進行無效重試，讓終端機工作階段更快進入可用狀態，有效減少開機等待時間。

問題修復

修復子工作階段繼承設定來源，並加強背景工作區信任檢查

透過 claude --bg 啟動背景工作階段時，如果目錄尚未通過工作區信任確認，現在會主動要求確認而非直接執行專案掛鉤。

透過 --setting-sources 指定的設定限制現在會完整傳遞給衍生出的隊友與背景工作階段。同時修復了非互動模式下工作目錄被刪除引發的錯誤，以及未設定外掛時啟動不必要等待受管設定網路請求的問題。

新功能

多代理支援讀取 JSON 檔案，批次執行支援自訂工作樹掛鉤

使用 --agents 啟動多代理時，現在能直接指定 JSON 檔案路徑並允許空白提示詞。

打 /batch 時即使不在 Git 倉庫內，只要有工作樹（worktree，平行開啟多份副本的功能）建立掛鉤提供目錄也能正常執行。此外從網頁端同步的技能清單會以簡短名稱顯示，深度研究（/deep-research）在長篇摘要上的穩定度也獲得提升。

問題修復

修復 Vim 模式按鍵動作，改進排隊訊息與文字貼上呈現

在終端機使用 Vim 編輯模式時，修復了 dj、cw、1G 與點號重複插入等多項游標與按鍵行為異常，避免帶有驚嘆號的文字誤切換至 Shell 模式。

在 Claude 思考中途排隊送出的訊息現在會固定顯示在載入動畫上方並保留編輯器選取範圍。單行文字貼上在多數情境下也不會再被意外換行打散，讓命令列輸入體驗更加順暢自然。

新功能

改進代理面板操作提示與焦點，更新背景工作列進度顯示

在終端機查看多代理面板時，底部提示鍵現在會如實反映自訂鍵盤對應，且不會在當前檢視的代理上重複提示切換按鍵。

滑鼠點擊代理列會同步更新鍵盤游標，按下 Esc 鍵只會取消選取而不會誤中斷正在進行的對話。輸入框下方的背景工作列則新增了進度條、耗時與文字單位（token，AI 處理與計費的文字單位）統計，掌握背景任務的即時進度變得更加一目了然。

新功能

改進工作流程清單排版，終止重大檢視前新增防誤觸確認

打 /workflows 查看工作流程時，每一列改為以狀態圖示與耗時開頭，在窄終端機中會優先保留名稱與時間。
