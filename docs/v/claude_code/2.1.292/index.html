Claude Code 2.1.292

發布日期：2026-10-06

繁體中文

新功能

擴充套件市集安裝與來源檢核

當你想安裝團隊推薦或第三方維護的外掛套件時，指令操作變得更加俐落安全。

claude plugin install 現在支援 --marketplace <source> 參數，<source> 是要安裝外掛的市集來源。若本地尚未加入該市集，會先執行相同的安全政策檢查並自動添加，再直接完成安裝。在初次啟動時，各項套件指令一定會等組織管理的原則完全載入才放行。若設定檔宣告的市集名稱看似官方來源，介面也會給予清楚的識別引導。

彷彿到圖書館借閱特定館藏，館員會先依規定審驗借書證並登記新書庫，隨即直接將書本遞到你手中，不必分兩趟跑櫃檯。
新功能

子代理思考深度與執行限制

當你指派背景任務給子代理處理繁重工作時，能更精準調度它的心力與權限。

Agent 工具新增 effort 參數，讓你指定子代理投入的思考深度。代理名稱最多 256 字元，超過會被拒絕；技能或外掛檔案的 name 超過此長度則會被忽略。自動模式若被設定停用、觸發 circuit breaker（斷路保護，達到保護條件時停用）或模型不支援，設有 permissionMode: auto 的子代理不會再進入自動模式。若主對話已因用量額度（允許使用的上限）耗盡而停止，背景代理碰到同一限制時，不再逐個重複跳出警示。

好比主管分派助手調研，可以交代各自要鑽研多深；預算耗盡後，也不再讓每位助手接連敲門重複警告。
新功能

外掛功能事件與測試機制

自訂外掛模組時，你能補上輸入建議，也能看清工具為何被擋。

prompt.autocomplete 事件讓模組加入輸入框的補齊選項。$.model.complete 的 prompt、system 接受文字區塊；在區塊上設 cache: true，會快取（暫存以便重用）截至該區塊的請求。agent.spawn 掛鉤（事件觸發的小程式）加入工作流程代理及其 run 執行、index 索引資訊，供模組拒絕啟動。Write、Edit、NotebookEdit、LSP 列及單筆 Read、Grep、Glob 列，現在會顯示模組拒絕呼叫的原因。執行 claude plugin test 時，測試註冊的掛鉤內 expect 檢查失敗，或引擎拒絕樁回應（測試用的替代回答），都會讓測試失敗，不再靜默過關。

問題修復

外掛攔截掛鉤與權限邏輯修復

外掛攔截操作時，失敗原因與確認視窗不該消失。

掛鉤（事件觸發的小程式）config.set、state.set、env.set、agent.spawn 呼叫 next(e) 後拒絕，改為具名回報掛鉤失敗；呼叫後在回合中斷時失敗，則拒絕呼叫。/theme、/config Theme 選單及首次主題設定，都先詢問 config.set 才儲存。tool.check 放行也不再跳過問題或計畫核准視窗。丟棄提示詞或拒絕設定的理由超過 4096 字元，不再被忽略。tool.call 看到的是修正錯名參數後的引數。另一模組的掛鉤在守衛自身 $ 呼叫下發起呼叫時，守衛的 .catch 現在會被詢問。掛鉤輸出的 <system-reminder> 標籤會先轉義，讓 Claude 收到的是文字。

問題修復

外掛模組載入效能與工作行程修復

在載入複雜外掛或背景工作單元重新啟動時，你可能遇到等待數分鐘或啟動工作重複出現。

掛鉤模組透過同一個 const 常數大量呼叫 $.state，不再拖慢載入與驗證。claude plugin validate 不再列出引擎從別處讀取的 matcher 匹配條件或狀態值；透過頂層 var 讀取狀態，若該變數重複宣告或被重新賦值，模組現在會被拒絕。外掛提供的 $ 方法不再重啟掛鉤來源，讓守衛掛鉤的 .catch 無限重跑。掛鉤（事件觸發的小程式）工作單元替換時，啟動提示詞、指令或子代理不再重複排隊。組織外掛重載或另一外掛崩潰後，若回傳個人模組已加入的 $ 名稱，改卸載個人模組。重啟期間，外掛介面呼叫仍經過其他外掛加上的掛鉤，工具呼叫也仍經過權限掛鉤。

新功能

沙盒隔離機制與敏感路徑防護

你在沙盒（限制存取的環境）跑指令時，不能再讀取~/.claude/seed-admin的/ultrareview上傳副本。

受管理及並列使用者禁讀路徑在工作階段中途出現或改指向，會撤銷內部專案授權、停止涵蓋檔案的憑證（登入證明）注入。macOS、Windows 讀筆記本或 PDF，不再因中途換連結取得未核准檔案。設定抓取失敗時，竄改快取（暫存）不能停用或取代內建原則外掛。Windows 家目錄或磁碟的 8.3 短檔名等拼法也算rm -rf刪除對象。PreToolUse 掛鉤核准與自動模式不再略過 UNC 網路檔案讀取的權限提示。在使用者設定、受管理設定或--settings指定的設定中啟用嚴格沙盒模式後，帶環境變數（執行時傳給程式的設定值）前綴的直譯器指令，例如FOO=bar python3 app.py，不再跳出詢問。

問題修復

工作階段恢復與背景排程修復

當你重新打開先前的對話繼續工作，或放著循環指令在背景執行時，恢復後的模式與排程不該悄悄失效。

從 claude --resume 選單或 /resume 回到工作階段，計畫模式會正確還原。/resume、/branch 或 /clear 後建立並儲存的排程不再永遠不觸發；任務檔案在相隔幾毫秒內寫入兩次後，也不再忽略後續新增與刪除。單次 claude -p 與 Agent SDK（讓程式呼叫代理的工具組）不再於最終結果後 5 秒停止背景指令，而會等待它們；只有單次 claude -p 另修好遺漏排程喚醒的問題，會等待喚醒。背景工作階段的行程重啟後，/loop 不再因喚醒遺失而默默停止。

智慧書籤以前會漏掉重開後的提醒，現在能保住閱讀模式，也不再把待響的計時器忘在上一頁。
新功能

檔案讀取、搜尋重試與大型附件處理

當你請 Claude 搜尋程式碼、翻閱文件或在提示詞中引用檔案時，各項讀取工具的回應更加明確。

Grep 與 Glob 遇到無法讀取的檔案或資料夾，不再誤報查無結果；Claude 會重試一次或告訴你。@ 引用超過 256KB 的文字檔不再被默默略過，Claude 會收到檔案大小及分段讀取指示。Read 讀取 PDF 時，若 pages 是 "6,9,15" 這類離散頁碼清單，不再只回傳第一頁，而會報錯要求逐頁或逐範圍讀取。設有 Read 拒絕規則且工作目錄位於符號連結（指向別處的捷徑檔）下時，不存在檔案的 @ 字詞不再誤顯示 "could not be examined"。Grep 接受以 file_path 代替 path；Write、WebFetch、Read 則忽略少數多餘參數，不再因此讓呼叫失敗。

新功能

提示詞指令與操作權限管理

當你在對話中切換操作模式、目錄或管理既有產出時，舊紀錄不該讓工具限制突然回來。

中途離開自動模式或計畫模式後，技能或斜線指令的 allowed-tools 規則不會再於後續回合復發。/cd 或權限變更後，"instruction file not loaded" 這類指引檔案未載入紀錄不再過時或缺漏；巢狀指引檔案未載入也會留下對話紀錄。對話壓縮摘要重複 /name，不再讓 Claude 呼叫保留給使用者的技能。Artifact 產物工具現在讓 Claude 看見已發布產物總數，一次可列出 200 項，上限原為 50 項。

調度中心翻閱舊紀錄時，以前可能誤開人工專用按鈕；現在舊摘要不再放行這些操作，清冊也能列出更多項目。
問題修復

終端機輸入、貼上與 Vim 操作修復

在終端機快速輸入、使用中文輸入法或透過 Vim 模式編輯提示詞時，你可能遇到文字被漏掉或按鍵被誤認。

多次貼上在同一提示詞中重疊進行，不再把部分貼上內容當成逐字鍵入。底欄列被選取時，快速輸入、輸入法文字及分解形式的重音字元不再遺失；! 也不再留住選取狀態。Vim（用按鍵指令編輯文字的模式）游標不再超出行尾，j/k 經過短行仍保留原欄位；f／t／F／T／;／, 不再跳至其他行的匹配位置，或刪除到那裡。/add-dir 路徑框不再讓 Shift+Enter 或貼上新增換行，也不再把快速打出的 "tab"、"up"、"down" 誤當按鍵。

鍵盤接待員以前會把字串認成按鍵、把貼上認成打字，現在能分清這些輸入。
效能優化

終端機畫面呈現與互動操作改善

當你瀏覽長篇回覆或找回草稿時，畫面與選單不該讓你重做操作。

/bug、/share、/feedback <text> 送出途中按 Ctrl+O 或 Ctrl+Z，不再重新開始；送出後也不再以取消狀態關閉。/remote-env 開啟時選中已儲存的預設環境，直接按 Enter 不再改掉它；沒有生效中的預設值時，各列都不打勾。偵測到 iTerm2 時，全螢幕模式不再於每次縮放或 Ctrl+L 都送出全螢幕清除，這可能是舊畫面塞滿捲動紀錄的原因。長篇項目符號或編號回覆在串流、縮放及 Ctrl+O 重開紀錄時，顯示更快。Ctrl+C 清掉的草稿，執行斜線指令或送出訊息後仍能按 Up 找回。/focus 提示會邀你在回合中試用聚焦檢視，並告訴你怎麼切回。

新功能

MCP 啟動等待與協定版本

串接 MCP（讓 AI 連接外部工具的協定）時，啟動不該卡在等待伺服器。

claude -p 與 SDK 工作階段首回合，不再等 HTTP／SSE 伺服器回應 resources/list。忽略新協定檢查的本機 stdio 伺服器，慢連一次後會被記住 7 天，之後改用舊方式連線、不用再等。本機 stdio MCP 連線在所有安裝環境，包括 Bedrock、Vertex、Foundry，預設協商協定版本 2026-07-28，設 MCP_PROTOCOL_NEGOTIATION=legacy 可退出。名稱超過 128 字元的 MCP 工具會被排除，並由錯誤訊息點名，不再讓每個請求都失敗。

新功能

代理設定、過載重試與可點連結

公司網路走代理伺服器時，有些位址本來就該直連。

HTTPS_PROXY 用來指定代理伺服器。設了它時，Claude Code 自身的 API 請求，包括登入、政策、意見回饋與產物，現在會遵守 NO_PROXY（不走代理的清單），以前會忽略它。新增環境變數 CLAUDE_CODE_OVERLOADED_RETRY_BASE_DELAY_MS，可延長遇到 529 過載時退避重試的基礎等待時間；退避重試就是失敗後拉長間隔再試。用量限制訊息裡的 claude.ai 設定連結改成帶 https:// 的寫法，終端機與應用程式能把它顯示成可點連結。

新功能

桌面應用程式與遠端操控協同

當你透過網頁遠端查看桌面版或 IDE（整合程式編輯與開發工具的環境）託管的工作階段時，背景子代理面板不再空白。

從 claude.ai/code 啟動新 Remote Control 遠端操控工作階段，第一則訊息現在和後續訊息一樣接受 PDF 及其他檔案，不再只能附圖片。跨工作階段的送達通知不再把名稱相似的兩個工作階段合成一個接收端；終端機工作階段讓訊息逾期時，逾期通知也不再錯怪桌面版。桌面版已有另一則訊息排隊時，按 Send now 不再結束當前回合正在等待的子代理。

中控室以前會把兩個相似櫃檯當成同一處，逾期還怪錯窗口；現在通知分清接收端，插送訊息也不再切斷正在等候的通話。
新功能

雲端工作階段狀態與背景任務恢復

把複雜任務交給雲端環境長時間運算時，重啟後哪些背景代理能接著做，需要說清楚。

工作單元恰在回合結束時停止，不再讓畫面顯示永遠未結束的回合；長對話也不再偶爾重問已核准的權限。Claude 正在讀取排程任務或其他佇列通知時，重試或編輯訊息不再使它們遺失。容器（承載工作階段的執行環境）重啟後，不再忘記你在用戶端選的思考設定；Claude 也會被告知哪些停止的背景代理可依 id 識別碼恢復。Anthropic 無法確認組織設定時，Cowork 雲端工作階段不再誤報代理伺服器阻擋產物。claude.ai 雲端工作階段無法連上 Claude in Chrome 瀏覽器擴充功能時，Claude 會收到說明：若使用者願意，可以繼續採用替代方式。

新功能

雲端例行工作與附件格式支援

讓例行工作自動產生私人檔案時，你不必每次都核准發布。

排程執行或按 Run now 立即執行，產出僅你可見的新產物都不再詢問核准；產物要求連接器（連接外部服務的工具）或其他存取權時仍會詢問。已完成的工作不再偶爾持續顯示執行中數小時。例行工作沒有已儲存的通知設定時，編輯或複製不再關掉推播通知。SVG、HEIC、TIFF 等較少見的圖片格式不再附加失敗，而會作為一般檔案附加。組織要求核准的連接器工具，不再提供原本無效的 "Always allow" 選項。

辦公室排程小幫手以前連私人草稿都要找你簽名，現在可以直接發布；要借用外部服務或其他權限，仍得先問你。
新功能

Claude Tag 團隊通訊與花費控制

團隊在 Slack 標記 @Claude 時，後續回覆不該等首個請求結束，或因相隔數秒而漏掉。

Enterprise 管理員可在頻道 Configure 頁的 Allowed domains 卡片按 Edit，開啟設定網域的存取組合。僅由 GitHub PR（提議合併分支改動的請求）活動或例行工作喚醒的討論串，改用管理員更新的頻道或工作區預設模型。組織額度耗盡不再誤報花費上限；Slack 無法回答的權限提示被自動拒絕後，工作階段不再卡住。@Claude !status 說明何時停止讀取未標記訊息、原因，以及再次標記會恢復讀取。!fork 延續討論串的首則卡片顯示來源、請求內容、提問者及原串連結。管理設定中花費上限頁的組織整體與預設欄位，按 Save 或 Enter 才儲存，點開別處不會儲存。

新功能

程式碼審查統計圖表與分支規則防護

評估團隊送審 PR（提議合併分支改動的請求）的工作成效或重構專案規範時，能看清各專案的審查數據，也不用擔心分支變更讓檢查失效。

審查圖表新增了當期審查總量、前期增減變化以及各儲存庫的明細分析；儲存庫是存放專案檔案與修改紀錄的地方。當 PR 切換目標分支且舊分支已刪除時，待審任務會自動重新排隊。若提交的改動剛好編輯了專案規則檔 CLAUDE.md，審查過程會堅持以目標分支上的既有規則為準。

就像品質檢驗站不僅能產出各產線的進度對比報表，在工件變更流水線時能自動重新排隊，檢驗標準也堅持採用母廠已核准的規範手冊。

English

FEATURE

Plugin Marketplace Installation and Source Verification

When you want to install plugins recommended by your team or maintained by third parties, command-line operations become cleaner and safer.

claude plugin install now supports the --marketplace <source> flag, where <source> is the marketplace source to install the plugin from. If the marketplace has not been added locally, it performs the same security policy checks, automatically adds it, and completes the installation directly. On initial startup, plugin commands wait until organization-managed policies are fully loaded before proceeding. If a configured marketplace name resembles an official source, the interface also provides clear identification guidance.

Like borrowing a specific collection from a library, the librarian verifies your library card according to regulations, registers the new catalog, and hands you the book directly without requiring two separate trips to the counter.
FEATURE

Subagent Thinking Depth and Execution Limits

When you assign background tasks to subagents for heavy workloads, you can allocate their effort and permissions more precisely.

The Agent tool adds an effort parameter, allowing you to specify the thinking depth invested by a subagent. Agent names are capped at 256 characters and rejected if they exceed this limit, while skill or plugin file name properties exceeding this length are ignored. If auto mode is disabled by configuration, triggers a circuit breaker (a safety mechanism that disables execution when protection thresholds are reached), or is unsupported by the model, subagents configured with permissionMode: auto will no longer enter auto mode. If the main conversation stops because the usage quota (the allowed usage ceiling) is exhausted, background agents encountering the same limit will not trigger repeated alerts one by one.

Think of a manager assigning assistants to research topics who can specify how deeply each should dig; once the budget is exhausted, assistants no longer knock on the door one after another with repeated warnings.
FEATURE

Plugin Feature Events and Testing Mechanisms

When customizing plugin modules, you can provide input suggestions and see clearly why tools were blocked.

The prompt.autocomplete event allows modules to contribute completion options to the input box. The prompt and system fields of $.model.complete accept text blocks; setting cache: true on a block caches (temporarily stores for reuse) requests up to that block. The agent.spawn hook (a small program triggered by events) adds workflow agents along with their run execution and index information, allowing modules to reject startup. Write, Edit, NotebookEdit, LSP rows, and single Read, Grep, and Glob rows now display why a module rejected the call. When running claude plugin test, failed expect checks inside test-registered hooks or an engine rejection of stub responses (substitute answers used for testing) will fail the test instead of passing silently.

BUGFIX

Plugin Interception Hooks and Permission Logic Fixes

When plugins intercept operations, failure reasons and confirmation prompts should not vanish.

When the hooks (small programs triggered by events) config.set, state.set, env.set, and agent.spawn reject after calling next(e), they now report the named hook failure; if they fail upon turn interruption after the call, the call is rejected. The /theme command, /config Theme menu, and initial theme setup now query config.set before saving. Approvals from tool.check no longer bypass question or plan approval prompts. Rejection reasons exceeding 4096 characters for dropped prompts or rejected settings are no longer ignored. tool.call now sees arguments with corrected parameter names. When another module's hook initiates a call under a guarded $ invocation, the guard's .catch handler is now consulted. The <system-reminder> tag output by hooks is now escaped so Claude receives it as plain text.

BUGFIX

Plugin Module Loading Performance and Worker Process Fixes

When loading complex plugins or restarting background worker units, you might have experienced multi-minute delays or duplicated startup jobs.

Hook modules making frequent $.state calls through the same const binding no longer slow down loading and validation. claude plugin validate no longer outputs matchers or state values read elsewhere by the engine; reading state through top-level var declarations is now rejected if the variable is re-declared or reassigned. Plugin-provided $ methods no longer restart the hook source, which previously caused guarded hook .catch handlers to rerun infinitely. When replacing hook (a small program triggered by events) worker units, startup prompts, commands, or subagents are no longer queued redundantly. After an organization plugin reloads or another plugin crashes, returning a $ method name already added by a personal module now unloads the personal module instead. During restarts, plugin interface calls still pass through hooks added by other plugins, and tool calls still pass through permission hooks.

FEATURE

Sandbox Isolation Mechanisms and Sensitive Path Protection

When running commands in a sandbox (an environment with restricted access), you can no longer read the /ultrareview upload copy in ~/.claude/seed-admin.

If managed or co-located user read-restricted paths appear or are repointed mid-session, internal project authorizations are revoked, and credential (proof of authentication) injection for covered files is stopped. Reading notebooks or PDFs on macOS and Windows no longer accesses unapproved files due to mid-operation symlink swapping. When fetching configuration fails, tampered cache (temporary storage) cannot disable or replace built-in policy plugins. The 8.3 short names and other alternate Windows spellings of home directories or drives are now recognized as deletion targets for rm -rf. PreToolUse hook approvals and auto mode no longer bypass permission prompts for reading UNC network files. After enabling strict sandbox mode in user settings, managed settings, or settings specified via --settings, interpreter commands prefixed with environment variables (runtime configuration values passed to programs), such as FOO=bar python3 app.py, no longer trigger confirmation prompts.

BUGFIX

Session Resumption and Background Scheduling Fixes

When you reopen a previous conversation to resume work or leave loop commands running in the background, restored modes and schedules should not silently break.

Returning to a session from the claude --resume menu or /resume correctly restores plan mode. Schedules created and saved after /resume, /branch, or /clear no longer fail to trigger permanently; task files written twice within milliseconds no longer ignore subsequent additions and deletions. One-shot claude -p and the Agent SDK (a toolkit allowing programs to invoke agents) no longer terminate background commands 5 seconds after the final result, waiting for them instead; only one-shot claude -p additionally fixes missed scheduled wakeups and waits for wakeups. After a background session process restarts, /loop no longer silently halts due to lost wakeups.

Picture a smart bookmark that previously forgot reminders upon reopening; it now preserves your reading mode and no longer leaves pending timers behind on the previous page.
FEATURE

File Reading, Search Retries, and Large Attachment Handling

When you ask Claude to search code, browse documents, or reference files in prompts, responses from various reading tools are much clearer.

When Grep and Glob encounter unreadable files or directories, they no longer falsely report no results; Claude retries once or notifies you. Mentioning text files exceeding 256KB with @ is no longer silently ignored, as Claude receives the file size alongside instructions to read in chunks. When Read parses PDFs, specifying discrete page lists such as "6,9,15" for pages no longer returns only the first page, but errors and requests reading page-by-page or by range. When Read deny rules are configured and the working directory is under a symlink (a shortcut pointing to another location), @ references to nonexistent files no longer erroneously display "could not be examined". Grep accepts file_path in place of path; Write, WebFetch, and Read ignore a few extra parameters rather than failing the call.

FEATURE

Prompt Commands and Operation Permission Management

When switching operation modes, changing directories, or managing existing outputs during a conversation, stale records should not suddenly revive tool restrictions.

After leaving auto mode or plan mode mid-session, allowed-tools rules from skills or slash commands no longer resurface in subsequent turns. Following /cd or permission changes, records for unloaded instruction files like "instruction file not loaded" are no longer outdated or missing; unread nested instruction files also leave conversation logs. Repeating /name in conversation compaction summaries no longer allows Claude to invoke user-reserved skills. The Artifact tool now allows Claude to see the total number of published artifacts and list up to 200 items at once, raised from 50 items.

A dispatch center reviewing old logs might previously have pressed manual-only buttons by mistake; now old summaries no longer permit those actions, and registries can display more items.
BUGFIX

Terminal Input, Paste, and Vim Operation Fixes

When typing quickly in the terminal, using Chinese input methods, or editing prompts in Vim mode, you might have experienced dropped characters or misinterpreted keystrokes.

Overlapping multiple paste actions in the same prompt no longer treats portions of pasted content as literal keystrokes. When the bottom bar is selected, fast input, IME text, and decomposed accented characters are no longer lost; ! also no longer preserves the selection state. The Vim (a mode for editing text using key commands) cursor no longer moves past the end of the line, and j/k motions retain their column across shorter lines; f, t, F, T, ;, and , no longer jump to matches on other lines or delete up to them. The /add-dir path box no longer allows Shift+Enter or pasted content to insert newlines, nor does it misinterpret quickly typed "tab", "up", or "down" as key events.

A keyboard receptionist who previously confused text strings for keystrokes and paste events for typing now distinguishes these inputs accurately.
FEATURE

Terminal Display Rendering and Interactive Operation Improvements

When browsing long responses or retrieving drafts, screens and menus should not force you to redo actions.

Pressing Ctrl+O or Ctrl+Z while submitting /bug, /share, or /feedback <text> no longer restarts them, nor do they close in a cancelled state after submission. Opening /remote-env selects the saved default environment, and pressing Enter directly no longer changes it; when no default is active, no rows are checked. When iTerm2 is detected, fullscreen mode no longer sends a fullscreen clear on every resize or Ctrl+L, which may have caused old screens to fill the scrollback history. Long bulleted or numbered responses render faster during streaming, resizing, and reopening history with Ctrl+O. Drafts cleared with Ctrl+C can still be retrieved by pressing Up after running a slash command or sending a message. The /focus prompt invites you to try focus view during a turn and explains how to switch back.

FEATURE

MCP Startup Wait Times and Protocol Versions

When connecting through MCP (a protocol that lets AI connect to external tools), startup should not get stuck waiting for servers.

The first turn of claude -p and SDK sessions no longer waits for HTTP/SSE servers to respond to resources/list. Local stdio servers that ignore new protocol checks are remembered for 7 days after one slow connection, subsequently connecting via the legacy method without further waiting. Local stdio MCP connections across all installation environments, including Bedrock, Vertex, and Foundry, negotiate protocol version 2026-07-28 by default, with MCP_PROTOCOL_NEGOTIATION=legacy available to opt out. MCP tools with names exceeding 128 characters are excluded and named in error messages, rather than failing every request.

FEATURE

When corporate networks route through a proxy server, certain addresses should connect directly.

HTTPS_PROXY specifies the proxy server. When configured, Claude Code's own API requests—including login, policy, feedback, and artifacts—now respect NO_PROXY (the proxy bypass list), which was previously ignored. A new environment variable, CLAUDE_CODE_OVERLOADED_RETRY_BASE_DELAY_MS, extends the base wait time for backoff retries when encountering 529 overloads, where retries wait for longer intervals after failures. Links to claude.ai settings within usage limit messages now include https://, allowing terminals and applications to render them as clickable links.

Desktop App and Remote Control Collaboration

When viewing sessions hosted on the desktop app or IDE (an environment combining code editing and development tools) remotely via web, the background subagent panel is no longer blank.

Cross-session delivery notifications no longer merge two sessions with similar names into a single recipient, and overdue notifications no longer blame the desktop app when a terminal session allows messages to expire. When another message is already queued in the desktop app, clicking Send now no longer terminates the subagent that the current turn is waiting for.

Imagine a central control room that previously merged two similar counters into one location and blamed the wrong desk for overdue items; notifications now separate recipients cleanly, and expediting a message no longer cuts off awaiting calls.

When delegating complex tasks to cloud environments for long-running computation, clarity is needed on which background agents can resume after a restart.

Work units stopping exactly at turn completion no longer leave the interface displaying an endless turn, and long conversations no longer occasionally re-prompt for approved permissions. When Claude is reading scheduled tasks or other queued notifications, retrying or editing messages no longer loses them. An office routine assistant previously required your signature even for private drafts but can now publish them directly, while borrowing external services or other permissions still requires asking first.

When evaluating team PR review performance or refactoring project conventions, review metrics across projects are clear without concern that branch changes will invalidate checks.

When a PR switches target branches and the old branch has been deleted, pending review tasks automatically re-queue. Consider a quality inspection station that not only produces progress comparison reports across production lines and automatically re-queues workpieces when lines change, but also strictly enforces the specification manual already approved by headquarters.
