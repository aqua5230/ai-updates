Claude Code 2.1.290

Released: 2026-10-05

Release notes

FEATURE

Plugin Hooks Support Server-Side Tool Logs and Organizational Approval Caps

When writing custom extensions for Claude, plugin hooks can now access more complete contextual information.

During execution steps, modules receive timestamps and the list of tools invoked by the API itself. Permission check events now include an agent identifier to distinguish between the main session and subagents. Maximum approval thresholds set by enterprise organizations are now factored directly into evaluations. The editor has also filled in theme color types.

Think of an inspector equipped with a detailed logbook and standard color swatches, making it clear who initiated each action and where approval limits lie.

When validating with claude plugin validate, you can also see whether error-handling logic is configured for each hook.

BUGFIX

User Modules No Longer Displace Enterprise Plugins, and Tool Rewrites Retain Security Checks

When installing personal extensions in a corporate environment, system security safeguards are now more rigorous.

Previously, module conflicts could accidentally unload officially provisioned enterprise plugins and cause security defenses to bypass checks; the system now unloads the conflicting user module first. Even if hooks rewrite input content before tool execution, existing permission rules and security checks still guard the process strictly.

Picture security guards confiscating a visitor's conflicting access card rather than letting the building's intrusion alarms fail.
BUGFIX

Extension Panels No Longer Loop Rerenders, and Multiline Non-Latin Text Renders Smoothly

When viewing custom panels or inline blocks rendered by extensions in the terminal, the screen will no longer rerender continuously.

Previously, if a module panel's tree structure changed height on every draw, the display fell into infinite rerenders; this issue has been resolved so infinite redraw loops no longer occur. If a module outputs long multiline non-Latin text such as Chinese characters, plugin hooks no longer stall during each rerender.

A stage crew used to lower the curtain repeatedly over minor prop tweaks, but now scene transitions happen seamlessly in one go.
BUGFIX

Plugin Hook Lifecycles Gain Stability, While Model Fallbacks and Reloads Preserve State

When developing complex plugins, state passing and exception handling across various hooks are much steadier.

Previously, hooks with error catching could be unloaded by mistake under heavy load, and tool calls discarded by model fallbacks no longer linger in logs. When subagents deliver reports in auto mode, completion events no longer read empty content. Failed reloads now clearly indicate that the previous version has been unloaded. Prompt interception and teardown hooks with spaced paths also no longer trigger silent ignores or infinite loops.

FEATURE

Plugin Validation Relaxes Destructuring Syntax, and Module Publishing Guidance Is Clearer

When building or testing your own extensions, toolchain compatibility and guidance are more thoughtful.

Previously, using claude plugin validate or loading modules rejected destructuring assignment variables sharing names with top-level functions, but they now parse correctly. Running claude plugin test after an upgrade also avoids getting stuck on legacy configurations. The built-in plugin authoring skill now proactively provides install commands and writes them to documentation. When receiving the /plugin command, the desktop app's code tab clearly guides you to the right place to manage plugins.

FEATURE

Module Subprocess Rejection Messages Are More Precise, and Oversized Text Is Truncated and Logged

Extensions provide more specific messages when calling external programs or passing large amounts of data.

When a subprocess spawned by one module is intercepted and rejected by another, the system clearly explains that the subprocess ran but its output was withheld. When hooks pass oversized text, the system now automatically truncates and logs it rather than rejecting it outright or silently discarding it. Running update commands on plugins loaded from local directories also prints the exact reason directly, without extraneous failure prefixes.

FEATURE

Enterprise Gateway Login Adds Reject Button, Supporting Dark Mode and Custom Auth

When logging in through an enterprise application gateway, authorization interfaces and permission controls are much friendlier.

A new reject button on the browser approval page terminates the connection immediately, so the terminal no longer has to wait out timeouts. The login page also adopts brand typography, a centered layout, and dark mode support. For users connecting via gateway URLs and keys without direct Anthropic accounts, extensions can now be enabled normally.

Imagine a visitor desk adding a direct turn-away button alongside clean, eye-friendly lighting across the counter.
FEATURE

Enterprise Gateway Supports Older Databases with Improved Identity Tokens and Expiry Warnings

When maintaining internal enterprise gateway servers, system compatibility and debugging diagnostics are more thorough.

The minimum supported PostgreSQL database version has been lowered from 14 to 11, and legacy databases no longer accidentally purge freshly refreshed developer identities when cleaning expired records. Servers with empty certificate subjects can now boot normally, and the system actively logs warnings 30 days before certificates expire. If a database connection URL is malformed, the system highlights the configuration key and the correct format, while also appending the root cause to log ends when upstream cloud credentials fail.

FEATURE

Managed Settings Warn on Outbound Links, Guarding Symlinks from Bypassing Security Boundaries

When distributing unified configuration files across enterprise environments, the system effectively prevents configs from being maliciously redirected to external locations.

If a managed settings file uses a symlink outside its dedicated directory, the system immediately issues a warning. Health checks will also alert you if managed settings ignore user-configured sandbox read paths or domains. Project rule files linked outside the working directory no longer bypass restrictions on out-of-directory reads. Model Context Protocol (MCP) server rules can also be fully applied.

FEATURE

Project Settings Cannot Disable Attachments, and Slow Disk Launch Stalls Are Resolved

In shared team repositories, local configuration files for individual projects can no longer disable attachment functionality on their own.

The CLAUDE_CODE_DISABLE_ATTACHMENTS toggle can now only be controlled by global user settings or enterprise managed settings, preventing individual projects from overriding security policies. In environments connected through an enterprise gateway, background commands and daemon services no longer unintentionally send telemetry data externally. On slower file systems such as Windows and WSL, startup lag and launch failures caused by read restriction rules have also been resolved.

FEATURE

Quickly Scaffold Managed Agents, Samples Disable Non-Essential Web Tools by Default

When you want to set up an automated agent architecture quickly, the new onboarding command saves you tedious configuration steps.

Entering /claude-api managed-agents-onboard <url> or specifying a Console quickstart template name directly generates configuration files and applies them via command-line tools. Official samples also update permission policies, disabling web search tools by default to reduce risk unless an agent explicitly requires them.

A preassembled toolbox arrives with only essential switches enabled, ready to be expanded as needed.
FEATURE

Connect to Sessions by Name Directly, Session Restarts Stop Resending Old Messages

Managing conversations running in the background is now more intuitive and responsive.

When using claude attach <name> or claude logs <name>, you can connect by entering part of a session name directly, without copying lengthy IDs. When you choose to restart a session from scratch, the system opens a blank conversation instead of accidentally resending old messages. Idle conversations moved to the background fully restore their history upon restarting, and loading large conversations no longer freezes input or rendering.

FEATURE

Rewind Menu Eliminates Keypress Lag, Rapid Left Arrow Navigation Becomes Smoother

When you want to revert or rewind previously sent prompts, interface interactions feel much smoother.

Previously, if long code snippets or stack traces had been pasted into the conversation, pressing Esc twice or running /rewind to open the rewind menu caused several hundred milliseconds of keypress lag, but the menu now opens without delay. Prompts submitted while Claude is processing are also correctly listed. After clearing the input box, double-tapping the left arrow key to switch sessions no longer requires deliberate pauses, and holding down the arrow key switches sessions directly.

BUGFIX

Agent List Fixes Accidental Deletions, Permission Prompts Add Stop-All Shortcut

When switching between tasks in the claude agents overview window, keyboard navigation is no longer prone to accidental deletions.

Previously, pressing Esc after searching or pressing Ctrl+X repeatedly could shift focus to section headers and accidentally delete entire sessions; now Esc only reopens a session and never mistakenly confirms restart prompts. When background agents trigger permission requests, the screen clearly indicates that the Ctrl+X Ctrl+K shortcut can stop all background agents at once.

FEATURE

Agent View Adjusts Model and Effort Instantly, Restarts Stop Replaying Old Commands

Adjusting parameters while controlling busy background sessions from the agent overview interface now takes effect immediately.

Sending /model, /effort, or /rename commands applies new settings on the spot without waiting for the current turn to finish or requiring manual confirmation. Slash commands or multiple-choice answers that previously failed to reach a stopped session are no longer automatically executed upon restarting. If a background session crashes and restarts, sent replies automatically retry for up to 12 seconds to ensure delivery.

BUGFIX

Agent Status Line Fixes Worktree Tracking, Services Persist After Package Upgrades

Status monitoring and environment upgrades are more reliable when running multiple background agents.

Previously, when a background session was created and switched to a worktree, the overview interface lost run counts and countdown timers; status line information now stays synchronized continuously. Running /clear resets and recalculates the count. Pasting images in manual permission mode no longer repeatedly prompts for read confirmation. An issue where upgrading via Homebrew displayed "Couldn't restart the background service" and halted background sessions has been fixed, though this fix takes effect starting with the subsequent upgrade.

FEATURE

Recurring Scheduled Tasks Persist After Compaction, Container Restarts Trigger Rescheduling

Scheduled wakeup mechanisms are more reliable when setting up periodic schedules for Claude, such as using /loop to check progress at intervals.

Previously, scheduled tasks silently disappeared when a conversation resumed after compaction; this is now prevented, though it applies only to compactions performed from this version onward. Foreground schedules handed off via ← or /background previously never fired, but now trigger properly; recurring schedules previously ran an extra turn during resume, respawn, or fork, but no longer do. If cloud sessions lose schedules due to container restarts, Claude is notified and can reschedule them. Background sessions whose schedules disappear transition to a completed state after about 20 seconds.

FEATURE

Subagents Resume Cleanly After System Sleep, Cross-Worktree Switching Retains Write Access

Permission isolation and compute states are more stable when multiple subagents collaborate in the background.

Previously, when the main session switched to a different worktree, background subagents unexpectedly lost write and Bash execution permissions for their own directories; independent access is now maintained. When a Mac wakes from sleep, background agents no longer stall or crash with errors. Subagents and teammates receiving mid-execution messages no longer lose prior reasoning chains or caches. Teammate agent IDs are also clearer, and idle subagents no longer mistakenly trigger teammate hooks.

FEATURE

Daemon Logs Escape Control Characters Safely, Restarts Verify Skip-Permissions Disclaimers

Terminal displays are no longer disrupted by special control characters when viewing daemon logs.

In logs output by claude daemon run and claude daemon logs, control characters are now safely escaped as \uXXXX encodings, and multiline messages are consolidated into single-line JSON formatting for programmatic parsing. When background worker units restart without explicitly accepting the disclaimer, the --allow-dangerously-skip-permissions flag is never automatically applied, ensuring safe operational permissions.

BUGFIX

Command Permission Checks Plug Gaps: Variable Prefixes, Wildcards, Pyright, and ps Prompt First

Several gaps in permission checks during terminal command execution have been resolved.

Previously, when variables were defined with prefixes like declare or export and then used to construct commands or paths, deny or prompt rules could miss them; they are now matched correctly. If arguments for read-only commands like rg or git grep expand into wildcards via the shell, they are now prompted instead of directly allowed; the same applies to variable names interpreted differently between zsh and bash. Wildcards in certain option values of read-only commands also now enforce read denial rules and out-of-directory read blocks. pyright is no longer treated as read-only, and additional ps command variations now require confirmation.

BUGFIX

Multiline pipeline input auto-approved in sandbox, large directory scans no longer freeze

Running scripts inside the sandbox isolated environment is smoother and more efficient.

Piping multiline text into other commands (such as cat <<EOF | python3) previously triggered repeated confirmation prompts every time, but the sandbox auto-approval mechanism now recognizes it properly. Short flags for git clone now correctly apply exemption rules just like long flags. On Linux and WSL, sandbox read rules that cover massive directories will no longer freeze the /sandbox configuration page. Monitoring tool commands also faithfully respect user permission settings.

BUGFIX

Plan mode strictly guards write tools, restricted mode closes cross-session communication

Safeguards for sensitive operations are tighter when you enable security restrictions or Plan mode.

Previously under Plan mode, the automatic classifier could mistakenly allow non-read-only connector tools that carried an ask policy, but such requests are now intercepted. Under restricted mode (--restricted), the system no longer opens cross-session sockets. When authorizing via relay channels, duplicate reply identifiers within the same session are automatically ignored to prevent mistakenly approving different prompts. Modifying the target file behind a configuration symlink will now also reliably trigger a permission confirmation prompt.

BUGFIX

Guard against mid-read symlink swapping, pasted images strictly apply deny rules

Path security is more comprehensive when mentioning files or dragging images into prompts.

Previously on macOS and Windows when reading images, if a link was swapped mid-read, it could access files outside the approved scope. Mentioning files with @ also risked letting Claude read files outside the working directory if a symlink was swapped during reading. This issue is now fixed, and links swapped mid-read will no longer let Claude access files outside the approved scope. Dragged or pasted image paths and filenames within mentioned folders now strictly apply read deny rules. Mentioning files in subdirectories also properly includes the AGENTS.md configuration file located in that directory.

BUGFIX

Sensitive key scanning no longer hangs, multiline filenames render cleanly in prompts

The terminal no longer abruptly freezes when conversations and operations involve extremely long strings or sensitive keys.

Previously, when sensitive data scanning and redaction encountered very long continuous text or key-like token strings, authorization dialogs caused the terminal UI to freeze for several seconds. That freeze issue is now resolved, allowing scanning and prompts to proceed smoothly. If a processed filename contains newline characters, formatting that previously broke in file tool errors and permission prompts now renders correctly and displays the full filename.

BUGFIX

Code deep review supports special Git setups, uncommitted changes upload safely

Packaging code across edge-case environments is safer when requesting an in-depth review of your current workspace with /ultrareview.

Previously on Windows, a stash failure could silently discard uncommitted changes, while enabling newline safety checks or using modern Git versions where branches reside outside the directory could cause upload failures or missed edits. These scenarios are now handled properly. If a git filter driver happens to be named unset or unspecified, the upload aborts and asks you to rename it to prevent uploading unfiltered files.

FEATURE

Remote review errors streamlined, merge and pull list modified files

Error messages are clearer and more approachable when running into issues during code synchronization or remote review.

When Git steps fail, instead of dumping raw error logs, message lengths are cut in half to directly highlight the failed step along with specific troubleshooting suggestions. Chained operations like merge or pull now present changed files in a concise list. When migrating with /teleport, directory name collisions are explicitly rejected with explanatory reasons to prevent file loss.

FEATURE

Plan mode preserves state across resume, skills discovered despite folder name mismatch

Resuming interrupted sessions is more reliable when architecting in Plan mode inside the terminal.

Unrendered plans are no longer lost before cloud session containers restart, and resuming a session with --continue or --resume <session-id> properly restores Plan mode. Custom skill commands saved with CRLF line endings on Windows now execute normally. When a skill folder name differs from the name inside SKILL.md (such as a non-English name), the skill is still discoverable by the name in SKILL.md, and listings display both names. Any ! command containing raw control characters other than tabs and newlines will be rejected with its location indicated.

FEATURE

Corporate proxy compatibility improved, long conversations stream in real time

Request transmission is more reliable when connecting through enterprise proxy servers.

Connections that previously dropped when a proxy rejected specific test headers now tolerate non-standard status codes. Custom endpoints defined in project settings also take effect on the initial request. In very long remote-control or cloud sessions, responses stream token-by-token in real time rather than popping up in delayed blocks. Disconnections after streaming structured output in headless mode no longer report false error statuses. Streaming interruptions after waking a computer from sleep are also resolved.

BUGFIX

Hundreds of images handled smoothly in long chats, thinking interruptions auto-retried once

Long, complex analysis can now carry much larger amounts of multimodal data.

Sessions with hundreds of accumulated images that previously broke with "failed to process" errors now parse reliably. If Claude's response during extended thinking is unexpectedly cut off by a content filter, the system automatically retries once before reporting an error. Switching to a fallback model no longer accidentally overrides or resets thinking effort settings. When using the SDK with --include-partial-messages, turn-complete signals are accurately received even if streaming is interrupted.

FEATURE

Large external tool responses no longer exhaust memory, proxy blocks skipped immediately

Resource management is more resilient when connecting to external extension services via MCP.

Memory no longer grows unbounded when an HTTP MCP server returns massive responses; this issue is now fixed. Listing parsing no longer hangs when external tool names contain numerous combining characters. In proxied environments, if a server is blocked with HTTP 403, the system skips it immediately instead of repeatedly retrying three times. Enterprise-provisioned tools are also no longer mislabeled as personal tools after re-authenticating or reconnecting.

FEATURE

Web Fetch Supports Resuming Past 100,000 Characters, Search Quotas Refill Hourly

When asking Claude to read long web pages or search for up-to-date information in interactive sessions, data retrieval is no longer bounded by a single-turn limit.

Previously, reading web pages over 100,000 characters silently truncated anything beyond that limit. Now, the system explicitly reports unread length and accepts an offset parameter to resume reading. Web search call limits are no longer fixed at 200 total uses; instead, 100 quota units are automatically refilled every hour. Allowlist rule matching for internationalized domain names is also more consistent.

BUGFIX

Multi-Chunk Pastes Merge Seamlessly, Thousands of Nested Blockquotes No Longer Crash

Pasting large volumes of data or multiple chunks of content into the input box now offers a smoother editing experience.

Previously, pasting text in rapid succession or filenames with special accented characters could misidentify parts of the content as manual keystroke input; this is now fixed to paste as a single cohesive block. Terminals no longer freeze even when sending extremely long messages. Pressing Ctrl+O to expand large conversation histories containing non-ASCII symbols like arrows and lines no longer lags. Even when responses contain thousands of layers of nested lists or blockquotes, they no longer trigger stack overflows that crash the application.

BUGFIX

Conversation Compaction Resumes After Sleep, Key Notes Honor Language Settings

When long conversations accumulate excessive content, the background compaction mechanism runs more smoothly.

Previously, if a Mac computer went to sleep during background compaction, waking it up often failed with a "prompt too long" error that caused it to give up entirely. Now, it reliably resumes and finishes the compaction job after wake-up. Empty-object errors no longer occur intermittently during compaction. The "You should know" notes callout on screen, which highlights key context, now faithfully follows your configured language preference instead of forcing English.

BUGFIX

Login Credentials Sync Accurately, Suffix-Timed Values Fall Back to Defaults

Setting CLAUDE_CODE_USER_DIALOG_TIMEOUT_MS=5m was previously parsed as 5 milliseconds; values with unit suffixes like m are no longer treated as milliseconds and now fall back to the default dialogExpiry.
