Claude Code 2.1.290

發布日期：2026-10-05

繁體中文

新功能

外掛掛鉤支援伺服器端工具記錄與組織審批上限

你在替 Claude 編寫自訂擴充模組時，外掛掛鉤（hook，特定事件發生時被觸發的小程式）現在能讀取更完整的背景資訊。

模組執行步驟時會收到 API 自身調用的工具清單與時間戳記。權限檢查事件也新增了代理識別碼，方便區分主工作階段與子代理。企業組織規定的最高審批門檻現在會直接帶入判定。編輯器也補齊了主題色彩型別。

如同巡檢人員配備了詳盡的登記簿與標準色卡，每項操作由誰發起、核准上限到哪裡都能一目了然。

使用 claude plugin validate 驗證時，還能列出各掛鉤是否已設置錯誤捕捉處理。

問題修復

使用者模組不再擠掉企業外掛，工具改寫守住安全檢查

當你在公司環境中安裝個人擴充模組時，系統安全防線變得更嚴謹。

以前個別模組發生衝突時，可能會意外卸載組織配發的官方外掛，甚至導致企業安全防護跳過檢查；現在系統會優先卸載引發衝突的使用者模組。即便掛鉤在工具執行前改寫了輸入內容，既有的權限規則與安全檢查依然會嚴格把關。

彷彿訪客自備的門禁卡若與大樓系統衝突，警衛會暫扣該張臨時卡，絕不讓大樓本身的防盜警報失效。
問題修復

擴充模組面板不再無限重繪，多行非拉丁文字渲染順暢

在終端機中查看擴充模組渲染的自訂面板或行內區塊時，畫面不會再一直重繪。

以前若模組面板的樹狀結構每次繪製高度都在改變，畫面會陷入無止境的重繪；這個問題已經修好，不會再無止境重繪。如果模組輸出了包含中文等多行非拉丁字元的長文字，外掛掛鉤（hook，特定事件發生時被觸發的小程式）在每次重繪時也不再停頓。

走進劇場看舞台換幕，以前只是道具高度微調，布幕就被反覆拉下重來；現在換幕一次就到位。
問題修復

外掛掛鉤生命週期更穩定，模型備援與重載不再丟失狀態

開發複雜外掛時，各類掛鉤的狀態傳遞與異常處理更加穩健。

以前帶有錯誤捕獲的掛鉤在忙碌時可能被誤卸載，模型備援（fallback，主模型異常時自動切換到替代模型）捨棄的工具調用也不會再殘留在記錄中。子代理在自動模式交付報告時，完成事件不再讀取到空內容。重新載入失敗後會清楚標示舊版已卸載。提示詞攔截與含空格路徑的結束掛鉤也不會再造成無聲忽略或無限循環。

新功能

外掛驗證解構語法放寬，模組發布指引更清晰

當你建立或測試自己的擴充套件時，工具鏈的相容性與提示更加周到。

以前使用 claude plugin validate 或載入模組時，若解構賦值變數與頂層函式同名會遭到拒絕，現在已能正常解析。升級後執行 claude plugin test 也不會因舊設定而卡住。內建的外掛編寫技能現在會主動提供安裝指令並寫入說明文件。桌面版應用程式的程式碼分頁在收到 /plugin 指令時，也會明確引導你到正確位置管理外掛。

新功能

模組子行程拒絕訊息更精確，超長文字自動截斷記錄

擴充模組在呼叫外部程式或傳遞大量資料時，回報的訊息更具體。

當一個模組產生的子行程（subprocess，由主程式啟動的獨立外部程式）被另一個模組攔截拒絕時，系統會清楚告知子行程曾執行但結果被扣留。掛鉤傳遞超長文字時，現在會自動裁切並記錄日誌，不再直接拒絕或無聲丟棄。針對本機目錄載入的外掛執行更新指令時，也會直接印出具體原因，不再加上多餘的失敗前綴詞。

新功能

企業閘道器登入新增拒絕按鈕，支援深色模式與自訂認證

透過企業應用程式閘道器登入時，授權介面與權限控制更加友善。

瀏覽器審批頁面新增了拒絕按鈕，按下後能立即結束連線，終端機不必再乾等逾時。登入頁面也換上品牌字體、置中版面並支援深色模式。針對透過閘道器網址與金鑰連線、沒有直接 Anthropic 帳號的使用者，擴充模組現在也能正常啟用。

彷彿訪客登記處增設了直接退件按鈕，同時櫃檯換上了清爽護眼的燈光。
新功能

企業閘道器支援舊版資料庫，身分憑證與過期警示更完善

維運企業內部閘道器伺服器時，系統相容性與除錯診斷更加完整。

閘道器支援的 PostgreSQL 資料庫最低版本從 14 放寬至 11，舊版資料庫在清理過期記錄時不再誤刪剛刷新的開發者身分。伺服器憑證主體為空時能正常啟動，憑證到期前 30 天會主動在日誌發出警告。若資料庫連線網址格式錯誤，系統會明確指出設定鍵與正確格式，上游雲端憑證失效時也會在日誌結尾標註根本原因。

新功能

託管設定外連警告，嚴防符號連結繞過安全邊界

在企業環境中分發統一設定檔時，系統能有效防止設定檔被惡意導向外部位置。

當託管設定檔使用符號連結（symlink，指向另一個位置的捷徑檔）連到專屬目錄外時，系統會立即發出警示。若託管設定忽略了使用者配置的沙盒讀取路徑或網域，狀態檢查也會提醒。專案規則檔若捷徑連至工作目錄外，不再繞過目錄外讀取封鎖。MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器規則也能完整套用。

新功能

專案設定禁止停用附件，慢速硬碟啟動不再卡頓

在團隊共用儲存庫中，個別專案的本機設定檔不再能私自關閉附件功能。

CLAUDE_CODE_DISABLE_ATTACHMENTS 開關現在只能由使用者全域設定或企業託管設定控制，避免個別專案覆寫安全政策。在透過企業閘道器連線的環境中，背景指令與常駐服務不再意外向外部傳送遙測數據。而在 Windows 與 WSL 等慢速檔案系統上，讀取限制規則引發的啟動緩慢與失敗問題也已獲得解決。

新功能

快速建立託管代理架構，範例預設關閉非必要網路工具

你想快速搭建自動化代理架構時，新增的引導指令能幫你省下繁瑣的設定步驟。

輸入 /claude-api managed-agents-onboard <網址> 或指定主控台（Console）快速入門範本名稱，就能直接生成設定檔並透過命令列工具套用。官方範例中也更新了權限策略，除非代理明確需要，否則預設會關閉網路搜尋工具以降低風險。

拿到預先組裝好的工具箱，預設只開啟必備開關，需要時再自行擴充。
問題修復

工作階段可用名稱直接連線，重啟對話不再誤發舊訊息

管理背景執行的對話時，操作變得更直覺且反應更靈敏。

現在使用 claude attach <名稱> 或 claude logs <名稱> 時，直接輸入工作階段（session，工作階段）名稱的一部分就能連線，不必再複製落落長的識別碼。當你選擇全新重啟工作階段時，系統會開啟空白對話，不再誤發舊訊息。閒置移至背景的對話重啟後能完整恢復記錄，載入大型對話時輸入與畫面也不再凍結。

新功能

倒帶選單告別按鍵卡頓，連按向左鍵切換更順暢

當你想要撤回或倒帶剛才發送的指令時，介面操作變得極為流暢。

以前對話中若貼上過超長程式碼或除錯追蹤記錄，按兩下 Esc 或輸入 /rewind 開啟倒帶選單時，每次按鍵都會卡頓數百毫秒；現在選單已不會延遲。在 Claude 處理過程中送出的提示詞也會正確列出。在清空輸入框後按兩下向左方向鍵切換工作階段時，不必再刻意等待間隔，長按方向鍵也能直接切換。

問題修復

代理清單修正按鍵誤刪，授權提示新增全部停止快捷鍵

在 claude agents 代理總覽視窗中切換各項任務時，鍵盤操作不再容易引發意外誤刪。

以前在搜尋後按下 Esc 或重複按 Ctrl+X，焦點可能會跳到區塊標題並意外刪除整組工作階段；現在 Esc 鍵只會重新開啟工作階段，絕不會誤確認重啟提示。背景代理跳出授權請求時，畫面上會明確提示可使用 Ctrl+X Ctrl+K 快捷鍵一次停止所有背景代理。

新功能

代理檢視即時調整模型與力度，重啟不再自動補發舊指令

當你從代理總覽介面控制正在忙碌的背景工作階段時，參數調整會立即生效。

現在發送 /model、/effort 或 /rename 指令不必等待當前輪次結束或手動確認，系統會當場套用新設定。以前未能成功送達停止工作階段的斜線指令或選擇題答案，重啟時不再自動擅自執行。若背景工作階段剛好崩潰重啟，發送的回覆也會自動重試最多 12 秒以確保送達。

問題修復

代理狀態列工作樹追蹤修復，套件升級後服務正常延續

在背景運行多個代理時，狀態監控與環境升級更可靠。

以前背景工作階段在建立並切換至工作樹（worktree，Git 讓同一專案平行開多份副本的功能）後，總覽介面會遺失執行計數與倒數計時；現在狀態列資訊會持續同步。執行 /clear 清除對話後計數會重新計算。手動授權模式下貼入圖片不再重複跳出讀取確認。透過 Homebrew 升級後出現「Couldn't restart the background service」、背景工作階段停止的問題也已修好，但這個修正要等再下一次升級才會生效。

新功能

定時循環任務對話壓縮後不丟失，容器重啟自動重新排程

你為 Claude 設定定期排程（例如使用 /loop 隔段時間自動檢查進度）時，定時甦醒機制更為可靠。

以前對話壓縮後再恢復，排程任務會無聲消失；現在不會，但只涵蓋這個版本起做的壓縮。前景排程在按 ← 或 /background 交接後，以前永遠不會觸發，現在會觸發；循環排程在 resume、respawn、fork 時以前會多跑一次，現在不會。若雲端工作階段因容器重啟導致排程遺失，Claude 會被告知並可重新排程。排程消失的背景工作階段約 20 秒後會轉為完成狀態。

新功能

子代理休眠喚醒不卡住，跨工作樹切換保持寫入權限

多個子代理在背景協同工作時，權限隔離與運算狀態更加穩定。

以前主工作階段切換至不同工作樹時，背景子代理會意外失去自己目錄的寫入與 Bash 執行權限；現在已能維持獨立存取。當 Mac 電腦從睡眠中喚醒時，背景代理不再因停滯而報錯中斷。執行途中收到訊息的子代理與隊友，不會再遺失先前的思考過程與快取（cache，把算過／查過的結果暫存起來直接用）。團隊成員的代理識別碼也更加清晰，子代理閒置時不再誤觸發隊友掛鉤。

新功能

背景常駐服務日誌安全轉義，重啟嚴格核對跳過授權宣告

查看背景常駐服務（daemon，在背景持續執行的支援程式）日誌時，終端機畫面不會再被特殊控制字元干擾。

在執行 claude daemon run 與 claude daemon logs 輸出的日誌中，控制字元現在會安全轉義為 \uXXXX 編碼顯示，多行訊息也整合為單行 JSON 格式以利程式解析。背景工作單元在重啟時，若未明確同意免責宣告，絕不會自動套用 --allow-dangerously-skip-permissions 參數，確保操作權限安全。

新功能

指令權限檢查補洞：變數前綴、萬用字元、pyright 與 ps 都會先詢問

執行終端機命令時，權限檢查有幾處漏洞補上了。

以前用 declare、export 等前綴設定變數，再拿變數組出指令或路徑時，拒絕或詢問規則可能漏掉它；現在會正確比對。rg、git grep 這類唯讀指令的參數若會被 Shell 展開成萬用字元，以前會直接放行，現在改成先問你；zsh 與 bash 讀法不同的變數名稱也一樣。唯讀指令某些選項值裡的萬用字元，現在也會套用讀取拒絕規則與目錄外讀取封鎖。pyright 不再算唯讀指令，更多 ps 寫法也會先詢問。

問題修復

沙盒管線多行輸入自動放行，掃描大型目錄不再凍結

在沙盒隔離環境中執行腳本時，流程更順暢且效能更好。

以前將多行文字透過管線傳遞至其他指令（例如 cat <<EOF | python3）時，每次都會反覆跳出確認，現在沙盒自動放行機制已能正常識別。使用 git clone 短選項時能與完整選項一樣正確套用豁免規則。在 Linux 與 WSL 環境下，沙盒讀取規則涵蓋超大資料夾時不會再造成 /sandbox 設定頁面凍結。監控工具指令也會忠實遵循使用者的權限設定。

問題修復

計畫模式嚴格把關寫入工具，限制模式關閉跨對話通訊

當你開啟安全限制或計畫模式時，敏感操作的防護機制更嚴密。

以前在計畫模式下，自動分類器可能會誤放行帶有詢問策略的非唯讀連接器工具；現在這類請求均會被攔截。在受限模式（--restricted）下，系統不會再開啟跨工作階段的通訊端。透過中繼通道授權時，同一工作階段內重複的回覆識別碼會被自動忽略，避免誤核准不同的提示詞。修改設定檔符號連結（symlink，指向另一個位置的捷徑檔）指向的實際檔案時，也一定會跳出權限確認提示。

問題修復

防範符號連結中途偷換，貼入圖片嚴格套用拒絕規則

在提示詞中提及檔案或拖曳圖片時，路徑安全防護更滴水不漏。

以前在 macOS 與 Windows 讀取圖片時，若連結在讀取中途被換掉，可能讀到核准範圍外的檔案；用 @ 提及檔案時，讀取中途被換掉的符號連結（symlink，指向另一個位置的捷徑檔）也可能讓 Claude 讀到工作目錄以外的檔案。這個問題已經修好，讀取中途被換掉的連結不會再讓 Claude 讀到核准範圍外的檔案。拖曳或貼入的圖片路徑以及提及資料夾內的檔名，現在均會嚴格套用讀取拒絕規則。提及子目錄檔案時也會正確附帶該目錄下的 AGENTS.md 設定說明檔。

問題修復

機敏金鑰掃描不再卡死，換行檔名提示正確顯示

當對話與操作中包含超長字串或機敏金鑰時，終端機不會再突然卡住。

以前機敏資料掃描與遮蔽機制遇到極長連續文字、或是類似金鑰的 token（授權令牌）長字串時，授權提示視窗會導致終端機畫面直接凍結數秒；現在已修復凍結問題，掃描與提示都能順暢進行。若處理的檔案名稱中包含換行字元，以前在檔案工具報錯與授權提示視窗中會排版錯亂，現在也能正確排版並完整顯示檔案名稱。

問題修復

程式碼深度審查支援特殊 Git 設定，未提交修改安全上傳

當你使用 /ultrareview 請求深度審查當前工作區時，各種邊界環境下的程式碼打包更安全。

以前在 Windows 環境下若暫存失敗可能無聲遺失未提交的變更，開啟換行安全檢查或在新版 Git（分支存於目錄外）中也可能導致上傳失敗或遺漏修改；現在這些情境都能妥善處理。若 git 過濾驅動程式剛好取名為 unset 或 unspecified，上傳會中止並請你把它改名，避免上傳未過濾的檔案。

新功能

遠端審查報錯精簡明瞭，合併拉取列出變更檔案清單

執行程式碼同步或遠端審查遇到問題時，錯誤提示變得更親切且容易理解。

以前 Git 步驟失敗時常會印出一整段生硬的原始報錯，現在提示訊息長度縮短一半，會直接點出失敗步驟與具體排解建議。在執行合併或拉取等連鎖指令時，變更檔案清單會以簡潔列表呈現。使用 /teleport 遷移若遇到同名資料夾衝突，系統也會明確拒絕並說明原因以防止檔案遺失。
