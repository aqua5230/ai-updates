Claude Code 2.1.286

Released: 2026-09-30

Release notes

FEATURE

Permission prompts show total pending count and unify command and tool authorization screens

When Claude performs multiple operations in a row and triggers a series of authorization requests, you can now see at a glance how many items remain to be confirmed.

Picture taking a number ticket at a bank counter, where the screen clearly shows the current number called and the total waiting count, while application forms across different windows follow the same layout.

Permission prompts now display counts such as "2 of 5" when multiple requests stack up, keeping you informed of the overall review progress. Authorization panels for web fetching, skills, file reading, sandbox network, Claude in Chrome, workflow scripts, and notebook editing all align their appearance with file edit prompts. Bash, PowerShell, and Monitor commands are framed with dashed lines during prompts, making the command boundaries clearer.

FEATURE

Fullscreen lists support mouse clicks with aligned layouts and scrollbar arrows

Browsing lengthy items in fullscreen mode is now more intuitive to navigate and read.

Think of flipping through a neatly formatted catalog with quick-turn buttons on the page margins, where clicking an omitted item immediately jumps to that section.

Collapsed rows like "↑ N more" and "↓ N more" now support mouse hover, pressed states, and clicks that navigate directly to the list ends. Clicking the text gaps of collapsed rows like "Thought for 4s" now properly expands content instead of merely highlighting text. Detailed information across lists such as /artifacts, /mcp, /skills, and /hooks is aligned in a single column. Rows without details, such as operation rows with long names, no longer push the details of other rows to the right. Scrollbars gain up and down arrows that can be clicked or held for continuous scrolling. In most lists, the scrollbar no longer shifts when ellipsis rows appear or disappear.

BUGFIX

Expired credentials avoid duplicate browser launches and accurately reflect login status

When running multiple windows or editor extensions simultaneously, account logins and credential states no longer conflict.

A residential guard updates access passes so that once you register at the main counter, every entrance grants entry in sync without asking for repeated identification.

When gcpAuthRefresh or awsAuthRefresh credentials expire, multiple processes will no longer each open separate browser login pages. After a macOS session logs in successfully via /login in another window, it is no longer misidentified as logged out even if a legacy ~/.claude/.credentials.json file remains. claude auth status accurately reports console-stored keys as api_key, and the VS Code extension correctly identifies them as key sessions. When an API key is present, /status explicitly marks Anthropic profiles as unused.

BUGFIX

Session resumption preserves conversations and fixes errors from non-text returns

When encountering terminal crashes or unexpected interruptions, resuming work no longer risks losing conversation progress.

Imagine reconnecting after disconnecting mid-game, where past chat logs alongside content after parallel tool calls are fully restored, and attached items with extra-long filenames load smoothly.

Resuming a previously crashed session with claude --resume or --continue will no longer lose conversation history following parallel tool calls. Non-text returns from tools or hooks—such as objects, numbers, or booleans—no longer trigger API 400 errors, which also applies to resumed sessions. For cloud sessions with massive histories, containers no longer terminate prematurely during transcript loading and fail to wake. Files with extremely long filenames attached to cloud sessions can now also be delivered properly.

FEATURE

Model unavailability triggers same-tier fallback with a unified retry limit

When an API rejects the default model or the model mapped by an alias, you no longer need to switch models manually every turn.

A backup generator kicks in when the main power trips, while the dashboard lights up to show output changes and prevent repeated restarts from draining battery reserves.

Claude Code retries only once, falling back to an earlier model of the same tier. If the fallback model and --fallback-model retries cannot run at high speed, they execute at standard speed and display a notification only once in interactive sessions. If a fallback reduces the context window from 1M to 200K tokens, both the fallback notification and error messages from repeated auto-compaction will state the capacity change. Failed API requests now calculate their retry limit per individual model call, sending at most 14 requests under default settings. Single-turn fallbacks will also not send duplicate Git commit note reminders.

BUGFIX

Remote Control disconnects on organization policy and queued messages resume on restart

Connecting across devices via Remote Control is now more dependable for connection states and message delivery.

Consider a walkie-talkie that beeps and cuts off when the base station closes the channel, while messages received before going offline remain saved in an inbox for the next startup.

When an organization policy disables Remote Control, sessions including claude remote-control proactively disconnect and display a notification. Claude is informed if attached files sent over remote connections fail to deliver, and an issue where the final download attempt sometimes had only 10 seconds remaining is resolved. Messages arriving right as the program exits are no longer mislabeled as delivered, remaining in the queue to be answered on the next run.

BUGFIX

Sensitive keys masked in error logs and report file formats fixed

When exporting transcripts or inspecting error messages, secret redaction is now far more airtight.

A shredder sanitizes classified paperwork by completely stripping away invisible ink and symbolic passwords without corrupting the document structure.

MCP error messages no longer expose credentials when Bearer or Basic precedes key names. Percent-encoded Bearer tokens are no longer only partially redacted. Secret settings with key names containing invisible characters like zero-width spaces are properly hidden in logs and transcripts. When URL passwords contain punctuation such as quotes, parentheses, &, or a second @, no partial characters linger in logs and transcripts. Passwords extending across / to bracketed hosts like [::1] in ssh URLs are also fully redacted. Responding to /feedback, redacted archives no longer produce malformed JSON lines in session transcripts.

FEATURE

MCP server re-authentication avoids duplicate prompts and logs tool usage properly

Connecting to MCP servers now offers more stable connection handshakes and login authorization workflows.

Like an external docking station reconnecting after a reboot, communication logs record usage per port without repeatedly prompting for authorization.

Headless sessions no longer display redundant prompts after successful re-authentication, a fix that applies when discovery caching is enabled. When servers deprecate legacy handshake protocols, MCP connectors will no longer lose track of tools for up to a day. Duplicate login requests will not overwrite pending verification links. Tool calls are accurately counted in /usage while MCP servers are connecting or just connected. When a host re-enables an already connected server, both the SDK and -p mode respond faster.

FEATURE

Subagent communication is more responsive and background transcript actions require confirmation

Dispatching subagents to handle heavy background tasks now provides a smoother experience when sending immediate messages and tracking progress.

Much like passing an urgent note to backstage staff, the recipient immediately moves background chores aside to read instructions and omits repetitive recaps when reporting back.

Pressing the immediate send shortcut (Ctrl+Enter) in a subagent window moves the subagent's running command to the background to read your input right away. Messages typed to subagents no longer appear twice in the transcript after being read. When background agents reply, they no longer needlessly repeat what you just said. Subagents without registered names display an agent alias instead of raw task IDs when yielding work. Typing /compact, /clear, or /rewind while viewing a background agent or teammate transcript opens a dialog naming the target to confirm, preventing accidental modifications to the main conversation.

BUGFIX

Subagent tool loss and duplicate loading fixed while approval statuses reflect accurately

Launching subagents to work on projects now offers a sturdier tool configuration and lifecycle in background environments.

Assigning an assistant to an isolated work area ensures every checklist tracking tool is on hand without repeatedly unboxing already reviewed guidelines.

In sessions with task tracking enabled, foreground subagents will no longer occasionally lose tools like TaskCreate, TaskGet, or TodoWrite. Subagents created with worktree isolation will not redundantly reload the project's CLAUDE.md and imported settings from the copy on the first file read. Workflow tool subagents experiencing a multi-minute stall mid-response will no longer restart from scratch using the initial prompt. Background tasks awaiting user approval are no longer falsely marked as completed on status screens.

FEATURE

Plugin Installation Restricts Package Sources and Clarifies Marketplace Loading Errors

When managing and installing plugin extensions, package dependency security and troubleshooting information are much clearer.

Just as procurement requires sourcing materials only from an official registry while rejecting goods from Git repositories or local folders, the system blocks unsafe packages and clarifies troubleshooting steps when a marketplace fails to load.

Plugin installation now rejects npm sources from Git repositories or local folders, allowing dependencies to be installed only from registry packages. When the system rejects loading a specific plugin marketplace, error messages explicitly explain the cause and remediation steps instead of merely showing "not found". On the /plugin Discover page, quotation marks around marketplace names maintain consistent formatting. Plugins enabled on claude.ai no longer abruptly disappear during the active session when brief server hiccups occur.

FEATURE

External Editor Precision Line Navigation and Smoother Slash Commands and Settings Menus

Writing long prompts or tweaking appearance settings in the terminal now feels significantly more responsive.

Opening a dedicated editor places the cursor on the exact line, quick menus filter instantly by keyword, and visual styles scroll smoothly within a tidy list.

When using an external editor (Ctrl+G), editors supporting line number arguments open directly at the prompt line where your cursor was positioned. When many skills or plugins are installed, slash command autocomplete is more responsive, matching description text by word prefix. The output style picker now focuses directly on the active style with detailed descriptions shown beneath each name; numeric keys no longer select output styles. The theme picker is now a scrollable list sized to terminal height so previews are not pushed off-screen, and numeric keys no longer select themes. /hooks is now grouped by event in a single list, allowing you to inspect details with a single Enter keystroke. The detailed view ending now says "this hook" instead of "it".

FEATURE

Bare Mode Limits Connections and Background Tasks while Guiding Skill Verification Before Commit

Running tasks or enforcing quality in clean environments now integrates command-line tools and background workflows much tighter.

A factory switching to manual mode disables background schedules, prompts quality control before shipping, and turns off engines before dismantling machinery.

If a project or personal skill includes a verify skill, Claude is prompted to run it before committing changes, except for pure documentation or test edits. Enabling the --bare flag connects only to specified MCP servers, sends the model no system reminders, and skips launching background tasks; timed-out shell commands stop immediately instead of moving to the background. Submitting prompts while idle instantly displays text in standard coloring instead of gray. Pressing the instant-send key sends skill-invoked shell commands to the background rather than terminating them. Removing a worktree via /exit now terminates servers and shells started by Claude Code inside that worktree first, preventing Windows folder deletion failures caused by locked files. Output from /ultrareview and claude ultrareview no longer includes browser links.

FEATURE

Unified Artifact Reading and Web Permissions with Precise Gateway Cache Billing

Reading claude.

ai artifacts or fetching web data now features more accurate permission prompts and billing calculations.

Mail clears customs item by item, blocked connections avoid knocking repeatedly, and billing scales settle charges strictly by storage duration.

When WebFetch reads claude.ai artifact links, it follows artifact tool rules: no prompts appear when session web access is enabled, and one prompt per artifact is shown when disabled; auto-mode cannot answer prompts that require your direct confirmation. When domain safety checks hit rate limits, error messages advise Claude against repeated retries. The Claude apps gateway previously miscalculated 1-hour prompt caching at the 5-minute rate, which is now fixed. Server-side tool streaming now counts toward input tokens for subsequent calls. The gateway /protocol page now aligns with the latest specification and notes that unknown inputs should not be rejected. The Managed Agents example in the claude-api skill now uses a restricted network environment.

FEATURE

Windows Resolves Case Sensitivity Mismatches in Folder Trust Checks

Running background agents on Windows no longer encounters access denials caused by folder path casing differences.

An access control system checks visitor logs, recognizing an approved resident whether their name is written in uppercase or lowercase and preventing false lockouts caused by casing mismatches.

Previously on Windows, if stored folder trust records used inconsistent casing, running claude --bg or opening agent views would misclassify the directory as untrusted and deny access; path evaluation logic is now fixed to correctly recognize existing trust states.

FEATURE

VS Code Adds Response Bookmarks, Question Previews, and Integrated Context Drawers

Organizing chat history and inspecting context in the VS Code editor is now significantly more convenient.

Sticky index tabs line notebook margins for quick reference, survey choices show visual diagrams alongside options, and expandable reference drawers sit right beneath messages.

The bookmark feature lets you save standout Claude responses to the sidebar Bookmarks panel for pinned viewing at any time. When answering question cards in the chat panel, screenshots or code snippets for the currently highlighted option appear beside or beneath that choice. Once answered, a Questions section is appended to the conversation to preserve the prompt and your selection history. A dedicated bar beneath messages lets you click to expand attached terminal outputs, browser tabs, browser actions, and selected code.

FEATURE

VS Code Status Bar Appears Across All Windows and Stop Action Halts Only Active Turn

Multitasking in VS Code now offers more intuitive extension controls and tab management.

An office suite keeps a status bar across every open window, and pressing pause halts printing for only the active document without interrupting background batch reports.

The "✻ Claude Code" status bar icon now displays across all windows, allowing you to open the interface even without any active files. Pressing the Stop button or Escape key now cancels only the active generation turn; background agents continue running and can be stopped individually from the agent map. When a session is already open in the sidebar, clicking it switches to the conversation in the sidebar instead of opening a duplicate tab in the editor area. Settings dialogs no longer falsely report save failures without confirmation when output exceeds 1 MB. An issue where unresponsive extensions remained stuck on a spinning "Teleporting session…" prompt is resolved. The plugin management view now clarifies why disabled plugins remain active due to other settings and explains plugin folder conflicts.

BUGFIX

Cloud Sessions Accurately Reflect Schedule and Run States with Audio Preview and Card Fixes

Running automated schedules or long-running tasks in cloud environments now features more accurate dashboards and controls.

A flight departures board marks delayed, unstarted flights as pending or cancelled instead of mislabeling unexecuted trips as arrived on time.

When a scheduled routine is overdue to run, the page displays "Due" with its scheduled time rather than an outdated next run time; if a session fails to start altogether, its status is accurately marked as Failed. After Claude sends a message and goes idle, replying to a question card or approving a tool call reliably triggers subsequent responses. Clearing the organization environment build script in admin settings ensures newly created cloud sessions no longer inherit obsolete scripts. Clicking audio or video files inside the Outputs card now plays media directly rather than opening an empty file search. The runner menu on the self-hosted management page no longer closes automatically seconds after opening.

BUGFIX

Claude Tag Supports Per-Channel Spending Limits with Fixes for Slack Memory and Session Titles

Collaborating with Claude via tags in Slack features sounder administrative controls and conversation continuity.

Setting spending limits on departmental accounts preserves channel preferences across workspace moves, ensuring answering prompts never loses unpushed progress from unexpected machine resets.

Admins can click "Add channel" on the spend limits page to assign quotas by channel ID or Slack link for any channel, including private channels. Organizations without access to the default Sonnet model can now retrieve long-term memory normally. When Enterprise Grid admins move channels between workspaces, channel settings remain intact even if the initial post does not mention Claude. Responding to Claude's questions in a thread no longer occasionally spawns a new machine and loses unpushed progress. Spend limit pages for large organizations properly display public channel names instead of raw IDs; session titles initiated from Slack on claude.ai are converted to plain text, stripping escape characters and user IDs.
