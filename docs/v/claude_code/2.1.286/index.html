Claude Code 2.1.286

發布日期：2026-09-30

繁體中文

新功能

權限提示標明待審總數，指令與工具授權畫面統一

當 Claude 連續執行多項操作而跳出一連串授權詢問時，你現在能一眼掌握還剩幾項要確認。

像在銀行櫃檯抽號碼牌辦理業務，螢幕清楚顯示目前叫號與等待人數，各個窗口的申請表單也採用同一套版型。

權限提示在多筆請求堆疊時會顯示「2 of 5」等計數，讓你知道整體審核進度。網路擷取、技能、檔案讀取、沙盒網路、Claude in Chrome、工作流程腳本與筆記本編輯的授權面板，外觀都對齊檔案編輯提示。Bash、PowerShell 與 Monitor 指令在詢問時會以虛線框起，指令範圍更清楚。

新功能

全螢幕清單支援滑鼠點選，排版對齊且捲軸增設箭頭

在全螢幕下瀏覽落落長的項目時，清單操作與閱讀變得更加直覺。

好比翻閱排版整齊的商品目錄，頁面邊緣附有快速翻頁按鈕，點擊省略項目就能立刻跳轉至該區段。

「↑ N more」與「↓ N more」等折疊列現在支援滑鼠懸停、按下狀態與點擊直達列表端點。點擊「Thought for 4s」等收合列的文字間隙時，會正常展開內容而非僅反白。/artifacts、/mcp、/skills 與 /hooks（掛鉤，特定事件發生時被觸發的小程式）等清單中的詳細資訊皆統一對齊於同一欄位；沒有詳細資訊的列，例如名稱很長的操作列，不再把其他列的詳細資訊推向右側。捲軸新增可點擊或按住持續捲動的上下箭頭；在大多數清單中，省略列出現或消失時，捲軸不再跟著位移。

問題修復

憑證過期不再重複跳轉瀏覽器，精確標示登入狀態

同時開啟多個視窗或編輯器擴充功能時，帳號登入與憑證狀態不再打架。

有如社區保全更新通行證，只要在主櫃檯完成登記，各出入口隨即同步放行，不再要求重複出示證件。

當 gcpAuthRefresh 或 awsAuthRefresh 憑證過期時，多個行程不會再各自彈出瀏覽器登入頁面。macOS 工作階段在另一個視窗以 /login 登入成功後，即使殘留舊版 ~/.claude/.credentials.json 檔案，也不會誤判為未登入。claude auth status 針對主控台儲存的金鑰會如實回報為 api_key，VS Code 擴充功能也會正確識別為金鑰工作階段。/status 在同時存在 API 金鑰時，會將 Anthropic 設定檔明確標註為未使用。

問題修復

工作階段恢復不再遺失對話，修復非文字回傳引發的錯誤

遇到終端機當機或非預期中斷時，重新接關不再面臨對話進度遺失的窘境。

正如遊戲中途斷線後重新連線，先前的對話紀錄連同平行工具呼叫後的內容都能找回，檔名過長的附加道具也能順利載入。

使用 claude --resume 或 --continue 恢復先前崩潰的工作階段（session）時，不會再遺失平行工具呼叫後的對話紀錄。工具或掛鉤回傳物件、數字或布林值等非純文字內容時，不再引發 API 400 錯誤；恢復的工作階段也適用。歷史紀錄極為龐大的雲端工作階段，容器不會在載入對話紀錄時提前停止而無法喚醒。附加檔名超長的檔案到雲端工作階段時，也能正常送達。

新功能

模型不可用時自動切換同級備援，重試次數改採單一上限

當 API 拒絕預設模型或模型別名對應的模型時，你不必每輪都手動換模型。

宛若主發電機跳電時切換至備用機組，儀表板會亮燈提示輸出功率變化，避免反覆重新發動造成電力耗盡。

Claude Code 只重試一次，改用同等級的前一版模型備援（fallback）。備援模型與 --fallback-model 重試若無法高速運行，會以標準速度執行，並只在互動式工作階段顯示一次通知。若備援使上下文視窗從 1M 縮減至 200K token（AI 處理與計費的文字單位），備援通知與自動壓縮反覆觸發時的錯誤訊息都會標明容量變化。失敗的 API 請求改以單次模型呼叫為單位計算重試上限，預設設定下最多發送 14 次請求。僅持續一輪的備援也不會重複發送 Git 提交註記提醒。

問題修復

遠端操控配合組織政策自動斷線，排隊訊息於重啟後接續處理

透過遠端操控（Remote Control）跨裝置連線時，連線狀態與訊息傳遞更加可靠。

如同對講機在總台關閉頻道時自動切斷並發出嗶聲，離線前收到的留言則妥善保存在收件匣等待下次開機。

當組織政策停用遠端操控時，包含 claude remote-control 在內的工作階段會主動中斷連線並顯示通知。透過遠端連線傳送的附加檔案若未成功送達，Claude 會獲知，且檔案最後一次下載嘗試有時只剩 10 秒的問題已修好。在程式即將退出時抵達的訊息不會被誤標為已送達，而是保留在佇列中供下次啟動時回覆。

問題修復

隱藏錯誤日誌中的敏感金鑰，修正回報檔案的格式

在匯出對話紀錄或查看錯誤訊息時，機密資訊遮蔽變得更加滴水不漏。

猶如保密公文銷毀機處理機密文件，不管是夾帶看不見的隱形墨水還是特殊符號密碼，都能完整抹除而不損及文件結構。

MCP（讓 AI 連接外部工具的協定）錯誤訊息在 Bearer 或 Basic 位於鍵名前方時，不會再暴露憑證內容。百分比編碼的 Bearer token（授權令牌）不再只有部分被遮蔽。鍵名含有零寬空格等不可見字元的機密設定，在日誌與對話紀錄中會確實隱藏。URL 密碼若包含引號、括號、& 或第二個 @ 等標點，在日誌與對話紀錄中不會再殘留部分字元。若密碼在 ssh 網址中跨過 /，延伸至 [::1] 這類方括號主機，也會完整遮蔽。/feedback 儲存的壓縮檔在脫敏後，工作階段對話紀錄不再出現格式錯誤的 JSON 行。

新功能

MCP 伺服器重新驗證不再重複提醒，正常記錄工具用量

串接 MCP（讓 AI 連接外部工具的協定）伺服器時，連線握手與登入授權流程更為穩定。

跟外接擴充座重新開機後恢復連線一樣，通訊記錄如實登記各埠口用量，也不再反覆顯示授權提醒。

無頭模式（沒有終端機視窗的執行方式）的工作階段重新驗證成功後，不再重複顯示提醒；這項修復適用於已啟用探索快取的情況。快取是把查過的結果暫存起來直接用。當伺服器停止舊版握手協定時，MCP 連接器不會再發生長達一天找不到工具的情況。重複發送的登入請求不會覆蓋尚未完成的驗證連結。MCP 伺服器仍在連線中或剛連上時，工具呼叫都會正確計入 /usage。主機重複啟用已連線伺服器時，SDK（供程式串接的開發工具包）與 -p 模式反應更快。

新功能

與子代理溝通更即時，操作背景對話紀錄前會先確認目標

派遣子代理在背景執行繁重任務時，即時發送訊息與檢視進度的體驗更加順暢。

類似向後台工作人員遞送緊急紙條，對方會立刻把手邊雜務轉入後台並讀取指示，回報時也省去冗長重複的複述。

在子代理視窗按下立即發送快捷鍵（Ctrl+Enter）時，會將子代理目前執行的指令移至背景，以便立刻讀取你的輸入。輸入給子代理的訊息在被讀取後，對話紀錄中不會再重複出現兩次。背景代理人回覆時，開頭不再多餘複述你剛剛說過的話。未註冊名稱的子代理交回工作時，會顯示代理人代稱而非原始任務識別碼。在檢視背景代理人或隊友的對話紀錄時輸入 /compact、/clear 或 /rewind，系統會跳出對話框標明目標並詢問確認，防止誤改主對話。

問題修復

修復子代理工具遺失與重複載入，精確反映審批狀態

當你啟動子代理處理專案時，背景環境的工具配置與生命週期更加健全。

彷彿分派助手至獨立工作區施工，工具箱裡的清單追蹤器具一應俱全，也不會把早已讀過的施工指南重複拆封。

在已啟用任務追蹤的工作階段中，前景子代理不會再偶爾遺失 TaskCreate、TaskGet 或 TodoWrite 等工具。透過工作樹（worktree，Git 讓同一專案平行開多份副本的功能）隔離建立的子代理，在首次讀取檔案時不會從副本重複載入專案的 CLAUDE.md 及其匯入設定。工作流程工具子代理在回應中途遇到幾分鐘的連線停頓時，不會再從初始提示詞被重頭重啟。等待使用者核准的背景工作，在狀態畫面上不再被錯誤標記為已完成。

新功能

外掛安裝限制套件來源，清楚說明市集載入錯誤

管理與安裝外掛擴充時，套件相依性安全與錯誤排查資訊都更加清楚。

就像從套件註冊表領取安裝材料，安裝時會拒絕從 Git 儲存庫或本地資料夾取得的套件；遇上無法載入的市集，也會說明原因與排解方式。

外掛安裝現在會拒絕來自 Git 儲存庫或本地資料夾的 npm 來源，且僅允許從套件註冊表（registry package）安裝相依套件。當系統拒絕載入特定外掛市集時，錯誤訊息會明確說明原因與修復步驟，不再僅顯示「not found」。在 /plugin 的 Discover 頁面中，市集名稱的引號顯示格式保持一致。伺服器發生短暫異常時，在 claude.ai 上啟用的外掛不會再於當前工作階段中突然消失。

新功能

外部編輯器精準定位游標行，斜線指令與設定選單更流暢

在終端機中撰寫長提示詞或調整外觀設定時，各項互動細節更加得心應手。

切換專業文字編輯器時游標停在同一行，快捷選單依據關鍵字快速過濾，外觀與樣式也能在清單內自如捲動挑選。

使用外部編輯器（Ctrl+G）時，支援行號參數的編輯器會直接開啟在游標所在的提示詞行數。安裝大量技能或外掛時，斜線指令的即時自動補齊更靈敏，說明文字改採單字前綴匹配。輸出風格選擇器會直接定位在目前使用的樣式，並在名稱下方顯示詳細說明；數字鍵不再選取輸出風格。主題選擇器改為符合終端機高度的可捲動清單，預覽畫面不再被推出螢幕外；數字鍵也不再選取主題。/hooks（掛鉤，特定事件發生時被觸發的小程式）現在依事件分組顯示於單一清單，只要按一次 Enter 即可檢視細節。詳細畫面的結尾也改說「this hook」，不再說「it」。

新功能

極簡模式限制連線與背景任務，提交前提示驗證技能

在乾淨環境執行任務或把關品質時，指令列與背景流程配合得更緊密。

工廠切換至純手動模式會關閉背景排程，出貨前提醒品管，收工先熄火才拆機具。

專案或個人技能若有 verify 技能，除純改文件或測試外，Claude 提交前會收到先執行它的指引。啟用 --bare 旗標時僅連線指定的 MCP 伺服器、不發系統提醒且不開背景工作；逾時 Shell 指令直接停止而非轉入背景。閒置時發送提示詞，文字立即顯示為標準顏色而非灰色。按下立即發送鍵時，技能自帶的 Shell 指令會轉入背景而非被終止。/exit 移除工作樹時會先停止 Claude Code 在該工作樹啟動的伺服器與 Shell，避免 Windows 因檔案佔用無法刪除資料夾。/ultrareview 與 claude ultrareview 輸出不再附瀏覽器連結。

新功能

統一成品讀取與網路授權流程，精準計算閘道快取費用

讀取 claude.ai 成品或抓取網路資料時，權限詢問與計費更為準確。

比照郵件逐件通關，連線受阻時不反覆敲門，計費磅秤如實按存放時效結算。

WebFetch 讀取 claude.ai 成品連結時比照成品工具：工作階段開啟網路時不詢問，關閉時各問一次；自動模式不能代答僅你能確認的問題。網域安全檢查若遇速率限制，錯誤訊息會提醒 Claude 不要反覆重試。Claude apps 閘道原本把 1 小時提示快取（把算過的結果暫存起來直接用）誤算為 5 分鐘費率，現已修正。伺服器端工具串流也計入後續呼叫的輸入 token（計量文字的單位）。閘道 /protocol 頁面已對齊最新規格，並註明不應拒絕未知輸入。claude-api 技能的 Managed Agents 範例改用受限網路環境。

新功能

Windows 解決資料夾信任大小寫不一致的判定問題

在 Windows 系統上使用背景代理人時，不再因為資料夾路徑大小寫不同而遭拒絕存取。

就像門禁系統比對訪客名單，不論英文名字寫成大寫還是小寫，都能認出是同一位獲准進入的住戶，不再因大小寫不一致而擋在門外。

以前在 Windows 環境下，若資料夾信任紀錄儲存時使用了不同的大小寫形式，執行 claude --bg 或開啟代理人檢視畫面時，會被誤判為未受信任的資料夾而遭拒絕；現在已修復路徑判定邏輯，能正確識別既有的信任狀態並順利運作。

新功能

VS Code 新增回覆書籤與問題預覽，整合終端機與選取程式碼

在 VS Code 編輯器中使用 Claude 時，對話紀錄的整理與上下文檢視變得更加方便。

比照在筆記側邊貼上索引標籤方便隨時翻閱，問卷選項旁直接附上示意圖，訊息下方也能隨時展開參考資料。

書籤功能讓你能將 Claude 的精彩回覆保存至側邊的 Bookmarks 面板，隨時固定檢視。在聊天面板回答問題卡片時，目前反白選項的畫面示意圖或程式碼片段，會顯示在選項旁或下方。回答完問題卡片後，對話中會新增 Questions 欄位完整保留問題與你的選擇紀錄。訊息下方新增專屬列，可直接點擊展開隨訊息一同傳送的終端機輸出、瀏覽器分頁、瀏覽器操作指令及選取的程式碼。

新功能

VS Code 狀態列常駐所有視窗，停止鍵僅結束當前輪次

在 VS Code 進行多工開發時，擴充功能的控制按鈕與分頁管理更符合操作直覺。

就像辦公軟體的快捷狀態列常駐在所有視窗底部，按下暫停鍵只會停止手邊這份文件的列印，不影響後台正在跑的批次報表。

「✻ Claude Code」狀態列（status bar）圖示現在會在所有視窗顯示，即使未開啟任何檔案也能直接開啟。按下 Stop 按鈕或 Escape 鍵改為僅結束當前輪次的生成，背景代理人會繼續運行，且可於代理人地圖中單獨停止。當對話已在側邊欄開啟時，點選不會再於編輯區重複開啟同一份對話分頁，而是直接切換過去。設定對話框在輸出超過 1 MB 時不再未經確認就誤報儲存失敗。擴充功能無回應時卡在「Teleporting session…」的旋轉圖示問題已獲得修復。外掛管理視窗會說明停用的外掛為何仍因其他設定而啟用，也會說明外掛資料夾衝突。

問題修復

雲端工作階段精準反映排程與執行狀態，修復音訊預覽與授權卡片

在雲端環境中運行自動化例行排程或長時間任務時，狀態看板與操作介面更加精確。

正如航班資訊看板將誤點未起飛的班次如實標記為待出發或取消，不再將未執行的航程誤判為順利抵達。

當例行排程逾期尚未啟動時，頁面會顯示「Due」與預定時間，不再顯示過期的下次執行時間；若工作階段根本未啟動，狀態會如實標示為 Failed。工作階段（session）在 Claude 送出訊息轉為閒置後，使用者回覆問題卡片或核准工具呼叫能正常觸發後續回應。管理員設定中清除組織環境的建置指令稿後，新建立的雲端工作階段不會再沿用舊指令稿。點擊 Outputs 卡片中的音訊或影片檔案時，會直接進行播放而非跳出空白檔案搜尋。自託管環境管理頁面上的 Runner 選單不再於開啟數秒後自動關閉。

問題修復

Claude Tag 支援個別頻道花費上限，修復 Slack 記憶讀取與對話標題

在 Slack 標記 Claude 協作時，管理設定與對話延續性更加健全。

替頻道設零用金上限，搬遷工作區保留設定，答題時也不會因換新機器弄丟進度。

管理員可在花費上限頁點選「Add channel」，以頻道 ID 或 Slack 連結為包含私人頻道的任何頻道設定額度（quota）。無法使用預設 Sonnet 模型的組織，現在也能正常讀取長期記憶。企業網格管理員將頻道移到其他工作區後，即使首則貼文沒提到 Claude，頻道設定也不會遺失。在討論串回覆 Claude 剛問的問題時，不再偶爾重開新機器而遺失未推送進度。大型組織的花費上限頁會正常顯示公開頻道名稱而非原始代碼；Slack 發起的工作階段在 claude.ai 上的標題也改為純文字，去除跳脫字元與使用者識別碼。
