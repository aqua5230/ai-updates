發布日期：2026-08-18

zh-TW

輸入即時拼字檢查，打字時自動標記錯字

在終端機裡打提示詞時，現在可以開啟即時拼字檢查。只要在個人設定檔中加入 "spellcheck": true，系統會使用你電腦裡安裝的 aspell、hunspell 或 ispell 等拼字檢查工具，在你邊輸入的同時即時標記拼錯的單字。若要啟用，可於 ~/.claude/settings.json 中設定：

{"spellcheck": true}

如此一來，在送出指令之前就能即時發現打錯的指令關鍵字或單字，不必等送出後才發現出錯。像隨身帶著一位字詞校對員，當你在稿紙上寫錯英文單字時，他立刻在底下畫一條紅波浪線提醒。

語言伺服器斷線重連，提示詞快取不再整批清空

寫程式時若是語言伺服器在對話中斷線又重連，你不再需要心疼遺失的快取（cache，把算過或查過的結果暫存起來直接用）與額外消耗的費用。過去在同一個工作階段（session）中，語言伺服器只要短暫斷開連線或重新接上，整個提示詞快取就會被徹底清空失效，迫使後續對話重新計算所有標記。現在這項問題已修正，連線中斷或重連時會妥善保留既有快取。就像廚房的備料台暫時換人接手，切好的食材仍整齊留在原位，不必從洗菜、切菜全部重做。

多行提示詞高亮精準對齊，斜線指令不顯示網頁實體編碼

在多行提示詞中輸入斜線指令或關鍵字時，高亮標記不再往前或往後歪掉一兩個字元。以前在輸入框打入多行文字時，斜線指令、關鍵字以及標註（@mention，用小老鼠符號提及檔案或符號的語法）的高亮色彩有時會出現字元位移，看起來十分錯亂；同時，若在 Claude 正在輸出回覆的當下執行斜線指令，終端機也不會再把字元印成像 &amp; 這樣的 HTML 實體編碼。像剪輯軟體的時間軸：色帶會對準對應片段，播放中的新標註也以正常文字顯示，不會變成代碼。

終端機 Markdown 清單排版修正，深層項目與折行對齊更工整

在終端機介面閱讀多層 Markdown 清單時，第 3 層或更深的項目現在會正確對齊，過長項目的換行也會使用懸掛縮排（hanging indent，讓換行後的第二行文字對齊上一行開頭而非標記點的排版方式）。過去，這些深層項目的對齊位置常常歪斜錯位，文字自動換行後也不會往內縮排。整理層級分明的大綱筆記時，若第三層以下的縮排全歪掉，閱讀節奏便會被打亂。

授權確認框收緊安全防護，留言按鍵不再誤送全域編輯權限

在權限授權對話框的留言欄位裡按 Shift+Tab，現在只會單純關閉該欄位，絕不會手滑把整個工作階段（session）的編輯權限直接送出去。以前在權限提示的備註框按下 Shift+Tab，會誤觸核准並賦予整個工作階段範圍的編輯權限；現在這個危險行為已被修正。此外，授權對話框的說明文字與「不再詢問」選項，現在保證與實際授權涵蓋的範圍完全一致；若對話框無法完整顯示內容，系統會主動隱藏「不再詢問」選項以策安全。像食譜 App 裡按返回只收起備註欄；食譜內容沒顯示完整時，也先不提供「往後照做、不再確認」的選項。

筆記本儲存格讀取失敗時，變更確認視窗主動說明原因

筆記本（notebook）儲存格無法讀取時，刪除或替換前的確認視窗不再一聲不吭地留下一片空白。以往當系統無法讀取 Jupyter 筆記本或特定儲存格的原始內容時，核准對話框會直接略過既有內容，讓使用者誤以為該儲存格原本就是空的；現在對話框會明確標註無法讀取的原因，幫助你在確認修改前了解真實狀況。像醫院的檢驗螢幕遇到無法讀出的結果時，不再把欄位留白而讓人誤以為沒有資料，而會說明無法顯示的原因。

選單對話框按鍵反應更即時，快按 Enter 精準選中當前目標

在各類選單對話框裡快速連按方向鍵與 Enter，你選中的項目就是游標最後停下的那一項。以前如果你的手速非常快，按下方向鍵切換選項後立刻按下 Enter 確認，介面偶爾會跟不上你的按鍵節奏，導致送出的是前一個高亮停頓的舊選項，容易造成手滑選錯；現在對話框的鍵盤事件處理更加敏捷，能精準捕捉你瞬間移動到的目標。猶如在自動販賣機上飛快按下一排按鈕時，出貨口掉出的確實是你最後停下的飲料，而不是前一毫秒還亮著燈的舊品項。

代理工具缺少型態參數時，主動列出目前可用的代理清單

當你在工作階段（session）中呼叫 Agent 工具卻省略指定型態時，現在會直接收到可用代理的清楚清單。以前在某些不支援全能預設代理的特殊環境中，系統仍會聲稱有預設代理可用，導致執行時碰壁；現在若省略了 subagent_type 參數，它會直接回報明確的錯誤訊息，並條列出目前環境中實際可用的代理清單。走進專門維修站請接待處派員協助，若今天沒有全能技師值班，櫃檯理應直接交給你一張「今日在場專家清單」，而不是口頭答應後才發現沒人可派。

跨工作階段訊息超重時直接拒收，不再無聲丟失資料

跨工作階段（session）傳送訊息時，文字量如果超出傳輸上限，SendMessage 現在會當場拒絕收件。以前在不同工作階段之間傳遞超大型訊息時，系統會因為資料量過大而默默把訊息丟棄，呼叫端完全收不到任何警告或報錯，造成資料在不知不覺中遺失；現在系統會在最前端直接攔截並主動報錯，明確告知訊息過大無法送達，讓你能提早拆分或縮短內容。像寄信時附檔超過信箱限制，按下送出前便會收到拒絕通知，不會表面寄出後又悄悄遺失。

背景雲端審查資源消耗最佳化，不再重複掃描歷史事件串流

當你在背景執行 /ultrareview 或 /autofix-pr 等雲端工作階段（session）時，記憶體與 CPU 使用量已改善。以往背景任務只要收到任何進度更新，系統就會把累積的事件串流從頭重新掃描並重新渲染一次；現在不再這樣做。觀察遠方工廠的即時日誌時，每進來一筆新紀錄，記錄員只需把新的一行貼上，不必每次都把整本歷史日誌從頭到尾重讀並重畫一遍。

內建搜尋提升極端樣式防護，限制筆數時精準擷取前後文

在 macOS 與 Linux 原生版本中使用內建搜尋，遇到病態比對樣式時現在會立即中止，不再把記憶體吃到乾涸。內建的 grep 搜尋工具迎來兩項重要改進：首先是遇到病態比對樣式時，系統會迅速判定失敗並中斷，避免耗盡系統記憶體；其次是當你搭配 -m N 限制匹配次數，並使用 -A 或 -C 抓取周圍上下文時，輸出的前後行數現在完全正確。就像試算表遇到無法處理的公式會先停止，不讓它吃光記憶體；需要相鄰儲存格時，也會精準顯示指定範圍。

對話長度觸及上限時，主動提示前往設定重新開啟自動壓縮

當對話長度觸及上下文上限，而你關閉了自動壓縮功能時，現在會看見明確的提示。以前如果使用者關閉了對話自動壓縮（auto-compact），一旦上下文長度達到上限，系統只會拋出冷冰冰的上下文上限錯誤，讓人摸不著頭緒；現在錯誤訊息會主動說明當前已停用自動壓縮，並明確指引你輸入 /config 指令前往設定介面將它重新開啟。如同行李箱裝滿時，拉鍊卡住的警示牌若能指引你開啟壓縮功能，就能省下倒出物品重新打包的麻煩。

Vim 模式狀態妥善保留，切換逐字稿或關閉面板不丟失游標

習慣使用 Vim 模式編輯的開發者，按下 ctrl+o 查看詳細對話紀錄或關閉側邊面板後，NORMAL 模式與游標位置都會原封不動保留下來。在過去的版本中，只要你在終端機中切換完整逐字稿檢視（按 ctrl+o 開啟或關閉），或者關閉任何彈出面板，系統就會重設 Vim 的狀態，導致游標跑位或跳出 NORMAL 模式，打斷編輯節奏；現在切換檢視後狀態會完整保留，讓你流暢地繼續輸入。彷彿在看書時抬頭查看附錄或關閉側邊筆記欄，視線與書籤依然精準停留在原本讀到的那一行文字上。

重連未結工作階段時，展開的任務清單維持開啟狀態

重新連回仍有未結任務的工作階段（session）時，按 ctrl+t 展開的任務清單不會再強制收合。在以往的版本中，即使當前工作階段還有未完成的任務，每當你重新連線或重新啟動進入該工作階段時，展開的任務清單總是會預設縮回摺疊狀態；現在系統會記住展開狀態，讓你一開工就能立即掌握所有進行中的任務進度。回到辦公桌重新開工時，只要手頭還有未完成的待辦事項，展開的白板便會維持攤開狀態，不必每次走進辦公室都得親手再拉開一次。

背景更新完成後，提示頁尾即時顯示重新啟動通知

背景自動更新完成後，提示詞底部的狀態列（status line，顯示在終端機最底下的狀態列）現在會老老實實秀出提示，提醒你重新啟動程式以套用新版。過去當 Claude Code 在背景默默下載並安裝好新版本時，最底部的提示頁尾往往漏掉顯示「Update installed」（更新已安裝）的重啟通知，導致使用者完全不知道背後已經升級、依然繼續跑著舊版；現在通知會如實出現，讓你能即時重啟換上最新版。就像門市更換新招牌後，門口收銀台底下會及時亮起「新裝潢已就緒，重開門即可生效」的提示燈，不再默默完工卻不聲不響。

遠端控制指令拉齊檢查標準，啟動時檢驗企業閘道器（enterprise gateway，企業網路的出入口）

透過 claude rc 啟動遠端控制時，現在會像一般互動式啟動一樣，在第一時間確實檢查企業閘道器是否可用。在企業資安環境中，互動式啟動 Claude Code 時原本就會嚴格檢驗閘道器連線狀態；然而過去使用遠端控制指令 claude rc 啟動時卻遺漏了這層檢查，容易引發連線異常。現在兩者的啟動檢驗標準完全拉齊，讓遠端連線同樣具備企業級的穩定度。不論在洗衣機面板按下啟動，還是用手機遠端啟動，洗衣機現在都會先確認供水是否可用。

VS Code 面板焦點維持穩定，視窗重載不再隨機跳轉分頁

在 VS Code 裡開啟多個 Claude 面板時，重新載入或還原視窗，焦點不再於各分頁之間胡亂跳動。以往在同一個視窗中若開了多個 Claude 面板分頁，當視窗重新載入（reload）或從背景還原時，編輯器焦點會在各個分頁之間自己亂跳，打斷工作思路；現在分頁焦點在視窗重載後會穩定留在原處，避免視窗切換帶來的困擾。瀏覽器重新開啟多個分頁時，焦點若能穩穩停在最後操作的分頁上，就不必在各分頁之間手動切換找回視線。

en

Optional real-time spellcheck underlines typos as you type

You can now turn on real-time spelling feedback while entering a terminal prompt. When you enable the optional spellcheck setting, it uses your locally installed aspell, hunspell, or ispell tools to underline misspelled words as you type. To turn it on, add it to your ~/.claude/settings.json:

{"spellcheck": true}

This catches misspellings and prompt typos before you send the message. Like having a personal proofreader hovering over your shoulder to scribble a red squiggly line under any typo the moment you write it.

Prompt cache survives language server disconnects and reconnects

When language servers disconnect or reconnect in the middle of a session, your prompt cache will no longer be wiped clean. Previously, any brief hiccup or reconnection with a language server invalidated the entire prompt cache, forcing subsequent turns to re-process tokens and waste credits. The cache is now safely preserved across mid-session language server reconnections. Like a kitchen prep station changing hands for a moment while the chopped ingredients stay neatly in place, rather than making the next cook wash and chop everything again.

Multi-line prompt highlights align accurately, and slash commands stop showing raw HTML entities

Multi-line prompt input highlighting and slash command characters now render cleanly. Previously, syntax highlights for slash commands, keywords, and @ mentions could appear shifted by one or more characters across multi-line inputs. Additionally, running a slash command while Claude was actively streaming a response showed raw HTML entities instead of real characters. Both visual bugs are now resolved. Like a video editor's timeline: colored bands align with their clips, and annotations added during playback appear as normal text rather than code.

Terminal Markdown lists align properly at depth 3+ with hanging indents

When you read deeply nested Markdown lists in the terminal UI, third-level and deeper items now align properly, and wrapped lines use a hanging indent. Previously, lists nested at depth 3 or deeper suffered from misalignment, and list items that wrapped across multiple lines lacked clean indentation. Like an outline notebook where third-level sub-bullets and long paragraphs wrap cleanly aligned with the text margin instead of drifting into a jagged, unreadable mess.

Permission prompts tighten safety, preventing accidental blanket grants on Shift+Tab

Permission prompts are now much safer and more accurate about what you grant. Previously, pressing Shift+Tab inside the permission comment field accidentally approved the edit and granted session-wide edit permissions instead of just closing the comment box. In addition, permission dialog text and "don't ask again" options now strictly match the true scope of the grant, and the "don't ask again" option is withheld whenever the full contents cannot be displayed. Like pressing Back in a recipe app to close only its notes field; when the full recipe is not shown, it also withholds an "always follow this without asking" option.

Notebook approval dialogs explain why unreadable cell contents could not be shown

Notebook cell delete and replace approval dialogs now state why content is missing when a read fails. Previously, if Claude could not read a notebook file or an individual cell, the approval dialog silently omitted the existing content, making it look as though you were deleting an empty cell. The dialog now explicitly explains why the existing content could not be read so you can make an informed decision before approving the change. Like a hospital test display that explains why a result cannot be shown rather than leaving the field blank and making it look as though no result exists.

Rapid dialog navigation selects your actual destination on Enter

Rapidly navigating dialogs with arrow keys and Enter now picks the correct option. Previously, if you tapped an arrow key and immediately pressed Enter in quick succession, the dialog sometimes lagged behind and selected the previously highlighted choice instead of the one you just moved to. Dialog keyboard handling is now properly synchronized to catch fast keystrokes. Like pressing buttons quickly on a vending machine and receiving the drink you actually stopped on, rather than the slot that was lit up a split second earlier.

Agent tool lists available subagents when an omitted type lacks a default

When you omit subagent_type while calling the Agent tool in a session without a general-purpose default, you now get a clear error listing the agents available to you. Previously, in sessions where the standard general-purpose agent was not supported, omitting the subagent_type parameter falsely advertised that a default was present. Like walking up to a specialized service desk and receiving a clear list of today's available technicians on duty instead of being told a general handyman is available when none exists.

SendMessage rejects oversized cross-session payloads up front instead of dropping them

SendMessage now explicitly rejects oversized messages before delivery rather than dropping them into the void. Previously, when sending data across different sessions, messages exceeding the cross-session payload limit were silently discarded without any warning or error, leaving developers wondering where the message went. The system now validates size constraints up front and immediately returns a refusal error so you can trim or chunk the content. Like an email client warning that an attachment is too large before you press Send, rather than appearing to send it and then silently losing it.

Background cloud sessions optimize CPU and memory by halting full stream re-renders

Running cloud sessions like /ultrareview or /autofix-pr in the background now uses memory and CPU more efficiently. Previously, whenever a background cloud session updated, its entire event stream was re-scanned and re-rendered from scratch. That no longer happens on every update. Like a warehouse clerk jotting down incoming deliveries by simply appending a new line to the clipboard, rather than re-reading and redrawing the entire historical ledger on every single tick.

Embedded grep handles pathological patterns safely and fixes context lines for -m N

The embedded grep tool in native macOS and Linux builds is now much safer and more accurate. When encountering pathological search patterns, grep now fails fast instead of exhausting system memory. Furthermore, combining -m N (maximum match count) with -A (after context) or -C (surrounding context) flags now prints the exact required context lines without dropping or duplicating them. Like a spreadsheet that stops an unworkable formula before it consumes all memory, while showing exactly the requested neighboring cells.

Context limit error guides users to /config when auto-compact is disabled

The context-limit error message now gives actionable advice when auto-compact is disabled. Previously, when conversations ran out of context window space with auto-compact turned off, the error gave no hint as to why compacting didn't happen. The system now explicitly warns you that auto-compact is off and directs you to run /config to turn it back on. Like a piece of luggage alerting you that its built-in vacuum compression valve is switched off before declaring that it cannot fit another shirt.

Vim mode preserves NORMAL mode and cursor position across transcripts and panels

Vim mode now reliably preserves NORMAL mode and your exact cursor position across UI toggles. Previously, pressing ctrl+o to toggle the detailed conversation transcript or closing an open panel would reset your Vim mode state and lose your cursor placement. The editor now remembers your active NORMAL mode state and cursor coordinates throughout these view transitions. Like looking up an appendix note or closing a sidebar on an e-reader while your reading cursor and bookmark stay locked precisely onto the sentence you were reading.

Expanded task list (ctrl+t) stays open when resuming sessions with unfinished tasks

The expanded task list (ctrl+t) no longer collapses on session restart if you still have active tasks. Previously, whenever you resumed or relaunched a session with unfinished tasks, the task list UI always defaulted to a collapsed state. It now properly starts expanded so you immediately see the status of all pending items upon resumption. Like returning to your desk to find the active task whiteboard still wide open, rather than having to manually unfold it every single time you walk into the room.

Prompt footer reliably shows update restart notices after background installs

The prompt footer now reliably shows the "Update installed" restart banner after background auto-updates. Previously, when an update finished installing quietly in the background, the footer notice failed to pop up, leaving you in the dark that a restart was needed to activate the new version. The notification now appears as expected so you know exactly when to restart and enjoy the latest release. Like a retail store finishing a store refresh and lighting up a "Renovations Complete — Please Re-enter" sign at the register, instead of wrapping up in silence.

Remote Control claude rc applies enterprise gateway checks consistently at startup

Launching Remote Control via claude rc now performs the exact same enterprise-gateway availability check as interactive startup. In corporate environments, standard interactive sessions verify gateway accessibility right at startup, but claude rc previously skipped this step, leading to inconsistent behavior. The check is now unified across both entry points to ensure reliable connectivity under enterprise policies. Whether you press Start on the washing machine or start it remotely from your phone, it first checks that the water supply is available.

VS Code extension stops erratic tab jumping during window reloads and restores

VS Code users with multiple Claude panels open will no longer experience phantom focus jumping when reloading or restoring windows. Previously, restoring a workspace containing several Claude tabs caused the cursor focus to spontaneously hop between tabs on its own. Focus is now cleanly preserved upon window reloads. Like reopening a browser window with multiple tabs and having your focus stay locked onto the active tab you were actually reading, instead of flickering erratically between them.
