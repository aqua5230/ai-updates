Claude Code 2.1.275

Released: 2026-09-17

Release notes

FEATURE

A Send-Now Key Flushes Queued Messages, Cloud Session Resume and Vim Cursor Get Precise

While Claude is streaming a long reply, you can now press ctrl+enter (or ctrl+x ctrl+s) at any time to interrupt the current turn and send every queued message at once.

Sent and queued text shows in gray until the model actually receives it. When a cloud session resumes, a stale question that a later message had already superseded no longer lingers in the transcript. And in vim mode, switching to shell mode with a dot-repeated shortcut or command no longer nudges the cursor one character to the right.

It's like an ER nurse cutting into the queue to hand over a chart, placing the latest patient update straight on top of the doctor's desk.
FEATURE

Apps Gateway Sign-In Adds a Confirmation Step, Logout Now Clears the Connection Cleanly

When you sign in through the Claude apps gateway (a relay server that forwards and manages enterprise connections), if the gateway names an account, the system now asks you to confirm it before the credential is saved, and /status shows the current account at any time.

It's like swapping badges at a multinational HQ's front desk: the visitor's department number gets checked before they're let in, and the access system revokes it the moment they leave.

Running /logout now also ends the session on gateways that advertise token revocation. And when a corporate network gateway rewrites API error responses while rejecting a beta header, the terminal no longer gets stuck with a 400 error on every turn.

FEATURE

Web Account Skills and Plugins Now Sync to the Terminal, Local Edits Say Clearly How to Save

Skills and plugins you've enabled on claude.

ai on the web now sync automatically into terminal sessions signed in with the same account. To opt out, set these in your config:

{
  "syncClaudeAiSkills": false,
  "syncClaudeAiPlugins": false
}

The ListPlugins tool description has been updated so Claude knows it lists plugins enabled on your account, not ones installed locally.

When you edit a file inside the synced skills folder, the edit result now says clearly that the change isn't saved to your cloud account, with instructions on how to save it. Four dead documentation URLs in the bundled claude-api skill's live-sources table have also been fixed.

It's like signing into an airline account and having your default meal preference and baggage allowance carried over automatically, while a change made only locally is clearly flagged as not yet synced to your membership profile in the cloud.
FEATURE

Plugin Install Can Name a Source Marketplace, Passwords Get Masked and Install Scripts Blocked

Installing a plugin can now name a source marketplace directly with /plugin install <plugin> --marketplace <source>, and the system offers to add that marketplace first if it isn't already added.

A failed marketplace update no longer deletes the local copy by mistake, and passwords or tokens embedded in a URL are now hidden everywhere they'd show up in messages and lists. A bug that showed the wrong server for some git addresses has been fixed. Reloading a plugin loaded from an archive no longer overwrites the extracted files of a running session. Plugins installed from an npm source are now fetched with npm pack --ignore-scripts and integrity-verified, so install scripts can no longer run silently.

It's like an app store running a security scan that strips out install scripts and hides your login credentials from the download URL before a new package is installed.
FEATURE

Artifact Publish Guidance Gets Sharper, Cross-Machine Resume and Routines Update in Place

A bug where Artifact updates failed after a session resumed on another machine or its scratchpad was cleared has been fixed; the page's last published version is now restored automatically.

It's like a shared bulletin-board poster: a member with edit rights updates the same sheet directly instead of pasting up a fresh copy every time.

Publish and read results now say clearly who can open the page and what the owner's Share menu offers, a first publish now asks for a one-word tab icon instead, and a warning appears when the page contains a NUL byte. A shared page you've been given edit access to now updates in place instead of publishing a separate copy. Scheduled and Run now routine runs can automatically save data to, and republish, a page you can edit, without asking each time.

FEATURE

Prompt Cache Hit Rate Goes Up, Telemetry Setup Gets a Warning and Usage Reads Get Shared

When your --system-prompt contains a __SYSTEM_PROMPT_DYNAMIC_BOUNDARY__ line, the text above it is now cached globally.

After a compaction or resume, a restored memory file's age note no longer changes between requests, which had been causing cache misses. A stray closing tag that occasionally appeared in replies has been fixed. Editor windows and non-interactive sessions on the same machine now share a plan-usage read made within the last minute instead of each calling the usage endpoint separately. A startup warning now appears when a configured telemetry headers helper fails to run.

It's like an office's shared phone directory: when a colleague looks up the same extension, they just check the page the front desk flipped open a minute ago instead of everyone calling the switchboard themselves.
BUGFIX

File Search and Reads No Longer Hang, Sandboxed Commands Report Status Correctly

When Grep, Glob, or an @ search returns more results than the cap, the tool no longer hangs or runs out of memory, and system ripgrep now reports an actual error instead of "no matches" after a flood of warnings.

With a custom file-suggestion command or when typing @., file suggestions are no longer buried below MCP (a protocol that connects AI to external tools) resources. When memory pressure keeps a large file from being decoded, the Read tool now reports an error instead of hanging. On Linux sandboxes running zsh, a failed Bash command no longer reports exit code 0, and sandboxes can now write to project directories named hooks/ or config/.

It's like a library catalog system that, even when a search turns up more books than the loan cap allows, still returns accurate results instead of freezing the lookup terminal.
BUGFIX

Session Resume Gets More Fault-Tolerant, Corrupted Records and Startup Crashes Now Recover

Resuming a session is now noticeably more stable.

It's like an archivist flipping through a yellowed, damaged file, smoothing out a torn page and picking the investigation back up without losing the thread.

A saved history containing a malformed task-reminder, @-file attachment entry, or message content block used to make --resume, the resume picker preview, or a resumed background agent fail; all of these now recover properly. Viewing such a conversation in fullscreen no longer crashes when new messages arrive while you're scrolled up. Continuing with --resume or --continue now keeps a conversation's earlier thinking intact, even when a built-in tool it started with has since been switched off by a server-side flag. A crash at launch caused by a malformed value in ~/.claude.json has also been fixed.

BUGFIX

Fullscreen Mode Gets Smoother, Background Notices and Text Selection Get Fixed

In a fullscreen session, a background task's completion notice now closes the open tool row right away and shows up exactly where it arrived, instead of getting buried beneath a long turn's collapsed tool row.

Scrolling up through a large file diff no longer freezes or blanks the screen for several seconds. Typing fast or holding a key while the slash-command dropdown is open no longer triggers an unrecoverable interface error that exits the program. Text selected with the mouse in the claude --resume session picker now actually reaches the clipboard. Responsiveness has also improved when the terminal is slow or paused, so output no longer keeps falling further behind while it waits.

It's like a hall's multi-purpose projector screen staying smooth through fast slide changes, never blanking out just because someone selected text with a mouse or a notification arrived.
BUGFIX

Subagent Message Forwarding Stays Complete, Background Tasks and Rewind Run Stably

When you spawn a subagent inside a forked skill, --forward-subagent-text stream-json output and the SDK no longer drop its forwarded messages.

Running /rewind in a background session no longer restores a zero-filled or truncated file when the session's file-history backups couldn't be fully copied. A command run through stdin on a machine that's run out of file descriptors no longer crashes and restarts the background worker. A self-hosted runner receiving a shutdown signal now waits briefly for the current turn to be reported before it loses the final result. A SubagentStop hook with a specific matcher no longer fires incorrectly for every stopping subagent whose agent type is empty.

It's like a stage manager backstage who, when the closing announcement sounds, waits patiently for an actor still taking a curtain call out front and logs the final result without missing a single bow.
FEATURE

Permission Rules Now Apply Correctly, Hosted Restarts and Image Access Go Smoother

Running /update-config now correctly writes Edit(path) permission rules instead of Write(path) rules that file permission checks don't match.

Pasted and attached images are now saved somewhere Claude can open them directly as files without repeated permission prompts. In a cloud-hosted session, an unanswered permission prompt now stays up after a container restart instead of asking again. Claude in Chrome in auto mode now skips the extension's per-site check for classifier-approved calls, fixing a permission issue with batch browsing after a redirect. When Claude Desktop won't open, the error message now says clearly why and what to do next. The startup notice about a one-off scheduled routine having run since your last session has also been removed.

It's like a security desk that, after a shift-change patrol, still keeps an unconfirmed visitor request on the access board instead of knocking on the resident's door all over again.
FEATURE

[VSCode] Memory Dialog Gets Editing, Diff Review Goes Change-by-Change and Images Send Without Text

In VS Code's Memory dialog, you can now view, edit, or delete a saved memory directly.

It's like a copy editor reviewing a marked-up draft who can accept or reject each polish suggestion paragraph by paragraph, instead of taking the whole revision at once.

The proposed-change diff tab now has accept and reject buttons under each change, so you can review an edit change by change. An attached image can now be sent without typing any text. When Preferred Location is set to Sidebar, a new session now opens in the sidebar instead of always opening another tab. Text contrast in the plan preview and the Hooks and Permission rules dialogs has been fixed under the High Contrast Light theme, and a rare case where text selected in a git-ignored file could be sent after the extension was unresponsive has also been fixed.

FEATURE

[VSCode] Agent Map Visualization Improves, Crash Recovery Status Gets More Accurate

The agent map in VS Code has gotten a solid upgrade: the pill now counts running agents live and turns red after a failure, the main agent stays pinned in view while the map scrolls, and the agent list sorts by state then end time.

After reopening a session, an agent a crash left unfinished is now correctly marked as failed instead of stopped. If a crash happens during a background task and the window reloads, the "Continuing the step" notice now appears correctly and the continue limit no longer resets by mistake. A background agent's completion notice and its status on the map, when it finishes while a tool is running, now also survive a window reload.

It's like an air traffic control radar screen that marks a malfunctioning drone with a red warning light while the main radar itself stays fixed at the center of the screen, so the controller can see everything at a glance.
FEATURE

[VSCode] Conversation Scrolling Improves, Slash Commands Queue and Send Behavior Is Configurable

While Claude is working, a newly sent message now waits neatly at the bottom of the conversation until Claude starts on it.

A slash command typed during that time now runs in order once the current reply finishes, instead of being sent to the model as plain text. When you scroll up to read earlier messages, a streaming reply no longer forces the view back to the bottom; to turn off the jump-to-bottom-on-send behavior entirely, add this setting:

{
  "claudeCode.scrollToBottomOnSend": false
}

A bug where scrolling on send didn't line up with the new reply, and a small jump in the screen while a permission card waits for confirmation, have both been fixed.

It's like a conference room's live notes board that, when someone scrolls up to read earlier remarks, doesn't force the view back to the bottom — letting everyone read at their own pace.
BUGFIX

[VSCode] Session List Timestamps Get Accurate, Forked Conversations Keep Permissions and Renaming Gets Fixed

In VS Code's session list, the sort time now faithfully reflects when the last message was sent, instead of updating just because the window was reopened.

It's like a library card that, even after being re-stamped, still sorts by the actual date of the last checkout — and a forked research note still carries over the original borrowing privileges.

Renaming a running session no longer reverts to the generated name for no reason. Using "Fork conversation from here" or rewinding a conversation now keeps the permission mode you had originally picked. A bug where forking failed on the message right after one sent while Claude was working has been fixed, and the prompt cache clock now shows the correct remaining time after reopening a session with a message sent while Claude was working. Some cloud conversations opening in VS Code as a blank screen has also been fixed.

FEATURE

[VSCode] MCP Server List Gets a Retry, Remote Control Toggle and Plugin Settings Get Safer

When the MCP (a protocol that connects AI to external tools) server list fails to load, the dialog now shows a Retry link so you can reconnect quickly.

If you want to cancel a Remote Control connection, running /remote-control again now turns it off immediately, and it now shows as off correctly after a failed turn-off. The Manage plugins dialog no longer leaks a password or token typed into a marketplace URL, and a bug with invalid install links opening the dialog has been fixed. An empty CLAUDE_CONFIG_DIR left in the environment variables setting no longer makes Claude Code keep its files in the workspace by mistake.

It's like a remote-control toggle that, if pressed again while still connecting, immediately aborts the connection — and a security panel that never exposes the key string sitting on the wire.
FEATURE

[Web] Routine Pages Get a New Shortcut, Notifications and Cloud Domain Settings Get Safer

When a routine link no longer resolves, the error page now shows a "New routine" button so you can create one quickly.

It's like a station's broadcast system that, when a scheduled announcement is paused, clearly tells the stationmaster to flip the resume switch themselves, while also guiding the admin to trim an overly long allow list.

A routine's "paused" and "on hold" notifications are no longer cut off mid-sentence, and the paused-subscription notice now says clearly that you need to turn the routine back on yourself once it resumes. When you ask Claude to edit, delete, or run a routine it didn't create, it now links you straight to that routine's page. A cloud environment with a very long allowed-domains list now fails to save up front with a message on how much to trim, instead of saving fine and failing every session start later. Claude's guidance when a personal account's GitHub access is denied now links directly to the correct account page.

BUGFIX

[Claude Tag] Access Bundles Can Reach Outside Channels, Cloud Monitoring Presets and S3 Get Fixed

In Claude Tag admin settings, an Owner can now set attach conditions for an access bundle, letting it also apply in channels with guests or Slack Connect channels, not just member-only ones.

New presets have been added to the Credentials tab, including Amazon CloudWatch, CloudWatch Logs, Amazon SNS, Google Cloud Monitoring, and Cloud Logging. Datadog connections now add presets for several sites and are limited to Datadog's read and query routes. A bug where S3 uploads from recent AWS CLI and SDK versions failed with a 502 error over an AWS connection has been fixed.

It's like an exhibition hall's badge administrator letting an exhibitor extend a specific device's access into the VIP lounge, while also handing out quick sign-up templates for the major cloud services.
FEATURE

[Claude Tag] Slack Threads Keep Their Identity, Channel Activity Detection and Enterprise Grid Notices Improve

Claude no longer mistakes a channel for inactive and skips untagged messages there while it's still posting in that channel from a routine or a thread.

It's like a cross-team assistant who, after coming back online, still remembers its own display name and chosen model in each separate thread.

After a session refreshes or restarts, a thread's dedicated task name no longer reverts to the default, and a manually switched model no longer silently resets to the channel default. A bug where Claude sometimes replied twice when another app or bot mentioned it in a top-level channel message has been fixed. In Enterprise Grid channels shared across workspaces, the notice now says clearly when no workspace has been set up yet.

FEATURE

[Code Review] Multi-Agent Analysis Stops Dropping Findings, Heavy-Review PRs Get Lighter Merge Checks

When multiple reviewing agents analyze code together, the review report no longer loses part of its analysis just because one agent returned its findings in an unexpected format.

On a pull request with more than 100 Claude reviews, a clean merge from the base branch now correctly triggers the lighter, merge-focused review instead of a full re-review. Every merge used to force a complete re-review, which wasted time; that repeated wait is now gone.

It's like a paper review committee that, on receiving a minor revision with only a few punctuation tweaks from the author, quickly checks just the changed spots instead of reconvening every reviewer for a full re-read.
