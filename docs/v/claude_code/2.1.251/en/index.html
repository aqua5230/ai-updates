Claude Code 2.1.251

Released: 2026-08-28

Release notes

FEATURE

Hooks can act around model switches and inspect resume costs

A band now reports a conductor change to the rehearsal crew: staff can pause or confirm it beforehand, annotate it afterward, and see how stale the music is and how much preparation must be repeated when rehearsal resumes.

If you need to block, confirm, or annotate a model change, you can now use the PreModelSwitch and PostModelSwitch hooks.

A hook is a small program triggered by a specific event. One acts before the switch and the other after it. When an old session resumes, its SessionStart hook also receives the session's staleness and estimated re-cache cost. Caching means keeping previously used material ready for reuse.

FEATURE

Remote Control streams foreground subagent actions live

An open-kitchen counter now shows more than a Cooking sign: you can watch the chef pick up each tool and see its result, while cooks away from the counter still report status only.

A foreground subagent's tool calls and results now stream live to Remote Control clients.

A subagent is an AI helper handling part of the main agent's work. Remote viewers can see what it is doing before the whole task ends. Background subagents remain the default and still show status only, without exposing each tool action.

FEATURE

Spend-limit progress appears in usage and status lines

If you work through a Claude apps gateway with a spend limit, /usage now shows a Spend limit bar, so the distance to that limit is visible rather than buried in a total.

Here, a gateway is the route a host app uses to relay Claude requests. The status line, the live information row at the bottom of the terminal, also gains rate_limits.spend_limit. Developers can use that field in their status-line scripts.

A household electricity meter now marks consumption beside its limit: you can read it at the meter or wire the same reading to a small display indoors. It reports an existing cap; it does not create or change one.
FEATURE

Cost views expose per-session prompt-cache health

Within each session, /cost now lists the prompt-cache hit ratio, misses, tokens re-cached, and whether the cache is warm or cold.

A token is a unit used to process and meter AI text. A prompt cache keeps previously used prompt material ready for reuse. Status-line scripts can read matching data from the new prompt_cache object and present it in their own layout.

A bakery labels how much dough prepared the day before can simply warm up, how much must be remade, and whether the batch is currently warm or cold. Both the counter and a custom sign can read the same preparation status.
FEATURE

Help now names every background-session command

When you forget how to manage a background session, claude --help now lists attach, logs, stop, respawn, and rm.

There is no need to guess the command names. If --resume encounters a background session that is still running, its message now gives the exact claude attach <id> command. Replace <id> with the session identifier shown on screen.

The furniture manual finally labels the parts for attaching, reading logs, stopping, restarting, and removing. Its resume page even tells you which numbered piece to pick up.
BUGFIX

File tools resist symlink swaps after permission checks

Read, Write, and Edit used to check a location inside the working directory, then follow it later.

If that symlink was swapped in between, the file tools could read or write beyond the approved location. A symlink is a shortcut file pointing somewhere else. The check-to-use gap is now closed, so a path cannot become a different destination after approval.

A warehouse picking sheet approves a storage-bin number. Even if someone moves that number plate to another section before pickup, the worker will not follow it beyond the approved warehouse area.
BUGFIX

Grep and Glob honor Read denials through symlink paths

Grep searches text and Glob finds file names.

When either reaches files through a symlinked search path, it now applies the same Read(...) deny rules. A symlink is a shortcut file pointing elsewhere. Previously, direct reading could be denied while searching through that shortcut still reached the same file; that detour no longer changes the decision.

One warehouse picking sheet governs bins reached from the main aisle and bins reached through a connecting aisle. If a number says do not pick, choosing another aisle cannot release the item.
BUGFIX

Workflow checks permission before reading scriptPath

When Workflow receives a scriptPath, it now checks whether the session may read that location before touching the file.

A scriptPath identifies where a workflow script lives. Previously, the tool could read an out-of-scope script and even quote it in an error before the permission check ran. A later denial came too late to prevent that read.

The warehouse picker now verifies that a bin is on the approved picking sheet before opening its box. The worker no longer opens a box in an unapproved section and copies its label into a rejection slip before asking.
BUGFIX

Marketplace plugin commands stay inside their plugin

A command declared by a marketplace plugin must now point inside that plugin's own directory.

A plugin is an add-on that extends Claude. Previously, its path could travel outside the directory, so a command presented as part of the plugin could execute content elsewhere. Such a path is now rejected with a path-traversal error, meaning the path notation tried to escape its allowed folder.

On the warehouse picking sheet, a bin in the plugin section may refer only to shelves within that section. If its written route winds into another area, the warehouse flags the route and does not pick the item.
BUGFIX

Projects cannot enable deep tracing or reroute telemetry

Samples must go to the laboratory selected by headquarters. A branch cannot copy the complete raw record or redirect a lower-level drop-off desk to another lab, whether the destination was fixed by policy or by the host facility.

Project settings can no longer enable detailed beta tracing or raw API-body logging.

Beta tracing is an experimental way to record diagnostic activity; an API body is the original content sent to a service. A lower-scope beta tracing endpoint also cannot bypass an OTLP collector pinned by managed settings or the host app. An OTLP collector centrally receives telemetry data.

FEATURE

Managed sandbox changes now require approval

Server-managed settings that terminate sandbox TLS, route sandbox traffic through a custom proxy, inject credentials, or weaken sandbox isolation now require approval before applying.

A sandbox confines program execution to a restricted area. Server ownership no longer makes these sensitive changes silent. Terminating sandbox TLS means unwrapping the encrypted connection partway; injecting credentials means attaching sign-in secrets to requests automatically.

Even when a landlord manages the lease, changes to wiring, stored keys, or the size of the isolated space must be shown to the tenant and signed again before taking effect.
FEATURE

Sensitive custom headers require approval

When ANTHROPIC_CUSTOM_HEADERS in managed or project settings adds credential, organization or tenant, routing, or API-behavior headers, approval is now required.

A header is an extra field sent with an API request. The named examples include Authorization and Host. This complete JSON can be placed in a settings file; Bearer example is only a sample value: {"env": {"ANTHROPIC_CUSTOM_HEADERS": "Authorization: Bearer example"}}.

A lease addendum about stored keys, the tenant organization, payment routing, or permitted use cannot quietly take effect as an attachment. It must be signed again.
FEATURE

Approval dialogs show only changed managed settings

When managed settings need approval, the dialog now lists only what changed since your last approval.

It no longer repeats the full set of settings you already reviewed and that remain unchanged. Signing in again to the same Claude apps gateway also does not reopen the prompt if its settings are identical.

When a lease is revised, the landlord circles only clauses added or changed since the last signature. Returning to the same office with an unchanged lease does not require signing the whole document again; signatures still cover real changes.
FEATURE

Project env can no longer relocate config or temp directories

The env block in project-level .claude/settings.json can no longer set CLAUDE_CONFIG_DIR, CLAUDE_CODE_TMPDIR, TMPDIR, TMP, or TEMP.

Put these directory choices in the shell, user settings, or managed settings instead, so a project cannot relocate personal configuration or temporary storage. This complete JSON is suitable for user or managed settings; every path is only an example value: {"env": {"CLAUDE_CONFIG_DIR": "/example/config", "CLAUDE_CODE_TMPDIR": "/example/claude-tmp", "TMPDIR": "/example/tmp", "TMP": "/example/tmp", "TEMP": "/example/tmp"}}.

An employee or central facilities team chooses the location of a company locker. Individual departments cannot move that locker by writing a different location in their own manuals.
BUGFIX

Background worktrees stay editable and retain plugin skills

A background session or its subagents can now edit files inside a worktree they created with git worktree add.

A worktree is Git's way to open parallel working copies of one project. Separately, if another Claude Code process refreshes the plugin marketplace at the same moment, a background session no longer starts with no plugin skills and stays that way.

A night-shift coworker can use the bench they assembled, with its tools and materials intact. Even while the day shift reorganizes the tool catalog, the night worker does not lose every specialized tool for the whole shift.
BUGFIX

Remote tmux copying and TTY editor controls work again

When you open a background session in tmux over SSH and select text, it now copies to the tmux buffer just as a foreground session does instead of falling back to OSC 52.

The tmux buffer is the terminal multiplexer's own place for copied text. Editors that open /dev/tty, including emacs -nw and micro, also no longer make Ctrl+G fail with Emacs quit unexpectedly in background sessions.

At the night-shift bench, clipped notes now land in the same desk tray, and the editor's control key is reconnected correctly. Pressing Ctrl+G no longer reports an error.
BUGFIX

Background sessions keep gateway settings and valid allowance

After an interactive session moves to the background with ←, /background, or --bg, it now keeps Vertex or Bedrock gateway environment variables exported by the shell.

Environment variables are settings supplied by the shell before a program starts. These include ANTHROPIC_*_BASE_URL and CLAUDE_CODE_SKIP_*_AUTH; losing them previously made every request fail. On Max plans, claude --bg --model fable also no longer stops for usage credits while the interactive session on the same account still has Fable allowance.

The night-shift coworker inherits both the bench wiring and its available materials. A shift change no longer unplugs the gateway or asks for more supplies while usable stock remains.
FEATURE

Suggestions wait for typing, and unattended sessions stay quiet

While you are typing, plugin or LSP installation suggestions and the offer to make auto mode the default now wait until the input is sent or cleared.

LSP is a language service that helps an editor understand code. The Enter key used to send your prompt can no longer answer a newly appeared suggestion by accident. Unattended sessions, such as agent-team teammate panes, also no longer show the one-time auto-mode offer, where a stray keypress could accept it unread.

A supermarket register waits until every item is scanned and the basket is cleared before showing its loyalty survey. With nobody at the checkout, the survey does not pop up and wait for an accidental tap.
BUGFIX

Fresh installs honor auto mode, and policy can switch it off mid-session

A newly unboxed appliance starts in the mode selected by its account. If a company-wide switch later forbids automatic operation, the appliance returns to its ordinary mode instead of continuing with stale behavior.

On the first launch after a fresh install, an account whose startup default is auto mode now actually starts there rather than in default mode.

Auto mode lets Claude act without asking about each step. If managed setting disableAutoMode arrives while a session is already in auto mode, that running session moves back to default mode without needing a restart.

FEATURE

Effort falls back safely and remembers each model

When thinking is disabled, Opus 5 requests with xhigh or max effort used to fail with effort … is not supported when thinking is disabled.

They now send high instead. Effort is the level of reasoning work assigned to the model, so this unsupported combination no longer stops the request. /effort also saves a separate default for each model and restores that model's own setting when you switch back.

Each gym machine remembers its own weight. If one machine disables its highest-intensity feature, an excessive setting drops to the supported high position instead of preventing the machine from starting.
FEATURE

Thinking-only turns recover, and malformed tool output is discarded

If a model turn produces only thinking and no text, the conversation no longer gets stuck on text content blocks must be non-empty.

Thinking is the model's reasoning work before an answer, and its absence of a text block no longer blocks what follows. If a tool call is malformed, retry now removes the broken output from context rather than retrying with the same bad material. This applies on Bedrock, Vertex, and Foundry.

A copier clears the crumpled sheet before printing again. If it is merely arranging pages internally and has not emitted a sheet yet, it does not mistake that pause for an empty-page fault and lock itself.
BUGFIX

Agent-team answers and replies reach the right teammate

The final relay runner now puts the baton in the team lead's hand instead of merely shouting that they are available. Even when the sender is identified only as a sibling or parent on the same team, the runner can return a reply along the incoming route.

A teammate's final answer now reaches the team lead in the idle notification rather than being replaced by an empty available notice.

Background subagents can also reply to messages from unnamed sibling or parent agents. Previously, from held an agent type rather than a deliverable address.

FEATURE

Desktop relays cross-session messages with clearer senders

After Claude Desktop delivers a message from another session, SendMessage replies to that session ID now travel back through Claude Desktop instead of failing with not reachable.

Claude is also told that the sender is a worker inside the current session, meaning a subagent assigned part of this work, not an unrelated Claude session. While viewing a background-subagent or fork transcript opened from the subagent panel or /tasks, the input placeholder now reads Message @name….

The relay not only returns the baton to the correct lane; its label names the runner from this team. At a split transcript, the exchange zone also displays the next runner's name.
FEATURE

Parallel-agent progress stops piling up and wasting redraws

With many parallel subagents, each per-second progress tick now replaces its predecessor instead of adding another transcript line and making the TUI lag.

A TUI is a text interface operated inside the terminal, and it now keeps only the latest progress view. Interactive sessions also cut redundant UI redraws during turns, reducing CPU use. Neither change hides final work; both avoid repainting transient information that need not remain.

Progress on a whiteboard is updated by erasing the old number and writing the new one, not by adding another sticky note each time. The writer also stops redrawing the whole board when its contents have not changed.
BUGFIX

Italics stop turning into highlighted blocks in screen and tmux

Imagine a projector mistaking italic type for a solid block of color: a gentle emphasis suddenly takes over the whole screen. The display rule now recognizes the type correctly, so italics stay italic.

In GNU screen and tmux sessions whose terminal type is screen, Claude Code used to render italic text as highlighted blocks, including the session recap line.

This fixes the existing display without changing the text itself, so the intended visual hierarchy remains readable in the terminal.

FEATURE

MCP instructions and server names now say exactly what they should

Text shown while managing MCP (Model Context Protocol, the standard that connects AI to external tools) is now more trustworthy.

The menu's copy shortcut explains how the sign-in URL was copied instead of always claiming success, while claude mcp add --header and claude mcp add-json now name the correct transports. MCP server names are also sanitized before appearing in errors, menus, and command results, keeping unwanted content out of those surfaces.

A hardware shop has relabeled its parts drawers: each label must describe the right pickup method and have any smudged text cleaned away, or customers will search the wrong bin.
BUGFIX

Broken additionalDirectories entries are skipped instead of stopping startup

When a barcode scanner meets one damaged label, it should set that parcel aside rather than stop the entire conveyor. Claude Code now skips the bad entry and continues with the rest.

additionalDirectories is the list of extra folders a session may use.

An entry containing a null byte (a non-text marker that does not belong inside a normal path) could previously crash startup. If it came from an SDK host, IDE, or hook (a small program triggered by an event), it could also break /add-dir and later settings updates. Only that malformed entry is now ignored, so one bad value no longer derails the following operations.

BUGFIX

Changing directories no longer overwrites a transcript with the same ID

Changing directories during a session can relocate its transcript (the file that preserves the conversation).

If the destination already held a transcript with the same session ID, the incoming one used to overwrite it silently. There was no warning, and the loss might remain hidden until you searched for the older conversation. That collision no longer overwrites the existing record.

A camera must not write a new photo over an image with the same filename and pretend nothing happened. Preserving the original keeps two memories from collapsing into only the newer one.

This fixes a storage risk during directory changes; it does not introduce a separate transcript system.

BUGFIX

stream-json tool calls no longer lose results when IDs are missing

A laundry shop cannot staple every claim ticket without a number under the first ticket; when the clothes return, their individual records would be impossible to match. Each tool call can now keep its own result.

With --input-format stream-json, a client can inject assistant tool calls.

Calls without a message ID used to be merged into the first call, causing their tool results to disappear. The same failure could occur while resuming older sessions. Missing IDs no longer let later calls and results get swallowed by the first one, preserving the intended mapping in streaming integrations.

BUGFIX

MCP handshakes time out cleanly and reconnect shows the real remedy

SDK and cloud sessions wait for an acknowledgment while connecting to an MCP server.

MCP is the protocol that connects AI to external tools. If that acknowledgment was lost, the whole session could wait forever; it now times out after 70 seconds and marks only the unresponsive server as failed, without inventing a fallback or rerouting the work. In Remote Control, /mcp reconnect also shows the actual remedy when another session disabled that server instead of hiding it behind a generic error.

If a phone rings for 70 seconds with no answer, hang up and note that this line failed. Keep the other calls intact, and write down how to restore the unavailable line.
BUGFIX

Force-stopping a session now stops its Bash processes too

At closing time, a factory cannot switch off only the office lights while production machines keep idling. Hitting the main stop must cut power to the machines still running underneath.

On a self-hosted runner (a machine you operate to execute jobs), a stuck Claude Code session may need to be force-stopped.

Previously the session could disappear while Bash tool processes it started kept running in the background, still consuming the machine or touching the work. The fix terminates those Bash processes with the stuck session, so the stopped state now reaches the work underneath.

FEATURE

Sandboxed Bash output files can no longer be redirected or replaced

When Bash runs in a sandbox (an isolated environment that limits what a program can touch), Claude Code creates an output file and reads it back for display.

The creation and readback path has changed: a sandboxed command can no longer redirect that output elsewhere or replace the file before Claude Code reads it. This strengthens the existing isolation. It does not change the intended Bash output; it makes sure the displayed content truly came from that command.

A print shop keeps a proof under one controlled process from printing to delivery, so nobody can slip a different sheet into the sleeve halfway through. The copy you approve is therefore the proof that was actually produced.
BUGFIX

Arithmetic assignments to integer shell variables now require approval

If a post-office scale treated certain wrapping as proof of free postage, it would never weigh what was inside. Those parcels now stop for a person to check instead of passing on appearance alone.

Bash permission checks (the step that decides whether a command needs your consent) used to auto-approve commands assigning arithmetic expressions to integer shell variables, including OPTIND and RANDOM.

The expression can still contain behavior that should not be skipped merely because its outer form looks like an assignment. Such commands now prompt for approval so you can inspect them first. This tightens an existing decision; it does not ban every integer-variable assignment.

BUGFIX

Claude stops announcing model switches that never happened

When the current Opus model already has a 1M context window (the amount of material a model can consider at once), Claude Code no longer suggests switching to Opus 1M for “5x more context.

” You are already using that capacity, so the tip was both redundant and misleading. A second false announcement affected cloud sessions: merely choosing the initial model at session creation caused Claude to be told that its model had changed. Initial selection is no longer described as a mid-session switch.

Navigation that keeps telling you to turn onto the road already under your wheels makes you wonder whether you are lost. It now checks the route first and stays quiet when you are already there.
FEATURE

Subagent model defaults yield to explicit choices, and Enterprise gets Opus 5

A company may name a default fleet car, while a department's dispatch sheet or an explicit choice for this trip can still select another. The default fills an empty choice; it does not erase a written assignment.

CLAUDE_CODE_SUBAGENT_MODEL now sets the default subagent model instead of overriding everything.

Both an agent definition's model: and a model explicitly chosen for each spawn take precedence over the environment variable; this release does not state which of those two wins over the other. A complete JSON shape is {"env": {"CLAUDE_CODE_SUBAGENT_MODEL": "opus"}}; opus is only an example value. Seat-based Enterprise subscriptions now default to Opus 5, matching other premium plans.

FEATURE

Third-party models now use a Claude Code commit signature

When the active model is not a recognized Claude model, a Git commit (a versioned record of code changes) should not guess a specific model identity.

This commonly happens with a third-party model behind a custom ANTHROPIC_BASE_URL. The default commit trailer is now the exact Co-Authored-By: Claude Code, crediting the tool that performed the work instead of inventing who sits behind it.

A signature stamp should name the office that actually submitted the document. If the ghostwriter cannot be identified, carving a random person's name into the stamp would be false.

Recognized Claude models are outside this change's condition.

BUGFIX

$0 usage-credit limits now point members to their admin

If a manager sets the company petty-cash allowance to $0, the clerk should not merely say that you spent it all. The useful next step is to ask the manager about the arrangement, and the notice now points to the person who can change it.

When Team and Enterprise members run /usage-credits under an organization limit of $0, the old message said the cap had been reached, which sounded like ordinary consumption.

It now suggests asking the admin. The command neither raises the limit nor bypasses organization policy; it correctly identifies this as an administrative setting and gives the member an appropriate next action.

BUGFIX

Claude apps gateway ignores stored Anthropic profiles it does not use

A Claude apps gateway session (one whose requests pass through a central relay) may coexist with a stored Anthropic profile, such as a Console sign-in.

Requests never use that profile, yet Claude Code used to list it as active in /status. When the gateway returned 401, it also retried with the unused profile. Stored but inactive profiles are now omitted from status and from those 401 retries.

An expired membership card may stay in your wallet, but a checkout counter must not list it among valid cards or swipe it again after payment fails.

The change aligns displayed and retry state with the credentials the gateway session actually uses.

FEATURE

Host-managed Bedrock sessions skip unnecessary inference-profile discovery

A branch may need to check its local roster when serving a customer on its own. If headquarters already sends the named worker with the job, the branch need not search that roster again; the two processes start with different information.

Under CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST (where the host manages provider connectivity for Claude Code), such as Claude Desktop, an Amazon Bedrock session may receive a Bedrock model ID or ARN directly.

With that identifier already supplied, the session no longer waits for inference-profile discovery. The change is limited to host-managed sessions given a model ID or ARN; it does not say that every Bedrock flow skips discovery.

FEATURE

Radio and PR badges keep working across providers and without telemetry

/radio is now available on Bedrock, Vertex AI, Foundry, Claude Platform on AWS, and when telemetry (product-usage data sent back to the service) is disabled.

On Bedrock, Vertex, Foundry, or with telemetry disabled, the footer PR badge (the small marker showing GitHub pull-request status) no longer runs gh pr view. It gets credentials through gh auth token, GH_TOKEN, or GITHUB_TOKEN and calls the GitHub API directly.

In a chain, all these special branches can keep their in-store radio playing. But only branches on Bedrock, Vertex, Foundry, or with telemetry disabled use their own display board to read the same progress update directly from headquarters.
FEATURE

Cloud-session errors now explain the real cause and next step

At a suit fitting, the tailor does not just say it does not fit: he points to the seam that split and why; if the cloth is briefly out of stock he asks you to come back next week rather than remeasure you; and when booking the alterations he says which accessories cannot go on that order.

If a session's network proxy drops during a Bash command, the tool result names the host and reason instead of only connection reset.

A transient GitHub failure during cloud-session creation now tells you to retry rather than redo GitHub setup. /schedule also explains that MCP servers configured in Claude Code cannot be attached to cloud routines, instead of merely reporting that no MCP connectors exist.

BUGFIX

Policy-disabled features now report the right reason quietly

When organization policy disables Remote Control (the feature for operating a current session from another device), Claude Code now shows one quiet notice instead of reporting the policy decision as a failure.

Disabling /bug or /share no longer produces a message claiming that /feedback was disabled. When policy or an environment variable truly disables /feedback, tips, /help, and refusal messages also stop recommending it, so users are not sent toward a command that cannot work.

A closed shop should post “closed,” not “equipment broken.” If a service is genuinely unavailable, its signs should not keep inviting customers to use it.
BUGFIX

Ultrareview stops early when its cloud session cannot start

Once a flight is known to be canceled, the airport should announce why immediately rather than leave passengers at the departure area for the full 30 minutes. ultrareview now ends early once launch failure is known.

Running claude ultrareview or /ultrareview requires a cloud session to start behind the command.

If that session failed to start, the command could still wait the full 30 minutes while the user watched it hang. It now stops early and reports the reason. This improves the failure path; when the cloud session starts normally, the existing ultrareview flow proceeds as before.

FEATURE

The native binary shrinks and drops six rarely used highlighters

The Claude Code native binary (a program file the operating system can run directly) is now about 5 MB smaller.

A separate trim removes syntax highlighting for six rarely used languages and makes the binary another 2.5 MB smaller: 1c, gml, isbl, mathematica, maxima, and sqf. Syntax highlighting colors text according to code structure, so the stated removal concerns colored display for those languages; it does not announce removal of every form of language support.

While moving, first compress a large case, then discard six unused sets of decorations. Each step saves its own space, and the two figures should not be silently turned into a new total.
FEATURE

Chrome browser actions now share Claude Code's permission checks

One application used to have two checking forms, forcing people to guess which one to submit. They now merge into one register, where the same clerk checks them by the same rules.

Browser actions from Claude in Chrome now always pass through Claude Code's permission checks (the step that decides whether an action needs your consent).

In sessions with telemetry disabled, those actions previously switched to the Chrome extension's own prompts, so identical actions could present a different approval path. They no longer detour to extension prompts when telemetry is off. This unifies the existing permission process; it does not make browser actions run without review.

BUGFIX

GitLab merge-request worktrees fetch the correct ref directly

For a repository whose origin is gitlab.com, a merge-request number with --worktree --tmux opens a worktree (Git's feature for making a parallel working copy).

Claude Code now fetches the GitLab ref directly; a ref names a particular Git revision. It previously tried a GitHub-style fetch first, but that attempt was doomed because the origin was GitLab. Removing the known-bad attempt lets the existing feature use a fetch method that matches the source from the start.

A repair center should read the parts procedure for the brand printed on the machine. Opening another manufacturer's manual first and waiting for an inevitable miss only adds a detour.
FEATURE

Gateway requirements no longer disable analytics before sign-in

Moving to another branch does not mean you must stop keeping accounts before entering. The ledger stays closed only after the branch registration is complete or when you explicitly ask to stop recording.

Analytics (data used to understand product usage) could previously turn off before sign-in solely because managed settings required gateway login.

The same happened when managed settings could not be read. Neither pre-sign-in condition now disables analytics by itself. Analytics stay off after signing in to the gateway or through DISABLE_TELEMETRY. A complete JSON example is {"env": {"DISABLE_TELEMETRY": "true"}}; true is an example value.

BUGFIX

VS Code fixes provider links and moves Remote Control into a footer pill

A trade-show booth need not block the view with a huge banner all day. A small sign near the floor can appear when needed and point visitors to the next booth; VS Code now treats Remote Control that way.

Its footer pill appears only while Remote Control is on or has failed.

Clicking it opens that session at claude.ai/code, and /remote-control turns the feature on or off. On the sign-in screen, the Bedrock, Foundry, or Vertex button now opens the third-party provider setup section rather than the top of the documentation. One change reduces persistent visual weight; the other lands users at the relevant setup instructions.
