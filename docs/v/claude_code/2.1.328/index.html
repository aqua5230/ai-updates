Claude Code 2.1.328

發布日期：2026-11-19

繁體中文

新功能

Opus 4.6 與 Sonnet 4.6 支援自動模式

在 Amazon Bedrock、Google Cloud 的 Agent Platform 或 Microsoft Foundry 跑任務，常得一直手動點確認。現在連同 Claude 應用程式閘道器在內，這兩款模型都能啟用自動模式，沒指定權限的互動工作階段會直接從它開始。 在第三方平台的規劃模式與 Bash 提示裡，它們也改為跟新版模型一樣使用並提供自動模式。想同時關掉這兩處，只要設定 disableAutoMode 就行。 以前在 Claude Desktop 以外的環境、設了 CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS 又遇到擋 beta 標頭的閘道器時，自動模式每輪都會失敗，這個問題已經修好。

像把智慧門鎖推廣到各家加盟門市，客人沒特別交代就預設開啟快速通關，以前某幾道感應門每刷必卡的毛病也一併修好了。
新功能

mcp_tool 掛鉤支援失敗時阻擋動作

接外部工具前的檢查程式若偶爾出錯，Claude 以前還是會照常執行動作。現在 mcp_tool 這類 hook（特定事件發生時自動觸發的小程式）也支援 "onFailure": "block" 設定，跟指令型和 HTTP 型掛鉤一樣，只要呼叫失敗就會擋下該動作。 想套用這個行為，在設定檔中該 mcp_tool 掛鉤加上 "onFailure": "block" 即可。

就像大樓警衛室的對講機突然斷線時，大門不會自動放行，而是先把訪客留在門外。
新功能

託管 PostToolUse 掛鉤不再處理被拒呼叫

有時操作還沒執行就被拒絕，事後紀錄卻還是多跑了一輪流程。面對這種提早喊卡的情況，託管的 PostToolUse 掛鉤現在不會再啟動。這表示該次呼叫不會留下紀錄項目，也不會經過改寫、阻擋或停止處理。 相對地，PostToolBatch 仍會收到大多數這類呼叫，但不會把它們標記成已拒絕。

好比餐廳櫃檯直接婉拒沒訂位的客人，事後檢討本就不再登記這筆，整批報表雖然看得到紀錄，也不會特別標註被拒。
新功能

用環境變數停用延後工具呼叫的續跑

透過宿主程式跑無互動模式並接續工作階段時，如果先前有工具呼叫被掛鉤延後處理，你不一定想在恢復時讓它繼續跑。現在可以設定環境變數 CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME，就能阻止 claude -p --resume 和 --continue 執行這類延後工具呼叫。 只要在啟動宿主環境時設定這個變數即可。

彷彿暫停播放後重開電影，直接跳過上次卡在片頭還沒放完的預告片，不讓它自己接續播下去。
問題修復

嵌入應用的原則控管與模組重載修正

把 Claude Code 嵌進自家應用或接上閘道器後，原則控管跟擴充模組載入多了幾項防護。 內嵌 Claude Code 的應用程式現在可以開啟原則外掛的 allowManagedModsOnly 選項。不過管理員的託管設定依然擁有最高優先權。 在 Claude 應用程式閘道器這邊，只要原則裡的 maxEffortLevel 填了無效的思考力度，啟動時就會跳出警告提醒。 剛開始新一輪對話就儲存擴充模組時，以前偶爾會在該輪中途就重新載入，這個問題已經修好，改在該輪結束後才重載。

新功能

單次執行與 SDK 加速載入 Git 託管外掛

在全新電腦跑 claude -p、SDK 或 Claude Desktop 工作階段，從 Git 市集派發的託管設定外掛現在會更早完成載入。不過極短的工作階段最多可能延後 30 秒才結束。 針對擁有獨立 Git 儲存庫的託管設定外掛，claude -p 和 SDK 工作階段也會先在背景抓取，留給下一個工作階段直接用。

跟飯店房務趁客人還沒進房前先把備品搬進倉庫一樣，下次入住就能馬上拿到，只是偶爾退房要多等半分鐘收尾。
問題修復

/plugin 介面操作與提示顯示修復

在 /plugin 管理外掛介面裡操作時，下面這幾個誤動作已經修好。 變更還在跑就先退回上一頁時，等存檔或移除完成後以前可能會誤開技能、關掉目前畫面、問你要不要移除別的外掛，甚至連 Esc 都沒反應，這些狀況已經修好。 在「Installed」分頁搜尋不到東西或點到分頁列後，以前打字跟方向鍵會失靈，按住 Enter 不放還會一次關掉好幾個已裝外掛，現在都恢復正常。 外掛彈出的提示訊息偶爾顯示成別款外掛文字的錯亂也已修好，操作清單時不用再擔心誤刪工具或看錯提示。

問題修復

OpenTelemetry 端點檢查與標籤修復

接上 OpenTelemetry 遙測後卻沒收到資料嗎？現在只要負責送出資料的匯出元件沒有設定目標網址、資料很可能遺失，執行 /status 和 claude doctor 都會直接跳出提醒。 在 OTEL_RESOURCE_ATTRIBUTES 環境變數裡，以前只要有一筆格式寫錯，其他正常的標籤都會跟著從指標、事件和追蹤區段裡掉光。現在已經修好，只會略過寫錯的那一筆。

就像寄出貼了一整排地址條碼的包裹，以前少一個字整張單子就退回，現在不光會先檢查收件地址有沒有填，還只劃掉寫錯的那行字。
問題修復

Token 用量統計與額度耗盡錯誤更準確

檢查畫面上耗費的 token（AI 處理與計費的文字單位）數字，以前常因為漏算或重複計算而失準。 等待圖示和子代理的計數以前會在思考時停住不動、漏掉非串流回覆，還把重試的回覆重複算兩次，這些都已修好。 使用 1M 上下文模型時，/usage 的外掛總計以前會卡在 2,000 tokens。沒選模型時 /usage 和 /plugin 的預估數字也會偏低，現在都會如實計入。 如果回覆到一半剛好把額度點數用完，以前錯誤訊息會誤報成速率限制，現在也會顯示正確的用盡原因。

問題修復

專案排程任務存檔不再誤刪其他設定

編輯自動化工作並按下儲存時，最怕原本安排好的其餘項目跟著消失。以前在第三方平台、或關掉遙測與功能旗標後，只要排程檔讀不到，存新任務就會把專案裡其他已存任務全部洗掉，這個問題已經修好。 如果排程檔裡某一條任務不小心打了錯字，以前下次存檔時那條任務會直接被刪掉，現在也不會再發生。

問題修復

修正閘道器連線逾時環境變數無效問題

連向閘道器、自訂網址或雲端平台時，以前就算你調高了 CLAUDE_STREAM_IDLE_TIMEOUT_MS，閒置連線還是會在 5 分鐘就被切斷。這個問題已經修好，現在這個設定能正常延長等待上限。

問題修復

第三方平台工具輸出過大不再中斷對話

第三方平台上的 Claude Desktop 一般工作階段（排程任務除外），碰到超大量的工具回傳資料以前可能會直接跳出「Prompt is too long」並徹底中斷。這個問題已經修好，現在遇到這種狀況會自動略過最大的幾筆工具結果，讓工作階段可以接續往下談。

問題修復

第三方平台下的 MCP 工具結構相容修復

連上第三方平台或關掉遙測與功能旗標後，以前有些 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）工具會莫名消失或拖垮整筆請求。 當工具的輸入格式定義以 anyOf、oneOf 或 allOf 開頭時，以前會整顆工具不見，現在已經修好並能正常出現。 如果某個工具的輸入格式本身無效，以前會害整筆請求跟著失敗。現在只會先把該工具排除，並告訴 Claude 排除的原因。

新功能

MCP 封鎖清單擴及雲端與自架執行器

團隊明明在 deniedMcpServers 裡填上 claude.ai <名稱> 擋掉特定連接器，換個環境跑卻怕設定失效。現在這條禁令會一併套用到雲端與自架執行器的工作階段。 不管是切換到雲端對話還是交給自架執行器跑任務，被列入這類格式的連接器都不會再被接上。

如同在健身房本店把某張會員卡設為停用後，限制同步套用到線上預約與所有分館閘門，換個入口也刷不進去。
問題修復

修正雲端平台誤關子代理思考力度問題

在 Bedrock、Google Cloud 的 Agent Platform 或 Foundry 執行任務時，你可能會發現派出去的助手突然不再深度推理。這是 2.1.327 版的退步現象：只要這些服務拒絕了進度摘要的思考力度設定，整個工作階段裡子代理模型的設定就會跟著被關掉。這個現象已經修好，不會再被牽連關閉。

新功能

終端機子代理進度摘要改由輕量模型撰寫

在命令列接 Anthropic API 跑長任務時，每次回報進度總覺得太燒額度。現在這份工作改由預設的小型快速模型接手，它會根據簡短筆記來寫子代理進度摘要，關掉遙測時也一樣適用，耗費的 token 數量比以前少很多。 跑多步驟任務看子代理回報進度時，摘要功能照常運作，卻不會再吃掉過多額度。

如同雜誌社先請採訪記者寫幾條短訊，再交給快手編輯彙整成進度簡報，不必勞駕總編輯每分鐘停下來親筆撰稿。
新功能

停用分岔時子代理預設會等下層完成

把 CLAUDE_CODE_FORK_SUBAGENT=0 設起來之後，最怕助手還沒等自己派出去的小幫手收工就先結束。現在在 claude -p、Agent SDK、桌面版和 VS Code 裡，子代理預設都會等待下層任務做完才收尾。 在 claude -p 搭配 CLAUDE_CODE_FORK_SUBAGENT=0 時，背景子代理跟它所等待的整串下層代理，現在共用同一個 10 分鐘的等待上限。如果你有多層接力任務需要跑更久，可以調高 CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS 來放寬上限。

好比大團領隊在遊覽車旁等各小隊各自逛完回來集合才發車，整團共用同一張十分鐘的停車券，行程太長就得先加買停車時數。
新功能

同時啟動多個隊友更不易鎖定衝突

一次叫起好幾個同行程內的代理隊友開工，以前常因為彼此搶著鎖定檔案而跳出「Lock file is already being held」失敗。現在這類失敗少了很多。

像幾位泳將同時在池畔準備熱身，以前搶同一個更衣室門鎖常卡在門外，現在排開動線後多數都能順利下水。
新功能

Code Mode 速度與 MCP 連線快取改善

在自動模式或略過權限模式下用 Code Mode 連續跑腳本，反應速度變快了，因為大多數腳本結束後不再硬等 0.75 秒。 工具說明文字也寫得更精簡，能幫你省下 token。 開新工作階段連著 MCP 伺服器時，提示詞快取（把查過或算過的結果暫存起來直接用）的效率提升了。只要有伺服器還在連線或清單有變動，Claude 都會即時得知。 前一支腳本還在跑時才連上的 MCP 伺服器，以前在自動或略過權限模式下執行下一支腳本常會呼叫失敗，這個問題也已經修好。

新功能

Code Mode 即時顯示輸出與失敗線索

跑比較久的 Code Mode 腳本，不用再面對空白畫面乾等結果。執行期間畫面上現在會即時秀出腳本正在跑哪個指令與目前的輸出內容。 腳本裡的編輯操作如果剛好沒改動到任何字元，現在不會再因此喊停。若編輯比對失敗，Claude 也會收到實際相符或最接近的位置線索，方便立刻修正。 萬一腳本中途出錯失敗，Claude 也會清楚知道當下還有哪些工具呼叫正在執行中。

像用滾筒洗衣機時透過透明門板看得到內槽在轉，哪一關卡住也能立刻看出卡在哪裡，不用猜是不是當機。
問題修復

Code Mode 腳本語法相容與失敗回報修復

寫 Code Mode 腳本常碰到的語法拒絕與報錯陷阱，這版一併修好了。 以大括號 { 區塊開頭的合法腳本，以及在最外層同時使用 await 和 return 的腳本，以前會被直接拒絕執行，現在都能正常通過。 前一支失敗的腳本若沒成功賦值，下一支腳本以前會默默把該頂層變數當成 undefined 拿來用，現在不會再這樣混用。 當指令失敗且長輸出被截斷時，腳本現在也會明確收到輸出已被裁切的通知。

問題修復

Code Mode 接續對話與檔案權限修復

在 Code Mode 接續舊工作階段或叫用子代理，幾項漏掉狀態的錯誤已經修好。 從 claude --resume 選單挑出工作階段後，在自動或略過權限模式下腳本現在會正常進背景執行。同一則回覆跑過多支腳本再接續時，已載入的技能、掛鉤脈絡與核准權限時附上的備註也不會再遺失。 從選單恢復對話或在需要詢問權限的模式中，若腳本被中斷，Claude 現在會確實收到被截斷的通知。 用 @ 提及的小檔案即使先被腳本讀寫過，還是會正常附加。唯讀子代理也不會再拿到它們根本不能呼叫的 write() 與 edit() 工具。

問題修復

Code Mode 權限等待與背景任務修正

在 Code Mode 搭配互動確認或背景服務一起工作，現在秩序更穩了。 在非自動或略過權限模式下，遇到權限詢問、規劃核准或提問視窗開著等了 10 分鐘，腳本不會再直接被喊停。 按完 Esc 再接著打 /model 這類指令，Claude 不會再自己搶先開啟新一輪對話。 在自動與略過權限模式下啟動開發伺服器，Claude 現在會被指示把它們當成能在 /tasks 看到的背景任務來跑。系統提示也補齊了只有你要求時才跑工作流，以及 /config 裡設好的工作流大小上限。

問題修復

Windows 版 Code Mode 釐清殼層環境差異

在微軟系統上寫自動化腳本時，有時會遇到指令跑起來跟預期不一樣的狀況。現在 Claude 執行 Code Mode 時會清楚掌握兩項殼層環境差異。它會知道腳本的殼層指令是在 Git Bash 裡跑的，而且在 PowerShell 環境中，別名會蓋過同名函式優先執行。

好比到陌生城市開車前先弄清當地的單行道與速限標誌，照著真實路況轉彎就不會老是走錯。
新功能

Code Mode 輸出不再觸發提示詞前掛鉤

Code Mode 執行腳本產生的輸出內容，現在不會再觸發 UserPromptSubmit 掛鉤，就連管理員設的託管掛鉤也一樣略過。 如果你原本靠這個掛鉤來過濾或遮罩腳本輸出裡的敏感資料，現在要改用執行後觸發的 PostToolUse 掛鉤來改寫工具輸出內容。

換個畫面看，報社調整校對流程後，發稿櫃檯不再回頭審查已經印出來的樣張，想遮蔽敏感字句得改在出廠前的裝訂站動手塗改。
新功能

跨工作階段傳訊的連線與擋訊提醒改善

讓不同工作階段互相傳訊時，現在更容易掌握訊息去向與失敗原因。 如果訊息來自略過權限確認的工作階段，可能會被雲端工作階段攔截或丟棄，畫面現在會先跳出警告。用 claude -p 純文字模式時，標準錯誤輸出也會提示是哪則訊息被擋下以及如何放行。 找不到雲端工作階段或另一台電腦時，Claude 會說明是因為還沒開啟 Remote Control（遠端控制功能）。 剛啟動或標題含有 @ 的雲端與遠端控制工作階段，從開啟遠端控制的對話傳訊過去不再連不上。Claude 也不會再誤以為雲端永遠無法回覆，而是會得知何時能等回信及改用哪種方式取回結果。

問題修復

遠端控制的狀態與差異顯示修復

打開 Remote Control 盯進度，這幾處誤報狀態與漏顯示的問題已經修好。 斷線後不再一直重複跳出同一則斷線訊息，也不會叫你重試一個根本無法重連的工作階段。剛開啟遠端控制時，原本閒置中的桌面版或 VS Code 工作階段也不再誤顯示成正在執行。 由編輯器擴充套件或其他 SDK 應用啟動的工作流，即使在最後一次有進展超過 1 小時後才打開遠端控制，執行中的代理依然會正常列出來。 指令切換進另一個程式庫後，以前 /diff、遠端控制的變更面板和編輯旁的差異對照常會漏掉已提交的修改，現在也會完整顯示。

問題修復

雲端與遠端對話重連與清除的穩定度修復

FEATURE

mcp_tool Hooks Can Block Actions on Failure

When a pre-tool check occasionally errored out, Claude still went ahead with the action. Now mcp_tool hooks (small programs triggered automatically by specific events) also support "onFailure": "block", blocking the action whenever the call fails, just like command and HTTP hooks. To enable this behavior, add "onFailure": "block" to that mcp_tool hook in your config file.

When a building security desk's intercom suddenly drops out, the gate doesn't automatically wave visitors through—it holds them outside instead.
FEATURE

Managed PostToolUse Hooks Skip Refused Calls

Sometimes an action is refused before it ever runs, yet post-action logging still goes through an extra pass. For calls cut short like this, managed PostToolUse hooks no longer fire. That means the call leaves no log entry and goes through no rewrite, block, or stop handling. By contrast, PostToolBatch still receives most of these calls, though without marking them as refused.

Picture a restaurant host turning away a walk-in guest without a reservation: the post-shift log skips that entry altogether, and while the batch report still lists the record, it won't flag it as refused.
FEATURE

Disable Resuming Deferred Tool Calls via Env Var

When running non-interactive mode through a host program and resuming a session, you may not want a tool call previously deferred by a hook to run upon resume. You can now set the CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME environment variable to prevent claude -p --resume and --continue from running those deferred tool calls. Just set this variable when launching the host environment.

More accurate checks and answers for shared artifact access

After publishing work or placing it in a shared folder, asking Claude who could see it used to often return the wrong answer. After reading an artifact (a standalone output file created by Claude) in a shared folder or publishing one to another organization, Claude previously mislabeled it as private. When everyone in the folder could open it, Claude also often claimed only named people had access, and these mistakes are now fixed. Now, when asked who can open a published artifact, Claude checks permissions again directly instead of repeating the old answer from the last publish.

At a company front desk, asking who can view a file in a shared drive now prompts the clerk to check the latest access roster instead of reading off an old sticky note.
FEATURE

Computer use approval dialog shows per-app permissions

Before letting Claude control your screen and keyboard, the computer use approval dialog is now clearer, listing the access level granted to each app and using plainer warning text.

Lending your phone to a relative no longer comes with a vague "full-device access" consent form; it spells out separately that photos can be viewed while banking apps are off-limits, with warnings written clearly.
BUGFIX

VS Code held-message notices and UI error fixes

When running Claude in the VS Code extension, held-message notices, permission buttons, and tool error messages are all much clearer. When a message from another session is temporarily held, a notice pops up with a direct link to the settings file that can allow it. When the panel is short or a command, URL, or description is very long, the "No" button, reply field, and title in the permission prompt are no longer cut off. Failed or blocked tool calls now show the full reason instead of appearing blank or truncated. When the Glob and Grep search tools return an error, error lines are no longer counted toward the number of search results.
