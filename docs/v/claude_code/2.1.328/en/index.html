Claude Code 2.1.328

Released: 2026-11-19

Release notes

FEATURE

Auto Mode Support for Opus 4.6 and Sonnet 4.6

Running tasks on Amazon Bedrock, Google Cloud's Agent Platform, or Microsoft Foundry often meant clicking through manual confirmations. Now, including on the Claude apps gateway, both models support auto mode, and interactive sessions without a specified permission mode start in it. In plan mode and Bash prompts on third-party providers, they now use and offer auto mode just like newer models. To turn both off, set disableAutoMode. Previously, outside Claude Desktop with CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS set behind a gateway that rejects beta headers, auto mode failed on every turn; that issue is now fixed.

Think of rolling out smart door locks to franchise stores: guests get express entry by default unless they specify otherwise, and those finicky sensors that jammed on every swipe are fixed too.
FEATURE

mcp_tool Hooks Can Block Actions on Failure

When a pre-tool check occasionally errored out, Claude still went ahead with the action. Now mcp_tool hooks (small programs triggered automatically by specific events) also support "onFailure": "block", blocking the action whenever the call fails, just like command and HTTP hooks. To enable this behavior, add "onFailure": "block" to that mcp_tool hook in your config file.

When a building security desk's intercom suddenly drops out, the gate doesn't automatically wave visitors through—it holds them outside instead.
FEATURE

Managed PostToolUse Hooks Skip Refused Calls

Sometimes an action is refused before it ever runs, yet post-action logging still goes through an extra pass. For calls cut short like this, managed PostToolUse hooks no longer fire. That means the call leaves no log entry and goes through no rewrite, block, or stop handling. By contrast, PostToolBatch still receives most of these calls, though without marking them as refused.

Picture a restaurant host turning away a walk-in guest without a reservation: the post-shift log skips that entry altogether, and while the batch report still lists the record, it won't flag it as refused.
FEATURE

Disable Resuming Deferred Tool Calls via Env Var

When running non-interactive mode through a host program and resuming a session, you may not want a tool call previously deferred by a hook to run upon resume. You can now set the CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME environment variable to prevent claude -p --resume and --continue from running those deferred tool calls. Just set this variable when launching the host environment.

It feels like resuming a paused movie and skipping past a half-played trailer stuck at the start so it doesn't keep playing on its own.
BUGFIX

Policy Controls and Mod Reload Fix for Embedded Apps

Embedding Claude Code in your own app or connecting it to a gateway now comes with several safeguards for policy control and extension mod loading. Apps that embed Claude Code can now turn on the policy plugin's allowManagedModsOnly option. However, an admin's managed settings still take top priority. On the Claude apps gateway, if a policy sets maxEffortLevel to an invalid effort level, a warning appears at startup. Saving an extension mod right after a new turn begins used to occasionally reload it mid-turn; this is fixed so it reloads after the turn ends.

FEATURE

Faster Git Managed Plugin Loading in One-Shot Runs and SDK

In claude -p, SDK, or Claude Desktop sessions on a fresh machine, managed-settings plugins distributed from a Git marketplace now finish loading sooner. However, very short sessions may take up to 30 seconds longer to exit. For managed-settings plugins that have their own Git repository, claude -p and SDK sessions also fetch them in the background for the next session to use right away.

Much like hotel housekeeping stocking the supply closet before guests arrive, the items are ready at check-in, though checkout can occasionally take half a minute longer to wrap up.
BUGFIX

/plugin UI Navigation and Toast Fixes

Several misbehaviors in the /plugin management interface have been fixed. Going back while a change was still running could previously reopen a skill, close the current page, ask to uninstall the wrong plugin, or even ignore Esc once the save or removal finished; all of these are now fixed. On the "Installed" tab, typing and arrow keys used to stop working after a search with no results or clicking the tab row, and holding Enter would turn off several installed plugins at once; both now work normally. A mix-up where a plugin's toast notification occasionally showed another plugin's text is also fixed, so you no longer have to worry about deleting the wrong tool or misreading a prompt while browsing the list.

BUGFIX

OpenTelemetry Endpoint Notice and Label Fix

Connected OpenTelemetry telemetry but not seeing any data? Now whenever the exporter responsible for sending data has no endpoint configured and data would likely be lost, both /status and claude doctor show a notice. In the OTEL_RESOURCE_ATTRIBUTES environment variable, a single malformed entry previously caused all other valid labels to be dropped from metric points, events, and spans. This is now fixed so only the malformed entry is skipped.

Imagine mailing a parcel covered in address barcodes: previously a single missing character got the whole label rejected, whereas now it checks whether a recipient address is filled in and only crosses out the mistyped line.
BUGFIX

More Accurate Token Counts and Credit Exhaustion Errors

Checking the token (the text units AI uses for processing and billing) counts on screen used to be inaccurate due to missed or double-counted entries. Counts on the spinner and for subagents previously froze while thinking, missed non-streamed replies, and double-counted retried replies; all of these are now fixed. On 1M context models, the /usage plugin total previously stopped at 2,000 tokens. Token estimates in /usage and /plugin when no model was picked were also too low, and both now count accurately. If usage credits run out mid-response, the error message previously misreported it as a rate limit, and now shows the actual reason.

BUGFIX

Saving Project Scheduled Tasks No Longer Erases Others

When editing an automated task and hitting save, the last thing you want is for your other scheduled items to vanish. Previously, on third-party providers or with telemetry or feature flags turned off, saving a new task whenever the scheduled tasks file couldn't be read would wipe out all other saved tasks in the project; this is now fixed. If a task in the scheduled tasks file had a typo, saving the file the next time used to delete that task outright, which also no longer happens.

BUGFIX

Fix gateway timeout environment variable not taking effect

When connecting to gateways, custom URLs, or cloud platforms, idle connections used to be cut off after 5 minutes even if you raised CLAUDE_STREAM_IDLE_TIMEOUT_MS. That issue is fixed, and the setting now lengthens the wait limit as expected.

BUGFIX

Large tool outputs no longer end third-party sessions

Regular Claude Desktop sessions on third-party platforms (excluding scheduled tasks) used to throw "Prompt is too long" and end for good when encountering oversized tool results. That is now fixed: the largest tool results are automatically left out in those cases so the session can continue.

BUGFIX

MCP tool schema compatibility fixes on third-party platforms

When connected to third-party platforms or with telemetry and feature flags turned off, some MCP (Model Context Protocol, a standard for connecting AI to external tools) tools used to vanish or bring down entire requests. Tools whose input schema starts with anyOf, oneOf, or allOf previously disappeared altogether; that is now fixed and they show up normally. If a tool's input schema itself is invalid, it used to cause the entire request to fail. Now only that tool is left out, and Claude is told why.

FEATURE

MCP blocklist now extends to cloud and self-hosted runners

Teams that add claude.ai <name> to deniedMcpServers to block a connector no longer have to worry about the setting failing in another environment. That restriction now applies to cloud and self-hosted runner sessions as well. Whether you switch to a cloud chat or hand a task to a self-hosted runner, connectors listed in that format will no longer be connected.

Just as deactivating a membership card at a gym's main branch syncs the block to online bookings and every branch turnstile, trying another entrance won't let you swipe in either.
BUGFIX

Fix cloud platforms accidentally disabling subagent effort

When running tasks on Bedrock, Google Cloud's Agent Platform, or Foundry, dispatched helpers could suddenly stop reasoning deeply. This was a regression in 2.1.327: whenever those services rejected the effort setting for progress summaries, the setting was turned off for the subagent's model across the entire session. That issue is fixed and it will no longer be disabled alongside it.

FEATURE

Terminal subagent progress summaries now use a lightweight model

Running long tasks on the Anthropic API from the command line used to burn too much quota on progress updates. Now the default small fast model takes over that job, writing subagent progress summaries from short notes—even with telemetry turned off—using far fewer tokens than before. When watching a subagent report progress during multi-step tasks, summaries work as usual without eating up excessive quota.

A magazine has field reporters jot down a few quick notes and hands them to a fast copy editor to compile the briefing, rather than pulling the editor-in-chief away every minute to write it by hand.
FEATURE

Subagents now wait for child tasks by default when forking is off

After setting CLAUDE_CODE_FORK_SUBAGENT=0, the last thing you want is a helper finishing before the sub-helpers it dispatched wrap up. Now in claude -p, the Agent SDK, desktop, and VS Code, subagents wait for their downstream tasks to finish by default. When using claude -p with CLAUDE_CODE_FORK_SUBAGENT=0, a background subagent and the entire chain of downstream agents it waits on now share a single 10-minute wait limit. If you have multi-stage relay tasks that need longer, you can raise CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS to widen the limit.

Like a tour leader waiting by the coach until every small group finishes exploring before pulling out, the whole group shares one ten-minute parking ticket—if the itinerary runs long, you have to buy extra parking time upfront.
FEATURE

Starting multiple teammates at once hits fewer lock conflicts

Spinning up several in-process agent teammates at once used to frequently fail with "Lock file is already being held" as they raced to lock files. Those failures are now far less common.

Swimmers warming up poolside at the same time used to jam up outside the same locker-room door lock; with their paths staggered, most now make it into the water smoothly.
FEATURE

Code Mode speed and MCP connection caching improvements

Running back-to-back scripts in Code Mode under auto or bypass-permissions mode is faster now, since most scripts no longer wait a forced 0.75 seconds after finishing. Tool descriptions are also written more concisely, saving you tokens. When starting a new session connected to MCP servers, prompt caching efficiency is improved. Whenever a server is still connecting or the server list changes, Claude is notified right away. Previously, if an MCP server finished connecting while an earlier script was still running, calling it from the next script in auto or bypass-permissions mode often failed; that issue is now fixed.

FEATURE

Code Mode shows live output and failure clues

When running longer Code Mode scripts, you no longer have to stare at a blank screen waiting for results. While a script runs, the screen now shows the command being executed and its current output in real time. If an edit inside a script happens to change no characters, it no longer halts execution. When an edit fails to match, Claude also receives clues showing where it actually matches or comes closest, making it easy to fix right away. If a script fails mid-run, Claude is also told which tool calls were still running at that moment.

Watching a front-loading washer through its clear door lets you see the drum spinning and spot the exact step where it stalls, instead of guessing whether it froze.
BUGFIX

Code Mode Script Syntax and Error Reporting Fixes

This release fixes several syntax rejection and error-reporting pitfalls common when writing Code Mode scripts. Valid scripts that start with a { block, as well as scripts that use both a top-level await and a top-level return, were previously rejected outright and now run as expected. When an earlier failed script never assigned a top-level variable, the next script no longer silently reuses it as undefined. When a command fails and its long output is cut off, scripts now receive a clear notice that the output was truncated.

BUGFIX

Code Mode Session Resumption and File Permission Fixes

Several state-dropping bugs when resuming sessions or invoking subagents in Code Mode are now fixed. After picking a session from the claude --resume picker, scripts now run in the background as expected in auto or bypass permissions mode. When resuming a session where one reply ran several scripts, loaded skills, hook context, and notes attached to permission approvals are no longer lost. When resuming from the picker or in a mode that asks for permission, Claude is now reliably notified if a script is cut off. Small files mentioned with @ are still attached properly even if a script read or wrote them first. Read-only subagents also no longer receive write() and edit() tools that they cannot call.

BUGFIX

Code Mode Permission Waits and Background Task Fixes

Working with interactive prompts or background services in Code Mode is now more reliable. Outside auto or bypass permissions mode, scripts no longer stop immediately when a permission prompt, plan approval, or question dialog stays open for 10 minutes. Pressing Esc followed by a command like /model no longer causes Claude to start a new turn on its own. When starting dev servers in auto or bypass permissions mode, Claude is now instructed to run them as background tasks visible in /tasks. The system prompt also now specifies running workflows only when you ask, along with the workflow size limit set in /config.

BUGFIX

Clearer Shell Environment Rules for Code Mode on Windows

When writing automation scripts on Windows, commands can sometimes behave differently than expected. Claude now has a clear picture of two shell environment differences when running Code Mode: it knows that scripts' shell commands run in Git Bash, and that in PowerShell, aliases take precedence over functions with the same name.

Before driving in an unfamiliar city, you learn the local one-way streets and speed limit signs so you can follow real road rules instead of making wrong turns.
FEATURE

Code Mode Output No Longer Triggers Pre-Prompt Hooks

Output produced by Code Mode scripts no longer triggers UserPromptSubmit hooks, including managed hooks configured by administrators. If you previously relied on that hook to filter or mask sensitive data in script output, switch to a PostToolUse hook that runs after execution to rewrite tool output.

Under a newspaper's updated proofreading workflow, the copy desk no longer reviews already-printed proofs, so anyone needing to redact sensitive lines must mask them at the bindery station before pages leave the press.
FEATURE

Better Connection and Blocked-Message Alerts for Cross-Session Messaging

When sending messages between sessions, it is now easier to see where messages go and why they fail. If a message comes from a session that skips permission prompts, a cloud session may hold or drop it, and a warning now appears first. In claude -p plain-text mode, standard error also notes which message was blocked and how to allow it. When a cloud session or another computer cannot be found, Claude now explains that Remote Control is turned off. Cloud and Remote Control sessions that just started, or have an @ in their title, are no longer unreachable when messaged from a session with Remote Control on. Claude also no longer assumes cloud sessions can never reply, and instead learns when to wait for a response and how else to retrieve the result.

BUGFIX

Remote Control Status and Diff Display Fixes

Several false status reports and missing displays when monitoring progress with Remote Control are now fixed. After disconnecting, it no longer repeats the same disconnect message or tells you to retry a session that cannot reconnect. When Remote Control is first turned on, idle Desktop or VS Code sessions no longer mistakenly appear as running. For workflows started by an IDE extension or another SDK app, running agents still appear as expected even if you open Remote Control more than an hour after the workflow last made progress. After a command moves into another repository, /diff, the Remote Control Changes pane, and the diff beside an edit no longer leave out committed work.

BUGFIX

Cloud and Remote Session Reconnection and Clear Stability Fixes

Cloud and remote sessions now hold onto progress and responses more reliably across slow restarts or history clears. When a cloud session saves a message late, resuming the conversation no longer drops its earlier compaction summary or recent messages. Rewinding and running /clear also no longer brings back the cleared history when you reopen the session. When the remote service slows down and triggers a session restart, a waiting permission prompt no longer vanishes and your reply is no longer ignored. If the runner disconnects after a dropped stream is retried, that turn's tool calls and results no longer disappear altogether.

FEATURE

Expanded Hook Labels and Identifiers for Self-Hosted Runners

Managing self-hosted runners (machines you host yourself to run tasks) often requires tagging sessions. claude self-hosted-runner orchestrator adds --hook-label and claude --environment adds --metadata key=value to pass labels to the spawn-runner hook, and claude --environment also fixes --correlation-id not reaching it. Both CLAUDE_RUNNER_SESSION_UUID and CLAUDE_CODE_REMOTE_SESSION_UUID are now set for the session as well as the checkout, post-session, and spawn-runner hooks.

FEATURE

Config Warnings and Monitoring Metrics for Self-Hosted Runners

If you maintain your team's own task-running machines, troubleshooting and rotating keys are now safer, with clearer signals across startup checks, key reminders, and monitoring endpoints. The runner now logs a startup warning when the host settings.json sets a default permission mode that sessions ignore. The setup wizard's key rotation advice is also fixed to warn that revoking a key stops the sessions running under it. The orchestrator's /metrics endpoint adds two new metrics that separate queue wait times for reopened sessions from new ones, and count by cause how many times Anthropic gave up starting a runner for a session.

FEATURE

Self-hosted runner repository folder and clone safety updates

This release adds folder specification and clone safeguards to how self-hosted runners prepare Git repositories. Under --capacity 1, you can use --repository-folder to directly name the repository folder a session uses, replacing the path under the base folder. This path cannot be a symbolic link (a shortcut pointing to another file location). If the repository path a runner pushes to is a symbolic link, it also refuses the session earlier under --capacity 1. Fixed an issue where a temporary disk error could mistakenly delete a kept clone's objects, refs, and commits that existed only there; that start now fails instead. When --capacity is above 1, archiving or requeueing a session while it waits for another session to prepare the same repository now takes effect immediately.

FEATURE

Self-hosted runner GitHub tools and managed Git rules

Permission boundaries and connection stability are now clearer when running tasks and connecting to repositories on your team's own machines. Whenever settings guard Claude's GitHub tools by name, the built-in gh api is now off by default, and requires --use-anthropic-gh true to turn on. If a wrapper script runs claude separately before the session's own claude is up or after it has ended, that process now receives no Anthropic-managed Git access. Two managed Git connection issues are also fixed: sessions no longer lose GitHub access after a script or hook in the session runs claude again, and fetching or pushing now works when the local Git config sets http.proactiveAuth.

BUGFIX

Self-hosted runner poll retries and error reporting fixes

Self-hosted runners no longer drop all sessions or exit silently when facing network filtering, slow clocks, or disk stalls. When a proxy or web filter answers a poll with HTTP 200 and an empty body such as {}, the runner now retries that poll instead of stopping all running sessions. Runners also no longer shut down when a slow or set-back host clock causes a token (authorization credential) to expire. If setup fails after a runner registers, it now deregisters with a reason before exiting, and on-demand runners also report failed starts. A failed start's key error details are also no longer crowded out when a checkout hook or Git prints a lot. The closing post-session hook is no longer skipped when a disk stalls for a few seconds, though on a dead disk a session's end can take 25 seconds longer by default.

FEATURE

Self-hosted runner restart fallback and missing work checks

Recovery for self-hosted runners is now more reliable when resuming old sessions or encountering a damaged config file. Under --trust-workspace false, even if .claude.json is damaged, subsequent starts no longer fail every time. The runner starts on defaults instead, with MCP servers turned off. Resuming a session in a new Claude config directory no longer loses its original task list. If a self-hosted session starts without one of its repositories, Claude is now notified and told why. When resuming an older runner session, Claude also checks whether its earlier work is still there and tells you what is missing.

BUGFIX

Linux clipboard image paste and suspend freeze fixes

Two frustrating clipboard issues on Linux desktops are now fixed. In environments with xclip or wl-copy installed, suspending Claude Code in the background with Ctrl+Z no longer causes pasting text in other apps to freeze. Pressing Ctrl+V to paste a clipboard image no longer misses the image, pastes an old one, or hangs, and now pastes the latest screenshot properly.

BUGFIX

Terminal shortcuts and fast-typing dropped-key fixes

Several issues with dropped keys or misread shortcuts when typing fast or using key combinations in the terminal are now fixed. Pressing Esc at a permission prompt or question and typing straight after it no longer drops Esc easily. In terminals that send Alt as Esc plus a key, pressing an unused Alt or Option key there now counts as declining. In terminals that report the Cmd key, pressing Cmd+letter no longer types the letter into the prompt. Shift+Enter in Konsole outside tmux and ssh, as well as Alt shortcuts on non-Latin keyboard layouts in terminals supporting the kitty keyboard protocol, now work properly again. Pressing Ctrl+C while the ? shortcuts list is open no longer misses the exit warning. During rapid keystrokes, fullscreen Ctrl+R search, the /theme color picker, and searches in /config and /plugin no longer pick the wrong row or drop keys.

BUGFIX

Fullscreen mouse and notification layout fixes

When focusing on a conversation in fullscreen mode, occasional unresponsive clicks, stray characters in copied text, and broken dialog layouts are now fixed. In GNOME Terminal, Ctrl+click on a link no longer opens it twice, side mouse buttons are not treated as clicks, and the first scroll wheel notch in the opposite direction after a pause is no longer ignored. Copying highlighted conversation text no longer includes the left quote bar, loses spaces at line wraps when dragging upward to scroll, or misses words covered under the "Jump to bottom" button. When many background notifications arrive at once, they no longer cut into the top border of an open dialog.

BUGFIX

Slow-connection split paste and command image path fixes

Fixed an issue where a paste or terminal reply split in two over a slow connection would have its second half typed straight into your prompt. Pasting an image file path into a shell command starting with ! no longer turns it into a conversation attachment, keeping it as plain path text.

BUGFIX

Terminal freezes and GNU screen color fixes

Several edge-case issues that froze the terminal screen, dropped colors, or crashed at startup are now fixed. Very long or malformed Markdown no longer freezes the screen, and rare occasional screen freezes are also fixed. Wrong or missing colors when running Claude Code inside GNU screen are fixed. Setting the FORCE_COLOR environment variable to a negative number no longer crashes on startup.

BUGFIX

Fix zsh "not found" error on words starting with equals

When Claude ran Bash commands in zsh containing words starting with =, such as echo ==== or [ a == b ], it used to stop with a "not found" error because =cmd expanded to a command path. This is now fixed, and words starting with = no longer undergo path expansion.

BUGFIX

Fix secret masking crash on low memory

When a machine is nearly out of memory, Claude Code could previously crash while masking secrets. This issue is fixed, so masking no longer crashes under tight memory conditions.

BUGFIX

Fix auto-compaction prompt rebuild and hook timeouts

When a conversation nears capacity and the background process summarizes your history, it previously kept reusing the session's earlier system settings without updating them. Automatic compaction is now fixed to rebuild the system prompt the way /compact does. When compaction runs after a request is refused for being too large, agent hooks (small programs triggered by specific events) previously kept running past their timeout without stopping; this is now fixed as well.

FEATURE

Bash sandbox failure reporting and exclusion updates

Clearer rules now apply when the Bash sandbox fails to start or a hook rewrites a shell command. When the sandbox cannot start, unless you have enabled sandbox.failIfUnavailable (which fails right away if isolation is unavailable) in your sandbox settings, the next Bash command that requires a sandbox is refused and tells you directly that the sandbox is off for this session. If a PermissionRequest hook rewrites a shell command into one on the sandbox exclusion list, it now runs directly outside the sandbox. In the Bash sandbox on Linux, when a branch name is not valid UTF-8, .git/HEAD previously got renamed after every command; that issue is also fixed.

If a sterile workbench breaks down, the operator halts the next step right away and lights up a notice that work has switched back to open air, while tools already cleared to skip the cleanroom simply take the regular hallway outside.
FEATURE

/code-review focuses on bugs with severity labels and fixes

To check your written code for errors, /code-review on most models now reports only bugs and CLAUDE.md rule violations. To also reuse code, simplify structure, or improve efficiency, run /simplify instead. On most models, each review finding is also tagged with one of three severity labels—"Important", "Pre-existing", or "Nit"—and ends the summary with a suggested fix. If there are no issues at all, the list displays "Code review found no issues.".

Emergency room doctors focus strictly on wounds and red-line contraindications while sending cosmetic care next door, and their chart clearly marks urgent cases versus minor scrapes alongside a written prescription.
BUGFIX

/bug confirms before sending and stops showing cancelled

Previously, pressing Enter a few times in a row after typing /bug could send the report right away or even open GitHub. Now /bug explicitly asks "Yes" or "No" before sending, and only sends after you confirm. A bug where the screen mistakenly showed cancelled after a report was successfully sent is also fixed.

FEATURE

Claude in Chrome clarifies it asks before acting

When opening the Chrome extension to let Claude operate webpages, many people worry it might click buttons without asking. The Claude in Chrome welcome screen and /chrome command now explain more plainly that Claude Code asks you before Claude acts on a site. The only exception is when your current permission mode or a rule in /permissions already provides the answer.

A valet service parking your car now posts a clear sign at the gate: the driver checks with you before every turn unless you already signed a standing waiver ahead of time.
FEATURE

/list-agents now shows its list to you alone

When checking which agents are currently in the conversation, the on-screen list is now shown only to you instead of being stuffed into messages sent to the model. After you enter /list-agents, Claude lists the sessions itself whenever it actually needs that list.

Employees can flip through their own contact book to verify names without reading the whole directory aloud to a busy teammate every time they look up a number.
BUGFIX

Fix settings menu back navigation and exit warnings

Several behaviors that caused menus to get stuck or close by mistake when backing out of options or ending a conversation are now fixed. When Pro and Max users are asked whether to share a transcript, pressing Esc now dismisses it cleanly. Pressing Esc on the Bedrock access keys step in /login also goes back to the previous step instead of closing the entire login window. Going back in the /hooks menu no longer loses your place. Running /exit and pressing Ctrl+D now describe running work consistently, and /exit no longer warns about a workflow that has already stopped.

BUGFIX

Fix /goal removing matching Stop hooks

When running a /goal task alongside another skill's Stop hook that happened to use the same wording, /goal previously removed the other Stop hook by mistake or ended early on another hook's result. This issue is fixed, and the two no longer interfere with each other.

BUGFIX

Fix /export writing nameless .txt file on empty name

If you ran /export to save a conversation transcript and accidentally submitted an empty filename, the program previously wrote a file named just .txt. This issue is fixed, so leaving the name empty no longer writes such a file.

BUGFIX

Fix Zed terminal setup overwriting symlinks

When keymap.json is set up as a symlink in the Zed editor, running /terminal-setup used to replace it with a plain file and break the original link. This is now fixed, so your symlink will no longer be overwritten.

BUGFIX

Fix extra review file created when updating GitHub app

Running /install-github-app and asking to update an existing workflow file used to also add a separate code review workflow file. This is now fixed, so asking to update an existing file will no longer create that extra review workflow.

FEATURE

Lower memory use when resuming large and long sessions

Old conversations packed with history or images now resume more smoothly and use fewer resources. Loading times are shorter when resuming large sessions. Memory use is also lower when continuing sessions that contain many images. Memory usage and overall responsiveness are improved in long desktop or SDK sessions running slow commands or tools.

Opening a thick photo album full of pictures no longer means spreading the whole book across the table; pulling out just the pages in front of you leaves the desk much roomier.
BUGFIX

Fix background agent stop status and pasted image display

Several display issues that caused the model to misread state when interacting with background agents or interrupting in the desktop app and SDK hosts are now fixed. After stopping background agents with an SDK interrupt command, the model used to think they were still running, and it will no longer report the wrong status. When clicking "Send now" in the desktop app and SDK hosts to send a message early, a stopped web search is no longer misreported as finding no results. When messaging a background agent with a pasted image, the UI no longer shows your screenshot as a long file path.

FEATURE

Closing a chat with an open question now ends the turn

When using Claude Desktop and the Agent SDK on third-party providers, or with telemetry or feature flags turned off, closing a session while a question is still open waiting for your reply used to let it keep running on its own. Now it ends the turn right away instead of continuing without an answer.

Suppose a house painter asks which shade you want for the wall and you lock the door and head out before replying; the painter now packs up for the turn instead of picking a color and painting anyway.
FEATURE

Mark pasted text on third-party providers and offline telemetry

When you copy a large block of reference material into the chat box, Claude needs to tell that it came from outside rather than being typed by hand. Pasted text is now specially marked for Claude even on third-party providers or with telemetry and feature flags turned off, just like in the official environment.

Handing an assistant a stack of clippings alongside dictated notes works the same way: every clipping now gets a "pasted" stamp in the corner so there is no guessing which lines were pasted in.
FEATURE

More accurate checks and answers for shared artifact access

After publishing work or placing it in a shared folder, asking Claude who could see it used to often return the wrong answer. After reading an artifact (a standalone output file created by Claude) in a shared folder or publishing one to another organization, Claude previously mislabeled it as private. When everyone in the folder could open it, Claude also often claimed only named people had access, and these mistakes are now fixed. Now, when asked who can open a published artifact, Claude checks permissions again directly instead of repeating the old answer from the last publish.

At a company front desk, asking who can view a file in a shared drive now prompts the clerk to check the latest access roster instead of reading off an old sticky note.
FEATURE

Computer use approval dialog shows per-app permissions

Before letting Claude control your screen and keyboard, the computer use approval dialog is now clearer, listing the access level granted to each app and using plainer warning text.

Lending your phone to a relative no longer comes with a vague "full-device access" consent form; it spells out separately that photos can be viewed while banking apps are off-limits, with warnings written clearly.
BUGFIX

VS Code held-message notices and UI error fixes

When running Claude in the VS Code extension, held-message notices, permission buttons, and tool error messages are all much clearer. When a message from another session is temporarily held, a notice pops up with a direct link to the settings file that can allow it. When the panel is short or a command, URL, or description is very long, the "No" button, reply field, and title in the permission prompt are no longer cut off. Failed or blocked tool calls now show the full reason instead of appearing blank or truncated. When the Glob and Grep search tools return an error, error lines are no longer counted toward the number of search results.
