Claude Code 2.1.289

發布日期：2026-10-03

繁體中文

新功能

支援隊友動態派工，外掛事件全程掌握代理身分

當你需要讓多個 AI 代理分工處理專案時，現在系統新增了隊友可呼叫的派工函式 agent.spawn。

在外掛掛鉤（特定事件發生時被觸發的小程式）接收各項事件的過程中，同一位代理的識別碼會全程維持一致，不會中途跳號。查詢清單 $.agent.list() 現在也會清楚列出閒置與等待中等狀態。

跟工地主任調派支援人員一樣，每位工人都持有固定的識別證，看板上也能隨時看清誰正在待命或等候材料。

這讓你在編寫多代理協作流程時，能精準追蹤每一位助手的進度。

問題修復

指令與檔案防護更嚴密，權限檢查不再被繞過

在受管制的環境或沙盒中操作檔案與執行終端機指令時，安全把關變得更周延。

在受管機器上，複合指令內部的阻擋或詢問規則，以前可能會被使用者自行安裝的模組覆蓋，現在安全規則能確實維持效力。透過符號連結（指向另一個位置的捷徑檔）在編輯器中以 @ 提及、變更或選取檔案時，讀取阻擋規則現在會正常發揮作用。當指令前綴帶有變數賦值或展開環境變數時，沙盒的自動放行機制不再漏掉後方的阻擋與詢問指令。使用者安裝的外掛也不再能竄改組織託管的 MCP（讓 AI 連接外部工具的協定）登入工具說明。這些安全邊界問題都已修復，讓各項存取限制徹底落實。

問題修復

程式碼標籤解析不再當機，終端機與成果網頁順暢載入

當你檢視含有特殊標籤的簡短程式碼片段時，畫面不再莫名卡死或崩潰。

以前只要程式碼中包含大量未閉合的 <script> 標籤，或是層層巢狀的 ${ 變數代換，終端機就會直接凍結。發布到線上的產出頁面（artifact）在瀏覽器分頁開啟時，過去也會因為這些未閉合標籤陷入卡死甚至崩潰。

好比碎紙機遇到夾帶特殊膠帶的短紙條，以前容易卡住齒輪停擺，現在能順暢吞吐不再噎住。

這項解析問題現在已修復：終端機不再因上述未閉合標籤或巢狀代換而凍結，產出頁面也不再因上述未閉合標籤卡住或讓瀏覽器分頁崩潰。

新功能

VSCode 已還原可能增加登出頻率的改動

在 VSCode 編輯器中使用 Claude 時，你可能曾遇到帳號無故被登出、寫程式寫到一半被打斷的困擾。

2.1.288 版本對檢查登入狀態的指令 claude auth status 所做的改動，可能讓登出變得更頻繁；現在已還原那項改動，避免使用時被無故登出。

大樓門禁若因一次調整變得過度敏感，撤回那次調整，就是撤回可能讓人反覆重新刷卡的變動。
問題修復

外掛清單更新即時生效，驗證指令不再誤判

當你自行開發或測試外掛套件時，相關管理與驗證指令現在運作得更準確。

從本機資料夾市集安裝外掛時，plugin list、plugin eval 與 plugin update 過去常抓到舊版本，使用符號連結（指向另一個位置的捷徑檔）搭配 --plugin-dir 指定外掛目錄時的即時重載也曾失效。驗證指令 claude plugin validate 以前遇到市集清單時會直接略過外掛，還可能誤判官方市集自家的外掛。

宛如庫存盤點機更新了讀卡程式，掃描本機貨架不再讀取舊標籤，驗收表格也能精準列出每件商品。

現在這些問題皆已修復；使用 --json 時，也不再把沒有問題的 plugin.json 列為問題。

問題修復

外掛介面出錯不再拖垮工作階段，故障元件單獨隔離

在背景或受控模式下執行任務時，畫面上的小外掛即使發生異常，也不會讓整個工作階段（session）直接終止。

以前外掛的非同步常式報錯、零高度區域異常擴張，或是 ui.render 掛鉤寫入的值引發錯誤時，整個對話都會因介面崩潰而被迫結束。現在引擎會自行繪製替代列；若外掛的客戶端元件繪製失敗，也只會獨立回報 ui.fault 故障事件。失敗的元件不再拖垮周圍畫面，也不會在接下來的時間裡一直處於壞掉狀態。

問題修復

終端機排版重疊修正，特殊連結與自訂框線正常繪製

在終端機裡查看外掛面板與文字版面時，文字重疊與元件破圖的狀況都已改善。

以前遇到包含本機網址、@ 符號、大寫網域名稱或 file: 路徑的連結時，面板會呈現一片空白。若外掛使用了終端機不支援的邊框樣式，甚至可能在啟動時直接卡死或閃退。含跳位字元（tab）、多餘的跳脫碼與 C1 控制字元的文字，過去會覆蓋下方文字列。短文字同時含有 tab 與 CRLF 換行時，也會發生相同問題。面板右側對齊的內容也會被關閉標記或 [-] 遮蔽。繪製失敗的頂部橫條不會再短暫擠壓下方的卡片。現在這些繪製問題都已修正，關閉標記與 [-] 也會離終端機邊緣一欄。

新功能

大檔檢視加速開啟，升級載入與錯誤訊息更清楚

當你在外掛面板中開啟龐大程式碼檔案，或剛完成版本升級時，系統反應變得更俐落。

程式碼面板現在會直接以最終寬度完成語法標亮排版，縮短開啟大檔案的等候時間。升級後的首個工作階段（session，一次使用中的連續互動期間）不會再遺漏載入已安裝的模組，全螢幕背景工作對話框開啟時，提示列上方的殘留列也不再卡住。外掛元件繪製失敗且沒有附帶錯誤訊息時，原因欄不再只顯示「Error」或留白。外掛的橫條或面板繪製失敗時，外掛作者看到的錯誤說明會標明模組名稱，並指出沒有繪製任何內容。

English

FEATURE

Support for Dynamic Teammate Dispatching with Full Agent Identity Tracking Across Plugin Events

When you need multiple AI agents to divide tasks across a project, the system now provides an agent.spawn dispatch function that teammates can call.

While plugin hooks (small programs triggered when specific events occur) receive various events, the identifier for the same agent remains consistent throughout and will not skip numbers midway. The query list $.agent.list() now also clearly displays statuses such as idle and waiting.

Just like a site supervisor dispatching support workers, each worker holds a fixed ID badge, and the board clearly shows at all times who is on standby or waiting for materials.

This allows you to accurately track the progress of every assistant when writing multi-agent collaboration workflows.

BUGFIX

Tighter Command and File Protections Prevent Permission Check Bypasses

Security controls are now more thorough when operating files and running terminal commands in managed environments or sandboxes.

On managed machines, block or ask rules inside compound commands could previously be overridden by user-installed modules, but security rules now reliably remain in effect. When referencing with @, changing, or selecting files in the editor via symlinks (shortcut files pointing to another location), read block rules now function normally. When a command prefix includes variable assignment or expands environment variables, sandbox auto-allow no longer misses subsequent block and ask commands. User-installed plugins can also no longer alter the tool descriptions for organization-managed MCP (a protocol that connects AI to external tools) login tools. These security boundary issues are all fixed, ensuring access restrictions are fully enforced.

BUGFIX

Code Tag Parsing No Longer Freezes, Ensuring Smooth Loading for Terminals and Artifact Pages

When viewing short code snippets containing special tags, screens will no longer freeze or crash unexpectedly.

Previously, if code contained many unclosed <script> tags or deeply nested ${ variable substitutions, the terminal would freeze directly. Published online artifact pages also used to hang or crash when opened in browser tabs due to these unclosed tags.

Think of a paper shredder taking short strips of paper with special tape, which previously jammed the gears, but now processes them smoothly without choking.

This parsing issue is now fixed: the terminal no longer freezes from unclosed tags or nested substitutions, and artifact pages no longer hang or crash browser tabs from these unclosed tags.

FEATURE

VSCode Reverts Changes That Could Increase Logout Frequency

When using Claude in the VSCode editor, you may have experienced the frustration of your account unexpectedly logging out and interrupting your coding.

Changes made in version 2.1.288 to claude auth status, the command that checks login state, may have made logouts more frequent; that change has now been reverted to prevent unexpected logouts during use.

If building access control becomes overly sensitive after an adjustment, rolling back that adjustment removes the change that caused people to repeatedly swipe their badges.
BUGFIX

Plugin List Updates Take Effect Immediately with Accurate Validation Commands

When developing or testing plugin packages, related management and validation commands now operate more accurately.

When installing plugins from a local folder marketplace, plugin list, plugin eval, and plugin update often fetched older versions, and live reloading when specifying the plugin directory with a symlink (a shortcut file pointing to another location) alongside --plugin-dir also previously failed. The validation command claude plugin validate previously skipped plugins when encountering marketplace manifests and could misjudge the official marketplace's own plugins.

Picture an inventory scanner with updated reading software, where scanning local shelves no longer reads old tags, and the acceptance sheet accurately lists every item.

These issues are now resolved; using --json also no longer lists valid plugin.json files as problems.

BUGFIX

Plugin Interface Errors No Longer Break Sessions with Isolated Faulty Components

When running tasks in background or controlled modes, small on-screen plugins will not terminate the entire session even if an exception occurs.

Previously, if a plugin's asynchronous routine threw an error, a zero-height region expanded abnormally, or values written by the ui.render hook triggered an error, the whole conversation was forced to end due to an interface crash. Now the engine renders a fallback bar; if a plugin's client-side component fails to render, it only reports a ui.fault error event independently. Failed components no longer disrupt the surrounding screen and will not remain broken over subsequent time.

BUGFIX

Terminal Layout Overlaps Fixed with Proper Rendering for Special Links and Custom Borders

When viewing plugin panels and text layouts in the terminal, text overlap and component clipping issues have been improved.

Previously, panels appeared completely blank when encountering links containing local URLs, @ symbols, uppercase domain names, or file: paths. If a plugin used border styles unsupported by the terminal, it could even freeze or crash upon startup. Text containing tabs, redundant escape codes, and C1 control characters previously overwrote lines below it. The same problem occurred with short text containing both tabs and CRLF line breaks. Right-aligned panel content was also obscured by close marks or [-]. Top bars that failed to render will no longer briefly compress cards below them. These rendering issues are now resolved, and close marks as well as [-] are positioned one column away from the terminal edge.

FEATURE

Faster Opening for Large File Views with Clearer Upgrade Loading and Error Messages

When opening large code files in plugin panels or right after completing a version upgrade, system responsiveness is now sharper.

Code panels now complete syntax-highlighted layout directly at the final width, reducing waiting time when opening large files. The first session (a continuous period of interaction during a single use) after an upgrade will no longer miss loading installed modules, and lingering lines above the prompt bar will no longer get stuck when a full-screen background task dialog opens. When a plugin component fails to render without an error message, the reason column no longer merely displays "Error" or remains blank. When a plugin bar or panel fails to render, the error description shown to plugin authors identifies the module name and notes that nothing was rendered.
