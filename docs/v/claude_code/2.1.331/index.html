Claude Code 2.1.331

發布日期：2026-11-23

繁體中文

新功能

終端機 Code Mode 支援四大雲端平台

企業或開發者透過雲端服務跑終端機工作階段，過去無法開啟 Code Mode。Amazon Bedrock 與 Google Cloud's Agent Platform 現已加入支援。Microsoft Foundry 和 Claude Platform on AWS 同樣可以使用這個模式。

就像家裡換了不同家電力公司供電，插頭插上去後原本的電器照樣運轉，不用為了換供應商重買一整套設備。
新功能

閘道器新增 oidc.groups_jsonpath

身分驗證回傳的群組資料如果包在物件清單裡，現在能直接從符合條件的項目挑出來讀取。管理員在 Claude apps 閘道器加上 oidc.groups_jsonpath 這個鍵，就能用精簡版的 JSONPath（從資料結構挑出欄位的查詢語法）讀取群組。這套查詢語法支援 RFC 9535 標準的一小部分功能。

像收到一長串混合明細的帳單，以前得整份從頭翻找，現在拿一張鏤空板蓋上去，只會露出符合條件的群組名稱。
新功能

claude doctor 新增 API 連線檢測

連不上 API 想查連線狀況，可以執行 claude doctor。這個診斷指令新增了 API 連線檢查區段，會直接告訴你連不連得到 API。能通或失敗時，畫面會附上 HTTP 狀態碼或錯誤訊息；如果沒有執行測試，也會說明跳過的原因。

好比汽車保養廠接上的檢測儀，插上去不只告訴你引擎順不順，還會印出故障代碼，或是直接註明這趟沒測哪一項。
新功能

點擊口述自動停止時會顯示提醒

講到一半才發現麥克風早就停了，語音輸入也可能遇到這種窘境。現在使用點擊開啟的語音口述模式，只要連續 15 秒沒辨識到說話內容，或是達到 2 分鐘單次上限而自動結束，畫面上都會跳出提醒通知。

就像投幣式卡拉 OK 時間到就停止收音並響鈴，現在口述自動停止也會顯示提醒。
新功能

新增環境變數避開代理截斷壓縮回應

公司或團隊的網路代理如果會把壓縮過的模型回應半路切斷，對話常常收到一半就失敗。現在可以設定環境變數 CLAUDE_CODE_DISABLE_RESPONSE_COMPRESSION，要求改送未壓縮的回應內容來避開截斷。不過目前還不建議在自託管執行器（公司或個人自己架設來跑自動化任務的機器）或遠端控制開啟這個選項。

跟寄海運一樣，怕真空壓縮袋被劃破時改用原箱寄出，只是特定路線暫時不適用。
新功能

閘道器支援經代理傳送 IdP 主機名稱

管理 Claude apps 閘道器若開啟 oidc.use_proxy: true，設定檔寫法如下： {"oidc": {"use_proxy": true}} 新增的環境變數（啟動程式時讀取的設定）可設為 CLAUDE_GATEWAY_IDP_CONNECT_BY_HOSTNAME=1。 即使設有 NO_PROXY（略過代理的名單），登入請求仍會把 HTTPS 身分提供者的主機名稱傳給代理。

好比貨運雖然列了「直達免經轉運站」的清單，但貼上這張特別標籤後，遇到加密包裹還是會把收件地址交給轉運站處理。
新功能

模型請求追蹤紀錄補齊用量與模型資訊

給用遙測追蹤服務的管理員與開發者：過去看紀錄時，常看不到實際執行動作、回應的是哪一版或花了多少資源。現在這類追蹤紀錄會補齊操作名稱、實際回應的模型，以及各項用量數據。 統計輸入用量時，提示詞快取（把重複內容暫存起來直接讀取）也會一併算進去。 這類模型請求追蹤紀錄中的輸入 token（AI 處理與計費的文字單位）數量確實包含這塊用量。

跟核對維修工單一樣，以前單子上只寫有派工，現在把執行項目、用了哪台機具，以及包含預備材料在內的耗用量都一併列清楚。
新功能

外掛清單新增可獨立拆裝的選用套件

裝了一個外掛卻被迫綁定一堆用不到的附帶功能，這對開發者與使用者都很困擾。外掛作者現在可以在外掛清單檔加上 optionalDependencies，列出選用的相依外掛。安裝主外掛時這些選用項目會跟著一起裝好，之後你還能隨時單獨停用或移除其中幾個，不會牽連原本的主體。

彷彿買沙發附贈了幾顆抱枕，雖然一起送到家，不想用時隨時可以個別收起來。
新功能

確認選項改把「是」排第一，預設仍停在「否」

執行 /ide 停止自動連線，或在子代理畫面呼叫 /clear、/compact、/rewind，確認視窗的選項順序已經調整。選項清單現在把「是」排在第一行，「否」排在下面，但預設游標依然停在「否」上面。如果照以前的習慣按「下」再按 Enter，現在選到的會是「否」。

好比遙控器把確認鍵和取消鍵上下對調，雖然一開始游標還是停在取消，但照舊按法往下就會選錯。
新功能

調整 PermissionDenied 掛鉤的重試規則

PermissionDenied 這個 hook（特定事件發生時會自動觸發的小程式）回傳 retry: true 後，重試行為現在多了一道把關。Claude 只會在這個被拒絕的呼叫確實是你要求執行的情況下，才重新送出該次呼叫。

跟櫃檯補寄掛號信一樣，經手人得先確認這封信確實是你當初交寄的，才會幫忙再送一次。
新功能

受管理外掛市集日後將預設自動更新

給管理企業或團隊受控環境的管理員：如果團隊裡用受控設定統一列管外掛來源，請留意即將到來的規則調整。在 2026 年 11 月 30 日（含）之後的未來版本，列在 extraKnownMarketplaces 裡的外掛市集將會預設自動更新。如果有特定市集不希望自動升級，記得在該市集的設定項目加上 "autoUpdate": false 來手動關閉。

換成訂報紙來看，過了指定日期就會預設每天自動送達，不想收那一份得先貼上停送通知。
新功能

Windows 登錄檔受管理設定需先檢查再升級

如果你的環境靠系統原則統一派送設定，改版前得先確認裡面沒有填錯。使用 Windows 版且仰賴登錄檔寫入受管理設定的管理者，升級前請先檢查裡面的內容。由於 HKLM 裡的原則設定優先權高於本機的 managed-settings.json，登錄檔裡若有壞掉的設定值，可能讓程式無法啟動。

如同總部發的公告效力大過分店守則，要是總部那張告示印錯字，整間分店當天可能就開不了門。
問題修復

Code Mode 續接工作階段與長輸出修正

終端機的 Code Mode 這次修好了幾項影響執行與輸出的問題。 用 --resume 或 --continue 換別種權限模式接回工作階段，不會再丟失思考過程與提示詞快取；原本從需要詢問的模式起步，腳本仍會沿用該模式的限制。 腳本還在跑時輸入 ! 或斜線指令，現在不會每秒狂送出一次請求。 長腳本輸出被砍掉中間那段的問題已修好，Claude 會拿到完整未裁切文字的檔案路徑。 搭配 --bare 執行時，Claude 現在能正常獲知腳本可呼叫哪些功能。 工具搜尋也顯示更多 MCP（讓 AI 連接外部工具的協定）工具說明，包含限制、格式與預設值。

問題修復

終端機窄矮視窗排版與清單顯示修正

畫面空間拉得很小或壓得很扁時，按鍵提示、選項與文字很容易被裁掉或擠成一團。 窄視窗下的單行工具結果截斷後會補上刪節號。/permissions 的自動模式分頁修掉 Markdown 星號殘留，分岔技能被 hook 擋下的理由也不再印兩次。 /diff 在 24 到 26 行的視窗不會再隱藏按鍵提示或選不到檔案。在尚無提交紀錄的 Git 儲存庫中，以 git add -N 加入的檔案也會列出。 矮視窗初次設定時能看到足夠的佈景主題數量，/usage 等長畫面也不再錯亂。 全螢幕執行 /bug 時，長報告不再蓋住「是」與「否」按鈕，極矮視窗也看得到「是」。 全螢幕的 /cd 與 /add-dir 信任提示改用更少行數顯示選項，啟動提示有大量警告時也會保住資料夾路徑。

問題修復

外掛安裝卡死與更新殘留損毀修復

安裝或自動更新外掛時，幾個容易卡住或漏裝元件的狀況已經解決。 外掛更新如果半路中斷或失敗，不會再留下不完整的資料夾導致之後少掉技能或其他元件。 受管理設定需要人工核准卻無法跳出詢問時，claude plugin install、marketplace add 這類指令不會再毫無回應地卡死。 外掛自動更新通知現在會把順便新裝的相依外掛獨立列出來，跟原本更新的外掛分開顯示。

問題修復

子代理訊息傳遞與工作流代理收尾修復

把複雜工作拆給多個背景幫手平行處理時，以前偶爾會遇到訊息石沉大海，或做完事卻沒關掉資源的狀況。 當 Agent 工具的權限規則擋掉並丟棄傳給已結束子代理的排隊訊息時，Claude 現在會收到明確通知。 像 Agent(model:*) 這類限制子代理模型的權限規則，不會再誤擋傳給本版啟動且未指定模型的子代理後續訊息。 工作流代理交回報告後，它在背景執行的命令殼層（負責解讀與執行指令的程式）與 MCP 伺服器現在會正常結束，不再繼續殘留執行。

問題修復

工具卡死、長回覆逾時與介面凍結修復

遇到連線卡住或等待回應時，終端機現在不會一直傻等甚至整片畫面凍結。 本機或 WebSocket 伺服器回傳格式有誤的訊息時，MCP 工具呼叫不再卡住長達 30 分鐘。 Claude 還在思考卻遇上回應靜止時，雲端工作階段的對話與子代理不再直接失敗，其他環境的長回覆也不再馬上逾時。Claude Code 會自動再重試一次請求。 讀取雲端或網路檔案卡住時，按 Esc 或點擊停止不再得等上約一分鐘甚至更久。 命令列工具收到部分特定回覆時不會再整段凍結，引用的文字也不會無故消失或重複出現兩次。

問題修復

Windows 啟動、安裝與記憶體穩定修復

Windows 版的安裝流程、啟動穩定度與指令反應速度都有改善。 執行 /desktop 不會再抓到舊版 Claude Desktop 安裝檔，就算留有舊版資料夾也不會誤跳更新提示。 登錄檔裡的受管理設定即使包含日文等非 ASCII 字元，現在也能正常啟動。 電腦記憶體快用盡時可能發生的當機問題已經修好。 如果機器上沒有自訂的命令殼層啟動檔，工作階段裡第一道 Bash 指令也會跑得更快。

問題修復

修正部分外掛寫 FAT32 反覆詢權

在 Windows 上開著特定外掛工作階段，要把檔案寫進 FAT32 或 exFAT 格式的磁碟時，以前每寫一次就得重按一次允許。這個問題已經修好，不會再反覆跳出權限確認。

問題修復

修正 Windows 遠端控制漏看新子代理步驟

在 Windows 遠端連線用戶端追蹤任務進度，剛啟動的子代理已經開始工作，畫面上卻沒列出它做了什麼。這個問題已經修好。現在能正常顯示這些步驟。

問題修復

修正無頭模式執行的推播通知狀態誤判

使用無頭模式（沒有終端機視窗介面的執行方式）跑排程等自動化任務時，PushNotification 過去在開跑第一分鐘會回報終端機處於活躍狀態。這個問題已經修好，現在它會改為正確回報是否請求了手機推播。

問題修復

修正 /install-github-app 跳步問題

跑 /install-github-app 找不到任何儲存庫又跳出設定警告後，程式過去會直接跳過選擇儲存庫的步驟。在工作流程清單或登入步驟想按 Esc 退回上一步，過去也按不動。這兩個問題都已經修好。

問題修復

修正對話壓縮遇特定 XML 標籤遺失摘要

長談到一半想幫對話瘦身，如果討論內容剛好引用到某些標記語法，濃縮後的重點以前可能會少掉一截。現在執行 /compact 或自動壓縮時，即使摘要裡出現特定 XML 標籤，內容也會完整保留。

問題修復

修正遠端控制訊息錯位顯示在回覆上方

看到畫面上的文字快寫完、趕緊先送出下一句話時，對話順序以前有時會亂掉。在遠端控制遇到這種情況，剛送出的訊息不會再錯位顯示在該段回覆的上方。

問題修復

修正 Stop 掛鉤漏讀最後回覆的問題

在 Claude Desktop 裡設定用來讀取對話逐字稿的 Stop hook，過去會漏掉最後一則回覆。這個問題已經修好，而且 SubagentStop hook 現在也會等這則回覆出現才執行。

問題修復

修正筆記本特定輸出無法讀取

拿一份包含執行結果的實驗筆記請 Claude 幫忙查看，以前遇到以下輸出會讀取失敗。 輸出為 null（沒有值），現在也能正常讀取。 錯誤輸出沒有 traceback（錯誤發生時的呼叫追蹤資訊），也不會再讓筆記本讀取失敗。

問題修復

修正回溯還原失敗後誤刪檔案的問題

使用回溯功能想把檔案退回先前的狀態，萬一還原步驟中途失敗，程式過去竟然還會把檔案刪掉。這個問題已經修好，還原失敗後不會再誤刪檔案。

問題修復

修正自動模式拒停 /loop 導致繼續觸發

在自動模式下想請 Claude 停止一個 /loop 定時循環，它發出的停止呼叫過去有時會被拒絕，導致下一次排程醒來又繼續執行。這個問題已經修好。

問題修復

修正掛鉤無法跨設定檔儲存技能允許規則

使用 PermissionRequest hook 時，如果想把 Skill(name:*) 這類允許規則存到本機設定以外的設定檔，過去會存不進去。這個問題已經修好，現在可以正常寫入其他範圍的設定檔。

問題修復

修正團隊共用額度阻擋與核准通知文字

被團隊共用群組預算擋住時，「Ask your admin」畫面過去卻會要你申請調高個人上限。如果管理員剛才已經核准了申請，它又會繼續顯示「Request sent」。這兩處錯誤提示都已經修好。

問題修復

修正忙碌時按住說話導致口述中斷漏字

Claude Code 正在忙著處理其他工作時，使用按住說話的語音口述過去會提早斷開，導致漏掉好幾個字。這個問題已經修好，忙碌期間按住口述不再提前中斷或漏字。

問題修復

修正自訂端點回傳無名工具呼叫導致當機

接上自己架設的外部介面時，萬一對方回傳了一筆漏寫名稱的指令請求，整個對話以前會直接崩潰中斷。現在這種無名工具呼叫會改成回報錯誤並失敗，原本的工作階段則會繼續進行。

問題修復

修正 @file#10-12 標記附上整份檔案

提問時只想截取程式碼裡的某幾行來討論，以前系統卻常把整份文件通通塞進對話裡。現在用 @file#10-12 這類標記指定行數時，只會附上第 10 到 12 行的內容。

問題修復

修正貼上成品邀請連結時誤讀的問題

收到別人分享的網址並直接貼進對話請 Claude 查看，它以前會誤判裡面的內容。現在遇到成品邀請連結，它會請你先接受邀請，再貼上該成品本身的連結。

問題修復

修正禁入暫存目錄且磁碟滿的 Bash 啟動

你設定了檔案規則，不讓程式去碰電腦放暫時資料的空間，剛好這塊硬碟又沒有剩餘容量了。以前受沙盒（限制程式存取範圍的隔離環境）保護的 Bash 指令有時還是會無法啟動。現在這種情況下，Bash 指令也能正常啟動。

效能優化

加速螢幕閱讀器模式長工作階段打字反應

依賴語音輔助軟體操作並持續對話很久之後，以前敲鍵盤常會覺得卡頓延遲。現在開啟螢幕閱讀器模式輸入文字時，打字反應速度比以前快了不少，特別是在長工作階段裡更為有感。

新功能

加快新開工作階段的啟動等待時間

剛開完一個工作階段不久又再開新的，現在不會再重新等待載入模型清單。如果工作目錄不在 Git 儲存庫裡，而且底下也沒有 .claude/settings.local.json 設定檔，啟動時也不再浪費時間等 git 回應。

新功能

縮短 /login 與主控台登入連結長度

要在終端機驗證帳號並把網址貼到瀏覽器開啟，過長的登入網址不方便查看。現在透過 /login 或 claude auth login --console 產生的主控台登入連結，變得短了許多。

The context usage indicator no longer disappears after an API error, "Prompt is too long", or a slash command. Messages queued behind a pending /clear command are no longer lost. When you switch models just as Claude's process has ended or while it is still starting, the next message now applies the model you picked. The session list no longer opens every transcript at once, preventing it from slowing down extensions or leaving out sessions in projects with many records.

BUGFIX

VS Code Plugin Manager and Settings Loading Fixes

Several issues that blocked troubleshooting and configuration when managing plugins or reading settings.json to switch models have been fixed. Manage Plugins no longer loses its search box or shows no message when a search has no match, and it now clearly reports when the list of available plugins fails to load. Switching models no longer fails with "Settings file is not valid JSON" when settings.json is empty or starts with a byte order mark. Manage Plugins now loads normally even when Claude Code is slow to start or fails to start, so you can turn off a plugin that blocks startup.

FEATURE

VS Code Connection, Voice, and Sign-In Prompt Improvements

When voice dictation drops or authentication is refused, VS Code now gives more accurate on-screen prompts. If the voice dictation connection drops or never opens, it no longer falsely reports "no speech was recognized" and now clearly states that the connection was lost or could not connect. The conversation panel no longer shows "Something went wrong" when a gateway sends a tool call with no name. When the sign-in screen opens because a request was refused, it now explains why it opened.

BUGFIX

Fix Electron Apps and Extension Tests Failing to Start

Starting Electron apps or extension tests from Claude, a hook, or an MCP server previously failed. This issue is fixed, though any wrapper script, hook, or server that runs VS Code as Node must now explicitly set ELECTRON_RUN_AS_NODE=1.

BUGFIX

VS Code Fix for Blank Tabs After Closing During Startup

In VS Code, closing a tab while Claude was still starting previously caused new Claude tabs opened afterward to stay blank and the side bar to fail to load. This issue is fixed, so reopened tabs and the side bar now display normally.

BUGFIX

Fix Accidental Triggers from Quick Double Clicks in VS Code Panel

When double-clicking quickly, the second click previously could press a newly appeared button or row, or accidentally start a second compaction on the context usage circle. This accidental trigger issue in the VS Code panel is now fixed.

BUGFIX

Fix Leftover Tab Helper Processes When Typing @

Typing @ in VS Code without a browser connected previously left a helper process running in the background per tab. This issue is fixed, and processes are no longer left behind unless Claude in Chrome's service cannot be reached.
