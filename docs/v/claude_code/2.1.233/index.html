Claude Code 2.1.233

發布日期：2026-08-14

繁體中文

GitLab 合併請求可直接開工作樹

同事丟來 GitLab 的合併請求網址時，現在可把網址交給 --worktree，也能在 claude agents 檢視裡直接辨認它。工作樹（worktree，Git 為同一專案開出的平行副本）讓你另開一份地方查看修改，不必離開手邊工作。

這像收到一張待辦房間的門牌；網址一貼，便能走進另一間房核對內容，而非先手抄房號。

合併請求會顯示成 !N，因此清單裡能看出它是 GitLab 的項目。

閘道可把使用者身分交給後端記帳

公司透過 apps gateway 連到 Anthropic 上游服務，又想知道費用算在誰身上時，可選擇開啟 forward_user_identity。這個設定會把已登入使用者的身分放進 headers（隨請求附上的資訊欄位）。再交給閘道後方代替你轉送請求的 proxy。

像包裹經過收發室時附上寄件人卡片，後方的記帳人便能把運費記到對的人名下。

此設定是選用項目；不開啟便不會轉送這份身分資訊。

Linux Bash 可替失控建置設記憶體上限

在 Linux 用 Bash 工具跑建置，若擔心失控的建置拖住工作階段，可選擇設定 CLAUDE_CODE_TOOL_MEMORY_LIMIT。它會替 Bash 指令啟用 memory cgroup（替一組程式設下記憶體界線的 Linux 機制）。

像共用儲物間替一台攪拌機劃出固定容量；它的材料塞滿自己的格子後，不能再占用整間空間，其他人的東西仍放得下。

這是選用支援，目的是避免失控的建置讓整個工作階段停住。

WebFetch 網址快取保存時間可自行設定

同一個 WebFetch 工作階段裡，想調整網址快取保存多久，現在可設定環境變數 CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS。快取（cache，把查過的結果暫存起來直接用）會在工作階段內保存網址查詢結果；這個變數專門調整它的存活時間。

像替已查過的電話簿頁面貼上有效期限標籤，到期前可直接翻那頁，到期後才重新查號。

預設值仍是 15 分鐘，沒有因這項設定而改變。

雲端關機等權限時，不再誤報遺失工作階段

Claude 正等你回應權限提示，雲端環境卻在此時關閉，先前偶爾會把雲端工作階段標成遺失。這次修正針對的正是「等待權限」與「環境關閉」同時發生的情況，也不把環境關閉誤當成工作階段遺失的錯誤依據。

如同櫃檯正等你簽名，辦公室卻先熄燈；現在不會因此把你的案件判成不見了。

之後遇到這種順序，工作階段不會再被錯誤標記為 lost。

MCP 長連線遇逾時不再反覆重開

使用會在固定時間結束長連線的 serverless 主機時，MCP v2 連線先前可能不停重開 subscriptions/listen 串流。MCP（Model Context Protocol，讓 AI 連接外部工具的協定）透過這條串流接收訂閱資訊。

像對講機的通話被建築物規則切斷後，舊作法會不斷重撥同一通；現在不再陷入反覆接通又斷線。

因此，面對會終止長持連線的伺服器，連線不會無止盡重啟。

桌面版與 VS Code 的權限提示會觸發通知掛鉤

你在 Claude Desktop 或 VS Code 裡等權限提示，若設了 Notification hook，先前它可能沒有反應。Notification hook（通知掛鉤，特定事件發生時被觸發的小程式）原本應在需要權限時告訴你。

像門鈴已接好線，訪客按了卻不響；現在有人要求進門時，鈴聲會跟著響起。

這項修正只針對兩個指定環境中的權限提示，讓掛鉤能正常觸發。

Linux 閒置沙盒不再佔滿單一 CPU 核心

Linux 上開著沙盒卻沒有操作時，先前有些閒置工作階段仍會讓一個 CPU 核心維持 100% 使用率。沙盒（sandbox，隔開程式可碰範圍的受限環境）本應在你沒動作時安靜待著，而非持續消耗處理器。

像空無一人的房間裡，風扇卻一直全速轉；現在沒人使用時，不會白白耗住那一台風扇。

修正後，啟用沙盒的閒置工作階段不再出現這個單核心滿載問題。

同名技能遮住內建指令時，別名仍可使用

你在 -p 模式執行，或載入 plugins、MCP 後輸入 /checkup、/review，若使用者或專案技能恰好同名，先前可能看到「Unknown command」。技能（skill，教 Claude 完成特定工作的說明組）名稱相撞時，不該讓內建別名失效。

像社區裡新開一家同名店，舊店的招牌卻被整塊蓋住；現在兩個既有別名仍找得到入口。

這次修正涵蓋 -p，以及 plugins 或 MCP 已載入的情況。

指令參數不會再被當成模板標記重算

技能或指令收到參數後，先前參數內容可能再被展開成 template markers（模板標記，會被程式替換的特殊符號）。這會把原本只是輸入值的文字，再當成另一輪要處理的指示，改變原有輸入的意思。

好比表單收件員已把你寫的姓名放進欄位，卻又把姓名當成填表規則重新解讀。

現在參數代入一次後便保留其值，不會被再次展開成模板標記。

Windows 特殊路徑不能繞過網路路徑檢查

Windows 路徑若用 NT 的 \??\ device prefix 拼寫，先前可能繞過 UNC 路徑驗證，留下 NTLM 憑證外洩風險。UNC 路徑驗證（檢查網路共享位置寫法的安全檢查）原本就該攔住這類路徑。

像大樓正門的證件檢查做得完整，卻有一扇寫法不同的側門沒被納入；現在側門也進了同一道檢查。

這項修正關閉的是透過該特殊前綴造成的 NTLM credential-leak 漏洞。

自架執行器啟動時不再改寫工作樹

啟動 claude self-hosted-runner 時，現在會先建立工作階段分支，且不必改寫工作樹。工作階段（session，一次持續工作的連線與狀態）一開始少了會擋住 agent 啟動的兩次伺服器往返。

像劇團開演前先在後台把分場表放好，不必把整個舞台重新布置完才准演員上場。

因此，這個 runner 的工作階段啟動時間獲得改善，agent 不再被那兩次往返阻住。

閘道轉送上游錯誤原文，方便看懂問題

apps gateway 接到 Vertex、Foundry 或 AWS 上 Claude Platform 回傳的 400 或 413 錯誤時，現在會帶出上游服務自己的錯誤訊息。上游（upstream，請求原本要送往的服務端）說明能讓你看到它實際拒絕的理由。

像客服把倉庫退貨單的原話交給你，而非只說「出問題了」，你才知道該改哪一項。

apps gateway 的自動壓縮錯誤已修正

使用 apps gateway 的 auto-compact 時，這項錯誤已修正。auto-compact（自動壓縮，將較早對話整理得更短以騰出內容空間）是 gateway 替工作階段整理內容的流程。

像整理員把塞滿的資料夾換成精簡摘要，原本卡住的整理步驟現在能完成。

因此，透過 apps gateway 進行自動壓縮時，不再受這項錯誤影響。

外掛驗證可找出技能說明檔格式錯誤

準備檢查 plugin 時，claude plugin validate 現在會查看單獨存在的 .claude/skills 資料夾。它會回報其中 frontmatter（檔案開頭給工具讀取的欄位）無法解析的 SKILL.md。

像出版前先翻開資料夾裡每本說明書的扉頁，哪本的基本資料讀不出來，便直接標給你。

即使 .claude/skills 是裸資料夾而非完整結構，驗證也會納入檢查。

螢幕閱讀器可用數字選擇努力程度

使用螢幕閱讀器調整 /effort 時，選擇器現在會呈現成編號清單，並要求輸入對應數字。螢幕閱讀器（screen reader，把畫面內容讀出聲的輔助工具）需要能循序讀懂每個操作選項與目前選擇。

像語音點餐不必在看不見的按鈕間猜位置，只要聽完菜單後說出菜號。

此外，提示文字和對話框文字不再被裁切，讀到的內容能完整保留。

列印模式會提示未認得的模型 ID

用 print mode 送出 Claude Code 不認得的 model ID 時，現在 stderr（標準錯誤輸出，程式用來報告問題的文字通道）會寫出 [claude-code:unrecognized_model]。這條診斷訊息告訴你請求確實帶了未識別的模型 ID。

像寄件櫃檯在收據蓋上「地址查無」章，而非讓包裹悄悄進入未知路線。

若想不再看到它，可用 modelOverrides 將該模型 ID 對應到已知模型。

非 GitHub 儲存庫不再收到錯誤的 App 設定提醒

你的儲存庫 origin remote 在 gitlab.com 或 bitbucket.org 時，GitHub app 設定提示不再冒出來。origin remote（儲存庫連向遠端來源的位置）既不是 GitHub，就不該叫你設定 GitHub app。

像火車站不會把前往另一座城市的旅客帶到錯誤月台；現在目的地不是 GitHub，便不發那張車票。

同時，enterprise marketplace 提示會涵蓋不是 GitHub 的內部 Git 主機。

較新模型預設不用待辦工具，仍可用環境變數取回

使用 Opus 4.8、Sonnet 5、Fable 5、Mythos 5 或更高版本模型時，TaskCreate、TaskGet、TaskUpdate、TaskList、TodoWrite 這些待辦與任務追蹤工具不再提供。這是既有工具可用範圍的變更，不是新增工具。

像工具箱換了新版內裝，這批型號先把待辦抽屜收起；需要的人仍可把抽屜裝回。

要恢復它們，設定環境變數 CLAUDE_CODE_ENABLE_TODO_TOOLS=1。

Windows Bash 權限調整收回過寬規則

Windows 的 auto mode 對一般 cd <dir> && <command> > file Bash 指令反覆停下要求手動核准，這個 2.1.232 回歸問題已修正。同時，2.1.232 對 Cygwin 風格符號連結與輸入重新導向 < file 的 Bash 權限改動被撤回。

像門禁先把普通的進出與兩種指定通道都攔下；現在普通路線恢復通行，而過寬的兩條規則先收回，等待較精準版本。

較窄的版本會在後續版本回來。

English

Open a worktree straight from a GitLab merge request

When a teammate sends a GitLab merge-request URL, you can now give that URL to --worktree and recognize it in the claude agents view. A worktree is a parallel copy of a Git project, so you can inspect changes somewhere separate from current work.

It is like receiving a room number on a work order: paste the address and walk into that room, rather than copying its number first.

Merge requests appear as !N, making their GitLab identity visible in the list.

Gateway can pass user identity to proxy accounting

If your company connects to Anthropic upstreams through an apps gateway and needs to assign spending to people, it can opt into forward_user_identity. This setting puts the signed-in user's identity into request headers for a proxy behind the gateway.

It is like attaching a sender card to a parcel at the mailroom, so the accountant down the line can charge delivery to the right person.

Leave it off and that identity is not forwarded.

Linux Bash can cap memory for a runaway build

When a build runs through the Bash tool on Linux, you can opt into CLAUDE_CODE_TOOL_MEMORY_LIMIT if a runaway build might stall the session. It enables a memory cgroup, Linux's boundary for the memory available to a group of programs.

It is like giving one mixer a fixed storage compartment: once its ingredients fill that compartment, they cannot take over the whole storeroom, and everyone else's things still fit.

The optional limit keeps a runaway build from stalling the session.

Set WebFetch URL cache lifetime yourself

Within one WebFetch session, you can now set CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS to choose how long its URL cache lasts. A cache keeps a URL lookup result for direct reuse during the session; this variable controls that lifetime.

It is like putting an expiry label on a phone-book page you already checked: use that page until it expires, then look up the number again.

The default remains 15 minutes.

Cloud shutdown during a permission wait no longer loses session

If Claude was waiting at a permission prompt and the cloud environment shut down, a cloud session could occasionally be marked as lost. This fix covers that exact overlap: waiting for permission while the environment closes.

It is like a desk clerk waiting for your signature when the office lights go out; the case is no longer declared missing because of that.

In that situation, the session is no longer wrongly marked lost.

MCP long connections stop reopening after timeouts

With a serverless host that ends long-held streams at a fixed timeout, an MCP v2 connection could keep reopening its subscriptions/listen stream. MCP is the protocol that connects AI to outside tools, and this stream receives subscription information.

It is like an intercom call cut off by building rules, where the old behavior kept redialing the same call; it no longer cycles through reconnecting and dropping.

Such servers no longer trigger endless stream reopening.

Permission prompts trigger notification hooks in Desktop and VS Code

If you use a Notification hook while working in Claude Desktop or VS Code, it may previously have stayed silent for a permission prompt. A Notification hook is a small program triggered by an event and should notify you when permission is needed.

It is like a wired doorbell that did not ring when a visitor pressed it; now the bell sounds when someone asks to enter.

The fix covers permission prompts in those two environments.

Idle Linux sandbox stops filling one CPU core

On Linux, an idle session could keep one CPU core at 100% even when sandboxing was enabled. A sandbox is a restricted environment that limits what a program can touch, and it should sit quietly when unused.

It is like a fan running at full speed in an empty room; when no one is using the room, it no longer consumes that fan for nothing.

Idle sandboxed sessions no longer hit that single-core saturation.

Bundled aliases still work when same-named skills shadow them

In -p mode, or after loading plugins or MCP, entering /checkup or /review could produce “Unknown command” if a user or project skill had the same name. A skill is a set of instructions that teaches Claude a particular job, and a name collision should not hide bundled aliases.

It is like a new shop with the same name covering an older shop's whole sign; now both bundled aliases still have a visible entrance.

The fix covers -p and the loaded plugin or MCP cases.

Command arguments no longer get re-read as template markers

After a skill or command received an argument, its value could be expanded again as template markers: special symbols the program replaces. That treated input text as another instruction to process.

It is like a form clerk placing your written name in a field, then reading the name again as instructions for filling out the form.

Now an argument keeps its value after substitution instead of becoming template markers again.

Windows device paths cannot bypass network-path checks

On Windows, a path spelled with the NT \??\ device prefix could bypass UNC path validation and expose an NTLM credential-leak vector. UNC validation is the safety check for network-share path spelling and should catch such paths.

It is like a building's main entrance checking badges while a side door written differently was left outside the same check; now that side door is checked too.

The fix closes the leak route created through that special prefix.

Self-hosted runner starts without rewriting worktree

When starting claude self-hosted-runner, the session branch is now created without rewriting the worktree. A session is the connection and state for one continuous stretch of work, and its start no longer waits for two server round trips that blocked the agent launch.

It is like placing the scene list backstage before a play, rather than rebuilding the whole stage before actors may enter.

The runner's session starts faster because those two round trips no longer block the agent.

Gateway forwards upstream error message itself

When an apps gateway receives a 400 or 413 error from Vertex, Foundry, or Claude Platform on AWS, it now carries the upstream service's own message. An upstream is the service the request was meant to reach, so its message tells you why it rejected the request.

It is like support handing you the warehouse's exact return slip instead of saying only “there is a problem,” so you know what to change.

Apps gateway auto-compact bug is fixed

A bug in auto-compact on apps gateway is fixed. Auto-compact condenses earlier conversation to make room for more content in a session.

It is like an organizer replacing an overstuffed folder with a shorter summary, so the filing step that was stuck can now finish.

Auto-compact through apps gateway is no longer affected by this bug.

Plugin validation finds malformed skill description files

When checking a plugin, claude plugin validate now examines a bare .claude/skills directory. It reports SKILL.md files whose frontmatter, the fields at a file's beginning for tools to read, cannot be parsed.

It is like opening the title page of every manual in a folder before publication and marking any whose basic details cannot be read.

Validation includes .claude/skills even when it stands alone rather than inside a full structure.

Screen readers can choose effort with numbers

When using a screen reader to change /effort, the selector now appears as a numbered list and asks for a typed number. A screen reader is an assistive tool that reads screen content aloud and needs an ordered way to convey choices.

It is like ordering by voice without guessing among unseen buttons: hear the menu, then say the dish number.

Hint text and dialog text are no longer clipped either.

Print mode flags unrecognized model IDs

If print mode sends a model ID Claude Code does not recognize, stderr, the program's text channel for reporting problems, now writes [claude-code:unrecognized_model]. The diagnostic line tells you the request went out with an unknown model ID.

It is like a mailing counter stamping “address not found” on the receipt instead of quietly sending a parcel onto an unknown route.

Map that ID with modelOverrides to silence the line.

Non-GitHub repositories stop getting wrong app setup tip

If a repository's origin remote is on gitlab.com or bitbucket.org, the GitHub app setup tip no longer appears. An origin remote is the repository's destination for its remote source, so a non-GitHub destination should not ask for GitHub app setup.

It is like a station not sending travellers for another city to the wrong platform; when the destination is not GitHub, it does not issue that ticket.

The enterprise marketplace tip now covers internal Git hosts that are not GitHub.

Newer models hide todo tools by default, with an opt-in return

On Opus 4.8, Sonnet 5, Fable 5, Mythos 5, and newer models, the task-tracking tools TaskCreate, TaskGet, TaskUpdate, TaskList, and TodoWrite are no longer available. This changes the availability of existing tools; it does not add a new tool.

It is like a new layout for a toolbox that stores the todo drawer away for these models, while people who need it can still put the drawer back.

Set CLAUDE_CODE_ENABLE_TODO_TOOLS=1 to restore them.

Windows Bash permission change narrows back overly broad rules

On Windows, auto mode repeatedly stopped for manual approval on ordinary cd <dir> && <command> > file Bash commands; that 2.1.232 regression is fixed. At the same time, 2.1.232 Bash permission changes for Cygwin-style symlinks and input redirection < file have been reverted.

It is like access control stopping ordinary passage and two named lanes; ordinary travel resumes, while the two overbroad rules are withdrawn until a narrower version returns.

A narrower version will arrive in a later release.
