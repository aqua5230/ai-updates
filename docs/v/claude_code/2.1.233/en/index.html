Claude Code 2.1.233

Released: 2026-08-14

Release notes

FEATURE

Open a worktree straight from a GitLab merge request

When a teammate sends a GitLab merge-request URL, you can now give that URL to --worktree and recognize it in the claude agents view.

A worktree is a parallel copy of a Git project, so you can inspect changes somewhere separate from current work.

It is like receiving a room number on a work order: paste the address and walk into that room, rather than copying its number first.

Merge requests appear as !N, making their GitLab identity visible in the list.

FEATURE

Gateway can pass user identity to proxy accounting

If your company connects to Anthropic upstreams through an apps gateway and needs to assign spending to people, it can opt into forward_user_identity.

This setting puts the signed-in user's identity into request headers for a proxy behind the gateway.

It is like attaching a sender card to a parcel at the mailroom, so the accountant down the line can charge delivery to the right person.

Leave it off and that identity is not forwarded.

FEATURE

Linux Bash can cap memory for a runaway build

When a build runs through the Bash tool on Linux, you can opt into CLAUDE_CODE_TOOL_MEMORY_LIMIT if a runaway build might stall the session.

It enables a memory cgroup, Linux's boundary for the memory available to a group of programs.

It is like giving one mixer a fixed storage compartment: once its ingredients fill that compartment, they cannot take over the whole storeroom, and everyone else's things still fit.

The optional limit keeps a runaway build from stalling the session.

FEATURE

Set WebFetch URL cache lifetime yourself

Within one WebFetch session, you can now set CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS to choose how long its URL cache lasts.

A cache keeps a URL lookup result for direct reuse during the session; this variable controls that lifetime.

It is like putting an expiry label on a phone-book page you already checked: use that page until it expires, then look up the number again.

The default remains 15 minutes.

BUGFIX

Cloud shutdown during a permission wait no longer loses session

If Claude was waiting at a permission prompt and the cloud environment shut down, a cloud session could occasionally be marked as lost.

This fix covers that exact overlap: waiting for permission while the environment closes.

It is like a desk clerk waiting for your signature when the office lights go out; the case is no longer declared missing because of that.

In that situation, the session is no longer wrongly marked lost.

BUGFIX

MCP long connections stop reopening after timeouts

With a serverless host that ends long-held streams at a fixed timeout, an MCP v2 connection could keep reopening its subscriptions/listen stream.

MCP is the protocol that connects AI to outside tools, and this stream receives subscription information.

It is like an intercom call cut off by building rules, where the old behavior kept redialing the same call; it no longer cycles through reconnecting and dropping.

Such servers no longer trigger endless stream reopening.

BUGFIX

Permission prompts trigger notification hooks in Desktop and VS Code

If you use a Notification hook while working in Claude Desktop or VS Code, it may previously have stayed silent for a permission prompt.

A Notification hook is a small program triggered by an event and should notify you when permission is needed.

It is like a wired doorbell that did not ring when a visitor pressed it; now the bell sounds when someone asks to enter.

The fix covers permission prompts in those two environments.

BUGFIX

Idle Linux sandbox stops filling one CPU core

On Linux, an idle session could keep one CPU core at 100% even when sandboxing was enabled.

A sandbox is a restricted environment that limits what a program can touch, and it should sit quietly when unused.

It is like a fan running at full speed in an empty room; when no one is using the room, it no longer consumes that fan for nothing.

Idle sandboxed sessions no longer hit that single-core saturation.

BUGFIX

Bundled aliases still work when same-named skills shadow them

In -p mode, or after loading plugins or MCP, entering /checkup or /review could produce “Unknown command” if a user or project skill had the same name.

A skill is a set of instructions that teaches Claude a particular job, and a name collision should not hide bundled aliases.

It is like a new shop with the same name covering an older shop's whole sign; now both bundled aliases still have a visible entrance.

The fix covers -p and the loaded plugin or MCP cases.

BUGFIX

Command arguments no longer get re-read as template markers

After a skill or command received an argument, its value could be expanded again as template markers: special symbols the program replaces.

That treated input text as another instruction to process.

It is like a form clerk placing your written name in a field, then reading the name again as instructions for filling out the form.

Now an argument keeps its value after substitution instead of becoming template markers again.

BUGFIX

Windows device paths cannot bypass network-path checks

On Windows, a path spelled with the NT \??\ device prefix could bypass UNC path validation and expose an NTLM credential-leak vector.

UNC validation is the safety check for network-share path spelling and should catch such paths.

It is like a building's main entrance checking badges while a side door written differently was left outside the same check; now that side door is checked too.

The fix closes the leak route created through that special prefix.

FEATURE

Self-hosted runner starts without rewriting worktree

When starting claude self-hosted-runner, the session branch is now created without rewriting the worktree.

A session is the connection and state for one continuous stretch of work, and its start no longer waits for two server round trips that blocked the agent launch.

It is like placing the scene list backstage before a play, rather than rebuilding the whole stage before actors may enter.

The runner's session starts faster because those two round trips no longer block the agent.

FEATURE

Gateway forwards upstream error message itself

When an apps gateway receives a 400 or 413 error from Vertex, Foundry, or Claude Platform on AWS, it now carries the upstream service's own message.

An upstream is the service the request was meant to reach, so its message tells you why it rejected the request.

It is like support handing you the warehouse's exact return slip instead of saying only “there is a problem,” so you know what to change.
FEATURE

Apps gateway auto-compact bug is fixed

A bug in auto-compact on apps gateway is fixed.

Auto-compact condenses earlier conversation to make room for more content in a session.

It is like an organizer replacing an overstuffed folder with a shorter summary, so the filing step that was stuck can now finish.

Auto-compact through apps gateway is no longer affected by this bug.

FEATURE

Plugin validation finds malformed skill description files

When checking a plugin, claude plugin validate now examines a bare .claude/skills directory.

It reports SKILL.md files whose frontmatter, the fields at a file's beginning for tools to read, cannot be parsed.

It is like opening the title page of every manual in a folder before publication and marking any whose basic details cannot be read.

Validation includes .claude/skills even when it stands alone rather than inside a full structure.

FEATURE

Screen readers can choose effort with numbers

When using a screen reader to change /effort, the selector now appears as a numbered list and asks for a typed number.

A screen reader is an assistive tool that reads screen content aloud and needs an ordered way to convey choices.

It is like ordering by voice without guessing among unseen buttons: hear the menu, then say the dish number.

Hint text and dialog text are no longer clipped either.

FEATURE

Print mode flags unrecognized model IDs

If print mode sends a model ID Claude Code does not recognize, stderr, the program's text channel for reporting problems, now writes [claude-code:unrecognized_model].

The diagnostic line tells you the request went out with an unknown model ID.

It is like a mailing counter stamping “address not found” on the receipt instead of quietly sending a parcel onto an unknown route.

Map that ID with modelOverrides to silence the line.

FEATURE

Non-GitHub repositories stop getting wrong app setup tip

If a repository's origin remote is on gitlab.

com or bitbucket.org, the GitHub app setup tip no longer appears. An origin remote is the repository's destination for its remote source, so a non-GitHub destination should not ask for GitHub app setup.

It is like a station not sending travellers for another city to the wrong platform; when the destination is not GitHub, it does not issue that ticket.

The enterprise marketplace tip now covers internal Git hosts that are not GitHub.

FEATURE

Newer models hide todo tools by default, with an opt-in return

On Opus 4.

8, Sonnet 5, Fable 5, Mythos 5, and newer models, the task-tracking tools TaskCreate, TaskGet, TaskUpdate, TaskList, and TodoWrite are no longer available. This changes the availability of existing tools; it does not add a new tool.

It is like a new layout for a toolbox that stores the todo drawer away for these models, while people who need it can still put the drawer back.

Set CLAUDE_CODE_ENABLE_TODO_TOOLS=1 to restore them.

FEATURE

Windows Bash permission change narrows back overly broad rules

On Windows, auto mode repeatedly stopped for manual approval on ordinary cd <dir> && <command> > file Bash commands; that 2.

1.232 regression is fixed. At the same time, 2.1.232 Bash permission changes for Cygwin-style symlinks and input redirection < file have been reverted.

It is like access control stopping ordinary passage and two named lanes; ordinary travel resumes, while the two overbroad rules are withdrawn until a narrower version returns.

A narrower version will arrive in a later release.
