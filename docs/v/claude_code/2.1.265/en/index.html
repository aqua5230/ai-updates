Claude Code 2.1.265

Released: 2026-09-08

Release notes

FEATURE

Plugin Directory Supports Batch Loading with Dynamic Hot-Reloading for Subfolders

If you regularly develop multiple extensions, you previously had to specify each plugin path individually whenever starting the command line.

This is like adding a multi-slot modular organizer to a display rack, where slotting in small drawers with manifest cards automatically enables them, and swapping or adding drawers midway requires no disassembly of the rack.

Now, the --plugin-dir flag directly supports pointing to a parent folder containing multiple plugins. As long as each child folder inside has a manifest file (a specification document recording plugin metadata), the system automatically discovers and loads all extensions on startup. Even better, adding or removing child folders under that directory while running is dynamically detected and applied immediately, saving you from repeatedly restarting sessions.

FEATURE

Plugin Path Containment Checks Hardened with More Complete Marketplace Details and Lists

Security validation and marketplace listing displays when managing plugins have received comprehensive fixes in this release.

On macOS and Linux, plugins with paths containing backslashes no longer bypass symlink containment checks. Folders whose names start with two dots are no longer mistakenly refused as outside the plugin root. If the OS cannot check a component folder (such as a symlink loop), it is now explicitly reported with an error code in /plugin instead of being silently skipped. Regarding information display, marketplace discovery listings and claude plugin list --json --available now fully display descriptions and names for plugins whose metadata lives only in plugin.json. Meanwhile, the Installed tab and claude plugin details prioritize marketplace registry entries, filling any missing fields from plugin.json.

The entire audit is like a commercial building strictly vetting registration shortcuts and unit numbers for every merchant while updating tenant signage and automatically filling in missing directory details against master records.
BUGFIX

Subagent Prompt Prefixes Locked for Higher Cache Reuse and Interrupted Tool Calls Preserved

Prompt caching mechanisms are now far more reliable during multi-agent collaboration and resumed workflows.

This is like researchers maintaining an identical index upon handover, keeping the preamble and tool catalog fixed so existing notes can be reused while bookmarking interrupted entries during an unexpected outage.

Previously, resuming a foreground-spawned subagent would alter its tool list and system prompt prefix, breaking prompt-cache reuse. Agent teammates and resumed subagents also moved SubagentStart hook context and preloaded skills out of the prompt prefix on later turns, similarly destroying cache benefits. Now, all these prefix structures remain locked in place. In addition, if a previous process died unexpectedly while a tool was running, resuming no longer rewrites the final prompt, but instead fully retains the tool call and marks it as interrupted.

FEATURE

Workflows Panel Unfolds Tool Calls with Clearer Forked Skill Streaming and Container Recovery

Progress tracking and diagnostics have become much clearer when running multi-step workflows and forked skills.

In the /workflows agent detail panel, individual tool calls are now clearly marked as running, failed, or done, displaying any subagent task lists and letting you press Enter to unfold calls with their inputs and results. When using forked skills (running in an isolated background branch with context: fork), kickoff prompts and text turns generated with --forward-subagent-text now stream properly as progress events to stream-json output. If a workflow container restarts and its run journal is missing, the system now fails with a clear error instead of blindly rerunning every agent.

The entire experience is like fitting a modern factory control room with multi-color status lights that display each workstation's progress while triggering an alarm and stopping lines if audit logs go missing, preventing duplicate production.
FEATURE

Enterprise Gateway Telemetry Exports Directly to Collectors with Identity Fields and Unpaused Relays

Transmission stability and identity metadata have been significantly enhanced when administrators collect audit data via gateways.

Telemetry sent by Claude Desktop and Cowork through an apps gateway now includes user.email and user.groups fields, matching the recording specs of terminal sessions. When gateway managed settings specify a collector endpoint via OTEL_EXPORTER_OTLP_ENDPOINT, gateway sessions export OpenTelemetry data directly to that collector instead of routing through the gateway relay, while sessions without a named collector continue using the relay. Furthermore, an issue where the relay paused all forwarding for 30 seconds after rejecting a few malformed or oversized payloads has now been resolved.

This is like an enterprise mailroom labeling departmental packages with full employee rosters and dispatching dedicated direct shuttles when available, rather than halting the entire conveyor belt for half a minute over a single overweight parcel.
FEATURE

Managed Settings Enforce Gateway Login on Startup with Accurate Subdirectory Agent Scoping

Login flows and permission boundaries are now strictly aligned in environments governed by enterprise managed settings.

This is like installing dedicated security turnstiles at corporate building entrances, requiring visitors to swipe company badges from the moment they step into the lobby, invalidating leftover visitor passes, and checking accurate permission registries during inter-floor transfers.

Machines with forceLoginGatewayUrl configured in managed settings now start directly as apps gateway sessions, behaving just like forceLoginMethod: "gateway", while leftover claude.ai logins or API keys are discarded. Re-running /login in these gateway sessions no longer falsely reports that no gateway URL is configured. Additionally, when loading subdirectories via /add-dir <subdirectory>, the system no longer refuses to load subdirectory agents when managed settings lock only skills to plugins, nor does it mistakenly promise agents when only agents are locked.

BUGFIX

Remote Control and Background Session Stability Upgraded with Persistent Working Directories Across Turns

Operational continuity for Remote Control and background sessions has improved significantly in this release.

Non-interactive sessions (such as -p with stream-json, Agent SDK, and cloud sessions) no longer reset their working directory on every message, allowing cd commands to persist across turns. Remote Control sessions no longer send an early end-of-turn signal before the final message arrives, preventing the app from prematurely showing the reply as finished. Running /clear via Remote Control no longer waits on SessionStart hooks or open terminal dialogs before completing. Background sessions (--bg) are no longer retired mid-turn when a message arrives just before the idle timeout. Remote sandboxes no longer stay alive while waiting for connector approvals or sign-in links. Furthermore, closing VS Code or SDK sessions while refreshing authentication tokens no longer forces a re-login.

This is like operating a remote exploration rover where voice channels never cut off early and updated coordinates are not snapped back to the origin on every round.
BUGFIX

MCP Supports Legacy Transport Fallback with Deferred Client Registration and Fixed Connection States

Connection handshakes and authentication mechanisms for external tools have become much more flexible.

For MCP servers configured as http that only speak the legacy HTTP+SSE transport architecture, which previously failed to connect entirely, the system now automatically falls back to SSE as described in the specification. For secure registration, connecting to remote servers that require sign-in no longer registers OAuth clients in advance, but instead waits until you actually authenticate. In addition, cloud sessions previously showed some external connector servers as requiring login if they responded to unsupported requests with HTTP 401, even if you were already connected on the web; this misleading status has now been fixed.

This is like visiting an international business desk where communication ports switch automatically to legacy backup lines and personalized access passes are printed on demand only when you arrive at the counter.
FEATURE

Tool Output Disk Writes Capped at 1 GB with Stricter Artifact Publishing and Malicious Prompt Defense

Tool output persistence safeguards and artifact security have been significantly reinforced in this release.

When external tool outputs are exceedingly large, saved disk files now have a 1 GB cap; if contents are truncated, in-conversation previews explicitly display truncation notices to prevent disk space exhaustion. For artifact management, publishing now strictly validates declared tools against connectors: publication is refused if none of the declared tools exist, and warned if only some are missing. Furthermore, when reading artifacts written by others, the summarization process now treats page content as untrusted data, actively flagging embedded instructions rather than relaying them to guard against prompt injection attacks.

The entire defensive setup is like a freight intake depot imposing weight caps on oversized cargo, validating stamp authorizations on clearance papers, and scrutinizing enclosed notes in external mail.
BUGFIX

Image Processing Moves to Built-in Engine with Specific Causes and Fixes for Size Limit Errors

Underlying architecture for handling images in the terminal is now much lighter and cleaner.

This is like a compact camera reading images directly using its built-in decoding chip rather than disassembling precision modules onto temporary trays, while also pinpointing oversized photos and suggesting how to downscale them.

The CLI now fully utilizes the runtime's built-in image features, no longer extracting native binary modules to temporary directories on startup, which reduces disk write overhead and leftover files. Meanwhile, when an image exceeding size limits cannot be decoded, error messages now state the underlying cause and provide troubleshooting suggestions instead of merely citing the limits, letting you quickly adjust image dimensions and continue your session.

BUGFIX

Git Worktrees Support Parallel Checkout with Fixes for Sandbox File Access and Permission Wording

This release brings multiple low-level improvements to file access, version control, and permission settings.

When creating worktrees via --worktree in large repositories, Git 2.32+ now checks them out in parallel, drastically reducing startup time. Resuming long sessions that previously read numerous files is also noticeably faster. On Windows, an issue where Read, Write, and Edit operations were completely rejected inside AppContainer or restricted-token sandboxes has been resolved. In addition, internal Git status and diff checks are no longer disrupted by clean filters configured in nested repositories within the working tree. Permission wording for the .claude folder has also been revised, clearly explaining that it allows editing files in the project's .claude directory or ~/.claude for that session.

The workflow is like a large library retrieving multiple collection copies in parallel, cleaning up inspection rules across floors, and clearly outlining access permissions on checkout slips.
FEATURE

Slash Commands Expand to Full Search Lists with Extended Two-Key Shortcut Windows and Layout Polish

Everyday terminal interactions and command menu handling have received thorough layout and responsiveness refinements in this release.

Typing slash commands mid-prompt now displays matching results in a full list (which can be opened with Tab outside fullscreen), and plugin skills can be found directly by their bare names. In multitasking environments like tmux, two-key shortcuts whose second key arrives more than 1 second later now wait 3 seconds and display a timeout notice instead of cancelling silently. Fullscreen transcripts no longer jump by a row when menus open or close. Dialog heights remain stable when switching tabs in /config. Permission prompts no longer drop characters following specific syntax sigils. Resumed sessions now display unfinished background tasks as concise status lines rather than cluttering the screen with lengthy internal instructions.

This is like a musician operating fast-tempo pedals where slight timing gaps trigger helpful cues while the sheet music stand remains rock-solid without shifting lines.
BUGFIX

Model Switching Supports Specific Target Names with Stable Advisor Decisions and Accurate Error Reporting

Decision logic when switching models and configuring advisor behaviors is now significantly more stable and transparent.

This is like hiring a consulting firm where assigned account representatives remain fixed rather than being reshuffled with every new request, sending formal notices whenever staffing rules change.

Previously, the advisor tool and its instructions were re-decided per request based on that request's model; decisions are now made once and announced directly in conversation whenever they change. In terms of commands, typing /model opusplan[1m] is no longer rejected with "Model not found". If saving a default model fails due to unwritable configuration files, /model no longer falsely claims success, but instead reports the failure and its underlying cause. In addition, the built-in claude-api skill reference documentation has been corrected: model access failures return 404 and unavailable beta headers return 400, rather than the previously documented 403.

BUGFIX

[VSCode] Auto-Archiving for Inactive Sessions with Fixes for Blank Restarts and Layout Glitches

Sidebar session management and visual details have received thoughtful fixes in the VS Code extension.

To keep conversation lists uncluttered over time, a new "Archive inactive sessions" setting automatically moves sessions to an archive after 14 days of inactivity by default. Previously, if a chat had been open for more than 10 minutes, reloading the window or restarting the editor often left the sidebar blank; this rendering bug has now been resolved. Additionally, a layout misalignment where the timeline dot sat beneath text in "Remote Control is active" notices has been corrected.

This is like an office organizing filing cabinets where cases untouched for over two weeks automatically move into archival folders, drawer contents never vanish mysteriously, and exterior labels stay neat and aligned.
