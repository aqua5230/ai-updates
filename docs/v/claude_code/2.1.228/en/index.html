Claude Code 2.1.228

Released: 2026-08-11

Release notes

FEATURE

The screen keeps redrawing, and terminal tabs wobble less

Claude may have kept working while the screen stopped updating, leaving you to wonder whether to wait or restart.

A rare internal layout error could halt redraws in an interactive session even though its process was still running; that failure is now avoided. It was like a live camera frozen on one frame while the people in the studio kept talking. A smaller change replaces busy-spinner glyphs in the terminal title, reducing tab-bar jitter in some terminals.

BUGFIX

Windows can find Git even when Claude starts above its folder

On Windows, Claude Code could say Git was missing even when it was installed, cutting off version-control work.

The failure happened when Claude Code was launched from a parent folder of Git's installation: git or Git Bash might not be found. This changes how it finds the existing installation; it does not install another Git. It was like knowing a tool is in a building but missing the entrance because you started at a nearby intersection. Now that route reaches Git too.

FEATURE

Model choice no longer rolls back, and Write rules are clearer

After changing models with /model, opening /tui should not quietly return your session to the earlier model; it now keeps your choice.

File handling also changed: newer models may use Write to overwrite an existing file they have not read in this session, matching Edit; older models must still read first. Think of changing train platforms, then looking at the timetable and being sent back to the old one. An outdated first-use note claiming auto-mode sessions cost slightly more has also been removed for Pro, Max, and Team plans.

FEATURE

Cross-session messages are visible, without leaking resumed chats

When two sessions exchange messages, the first session after an install or upgrade could sometimes have no inbox, and messages were collapsed to one line.

Now an inbox is created and both sender and body appear inline. For messages sent to a Remote Control session on another machine, the sender shows your Remote Control session name. More importantly, using /resume while connected through Remote Control no longer leaks a resumed conversation's title or history into the connected session. It is like office notes gaining an inbox, signature, and full text while old records in the next meeting room stay behind a locked door.

BUGFIX

Self-hosted runners stop failing for irrelevant repos or ending early

When running claude self-hosted-runner yourself, a checkout hook failing for a repository the session would never push to could make every fresh runner session fail.

Such a repository is now skipped with a warning instead of taking down the work. A runner could also end a session in the handoff gap after a background task finished but before its follow-up turn began; that gap is now covered. It is like a relay team being disqualified because a broken equipment locker was never part of the race. Now they pass it with a notice, and the next runner is not dismissed before receiving the baton.

BUGFIX

Cleanup keeps project memory and in-development plugins intact

If you keep a project's memory folder so Claude retains context, or develop a plugin through a symlink (a shortcut file pointing somewhere else), cleanup must not mistake active material for trash.

Session cleanup could delete contents inside the project's memory folder. Background plugin-cache cleanup could also delete a plugin's cache when its only version was a symlinked development checkout. Both accidental deletions are fixed. It was like an office manager clearing out notes in a project cabinet and active tools inside the workshop; now those live materials are recognized.

BUGFIX

Marketplace settings no longer inherit headers from another tier

When the same marketplace entry existed in settings tiers with different precedence, redefining it in a higher tier should have replaced the whole entry.

Instead, custom headers from another tier could be inherited. Marketplace entries now merge as whole entries, rather than as a mix of pieces. This matters if you manage several layers of settings: changing the higher-precedence form will no longer quietly bring along headers from another form. It was like filing a supplier's new contract on top, then accidentally gluing the old contract's letterhead onto it. Now the full new contract is used.

FEATURE

Skill reminders stop duplicating, and cloud skills cannot override local controls

After invoking a skill (instructions that tell Claude how to handle a particular kind of work), the deferred-tools reminder could sometimes be sent to the model twice; it now appears once.

More importantly, skills synced from claude.ai are restricted: they cannot shadow local commands or MCP (Model Context Protocol, a protocol that connects AI to external tools) prompts, their descriptions are sanitized and labeled, and their bodies cannot run ! commands or expand @ files on your machine. An outside manual may sit on your shelf, but it cannot cover the buttons on your desk or open files from your drawers by itself.

FEATURE

Expired credentials fail fast, and compaction shows its progress

When Google Cloud credentials for Vertex AI are expired or missing, Claude Code used to retry for minutes before failing; it now fails within seconds.

You no longer have to stare at a lit elevator button without knowing whether anything is moving. Compaction, which condenses an overlong conversation to make room, also shows more useful signals: its retry countdown and a stall hint now appear while it runs instead of leaving only a progress bar. One change surfaces an error sooner; the other tells a waiting person whether it is retrying or has stopped.
