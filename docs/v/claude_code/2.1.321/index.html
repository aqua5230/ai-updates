Claude Code 2.1.321

發布日期：2026-11-09

繁體中文

新功能

預設模型切換為 Fable 5.2，快取計費與企業席位提示更新

想要在日常對話中調用超長文本，Claude Code 已將預設 Fable 模型升級至 claude-fable-5-2。

好比租借公事包時直接換上容量更大的旗艦款，開口能塞進厚重企劃案，重複翻閱舊頁時租金更便宜，企業方案用戶也不會再收到額外扣抵點數的通知。

新模型具備 1M 上下文長度，每百萬 token（AI 處理與計費的文字單位）輸入價格是 8 美元、輸出 40 美元。使用快取（把算過的結果暫存起來直接用）時，每百萬 token 讀取價格是 0.20 美元。原本已包含 Fable 的企業版席位在切換後，不再跳出扣除額度點數的提示。原本儲存使用 Fable 5.1 的設定會自動切換為 fable，Pro 與 Max 方案立刻生效，Team 與 Enterprise 則待組織允許；若想切回舊版可輸入 /model claude-fable-5-1。

新功能

工作階段回饋與升級選項納入 Ultra，登入說明涵蓋所有付費方案

如果你正在查看帳號方案或調整團隊設定，介面文字現在已將新的 Ultra 方案完整納入。

恰似健身房在會員公告牌上補齊頂級會員級別，所有櫃檯說明書與續約按鈕都同步列出新標籤，安全守則字樣也對齊總店公告。

在工作階段回饋訊息與 allowedProviders 設定說明裡，Ultra 已與 Pro 和 Max 並列顯示。升級選項由原本的升級至 Max 改為「Upgrade to Max or Ultra」。forceLoginMethod 的設定說明擴大涵蓋所有付費方案。觸發網路安全防護攔截時，畫面顯示的 Cyber Verification Program 提示文字已對齊 claude.ai 官方站台的措辭。

新功能

快速模式連線受阻退回同模型標準速，模型選單新增未編號展開列

在終端機切換快速模式或挑選模型時，回應與選單的互動方式有了調整。

好似快捷櫃檯客滿時，服務員先請你在同一個窗口改走一般排隊動線，而不會將你轉介到其他業務櫃檯，目錄底部的更多項目展開時也不會打亂原本排好的號碼牌。

當快速伺服遇到限流、過載或故障時，不再遺失回覆或重試數分鐘，而是優先切換至同一個模型的標準速度。輸入 /model 時，「More models」改為置於最下方的未編號選項，展開舊模型時不會改變其他項目的編號。在 /fast、/config 與 /model 的標籤中，只要目前模型支援快速模式就會直接標註名稱，並移除了 VS Code 列上的「(Opus only)」註記。第一順位模型若在回覆前遭阻擋，備援模型（fallback，主要模型失效時接手處理的替代模型）不再誤稱回覆已被中止。模型回覆包含工具呼叫時，提示建議也不會再發出額外的請求。

新功能

Remote Control 支援載入獨立設定檔，鎖定工作目錄並強化初次執行提示

使用遠端操控管理多個工作階段時，現在可以為所有連線統一套用固定的組態環境。

宛如巡迴值勤前配發固定公事包，值勤期間不得擅自更換巡邏基地，遇上無人應答的確認單時也會清楚註明下一步該找哪位窗口。

執行 claude remote-control --settings <file> 可以指定設定檔並套用至啟動的每個工作階段；如果該設定檔在執行期間變更，必須重新啟動遠端操控才會建立新工作階段。連線進來的客戶端無法再將工作階段搬移到其他資料夾。針對首次執行的確認提示，未回答的訊息現在會直接說明下一步該做什麼，並修正了終端機輸入結束時直接將未按 Enter 的「y」誤判為同意的問題。

問題修復

Remote Control 修復延後排隊機制，連線中斷與登入過期狀態回報更準確

透過網頁、手機或桌面應用程式使用遠端操控時，訊息排隊與連線狀態不再產生混淆。

跟郵局收發包裹一樣，寄件人勾選等候通知時信件就不會在處理中途被硬塞進櫃檯，窗口連線切斷時也不會繼續亮著服務燈。

在網頁與行動版上，/compact 選項不再重複顯示兩次。桌面應用程式若短暫無法遞交授權令牌（token，驗證身分的數位憑證），遠端操控不會在連線正常時誤報登入已過期。選擇「Queue for later」暫存的訊息，不會在目前回合執行途中提前遞交給 Claude。當工作階段的歷史紀錄仍在背景上傳但連線已徹底關閉時，介面不再繼續顯示為已連線。若執行行程發生當機，遠端操控工作階段能更快重新接收並處理新訊息。

問題修復

MCP 工具轉址防護敏感金鑰，修復名稱衝突斷線與重載空白

為專案串接外部工具時，MCP（讓 AI 連接外部工具的協定）在重導向與連線載入時不再產生安全疑慮。

就像寄送機密文件遇上轉址時快遞員會取下附帶的保管箱鑰匙，工具清單在重新入庫時也不會因為搬動辦公桌而遺失登記欄位。

伺服器轉址時，OAuth 流程不再將更新憑證洩漏給其他主機。登入註冊過的伺服器時，claude mcp login 不再反覆跳出 SEP-2352 警示。在桌面版 Code 標籤頁工作階段中，伺服器不再因與桌面應用同名而中斷連線。載入工具途中重新連線或變更目錄，伺服器不再誤顯示為無可用工具。stdio 與 HTTP 伺服器的掛鉤輸出若超過 16 MiB，會直接拒絕該工具呼叫。登入紀錄若為空值，啟動時不再畫面空白或 claude mcp list 輸出無內容。

問題修復

Bash 檔案寫入與路徑比對修正，複製移動指令套用統一防護規則

排查批次執行的檔案操作時，終端機對目錄位置與保護規則的判定標準已完成對齊。

恰如警衛在核對倉庫進出單據，搬移箱子進特定庫房時一律逐件檢查封條，換到新隔間作業時也不會遺漏登記正確的房號。

以前 Bash 權限檢查有時會從錯誤的資料夾判斷檔案寫入，導致未能適時發出提問，這個問題已經修好。當使用 cp 或 mv 指令將檔案移入目錄時，該寫入動作現在會確實受到拒絕規則與保護檔案提問的約束。連續發送多個 Bash 指令且前方指令更換過目錄時，後續指令不會再跑去錯誤的資料夾執行。輸入 grep -r foo "$PWD/src" 這類含有環境變數的讀取指令時，行為與直接打出完整路徑一致，不再額外跳出提問。使用 /bin/cp 這類帶有絕對路徑的指令時，檢查標準也已與一般的 cp 保持相同。

問題修復

修正自動模式權限設定與沙盒防護，放行常態排程命令

調整權限設定檔或執行自動排程時，終端機的提問邏輯與指令回傳維持正常秩序。

如同大門守衛只嚴查同時帶有通訊錄與派送單的特殊包裹，其他日常巡邏公文則正常放行，修改通行證預設值時也不再跳出不相干的選項。

在 /config 設定畫面中，新工作階段在自動模式啟動時不會再誤將 Manual 標為預設，在「Auto (default)」上按下空白鍵現在會正確儲存為 Don't Ask。唯讀的 Bash 指令若在沙盒外執行，不再發生跳過權限提問的情況。對於在 .zshrc 中啟用 KSH_OPTION_PRINT 的使用者，指令執行結果不會再回傳空值。帳號電子郵件檢查現在僅針對同時包含郵件地址並指名 User-Agent 的指令直接拒絕，其餘命令與排程任務不再停下來詢問。權限提問與背景任務引發的偶發崩潰也已獲得解決。

新功能

自訂模組於自動模式免提問載入，無頭模式支援檔案即時重載

讓 Claude 撰寫擴充模組並在後台無人值守執行時，模組的載入與授權變得更加流暢。

宛若給駐場技師派發經認證的專用工具袋，在維修通道內換裝零組件不必每次反覆向主控台申請審核，只要零件圖面一更新技師便即刻換上。

在 auto 與 bypass 模式下，Claude 撰寫的模組會直接啟用而不跳出提問，即使設有禁止非沙盒指令或限定網域的政策也一樣，但在 dontAsk 模式下則不載入。模組內部發起的工具呼叫（例如 $.tool.call 與 $.mcp.call）不再觸發權限提問，不過組織政策與明確的拒絕規則依然有效。在無頭模式（沒有視窗畫面的執行模式）的工作階段中，.claude/skills 內的模組檔案若有變更會自動重新載入，若想關閉此偵測，可將環境變數設為 CLAUDE_CODE_PLUGIN_DIR_WATCH=0。

問題修復

網路共享路徑筆記本與文字編輯修復，改動失敗如實回報狀態

經由區域網路共享、WSL 資料夾或遠端掛載編輯 Jupyter 筆記本時，檔案內容不再遭到意外破壞。

猶如在圖書館遠端借閱裝訂資料夾，翻修內頁時不會因為沒指定頁碼就塗掉封面，若在等待簽核時文件被其他人抽換，系統也會老實登記修改失敗。

在網路路徑（包含 UNC 共享、WSL 資料夾與 /net 掛載）上使用 NotebookEdit 時，以前未指定單元格可能導致首個單元格被刪除或覆寫，現在已修復。使用一般編輯工具時，也不會再因為網路路徑而誤把筆記本當純文字編輯、在字串空白時替換整份檔案，或錯誤修改多筆相符中的第一筆。若筆記本在權限提問視窗開啟時於外部被更動而導致修改失敗，NotebookEdit 不會再向掛鉤與遙測紀錄虛報成功。

問題修復

Windows 啟動速度加快，檔案監控修復磁碟代號問題

在 Windows 系統開啟終端機時，工具啟動與首個指令的響應速度變得更加迅速。

就像計程車司機記住了常用導航路線，出車時不再反覆重啟額外的定位儀器，檢查門牌號碼時也不會因為英文字母大小寫不同而停止哨戒。

在搜尋環境變數中的程式時，不再啟動輔助行程，直接在主要流程中尋找目標。對於標準的 Git for Windows 環境，每次啟動不再反覆檢查要使用哪一個 git 執行檔。尋找內部啟動程式時，會略過相對路徑、網路共享捷徑與 UNC 路徑，並能即時套用設定檔中的路徑變更。當工作階段的工作目錄包含小寫磁碟機代號時，watchPaths 監聽路徑在第一個命令執行後 FileChanged 掛鉤停止運作的問題也已獲得修復。

新功能

VS Code 擴充套件新增金鑰衝突警示，遮蔽字元套件統一標註名稱

在 VS Code 中開啟 Claude 進行提問時，介面會及時提醒憑證設定上的衝突。

正如大樓門禁同時感應到兩張通行卡時會主動亮燈提醒，登記名冊若遇到無法辨識的字元也會直接貼上標準訪客標籤。

當你在編輯器環境中同時設定了授權金鑰與 API 金鑰時，輸入框上方現在會跳出警示提示，與終端機啟動時的警告保持一致。如果有外掛套件的名稱包含不可見的隱藏控制字元，權限請求視窗不再顯示殘缺字元，而是統一標明為「a plugin」。

新功能

外掛套件更新避免跨目錄重複下載，受管市集強化來源管控

管理專案自訂外掛或市集來源時，目錄配置與版本更新的規則完成統整。

恰似社區訂閱報紙時由管理室統一收發，各分戶不再各自重複訂購同一份刊物，未經認證的攤商想要頂替既有名號時也會被直接隔絕並封存貨品。

自動更新與 /plugin 市集更新不再為同一個儲存庫的工作樹（Git 讓同一專案平行開多份副本的功能）或個別資料夾重複下載外掛。使用 --plugin-dir 載入目錄時，不再將內建外掛的型別檔誤寫入 builtin 資料夾。在 ~/.claude/plugins 底下的檔案上工作時，該處內層的 .claude/skills 資料夾不再載入。受管市集名稱不可被外部來源冒用，遭未宣告來源接管時，已存資料會被隔開保留 cleanupPeriodDays 天，選項與機密則保留到執行 claude plugin restore-set-aside 為止。

問題修復

背景子代理回報支援合併答覆，修復對話壓縮與中斷重啟遺失

指派多個背景子代理同時執行複雜任務時，進度彙整與工作階段回復變得更可靠。

恰如專案主管在辦公室彙整多位外勤調查員的便條，多張便條會在一封信件中一併批覆，開會重新整理桌面時也不會弄丟剛送達的最新報告。

在無頭模式、桌面應用與 VS Code 中，同時等待的多個子代理進度回報現在會像終端機一樣合併在單次模型呼叫中一併回答。如果工作階段在 Claude 回應前執行了對話壓縮，自動模式不會再丟失剛開啟新回合的子代理報告。當使用者手動中止後有多個報告等待時，單一請求不會再塞入超出預期的回報量。子代理進度摘要在模型回覆工具呼叫後，不再將請求一路執行到結束。雲端工作階段若遭服務中斷，子代理不再被誤記為手動停止而拒絕恢復，重啟後發送至主對話的訊息也會確實獲得答覆。

新功能

Git 分支暫存後保留專案技能，代理人檢視完整顯示工作樹錯誤

利用 Git 工作樹切換不同分支時，專案自訂的指令與技能不會無故消失。

好比工匠在不同工作台之間切換時，工具架上的刻度名牌始終保持在視野範圍內，若副工作台架設失敗也會直接印出完整的錯誤原因。

以前當專案技能資料夾因為執行 git stash 暫存變更而短暫消失又回復時，技能與自訂代理人會在選單中持續遺失，現在即使進入工作樹也能正常載入。在桌面應用與 SDK 工作階段中，專案指令也不再因切入工作樹而從選單消失。執行 claude agents 時，若命令列同時帶有 --verbose，打在主指令前方的 --model 等參數不再遭到忽略。名稱中帶有易造成字體空白的巴姆字母的技能會被直接拒絕。在代理人檢視畫面中，若背景工作樹架設失敗，錯誤訊息改由開頭完整列出，不再只截取後段字元。

問題修復

背景指令修復逾時通知與父行程比對，工作流暫停即時同步狀態

安排長時間執行的背景任務時，進程管理與狀態同步更貼合實際運行情況。

好似工廠監控看板精準掌握流水線動態，停工時立刻切換顯示燈號，長篇的工作回報單只保留頭尾摘要，搜尋運轉機台時也不會誤扣總部主機。

在非互動模式下，背景指令若在 10 分鐘後中止，不會再向 Claude 誤報擁有 30 分鐘執行時間。在雲端工作階段中，使用 pkill 或 pgrep 等進程管理命令時，不會再誤比對到該工作階段自身的父行程。當你停止或暫停正在運行的工作流程時，Claude 會即時得知最新狀態，不再誤稱流程仍在繼續。遇到超過 1000 字元的超長背景指令，通知訊息只保留指令開頭與結尾以節省上下文長度。背後代理伺服器連線延遲時，Chrome 與電腦操作伺服器進程在父行程結束後不會再持續滯留在系統中。

問題修復

修復掛鉤輸出檔案覆寫與攔截衝突，重放授權答案不再中斷

於工作流程中部署自動化掛鉤時，多個小程式之間的事件處理與回傳順序獲得梳理。

跟輸送帶上的多重感應器一樣，兩道檢查同時要求確認時原因不會彼此覆蓋，重啟機器重放記錄時也不會被前方的柵欄再次擋下。

同一次工具呼叫若有多個掛鉤（特定事件發生時被觸發的小程式）輸出大容量內容，不會再發生路徑指向同一檔案的錯誤。嵌入 Claude Code 的應用程式在多個掛鉤同時發出詢問時，能正確保留外部掛鉤的提問原因，延後處理的請求也不會導致提問遺失。遠端工作階段重啟重放先前的授權答覆時，不再觸發 UserPromptSubmit 掛鉤而造成無回應。在雲端協作階段中，後置掛鉤無法再擅自竄改使用者的回答或既定計畫。非互動工作階段在 Bash 與 PowerShell 呼叫後，num_hooks 與 num_success 兩個欄位也不再計入兩個內建掛鉤。
