Claude Code 2.1.321

Released: 2026-11-09

Release notes

FEATURE

Default Model Switches to Fable 5.2, Updating Cache Billing and Enterprise Seat Prompts

To work with extra-long context in everyday conversations, Claude Code has upgraded its default Fable model to claude-fable-5-2.

Picture renting a briefcase and immediately upgrading to a flagship model with greater capacity: its opening fits bulky proposals, browsing through old pages costs less in rental fees, and enterprise plan users no longer receive alerts about extra deducted credits.

The new model features a 1M context window, with pricing at $8 for input and $40 for output per million tokens (units of text processed and billed by the AI). For cache reads, the price is $0.20 per million tokens. Enterprise seats that already include Fable no longer show the "Draws from usage credits" note after switching. Saved settings using Fable 5.1 automatically switch to fable, taking effect immediately on Pro and Max plans and on Team and Enterprise plans once your organization allows it. To switch back to the older version, you can enter /model claude-fable-5-1.

FEATURE

Session Feedback and Upgrade Options Add Ultra, Login Descriptions Cover All Paid Plans

If you are reviewing account plans or adjusting team settings, interface text now fully incorporates the new Ultra plan.

Think of a gym adding a top-tier membership tier to its announcement board: every front-desk pamphlet and renewal button displays the new label in sync, while safety guideline wording aligns with the main branch notice.

In the session-feedback message and the allowedProviders setting description, Ultra is now listed alongside Pro and Max. The upgrade option has changed from upgrading to Max to "Upgrade to Max or Ultra". The description for forceLoginMethod has expanded to cover all paid plans. When a cyber safeguard block triggers, the Cyber Verification Program message on the screen now uses the same wording as the official claude.ai website.

FEATURE

Fast Mode Falls Back to Standard Speed on Same Model, Model Menu Adds Unnumbered Expansion Row

When switching fast mode or selecting models in the terminal, response handling and menu interactions have been adjusted.

Imagine an express counter where staff redirect you to regular queuing at the very same window instead of sending you to another counter, and expanding extra catalog items leaves existing ticket numbers untouched.

When fast serving encounters rate limits, overloading, or failures, it no longer loses replies or retries for minutes, trying standard speed on the same model first. When entering /model, "More models" is now an unnumbered option placed at the very bottom, and expanding older models does not change the numbering of other items. In /fast, /config, and /model labels, your current model is explicitly named whenever it supports fast mode, and "(Opus only)" has been removed from the VS Code row. If the first-choice model is blocked before replying, fallback models (backup models that take over when the primary model fails) no longer mistakenly claim that the response was stopped. When a model response includes a tool call, prompt suggestions no longer make extra requests.

FEATURE

Remote Control Supports Loading Dedicated Settings Files, Locks Working Folders, and Clarifies First-Run Prompts

When managing multiple sessions with Remote Control, you can now apply a fixed configuration environment across all connections.

Security guards receive a designated briefcase before patrol and cannot switch duty stations midway, while unanswered confirmation forms clearly state which contact to approach next.

Running claude remote-control --settings <file> lets you specify a settings file that applies to every session it starts. If that settings file changes during runtime, no new session will start until you restart claude remote-control. Connected clients can no longer move a session to another folder. For first-run confirmation prompts, unanswered messages now explain what to do next. An issue where terminal input ending would misinterpret a y typed without Enter as consent has also been resolved.

BUGFIX

Remote Control Fixes Delayed Queuing, Accurately Reporting Disconnections and Expired Logins

When using Remote Control across web, mobile, or desktop applications, message queuing and connection status no longer cause confusion.

A post office handling packages avoids cramming hold-for-pickup mail onto active counters, and counter service lights do not stay lit once a terminal disconnects.

On web and mobile, the /compact option no longer appears twice. If the desktop app is briefly unable to hand over sign-in tokens (digital credentials used to verify identity), Remote Control no longer falsely reports that login expired while the connection remains up. Messages held using "Queue for later" do not reach Claude early in the middle of a running turn. When session history is still uploading in the background but the connection has closed for good, the interface no longer continues showing as connected. If a process crashes, the Remote Control session can pick up and process new messages sooner.

BUGFIX

MCP Tool Redirections Guard Sensitive Keys, Fixing Name Collision Disconnects and Empty Reloads

When connecting external tools to a project, MCP (a protocol connecting AI to external tools) no longer raises security concerns during redirections and connection loading.

Couriers rerouting confidential documents remove any attached safe keys, while cataloging tools during a reorganization prevents registration fields from vanishing when desks move.

During server redirections, the OAuth flow no longer leaks refresh credentials to other hosts. When signing in to a registered server, claude mcp login no longer repeatedly displays the SEP-2352 warning. In a Claude Desktop Code tab session, servers no longer disconnect due to sharing the same name as a desktop application. If a server reconnects or the directory changes while tools are still loading, it no longer falsely displays as having no available tools. When hook output on stdio and HTTP servers exceeds 16 MiB, the tool call is refused directly. If a sign-in record is null, startup no longer displays a blank screen and claude mcp list output is no longer empty.

BUGFIX

Bash File Writes and Path Matching Corrected, Applying Uniform Protection to Copy and Move Commands

When troubleshooting batch file operations, terminal evaluation standards for directory locations and protection rules are now aligned.

Warehouse guards verifying shipment manifests inspect every seal whenever boxes move into secure storage, while shifting to a new bay never causes the wrong room number to be logged.

Bash permission checks previously judged a file write from the wrong folder and failed to prompt in time, which has now been fixed. When using cp or mv commands to move files into a directory, the write action is now strictly bound by deny rules and protected-file prompts. When sending several Bash commands in sequence and an earlier command changes folders, subsequent commands no longer run in the wrong folder. Entering read commands containing environment variables, such as grep -r foo "$PWD/src", now behaves consistently with typing out the full path and no longer prompts extra. Using path-specified commands like /bin/cp now applies the same inspection standards as standard cp.

BUGFIX

Auto Mode Permissions and Sandbox Protection Fixed, Allowing Routine Scheduled Commands

When adjusting permission profiles or running automated schedules, terminal prompt logic and command responses maintain normal order.

Gate guards inspect only suspicious packages bearing both an address book and a delivery slip while waving through routine patrol paperwork, and adjusting default badge settings never surfaces unrelated options.

In the /config settings screen, starting new sessions in auto mode no longer mistakenly flags Manual as default. Pressing Space on "Auto (default)" now correctly saves Don't Ask. Read-only Bash commands running outside the sandbox no longer skip permission prompts. For users enabling KSH_OPTION_PRINT in .zshrc, command execution results no longer come back empty. Account email checks now directly refuse only commands that simultaneously contain an email address and name a User-Agent, so other commands and scheduled tasks no longer stop to prompt. Rare crashes triggered by permission prompts and background tasks have also been resolved.

FEATURE

Custom Mods Load Without Prompts in Auto Mode, Headless Sessions Support Live File Reloading

When having Claude author extension mods for unattended background runs, mod loading and authorization are noticeably smoother.

Equipping on-site technicians with certified tool bags lets them replace components inside maintenance corridors without repeatedly asking dispatch for approval, swapping in fresh parts the moment blueprints update.

In auto and bypass modes, mods written by Claude activate directly without prompts, even under policies prohibiting unsandboxed commands or restricting domains, but they do not load in dontAsk mode. Tool calls initiated by mods themselves ($.tool.call and $.mcp.call) no longer trigger permission prompts, though organization policies and explicit deny rules remain in effect. In headless sessions (an execution mode without a visual interface), mod files in .claude/skills reload automatically when changed. To turn off this detection, you can set the environment variable to CLAUDE_CODE_PLUGIN_DIR_WATCH=0.

BUGFIX

Notebook and Text Edits on Network Paths Fixed, Accurately Reporting Failed Changes

When editing Jupyter notebooks across local network shares, WSL folders, or remote mounts, file contents are no longer accidentally corrupted.

Borrowing bound folders remotely from a library ensures that refurbishing inner pages never erases the cover when page numbers are omitted, and records faithfully log failed edits if someone swaps the document while approval is pending.

When using NotebookEdit on network paths (including UNC shares, WSL folders, and /net mounts), an issue where omitting a cell name could delete or overwrite the first cell has been resolved. Standard editing tools on network paths also no longer mistakenly edit notebooks as plain text, replace an entire file on an empty string, or erroneously modify the first of several matches. If an edit fails because the notebook was altered externally while the permission prompt was open, NotebookEdit no longer falsely reports success to hooks and telemetry.

BUGFIX

Windows startup accelerates, while file monitoring fixes drive letter issue

When opening the terminal on Windows, tool startup and response times for the first command become faster.

Taxi drivers memorize routine navigation routes, skipping the repeated reboot of extra GPS gear when rolling out, and never drop watch over house numbers simply because letter casing differs.

When searching for programs in environment variables, it no longer starts a helper process, finding targets directly in the main flow instead. For a standard Git for Windows environment, it no longer repeatedly checks which git executable to run on every launch. When looking for internally started programs, it skips relative paths, network share shortcuts, and UNC paths, while immediately applying path changes from configuration files. An issue where FileChanged hooks stopped working after the first command for paths monitored via watchPaths when the session's working directory contained a lowercase drive letter has also been fixed.

FEATURE

Much as a building access gate lights up an alert when sensing two access cards simultaneously, the visitor log attaches a standard guest label whenever encountering unrecognizable characters.

When both an authorization token and an API key are configured in the editor environment, a warning alert now appears above the prompt box, matching the warning shown at terminal startup. If a plugin's name contains invisible hidden control characters, the permission request window no longer displays broken characters, reading "a plugin" instead.

When managing custom plugins or marketplace sources for a project, rules for directory layouts and version updates have been unified.

In a residential community subscribing to newspapers, the front office handles centralized distribution so individual households never reorder duplicate copies, while uncertified vendors trying to impersonate established stalls are quarantined and their goods sealed.

A project supervisor collates notes from multiple field investigators in the office, answers multiple slips in a single dispatch, and never misplaces a newly arrived report while clearing the desk during meetings.

In headless mode, the desktop application, and VS Code, progress reports from multiple concurrently waiting subagents are now answered together in a single model call, matching the behavior in the terminal. If a session undergoes conversation compaction before Claude responds, auto mode no longer loses subagent reports that had just started a new turn. When multiple reports are waiting after a user manually stops an operation, a single request will no longer take in more reports than expected. Subagent progress summaries no longer execute a request all the way to completion after the model responds with a tool call. If a cloud session is interrupted by a service issue, subagents are no longer mistakenly marked as manually stopped and refused resumption, and messages sent to the main conversation after restart are reliably answered.

When encountering unstable networks or sluggish proxy connections, conversations will no longer crash outright due to failed cryptographic handshakes.

Radios tuning through momentary static play whatever clear segments they already captured while attempting reconnection, and rapidly pull authorized rosters from credential binders at boot rather than idling indefinitely.

When a connection drops midway through a model response, the turn no longer terminates abruptly by throwing an API error for a TLS handshake failure; instead, it preserves the partially generated reply or automatically retries the request. If the network endpoint accepts the connection but persistently stalls on completing the cryptographic handshake, sign-in, token refresh, and sign-out flows no longer hang indefinitely. By accelerating how trusted certificates load from the certificate store (where the system keeps root certificates), the tool's overall startup time has also been shortened.
