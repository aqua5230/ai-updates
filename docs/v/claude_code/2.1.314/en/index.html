Claude Code 2.1.314

Released: 2026-10-30

Release notes

FEATURE

Strictly Restricting Write Directories to Prevent Modifying Files Outside Project Boundaries

When authorizing Claude to modify a project in the terminal, tools might accidentally touch other folders if boundaries are not specifically defined. A new permissions.blockWritesOutsideWorkingDirectories setting has now been added. Once enabled in the configuration file, all writing tools such as Write, Edit, and NotebookEdit will directly refuse to modify paths outside the working directories, regardless of the current permission mode.

{
  "permissions": {
    "blockWritesOutsideWorkingDirectories": true
  }
}

Picture a safety guard mounted on a woodworking workbench: operating tools previously risked shaving clutter beyond the table edge, but now every cutting blade is strictly confined within the tabletop.

When letting tools automatically modify large numbers of files, enabling this setting ensures personal files outside the project are not accidentally changed.

BUGFIX

Application Gateways Support Group Routing, Refined Guardrail Logging, and Timeout Fixes

When routing requests through an application gateway inside an enterprise, teams often need to divide routes based on developer identities. Gateway upstreams now add an optional group list so only developers in identity provider groups are directed to the designated upstream, maintaining the same rule during failover. For Amazon Bedrock upstreams, a new guardrail trace setting logs which safety filter fired without printing the matched text. In addition, an issue where a Vertex upstream hung for minutes when a Google credential endpoint was unresponsive has been fixed, and the startup warning message for expired keys was also corrected.

Like airport customs dividing lanes by passport category, only travelers with designated identities can use the dedicated inspection lane, and the same security standards are maintained when switching transfer counters.
FEATURE

Automatic Summaries for Idle Conversations, Major Cloud Platform Support, and Hook Safeguards

Leaving long conversations sitting aside in an editor often consumes extra processing resources due to excessive length when asking follow-up questions. VS Code and Claude Desktop have added an idle compaction mechanism. Whenever a conversation exceeds 200,000 tokens (text units processed and billed by AI) and sits idle, the system generates a summary in advance.

Imagine an accounting firm binding vouchers during lunch break: scattered case files previously slowed down audits, but now outdated receipts are condensed into summary sheets during breaks away from desks, letting accountants reconcile accounts immediately upon returning.

Once the cache expires, your next message will directly use this summary. This mechanism is now also available for users with telemetry turned off, as well as Bedrock, Vertex, Foundry, and major gateways with one-hour caching enabled. If output from pre-compact hooks (small programs triggered by specific events) is too large, the content is strictly truncated to 10,000 characters to prevent compaction failures.

BUGFIX

Adapting to Organization Effort Caps and Auto-Switching to Compatible Models on Missing Deployments

When teams place restrictions on model access, sessions often abruptly halt due to parameter limits or missing deployments. If an organization administrator caps thinking effort, invalid parameters now automatically trigger a lower effort level, a retry, and a notice stating the level used. When Microsoft Foundry lacks a deployment for the default model, the system automatically falls back to an older model in the same family. After managed settings pin a model, Bedrock and Vertex will no longer display upgrade prompts on every startup. Even if a personal plugin manifest is broken, model switching is no longer blocked. In addition, restoring or resuming a session preserves unrecognized custom model names, and flagged requests will attempt to retry on another available model if settings permit. Where switching or resuming models in strictly managed environments previously threw errors and halted, the system now autonomously finds compatible configurations to keep conversations flowing smoothly.

BUGFIX

Command-Line Non-Zero Exit Code Fix, Certificate Verification, and Background Execution

When calling command-line tools in scripts or automated pipelines, failing to report errors correctly often misguides debugging efforts. When startup fails with claude -p, the tool now prints the error cause and exits with code 1 instead of silently returning success. When a renewed root certificate in the system certificate store (a repository holding root certificates) is cross-signed by its predecessor, TLS connections no longer fail due to missing issuers. Background daemon startup failures are also no longer misreported as deleted binaries. Additionally, prompts containing command output tags acknowledge correctly to the local host, and setting FORCE_HYPERLINK to false, no, or off turns off terminal hyperlinks.

BUGFIX

Handling Long Documents and Multiple Images with Proactive Notices for Unread Content

Once conversations receive large numbers of screenshots or long documents, oversized inputs often cause remote tools to silently miss information. When too many images accumulate in Bedrock sessions, compacting now actively removes older images to reduce length smoothly, rather than getting stuck on input-too-long errors on every turn. When connecting via SSH to a remote Linux host, attempting to paste an image directly now prompts you to copy the file over and paste its path instead of doing nothing silently.

Just as a courier dispatch center handles overweight packages, where previously overfilled boxes were rejected outright or items were quietly withheld, staff now proactively repack shipments into separate parcels and clearly note unincluded items on the manifest.

When using web fetching tools to read PDFs in Cowork cloud sessions, if text exceeds 100,000 characters, the tool proactively explains how much content was unread and how to continue reading.

BUGFIX

Enterprise Gateway Forwarding Compatibility, Backoff Settings, and Custom Model Recognition

Many teams route requests through custom gateways, where forwarders lacking support for certain beta headers often cause connection failures. If a gateway cannot process reference blocks in tool searches, the session automatically retries once without that block and remembers this preference to avoid repeated rejections. When a cloud provider or gateway explicitly rejects specific beta headers, the request is automatically resent with the header removed.

Consider international packages clearing transit stations: when scanners fail to read special barcodes, handlers strip auxiliary labels to reweigh parcels and record the station's clearance conventions on the log card.

Furthermore, custom models with dots in their names (such as claude-opus-4.8) are no longer misidentified as older models, correctly applying context window sizes, output limits, and billing configurations.

FEATURE

Auto-Downgrade to Guest on Expired Tool Credentials and Faster Lookups for Thousands of Tools

When projects connect many external extensions, expired login credentials often prevent publicly available functions from being invoked. Now, even if stored sign-ins on MCP (a protocol connecting AI to external tools) servers stop working, as long as the server works without sign-in, it will automatically operate signed out instead of halting on authentication errors. When a locked keychain prevents credentials from being removed during SSH connections, running claude mcp logout no longer falsely reports success.

Much like visiting an open exhibition hall, where an expired membership card previously barred entry at the front doors, guests with invalid credentials are now issued visitor wristbands to view the permanent exhibits.

In addition, when a session mounts ten thousand or more extension tools, typing /context to inspect the environment is significantly faster.

FEATURE

Strict Workspace Trust Checks and Required Confirmation for Modifying Managed Settings

In automated integration workflows or team collaborations, tools reading untrusted code without boundaries can pose severe security threats. In continuous integration environments with a terminal, when CI is detected in environment variables, running reviews or remote control will immediately abort if a directory is untrusted, instead of prompting for confirmation. Typing /ultrareview in the terminal also verifies workspace trust before executing Git commands.

Think of an automated guard post on duty: upon detecting unauthorized visitors it immediately drops the gate, and operator passwords must first be verified before servicing a confidential headquarters console.

In addition, when file tools attempt to modify the locally cached copy of an organization's server-managed settings, they must first obtain your confirmation, following the strict standards applied to personal configuration files.

BUGFIX

Furthermore, when organizational policies disable cloud sessions or remote control, related prompt notices are completely hidden. Where expired settings or switched execution environments previously created policy loopholes, administrative boundaries now remain fully enforced regardless of connection status.

BUGFIX

Limit quota retries and notify when interrupted commands may have run

When letting scheduled or background tasks run on their own without proper braking mechanisms, the system can spin uselessly after exhausting its quota. At usage limits, the "Continue automatically at usage limit" feature is now strictly capped at three automatic retries without a new prompt, preventing goal check-ins or background tasks from restarting indefinitely. If you turn off Ultracode in background or cloud sessions, it reliably stays off on the next launch rather than turning itself back on. In addition, when you interrupt a command in cloud sessions or the IDE using Esc or the Stop button, notifications no longer just report that the command was declined, but clearly warn that parts of the code may have already executed. While interrupted tasks previously risked misjudging environment states or looping through retries, the system now enforces strict retry limits and gives the assistant a realistic view of command execution progress.

BUGFIX

Stabilize streaming table layouts and clean leftover artifacts from failed retries

When viewing long assistant responses streamed in the terminal, flickering displays or leftover fragments disrupt the reading experience. When a tool call cannot be parsed and is ultimately abandoned, the conversation no longer retains broken replies and retry prompts. Streaming Markdown tables no longer jitter between grid and stacked layouts on unfinished rows, nor do very long tables fall back to raw pipe characters.

A printing press calibrates its cylinders during high-speed proofing: while incomplete sections previously caused misaligned layouts and ink spills, fresh inking is now crisp and uniform, and scrapped proofs are cleared away immediately.

Blank lines at the start of code blocks no longer vanish inside quotes, and viewing transcripts with Ctrl+O avoids extra blank lines above folding markers. Additionally, restoring a conversation while scrolled up no longer leaves the fullscreen transcript frozen midway through an unfinished view.

BUGFIX

Prevent background diffs from locking Git, cap trash folders, and lighten file watching

When saving files frequently in large projects, background tools that consume excessive system resources can interfere with routine version control. Background diff generation no longer contends for lock resources with Git commands running in your terminal after previously locking the Git index briefly. Trash directories for skills and plugins now have a capacity cap of about 1024 entries, and the file watcher stops scanning discarded files inside trash to lighten disk overhead.

Cleaning staff restock supplies backstage without hogging carts in main corridors and routinely empty disposal bins to ensure front-stage traffic flows unimpeded.

Editing files in projects with newline conversion enabled will no longer misidentify an entire file as modified after a single-line edit. Searches on macOS now switch to the C locale, preventing regex (syntax that matches text patterns with symbols) libraries from leaking memory when reading non-UTF-8 files.

When running slash commands, the session picker no longer mistakenly grabs contents from documentation files as session titles. Deleted transcripts no longer reappear unexpectedly, and restoring conversations with --resume offers noticeable improvements in speed and memory usage when handling damaged transcript files. While session lists previously suffered from blank entries or misplaced filenames, conversations are now named accurately so parallel workflows remain clear across windows.
