Claude Code 2.1.314

發布日期：2026-10-30

繁體中文

新功能

嚴格限制寫入目錄，防止修改專案範圍外的檔案

在終端機授權 Claude 修改專案時，若沒有特別劃定邊界，工具可能會不小心碰到其他資料夾。現在新增了 permissions.blockWritesOutsideWorkingDirectories 設定。只要在設定檔中啟用，無論目前處於哪種權限模式，Write、Edit 與 NotebookEdit 等所有寫入工具，都會直接拒絕修改工作目錄外的路徑。

{
  "permissions": {
    "blockWritesOutsideWorkingDirectories": true
  }
}

猶如在木工工作台上加裝安全擋板，以前工具運轉時容易削到桌緣外的雜物，現在所有切削刀具都被硬性限制在桌面範圍內。

當你要讓工具自動修改大量檔案時，開啟這項設定就能確保專案以外的個人檔案不會被意外改動。

問題修復

應用程式閘道支援群組分流，完善防護紀錄與逾時修復

企業內部透過應用程式閘道派發請求時，往往需要依據開發團隊的身分劃分不同線路。現在閘道上游新增了選填群組名單，只有在身分提供者群組內的開發者才會被導向指定上游，發生備援切換時也維持相同規則。針對 Amazon Bedrock 上游新增了防護追蹤設定，會記錄觸發了哪一項安全過濾機制而不會印出比對文字。此外修正了 Vertex 上游遇到 Google 憑證端點無回應而卡住數分鐘的問題，過期金鑰的啟動警告文字也一併修正。

彷彿機場海關依護照類別分流通道，指定身分的旅客才能走專屬查驗線，遇到轉機換櫃也維持相同安檢標準。
新功能

閒置對話自動整理摘要，支援主流雲端平台與掛鉤防護

把長對話擱置在編輯器一旁後，重新提問時往往會因為超出長度而耗費額外的處理資源。VS Code 與 Claude Desktop 新增了閒置壓縮機制。只要對話超過 20 萬個 token（AI 處理與計費的文字單位）且處於閒置，系統便會預先產出摘要。

宛若會計事務所利用午休裝訂憑證，以前案卷散落會拖慢查帳，現在趁離席空檔將過期單據濃縮成總表，回到座位便能直接對帳。

一旦快取（cache，把算過的結果暫存起來直接用）過期，下一次送出訊息就會直接使用這份摘要。這項機制現在也開放給關閉遙測的使用者，以及開啟一小時快取的 Bedrock、Vertex、Foundry 與各大閘道。壓縮前掛鉤（hook，特定事件發生時會觸發的小程式）輸出若過大，內容會硬性截斷在 10,000 字元以內，避免對話壓縮失敗。

問題修復

調適組織思考強度上限，遇部署缺漏自動切換相容模型

團隊若對模型存取設有限制，工作階段常因為參數超標或缺少部署而突然中斷。若組織管理員限制了思考強度上限，現在遇到參數無效時會自動調降強度、重新嘗試並告知使用等級。在 Microsoft Foundry 缺少預設模型部署時，會自動切換至同系列的舊版模型作為備援。受管設定釘選模型後，Bedrock 與 Vertex 不會再於每次啟動時跳出升級提示。即使個人外掛程式清單損壞，也不再阻擋模型切換。此外，復原或繼續工作階段時會保留原本未知的自訂模型名稱，而遇到要求被標記時，若設定允許也會嘗試改用其他可用模型重送。以前在嚴格受管的環境下切換或復原模型容易直接報錯卡死，現在系統會自主尋找相容配置維持對話順暢。

問題修復

修正命令列非零結束代碼，強化憑證驗證與背景執行

在腳本或自動化管線中呼叫指令列工具時，若錯誤沒有正確回報，常會導致除錯方向徹底偏差。現在使用 claude -p 啟動失敗時，會印出錯誤原因並以結束代碼 1 離開，不再靜默回傳成功。當系統憑證庫（certificate store，存放根憑證的地方）中更新後的根憑證由前一版根憑證交叉簽署時，TLS 連線不再因找不到簽發者而中斷。背景常駐程式啟動失敗時，也不再誤報成執行檔已被刪除。另外，包含指令輸出標籤的提示能正確向本機回應，而將 FORCE_HYPERLINK 設為 false、no 或 off 都會關閉終端機超連結。

問題修復

改善長篇文件與多圖處理，長度超標主動提示未讀範圍

對話中一旦傳送大量截圖或長篇文件，輸入內容過大常會讓遠端工具無聲無息地遺漏資訊。現在在 Bedrock 工作階段中堆積過多圖片時，執行壓縮會主動移除舊圖片來順利縮減長度，不再每次回覆都卡在輸入過長的錯誤。在遠端 Linux 主機透過 SSH 連線時，若嘗試直接貼上圖片，提示框會明確指引你將檔案複製到主機並貼上路徑，不再毫無反應。

恰似快遞收發中心處理超重包裹，以前遇到箱子塞不下便直接拒收或偷偷扣件，現在會主動分裝打包並在清單上清楚註明未裝入的項目。

在 Cowork 雲端工作階段中使用網頁抓取工具讀取 PDF 時，若文字內容超出 10 萬字元，會主動說明有多少內容未被讀取以及如何接續查閱。

問題修復

相容企業閘道轉發規則，記住退避設定並正確認知自訂模型

許多團隊透過自建閘道轉發請求，常會因為轉發器不支援部分測試標頭而導致連線失敗。若閘道無法處理工具搜尋中的參考區塊，工作階段會自動略過該區塊重送一次並記住這項偏好，避免反覆被拒。當雲端提供者或閘道明確拒絕特定的測試標頭時，也會自動剔除該標頭並重新發送請求。

比照國際包裹在轉運站通關，遇到查驗機讀取不到特殊條碼時，轉運員會撕去附加標籤重新過磅，並在紀錄卡記下該站點的清關慣例。

此外，針對名稱中帶有小數點的自訂模型（例如 claude-opus-4.8），也不會再誤判為舊型號，能套用正確的上下文視窗大小、輸出長度與計費設定。

新功能

擴充工具憑證過期自動轉為訪客，加速查詢上萬工具

專案若串接了大量外部擴充套件，過期的登入憑證常會讓原本公開可用的功能無法調用。現在即使 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器儲存的登入狀態失效，只要該伺服器支援免登入，就會自動以訪客身分繼續運作，不再卡在需要身分驗證的錯誤提示。在 SSH 連線導致鑰匙圈鎖定而無法移除憑證時，執行 claude mcp logout 不會再虛報登出成功。

跟參觀開放展覽館一樣，以前會員卡過期就連大門都不准進，現在驗證失效時會引導你換發一般訪客手環，照樣能瀏覽常設展區。

此外，當工作階段掛載上萬個擴充工具時，輸入 /context 檢查環境的載入速度顯著提升。

新功能

嚴格執行工作區信任檢查，修改組織託管設定主動確認

自動化整合流程或團隊協作中，若工具隨意讀取不受信任的程式碼，可能帶來嚴重的資安威脅。在帶有終端機的持續整合環境中，若環境變數偵測到 CI，執行審查或遠端操控時只要目錄未獲信任便會立刻中止，不再跳出詢問提示。在終端機輸入 /ultrareview 時，也會在執行 Git 指令前先確認工作區是否獲得信任。

猶如自動化無人哨所執勤，偵測到非授權訪客時直接拉下閘門，而遇到維修總部機密控制台時也必須先核驗操作員密碼。

此外，當檔案工具嘗試修改本機快取的組織伺服器託管設定時，必須先獲得你的確認同意，比照一般個人設定檔的嚴格標準處理。

問題修復

強化企業受管原則套用，避免無網路時脫離安全政策

管理者為內部成員配置統一的安全原則時，設定不該因為離線或客戶端差異而失效。現在管理者在託管設定中指定的憑證信任原則，會確實套用至 Claude Desktop 的工作階段中。設定了強制遠端重新整理時，即便本機快取過期且無法連上伺服器，也不會再允許工作階段在無防護狀態下啟動。透過 --setting-sources 明確排除的設定檔，其內部的自動模式規則與授權紀錄會被徹底忽略。另外，當組織政策停用雲端工作階段或遠端操控時，相關提示訊息會徹底隱藏。以前設定過期或切換執行環境容易讓政策出現漏洞，現在各項管理邊界無論連線狀態都能完整生效。

問題修復

限制額度重試次數，手動中斷指令能告知已執行的可能

放手讓排程或背景任務自行運作時，若缺乏適當的剎車機制，系統可能會在耗盡額度時不斷無效空轉。遇到額度上限時，「自動繼續」功能現在嚴格限制在未收到新提示的情況下最多僅能自動重試三次，防止目標檢查或背景任務無限重啟。如果在背景或雲端工作階段關閉了 Ultracode，下次啟動時會確實維持關閉狀態，不會再度擅自開啟。此外，當你在雲端或整合開發環境按下 Esc 或停止按鈕中斷指令時，通知不會只回報指令被拒絕，而是會明確提醒可能已經有部分程式碼實際執行過。以前任務中斷後容易誤判環境狀態或陷入重試迴圈，現在系統既能嚴守重試上限，也能讓助手更真實地掌握指令執行進度。

問題修復

穩定表格即時串流排版，清理對話失敗重試殘留痕跡

在終端機瀏覽助手即時生成的長篇回答時，畫面若頻繁跳動或遺留殘缺內容，非常影響閱讀體驗。當工具呼叫解析失敗且最終放棄時，對話中不再保留破裂的回答與重試提示。現在即時串流輸出 Markdown 表格時，未完成的資料行不會再於格狀與直列排版間反覆跳動，超長表格也不會退回成原始管道符號。

如同印刷機在高速打樣時校正滾筒，以前未印完的段落會造成排版錯位與溢墨，現在即時上墨整齊劃一，作廢的校樣也會立刻收納乾淨。

程式碼區塊開頭的空行不會在引號內消失，按 Ctrl+O 查看對話紀錄時也不會在折疊符號上方冒出多餘空行。另外，在向上捲動狀態下執行復原對話時，全螢幕紀錄不會再停在半截未完成的位置。

問題修復

避免背景比對鎖死 Git，設定垃圾桶上限並降載檔案監聽

頻繁在大型專案中儲存檔案時，背景工具如果過度占用系統資源，很容易干擾日常的版控操作。以前背景自動整理差異時會短暫鎖定 Git 索引，現在不再與你在終端機執行的 Git 指令搶奪鎖定資源。技能與外掛程式的垃圾桶目錄現在設有約 1024 筆的容量上限，且檔案監聽器不再掃描垃圾桶內的廢棄檔案，能減輕磁碟負擔。

宛如清潔人員在後台整理備品，不再霸佔主走道的貨物推車，並定期清空廢棄物暫存區，確保前台物流通行無阻。

在啟用換行符號轉換的專案中編輯檔案時，不會再因單行修改而將整份檔案誤判為全部變更。在 macOS 上執行搜尋時也改用 C 語言區域設定，避免正規表達式（regex，用符號匹配字串的語法）函式庫在讀取非 UTF-8 檔案時發生記憶體流失。

問題修復

智慧生成工作階段標題，修復重命名遺失與清單殘留

平時在多個終端機視窗並行處理任務時，清單若無法清楚辨認每個對話名稱，往往會浪費許多翻找時間。現在以特定技能或指令開頭的工作階段，會自動以該指令命名，即使首則提問失敗也不會再永久顯示為未命名。在執行斜線指令時，工作階段選擇清單不會再錯誤抓取說明檔案內容作為標題。在等待權限確認時，透過 /rename 設定的名稱會持續保留，方便辨識並列視窗。已刪除的紀錄不再異常重新現身，而面對損毀的紀錄檔時，使用 --resume 恢復對話的速度與記憶體表現也顯著提升。以前工作階段清單容易出現空白或錯置的檔名，現在對話命名更加精確，並行作業時不再混淆各個視窗的進度。

問題修復

隔離子代理互動範圍，修正按鍵誤觸並釋放背景記憶體

開啟子代理進行深度除錯或背景研究時，若主畫面與背景工作的控制項交纏在一起，容易誤停正在進行的工作。在子代理檢視畫面中輸入 /btw，會依據該子代理的上下文回答，按下 Esc 鍵也不會誤連帶中斷正在背景執行的子代理。全螢幕頂端會正確顯示該子代理實際運行的模型，而非主對話的模型。代理面板的按鍵選取修復了清單變動時誤點其他成員的狀況。在長耗時的無頭模式（headless，沒有終端機視覺介面的執行模式）與軟體開發套件中，主工作階段不再囤積已結束子代理的工具結果，顯著改善記憶體占用。此外，設定選單也補充了如何取消預設開啟代理檢視的說明。以前同時調度多個代理人容易發生按鍵誤判或記憶體膨脹，現在介面權責劃分清楚，長時間協同運算更為可靠。

新功能

妥善處理多工作階段憑證鎖定，行動訂閱升級精確引導

本機若同時開啟多個工作階段，或者透過不同管道訂閱方案，帳號驗證一旦衝突便會中斷手邊工作。現在當多個工作階段共用同一個登入設定檔時，即使憑證鎖定正忙碌，也不會再觸發不必要的重複換發手續。對於透過行動應用商店扣款的訂閱方案，輸入 /upgrade 不會再開啟瀏覽器強制重新登入，而是直接說明應前往何處變更方案。

跟持專案工作證進出管制大樓一樣，同組人員共用憑證不再重複在門口換證，由特殊通路簽約的成員也能獲得正確的續約指引。

雲端工作階段遇到帳號存取被拒時，錯誤提示會主動建議執行 claude auth login 重新驗證。針對企業行動裝置管理與遠端設定網址不一致的狀況，也優化了儲存憑證的套用行為。

問題修復

強化遠端操控連線重試，開啟即時同步真實權限模式

透過手機或另一台裝置遠端連線回本機工作時，連線若遇延遲或顯示錯誤狀態，會讓人難以放心授權。現在 claude remote-control 啟動工作階段遇到伺服器短暫遲緩時，會採用遞增間隔自動重試註冊，避免連線失敗。切換模型超過 8 秒時，能正常等待最終回覆，不再中途跳出逾時錯誤。客戶端在壓縮對話後不再殘留多餘的摘要提示列，權限模式按鈕更會在連線開啟當下立即顯示真實狀態，不必等到輸入文字才更新。

猶如操作遠端無人監控設備，連線不穩時主動拉長間隔重撥，儀表板一連線就精確對齊當前檔位，不再顯示前一次殘留的虛假燈號。

此外，當組織關閉遠端操控或推播設定被隱藏時，也不會再跳出推播通知的閒置提醒。

問題修復

沙盒保護涵蓋分支副本，指令掛鉤支援監視工具過濾

在獨立分支中驗證未經測試的腳本時，安全沙盒必須滴水不漏地涵蓋所有衍生的工作環境。現在透過續接參數進入工作樹（worktree，Git 讓同一專案平行開多份副本的功能）時，沙盒防護依然會嚴格套用。設定說明也精準更正為：一次呼叫中的所有指令都必須符合清單，才會在沙盒外執行。監視工具啟動的指令現在能正確觸發 Bash 掛鉤以進行阻擋或確認，掛鉤判斷條件也新增了對監視指令的語法支援。另外，Bash 工具會清除繼承的指令別名與函式，確保查詢指令一律指向正規的系統程式或內建功能。以前在分支副本或特殊工具環境下執行指令容易脫離安全管轄，現在環境隔離更為徹底，避免了自訂別名干擾系統判斷。
