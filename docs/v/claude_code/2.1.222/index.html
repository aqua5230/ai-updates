Claude Code 2.1.222

發布日期：2026-08-04

zh-TW

代理各做各的，安全界線不再被繞過

你讓 Claude 在工作樹（Git 讓同一專案平行開多份副本的功能）裡處理另一件事時，最怕它回頭動到主工作副本。現在不論哪種工作階段，隔離都同時管住檔案編輯和 Bash 指令，子代理也不能對主工作副本下破壞性 Git 指令。背景任務裡的 PreToolUse 掛鉤（特定事件發生時被觸發的小程式）原本能自動放行而繞過工具限制，這個缺口也補上了。代理要用 SendMessage 傳話給另一個工作階段，訊息會先交給權限分類器檢查；若某個 skill 標了 disable-model-invocation，Claude 會請你親自執行，不會照著猜流程重做一遍。像把分工的人各留在自己的房間，門禁和鑰匙都還在。

被駁回過的額度申請，現在能重新送出

你在 Team 或 Enterprise 方案替成員申請 /usage-credits，先前那次若被駁回，本來該能再送一次。舊版卻把被駁回的申請誤當成還在處理，跳出「你已送出用量點數申請」並把人擋在門外。現在這扇門會在申請被駁回後重新打開：成員可以提出新的用量點數申請，不必因為上一張失敗的申請一直卡住。這就像申請通道在上一份申請被駁回後重新開放，讓你再送一份新申請。

代理伺服器後的連線，不再假斷線或卡到失敗

公司網路走 HTTPS proxy（替你轉送加密網路連線的中介站）時，Claude Code 啟動前的連線檢查曾會卡住，最後才失敗。它現在改用和 API 請求相同、認得 proxy 的連線方式，逾時也會說清楚原因。回覆其實已經完整送達，卻被標成「回覆中途關閉」的誤報也修好了。若你把 ANTHROPIC_BASE_URL 指到自訂 gateway，伺服器明明持續送 keep-alive ping，閒置逾時器以前仍會響；現在會把這些 ping 算進去。像快遞車隔著轉運站仍持續回報位置，收件人不會再被通知包裹半路遺失。

用量、登入與錯誤訊息，終於各自說對話

你查 /usage 時，MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器的用量不會再被算得太多：只有實際消耗到它回傳工具結果的請求，才會歸到它名下。claude.ai connector 的工作階段 token（登入驗證用的令牌）失效時，畫面不會假稱還要授權，而會提示你用 /login 登入。若你剛移除一台 MCP 伺服器，原本看不到的工具錯誤也會顯示出來；SendMessage 遇到太長的摘要則會截短後送出，不會撞上字數上限直接失敗。把它想成客服中心的案件流程：只有案件確實採用了某櫃台提供的資料，該櫃台才計入用量；通行證失效就附上 /login 指示；撤掉櫃台後，舊案件的錯誤紀錄仍可查看；交接摘要太長，先裁到收件欄上限再送出。

分支、差異與遠端遙控，回到你真正的設定

你先推送分支、之後才建立 pull request 時，Claude Code 現在也能把工作階段連到那張 PR，包括透過 GitHub REST API 建立的 PR。查看 /diff、Remote Control 工作區差異或網頁版編輯差異時，它會直接讀 Git blob 的原始內容，不再受專案自訂 diff driver 或 textconv 影響；同一份變更不會被不同顯示規則扭曲。Remote Control 則收緊了啟動權：專案裡的 .claude/settings.json 與 .claude/settings.local.json 只能把它關掉，不能偷偷開啟；要開請在使用者範圍輸入 /config。像共用專案能貼告示說「今天不營業」，卻不能替每位同事擅自開門。

代理選模與進度顯示更準，UltraPlan 功能下架

組織限制某個模型家族時，子代理或隊友指定 model: opus 這類別名，先前可能錯退回父代理的模型。現在它會在同一家族裡往下改選組織允許的最新模型，選擇和限制終於對得上。子代理逐字稿的 spinner（畫面上轉圈的等待動畫）標籤改了。它會顯示子代理自己的 effort:（思考力道／投入程度的設定），不再顯示整個工作階段的等級。若主機用 CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST 管理模型，主機的選模鍵會壓過磁碟裡過期的 managed-settings.json。另外，UltraPlan 功能已移除。像派工板終於標出每個人的實際班別，總部的最新規則也不再被檔案櫃裡的舊紙條蓋過。

檔案監看更穩，螢幕閱讀器不再重念整行

你正在輸入問題又按了退格鍵，使用 --ax-screen-reader 模式的螢幕閱讀器以前會把整行輸入內容重新念一遍；現在刪除行尾文字時只回應剛刪掉的字元，耳朵不用反覆聽同一句。另一個少見但惱人的中斷也補好了：檔案監看器碰到檔案系統錯誤，或正在結束監看時，Claude Code 可能會當掉。現在這兩種時刻不再引發罕見崩潰。像校對員擦掉句尾一個字，只念那個被擦掉的字；門口的值班員遇到小狀況，也不會整間辦公室關燈離開。

Agents stay in their lanes, with safety checks intact

When Claude is handling another task in a worktree, you do not want it reaching back into your main checkout. Isolation now covers both file edits and Bash commands in every session type, so those sessions and their subagents cannot run destructive Git commands against the main checkout. A PreToolUse hook that could auto-allow its way around tool limits in background tasks has also been fixed. Messages sent with SendMessage to another agent session now pass through the permission classifier first. And when a skill is marked disable-model-invocation, Claude tells you to run it yourself instead of imitating its workflow. It is like keeping each collaborator in their own room while leaving the locks in place.

Dismissed credit requests can be sent again

On a Team or Enterprise plan, a member whose earlier /usage-credits request was dismissed should be able to submit another one. Instead, Claude Code treated that dismissed request as if it were still pending, showed “you've already sent a usage credit request,” and blocked the new request. That record now stops blocking the member after dismissal. It is like an application channel reopening after a dismissal, so you can send a new request.

Connections behind proxies stop timing out by mistake

If your company network uses an HTTPS proxy, Claude Code's startup check used to hang and then fail. It now uses the same proxy-aware transport as API requests and gives a clear timeout message. The false “Connection closed mid-response” report is also gone when a response had already finished. And when ANTHROPIC_BASE_URL points to a custom gateway, the idle timer now recognizes keep-alive pings arriving from the server instead of timing out anyway. Think of a parcel still reporting its location through a transfer station: the recipient should not be told it vanished halfway there.

Usage, sign-in, and errors now tell the right story

When you open /usage, an MCP server is no longer charged for every turn after someone called it. Its share now includes only requests that actually consumed its tool results. If a claude.ai connector has an invalid session token, it shows a /login hint rather than wrongly asking for authorization. Tool errors also remain visible after the local MCP server that supplied a tool has been removed. Finally, SendMessage truncates an overly long summary instead of failing on its character limit. Think of a customer-service desk's ticket workflow: only a ticket that actually used a desk's supplied information counts usage for that desk; an invalid pass gets a /login instruction; an old ticket's error record stays viewable after its desk closes; and an overlong handoff summary is trimmed to fit the receiving field before it is sent.

Branches, diffs, and Remote Control follow the right settings

If you push a branch and create its pull request later, Claude Code can now link the session to that PR, including one created through the GitHub REST API. The /diff view, Remote Control workspace diff, and web-session file-edit diffs now read raw Git blob content, so project-configured diff drivers and textconv no longer distort what is shown. Remote Control also has a tighter start switch: repo-local .claude/settings.json and .claude/settings.local.json may turn it off, but cannot turn it on. To enable it, use /config at user scope. A shared project can post a “closed today” sign, but it cannot quietly open every collaborator's door.

Agent model choices and progress labels are corrected; UltraPlan is removed

When an organization restricts a model family, a subagent or teammate using an alias such as model: opus could previously fall back to the parent agent's model. It now steps down within that family to the newest model the organization allows. A subagent transcript's spinner effort label now shows that subagent's own effort: setting, not the session-wide level. When the host manages models through CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST, its model-selection keys now beat stale on-disk managed-settings.json values. UltraPlan has also been removed. It is like a staffing board finally showing each person's actual shift, while the current rule from headquarters no longer loses to an old note in a filing cabinet.

File watching is steadier, and screen readers stop repeating lines

While you are typing and hit Backspace, a screen reader in --ax-screen-reader mode used to read the entire input line again. Deleting at the end of a line now echoes only the characters just deleted, so you do not have to hear the same sentence repeatedly. Another rare interruption is fixed too: Claude Code could crash when its file watcher met a filesystem error or while that watcher was shutting down. Those moments no longer cause the rare crash. It is like a proofreader who erases one character at the end and reads only that character aloud, while the person watching the door does not switch off the whole office over a small incident.

エージェントの作業範囲を守り、安全確認もすり抜けない

別の作業を worktree（Git で一つのプロジェクトに並行した作業コピーを複数作る機能）で任せるなら、メインの作業コピーに手を伸ばされるのは困る。今回から全種類のセッションで、隔離はファイル編集と Bash コマンドの両方に効く。子エージェントもメインの作業コピーに破壊的な Git コマンドを実行できない。バックグラウンド作業の PreToolUse フック（特定の出来事で動く小さなプログラム）が自動許可でツール制限を抜ける穴も塞いだ。SendMessage で別セッションへ送る文面は権限分類器が先に調べ、disable-model-invocation を付けた skill は Claude が勝手に手順を真似ず、利用者に実行を頼む。分担した人を別々の部屋に置き、鍵も外さない形である。

却下されたクレジット申請をもう一度送れる

Team または Enterprise でメンバーの /usage-credits を申請し、前の申請が却下されたなら、もう一度送れるはずである。以前は却下済みの申請まで処理中だと誤認し、「すでに使用クレジットの申請を送った」と表示して新しい申請を止めていた。今は却下後にその記録が通せんぼをしないため、メンバーは改めて使用クレジットを申請できる。前の申請が却下された後、申請の受付が再開され、新しい申請を出せるようになるようなものである。

プロキシ越しの接続が、誤って切れたり止まったりしない

会社のネットワークが HTTPS proxy（暗号化された通信を代わりに中継する場所）を通ると、Claude Code の起動時接続確認は止まった後に失敗していた。今は API リクエストと同じプロキシ対応の通信を使い、時間切れなら理由も明示する。返答が最後まで届いているのに「途中で接続が閉じた」と出る誤報も直した。ANTHROPIC_BASE_URL を独自 gateway に向けた場合も、サーバーから届く keep-alive ping を待機時間の判定に含める。中継所を通る配達車が現在地を送り続けているのに、荷物が途中で消えたと通知されることはなくなる。

使用量、ログイン、エラー表示がそれぞれ正しい話をする

/usage を見る際、MCP（Model Context Protocol、AI を外部ツールへつなぐプロトコル）サーバーの使用量が、呼び出した後の全ターンへ過大に配分されなくなった。実際にそのツール結果を使ったリクエストだけが対象である。claude.ai connector のセッション token（ログイン認証に使うトークン）が無効なら、許可が必要だと誤表示せず /login を案内する。ローカルで MCP サーバーを削除した後も、そのツールのエラーは表示される。さらに SendMessage は長すぎる要約を文字数上限で失敗させず、切り詰めて送る。顧客窓口の案件処理にたとえられる。窓口が提供した情報を実際に使った案件だけがその窓口の使用量に入り、入館証が無効なら /login を案内し、窓口を閉じた後も古い案件のエラー記録は見られ、長い引き継ぎ要約は受け取り欄に収まるよう切り詰めて送る。

ブランチ、差分、遠隔操作が本来の設定に従う

ブランチを push してから pull request を作った場合も、Claude Code はその PR にセッションを結び付けられる。GitHub REST API 経由で作った PR も含まれる。/diff、Remote Control の作業領域の差分、Web セッションの編集差分は、Git blob の生の内容を読むため、プロジェクトが指定した diff driver や textconv で表示が曲げられない。Remote Control の起動権限も絞った。リポジトリ内の .claude/settings.json と .claude/settings.local.json は停止だけでき、開始はできない。開始するならユーザー範囲で /config を使う。共有プロジェクトは「今日は閉店」と掲示できても、全員の扉を勝手に開けられないのである。

エージェントのモデル選択と進捗表示を正し、UltraPlan は削除された

組織があるモデル系列を制限していると、子エージェントや仲間が model: opus のような別名を指定した際、以前は親エージェントのモデルへ誤って戻ることがあった。今は同じ系列の中で、組織が許可する最新モデルへ段階的に切り替える。子エージェントの transcript に出る spinner（画面で回る待機アニメーション）の表示が変わった。子自身の effort:（考える力の入れ具合の設定）を示し、セッション全体の値は示さない。CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST でホストがモデルを管理するなら、ホスト側の選択キーが古い managed-settings.json より優先される。UltraPlan 機能も削除された。派遣表に各人の実際の勤務が載り、本部の新しい規則が棚の奥の古いメモに負けなくなるようなものだ。

ファイル監視が安定し、スクリーンリーダーは行全体を読み直さない

入力中に Backspace を押すと、--ax-screen-reader モードのスクリーンリーダーは以前、入力行全体をもう一度読んでいた。行末を消す場合は、今は消した文字だけを読み上げるため、同じ文を繰り返し聞かなくてよい。もう一つ、ファイル監視がファイルシステムのエラーに当たった時や、監視を終える途中に Claude Code がまれにクラッシュする問題も直した。校正者が行末の一字を消して、その一字だけを声に出すようなものだ。入口の見張りも小さな異常だけで事務所全体の電気を消して帰らない。

에이전트는 제 구역에서 일하고, 안전 검사는 우회되지 않는다

Claude에게 다른 일을 worktree(Git에서 한 프로젝트의 병렬 작업 사본을 여러 개 만드는 기능)에서 맡길 때, 주 작업 사본까지 건드리는 일은 피하고 싶다. 이제 모든 세션 종류에서 격리가 파일 편집과 Bash 명령어 모두에 적용된다. 그 세션과 하위 에이전트는 주 작업 사본에 파괴적인 Git 명령어를 실행할 수 없다. 백그라운드 작업의 PreToolUse 훅(특정 일이 생기면 실행되는 작은 프로그램)이 자동 허용으로 도구 제한을 넘던 구멍도 막았다. SendMessage로 다른 에이전트 세션에 보내는 내용은 권한 분류기가 먼저 살피며, disable-model-invocation이 붙은 skill은 Claude가 절차를 흉내 내지 않고 사용자가 직접 실행해 달라고 말한다. 역할을 나눈 사람을 각 방에 두고 문잠금도 남겨 둔 셈이다.

거절된 크레딧 요청을 다시 보낼 수 있다

Team 또는 Enterprise에서 구성원의 /usage-credits 요청이 전에 거절됐다면 새 요청을 보낼 수 있어야 한다. 이전에는 거절된 요청까지 아직 처리 중인 것으로 잘못 보고 “이미 사용 크레딧 요청을 보냈다”라고 표시하며 새 요청을 막았다. 이제 거절 뒤에는 그 기록이 길을 막지 않으므로 구성원이 다시 사용 크레딧을 요청할 수 있다. 앞선 신청이 거절된 뒤 신청 접수가 다시 열려 새 요청을 낼 수 있게 되는 것과 같다.

프록시 뒤의 연결이 잘못 끊기거나 멈추지 않는다

회사 네트워크가 HTTPS proxy(암호화된 네트워크 연결을 대신 중계하는 곳)를 거치면 Claude Code의 시작 연결 확인이 멈췄다가 실패하곤 했다. 이제 API 요청과 같은 프록시 인식 전송 방식을 쓰고 시간 초과 이유도 분명히 알린다. 답변이 이미 끝까지 도착했는데도 “응답 중 연결이 닫혔다”라고 뜨던 오보도 고쳤다. ANTHROPIC_BASE_URL을 사용자 지정 gateway로 향하게 한 경우에도 서버에서 오는 keep-alive ping을 유휴 시간 판단에 넣는다. 중계지를 지나는 택배차가 계속 위치를 알리는데도, 소포가 중간에 사라졌다는 통지를 받지 않는 셈이다.

사용량, 로그인, 오류 표시가 각자 맞는 말을 한다

/usage를 볼 때 MCP(Model Context Protocol, AI를 외부 도구에 연결하는 규약) 서버의 사용량이 누군가 한 번 호출한 뒤의 모든 차례에 과하게 붙지 않는다. 실제로 그 도구 결과를 소비한 요청만 그 서버 몫으로 계산한다. claude.ai connector의 세션 token(로그인 확인에 쓰는 토큰)이 무효이면 권한이 더 필요하다고 잘못 말하지 않고 /login 힌트를 보인다. 로컬 MCP 서버를 지운 뒤에도 그 도구의 오류는 표시된다. SendMessage는 너무 긴 요약을 글자 수 제한에서 실패시키지 않고 잘라서 보낸다. 고객 지원 창구의 티켓 처리 흐름이라고 생각하면 된다. 어떤 창구가 준 정보를 실제로 쓴 티켓에만 그 창구의 사용량이 잡히고, 출입증이 무효하면 /login 안내를 붙이며, 창구를 없앤 뒤에도 예전 티켓의 오류 기록은 볼 수 있고, 긴 인계 요약은 받는 칸에 맞게 잘라서 보낸다.

브랜치, 차이 보기, 원격 제어가 올바른 설정을 따른다

브랜치를 push한 뒤 pull request를 만들었어도 Claude Code는 이제 그 PR에 세션을 연결할 수 있다. GitHub REST API로 만든 PR도 포함된다. /diff, Remote Control 작업 공간의 차이, 웹 세션의 파일 편집 차이는 Git blob의 원본 내용을 읽으므로 프로젝트가 정한 diff driver나 textconv가 표시를 바꾸지 못한다. Remote Control의 시작 권한도 좁혔다. 저장소 안의 .claude/settings.json과 .claude/settings.local.json은 기능을 끌 수만 있고 켤 수는 없다. 켜려면 사용자 범위에서 /config를 쓴다. 공동 프로젝트는 “오늘은 닫음” 안내문을 붙일 수 있어도, 모든 동료의 문을 몰래 열 수는 없는 셈이다.

에이전트 모델 선택과 진행 표시를 바로잡고 UltraPlan을 제거했다

조직이 특정 모델 계열을 제한할 때 하위 에이전트나 팀원이 model: opus 같은 별칭을 쓰면, 이전에는 부모 에이전트의 모델로 잘못 돌아가기도 했다. 이제 같은 계열 안에서 조직이 허용한 가장 최신 모델로 한 단계 낮춰 고른다. 하위 에이전트 transcript의 spinner(화면에서 빙글 도는 대기 애니메이션) 표기가 바뀌었다. 하위 에이전트 자신의 effort:(생각의 강도나 투입 정도를 정하는 설정)를 보여 주며 세션 전체 수준은 보여 주지 않는다. 호스트가 CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST로 모델을 관리하면 호스트의 모델 선택 키가 오래된 디스크의 managed-settings.json보다 우선한다. UltraPlan 기능도 제거됐다. 업무표에 각자의 실제 근무가 표시되고, 본부의 새 규칙이 서랍 속 낡은 쪽지에 밀리지 않는 것과 같다.

파일 감시는 더 안정되고 화면 읽기 프로그램은 줄 전체를 되읽지 않는다

입력하다 Backspace를 누르면 --ax-screen-reader 모드의 화면 읽기 프로그램은 이전에 입력 줄 전체를 다시 읽었다. 이제 줄 끝을 지울 때는 방금 지운 문자만 알려 주므로 같은 문장을 반복해 들을 필요가 없다. 또 파일 감시기가 파일 시스템 오류를 만나거나 감시를 끝내는 중 Claude Code가 드물게 충돌하던 문제도 고쳤다. 교정자가 줄 끝의 글자 하나를 지우고 그 글자만 소리 내는 것과 같다. 입구를 지키는 사람도 작은 이상 하나 때문에 사무실 전체의 불을 끄고 떠나지 않는다.
