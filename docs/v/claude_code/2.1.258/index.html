macOS 12 上打不開的問題修好了

如果你的 Mac 還停在 macOS 12（Monterey），前陣子會發現 Claude Code 根本打不開。這不是舊系統本來就不支援，而是 2.1.255 那一版改動時弄壞的，屬於回歸（regression，原本正常的功能在後續版本被改壞）。換句話說，你什麼都沒動，只是跟著更新，程式就開不起來了。這次已經修好，macOS 12 上可以照常啟動。

點名時有人代答了一聲，名冊上卻留著空白；承辦人拿到一份沒有內容的紀錄，索性整份退回不辦。

遠端工作階段與排程工作階段碰過類似的事。你在權限詢問上按了同意，這個同意被重送了一次，但系統套用不上去，於是留下一則沒有內容的訊息。這則空訊息傳出去，整個工作階段就以 user messages must have non-empty content 收場，你等半天等到一句錯誤。這次修掉了這種失敗，重送的同意套不上去時，工作階段不會再整個垮掉。

English

Claude Code launches again on macOS 12

If your Mac is still on macOS 12 (Monterey), Claude Code would not launch at all recently. This was not a case of an old system never being supported: it was a regression, meaning something that used to work got broken by a later change, introduced in 2.1.255. You changed nothing yourself; you just took the update, and the program stopped opening. It is fixed now, and Claude Code starts normally on macOS 12.

The door of an old house used to open fine, then a crew replaced the frame and it jammed; the frame is now back to a size the door can clear.

Remote and scheduled sessions survive a re-sent approval that cannot be applied

Someone answers the roll call on another person's behalf, but the register stays blank; the clerk receives a record with nothing in it and sends the whole thing back unprocessed.

Remote and scheduled sessions ran into something similar. You approved a permission request, that approval was sent again, and it could not be applied, leaving a message with no content. Once that empty message went out, the whole session ended with user messages must have non-empty content, and your long wait produced an error. That failure is now fixed: when a re-sent approval cannot be applied, the session no longer collapses.
