macOS 12 上打不開的問題修好了

如果你的 Mac 還停在 macOS 12（Monterey），前陣子會發現 Claude Code 根本打不開。這不是舊系統本來就不支援，而是 2.1.255 那一版改動時弄壞的，屬於回歸（regression，原本正常的功能在後續版本被改壞）。換句話說，你什麼都沒動，只是跟著更新，程式就開不起來了。這次已經修好，macOS 12 上可以照常啟動。老宅的門原本進得去，工班換過門框後卻卡住開不了，現在門框調回能開的尺寸。

重送的授權沒套上時，遠端與排程工作階段不再整個失敗

點名時有人代答了一聲，名冊上卻留著空白；承辦人拿到一份沒有內容的紀錄，索性整份退回不辦。遠端工作階段與排程工作階段碰過類似的事。你在權限詢問上按了同意，這個同意被重送了一次，但系統套用不上去，於是留下一則沒有內容的訊息。這則空訊息傳出去，整個工作階段就以 user messages must have non-empty content 收場，你等半天等到一句錯誤。這次修掉了這種失敗，重送的同意套不上去時，工作階段不會再整個垮掉。

en

Claude Code launches again on macOS 12

If your Mac is still on macOS 12 (Monterey), Claude Code would not launch at all recently. This was not a case of an old system never being supported: it was a regression, meaning something that used to work got broken by a later change, introduced in 2.1.255. You changed nothing yourself; you just took the update, and the program stopped opening. It is fixed now, and Claude Code starts normally on macOS 12. The door of an old house used to open fine, then a crew replaced the frame and it jammed; the frame is now back to a size the door can clear.

Remote and scheduled sessions survive a re-sent approval that cannot be applied

Someone answers the roll call on another person's behalf, but the register stays blank; the clerk receives a record with nothing in it and sends the whole thing back unprocessed. Remote and scheduled sessions ran into something similar. You approved a permission request, that approval was sent again, and it could not be applied, leaving a message with no content. Once that empty message went out, the whole session ended with user messages must have non-empty content, and your long wait produced an error. That failure is now fixed: when a re-sent approval cannot be applied, the session no longer collapses.

如果你的 Mac 还停在 macOS 12（Monterey），前阵子会发现 Claude Code 根本打不开。这不是旧系统本来就不支持，而是 2.1.255 那一版改动时弄坏的，属于回归（regression，原本正常的功能在后续版本被改坏）。换句话说，你什么都没动，只是跟着更新，程序就开不起来了。这次已经修好，macOS 12 上可以照常启动。老宅的门原本进得去，工班换过门框后却卡住开不了，现在门框调回能开的尺寸。

ja

macOS 12 で起動できなかった問題が直る

Mac がまだ macOS 12（Monterey）のままなら、少し前から Claude Code がまったく起動しなかったはずである。これは古いシステムが元々未対応だったわけではなく、2.1.255 の変更で壊れたリグレッションである。リグレッションとは、正常に動いていた機能が後の版で壊れることを指す。つまり自分では何も触っておらず、更新に付いていっただけで起動しなくなっていた。今回これが修正され、macOS 12 でも通常どおり起動する。古い家の扉は元々問題なく通れたのに、業者が枠を入れ替えた後につかえて開かなくなり、今その枠が通る寸法に戻された。

再送された許可が適用できないとき、リモートと予約実行が失敗しなくなる

点呼で誰かが代わりに返事をしたのに名簿は空欄のままで、担当者は中身のない記録を受け取り、一式まるごと差し戻して処理しない。リモートセッションと予約実行のセッションでも似たことが起きていた。権限の確認に同意し、その同意が再送されたものの適用できず、中身のないメッセージが残る。その空のメッセージが送られると、セッション全体が user messages must have non-empty content で終わり、待った末にエラーだけが返ってきた。今回この失敗が修正され、再送された同意が適用できなくてもセッションは崩れない。

ko

macOS 12에서 실행되지 않던 문제를 고침

Mac이 아직 macOS 12(Monterey)라면 얼마 전부터 Claude Code가 아예 실행되지 않았을 것이다. 오래된 시스템이 원래 지원 대상이 아니었던 것이 아니라, 2.1.255 변경에서 깨진 리그레션이다. 리그레션은 잘 돌아가던 기능이 이후 버전에서 망가지는 것을 말한다. 다시 말해 본인은 아무것도 건드리지 않고 업데이트만 따라갔는데 프로그램이 열리지 않았다. 이번에 고쳐져서 macOS 12에서도 평소대로 실행된다. 오래된 집 문은 원래 잘 지나다녔는데 인부가 문틀을 갈아 끼운 뒤 걸려서 열리지 않았고, 이제 그 문틀이 지나갈 수 있는 치수로 돌아왔다.

다시 보낸 승인이 적용되지 않아도 원격·예약 세션이 실패하지 않는다

점호에서 누군가 대신 대답했는데 명부는 빈칸으로 남고, 담당자는 내용 없는 기록을 받아 한 묶음을 통째로 돌려보내며 처리하지 않는다.원격 세션과 예약 실행 세션에서도 비슷한 일이 있었다. 권한 확인에 동의했고 그 동의가 다시 보내졌지만 적용되지 못해 내용 없는 메시지가 남았다. 그 빈 메시지가 나가면 세션 전체가 user messages must have non-empty content로 끝나, 한참 기다린 끝에 오류만 돌아왔다. 이번에 이 실패가 고쳐져서 다시 보낸 동의가 적용되지 않아도 세션이 무너지지 않는다.
