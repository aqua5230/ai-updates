Claude Code 2.1.329

發布日期：2026-11-19

繁體中文

新功能

打開資料夾與對話時會先提醒 hook 狀況

打開陌生資料夾，你怎麼確定裡面沒有藏著會自動執行的腳本？進到信任確認畫面時，現在會直接寫明這個資料夾的 hook（掛鉤，特定事件發生時被觸發的小程式）宣告在哪裡。 如果你在 Claude Desktop 或其他非互動式環境工作，遇到管理設定裡的 hook 載入失敗，對話裡也會直接跳出警告通知你。

像進租屋處簽約前，房東把電錶箱與門鎖開關標得清清楚楚，哪條線路上不了電也會貼條通知，不用等你搬進去才自己摸黑猜。
新功能

/tasks 納管排程並統一背景任務計數

對話跑著跑著，背景常同時掛著定時提醒與各類執行項目，以前總散在不同角落。輸入 /tasks 後，清單現在會把目前工作階段的排程任務、/loop 喚醒項目、目標以及對話分岔全部列進來，選中某項按 x 確認後就能停掉它。 清單標題與底部背景計數已整合成單一數字。裡面包含終端機指令、監控腳本、MCP（讓 AI 連接外部工具的協定）呼叫、代理、工作流與排程任務。

如同機場把登機門廣播、行李轉盤與接駁車動態收進同一面出發總表，抬頭掃一眼總數，想取消哪一班也能當場抽單。
新功能

排程任務在重開與離開時的執行規則調整

更新後重開新的登入工作階段，舊版存下來的排程任務多半需要重新設定排程。不過如果你用 --resume 接回原本的工作階段，它們還是會照常跑。 選用「Exit and stop tasks」時，現在會真正結束這個工作階段的排程任務，下次恢復對話時不會再自己啟動。唯一例外是你在 Claude 還在回覆時就離開，任務才不會被停掉。

跟鬧鐘改版一樣，另開一個已登入的新工作階段得重新勾選提醒時段，但接回舊時光軸依然會響；親手按掉「離開並停止任務」後，下次翻開紀錄也不會再突然鈴聲大作。
新功能

Stop 掛鉤改將監控腳本標為 monitor

給有設定 Stop 與 SubagentStop hook 的使用者或開發者，這裡有個分類調整。當你的腳本讀取背景任務清單時，由 Monitor 執行的腳本現在會標成 monitor，不再歸類成 shell。

問題修復

/mcp 顯示連線拒絕訊息並修正 410 誤判

遠端 HTTP MCP 伺服器拒絕連線時，以前畫面常只給一個冷冰冰的失敗結果，搞不清對方擋在哪。現在打開 /mcp 裡該伺服器的頁面，會多出一行「Server message」，直接把遠端回傳的 JSON-RPC 錯誤訊息攤給你看。 用 claude mcp login 或 /mcp 登入時，若對方的用戶端註冊已經停用並回傳 HTTP 410 Gone，畫面也不會再誤判成該服務不接受從 Claude Code 登入。

好比打客服專線被掛斷時，電話不再只響忙音或誤報「門號禁止撥打」，而是直接播報對方總機寫好的故障原因，讓你立刻知道是哪一關擋下來。
問題修復

MCP 驗證、重連與工具載入的四項修復

連接外部工具最怕遇上斷線或驗證打架，這幾項異常狀態現在穩多了。 剛清除某台 MCP 伺服器的登入驗證，剛好撞上背景正在更新 token（授權令牌）時，伺服器不會再莫名其妙又自動登入回來。 背景的 MCP 任務在慢速重連後不再卡死。只要遠端 HTTP MCP 伺服器停留在較舊的協定版本，Claude Code 現在會自己幫大多數這類伺服器重新連線。 開啟工具搜尋的工作階段裡，已連上的 MCP 伺服器若工具載入失敗，Claude 現在會收到明確告知，不再誤以為它沒有任何工具。 同一網址的其他外掛或 MCP 伺服器連線失敗時，Claude Docs 連接器的工具不會跟著消失，錯誤提示也不會再亂叫你去執行 /login。

問題修復

修正檔案收存變 .bin 與首次傳檔失敗

從 MCP 伺服器或網站傳來的 PDF、圖片，以及 .docx、.xlsx、.pptx 檔案，有時會以 application/octet-stream 格式送出。過去這類檔案會被存成 .bin，導致 Claude 讀不到 PDF 與圖片，現在已經修好。 使用 Opus 4.8 與 Opus 5 請 Claude 傳檔案給你時，第一次傳檔偶爾失敗的狀況也修好了，不用再請它重傳一次。

新功能

Code Mode 啟用條件放寬與停用方式調整

想讓 Claude 自己寫腳本串接工具來跑的 Code Mode，過去遇到監控或特定模組就會被默默關掉。現在就算開啟 OpenTelemetry 事件與指標，Code Mode 也能啟用，腳本裡每次呼叫工具都會送出事件；只有開啟追蹤功能時仍會維持關閉。 就算關掉了遙測、非必要流量或功能旗標，Code Mode 一樣能啟動。如果管理員想明確停用，改由受管理的設定檔去關閉即可。 只列出部分工具的模組，也不會再悄悄把 Code Mode 關掉，想停用同樣要靠管理員設定控制。

打個比方，以前天文台只要氣象感測沒全接上就不開圓頂，現在就算拔掉幾條回報線也能觀星，真的不想開放得由館長親手下鎖。
新功能

Code Mode 腳本限制與掛鉤行為對齊一般模式

寫進 Code Mode 腳本裡的規則，現在跟一般對話操作越來越一致了。PreToolUse hook 如果出錯，不再直接擋下腳本裡的工具呼叫，跟一般模式相同。若在指令、HTTP 或 MCP 工具的 hook 上遇到失敗必須擋下，請加上 "onFailure": "block"。 腳本內如果自己宣告了 log、preview 或 sleep 這幾個名稱，以前會被直接拒跑，現在可以正常執行。 在 Code Mode 裡啟動子代理後，Claude 收到的等待指引也跟一般模式看齊，不再各走各的規則。

換成考場來看，內外原本各有兩套作答規矩，現在把錯題不倒扣、可用字詞跟交卷等待方式全對齊，真要嚴格擋下再另外標記。
新功能

Code Mode 記憶體控管與大檔讀取上限

讓 Code Mode 處理大檔案或跑長腳本，電腦比較不容易被拖垮。 腳本陷入無止境迴圈時，現在會在達到上限後自動停下，不再把整台機器的記憶體塞爆。 讀過的大型文字檔不再全部留駐在記憶體裡，背景子代理每次被喚醒時記憶體也不會持續膨脹。 腳本一次嘗試讀取超過 256 MiB 的行數範圍會被直接拒絕，避免吃掉幾 GB 的記憶體；讀取超長單行時逾時的問題也修好了。 當腳本執行上千次工具呼叫後，終端機畫面卡住不動的時間也縮短很多。

問題修復

Code Mode 呼叫 MCP 工具的等待與結束修復

在 Code Mode 腳本裡呼叫 MCP 工具等回應，過去可能在等待期間被停止，或直接無視工具訊號。 腳本等待 MCP 表單、連結提示或每次必問的提示回答期間，不會再因十分鐘上限而被停止。 大多數超過 2 分鐘的 MCP 呼叫，不再把「移到背景執行」這句話當成資料塞回給腳本。腳本現在最多會等到 10 分鐘，超過才回報錯誤。 當 Claude 等待腳本執行期間，若裡面的 MCP 工具要求結束這一輪對話，Code Mode 現在會照辦，不再忽視這個訊號。

問題修復

Code Mode 腳本變數、參數與中斷顯示修復

在 Code Mode 寫腳本並按 Esc 中斷，以前容易遇到幾個摸不著頭緒的毛病。 按 Esc 中斷後，腳本已經完成的編輯與被停下的指令不再躲起來，離開時也不會一併消失。 新腳本宣告 let x; 時，終於會是個乾淨的變數，不會偷留前一段腳本塞給 x 的舊值。 呼叫本來就不需要參數的工具時，不傳引數過去也不會再錯報「缺少參數」。 當工作階段裡掛了超過 4,096 個工具時，腳本透過 tools 依然找得到所有工具，不會半路失去存取權。

問題修復

修正網路卡頓導致 ~/.claude.json 遭重置

以前萬一遇到網路卡頓或檔案被鎖住，讓 ~/.claude.json 一時讀不到，存檔時整個設定檔就可能被清空重設回預設值。這個問題已經修好，你的設定不會再無故被洗白。

問題修復

macOS 鑰匙圈無法寫入時的登入與診斷調整

在 Mac 上如果 Claude Code 讀得到鑰匙圈卻寫不進去，以前常會把你反覆登出。現在更新登入憑證時會改用名為 Claude Code-write-check 的項目測試寫入權限。真的寫不進去時，只會讓目前這個工作階段在憑證到期時停下並說明原因，其他工作階段會繼續保持登入。 在 macOS 沙盒環境裡執行 claude doctor 時，也不會再誤建議你解鎖鑰匙圈，因為在沙盒裡解鎖根本幫不上忙。

像員工打卡鐘一時只能讀紀錄卻寫不進新班別，其他樓層的門禁不受影響，只有剛好到期的那張證件會亮燈說明停卡原因，管理室也不再叫你重設鎖死的分機。
問題修復

/terminal-setup 與自訂快捷鍵修復

操作表單、查看按鍵提示，或請它設定終端機與編輯器，現在不會再出錯或失靈。 跑 /terminal-setup 改 VS Code 設定或 keybindings.json，不再破壞區塊註解附近內容，有未閉合字串也不會漏掉 Shift+Enter 綁定卻回報成功。 在 macOS 27 的 Terminal.app，不再開啟「Use Option as Meta key」，提示也不再把 Shift+Enter 寫成 Option+Enter。 權限確認、提問、/model 與 /rewind 提示，都改照 keybindings.json 顯示。 自訂取消鍵在 /add-dir、/tui 回饋與儲存工作流表單都有效；在該表單按方向鍵不再移動背後游標。

問題修復

修正 IDE 差異存檔遺失換行與 BOM 標記

在 IDE 差異比對畫面點選接受修改，過去存檔後常少掉檔案最後一個換行符號。在 VS Code 直接儲存差異檔，甚至會弄丟開頭的位元組順序記號 BOM，這兩個問題都已修好。

問題修復

修正 /teleport 挑選雲端對話覆蓋目前紀錄

在 /teleport 挑選雲端工作階段時，以前會直接把你眼前正在聊的對話蓋掉。這個問題已經修好，現在選取後會像輸入 /clear 一樣開出一個新工作階段，想找回原本的對話只要打 /resume 就回得來。

問題修復

額度點數、消費上限與 /passes 顯示修復

查看額度或調整消費上限，以前可能遇到重複登入或提示與實際狀態不符。 Pro 與 Max 用戶開 /usage-credits 打開瀏覽器後，不再被要求重新登入。若瀏覽器沒開起來且任務因點數暫停，連結也不會在 8 秒後就消失。 使用點數用完或達到每月上限時，/usage 不再誤報點數功能已關閉。每月上限擋住使用點數運作的模型時，/model 會提醒 Pro 與 Max 用戶。 消費上限選單不再把目前花費錯印成每月上限，視窗較窄時選項也不會折行壓到滑鼠游標底下。 /passes 在伺服器出錯後不再顯示錯誤的訪客券數量，沒剩訪客券時也不再提示分享可得使用點數。

問題修復

修正 /config 開關連動與狀態列卡死

在設定畫面切開關或自訂終端機底部工具，介面反應與回饋都修正了。 若你自己寫的 status line（顯示在終端機最底下的狀態列）腳本停不下來一直印出內容，現在不會再把輸入列卡死並吃掉好幾 GB 記憶體。 在正在跑的工作階段裡改 /config 開關時，自動捲動、PR 狀態徽章、自動壓縮警告與 ultracode 標籤現在都會跟著即時切換。 在 /config 一次改了好幾個設定後，畫面也不再安靜沒反應或只冷冷回一句「dismissed」。

新功能

/status 顯示市集更新狀態與模型細節

想知道目前套了哪個模型、又有哪些市集沒在自動更新嗎？輸入 /status 後，畫面新增了「Marketplace auto-update」一欄，直接點名不會自動更新的受管理市集並說明原因。 規劃模式下跑 /status 時，現在也會明確寫出 opusplan 與 haiku 各自實際使用的模型名稱。 在 /model 選單裡，如果 Default 那一列本來就顯示你儲存的模型，點選它時不再被組織的預設模型覆蓋。

看懂這點就像翻手機電信帳單，明細表現在會直接寫清哪項服務沒開自動續約、目前實際跑哪套網路方案，選回預設也不會偷換成團體合約。
問題修復

/code-review 比對與結果顯示修正

請 Claude 用 /code-review 幫忙檢查程式碼，過去常審錯分支，或莫名卡在不存在的檔案權限。 不帶目標時，多數模型改把整條分支跟預設分支比對，並修好跨多筆提交漏掉差異。 指定 /code-review <pr number> 會改用 gh pr diff 讀該 PR，不再默默審本地分支。讀不到會說明。 帶 --fix 的 PR 編號形式，或提供 PR 網址時，若 gh pr diff 失敗或被拒，會直接停止審查。 多數模型不再為不存在的 ~/.claude/CLAUDE.md 跳權限確認，結果卡片也不再把中等審查標成「high」。

問題修復

自架執行器修正 Git LFS、SSH 與啟動誤判

在 Self-hosted runner（自架執行器）環境跑工作階段，Git 倉庫設定與連線問題少了很多。 加上 --push-outcome-on-release 時，不再偶爾誤刪遠端 Git 主機上該工作階段的分支。 透過 Anthropic 託管 Git 複製 Git LFS 倉庫時，工作階段準備失敗的問題已修好。工作階段會先從指標檔啟動，需要實際內容時再執行 git lfs pull 抓下來。 遠端網址若使用 SSH 主機別名、GitHub SSH 憑證或 GHE.com SSH 使用者，現在都能順利啟動。遇到無法解析的別名時，錯誤訊息還會直接附上兩個 git 指令。 遇上逾時或網路錯誤後，遠端 MCP 伺服器不再停在無工具或 HTTPS 斷線狀態；Claude Code 還在啟動期間，也不再被誤顯示成沒有回應。

新功能

自架執行器調整倉庫複製路徑與資料夾規則

管理 Self-hosted runner 的機器磁碟與掛載規則，有幾項資料夾路徑變動要留意。 同一個擁有者與倉庫名稱若來自第二個主機名稱，新的複製檔會放進基礎資料夾底下的 _repos/clones/<host>/，既有的複製檔不會搬動。 網址路徑含有特殊字元的倉庫，現在會改在新的資料夾重新複製。原本指定舊資料夾的規則與磁碟掛載區不再套用，舊資料夾本身則會留在原地。 啟動時若加上 --capacity 1，--repository-folder 可以接納基礎資料夾內大多數的資料夾。容量大於 1 時，若將 --repository-folder 指向基礎資料夾內的這類資料夾，會停止啟動。若有其他倉庫的工作階段重疊到該資料夾也會被拒絕。

問題修復

代理團隊與背景任務的中斷、執行調整

同時指揮多個代理或跑背景任務，控制與中斷反應終於對得上指令了。 在代理團隊裡替具名隊友設定 Agent 工具的 effort 參數時，現在會真正生效，不再被忽略。 部分隊友窗格現在改透過 /bin/sh 啟動，因此可能不會讀取你原本設定的 shell 啟動檔。 背景代理正在恢復時被喊停，不會再繼續往下跑；雲端工作階段重啟期間若背景任務被停掉，Claude 現在也會收到通知。 在 Bedrock 上用 Claude Desktop 工作階段時，若卡在沒回應的 AWS credential_process 或登入呼叫，按下 Stop 現在能真正結束這次請求。

新功能

長時間對話、Desktop 與背景的記憶體瘦身

跑久了編輯大量檔案或開著遠端連線，電腦記憶體比較不容易越吃越多。 背景執行的終端機指令，不會再在結束前一直抓著早期對話的記憶體不放。 在 Claude Desktop、各款 IDE 或 SDK 執行的工作階段裡，對話經過壓縮或執行 /clear 後，Remote Control 也不再繼續佔用早期對話的記憶體。 在編輯過大量檔案的長工作階段，以及 macOS 和 Linux 上累積許多大型 MCP 工具結果的 Claude Desktop 長工作階段中，記憶體用量都降低了。 閒置的 Claude Desktop 與 SDK 工作階段在長回合結束後，或是用 --resume、--continue 接回帶有截圖或大型工具結果的工作階段時，佔用的記憶體也更少。

問題修復

外掛同步、無頭斷線與雲端重試修復
