Claude Code 2.1.329

Released: 2026-11-19

Release notes

FEATURE

Hook warnings when opening folders or conversations

When you open an unfamiliar folder, how can you tell there aren't any hidden scripts that run on their own? The trust dialog now spells out where that folder's hooks (small programs triggered by specific events) are declared. If you are working in Claude Desktop or another non-interactive host and hooks in managed settings fail to load, a warning now appears right in the conversation.

Picture walking through a rental before signing the lease: the landlord clearly labels the breaker box and door locks, and tapes a note on any circuit that cannot power on, so you are not left guessing in the dark after moving in.
FEATURE

/tasks adds scheduled tasks and unifies background counts

As a conversation runs, timed reminders and various background runs often pile up in different places. When you enter /tasks, the list now includes this session's scheduled tasks, /loop wakeups, the goal, and this conversation's forks, and you can select an item and press x to stop it after confirming. The list header and the footer's background count now show a single combined number. It covers shells, monitor scripts, MCP (a protocol that connects AI to external tools) calls, agents, workflows, and scheduled tasks.

Think of an airport pulling gate announcements, baggage carousels, and shuttle statuses onto one departures board: you can see the total at a glance and pull a flight from the board on the spot.
FEATURE

Updated rules for scheduled tasks on reopen and exit

After updating, if you start a new signed-in session, most scheduled tasks saved by earlier versions will need to be scheduled again. However, if you use --resume to return to their original session, they will still run as usual. Choosing "Exit and stop tasks" now actually ends this session's scheduled tasks so they do not start on their own next time you resume the conversation. The only exception is if you exit while Claude is still responding, in which case the tasks are not stopped.

Like updating an alarm app, opening a new signed-in session means re-checking your reminder times, though jumping back onto the old timeline still rings them; once you tap "Exit and stop tasks" yourself, reopening the log later will not set off unexpected alarms either.
FEATURE

Stop hooks now label monitor scripts as monitor

For users or developers with Stop and SubagentStop hooks configured, there is a classification change. When your script reads the background tasks list, scripts run by a Monitor are now labeled monitor instead of shell.

BUGFIX

/mcp shows connection refusal messages and fixes 410 mislabeling

When a remote HTTP MCP server refuses a connection, the screen used to show only a cold failure notice without explaining where it got blocked. Now, opening that server's page in /mcp includes a "Server message" row that displays the JSON-RPC error message returned by the remote server. When signing in with claude mcp login or /mcp, if the other side's client registration has been retired and returns HTTP 410 Gone, the screen will no longer mistakenly report that the service does not accept sign-ins from Claude Code.

Imagine calling a support hotline and getting disconnected: instead of just hearing a busy tone or a false "number not permitted" error, the line plays the exact fault reason written by the other side's switchboard so you know right away which step blocked you.
BUGFIX

Four fixes for MCP auth, reconnects, and tool loading

Connecting to external tools is hardest when disconnects or auth conflicts hit, and several of those edge cases are now much more stable. If you clear an MCP server's sign-in authentication right as a background token (authorization credential) refresh is running, the server will no longer mysteriously sign itself back in. Background MCP tasks no longer stall after a slow reconnect. When a remote HTTP MCP server stays on an older protocol version, Claude Code now reconnects most of those servers on its own. In sessions with tool search enabled, if a connected MCP server fails to load its tools, Claude is now explicitly told instead of assuming the server has no tools. When another plugin or MCP server at the same address fails to connect, the Claude Docs connector's tools no longer disappear along with it, and the error prompt no longer wrongly tells you to run /login.

BUGFIX

Fixed files saved as .bin and first-try file send failures

PDFs, images, and .docx, .xlsx, and .pptx files sent from MCP servers or websites sometimes arrive as application/octet-stream. Previously, those files were saved as .bin, preventing Claude from reading the PDFs and images; that is now fixed. When asking Claude to send you a file on Opus 4.8 and Opus 5, occasional failures on the first attempt are also fixed, so you no longer need to ask it to resend.

FEATURE

Relaxed Code Mode startup conditions and disable controls

Code Mode, which lets Claude write its own scripts to chain tools together, used to be silently turned off when monitoring or certain mods were active. Now Code Mode can stay on even when OpenTelemetry events and metrics are enabled, and each tool call in a script sends its events; only tracing still keeps it off. Code Mode can also start when telemetry, nonessential traffic, or feature flags are turned off. If an administrator wants to explicitly keep it off, they can disable it in managed settings instead. Mods that list only some tools will no longer silently turn Code Mode off either; disabling it likewise requires administrator settings.

An observatory used to keep its dome shut whenever a single weather sensor was unplugged, whereas now it still opens for stargazing with a few reporting lines disconnected—keeping it closed takes the director locking it by hand.
FEATURE

Code Mode script rules and hook behavior match standard mode

Rules for Code Mode scripts are becoming more consistent with regular conversation behavior. If a PreToolUse hook errors, it no longer blocks the script's tool call, matching regular mode. If a failure on a command, HTTP, or MCP tool hook must block execution, add "onFailure": "block". Scripts that declare their own log, preview, or sleep names used to be refused outright, and now run normally. After starting a subagent in Code Mode, Claude now receives the same waiting guidance as in regular mode instead of following separate rules.

Previously, the exam hall enforced one set of rules inside and another outside, but now no-penalty errors, allowed terms, and turn-in waiting rules are all aligned, with strict blocks marked separately.
FEATURE

Code Mode memory controls and large-file read limits

Having Code Mode process large files or run long scripts is now much less likely to bog down your computer. When a script gets stuck in a runaway loop, it now stops automatically at a limit instead of filling up the entire machine's memory. Large text files that have been read are no longer all kept in memory, and memory no longer keeps growing each time a background subagent is woken. If a script tries to read a line range over 256 MiB at once, it is now refused to avoid using gigabytes of memory; timeouts when reading very long single lines are also fixed. After a script makes thousands of tool calls, the terminal freezes for far less time.

BUGFIX

Fixes for Waiting and Ending in Code Mode MCP Calls

When a Code Mode script called an MCP tool and waited for a response, it could previously be stopped while waiting or ignore the tool's signal. A script waiting for an answer to an MCP form, an MCP link prompt, or a prompt that always asks is no longer stopped at the ten-minute limit. Most MCP calls over 2 minutes no longer pass a "moved to the background" message back to the script as data. The script now waits up to 10 minutes before reporting an error. When an MCP tool called from a script that Claude is waiting on asks to end the turn, Code Mode now honors that request instead of ignoring the signal.

BUGFIX

Fixes for Code Mode Script Variables, Arguments, and Interrupts

Writing scripts in Code Mode and interrupting them with Esc used to trigger several puzzling issues. After pressing Esc, finished edits and the stopped command from a script no longer stay hidden or disappear on exit. When a new script declares let x;, it now starts clean instead of keeping the old value an earlier script gave x. Calling a tool that needs no parameters without arguments no longer fails with a missing-parameter error. When a session has more than 4,096 tools, scripts still find every tool through tools instead of losing access partway through.

BUGFIX

Fix for ~/.claude.json Resetting During Network Stalls

Previously, if a network stall or file lock made ~/.claude.json temporarily unreadable, saving could clear the entire configuration file and reset it to defaults. That issue is now fixed, so your settings will no longer be wiped for no reason.

BUGFIX

Login and Diagnostic Adjustments for Read-Only macOS Keychain

On a Mac, when Claude Code could read the Keychain but not write to it, it used to sign you out repeatedly. Now, renewing login credentials tests write access using an item named Claude Code-write-check. If writing actually fails, only the current session stops at credential expiry and explains why, while other sessions stay signed in. Running claude doctor inside a macOS sandbox also stops mistakenly advising you to open the locked Keychain, since doing so cannot help inside a sandbox.

A time clock can read punch records for a moment yet cannot write new shifts: access on other floors stays untouched, only the badge that happens to expire lights up to explain why it stopped, and the front desk stops telling you to reset a locked extension.
BUGFIX

Fixes for /terminal-setup and Custom Keybindings

Working with forms, checking key hints, or having Claude configure your terminal and editor will no longer break or fail. Running /terminal-setup to update VS Code settings or keybindings.json no longer corrupts content around block comments, and an unclosed string no longer drops the Shift+Enter binding while reporting success. In Terminal.app on macOS 27, it no longer turns on "Use Option as Meta key", and tips no longer suggest Option+Enter instead of Shift+Enter. Key hints in permission prompts, questions, /model, and /rewind now follow keybindings.json. A custom cancel key now works in /add-dir, /tui feedback, and the save-workflow form; pressing arrow keys in that form no longer moves the cursor behind it.

BUGFIX

Fix for Missing Final Newlines and BOM in IDE Diffs

When you accepted edits in the IDE diff view, saved files used to lose their final newline. Saving a diff directly in VS Code could even drop the leading byte order mark (BOM); both issues are now fixed.

BUGFIX

Fix for /teleport Overwriting the Current Conversation

Picking a cloud session in /teleport used to overwrite the conversation you were currently in. That is now fixed: selecting one starts a new session just like /clear, and you can bring your old conversation back anytime with /resume.

BUGFIX

Fixes for Usage Credits, Spend Limits, and /passes Display

Checking your usage credits or adjusting spend limits could previously trigger repeated logins or show prompts that did not match the actual state. Pro and Max users opening the browser from /usage-credits are no longer asked to log in again. If the browser fails to open and a task pauses for usage credits, the link no longer disappears after 8 seconds. When usage credits run out or hit the monthly limit, /usage no longer falsely reports that usage credits are off. When the monthly limit blocks a model that runs on usage credits, /model now notifies Pro and Max users. The spend limit menu no longer displays your current spend as your monthly limit, and in narrow windows its rows no longer wrap under the mouse pointer. /passes no longer shows the wrong number of guest passes after a server error, and it stops offering usage credits for sharing when no guest passes remain.

BUGFIX

Fixes for /config Toggles and Status Line Freezes

Toggling settings or customizing the bar at the bottom of your terminal now gives proper UI responsiveness and feedback. If a custom status line (the bar shown at the bottom of your terminal) script prints endlessly without stopping, it no longer freezes the input prompt and consumes gigabytes of memory. Changing /config switches in a running session now updates auto-scroll, the PR status badge, the auto-compact warning, and the ultracode tag right away. After changing several settings at once in /config, the screen no longer stays silent or just replies "dismissed".

FEATURE

/status Shows Marketplace Updates and Model Details

Want to know which model is active and which marketplaces are not auto-updating? Running /status now includes a "Marketplace auto-update" row that names managed marketplaces getting no automatic updates and explains why. When you run /status in plan mode, it also explicitly names the actual models used by opusplan and haiku. In the /model menu, when the Default row already shows your saved model, selecting it no longer overwrites it with your organization's default model.

Reading this feels like checking a mobile carrier bill where the breakdown now spells out which service has auto-renew turned off and which data plan is actually running, and picking the default option no longer swaps you into a group contract.
BUGFIX

Fixes for /code-review diffs and findings display

Asking Claude to check code with /code-review used to review the wrong branch or get stuck on permissions for a missing file. With no target, most models now compare the whole branch against the default branch and no longer lose diffs across multiple commits. Passing /code-review <pr number> now reads that pull request with gh pr diff instead of silently reviewing the local branch. It says so when it cannot read it. When using the PR number form with --fix or providing a pull request URL, the review now stops immediately if gh pr diff is refused or fails. Most models no longer show a permission prompt for a missing ~/.claude/CLAUDE.md, and the findings card no longer labels a medium review as "high".

BUGFIX

Self-hosted runner fixes for Git LFS, SSH, and startup

Running sessions in a self-hosted runner environment now has far fewer Git repository setup and connection issues. Using --push-outcome-on-release no longer occasionally deletes the session's branch on the remote Git host. Session setup no longer fails on Git LFS repositories cloned through Anthropic-managed Git. Sessions now start from pointer files and run git lfs pull when the actual content is needed. Sessions now start cleanly from remotes using an SSH host alias, GitHub SSH certificates, or a GHE.com SSH user. When an alias cannot be resolved, the error message includes two git commands directly. After a timeout or network error, remote MCP servers no longer stay without tools or disconnected over HTTPS, and Claude Code is no longer shown as unresponsive while still starting.

FEATURE

Self-hosted runner clone paths and folder rules

If you manage disk and mount rules for self-hosted runner machines, several folder path changes apply. When a clone of the same owner and repository name comes from a second host name, it now goes under _repos/clones/<host>/ in the base folder, and existing clones do not move. Repositories with unusual characters in their URL path now clone anew into a new folder. Rules and disk volumes naming the old folder stop applying, while the old folder stays in place. When starting with --capacity 1, --repository-folder accepts most folders inside the base folder. Above capacity 1, pointing --repository-folder to one of those folders in the base folder stops startup, and any session from another repository overlapping that folder is also refused.

BUGFIX

Agent team and background task execution fixes

Control and interruption responses now match your commands when directing multiple agents or running background tasks. Setting the Agent tool's effort parameter for named teammates in agent teams now takes effect instead of being ignored. Some teammate panes now start through /bin/sh, so they may not read your configured shell start-up files. A background agent stopped while resuming no longer keeps running, and Claude is now notified when a background task is stopped while a cloud session is restarting. In Claude Desktop sessions on Bedrock, pressing Stop now ends the request when waiting on an unresponsive AWS credential_process or sign-in call.

FEATURE

Memory reductions for long sessions, Desktop, and background

Memory is less likely to keep growing during long runs that edit many files or keep remote connections open. Background shell commands no longer hold onto memory from the earlier conversation until they exit. In sessions run by Claude Desktop, IDEs, or the SDK, Remote Control no longer holds onto memory from the earlier conversation after compaction or /clear. Memory use is lower in long sessions that edit many files, as well as in long Claude Desktop sessions on macOS and Linux with many large MCP tool results. Idle Claude Desktop and SDK sessions also use less memory after a long turn, or after using --resume or --continue on a session holding screenshots or large tool results.

BUGFIX

Plugin sync, headless disconnect, and cloud retry fixes

When syncing plugins across devices, plugins and their underlying tools now stay in sync. Fixed another case on macOS where a claude.ai-synced plugin hook failed with "Plugin directory does not exist" while a session was still running. In headless (running without a terminal window) sessions, MCP servers attached to a removed plugin now disconnect after running reload_plugins or when the plugin is dropped from the account list. Cloud sessions now retry plugins that fail to download at startup.

FEATURE

Faster auto mode checks and improved allow rules

Letting Claude work in auto mode now involves fewer unnecessary waits and false blocks. Auto mode runs git status less often, shortening wait times for most requests in large repositories. However, a git command that discards changes may still be blocked until the working tree is checked. When running /auto-mode-setup to scan a project for rules to suggest, it now considers recent auto mode denials and may propose allow rules from them, letting you review each one before saving. Using rm to delete a symlink (a shortcut file pointing to another location) that points outside the working directory or at itself no longer asks for manual approval. Handling of short replies such as "yes" is more accurate when telemetry is off, behind a gateway to the Anthropic API, or on Microsoft Foundry. After a failed request in cloud sessions, Claude is no longer told to run a network proxy check that auto mode would block.

BUGFIX

Fixed Linux /sandbox socket status display

Seeing allowUnixSockets listed as allowed made it look like the setting took effect. In practice, running /sandbox on Linux does not open those sockets, and /sandbox now states that accurately.

BUGFIX

Fixed /install-github-app and sharing status reporting

When installing the GitHub app with /install-github-app, pressing Esc twice to clear a mistyped code no longer ends the sign-in, so you can clear and re-enter it. When running /team-onboarding on Team and Enterprise plans, the screen no longer reports a guide as shared if the server actually refused the upload.

FEATURE

Remote Control status sync and response speed improvements

Screen info and responsiveness now stay better aligned when controlling desktop sessions from mobile or the web. After a Remote Control session restarts, it no longer falls back to its initial effort level while the app still shows the level you picked. However, this does not yet apply to sessions that start in Ultracode. Titles set with /rename or a UserPromptSubmit hook in claude remote-control sessions now appear on claude.ai and mobile. When a branch renames a file and then edits it, the Remote Control diff no longer lists the same file twice. Claude Desktop Code sessions with Remote Control enabled are now ready for the next message faster after an answer.

BUGFIX

Fix Missed Extra-Directory Scans and Early Headless Forking

When you use --add-dir to point to the current working directory, or start Claude Code from your home folder, newly created skills, commands, or agents folders could previously be missed; now they are all scanned. In headless mode (running without a terminal window), if a message sent right after switching models is still waiting for the model switch to finish, rewind and fork will no longer jump ahead and run early.

BUGFIX

Project Settings Application and Permission Save Warning Fixes

If you changed project settings and felt they didn't take effect, or saw an unexpected warning when saving permissions, those issues are now fixed. Sessions started from a pre-warmed process now read the autoCompactWindow setting in the project's .claude/settings.json instead of skipping it. After removing CLAUDE_AUTOCOMPACT_PCT_OVERRIDE from settings.json, running sessions also immediately lift its effect instead of letting it linger. In a subfolder or worktree (a Git feature that lets you open multiple parallel copies of the same project), its own .claude/settings.local.json can sometimes be unreadable or malformed. Adding a permission rule or folder there will no longer falsely trigger a "Couldn't save this change" warning.

BUGFIX

Terminal Scrolling, Prompt Bar, and Window Clipping Fixes

When browsing history in the terminal, going fullscreen, or shrinking the window, the display no longer drops characters or breaks lines unexpectedly. Panels and questions in fullscreen are no longer cut off at the prompt bar. In shorter windows, /help, history search, and the background tasks list no longer drop rows or lose titles, and tables in dialogs no longer wrap awkwardly. After copying text and scrolling up, the "Jump to bottom" button no longer stays hidden, and the row beneath it no longer goes blank when its label changes. Pressing PageUp repeatedly in fullscreen also no longer scrolls too far. When memory is tight, screen updates are no longer occasionally skipped, and long code blocks in scrollback no longer drop a blank line while repeating another. When prompt text contains a color code that sets multiple styles at once and a keyword or command is highlighted, characters no longer disappear for no reason.

BUGFIX

Session Resume Labels, File Line Counts, and Help Output Fixes

Several misleading bits of text on screen when resuming an old conversation or viewing files and command help have been removed. When resuming a previous session, edits, questions, and plans that were cut off because the conversation ended are no longer mislabeled as "Rejected" or "Declined". The hint line mentioning earlier messages on resume also no longer falsely blames an intact file for being damaged. The Read tool and @ mentions no longer display one extra line for files that end with a newline. Prompt suggestions in the input box no longer occasionally show placeholder text like _(no suggestion)_. Piping claude --help output to another program no longer cuts off the text partway through.

FEATURE

Setup Screen Freeze Fix, Restart Login Wait, and Old Session Cleanup

Entering or leaving sessions and restarting the interface now comes with far fewer freezes or unexpected sign-outs. When the --resume picker, trust confirmation dialog, or another setup screen is waiting for your input, approving managed settings no longer leaves you stuck on an empty, frozen screen. Running /tui or other in-place restarts now waits briefly for the login state to finish refreshing, making it less likely to sign you out. On computers with managed settings applied, automatic cleanup of old sessions has also been improved.

FEATURE

Shorter Wait on Windows PCs With Slow Search Startup

When you open Claude Code on Windows to get started or run your first query, if its built-in search tool takes a while to start up, it used to stall for a bit. Now the wait time for startup and the first search is shorter.

FEATURE

New Safety Rules and Launch Timeout for macOS Computer Use

When letting Claude operate your macOS screen directly, there are new rules for both safety boundaries and wait times. Computer use has been updated to newer safety guidelines, so some actions will be refused and certain apps have reduced access. When asking it to open an app, if the launch hasn't finished after 30 seconds, it gives up right away instead of waiting indefinitely.

Asking a neighbor's kid to come inside and flip appliance switches works much the same way: now several drawers are locked off-limits, and if an old faucet won't budge after 30 seconds, they just let go instead of waiting around.
FEATURE

Boxed Startup Warning on Every Launch When Gateway Allowlist Is Empty

When running Gateway (an entry service that forwards traffic), if the access_control.allow_cidrs allowlist is left empty, the previous startup warning now appears on every launch. This notice is boxed in plain-text logs: never expose Gateway directly to the public internet.

Much like a shop opening its doors each morning, as long as nobody has set who is allowed inside, rolling up the shutter prints a boxed reminder in the log: "Don't leave the front door wide open to the street."
FEATURE

Remove Automatic Retry on max_tokens Errors

If your request hit the max_tokens limit, 2.1.326 previously retried using the cap listed in the error message. This release removes that behavior. If the model behind your gateway accepts fewer output tokens (the text units AI processes and bills by), set the CLAUDE_CODE_MAX_OUTPUT_TOKENS environment variable to that limit yourself.

When a truck gets pulled over for being overweight, the fleet used to automatically lighten the load to match the posted limit and send it back out, whereas now it won't retry on its own and you have to enter the limit before heading out.
FEATURE

VS Code Review Trust Prompt, Sign-In Refresh, and Credits Banner

Declining folder trust, waiting on sign-in responses, and viewing the quota banner in VS Code are all smoother now. After you decline the trust prompt, an extra line with a "Review trust" button appears above the message box so you can bring the trust prompt back without reloading the whole window. When the sign-in server takes 10 to 30 seconds to answer the extension's token refresh, it no longer signs you out of Claude Code across all windows and terminals. When usage credits are in use, the limit banner now says so accurately, and the session survey no longer covers that banner or the usage credits card.

Suppose you clicked "Decline terms for now" on a website: now a small button stays above the input bar so you can accept anytime without reloading the whole page, and the survey card no longer covers your remaining credits.
FEATURE

VS Code Permission Prompt Reasons and Keyboard Focus

When confirming permissions for built-in tools in VS Code, you can now see why a safety check is asking; other permission prompts are also easier to use with a keyboard or screen reader. When built-in tools such as Bash, Edit, and Write ask for confirmation, the prompt now states why the safety check is asking instead of leaving you to guess. If a new permission request arrives while the "Account & Usage" dialog is open, screen readers now announce it right away instead of waiting until you close the dialog. When buttons in a permission prompt switch on, keyboard focus is no longer pulled away so you can keep scrolling down through the details. Pressing the Down arrow key through a permission prompt now stops at the last item instead of wrapping back to "Yes".

BUGFIX

VS Code Chinese Input Method Composition Fixes

Ever hit Enter by mistake while picking a character in a Chinese input method? When typing with an input method such as Chinese or Japanese in VS Code, a single keystroke no longer triggers menus or overwrites your input by accident. Keys pressed while an input method is composing no longer move focus on a permission prompt, decline confirmation, trigger menu bar items, or close dialogs. A half-written plan comment is no longer lost or moved to another passage. Pressing Enter while composing also no longer sends the comment, ends a session rename early, or picks an @-mentioned file by mistake. Pressing the Up arrow key while composing in the message box no longer pulls up an earlier message over the text you are composing.

BUGFIX

VS Code Tab Opening, Diff, and Drag-and-Drop Fixes

Dragging folders, clicking links to open files, and viewing tool output in VS Code no longer fight you with broken tabs and buttons. After a terminal Claude Code session disconnects, its proposed-edit diff tab no longer stays open along with the Accept button that did nothing. When short tool inputs and outputs are cut off at the panel's edge, you can now click to open the full content in an editor tab. Dragging to select text also no longer opens a new tab by mistake. On VS Code 1.103 to 1.139 or in a floating chat window, dropping an Explorer folder onto the chat no longer does nothing, and the drop highlight no longer vanishes with a false "Hold Shift" hint. When claudeCode.lockEditorGroups is off, clicking file links in a Claude tab no longer opens them in another editor group.

FEATURE

VS Code Strikethrough, Dictation, and Command Text Display

Viewing chat text or command output in VS Code comes with a few changes to how formatting and characters are displayed. Numeric ranges written with a single tilde, such as 3~5 … 7~10, no longer lose their tildes and show struck-through text in between; only double tildes ~~text~~ render as strikethrough now. Dictation error messages no longer wrap into a narrow column, the spinner no longer keeps turning while a question card waits for an answer, and output from a failed UTF-16 command no longer shows a NUL symbol after each letter. Command output now renders hidden characters and control sequences other than plain colors as visible symbols. As a result, Persian, Khmer, Lao, Sinhala, and Malayalam text can currently look broken or out of order.

Proofreading a manuscript this way restores the tildes meant to be printed and flags hidden formatting codes with visible symbols, though the layout of a few specific languages breaks for now.
