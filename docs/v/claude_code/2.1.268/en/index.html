Claude Code 2.1.268

Released: 2026-09-10

Release notes

FEATURE

Enterprise Gateway Pricing Sync, Startup Warnings, and Internal Network Sign-In

When enterprises deploy a Claude apps gateway for their teams, they now get more consistent billing and security controls.

This is like setting up a dedicated shuttle terminal on a corporate campus, where dispatch fares are posted centrally, horns sound whenever unfamiliar outside passengers board, and only the company's designated commuter routes are approved.

By setting pricing: in gateway.yaml, signed-in Claude Code clients receive the same rates through managed settings, keeping the /cost command and telemetry accurately matched to the spend meter. When access_control.allow_cidrs is empty, the gateway now issues a warning at startup and a one-time warning the first time a request arrives from a public address. In addition, administrators can configure the gatewayInternalNetworks managed setting to allow users to /login to the gateway on their organization's own public IPv4 block.

FEATURE

Dedicated Artifact Tab Icons, Data-Edit Cards, and Hardened Access Checks

Artifacts receive visual and permission updates.

When published, browser tabs now display a dedicated icon chosen by Claude to match each page. The terminal permission prompt now leads with the ask's question, and data-edit permission prompts switch to a card showing the document count and who can open the artifact. In local Cowork sessions configured to skip all approvals, security protections are further hardened. The Artifact tool now directly refuses to read local files outside session folders or behind symlinks. Plain WebFetch rules no longer apply to Artifact tool reads and updates, requiring dedicated rules to gate them:

# Block or gate Artifact reads and updates
Artifact
WebFetch(domain:claude.ai)

An issue since version 2.

1.265 where third-party compatible endpoints returned HTTP 400 due to a regex in the schema has also been fixed.

The overall protection is like a museum glass display case, where clear exhibit icons and visitor guides are posted outside, items inside cannot be swapped across boundaries, and non-dedicated corridors no longer connect freely to external tour routes.
FEATURE

Plugin Management Structured Output and Instant Menu Updates

For automating tool management via scripts, plugin commands now provide full structured output support, with error and note details added to list rows:

claude auth status --json             # Output includes configDirectory
claude plugin install --json          # Install plugin
claude plugin uninstall --json        # Uninstall plugin
claude plugin update --json           # Update plugin
claude plugin enable --json           # Enable plugin
claude plugin disable --json          # Disable plugin
claude plugin list --json             # Each row includes errorDetails and noteDetails

When installing, enabling, or disabling plugins through the /plugin terminal menu, changes take effect immediately upon closing the menu without running /reload-plugins.

Additionally, fixes resolve claude plugin validate mistakenly rejecting plugin paths beginning with two dots, as well as plugin checks silently skipping default monitors files or root SKILL.md files.

This workflow is like upgrading a toolbox with standardized latches and clear labels, where swapped bits lock in instantly for immediate use, while spec sheets and error codes are cleanly read by automated conveyor belts.
BUGFIX

Strict Symlink Permission Checks, Masked Connection Secrets, and Untrusted Agent Isolation

Terminal security protections are now more thorough.

This defense is like a multi-stage identity verification gate across a campus, verifying fingerprints whether visitors arrive at the main entrance or side doors, keeping confidential credentials in sealed pouches, and never letting anyone through merely because invocation phrases change.

Deny and ask rules now apply to /etc, /tmp, and /var on macOS or /bin on Linux whether specified by their real location or a symlink, and Bash commands no longer ignore symlink spellings. Read and Edit deny rules remain effective even when unanalyzable commands such as env -C or eval appear on the same line. Plugin and marketplace errors no longer leak tokens or passwords from Git URLs. Resolved secrets from ${VAR} placeholders in configs no longer appear in /mcp or /plugin details, claude mcp list/get, or MCP login errors. Respawned in-process teammates no longer pick up tools or prompts from untrusted directories, and Bash sandbox instructions no longer overstate confinement restrictions.

FEATURE

Stable Cloud Inference Tools and Tiered Task-Tracking Rollout

When developing with Claude through major cloud platforms, inference environments and tool-loading mechanisms are now more standardized.

In Bedrock, Vertex, and Foundry sessions, environment, model, and settings details are delivered as attachments, matching first-party sessions. Tool lists on these platforms remain byte-stable across conversations, with late-connecting tools loading deferred instead of rewriting the list. Task-tracking tools are now offered by default only on designated model families:

# Only Claude 3.x, Opus 4.0 to 4.7, Sonnet 4.0 to 4.6, and Haiku 4.5
# Enable for other models via environment variable:
CLAUDE_CODE_ENABLE_TODO_TOOLS=1

This includes TaskCreate, TaskGet, TaskUpdate, TaskList, and TodoWrite tools.

Furthermore, for SDK sessions using excludeDynamicSections, the first message is no longer re-rendered on each request, fixing prompt caching and extended thinking breaking mid-session.

The overall architecture is like distributing standardized equipment crates to branch laboratories, where instruments stay in place according to fixed manifests without mid-way reshuffling, and only qualified technicians receive project work orders.
BUGFIX

Model Cache Access Fixes and Accurate 1M-Context Prompts for Long Sessions

For users frequently switching models or sending lengthy prompts in conversations, access permissions and error notices are now more accurate.

This is like a VIP library pass where membership access is never blocked upon re-entry due to outdated records, and desks are never silently downgraded while reading.

Entitled users no longer receive false model restriction messages after restart or in the Desktop Code tab due to stale cached access denials. When another Claude Code process refreshes a stale model-access entry, running sessions no longer silently switch back to the organization's default model. For Pro and Team plan users triggering long-context 429 rate limits on Fable models, the prompt now correctly shows the 1M-context message instead of the usage-credits consent dialog. Related messaging has also been improved to clearly remind users that usage credits enabled mid-session take effect after restarting Claude Code.

FEATURE

Preserved Special Characters in Compaction and Line-Marked Memory Truncation

History summaries and project memory after lengthy conversations no longer suffer text corruption from special characters.

When executing the /compact command in the terminal or triggering auto-compact, generated summaries no longer mangle text containing $ character sequences. When resuming conversations that ended with /compact, restored-file notes now maintain the exact same loading order on every resume. For SDK prompt suggestions, side questions, and /rename, fixes ensure they no longer send the pre-compaction transcript. When a project's MEMORY.md file is truncated due to length limits, the warning message now explicitly states how many lines were cut and where the truncation begins.

This is like an archival binding process where condensing thick dossiers preserves symbols and paragraphs orderly, and trimming oversized sheets stamps the starting position and total cut pages.
BUGFIX

Faster Agents Panel Navigation, Worktree Stuck Fixes, and Script Parsing Optimizations

Interface operations for managing background agents and workflows are now snappier.

In the claude agents UI, pressing the left arrow key ← to return to the agent list is no longer ignored, eliminating the need to pause for over a second. Fixes improve issues where deleting an agent session got stuck. If removal halts because a worktree cannot be removed, the message specifies the cause and next steps, and pressing Ctrl+X again still force-deletes the directory. Background agent and workflow rows in the panel no longer stretch into multiple lines when text contains line breaks. Remote Control sessions served by claude remote-control now display session titles instead of generated names in ListAgents. Furthermore, listing .claude/workflows/ scripts at startup no longer parses each script individually, speeding up launch times.

This workflow operates like an airport flight status board, switching screens instantly on demand, force-towing obstacles when clearing gates, and displaying schedules immediately even with numerous crew scripts.
BUGFIX

MCP Sign-In Fixes, Streamlined Notices, and Intact Tool Allowlists

Connection and sign-in workflows for external tool integrations fix multiple subtle disruption bugs.

This is like an external specialist reception desk at a major institution, verifying credentials only once upon arrival, keeping access ports open, and never confiscating vital tools just because headquarters updates a roster.

A bug where Claude occasionally replied "your message came through empty" after an MCP tool call is now fixed. When local redirect port ranges cannot be bound, MCP server OAuth sign-in no longer throws errors claiming no ports are available. When organization managed settings enable an MCP allowlist, Claude in Slack sessions no longer lose their built-in Slack tools. In addition, the startup notice announcing "N MCP servers need authentication" now broadcasts only once per server instead of appearing on every launch.

FEATURE

WebFetch Timeout Limits and Alternative Command Guidance for Dotless Hosts

Fetching web pages with AI no longer hangs indefinitely, as web scraping tools now enforce explicit connection deadlines.

When a server holds a connection open without finishing transmission, the WebFetch tool now times out and fails after 300 seconds; you can set the CLAUDE_CODE_WEBFETCH_DEADLINE_MS environment variable to customize this deadline, or set it to 0 to disable the limit. When accessing localhost or other dotless hostnames, WebFetch errors now explain why the URL was refused and suggest using curl instead. In the Claude in Chrome extension, navigation URLs with a scheme but unparseable hostnames no longer prompt to allow the host "https". When reading lengthy web pages, content is now presented directly inline rather than being saved to a local file and read back.

The entire scraping mechanism is like cargo dock unloading controls, where berthed vessels blocking slips for too long are ordered to depart, non-standard waterways direct traffic to alternative overland routes, and accompanying documents are inspected directly on the pier.
BUGFIX

Cloud Command Sign-In URL Guidance and Uninterrupted Workload Identity Federation

Prompt messages are now more context-aware when executing cloud remote commands and cross-platform authentication.

This is like a corporate travel handbook for a multinational enterprise, preventing travel passes from being mistakenly flagged as reused during regional trips, guiding signed-out staff clearly to time clocks, and explaining policies when permissions are closed.

When using workload identity federation via a profile (such as configurations by claude-code-action), multiple processes sharing a profile no longer fail mid-run with 401 … jti reused errors. Running commands like /remote-control while signed out now actively suggests /login instead of displaying Claude for Enterprise migration messages. Entering cloud-session commands like /autofix-pr without a connected GitHub account directs users to /web-setup or the web connect page rather than asking to retry or install the app. When organization policies disable /teleport or /remote-env, the terminal explains the specific reason instead of simply responding with an unknown command.

FEATURE

Optional Runner State Cleanup, Headless Warnings, and Extended Hook Timeouts

Cleanup for self-hosted runners is disabled by default; only when passing claude self-hosted-runner --remove-session-state will dedicated directories under <base-dir>/_sessions/ be deleted upon session completion.

PermissionRequest hooks fix an issue where they failed to fire in --print mode. Policy-helper warnings now also print during headless (-p) runs. The /resume command now labels background sessions created by /fork with their dedicated ⑂ fork name instead of incorrectly listing them under their parent's name. SessionEnd hooks without a per-hook timeout are no longer forcibly cancelled after 1.5 seconds, allowing extensions via CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS.

Like ending a coworking lease, lockers are destroyed only upon request, access chimes ring as usual, and overtime submissions can be extended.

This is like equipping vehicles with high-speed sensor tolls and smart navigation, eliminating engine idling at entrances, clearly routing traffic around construction via side streets, and smoothly completing the remaining trip.

Tool execution turns no longer redraw transcripts for hidden reminders; when actions are blocked in auto mode, Claude receives messages identifying the blocking rule and instructing it to try safer methods to finish unrelated work first rather than abruptly stopping to ask.
