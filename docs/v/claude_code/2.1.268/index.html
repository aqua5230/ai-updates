企業閘道費率同步計費，啟動警告與內部網段登入

企業為團隊架設 Claude 應用程式閘道器（gateway）時，現在能享有更一致的計費與安全管控。

這宛如在企業園區設立專屬接駁總站，發車計費全由站內統一公告，遇到外部陌生旅客上車時主動鳴笛警示，並只認可公司名下的專屬通勤路線。

只要在 gateway.yaml 設定 pricing:，已登入的 Claude Code 用戶端就會透過受管設定接收相同費率，使 /cost 指令與遙測數據精準對齊支出計量表。當 access_control.allow_cidrs 保持空白時，閘道器在啟動時會主動發出警告，且首次有請求從公開位址抵達時也會發出一次性警告。此外，管理員可配置 gatewayInternalNetworks 受管設定，允許使用者在組織自有的公開 IPv4 網段向閘道器執行 /login 登入。

工件分頁專屬圖示，資料編輯卡片與存取審核加固

工件（artifact，在獨立視窗展示的成果文件）迎來視覺與權限更新。發布時瀏覽器分頁會由 Claude 挑選符合頁面的專屬圖示。終端機權限提示改以提問開頭，資料編輯審核改用卡片顯示文件數與可開啟對象。在跳過核准的本機協同工作階段（session）中，安全防護進一步加固。工件工具遇到資料夾外或符號連結（指向另一個位置的捷徑檔）後的檔案會直接拒絕讀取。一般的 WebFetch 規則不再套用至工件讀寫，需改用專屬規則把關：

# 阻擋或把關工件讀寫
Artifact
WebFetch(domain:claude.ai)

自 2.1.265 版起第三方相容端點因結構中的正規表達式（用符號匹配字串的語法）導致回傳 HTTP 400 的問題也已修復。

整體防護好似博物館的玻璃陳列櫃，外側貼上清晰的展品圖示與參觀說明，櫃內展品不允許任意越界調換，非專屬通道也不再隨意連通外部參觀動線。

外掛管理支援結構化輸出，選單改動即時生效

想要透過腳本自動化管理工具，外掛指令現在全面補齊了結構化輸出，清單各列也補上錯誤與備註細節：

claude auth status --json             # 輸出包含 configDirectory
claude plugin install --json          # 安裝外掛
claude plugin uninstall --json        # 解除安裝
claude plugin update --json           # 更新外掛
claude plugin enable --json           # 啟用外掛
claude plugin disable --json          # 停用外掛
claude plugin list --json             # 每列含 errorDetails 與 noteDetails

在終端機操作 /plugin 選單進行安裝、啟用或停用時，只要關閉選單就會直接生效，不必手動輸入 /reload-plugins。此外，claude plugin validate 先前誤拒以兩個點開頭的外掛路徑，以及外掛檢查時靜默略過預設 monitors 檔案或根目錄 SKILL.md 的問題均已修復。

這套流程宛若將工具箱換上標準卡榫與透明標籤，抽換刀頭當場卡緊即用，規格清單與錯誤代碼也能讓自動化輸送帶即時讀取。

符號連結權限嚴格比對，遮蔽連線機密與未信任代理

終端機安全防護更周全。

這套防線好似園區的多重身分核驗閘門，訪客走正門或側門得比對指紋，私密證件封入暗袋，不因呼叫口令改變就放行。

針對 macOS 的 /etc、/tmp、/var 或 Linux 的 /bin，無論真實路徑或符號連結（指向另一個位置的捷徑檔），拒絕與詢問規則皆能套用，Bash 指令不再忽視捷徑拼法。同列含 env -C 或 eval 等無法分析的指令時，讀取與編輯拒絕規則依然生效。外掛與市集報錯不再洩漏 Git 網址內的 token（授權令牌）或密碼。在 /mcp、/plugin 詳情、claude mcp list/get 或登入錯誤中，${VAR} 解析出的機密不再曝光，涵蓋 MCP（讓 AI 連接外部工具的協定）配置。重啟的行程內隊友不再取用未信任目錄的工具或提示詞；Bash 沙箱指示也不再過度宣稱限制。

雲端推論保持工具穩定，分級開放任務追蹤功能

透過各大雲端平台租用 Claude 進行開發，推論環境與工具載入機制變得更加標準化。在 Bedrock、Vertex 與 Foundry 上的工作階段（session）中，環境、模型與設定改以附件形式送達，與原生對話一致。這些平台上的工具清單在對話中保持位元組層級穩定，較晚連線的工具改以延遲載入而非重寫清單。任務追蹤工具現在預設僅提供給指定模型族系：

# 僅支援 Claude 3.x、Opus 4.0 至 4.7、Sonnet 4.0 至 4.6 與 Haiku 4.5
# 其餘模型需在環境變數開啟：
CLAUDE_CODE_ENABLE_TODO_TOOLS=1

包含 TaskCreate、TaskGet、TaskUpdate、TaskList 與 TodoWrite 工具。此外，使用 excludeDynamicSections 的 SDK 工作階段首則訊息不再於每次請求重新渲染，修復了提示快取（把算過結果暫存起來直接用）與延伸思考中途斷裂的問題。

整體架構猶如為各家分校實驗室配發標準封裝箱，儀器按既定清單就位而不中途翻箱，只有具備對應資格的專業技工才配發專案工作單。

模型快取存取修正，長對話精準提示百萬上下文

經常在對話中切換模型或送出長篇文字的讀者，存取權限與錯誤提示現在更準確。

這恰似高級圖書館的貴賓通行證，會員資格即使重新進出也不會因舊記錄而被擋在門外，桌位更不會在看書途中被擅自降等。

擁有合法授權的使用者，在重啟後或於桌面端 Code 分頁中，不再因過期的快取（把算過結果暫存起來直接用）而誤收到模型存取受限的阻擋訊息。當其他 Claude Code 行程重新整理過期的存取記錄時，進行中的工作階段（session）也不會再默默切換回組織預設模型。針對 Pro 與 Team 方案的使用者，在 Fable 模型上觸發長上下文 429 限流時，不再誤顯示用量額度同意提示，而是正確顯示 1M 上下文說明。相關訊息也經過改善，明確提醒使用者在中途開啟的額度需在重啟 Claude Code 後正式生效。

對話壓縮保留特殊符號，記憶截斷標明行數與起點

長時間對話後的歷史摘要與專案記憶，不再因為特殊符號而產生文字損毀。在終端機執行 /compact 指令或觸發自動壓縮時，產生的對話摘要不再損毀包含 $ 字元序列的文字。以 /compact 結尾的對話在恢復時，還原檔案的註記現在於每次恢復時都能維持相同載入順序。SDK 的提示建議、旁支提問與 /rename 指令，修復了在壓縮後仍送出壓縮前舊對話的問題。當專案內的 MEMORY.md 記憶檔案因篇幅超標遭到截斷時，警告訊息現在會清楚說明切除了多少行，以及裁切是從檔案的何處開始。

這如同文卷室的檔案裝訂程序，厚重卷宗提煉精要時符號與段落井然有序，若紙頁過長而修剪邊緣，也會蓋章註明起點與裁切頁數。

代理人面板快速導覽，修復工作樹卡死與腳本解析

管理背景代理人與工作流程的介面操作，變得更加俐落敏捷。在 claude agents 介面中，按向左鍵 ← 返回清單不再被忽略，不必停頓超過 1 秒。刪除代理人的工作階段（session）卡死問題已獲改善。若因工作樹（Git 讓同一專案平行開多份副本的功能）無法移除而停滯，訊息會指明原因與處置，再次按下 Ctrl+X 仍可強制刪除目錄。面板中的背景代理與工作流程橫列，遇到換行符號不再異常撐開成多行。由 claude remote-control 服務的遠端工作階段，在 ListAgents 中會顯示工作階段標題而非隨機名稱。此外，啟動時列出 .claude/workflows/ 流程不再逐一解析每份腳本，加快了啟動速度。

這般運作好似機場調度中心的航班看板，切換螢幕隨按隨翻，清除停機位遇到障礙能強制拖吊，即使機組腳本再多也能瞬間列出班表。

外部工具協定登入修復，通知精簡且白名單不漏接

串接外部工具的協定連線與登入流程，修復了多處意外中斷的隱蔽錯誤。

這好似大型機構的委外專家接待窗口，每一位外聘顧問進駐時只審核一次證件，通訊埠隨時保持暢通，絕不因總公司更新名冊就把重要工具沒收。

過去在呼叫外部工具後，Claude 有時會異常回覆「你的訊息內容為空」，這項問題已經修好。當本機重新導向通訊埠範圍無法綁定時，MCP（讓 AI 連接外部工具的協定）伺服器進行 OAuth 登入不再拋出無可用通訊埠的錯誤。當組織受管設定啟用了 MCP 白名單時，Claude in Slack 的工作階段（session）不會再丟失原本自帶的 Slack 工具。此外，啟動時提示「N 個 MCP 伺服器需要驗證」的通知，現在改為每部伺服器僅公告一次，不再於每次啟動時重複跳出。

網頁擷取限制等候逾時，無點主機導引替代指令

讓 AI 抓取線上網頁不再陷入無止境的乾等，網路擷取工具正式迎來明確的連線時限。WebFetch 工具遇到伺服器維持連線不結束傳輸時，現在會在 300 秒後逾時判定失敗；你可設定環境變數 CLAUDE_CODE_WEBFETCH_DEADLINE_MS 自訂時限，設為 0 則關閉上限。讀取 localhost 或其他無小數點的主機名稱時，WebFetch 報錯會主動說明遭拒原因並建議改用 curl 指令。在 Claude in Chrome 瀏覽器擴充套件中，導覽網址帶有協定但主機名稱無法解析時，不再詢問是否允許主機「https」。閱讀長篇網頁時內容會直接在對話呈現，不再儲存至本機檔案後再讀回。

整套抓取機制宛如貨運碼頭的卸貨管制，靠岸船隻若長時間卡住泊位便會強制離港，非標準航道清楚指引替代陸運，隨船文件也能直接在碼頭拆閱。

雲端連線引導登入網址，工作負載身分同盟不中斷

執行雲端遠端指令與跨平台驗證，提示訊息現在更加切合情境。

這有如跨國企業的差旅通行手冊，員工跨區出差時通行證不再被誤判重複使用，未登入時明確導引至打卡機，遇到權限封閉也清楚告知政策規定。

透過設定檔使用工作負載身分識別同盟時（如 claude-code-action 的配置），共用設定檔的多行程不再中途出現 401 … jti reused 錯誤。未登入時執行 /remote-control 等指令，系統主動建議輸入 /login，不再顯示企業遷移訊息。未連接 GitHub 帳號時輸入 /autofix-pr 等雲端工作階段（session）指令，畫面指引前往 /web-setup 或網頁連線頁，不再要求重試或安裝應用程式。組織政策停用 /teleport 或 /remote-env 時，終端機會具體說明禁用原因，不再只回覆未知指令。

執行器可選清理暫存，無頭模式警告與掛鉤逾時放寬

自託管執行器的清理預設關閉；只有加上 claude self-hosted-runner --remove-session-state，才會在工作階段結束時刪除 <base-dir>/_sessions/ 下的專屬目錄。權限請求掛鉤（hook，特定事件發生時被觸發的小程式）修復了在 --print 模式下未被觸發的問題。政策協助工具警告也能在無頭模式（headless，沒有終端機視窗的執行模式，即 -p）下印出。/resume 會把 /fork 產生的背景工作階段標成專屬 ⑂ 分岔名稱，不再誤列為父層名稱。未單獨設定超時的 SessionEnd 掛鉤不再強制於 1.5 秒後取消，能依 CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS 延長。

像共享工作室退租，申請後才銷毀置物盒，門禁鈴聲照響，加班交件也能延長。

閒置工作階段修復高耗能，自動模式拒絕引導替代做法

終端機的日常反應速度迎來全面提升，有效降低資源浪費。

這如同為車輛加裝高速感應閘道與智慧導航，車流不再於入口處空踩油門乾等，遇到施工路段會明確引導替代小路，繼續完成其餘平順路程。

長時間閒置的工作階段（session）修復了迴圈空轉鎖死 CPU 核心的問題，對話摘要時密集的視窗焦點回報也不再維持高負載。全螢幕模式下按 Shift+Enter 增減換行時，重繪速度與打字一樣迅捷，不再重新渲染整個對話紀錄。使用 --continue 或 --resume 恢復對話時，畫面立即呈現，不必等候 SessionStart 掛鉤（hook，特定事件發生時被觸發的小程式），首則訊息也不再重讀完整歷史。執行工具時不再因隱藏提醒重繪對話；自動模式被拒絕時，Claude 收到的訊息會具體標明被哪條規則阻擋，並指示嘗試更安全的做法以先完成其他不相關工作，而非貿然中斷停下詢問。

輸入列提示建議修復，進度指示保持單行與游標重現

終端機輸入框與排版細節修復了多處顯示瑕疵。在提示詞輸入列中，使用方向鍵向上鍵 ↑ 召回前一次提問並進行修改後，輸入 @ 檔案與 / 指令的自動建議選單現在能穩定彈出。當目前任務的標籤名稱較長時，進度旋轉動畫不再折行換列，任務標籤與「Next:」提示列現在能整齊維持在單一終端機列內。在開啟終端機原生游標的環境下，輸入 /bug 與 /feedback 指令的描述文字欄位修復了游標隱形的問題。輸入列底部的資訊呈現也獲得重新調整，編輯器或 /diff 的選取範圍現在直接展示於提問輸入框內，而在全螢幕模式下，遠端控制的連線狀態改於頂端標頭顯示，不再佔用底部空間。

整體介面猶如重新校正的精準打字機，字軌與自動補字齒輪隨撥即動，進度指示燈維持水平不偏位，指標刻度隨時清晰可見。

[VSCode] 輔助使用按鍵支援，外掛異動免重啟即時生效

VS Code 擴充套件為習慣鍵盤操作與螢幕報讀工具的使用者，帶來了更順手的新導覽鍵。

這好似為混音控制台換上點字琴鍵與快速推桿，調音師能單靠按鍵隨意切換聲道並跳至最新音軌，外接效果器插拔時也不必將全場設備關機重開。

在權限詢問畫面中現在能使用方向鍵向左鍵與向右鍵 ← →，切換「一律允許」規則的儲存層級。同時新增了「Claude Code: Focus last message」指令，能隨時將鍵盤焦點快速移回對話中的最新訊息。在外掛管理對話框中進行安裝、啟用、停用或解除安裝時，變更會立即套用至已開啟的工作階段（session），完全無須重新啟動編輯器。此外，部分工件（artifact）權限提示比照命令列終端機規範，移除了「不再詢問」選項以確保每次操作安全。

[VSCode] 多分頁模型選單不閃爍，啟動排程消除多餘行程

在編輯器中開啟多個對話分頁或切換帳戶，選單與模型狀態不再莫名閃爍留白。登入、登出或切換帳號後，已開啟分頁的模型標籤、模型選取器與指令選單，修復了在數秒間呈現空白的問題。當專案或本機設定覆蓋全域設定中的模型時，新分頁或重新整理的對話中「Auto」選項不再無故消失。配置了 SessionStart 掛鉤（hook，特定事件發生時被觸發的小程式）時，視窗重載後的命名問題已獲修正。工作階段（session）名稱重載後不再退回最後一次提問。視窗內已有其他分頁運行時，底部狀態列的模型與遠端控制狀態燈不再空等新行程啟動。若分頁啟動在讀取設定後超過半秒抵達，第二個 Claude 行程也不再重複完整啟動流程。

這項排程安排宛若舞台燈光控制矩陣，主控機台啟動後各燈組隨即跟進同步，換場或換幕時號碼燈不暗滅，備用迴路也不再盲目重複預熱。

[VSCode] 自訂設定目錄正常讀取，視窗診斷精準回傳

自訂目錄與 Windows 診斷，現在能切合實際開發環境。

這好似建築師調整個人繪圖桌的收納櫃與抽屜配置，自訂工具箱無論擺在側邊欄還是主桌面都確實定位，跨平台描圖時標尺刻度也分毫不差。
