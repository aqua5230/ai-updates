Claude Code 2.1.238

Released: 2026-08-20

Release notes

FEATURE

Terminal gains a Readline keybinding flavor for Ctrl+W word deletion

If you are used to pressing Ctrl+W in Bash to delete the previous word, you can now add {"keybindingFlavor": "readline"} to your user settings file at ~/.claude/settings.json to switch Ctrl+W to delete back to the previous whitespace, matching Bash; the default "classic" flavor remains unchanged if you don't set it.

It is like swapping in a new instruction sheet for the keyboard: the same key now means "delete back to the last space" under the new sheet, while anyone who didn't swap sheets keeps the old behavior — the two never interfere.
FEATURE

Fullscreen shortcuts focus purely on repainting, and the double-press clear shortcut is removed

In fullscreen mode, pressing Ctrl+L or Cmd+K used to both repaint the display and, if double-pressed, trigger /clear, wiping out the whole conversation by accident.

These shortcuts now focus exclusively on repainting the display; the double-press /clear shortcut has been removed, and 1-row nvim terminal windows no longer trigger unexpected clear loops.

It keeps shortcut actions predictable, like a chalkboard eraser that only wipes away surface dust without erasing the entire board if tapped twice.
FEATURE

Plugin marketplaces gain dynamic auth headers with explicit installation confirmation

Plugin marketplaces now support dynamic authentication.

Like checking into a secure building where visitors receive short-lived access badges, and guards display the requested permissions on a screen before asking for signature approval.

By configuring headersHelper on a URL marketplace or catalog entry, the system runs a custom command to mint dynamic HTTP headers, using a short-lived token to fetch catalogs and same-origin archive files. Catalog helpers only execute when installing or updating that plugin after displaying the command, and claude plugin install or update will prompt with [y/N] unless -y is passed.

FEATURE

Self-hosted runners defer shutdown and withstand a missed poll

On SIGTERM, claude self-hosted-runner --defer-shutdown-max-min <minutes> lets a self-hosted runner keep serving attached sessions, then park remaining work before exiting.

A single slow or lost poll request also no longer removes a healthy runner and hands its sessions to another runner.

Like a service desk finishing with people already at the counter; one burst of radio static does not close the desk.
FEATURE

Self-hosted runners refresh proxy authorization for every connection

For egress proxies requiring a freshly issued Proxy-Authorization header for every connection, self-hosted runners can use claude self-hosted-runner --proxy-authorization-command or claude self-hosted-runner --proxy-authorization-file.

It is like getting a new barcode from the post office for every registered parcel, rather than sticking the last parcel's receipt on this one.
BUGFIX

Long sessions release off-screen subagent tool results

Long sessions no longer keep accumulating memory from subagent tool results.

Results remain in memory while in the recent display window, then are released once they leave it, preventing unbounded memory growth.

Like keeping only the notes you are reading on a desk and returning older subtask notes to a file box.
BUGFIX

Custom, project, and plugin output styles stay in effect

Custom, project, and plugin output styles no longer drift back to the default voice mid-session.

It is like a radio host keeping the programme’s chosen delivery throughout the broadcast.
BUGFIX

Permission prompts handle wide characters, text wrapping, and long URLs correctly

Permission dialogs and diff previews now format text reliably across all terminal sizes.

When MCP (Model Context Protocol, an open standard connecting AI to external tools) opens an elicitation prompt, URLs exceeding 4,096 characters no longer render completely blank. If a project path is wider than your terminal window, the permission prompt will no longer drop the "don't ask again" choice. Furthermore, line wrapping in permission diff views has been fixed so that lines with tabs or wide multi-code-point characters like emoji are never clipped.

Like an adjustable bulletin board that wraps long addresses and symbols cleanly without pushing action buttons off the frame.
BUGFIX

Terminal input catches bursty backspaces and restores clean cursor states after Ctrl+Z

Input responsiveness and terminal state cleanup are now reliable over laggy remote connections.

Like riding a bicycle over bumpy terrain where holding the brakes never misses an input, and parking with the handbrake leaves the controls perfectly aligned when resuming.

Previously over high-latency SSH or mosh connections where terminals map Backspace to Ctrl+H, holding down Backspace during keystroke bursts would cause inputs to be dropped; these bursts are now handled accurately. Additionally, killing a session suspended with Ctrl+Z will no longer leave your terminal with a hidden cursor or stuck in bracketed-paste mode.

PERF

Startup speeds up on macOS, and update checks defer to save CPU

Launching the tool is now noticeably snappier from the command line.

On macOS, running bare claude opens the interface significantly faster so you can get straight to work. To keep the app responsive from the very first keystroke, the automatic update check now waits approximately 10 seconds after launch instead of competing with startup routines for CPU cycles.

Like a shopkeeper who prioritizes seating the first guests at the door, waiting about 10 seconds before heading to the back office to review inventory lists.
FEATURE

MCP helpers require folder trust approval and isolate credential environment variables

Security boundaries around external tool configurations have tightened significantly.

Like a restaurant adopting a new recipe only after the head chef approves it: cooking does not bring in private ingredients from another kitchen, and designated recipes are prepared only at their own station.

If a project .mcp.json contains headersHelper, or if inline MCP (Model Context Protocol, an open standard connecting AI to external tools) servers exist in project or --add-dir agent files, that directory's trust dialog must now be accepted first, even when running non-interactively via claude -p. In addition, helpers launched from project files, plugins, or agent configurations no longer inherit credential environment variables, and user, managed, or claude.ai-scoped helpers now run strictly from the Claude config directory.

BUGFIX

MCP lazy initialization fixed and disabled servers badge as ⊘ Disabled

Inspecting external tools no longer wakes up dormant or disabled services.

Previously, stdio MCP (Model Context Protocol, an open standard connecting AI to external tools) servers received a server/discover request before initialize, unnecessarily forcing lazy-loaded servers to boot up their backends every time a session opened. This handshake order is now resolved. In addition, claude mcp list and claude mcp get now display disabled servers directly as ⊘ Disabled rather than opening a connection to perform a health check.

Like putting an "out of order" tag on a spare tool in the shed instead of plugging it into the wall to test it every time you open the door.
FEATURE

Bash permission checks recognize zsh conditionals and avoid worktree false refusals

Bash tool permission checks now evaluate zsh-specific conditional syntax correctly.

In isolated git worktrees, commands without a redirect stop receiving false refusals telling you to remove one.

Like a gatekeeper who understands another local form style and does not ask you to cross out a field that is absent.
BUGFIX

Interrupted Bash commands no longer leave work-directory temp files

When a Bash command is killed, times out, or is interrupted, it no longer leaves /tmp/claude-*-cwd files behind.

These work-directory temporary files are cleaned up even when the command does not finish normally.

Like temporary site signs being removed after an event is suddenly cancelled.
FEATURE

Remote Control bolsters network resilience, retrying sign-ins and naming blocking proxies

Remote Control connectivity is now far more resilient across complex network environments.

When a proxy refuses a connection, it now names that proxy rather than returning a generic network error. Separately, when a network edge, VPN, or proxy briefly returns HTTP 403, it tolerates the refusal and retries for up to 3 minutes; if the block persists, it names the refusing party. When a brief network hiccup delays your sign-in credential refresh, the client retries seamlessly instead of abruptly dropping out with "login expired". Signing out also concludes the session cleanly without misreporting a reconnection failure.

Like a courier that keeps attempting delivery through a brief traffic delay and, if a receiving desk repeatedly refuses it, notes exactly which desk turned it away.
BUGFIX

Remote model choices sync to the terminal and mid-turn messages stay in the transcript

A model chosen from a phone or web client now updates the terminal display.

A new message sent from the web or Desktop while Claude is mid-turn also remains in the transcript after the turn ends.

Like sending a changed order to the kitchen display while keeping an extra note in the order folder.
BUGFIX

Remote task Stop now works for CLI sessions

When you want to stop one named task in the Remote Control panel, its individual Stop button now works for a CLI (command-line interface, a way to operate programs with typed commands) hosted session too.

Previously, pressing it left that type of session running; the panel's task control now reaches it.

It is like pressing the stop control beside one song in a playlist: only that track stops, while the player and other tracks remain unaffected.
BUGFIX

Invalid-role messages no longer end remote sessions

A remote session no longer exits when it receives a user message from a client without a valid role.

A role is the field that identifies a message's identity and purpose; before, an invalid value could end the whole session, while it now remains usable. Later messages can still go to the same remote session instead of requiring a new one because of a single bad field.

Like a recording studio where one track has the wrong label: the sound engineer isolates that track instead of shutting down the whole recording.
BUGFIX

Remote sessions no longer inherit environment variables from the launching shell

New remote sessions started by claude remote-control no longer inherit session-scoped environment variables from the launching shell.

They are now isolated instead of being carried into the remote environment.

Like handing a new tenant the door key separately from the previous tenant’s drawers.
BUGFIX

Crashed Remote Control sessions can be reused on the next message

After a Remote Control session process crashes, it used to stay unavailable until claude remote-control was restarted.

Now, the next message can reinitialize and reuse it.

A broken vending machine restarts when the next customer inserts a coin instead of staying out of order.
FEATURE

Cross-session messaging notifies senders on refused deliveries and dropped inboxes

Cross-session messaging now provides direct feedback when messages cannot be delivered.

Like a concert song-request system: if the performer has stopped taking requests, a person's request limit is reached, or the upcoming playlist is full, its screen immediately tells the requester it failed instead of leaving them to think the song was queued.

When sending messages to a local session that rejects incoming chats via {"crossSessionInbound": "refuse"}, the sender now receives a clear "refused" status instead of a deceptive success report. Likewise, if a target inbox drops messages due to rate limits or a full queue, your active session is notified immediately instead of messages vanishing silently.

BUGFIX

Multi-agent tools reach Remote Control peers and hide unassigned standby workers

Multi-agent collaboration tools can now discover and communicate with peers across environments.

Running ListAgents or SendMessage inside sessions hosted by claude remote-control server mode, Desktop, or IDE hosts previously failed with "Remote Control is not connected"; they can now locate and message remote peers reliably. Additionally, idle workers pre-warmed in the background to speed up your next session are no longer prematurely listed, appearing only after a task officially claims them.

Like a theater roster that lets stage directors call remote cast members anytime, while keeping standby understudies hidden until they are formally assigned a role.
BUGFIX

Prompt suggestions stay active near usage limits and expired cache warnings are suppressed

Prompt suggestions and cache status warnings now reflect exact account and cache states.

If you set CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=true, suggestions previously shut off prematurely when your account approached its usage limit; they now remain active until the quota is genuinely reached. Meanwhile, switching models with /model or tweaking reasoning depth with /effort will no longer display false cache-miss warnings when prompt caches had simply expired on their own schedule.

Like a kettle that refrains from sounding an alarm while water levels remain safely within bounds, without flagging a tea bag that steeped to completion as a defect.
FEATURE

Bundled claude-api skill updates for sandboxed domain controls and memory stores

The bundled claude-api skill has been updated to align with the Managed Agents release from August 19.

On self-hosted sandboxes, agents can now configure allowed domains for web searching and web fetching, giving you granular control over external site access. Sandboxes also introduce memory stores, allowing managed agents to persist and retrieve long-term state securely within their private sandboxed environments.

Like equipping a research lab with an approved network directory and a dedicated filing cabinet to control outbound lookups while preserving findings locally.
