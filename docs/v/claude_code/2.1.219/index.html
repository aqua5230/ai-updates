zh-TW

Opus 5 上線成為預設，快速模式跟著換人

新的 Claude Opus 5 接手成為預設的 Opus 模型，代號是 claude-opus-5。它一次能讀進一百萬 context（模型一次記得住的文字量），快速模式的計價是每百萬文字單位進 10 美元、出 50 美元。連帶兩件事也跟著調整：/fast 這個快速模式不再適用 Opus 4.7，改成套用在 Opus 5 和 Opus 4.8 上；claude-api 這份技能檔的預設模型也換成 Opus 5，並附上從 Opus 4.8 搬過來的做法。像學校換了新版教科書，開學領到的自動就是新版；但你書單上如果寫死舊版書號，訂起來就會撲空。你什麼都不用改就會用到新模型，只有手邊寫死舊模型代號的腳本，得回頭檢查。

`/model` 選單的三個看走眼，一次修好

挑模型是很快的動作，你掃一眼就按下去，所以清單寫錯特別傷。這版修掉三處：合併後的 Opus 那一列只寫「Opus」，看不出它其實是「Opus (1M context)」；Fable 那一列對明明已包含它的方案顯示「需要用量點數」，原因是舊的暫存把那句標籤烙在裡面沒更新；還有高亮，以前會標到清單中不特定的一段，現在只標最新那個模型的名字，你一眼就知道新的是哪個。像餐廳菜單把價格印錯又把招牌菜標在別道菜旁邊——菜沒問題，是菜單在誤導人。

子代理可以再叫子代理，最多疊三層

派一個助手去做事，它做到一半發現該再找兩個人分頭查——以前它做不到，只能自己吞下去。現在子代理預設可以往下再開子代理，最多疊到三層（原本只有一層）。不想要這種層層轉包，在環境變數設 CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 就關掉。同時，第二層以下開出來的子代理不再是黑箱：只要加上 --forward-subagent-text，它們的輸出會出現在 stream-json 裡，並掛在當初叫出它的那個代理底下，看得出誰是誰派的。像工班分包，以前只准分一層，現在准到三層，但每一層是誰發包的都要登記在同一張表上。

動態工作流程預設收斂到 15 個代理以內，可自己改

交給系統自動編排的工作流程，以前沒有規模上的建議，一個任務可能被拆成幾十個代理各跑各的，你既看不出全貌也算不出成本。現在預設是中等規模，也就是「盡量少於 15 個代理」，這只是建議不是硬限制。想換規模有兩條路。臨時改：在 /config 裡選 Dynamic workflow size，可以挑別的大小或不設限。想固定下來：在設定檔加一行 workflowSizeGuideline，這樣任何設定檔都能指定，例如

{"workflowSizeGuideline": "medium"}

設定檔一旦寫了這個鍵，/config 裡那一列就會自動隱藏，避免兩邊講不一樣的話。另外，工作流程跑起來時，狀態列會直接顯示目前用的是哪個規模，旁邊附上去 /config 改的指路。像旅行團有沒有規定團員人數上限——沒規定不代表比較自由，只是你到了現場才知道來了幾個人。

沙箱連外網，可以設成直接擋掉不再問你

在沙箱（把指令關在受限環境裡跑的隔離區）裡執行的指令想連某個網站，而那個網站不在你的允許清單上時，以前會跳出來問你要不要放行。跑自動化的場合沒人在鍵盤前，這一問就是整條流程停住。新的 sandbox.network.strictAllowlist 讓你選擇直接拒絕、連問都不問。要開的話，在設定檔加上這段：

{"sandbox": {"network": {"strictAllowlist": true}}}

這裡的巢狀寫法是「一層包一層」：sandbox 裡有 network，network 裡才是 strictAllowlist。像大樓門禁改成沒登記就是進不來，警衛不再打電話上樓問你要不要放行——訪客會吃閉門羹，但半夜也不會有人被吵醒。

外部工具接不上時，終於說得出哪裡出錯

MCP（Model Context Protocol，讓 AI 接上外部工具的協定）伺服器連不上，以前只知道失敗，不知道為什麼。這版三處補上線索。claude mcp list 和 /mcp 現在會附上 HTTP 狀態碼和錯誤內容，是憑證過期還是位址打錯，一看就分得出來；設定值前後藏著看不見的空白時，也會出聲警告——那種錯最折磨人，因為畫面上看起來完全正常。沒有畫面的 stream-json 啟動事件則多了 mcp_server_errors，把 --mcp-config 裡因為驗證不通過而被略過的項目列出來，終端機執行時也會在開頭印警告。像寄信被退回，以前只收到一張「無法投遞」，現在退件單上寫了地址哪一行有問題。

公司派下來的外部工具清單，不再被本機設定改寫

公司統一派發的 MCP 允許與拒絕清單，裡面常寫 ${VAR} 這種變數，等實際執行時再換成真正的值。問題是以前它從設定檔裡的環境變數區塊取值——而設定檔就在使用者手上，等於管理者訂的規則，可以被本機的一行設定改掉。現在改成從啟動時的環境和受管理設定自己的環境取值，設定檔那份不再參與。像醫院的用藥規定，以前各護理站自己抄一份貼在白板上，誰都擦得掉；現在改成每次掃碼直接讀系統裡的正本。

聊到一半加資料夾，掛鉤跟著醒過來

同一個工作階段聊到一半，才想起另一個資料夾也得一起看，於是你把它加了進來。新的 DirectoryAdded 掛鉤（特定事件發生時自動觸發的小程式）就在這一刻醒過來，向周邊工具發出通知。只要輸入 /add-dir 指令，或是透過 SDK 發出 register_repo_root 控制請求來註冊新目錄，Claude Code 就會自動觸發這個掛鉤，讓周邊工具第一時間掌握目錄變更。像展覽館在展覽進行中臨時加設新展位，廣播室與服務台隨即收到連線通知，周邊服務就能馬上配合跟上。

複製、方向鍵、朗讀，三個按下去才發現的毛病

這三個毛病都要等你手指按下去才會發現，所以特別磨人。首先是在 GNU screen 環境下劃選文字時，終端機不再印出一串 base64（將任意資料轉成純英數字串的編碼）字串，而是正常完成複製；其次是在 Vim 模式下的空白輸入列按左箭頭鍵（←），除了 INSERT 模式外，NORMAL 模式現在也能順利退回代理畫面；最後是螢幕閱讀器模式打字時只會朗讀剛輸入的字元，不會每按一下就重讀整行文字。像使用按鈕回饋錯亂的控制面板：劃選複製跳出無關字串、按返回鍵像卡住按不動、打字時語音重讀整行，都是按下去那一刻的動作與回饋對不上。

遙控端不再顯示過期狀態，出錯也說得出是哪個設定

隔著一台裝置操作，最怕畫面上寫的跟實際狀況對不上。這版把遠端控制（Remote Control）的三處落差補起來。首先修復了遠端控制用戶端在切換模型、斷線重連或組織權限檢查失敗後，快速模式仍殘留舊狀態的問題；其次，當跳出「遠端控制僅支援 api.anthropic.com」的錯誤時，錯誤訊息會直接點名是哪一個設定項導致衝突；最後，執行 claude --teleport 遇到手邊 checkout 的專案庫與工作階段不一致時，現在會明確印出你目前 checkout 指向的是哪一個專案庫。像遠端駕駛艙的儀表板，開關狀態即時同步、故障時精準亮起對應燈號，定位不符時也會清楚顯示你實際停在哪個車庫。

無效 Git Bash 路徑改發警告，中途斷線保留已產出回答

設定檔填錯與中途網路中斷這兩類突發狀況，現在都不會再一秒蒸發你的作業結果。這版做了兩項重要修復：在 Windows 上如果將 CLAUDE_CODE_GIT_BASH_PATH 環境變數指向非 bash 或 sh 的執行檔，以前會直接崩潰或硬當成 bash 執行，現在改為印出警告並自動忽略該無效路徑；另外，使用 claude -p（無畫面直接印出文字的執行模式）時，若在生成答案中途遇到 API 網路錯誤而中斷，Claude Code 不會再把已經產出的前半段回答全部丟掉，而是完整保留並印出來。像車載導航系統：填錯無效路徑時跳出警告並繼續走主幹道，就算中途訊號中斷，也完好保留已下載的前半段路線。

Opus 5 lands as the default, and fast mode moves with it

Claude Opus 5 (claude-opus-5) takes over as the default Opus model, with a 1M context window and fast-mode pricing of $10 in and $50 out per million tokens. Two things move with it: /fast no longer covers Opus 4.7 and now applies to Opus 5 and Opus 4.8, and the claude-api skill defaults to Opus 5 with a documented path over from Opus 4.8. A school switching to a new edition of a textbook works the same way: what you are handed at the start of term is the new one, but a reading list with the old ISBN written into it will order nothing. You get the new model without changing anything; only scripts with an older model id hard-coded need a second look.

Three ways the `/model` picker misled you, now fixed

Picking a model is a glance-and-click action, which is exactly why a wrong list hurts. Three fixes here: the merged Opus row read plain "Opus" instead of "Opus (1M context)"; the Fable row claimed "Requires usage credits" on plans that already include it, because a stale cache had baked that label in; and the highlight, which used to mark an arbitrary subset of the list, now marks only the newest model's name so you can see at a glance which release is new. A menu with the wrong prices and the chef's-special marker next to the wrong dish — the kitchen is fine, the menu is misleading you.

Subagents can now spawn subagents, three layers deep

You send one assistant off to do a job; halfway through it realises the work should be split between two more people — and until now it could not do that, it had to swallow the whole thing itself. Subagents can now spawn their own subagents, three levels deep by default, up from one. If you would rather not have work subcontracted down a chain, set CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 to switch nesting off. The deeper ones are no longer a black box either: with --forward-subagent-text, subagents spawned at depth two and below show up in stream-json, keyed to the agent tool_use id that spawned them, so you can see who dispatched whom. Building trades subcontract the same way — one level used to be the limit, three is now allowed, and every level is logged against whoever hired it.

Dynamic workflows now aim for under 15 agents by default

Workflows the system plans for you had no size guidance, so one task could fan out into dozens of agents running in parallel, leaving you unable to see the shape of it or estimate the cost. The default is now a medium guideline — aim for fewer than 15 agents — and it is advisory, not a hard cap. There are two ways to change it. Ad hoc: pick Dynamic workflow size in /config for another size or unrestricted. Permanently: set workflowSizeGuideline in any settings file, for example

{"workflowSizeGuideline": "medium"}

While a settings file specifies that key, the /config row hides itself so the two cannot disagree. A running workflow also shows the current size in its status line, with a pointer to /config if you want to change it. Think of a tour with no stated cap on group size: the absence of a limit is not freedom, it just means you find out how many people showed up when you get there.

Sandboxed commands can now block unlisted hosts silently

When a command running inside the sandbox — the restricted area commands are confined to — tries to reach a host that is not on your allowlist, you used to get a prompt asking whether to permit it. In an automated run there is nobody at the keyboard, so that prompt is where the whole pipeline stops. The new sandbox.network.strictAllowlist setting lets you deny outright, without asking. To turn it on, add this to a settings file:

{"sandbox": {"network": {"strictAllowlist": true}}}

The nesting reads as one box inside another: sandbox contains network, and network contains strictAllowlist. It is a building switching to strict door policy — unregistered visitors simply do not get in, and the guard stops phoning upstairs to ask. Some visitors are turned away, but nobody gets woken at three in the morning.

When an MCP server fails, you finally hear why

When an MCP server would not connect, you knew it had failed and nothing more. Three additions here. claude mcp list and /mcp now report the HTTP status and error text, so an expired credential looks different from a mistyped address; and config values with hidden leading or trailing whitespace now raise a warning — the most maddening class of error, because the screen looks entirely correct. The headless stream-json init event gained mcp_server_errors, listing the --mcp-config entries that config validation skipped, and terminal runs print a startup warning too. A returned letter used to come back stamped only "undeliverable"; now the slip tells you which line of the address is wrong.

Managed MCP lists stop reading variables from the settings file

Centrally managed MCP allowlists and denylists often contain ${VAR} entries that get substituted at run time. The catch was where the substitution read from: the env block of a settings file — a file that sits in the user's own hands, which meant a rule set by an administrator could be rewritten by one local line. Those entries now resolve from the startup environment and the managed-settings env instead, and the settings-file env no longer participates. Think of dosage rules in a hospital: they used to be copied onto a whiteboard at each nurses' station, where anyone could rub a figure out. Now they are scanned straight from the system's master copy each time.

Add a folder mid-conversation and a hook wakes up

Halfway through a conversation you remember that another folder needs to be in scope, so you bring it in. The new DirectoryAdded hook wakes up at exactly that moment and notifies the tools around you. A new DirectoryAdded hook fires whenever a new working directory is registered mid-session — whether you type the /add-dir command or issue a register_repo_root control request via the SDK. Secondary tools learn right away that the folder list has changed. Think of an exhibition hall opening an extra booth mid-event: the moment the new space is registered, the information desk and public address system get an instant update so services can adjust without delay.

Three faults you only meet the moment you press a key

All three of these only show up at the instant your finger presses a key, which is what makes them grating. Text highlighted inside GNU screen now copies properly instead of dumping raw base64 strings into your terminal. Pressing the left arrow (←) on an empty prompt in Vim mode now returns to the agent view from NORMAL mode as well as INSERT mode. Finally, screen-reader mode echoes only the single typed character per keystroke rather than re-reading the entire input line. Like using a control panel with miswired button feedback: selecting text prints extra code, pressing back feels stuck, and typing echoes the entire line — every action produces the wrong immediate response.

No more stale remote status, and errors that name the setting

Operating something through another device, the thing you dread is the screen disagreeing with reality. Three such gaps in Remote Control are closed here. Remote Control clients no longer hold onto a stale fast-mode status after switching models, reconnecting, or failing an organization check. When the error "Remote Control is only available via api.anthropic.com" appears, the diagnostic text now explicitly names the specific setting that triggered it. Finally, running claude --teleport when your current checkout repository differs from the session's repository now prints which repository your current checkout actually points to. Like a remote cockpit dashboard: switch toggles update in real time, error lights pinpoint the exact faulty breaker, and location mismatches show the actual hanger where your vessel is parked.

Invalid Git Bash paths now raise warnings, and mid-stream errors preserve output

Mistyped path settings and mid-stream network drops will no longer wipe out your progress in an instant. Two essential fixes are included: on Windows, if CLAUDE_CODE_GIT_BASH_PATH points to a file that is not a bash or sh binary, it no longer crashes or gets misused as bash, but instead ignores the invalid path with a warning. Furthermore, when running claude -p (the headless mode that prints text output), if a turn dies due to a mid-stream API network error, Claude Code no longer discards the answer already generated, but preserves and prints it completely. Think of a car navigation system: it issues a warning about an invalid shortcut while keeping you on the main highway, and even if signal drops mid-trip, it preserves the route segment already downloaded.

公司派下来的外部工具清单，不再被本机设置改写

公司统一派发的 MCP 允许与拒绝清单，里面常写 ${VAR} 这种变量，等实际执行时再换成真正的值。问题是以前它从配置文件里的环境变量区块取值——而配置文件就在用户手上，等于管理者订的规则，可以被本机的一行设置改掉。现在改成从启动时的环境和受管理设置自己的环境取值，配置文件那份不再参与。像医院的用药规定，以前各护理站自己抄一份贴在白板上，谁都擦得掉；现在改成每次扫码直接读系统里的正本。

聊到一半加文件夹，挂钩跟着醒过来

同一个工作阶段聊到一半，才想起另一个文件夹也得一起看，于是你把它加了进来。新的 DirectoryAdded 挂钩（特定事件发生时自动触发的小程序）就在这一刻醒过来，向周边工具发出通知。只要输入 /add-dir 命令，或是透过 SDK 发出 register_repo_root 控制请求来注册新目录，Claude Code 就会自动触发这个挂钩，让周边工具第一时间掌握目录变更。像展览馆在展览进行中临时加设新展位，广播室与服务台随即收到连线通知，周边服务就能马上配合跟上。

复制、方向键、朗读，三个按下去才发现的毛病

这三个毛病都要等你手指按下去才会发现，所以特别磨人。首先是在 GNU screen 环境下划选文字时，终端不再打印出一串 base64（将任意数据转成纯英数字符串的编码）字符串，而是正常完成复制；其次是在 Vim 模式下的空白输入列按左箭头键（←），除了 INSERT 模式外，NORMAL 模式现在也能顺利退回代理视图；最后是屏幕阅读器模式打字时只会朗读刚输入的字符，不会每按一下就重读整行文字。像使用按钮反馈错乱的控制面板：划选复制跳出无关字符串、按返回键像卡住按不动、打字时语音重读整行，都是按下去那一刻的动作与反馈对不上。

遥控端不再显示过期状态，出错也说得出是哪个设置

隔着一台设备操作，最怕画面上写的跟实际状况对不上。这版把远端控制（Remote Control）的三处落差补起来。首先修复了远端控制客户端在切换模型、断线重连或组织权限检查失败后，快速模式仍残留旧状态的问题；其次，当弹出「远端控制仅支持 api.anthropic.com」的错误时，错误信息会直接点名是哪一个设置项导致冲突；最后，执行 claude --teleport 遇到手边 checkout 的项目库与会话不一致时，现在会明确打印出你目前 checkout 指向的是哪一个项目库。像远端驾驶舱的仪表板，开关状态实时同步、故障时精准亮起对应灯号，定位不符时也会清楚显示你实际停在哪座车库。

无效 Git Bash 路径改发警告，中途断线保留已产出回答

配置文件填错与中途网络中断这两类突发状况，现在都不会再一秒蒸发你的作业结果。这版做了两项重要修复：在 Windows 上如果将 CLAUDE_CODE_GIT_BASH_PATH 环境变量指向非 bash 或 sh 的可执行文件，以前会直接崩溃或硬当作 bash 执行，现在改为打印出警告并自动忽略该无效路径；另外，使用 claude -p（无画面直接打印文字的执行模式）时，若在生成答案中途遇到 API 网络错误而中断，Claude Code 不会再把已经产出的前半段回答全部丢掉，而是完整保留并打印出来。像车载导航系统：填错无效路径时弹出警告并继续走主干道，就算中途信号中断，也完好保留已下载的前半段路线。

Opus 5 が既定になり、高速モードの対象も入れ替わった

新しい Claude Opus 5 が既定の Opus モデルを引き継いだ。識別子は claude-opus-5 だ。一度に読み込める context（モデルが一度に覚えていられる文字量）は百万で、高速モードの料金は百万文字単位あたり入力 10 ドル、出力 50 ドルになる。あわせて二点が動く。/fast は Opus 4.7 の対象から外れ、Opus 5 と Opus 4.8 に適用される。claude-api スキルの既定も Opus 5 になり、Opus 4.8 からの移行手順が添えられた。学校の教科書が新版に切り替わるのと同じで、始業時に配られるのは自動的に新しいほうだ。ただし書名一覧に旧版の番号を書き込んだままなら、注文しても届かない。何もしなくても新しいモデルを使うことになり、見直しが要るのは古い識別子を直接書き込んだスクリプトだけだ。

`/model` の一覧で見誤る三点をまとめて直した

モデル選びは一目見て押すだけの動作だから、一覧が誤っていると効き方が大きい。今回は三点を直した。統合された Opus の行が「Opus (1M context)」ではなく素の「Opus」と出ていた点。Fable の行が、それを含むプランに対して「利用クレジットが必要」と表示していた点。これは古いキャッシュがその文言を焼き付けたまま残っていたためだ。そして強調表示で、以前は一覧の中途半端な範囲を指していたが、今は最新モデルの名前だけを標す。どれが新しいのかが一目でわかる。値段を刷り間違え、看板料理の印を別の皿に付けた品書きのようなものだ。厨房ではなく品書きが人を惑わせていた。

サブエージェントがさらにサブエージェントを呼べる、三層まで

助手を一人送り出したところ、途中で「これは二人に分けて調べさせるべきだ」と気づく。これまではそれができず、自分で抱え込むしかなかった。今はサブエージェントがさらにサブエージェントを立てられる。既定で三層まで、以前は一層だった。下請けが連なるのが好みでないなら、環境変数に CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 を設定すれば入れ子は止まる。二層目以降も箱の中身が見えないままではない。--forward-subagent-text を付ければ、深さ二以上で立ったサブエージェントの出力が stream-json に現れ、呼び出した側のエージェントの tool_use id にひも付く。誰が誰を出したのかがたどれる。建設の下請けと同じ話で、以前は一次までだったのが三次まで認められ、そのかわり各段の発注元は同じ台帳に載る。

動的ワークフローは既定で 15 エージェント未満をめざす

自動で組み立てられるワークフローには規模の目安がなく、一つの依頼が数十のエージェントに分かれて並走することもあった。全体像も費用も掴めない。既定は中規模、つまり「エージェント 15 未満をめざす」になった。これは目安であって上限ではない。変え方は二通り。その場で変えるなら /config の Dynamic workflow size から別の規模か無制限を選ぶ。固定したいなら、任意の設定ファイルに workflowSizeGuideline を書く。たとえば

{"workflowSizeGuideline": "medium"}

設定ファイルがこの鍵を指定している間、/config の行は自動的に隠れる。両側で食い違わないためだ。実行中のワークフローでは、いま使っている規模がステータス行に出て、変更したいときの /config への道案内も添う。人数の上限を告げないツアーのようなものだ。上限がないのは自由ではなく、現地に着くまで何人来るかわからないというだけだ。

サンドボックスの外部接続を、訊かずに遮断する設定が入った

サンドボックス（コマンドを閉じ込めて動かす制限区画）の中のコマンドが、許可一覧にない相手に接続しようとすると、これまでは通してよいか尋ねる確認が出ていた。自動実行では鍵盤の前に誰もいないので、その確認で流れ全体が止まる。新しい sandbox.network.strictAllowlist を使えば、尋ねずにそのまま拒否できる。有効にするには設定ファイルにこう書く。

{"sandbox": {"network": {"strictAllowlist": true}}}

入れ子は「箱の中に箱」と読む。sandbox の中に network があり、その中に strictAllowlist がある。建物の入館規則を厳格側に倒すのと同じだ。登録のない来訪者はそもそも入れず、警備が上階に電話して可否を訊くこともなくなる。断られる客は出るが、深夜に起こされる人もいなくなる。

外部ツールにつながらないとき、理由がやっと出るようになった

MCP（AI を外部ツールにつなぐための取り決め）のサーバーにつながらないとき、失敗したことだけがわかって理由はわからなかった。今回は三点で手がかりが増えた。claude mcp list と /mcp は HTTP のステータスとエラー本文を添えるようになり、資格情報の期限切れなのか、宛先の打ち間違いなのかが見分けられる。設定値の前後に見えない空白が紛れている場合も警告が出る。画面上は正しく見えるだけに、この手の誤りがいちばん厄介だ。画面を持たない stream-json の初期化イベントには mcp_server_errors が加わり、--mcp-config の項目のうち検証で飛ばされたものを並べる。端末での実行でも起動時に警告が出る。差し戻された郵便のようなもので、以前は「配達不能」の判だけだったが、今は住所のどの行が問題かが伝票に書いてある。

会社が配る外部ツールの一覧が、手元の設定に書き換えられなくなった

会社がまとめて配る MCP の許可・拒否一覧には、${VAR} のような変数がよく書かれ、実行時に本当の値へ置き換わる。問題は置き換えの参照元だった。設定ファイルの環境変数の欄から読んでいたのだが、その設定ファイルは利用者の手元にある。つまり管理者が定めた規則を、手元の一行で書き換えられた。今は起動時の環境と、管理設定側の環境から解決するようになり、設定ファイルのものは関与しない。病院の投薬規定に似ている。以前は各詰所が白板に書き写していて、誰でも消せた。今は毎回コードを読み取って、システムの正本を直に参照する形になった。

会話の途中でフォルダを足すと、フックが目を覚ます

話の途中で「あのフォルダも見せないと」と気づき、手元に取り込む。新しい DirectoryAdded フック（特定の出来事が起きると自動的に呼び出される小さなプログラム）はその瞬間に目を覚まし、周辺の自動化ツールへ通知を送る。/add-dir コマンドを実行するか、SDK から register_repo_root 制御リクエストを送ってセッション途中に新たな作業ディレクトリを登録すると、DirectoryAdded フック（特定イベントの発生時に動作する小プログラム）が発火する。周辺スクリプトはフォルダ構成の変更をただちに把握できる。会期中の展示場に新しいブースを急遽追加した際、案内所や放送室へ即座に連絡が入り、周辺の運用が遅滞なく連動するようなものだ。

押したその瞬間にしか出会わない三つの不具合

この三つはいずれも、指が鍵を押したその瞬間にしか姿を見せない。だからいらだちが大きい。GNU screen 内でテキストを選択コピーした際、端末に base64（任意のデータを英数字のみに変換する符号化方式）の文字列が出力される現象が治り、正しくコピーされる。Vim モードの空プロンプトで左矢印キー（←）を押した際、INSERT モードだけでなく NORMAL モードからでもエージェント画面へ戻れる。スクリーンリーダーモードでの入力時に、キーを叩くたび行全体を読み直さず、入力した一文字だけを音読する。ボタンの反応が乱れた操作パネルを使うようなものだ。選択テキストに無関係な文字列が出力され、戻るキーが引っ掛かり、入力のたびに全文が読み上げられ、押した瞬間の応答がすべて食い違っていた。

遠隔側が古い状態を映さなくなり、エラーも原因の設定を名指しする

一台挟んで操作していて怖いのは、画面の表示と実際の状況が食い違うことだ。今回はリモートコントロール（遠隔操作）のそうしたずれを三か所ふさいだ。モデル切り替えや再接続、組織権限チェックの失敗後に、リモートコントロール側で高速モードの古い状態が残る問題を解消した。また「Remote Control is only available via api.anthropic.com」のエラーが出た際、原因となった具体的設定項目を画面上で明示するように改善した。そして claude --teleport を実行した際、手元の checkout リポジトリがセッションのリポジトリと一致しない場合、現在どこを指しているかを明確に表示する。遠隔操縦の計器盤と同じで、スイッチの状態がリアルタイムに一致し、故障時は該当のブレーカー名を指し示し、位置が合わない時は実際にどの格納庫にいるか教えてくれる。

無効な Git Bash パスを警告して無視、応答途中のエラーでも生成済み回答を保持

パス設定の誤入力や途中の回線切断が起きても、生成中の結果や実行の流れが消えてなくなる事故を防げる。重要な修正が二点入った。Windows で CLAUDE_CODE_GIT_BASH_PATH 環境変数が bash や sh 以外のファイルを示している場合、以前は終了するか誤作動していたが、警告を出して無効パスを無視するようになった。また画面なしでテキストを出力する claude -p の実行中、応答の途中で API エラーが発生して処理が中断しても、すでに生成された回答の前半部分を破棄せず保持して出力する。カーナビのようなものだ。無効なルートを指定しても警告を出して本道を走り続け、途中で電波が切れても読み込み済みの前半ルートをそのまま残してくれる。

새 Claude Opus 5가 기본 Opus 모델을 넘겨받았다. 식별자는 claude-opus-5다. 한 번에 읽어 들이는 context(모델이 한 번에 기억하는 글자 분량)는 백만이고, 빠른 모드 요금은 백만 문자 단위당 입력 10달러, 출력 50달러다. 여기에 두 가지가 함께 움직인다. /fast는 Opus 4.7에서 빠지고 Opus 5와 Opus 4.8에 적용된다. claude-api 스킬의 기본값도 Opus 5로 바뀌고 Opus 4.8에서 옮겨 오는 방법이 함께 붙었다. 학교가 교과서를 새 판으로 바꾸는 것과 같아서, 학기 초에 받는 것은 자동으로 새 판이다. 다만 도서 목록에 옛 판 번호를 박아 두었다면 주문해도 오지 않는다. 아무것도 하지 않아도 새 모델을 쓰게 되고, 되짚어 볼 것은 옛 식별자를 그대로 적어 둔 스크립트뿐이다.

`/model` 목록에서 잘못 보게 되던 세 가지를 한 번에 고쳤다

서브에이전트가 다시 서브에이전트를 부른다, 세 층까지

동적 워크플로가 기본적으로 에이전트 15개 미만을 목표로 한다

알아서 짜 주는 워크플로에는 규모 기준이 없어서, 요청 하나가 수십 개 에이전트로 갈라져 나란히 도는 일도 있었다. 전체 모습도 비용도 잡히지 않는다. 이제 기본은 중간 규모, 곧 "에이전트 15개 미만을 목표로"이며, 상한이 아니라 권고다. 바꾸는 길은 둘이다. 그때그때 바꾸려면 /config의 Dynamic workflow size에서 다른 규모나 무제한을 고른다. 고정하려면 아무 설정 파일에나 workflowSizeGuideline을 적는다. 예를 들면

{"workflowSizeGuideline": "medium"}

설정 파일이 이 키를 지정하고 있는 동안 /config의 그 줄은 알아서 숨는다. 양쪽이 서로 다른 말을 하지 않게 하기 위해서다. 실행 중인 워크플로에서는 지금 쓰는 규모가 상태 줄에 나오고, 바꾸고 싶을 때 갈 /config 안내도 함께 붙는다. 인원 상한을 알리지 않는 여행처럼, 상한이 없다는 것은 자유가 아니라 현장에 가서야 몇 명이 왔는지 안다는 뜻이다.

샌드박스의 외부 연결을 묻지 않고 막는 설정이 생겼다

샌드박스(명령을 가둬 놓고 돌리는 제한 구역) 안의 명령이 허용 목록에 없는 상대에 접속하려 하면, 지금까지는 통과시킬지 묻는 확인이 떴다. 자동 실행에서는 자판 앞에 아무도 없으니 그 확인에서 흐름 전체가 멈춘다. 새로 들어온 sandbox.network.strictAllowlist를 쓰면 묻지 않고 바로 거절할 수 있다. 켜려면 설정 파일에 이렇게 적는다.

{"sandbox": {"network": {"strictAllowlist": true}}}

중첩은 "상자 속의 상자"로 읽는다. sandbox 안에 network가 있고 그 안에 strictAllowlist가 있다. 건물 출입 규정을 엄격한 쪽으로 돌리는 것과 같다. 등록 없는 방문자는 애초에 들어오지 못하고, 경비가 위층에 전화해 가부를 묻는 일도 없어진다. 돌아가는 손님은 생기지만 새벽에 깨는 사람도 없어진다.

외부 도구에 연결되지 않을 때 이유를 드디어 알려준다

MCP(AI를 외부 도구에 연결하는 약속) 서버에 연결되지 않을 때, 실패했다는 것만 알 뿐 이유는 알 수 없었다. 이번에 세 군데에서 단서가 늘었다. claude mcp list와 /mcp는 HTTP 상태와 오류 본문을 함께 알려주어, 자격 증명이 만료된 것인지 주소를 잘못 친 것인지 가려낼 수 있다. 설정값 앞뒤에 보이지 않는 공백이 섞여 있을 때도 경고가 뜬다. 화면상으로는 멀쩡해 보이기에 이런 오류가 가장 고약하다. 화면 없는 stream-json 초기화 이벤트에는 mcp_server_errors가 붙어, --mcp-config 항목 가운데 검증에서 건너뛴 것을 나열한다. 터미널 실행에서도 시작할 때 경고가 나온다. 반송된 우편과 같아서, 예전에는 "배달 불가" 도장만 찍혀 왔지만 이제는 주소의 어느 줄이 문제인지 전표에 적혀 있다.

회사가 내려보낸 외부 도구 목록이 로컬 설정에 덮이지 않는다

회사가 일괄로 내려보내는 MCP 허용·거부 목록에는 ${VAR} 같은 변수가 자주 들어가고, 실행할 때 진짜 값으로 바뀐다. 문제는 그 값을 어디서 읽어 오느냐였다. 설정 파일의 환경 변수 칸에서 읽었는데, 그 설정 파일은 사용자 손안에 있다. 관리자가 정한 규칙을 로컬의 한 줄로 다시 쓸 수 있었다는 뜻이다. 이제는 시작할 때의 환경과 관리 설정 쪽 환경에서 해결하고, 설정 파일의 것은 끼어들지 않는다. 병원의 투약 규정과 비슷하다. 예전에는 각 간호 스테이션이 화이트보드에 옮겨 적어 두어 누구든 지울 수 있었다. 이제는 매번 코드를 읽어 시스템의 원본을 그대로 참조한다.

대화 도중 폴더를 더하면 훅이 깨어난다

이야기 도중에 "저 폴더도 봐야 한다"는 생각이 나서 끌어온다. 새 DirectoryAdded 훅(특정 사건이 일어나면 자동으로 불려 나오는 작은 프로그램)이 바로 그 순간 깨어나 주변 자동화 도구에 알린다. /add-dir 명령을 입력하거나 SDK에서 register_repo_root 제어 요청을 보내 세션 중간에 새 작업 디렉터리를 등록하면 DirectoryAdded 훅(특정 이벤트가 일어날 때 실행되는 소형 프로그램)이 발생한다. 주변 도구들이 폴더 목록의 변화를 곧바로 알 수 있다. 행사 도중 전시장에 새 부스를 새로 넣었을 때 안내소와 방송실로 즉시 연결 통보가 들어가 주변 서비스가 지체 없이 맞춰 움직이는 것과 같다.

누르는 순간에만 마주치는 세 가지 결함

이 셋은 모두 손가락이 자판을 누르는 그 순간에만 모습을 드러낸다. 그래서 거슬림이 크다. GNU screen 환경에서 텍스트를 드래그해 복사할 때 터미널에 base64(임의의 데이터를 영문자와 숫자로 바꾸는 인코딩) 문자열이 찍히던 현상이 사라지고 정상 복사된다. Vim 모드의 빈 프롬프트에서 왼쪽 화살표(←)를 누르면 INSERT 모드뿐 아니라 NORMAL 모드에서도 에이전트 화면으로 정상 돌아간다. 스크린 리더 모드에서 자판을 칠 때 매번 줄 전체를 다시 읽는 대신 방금 입력한 한 글자만 읽어 준다. 버튼 반응이 어긋난 조종 판넬을 쓰는 것과 같다. 텍스트를 선택하면 무관한 문자열이 찍히고, 되돌아가기 키가 걸리며, 자판을 칠 때마다 전체 문장이 낭독되어 누르는 순간의 반응이 모두 엇갈렸던 셈이다.

원격 쪽이 옛 상태를 비추지 않고, 오류도 원인 설정을 짚어 준다

장치 하나를 사이에 두고 다루다 보면 가장 무서운 것은 화면에 적힌 것과 실제가 어긋나는 일이다. 이번에는 원격 제어(Remote Control)의 그런 어긋남 세 군데를 메웠다. 모델 변경이나 재연결, 조직 권한 확인 실패 후 원격 제어 클라이언트에 빠른 모드의 옛 상태가 남아 있던 문제를 고쳤다. 또한 "Remote Control is only available via api.anthropic.com" 에러가 뜰 때 충돌을 일으킨 특정 설정 항목 이름을 화면에 바로 찍어 준다. 그리고 claude --teleport를 실행할 때 로컬 checkout 저장소가 세션의 저장소와 다르면 현재 가리키는 저장소가 어디인지 명확히 출력한다. 원격 조종석의 계기판처럼 스위치 상태가 실시간으로 일치하고, 고장 시 해당 차단기 이름을 알려주며, 위치가 맞지 않을 때 실제로 어느 차고에 서 있는지 알려주는 셈이다.

잘못된 Git Bash 경로는 경고 후 무시하며, 중도 오류 발생 시에도 기존 답변을 보존한다

경로 설정 오류나 도중 네트워크 중단이 발생해도 작업 결과물과 실행 흐름이 순식간에 날아가는 사고를 막아준다. 두 가지 중요한 수정이 이루어졌다. Windows에서 CLAUDE_CODE_GIT_BASH_PATH 환경 변수가 bash나 sh 실행 파일이 아닌 경로를 가리킬 때 이전에는 바로 종료되거나 잘못 실행되었지만, 이제는 경고를 출력하고 해당 무효 경로를 무시한다. 또한 화면 없이 텍스트를 출력하는 claude -p 실행 중 답변 생성 중간에 API 네트워크 에러로 중단되더라도, 이미 생성된 이전 답변을 버리지 않고 그대로 보존하여 출력한다. 네비게이션과 같다. 잘못된 경로를 넣어도 경고를 띄우며 본선 도로를 계속 달리고, 도중에 신호가 끊겨도 이미 불러온 앞쪽 경로를 그대로 남겨 준다.
