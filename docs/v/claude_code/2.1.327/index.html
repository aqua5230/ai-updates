Claude Code 2.1.327

發布日期：2026-11-17

繁體中文

新功能

/install-github-app 修改前會先確認

想在專案裡裝好 GitHub 應用程式，輸入 /install-github-app 後現在不會直接改動儲存庫，而是先問過你再繼續。挑選儲存庫、設定金鑰與 API key 的步驟也換成標準清單與按鍵操作，搭配簡短提示、載入動畫和更清楚的錯誤訊息。

就像請水電工進家門裝新開關，動手鑽牆前會先跟屋主確認位置，手上的工具箱也整理得一目了然。
新功能

claude mcp 讀設定不留金鑰且保護原檔

想用 MCP（連接外部工具的協定）串接外部服務，現在可在終端機外從標準輸入讀取 JSON 設定。這讓 token（授權令牌）不用寫在指令列上，但這指令不能在 Claude Code 工作階段內執行。

claude mcp add-json <name> -

以專案層級執行 claude mcp add 或 claude mcp remove 時，不會再誤刪 .mcp.json 的 $schema 或 servers 等頂層欄位。 若 .mcp.json 沒有 mcpServers 鍵而把伺服器列在最外層，claude mcp add --scope project 會直接停下，不再覆寫原檔。

好比收件人遞來摺好的密碼紙條照單登記，既不把密碼抄在公開名冊上，也不塗掉旁邊別人寫好的欄位。
問題修復

遠端 MCP 長時間斷線後改在背景自動重試

連著公司內網或遠端工具寫程式，VPN 斷線重連後 MCP 伺服器卻一直卡在斷線狀態。只要是透過主機名稱走 HTTPS 連線的外機伺服器，大多會在斷線後改由背景持續重試約一天，不再直接放棄。

像手機進地下停車場沒訊號後，不用每次都手動重開飛航模式，回到地面就會自己在背景把連線接回來。
新功能

/mcp 頁面統一版面並改善操作與狀態提示

在工作階段中途剛新增或婉拒過一個 MCP 伺服器，打開 /mcp 卻只看到尚未設定伺服器的錯誤說法。這個提示已經修正，現在會直接告訴你接下來該怎麼處理。 /mcp 內的本機、遠端與代理伺服器頁面也改為共用同一套版面，所有選單最底下都加上 Back 返回項。除了螢幕閱讀器模式外，操作選項不再顯示編號，改用方向鍵與 Enter 鍵挑選即可。

像把分散各棟樓的公佈欄換成同一套格式，每張選單最底都固定留一格回上頁，不用再找編號按鍵。
新功能

MCP 伺服器日誌不再寫入請求與回應全文

想查看除錯紀錄又擔心把互動填寫的細節全部寫進 log，現在這條規則改得更保守了。MCP 伺服器的日誌遇到引導輸入請求與 hook（掛鉤，特定事件發生時被觸發的小程式）回應時，只會記下模式、動作與欄位名稱，不再存下完整內容。

跟學校點名簿只勾選出席與請假類別、不抄寫請假條全文一樣，紀錄照樣齊全卻不會留下多餘內容。
新功能

/status 新增設定與檔案錯誤檢查清單

寫好的代理、技能、自訂指令或輸出樣式檔案突然沒反應，以前常不知道問題出在哪。現在輸入 /status，畫面裡會直接列出一份異常清單，把這幾類損壞的檔案一次找出來。 清單還會同步抓出快捷鍵設定錯誤、無法使用的沙盒、被忽略的權限設定，以及永遠匹配不到的 hook 條件規則。

如同汽車儀表板多了一排故障檢修燈，不用自己逐一拆引擎蓋，掃一眼就知道哪條設定管線沒接上。
新功能

/config 顯示設定覆蓋來源並改進操作提示

在 /config 調整選項後卻發現設定沒生效，或是不知道該按哪個鍵切換數值，這些困擾現在一起處理了。 如果某一行設定已被其他層級的設定覆蓋，/config 旁邊現在會直接附註說明。從 /config 與類似指令修改設定卻儲存失敗時，過去完全沒有任何警告，現在提示詞下方會顯示一行訊息告知你。 切換主題後不再誤顯示為已關閉對話框，而是正確提示 Set theme to …。/sandbox 與多數 /config 的數值清單在非螢幕閱讀器模式下也取消編號，改用方向鍵與 Enter 選取。

就像調整冷氣遙控器時，螢幕會明白標出哪段風速被總控鎖定、設定失敗也會亮燈提醒，不用盲猜按鈕有沒有送出。
問題修復

修復自訂設定路徑與環境變數未正確套用

自己指定了設定檔資料夾或額外設定來源，功能卻還是讀成預設位置或漏掉項目，這組更新把這些讀取錯位一起修好。 專案 .claude/settings.json 透過 ANTHROPIC_BASE_URL 連往其他 LLM 閘道器時，部分終端機工作階段執行 /model 曾列出錯誤模型清單，現在已修正。 當 CLAUDE_CONFIG_DIR 指向其他資料夾時，/statusline（顯示在終端機最底下的狀態列）過去仍誤寫回 ~/.claude/settings.json，現在不再寫錯檔案。 在 Windows 設定 claudeMdExcludes 排除規則時，就算磁碟機代號大小寫與實際路徑不同，現在也能正常比對。透過 --settings 傳入的 hook，現在也會完整列在 /hooks 裡。

新功能

企業閘道器新增設定校驗與計費群組支援

這項更新主要給管理 Claude apps 閘道器的團隊管理員使用。當受管設定開啟 CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 時，送給閘道器的提示標頭裡現在會多帶一筆受管設定的校驗碼，原本已有傳送提示標頭的地方也會一併附上。 如果閘道器端已啟用計費群組標籤，現在還可以在設定檔加入 attributionProject，幫每個工作階段指定對應的計費群組名稱。

好比公司各部門領用影印卡時，卡面上不但附上規定版本的核對印記，也能順手寫好要掛帳的部門代號。
新功能

Anthropic 雲端忽略更多儲存庫設定

在遠端託管環境開啟工作階段時，專案資料夾裡自帶的旗標與外掛派送規則，現在更不容易覆蓋原有運作。 從現在起，在 Anthropic 託管的雲端工作階段裡，這類來自儲存庫的旗標與外掛發佈設定將被忽略更多。就算儲存庫設了 CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC，效果最多也只相當於 DISABLE_TELEMETRY。

有如進到統一控溫的植物溫室，訪客手冊最多只管得了單一花盆的澆水提醒，整座溫室的空調跟灑水還是照場館規則走。
問題修復

雲端與自託管執行器的目錄保護與停止修復

在雲端環境或自架執行器跑自動化流程，這批修補處理了幾種會誤刪資料或停不下來的狀況。 使用 --use-anthropic-git-proxy 啟動自託管執行器時，若環境變數 GIT_CONFIG_GLOBAL 指向一個非空資料夾，過去會在開機時把它整包刪掉。現在會改為保留該目錄、忽略這個變數並印出警告。 工作階段內的腳本或 hook 呼叫 claude -p 時，以前會繼承原本工作階段的重試設定而在遇到速率限制時乾等，現在已修正。 在未載入功能旗標的雲端與自託管執行器工作階段裡，若重啟後才收到核准、原本按過 Stop 的指令過去仍會繼續跑，現在也不會再執行。

新功能

切換或重新登入帳號後的背景工作與暫停規則

操作中途因為觸及用量上限而重登，或是直接換成另一個帳號使用，背景跟終端機裡的工作流程不會立刻跟著混跑。 切換帳號之後，部分預先啟動好的背景工作階段會直接捨棄，不留給新帳號接手。終端機裡因用量上限而暫停的工作流程，就算中途重新登入也會維持暫停，直到切回原本的登入帳號，或由你手動輸入新提示詞才會繼續。

好比打球到一半換人上場時，先前的暫停牌不會自動收走，前一位選手回來或你重新發球，比賽才繼續往下走。
新功能

多組憑證並存與指定組織時的登入提示改善

電腦上同時設定了 API key、組織綁定或登入方式限制，遇到拒絕連線常搞不清問題出在哪組憑證。 在巢狀呼叫的 claude 裡帶著自己的 token 執行時，過去會被 forceLoginOrgUUID 擋掉。現在拿不到母工作階段 token 的指令不再繼承它的 CLAUDE_CODE_OAUTH_SCOPES，有需要時再為該指令單獨設定。 當電腦把 forceLoginMethod 設為 console（主控台模式）時，兩則登入錯誤訊息不再誤導你去選 Claude 訂閱方案。同時設了 API key 與 Anthropic 設定檔時，警告也會明白寫出目前正用哪一組，以及怎麼切回設定檔。

新功能

新增 /tui classic 切換回非全螢幕模式

習慣在一般終端機捲動畫面裡看對話，不想切進全螢幕介面時，現在多了一個更好記的切換指令。輸入 /tui classic 就能切成非全螢幕顯示模式，原本的 /tui default 指令也照常有效。

如同電子書閱讀器保留了傳統翻頁鈕，只是順手把選項名字標得更貼近實際畫面，原本按慣的舊名稱照樣能用。
新功能

全螢幕選取複製不再夾帶訊息前綴符號

在全螢幕模式裡用滑鼠反白複製 Claude 的回覆，貼出來卻常連帶複製到系統、思考或傳入訊息開頭的符號。現在全螢幕的文字選取會自動略過這些訊息行前方的圖示符號，只留下真正要複製的內容。

就像抄寫黑板上的重點時，手邊會自動跳過老師畫在行首的星號與箭頭，只把句子本身帶走。
新功能

遠端桌面編輯器首次啟動跳過終端機設定

在遠端連線的 VS Code、Cursor 或 Devin Desktop 裡第一次開啟 Claude Code，原本還會跑一段終端機設定流程，但這幾個環境其實改不到本地設定。現在首次啟動設定在這些遠端工作階段會直接跳過這一步。

好比訂好已經組裝完成的辦公桌椅，搬進去坐下就能直接開工，省去重新鑽孔鎖螺絲的白忙。
問題修復

終端機畫面錯亂、凍結與整體穩定性修復

調整視窗大小或遇上短暫資源吃緊時，終端機畫面偶爾會出現錯亂字元甚至整片卡死，這批更新把這些顯示與穩定問題修好了。 在 Ghostty 縮放視窗後的回捲錯亂，以及 16 色環境下選取反白消失的問題都已修正。Windows Terminal 搭配舊版 tmux 或 VTE 0.50.0 時，看不到連結網址的狀況也修好了。 在 kitty、Ghostty 或 iTerm2 裡開啟 tmux 的 allow-passthrough 時，部分文字行變成亂碼的狀況也已解決。 短暫記憶體不足後畫面卡在空白或凍結、罕見會凍結畫面或結束工作階段的顯示異常，以及其餘錯誤修復與穩定性改善也一併處理完成。

問題修復

切換全螢幕與代理檢視的終端殘留與閃爍修復

在工作階段剛切換畫面或結束時按下按鍵，有時會讓終端機卡在奇怪的狀態，這幾個切換漏洞都已經修好。 按 ← 打開代理檢視後立刻按 ctrl+c 離開，過去會讓殼層留下空白畫面與多餘的滑鼠控制碼，現在退出會乾淨恢復。 在信任確認題之後馬上按 Ctrl+C，終端機不再一直被留在全螢幕模式裡。全螢幕模式下按 ← 開啟代理檢視時，原本底下的殼層畫面也不會再閃現一下。

新功能

窄視窗與短螢幕的版面配置及長文顯示改善

用半邊螢幕或小視窗開終端機工作，文字被裁掉、分隔線重複或找不到關閉提示都容易讓人卡住。 MCP 伺服器的長提問不再只顯示一行就被截斷，文字欄位貼上長內容時會有提示，/plugin 選項與 /login 的 Bedrock、Vertex 步驟也去掉重複的分隔線。 帶顏色或連結的指令輸出不再多算 "+N lines" 的行數，對話紀錄在矮視窗按 ? 叫出說明時也能看得到怎麼離開。 /status、表單與詳情頁在窄終端機重新整理了排版，/model 與 /effort 在約 40 欄寬也能擺下，像 ←/→ to adjust 這類按鍵提示也不會被擠掉。

新功能

恢復超長工作階段重試讀檔並在缺漏時提醒

隔幾天回來接續一場聊了很久的工作階段，誰都不希望前面的討論莫名缺了一大塊。現在恢復非常長的工作階段時，如果讀取對話紀錄提早中斷，Claude Code 會自動再重試讀取一次，減少訊息遺漏的機會。 要是之前的舊訊息真的無法載入，畫面現在還會多顯示一行明確提示，讓你立刻知道紀錄不完整。

跟轉存老錄音帶一樣，讀到一半斷掉會自動重讀一次，真的缺了一段也會先在上面標出空白記號。
問題修復

工作階段當機或清除後重開不再漏失訊息

對話跑到一半遇到當機、被強制結束或丟到背景後再回來接續，過去偶爾會掉回答或讓清掉的項目死灰復燃，這幾種紀錄錯亂都修好了。 headless（無頭模式，沒有終端機視窗的執行模式）工作階段在程序被終止後，即使收到同一組識別碼重送的訊息，恢復時也不再丟失已存訊息。 遇到空白回覆或被中止的指令後再次當機或切到背景，重開時不再遺漏該則回答，也不會把已倒帶撤回的提示詞翻出來。 遠端工作階段若在重啟期間按過 Stop 後送出訊息又遇上當機，以及未載入功能旗標的雲端與自託管工作階段在 /clear 之後建的工作，現在恢復時都能正確保留狀態。

問題修復

/export 匯出檔案前改為先詢問是否覆蓋

用 /export 把對話匯出存檔，以前只要檔名跟現有檔案撞名就會直接覆蓋過去。現在透過對話框匯出撞名時會先問你是否覆蓋；直接執行 /export <name> 則會保留原本檔案，並提醒你改跑 /export 來操作。

問題修復

/teleport 與 /rewind 失敗時不再默默關閉

把對話傳送到另一端或把檔案倒帶回舊版本，萬一中途失敗卻什麼都不講直接關掉畫面，常讓人誤以為一切正常。 用 /teleport 切換並載入指定的工作階段卻恢復失敗時，現在會顯示明確的失敗訊息，而且在 /teleport 的載入錯誤畫面上按 Enter 也不會誤把視窗直接關掉。 使用 /rewind 還原檔案若遇上部分檔案無法復原，過去會不發一語直接關閉，現在不再沒交代一聲就關掉。

新功能

長回覆撞到輸出上限後的自動接續與壓縮保留

請 Claude 一次吐出很長的程式或報告，萬一回覆寫到一半撞到輸出上限，接續處理容易掉資料。現在使用未辨識型號的模型時，若回覆在 32,000 個輸出 token（計量文字單位）處被截斷，接著會改用 128,000 的上限繼續寫完。 回覆剛因輸出上限截斷就立刻觸發對話壓縮時，過去會連帶把那一輪的工具呼叫與執行結果一併弄丟，這個遺失問題現在也已修好。

像畫草圖畫滿小畫紙被喊停時，現在會換上一張大畫布接著畫完，不會把剛貼上去的色票也一併掃進抽屜。
問題修復

/resume 清單顯示與花費上限提示不再誤報

挑舊工作階段接續或觸及花費上限，畫面若顯示錯了數字或給出沒用的操作建議，只會越按越迷惘。 在 claude --resume 與 /resume 挑選紀錄時，即使分支名稱或資料夾路徑很長，目前選中的工作階段也不再跑出螢幕外面。清單也補回原本少列的一筆空間。 碰上多數花費上限後，畫面不再冒出重送也無濟於事的 'Resend your message' 提示。花費上限選單被伺服器拒絕修改時，也不會再誤報已經改好。

新功能

歷史紀錄不再收錄其他 Claude 開的背景指令

用上下鍵翻找自己打過的提示詞歷史時，裡頭卻夾雜一大堆由 Claude 自己在背景跑起來的啟動指令，往往把真正常用的提問洗掉。現在提示詞歷史會略過大多數由另一個 Claude Code 工作階段啟動的開局提示，例如 Claude 自己執行的 claude --bg。

換成廚房點單來看，主廚自己叫學徒切菜的小單不會混進客人的點菜單裡，櫃檯翻起來清楚許多。
新功能

非互動 -p 模式與子代理的模型設定等待調整
