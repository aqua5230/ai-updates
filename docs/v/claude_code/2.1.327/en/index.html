Claude Code 2.1.327

Released: 2026-11-17

Release notes

FEATURE

/install-github-app Asks Before Making Changes

To set up the GitHub app in your project, running /install-github-app now asks for your confirmation before modifying the repository. The steps for choosing a repository and setting secrets and API keys now use the standard list and key controls, paired with shorter prompts, a loading spinner, and clearer error messages.

Picture hiring an electrician to install a new switch: before drilling into the wall, they confirm the spot with you, and their toolbox is neatly organized.
FEATURE

claude mcp Reads Config Without Exposing Keys and Protects Files

To connect external services via MCP (a protocol for linking external tools), you can now read JSON configuration from standard input outside the terminal. This keeps tokens (authorization credentials) off the command line, though the command cannot run inside a Claude Code session.

claude mcp add-json <name> -

Running claude mcp add or claude mcp remove at the project level no longer deletes top-level fields such as $schema or servers from .mcp.json. If .mcp.json omits the mcpServers key and lists servers at the top level, claude mcp add --scope project now stops instead of overwriting the original file.

Think of a clerk logging a folded slip with a passcode: they never copy the passcode onto the public ledger, nor do they erase the fields others have already written beside it.
BUGFIX

Remote MCP Retries in the Background After Long Disconnects

When coding against a company intranet or remote tools, MCP servers could stay stuck disconnected after a VPN drops and reconnects. Most servers on external machines reached by hostname over HTTPS now retry in the background for about a day after disconnecting instead of giving up right away.

Like a phone losing signal in an underground garage, you do not have to toggle airplane mode every time—once back above ground, it reconnects in the background on its own.
FEATURE

Unified /mcp Layout with Clearer Prompts and Navigation

After adding or declining an MCP server mid-session, opening /mcp used to wrongly claim no servers were configured. That message is now fixed and tells you what to do next. The local, remote, and agent server pages in /mcp now share a single layout, with a Back item added at the bottom of every menu. Outside screen reader mode, action options are no longer numbered; use the arrow keys and Enter to select them instead.

A building manager standardizes bulletin boards across every wing so each menu keeps a fixed slot at the bottom to go back, sparing you from hunting for numbered keys.
FEATURE

MCP Server Logs Omit Full Request and Response Bodies

If you want to inspect debug records without dumping every interactive detail into the log, this rule is now stricter. When logging elicitation requests and hook (small program triggered by a specific event) responses, MCP server logs now record only the mode, action, and field names rather than the full contents.

Just as a school attendance sheet checks off presence and leave type without copying the full absence note, the record stays complete without storing extra text.
FEATURE

/status Adds a Checklist for Config and File Errors

When a custom agent, skill, command, or output style file suddenly stops working, it used to be hard to tell why. Running /status now displays an issue list that surfaces all of these broken files in one place. The list also catches keybinding errors, an unavailable sandbox, ignored permission settings, and hook matchers that can never match.

Imagine a car dashboard gaining a row of warning lights: instead of popping the hood piece by piece, one glance shows which line is disconnected.
FEATURE

/config Shows Setting Overrides and Improves Prompts

Adjusting an option in /config only to see it take no effect, or not knowing which key switches values, are both addressed here. When a setting row is overridden by another layer, /config now displays a note next to it. If a change made from /config or similar commands fails to save, there used to be no warning at all; now a line under the prompt lets you know. Changing the theme no longer mistakenly says the dialog was dismissed, and instead shows Set theme to …. Outside screen reader mode, /sandbox and most /config value lists are also unnumbered, letting you pick with the arrow keys and Enter.

An air-conditioner remote shows on its screen which fan speed is locked by the main controller and lights up if a change fails, so you never have to guess whether a button press went through.
BUGFIX

Fixes for Custom Config Paths and Environment Variables

When you specified a custom config folder or extra settings source, features could still fall back to default paths or miss entries; this batch fixes those mismatches. When a project's .claude/settings.json points ANTHROPIC_BASE_URL to another LLM gateway, /model no longer lists the wrong models in certain terminal sessions. When CLAUDE_CONFIG_DIR points to another folder, /statusline (the bar displayed at the very bottom of the terminal) no longer writes back to ~/.claude/settings.json by mistake. On Windows, claudeMdExcludes patterns now match paths even when the drive letter case differs from the actual path. Hooks passed via --settings now appear in full under /hooks as well.

FEATURE

Enterprise Gateways Add Config Checksums and Billing Groups

This update is mainly for team admins managing Claude apps gateways. When managed settings enable CLAUDE_CODE_GATEWAY_HINT_HEADERS=1, the hint headers sent to the gateway now include a checksum of the managed settings, including places that already send hint headers. If billing group tags are enabled on the gateway, you can now add attributionProject to your config to assign a billing group name to each session.

Each department's copy card carries both an official version stamp for verification and the department code to charge expenses to.
FEATURE

Anthropic Cloud Ignores More Repository Settings

When starting a session in a remotely hosted environment, flags and plugin delivery rules bundled in the project folder are now less likely to override default behavior. From now on, Anthropic-hosted cloud sessions ignore more of these repository-level flag and plugin delivery settings. Even if a repository sets CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC, it takes effect at most as DISABLE_TELEMETRY.

Step into a climate-controlled botanical greenhouse, and a visitor's handbook can at most adjust the watering reminder for a single pot while the facility's rules still govern the whole building's airflow and sprinklers.
BUGFIX

Directory protection and stop fixes for cloud and self-hosted runners

When running automated workflows in cloud environments or on self-hosted runners, these fixes address cases where data could be deleted by mistake or commands refused to stop. When starting a self-hosted runner with --use-anthropic-git-proxy, if the GIT_CONFIG_GLOBAL environment variable pointed to a non-empty folder, startup previously deleted the entire directory. It now keeps the directory, ignores the variable, and prints a warning. When a script or hook inside a session invokes claude -p, it previously inherited the original session's retry settings and waited out rate limits; this is now fixed. In cloud and self-hosted runner sessions with no feature flags loaded, a command you had pressed Stop on would still run if its approval arrived after a restart; it now no longer executes.

FEATURE

Background sessions and pause rules after switching or re-logging in

If you log back in mid-task after hitting a usage limit, or switch directly to another account, background and terminal workflows will not immediately mix together. After an account switch, some pre-started background sessions are discarded rather than handed off to the new account. A terminal workflow paused at a usage limit stays paused even if you log back in mid-way, until you switch back to the earlier login or manually enter a new prompt.

When players swap out mid-game, the earlier timeout sign stays up until the previous player returns or you serve again to resume play.
FEATURE

Improved sign-in prompts with multiple credentials and organization locks

When a machine has an API key, an organization binding, or a login method restriction configured at the same time, rejected connections often leave it unclear which credential is at fault. When running a nested claude call with its own token, forceLoginOrgUUID previously blocked it. Commands that do not receive the parent session's token no longer inherit its CLAUDE_CODE_OAUTH_SCOPES, so you can set it individually on any command that needs it. When forceLoginMethod is set to console on a computer, two sign-in error messages no longer point you to the Claude subscription option. When both an API key and an Anthropic profile are set, the warning now clearly states which one is currently in use and how to switch back to the profile.

FEATURE

Added /tui classic to switch back to non-fullscreen mode

If you prefer reading conversations in standard terminal scrollback rather than switching to the fullscreen interface, there is now an easier-to-remember command. Entering /tui classic switches to the non-fullscreen display mode, while /tui default continues to work as before.

An e-reader keeps its classic page-turn button while giving the option a clearer name that matches the screen, so the old label still works as before.
FEATURE

Fullscreen copy selection no longer includes message prefix glyphs

Highlighting and copying Claude's replies with the mouse in fullscreen mode used to pull in the leading symbols from system, thinking, and inbound message lines. Fullscreen text selection now automatically skips those prefix icons, leaving only the content you actually want to copy.

Copying notes from a blackboard means your hand naturally skips the stars and arrows drawn at the start of each line, taking only the sentences themselves.
FEATURE

First-run setup skips terminal setup in remote desktop editors

Opening Claude Code for the first time in a remote VS Code, Cursor, or Devin Desktop session used to run a terminal setup step even though those environments cannot change local settings. First-run setup now skips this step in those remote sessions.

Ordering an office desk and chair that arrive pre-assembled lets you sit down and get straight to work, skipping the wasted effort of drilling and tightening screws.
BUGFIX

Terminal display corruption, freezes, and stability fixes

When resizing the window or hitting brief resource pressure, the terminal screen could occasionally show garbled characters or freeze completely; this update fixes those display and stability issues. Scrambled scrollback in Ghostty after resizing, along with missing selection highlights in 16-color environments, are now fixed. Link addresses being hidden in Windows Terminal under older tmux or VTE 0.50.0 is also resolved. Garbled text rows when tmux's allow-passthrough is enabled inside kitty, Ghostty, or iTerm2 have also been fixed. The screen staying blank or frozen after a brief out-of-memory error, a rare display fault that could freeze the screen or end the session, and other bug fixes and reliability improvements are included as well.

BUGFIX

Fixes for terminal leftovers and flashes when switching fullscreen and agents view

Pressing keys right as a session switches screens or exits could leave the terminal in an odd state; these switching bugs are now fixed. Pressing ← to open the agents view and immediately hitting ctrl+c to quit used to leave a blank screen and stray mouse codes in the shell; exiting now restores it cleanly. Pressing Ctrl+C right after the trust question no longer leaves the terminal stuck in fullscreen mode. Opening the agents view with ← in fullscreen mode no longer flashes the underlying shell on screen.

FEATURE

Layout and long-text display improvements for narrow and short windows

Working in a half-screen or small terminal window makes it easy to get stuck when text is clipped, divider lines repeat, or exit hints disappear. Long questions from an MCP server are no longer cut off after a single row, text fields show a sign when long pastes are hidden, and duplicate divider lines are removed from /plugin options and /login's Bedrock and Vertex steps. Command output with colors or links no longer overcounts "+N lines", and opening the transcript's ? help in a short window no longer hides how to exit. /status, forms, and detail screens now lay out better on narrow terminals, /model and /effort fit at around 40 columns, and key hints like ←/→ to adjust stay visible.

FEATURE

Retry reading and warn on missing messages when resuming very long sessions

Returning days later to continue a long conversation, nobody wants a chunk of earlier discussion to vanish unexpectedly. When resuming very long sessions, if reading the transcript ends early, Claude Code now retries reading once automatically so messages are lost less often. If earlier messages still cannot be loaded, the screen now displays a clear extra line letting you know the history is incomplete.

Dubbing an old cassette tape works the same way: if reading stops halfway, it tries reading again once, and if a section is truly missing, it marks the gap up front.
BUGFIX

Resuming Sessions After Crashes or Clears No Longer Drops Messages

When a conversation crashes, gets force-killed, or moves to the background midway and you pick it back up, several log glitches that used to drop replies or bring back cleared items are now fixed. After a headless (running without a terminal window) session's process is terminated, resuming it no longer loses stored messages even if a message is resent with the same identifier. If another crash or move to the background happens after an empty reply or a killed command, reopening the session no longer drops that answer or brings back prompts that were already rewound. Remote sessions that had a message sent after Stop was pressed during a restart and then crashed, as well as tasks created after /clear in cloud or self-hosted sessions with no feature flags loaded, now keep their state properly when resumed.

BUGFIX

/export Now Asks Before Overwriting Existing Files

When saving a conversation with /export, a matching filename used to overwrite the existing file right away. Now, exporting through the dialog asks before overwriting on a name conflict, while running /export <name> directly keeps the original file and prompts you to run /export instead.

BUGFIX

/teleport and /rewind No Longer Close Silently on Failure

When transferring a conversation or rewinding files to an earlier version, having the screen close silently on a failure makes it look like everything went fine. If switching to and loading a chosen session with /teleport fails to resume, it now shows a clear failure message, and pressing Enter on /teleport's load error screen no longer closes the window by mistake. When restoring files with /rewind runs into files that cannot be recovered, it no longer closes without a word as it used to.

FEATURE

Automatic Continuation and Compaction Retention After Hitting Output Limits

Asking Claude for a very long piece of code or report can risk losing data if the reply hits the output limit partway through and needs to continue. Now, on unrecognized models, if a reply is cut off at 32,000 output tokens (units of text measured by the model), it continues writing with a limit of 128,000. When conversation compaction triggered right after a reply was cut off at the output limit, it used to drop that turn's tool call and its result along with it, and that loss is now fixed.

Switching to a larger canvas when a small sketchpad fills up lets you finish the drawing without sweeping the color swatches you just pasted into a drawer.
BUGFIX

/resume List Display and Spend Cap Hints No Longer Misreport

When picking an old session to resume or hitting a spend cap, showing the wrong numbers or unhelpful action tips on screen only makes things more confusing. When choosing a record in claude --resume and /resume, the currently selected session no longer scrolls off screen even when branch names or folder paths are long. The list also restores the one slot it used to leave out. After hitting most spend caps, the screen no longer pops up a 'Resend your message' hint where resending cannot help. When the server refuses a change in the spend limit menu, it also stops falsely reporting that the limit was updated.

FEATURE

Prompt History Excludes Background Commands Started by Other Claude Sessions

When using the up and down arrows to flip through your own prompt history, having it cluttered with launch commands that Claude started in the background often buries your actual questions. Prompt history now skips most opening prompts launched by another Claude Code session, such as claude --bg run by Claude itself.

At a kitchen pass, little prep notes from the chef to an apprentice no longer get mixed into the stack of customer order tickets, keeping the counter tidy when you flip through them.
FEATURE

Model Settings Wait Adjustments for Non-Interactive -p Mode and Subagents

When running commands directly in automation scripts or dispatching a helper to handle a task, those first few seconds often run into stalls or things not being ready yet. Non-interactive mode (-p) now runs fewer git commands before sending its first request. When fetching model settings stalls, such as at a proxy server, claude -p waits 10 seconds and then continues instead of hanging. When launching the first subagent on a model, it now waits up to 1.5 seconds (10 seconds in claude -p) for that model's settings from Anthropic instead of starting without them.

Much like a bus pausing at a stop for a few seconds to wait for transferring riders, it no longer pulls away before rules are aligned, yet still departs on schedule if nobody shows up.
BUGFIX

Proxy Settings in Non-Terminal Environments and Linux Startup Fixes

When hooking Claude Code into the desktop app, an SDK, or a scheduler, or when starting and resuming sessions on Linux, several environment combinations used to make the process fail outright or report a false crash. When https_proxy or HTTPS_PROXY is set to a bare host:port and neither input nor output is a terminal (such as the desktop app, an SDK, or cron), it now starts normally instead of refusing to open. On Linux, when the process restarts itself during startup (such as after first signing in to a Claude apps gateway or turning on Code Mode), it no longer occasionally drops back to the shell. When a Linux security policy blocks a process from signaling itself, resuming a suspended session or exiting no longer triggers a false crash report and wrong exit code.

FEATURE

Stricter Permission Controls for Working Directory Boundaries and Cross-Directory Reads

To help make sure Claude stays inside the project folder and does not touch outside files unchecked, this release tightens the checks on both directory boundaries and shortcuts. Path checks now refuse some symlinks (shortcut files pointing to another location), and the rules for what counts as inside a working directory are stricter, so some paths now prompt for confirmation. If the setting that blocks reading files outside working directories is enabled (see the key below):

{
  "permissions": {
    "blockReadsOutsideWorkingDirectories": true
  }
}

In bypass and auto modes, more Bash commands now ask you first before running, and some are denied outright in auto mode. If a Bash command names a path covered by a Read or Edit deny rule, it is now blocked directly instead of asking.

Rebuilding a bamboo fence around your vegetable patch and sealing the drainage ditches underneath means anyone reaching for a neighbor's row has to ask the owner first.
FEATURE

Auto Mode Ignores More Package Rules and Announces Fallback Removal

When auto mode is on and Claude decides on its own whether commands are safe, there are important updates to allowlist matching and the upcoming billed fallback behavior. When auto mode needs to fall back to billed classifier requests, the notice now tells you upfront that an upcoming release will remove this fallback, and actions it would have checked will instead ask you or be denied. For rule matching, auto mode now ignores more allow rules that can run arbitrary packages, such as Bash(pnpm dlx *). Path or version forms of rules it already ignored (such as /usr/bin/npm run:*) are now handed to the safety check as well. Auto mode also used to miss wildcard rules that name a script with .\, such as PowerShell(.\scripts\build.ps1 *), and now matches them properly.

A driving school tightening its road-test rules stops hiring outside fee-based examiners as a backup and instead has the instructor step in on the spot whenever a move looks uncertain.
BUGFIX

Code Mode Allows Tool-Hooking Mods and Fixes False Blocks

Previously, opening Code Mode was blocked outright whenever you had an extension mod installed that intercepts tool calls. Code Mode now starts normally even with those mods installed, though administrators can still force it off in managed settings. When running a Code Mode script in auto mode, the first running script no longer suddenly hits permission prompts or denials even if Claude launches a second script that auto mode also allows. For mod authors: when an internal call to the model completion or classification interface hits a usage limit, it now receives the API error immediately instead of hanging the entire turn, so make sure your mod catches and handles that error.

An amusement park lets runners wearing safety gear onto two tracks at once, so a mid-run handoff no longer trips the emergency stop.
FEATURE

Bash Blocks Long Variables and PowerShell Prompt Changes

Before running terminal commands, Claude Code adds another safeguard around oversized arguments and PowerShell commands. Whenever variables in a Bash command expand into very long text, the command is now denied with a prompt to use shorter values or write them to a file. Even when a rule already names a specific command, the PowerShell tool now asks before running one more kind of command. If nobody answers, it is refused unless a whole-tool allow rule, auto mode, or bypass permissions mode permits it.

A convenience-store drop box cannot fit an oversized scroll and asks for a shorter one or a box instead, and borrowing a key to open one extra drawer still waits for someone to nod before letting it pass.
FEATURE

Disallowed-Rule Parentheses and Sandbox Command Checks Improved

Commands that are not actually dangerous or are clearly covered by rules can still get blocked by checks or stuck in the sandbox, and these improvements make both evaluation and feedback more accurate. Some --disallowedTools rules containing parentheses previously misbehaved at times and now match properly. When a command exempt from the sandbox actually stays inside the sandbox because its permission check relied on it, Claude can now see that state. For commands without rm that the dangerous rm checker fails to parse, the refusal message has also been improved so Claude can resend harmless commands in plain syntax instead of giving up.

FEATURE

Preventing Commits and Uploads of Secret or Credential Files

When asking Claude to commit code or use the browser to upload attachments, the last thing you want is a password or private key slipping out. Now, when committing changes on newer models or through PowerShell, instructions explicitly tell Claude not to include files that may contain secrets in the commit. In the Claude in Chrome browser extension, when encountering certain login credential files, Claude now refuses to upload them and asks you to attach those files to the page yourself.

When you ask a friend to mail packages for you, they set any pouch stamped with private IDs back on the table so you can hand it over yourself when needed.
BUGFIX

Permission Prompts and Foreground Resume Key Guardrails

Just after switching back to the terminal or pressing arrow keys too quickly, it is easy to confirm a permission prompt by mistake the moment it appears. Most confirmation screens now handle keys differently so a slip does not turn into approval. For a brief moment after bringing a session back to the foreground with fg, most confirmation prompts only recognize Esc to cancel and ignore other key responses. On most permission prompts, pressing the down arrow key stops at No instead of wrapping back to the first option, and typing a number past the last option also lands on No. Pressing Esc right as a permission prompt appears no longer gets ignored occasionally, and pressing a number and Enter too early while reviewing a plan in screen reader mode no longer swallows the next number as well.

A microwave pauses a beat after the door shuts before accepting the start button, and the keypad stops at Cancel so an accidental extra press never turns on the heat.
BUGFIX

Confirming Before Worktree Removal and Fixing Accidental Deletions

When working across parallel branches at the same time, it is easy to worry about accidentally wiping unsaved files or ignored config files when leaving or cleaning up a workspace. Before ExitWorktree removes a worktree (a Git feature for opening parallel working copies) that may contain unsaved work, it now asks for confirmation. In don't-ask mode or when nobody can answer, removal is refused unless an allow rule, auto mode, or bypass permissions mode permits it. Stopping the server in worktree mode via Remote Control no longer deletes a running session's git-ignored files (such as .env). Exiting also clearly tells you when a worktree is kept. If a file or folder named HEAD sits at the top level, claude agents and claude rm no longer misread it as unpushed commits and refuse to clean up.

Before closing up shop, you lift the workbench drawer and ask the craftsperson whether any loose parts remain inside, so the private recipe taped to the side is not swept into the trash.
FEATURE

Sandbox Directory Scoping for --worktree With --add-dir

When opening a new workspace with --worktree and passing a relative folder path via --add-dir, it is easy to miscalculate which location the sandbox can actually see. If the relative path points to a directory beside the launch folder, the Bash sandbox now mounts the one beside the launch folder rather than a same-named location beside the worktree. If the relative path points above the launch folder (such as ..), these --worktree launches now give the Bash sandbox and --bg background sessions only the worktree itself, without also opening up the parent directory.

Booking a dance studio next door opens the room at the original venue's location, while naming the whole floor's main door opens only the dance studio itself.
BUGFIX

Subagents and Teammates Keep Their Own Models and Permissions

When multiple subagents or teammates with different specialties collaborate, compacting conversations or messaging each other to resume could abruptly switch their model or bypass original limits. In-process agent teammates running on a different model no longer compact using the lead agent's limit and model, and instead calculate using their own model's context limit, model, and rate. When a finished subagent is woken up and resumed by a message from another subagent, it no longer switches to the sender's model and reasoning effort. It also follows the current session's permission settings, prompting when needed or getting refused when nobody can answer. Subagents launched without a specified model now stay on the model they started on when resumed, even if you later switch the main model with /model.

Catering chefs working across stations each keep cooking at their own stove's heat and follow the kitchen's access rules, even if the head chef changes mid-service or another table comes over to borrow a flame.
BUGFIX

Background Agent Completion and Permission-Wait Reporting Fixes

Handing work off to a background agent only to hear nothing back, or seeing raw system notification strings appear on screen, were both caused by disconnected and jumbled background reporting that is now fixed. Outside auto mode, even if the subagent that launched a background agent finishes on its own without reading the result, the main conversation still receives notice that the background agent is done. In the desktop app, on the web, and in the SDK, if a background agent has been stuck waiting 30 seconds or more on a permission prompt, Claude no longer misreports it as still running. In auto mode, Claude is now notified when a background agent's reply to a follow-up message is dropped, and repeat wake-ups while waiting on background commands are reduced. The desktop app, the web, and VS Code also no longer display raw task notifications directly on screen as a subagent's prompt.

BUGFIX

Keeping Agent Definitions Across Plugin Loads and Resumed Sessions

Custom or plugin-provided agent roles used to vanish out of nowhere whenever plugins loaded, reloaded, or an older session was resumed from the list. Agents passed via --agents no longer disappear after plugins load or reload. Built-in plugin agents are also no longer dropped when resuming a session from the --resume menu. Restarted background subagents and turns that start automatically now wait for all plugins to finish loading before getting to work.

A theater troupe checks off every costume and stagehand from the prop truck before showtime, waiting until everyone is in place before raising the curtain.
FEATURE

Improved Long Subagent Replies, Cloud Progress Summaries, and Related Behaviors

When you hand large tasks to a helper or open terminal sessions on third-party platforms, you will now see fewer cut-off replies and less unnecessary reading of full conversations. When a subagent's reply hits the output token limit twice, it now comes back whole more often, or states up front that it is only a partial result. When a reminder about a completed subagent arrives after compaction, if Claude cannot read its output file, it now messages that subagent directly to ask for the result. In terminal sessions on Amazon Bedrock, Google Vertex AI, and Microsoft Foundry, subagent progress summaries are now generated from short notes. This approach avoids rereading the entire conversation, saving a large number of tokens.

After a long meeting, a secretary can put together a progress summary from a few key sticky notes instead of listening to the whole recording again.
BUGFIX

Fixes for Message Queuing and Blocked Notifications in Cloud and Remote Sessions

When Remote Control, desktop, or cloud sessions were busy, follow-up messages sent from elsewhere could cut into the current turn or appear undelivered; these status reports are now fixed. In Remote Control and Claude Desktop sessions, cross-session messages set to "later" priority now wait for the current turn to finish instead of cutting into the running turn. When sending a message to a cloud or Remote Control session hits a timeout or rate limit, it no longer falsely reports a guaranteed failure with a stale address, and instead tells you the message may have arrived. If a message sent while a cloud session is running gets blocked by a hook like UserPromptSubmit, it now properly reports an error instead of failing silently.

BUGFIX

Fixes for High Cloud Connections and Large Organization List Performance

Accounts with a huge number of cloud sessions or organizations with tens of thousands of connector permission rules used to run into missing list items or sluggish responses; these high-load issues are now fixed. When a program leaves thousands of open connections to a cloud session's network proxy, the session no longer crashes and disconnects. When an account holds many cloud or Remote Control sessions, overly long agent lists no longer show just a handful and hide most entries; they are now sent in pages. For organizations with tens of thousands of connector tool permissions, turns in resumed sessions no longer slow down as a result.

FEATURE

Crash Prevention and Marketplace Removal Prompt Improvements in /plugin

When opening /plugin to pick plugins or manage marketplaces, fast mouse-and-keyboard input used to accidentally install or disable plugins or even crash the window; these UI details are now solid. Clicking with the mouse and then pressing Enter no longer immediately installs or disables a plugin. Typing a rapid burst of keys into the search box no longer triggers a crash either. The confirmation prompt before removing a plugin marketplace now states that its plugins' settings and saved data will be deleted too, and each marketplace page no longer displays another marketplace's error message.

FEATURE

claude plugin eval Preserves Deny Rules and Flags Allowed Calls

When running a command to evaluate whether a plugin is safe, the plugin's own permission hook should not bypass the deny rules you already set. When running claude plugin eval, your own deny rules now take priority over a plugin's permission hook and will not be overridden by it. Any call let through by that hook is also specially flagged in the results.

During a match with a guest referee, the organizer's red lines still come first, and any play the referee waves through gets circled on the scorecard.
BUGFIX

Fixes for Hook Failure Display and Focus View Waiting

When hooks are set up to check status or wrap up automatically, errors sometimes failed to appear on screen or kept a finished reply hidden; these fixes restore normal reporting across hooks. SubagentStop in background agents, SessionEnd at /clear and /resume, and CwdChanged and FileChanged in fullscreen now display messages normally instead of staying blank when they fail. When a Stop hook fails to run at all, it is no longer mistakenly shown as having reported a problem. While waiting for a Stop hook to finish in focus view, an already completed reply is no longer kept hidden. When a mod adds extra context to a tool call, long managed PostToolUse hook output is no longer fed to Claude twice. The /hooks help page also no longer lists input field names that do not exist.

FEATURE

Tighter Artifact Approval Thresholds and Disablement Controls

Your team requires every new Artifact (a standalone page or creation generated by Claude) to be approved first. This release tightens approval rules for plugins, unattended sessions, and disabled features. In organizations that require per-item approval for new Artifacts, an Artifact created or allowed solely by a plugin may now be refused. If nobody is present in the session to respond to a confirmation, it skips the prompt and refuses right away. Once settings turn Artifacts off, even already-running sessions immediately refuse Artifact tool calls. When publishing an Artifact brings up a confirmation prompt, the "don't ask again" option is no longer offered inside subagents or right after a background task result, someone else's message, or a compaction.

Suppose a school voids a substitute teacher's pre-stamped permission slips: if nobody is in the classroom or the principal halts the activity, classes already underway must stop at once.
BUGFIX

Fixes for Artifact Publish Refusals and List Loading

Publishing used to fail even after approval, and opening /artifacts could show no items when many existed; these approval and loading bugs are now fixed. If a synced folder or remote-backed directory only changed a file's timestamp, publishing no longer misreads it and throws "the source file changed between approval and publish". In organizations that require per-item approval for new Artifacts, a new Artifact you approved in a cloud scheduled task session is no longer refused. New Artifacts approved by an app built on the Agent SDK are no longer refused either. When /artifacts failed to fetch more of the list from the server, it used to show a partial list or mistakenly print "No artifacts yet". It now retries automatically once and only shows a warning if the full list still cannot load.

FEATURE

Improved Uploaded File Reading and Parameter Handling in the Artifact Tool

Asking the Artifact tool to read a file uploaded through the UI used to fail over path formatting or extra parameters. The Artifact tool can now read uploaded files directly using the address shown on the artifact's page. Other forms still fail, most with a message saying to read uploads one per call by id. On some calls that do not use prompt, limit, and label, the tool now ignores those parameters instead of failing outright.

Picking up a parcel works the same way: enter the pickup code printed on the slip to get your package, and filling in a few unused note boxes will not get the whole form rejected.
BUGFIX

Fixes for File and Notebook Tools and Search Paging

Having Claude read or write files, edit Jupyter notebooks, or page through code searches used to hit edge cases that threw false errors or broke formatting; this batch of updates fixes them all. For unchanged files outside the project that Claude has already read in full, the Edit tool no longer falsely reports "File has not been read yet" and refuses edits after compaction. When paging with Grep using head_limit and offset, content and count results are now sorted by file path, preventing duplicates and skipped pages. Read no longer fails on Jupyter notebooks containing an output of an unknown type. When a file is 10 MB or larger and too big to read at once, it no longer misreports the size as 512KB and reports the real size instead. NotebookEdit also no longer strips the final newline from notebook files.

FEATURE

Improved Bash Diff Display and Deep Path Check Speed

Checking changed file diffs after a command, or running deep path checks and secret masking on very long text, is now faster and lists filenames more completely. When the Bash tool shows diffs of changed files, it now clearly lists the filenames even for files that are binary, too large, or too many to expand. In auto and bypass permissions modes, the Bash diff of changed files is ready sooner. On macOS and Linux, Bash permission checks are faster on deeply nested missing paths, and secret masking on very long text with a URL is also faster.

FEATURE

Tool Improvements for Long URLs, Mass Mentions, and Stalls

Pasting thousands of tags at once, packing a message with file mentions, or rejecting a write to a huge file used to leave the chat frozen, and those bottlenecks are now cleared. Compaction replies no longer stall on thousands of unclosed tags. WebFetch now refuses URLs over 2,000 characters before any permission prompt. When a message contains thousands of @ mentions, only the first 100 are now looked up as files, preventing stalls before Claude replies. After rejecting a write to a very large file, the screen now shows a short preview instead of freezing the prompt. Reading large PNG images is also faster, and the JPEG sent in their place has clearer quality.

BUGFIX

Fix Reading Nonexistent Spec Files When Starting Design Work

When you ask Claude to start a deck or design, it used to try reading design system spec files at the start that do not exist. This issue is fixed, so it no longer reads those nonexistent files.

FEATURE

Faster Startup and PowerShell Execution on Windows

Opening Claude Code or running PowerShell commands on Windows is now faster from startup discovery through every execution. If Git Bash is missing and pwsh is not on PATH, startup now checks PowerShell's standard install locations all at once to launch faster. The powershell.exe in System32 also takes priority over one earlier on PATH. When PATH points to Git for Windows' bin folder, git.exe starts directly instead of going through its launcher. The PowerShell tool also saves up to about half a second per command on average.

Heading out in the morning no longer means rummaging through every room for your ID when you can spot it on the entryway wall and grab it right away, making even closing the door behind you brisker.
PERF

Faster First Bash Command with Opt-Out Environment Variable

Running the first Bash command in a session often feels slow while waiting for shell start-up files to load. To speed up that first command, shell start-up files may now run before the command is approved, and they have already executed even if the command is later refused. If your shell start-up files perform sensitive actions and you do not want them running early, set the CLAUDE_CODE_DISABLE_SHELL_HEAD_START=1 environment variable to turn off this speedup.

In a kitchen, a chef turns on the stove to preheat the soup base before you even confirm whether to add spice, and if your broth holds pricey herbs you do not want cooked early, a quick note stops it.
BUGFIX

Transcript Search Covers Edits and Fixes Jump Issues

When scrolling back through a long transcript to find text, you can now search inside edited and written file contents as well. Transcript search now matches text in edits and written files, and pressing n or N to move between the next and previous matches no longer skips results. If you open search in a long session with ctrl+o followed by / and cancel midway, the cursor no longer lands far from where you started and instead stays near your original spot.

Index tabs in a thick planner keep you from skipping pages while hunting for a keyword, and closing the book midway still leaves your finger on the same page.
BUGFIX

Fixes for Prompt Input, Pasted Images, and Shell Tab Completion

Several small annoyances that interrupted typing in the prompt, pasting images, or entering commands in shell mode are now fixed. A half-typed ! command no longer submits early on an extra Enter after the usage limit menu, and pasted images are no longer dropped when the prompt starts with a file path like /tmp/a.txt. Moving up and down past short or blank lines now preserves the cursor's column position. Pressing Tab after &&, ;, or | in shell mode no longer fills in a filename where a command belongs. If you rebound the external editor shortcut, question dialogs also no longer still say ctrl+g.

BUGFIX

Key Fixes for Stopping Background Tasks and Closing Menus

Pressing a shortcut to stop a running task or exit a list used to freeze or stop two items by mistake, and those close actions now work accurately. Pressing x twice on a task's details page in /tasks no longer stops the next task as well. Pressing Ctrl+C twice on the browser list screen in /chrome now closes it properly. Pressing Esc after running /autofix-pr no longer locks the keyboard while waiting for the cloud session to stop; the dialog closes immediately. If stopping fails, it reports back afterwards with a link.

FEATURE

Improvements for Slash Menu Duplicates and Cursor Position

Scrolling and selecting items across slash command menus now feels much smoother. Lists that load their rows late no longer occasionally ignore Enter and the arrow keys. When the / menu has skills with the same name, it no longer lists every entry while always running only the first. When you open an MCP tool in /mcp or /plugin and return to the list, the cursor stays in its previous position instead of losing your place. Running /desktop also replaces the y/n download prompt with a standard list selection.

FEATURE

Add to Chat Right-Click Action in VS Code Explorer

When you spot related files in the VS Code sidebar that you want Claude to read together, you used to have to switch back to the input box and type @ to pick them one by one. Now you can select files or folders in the Explorer, right-click, and choose "Claude Code: Add to Chat" to bring them straight into the chat as @ mentions.

Checking off multiple items online and tossing them straight into a cart beats switching tabs to type each product name by hand.
FEATURE

VS Code extension removes unused legacy IDE connection tools

This change is a low-level connection cleanup for developers and users who want to know how the VS Code extension communicates with the editor. Several long-unused legacy tools (including opening files, saving documents, getting the list of open editors, and related features) have been officially removed from the connection between Claude Code and the IDE.

Clearing out a utility truck's trunk by unloading spare parts that sat untouched for years leaves the toolbox much leaner.
FEATURE

VS Code diff views stay open without interruption or stale proposals

When coding in VS Code with both the sidebar chat and the integrated terminal open, the last thing you want while reviewing Claude's file diffs is losing focus or seeing an outdated version. Now, when a terminal session in the same window sends a prompt, any chat edit diff you are viewing stays open and continues waiting for your approval instead of closing abruptly. Additionally, after you type manually in a terminal session's diff view, if Claude edits the same file again, the screen now displays the latest changes rather than mistakenly showing the previous round's proposal.

Two production lines run side by side for blueprint checks, and when a colleague at another desk calls out, your comparison monitor stays lit waiting for your sign-off while newly revised drawings swap in right away.
BUGFIX

VS Code fixes for permission prompts, popups, and Escape key

When a VS Code permission prompt popped up or you pressed Esc to close a small menu, key details used to get cut off, or a single keypress would halt Claude's mid-flight response. When a PreToolUse hook asks for confirmation, the permission prompt now properly displays the reason it provides, and overly long tool or file names are no longer truncated in the prompt title. Pressing Esc to close the feedback dialog, the "Build a custom style" dialog, the @-mention menu, or popups such as the model, mode, and + menus no longer stops Claude's ongoing response at the same time.

FEATURE

VS Code speeds up consecutive edits, search, and startup

When using the VS Code extension in large workspaces or opening a new folder to get started, this release speeds up several steps where waiting used to be noticeable. When Claude makes several edits in a row, queued edits share a single wait for new diagnostic problems, and some issues may be reported together with a later edit. When rg is available on your system PATH, @ file search in large workspaces is faster and ranks results more like the terminal version, though with slightly less tolerance for typos. Except on third-party providers, folders opened for the first time, empty windows, and worktrees now let you open and select from the model picker right away.
