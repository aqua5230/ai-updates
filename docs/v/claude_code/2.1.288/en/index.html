Claude Code 2.1.288

Released: 2026-10-02

Release notes

FEATURE

After Ctrl+C clears the input box, press Up to recover your draft

If you accidentally hit a shortcut mid-typing and wipe out your input, you no longer have to stare at a blank terminal in despair and retype everything.

Just press the Up arrow key in the empty prompt input box, and the draft you just cleared comes back intact. Previously pasted text and attached images return to the input box along with it.

It is like accidentally hitting the clear key on a physical drawing board: one tap of the restore button and the carefully laid-out text and sketches come back, the whole page good as new.
FEATURE

/code-review supports a custom cap on the findings list

Whether you want to see every detail of a full code review at once or just control how many issues get reported, you can now set the limit yourself.

In Claude's interactive interface, type /code-review --max-findings <n> to specify a count, or /code-review --max-findings all to list every issue found. This choice carries over until you type /code-review --max-findings default to restore the default.

Think of telling a professional proofreader how long the report should be: before, you could only receive a fixed length, but now you can specify a number of items or request the full report, and every review afterward is delivered to that standard.
FEATURE

Session list supports shortcut search; press Enter to jump straight to the best match

When you have several background tasks running at once, finding a specific task in the agent overview screen is now much faster.

You can press Ctrl+F to search sessions by name (a session is an independent conversation flow with the AI), and use Alt+↑ or Alt+↓ to jump quickly between groups. These shortcuts, along with the rename function, can all be remapped in keybindings.json. When filtering with n: or searching with Ctrl+F, pressing Enter opens the most relevant session directly, instead of mechanically opening the first row at the top of the list.

Picture a smart catalog machine in a library: type a keyword and press confirm, and the cursor locks onto the book that best matches the topic, without manually flipping through every catalog on the shelf.
FEATURE

Screen reader mode strengthens prompt announcements; permissions list supports number-key selection

When operating the terminal with voice assistance software, several prompts are now clearer.

When you approve an execution plan, the screen reader immediately reads out the new permission mode being applied, and it speaks correctly even when you switch quickly with Shift+Tab. On the /permissions management page, pressing a number key directly selects the corresponding rule, without accidentally triggering the search box. Brief prompts such as word deletion stay on screen until you press any key or the content above changes; questions already answered in a dialog are also clearly marked with the word answered, making it easy to confirm their status. All of these adjustments apply only to screen reader mode.

BUGFIX

Terminal search cursor follows your typing; multiple input and prompt glitches fixed

When digging through history or picking a theme color in full-screen mode, the cursor position now follows your typing in real time.

Previously, when searching text in the full-screen history viewer or customizing colors with /theme, the terminal cursor often stayed frozen in place; now it accurately follows the input position. On Windows, the issue where the keyboard could not type after the software auto-restarted due to first-time gateway login, setting up a service provider, or switching the /tui interface has been resolved. After sending a queued message with ctrl+enter, the interrupt prompt line no longer shows a redundant alternative-action hint.

FEATURE

Conversation history restore is more stable; auto-compact settings saved per model

When continuing the same project across sessions over a long period, conversation records and context are now fully preserved.

Previously, if the last reply reported zero tokens (the unit of text the AI processes and bills), an overlong conversation would immediately throw a prompt-too-long error; now auto-compaction triggers normally. When resuming a session with --resume, fixes cover restored file context going missing, the last reply not being saved so it looked unanswered, and history being truncated because files were overwritten during loading; restoring conversations created by version 2.1.286 or earlier no longer loses the model's prior thinking either. In addition, the /autocompact auto-compact window size is now stored independently per model, and switching models automatically applies that model's own setting.

FEATURE

Auto mode safety classification upgraded; overlong conversations auto-compact first

When letting the AI run a series of commands on its own, the local safety check mechanism is now steadier and more reliable.

When auto mode blocks a non-Bash tool call, it no longer wrongly prompts you to set a Bash permission rule. In the Bedrock and Mantle cloud environments, after auto mode encounters operations that request older models—such as web fetch summarization or a sonnet subagent—the rest of the session no longer falls back to the local classifier. When conversation length exceeds the client safety classifier's checking limit, the conversation history is auto-compacted first, avoiding a confirmation prompt or outright failure on every subsequent tool call; the client classifier also now ignores the lock when ANTHROPIC_DEFAULT_SONNET_MODEL is pinned to Claude Sonnet 5.5 or Opus 5.5, and uses Claude Sonnet 5 instead.

FEATURE

Cloud environments get a built-in GitHub API with automatic pagination for long lists

When running tasks in cloud images that do not have GitHub tooling preinstalled, you can now call the built-in API forwarding directly.

Cloud sessions now ship with the gh api tool built in, and the issue of filenames, filter conditions, or error messages carrying terminal control characters has been fixed. In self-hosted runners, this built-in tool is further enhanced: when a regular gh command is denied, it prints the corresponding gh api syntax directly; the --paginate flag automatically fetches multi-page repository lists in full; and nested claude invocations no longer accidentally remove the built-in tool.

Like carrying a universal adapter on a business trip: even at a venue without the dedicated outlet, you can plug straight into the line and pull down every list in one go without interruption.
BUGFIX

Cowork and cloud sessions fix multiple state sync issues

When collaborating with teammates on cloud tasks across devices, connection state and permission judgments are now more accurate.

Previously in Cowork cloud sessions, if an unapproved web fetch permission prompt sat unanswered for five minutes, the session got stuck in a waiting-for-input state; now, after five minutes without a response, the session no longer keeps showing as waiting for input. When a phone joins a Cowork session started from another device, prompt suggestions now display properly; and for messages sent before a /compact compression, the edit-and-retry function is no longer denied. After a cloud session restarts, if the server rejects the newly selected model, replies no longer continue with that model; on restart, models rejected by the organization-enforced model list are no longer restored either.

BUGFIX

Mod extensions support selected-text detection; full-screen button and crash issues fixed

When building custom interface extensions (mods) for the terminal, you can now precisely capture what the user has highlighted in full-screen mode.

The new $.ui.selection() method returns the last selected text; if the selection falls within a single history row, it also returns that row's data. This release also fixes several interface glitches: clicking a button on a screen drawn before the program restarted no longer triggers another button's action; and when an extension displays custom content above the input box, opening the background-task dialog no longer causes an unrecoverable interface error that crashes the app.

BUGFIX

Plugin installs get automatic HTTPS fallback, and marketplace connection errors are shown in full

Installing plugins on different operating systems or older environments is now more flexible.

On macOS and Linux, if the machine lacks a GitHub SSH key, running claude plugin install for a GitHub-sourced plugin will automatically fall back to the HTTPS protocol when cloning fails and print a notice. Installing subdirectory plugins with older Git versions no longer fails or leaves the cache (previously computed or looked-up results stored for direct reuse) incomplete. When a plugin marketplace fails to fetch over both SSH and HTTPS, the error messages from both attempts are shown, with the transport tried first listed on top. Plugins loaded via --plugin-dir now display their settings options properly in /plugin, and claude plugin test no longer misjudges an extension as disabled because of stale settings.

BUGFIX

Plugin LSP support gains variable substitution, plus timeout protection for stalled requests

Running complex plugins that include a Language Server Protocol (LSP) server or background timers is now significantly more stable.

Plugin LSP settings now correctly substitute ${user_config.*} and ${CLAUDE_PLUGIN_ROOT} with actual setting values or defaults, instead of sending unresolved text variables. When a language server uses dynamic capability registration or stops responding, tool calls automatically time out after 60 seconds instead of hanging forever. For subagents running in a worktree (a Git feature that opens multiple parallel copies of the same project), tool.call hooks no longer cause Bash execution to fail or file searches to read the wrong directory. When these hooks (small programs triggered when specific events occur) fire, they maintain the correct working path. Reloading or disabling a plugin while its timers or read operations are still running no longer forcefully interrupts the background session; if a plugin panel encounters a code diff it cannot parse, it safely falls back to plain-text display.

FEATURE

Stronger safeguards for dangerous delete commands, simpler permission prompts

When running terminal commands that contain scripts or custom variables, safety checks and convenience are now better balanced.

If a bash -c or sh -c script contains a dangerous rm deletion targeting the root or home directory, a confirmation prompt is now forced even in bypass-permissions mode or when an allow rule is configured. Commands involving BASHPID arithmetic assignment also proactively prompt before execution instead of silently passing. In sandbox auto-allow mode, heredoc multi-line input with an unquoted delimiter that contains only plain text and simple variables no longer asks for approval every time. When blocking reads outside the working directory is enabled, credential settings in git config files still take effect normally, and commands that were not fully checked now give a more concise reason in the prompt.

BUGFIX

Rules files now load on edit and file creation, and hook scheduling is stricter

When editing project files in a multi-level directory structure, scoped rules now take effect at more precise moments.

Previously, path-scoped .claude/rules and nested CLAUDE.md files only loaded when a file was read; now they also load immediately for the corresponding scope when files are created or modified through the write or edit tools. The idle_prompt idle-notification hook no longer fires early while a background agent is still running. If a PreToolUse or PermissionRequest hook fails to match or its input cannot be converted to JSON, the tool call is blocked outright for safety; when a subagent loads rules by accessing files, the InstructionsLoaded hook now fills in the agent ID and type information and correctly reports the thinking effort level.

FEATURE

Agent teams support custom tools and parameters, with more accurate cross-session messaging

When dispatching multiple subagents (independent AI assistants that handle specific subtasks) to work together, configuration and message delivery are more transparent.

Agent teams launched by name from a plugin now properly apply their own prompts, tool lists, disallowed tools, and thinking effort levels, instead of falling back to global defaults. When a cross-session message is held by the target session and not delivered, the notification clearly states it was undelivered and names that session; in SDK sessions, the AI can also learn the delivery status in real time mid-turn. The lag when launching an agent with an overly long tool list has been fixed; claude mcp serve correctly reports the available subagent types, and prompt annotations in the interface are precisely labeled as us, the main agent, or you depending on the decision maker.

FEATURE

MCP tool calls support re-authorization, and the web authorization flow is smoother

Connecting to external services through MCP (Model Context Protocol, the protocol that lets AI connect to external tools) is now more stable for authorization and tool calls.

When an MCP server requests additional authorization scopes during a tool call, a re-authorization prompt now appears proactively. For servers that cannot report authorization completion on their own, the interface waits for you to click done before continuing, giving you plenty of time to work in the browser. When a remote server returns a result over 16 MB or one that cannot be parsed, it no longer triggers repeated calls; subagents in the desktop Code tab can now properly use tools from an MCP server named memory; and cloud sessions no longer wait idly on the first turn for stdio servers configured not to load automatically.

FEATURE

Immediate alerts when credential storage fails, and no duplicate verification after wake from sleep

When logging in or rotating cloud keys, status reporting from the credential store (where login proofs are kept) is more accurate.

Previously, running /login would still show success even if the credential could not be written to secure storage; now it honestly reports the failure reason and offers a retry option when the login did not take effect. In a --bare clean session, the ineffective login flow no longer runs, avoiding overwriting saved credentials, and you are told which credentials are available. When a laptop wakes from sleep and a background process is already verifying, a second browser login window no longer pops up; pressing stop while Bedrock is querying credentials now ends the request directly instead of mistakenly switching the session to a fallback model; and for Team and Enterprise plan members with credit requests disabled, /usage-credits also shows a clear explanatory message.

FEATURE

API timeouts support resuming from partial replies, and background command time limits are split by environment

Exception handling is more thorough when running long tasks in automated schedules or headless mode (an execution mode with no terminal window or visual interface).

When the API times out mid-reply, non-interactive sessions and subagents now continue from the partial reply already received, while timeouts during a pure thinking phase are automatically retried. The watchdog mechanism restarts the stream after a long stream breaks and stops retrying after 3 timeouts. The execution time limit for background commands now applies only to unattended sessions (-p, Agent SDK, CI, cloud); terminal, desktop, and VS Code sessions are unrestricted; and the issue where headless mode ignored termination signals while sending SIGCONT to a monitored process has been fixed. In -p, SDK sessions, and PreToolUse hook approvals, telemetry previously showed the source or decision of a blocked tool as unknown; in -p or interrupted turns, unanswered permission prompts failed to log the tool_decision event. Both have been fixed.

FEATURE

Remote Control sessions stay connected during key rotation and avoid mistaken archiving

When managing tasks over long periods with the Remote Control feature, connection stability and session retention have been strengthened.

When a server credential expires, the session stays connected while the credential is being rotated; even if the server fails and retries stop, the original session is properly preserved instead of being cleared. During background cleanup, sessions that are still connected or were just reattached by another process are no longer mistakenly archived.

A guard at the building front desk renewing your badge keeps your access rights even if the window briefly disconnects mid-rotation, and never seals away or destroys the registration records of people still on site.
BUGFIX

Structured outputs can be disabled for compatibility with custom gateways, and long-PDF reading is fixed

Behind Mantle or gateways that reject structured outputs, session titles, memory recall, and prompt hooks (small programs triggered when a prompt arrives) previously failed; you can now disable structured outputs with the CLAUDE_CODE_DISABLE_STRUCTURED_OUTPUTS environment variable.

The issue where Claude 3 Opus and Sonnet errored on every turn after loading a full PDF has been fixed. When the Chrome extension cannot use auto mode, screenshots and reads on approved sites no longer ask repeatedly; typing, navigating, and running JavaScript still prompt. On Team and Enterprise plans or managed machines, creating slides or designs with Artifacts now applies the organization's design system; when the Artifact database reaches its capacity limit, you are told the size limit and how to free up space; and the first request in a fresh environment or after switching models applies the server-configured output limit and compaction window, possibly waiting up to 1.5 seconds.

FEATURE

[VSCode] New-conversation shortcut now scoped to the active view; archiving opens a blank chat

When using the Claude extension interface inside the VS Code editor, tab handling and conversation management are now tidier.

With the new-conversation shortcut enabled, pressing Cmd+N or Ctrl+N now creates a new conversation only in the currently active view, instead of opening a new session in every visible Claude window on screen. After archiving the current conversation in the chat view, the interface cleanly opens a brand-new blank conversation and no longer automatically loads the next saved record. After authorizing a claude.ai connector, if the status remains stuck at needing verification, the MCP server dialog now offers a check-connection option to manually reconfirm the status.

FEATURE

[Cloud sessions] Cloud toggle freed from unrelated settings locks; stopping during startup cancels the queue

When adjusting cloud features in the admin console or managing self-hosted execution nodes, settings and scheduling controls are more responsive.

On the admin settings page, the cloud sessions toggle no longer gets stuck in the off position just because other unrelated security settings are still loading or failed to load. If you press the stop button while a self-hosted runner is starting up, queued messages are now actually canceled, preventing the runner from unexpectedly executing tasks you meant to cancel once it becomes ready.

Canceling a ride before the driver starts the engine simply withdraws the request—the car won't pull up to your door and force the trip anyway.
FEATURE

[Claude Tag] Smarter cross-channel thread tracking; channel setting saves report failures more specifically

When collaborating with the Claude Tag feature in the Slack team messaging app, cross-channel information stays in sync more promptly.

When a task the AI is working on depends on a relevant thread in another channel that Claude had read but wasn't tracking, it now proactively follows that thread, ensuring newly added context reaches the current conversation in time. For channel settings management, channels whose settings were created automatically no longer show a remove-scope option that was guaranteed to fail; when saving on the channel settings page fails, an overly long custom instruction now triggers a clear request to shorten it, and a save rejected due to lost permissions no longer misleadingly suggests retrying.

FEATURE

claude purge command name shortened; package install verification more rigorous

For routine project cleanup or tool version updates, commands are shorter to type and installation checks are stricter.

claude project purge has been renamed to claude purge; the old name still works and prints a rename notice. When auto-updating packages via npm, if the native binary download fails and the system only has a placeholder stub installed, the update process now honestly reports the failure instead of falsely claiming the update succeeded.

Signing for an online order only after confirming the contents are genuine—if all that arrives is an empty display box, delivery is never falsely reported.
