新的 Fable 5.1 模型上場，本機變預設、閘道暫時還給 5

你在 Claude Code 裡選 Fable 這一檔模型時，現在拿到的是新版 Fable 5.1（模型代號 claude-fable-5-1），已接手成 Fable 系列的預設，不必自己指定。它能一次讀進一百萬個 token（AI 一次能納入考量的文字量單位），大專案的程式碼一次丟給它都吞得下。計費每百萬輸入 token 十美元、輸出五十美元；暫存過的內容再讀一次只要每百萬 0.25 美元，反覆追問同一批檔案便宜很多。但有個過渡限制：透過官方閘道（gateway，把請求轉給模型的中間層）跑的工作階段，打 fable 或 best 目前仍落到 Fable 5——閘道還沒設定好會拒收 5.1，要用就在 /model 手動挑。像新款引擎已是門市標配，但合作車行的加油站還沒換供油規格，開進去只能先加舊款的油，除非你指定要新的。

可以自訂時間怎麼顯示，還有用哪個時區

Claude Code 每輪回答結束會標一個時間，逐字稿（transcript，把整段對話存成純文字的紀錄）裡每則訊息也有時間戳記。以前這個格式固定，現在多了兩個設定：timeFormat 決定顯示樣式，可填 12 小時制、24 小時制、24 小時制 UTC，或一段 strftime 格式字串（用 %H:%M 這類代號自己拼時間長相）；timeZone 決定用哪個時區換算。在 settings.json 裡加，例如：

{
  "timeFormat": "24-hour",
  "timeZone": "Asia/Taipei"
}

像把牆上時鐘換成你看得順眼的款式，再撥到自己所在城市的時間。

自動模式收緊三道關卡：雲端憑證、工作目錄外的檔案、別人的產物

自動模式（auto mode，Claude 不逐項問你、直接執行的檔次）下跑一長串工作時，現在多攔三種動作。第一是「Containment Escape」規則：抓雲端主機的中繼資料憑證（metadata-credential，換取存取權的一段資訊）、繞過對外流量限制、或跨租戶讀別人的資源，不再自動放行，除非環境標示為預期行為。第二是第一次讀工作目錄外的檔案時跳一次性提醒，可當場擋掉；要永遠擋就在 settings.json 放 {"permissions": {"blockReadsOutsideWorkingDirectories": true}}。第三是 Cowork／claude.ai 雲端階段裡，讀不屬於你的產物（artifact，對話生成的檔案）一律先問你，自動模式也不例外。像請人代管你家：能自由走動，但翻抽屜找鑰匙、走後門、進鄰居家，得先問過你。

一個環境變數，強制所有子代理都用同一個模型

你請 Claude 分頭跑好幾個子代理（subagent，主對話派出去、各自幹一小塊活的分身）時，每個子代理可能有自己被指定的模型：有的在派出當下指定，有的寫死在代理定義檔裡。想讓它們全部改用某一個模型，以前得一個個翻出來改。現在多了 CLAUDE_CODE_SUBAGENT_MODEL_FORCE 這個環境變數（environment variable，在系統層設定、程式啟動時讀取的參數）。把它打開，CLAUDE_CODE_SUBAGENT_MODEL 指定的模型（沒指定就是主對話用的模型）會套到每一個子代理身上，那些個別指定一律被忽略。適合你想壓成本、或想確保整批任務一致時一次生效。像帶一團人出門，直接宣布今天全部搭同一班車，各自原本訂的車票都作廢。

改推理力度可以只改這次工作階段，不動長期設定

/effort 是調 Claude 想多久再回答的指令——力度高，思考更透徹但慢、也更貴；力度低則相反。以前用它會把設定改成長期的，之後每個工作階段（session，一次從開啟到結束的對話）都跟著變。現在 /effort 選單裡多了一個 s：挑它就只改當前這個工作階段，關掉視窗就回到你原本的預設，跟 /model 早就有的作法一致。另外，換到一個新模型時，它自帶的「預設力度鎖定」現在也只鎖這個工作階段，不再是永久；如果你是透過遠端遙控（Remote Control）從 claude.ai 那邊挑好力度再連進來，那個選擇在鎖定期間會直接生效。像相機的「這張照片先用這個 ISO」，拍完自動跳回你平常設定，不會把總設定覆蓋掉。

透過閘道發現模型時，選單會顯示每個模型的說明

有些公司會讓 Claude Code 透過自家閘道（gateway，把請求轉給模型的中間層）連到一批內部模型，開關是環境變數 CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY。以前這些模型在 /model 選單裡只有名字，看不出差別。現在閘道可以隨每個模型附一段 description，選單就照著顯示；沒附說明的仍寫「From gateway」。搭配的一項調整：這個發現動作即使你設了 CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC（關掉非必要對外連線）也照跑，因為它只問你自己的閘道、不對外。像自助餐檯的菜牌，以前每格只貼菜名，現在多了一行「主廚推薦、微辣」，不想貼的那格就還是空白菜名。

問完插話的問題，回主線的按鍵改了

/btw（by the way 的縮寫）讓你在不打斷主線任務的情況下，臨時問 Claude 一個小問題，問完再回到原本的答案。以前在這些側邊問答之間翻頁用 ←／→，跟其他地方的方向鍵功能容易撞。現在改成 Shift+←／Shift+→，也可以用 [／]，一路翻過你最近幾個插話問題、再翻回正在進行的答案。另外修好一個卡點：在 claude agents（管理子代理的畫面）裡開著 /btw 面板時按 ← 原本沒反應，現在它會帶你回子代理清單，就算問答還沒結束也行；重新打開那個工作階段時，面板會再出現。像看書時夾的臨時便利貼，翻閱便利貼的手勢跟翻正文分開，才不會一滑就跳出正在讀的章節。

`/add-dir` 兩處調整：拒收網路路徑、接受目前目錄底下的資料夾

/add-dir（以及啟動時的 --add-dir、設定裡的 additionalDirectories）用來把額外的資料夾納入 Claude 的工作範圍，連同那個資料夾的 skills、指令、代理一起載入。這版收拾了兩個相反方向的毛病。一是網路路徑：Windows 的 UNC 網路共享、/net/<主機> 這類自動掛載，現在會在真的去碰之前就擋下並說明，Windows 使用者請改用對應到磁碟機代號的路徑。二是就在你目前工作目錄底下的子資料夾，以前 /add-dir 會無理由拒絕，現在會接受，並像啟動時的 --add-dir 一樣載入該資料夾的 skills、指令、代理。像門禁系統，之前把住同一棟樓的鄰居擋在外面、卻對遠端撥進來的陌生連線不設防，現在兩邊都調對了。

專案資料夾裡設 `bypassPermissions` 不再有效

bypassPermissions 是最寬鬆的權限檔次，Claude 幾乎什麼都不問就做。過去只要在專案的 .claude/settings.json 或 .claude/settings.local.json 裡把 defaultMode 設成 "bypassPermissions"，一打開這個專案就進入這個模式。問題是這種檔案常跟著程式碼一起流通，等於任何人送你一份專案就能決定你的機器不設防。現在專案層級的這個值會被忽略，行為跟設 "auto" 一樣。要真的用這個模式，改在使用者層級或受管理設定裡設，或每次啟動時自己加 --permission-mode。像家門鑰匙：可以自己決定要不要不鎖門，但不能讓「別人塞進你信箱的一張紙條」替你決定門不上鎖。

公司統一派下來的設定：更早生效、更會報錯、極端數值會被夾住

公司用受管理設定統一配置 Claude Code 時，這批修那條路上的毛病。policyHelper（核對公司政策的小程式）被開機快取蓋掉，以前要等下次開機才更新，現在伺服器一回報設定移除就立刻改跑或退出。managedSourcesBehavior: "merge" 下，sandbox.credentials.awsPairs、sandbox.ripgrep 現在採最高階來源整份沿用；timeoutMs、refreshIntervalMs 填超過計時器上限（2147483647）也會被夾回合法範圍，不再整個失敗。診斷更清楚：更新失敗顯示在 /status，婉拒對話框印出退出原因，逾時明講成逾時；核准對話框在設定同時動追蹤或匯出時也顯示對應措辭。像公司發的制式表單，以前欄位互蓋、填錯不說原因；現在改成填錯即時提示、超範圍自動修正、退件附理由。

接雲端供應商時，多送出去的憑證與殘留身分都清乾淨了

透過 Bedrock、Vertex、Foundry 跑 Claude Code，這批修的是請求裡夾帶不該夾的登入資訊。重複列了兩次的自訂 Authorization 標頭曾蓋掉你的憑證（Bedrock、Mantle、Vertex、WIF 都中招）、Vertex 精靈撿到殘留舊設定檔、官方閘道把多餘標頭送給 Foundry／Vertex／Bedrock 且 Foundry Entra ID 上游啟動失敗、API 金鑰模式下殘留 Anthropic 金鑰跟著多送——都不再發生，閘道登入與 token 更新也開始驗證固定 TLS 憑證。另外，工作階段過期後重開會說「已結束」並給 /login；免金鑰的 Console 登入也會套用組織設定、/status 顯示所屬組織。像出國轉機，行李箱混進別人的證件，海關每關被卡；現在託運前先清一遍，只留當次要用的證件。

權限確認框這一批：少了一行舊提示、對付得了幾種混淆寫法

這組都跟「Claude 要不要停下來問你」有關。介面上，權限確認框底下的 Ctrl+E 指令說明拿掉了；Edit（改檔）確認框的差異檢視，以前把 emoji 等多碼字元寬度算錯、排版會歪，現在對齊了。真正重要的是三個漏洞收口：permissions.ask（要求先問過的規則）若指令包在複合指令或子殼層裡跑，以前會被自動模式跳過不問，現在照攔；某些 [[ ]] 條件 zsh 跟 bash 解讀不同，以前自動放行，現在跳確認；Bash 的 Read／Edit 拒絕規則，以前對 < 檔案 重新導向、tac、egrep 這類讀檔指令不生效，現在命中任一參數或導向目標就整條拒絕。像機場安檢，之前拆開包裝、藏進夾層、換個名字報就能過，現在這幾種繞法都補上了。

背景工作階段開不起來的幾種情形，這版都堵上

背景工作階段（background session，丟給 Claude 在後台跑的任務）這批修「根本啟動不了」的幾種情形。macOS 上用 npm 安裝、碰上 Claude Code 自我更新時，背景工作階段會開不起來；Windows 上過期的 daemon（常駐服務程式）鎖檔指向被重用行程編號，也一樣。另一種是另一個行程正在下載更新，開背景工作階段會直接報「Couldn't start the background service」，現在會等下載完再啟動。還有兩個收拾殘局的：更新後仍跑舊版執行檔的背景工作階段以前會堆著不退場，現在會被汰換；cc-daemon-* 這種啟動中斷留下的暫存資料夾，現在會被 cleanupPeriodDays 保留期一併掃掉。像早班公車卡在總站：鑰匙孔卡住、排班紀錄沒清、加油站沒開門，這幾個原因一次排除，空車也拖回停車場。

背景工作階段的清單顯示，這批修對了幾個記錯的地方

這批修 claude agents（管理背景工作階段的畫面）跟指令列「記錯狀態」的幾個地方。state.json 的 detail 欄位被排程喚醒後會重複原本派工指令，不更新。重新對已完成的背景工作階段追問後，理應回清單前面，卻卡在「Completed」舊位置，現在照最新完成時間排序。從已刪掉的目錄打 claude --bg，以前謊報成功、留下壞紀錄，現在印出失敗原因並以結束碼 1 收場。--resume 把背景對話列兩次，--continue 打開的是背景化前卡住的舊副本；現在 --continue 也能打開跑完的背景工作階段，claude --resume <session-id> --bg 在沒人跑那個工作階段時會接續原編號，真要另起副本才明講。像旅館房間看板，退房了還顯示住客名字、同一人登記成兩間房；這次把看板跟房卡實際狀態對齊。

背景工作階段對停止與通知的反應，這批修得更誠實

背景工作階段被中斷時，這批讓狀態如實反映。Ctrl+S 在開啟的背景工作階段暫存提示，閒置或停止後重開以前會不見，現在保得住。用 ← 或 Ctrl+B 把任務丟到背景時，子代理或工具正跑，曾誤判工具被拒絕；現在會正確重跑。從任務面板或用戶端停止背景指令時，以前 Claude 不會被告知，現在會。停止背景子代理時，它的監控（monitor，代替你盯著某件事、完成或逾時就通知）以前會繼續跑，現在會停掉。用 timeout 或 setsid 把背景指令和 shell 脫鉤時，停止任務或結束 Claude Code 後它以前仍會跑，現在也會結束。另外，claude agents 以前不會說「有背景工作階段在等你核准另一階段傳來的訊息」也不說是誰傳的，現在會清楚顯示。像請人代班顧店，按了下班鈴代班的人卻沒收到訊號；這批修完，鈴聲、代班狀態、跟手上紀錄終於對得上。

`claude agents` 畫面與子代理逐字稿，這批修的是「看得到、跟得上」

這批修 claude agents（管理子代理畫面）跟逐字稿的可用性。用 ← 開子代理工作階段，以前沿用原權限模式、蓋掉目標 defaultMode 與 permissionMode，現在照目標走；Ctrl+G 重新綁定以前不生效，Ctrl+S、Ctrl+T 現在可透過新 Agents 情境重綁。切到另一子代理逐字稿，用量計數器常凍住，現在即時更新；claude agents --json 以前會短暫切終端機成 raw 模式、退出蓋掉別程式設定，現在不會。子代理被睡眠、斷線或伺服器錯誤打斷，以前停在半截，現在自動接完；重新接續已停掉的子代理，主對話以前不被告知，現在會；逐字稿超 5MB 的子代理恢復或傳訊，以前報「No transcript found」，現在正常。像盯著幾支監視器的保全室：畫面卡格、按鍵對不上、錄影錄到一半當機，這批一次修順。

五種讓提示快取失效的情形，這批一次修掉

提示快取（prompt cache，記住送過的內容、下次不重算不重收費）本是省錢機制，這批修幾個讓它悄悄失效的漏洞。遠端遙控在工作階段進行到一半才連上時，會重送一次 Bash 工具定義，光這樣就讓快取失效，現在不會。設了顧問模型（advisor model，輔助主模型判斷的模型）的工作階段，背景請求以前吃不到快取、每次重送整段對話，現在能命中；背景請求指壓縮對話、/recap 這類動作。對話倒帶回空白後，/model 跟 /effort 以前會多顯示一則快取警告，現在不會。長時間夾大量截圖的工作階段，圖片超單次請求上限後每輪快取失誤，這問題已修。/fork（把對話另開一份背景工作階段）現在會把原本快取保留到新階段，做法是把工作樹簡報改成訊息帶過去，不動系統提示本身。像影印店的收據存根，留著本該省時間，這幾個環節卻讓存根每次被撕掉重印，現在一一補回去。

遠端遙控的兩個信任漏洞補上了

遠端遙控（Remote Control，讓你從手機或另一台裝置連進正在跑的 Claude Code）這批修的是「同意」跟「聽誰的」出錯的地方。以前不管是按 Esc、還是在 claude remote-control 選單裡按 n，用意都是拒絕連線，卻被系統當成「已經同意」記下來，導致下一次請求直接連上、不再問你。這次修好，真的按了拒絕才算數。另一個是從 Claude app 發起的遠端遙控工作階段，以前會忽略你在 app 裡選好的模型，逕自用這台機器的預設模型跑，現在會照你選的模型執行。像門口的對講機，你明明按了「不開」，系統卻記成「已放行」，下次陌生人直接推門進來；這次改成按下拒絕才是真的拒絕。

MCP 連線這批：該擋的擋住、該清的清乾淨、錯誤訊息看得懂了

MCP（Model Context Protocol，讓 Claude 連外部工具的協定）這批修連線與紀錄。/mcp 重新連線或啟用時，現在會擋住啟動後才被允許／拒絕清單或 strictPluginOnlyCustomization 禁用的設定檔伺服器。受此設定限制時，claude mcp remove 會連同遠端伺服器的 OAuth 憑證清掉。claude mcp add/remove 遇到 .mcp.json 是 FIFO 或裝置檔符號連結，現在會快速失敗並說明原因，不再卡住或吃光記憶體。WebSocket 失敗會顯示真正錯誤，不再只印「[object ErrorEvent]」；連線與 OAuth 紀錄也會遮蔽網址或標頭的憑證。像大樓門禁，名單、鑰匙、監視畫面以前各有漏洞，現在都對齊了。

沙盒與工作樹的邊界，這批修的是「不該過去的路」跟「該提醒的殘留」

When you pick the Fable model in Claude Code, you now get the new Fable 5.1 (model id claude-fable-5-1), which has taken over as the default for the Fable line. Choose how times are shown, and in which time zone

Claude Code stamps a time at the end of every turn, and each message in the transcript — the plain-text record of the whole conversation — carries a timestamp too. That format used to be fixed. Now there are two settings: timeFormat sets the style and accepts 12-hour, 24-hour, 24-hour UTC, or an strftime pattern (codes like %H:%M that let you spell out the shape of the time yourself); timeZone sets which zone the clock is converted to. Add them in settings.json, for example:

{
  "timeFormat": "24-hour",
  "timeZone": "America/New_York"
}

It is like swapping the wall clock for a face you find easy to read, then setting it to the time in your own city.

Auto mode tightens three gates: cloud credentials, files outside your working directories, other people's artifacts

When you let Claude run a long stretch of work in auto mode — where it acts without checking each step with you — it now holds back three more kinds of action. First, a Containment Escape rule: fetching a cloud host's metadata credentials (a piece of information a cloud platform hands out in exchange for access), slipping past outbound-traffic limits, or reaching across tenants to read someone else's resources are no longer auto-approved unless your environment marks them as expected. Second, a one-time prompt the first time it wants to read a file outside your working directories; block it on the spot, or for good with {"permissions": {"blockReadsOutsideWorkingDirectories": true}} in settings.json. Third, in Cowork and claude.ai cloud sessions, reading an artifact (a file produced by a conversation) that is not yours now always asks you first, even in auto mode. It is like asking someone to house-sit: they move around the rooms freely, but rummaging in drawers for keys, using the back door, or stepping into the neighbour's place are things they check with you first.

One environment variable forces every subagent onto the same model

When you have Claude fan out across several subagents — the helpers the main conversation dispatches to each do a slice of the work — each one may carry its own assigned model: some set at dispatch time, some hard-coded in an agent definition file. Switching them all to one model used to mean hunting each down. Now there is an environment variable, CLAUDE_CODE_SUBAGENT_MODEL_FORCE — a setting made at the system level and read when the program starts. Turn it on and the model named by CLAUDE_CODE_SUBAGENT_MODEL (or the main conversation's model if none is named) applies to every subagent, and those per-subagent choices are all ignored. Handy when you want to hold costs down, or keep a whole batch of work consistent, in one move. It is like taking a group out for the day and announcing everyone rides the same bus — the tickets people booked separately no longer count.

Change effort for just this session, leaving your long-term setting alone

/effort tunes how long Claude thinks before answering — higher effort means deeper reasoning but slower and pricier; lower is the reverse. Using it used to change the setting for the long term, so every later session (one conversation from open to close) inherited it. Now the /effort menu has an s option: pick it and only the current session changes, and closing the window returns you to your own default — matching what /model has done for a while. Separately, when you move to a new model, the default-effort hold it ships with now locks only this session rather than permanently; and if you connected via Remote Control after picking an effort on claude.ai, that choice now applies during the hold. 自动模式收紧三道关卡：云端凭证、工作目录外的文件、别人的产物

你在自动模式（auto mode，Claude 不逐项问你、直接执行的档次）下让它跑一长串工作时，现在会多拦三种动作。第一是“Containment Escape”规则：去抓云端主机的元数据凭证（metadata-credential，云平台用来换取访问权的一段信息）、绕过对外流量限制、或跨租户读别人的资源，这些不再自动放行，除非你的环境明确标示为预期行为。第二是第一次要读工作目录以外的文件时跳一次性提醒，可当场挡掉；要永远挡就在 settings.json 放 {"permissions": {"blockReadsOutsideWorkingDirectories": true}}。第三是在 Cowork 与 claude.ai 云端会话里，读取不属于你的产物（artifact，对话生成的文件）一律先问过你，即使在自动模式也一样。像请人代管你家：屋里能自由走动，但翻抽屉找钥匙、走后门、进邻居家这几件事，得先问过你一声。

一个环境变量，强制所有子代理都用同一个模型

你请 Claude 分头跑好几个子代理（subagent，主对话派出去、各自干一小块活的分身）时，每个子代理可能有自己被指定的模型：有的在派出当下指定，有的写死在代理定义文件里。想让它们全部改用某一个模型，以前得一个个翻出来改。现在多了 CLAUDE_CODE_SUBAGENT_MODEL_FORCE 这个环境变量（environment variable，在系统层设置、程序启动时读取的参数）。把它打开，CLAUDE_CODE_SUBAGENT_MODEL 指定的模型（没指定就是主对话用的模型）会套到每一个子代理身上，那些个别指定一律被忽略。适合你想压成本、或想确保整批任务一致时一次生效。像带一团人出门，直接宣布今天全部搭同一班车，各自原本订的车票都作废。

改推理力度可以只改这次会话，不动长期设置

/effort 是调 Claude 想多久再回答的指令——力度高，思考更透彻但慢、也更贵；力度低则相反。以前用它会把设置改成长期的，之后每个会话（session，一次从打开到结束的对话）都跟着变。现在 /effort 菜单里多了一个 s：挑它就只改当前这个会话，关掉窗口就回到你原本的默认，跟 /model 早就有的做法一致。另外，换到一个新模型时，它自带的“默认力度锁定”现在也只锁这个会话，不再是永久；如果你是通过远程遥控（Remote Control）从 claude.ai 那边挑好力度再连进来，那个选择在锁定期间会直接生效。像相机的“这张照片先用这个 ISO”，拍完自动跳回你平常设置，不会把总设置覆盖掉。

通过网关发现模型时，菜单会显示每个模型的说明

有些公司会让 Claude Code 通过自家网关（gateway，把请求转给模型的中间层）连到一批内部模型，开关是环境变量 CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY。以前这些模型在 /model 菜单里只有名字，看不出差别。现在网关可以随每个模型附一段 description，菜单就照着显示；没附说明的仍写“From gateway”。配套的一项调整：这个发现动作即使你设了 CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC（关掉非必要对外连接）也照跑，因为它只问你自己的网关、不对外。像自助餐台的菜牌，以前每格只贴菜名，现在多了一行“主厨推荐、微辣”，不想贴的那格就还是空白菜名。

问完插话的问题，回主线的按键改了

/btw（by the way 的缩写）让你在不打断主线任务的情况下，临时问 Claude 一个小问题，问完再回到原本的答案。以前在这些侧边问答之间翻页用 ←／→，跟其他地方的方向键功能容易撞。现在改成 Shift+←／Shift+→，也可以用 [／]，一路翻过你最近几个插话问题、再翻回正在进行的答案。另外修好一个卡点：在 claude agents（管理子代理的界面）里开着 /btw 面板时按 ← 原本没反应，现在它会带你回子代理列表，就算问答还没结束也行；重新打开那个会话时，面板会再出现。像看书时夹的临时便利贴，翻阅便利贴的手势跟翻正文分开，才不会一滑就跳出正在读的章节。

`/add-dir` 两处调整：拒收网络路径、接受当前目录底下的文件夹

/add-dir（以及启动时的 --add-dir、设置里的 additionalDirectories）用来把额外的文件夹纳入 Claude 的工作范围，连同那个文件夹的 skills、命令、代理一起载入。这版收拾了两个相反方向的毛病。一是网络路径：Windows 的 UNC 网络共享、/net/<主机> 这类自动挂载，现在会在真的去碰之前就挡下并说明，Windows 用户请改用映射到盘符的路径。二是就在你当前工作目录底下的子文件夹，以前 /add-dir 会无理由拒绝，现在会接受，并像启动时的 --add-dir 一样载入该文件夹的 skills、命令、代理。像门禁系统，之前把住同一栋楼的邻居挡在外面、却对远端拨进来的陌生连接不设防，现在两边都调对了。

如果你的 Claude Code 由公司通过受管理设置统一配置，这批修的是那条路上的毛病。policyHelper（核对公司政策的小程序）被开机当下的缓存设置盖掉时，以前要等下次开机才更新，现在服务器一回报设置已移除就立刻改跑或退出。managedSourcesBehavior: "merge" 下，sandbox.credentials.awsPairs 与 sandbox.ripgrep 现在整份采用设得最高阶的来源，不再搅在一起；timeoutMs、refreshIntervalMs 填超过计时器上限（2147483647）也不再整个失败，会被夹回合法范围。诊断更清楚：更新失败显示在 /status，婉拒对话框会打印出退出原因，超时明讲成超时；核准对话框在设置同时关掉追踪、关掉原始 API 记录、或开启追踪导出时，也会显示对应的遥测措辞。像公司发的制式表单，以前字段互盖、填错不说原因；现在改成填错即时提示、超范围自动修正、退件附理由。

通过 Bedrock、Vertex、Foundry 这些云端供应商跑 Claude Code，这批修的是“送出的请求夹了不该夹的登录信息”。重复列了两次的自定义 Authorization 头会盖掉你设好的凭证（Bedrock、Mantle、Vertex、WIF 都中招）；Vertex 设置向导会捡到 ~/.config/anthropic 残留的旧配置文件；官方网关会把多余标头送给 Foundry、Vertex、Bedrock，ANTHROPIC_FOUNDRY_API_KEY 设置时 Foundry 的 Entra ID 上游还会启动失败；API 密钥模式接 Foundry 订阅密钥时，旁边会多送一把残留的 Anthropic 密钥。以上都不再发生，网关登录与 token 刷新也开始验证固定 TLS 证书。另外，会话过期后重开会直接说“已结束”并给 /login；免密钥的 Console 登录现在会套用组织设置、/status 显示所属组织。像出国转机，行李箱混进别人的证件，海关每关被卡；现在托运前先清一遍，只留当次要用的证件。

后台会话开不起来的几种情形，这版都堵上

后台会话（background session，你丢给 Claude 在后台自己跑、不占用当前界面的任务）这一批修的是“根本启动不了”的几种情形。在 macOS 上用 npm 安装、刚好碰上 Claude Code 自我更新时，后台会话会开不起来；Windows 上若有一份过期的 daemon 锁文件（daemon，常驻在后台的服务程序）指向一个被重用的进程号，也一样。另一种是另一个 Claude Code 进程正在下载 npm 更新，这时开后台会话会直接报“Couldn't start the background service”，现在会等它下载完再启动。还有两个收拾残局的：自我更新后，仍在跑旧版 Claude Code 可执行文件的后台会话以前会一直堆着不退场，现在会被汰换；后台 daemon 启动被中断后留在系统临时目录的 cc-daemon-* 文件夹，现在会被 cleanupPeriodDays 的保留期清扫一并扫掉。像早班公交卡在总站发不了车：有时是钥匙孔卡住、有时是上一班的排班记录没清、有时是加油站还没开门，这几个原因一次排除，顺便把没开走的空车拖回停车场。

后台会话的列表显示，这批修对了几个记错的地方

这一批修的是 claude agents（管理后台会话的界面）跟命令行在“记住哪个会话是什么状态”上出的错。会话的 state.json 里 detail 字段，被计划唤醒后会一直重复自己原本的派工提示，不会更新成新状态。你重新对一个已完成的后台会话追加提问后，它理应回到列表前面，却一直卡在“Completed”列表里旧的位置，现在 Completed 会按最新完成时间排序。刚从一个被删掉的目录打 claude --bg，以前会谎报“backgrounded”成功、留下一条坏掉的会话记录，现在会打印失败原因并以结束码 1 收场。--resume 会把一个后台中的对话列两次，--continue 则会打开它卡住的、后台化之前那份旧副本；现在 --continue 也能打开已经跑完的后台会话。另外，claude --resume <session-id> --bg 在没人在跑那个会话时，现在会接续原本的编号继续，而不是悄悄另起一份副本；真的要另起副本时会明说。像旅馆的房间看板，退房了还显示住客名字、换房了牌子没跟着换、甚至同一个人被登记成两间房，这次把看板重新对过一轮，跟房卡实际状态一致。

后台会话对停止与通知的反应，这批修得更诚实

这批修的是后台会话在被中断或被观察时，状态没有如实反映。用 Ctrl+S 在一个已打开的后台会话里暂存一个提示，若那个阶段空闲或被停止后再重开，暂存的内容以前会不见，现在保得住。用 ← 或 Ctrl+B 把某一轮任务丢到后台时，若当下正好有子代理或其他工具在跑，偶尔会让后台会话误判那个工具被拒绝，其实它该重跑；现在会正确重跑。从任务面板或连接的客户端停止一个后台命令时，以前 Claude 不会被告知，现在会。停止一个后台中的子代理时，它启动的监控（monitor，代替你盯着某件事、完成或超时就通知的后台任务）以前会留着继续跑，现在会一起停掉。用 timeout 或 setsid 让后台命令脱离 shell 后，以前停止任务或退出 Claude Code，它仍会继续跑，现在也会一起结束。另外，claude agents 以前不会告诉你“有后台会话在等你核准另一个会话传来的消息”，也不会说是谁传的，现在会清楚显示。像请人代班顾店，你按了下班铃，代班的人却没收到信号、继续开着收银机；这批修完，铃声、代班状态、跟你手上那份记录终于对得上。

`claude agents` 界面与子代理逐字稿，这批修的是“看得到、跟得上”

这批围绕 claude agents（管理子代理的界面）跟子代理逐字稿的可用性。从这个界面用 ← 打开一个子代理的会话时，以前一律沿用原本会话的权限模式，盖掉目标目录自己的 defaultMode 与那个代理定义的 permissionMode，现在会照目标的设置走。keybindings.json 里对 Ctrl+G 的重新绑定，在 claude agents 里以前不生效；它的 Ctrl+S、Ctrl+T 现在则可以通过新的 Agents 情境重新绑定。切换到另一个子代理的逐字稿时，右上角的用量计数器常常冻住不动或跑得很慢，现在会即时更新，后台子代理与队友的计数器也是。claude agents --json 以前会短暂把终端切成 raw 模式，退出时把别的程序设好的终端设置盖掉，现在不会。子代理若因为电脑睡眠、断线或服务器错误而在流式响应中被硬生生打断，以前就停在那个不完整的回应，现在会自动接着讲完。你从逐字稿界面把一个子代理停掉、之后又让它继续，主对话以前不会被告知你做了这件事，现在会。逐字稿长超过 5MB（常见于读了很多图片之后）的子代理，恢复或传消息给它以前会报“No transcript found”失败，现在正常。像盯着好几支监控画面的保安室：切换画面会卡格、遥控器按键对不上想按的那支、有支摄像头录到一半死机没接着录——这批把整间保安室的画面、按键、录影都修顺了。

五种让提示缓存失效的情形，这批一次修掉

提示缓存（prompt cache，把送过一次的对话内容记住，下次同样内容不用重新算、也不用重新收费）本来就是省时间跟省钱的机制，这批修的是几个让它悄悄失效的漏洞。远程遥控（Remote Control）在会话进行到一半才连上时，会重新送一次 Bash 工具的定义，光这样就让缓存失效；现在不会。设了顾问模型（advisor model，辅助主模型判断的模型）的会话，后台请求以前吃不到缓存、每次重送整段对话，现在能命中；后台请求指压缩对话、/recap 这类动作。把对话倒带回空白状态后，/model 跟 /effort 会多显示一则缓存警告，现在不会。长时间夹杂大量截图的会话，一旦图片超过单次请求的大小上限，之后每一轮都会缓存失误，这个上限问题已修。/fork（把当前对话另开一份后台会话接着跑）现在会把原本对话的缓存保留到新的后台会话里，做法是把工作树简报改成消息带过去，而不是动系统提示本身。像影印店的收据存根，本来留着就能直接核对省时间，这几个环节却让存根每次都被撕掉重印，现在把撕掉的环节一一补回去。

远程遥控的两个信任漏洞补上了

远程遥控（Remote Control，让你从手机或另一台设备连进正在跑的 Claude Code）这批修的是“同意”跟“听谁的”出错的地方。以前不管是按 Esc、还是在 claude remote-control 菜单里按 n，用意都是拒绝连接，却被系统当成“已经同意”记下来，导致下一次请求直接连上、不再问你。这次修好，真的按了拒绝才算数。另一个是从 Claude app 发起的远程遥控会话，以前会忽略你在 app 里选好的模型，径自用这台机器的默认模型跑，现在会照你选的模型执行。像门口的对讲机，你明明按了“不开”，系统却记成“已放行”，下次陌生人直接推门进来；这次改成按下拒绝才是真的拒绝。

MCP 连接这批：该挡的挡住、该清的清干净、错误信息看得懂了

MCP（Model Context Protocol，让 Claude 连接外部工具的协议）这批修的是连接管理跟错误信息。/mcp 的重新连接与启用功能，以前仍会连上一个在启动后才被受管理的 MCP 允许／拒绝列表、或 strictPluginOnlyCustomization（限定只能用插件提供的 MCP 服务器）挡下的配置文件服务器，现在会照挡。strictPluginOnlyCustomization 锁定“MCP 只能用插件提供”时，claude mcp remove 移除一个远程服务器后，以前会留下它存的 OAuth 凭证没清掉，现在会一并清除。claude mcp add/remove 遇到项目的 .mcp.json 其实是一个 FIFO（先进先出的命名管道文件）或设备文件的符号链接时，以前会卡住或吃光内存，现在会快速失败并给出可行动的错误信息。WebSocket 型 MCP 服务器连接失败时，日志以前只会打一句看不懂的“[object ErrorEvent]”，现在会打出底层真正的错误。另外，MCP 连接与 OAuth 的调试／错误日志，以前可能把服务器网址或请求头里夹带的凭证原样打出来，现在会遮蔽掉。像大楼的门禁登记簿，以前访客名单更新了保安却没跟上、退租的人钥匙没收回、监控画面糊成一片还看不清楚，这次名单、钥匙、画面都对齐了。

沙盒与工作树的边界，这批修的是“不该过去的路”跟“该提醒的残留”

沙盒（sandbox，把 Claude 动作限制在安全范围内的隔离环境）与工作树这批，修的是边界没守住、或残留没被发现的地方。网络主机名结尾多打一个点时，deniedDomains 以前挡不住这个 host，“不要再问”也一直重复跳出，现在能正确挡下。插件声明的组件路径如果是指向外部的符号链接，以前能借此读到外面的文件，现在会被拒绝并报错。工作树隔离的会话，以前把不碰 git 的 Bash 循环、$VAR 读取、heredoc 都当成太复杂而拒绝，现在能正确放行；cd 进链接工作树的子目录后，对共用 .git 目录的写入权限以前会不见，现在不会。另外，/doctor 现在会提醒你，被强制结束的会话留下的沙盒遮罩文件还在。像小区围栏：有个没堵住的缝、外卖员能溜进邻户阳台、保安偶尔认错人，这批把缝补上、侧门锁好，还留了张纸条提醒你忘记收走的旧钥匙。

设置重新加载这几个环节，以前会漏掉或忘记已经变了

这批修的是 Claude Code “重新读设置”这件事没做彻底的几个地方。项目里如果是启动之后才创建的 .claude/ 文件夹，里面的设置以前要等重启才会被读到，现在启动后创建也能生效。allowManagedPermissionRulesOnly（只允许受管理规则生效）打开时，第一次设置重新加载后，--disallowedTools 跟会话层级的拒绝规则以前会被连带清掉，现在会保留。另外，遥测（telemetry，回报使用状况的机制，这里指 OTEL）通过受管理设置推送下来的值，热启动时以前会被忽略，桌面版 App 开的 Code 会话也中招，现在都会生效。热启动指沿用既有进程、不是整个重开机的启动方式。像换了新规定却没通知轮班的第二班警卫：有的门忘记解锁、有的旧规定该撤没撤、广播系统选择性失聪，这批把交接记录补齐了。

终端画面这一批：跑起来更顺、几个卡格的地方修好了

无头模式与长时间流式这批：不再提早挂断、不再闷着头空转

这批修的是无头模式（headless，没有终端窗口、常见于脚本或 CI 环境）跟长时间流式连接里“该等却没等”或“该停却不停”的情形。claude -p 打印出最终结果后大约 5 秒就会结束，但如果模型自己启动的一个 Monitor（后台监看任务）还在跑，以前照样直接退出，现在会等那个监看真的触发或超时才结束。用 claude -p --input-format stream-json 读取管道输入时，如果喂进去的不是合法的 JSONL（一行一条 JSON 的格式），以前内存会无止尽增长，现在会快速失败并给出清楚的错误。Proactive 这种输出风格的会话，以前在自己启动的后台命令或 Monitor 还在跑的时候，会不断用填充消息、重复读日志来瞎忙，而不是安静等待，现在会老实空闲。Bedrock 与 Bedrock Mantle 在 Opus 4.7 以上型号、长时间隐藏思考（模型在背后推理、界面上看不到过程）的阶段，以前连接会悄悄断开，因为空闲超时把连接切了；现在流式传输会持续带着进度事件，不会被误判成没反应。另外，在 SDK 主机那端，遇到网关保活机制让响应被撑住不结束时，回报存活状态的机制也改善了，CLAUDE_STREAM_IDLE_TIMEOUT_MS 调高后的长时间等待不会被误判成卡死。像客服电话的等候线：有的把你提早挂断、有的收到乱码指令就死机死到内存爆掉、有的让客服员假装忙碌其实没事做、有的干脆整通安静到你以为断线——这批把等候线一段段修顺。

時刻の表示形式とタイムゾーンを選べる

Claude Code は各ターンの終わりに時刻を表示し、会話全体をプレーンテキストで残す記録（transcript）の各メッセージにもタイムスタンプが付く。この形式は以前は固定だった。今は二つの設定が増えた。timeFormat は表示スタイルを決め、12 時間制・24 時間制・24 時間制 UTC・strftime パターン（%H:%M のような記号で時刻の見た目を自分で組む書式）を指定できる。timeZone はどのタイムゾーンで換算するかを決める。settings.json に次のように加える。

{
  "timeFormat": "24-hour",
  "timeZone": "Asia/Tokyo"
}

壁の時計を自分が見やすい文字盤に替え、自分のいる街の時刻に合わせるようなものだ。

オートモードが三つの関門を締める。クラウド資格情報、作業ディレクトリ外のファイル、他人の成果物

オートモード（auto mode、Claude が一手ずつ確認せずそのまま実行する区分）で長い作業を任せるとき、これからは三種類の動作を追加でせき止める。一つ目は「Containment Escape」ルールだ。クラウドホストのメタデータ資格情報（metadata-credential、クラウド基盤がアクセス権と引き換えに渡す情報）の取得、外向き通信制限のすり抜け、テナントをまたいで他人のリソースを読む行為は、環境が想定内と明示しない限り自動承認されなくなる。二つ目は、作業ディレクトリの外のファイルを初めて読もうとしたときの一度きりの確認だ。その場で拒否できるほか、settings.json に {"permissions": {"blockReadsOutsideWorkingDirectories": true}} を置けば恒久的に止まる。三つ目は、Cowork と claude.ai のクラウドセッションで、自分のものでない成果物（artifact、会話が生成したファイル）を読むときは、オートモードでも必ず先に確認する。留守を頼むようなものだ。部屋の中は自由に動けるが、引き出しを開けて鍵を探す、裏口を使う、隣家に入る、この三つは先に一声かける。

環境変数一つで、すべてのサブエージェントを同じモデルに固定

Claude に複数のサブエージェント（subagent、メイン会話が送り出し、それぞれ作業の一部を担う分身）を分担させるとき、各サブエージェントには個別に指定されたモデルがあることがある。送り出す時点で指定されたものもあれば、エージェント定義ファイルに固定されたものもある。全部を一つのモデルに切り替えるには、以前は一つずつ探して直す必要があった。今は環境変数 CLAUDE_CODE_SUBAGENT_MODEL_FORCE（システム側で設定し、プログラム起動時に読まれる値）が増えた。これを有効にすると、CLAUDE_CODE_SUBAGENT_MODEL で指定したモデル（未指定ならメイン会話のモデル）がすべてのサブエージェントに適用され、個別指定は無視される。コストを抑えたいとき、あるいは一括作業をそろえたいときに一手で効く。団体で出かけるとき、今日は全員同じバスに乗ると宣言するようなものだ。各自が別に取った切符は無効になる。

推論の強さを今回のセッションだけ変更でき、長期設定は動かさない

/effort は Claude が答える前にどれだけ考えるかを調整するコマンドだ。強くすると思考は深いが遅く高くつき、弱くすると逆になる。以前はこれを使うと設定が長期的に変わり、以後のセッション（session、開いてから閉じるまでの一つの対話）すべてに引き継がれた。今は /effort のメニューに s が加わった。選ぶと現在のセッションだけが変わり、ウィンドウを閉じれば自分の既定に戻る。/model が以前からしている動きと同じだ。別途、新しいモデルに移ると、そのモデルが持つ既定の強さのロックも、今は恒久ではなくこのセッションだけになる。リモートコントロール（Remote Control）で claude.ai 側で強さを選んでから接続した場合、その選択はロック中に適用される。カメラの「この一枚はこの ISO で」に似ている。撮り終えると普段の設定に戻り、全体設定を上書きしない。

ゲートウェイ経由で見つけたモデルに、選択画面で説明が付く

一部の企業は、自社のゲートウェイ（gateway、リクエストをモデルへ転送する中間層）経由で Claude Code を社内モデル群につなぐ。スイッチは環境変数 CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY だ。以前これらのモデルは /model の選択画面に名前だけが並び、違いが分からなかった。今はゲートウェイが各モデルに description を付けられ、選択画面がそれを表示する。説明のないものは従来どおり「From gateway」と出る。対になる変更として、この発見処理は CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC（非必須の外向き通信を止める設定）を入れていても実行される。問い合わせ先は自分のゲートウェイだけで、外部には出ないためだ。ビュッフェの札のようなものだ。以前は各枠に料理名だけ、今は一部に「シェフのおすすめ・軽い辛さ」が加わり、誰も書かなかった枠は素の名前のままだ。

差し込み質問を行き来するキーが変わった

/btw（by the way の略）は、メインの作業を脱線させずに Claude へ小さな質問を差し込み、済んだら元の答えに戻る機能だ。これらの差し込みのやり取りをめくるのは以前 ←／→ で、他の場所での矢印キーの働きと衝突しやすかった。今は Shift+←／Shift+→、または [／] になり、最近の差し込み質問をたどって進行中の答えまで戻れる。別の詰まりも直した。claude agents（サブエージェントを管理する画面）内で /btw パネルを開いた状態で ← を押しても無反応だったが、今は回答の途中でもエージェント一覧に戻り、そのセッションを開き直すとパネルが再び現れる。本に挟む仮の付箋のようなものだ。付箋をめくる動作は本文をめくる動作と分かれているので、一度のすべりで読んでいた章から放り出されない。

`/add-dir` の二点変更。ネットワークパスは拒否、現在ディレクトリ配下のフォルダは受け付け

/add-dir（および起動時の --add-dir、設定の additionalDirectories）は、追加のフォルダを Claude の作業範囲に取り込み、そのフォルダの skills・コマンド・エージェントも一緒に読み込む。今回は逆方向の二つの不具合を片付けた。一つはネットワークパスだ。Windows の UNC 共有や /net/<ホスト> の自動マウントは、実際に触れる前にメッセージ付きで拒否されるようになった。Windows 利用者はドライブ文字に割り当てたパスを使う。もう一つは、現在の作業ディレクトリのすぐ下にあるサブフォルダで、/add-dir は理由もなく拒否していたが、今は受け付け、起動時の --add-dir と同じくそのフォルダの skills・コマンド・エージェントを読み込む。入退室システムのようなものだ。同じ建物の隣人を締め出す一方、遠隔から掛けてくる見知らぬ接続には無防備だった。今は両側とも直っている。

プロジェクトフォルダで `bypassPermissions` を設定しても効かなくなった

bypassPermissions は最も緩い権限区分で、Claude はほとんど何も尋ねずに実行する。以前はプロジェクトの .claude/settings.json か .claude/settings.local.json で defaultMode を "bypassPermissions" にするだけで、そのプロジェクトを開くとこのモードに入った。問題は、この種のファイルがコードと一緒に出回ることだ。誰かがプロジェクトを渡すだけで、あなたのマシンを無防備にできることになる。今はプロジェクト階層のこの値は無視され、"auto" と同じ挙動になる。本当にこのモードを使うには、ユーザー階層か管理設定で設定するか、起動ごとに --permission-mode を付ける。玄関の鍵のようなものだ。施錠しないかどうかは自分で決められるが、郵便受けに差し込まれた紙切れに決めさせはしない。

会社が一括で配る設定。適用が早まり、失敗をより報告し、極端な値は丸める

あなたの Claude Code が会社の管理設定で構成されているなら、この一群はその経路の不具合を直す。policyHelper（会社ポリシーを照合する小さなプログラム）が起動時のキャッシュ設定で上書きされていた場合、以前は次回起動まで更新されなかったが、今はサーバーが削除を報告した時点で実行または終了する。managedSourcesBehavior: "merge" では sandbox.credentials.awsPairs と sandbox.ripgrep は混ぜず最上位ソースから丸ごと採る。timeoutMs・refreshIntervalMs がタイマー上限（2147483647）を超えても失敗せず、範囲に丸められる。診断も明確に。更新失敗は /status に表示、拒否理由が印字され、タイムアウトはタイムアウトと報告される。承認ダイアログも、詳細追跡や生 API ログ、トレースエクスポートに関わる設定なら対応する文言を示す。会社の定型書式のようなものだ。以前は欄を上書きし理由もなく差し戻したが、今は入力ミスをその場で示し、範囲外を補正し、差し戻し理由を添える。

クラウド事業者への送信で、余分な資格情報と残った ID を掃除した

Bedrock・Vertex・Foundry 経由で Claude Code を使う人向けに、この一群は送信リクエストへのログイン情報混入を直す。二重のカスタム Authorization ヘッダーが資格情報を上書きしていた（Bedrock・Mantle・Vertex・WIF 該当）。Vertex ウィザードは ~/.config/anthropic の古いプロファイルを拾っていた。公式ゲートウェイは余分なヘッダーを Foundry・Vertex・Bedrock へ送り、ANTHROPIC_FOUNDRY_API_KEY 設定時は Foundry の Entra ID 上流が起動失敗していた。API キーモードでは Foundry キーに残った Anthropic キーが一緒に送られていた。これらは今は起きず、ゲートウェイのサインインとトークン更新も固定 TLS 証明書を検証する。また、セッション期限切れ後の起動は「終了しました」と表示し /login を案内する。キー不要の Console サインインも組織の設定を適用し /status に組織が出る。海外で乗り継ぐとき他人の書類がかばんに混ざり毎回止められたようなものだ。今は預ける前に整理する。

権限確認ダイアログのまとめ。古いヒント一行を削除、紛らわしい書き方に対応

この一群はすべて「Claude が立ち止まって尋ねるかどうか」に関わる。表面では、Bash と PowerShell の権限確認ダイアログ下の Ctrl+E コマンド説明の行が消えた。Edit（ファイル編集）ダイアログの差分表示は、絵文字や複数コードポイントで構成される文字の幅を誤って数え、レイアウトが崩れていたが、今は揃う。重要なのは三つの穴をふさいだことだ。permissions.ask ルール（先に尋ねることを求める規則）は、対象コマンドが長い複合コマンドやサブシェルの中で実行されると、オートモードで飛ばされ確認なしに走っていたが、今は捕まえる。zsh が bash と異なる解釈をする一部の [[ ]] 条件は自動承認されていたが、今は確認が出る。Bash の Read()／Edit() 拒否ルールは < ファイル のリダイレクトや tac・egrep のような読み取りコマンドに効いていなかったが、今はどの引数やリダイレクト先に一致してもコマンド全体を拒否する。空港の検査のようなものだ。以前は包装を解く、内張りに隠す、別名で申告する、で通れた。今はこれらの抜け道がすべて塞がれている。

バックグラウンドセッションが起動しない数パターンを、今回すべてふさいだ

バックグラウンドセッション（background session、現在の画面を占有せず裏で走らせる作業）に、「そもそも起動しない」系の修正がまとまって入った。macOS の npm インストールが Claude Code の自己更新と重なると、バックグラウンドセッションが開けなかった。Windows で、再利用されたプロセス ID を指す古い daemon（バックグラウンドに常駐するサービスプログラム）のロックファイルがある場合も同様だった。別のケースとして、他の Claude Code プロセスが npm 更新をダウンロード中にバックグラウンドセッションを開くと「Couldn't start the background service」と出ていたが、今はそのダウンロード完了を待つ。後始末の修正が二つ。自己更新後、古い Claude Code 実行ファイルで走り続けるバックグラウンドセッションは退かずに積み上がっていたが、今は置き換えられる。daemon 起動が中断された後にシステムの一時ディレクトリに残る cc-daemon-* フォルダは、cleanupPeriodDays の保持期間の掃引でまとめて除去される。始発バスが車庫で出られないようなものだ。鍵穴が固い、前の便の運行記録が消えていない、給油所がまだ開いていない。これらを一度に解消し、出られなかった空車も駐車場へ引き戻す。

バックグラウンドセッション一覧の記録違いを、まとめて直した

この一群は、claude agents（バックグラウンドセッションを管理する画面）とコマンドラインが「どのセッションが今どの状態か」を取り違えていた点を直す。セッションの state.json の detail フィールドは、スケジュール起床の後も自分の元の指示を繰り返すだけで、新しい状態に更新されなかった。終わったバックグラウンドセッションに再度質問すると本来は一覧の先頭に戻るはずが、Completed の古い位置に居座っていた。Completed は今、最新の完了時刻順に並ぶ。削除されたばかりのディレクトリから claude --bg を打つと、以前は「backgrounded」と誤って報告し、壊れたセッション行を残していたが、今は理由を表示し終了コード 1 で終わる。--resume はバックグラウンド中の対話を二重に一覧表示し、--continue はバックグラウンド化前の止まった古いコピーを開いていた。今は --continue も終了済みのバックグラウンドセッションを開ける。さらに、claude --resume <session-id> --bg は、誰もそのセッションを動かしていなければ、静かにコピーを新規開始する代わりに自分の ID のまま続行するようになり、本当にコピーを始めるときはそう告げる。ホテルの部屋掲示板が、チェックアウト後も客の名前を出したまま、部屋替え後も札が更新されず、同じ人が二部屋に登録されているようなものだ。今回、掲示板をカードキーの実際の状態と突き合わせ直した。

バックグラウンドセッションの停止と通知への応答を、より正直に直した

この一群は、バックグラウンドセッションが中断や監視の際に状態を正直に反映していなかった点を直す。開いたバックグラウンドセッションで Ctrl+S により一時保存したプロンプトは、そのセッションがアイドルになるか停止して再度開くと以前は失われたが、今は残る。← や Ctrl+B でターンをバックグラウンド化する際、サブエージェントや他のツールがちょうど走っていると、そのツールを拒否されたと誤認識することが時々あったが、実際は再実行すべきだった。今は正しく再実行する。タスクパネルや接続中のクライアントからバックグラウンドコマンドを止めると、以前 Claude には伝わらなかったが、今は伝わる。バックグラウンドのサブエージェントを止めると、それが起動したモニター（monitor、代わりに何かを見張り、完了やタイムアウトで知らせるバックグラウンドの仕事）は以前走り続けていたが、今は一緒に止まる。timeout や setsid でシェルから切り離したバックグラウンドコマンドは、以前はタスクを止めても Claude Code を終了しても走り続けたが、今は一緒に終わる。また claude agents は、他のセッションからのメッセージ承認をバックグラウンドセッションが待っていること、誰から来たかを以前は伝えなかったが、今ははっきり示す。店番を代わってもらうようなものだ。閉店の鈴を鳴らしても代役に信号が届かず、レジを開けたままにしている。この一群でようやく鈴と代役の状態と手元の記録が一致する。

`claude agents` 画面とサブエージェントの記録。「見える・追える」を直した

この一群は claude agents（サブエージェントを管理する画面）とサブエージェントの記録の「見える・追える」を直す。この画面から ← でサブエージェントのセッションを開くと、以前は常に元のセッションの権限モードを引き継ぎ、対象ディレクトリ自身の defaultMode やそのエージェントの permissionMode を上書きしていたが、今は対象の設定に従う。keybindings.json の Ctrl+G の再割り当ては claude agents 内で効かなかったが、その Ctrl+S・Ctrl+T は新しい Agents コンテキストで再割り当てできるようになった。別のサブエージェントの記録に切り替えると右上の使用量カウンターが固まる、または遅くなることが多かったが、今はライブ更新される。バックグラウンドのサブエージェントやチームメイトのカウンターも同様だ。claude agents --json は以前、終端を一時的に raw モードへ切り替え、終了時に他のプログラムの終端設定を消してしまっていたが、今はしない。コンピュータのスリープ、接続断、サーバーエラーでストリーミング中に打ち切られたサブエージェントは、以前はその不完全な応答のまま止まっていたが、今は自動的に続きを話す。記録画面から止めたサブエージェントを再開すると、メインエージェントには以前伝わらなかったが、今は伝わる。記録が 5 MB を超えたサブエージェント（画像を多く読んだ後によくある）は、再開やメッセージ送信が「No transcript found」で失敗していたが、今は正常に動く。複数の監視カメラ映像を見る警備室のようなものだ。画面切り替えがカクつき、リモコンのボタンが押したい映像と合わず、あるカメラは録画途中で固まって続きを撮らない。この一群で映像もボタンも録画もまとめて滑らかになった。

プロンプトキャッシュを無駄にしていた五つのパターンをまとめて直した

プロンプトキャッシュ（一度送った会話内容を覚えておき、同じ内容を次に送るときは計算も課金もし直さない仕組み）は本来、時間とお金を節約するためのものだが、この一群は静かに無効化させていた穴をいくつか直す。リモートコントロール（Remote Control）がセッション途中で接続すると Bash ツールの定義を送り直し、それだけでキャッシュを外していたが、今はしない。アドバイザーモデル（advisor model、メインモデルの判断を助けるモデル）を設定したセッションは、バックグラウンドリクエストでキャッシュを外し会話全体を送り直していたが、今は当たる。対象は圧縮や /recap などだ。会話を空の状態まで巻き戻すと /model と /effort が余分なキャッシュ警告を出していたが、今は出ない。長時間スクリーンショットを多用するセッションは、画像がリクエストごとのサイズ上限を超えると以後毎ターンキャッシュを外していたが、この上限の問題は直った。/fork（現在の会話を新しいバックグラウンドセッションへ分岐させる）は、元の会話のキャッシュを新しいセッションでも保つようになった。ワークツリー（worktree、Git で同じプロジェクトを並行して複数コピー開く機能）の説明をシステムプロンプトの変更ではなく通常のメッセージとして送ることで実現している。コピー店の受領控えのようなものだ。取っておけば照合が速いはずが、いくつかの工程で毎回控えを破って刷り直していた。この一群でその破りを一つずつ止めた。

リモートコントロールの信頼に関わる穴を二つ塞いだ

リモートコントロール（Remote Control、スマホや別の端末から動作中の Claude Code に接続する機能）は、「同意」と「誰の指示を聞くか」の誤りを二つ直す。Esc を押しても claude remote-control で n を押しても、意図は拒否だったのに、システムは同意として記録し、次のリクエストが確認なしにそのまま接続してしまっていた。今回、本当に拒否を押したときだけ拒否として扱われる。もう一つは、Claude アプリから開始したリモートコントロールセッションが、以前はアプリ側で選んだモデルを無視してこのマシンの既定モデルで動いていたが、今は選んだモデルで動く。玄関のインターホンで「開けない」を押したのに、システムが「許可済み」と記録し、次は見知らぬ人がそのまま入って来られたようなものだ。今回、拒否を押せば本当に拒否になる。

MCP 接続のまとめ。止めるべきは止め、消すべきは消し、エラーが読めるようになった

MCP（Model Context Protocol、Claude を外部ツールにつなぐ規格）は接続管理とエラーログの一群を直す。/mcp の再接続と有効化は、起動後に読み込まれた管理下の MCP 許可／拒否リストや strictPluginOnlyCustomization（MCP をプラグイン提供のサーバーのみに限定する設定）で止めるべき設定ファイルサーバーに、以前は接続してしまっていたが、今はきちんと止まる。strictPluginOnlyCustomization が MCP をプラグイン限定にしているとき、claude mcp remove はリモートサーバーを削除しても保存済み OAuth 資格情報を残していたが、今はそれも消える。claude mcp add/remove は、プロジェクトの .mcp.json が実は FIFO（先入れ先出しの名前付きパイプファイル）やデバイスファイルへのシンボリックリンクだった場合、以前はハングするかメモリを食い尽くしていたが、今はすぐに失敗して実行可能なエラーメッセージを出す。WebSocket 型 MCP サーバーの接続失敗は、以前はログに読めない「[object ErrorEvent]」とだけ出ていたが、今は本来のエラーが出る。さらに、MCP 接続と OAuth のデバッグ／エラーログは、サーバーの URL やリクエストヘッダーに含まれる資格情報をそのまま出力していたが、今は伏せ字にする。ビルの入退室記録のようなものだ。訪問者リストは更新されたのに警備員が把握しておらず、退去者の鍵は回収されず、監視カメラの映像はぼやけて分からない。この一群でリストも鍵も映像もようやく揃った。

サンドボックスとワークツリーの境界。「通ってはいけない道」と「知らせるべき残骸」を直した

サンドボックス（Claude の動作を安全な範囲に閉じ込める隔離環境）とワークツリーは、境界が守られていなかった箇所や見過ごされた残骸を直す。ネットワークホスト名の末尾に点が余分に付くと deniedDomains はこのホストを塞げず、「二度と尋ねない」も出続けていたが、今は正しく塞ぐ。プラグインが宣言するコンポーネントパスが外部を指すシンボリックリンクだと、以前は外部ファイルを読めたが、今はエラーで拒否される。ワークツリーで隔離されたセッションは、git に触れない Bash ループや $VAR 読み取り、heredoc を複雑すぎるとして拒否していたが、今は正しく許可される。連結ワークツリーのサブディレクトリへ cd した後、共有 .git への書き込み権限を失っていたが、今は失わない。また /doctor は、強制終了されたセッションが残したサンドボックスマスクファイルについて警告する。団地の柵のようなものだ。塞がれていない隙間、隣のベランダに入り込む配達員、人を見誤る警備員。この一群で隙間を塞ぎ、側門に鍵をかけ、回収し忘れた古い鍵についてメモを残す。

設定の再読み込みで、以前は見落としや変更忘れがあった

この一群は Claude Code の「設定を読み直す」処理が徹底していなかった箇所を直す。プロジェクトで起動後に作られた .claude/ フォルダの設定は、以前は再起動しないと読み込まれなかったが、今は作成後すぐに効く。allowManagedPermissionRulesOnly（管理下のルールのみ有効にする設定）が有効なとき、最初の設定再読み込みの後に --disallowedTools とセッション単位の拒否ルールが消えていたが、今は残る。さらに、テレメトリ（telemetry、利用状況を報告する仕組み。ここでは OTEL 規格を指す）がサーバー管理設定経由で送られてきた値は、ウォームスタート（既存のプロセスを使い回す起動、フル再起動ではない）では無視されていた。デスクトップアプリの Code セッションも同様だったが、今はいずれも反映される。規則を変えたのに次の勤務の警備員に引き継がなかったようなものだ。開けっぱなしにすべきでないドアが残り、外すべき古い規則が残り、放送システムが一部だけ聞こえない。この一群で引き継ぎメモを埋めた。

ターミナル画面のまとめ更新。動きが滑らかに、詰まっていた箇所も直った

この一群は、長い会話でのターミナル画面の動きを滑らかにし、詰まっていた箇所をいくつか直す。描画性能が改善し、長い会話での毎ターンの再描画量が減り、返信が長くなってもストリーミングが遅くならず、バックグラウンドエージェントの更新も画面全体を再描画しなくなった。入力欄も一打鍵ごとの再描画が減り、入力の遅延が下がる。修正点。作業スピナーは以前、応答がスラッシュコマンドパネルの裏でストリーミングされている間に止まって固まったように見えたが、今は止まらない。自動継続したスラッシュコマンドの応答がストリーミング中、以前は画面下部に幽霊のような重複コマンド行が現れていたが、今は現れない。フルスクリーンモードでは以前 ! の shell コマンド出力をクリックして展開できなかったが、今はできる。ANSI カラーコード付きテキスト（CI ログなど）を /feedback などのダイアログに貼り付けるとクラッシュしていたが、今はしない。さらに、絵文字の自動補完が残りの GitHub／Slack ショートコードの別名（:satisfied:、:telephone:、:collision: など）に対応した。古い映写機のベルト、フォーカスリング、フィルムゲートを一度に調整するようなものだ。画面の揺れが止まり、以前詰まっていた箇所もなめらかに動くようになる。

ヘッドレスモードと長時間ストリーミングのまとめ。早すぎる切断も、静かな空回りもなくなった

この一群は、ヘッドレスモード（headless、ターミナル画面がなく、スクリプトや CI 環境でよく使われる）と長時間のストリーミング接続で「待つべきなのに待たない」「止まるべきなのに止まらない」状況を直す。claude -p は最終結果を表示してから約 5 秒で終了していたが、モデル自身が仕掛けた Monitor（バックグラウンドの監視タスク）がまだ動いていても以前はそのまま終了していた。今はその監視が実際に発火するかタイムアウトするまで待つ。claude -p --input-format stream-json でパイプ入力を読むとき、渡されたものが正しい JSONL（一行に一つの JSON オブジェクト）でなければ、以前はメモリが際限なく増え続けたが、今はすぐに失敗して明確なエラーを出す。Proactive 出力スタイルのセッションは、自分が開始したバックグラウンドコマンドや Monitor がまだ動いている間、静かに待つ代わりに埋め合わせのメッセージや繰り返しのログ読み込みで空回りしていたが、今は正直にアイドル状態でいる。Bedrock と Bedrock Mantle では、Opus 4.7 以降で長時間の隠れた思考（モデルが画面に出さず裏で推論すること）フェーズになると、以前は接続が静かに切れていた。アイドルタイムアウトが接続を切っていたためだが、今はストリームが進捗イベントを運び続けるので無応答と誤認されない。さらに SDK ホスト側では、ゲートウェイの keep-alive で応答が保持されている間の生存報告も改善され、CLAUDE_STREAM_IDLE_TIMEOUT_MS を上げた後の長い待機がハングしたセッションと誤認されなくなった。コールセンターの保留回線のようなものだ。あるものは早く切り、あるものは崩れた指示でメモリが尽きるまで固まり、あるものは担当者が忙しいふりをして何もせず、あるものはただ静かになって回線が切れたと思わせる。この一群が保留回線を一つずつ整える。

시각 표시 형식과 시간대를 고를 수 있음

Claude Code는 매 턴이 끝날 때 시각을 찍고, 대화 전체를 일반 텍스트로 남기는 기록(transcript)의 각 메시지에도 타임스탬프가 붙는다. 이 형식은 전에는 고정이었다. 이제 설정 두 개가 늘었다. timeFormat은 표시 방식을 정하며 12시간제, 24시간제, 24시간제 UTC, 또는 strftime 패턴(%H:%M 같은 기호로 시각 모양을 직접 짜는 서식)을 넣을 수 있다. timeZone은 어느 시간대로 환산할지 정한다. settings.json에 이렇게 넣는다.

{
  "timeFormat": "24-hour",
  "timeZone": "Asia/Seoul"
}

벽시계를 보기 편한 문자판으로 바꾸고 내가 있는 도시 시각에 맞추는 것과 같다.

오토 모드가 세 관문을 조인다: 클라우드 자격 증명, 작업 디렉터리 밖 파일, 남의 산출물

오토 모드(auto mode, Claude가 한 단계씩 확인하지 않고 바로 실행하는 구분)로 긴 작업을 맡길 때, 이제 세 종류의 동작을 더 막는다. 첫째는 'Containment Escape' 규칙이다. 클라우드 호스트의 메타데이터 자격 증명(metadata-credential, 클라우드 기반이 접근 권한과 맞바꿔 내주는 정보) 가져오기, 외부 트래픽 제한 우회, 테넌트를 넘어 남의 자원 읽기는 환경이 예상된 동작이라고 명시하지 않는 한 자동 승인되지 않는다. 둘째는 작업 디렉터리 바깥 파일을 처음 읽으려 할 때 한 번만 뜨는 확인이다. 그 자리에서 막거나, settings.json에 {"permissions": {"blockReadsOutsideWorkingDirectories": true}}를 넣어 영구히 막는다. 셋째는 Cowork와 claude.ai 클라우드 세션에서, 내 것이 아닌 산출물(artifact, 대화가 만들어 낸 파일)을 읽을 때는 오토 모드라도 반드시 먼저 묻는다. 집을 봐 달라고 부탁하는 것과 같다. 방 안은 자유롭게 다니되 서랍을 열어 열쇠를 찾거나 뒷문을 쓰거나 옆집에 들어가는 세 가지는 먼저 한마디 묻는다.

환경 변수 하나로 모든 서브에이전트를 같은 모델로 고정

Claude에게 여러 서브에이전트(subagent, 메인 대화가 내보내 각자 작업 일부를 맡는 분신)로 나눠 일을 시킬 때, 서브에이전트마다 지정된 모델이 따로 있을 수 있다. 내보내는 시점에 지정된 것도 있고, 에이전트 정의 파일에 박혀 있는 것도 있다. 전부를 한 모델로 바꾸려면 예전에는 하나씩 찾아 고쳐야 했다. 이제 환경 변수 CLAUDE_CODE_SUBAGENT_MODEL_FORCE(시스템 쪽에서 설정하고 프로그램이 시작할 때 읽는 값)가 생겼다. 켜면 CLAUDE_CODE_SUBAGENT_MODEL이 지정한 모델(지정이 없으면 메인 대화의 모델)이 모든 서브에이전트에 적용되고, 개별 지정은 무시된다. 비용을 낮추거나 한 묶음의 작업을 일관되게 맞추고 싶을 때 한 번에 듣는다. 단체로 나갈 때 오늘은 다 같은 버스를 탄다고 선언하는 것과 같다. 각자 따로 끊은 표는 무효가 된다.

추론 강도를 이번 세션만 바꾸고 장기 설정은 그대로 둠

/effort는 Claude가 답하기 전에 얼마나 오래 생각할지 조절하는 명령이다. 강도를 높이면 사고가 깊지만 느리고 비싸며, 낮추면 반대다. 예전에는 이걸 쓰면 설정이 장기로 바뀌어, 이후의 세션(session, 열고서 닫을 때까지의 한 대화)마다 따라 바뀌었다. 이제 /effort 메뉴에 s가 생겼다. 고르면 현재 세션만 바뀌고, 창을 닫으면 원래 기본값으로 돌아온다. /model이 진작부터 하던 방식과 같다. 별도로, 새 모델로 옮기면 그 모델이 지닌 기본 강도 잠금도 이제 영구가 아니라 이 세션만 잠근다. 원격 제어(Remote Control)로 claude.ai 쪽에서 강도를 고른 뒤 연결했다면, 그 선택이 잠금 동안 적용된다. 카메라의 '이 한 장은 이 ISO로'와 비슷하다. 찍고 나면 평소 설정으로 돌아가고 전체 설정을 덮어쓰지 않는다.

게이트웨이로 발견한 모델에 선택 화면에서 설명이 붙음

일부 회사는 자사 게이트웨이(gateway, 요청을 모델로 넘기는 중간층)를 거쳐 Claude Code를 사내 모델 묶음에 연결한다. 스위치는 환경 변수 CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY다. 예전에는 이 모델들이 /model 선택 화면에 이름만 나열되어 차이를 알 수 없었다. 이제 게이트웨이가 모델마다 description을 붙일 수 있고 선택 화면이 그대로 보여 준다. 설명이 없는 항목은 여전히 "From gateway"로 나온다. 짝이 되는 변경으로, 이 발견 동작은 CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC(비필수 외부 연결을 끄는 설정)를 켜 두어도 실행된다. 묻는 대상이 내 게이트웨이뿐이고 바깥으로는 나가지 않기 때문이다. 뷔페의 표찰과 같다. 예전에는 칸마다 요리 이름만, 이제 일부에는 '셰프 추천, 약한 매움'이 붙고, 아무도 안 적은 칸은 맨 이름 그대로다.

곁다리 질문을 오가는 키가 바뀜

/btw(by the way의 약자)는 메인 작업을 탈선시키지 않고 Claude에게 작은 질문을 끼워 넣고, 끝나면 원래 답으로 돌아가는 기능이다. 이 곁다리 대화를 넘기는 키가 예전에는 ←／→여서 다른 곳의 화살표 키 기능과 부딪히기 쉬웠다. 이제 Shift+←／Shift+→, 또는 [／]로 바뀌어 최근 곁다리 질문을 훑고 진행 중인 답까지 되돌아간다. 별도의 걸림도 고쳤다. claude agents(서브에이전트를 관리하는 화면) 안에서 /btw 패널을 연 채 ←를 눌러도 반응이 없었는데, 이제 답변 도중이라도 에이전트 목록으로 돌아가고, 그 세션을 다시 열면 패널이 다시 나타난다. 책에 끼우는 임시 포스트잇과 같다. 포스트잇을 넘기는 동작이 본문을 넘기는 동작과 나뉘어 있어, 한 번 미끄러졌다고 읽던 장에서 튕겨 나가지 않는다.

`/add-dir` 두 가지 변경: 네트워크 경로 거부, 현재 디렉터리 하위 폴더 허용

/add-dir(그리고 시작 시의 --add-dir, 설정의 additionalDirectories)는 추가 폴더를 Claude의 작업 범위에 넣고, 그 폴더의 skills, 명령, 에이전트도 함께 불러온다. 이번 판은 반대 방향의 결함 두 가지를 정리했다. 하나는 네트워크 경로다. Windows의 UNC 공유, /net/<호스트> 같은 자동 마운트는 실제로 건드리기 전에 메시지와 함께 거부된다. Windows 사용자는 드라이브 문자에 매핑한 경로를 쓴다. 다른 하나는 현재 작업 디렉터리 바로 아래의 하위 폴더로, /add-dir가 이유 없이 거부했지만 이제 받아들이고, 시작 시의 --add-dir처럼 그 폴더의 skills, 명령, 에이전트를 불러온다. 출입 시스템과 같다. 같은 건물 이웃은 막으면서 원격에서 걸어 오는 낯선 연결에는 무방비였는데, 이제 양쪽 다 바로잡혔다.

프로젝트 폴더에서 `bypassPermissions`를 설정해도 듣지 않음

bypassPermissions는 가장 느슨한 권한 구분으로, Claude가 거의 아무것도 묻지 않고 실행한다. 예전에는 프로젝트의 .claude/settings.json이나 .claude/settings.local.json에서 defaultMode를 "bypassPermissions"로 두기만 하면, 그 프로젝트를 열 때 이 모드로 들어갔다. 문제는 이런 파일이 코드와 함께 돌아다닌다는 점이다. 누군가 프로젝트를 건네주기만 해도 당신 기계를 무방비로 만들 수 있다는 뜻이다. 이제 프로젝트 계층의 이 값은 무시되고 "auto"와 같게 동작한다. 정말 이 모드를 쓰려면 사용자 계층이나 관리 설정에서 설정하거나, 시작할 때마다 --permission-mode를 붙인다. 현관 열쇠와 같다. 문을 잠그지 않을지는 스스로 정하지만, 누가 우편함에 밀어 넣은 쪽지가 대신 정하게 두지는 않는다.

회사가 일괄로 내리는 설정: 더 일찍 적용, 실패를 더 알림, 극단값은 제한

당신의 Claude Code가 회사의 관리 설정으로 구성된다면, 이 묶음은 그 경로의 결함을 고친다. policyHelper(회사 정책을 대조하는 작은 프로그램)가 시작 시점 캐시 설정에 덮였을 때, 예전에는 다음 시작까지 갱신 안 됐는데 이제 서버가 제거를 알리는 즉시 실행하거나 종료한다. managedSourcesBehavior: "merge"에서 sandbox.credentials.awsPairs와 sandbox.ripgrep은 섞지 않고 최상위 출처에서 통째로 가져온다. timeoutMs, refreshIntervalMs가 타이머 상한(2147483647)을 넘어도 실패하지 않고 범위로 제한된다. 진단도 명확해졌다. 갱신 실패는 /status에 표시되고, 거절 이유가 찍히며, 시간 초과는 시간 초과로 보고된다. 승인 대화상자도 상세 추적이나 원시 API 로깅, 추적 내보내기와 관련된 설정이면 해당 문구를 보여 준다. 회사가 주는 정형 양식과 같다. 예전에는 칸을 덮어쓰고 이유 없이 반려했는데, 이제 입력 오류를 즉시 알리고 범위를 바로잡고 반려 이유를 붙인다.

클라우드 공급자로 보내던 여분 자격 증명과 남은 신원을 정리함

Bedrock, Vertex, Foundry를 거쳐 Claude Code를 쓰는 사람을 위해, 이 묶음은 나가는 요청에 로그인 정보가 섞이던 문제를 고친다. 두 번 나열된 사용자 지정 Authorization 헤더가 자격 증명을 덮어썼다(Bedrock, Mantle, Vertex, WIF 모두 해당). Vertex 마법사는 ~/.config/anthropic에 남은 옛 프로필을 주웠다. 공식 게이트웨이는 여분 헤더를 Foundry, Vertex, Bedrock으로 보냈고, ANTHROPIC_FOUNDRY_API_KEY 설정 시 Foundry의 Entra ID 상류가 시작에 실패했다. API 키 모드로 Foundry 키를 쓸 때 남은 Anthropic 키가 함께 전송됐다. 이제 이런 일은 없고, 게이트웨이 로그인과 토큰 갱신도 고정 TLS 인증서를 검증한다. 또한 세션 만료 뒤 시작하면 '끝났다'고 말하고 /login을 준다. 키가 필요 없는 Console 로그인도 조직 설정을 적용하고 /status에 조직이 나온다. 해외 환승에서 남의 서류가 가방에 섞여 매번 걸리던 것과 같다. 이제 부치기 전에 정리한다.

권한 확인창 묶음: 옛 힌트 한 줄 제거, 헷갈리는 표기 몇 가지 대응

이 묶음은 모두 'Claude가 멈춰서 물어볼지'와 관련된다. 겉으로는 Bash와 PowerShell 권한 확인창 아래의 Ctrl+E 명령 설명 줄이 사라졌고, Edit(파일 편집) 확인창의 차이 보기는 이모지와 여러 코드포인트로 이뤄진 문자의 폭을 잘못 세어 배치가 틀어졌는데 이제 맞춰진다. 중요한 것은 구멍 셋을 막은 것이다. permissions.ask 규칙(먼저 묻기를 요구하는 규칙)은 해당 명령이 긴 복합 명령이나 서브셸 안에서 실행되면 오토 모드에서 건너뛰어 확인 없이 돌았는데, 이제 잡는다. zsh가 bash와 다르게 해석하는 일부 [[ ]] 조건은 자동 승인됐는데 이제 확인이 뜬다. Bash의 Read／Edit 거부 규칙은 < 파일 리디렉션이나 tac, egrep 같은 읽기 명령에 듣지 않았는데, 이제 규칙이 어느 인자나 리디렉션 대상에 걸리든 명령 전체를 거부한다. 공항 검색과 같다. 예전에는 포장을 풀거나 안감에 숨기거나 다른 이름으로 신고하면 통과됐다. 이제 이런 우회로가 모두 막혔다.

백그라운드 세션이 시작되지 않던 몇 가지 상황을 이번에 모두 막음

백그라운드 세션(background session, 현재 화면을 차지하지 않고 뒤에서 돌리는 작업)에 '아예 시작이 안 되던' 부류의 수정이 한 묶음 들어왔다. macOS의 npm 설치가 Claude Code 자체 업데이트와 겹치면 백그라운드 세션이 열리지 않았고, Windows에서 재사용된 프로세스 번호를 가리키는 오래된 daemon(백그라운드에 상주하는 서비스 프로그램) 잠금 파일이 있을 때도 마찬가지였다. 다른 경우로, 다른 Claude Code 프로세스가 npm 업데이트를 내려받는 중에 백그라운드 세션을 열면 "Couldn't start the background service"가 떴는데, 이제 그 내려받기가 끝날 때까지 기다린다. 뒷정리 수정이 둘. 자체 업데이트 후 옛 Claude Code 실행 파일로 계속 도는 백그라운드 세션은 물러나지 않고 쌓였는데 이제 교체된다. daemon 시작이 중단된 뒤 시스템 임시 디렉터리에 남는 cc-daemon-* 폴더는 cleanupPeriodDays 보존 기간 정리에서 함께 쓸린다. 첫차가 차고에서 못 나가는 것과 같다. 열쇠 구멍이 뻑뻑하거나, 지난 근무의 배차 기록이 안 지워졌거나, 주유소가 아직 안 열렸거나. 이것들을 한 번에 풀고, 못 나간 빈 차도 주차장으로 끌어온다.

백그라운드 세션 목록의 기록 오류 몇 가지를 고침

이 묶음은 claude agents(백그라운드 세션을 관리하는 화면)와 명령줄이 '어느 세션이 지금 어떤 상태인지' 착각하던 부분을 고친다. 세션의 state.json의 detail 필드는 예약 기상 뒤에도 원래 지시를 계속 반복할 뿐 새 상태로 갱신되지 않았다. 끝난 백그라운드 세션에 다시 질문하면 원래 목록 맨 앞으로 와야 하는데, Completed 목록의 옛 자리에 그대로 걸려 있었다. Completed는 이제 최신 완료 시각순으로 정렬된다. 방금 삭제된 디렉터리에서 claude --bg를 치면 예전에는 "backgrounded"라고 거짓 보고하고 깨진 세션 행을 남겼는데, 이제 이유를 출력하고 종료 코드 1로 끝난다. --resume은 백그라운드 중인 대화를 두 번 나열했고 --continue는 백그라운드화 전의 멈춘 옛 사본을 열었다. 이제 --continue도 끝난 백그라운드 세션을 연다. 또한 claude --resume <session-id> --bg는 아무도 그 세션을 돌리고 있지 않을 때 조용히 사본을 새로 시작하는 대신 원래 ID로 이어서 돌고, 정말 사본을 시작할 때는 그렇다고 알린다. 호텔 방 게시판이 체크아웃 뒤에도 손님 이름을 그대로 보여 주고, 방을 바꿔도 표가 안 바뀌고, 같은 사람이 방 두 개에 등록된 것과 같다. 이번에 게시판을 카드키의 실제 상태와 다시 맞췄다.

백그라운드 세션이 중단 신호와 상태에 더 정직하게 반응하도록 고침

이 묶음은 백그라운드 세션이 중단되거나 관찰될 때 상태를 정직하게 반영하지 않던 점을 고친다. 열려 있는 백그라운드 세션 안에서 Ctrl+S로 임시 저장한 프롬프트는 그 세션이 유휴 상태가 되거나 멈췄다가 다시 열리면 예전에는 사라졌는데, 이제 남는다. ←나 Ctrl+B로 턴을 백그라운드로 보낼 때 마침 서브에이전트나 다른 도구가 돌고 있으면 이따금 백그라운드 세션이 그 도구를 거부된 것으로 잘못 판단했는데, 실제로는 다시 돌았어야 했다. 이제 올바르게 다시 돈다. 작업 패널이나 연결된 클라이언트에서 백그라운드 명령을 멈추면 예전에는 Claude가 통보받지 못했는데, 이제 통보받는다. 백그라운드 서브에이전트를 멈추면 그것이 시작한 모니터(monitor, 대신 무언가를 지켜보다 완료나 시간 초과 시 알리는 백그라운드 작업)가 예전에는 계속 돌았는데, 이제 함께 멈춘다. timeout이나 setsid로 셸에서 분리한 백그라운드 명령은 예전에 작업을 중지하거나 Claude Code를 종료해도 계속 돌았지만, 이제 함께 끝난다. 또 claude agents는 다른 세션에서 온 메시지 승인을 백그라운드 세션이 기다리고 있다는 것과 누가 보냈는지를 예전에는 알려 주지 않았는데, 이제 분명히 보여 준다. 가게를 대신 봐 달라고 부탁하는 것과 같다. 마감 종을 울려도 대타에게 신호가 안 가서 계산대를 계속 열어 둔다. 이번에야 종소리와 대타의 상태와 손에 든 기록이 맞아떨어진다.

`claude agents` 화면과 서브에이전트 기록: '보이고 따라갈 수 있게' 고침

이 묶음은 claude agents(서브에이전트를 관리하는 화면)와 서브에이전트 기록의 '보이고 따라갈 수 있게' 하는 부분을 고친다. 이 화면에서 ←로 서브에이전트의 세션을 열면 예전에는 항상 원래 세션의 권한 모드를 물려받아 대상 디렉터리 자체의 defaultMode와 그 에이전트의 permissionMode를 덮어썼는데, 이제 대상의 설정을 따른다. keybindings.json의 Ctrl+G 재배정은 claude agents 안에서 듣지 않았는데, 그 Ctrl+S, Ctrl+T는 이제 새 Agents 컨텍스트로 재배정할 수 있다. 다른 서브에이전트의 기록으로 전환하면 오른쪽 위 사용량 카운터가 자주 멈추거나 느려졌는데, 이제 실시간으로 갱신되며 백그라운드 서브에이전트와 팀원의 카운터도 마찬가지다. claude agents --json은 예전에 터미널을 잠깐 raw 모드로 바꾸고 종료 시 다른 프로그램의 터미널 설정을 지웠는데, 이제 그러지 않는다. 컴퓨터 절전, 연결 끊김, 서버 오류로 스트리밍 도중 끊긴 서브에이전트는 예전에 그 불완전한 응답에서 멈췄는데, 이제 자동으로 이어서 말한다. 기록 화면에서 멈춘 서브에이전트를 다시 시작하면 메인 에이전트에게 예전에는 알려지지 않았는데, 이제 알려진다. 기록이 5MB를 넘은 서브에이전트(이미지를 많이 읽은 뒤 흔함)는 재개나 메시지 전송이 "No transcript found"로 실패했는데, 이제 정상 동작한다. 여러 카메라 화면을 보는 경비실과 같다. 화면 전환이 끊기고, 리모컨 버튼이 누르려던 화면과 안 맞고, 카메라 하나는 녹화 도중 멈춰 이어 찍지 못한다. 이번에 화면도 버튼도 녹화도 한꺼번에 매끄러워졌다.

프롬프트 캐시를 무효로 만들던 다섯 가지 상황을 한 번에 고침

프롬프트 캐시(한 번 보낸 대화 내용을 기억해 다음에 같은 내용이 오면 다시 계산도, 다시 청구도 하지 않는 장치)는 원래 시간과 돈을 아끼려는 것인데, 이 묶음은 그것을 조용히 무효로 만들던 몇 가지 구멍을 고친다. 원격 제어(Remote Control)가 세션 도중에 연결되면 Bash 도구 정의를 다시 보냈고, 그것만으로 캐시가 빗나갔는데 이제 그러지 않는다. 어드바이저 모델(advisor model, 메인 모델의 판단을 돕는 모델)을 설정한 세션은 백그라운드 요청에서 캐시를 놓치고 대화 전체를 다시 보냈는데, 이제 캐시에 맞는다. 대상은 압축, /recap 같은 동작이다. 대화를 빈 상태로 되감으면 /model과 /effort가 불필요한 캐시 경고를 보였는데, 이제 보이지 않는다. 스크린샷이 많은 긴 세션은 이미지가 요청당 크기 상한을 넘으면 이후 매 턴 캐시가 빗나갔는데, 그 상한 문제를 고쳤다. /fork(현재 대화를 새 백그라운드 세션으로 갈라 이어 돌리기)는 이제 원래 대화의 캐시를 새 세션에도 유지한다. 워크트리(worktree, Git이 같은 프로젝트를 나란히 여러 벌 열게 해 주는 기능) 브리핑을 시스템 프롬프트를 바꾸는 대신 일반 메시지로 보내는 방식이다. 복사집 영수증 부본과 같다. 보관해 두면 빨리 대조할 수 있어야 하는데, 몇몇 단계가 매번 부본을 찢고 다시 인쇄했다. 이번에 그 찢는 단계를 하나씩 멈췄다.

원격 제어의 신뢰 관련 구멍 두 개를 막음

원격 제어(Remote Control, 휴대폰이나 다른 기기에서 돌아가는 Claude Code에 접속하는 기능)는 '동의'와 '누구 말을 들을지'의 오류 두 가지를 고친다. Esc를 누르든 claude remote-control에서 n을 누르든 의도는 거절이었는데, 시스템이 동의로 기록해 다음 요청이 묻지 않고 바로 연결됐다. 이번에 진짜 거절을 눌러야만 거절로 친다. 다른 하나는 Claude 앱에서 시작한 원격 제어 세션이 예전에는 앱에서 고른 모델을 무시하고 이 기기의 기본 모델로 돌았는데, 이제 고른 모델로 돈다. 현관 인터폰에서 '열지 않음'을 눌렀는데 시스템이 '이미 허가함'으로 기록해 다음엔 낯선 사람이 그냥 들어오는 것과 같다. 이번에 거절을 눌러야 진짜 거절이 된다.

MCP 연결 묶음: 막을 건 막고, 지울 건 지우고, 오류가 읽히게 됨

MCP(Model Context Protocol, Claude를 외부 도구에 연결하는 표준)는 연결 관리와 오류 로그 묶음을 고친다. /mcp의 재연결과 활성화는 예전에 시작 뒤 불러온 관리형 MCP 허용／거부 목록이나 strictPluginOnlyCustomization(MCP를 플러그인 제공 서버로만 제한하는 설정)이 막아야 할 설정 파일 서버에 여전히 연결됐는데, 이제 제대로 막힌다. strictPluginOnlyCustomization이 MCP를 플러그인 전용으로 잠갔을 때, claude mcp remove는 원격 서버를 제거해도 저장된 OAuth 자격 증명을 남겼는데, 이제 함께 지운다. claude mcp add/remove는 프로젝트의 .mcp.json이 알고 보니 FIFO(선입선출 이름 있는 파이프 파일)나 장치 파일 심볼릭 링크일 때 예전에는 멈추거나 메모리를 다 먹었는데, 이제 빠르게 실패하며 실행 가능한 오류 메시지를 준다. WebSocket형 MCP 서버 연결 실패는 예전에 로그에 읽을 수 없는 "[object ErrorEvent]"만 찍혔는데, 이제 실제 오류가 찍힌다. 또한 MCP 연결과 OAuth 디버그／오류 로그는 서버 URL이나 요청 헤더에 담긴 자격 증명을 그대로 출력했는데, 이제 가려진다. 건물의 출입 기록부와 같다. 방문자 명단은 갱신됐는데 경비는 못 따라갔고, 나간 세입자의 열쇠는 회수 안 됐고, 감시 화면은 흐려서 안 보였다. 이번에 명단도 열쇠도 화면도 맞춰졌다.

샌드박스와 워크트리 경계: '지나가면 안 될 길'과 '알려야 할 잔재'를 고침

샌드박스(Claude의 동작을 안전한 범위에 가두는 격리 환경)와 워크트리는 경계가 지켜지지 않던 곳, 알려지지 않던 잔재를 고친다. 네트워크 호스트 이름 끝에 점이 하나 더 붙으면 deniedDomains가 이 호스트를 막지 못했고 '다시 묻지 않음'도 계속 떴는데, 이제 올바르게 막는다. 플러그인이 선언한 구성 요소 경로가 외부를 가리키는 심볼릭 링크라면 예전에는 바깥 파일을 읽을 수 있었는데, 이제 오류로 거부된다. 워크트리로 격리된 세션은 git을 안 건드리는 Bash 반복문, $VAR 읽기, heredoc을 너무 복잡하다며 거부했는데, 이제 올바르게 허용된다. 연결된 워크트리 하위 디렉터리로 cd한 뒤 공유 .git 쓰기 권한을 잃었는데, 이제 잃지 않는다. 또한 /doctor는 강제 종료된 세션이 남긴 샌드박스 마스크 파일에 대해 경고한다. 동네 울타리와 같다. 막히지 않은 틈, 남의 발코니로 들어가는 배달원, 사람을 잘못 보는 경비. 이번에 틈을 막고 옆문을 잠그고, 못 챙긴 옛 열쇠에 대해 쪽지를 남긴다.

설정 다시 불러오기에서 예전에 빠뜨리거나 바뀐 걸 잊던 부분

이 묶음은 Claude Code가 '설정을 다시 읽는' 일을 철저히 하지 못하던 몇 곳을 고친다. 프로젝트에서 시작 뒤에 만들어진 .claude/ 폴더의 설정은 예전에 재시작해야만 읽혔는데, 이제 만들어지는 즉시 적용된다. allowManagedPermissionRulesOnly(관리형 규칙만 적용)를 켰을 때, 첫 설정 다시 불러오기 뒤 --disallowedTools와 세션 단위 거부 규칙이 함께 지워졌는데, 이제 남는다. 또한 텔레메트리(telemetry, 사용 현황을 보고하는 장치, 여기서는 OTEL)가 서버 관리 설정을 통해 내려온 값은 웜 스타트에서 예전에는 무시됐고 데스크톱 앱의 Code 세션도 마찬가지였는데, 이제 모두 적용된다. 웜 스타트는 기존 프로세스를 재사용하는 시작 방식이다. 규칙을 바꾸고도 다음 근무 경비에게 인계하지 않은 것과 같다. 열려 있으면 안 될 문이 남고, 없어져야 할 옛 규칙이 남고, 방송 장치가 일부 채널만 안 들린다. 이번에 인계 기록을 채웠다.

터미널 화면 묶음: 더 매끄럽게, 막혀 있던 몇 곳도 고침

이 묶음은 긴 대화에서 터미널 화면이 더 매끄럽게 돌아가게 하고 막혀 있던 몇 곳을 고친다. 렌더링이 개선돼 긴 대화에서 매 턴 다시 그리는 양이 줄고, 답이 길어져도 스트리밍이 느려지지 않으며, 백그라운드 에이전트 갱신도 화면 전체를 다시 그리지 않는다. 입력창도 키를 칠 때마다 다시 그리는 양이 줄어 입력 지연이 낮아진다. 수정된 것. 작업 스피너는 예전에 응답이 슬래시 명령 패널 뒤에서 스트리밍되는 동안 멈춰 막힌 것처럼 보였는데, 이제 멈추지 않는다. 자동으로 이어지는 슬래시 명령 응답이 스트리밍되는 동안 예전에는 화면 아래쪽에 유령 같은 중복 명령 줄이 나타났는데, 이제 나타나지 않는다. 전체 화면 모드에서 예전에는 ! 셸 명령 출력을 클릭해 펼칠 수 없었는데, 이제 된다. ANSI 색상 코드가 있는 텍스트(CI 로그 같은)를 /feedback 같은 대화상자에 붙여넣으면 예전에는 죽었는데, 이제 죽지 않는다. 또한 이모지 자동완성이 남은 GitHub／Slack 짧은 코드 별칭(:satisfied:, :telephone:, :collision: 등)을 받아들인다. 낡은 영사기의 벨트, 초점 링, 필름 게이트를 한 번에 손보는 것과 같다. 화면이 더는 떨리지 않고, 막히던 곳도 매끄럽게 돈다.

헤드리스 모드와 장시간 스트리밍 묶음: 일찍 끊지도, 조용히 헛돌지도 않음

이 묶음은 헤드리스 모드(headless, 터미널 창이 없는 방식으로 스크립트나 CI 환경에서 흔함)와 장시간 스트리밍 연결에서 '기다려야 하는데 안 기다리거나' '멈춰야 하는데 안 멈추던' 상황을 고친다. claude -p는 최종 결과를 출력하고 약 5초 뒤 끝났는데, 모델이 스스로 건 Monitor(백그라운드 감시 작업)가 아직 돌고 있어도 예전에는 그냥 종료했다. 이제 그 감시가 실제로 발동하거나 시간 초과될 때까지 기다린다. claude -p --input-format stream-json으로 파이프 입력을 읽을 때 들어온 것이 올바른 JSONL(줄마다 JSON 하나인 형식)이 아니면 예전에는 메모리가 끝없이 늘었는데, 이제 빠르게 실패하며 분명한 오류를 준다. Proactive 출력 스타일 세션은 예전에 자신이 시작한 백그라운드 명령이나 Monitor가 아직 도는 동안 채움 메시지와 반복된 로그 읽기로 헛바퀴를 돌았는데, 이제 정직하게 유휴 상태로 있는다. Bedrock과 Bedrock Mantle에서 Opus 4.7 이상 모델로 긴 숨은 사고(모델이 화면에 안 보이게 뒤에서 추론하는 것) 단계에 있을 때, 예전에는 연결이 조용히 끊겼다. 유휴 시간 초과가 연결을 끊었기 때문인데, 이제 스트림이 진행 이벤트를 계속 실어 응답 없음으로 오판되지 않는다. 그리고 SDK 호스트 쪽에서 게이트웨이 연결 유지 때문에 응답이 붙들려 있을 때 생존 보고도 개선돼, CLAUDE_STREAM_IDLE_TIMEOUT_MS를 올린 뒤의 긴 대기가 멈춘 세션으로 오판되지 않는다. 고객센터 대기줄과 같다. 어떤 건 일찍 끊고, 어떤 건 깨진 지시를 받으면 메모리가 터질 때까지 멈추고, 어떤 건 상담원이 바쁜 척만 하고, 어떤 건 아예 조용해져 전화가 끊긴 줄 알게 만든다. 이 묶음이 대기줄을 하나씩 바로잡는다.

이번 판의 남은 자잘한 수정: 예약, 팀원, 자격 증명, CLI 몇 가지 개선

이 카드는 이번 판의 나머지, 서로 무관한 자잘한 수정과 개선을 모은다. /schedule(예약 기능)에서 저장된 프롬프트에 메시지 역할이 빠진 루틴은 예전에 예약 시각이 되면 아무것도 안 하고 헛돌았는데, 이제 제대로 실행된다. 팀원(teammate, 다중 에이전트 협업에서 동료 역할)의 권한 요청이 리더 쪽 메일함 쓰기가 잠깐 잠긴 시점과 겹치면 예전에는 두 번 답이 갔는데, 이제 한 번만 간다. agent-team(다중 에이전트 팀)의 팀원은 tmux나 iTerm2 창에서 종료 요청을 확인하고도 이따금 안 닫힌 채 남았는데, 이제 확실히 닫힌다. 시작할 때 네트워크 프록시가 뜨지 못한 클라우드 세션은 예전에 그 세션 나머지 내내 git／GitHub 자격 증명을 잃었는데, 이제 백그라운드에서 재시도해 회복한다. CLI 쪽 작은 개선 세 가지. /code-review --comment는 이제 glab mr note로 GitLab 병합 요청에 결과를 올릴 수 있어 '지원하지 않는 대상'이라고 보고하지 않는다. 다른 대화상자 뒤에 밀려 있던 MCP elicitation(추가 정보를 요청하는 확인)이나 권한 확인은 이제 눈에 보이는 확인과 같은 지연으로 유휴 알림을 보낸다. claude self-hosted-runner --configure-git는 이제 git push 협상도 켜서, 한동안 묵혀 둔 클론에서 새 브랜치를 처음 push할 때 트리 전체가 아니라 새 커밋만 올린다. 또한 상세／기록 출력에서 동시에 끝난 여러 비동기 hook 알림이 이제 한 줄로 합쳐지고, hook마다 한 줄씩 화면을 채우지 않는다. 책상 맨 아래 서랍 잡동사니를 정리하는 것과 같다. 잉크 마른 펜, 제자리로 안 돌아간 클립 통, 기한 지난 포스트잇. 서로 무관하지만 정리하고 나면 뭘 찾든 손이 빠르다.

VSCode 확장 묶음 업데이트: 사이드바 정리, 모델 전환, 접근성 수정

이번 판의 VSCode(마이크로소프트의 코드 편집기) 확장 업데이트는 사이드 패널 정리와 막혀 있던 몇 곳 해소에 집중한다. 세션 목록에 접을 수 있는 'ACCOUNT & USAGE'와 'SESSION MANAGER' 제목 구역이 생겨 계정 email, 사용량 미터, 사용량 대화상자를 여는 링크를 담는다. 입력창 푸터에는 현재 모델을 보여 주고 선택기를 여는 모델 필이 붙고, Effort 행과 'More models' 페이지도 있다. 미분류 구역도 접힌다. 명령 메뉴에서 출력 스타일을 고를 수 있고 사용자 지정도 포함한다. 수정된 것. Bedrock, Vertex 같은 제3자 공급자 배포가 claude.ai 전용 기능과 남은 로그인을 계속 보여 주던 것을 숨겼다. 패널 로드 뒤 빈 채였던 사용량 미터는 먼저 지난번 알려진 사용량을 보여 준다. 'Enable Remote Control for all sessions' 토글이 이미 열린 세션에도 적용된다. 스크린 리더 읽기도 두 곳 고쳤다. 'Delete session'은 'Archive session'으로 이름을 바꿨고, 보관 항목은 목록 아래쪽의 접을 수 있는 'Archived sessions' 그룹으로 옮겨지며 Unarchive로 되돌린다. 작업 메뉴는 슬래시 명령을 인라인이 아니라 필터링 가능한 대화상자로 나열하게 바뀌었고, MCP 서버 대화상자에도 같은 필터가 붙었다. 꽉 찬 서랍장에 라벨을 다시 붙이고 잘 당겨지는 손잡이로 바꾸고 뻑뻑하던 몇 칸에 기름을 치는 것과 같다.
