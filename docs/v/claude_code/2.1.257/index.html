Claude Code 2.1.257

發布日期：2026-09-01

zh-TW

新的 Fable 5.1 模型上場，本機變預設、閘道暫時還給 5

你在 Claude Code 裡選 Fable 這一檔模型時，現在拿到的是新版 Fable 5.1（模型代號 claude-fable-5-1），已接手成 Fable 系列的預設，不必自己指定。它能一次讀進一百萬個 token（AI 一次能納入考量的文字量單位），大專案的程式碼一次丟給它都吞得下。計費每百萬輸入 token 十美元、輸出五十美元；暫存過的內容再讀一次只要每百萬 0.25 美元，反覆追問同一批檔案便宜很多。但有個過渡限制：透過官方閘道（gateway，把請求轉給模型的中間層）跑的工作階段，打 fable 或 best 目前仍落到 Fable 5——閘道還沒設定好會拒收 5.1，要用就在 /model 手動挑。像新款引擎已是門市標配，但合作車行的加油站還沒換供油規格，開進去只能先加舊款的油，除非你指定要新的。

可以自訂時間怎麼顯示，還有用哪個時區

Claude Code 每輪回答結束會標一個時間，逐字稿（transcript，把整段對話存成純文字的紀錄）裡每則訊息也有時間戳記。以前這個格式固定，現在多了兩個設定：timeFormat 決定顯示樣式，可填 12 小時制、24 小時制、24 小時制 UTC，或一段 strftime 格式字串（用 %H:%M 這類代號自己拼時間長相）；timeZone 決定用哪個時區換算。在 settings.json 裡加，例如：

{
  "timeFormat": "24-hour",
  "timeZone": "Asia/Taipei"
}

像把牆上時鐘換成你看得順眼的款式，再撥到自己所在城市的時間。

自動模式收緊三道關卡：雲端憑證、工作目錄外的檔案、別人的產物

自動模式（auto mode，Claude 不逐項問你、直接執行的檔次）下跑一長串工作時，現在多攔三種動作。第一是「Containment Escape」規則：抓雲端主機的中繼資料憑證（metadata-credential，換取存取權的一段資訊）、繞過對外流量限制、或跨租戶讀別人的資源，不再自動放行，除非環境標示為預期行為。第二是第一次讀工作目錄外的檔案時跳一次性提醒，可當場擋掉；要永遠擋就在 settings.json 放 {"permissions": {"blockReadsOutsideWorkingDirectories": true}}。第三是 Cowork／claude.ai 雲端階段裡，讀不屬於你的產物（artifact，對話生成的檔案）一律先問你，自動模式也不例外。像請人代管你家：能自由走動，但翻抽屜找鑰匙、走後門、進鄰居家，得先問過你。

一個環境變數，強制所有子代理都用同一個模型

你請 Claude 分頭跑好幾個子代理（subagent，主對話派出去、各自幹一小塊活的分身）時，每個子代理可能有自己被指定的模型：有的在派出當下指定，有的寫死在代理定義檔裡。想讓它們全部改用某一個模型，以前得一個個翻出來改。現在多了 CLAUDE_CODE_SUBAGENT_MODEL_FORCE 這個環境變數（environment variable，在系統層設定、程式啟動時讀取的參數）。把它打開，CLAUDE_CODE_SUBAGENT_MODEL 指定的模型（沒指定就是主對話用的模型）會套到每一個子代理身上，那些個別指定一律被忽略。適合你想壓成本、或想確保整批任務一致時一次生效。像帶一團人出門，直接宣布今天全部搭同一班車，各自原本訂的車票都作廢。

改推理力度可以只改這次工作階段，不動長期設定

/effort 是調 Claude 想多久再回答的指令——力度高，思考更透徹但慢、也更貴；力度低則相反。以前用它會把設定改成長期的，之後每個工作階段（session，一次從開啟到結束的對話）都跟著變。現在 /effort 選單裡多了一個 s：挑它就只改當前這個工作階段，關掉視窗就回到你原本的預設，跟 /model 早就有的作法一致。另外，換到一個新模型時，它自帶的「預設力度鎖定」現在也只鎖這個工作階段，不再是永久；如果你是透過遠端遙控（Remote Control）從 claude.ai 那邊挑好力度再連進來，那個選擇在鎖定期間會直接生效。像相機的「這張照片先用這個 ISO」，拍完自動跳回你平常設定，不會把總設定覆蓋掉。

透過閘道發現模型時，選單會顯示每個模型的說明

有些公司會讓 Claude Code 透過自家閘道（gateway，把請求轉給模型的中間層）連到一批內部模型，開關是環境變數 CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY。以前這些模型在 /model 選單裡只有名字，看不出差別。現在閘道可以隨每個模型附一段 description，選單就照著顯示；沒附說明的仍寫「From gateway」。搭配的一項調整：這個發現動作即使你設了 CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC（關掉非必要對外連線）也照跑，因為它只問你自己的閘道、不對外。像自助餐檯的菜牌，以前每格只貼菜名，現在多了一行「主廚推薦、微辣」，不想貼的那格就還是空白菜名。

問完插話的問題，回主線的按鍵改了

/btw（by the way 的縮寫）讓你在不打斷主線任務的情況下，臨時問 Claude 一個小問題，問完再回到原本的答案。以前在這些側邊問答之間翻頁用 ←／→，跟其他地方的方向鍵功能容易撞。現在改成 Shift+←／Shift+→，也可以用 [／]，一路翻過你最近幾個插話問題、再翻回正在進行的答案。另外修好一個卡點：在 claude agents（管理子代理的畫面）裡開著 /btw 面板時按 ← 原本沒反應，現在它會帶你回子代理清單，就算問答還沒結束也行；重新打開那個工作階段時，面板會再出現。像看書時夾的臨時便利貼，翻閱便利貼的手勢跟翻正文分開，才不會一滑就跳出正在讀的章節。

`/add-dir` 兩處調整：拒收網路路徑、接受目前目錄底下的資料夾

/add-dir（以及啟動時的 --add-dir、設定裡的 additionalDirectories）用來把額外的資料夾納入 Claude 的工作範圍，連同那個資料夾的 skills、指令、代理一起載入。這版收拾了兩個相反方向的毛病。一是網路路徑：Windows 的 UNC 網路共享、/net/<主機> 這類自動掛載，現在會在真的去碰之前就擋下並說明，Windows 使用者請改用對應到磁碟機代號的路徑。二是就在你目前工作目錄底下的子資料夾，以前 /add-dir 會無理由拒絕，現在會接受，並像啟動時的 --add-dir 一樣載入該資料夾的 skills、指令、代理。像門禁系統，之前把住同一棟樓的鄰居擋在外面、卻對遠端撥進來的陌生連線不設防，現在兩邊都調對了。

專案資料夾裡設 `bypassPermissions` 不再有效

bypassPermissions 是最寬鬆的權限檔次，Claude 幾乎什麼都不問就做。過去只要在專案的 .claude/settings.json 或 .claude/settings.local.json 裡把 defaultMode 設成 "bypassPermissions"，一打開這個專案就進入這個模式。問題是這種檔案常跟著程式碼一起流通，等於任何人送你一份專案就能決定你的機器不設防。現在專案層級的這個值會被忽略，行為跟設 "auto" 一樣。要真的用這個模式，改在使用者層級或受管理設定裡設，或每次啟動時自己加 --permission-mode。像家門鑰匙：可以自己決定要不要不鎖門，但不能讓「別人塞進你信箱的一張紙條」替你決定門不上鎖。

公司統一派下來的設定：更早生效、更會報錯、極端數值會被夾住

公司用受管理設定統一配置 Claude Code 時，這批修那條路上的毛病。policyHelper（核對公司政策的小程式）被開機快取蓋掉，以前要等下次開機才更新，現在伺服器一回報設定移除就立刻改跑或退出。managedSourcesBehavior: "merge" 下，sandbox.credentials.awsPairs、sandbox.ripgrep 現在採最高階來源整份沿用；timeoutMs、refreshIntervalMs 填超過計時器上限（2147483647）也會被夾回合法範圍，不再整個失敗。診斷更清楚：更新失敗顯示在 /status，婉拒對話框印出退出原因，逾時明講成逾時；核准對話框在設定同時動追蹤或匯出時也顯示對應措辭。像公司發的制式表單，以前欄位互蓋、填錯不說原因；現在改成填錯即時提示、超範圍自動修正、退件附理由。

接雲端供應商時，多送出去的憑證與殘留身分都清乾淨了

透過 Bedrock、Vertex、Foundry 跑 Claude Code，這批修的是請求裡夾帶不該夾的登入資訊。重複列了兩次的自訂 Authorization 標頭曾蓋掉你的憑證（Bedrock、Mantle、Vertex、WIF 都中招）、Vertex 精靈撿到殘留舊設定檔、官方閘道把多餘標頭送給 Foundry／Vertex／Bedrock 且 Foundry Entra ID 上游啟動失敗、API 金鑰模式下殘留 Anthropic 金鑰跟著多送——都不再發生，閘道登入與 token 更新也開始驗證固定 TLS 憑證。另外，工作階段過期後重開會說「已結束」並給 /login；免金鑰的 Console 登入也會套用組織設定、/status 顯示所屬組織。像出國轉機，行李箱混進別人的證件，海關每關被卡；現在託運前先清一遍，只留當次要用的證件。

權限確認框這一批：少了一行舊提示、對付得了幾種混淆寫法

這組都跟「Claude 要不要停下來問你」有關。介面上，權限確認框底下的 Ctrl+E 指令說明拿掉了；Edit（改檔）確認框的差異檢視，以前把 emoji 等多碼字元寬度算錯、排版會歪，現在對齊了。真正重要的是三個漏洞收口：permissions.ask（要求先問過的規則）若指令包在複合指令或子殼層裡跑，以前會被自動模式跳過不問，現在照攔；某些 [[ ]] 條件 zsh 跟 bash 解讀不同，以前自動放行，現在跳確認；Bash 的 Read／Edit 拒絕規則，以前對 < 檔案 重新導向、tac、egrep 這類讀檔指令不生效，現在命中任一參數或導向目標就整條拒絕。像機場安檢，之前拆開包裝、藏進夾層、換個名字報就能過，現在這幾種繞法都補上了。

背景工作階段開不起來的幾種情形，這版都堵上

背景工作階段（background session，丟給 Claude 在後台跑的任務）這批修「根本啟動不了」的幾種情形。macOS 上用 npm 安裝、碰上 Claude Code 自我更新時，背景工作階段會開不起來；Windows 上過期的 daemon（常駐服務程式）鎖檔指向被重用行程編號，也一樣。另一種是另一個行程正在下載更新，開背景工作階段會直接報「Couldn't start the background service」，現在會等下載完再啟動。還有兩個收拾殘局的：更新後仍跑舊版執行檔的背景工作階段以前會堆著不退場，現在會被汰換；cc-daemon-* 這種啟動中斷留下的暫存資料夾，現在會被 cleanupPeriodDays 保留期一併掃掉。像早班公車卡在總站：鑰匙孔卡住、排班紀錄沒清、加油站沒開門，這幾個原因一次排除，空車也拖回停車場。

背景工作階段的清單顯示，這批修對了幾個記錯的地方

這批修 claude agents（管理背景工作階段的畫面）跟指令列「記錯狀態」的幾個地方。state.json 的 detail 欄位被排程喚醒後會重複原本派工指令，不更新。重新對已完成的背景工作階段追問後，理應回清單前面，卻卡在「Completed」舊位置，現在照最新完成時間排序。從已刪掉的目錄打 claude --bg，以前謊報成功、留下壞紀錄，現在印出失敗原因並以結束碼 1 收場。--resume 把背景對話列兩次，--continue 打開的是背景化前卡住的舊副本；現在 --continue 也能打開跑完的背景工作階段，claude --resume <session-id> --bg 在沒人跑那個工作階段時會接續原編號，真要另起副本才明講。像旅館房間看板，退房了還顯示住客名字、同一人登記成兩間房；這次把看板跟房卡實際狀態對齊。

背景工作階段對停止與通知的反應，這批修得更誠實

背景工作階段被中斷時，這批讓狀態如實反映。Ctrl+S 在開啟的背景工作階段暫存提示，閒置或停止後重開以前會不見，現在保得住。用 ← 或 Ctrl+B 把任務丟到背景時，子代理或工具正跑，曾誤判工具被拒絕；現在會正確重跑。從任務面板或用戶端停止背景指令時，以前 Claude 不會被告知，現在會。停止背景子代理時，它的監控（monitor，代替你盯著某件事、完成或逾時就通知）以前會繼續跑，現在會停掉。用 timeout 或 setsid 把背景指令和 shell 脫鉤時，停止任務或結束 Claude Code 後它以前仍會跑，現在也會結束。另外，claude agents 以前不會說「有背景工作階段在等你核准另一階段傳來的訊息」也不說是誰傳的，現在會清楚顯示。像請人代班顧店，按了下班鈴代班的人卻沒收到訊號；這批修完，鈴聲、代班狀態、跟手上紀錄終於對得上。

`claude agents` 畫面與子代理逐字稿，這批修的是「看得到、跟得上」

這批修 claude agents（管理子代理畫面）跟逐字稿的可用性。用 ← 開子代理工作階段，以前沿用原權限模式、蓋掉目標 defaultMode 與 permissionMode，現在照目標走；Ctrl+G 重新綁定以前不生效，Ctrl+S、Ctrl+T 現在可透過新 Agents 情境重綁。切到另一子代理逐字稿，用量計數器常凍住，現在即時更新；claude agents --json 以前會短暫切終端機成 raw 模式、退出蓋掉別程式設定，現在不會。子代理被睡眠、斷線或伺服器錯誤打斷，以前停在半截，現在自動接完；重新接續已停掉的子代理，主對話以前不被告知，現在會；逐字稿超 5MB 的子代理恢復或傳訊，以前報「No transcript found」，現在正常。像盯著幾支監視器的保全室：畫面卡格、按鍵對不上、錄影錄到一半當機，這批一次修順。

五種讓提示快取失效的情形，這批一次修掉

提示快取（prompt cache，記住送過的內容、下次不重算不重收費）本是省錢機制，這批修幾個讓它悄悄失效的漏洞。遠端遙控在工作階段進行到一半才連上時，會重送一次 Bash 工具定義，光這樣就讓快取失效，現在不會。設了顧問模型（advisor model，輔助主模型判斷的模型）的工作階段，背景請求以前吃不到快取、每次重送整段對話，現在能命中；背景請求指壓縮對話、/recap 這類動作。對話倒帶回空白後，/model 跟 /effort 以前會多顯示一則快取警告，現在不會。長時間夾大量截圖的工作階段，圖片超單次請求上限後每輪快取失誤，這問題已修。/fork（把對話另開一份背景工作階段）現在會把原本快取保留到新階段，做法是把工作樹簡報改成訊息帶過去，不動系統提示本身。像影印店的收據存根，留著本該省時間，這幾個環節卻讓存根每次被撕掉重印，現在一一補回去。

遠端遙控的兩個信任漏洞補上了

遠端遙控（Remote Control，讓你從手機或另一台裝置連進正在跑的 Claude Code）這批修的是「同意」跟「聽誰的」出錯的地方。以前不管是按 Esc、還是在 claude remote-control 選單裡按 n，用意都是拒絕連線，卻被系統當成「已經同意」記下來，導致下一次請求直接連上、不再問你。這次修好，真的按了拒絕才算數。另一個是從 Claude app 發起的遠端遙控工作階段，以前會忽略你在 app 裡選好的模型，逕自用這台機器的預設模型跑，現在會照你選的模型執行。像門口的對講機，你明明按了「不開」，系統卻記成「已放行」，下次陌生人直接推門進來；這次改成按下拒絕才是真的拒絕。

MCP 連線這批：該擋的擋住、該清的清乾淨、錯誤訊息看得懂了

MCP（Model Context Protocol，讓 Claude 連外部工具的協定）這批修連線與紀錄。/mcp 重新連線或啟用時，現在會擋住啟動後才被允許／拒絕清單或 strictPluginOnlyCustomization 禁用的設定檔伺服器。受此設定限制時，claude mcp remove 會連同遠端伺服器的 OAuth 憑證清掉。claude mcp add/remove 遇到 .mcp.json 是 FIFO 或裝置檔符號連結，現在會快速失敗並說明原因，不再卡住或吃光記憶體。WebSocket 失敗會顯示真正錯誤，不再只印「[object ErrorEvent]」；連線與 OAuth 紀錄也會遮蔽網址或標頭的憑證。像大樓門禁，名單、鑰匙、監視畫面以前各有漏洞，現在都對齊了。

沙盒與工作樹的邊界，這批修的是「不該過去的路」跟「該提醒的殘留」

沙盒（sandbox，把 Claude 動作限制在安全範圍內的隔離環境）與工作樹這批，修的是邊界沒守住、或殘留沒被發現的地方。網路主機名結尾多打一個點時，deniedDomains 以前擋不住這個 host，「不要再問」也一直重複跳出，現在能正確擋下。外掛宣告的元件路徑如果是指向外部的符號連結，以前能藉此讀到外面的檔案，現在會被拒絕並報錯。工作樹隔離的工作階段，以前把不碰 git 的 Bash 迴圈、$VAR 讀取、heredoc 都當成太複雜而拒絕，現在能正確放行；cd 進連結工作樹的子目錄後，對共用 .git 目錄的寫入權限以前會不見，現在不會。另外，/doctor 現在會提醒你，被強制結束的工作階段留下的沙盒遮罩檔還在。像社區圍籬：有個沒堵住的縫、外送員能溜進鄰戶陽台、警衛偶爾認錯人，這批把縫補上、側門鎖好，還留了張紙條提醒你忘記收走的舊鑰匙。

設定重新載入這幾個環節，以前會漏掉或忘記已經變了

這批修的是 Claude Code 「重新讀設定」這件事沒做徹底的幾個地方。專案裡如果是啟動之後才建立的 .claude/ 資料夾，裡面的設定以前要等重開才會被讀到，現在啟動後建立也能生效。allowManagedPermissionRulesOnly（只允許受管理規則生效）開啟時，第一次設定重新載入後，--disallowedTools 跟工作階段層級的拒絕規則以前會被連帶清掉，現在會保留。另外，遙測（telemetry，回報使用狀況的機制，這裡指 OTEL）透過受管理設定推送下來的值，暖啟動時以前會被忽略，桌面版 App 開的 Code 工作階段也中招，現在都會生效。暖啟動指沿用既有行程、不是整個重開機的啟動方式。像換了新規定卻沒通知輪班的第二班警衛：有的門忘記解鎖、有的舊規定該撤沒撤、廣播系統選擇性失聰，這批把交接紀錄補齊了。

終端機畫面這一批：跑起來更順、幾個卡格的地方修好了

這批讓終端機畫面在長對話裡跑得更順，也修掉幾個卡住的小地方。渲染效能改善：每輪要重繪的東西變少，串流不會因回答變長跟著變慢，背景代理更新不再整個畫面重繪；輸入框打字要重繪的量也減少，延遲跟著降。修好的：工作指示燈以前會在回應串流到一半、被 slash 指令面板擋住時停止轉動，看起來像卡住，現在不會；自動接續的 slash 指令回應串流時，畫面下方以前會多冒一行幽靈重複指令列，現在不會；全螢幕模式下以前點不了 ! 的 shell 輸出去展開，現在點得到；貼帶 ANSI 顏色碼的文字進 /feedback 這類對話框以前會當掉，現在不會。另外，emoji 自動完成現在認得剩下的 GitHub／Slack 簡碼別名。像把老舊放映機的皮帶、對焦環、片門一次調校，畫面不再抖動，卡住的地方也順了。

無頭模式與長時間串流這批：不再提早掛斷、不再悶著頭空轉

這批修無頭模式（headless，沒有終端機視窗，常見於腳本、CI）跟長時間串流該等或該停的情形。claude -p 印完結果後，模型啟動 Monitor（背景監看任務）若還在跑，以前約 5 秒就退出，現在等它觸發或逾時。管線輸入不是合法 JSONL 時，以前記憶體會無止盡成長，現在會快速失敗並說明錯誤。Proactive 輸出風格的工作階段，背景指令或 Monitor 還在跑時以前會用填充訊息與重讀日誌瞎忙，現在會閒置。Bedrock 與 Bedrock Mantle 長時間隱藏思考時，以前會被閒置逾時切斷；現在串流帶進度事件。SDK 主機端也改善存活回報，調高 CLAUDE_STREAM_IDLE_TIMEOUT_MS 後的長等待不再被誤判卡死。像客服電話等候線：有的提早掛斷、有的收到亂碼就當機、有的裝忙、有的乾脆安靜到你以為斷線——這批把等候線一段段修順。

這版剩下的零散修復：排程、隊友、憑證、幾個 CLI 小改進

Fable 5.1 lands as the local default; gateways stay on Fable 5 for now

When you pick the Fable model in Claude Code, you now get the new Fable 5.1 (model id claude-fable-5-1), which has taken over as the default for the Fable line. It takes in a million tokens at once — the unit of text an AI weighs in a single pass — enough for the code of a whole large project in one go. Pricing is $10 per million input tokens and $50 per million output; cached content costs $0.25 per million to read again, so repeated questions about the same files are far cheaper. One transitional catch: sessions run through the official gateway (the middle layer that forwards requests to a model) still resolve fable and best to Fable 5, since gateways not yet configured for 5.1 reject it — pick Fable 5.1 in /model yourself. A new engine is already standard on the showroom floor, but a partner garage's pumps have not switched fuel grades, so driving in you get the old fuel unless you ask for the new one.

Choose how times are shown, and in which time zone

Claude Code stamps a time at the end of every turn, and each message in the transcript — the plain-text record of the whole conversation — carries a timestamp too. That format used to be fixed. Now there are two settings: timeFormat sets the style and accepts 12-hour, 24-hour, 24-hour UTC, or an strftime pattern (codes like %H:%M that let you spell out the shape of the time yourself); timeZone sets which zone the clock is converted to. Add them in settings.json, for example:

{
  "timeFormat": "24-hour",
  "timeZone": "America/New_York"
}

It is like swapping the wall clock for a face you find easy to read, then setting it to the time in your own city.

Auto mode tightens three gates: cloud credentials, files outside your working directories, other people's artifacts

When you let Claude run a long stretch of work in auto mode — where it acts without checking each step with you — it now holds back three more kinds of action. First, a Containment Escape rule: fetching a cloud host's metadata credentials (a piece of information a cloud platform hands out in exchange for access), slipping past outbound-traffic limits, or reaching across tenants to read someone else's resources are no longer auto-approved unless your environment marks them as expected. Second, a one-time prompt the first time it wants to read a file outside your working directories; block it on the spot, or for good with {"permissions": {"blockReadsOutsideWorkingDirectories": true}} in settings.json. Third, in Cowork and claude.ai cloud sessions, reading an artifact (a file produced by a conversation) that is not yours now always asks you first, even in auto mode. It is like asking someone to house-sit: they move around the rooms freely, but rummaging in drawers for keys, using the back door, or stepping into the neighbour's place are things they check with you first.

One environment variable forces every subagent onto the same model

When you have Claude fan out across several subagents — the helpers the main conversation dispatches to each do a slice of the work — each one may carry its own assigned model: some set at dispatch time, some hard-coded in an agent definition file. Switching them all to one model used to mean hunting each down. Now there is an environment variable, CLAUDE_CODE_SUBAGENT_MODEL_FORCE — a setting made at the system level and read when the program starts. Turn it on and the model named by CLAUDE_CODE_SUBAGENT_MODEL (or the main conversation's model if none is named) applies to every subagent, and those per-subagent choices are all ignored. Handy when you want to hold costs down, or keep a whole batch of work consistent, in one move. It is like taking a group out for the day and announcing everyone rides the same bus — the tickets people booked separately no longer count.

Change effort for just this session, leaving your long-term setting alone

/effort tunes how long Claude thinks before answering — higher effort means deeper reasoning but slower and pricier; lower is the reverse. Using it used to change the setting for the long term, so every later session (one conversation from open to close) inherited it. Now the /effort menu has an s option: pick it and only the current session changes, and closing the window returns you to your own default — matching what /model has done for a while. Separately, when you move to a new model, the default-effort hold it ships with now locks only this session rather than permanently; and if you connected via Remote Control after picking an effort on claude.ai, that choice now applies during the hold. It is like a camera's "use this ISO for this shot" — after the frame it snaps back to your usual setting instead of overwriting it.

Gateway-discovered models can now carry a description in the picker

Some companies let Claude Code reach a set of internal models through their own gateway — the middle layer that forwards requests to a model — switched on by the environment variable CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY. Those models used to appear in the /model picker as bare names with nothing to tell them apart. Now the gateway can attach a description to each one and the picker shows it; entries without one still read "From gateway". A paired change: this discovery step now runs even when you have set CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC (which turns off non-essential outbound calls), because it only queries your own gateway and reaches nothing outside. It is like a buffet's labels: each slot used to show just a dish name, now some add "chef's pick, mild heat", and the ones nobody labelled still show the plain name.

The keys for stepping through side questions have changed

/btw (short for by the way) lets you slip Claude a quick question without derailing the main task, then return to the original answer. Paging between these side exchanges used to be ←/→, which clashed with what the arrow keys do elsewhere. It is now Shift+←/Shift+→, or [/], stepping through your recent side questions and back to the live answer. A separate snag is fixed: with the /btw panel open inside a claude agents session (the screen for managing subagents), pressing ← did nothing; it now takes you back to the agents list even mid-answer, and the panel returns when you reopen that session. It is like the temporary sticky notes you tuck into a book: flipping through the notes is a separate gesture from turning the pages, so one stray swipe does not throw you out of the chapter you were reading.

Two `/add-dir` changes: network paths refused, subfolders of the current directory accepted

/add-dir — along with --add-dir at startup and additionalDirectories in settings — brings an extra folder into Claude's working scope, loading that folder's skills, commands and agents with it. This release cleans up two faults pointing opposite ways. One is network paths: Windows UNC shares and /net/<host> automounts are now refused with a message before anything touches them, and Windows users should use a mapped drive letter instead. The other is a subfolder right under your current working directory, which /add-dir used to reject for no reason; it is now accepted, and its skills, commands and agents load just as --add-dir does at startup. It is like a door-entry system that had been shutting out a neighbour from the same building while leaving a remote dial-in from a stranger wide open — both ends are set right now.

Setting `bypassPermissions` in a project folder no longer works

bypassPermissions is the most permissive mode, where Claude acts on almost anything without asking. It used to be enough to set defaultMode to "bypassPermissions" in a project's .claude/settings.json or .claude/settings.local.json, and opening that project dropped you into the mode. The trouble is that such files travel with the code, so anyone who hands you a project could decide your machine runs unguarded. Now that value is ignored at the project level and behaves like "auto". To really use the mode, set it in user or managed settings, or pass --permission-mode at each startup. It is like your front-door key: you get to decide whether to leave the door unlocked, but a note someone slipped into your mailbox does not get to make that call for you.

Company-pushed settings: apply sooner, report failures better, clamp extreme values

If your Claude Code is centrally configured by your company through managed settings, this batch fixes faults along that path. A policyHelper (the small program that checks company policy) shadowed at launch by cached settings used to wait until next launch to update; now it runs or exits as soon as the server reports that setting removed. Under managedSourcesBehavior: "merge", sandbox.credentials.awsPairs and sandbox.ripgrep are now taken whole from the highest source that sets them, not blended; timeoutMs and refreshIntervalMs above the timer maximum (2147483647) no longer fail outright, and are clamped instead. Diagnostics are clearer: refresh failures show in /status, declining prints why it exited, timeouts are reported as timeouts; the approval dialog also shows matching telemetry wording when the settings also touch tracing, raw API logging, or trace export. It is like a company's standard form that used to overwrite fields and bounce back with no reason — now it flags mistakes as you type, fixes out-of-range entries, and explains a bounce.

Stray credentials and leftover identities sent to cloud providers are cleaned up

For anyone running Claude Code through Bedrock, Vertex or Foundry, this batch fixes login details getting into outgoing requests. A doubly-listed custom Authorization header used to override your configured credential (Bedrock, Mantle, Vertex, WIF all affected); the Vertex setup wizard picked up a leftover profile from ~/.config/anthropic; the official gateway sent stray headers to Foundry, Vertex and Bedrock, and Foundry's Entra ID upstream failed to start when ANTHROPIC_FOUNDRY_API_KEY was set; API-key mode against a Foundry key sent a leftover Anthropic key alongside it. None of that happens now, and gateway sign-in and token refresh now verify the pinned TLS certificate too. Also, launching after a session expired now says "ended" and offers /login; the keyless Console sign-in now applies your organization's settings and /status shows the Organization. It is like changing planes with someone else's documents mixed into your bag, stopped at every checkpoint — now the bag is cleared before check-in.

The permission-prompt batch: one old hint gone, several sneaky forms now caught

This group is all about whether Claude stops to ask you. On the surface, the Ctrl+E command-explanation line under Bash and PowerShell permission prompts is gone, and the Edit prompt's diff view — which had been miscounting the width of emoji and characters built from several code points, skewing the layout — now lines up. The substantive part is three holes closed: a permissions.ask rule (one that requires asking first) was skipped in auto mode when the matching command ran inside a long compound command or a subshell, running without a prompt; it is caught now. Certain [[ ]] conditionals that zsh parses differently from bash were auto-approved and now prompt. And Bash Read()/Edit() deny rules did not apply to a < file redirect or to reader commands like tac and egrep; now a deny rule matching any argument or redirect target refuses the whole command. It is like airport screening where unwrapping the item, tucking it in a lining, or booking under a different name used to get it through — those routes are all covered now.

Several ways background sessions failed to start are now closed off

Background sessions — work you hand Claude to run behind the scenes without taking over your current screen — get a batch of "would not start at all" fixes. On macOS npm installs that coincided with Claude Code self-updating, a background session would fail to open; so would one on Windows when a stale daemon lock file (a daemon is a service program that stays resident in the background) pointed at a reused process id. Another case: with a different Claude Code process downloading an npm update, opening a background session reported "Couldn't start the background service"; it now waits for that download to finish. Two cleanup fixes go with it: after a self-update, background sessions still running an older Claude Code binary used to pile up instead of retiring, and are now replaced; and cc-daemon-* folders left in the system temp directory after an interrupted daemon start are now swept by the cleanupPeriodDays retention pass. It is like the first bus stuck at the depot: sometimes the ignition jams, sometimes last shift's roster was not cleared, sometimes the fuel station is not open yet — all cleared at once, and the empty buses that never left are towed back to the lot.

The background session list gets several bookkeeping fixes

This batch fixes claude agents (the screen for managing background sessions) and the CLI misremembering which session is in what state. A session's state.json detail field kept repeating its own original dispatch prompt after a scheduled wake-up instead of updating to the new state. Re-prompting a finished background session should bring it back to the front, but it stayed stuck at its old spot under Completed; Completed now orders by the latest finish. Running claude --bg from a directory that was just deleted used to falsely report "backgrounded" and leave a crashed session row; it now prints the reason and exits with code 1. --resume listed a backgrounded conversation twice, and --continue reopened its stalled pre-background copy; --continue now also opens finished background sessions. It is like a hotel's room board still showing a checked-out guest's name, not updating after a room swap, or listing the same person under two rooms — this pass rechecks the board against what the key cards actually say.

Background sessions respond more honestly to stop signals and status

This batch fixes background sessions not honestly reflecting their state when interrupted or watched. Stashing a prompt with Ctrl+S inside an opened background session used to lose it if that session went idle or was stopped and reopened; it now survives. And claude agents used to say nothing about a background session waiting for you to approve a message from another session, or who sent it — it now shows this clearly. It is like asking someone to cover your shop: you ring the closing bell but the cover never gets the signal and keeps the register open — this batch finally lines up the bell, the cover's status, and the record in your hand.

The claude agents view and subagent transcripts, fixed for visibility and continuity

This batch is about visibility and continuity in claude agents (the screen for managing subagents) and subagent transcripts. Opening a subagent's session with ← from this view used to always inherit the original session's permission mode, overriding the target directory's own defaultMode and that agent's permissionMode; it now follows the target's settings. keybindings.json rebinds of Ctrl+G were ignored inside claude agents; its Ctrl+S / Ctrl+T are now rebindable through a new Agents context. Switching to another subagent's transcript often froze or crawled the usage counter in the corner; it now updates live, for background subagents and teammates too. claude agents --json used to briefly switch the terminal to raw mode and undo another program's terminal settings on exit; it no longer does. A subagent cut off mid-stream by a computer sleep, dropped connection, or server error used to stop at that incomplete response; it now automatically continues. Resuming a subagent you had stopped from its transcript view used to leave the main agent uninformed that you did so; now it is told. A subagent whose transcript grew past 5 MB (common after reading many images) used to fail to resume or message with "No transcript found"; that now works. It is like a security room watching several camera feeds: switching feeds stutters, the remote's buttons do not match the feed you meant to hit, and one camera freezes mid-recording without picking back up — this batch smooths out the feeds, the buttons, and the recording all at once.

Five ways the prompt cache was going stale, fixed together

The prompt cache — remembering conversation content already sent once so the same content is not recomputed or rebilled next time — is a time- and money-saver by design, and this batch fixes several ways it was quietly going stale. Remote Control connecting mid-session used to re-send the Bash tool definition, and that alone missed the cache; it no longer does. Sessions with an advisor model set (an extra model consulted to help the main model decide) used to miss the cache on background requests — compaction, /recap, prompt suggestions — resending the full conversation uncached each time; they now hit the cache. Rewinding a conversation back to empty made /model and /effort show an extra cache warning; it no longer does. Long screenshot-heavy sessions missed the cache on every turn once images exceeded the per-request size cap; that cap issue is fixed. /fork (spinning the current conversation off into a new background session) now keeps the original conversation's cache in that new session, by sending its worktree briefing — the message about the parallel copy of the project Git sets up — as a regular message instead of changing the system prompt. It is like a copy shop's receipt stubs: keeping them should let you check fast, but a few steps kept tearing the stub up and reprinting it each time — this batch stops the tearing, one step at a time.

Two trust gaps in Remote Control are closed

Remote Control — connecting into a running Claude Code from your phone or another device — gets two fixes about consent and whose choice wins. Dismissing the consent prompt, whether by Esc or by pressing n at claude remote-control, was meant as a refusal, but the system recorded it as consent, so the next request connected straight in without asking again. That is fixed: a real refusal now counts as one. The other: a Remote Control session started from the Claude app used to ignore the model you had selected there and run on the machine's default instead; it now runs on the model you selected. It is like a door intercom where pressing "don't let them in" got logged as "already approved," so next time a stranger just walked in — now pressing refuse actually refuses.

The MCP batch: blocked when it should be, cleaned up when it should be, errors now readable

MCP (Model Context Protocol, the standard that lets Claude connect to external tools) gets a batch of connection-management and error-logging fixes. /mcp's reconnect and enable used to still connect a settings-file MCP server that a managed MCP allow/deny list or strictPluginOnlyCustomization (restricting MCP to plugin-supplied servers only) loaded after startup should have blocked; now it is blocked as it should be. With strictPluginOnlyCustomization locking MCP to plugin-only servers, claude mcp remove used to leave a removed remote server's stored OAuth credentials behind; they are now cleaned up too. claude mcp add/remove used to hang or exhaust memory when a project's .mcp.json turned out to be a FIFO (a named pipe file) or a device-file symlink; it now fails fast with an actionable message. WebSocket MCP server connection failures used to log only the unreadable "[object ErrorEvent]"; the underlying error is logged now. And MCP connection and OAuth debug/error logs used to print credentials carried in a server's URL or request headers as-is; they are now redacted. It is like a building's entry log where the visitor list updated but the guard did not, a departed tenant's key was never collected, and the camera feed was too blurry to make out — this batch lines up the list, the keys, and the feed at once.

Sandbox and worktree boundaries: routes that should be blocked, leftovers that should be flagged

Sandbox (the isolated environment keeping Claude's actions inside a safe boundary) and worktree get fixes for boundaries that were not holding, or leftovers nobody flagged. A trailing dot on a network host used to slip past a deniedDomains entry, and "don't ask again" kept re-prompting; both are now handled correctly. A plugin's declared component path, if it was a symlink reaching outside the plugin, could be used to read files outside it; such paths are now refused with an error. Worktree-isolated sessions used to reject Bash loops, $VAR reads, and heredocs that never touch git as too complex; they are now correctly allowed. Sandboxed git in a linked worktree used to lose write access to the shared .git directory after cd into a subdirectory; it no longer does. And /doctor now warns about a stale sandbox mask file left by a killed session. It is like a neighborhood fence: a gap nobody patched, a delivery rider slipping onto someone's balcony, a guard misreading faces — this batch patches the gap, locks the side door, and leaves a note about an old key you forgot to collect.

Settings reload used to miss or forget a few things

This batch fixes a few places where Claude Code did not "reload settings" thoroughly enough. Settings in a .claude/ folder created after startup used to be picked up only after a restart; now they take effect once created. With allowManagedPermissionRulesOnly (only managed rules take effect) turned on, --disallowedTools and session-level deny rules used to be dropped after the first settings reload; they are now kept. And telemetry (OTEL, the standard for reporting usage) values pushed through server-managed settings used to be ignored on a warm start (one that reuses an existing process rather than a full restart), desktop-app Code sessions included; they now apply. It is like changing a rule but never briefing the next shift's guard: some doors stay unlocked that should not, some old rules linger that should have been dropped, the announcement system goes deaf on some channels — this batch fills in the handover notes.

The terminal-UI batch: smoother rendering, a few stuck spots cleared

This batch makes the terminal UI run smoother in long conversations and clears a few stuck spots. Rendering is improved: less work to redraw each turn in long conversations, streaming no longer slows down as a reply grows, and background-agent updates no longer redraw the whole screen. The input box also redraws less per keystroke, cutting typing lag. Fixes: the working spinner used to stop turning — looking stuck — while a response streamed behind a slash-command panel, and no longer does; a phantom duplicate slash-command row used to appear below the in-flight turn while an auto-continued response streamed, and no longer does; fullscreen mode used to block clicking ! shell-command output to expand it, and now allows it; pasting ANSI-colored text (like a CI log) into a dialog such as /feedback used to crash, and no longer does. Also, emoji autocomplete now accepts the remaining GitHub/Slack shortcode aliases (:satisfied:, :telephone:, :collision:, and others). It is like tuning an old film projector's belt, focus ring, and gate all at once — the picture stops shaking, and the spots that used to jam run smoothly again.

The headless and long-stream batch: no more hanging up early, no more spinning quietly in place

This batch fixes headless mode (no terminal window, common in scripts or CI) and long-lived streams either not waiting when they should, or not stopping when they should. claude -p used to exit about 5 seconds after printing its final result even if a Monitor (a background watch task) the model had armed was still running; it now waits for that watch to actually fire or time out. Reading piped input with claude -p --input-format stream-json, if what came in was not valid JSONL (one JSON object per line), used to grow memory without bound; it now fails fast with a clear error. Sessions using the Proactive output style used to busy-loop with filler messages and repeated log reads instead of idling quietly while a background command or Monitor they had started was still running; they now idle honestly. On Bedrock and Bedrock Mantle with Opus 4.7 and later, long hidden-thinking phases (the model reasoning behind the scenes, invisible on screen) used to go silent and get cut by an idle timeout; the stream now carries progress events so it is not mistaken for unresponsive. And on the SDK-host side, liveness reporting is improved while a response is held open by gateway keep-alives, so long waits under a raised CLAUDE_STREAM_IDLE_TIMEOUT_MS are no longer mistaken for a hung session. It is like a call-center hold line: one variant hangs up on you early, another chokes on a garbled instruction until memory overflows, another has the agent fake being busy while doing nothing, and another just goes silent until you assume the line dropped — this batch straightens the hold line out, piece by piece.

The rest of this version's loose ends: scheduling, teammates, credentials, a few CLI touches

This card gathers the rest of this version's unrelated small fixes and touches. /schedule (the scheduling feature): a routine whose saved prompt was missing a message role used to fire at its scheduled time and run with nothing to do; it now runs properly. A teammate's (the peer role in multi-agent collaboration) permission request, if it landed just as the leader's mailbox write was briefly locked, used to get answered twice; now only once. Agent-team teammates in tmux or iTerm2 panes sometimes stayed open after acknowledging a shutdown request; they now actually close. Cloud sessions whose network proxy failed to start at launch used to lose git/GitHub credentials for the rest of the session; it now retries in the background and recovers. Three small CLI improvements: /code-review --comment can now post findings on GitLab merge requests via glab mr note instead of reporting the target as unsupported; an MCP elicitation (a request for more information from you) or permission ask queued behind another dialog now sends its idle desktop notification at the same delay as a visible one; claude self-hosted-runner --configure-git now also enables git push negotiation, so the first push of a new branch from a clone that has sat around for a while uploads only the new commits instead of the whole tree; and in verbose/transcript output, several async hook completion notices arriving together now appear on one line instead of flooding the screen one line per hook. It is like clearing out the bottom drawer of a desk: a dried-up pen, a paperclip box that never made it back, an expired sticky note — none of it related to the others, but everything is easier to find once it is tidy.

The VSCode extension batch: sidebar tidy-up, model switching, accessibility fixes

This release's updates to the VSCode extension — Microsoft's code editor — center on tidying the side panel and clearing a few stuck spots. The session list gains collapsible ACCOUNT & USAGE and SESSION MANAGER headers holding the account email, the usage meter, and a link that opens the usage dialog; the input footer gains a model pill showing the current model and opening the picker, with an Effort row and a More models page; the Ungrouped section can now be collapsed; and the command menu can select an output style, custom ones included. Fixes: third-party provider deployments such as Bedrock and Vertex were still showing claude.ai-only features and a leftover login, now hidden; the usage meter that stayed blank after the panel loaded now shows the last known usage first; the Enable Remote Control for all sessions toggle now applies to already-open sessions; two screen-reader announcement bugs are corrected. Delete session is renamed Archive session, with archived items moving to a collapsible Archived sessions group at the bottom and an Unarchive action; the action menu now lists slash commands in a filterable dialog instead of inline, and the MCP servers dialog gained the same filter box. It is like relabelling a stuffed chest of drawers, fitting handles that actually pull, and oiling the few drawers that jammed.
