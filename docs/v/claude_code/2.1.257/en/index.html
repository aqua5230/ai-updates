Claude Code 2.1.257

Released: 2026-09-01

Release notes

FEATURE

Fable 5.1 lands as the local default; gateways stay on Fable 5 for now

When you pick the Fable model in Claude Code, you now get the new Fable 5.

1 (model id claude-fable-5-1), which has taken over as the default for the Fable line. It takes in a million tokens at once — the unit of text an AI weighs in a single pass — enough for the code of a whole large project in one go. Pricing is $10 per million input tokens and $50 per million output; cached content costs $0.25 per million to read again, so repeated questions about the same files are far cheaper. One transitional catch: sessions run through the official gateway (the middle layer that forwards requests to a model) still resolve fable and best to Fable 5, since gateways not yet configured for 5.1 reject it — pick Fable 5.1 in /model yourself.

A new engine is already standard on the showroom floor, but a partner garage's pumps have not switched fuel grades, so driving in you get the old fuel unless you ask for the new one.
FEATURE

Choose how times are shown, and in which time zone

Claude Code stamps a time at the end of every turn, and each message in the transcript — the plain-text record of the whole conversation — carries a timestamp too.

That format used to be fixed. Now there are two settings: timeFormat sets the style and accepts 12-hour, 24-hour, 24-hour UTC, or an strftime pattern (codes like %H:%M that let you spell out the shape of the time yourself); timeZone sets which zone the clock is converted to. Add them in settings.json, for example:

{
  "timeFormat": "24-hour",
  "timeZone": "America/New_York"
}

It is like swapping the wall clock for a face you find easy to read, then setting it to the time in your own city.
FEATURE

Auto mode tightens three gates: cloud credentials, files outside your working directories, other people's artifacts

When you let Claude run a long stretch of work in auto mode — where it acts without checking each step with you — it now holds back three more kinds of action.

First, a Containment Escape rule: fetching a cloud host's metadata credentials (a piece of information a cloud platform hands out in exchange for access), slipping past outbound-traffic limits, or reaching across tenants to read someone else's resources are no longer auto-approved unless your environment marks them as expected. Second, a one-time prompt the first time it wants to read a file outside your working directories; block it on the spot, or for good with {"permissions": {"blockReadsOutsideWorkingDirectories": true}} in settings.json. Third, in Cowork and claude.ai cloud sessions, reading an artifact (a file produced by a conversation) that is not yours now always asks you first, even in auto mode.

It is like asking someone to house-sit: they move around the rooms freely, but rummaging in drawers for keys, using the back door, or stepping into the neighbour's place are things they check with you first.
FEATURE

One environment variable forces every subagent onto the same model

When you have Claude fan out across several subagents — the helpers the main conversation dispatches to each do a slice of the work — each one may carry its own assigned model: some set at dispatch time, some hard-coded in an agent definition file.

Switching them all to one model used to mean hunting each down. Now there is an environment variable, CLAUDE_CODE_SUBAGENT_MODEL_FORCE — a setting made at the system level and read when the program starts. Turn it on and the model named by CLAUDE_CODE_SUBAGENT_MODEL (or the main conversation's model if none is named) applies to every subagent, and those per-subagent choices are all ignored. Handy when you want to hold costs down, or keep a whole batch of work consistent, in one move.

It is like taking a group out for the day and announcing everyone rides the same bus — the tickets people booked separately no longer count.
FEATURE

Change effort for just this session, leaving your long-term setting alone

/effort tunes how long Claude thinks before answering — higher effort means deeper reasoning but slower and pricier; lower is the reverse.

Using it used to change the setting for the long term, so every later session (one conversation from open to close) inherited it. Now the /effort menu has an s option: pick it and only the current session changes, and closing the window returns you to your own default — matching what /model has done for a while. Separately, when you move to a new model, the default-effort hold it ships with now locks only this session rather than permanently; and if you connected via Remote Control after picking an effort on claude.ai, that choice now applies during the hold.

It is like a camera's "use this ISO for this shot" — after the frame it snaps back to your usual setting instead of overwriting it.
FEATURE

Gateway-discovered models can now carry a description in the picker

Some companies let Claude Code reach a set of internal models through their own gateway — the middle layer that forwards requests to a model — switched on by the environment variable CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY.

Those models used to appear in the /model picker as bare names with nothing to tell them apart. Now the gateway can attach a description to each one and the picker shows it; entries without one still read "From gateway". A paired change: this discovery step now runs even when you have set CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC (which turns off non-essential outbound calls), because it only queries your own gateway and reaches nothing outside.

It is like a buffet's labels: each slot used to show just a dish name, now some add "chef's pick, mild heat", and the ones nobody labelled still show the plain name.
FEATURE

The keys for stepping through side questions have changed

/btw (short for by the way) lets you slip Claude a quick question without derailing the main task, then return to the original answer.

Paging between these side exchanges used to be ←/→, which clashed with what the arrow keys do elsewhere. It is now Shift+←/Shift+→, or [/], stepping through your recent side questions and back to the live answer. A separate snag is fixed: with the /btw panel open inside a claude agents session (the screen for managing subagents), pressing ← did nothing; it now takes you back to the agents list even mid-answer, and the panel returns when you reopen that session.

It is like the temporary sticky notes you tuck into a book: flipping through the notes is a separate gesture from turning the pages, so one stray swipe does not throw you out of the chapter you were reading.
FEATURE

Two `/add-dir` changes: network paths refused, subfolders of the current directory accepted

/add-dir — along with --add-dir at startup and additionalDirectories in settings — brings an extra folder into Claude's working scope, loading that folder's skills, commands and agents with it.

This release cleans up two faults pointing opposite ways. One is network paths: Windows UNC shares and /net/<host> automounts are now refused with a message before anything touches them, and Windows users should use a mapped drive letter instead. The other is a subfolder right under your current working directory, which /add-dir used to reject for no reason; it is now accepted, and its skills, commands and agents load just as --add-dir does at startup.

It is like a door-entry system that had been shutting out a neighbour from the same building while leaving a remote dial-in from a stranger wide open — both ends are set right now.
FEATURE

Setting `bypassPermissions` in a project folder no longer works

bypassPermissions is the most permissive mode, where Claude acts on almost anything without asking.

It used to be enough to set defaultMode to "bypassPermissions" in a project's .claude/settings.json or .claude/settings.local.json, and opening that project dropped you into the mode. The trouble is that such files travel with the code, so anyone who hands you a project could decide your machine runs unguarded. Now that value is ignored at the project level and behaves like "auto". To really use the mode, set it in user or managed settings, or pass --permission-mode at each startup.

It is like your front-door key: you get to decide whether to leave the door unlocked, but a note someone slipped into your mailbox does not get to make that call for you.
FEATURE

Company-pushed settings: apply sooner, report failures better, clamp extreme values

If your Claude Code is centrally configured by your company through managed settings, this batch fixes faults along that path.

A policyHelper (the small program that checks company policy) shadowed at launch by cached settings used to wait until next launch to update; now it runs or exits as soon as the server reports that setting removed. Under managedSourcesBehavior: "merge", sandbox.credentials.awsPairs and sandbox.ripgrep are now taken whole from the highest source that sets them, not blended; timeoutMs and refreshIntervalMs above the timer maximum (2147483647) no longer fail outright, and are clamped instead. Diagnostics are clearer: refresh failures show in /status, declining prints why it exited, timeouts are reported as timeouts; the approval dialog also shows matching telemetry wording when the settings also touch tracing, raw API logging, or trace export.

It is like a company's standard form that used to overwrite fields and bounce back with no reason — now it flags mistakes as you type, fixes out-of-range entries, and explains a bounce.
FEATURE

Stray credentials and leftover identities sent to cloud providers are cleaned up

For anyone running Claude Code through Bedrock, Vertex or Foundry, this batch fixes login details getting into outgoing requests.

A doubly-listed custom Authorization header used to override your configured credential (Bedrock, Mantle, Vertex, WIF all affected); the Vertex setup wizard picked up a leftover profile from ~/.config/anthropic; the official gateway sent stray headers to Foundry, Vertex and Bedrock, and Foundry's Entra ID upstream failed to start when ANTHROPIC_FOUNDRY_API_KEY was set; API-key mode against a Foundry key sent a leftover Anthropic key alongside it. None of that happens now, and gateway sign-in and token refresh now verify the pinned TLS certificate too. Also, launching after a session expired now says "ended" and offers /login; the keyless Console sign-in now applies your organization's settings and /status shows the Organization.

It is like changing planes with someone else's documents mixed into your bag, stopped at every checkpoint — now the bag is cleared before check-in.
FEATURE

The permission-prompt batch: one old hint gone, several sneaky forms now caught

This group is all about whether Claude stops to ask you.

On the surface, the Ctrl+E command-explanation line under Bash and PowerShell permission prompts is gone, and the Edit prompt's diff view — which had been miscounting the width of emoji and characters built from several code points, skewing the layout — now lines up. The substantive part is three holes closed: a permissions.ask rule (one that requires asking first) was skipped in auto mode when the matching command ran inside a long compound command or a subshell, running without a prompt; it is caught now. Certain [[ ]] conditionals that zsh parses differently from bash were auto-approved and now prompt. And Bash Read()/Edit() deny rules did not apply to a < file redirect or to reader commands like tac and egrep; now a deny rule matching any argument or redirect target refuses the whole command.

It is like airport screening where unwrapping the item, tucking it in a lining, or booking under a different name used to get it through — those routes are all covered now.
BUGFIX

Several ways background sessions failed to start are now closed off

Background sessions — work you hand Claude to run behind the scenes without taking over your current screen — get a batch of "would not start at all" fixes.

On macOS npm installs that coincided with Claude Code self-updating, a background session would fail to open; so would one on Windows when a stale daemon lock file (a daemon is a service program that stays resident in the background) pointed at a reused process id. Another case: with a different Claude Code process downloading an npm update, opening a background session reported "Couldn't start the background service"; it now waits for that download to finish. Two cleanup fixes go with it: after a self-update, background sessions still running an older Claude Code binary used to pile up instead of retiring, and are now replaced; and cc-daemon-* folders left in the system temp directory after an interrupted daemon start are now swept by the cleanupPeriodDays retention pass.

It is like the first bus stuck at the depot: sometimes the ignition jams, sometimes last shift's roster was not cleared, sometimes the fuel station is not open yet — all cleared at once, and the empty buses that never left are towed back to the lot.
BUGFIX

The background session list gets several bookkeeping fixes

This batch fixes claude agents (the screen for managing background sessions) and the CLI misremembering which session is in what state.

A session's state.json detail field kept repeating its own original dispatch prompt after a scheduled wake-up instead of updating to the new state. Re-prompting a finished background session should bring it back to the front, but it stayed stuck at its old spot under Completed; Completed now orders by the latest finish. Running claude --bg from a directory that was just deleted used to falsely report "backgrounded" and leave a crashed session row; it now prints the reason and exits with code 1. --resume listed a backgrounded conversation twice, and --continue reopened its stalled pre-background copy; --continue now also opens finished background sessions. And claude --resume <session-id> --bg now continues that session under its own ID when nothing is running it, instead of quietly starting a copy — and announces it when a copy really is started.

It is like a hotel's room board still showing a checked-out guest's name, not updating after a room swap, or listing the same person under two rooms — this pass rechecks the board against what the key cards actually say.
BUGFIX

Background sessions respond more honestly to stop signals and status

This batch fixes background sessions not honestly reflecting their state when interrupted or watched.

Stashing a prompt with Ctrl+S inside an opened background session used to lose it if that session went idle or was stopped and reopened; it now survives. Backgrounding a turn with ← or Ctrl+B while a subagent or other tool happened to be running would occasionally make the background session wrongly treat that tool as rejected when it should have re-run; it now re-runs correctly. Stopping a background command from the tasks panel or a connected client used to leave Claude uninformed; now it is told. Stopping a background subagent used to leave the monitors it had started (a monitor is a background watcher that notifies you when something finishes or times out) still running; now they stop with it. A background command detached from its shell with timeout or setsid used to survive stopping a task or exiting Claude Code; it now ends too. And claude agents used to say nothing about a background session waiting for you to approve a message from another session, or who sent it — it now shows this clearly.

It is like asking someone to cover your shop: you ring the closing bell but the cover never gets the signal and keeps the register open — this batch finally lines up the bell, the cover's status, and the record in your hand.
BUGFIX

The claude agents view and subagent transcripts, fixed for visibility and continuity

This batch is about visibility and continuity in claude agents (the screen for managing subagents) and subagent transcripts.

Opening a subagent's session with ← from this view used to always inherit the original session's permission mode, overriding the target directory's own defaultMode and that agent's permissionMode; it now follows the target's settings. keybindings.json rebinds of Ctrl+G were ignored inside claude agents; its Ctrl+S / Ctrl+T are now rebindable through a new Agents context. Switching to another subagent's transcript often froze or crawled the usage counter in the corner; it now updates live, for background subagents and teammates too. claude agents --json used to briefly switch the terminal to raw mode and undo another program's terminal settings on exit; it no longer does. A subagent cut off mid-stream by a computer sleep, dropped connection, or server error used to stop at that incomplete response; it now automatically continues. Resuming a subagent you had stopped from its transcript view used to leave the main agent uninformed that you did so; now it is told. A subagent whose transcript grew past 5 MB (common after reading many images) used to fail to resume or message with "No transcript found"; that now works.

It is like a security room watching several camera feeds: switching feeds stutters, the remote's buttons do not match the feed you meant to hit, and one camera freezes mid-recording without picking back up — this batch smooths out the feeds, the buttons, and the recording all at once.
BUGFIX

Five ways the prompt cache was going stale, fixed together

The prompt cache — remembering conversation content already sent once so the same content is not recomputed or rebilled next time — is a time- and money-saver by design, and this batch fixes several ways it was quietly going stale.

Remote Control connecting mid-session used to re-send the Bash tool definition, and that alone missed the cache; it no longer does. Sessions with an advisor model set (an extra model consulted to help the main model decide) used to miss the cache on background requests — compaction, /recap, prompt suggestions — resending the full conversation uncached each time; they now hit the cache. Rewinding a conversation back to empty made /model and /effort show an extra cache warning; it no longer does. Long screenshot-heavy sessions missed the cache on every turn once images exceeded the per-request size cap; that cap issue is fixed. /fork (spinning the current conversation off into a new background session) now keeps the original conversation's cache in that new session, by sending its worktree briefing — the message about the parallel copy of the project Git sets up — as a regular message instead of changing the system prompt.

It is like a copy shop's receipt stubs: keeping them should let you check fast, but a few steps kept tearing the stub up and reprinting it each time — this batch stops the tearing, one step at a time.
BUGFIX

Two trust gaps in Remote Control are closed

Remote Control — connecting into a running Claude Code from your phone or another device — gets two fixes about consent and whose choice wins.

Dismissing the consent prompt, whether by Esc or by pressing n at claude remote-control, was meant as a refusal, but the system recorded it as consent, so the next request connected straight in without asking again. That is fixed: a real refusal now counts as one. The other: a Remote Control session started from the Claude app used to ignore the model you had selected there and run on the machine's default instead; it now runs on the model you selected.

It is like a door intercom where pressing "don't let them in" got logged as "already approved," so next time a stranger just walked in — now pressing refuse actually refuses.
FEATURE

The MCP batch: blocked when it should be, cleaned up when it should be, errors now readable

MCP (Model Context Protocol, the standard that lets Claude connect to external tools) gets a batch of connection-management and error-logging fixes.

/mcp's reconnect and enable used to still connect a settings-file MCP server that a managed MCP allow/deny list or strictPluginOnlyCustomization (restricting MCP to plugin-supplied servers only) loaded after startup should have blocked; now it is blocked as it should be. With strictPluginOnlyCustomization locking MCP to plugin-only servers, claude mcp remove used to leave a removed remote server's stored OAuth credentials behind; they are now cleaned up too. claude mcp add/remove used to hang or exhaust memory when a project's .mcp.json turned out to be a FIFO (a named pipe file) or a device-file symlink; it now fails fast with an actionable message. WebSocket MCP server connection failures used to log only the unreadable "[object ErrorEvent]"; the underlying error is logged now. And MCP connection and OAuth debug/error logs used to print credentials carried in a server's URL or request headers as-is; they are now redacted.

It is like a building's entry log where the visitor list updated but the guard did not, a departed tenant's key was never collected, and the camera feed was too blurry to make out — this batch lines up the list, the keys, and the feed at once.
FEATURE

Sandbox and worktree boundaries: routes that should be blocked, leftovers that should be flagged

Sandbox (the isolated environment keeping Claude's actions inside a safe boundary) and worktree get fixes for boundaries that were not holding, or leftovers nobody flagged.

A trailing dot on a network host used to slip past a deniedDomains entry, and "don't ask again" kept re-prompting; both are now handled correctly. A plugin's declared component path, if it was a symlink reaching outside the plugin, could be used to read files outside it; such paths are now refused with an error. Worktree-isolated sessions used to reject Bash loops, $VAR reads, and heredocs that never touch git as too complex; they are now correctly allowed. Sandboxed git in a linked worktree used to lose write access to the shared .git directory after cd into a subdirectory; it no longer does. And /doctor now warns about a stale sandbox mask file left by a killed session.

It is like a neighborhood fence: a gap nobody patched, a delivery rider slipping onto someone's balcony, a guard misreading faces — this batch patches the gap, locks the side door, and leaves a note about an old key you forgot to collect.
BUGFIX

Settings reload used to miss or forget a few things

This batch fixes a few places where Claude Code did not "reload settings" thoroughly enough.

Settings in a .claude/ folder created after startup used to be picked up only after a restart; now they take effect once created. With allowManagedPermissionRulesOnly (only managed rules take effect) turned on, --disallowedTools and session-level deny rules used to be dropped after the first settings reload; they are now kept. And telemetry (OTEL, the standard for reporting usage) values pushed through server-managed settings used to be ignored on a warm start (one that reuses an existing process rather than a full restart), desktop-app Code sessions included; they now apply.

It is like changing a rule but never briefing the next shift's guard: some doors stay unlocked that should not, some old rules linger that should have been dropped, the announcement system goes deaf on some channels — this batch fills in the handover notes.
FEATURE

The terminal-UI batch: smoother rendering, a few stuck spots cleared

This batch makes the terminal UI run smoother in long conversations and clears a few stuck spots.

Rendering is improved: less work to redraw each turn in long conversations, streaming no longer slows down as a reply grows, and background-agent updates no longer redraw the whole screen. The input box also redraws less per keystroke, cutting typing lag. Fixes: the working spinner used to stop turning — looking stuck — while a response streamed behind a slash-command panel, and no longer does; a phantom duplicate slash-command row used to appear below the in-flight turn while an auto-continued response streamed, and no longer does; fullscreen mode used to block clicking ! shell-command output to expand it, and now allows it; pasting ANSI-colored text (like a CI log) into a dialog such as /feedback used to crash, and no longer does. Also, emoji autocomplete now accepts the remaining GitHub/Slack shortcode aliases (:satisfied:, :telephone:, :collision:, and others).

It is like tuning an old film projector's belt, focus ring, and gate all at once — the picture stops shaking, and the spots that used to jam run smoothly again.
FEATURE

The headless and long-stream batch: no more hanging up early, no more spinning quietly in place

This batch fixes headless mode (no terminal window, common in scripts or CI) and long-lived streams either not waiting when they should, or not stopping when they should.

claude -p used to exit about 5 seconds after printing its final result even if a Monitor (a background watch task) the model had armed was still running; it now waits for that watch to actually fire or time out. Reading piped input with claude -p --input-format stream-json, if what came in was not valid JSONL (one JSON object per line), used to grow memory without bound; it now fails fast with a clear error. Sessions using the Proactive output style used to busy-loop with filler messages and repeated log reads instead of idling quietly while a background command or Monitor they had started was still running; they now idle honestly. On Bedrock and Bedrock Mantle with Opus 4.7 and later, long hidden-thinking phases (the model reasoning behind the scenes, invisible on screen) used to go silent and get cut by an idle timeout; the stream now carries progress events so it is not mistaken for unresponsive. And on the SDK-host side, liveness reporting is improved while a response is held open by gateway keep-alives, so long waits under a raised CLAUDE_STREAM_IDLE_TIMEOUT_MS are no longer mistaken for a hung session.

It is like a call-center hold line: one variant hangs up on you early, another chokes on a garbled instruction until memory overflows, another has the agent fake being busy while doing nothing, and another just goes silent until you assume the line dropped — this batch straightens the hold line out, piece by piece.
FEATURE

The rest of this version's loose ends: scheduling, teammates, credentials, a few CLI touches

This card gathers the rest of this version's unrelated small fixes and touches.

/schedule (the scheduling feature): a routine whose saved prompt was missing a message role used to fire at its scheduled time and run with nothing to do; it now runs properly. A teammate's (the peer role in multi-agent collaboration) permission request, if it landed just as the leader's mailbox write was briefly locked, used to get answered twice; now only once. Agent-team teammates in tmux or iTerm2 panes sometimes stayed open after acknowledging a shutdown request; they now actually close. Cloud sessions whose network proxy failed to start at launch used to lose git/GitHub credentials for the rest of the session; it now retries in the background and recovers. Three small CLI improvements: /code-review --comment can now post findings on GitLab merge requests via glab mr note instead of reporting the target as unsupported; an MCP elicitation (a request for more information from you) or permission ask queued behind another dialog now sends its idle desktop notification at the same delay as a visible one; claude self-hosted-runner --configure-git now also enables git push negotiation, so the first push of a new branch from a clone that has sat around for a while uploads only the new commits instead of the whole tree; and in verbose/transcript output, several async hook completion notices arriving together now appear on one line instead of flooding the screen one line per hook.

It is like clearing out the bottom drawer of a desk: a dried-up pen, a paperclip box that never made it back, an expired sticky note — none of it related to the others, but everything is easier to find once it is tidy.
BUGFIX

The VSCode extension batch: sidebar tidy-up, model switching, accessibility fixes

This release's updates to the VSCode extension — Microsoft's code editor — center on tidying the side panel and clearing a few stuck spots.

The session list gains collapsible ACCOUNT & USAGE and SESSION MANAGER headers holding the account email, the usage meter, and a link that opens the usage dialog; the input footer gains a model pill showing the current model and opening the picker, with an Effort row and a More models page; the Ungrouped section can now be collapsed; and the command menu can select an output style, custom ones included. Fixes: third-party provider deployments such as Bedrock and Vertex were still showing claude.ai-only features and a leftover login, now hidden; the usage meter that stayed blank after the panel loaded now shows the last known usage first; the Enable Remote Control for all sessions toggle now applies to already-open sessions; two screen-reader announcement bugs are corrected. Delete session is renamed Archive session, with archived items moving to a collapsible Archived sessions group at the bottom and an Unarchive action; the action menu now lists slash commands in a filterable dialog instead of inline, and the MCP servers dialog gained the same filter box.

It is like relabelling a stuffed chest of drawers, fitting handles that actually pull, and oiling the few drawers that jammed.
