Claude Code 2.1.246

Released: 2026-08-25

Release notes

FEATURE

Auto mode classifier tab in permissions, with scaled timeout for long sessions

Like an automated factory inspection station where operators can tune safety thresholds directly on the console, and where the belt extends inspection time during huge shipments instead of rejecting packages.

Managing the boundaries of auto mode is now much more straightforward.

Running /permissions introduces a dedicated Auto mode tab for viewing and editing classifier rules. Furthermore, tool calls during very large sessions are no longer denied with a "temporarily unavailable" error; the safety-check deadline now scales dynamically with prompt size, giving extensive sessions ample time to complete validation.

FEATURE

Startup warnings for Bash wildcard rules, with faster snapshot replay

Security checks and execution latency for Bash commands are significantly improved.

When defining Bash allow rules with a wildcard placed before the subcommand (such as Bash(git * main)), Claude Code now displays a startup warning because that pattern also inadvertently matches options inserted before the subcommand. Malformed commands that leave a trailing && or || operator dangling will now strictly require explicit user approval. Furthermore, executing the Bash tool in bash environments now replays snapshot functions without spawning an extra base64 subshell per function, speeding up command startup.

Like building security auditing guest badges to flag loose registration formats and halt incomplete passes while streamlining routine stamp processing.
BUGFIX

Resilient background session startup, surviving sleep and npm reinstalls

Like a dispatch vehicle that waits patiently when its depot relocates, the driver naps, or the garage swaps parts, rather than scrapping the entire run after 45 seconds.

Launching background sessions is now significantly more dependable across edge cases.

Previously, if the starting directory was removed, the computer slept, or the host was slow to spawn processes, background sessions would fail to open after 45 seconds; these delays are now handled smoothly. Background service startup no longer crashes with an EACCES error when another Claude Code instance is reinstalling npm packages at that exact moment. On Windows and other platforms, opening a freshly spawned session in claude agents while its worker boots no longer halts it prematurely with an in-flight respawn error.

FEATURE

Numbered duplicate background tasks, safe worktrees, and headless cleanup

Managing multiple background tasks in the terminal is cleaner and safer.

When viewing claude agents, backgrounding a conversation that shares a name with an existing session no longer prints identical duplicate rows; instead, it automatically appends an incremental number (such as my-session (2)). The background retention cleanup sweep will no longer remove git worktrees (a Git feature for opening parallel working copies of a project) located under .claude/worktrees/ that you created manually, even if an older session points toward them. Additionally, on Windows and macOS, headless sessions cleanly purge stale records in ~/.claude/sessions left behind after unexpected terminations.

Like a warehouse supervisor tagging repeat packages with unique series numbers, leaving employee lockers untouched during maintenance, and shredding orphaned packing slips.
FEATURE

Protected finished subagents and capped idle check-ins for /goal

Like a team coordinator assigning multiple assistants who won't recall completed helpers if someone bumps the back button, marks unfinished shifts clearly, and knocks on the office door at most 3 times during idle periods.

Subagent workflows are much more cooperative.

Pressing the left arrow key or running /background during a dynamic workflow no longer silently restarts already-finished subagents; it asks for confirmation first and displays how many subagents would restart. When a subagent hits its maxTurns limit, it returns output marked as partial with a hint to resume via SendMessage, rather than masquerading as fully finished. For /goal tasks, idle sessions now start at most three check-ins on long-running background jobs, with your next message allowing three more.

BUGFIX

Explicit MCP tool interruption errors and real parameter types

Tool invocations and permission prompts over MCP (Model Context Protocol, an open standard connecting AI to external tools) are far more reliable.

In headless or remote sessions, if an MCP tool call is interrupted by an incoming message, Claude now receives an explicit interrupted error instead of an empty successful output. Tool parameters with empty schemas ({}) receive arguments matching their real data types rather than raw JSON strings. Under --strict-mcp-config, Claude Code skips permission prompts for .mcp.json servers that will never load, preventing background sessions from hanging at startup. Interactive tools marked requiresUserInteraction also no longer show the non-functional "Yes, and don't ask again" choice.

Like an external peripheral protocol standardizing interrupt codes and parameter types while discarding redundant pairing alerts.
BUGFIX

Smooth fullscreen resizing and navigation, with reduced transcript memory

Like upgrading to an e-reader for massive manuscripts that never blanks out when resized, scrolls seamlessly through older chapters, protects button clicks, and stays lightweight across thousands of pages.

Fullscreen and transcript view interactions are noticeably smoother.

Resizing the terminal in fullscreen mode no longer renders a blank transcript or snaps to the bottom until the next keystroke. Scrolling through older messages and jumping to the bottom no longer stutters mid-transcript. Clicking the terminal window simply to restore window focus won't shift keyboard focus onto the UI control sitting under the cursor. Additionally, message rows in fullscreen and Ctrl+O views no longer hold copies of tool lookup tables, stopping memory growth on long sessions.

FEATURE

Completion timestamps per turn, with truncated long diff lines

Terminal output and status formatting are much more informative.

The duration line at the end of each turn now appends the exact completion timestamp (such as ✻ Sautéed for 23s · done 6:05 PM). When a code diff contains a massive single line (like a base64 string), Claude Code truncates it with a marker to prevent terminal slowdowns. Markdown parsing no longer disables rendering across an entire response simply because the first 500 characters lacked formatting, and properly formats + and N) lists alongside setext headings. If a running shell command is aborted mid-run, the interface explicitly marks it as cut rather than printing a deceptive finished message.

Like a kitchen timer stamping finish times, folding endless recipe lines, and showing an alert when power cuts early.
BUGFIX

Special prompt comments preserved, with clean file pickers and null byte completion

Like a smart typing assistant that drops suggestion popups when no valid matches remain, ignores code comment slashes, and handles special characters in folder names without freezing.

Input parsing and path autocompletion handle edge cases gracefully.

Prompts beginning with /-- (such as Lean doc comments) are cleanly forwarded to Claude rather than being rejected as nonexistent slash commands. The @ file picker automatically dismisses itself as soon as typed characters stop matching any filesystem path. Furthermore, path autocompletion no longer breaks when completion tokens or directory paths contain null bytes.

BUGFIX

Theme prompt border preservation on rename, with custom diff colors

Theme styling and keyboard customization are much more resilient.

Running /rename to title a session now preserves your active theme prompt border color (including custom theme promptBorder definitions) instead of reverting to default cyan unless changed with /color. Custom theme diff highlights (diffAdded, diffRemoved, and their dimmed variants) correctly display in rendered diffs and within the /theme preview. Furthermore, binding an unrecognized action name in keybindings.json no longer deadens that key; Claude Code now skips the invalid action, keeps the default keybinding alive, and logs a descriptive warning when launched with --debug.

Like updating an office nameplate without repainting the door, applying custom color palettes accurately, and preventing a single miswired switch from disabling the panel.
BUGFIX

Status line persistence across views, with accurate timezone heatmaps

Like a trip odometer and punch clock where checking another dashboard tab doesn't wipe your recorded mileage, and calendar grids align across global timezones.

Status metrics and usage charts now report accurate figures.

Navigating between the main conversation and the agent task view no longer clears the status line's accumulated cost and session duration back to zero. Additionally, running /stats in timezones east of UTC no longer shifts daily activity heatmap cells by one day (which previously plotted Sunday counts under Monday), ensuring daily totals match your actual calendar schedule.

FEATURE

Instant /cd workspace updates, with preserved fork history and plan mode

Switching directories and continuing workflows is much smoother.

When running /cd to navigate into another project directory, its project settings, hooks (small automated scripts triggered by events), approvable .mcp.json servers, skills, and agents take effect immediately without requiring --resume. Running /fork from an already-forked or backgrounded session now brings along the active conversation history instead of opening a blank screen. Furthermore, sessions that ended in plan mode properly remain in plan mode when resumed within the VS Code extension or via claude -p --continue without explicit permission mode flags.

Like walking into a new conference room with all audio gear connecting instantly, branching meeting agendas without losing notes, and resuming suspended project plans seamlessly.
FEATURE

Simplified plugin updates, UTF-8 BOM compatibility, and clean cache dirs

Like an app store enhancing package installation and caching so bare name updates, encoded headers, and corrupted catalog files report clear errors without wasting disk space.

Plugin management and caching are much more polished.

Running claude plugin update now accepts an installed plugin's bare name without requiring fully-qualified namespace identifiers. Installing plugins whose plugin.json files contain UTF-8 byte-order marks (BOM) no longer fails. If known_marketplaces.json is corrupted or empty, claude plugin install prints a helpful error rather than hanging or silently exiting. Furthermore, plugin caching stops creating duplicate SHA-named directories for the same package, and OpenTelemetry events for plugins synced from claude.ai correctly log authentic marketplace metadata and admin-installed status.

BUGFIX

Clean plugin skill prefixes, nested skill reloading, and hook error paths

Plugin skills and hooks (automated scripts triggered by specific events) now resolve naming and directory paths accurately.

When a plugin skill includes the <plugin>: prefix in its frontmatter name, slash menus no longer render doubled prefixes like /plugin:plugin:skill. Running /reload-plugins correctly discovers skills organized under the skills/*/SKILL.md file pattern instead of mistakenly reporting zero skills. Furthermore, hook error messages print the fully-resolved local plugin path instead of displaying the unexpanded literal ${CLAUDE_PLUGIN_ROOT} template string.

Like an internal phone directory stripping accidental duplicate country codes, locating sub-extensions, and citing exact office room numbers on system errors.
BUGFIX

Compatibility with custom gateways, and strict telemetry key isolation

Like a border checkpoint distinguishing passport formats that tolerates minor structural differences while ensuring custom transit passes never leak back to global headquarters.

Using Anthropic-compatible third-party gateways and proxies is safer and more reliable.

When a custom endpoint (ANTHROPIC_BASE_URL) streams a tool_use payload without an id, Claude Code no longer halts with a UI rendering error. Resuming sessions whose histories include proxy-generated tool blocks rejected by Anthropic APIs will no longer cause continuous 400 errors on each turn. Crucially, telemetry and metrics sent to Anthropic will no longer carry the API key designated for third-party gateways; credentials are sent strictly to their matching host.

FEATURE

Automatic JWT refresh on idle, with autonomous code reviews across platforms

Authentication handling and enterprise telemetry attribution have been updated.

When using apiKeyHelper to fetch short-lived JWT tokens (authentication strings proving identity), sending a prompt after an idle period now refreshes expired cached tokens before transmission and quietly retries on 401 or 403 status codes. Usage metrics for workload identity federation sessions, startup helper scripts, and post-idle token refreshes are also accurately attributed to your organization. Furthermore, Claude can now autonomously trigger /code-review across Bedrock, Vertex AI, Foundry, the Claude apps gateway, and setups where non-essential traffic is disabled.

Like smart security turnstiles renewing expired visitor passes behind the scenes, billing department accounts correctly, and letting guards initiate inspections autonomously.
FEATURE

Parallel cloud session isolation, accurate task counts, and auto-resume on disconnect

Cloud workflows, Remote Control, and automated runners have received significant stability enhancements.

Launching /ultrareview and cloud sessions concurrently from different worktrees in the same repository no longer incorporates uncommitted changes from another launch. Cloud background workflows like /autofix-pr reliably track task progress (e.g. 3/5) without skipping tasks. Remote Control sessions show auto-generated conversation titles across claude.ai and mobile apps right after the first prompt. Self-hosted runners retry upon receiving malformed responses (such as proxy error pages) instead of quitting. Furthermore, non-interactive sessions (-p, SDK, and cloud runs) automatically resume stream cutoffs caused by network loss or server stalls.

Like an automated cloud pipeline isolating production branches, updating status boards promptly, and resuming assembly lines after network blips.
FEATURE

Safe large file overwrites in Write tool, with deferred managed settings prompts

File operations, sandbox boundaries, and enterprise installation flows have been reinforced.

Overwriting a large existing file with the Write tool no longer freezes the session or incorrectly claims out-of-memory errors after a successful write. The Notification hook (an automated script triggered by system events) now fires properly while the sandbox waits on user permission for external network requests. Command sandbox filesystem restrictions strictly honor the --setting-sources flag. Furthermore, Team and Enterprise installations via curl scripts no longer fail with "Raw mode is not supported" errors, and running claude install or claude update defers managed-settings consent prompts to your next interactive session instead of interrupting command execution.

Like an editor saving large charts cleanly, ringing notification bells while awaiting external network clearance, enforcing file boundaries from designated sources, streaming pipeline installations without terminal mode failures, and deferring compliance terms to the first interactive launch.
