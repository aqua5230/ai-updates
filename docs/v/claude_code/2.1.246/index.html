クラウド連携、リモート制御、セルフホストランナーの堅牢性が高まった。同一リポジトリの複数ワークツリーから /ultrareview やクラウドセッションを同時実行した際、別の実行に含まれる未コミットの変更が混入しなくなった。/autofix-pr などの進捗表示（3/5 など）でタスクが漏れる問題も修正された。リモートコントロール（Remote Control）では、最初のプロンプト入力後に自動生成されたタイトルが claude.ai やアプリ側へ即時反映される。セルフホストランナーがプロキシの HTML などの不正なポーリング応答を受け取っても終了せず再試行する。非対話セッション（-p、SDK、クラウド）で通信が切断された際もエラー終了せず自動で続きが生成される。クラウドの製造ラインが別ラインの仕掛品を隔離し、進捗掲示板を即座に更新し、通信切断時にも自動で作業を再開するようなものである。

Write ツールの巨大ファイル上書き修正と管理設定の確認保留

ファイルの書き込みやサンドボックス、管理者設定の導入手順が改善された。Write ツールで大容量ファイルを上書きした際、正常に書き込めたにもかかわらずメモリ不足を報告したりフリーズしたりする問題が修正された。サンドボックス外への通信許可ダイアログの待機中にも Notification フック（hook、特定イベント時に動作するスクリプト）が正しく発火する。コマンドサンドボックスのファイル構成も --setting-sources の指定に従うようになった。さらに企業向け管理環境で curl からインストールする際に Raw mode エラーで落ちる問題が解消し、claude install や claude update での管理設定の同意確認は次の対話起動時まで保留されるようになった。エディタが大容量データを軽快に保存し、警備エリアで外部通信の許可待ち中に通知ベルを鳴らし、指定された設定元に従ってファイル境界を区画し、パイプ経由の導入で端末モードのエラーを出さず、規約確認を初回の対話起動時まで後回しにするようなものである。

자동 모드 권한 탭 추가 및 긴 대화의 안전 점검 제한 시간 완화

공장의 자동 검사대에서 관리자가 판정 기준을 조절할 수 있고, 대량의 화물이 들어와도 대기열이 길다는 이유로 반송하지 않고 검사 시간을 늘려주는 것과 같다. 자동 모드(auto mode, Claude가 일일이 묻지 않고 스스로 실행하는 모드)의 규칙을 편리하게 관리할 수 있게 되었다. /permissions 명령어를 실행하면 새로 추가된 Auto mode 탭으로 이동하여 분류기 규칙을 직접 확인하고 편집할 수 있다. 아울러 매우 긴 세션(session)에서 도구 호출이 일시적으로 사용할 수 없다며 거부되던 문제도 해결되었다. 프롬프트 크기에 맞춰 안전 점검 제한 시간이 유연하게 늘어나므로, 방대한 대화에서도 끊김 없이 작업을 이어갈 수 있다.

Bash 허용 규칙의 와일드카드 경고 및 스냅샷 함수 실행 가속

Bash 명령어 자동 허용 규칙의 보안과 실행 속도가 개선되었다. 서브커맨드 앞에 와일드카드를 둔 Bash(git * main) 같은 허용 규칙을 지정한 경우, 서브커맨드 앞에 삽입된 옵션까지 함께 허용될 수 있어 시작 시 경고를 출력한다. 끝에 && 또는 || 연산자가 불안정하게 남은 불완전한 명령어는 권한 확인 시 반드시 수동 승인을 요구하도록 바로잡았다. 또한 bash 환경에서 Bash 도구를 실행할 때 함수마다 base64 서브셸을 띄우지 않고 스냅샷 함수를 재생하도록 최적화하여 실행 지연 시간을 줄였다. 경비실이 출입 명부의 허점을 짚어내고 덜 작성된 출입증을 막아서면서도, 일상적인 승인 절차는 빠르게 단축한 것과 같다.

백그라운드 세션 시작 안정화, 절전 및 패키지 재설치 충돌 해결

배차된 차량이 출발지 변경이나 운전자의 휴식, 정비 작업이 있더라도 45초 만에 운행을 취소하지 않고 차분히 기다릴 수 있게 된 것과 같다. 백그라운드 세션(session)의 시작 안정성이 크게 강화되었다. 시작 디렉터리가 삭제되었거나 컴퓨터가 절전 모드에 들어갔을 때, 또는 프로세스 기동이 느린 호스트에서 45초 후 세션 열기에 실패하던 문제를 해결했다. 다른 프로세스가 npm 패키지를 재설치하는 도중 권한 충돌로 EACCES 오류를 내며 백그라운드 서비스를 시작하지 못하던 현상도 수정되었다. Windows 등에서 작업 프로세스가 켜지는 중에 claude agents로 세션을 즉시 열어도 재기동 중 중단되는 오류 없이 안전하게 열린다.

중복 백그라운드 작업 자동 번호 부여 및 사용자 워크트리 보호

여러 백그라운드 작업을 관리할 때 목록 표시와 정리 작업이 깔끔해졌다. claude agents 목록에서 같은 이름을 가진 대화를 다시 백그라운드로 보낼 때 중복 행이 생기지 않고 새 행에 my-session (2) 같은 순번이 매겨진다. 오래된 세션을 정리하는 보존 정리 작업 시 사용자가 .claude/worktrees/ 아래에 직접 만든 워크트리(worktree, 프로젝트의 병렬 작업 사본을 여러 개 관리하는 Git 기능)를 삭제하던 문제도 바로잡았다. 아울러 Windows와 macOS 환경에서 헤드리스(headless, 터미널 화면 없이 동작하는 실행 모드) 세션이 비정상 종료되면서 ~/.claude/sessions에 남긴 오래된 기록을 깨끗이 정리한다. 창고 관리자가 같은 이름의 화물에 연번을 붙여 구분하고, 정리 중에 직원의 개인 사물함을 건드리지 않으며 버려진 영수증을 치우는 것과 같다.

완료된 서브에이전트 보호 및 /goal 유휴 확인 횟수 제한

여러 보조자에게 업무를 맡겼을 때 뒤로 가기를 잘못 눌렀다고 끝난 보조자를 다시 불러내지 않고, 시간 초과 시 남은 분량을 분명히 알리며, 대기 중 확인 노크를 최대 3회로 제한하는 것과 같다. 동적 워크플로우와 서브에이전트 제어가 정교해졌다. 워크플로우 진행 중 왼쪽 화살표 키를 누르거나 /background를 실행할 때 이미 완료된 서브에이전트를 곧바로 다시 실행하지 않고, 재시작될 서브에이전트 수를 알리며 확인을 먼저 구한다. 서브에이전트가 maxTurns 한도에 도달해 멈춘 경우 작업을 완전히 끝낸 것처럼 표시하지 않고 부분 완료 상태로 표시하며 SendMessage로 이어갈 수 있는 안내를 제공한다. 아울러 /goal 작업이 유휴 상태일 때 백그라운드 작업 확인을 최대 3회까지만 실행하고, 사용자가 새 메시지를 보낸 뒤에야 3회 더 확인할 수 있도록 조정했다.

MCP 도구 중단 오류 명시 및 빈 스키마 인자 타입 수정

MCP(Model Context Protocol, AI가 외부 도구를 다루도록 돕는 규약) 도구 호출과 권한 관리가 한결 정확해졌다. 헤드리스나 원격 세션에서 도구 호출이 새 메시지로 중단되었을 때 빈 출력으로 성공 처리되지 않고 명확한 중단 오류를 모델에 전달한다. 매개변수 스키마가 빈 객체 {}인 경우 인자를 JSON 문자열로 변환하지 않고 실제 데이터 타입 그대로 전달한다. --strict-mcp-config 옵션을 사용할 때 불러오지 않을 .mcp.json 서버의 승인 창을 띄우지 않아 백그라운드 세션이 멈추는 현상을 방지했다. 또한 requiresUserInteraction으로 지정된 상호작용 도구에서 작동하지 않는 '다시 묻지 않음' 선택지를 제거했다. 외장 장치 연결 프로토콜이 중단 신호와 데이터 형식을 다듬고 불필요한 페어링 요청을 걸러낸 것과 같다.

전체 화면 크기 조절 및 스크롤 개선, 대화 기록 메모리 부담 감소

방대한 전자 문서를 읽을 때 화면 크기를 조절해도 백지 상태가 되지 않고, 지난 내용을 매끄럽게 넘나들며, 창을 클릭해도 엉뚱한 버튼이 눌리지 않고, 페이지가 늘어나도 메모리를 적게 쓰는 것과 같다. 전체 화면 모드와 대화 기록 화면의 편의성이 향상되었다. 전체 화면에서 터미널 창 크기를 조절할 때 기록이 하얗게 비거나 다음 키 입력 전까지 바닥으로 튀던 문제가 고쳐졌다. 이전 메시지 위치로 스크롤할 때나 맨 아래로 이동할 때 중간에 멈추는 현상도 해결되었다. 창을 활성화하려고 터미널을 클릭했을 때 마우스 아래의 컨트롤로 키보드 포커스가 튀던 동작도 수정되었다. 또한 전체 화면 및 Ctrl+O 기록 보기에서 각 메시지 행이 도구 조회 테이블 복사본을 유지하지 않아 세션(session)이 길어져도 메모리가 팽창하지 않는다.

턴 완료 시각 표시 및 긴 diff 줄임 처리로 화면 멈춤 방지

터미널 출력과 상태 표시가 더욱 명확해졌다. 각 턴이 끝날 때 표시되는 소요 시간 안내 줄에 완료 시각(예: ✻ Sautéed for 23s · done 6:05 PM)이 함께 찍힌다. 코드 diff에 base64 문자열처럼 매우 긴 단일 행이 포함된 경우 생략 표시와 함께 줄여서 출력하여 터미널이 심하게 느려지는 문제를 방지했다. 첫 500자에 서식이 없다는 이유로 전체 메시지의 Markdown 렌더링이 꺼지던 오류를 고쳤으며, + 및 N) 목록과 밑줄 제목도 바르게 표시한다. 실행 중이던 명령어가 중단된 경우에도 정상 실행된 것처럼 알리지 않고 중단되었음을 명확히 표시한다. 조리 타이머에 완료 시각이 각인되고, 지나치게 긴 레시피는 요약해 주며, 조리가 중간에 끊겼을 때 경고등을 켜주는 것과 같다.

특수 주석 프롬프트 오인 방지 및 파일 선택기와 경로 자동 완성 수정

입력창이 일치하는 경로가 사라지면 후보 창을 닫고, 특수 주석을 명령어로 착각하지 않으며, 특수 문자가 섞인 폴더 경로도 멈춤 없이 완성해 주는 것과 같다. 프롬프트 입력과 파일 경로 자동 완성이 매끄러워졌다. /--로 시작하는 입력(예: Lean 언어의 문서 주석)이 알 수 없는 슬래시 명령어로 거부되지 않고 정상적으로 Claude에게 전송된다. @ 파일 선택기에서 입력한 글자가 실제 파일 경로와 맞지 않게 되면 선택 창이 닫힌다. 또한 자동 완성 문자열이나 작업 디렉터리에 널 바이트(null byte)가 포함되어 있어도 경로 자동 완성이 오류 없이 작동한다.

대화 이름 변경 시 테두리 색상 유지 및 맞춤 diff 색상과 키 설정 보호

터미널 테마 표현과 단축키 설정의 안정성이 향상되었다. /rename으로 대화 이름을 바꿀 때 맞춤 테마의 promptBorder 설정을 포함하여 기존 프롬프트 테두리 색상이 유지되며 기본 청록색으로 덮어씌워지지 않는다. 테마에 지정한 diff 강조 색상(diffAdded, diffRemoved 및 연한 음영 색상)도 diff 출력과 /theme 미리보기에 반영된다. 또한 keybindings.json 설정에 유효하지 않은 동작 이름을 지정하더라도 해당 키가 먹통이 되지 않고 기본 단축키 동작을 유지하며, --debug 모드에서 경고 로그를 남긴다. 문패를 바꿔 달아도 문틀 페인트가 지워지지 않고, 고른 색상이 바르게 칠해지며, 잘못 연결된 스위치 하나 때문에 방 전체 전기가 나가지 않는 것과 같다.

화면 전환 시 상태 표시줄 유지 및 동반구 시간대 사용량 통계 보정

계기판의 다른 탭을 둘러보고 와도 주행거리가 0으로 지워지지 않고, 시간대가 다른 지역에서도 출근부 요일 칸이 어긋나지 않는 것과 같다. 상태 표시줄과 사용량 통계의 표시 오류를 바로잡았다. 기본 대화 화면과 에이전트 목록 화면 사이를 이동할 때 상태 표시줄에 기록된 누적 비용과 소요 시간이 0으로 초기화되던 현상을 해결했다. 또한 UTC 기준 동쪽 시간대에서 /stats 활동 히트맵을 볼 때 일요일 사용량이 월요일 칸에 찍히며 하루씩 밀려 표시되던 시간대 계산 오류를 고쳤다.

/cd 실행 시 새 디렉터리 설정 즉시 반영 및 분기 대화와 계획 모드 유지

대화 도중 작업 디렉터리를 변경하거나 작업을 이어 나갈 때 설정과 모드가 유지된다. /cd로 새 디렉터리로 이동하면 해당 디렉터리의 프로젝트 설정, 훅(hook, 특정 이벤트 발생 시 실행되는 소형 스크립트), 승인 절차를 거친 .mcp.json 서버, 스킬 및 에이전트가 --resume 없이 즉시 적용된다. 이미 분기되었거나 백그라운드로 전환된 세션에서 /fork로 새 세션을 시작할 때 빈 대화로 열리지 않고 이전 기록을 유지한다. 아울러 계획 모드 상태로 끝난 세션을 VS Code 확장 프로그램이나 claude -p --continue로 다시 열 때 권한 모드가 지정되지 않아도 계획 모드가 유지된다. 새 회의실에 들어가자마자 장비가 연결되고, 분과 회의를 열어도 회의록이 유실되지 않으며, 세워둔 계획대로 일을 이어갈 수 있는 것과 같다.

플러그인 짧은 이름 업데이트 및 BOM 지원, 캐시 중복 방지

앱 스토어의 패키지 설치와 캐시 관리가 다듬어져, 짧은 이름 업데이트나 특수 인코딩, 마켓플레이스 목록 손상에도 오류를 안내하고 디스크 낭비를 줄이는 것과 같다. 플러그인 관리와 캐시(cache, 작업 결과를 임시 보관하여 재사용하는 구조) 관리가 한층 탄탄해졌다. claude plugin update 실행 시 긴 전체 이름 대신 패키지의 짧은 기본 이름만 넘겨도 업데이트할 수 있다. plugin.json 파일에 UTF-8 BOM 표식이 포함되어 있어도 설치에 실패하지 않는다. known_marketplaces.json 파일이 비어 있거나 손상된 경우 멈추거나 조용히 꺼지지 않고 명확한 오류를 출력한다. 또한 동일한 플러그인에 대해 중복된 SHA 폴더가 생성되지 않도록 바로잡았으며, claude.ai와 동기화된 플러그인의 원격 측정 이벤트도 실제 마켓플레이스와 관리자 설치 여부를 정확히 기록한다.

플러그인 스킬 접두사 중복 제거 및 훅 오류 경로 정상 표기

플러그인 스킬과 훅(hook, 특정 사건 발생 시 불려 나가는 소형 스크립트)의 이름 표기와 경로 인식이 개선되었다. 스킬 정의에 이미 <plugin>: 접두사가 붙어 있는 경우 슬래시 메뉴에서 /plugin:plugin:skill처럼 중복되어 뜨지 않는다. skills/*/SKILL.md 경로에 스킬을 둔 플러그인도 /reload-plugins 실행 시 0개로 잘못 인식되지 않고 정상적으로 불러온다. 아울러 훅 실행 중 오류가 났을 때 ${CLAUDE_PLUGIN_ROOT} 텍스트가 그대로 노출되지 않고 실제 풀린 로컬 경로가 오류 창에 표시된다. 사내 연락망에서 중복된 국번을 정리하고, 하위 부서 번호를 빠짐없이 등록하며, 고장 시 실제 방 번호를 정확히 알려주는 것과 같다.

서드파티 호환 엔드포인트 도구 블록 호환 및 원격 측정 키 분리

출입국 심사대가 다른 양식의 통행증을 유연하게 처리하면서도, 특정 시설의 출입증을 본사 우편함에 잘못 넣지 않도록 분리하는 것과 같다. 서드파티 호환 API 게이트웨이와 프록시를 사용할 때의 안정성과 보안이 강화되었다. 호환 엔드포인트(ANTHROPIC_BASE_URL)에서 id 없는 tool_use 블록을 스트리밍해도 렌더링 오류로 멈추지 않는다. 프록시가 작성한 특수 도구 블록이 포함된 세션을 다시 열었을 때 매 턴마다 400 오류를 내던 문제도 해결했다. 또한 Anthropic으로 전송되는 원격 측정 요청에 서드파티 게이트웨이용 API 키가 섞여 들어가지 않도록 바로잡아 각 호스트에 맞는 자격 증명만 전달한다.

단기 JWT 자동 갱신 및 주요 클라우드 환경의 자율 코드 검토

인증 처리와 기업용 사용량 집계가 매끄러워졌다. apiKeyHelper를 통해 수명이 짧은 JWT 토큰(token, 사용자 신원을 증명하는 인증 표식)을 발급받아 쓰는 경우, 대기 후 첫 메시지를 보낼 때 만료된 캐시를 자동 갱신하며 401이나 403 인증 오류 발생 시 조용히 재시도한다. 워크로드 아이덴티티 페더레이션 및 시작 단계, 토큰 만료 후의 사용량 통계도 조직에 맞게 집계된다. 또한 Bedrock, Vertex AI, Foundry, Claude 앱 게이트웨이 및 불필요한 트래픽 차단 환경에서 Claude가 스스로 /code-review를 시작할 수 있게 되었다. 출입 카드가 만료되어도 게이트에서 갱신되고, 사용 기록이 소속 부서로 집계되며, 보안 담당자가 점검을 직접 시작할 수 있는 것과 같다.

클라우드 작업 격리 및 진척도 수정, 비대화형 연결 끊김 자동 복구

클라우드 연동과 원격 제어 및 자체 호스팅 러너의 신뢰성이 향상되었다. 한 저장소의 여러 워크트리에서 /ultrareview나 클라우드 세션을 동시에 실행할 때 다른 작업의 커밋되지 않은 변경 사항이 섞여 들어가지 않는다. /autofix-pr 같은 백그라운드 클라우드 작업에서 진행률(예: 3/5) 숫자가 누락되던 현상도 해결했다. 원격 제어(Remote Control) 사용 시 첫 번째 프롬프트를 입력하면 자동으로 생성된 대화 제목이 claude.ai와 앱에 표시된다. 자체 호스팅 러너가 잘못된 폴링 응답(예: 프록시의 HTML 페이지)을 받더라도 종료되지 않고 재시도한다. 비대화형 세션(-p, SDK, 클라우드)에서 통신 끊김이나 서버 오류로 답변이 잘려도 오류로 끝나지 않고 생성을 이어 나간다. 자동화 라인이 다른 라인의 작업물을 분리하고, 현황판을 갱신하며, 통신이 끊겨도 작업을 스스로 이어가는 것과 같다.

Write 도구 대용량 파일 덮어쓰기 개선 및 관리 설정 동의 지연

파일 쓰기와 샌드박스 및 설치 절차가 안정화되었다. Write 도구로 대용량 파일을 덮어쓴 뒤 파일이 정상 작성되었음에도 메모리 부족 오류를 띄우거나 멈추던 현상을 해결했다. 샌드박스 외부 네트워크 요청 권한 승인을 기다리는 동안 Notification 훅(hook, 특정 상황에 실행되는 소형 스크립트)이 정상적으로 작동한다. 명령어 샌드박스의 파일 시스템 설정도 --setting-sources 옵션을 따른다. 아울러 curl 스크립트를 통한 설치 시 Raw mode 오류가 발생하던 문제를 해결했고, claude install 및 claude update 실행 중 관리 설정 동의 창을 띄우지 않고 다음 대화 세션으로 미뤄 작업 흐름을 끊지 않도록 했다. 문서 편집기가 대용량 파일을 가볍게 저장하고, 보안 구역에서 외부 통신 허가를 기다리는 동안 알림 벨을 울리며, 지정된 설정 기준에 따라 파일 접근 경계를 나누고, 파이프를 통한 설치 시 터미널 모드 오류를 내지 않으며, 관리 설정 동의를 첫 대화 실행으로 미뤄주는 것과 같다.
