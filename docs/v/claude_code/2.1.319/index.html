Claude Code 2.1.319

發布日期：2026-11-06

繁體中文

新功能

自動模式關閉遙測時改走詢問或拒絕，外部關閉後專案無法擅自重啟

在停用遙測或功能旗標的環境下使用自動模式，只要伺服器無法執行安全審查，呼叫就會直接改為詢問你或予以拒絕，不再備援（fallback）回內建分類器。Bedrock、Vertex 與 Foundry 行為維持不變，設 CLAUDE_CODE_AUTO_MODE_SERVER=0 可沿用舊機制。在大型語言模型閘道後方，設 CLAUDE_CODE_AUTO_MODE_SERVER=1，即使指定 CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS 也會啟用伺服器檢查；若後者由受管設定指定，前者也須設在受管設定。閘道網址只設於受管設定、且無法取得伺服器受管設定時，該處的啟用值被忽略的問題已修好。此外，一旦在專案外關閉檢查，個別專案設定或外掛無法擅自重新開啟。

保全總機關掉主控鎖後，以前房內開關還能覆寫，現在各房間無法自行重開。
問題修復

自動模式拒絕動作後修正退出狀態，修復狀態誤報與規則過長拒絕

在指令列以非互動模式執行 claude -p 時，若動作原本已因缺乏安全檢查而遭拒絕，純文字與 JSON 格式輸出的退出狀態代碼現在都會正確設為 1，不再錯誤回傳代表成功的 0。當客戶端連續發送切換模型與啟用自動模式的請求時，過去容易被系統誤判拒絕，這項問題已經排除。如果在大型語言模型閘道背後發生審查無法送達工作階段的情況，輸入 /status 也不再錯誤顯示伺服器端已啟用。當權限規則或 autoMode 設定內容極度龐大時，過去會在沒有說明原因的情況下拒絕執行；現在會明確給出解釋，且除非已明定 autoMode 拒絕規則，否則會在終端機提示詢問你。

貨物原本就被海關拒收，以前回條卻誤印「成功」，現在改印「失敗」；退件結果沒變，改的是回條不再報錯狀態。
新功能

終端機支援 MCP 任務背景執行，提供環境變數切換等待模式

當你透過終端機呼叫 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器時，若工具將呼叫當成任務執行，Claude Code 會立刻將它移至背景運作，並在完成時主動回報結果給 Claude。這項功能現在無須抓取功能旗標即可在終端機運作，包含 Bedrock、Vertex、Foundry、大型語言模型閘道以及停用遙測的環境都能直接使用。如果你希望工具呼叫維持在前景等待任務完成，可以設定環境變數 CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND。若完全不想使用這項機制，則可將 CLAUDE_CODE_DISABLE_MCP_TASKS 設為 1 來予以停用。

如同將繁瑣的送印差事交給影印部，以前整個人必須守在影印機旁乾等成品；現在單據一送出即可轉身處理其他事務，印妥時櫃檯自會派員遞送通知。
問題修復

修復舊版 MCP 握手協定連線、恢復工作階段後的結果回傳與桌面版規則

當你連線至採用舊版握手協定的外部工具伺服器時，過去可能因為宣告了新伺服器專用的擴充項目而連線失敗或傳回空結果，這個問題已經修復。針對連接 claude.ai 連接器的長時間工具呼叫，過去在恢復工作階段後有時會遺失結果回報，現在已能正常取得。若在執行 claude -p --resume 帶有提示詞時缺少對應的工具伺服器，執行程序會以代碼 1 退出，並保留該次呼叫且拒絕後續輸入，避免延後執行的工具呼叫憑空遺失。在 Claude Desktop，以 mcp__claude_ai_Slack 這類連接器終端名稱撰寫的拒絕與詢問規則、disallowedTools 禁用工具清單及 hook（掛鉤，特定事件發生時被觸發的小程式）匹配器被略過的問題也已修正，但須待桌面版納入此版本才生效。

新功能

權限提示支援直接拒絕設定，廣義拒絕規則優先於特定詢問

在終端機工作階段、子代理或協作隊友中執行工具時，若不想讓流程卡在權限詢問畫面，可啟用 permissions.denyInsteadOfPrompting 設定。開啟後，原本需要等待手動確認的工具呼叫會直接遭到拒絕，並讓輪次繼續往下執行。當 Bash 或 PowerShell 的指令同時符合特定詢問規則與更廣泛的拒絕規則時，工具會直接拒絕執行該指令，不再跳出詢問提示。另外，Bash 工具在執行 which 指令時，只要參數超出一般的查詢與顯示旗標範圍，便會主動要求授權許可。

好似自動售票機切換為夜間直通模式，遇到不支援的冷門支付方式直接退幣跳過，不再卡在付款畫面等待專人排除障礙，以前必須手動逐一確認，現在自動化直接判定。
問題修復

修復 Bash 權限檢查引號漏判、環境變數前綴繞過與逾時唯讀確認

當你在安全規則中限制 Bash 指令時，多種指令解析漏洞已獲得修復。過去包含引號字詞的指令可能會脫離拒絕與詢問規則的過濾範圍，精心構造的環境變數前綴也可能將部分指令隱藏起來繞過檢查，這些漏判情況都已修復。在接受編輯模式與自動模式下，先前特定 sed 指令可能跳過權限檢查的漏洞也已補強。同時，唯讀指令外面加上單純的 timeout DURATION，例如 timeout 30 rg foo，不再出現多餘的權限詢問。以前唯讀指令包一層 timeout 就會被多問一次，含引號或帶環境變數前綴的指令也可能溜過拒絕規則；現在這幾個漏洞都已修好。

問題修復

代理伺服器支援 TLS 檢驗握手修復，明確限制環境變數宣告位置

在代理後方且本機沒有 DNS（查詢網域位址的服務）時，設定 CLAUDE_CODE_PROXY_RESOLVES_HOSTS 後，Monitor 的 WebSocket 監控不再出現無法解析主機名稱的錯誤。主機管理網路時，該變數須設於處理程序環境，不能由設定檔指定。Monitor 遇到 Bash 拒絕規則就禁止監控；遇到詢問規則，對 Monitor 的允許、略過權限模式及自動模式都不能跳過詢問。在 TLS 檢驗代理後方，設 CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC 時，憑證失敗後會與設定的 API 主機進行 TLS 握手，若有設定 http:// 代理才經由它連線，不發送 API 請求。自動憑證修復不再於僅設 ALL_PROXY 時觸發，須將 HTTPS_PROXY 設為代理的 http:// 位址。

新功能

新增 API 延遲最佳化指令，同步管理型代理設定範本

當你著手調整 Claude API 程式碼時，現在只要輸入 /claude-api latency-optimize，工具就會協助找出程式中造成使用者等待的瓶頸，並根據你的評估集測試更快的設定組合。針對管理型代理工作階段，修正了技能說明中聲稱主控台網頁設定不適用的錯誤，並收緊了相關憑證與權限範例。此外，/claude-api managed-agents-onboard 中的模板已對齊主控台規格，移除 Performance tuner 範本，重新命名兩項範本，並在五個提示詞不需要網路功能的範本中關閉了搜尋與網頁讀取。

恰似車廠技師拿著調校儀器診斷引擎管線，針對耗損嚴重的組件替換輕量零件，去除車內多餘載重以縮短起步加速時間。
新功能

設定檔存檔不再變成空檔，支援單獨關閉功能旗標抓取

當你想維持遙測但停止抓取實驗性開關時，現在可設定環境變數 CLAUDE_CODE_DISABLE_FEATURE_FLAGS，讓每項功能旗標直接套用內建預設值。過去在寫入設定檔數秒內進行的手動修改常被忽略，這個問題已修好。家目錄若殘留舊版檔名而有兩份設定檔，會在標準錯誤輸出說明正在用哪一份。在唯讀資料夾或綁定掛載檔案遇到磁碟寫滿時（一次由一個工作階段存檔），~/.claude.json、設定檔與正在編輯的檔案不再變成空檔或被截斷。Windows 平台儲存設定時則會延長等待其他程式釋放檔案的時間，降低存檔期間程序被終止後 ~/.claude.json 變成空檔的機率。

新功能

Claude Apps 閘道支援群組共用預算排程、JSON 日誌與登入公告

企業透過 Claude Apps 閘道管理團隊使用時，帳務與維運控制獲得更完整的支援。若開發者隸屬多個群組，管理員可透過 admin.pooled_conflict_rule 與 admin.pooled_priority_order 設定優先扣款的群組預算。閘道執行此版本或更新版本、且開發者無花費上限時，輸入 /usage 可查詢本日、本週與本月開銷。閘道新增 login_notice 可在驗證與登入頁面展示公告；指定 CLAUDE_GATEWAY_LOG_FORMAT=json，維運日誌會轉為 JSON，包含 severity 等級、time 時間與 message 訊息，供從欄位讀取等級的日誌收集器使用。達上限時，錯誤訊息會顯示重設日期；若設定了 admin.blocked_message，才會附上自訂封鎖說明。

新功能

Claude Apps 閘道強化啟動警示，明確標註上游名稱與模型設定

部署 Claude Apps 閘道時，可留意啟動警告。其他策略的 availableModels 也允許某策略具名列出的自訂模型識別碼時，會警告。策略缺少 desktopHome，卻依賴 coworkTabEnabled: false 或 chatSessionRetentionDays 時，會在 Claude Desktop 11 月 10 日變更前警告。AWS GovCloud 與其他上游混用，或閘道環境含基礎網址變數，也會警告。受管設定標頭列出閘道不轉發的 Amazon Bedrock 防護欄，且沒有任何 bedrock 上游設定 guardrail，啟動日誌也會警告。呼叫失敗的警告會點名上游，不再只顯示提供者。全數上游為 Amazon Bedrock 時，Claude Desktop 不再提供必然失敗的網路搜尋工具。

問題修復

帳號切換自動警示 Console 計費組織，修復 401 憑證刷新連鎖錯誤

當你的個人帳號登入過期時，若系統自動改用 ant auth login 的登入狀態繼續執行，終端機會跳出警示，並在 Claude Code 啟動時指名費用將計入哪一個主控台組織。在登入機制方面，修復了持續遭遇 401 未授權錯誤的請求在每次重試時都會刷新登入，進而導致其他終端機工作階段同步引發 401 錯誤的連鎖問題。在 /login 成功畫面按下確認鍵後的半秒卡頓也已排除，對話框會立即關閉並在背景刷新。此外，若終端機在閘道的登入已過期，不再持續發送會被閘道拒絕並記錄無效權杖（invalid_token）的遙測與受管設定請求。以前一個卡住的請求會讓其他工作階段跟著出現 401；現在這個問題已經修好。

新功能

任務清單新增歷史子代理記錄，改善交回報告與安全防護回報

輸入 /tasks 檢視任務清單時，現在多了「此工作階段稍早項目」區塊，完整列出已結束的子代理，即使項目已移出清單或重新啟動，你隨時都能重新打開並發送訊息。子代理交回報告在非詳細模式下展開時，過去會顯示內部標記與來源註記的問題已經修復。當對話完成歷程濃縮後，子代理不會再被告知去等待未曾負責的背景代理完成通知。若背景代理稍後的報告被拒絕，系統不再無聲丟失回報，而是會提示已被拒絕並告知如何索取。當安全防護措施阻擋了子代理時，Claude 收到的指示改為縮小提示詞範圍重試或主動告知你，不再自行接手該項工作。

就像客服中心的主管看板，過往結案的工單依然整齊陳列可隨時調閱追問，交接紀錄抹去內部代碼，出現異常時也能即時亮起警示。
新功能

循環指令支援容器生命週期警示，自定節奏結束時不再排定喚醒

在雲端工作階段設定 /loop 循環指令時，確認畫面現在會明確提醒你計時器將隨著容器終止而停止，並提供能在容器重啟後持續存活的循環選項。針對自定節奏的循環操作，若單次回合執行完畢且未重新排程，流程會直接結束，不再自動排定備援的喚醒程序；若你的自動化工作流仍依賴舊有機制，可將環境變數 CLAUDE_CODE_LOOP_KEEPALIVE 設為 1 來維持原先行為。

好比廚房的倒數計時器，以前時間到了就算無人點單也會按時反覆響鈴，現在只要菜餚出餐完畢便自動歸零靜止，同時在離店前提醒你設備將隨店面打烊斷電。
問題修復

修復目錄包含 HEAD 檔案時的差異比對失敗與多輪編輯空白問題

檢視修改內容時，若 Claude Code 執行所在資料夾有名為 HEAD 的檔案或資料夾，claude.ai 與行動版原本會載不出工作階段的變更；若 Git 儲存庫最上層有這類檔案或資料夾，/diff 則會顯示無法使用。此外，在已有至少 64 個回合編輯過檔案的工作階段中，原本點開 /diff 面板可能呈現一片空白。上述載入失敗與空白面板問題已修好。

問題修復

修復程式碼回溯在分支建立前之還原錯誤，堵住目錄符號連結與工作樹漏洞

當你想使用 /rewind 還原程式碼時，版本切換的安全性與穩定度獲得顯著強化。若嘗試將專案回復至執行 /branch 建立分支之前的檢查點，過去容易出現未還原任何檔案的錯誤，現在已能精準還原。在路徑處理上，可能透過目錄符號連結（symlink，指向另一個位置的捷徑檔）還原或刪除檔案的問題已修好。同時，也修復了建立 worktree（工作樹，Git 讓同一專案平行開多份副本的功能）時可能逃逸出安全沙盒的漏洞。以前執行回溯可能卡在分支邊界，現在跨分支還原的問題已經修好。

新功能

斜線指令支援前導空白，模型名稱錯字主動推薦正確選項

在終端機輸入指令時，打字體驗顯得更加寬容流暢。若你在輸入斜線指令前不小心夾帶了空格、定位鍵（Tab）或換行符號，過去會被當成一般純文字直接送出給 Claude，現在會正確辨識為指令並直接執行。當手滑打錯模型名稱時（例如輸入 opus-5-5），不再誤導你更新工具版本，而是會主動推薦你可能想輸入的正確名稱。在切換模型的 /model 選單中，舊款模型已收進「More models」分組。在使用螢幕報讀機模式回答問題時，輸入「其他」選項可隨時按 Ctrl+G 開外部編輯器。而若執行 /rename 時無法將新名稱寫入工作階段的對話記錄，也會主動警告新名稱可能無法保留。

新功能

終端機超連結支援跨行完整開啟，路徑拒絕提示大小寫拼法

終端機介面的可讀性與互動細節在多種終端機環境中獲得改善。在 Ghostty 終端機搭配 tmux（終端機多工器），且從代理管理檢視開啟的工作階段中，Cmd+click 無法打開連結的問題已解決。當 /status 狀態檢視或自動模式計費通知中的說明連結因為視窗寬度而折行時，先前只會開啟前半截網址的臭蟲也已修正。在 macOS 與 Windows 平台上，若存取工作目錄外部路徑遭到拒絕，而該路徑僅與工作目錄內的路徑有字母大小寫的差異，拒絕訊息現在會具體指出該內部路徑的拼法。此外，/stats、/model 與 /sandbox 中的提示說明、次要文字以及拒絕動作訊息，淺灰色對比度皆已提高。

跟圖書館翻新導覽標示一樣，以前長網址換行就斷裂失效，燈光太暗還看不清書目說明；現在標牌加深字體顏色，指引細節也更加清晰。
新功能

`/context` 摘要表格精簡化，按需載入工具收納節省文字額度

當你想檢查目前對話的內容配置時，輸入 /context 檢視上下文後的開銷明顯降低。過去在終端機執行該指令後，後續每一次對話都會將完整的視覺化網格資訊全部傳送給模型，白白佔用大量 token（AI 處理與計費的文字單位）。現在已修正為僅讀取純文字表格。同時，這份表格的長度也經過精簡最佳化，每個清單最多僅保留占用空間前 10 大的項目，而按需載入的 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）工具在真正被呼叫之前，同一個伺服器底下的工具只會合併列在一列。

如同開會報告財務報表，以前每次發言都把全套百頁帳冊反覆投影給與會者，現在只保留前十大開銷摘要，零星項目則併入所屬部門統一呈現。
