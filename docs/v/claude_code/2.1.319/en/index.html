Claude Code 2.1.319

Released: 2026-11-06

Release notes

FEATURE

Auto mode asks or denies when telemetry is disabled, and projects cannot reopen checks turned off outside

When using auto mode with telemetry or feature flags disabled, calls the server cannot review for safety are now asked about or denied directly, without falling back to the built-in classifier. Behavior on Bedrock, Vertex, and Foundry remains unchanged, and setting CLAUDE_CODE_AUTO_MODE_SERVER=0 keeps the legacy mechanism. Behind an LLM gateway, setting CLAUDE_CODE_AUTO_MODE_SERVER=1 turns on server-side checks even if CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS is specified. If the latter is set by managed settings, the former must also be configured in managed settings. A bug has been fixed where CLAUDE_CODE_AUTO_MODE_SERVER=1 in managed settings was ignored behind an LLM gateway when the gateway URL was configured only there and server-managed settings could not be fetched. In addition, once you switch off the check outside a project, individual project settings or plugins can no longer turn it back on.

Picture a central security desk locking the master switch: while room switches could previously override it, individual rooms can no longer reopen the lock on their own.
BUGFIX

Auto mode fixes exit status on denied actions, rectifying status misreports and oversized-rule refusals

When running claude -p non-interactively on the command line, if actions are refused because no safety check was available, the exit status code for text and JSON outputs is now properly set to 1 instead of mistakenly returning 0 for success. An issue where auto mode was wrongly refused when a client sent a model change and a request for auto mode back to back has been resolved. Entering /status also no longer incorrectly displays that the server side is enabled when reviews fail to reach the session behind an LLM gateway. When permission rules or autoMode settings are extremely large, executions previously refused without explanation now provide a clear reason, and prompt you in the terminal unless autoMode deny rules are explicitly configured.

Think of customs rejecting a shipment where the receipt mistakenly printed "Success" in the past: it now prints "Failure," leaving the rejected outcome unchanged while ensuring the slip no longer misreports the status.
FEATURE

Terminal supports background execution for MCP tasks, offering an environment variable to toggle waiting mode

When you call an MCP (Model Context Protocol, a protocol for connecting AI to external tools) server through the terminal, if a tool executes the call as a task, Claude Code immediately moves it to the background and reports the result to Claude upon completion. This capability now works in the terminal without fetching feature flags, making it directly available across Bedrock, Vertex, Foundry, LLM gateways, and environments with telemetry disabled. If you prefer the tool call to stay in the foreground waiting for the task to complete, you can configure the CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND environment variable. If you do not want to use this mechanism at all, set CLAUDE_CODE_DISABLE_MCP_TASKS to 1 to turn it off.

A clerk delivers a bulky print job to the copy center: where you previously had to wait right by the copier for the output, you can now hand over the slip and attend to other work, receiving a desk delivery once printing finishes.
BUGFIX

Fixes for legacy MCP handshake connections, post-resume result delivery, and Desktop rules

When connecting to external tool servers that use an older handshake, failures to connect or empty results caused by declaring extensions reserved for newer servers have now been fixed. For long-running tool calls on claude.ai connectors, where result reports were sometimes lost after resuming a session, results are now properly retrieved. When running claude -p --resume with a prompt while the corresponding tool server is missing, the process now exits with code 1, keeps the call, and refuses subsequent input to prevent deferred tool calls from vanishing. In Claude Desktop, an issue where deny and ask rules, disallowedTools entries, and hook (small programs triggered by specific events) matchers written with connector terminal names like mcp__claude_ai_Slack were ignored has also been corrected, though this takes effect once the desktop version incorporates this release.

FEATURE

Permission prompts support direct denial, prioritizing broad deny rules over specific asks

When running tools in terminal sessions, subagents, or teammates, if you do not want workflows getting stuck on permission prompts, you can enable the permissions.denyInsteadOfPrompting setting. Once turned on, tool calls that would otherwise wait for manual confirmation are denied immediately, allowing the turn to continue. When a Bash or PowerShell command matches both a specific ask rule and a broader deny rule, the tool directly refuses to execute the command rather than presenting a prompt. In addition, the Bash tool now actively requests permission before running which whenever flags fall outside a standard lookup and display set.

Consider a ticket kiosk switching to direct night mode: when encountering an unsupported obscure payment method, it spits out the coin and moves on instead of freezing on the payment screen for an attendant, replacing manual confirmation with immediate automated decisions.
BUGFIX

Fixes for Bash permission check quote misses, environment prefix bypasses, and timeout read-only prompts

When restricting Bash commands in security rules, several command-parsing loopholes have now been fixed. Previously, commands containing quoted words could slip past deny and ask rules, while a crafted environment variable prefix could hide parts of a command from inspection; both gaps have now been resolved. A vulnerability where specific sed commands could skip permission checks under accept-edits and auto mode has also been patched. At the same time, wrapping read-only commands in a plain timeout DURATION, such as timeout 30 rg foo, no longer triggers needless permission prompts. Where read-only commands wrapped in timeout were previously prompted an extra time and commands with quotes or environment variable prefixes could slip past deny rules, these flaws are now all fixed.

BUGFIX

Proxy support adds TLS inspection handshake repair, clarifying environment variable locations

Behind a proxy where the local machine has no DNS (a service that resolves domain names), setting CLAUDE_CODE_PROXY_RESOLVES_HOSTS prevents Monitor's WebSocket watch from failing with host resolution errors. Where the host manages the network, this variable must be set in the process environment and can no longer be defined by settings files. When Monitor encounters a Bash deny rule, it refuses the watch. Under an ask rule, an allow on Monitor, bypass permissions mode, and auto mode can no longer skip the prompt. Behind a TLS-inspecting proxy, when CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC is set, Claude Code performs a TLS handshake with the configured API host following a certificate failure—connecting through your http:// proxy if one is configured—without sending any API request. Automatic certificate repair no longer triggers when ALL_PROXY is the only proxy variable set; you must set HTTPS_PROXY to the proxy's http:// address instead.

FEATURE

Adds API latency optimization command, synchronizing Managed Agents configuration templates

When tuning Claude API code, entering /claude-api latency-optimize now helps find bottlenecks that make people wait and tests faster configuration combinations against your eval. For Managed Agents sessions, an error in the skill description claiming Console web settings do not apply has been corrected, and its credential and permission examples have been tightened. Additionally, templates in /claude-api managed-agents-onboard now match Claude Console specifications, removing the Performance tuner template, renaming two others, and disabling web search and fetch across five templates whose prompts do not require network access.

A garage mechanic runs diagnostic instruments across engine piping: replacing worn parts with lightweight components and stripping excess vehicle weight cuts down initial acceleration time.
FEATURE

Config saves no longer leave empty files, supporting standalone disabling of feature-flag fetching

When you want to retain telemetry while stopping the retrieval of experimental toggles, you can now set the CLAUDE_CODE_DISABLE_FEATURE_FLAGS environment variable so that every feature flag directly applies its built-in default. A bug where manual edits made within a few seconds of writing a settings file were ignored has now been resolved. If your home directory holds two configuration files due to a lingering legacy filename, Claude Code now explains on stderr which one is currently in use. When disk space fills up during a save inside a read-only folder or to a bind-mounted file (with one session saving at a time), ~/.claude.json, settings files, and edited files no longer end up empty or cut off. On Windows, config saves now wait longer for other programs to release the file, reducing the likelihood that terminating the process during a save leaves ~/.claude.json empty.

FEATURE

Claude Apps gateway supports pooled group budgets, JSON logs, and login notices

When organizations manage team usage through the Claude apps gateway, billing and operational controls receive more comprehensive support. If a developer belongs to multiple groups, administrators can use admin.pooled_conflict_rule and admin.pooled_priority_order to configure which pooled group budget pays first. When the gateway runs this version or later and a developer has no spend limit, entering /usage allows checking spend for today, this week, and this month. The gateway adds login_notice to display announcements on verification and sign-in pages. By specifying CLAUDE_GATEWAY_LOG_FORMAT=json, operational logs become JSON containing severity level, time, and message fields for log collectors that read severity levels from structured fields. When reaching the limit, the error message displays the reset date, appending a custom block notice only if admin.blocked_message is set.

FEATURE

Claude Apps Gateway Strengthens Boot Warnings, Explicitly Labeling Upstream Names and Model Settings

When deploying the Claude apps gateway, note several new startup warnings. The gateway now warns when another policy's availableModels also allows a custom model id that one policy lists by name. It also warns ahead of Claude Desktop's November 10 change if policies have no desktopHome while relying on coworkTabEnabled: false or chatSessionRetentionDays. Warnings also trigger when upstreams mix AWS GovCloud with other upstreams, or when base URL variables exist in the gateway's environment. A startup log warning is also added when managed settings name an Amazon Bedrock guardrail in a header that the gateway does not forward, while no bedrock upstream sets a guardrail. Warnings about a failed upstream call now name the upstream rather than only its provider. Finally, Claude Desktop no longer offers a web search tool that always failed when every upstream is Amazon Bedrock.

BUGFIX

Account Switching Warns of Console Billing Organization, Fixing Chained 401 Login Refresh Errors

When your personal claude.ai login expires, if the system continues on the sign-in from ant auth login, the terminal displays a warning and names at startup which Claude Console organization is billed. For authentication, a bug was fixed where a request that kept failing with a 401 error refreshed your login on every retry, triggering a chain of 401 errors across your other terminal sessions. A half-second hang after pressing Enter on the /login success screen has also been resolved: the dialog dismisses immediately while the post-login refresh runs in the background. Furthermore, a terminal whose sign-in for the Claude apps gateway has expired no longer sends telemetry and managed-settings requests that the gateway refused and logged as invalid_token. Previously, one stuck request could cause 401s in other sessions; that issue is now fixed.

FEATURE

Task List Adds Historical Subagent History, Improving Hand-Back Reports and Safeguard Alerts

When running /tasks to view the task list, an "Earlier in this session" row is now added to fully list finished subagents, allowing you to reopen and message one at any time even after it leaves the list or you restart. A fix resolves an issue where subagent hand-back reports displayed an internal marker and provenance note when expanded outside verbose mode. Following context compaction, subagents are no longer told to expect a completion notice for background agents they neither started nor took over. If a background agent's later report is refused, the system no longer silently drops it, but instead notifies you that it was refused and explains how to request it. When safeguards stop a subagent, Claude is now instructed to retry with a narrower prompt or inform you directly, rather than taking over the work itself.

Much like a support desk supervisor dashboard, closed tickets remain neatly listed for review or follow-up at any time, internal codes are cleared from handover notes, and warnings surface immediately whenever exceptions arise.
FEATURE

Loop Command Adds Container Lifecycle Warnings, Ending Self-Paced Loops Without Wakeups

When setting up a /loop command in cloud sessions, the confirmation screen now clearly notes that a timer stops with its container, offering a loop option that survives restarts. For self-paced /loop operations, when a single turn finishes without rescheduling, the process ends directly instead of scheduling a fallback wakeup; if your automated workflows rely on the legacy behavior, set environment variable CLAUDE_CODE_LOOP_KEEPALIVE=1 to preserve it.

Like a kitchen countdown timer, it previously rang repeatedly on schedule even when no tickets arrived, but now resets and stays silent once dishes are served, while reminding you before leaving that equipment shuts off when the store closes.
BUGFIX

Fix Diff Loading Failures with HEAD Files and Blank Panes in Multi-Turn Sessions

When inspecting modifications, if the folder where Claude Code runs contains a file or folder named HEAD, a session's diff previously failed to load on claude.ai and the mobile apps; if a Git repository has such a file or folder at its top level, /diff showed "Diff unavailable". In addition, in sessions where 64 or more turns edited files, the /diff pane could open completely blank. These loading failures and blank pane issues have now been fixed.

BUGFIX

Fix Code Rewind Errors Before Branch Creation, Closing Symlink and Worktree Exploits

When using /rewind to restore code, version switching is significantly safer and more reliable. If you attempt to restore project code to a checkpoint from before running /branch, the command previously failed with "No files were restored", but now restores accurately. In path handling, an issue where /rewind could restore or delete a file through a directory symlink (a shortcut file pointing to another location) has been fixed. Additionally, a vulnerability where creating a worktree (a Git feature allowing parallel copies of the same project) could escape the security sandbox was closed. Where rewinding previously stumbled at branch boundaries, restoring across branches is now resolved.

FEATURE

Slash Commands Support Leading Whitespace, Recommending Correct Model Names on Typos

Typing in the terminal is now more forgiving and fluid. If you accidentally include a leading space, tab, or newline before a slash command, it was previously sent to Claude as plain text, but is now recognized and executed as a command. When you mistype a model name (such as opus-5-5), the CLI no longer misleads you to update versions, actively suggesting the model you meant instead. In the /model picker, older models are now grouped under a "More models" row. When answering questions in screen reader mode, typing an "Other" answer lets you press Ctrl+G at any time to open the external editor. Finally, if /rename cannot save a new name to the session transcript, it now warns that the new name may not last.

FEATURE

Terminal Hyperlinks Open Across Wrapped Lines, Path Refusals Hint at Letter Casing

Terminal readability and interaction details have been improved across multiple terminal environments. In Ghostty over tmux (a terminal multiplexer), an issue where Cmd+click could not open links in sessions launched from the agents view is now resolved. When help links in /status or auto mode billing notices wrap due to window width, a bug that opened only the first part of the address has been fixed. On macOS and Windows, when access to a path outside the working directories is refused and differs only by letter case from an internal path, the refusal message explicitly names that spelling. Furthermore, the contrast of faint gray secondary text—including hints, details in /stats, /model, /sandbox, and rejected-action messages—has been increased.

In the manner of a library updating its directory signs, long addresses previously broke across line wraps while dim lighting obscured catalog notes; now signs deepen text contrast and directional cues become noticeably clearer.
FEATURE

Context Summary Table Compacted, Grouping On-Demand Tools to Conserve Token Usage

When checking current conversation usage, running /context incurs noticeably lower overhead. Previously, running the command in the terminal sent the full visual grid to Claude on every later turn, consuming substantial tokens (units of text processed and billed by AI). Claude is now fixed to read only the plain-text table. This table is also compacted so each list keeps only its 10 largest rows. Meanwhile, on-demand MCP (Model Context Protocol, a protocol connecting AI to external tools) tools share one row per server until called.

Resembling a financial audit meeting, presenters previously projected full hundred-page ledgers on every remark, but now summarize only the top ten expenses while grouping scattered items under their parent departments.
BUGFIX

Fix Network File System Startup Scans, Refining File Writes and Background Command Output Capture

When opening projects on Linux over network file systems (including NFS, SMB, and Lustre), an issue where startup scanned and listed every project file has been eliminated. The Write tool no longer ends the turn as a refusal when failing to read the original file to overwrite. For command execution, fixes resolve issues where background Bash commands that finish almost instantly lost output when marked completed, as well as diffs missing files written just before command completion. When using the notebook editor (NotebookEdit), a bug where modifying the wrong cell occurred if notebook contents changed during permission prompts has been fixed. Additionally, claude purge and old session cleanup now retry folders that could not be fully deleted, reporting an error if they still remain.

BUGFIX

Surveys and feedback prompts stop appearing after server refusal, and third-party gateways stop drafting feedback

After the server refuses feedback for your organization, satisfaction surveys, Claude-drafted feedback, and /feedback will no longer keep popping up in the terminal. In addition, Claude no longer drafts feedback on third-party gateways where it cannot be sent.

A building's security desk notes a clear policy against visitor surveys: while forms previously still reached individual offices, the front desk now blocks them all to restore complete quiet to the work environment.
BUGFIX

Agent SDK enhances error reporting and telemetry, running hooks for tools finished after interruptions

Debugging and monitoring are now more precise when developing automated applications with the Agent SDK. Informational messages sent to clients no longer drop text, and when a host disk is full, you receive the specific failure reason instead of a generic exit code. Telemetry metrics are also more accurate, as pre-started processes are no longer counted early in session counts, counting only once when they are actually claimed. Detailed beta tracing now provides CLAUDE_CODE_CLIENT_CERT to collectors that require client certificates. Tool calls that finish after a new message interrupts a turn still run PostToolUse hooks (small programs triggered after a tool completes), giving the hook up to 10 seconds to finish. If an execution was previously interrupted in plan mode, the environment variable CLAUDE_CODE_RESUME_INTERRUPTED_TURN will no longer rerun that turn without reason when resuming in another permission mode.

BUGFIX

Plugin updates automatically install new dependencies, and directories register marketplaces only after trust

When an installed plugin releases a new version, newly added dependencies are installed whether through background auto-updates, manually entering claude plugin update, or choosing "Update now" in /plugin. Directories introduced via --add-dir register plugin marketplaces only after their own trust dialog has been accepted. A plugin-provided subagentStatusLine command now properly expands the environment variable ${CLAUDE_PLUGIN_ROOT}, making it convenient to reference the plugin's own scripts directly. When running plugin evaluations, warnings no longer suggest max: 0 for tools that must not be called, which could never pass.

BUGFIX

Mod hot reloading fixes file watching, while sandbox mode restricts nested directory loading

When developing and debugging mods (custom modules), hot reload previously could miss a file that was deleted right after appearing as well as its return. Hot reload is the mechanism that applies changes without restarting; in .claude/skills, neither of these file changes is missed now. In cloud sessions, typing three consecutive messages instead of answering a module's question will no longer cause mod hot reload to turn off unexpectedly for that session. In addition, with the Bash sandbox enabled, skill folders below the starting folder no longer load automatically by default, requiring you to start the tool in that subdirectory or switch there using /cd to load them.

FEATURE

Artifact database writes gain marker protection, while web fetching prompts pasting shared chats

Multiple operational hints and file protection mechanisms have been improved when using the Artifact database feature. A previously refused issue when reading the database and saving to a destination folder using out_dir has been resolved; error messages now provide more specific guidance when updates target nonexistent documents or when the service pauses repeated refused writes. When saving rows that others may have written, a hidden marker file is created, and existing files lacking this marker (including exports from earlier versions) are left alone and reported. Artifacts without a database no longer futilely retry database calls and clearly indicate whether republishing helps. In addition, fetching claude.ai shared chat links with the web-fetching tool no longer misreports them as empty pages, but clearly states they cannot be read and suggests pasting the conversation directly into the input box.

BUGFIX

Agent management view preserves unsent drafts, fixing background session replies and preview formatting

In the terminal's multi-agent management view, the experience of switching and operating across different sessions has been improved. When a background session is waiting at a permission prompt, sending a reply in the management view no longer appears as if it was sent; your input stays in the text box with a prompt to open that session and reply. When multiple management views run in the same directory, one view exiting or restarting for an update will no longer mistakenly delete or load draft text saved by another view. For command previews, long commands, results, and status lines (bars displayed at the very bottom of the terminal) now include an ellipsis when truncated, while bold text, backticks, and tags are fully preserved in commands waiting for approval. These reply, draft, and preview issues have been resolved.

FEATURE

Chrome extension auto-checks interrupted connections, retaining JavaScript tool results in conversation

Interruption recovery and web workflows have been improved when using the Claude in Chrome browser extension. If a connection drops mid-action, the tool no longer arbitrarily reports the extension as disconnected; instead, it checks the current page state before repeating an action that may have already executed, and waits up to 6 seconds after a brief disconnect for the session's original browser to return before selecting another. Returned content from the JavaScript tool javascript_tool of up to 60,000 characters now stays directly in the current conversation instead of being forced into an external file. In addition, built-in tools no longer include shortcuts_list and shortcuts_execute, which previously listed and launched shortcuts saved in the extension.

An online shopper encounters a sudden connection drop during payment: upon reconnecting, the system first verifies transaction records rather than charging twice, waits briefly for the initial connection to recover, and displays details right on screen without needing a separate receipt.
BUGFIX

Remote control handles first-run prompts, accepts piped y without a trailing newline, and syncs externally lifted usage limits

Error handling for scripts and automation integrations has been reinforced when connecting remotely with claude remote-control. When a first-run question receives no response (such as when running in background services, batch jobs, or pressing Ctrl+C), the tool no longer silently exits with status 0 representing success, but explains why and exits with status 1. Passing a piped letter y without a trailing newline is now also correctly treated as confirmation. Across devices, when a usage limit is lifted externally, remote sessions on other devices no longer stay stuck on "Limit reached". An issue where the Claude iOS app occasionally missed the file card when Claude sent a single file has also been fixed. Additionally, idle background sessions started through environment-variable gateway routing no longer disconnect from the gateway unexpectedly after an update.

FEATURE

Self-hosted runner isolates workspace naming, disables untrusted hooks, and exits early on failed self-checks

Security isolation and multi-project handling mechanisms have been strengthened when maintaining runners in enterprise self-hosted environments. Specifying --trust-workspace false now also prevents hooks in repository configuration files and skills from running, in addition to existing protections. Runners started with --use-anthropic-git-proxy or --configure-git will now exit first if a startup self-check fails, rather than registering with the server beforehand. If the server repeatedly refuses to renew model access, the runner retries sooner and posts a warning in the session. When CLAUDE_RUNNER_CHECKOUT_PATH is configured, each repository within the same session receives its own dedicated folder, with duplicate folder names automatically separated by numeric suffixes. Furthermore, debug logs are no longer uploaded after a session ends; logs from failed sessions remain on the runner host unless --remove-session-state is set.

FEATURE

Cloud sessions preserve permission rules across node migrations, keeping background agents running during pending sends

Container scheduling and permission rule transitions receive stronger safeguards when running sessions in the cloud. An issue that caused session-specific deny and ask rules to be lost when a session moved to a new worker node has been fixed. If such deny and ask rules cannot all be preserved, the session's allow rules are dropped, meaning you may be asked again. Entering /permissions no longer merely reports that it is unavailable, but clearly indicates where rules reside and how to modify them. Clicking Send now on a waiting message no longer terminates agents running in the background. Scheduled tasks encountering a connector named memory now automatically attach a short suffix to complete mounting and retain it. Additionally, links in stalled-setup warnings for self-hosted environments now prefer and explicitly name your organization's default environment or one with an active runner.

FEATURE

Clearing the screen preserves running background tasks, syncing the web task list and slash menu

When you want to tidy your view in the terminal, entering /clear to clear the conversation screen no longer accidentally kills running tasks. Running commands are safely preserved for background agents, teammates, workflows that keep running, and foreground subagents belonging to background agents and teammates. On the web interface, the issue where background tasks disappeared from the list after /clear until another task started or ended has been fixed. In cloud sessions on mobile and web, hidden commands that should not be public no longer mistakenly appear in the slash command menu. In addition, typing /usage in cloud sessions where plan limits cannot be directly displayed now proactively provides a hyperlink to the website settings page to view usage.

Just as erasing an office whiteboard only wipes away outdated notes, the production lines and gauge monitors running in the factory behind it continue operating, and the board list stays connected and in sync across departments.
FEATURE

Unlinking a GitHub organization turns off the "All repositories" review setting

For enterprise plan admin backends, permission protections and settings interfaces have received multiple enhancements. When unlinking a GitHub organization in the code review service, the "All repositories" review setting under that organization turns off automatically, and it stays off after relinking until an admin manually turns it back on. On the Models admin page for enterprise backends with Claude Tag connected, a dedicated row has been added with a link pointing directly to where its model defaults are managed. During Claude Tag setup, if the channel list cannot fully load, admins can now launch directly without picking a specific channel. In addition, concurrency conflict protection has been added when saving auto mode allow rules. If the system detects that another admin modified settings in the meantime, the save is refused with a notice, preventing settings from being overwritten silently.

BUGFIX

VSCode extension protects long prompts in the input box and improves dictation and chat panel performance

When using the Claude extension in the Visual Studio Code editor, interactive performance in the chat panel has received comprehensive improvements. When entering extra-long prompts exceeding 50,000 characters, the content is no longer cut off silently. Instead, it stays in the chat box with a notice, and pasting text over the limit is explicitly refused. Clicking the survey or "Report a problem" buttons no longer accidentally sends an unfinished draft. Running the dictation command claude-vscode.toggleDictation acts only on the currently used Claude view, and pressing it again stops it. Dragging a file whose path contains a very long run of consecutive / characters no longer freezes the panel, nor does the panel stutter while a reply streams in with many unclosed $$ math blocks that are each shorter than the last. Furthermore, the diagnostics tool for large workspaces now automatically skips files with no problems, supports specifying a severity threshold, and returns compact JSON format.

FEATURE

VSCode extension protects plans on window reload, refining session and marketplace management

When reloading a window in Visual Studio Code, Claude no longer carries out unapproved plans without authorization. If a step was previously interrupted in plan mode, execution stops immediately with a notice when the session resumes in another permission mode. When opening cloud sessions from the extension's Web tab, conversation turns removed by /clear, or by Retry or Edit of an entered prompt, no longer bizarrely reappear. In addition, renaming a deleted session will not cause its file to come back. When removing a plugin marketplace, the confirmation screen now checks which of that marketplace's plugins are currently installed. When encountering an unauthenticated state behind a gateway, the prompt message appears in a prominent error style with a sign-in link. In addition, links in replies pointing to Claude sign-in, connector, or API addresses are now displayed as text showing the address instead of opening in a browser.
