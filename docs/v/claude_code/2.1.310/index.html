Claude Code 2.1.310

發布日期：2026-10-23

繁體中文

新功能

Bedrock、Vertex 與 Foundry 支援監控工具，並阻擋前景長時等待

透過 Bedrock、Vertex 或 Foundry 使用 Claude Code，或關閉遙測或非必要網路流量時，現在也能使用監控工具（Monitor tool，用來追蹤背景任務進度的小工具）與外掛監控功能。在上述情況下，如果程式發出長時間的前景暫停等待，也會被直接阻擋，避免終端機長時間卡在等待畫面。

走進實驗室，以前進度儀表板無法啟用，遇到長耗時工作只能原地乾等；現在能查看儀表板掌握背景工作狀態，也會攔下讓人原地久候的等待安排。

當你請 Claude 執行多步驟資料轉換，並將工作丟到背景執行時，就能透過監控工具掌握外掛與任務狀態，不必擔心前景指令無休止地休眠空轉。

問題修復

連線網關拒收特定測試參數時，自動移除並重試請求

透過特定代理伺服器或自訂網關連線時，部分相容伺服器會拒收 effort-2025-11-24 測試參數，或不允許在對話中途加入系統訊息。以前這類請求會直接宣告失敗並中斷操作。現在遇到這種錯誤時，Claude Code 會自動去除不被接受的參數與中途訊息並重新發送請求，讓你在企業網關後方也能順暢發問。

問題修復

清理週期設為極大值時，不再誤刪貼上的圖片等近期檔案

當你為了保留歷史紀錄而刻意把暫存清理天數 cleanupPeriodDays 設得非常大時，背景清理機制以前存在邏輯瑕疵，反而會把剛貼到對話中的圖片等近期檔案誤刪。這個問題現在已經修好。即使清理週期設得再長，Claude Code 也不會再提早清除這些近期剛建立的重要檔案。

新功能

對話壓縮精簡密集文字，並改善龐大逐字稿的記憶體用量

遇到提示詞超出上限（Prompt is too long）的錯誤後，壓縮對話仍可能留下太多內容，讓下一次請求再次失敗。這項壓縮處理（compaction，把落落長的前文摘要簡化）能釋放空間。以前面對含有 base64 編碼字串或 SVG 圖形等密集文字時，壓縮過程會保留過多原始內容，導致剛縮完的下一次請求仍可能報錯失敗，這個問題已經修好。

整理超重的行李箱時，以前收拾過後仍留下太多東西，再過磅還是可能超標；現在修好的，就是整理後仍保留過多內容的問題。

逐字稿檔案非常龐大時，改善非互動工作階段在壓縮期間的記憶體用量，例如加上 -p 參數或透過 Agent SDK 呼叫的工作階段。

新功能

權限提示明列符號連結目標，並補強掛鉤檢查與外部讀取說明

審核工具存取權限或執行外部操作時，清楚的提示資訊能協助你做出正確判斷。當 Claude 請求讀取符號連結（symlink，指向另一個位置的捷徑檔）時，提示視窗以前只顯示捷徑名稱，現在會直接標明它指向的實際目標。在 Windows 系統中，如果未安裝 Git Bash 且掛鉤指令只包含帶引號的字串，例如帶引號的路徑，PreToolUse 與 PermissionRequest 掛鉤（hook，特定事件發生時被觸發的小程式）以前會錯誤放行工具呼叫，這項問題已經修好。在 auto 模式首次讀取工作目錄外部前，提示會說明，在什麼情況下封鎖這些讀取，會讓後續終端機指令要求權限。以前你可能看不清捷徑去向或摸不透權限連鎖反應，現在每項提示都交代清楚，掛鉤也能確實把關。

問題修復

外部編輯器長時間編輯關閉後，不再立即觸發逾時自動繼續

回答問題時，你可能會在 Vim 或 VS Code 等外部編輯器中仔細推敲回覆內容。以前編輯較久後關閉視窗，自動繼續的逾時會在關閉瞬間觸發。現在這個計時問題已經修好，不會再於關閉瞬間觸發。

新功能

tmux 內啟用直通時，kitty、Ghostty 與 iTerm2 可正常繪製模組圖片

平時習慣在 kitty、Ghostty 或 iTerm2 3.5 以上版本的終端機裡開啟全螢幕渲染，並搭配 tmux 多工器工作的使用者，現在模組的圖片元件能正確繪製畫面。只要你在 tmux 中開啟 allow-passthrough 直通選項與 focus-events 焦點事件，模組內的圖片元件就能直接顯示圖像。

站在特製玻璃窗前觀賞室內畫展時，以前若拉上雙層隔板，參觀者只能透過底部的標籤紙閱讀文字說明；現在只要開啟專用透光通道與感應開關，窗內鮮豔的畫作就能原汁原味投射出來。

在此之前，符合這些條件的終端機環境往往無法渲染圖形，畫面只會乾巴巴地印出替代文字（alt text）。這項改進讓終端機內的視覺外掛與圖片預覽恢復正常顯示。

新功能

Linux 沙盒啟動受阻時，提示 Ubuntu 的 AppArmor 限制與解除方式

在 Linux 系統尤其是 Ubuntu 環境下啟動隔離沙盒時，安全機制有時會引發衝突。當系統安全模組 AppArmor 對使用者命名空間（user namespaces）的存取限制導致底層工具 bubblewrap 無法順利啟動沙盒時，/sandbox 指令與啟動警告現在會明確點名這項具體原因。

向大樓管理處申請租借活動隔間時，以前警衛發現施工許可不足時只在門口亮紅燈，讓人完全摸不著頭緒；現在告示牌會明確寫出是大樓的防火防護條例限制了臨時搭棚，並附上前往服務台簽署豁免文件的具體步驟。

提示訊息中會詳細列出 Ubuntu 的限制來源，並同步說明解除封鎖的操作方法，遇到沙盒無法啟動時不必再去翻找系統日誌除錯。

新功能

非互動模式下 MCP 工具詢問逾時，通知 Claude 勿重複呼叫

藉由指令碼或自動化排程執行非互動工作階段，並調用 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）工具時，雙向溝通若卡住會影響後續決策。如果工具伺服器在執行中拋出進一步詢問，而在無人值守的非互動狀態下無人應答導致逾時，系統傳回的錯誤訊息現在有了具體調整。

總機櫃檯透過廣播呼叫未到場的訪客時，以前若無人應答，系統只回傳線路逾時代碼，導致助理不斷重複廣播同一通呼叫；現在櫃檯會收到註記無人前來的單據，明確告知不要再次呼叫，直接依現況結案。

新的錯誤回報會清楚告訴 Claude 剛剛並未收到任何答案，並指示它不要再重複嘗試發起相同的工具呼叫，防止自動化任務陷入無意義的死循環。

問題修復

VS Code 修復計畫意見回饋誤核准，與雲端切換分支報錯

在 VS Code 擴充套件中審查規劃步驟或管理歷史紀錄時，兩處按鈕互動問題已經修復。在計畫審查卡片中，當你輸入修改建議並對「Send feedback and keep planning」按鈕按下 Enter 鍵時，以前擴充套件會錯誤地直接核准整份計畫，而非將你的意見送回重新規劃。

填寫紙本問卷調查時，以前按下意見欄的提交鈕卻被櫃檯當作同意跳過後續步驟，從網頁存檔調閱檔案切換工作夾時面板甚至直接黑屏；現在遞交回饋會確實退回修正，跨分頁切換分支時也能平穩銜接。

另一項修復針對工作階段歷史（Session history）的 Web 標籤頁：點開雲端工作階段並點擊「Switch branch & continue」切換分支後，面板不會再無端跳出「Something went wrong」的報錯訊息。

新功能

企業自訂角色支援雲端工作階段與遠端控制，開啟前列出授權清單

公司想要開放成員使用新工具，卻又擔心權限範圍無法精準控管。Enterprise 自訂角色現在正式納入 Claude Code 雲端工作階段與遠端控制的存取權限，所有者可依據各團隊職責分別授予或收回。

企業總部的門禁通行系統調整了高階防護規則，以前開啟特殊機房通道時只要扳動總開關便直接放行，容易忽略哪些部門持有感應磁扣；現在扳下開關時系統會跳出確認視窗，逐一列出擁有進出權限的職務清單，避免權限意外大開。

配合這項調整，在管理員設定中開啟這兩項功能時，介面會主動要求你再次確認，並完整列出目前已擁有該權限的自訂角色，防止權限在不知情的情況下外溢。

新功能

雲端環境設定支援檔案載入腳本，排版簡化並明列對話框錯誤

網頁介面上配置雲端工作階段的執行環境與例行排程時，多項表單操作與錯誤反饋獲得改善。環境設定對話框調整了版面結構，網路存取權限、安裝腳本與環境變數改由各自獨立的整列項目展開，不再把所有編輯區塊一口氣全塞在同一個畫面中。在載入安裝腳本時，新增了「Choose file」按鈕，讓你能直接選取檔案上傳。工作階段啟動檢查清單中的腳本輸出，現在也收納在可捲動的方框內，方便閱讀長篇日誌。錯誤回報方面，在雲端環境編輯對話框中執行儲存或封存若不幸失敗，內部會直接顯示錯誤說明。例行排程的 API 授權令牌（token，用來驗證身分的授權代碼）操作若遭遇失敗，錯誤也不再只是短暫閃過快顯通知，而是完整呈現在編輯對話框內。

問題修復

Claude Tag 支援富文字格式指令，並修正後台載入與篩選錯誤

使用 Claude Tag 協同工具時，指令辨識與管理後台修正了多項介面顯示異常。以往在聊天視窗中輸入帶有驚嘆號的指令（例如 !restart 與 !help）時，若套用了粗體、斜體或刪除線等文字造型，系統會誤當成普通文字聊天而忽略執行，現在帶有格式的指令均能正常被辨識與觸發。在管理後台方面，背景重新整理套件組合清單若發生暫時性失敗，管理頻道與工作區頁面不會再直接被整片錯誤畫面取代，保留原有操作介面。在管理員設定的支出上限頁面中，頻道名稱載入期間若套用篩選條件，系統也不會再過早斷定查無頻道，避免載入中途產生誤導。

新功能

Code Review 儲存庫載入失敗自動重試，並維持列表正常顯示

管理後台配置程式碼審查（Code Review）的儲存庫清單時，重新整理失敗的畫面處理獲得改善。以前只要儲存庫清單背景重新整理失敗，管理區塊就會把所有已設定的儲存庫與功能切換開關整片隱藏，造成管理員無法操作。

圖書館閱覽室更新藏書架目錄時，以前只要網路斷線查不到最新清單，管理員便把整排架子全部蓋上黑布隱藏；現在不僅會自動再次連線抓取，連線失敗時也會維持原有書冊展示，只在頂部掛上一張醒目的重試牌子。

現在當首次載入清單遭遇問題時，系統會自動發起重試；如果重試後依然無法取得資料，頁面會跳出單一「Try again」橫幅方便你手動再次嘗試，不再無故清空畫面上的儲存庫與開關。

FEATURE

Bedrock, Vertex, and Foundry Support the Monitor Tool and Block Long Foreground Waits

When using Claude Code through Bedrock, Vertex, or Foundry, or when telemetry or nonessential network traffic is disabled, you can now use the Monitor tool (a utility for tracking the progress of background tasks) alongside plugin monitoring features. In these scenarios, if a program issues a long foreground pause wait, it is also directly blocked to prevent the terminal from being stuck on a waiting screen for extended periods.

Step into a laboratory: previously, the progress dashboard could not be enabled, leaving you waiting idly during lengthy tasks; now you can check the dashboard to track background work, and arrangements that keep you waiting idly are intercepted.

When you ask Claude to run a multi-step data transformation and send the work to the background, you can track plugin and task status through the Monitor tool without worrying about foreground commands sleeping indefinitely.

BUGFIX

Automatically Stripping Rejected Beta Parameters and Retrying Requests Behind Gateways

When connecting through certain proxy servers or custom gateways, some compatible servers reject the effort-2025-11-24 beta parameter or disallow adding system messages in the middle of a conversation. Previously, such requests would directly fail and interrupt the operation. Now when encountering this error, Claude Code automatically strips the unaccepted parameter and mid-conversation messages before retrying the request, allowing you to prompt smoothly even from behind corporate gateways.

BUGFIX

Setting the Cleanup Period to a Very Large Value No Longer Mistakenly Deletes Recent Files Like Pasted Images

When you intentionally set the temporary cleanup day count cleanupPeriodDays to a very large value to preserve history, the background cleanup mechanism previously had a logic flaw that mistakenly deleted recent files, such as images just pasted into the conversation. This issue is now fixed. Even when the cleanup period is set arbitrarily long, Claude Code will no longer prematurely purge these recently created important files.

FEATURE

Compacting Conversations Trims Dense Text and Improves Memory Usage for Huge Transcripts

After encountering an error where the prompt exceeds the limit ("Prompt is too long"), compressing the conversation could still leave behind too much content, causing the subsequent request to fail again. This compaction process (summarizing and streamlining lengthy earlier context) frees up space. Previously, when dealing with dense text containing base64-encoded strings or SVG graphics, the compaction process retained too much original content, causing the next request immediately after shrinking to still fail with an error; this issue is now fixed.

Picture packing an overweight suitcase: previously, too much remained even after tidying up, so it could still exceed the weight limit on the scale; what has now been fixed is the issue of keeping too much content after tidying.

When transcript files are very large, memory usage during compaction has been improved for non-interactive sessions, such as sessions with the -p parameter or those called via the Agent SDK.

FEATURE

Permission Prompts Explicitly List Symlink Targets, Strengthening Hook Checks and External Read Details

When reviewing tool access permissions or executing external operations, clear prompt details help you make the right call. When Claude requests to read a symlink (a shortcut file pointing to another location), the prompt window previously showed only the shortcut name, but now directly indicates the actual target it points to. On Windows systems, if Git Bash is not installed and the hook command contains only quoted strings, such as a quoted path, PreToolUse and PermissionRequest hooks (small programs triggered when specific events occur) previously allowed tool calls through by mistake, which has now been fixed. Before the first read outside the working directory in auto mode, the prompt explains under what circumstances blocking these reads will cause subsequent terminal commands to require permissions. Where you might previously have been unable to see where shortcuts lead or understand cascading permission effects, each prompt now provides clear explanations and hooks act as reliable gatekeepers.

BUGFIX

Closing an External Editor After a Long Edit No Longer Immediately Triggers Auto-Continue Timeout

When answering questions, you might carefully draft your response in an external editor such as Vim or VS Code. Previously, after editing for an extended period and closing the window, the auto-continue timeout would trigger the moment it closed. This timing issue has now been fixed and will no longer fire at the instant of closing.

FEATURE

kitty, Ghostty, and iTerm2 Can Render Mod Images Inside tmux with Passthrough Enabled

Users who customarily enable fullscreen rendering in kitty, Ghostty, or iTerm2 3.5+ while working with the tmux multiplexer can now have a mod's Image component render properly. As long as you turn on the allow-passthrough option and focus-events inside tmux, the Image component in the mod can display pictures directly.

Think of viewing an indoor art exhibition behind a special glass window: previously, if a double partition was drawn, visitors could only read text descriptions through bottom label strips; now, as long as you open the dedicated light-transmitting channel and sensor switch, the brightly colored paintings inside can be projected as intended.

Prior to this, terminal environments matching these conditions often failed to render graphics, printing only plain alt text on the screen. This improvement restores visual plugins and image previews inside the terminal to normal display.

FEATURE

Linux Names Ubuntu AppArmor Restrictions and Fixes When Sandbox Startup Is Blocked

When starting an isolated sandbox on Linux, particularly in an Ubuntu environment, security mechanisms sometimes cause conflicts. When AppArmor restrictions on user namespaces prevent the underlying tool bubblewrap from starting the sandbox smoothly, the /sandbox command and startup warnings now explicitly name this specific cause.

Consider renting a movable partition from building management: previously, guards merely flashed a red light at the entrance when construction permits fell short, leaving people completely puzzled; now, signs explicitly state that building fire prevention codes restrict temporary canopies and provide concrete steps to visit the service desk to sign an exemption document.

The prompt details the source of the Ubuntu restriction while explaining how to lift it, so you no longer have to dig through system logs to troubleshoot when a sandbox fails to start.

FEATURE

MCP Tool Prompt Timeouts in Non-Interactive Mode Inform Claude Not to Repeat Calls

When running non-interactive sessions via scripts or automated schedules and invoking MCP (Model Context Protocol, a protocol connecting AI to external tools) tools, stalled two-way communication impacts subsequent decisions. If a tool server raises a further inquiry during execution and nobody responds in the unattended non-interactive state causing a timeout, the error message returned by the system has now been specifically adjusted.

Imagine a reception desk paging an absent visitor over the intercom: previously, if no one answered, the system only returned a line timeout code, leading the assistant to repeatedly broadcast the same page; now, the desk receives a slip noting that no one arrived, explicitly directing them not to page again and to close the matter as is.

The updated error report clearly informs Claude that no answer arrived and instructs it not to retry the same tool call, preventing automated tasks from falling into meaningless dead loops.

BUGFIX

VS Code Fixes Feedback Misapproval on Plans and Cloud Branch Switching Errors

When reviewing planning steps or managing history in the VS Code extension, two button interaction issues have been fixed. In the plan review card, when you type feedback suggestions and press Enter on the "Send feedback and keep planning" button, the extension previously mistakenly approved the entire plan rather than sending your comments back for re-planning.

Take filling out a paper survey: previously, pressing the submit button in the feedback field was mistakenly treated by the front desk as approval that skipped follow-up steps, and retrieving files from web archives to switch folders even caused the panel to go black; now, submitting feedback reliably sends it back for revision, and switching branches across tabs transitions smoothly.

Another fix addresses the Web tab in Session history: after opening a cloud session and clicking "Switch branch & continue" to switch branches, the panel will no longer unexpectedly pop up a "Something went wrong" error message.

FEATURE

Enterprise Custom Roles Support Cloud Sessions and Remote Control, Listing Granted Roles Before Activation

Companies want to let members use new tools without losing precise control over permission boundaries. Enterprise custom roles now officially include access permissions for Claude Code cloud sessions and Remote Control, allowing Owners to grant or revoke access based on team responsibilities.

A corporate headquarters updates its high-level security protocol for access gates. Previously, flipping a master switch immediately opened passage to a secure server room, making it easy to overlook which departments held keycards. Flipping that switch now brings up a confirmation prompt that lists every job title with access clearance, preventing permissions from widening unintentionally.

Alongside this change, turning on either feature in admin settings now prompts you for confirmation and lists the custom roles that currently hold that permission, preventing unintended privilege expansion.

FEATURE

Cloud Environment Settings Support Script File Loading with a Simplified Layout and In-Dialog Errors

Several form interactions and error reporting behaviors have been improved when configuring cloud session runtime environments and routines on the web interface. The cloud environment dialog refines its layout structure, opening network access, setup script, and environment variables from dedicated rows instead of listing every editor at once on a single screen. A new "Choose file" button lets you select and upload a setup script directly from a file. Setup script output in the session start checklist now appears inside a scrolling box, making long logs easier to read. For error reporting, failed saves and archives in the cloud environment edit dialog now display an error message directly inside the dialog. If an action on a routine API token (an authorization code used to verify identity) fails, the error no longer flashes only as a toast notification, but appears fully inside the routine edit dialog.

BUGFIX

Claude Tag Supports Formatted Commands and Fixes Admin Loading and Filtering Errors

Several display issues in command recognition and the admin console have been resolved when using the Claude Tag collaboration tool. When entering ! commands (such as !restart and !help) in a chat window, applying text formatting like bold, italic, or strikethrough previously caused the system to treat them as ordinary messages and skip execution. Formatted commands are now recognized and executed properly. In the admin console, if a background refresh of the bundle list encounters a temporary failure, the admin channel and workspace pages are no longer replaced entirely by a load error, preserving the existing interface. On the spend limits page in admin settings, applying a filter while channel names are still loading will no longer prematurely report that no channels match, avoiding confusion midway through loading.

FEATURE

Code Review Retries Failed Repository Loads Automatically and Preserves the List Display

Screen handling during a failed refresh has been improved when configuring repository lists for Code Review in the admin console. Previously, whenever a background refresh of the repository list failed, the admin section completely hid all configured repositories and switches, preventing administrators from taking action.

A library reading room updates its shelf catalog. In the past, whenever a network drop prevented staff from fetching the newest list, the librarian draped black cloths over the entire row of shelves to hide them completely. Now the system automatically attempts to reconnect, keeps the existing books on display if the connection fails, and hangs a single visible retry sign above the shelf.

The system now automatically retries when the initial list load encounters an issue. If data still cannot be retrieved after retrying, the page displays a single "Try again" banner for manual retry instead of clearing repositories and switches from the screen.
