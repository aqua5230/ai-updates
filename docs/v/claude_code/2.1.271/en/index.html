Claude Code 2.1.271

Released: 2026-09-14

Release notes

FEATURE

Code Review Stops Duplicate Posts and Won't Re-report Resolved Findings

When submitting pull requests on GitHub for review, missing reviews or duplicate reports are frustrating.

In repositories configured to review once per PR, if a new commit arrives while waiting in the queue, it now properly reviews that requested commit. When GitHub reports an error for a review that was actually created, it no longer repeatedly posts the same findings two or three times. For security findings previously resolved by a human, follow-up reviews will not re-post them even if subsequent code line numbers shift. Reopening a completed /ultrareview cloud session in the Claude app will no longer restart the entire review unprompted.

This is like a magazine editor proofreading manuscripts: updating a paragraph won't trigger three duplicate rejection notices for the same typo, and chapters already verified as fixed won't be flagged again just because page numbers shifted.
FEATURE

Claude Tag Preserves Thread Context and Clarifies Notifications and Environment Menus

When invoking Claude Tag in chat groups to assist with work, managing messages across multiple threads is now far more reliable.

In channels where Claude stays continuously active, even if conversations mostly take place within threads, thread activity now preserves working context instead of resetting memory roughly once every hour. A thread asking Claude to monitor a pull request continues to receive CI failure, comment, and review notifications even after restarting Claude. When the first message of a thread that Claude already replied to is deleted, Claude terminates its work there as expected. Claude no longer holds back posts due to earlier instructions addressed to other bots; only instructions addressed to Claude take effect, and it proactively asks when unsure. The card posted upon joining a busy channel now explains the real reason rather than incorrectly claiming it sees a lot of automated posts. The Environment picker in admin settings clearly labels Anthropic-hosted or self-hosted options and provides links to edit or create them.

This is like a dedicated secretary in a meeting room who won't suddenly forget recent decisions as long as people are still speaking in breakout threads, nor interject when someone delegates tasks to a different assistant.
FEATURE

Web Routines Page Redesigned with Dual Tabs Displaying Run Status

When managing automated scheduled tasks on the web, the Routines page introduces a fresh layout.

On claude.ai/code, the layout is split into two major tabs, "Yours" and "Templates", using two-column routine cards that intuitively display the run status of each routine. The previous calendar view has also been removed to keep the list view streamlined.

This is like organizing a toolbox into "Custom Tools" and "Ready-made Templates" drawers, where each task card displays a status light so you can find what you need at a glance.
FEATURE

Cloud Environments Add Custom Domain Whitelisting, Offline Sessions Restart on Message

Managing cloud development environments now offers finer network access controls and a rapid recovery mechanism.

In the Cloud environments editor within admin settings, a Custom network access option has been added, offering the same allowed-domains list available in the claude.ai/code environment dialog. The admin page clearly lists the default environments for Claude Tag and Claude Code, complete with links to change them and labels indicating recommended types to create. When a cloud session's background process exits while the session still appears connected, it previously took about ten minutes to respond; now sending a message restarts it immediately.

This control setup is like gated community access management: only pre-registered domains on the allowlist can connect, and if a remote connection drops, ringing the doorbell instantly reconnects the power.
FEATURE

VSCode Supports Disabling Auto-Attached Files and Stabilizes Session List

When coding with Claude Code in VSCode, message attachments and history lists receive several user experience improvements.

A new "Attach Open File" setting allows turning off the automatic inclusion of currently open files in messages, while explicitly selected text is still attached. Fixed an issue where session history only showed the current session when the workspace was located on a Windows mapped network drive or SUBST virtual drive. When both Active and Open are checked in the filter menu, open idle sessions are no longer hidden. When the session list refreshes, newly created chat windows no longer switch back to the previous conversation. After changing the CLAUDE_CONFIG_DIR environment variable in settings, the sidebar and open tabs immediately apply the new directory. The "on" state color of toggle switches has also changed from Claude orange to the editor theme's button color.

This is like adding a toggle sticky note to a sketchbook: when you don't want to send the entire portfolio, simply flipping the switch sends only the draft excerpt highlighted with your marker.
FEATURE

VSCode Upgrades Hook Save Guards and Eliminates Flashing Console Windows

When fine-tuning automation rules in the VSCode extension, settings dialogs and background window disturbances are now resolved.

The Hooks and Permission rules dialogs no longer falsely report successful saves as failed, and issues causing the screen to go blank under plugin policy locks or showing color codes in save errors are fixed. Saving hooks on replace no longer produces duplicates, retyping header names in different capitalization preserves secrets, and the local settings file is added to gitignore before the save returns. When the settings file itself blocks saving, the popup includes an "Open settings file" button alongside the error reason. Background Git, ripgrep, or sign-in checks on Windows no longer cause black console windows to flash frequently. Prompt cache clock hover text delays and duplicate tooltips on the auto-compact icon are also fixed.

This is like foolproof design on an electronic form: providing an edit button whenever a configuration error occurs, while background verification runs silently without flashing black windows on your screen.
BUGFIX

Remote Connections Add Fast Mode, Fixing /fast Disabling and Fallback Speeds

When running Claude Code Remote sessions in cloud or self-hosted environments, users can now enjoy the accelerated experience of fast mode.

Where organization policy allows, fast mode can be enabled via host settings or by typing /fast directly in the session. When the organization disables fast mode, typing /fast off now turns it off properly instead of returning an error stating the mode is unavailable. Sessions started by skipping organization checks will display the rejection reason and stop resending fast requests every turn once the API rejects them. When encountering usage quota limits or system overloads, the retry watchdog automatically switches speeds. The system falls back to standard speed rather than failing the turn or insisting on fast retries.

This is like driving in an express lane on a highway: you cruise smoothly with company clearance, but automatically blend back into standard lanes if quotas run out or traffic becomes congested.
FEATURE

Enterprise Policies Update Instantly with Custom Model Pricing Multipliers

Managing development environments across organizations now features more precise policy distribution and cost chargebacks.

A multiplier parameter above 1 and up to 10 has been added to the modelPricing managed setting and the Claude apps gateway pricing block to facilitate marked-up internal chargeback rates. When switching accounts, organizations, or API keys, cached organization policies refresh immediately. When policies finish loading after startup or change mid-session, tool and command lists update synchronously. When an enterprise managed-mcp.json file cannot be parsed, it issues a warning at startup while maintaining exclusive control, blocking unapproved MCP servers from loading. Fixed an issue where organization policies were rejected when fetched through third-party local proxies configured via ANTHROPIC_UNIX_SOCKET.

This is like a corporate accounting system where departments split budgets accurately using custom multipliers, and scanning a new employee badge immediately activates their updated authorization rules.
FEATURE

Self-Hosted Runners Support Drain Markers and Store Oversized Configs on Disk

When operating self-hosted runners on your own servers, host maintenance and large project setups are significantly more reliable.

Running claude self-hosted-runner --drain-marker-file <path> allows the runner to report its exit to the server as a host drain upon receiving a SIGTERM signal if the specified file exists, though this functions strictly as telemetry reporting without triggering extra scheduling. When the host config directory exceeds 64 MiB, sessions previously suffered from silently losing the entire host config, including settings, skills, plugins, and MCP servers. A new --host-config-snapshot disk|memory option now allows placing config snapshots on disk or in memory.

This is like placing a maintenance tag on a freight train before depot servicing: dispatch receives the telemetry status while the full manifest is backed up safely so no cars are lost.
FEATURE

Sandboxed Commands Configure Domain Access Independently, Auto Mode Reviews Inline Commands

When executing terminal operations in auto mode with sandboxing, network security boundaries are much tighter.

Bash, PowerShell, and Monitor commands in sandboxed mode now include per-command allowed_domains lists, ensuring required network hosts are reviewed alongside each command and opened exclusively for it while all other hosts are refused. Inline ! shell commands embedded inside skills or slash commands now follow default-mode permission rules rather than being evaluated entirely by the classifier; commands not covered by any rule execute as reviewed tool calls.

This protection is like an isolated fume hood in a laboratory: each chemical experiment connects only to its dedicated reagent lines, preventing accidental contact with chemicals on neighboring workbenches.
BUGFIX

Bash Permission Checks Cover Wildcards to Prevent Cross-Directory Read Leaks

When running Bash tools from the command line, permission guards identify file paths and arguments with greater precision.

When commands like fmt or column are followed by unrecognized options, the file paths they read are no longer missed. When wildcards sit inside a command's pattern or option value, such as in grep -v dir/* file, all expanded files are now included in permission checks. Shell variable declaration flags can no longer misrepresent the command being run. Commands containing two directory changes, a subshell, or a cd and git chain will not bypass confirmation prompts when permissions.blockReadsOutsideWorkingDirectories is enabled in bypass or auto mode.

This is like a warehouse inspector auditing inventory sheets: even when cargo names contain wildcards or special abbreviations, every item must be checked individually to ensure it stays within designated storage bays.
FEATURE

Plugin Installations Support SHA-256 Verification to Prevent Tampered Commands

When installing or updating plugins within automated scripts, a safer verification mechanism replaces blind confirmations.

Both claude plugin install and claude plugin update have added the --accept-command <sha256> parameter to accept the exact command hash displayed in a previous --json run. This matches the displayed command hash precisely instead of passing -y unconditionally.

This is like checking an anti-tamper security seal on a parcel upon delivery: you only unbox after verifying the exact serial number, preventing goods from being swapped for different instructions in transit.
FEATURE

Subagents Support Lean Mode, Dynamic Workflows Auto-Pause at Quota Limits

When splitting projects across multiple agents, subagents load fewer rules and provide controllable reporting.

Custom and plugin subagents can use omitClaudeMd in agent frontmatter or --agents JSON to run without loading user, project, or local CLAUDE.md files, while managed policy files still load. Cloud sessions no longer reject subagent tool calls after worker restarts. Dynamic workflows pause upon hitting usage limits and resume automatically when reset, rather than dropping agents. Auto mode now reports back via dedicated hand-back calls reviewed by the safety classifier. The default dynamic workflow size on Pro plans is now small, and the medium guideline is lowered from 15 to 10 agents. The claude-api skill enables eager_input_streaming on streaming custom tools and initiates deliverable-shaped Managed Agents work with user.define_outcome.

This is like contractors working strictly off work orders and pausing production when materials run out.
FEATURE

Fullscreen /config Adds Mouse Support, Optimizing Paths and Selection Pills

Adjusting system preferences or typing paths in the terminal is now far more ergonomic.

The fullscreen /config panel adds mouse support, allowing the scroll wheel to navigate settings, clicking values to toggle them, and highlighting the row under the pointer. The /add-dir path input supports left and right arrow keys to move the cursor, and pressing Enter adds only the typed path instead of including highlighted autocompletions. Text fields outside the main prompt no longer shift a leading exclamation mark ! to the end of your input. Fixed a fullscreen rendering glitch where text retained a stale background color. The IDE selection indicator in prompts is now a [⧉ …] pill that wraps cleanly with text and can be removed with Backspace.

This overhaul feels like upgrading a control panel to a touchscreen: scrolling turns pages, clicking toggles switches, and the cursor moves freely while typing.
FEATURE

MCP Supports Bare Name Tool Searches and Periodic Updates for Long Tasks

Expanding toolsets via MCP now provides more reliable server connections and execution flows.

Tool search allows Claude to select tools by bare names without requiring full prefixed names. When an MCP server sends rapid list change notifications, sustained high CPU usage and duplicate requests are effectively prevented. Running tool calls in claude mcp serve send progress updates every 30 seconds, preventing idle timeouts from aborting long commands that produce no output. MCP servers marked alwaysLoad in cloud platforms can be used on the next turn once connected mid-conversation. Resuming single-prompt sessions whose tools come entirely from MCP servers no longer throws errors.

This is like a kitchen updating the order counter periodically so the front desk doesn't cancel orders assuming the system froze, while tools can be located quickly by shorthand names.
BUGFIX

MCP OAuth Registration Logic Fixed, Shortcuts Won't Cancel Reconnects

Connecting to third-party MCP servers requiring authentication is now much more stable during handshakes and remote control.

MCP OAuth client registration handling is fixed, resolving issues where denying consent forced re-registration, reused registrations for different redirect URIs, or, during concurrent writes, deleted valid credentials or kept a mismatched registration. Pressing Ctrl+O no longer cancels pending MCP server reconnections. Fixed an error where /mcp commands sent from Remote Control failed while the transcript view was open.

This is like issuing temporary visitor badges: visiting a different desk won't issue duplicate passes, and reconnecting won't be interrupted by someone opening a log window.
FEATURE

Artifacts Render as Styled Documents, Doubling Watched Artifact Limits

Preview quality and file synchronization for documents and code generated via artifacts receive significant upgrades.

Markdown files published as artifacts now render as styled document pages with title headers, document typography, and syntax-highlighted code. The maximum number of published artifacts a single session can watch simultaneously has increased from 5 to 10, facilitating tracking of republishes made elsewhere. Background sessions now watch artifacts they publish. Artifacts attached via /artifacts no longer disappear after resuming a session with --resume. Publish error messages are clearer, prompting users to write to a file first when none is specified and listing all supported capabilities.

This is like typesetting manuscript drafts into hardcover pages with dedicated color palettes for headers and code blocks, while simultaneously tracking revisions across multiple external documents.
BUGFIX

Precise Session Resumes Prevent False Cache Loss Warnings on Model Switches

Resuming earlier development work after interruptions is now smoother thanks to multiple session recovery fixes.

Resuming sessions via /resume or /teleport no longer retains previous file-read tracking, ensuring clean permission states. Resuming via --resume preserves the 1M token context window even when the resumed session's model family differs from the configured default. Switching back to the model a conversation originally ran on via /model no longer falsely warns about losing the conversation cache. After conversation compaction, running background commands are not duplicated. Cross-session messaging provides clear delivery notifications, and fullscreen menus on short terminals display session lists properly.

This is like placing a precise bookmark in a book: reopening it the next day preserves the memory and context of the current chapter without accidentally opening two copies of the book.
FEATURE

Hook Executions Display Elapsed Time, Supporting Esc to Cancel Waiting

Configuring automation hooks provides more immediate and transparent feedback.

While a SessionStart, UserPromptSubmit, PreToolUse, or SessionEnd hook runs, the status spinner clearly shows its execution status alongside elapsed time. While waiting for a SessionStart hook to complete, pressing Esc cancels the prompt at any time. Fixed crashes in the interactive /hooks menu when a hook matcher is named after inherited properties like __proto__ or constructor.

This is like displaying an elapsed-second progress bar while a webpage loads, allowing you to cancel with a keystroke without freezing the system menu over special naming.
FEATURE

Spinner Displays Long Thinking Status and Guides Desktop and Mobile Downloads

Waiting for AI computations during complex tasks now offers clearer progress indicators and multi-device app guidance.

When thinking exceeds 45 seconds, the spinner displays "deep in thought". While recovering from output-token limits, it displays "picking the thought back up". Typing /desktop provides download links for the desktop app alongside dedicated tips for cloud platform users. Typing /mobile displays a single QR code URL that automatically routes to the appropriate app store for your phone. Fixed spinner tips recommending commands unavailable for the current account type or disabled in the session.

This is like navigation software clearly showing in-depth route calculations for long journeys, with on-screen shortcuts to scan QR codes and download the mobile app.
BUGFIX

Cross-Platform File Watching Stabilized, Stale Git Lock Files Fixed

Operating across macOS, Linux, and Windows now delivers smoother low-level file and terminal handling.

On Linux, when a sandboxed command fails to start, stale .git/config.lock files are no longer left behind to break subsequent Git commands in the session. When system file-event services are saturated on macOS, the config watcher automatically falls back to polling to detect external changes. Fixed custom agents and slash commands failing to load from virtual drives reporting inode 0 on Windows. Synced skills not refreshed within cleanupPeriodDays after signing out move to the recoverable trash upon the next launch. Fixed keybindings in specialized terminals and terminal query strings leaking to the shell prompt upon exit.

This is like a universal adapter that flexibly shifts file-watching mechanisms across operating systems, responding accurately even when pressing Delete in niche terminal emulators.
FEATURE

Claude in Chrome Notes Sleep State, Remote Control Leaves Fewer Empty Sessions

When interacting with Claude via browser extensions or Remote Control, connection error messages reflect real conditions more accurately.

When a cloud session cannot reach the local browser, the message notes that the computer may be asleep before suggesting an extension install. When ToolSearch is unavailable, it no longer instructs the model to load tools via ToolSearch. When Remote Control setup fails on unstable networks, fewer empty sessions are left behind on claude.ai.

This is like a TV remote displaying "TV may be in standby" during weak signals, rather than immediately urging the user to buy a new remote.
FEATURE

Terminal Renders Large Diffs Smoothly, Monitor Watches Enforce Deadlines

When dealing with massive code diffs and long-running monitoring tasks, command-line responsiveness and resource management are much more reliable.

Terminal rendering performance is improved so large diffs and long transcripts render faster with fewer frame drops. Startup time is slightly reduced by skipping redundant validation of built-in model data. Monitor watches now enforce a mandatory deadline (at most 30 minutes in regular sessions, 10 minutes in single-prompt -p runs) and notify Claude to re-arm, replacing the previous no-timeout persistent option. Fixed an issue on Windows where PowerShell commands failed with "Exit code 1" and no output when the session temp output path reached the 260-character limit.

This is like replacing an old projector with a high-refresh display so paging through massive diffs no longer stutters, while monitoring equipment is fitted with safety timers that report regularly.
FEATURE

LLM Gateways Support Plaintext Replies, Skill Counts Stay Accurate After Directory Changes

Connecting through LLM gateways or switching directories now features more accurate formatting and environment cleanup.

When an LLM gateway returns non-streaming replies as text/plain, turns no longer fail with empty or malformed response errors. After changing directories via /cd, /reload-skills reports a skill count that perfectly matches the slash menu. When referencing PDF files where page count cannot be determined, it explicitly notes "page count unknown" rather than guessing based on file size. Sessions on the Claude apps gateway and third-party cloud platforms (Bedrock, Vertex AI, and Foundry) no longer refresh unused leftover claude.ai logins.

This is like a package sorter reliably delivering plain-text parcels, while changing workspaces keeps tool counts accurate without leaving redundant login sessions behind.
