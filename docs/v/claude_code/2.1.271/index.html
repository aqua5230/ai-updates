Claude Code 2.1.271

程式碼審查不再重複發文，已解決問題不重複回報

在 GitHub 上提交拉取請求等待審查時，最怕遇到審查遺漏或重複回報。現在限制每個拉取請求審查一次的儲存庫中，若在排隊等候時送入新修訂，會如實審查該次修訂。當 GitHub 回報錯誤但實際已建立審查時，不再重複張貼兩三次相同的意見。針對先前已由真人標記解決的資安問題，即使後續程式碼行數挪移，追蹤審查也不會重新貼出。在應用程式中重新打開已完成的 /ultrareview 雲端工作階段（session），也不會無故重頭跑完整輪審查。

這有如雜誌社編輯校對稿件，當作者更新段落時不會把同一個錯字反覆退件三次，已確認修正的章節也不會因為頁碼挪移就重新抓出來糾正。

Claude Tag 串流討論不中斷記憶，通知與環境選單更清楚

在通訊軟體群組裡呼叫 Claude Tag 協助工作時，多討論串的訊息管理變得更加可靠。在持續啟用的頻道中，即使對話主要發生在討論串內，討論串活動現在能維持工作上下文，不再每隔約一小時就重置記憶。指派 Claude 監控拉取請求的討論串，在重啟後能持續接收持續整合（CI）失敗、留言與審查通知。刪除已獲回覆的討論串首則訊息時，Claude 會如期終止該處的工作。不再因為其他機器人的舊指令而扣留發文，只有指名給 Claude 的指令才生效，不確定時會主動詢問。加入熱門頻道時的卡片會說明真實原因，不再誤稱看見大量自動發文。管理設定中的環境挑選器明確標示 Anthropic 託管或自託管選項並提供編輯連結。

這好比會議室裡的專屬秘書，只要大家還在子討論串裡發言就不會突然遺忘剛才的決議，聽到別人向其他助理交代事情時也不會胡亂插嘴。

網頁版例行工作頁面改版，雙分頁呈現執行狀態

登入網頁版管理自動排程任務時，例行工作（routines）頁面帶來全新架構。在 claude.ai/code 頁面上，版面劃分為「你的例行工作」與「範本」兩大分頁，並以雙欄卡片直觀呈現每項例行工作的執行狀態。同時移除了先前的日曆視圖，讓清單檢視更為俐落。

這就像把工具箱分成「自訂專用」與「現成範本」兩個抽屜，每張工作卡片上直接亮出執行燈號，找工具時一目了然。

雲端環境支援自訂網域白名單，離線工作階段發話即重啟

管理雲端開發環境時，現在擁有更細緻的網路存取控制與快速恢復機制。在管理員設定的雲端環境編輯器中，新增了自訂網路存取選項，提供與 claude.ai/code 環境對話框相同的允許網域清單。管理頁面清楚列出 Claude Tag 與 Claude Code 的預設環境，附上切換連結並標註建議建立的類型。雲端工作階段（session）在背後行程結束但外觀仍保持連線時，以前可能卡住約十分鐘才回應，現在只要發送訊息就會立刻重新啟動。

整套控管好比社區門禁的名冊管理，只有事先登記在白名單上的網址才能連線，遇到遠端連線中斷只要按門鈴就能立刻重新通電。

VSCode 支援關閉自動附加檔案，工作階段清單更穩定

在 VSCode 編輯器中使用 Claude Code 寫程式時，對話傳送內容與歷史清單獲得多項體驗改善。新增「附加開啟中檔案（Attach Open File）」設定，關閉後不再自動將當前開啟的檔案內容塞入對話，但選取的文字片段依然會附加。工作區位於 Windows 網路磁碟機或 SUBST 虛擬磁碟時，修復歷史記錄只顯示目前工作階段（session）的問題。篩選選單同時勾選作用中與開啟時，不再隱藏處於閒置狀態的已開啟工作階段。工作階段清單重新整理時，新建的聊天視窗不會跳回上一筆對話。修改設定中的 CLAUDE_CONFIG_DIR 環境變數後，側邊欄與分頁會即時套用新目錄。切換開關的開啟狀態顏色從原本的 Claude 橘色改為跟隨編輯器主題的按鈕顏色。

這如同在素描本上加上開關便利貼，不想把整份畫冊寄出時只要撥開開關，就只會傳送你用螢光筆圈選的那一段草稿。

VSCode 掛鉤儲存防呆升級，消除主控台視窗閃爍

在 VSCode 擴充套件中微調自動化規則時，設定對話框與背景視窗干擾問題已全面改善。掛鉤（hook，特定事件發生時被觸發的小程式）與權限規則對話框不再把已成功的儲存誤報為失敗，並修正受外掛政策鎖定時畫面反白或儲存錯誤顯示顏色代碼的異常。儲存掛鉤時替換不再產生重複項目，修改標頭大小寫時能保留金鑰機密，且返回前會自動將本機設定檔加入忽略清單。設定檔本身導致儲存受阻時，彈出視窗會附帶「開啟設定檔」按鈕與錯誤原因。在 Windows 上執行背景 Git 或登入檢查時，不再頻繁閃爍黑色的主控台（console）視窗。提示快取（cache，把算過或查過的結果暫存起來直接用）時鐘懸浮文字與自動壓縮圖示的提示框顯示也已修復。

這好似填寫電子表單時的防呆設計，設定檔出問題時主動提供修改按鈕，背景查驗資料時也不會在螢幕前不斷閃爍黑色小視窗。

遠端連線支援快速模式，/fast 關閉與降速備援修復

在雲端或自託管環境連線執行 Claude Code 遠端工作階段（session）時，現在也能享受快速模式的加速體驗。只要組織政策允許，遠端主機的設定或在工作階段中輸入 /fast 即可啟用快速模式。當組織停用快速模式時，輸入 /fast off 現在會如實關閉，不再錯誤回應模式不可用。跳過組織檢查啟動的工作階段在 API 拒絕快速請求後，會明確顯示原因並停止每回合重送。遇上用量額度（quota）上限或系統過載時，重試監控機制會自動切換速度。系統改以標準速度作為備援（fallback），不再直接中斷或堅持高速重試。

這就像行駛在高速公路的快速通行車道，只要公司授權就能順暢前進，遇到額度用盡或車流壅塞時也會自動切回一般車道穩定前行。

企業政策即時更新，支援自訂模型計費倍率

在企業組織中統籌多位成員的開發環境時，政策派發與成本拆帳迎來更精確的控管機制。在 modelPricing 管理設定與應用程式閘道器中，新增高於 1 且最高至 10 的 multiplier 參數，方便計算內部拆帳。切換帳號或金鑰時，組織政策快取（cache，把查過的結果暫存起來直接用）會即時刷新。工作階段（session）中途政策載入完成或變更後，工具與指令清單會同步更新。當企業的 managed-mcp.json 設定檔無法解析時，會在啟動時發出警告並維持專屬管制，禁止載入非核准的 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器。透過本機代理轉發組織政策時遭拒絕的問題也已修復。

這好比總公司的記帳系統，各部門調用資源時能依倍率精確分攤預算，一旦切換員工識別證，最新的授權規範也會立刻生效。

自託管 Runner 支援退場標記，超大設定檔改存磁碟快照

自行架設伺服器執行自託管執行器（self-hosted runner）時，主機維護與大型專案設定更可靠。執行 claude self-hosted-runner --drain-marker-file <path> 後，只要指定檔案存在且收到 SIGTERM 退場信號，執行器會向伺服器通報 host drain，但這僅作 telemetry 通報，不代表額外調度行為。當主機設定資料夾超過 64 MiB 時，過去工作階段可能默默遺失整份 host config，包含 settings、skills、plugins、MCP servers。現在新增 --host-config-snapshot disk|memory，可把快照放在磁碟或記憶體。

這如同貨運列車進站維修前掛上整備標誌，調度中心只收到狀態回報，同時整份行車紀錄先完整備份，不會漏掉車廂清單。

沙盒指令獨立設定連線網域，自動模式審查行內指令

在自動模式搭配沙盒環境執行終端機操作時，網路安全界限變得更加嚴密。Bash、PowerShell 與 Monitor 指令在沙盒模式下新增個別指令的 allowed_domains 網域清單，指令所需的網路主機會與指令一同審查並僅向該指令開放，其他連線一律拒絕。技能或斜線指令中內嵌的 ! 開頭 Shell 指令，改為遵循預設模式的權限規則而非由分類器全權判定，若無規則適用的指令則作為需審查的工具呼叫執行。

這套防護猶如實驗室的獨立通風櫥，每項化學實驗只能連接自己專屬的試劑管線，不會順手碰到隔壁工作台的藥品。

Bash 權限檢查涵蓋萬用字元，防堵跨目錄讀取漏洞

透過命令列執行 Bash 工具時，權限防護系統對檔案路徑與參數的識別更加縝密。當 fmt 或 column 等指令跟隨未識別的選項時，不再遺漏其讀取的檔案路徑。萬用字元（wildcard，用星號代表多個檔案的符號）位於指令模式或選項值中時，例如 grep -v dir/* file 這類指令展開後的檔案都會納入權限檢查。Shell 變數宣告旗標不再造成指令被偽裝誤判。包含兩次目錄切換、子 Shell 或 cd 與 git 連接的指令，在啟用禁止讀取工作目錄外部設定時，不會跳過確認提示。

這就像倉庫巡檢員核對出入庫清單，即使貨物名稱帶有星號或特殊縮寫，也必須逐件核對是否超出指定的儲位範圍。

外掛安裝支援 SHA-256 驗證，確保指令未被竄改

在自動化腳本中安裝或更新擴充外掛時，現在有比盲目確認更安全的核可機制。claude plugin install 與 claude plugin update 都新增 --accept-command <sha256> 參數，用來接受前一次 --json run 顯示的指令雜湊值。這會精確比對那次顯示的 command hash，取代原本直接用 -y 放行。

這好比快遞簽收時對照包裹上的防偽標籤，確認序號完全相符才開箱，避免途中被調包成不同指令。

子代理支援精簡模式，動態工作流程達額度自動暫停

多代理拆專案時，子代理（subagent）少載規則，回報可控。自訂/外掛子代理可用 frontmatter/--agents JSON 裡的 omitClaudeMd，不載入使用者、專案、本機 CLAUDE.md，但載入管理政策。雲端工作階段（session）重啟工作單元後，不再拒絕子代理工具呼叫。動態工作流程遇到用量額度（quota）上限會暫停，重置後接續。自動模式改用 hand-back call 回報並由安全分類器審查。Pro 預設規模改為 small，medium 上限從 15 降到 10。claude-api 技能讓串流自訂工具啟用 eager_input_streaming，並用 user.define_outcome 開始 deliverable-shaped Managed Agents work。

這像外包只收工單，缺料時先停工。

/config 支援全螢幕滑鼠滾輪，路徑與選取標籤優化

在終端機介面中調整系統偏好或輸入路徑時，互動操作變得更符合現代使用習慣。全螢幕 /config 設定面板加入滑鼠支援，可透過滾輪滾動清單、點擊數值直接切換，游標下方的列也會高亮顯示。/add-dir 路徑輸入支援左右方向鍵移動游標，按下 Enter 鍵只會加入實際輸入的路徑，不會誤加反白的自動補齊項。主提示詞外的文字欄位不再將開頭的驚嘆號 ! 移至末尾。修正全螢幕渲染殘留背景顏色的破圖。提示詞中的 IDE 選取標籤改為可隨文字換行的 [⧉ …] 膠囊標籤，按 Backspace 即可移除。

整套操作宛如將控制面板升級為觸控介面，滑動滾輪就能翻頁、點選就能變更開關，輸入文字時游標也能自由左右移動。

MCP 支援工具簡稱搜尋，長任務定時回報防止中斷

透過 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）擴充工具庫時，伺服器連線與呼叫流程更為穩健。工具搜尋支援 Claude 以簡短名稱選取工具，不再強制使用完整前綴名稱。當 MCP 伺服器密集發送清單變更通知時，能有效防止 CPU 負載過高與重複請求。claude mcp serve 執行中的工具呼叫每 30 秒發送一次進度更新，避免因長時間無輸出而被閒置逾時中斷。雲端平台中標記為 alwaysLoad 的 MCP 伺服器在中途連線完成後，下一回合即可直接使用。恢復工具全來自 MCP 的單次提示詞工作階段（session）時不再報錯。

這好比廚房出餐時每隔一段時間向點餐櫃檯回報進度，避免外場誤以為當機而直接取消訂單，尋找工具時也能憑簡稱迅速定位。

MCP 授權註冊邏輯修復，快捷鍵不再中斷重新連線

連接需要身分驗證的第三方 MCP 伺服器時，授權交握與遠端遙控操作更加穩定。修正 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）OAuth 授權用戶端註冊處理，解決拒絕同意時強制重新註冊、誤用其他轉址 URI，以及多重寫入刪除有效憑據或保留錯誤設定的問題。按下 Ctrl+O 快捷鍵不再意外取消正在排隊的 MCP 伺服器重新連線。修復在開啟對話紀錄視圖時，從遠端操控（Remote Control）發送 /mcp 指令失敗的異常。

這就像辦理證件時核發的臨時通行證，換個窗口辦理不會重複發卡，重新連線時也不會被中途開啟的紀錄視窗意外打斷。

產出物渲染為精美排版文件，監聽數量上限翻倍

利用產出物（artifacts）功能產出文件或程式碼時，預覽效果與檔案同步能力獲得顯著增強。發佈為產出物的 Markdown 檔案現在會渲染為具備標題列、排版樣式與語法高亮的精美文件頁面。單一工作階段（session）可同時監聽的發佈產出物上限從 5 個提升至 10 個，方便追蹤其他地方的重新發佈。背景工作階段會如實監聽自己發佈的產出物。透過 /artifacts 附加的產出物在以 --resume 恢復工作階段後不會消失。發佈錯誤訊息更清楚，未指定檔案時會提示先寫入檔案，並列出所有支援的功能規格。

這如同將草稿紙重新排版印刷成精裝書頁，標題與程式碼區塊都有專屬配色，還能同時追蹤多份文件在其他地方的修訂。

工作階段恢復記憶精準，模型切換不誤報快取遺失

中斷工作後想接續先前的開發進度時，各項工作階段（session）恢復與狀態同步問題已獲得修復。使用 /resume 或 /teleport 恢復工作階段時，不會殘留前次對話的檔案讀取追蹤，確保權限狀態乾淨。使用 --resume 恢復工作階段時，即使模型系列與預設不同，也能正確保留百萬 token（AI 處理與計費的文字單位）的上下文視窗。使用 /model 切換回對話原本運行的模型時，不再誤報即將遺失快取（cache，把查過的結果暫存起來直接用）。對話壓縮後，仍在運行的背景指令不會被重複啟動第二份。跨工作階段傳送訊息時提供明確遞送狀態通知，而在高度較矮的終端機上使用全螢幕選單也能完整列出工作階段。

這好比看書時夾上精準的章節書籤，隔天翻開時能完整保留當前章節的記憶與快取，不會無故把書本重複翻開兩遍。

掛鉤執行顯示耗時進度，支援 Esc 取消等待

設定自動化掛鉤（hook，特定事件發生時被觸發的小程式）時，執行狀態反饋更加即時透明。當 SessionStart、UserPromptSubmit、PreToolUse 或 SessionEnd 掛鉤執行時，狀態轉輪會明確顯示執行狀態與已耗費時間。在等待 SessionStart 掛鉤完成期間，可隨時按下 Esc 鍵取消當前提示詞。修復互動式 /hooks 選單在掛鉤比對名稱包含 __proto__ 或 constructor 等保留屬性時發生的當機問題。

這如同在等待網頁載入時顯示具體的秒數進度條，隨時能按鍵中斷等待，設定特殊名稱時也不會讓整個系統選單卡死。

轉輪提示長思考狀態，引導下載桌面與行動版

這好似導航軟體在規劃長途路線時清楚顯示正在深度計算路線，並在畫面上提供掃碼下載手機版應用的捷徑。

跨作業系統檔案監聽更穩固，Git 鎖定檔殘留修復

這就像多功能萬用轉接頭，在不同作業系統間靈活調度檔案監聽機制，即使在特殊終端機裡按刪除鍵也能精準響應。

終端機長文渲染不再卡頓，監聽任務設有逾時上限

面對龐大程式碼變更與長時間監控任務時，命令列工具的反應速度與資源管理更有保障。終端機渲染效能改善，大量差異比對與長對話紀錄顯示更加流暢。介面減少掉格卡頓（jank，短暫畫面停頓現象）。啟動時略過內建模型資料的重複驗證，略微縮短啟動時間。Monitor 監聽機制改為強制設定時間上限（一般工作階段最多 30 分鐘，單次提示詞模式為 10 分鐘），到期前提醒 Claude 重新武裝，取代過去無逾時的常駐選項。Windows 環境下暫存輸出路徑達到 260 字元上限時，修復 PowerShell 指令報錯 Exit code 1 且無輸出的問題。
