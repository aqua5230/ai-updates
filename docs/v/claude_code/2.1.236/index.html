Claude Code 2.1.236

發布日期：2026-08-19

繁體中文

新增預設模型環境變數，手動挑選仍可在重啟後保留

這像收音機的開機預設電台，每次打開自動轉到預設頻率，但只要你旋轉按鈕切換頻道，新頻道就會保留下來，不會一關機就強制還原。

新增的 ANTHROPIC_DEFAULT_MODEL 環境變數（開程式前先給它的設定值）。它可指定新工作階段（session）預設啟動的模型。若使用 zsh，請把下列內容加到家目錄的 ~/.zshrc，再開新終端機後啟動 Claude Code：

export ANTHROPIC_DEFAULT_MODEL=sonnet

sonnet 就是要填入的預設模型別名；想用 Opus 可改填 opus，也可填可用模型的完整名稱。對話中用 /model 另選模型時，手動選擇仍會覆蓋預設並在重啟後保留；會鎖死模型的 ANTHROPIC_MODEL 則不會。

跨工作階段訊息新增閒置通知，無須輪詢即可掌握進度

在 macOS 與 Linux 上跨工作階段（session）傳送訊息時，SendMessage 工具現在新增了 notify_when_idle 參數。當你在本機同時開了多個 Claude Code 視窗，你可以透過這個參數請求另一個工作階段在下次進入閒置狀態時，主動回傳一次通知。這項機制屬於主動啟用且為單次發送，呼叫端完全不需要寫迴圈持續輪詢（polling）等待。

像請隔壁辦公室的同事在忙完手邊工作時敲門提醒一聲，你不必每隔幾分鐘就探頭查看他的進度。

macOS 沙盒嚴防機密外洩，萬用字元拒讀規則更嚴謹

這好比在金庫的准入許可中貼上禁止翻閱帳冊的特別禁令，即使訪客獲准進入整個資料室、或者把帳冊裝進新皮套，禁令依然直接生效且涵蓋整個檔案夾。

在 macOS 的沙盒（sandbox）環境中，萬用字元讀取拒絕規則現在具備更高優先權。例如比對到 **/.env 的規則，即使該路徑位於原本允許讀取的目錄範圍內，拒絕規則依然優先適用；同時，規則能完整涵蓋符合條件的目錄內所有檔案，且無法透過將被拒絕的檔案重新命名來規避讀取限制。

工作資料夾遭外部刪除時，剪貼簿與背景任務不再損毀

當工作階段（session）切換進入的資料夾被外部刪除後，各項背景與周邊功能不再整批壞掉。自 2.1.229 版本以來，一旦所在目錄消失，剪貼簿複製、背景日常維護、背景工作階段與本機 MCP（讓 AI 連接外部工具的協定）日誌都會損毀；SDK 與 VS Code 工作階段在技能變更時也會反覆報錯。現在系統已妥善處理目錄遺失的狀況，所有功能均能穩定維持運作。

如同臨時辦公桌被撤走時，工作人員手上的記事本、對講機與工具箱依然能正常運作，不會當場癱瘓。

全螢幕渲染器啟動失敗時，自動退回傳統渲染模式

全螢幕渲染器現在具備自我修復與備援（fallback）機制。過去如果全螢幕渲染器在啟動時遭遇單一次失敗，整個設定便會陷入永久損毀狀態，導致後續每次啟動 Claude Code 時都會直接崩潰退出。現在系統遇到全螢幕渲染啟動失敗時，會主動退回至穩定的傳統渲染器，確保終端機依然能順利開啟並供你正常操作。

像舞台上的數位投影特效機若故障，燈光系統會自動切換為傳統聚光燈繼續照明，不會讓整個劇場直接熄燈散場。

模型挑選選單支援滾動瀏覽，且只醒目標示最新釋出型號

走進冰淇淋店看數位菜單，螢幕若放不下全部口味，會自動切成上下捲動頁面，並只在剛上市的當季新品旁標上醒目的星號，不再隨意圈選其他舊品項。

輸入 /model 挑選模型時，選單的高度現在會自動符合終端機視窗大小。當清單內容超出視窗高度時，系統只會顯示容得下的項目，其餘模型可透過滾動查看；同時，介面改為僅醒目標示最新釋出的模型名稱，讓視覺焦點明確落在最新版本上。

修正跨工作階段訊息解析，標籤異常不再導致訊息遭拒

跨工作階段（session）傳送訊息時，格式解析變得更具容錯能力。以往在使用 SendMessage 工具時，如果訊息內容中含有格式錯誤的閉合標籤，系統解析時會不小心把整段訊息文字誤塞進摘要（summary）欄位中，進而導致整筆發送請求被後端直接拒絕。現在這項解析邏輯已修正完畢。

就像診所掛號時，表單的結尾欄位寫壞了，櫃檯仍會把病況說明留在說明欄，而不會誤塞進摘要欄後拒絕掛號。

子行程啟動失敗妥善攔截，避免 WSL 環境直接崩潰

好比派外送員出門時如果發現機車發不動，調度台會妥善處理這次派工失敗，不會讓整個調度中心警報大作。

當外部子行程（subprocess）無法啟動時，系統現在能優雅地捕捉錯誤。在 2.1.234 版本中，如果在關閉 Windows 互通性的 WSL（Windows 子系統）環境中嘗試啟動 powershell.exe，系統會因為未妥善處理非同步拒絕而直接崩潰；現在這類錯誤會被妥善捕捉與處理。

全螢幕視窗縮放重繪修復，多行輸入清除不再殘留白邊

全螢幕模式下的畫面重繪與文字顯示迎來多項細節修正。過去在縮放終端機視窗大小後，新送出的訊息有時會卡住，直到下一次畫面更新才突然冒出來；清除多行提示詞時，輸入框上方也常留下一道空白帶；且將視窗縮小後再放大時，各面板畫面更會出現無法重繪的缺塊。現在這些介面重繪問題已全數修復。

如同控制室的單一看板：縮放後的新通知會立刻亮起，清除多行輸入後不留空白帶，面板重新放大時各區也會完整顯示。

受管設定啟動審查確實顯示，防止首個按鍵誤當核准

如同辦理重要合約時，櫃檯必須先把同意書端到你眼前確認，不能把文件藏在桌下、卻將你走進門按的第一個電鈴當成簽字同意。

系統修復了受管設定（managed settings，由企業或管理者統一推送的設定檔）在啟動時的嚴重安全風險。過去在特定狀況下，啟動時的設定核准視窗未能正常顯示在畫面上，卻依然偷偷將使用者的第一次按鍵當成同意審查，造成誤按核准；現在對話框必定會確實顯示後才接收輸入。

tmux 分頁標題不再頻繁跳動，文字有變更才寫入更新

在 tmux（特別是搭配 iTerm 的 tmux 整合模式）中執行時，分頁標題不再持續抖動。過去系統每隔 960 毫秒就會進行一次動畫式的標題重寫，導致終端機分頁上的文字不斷閃爍跳動，干擾視覺專注；現在系統改為僅在標題文字真正發生改變時才執行寫入操作，保持分頁列的穩定與清爽。

這好比會議室門口的電子名牌，只有在更換會議主題時才刷新字樣，不再每秒閃爍一次背光。

雲端環境清單為空或損毀時，提供清楚的錯誤原因說明

當你存取雲端環境時，遇到清單異常不再摸不著頭緒。以往如果從遠端取回的雲端環境清單為空白，或者回傳的資料結構格式損毀，系統只會跳出語意模糊、難以排查的錯誤代碼；現在錯誤訊息已大幅改善，會清楚指明清單為空或格式不符的具體原因，方便你即時排查網路或遠端設定問題。

像大樓樓層導覽螢幕會清楚寫出「目前沒有登錄租戶」或「導覽資料格式錯誤」，而不是只丟出難懂的故障代碼。

遠端遙控下額度提示逾時，不再擅自替你選取備援模型

像在餐廳點餐時店員詢問是否改點另一道備選餐點，若你剛好離座洗手，店家應當靜候你回來確認，而不該在一分鐘後擅自替你更換餐點。

使用遠端遙控（Remote Control）時，額度提示不再逾時亂選。針對 Fable 5 的首次使用額度確認對話框，過去若等了 60 秒仍未收到使用者回應，系統會自動套用備援（fallback）模型；現在已移除這項自動選擇，靜候你的決定。

訪客通行證快取損毀時，修復背景錯誤並恢復提示顯示

在等待 Claude 運算時，旋轉指示器旁的小提示（spinner tips）現在能穩定顯示。以前如果個人目錄設定檔 ~/.claude.json 中快取（cache，把算過或查過的結果暫存起來直接用）的訪客通行證獎勵資料格式損毀，系統會在背景不斷陷入重複報錯的迴圈，導致轉圈等待時的小提示完全無法跳出來。現在系統會妥善防護並略過格式錯誤的快取資料。

猶如導航程式讀到損毀的已存路線時，會略過那筆資料並照常顯示下一步提示，不再反覆跳出錯誤。

自架執行器完成後置掛鉤後，才允許在其他節點恢復工作

如同租車公司還車時，必須等前一位駕駛的車輛清潔與交車檢查徹底完成，系統才能把鑰匙交給下一位客人，避免兩邊撞期。

自架執行器（self-hosted runner）的工作階段調度更穩固了。工作階段可能因閒置、除役（retire）或啟動逾時而釋放。過去在此類情境下，後置掛鉤（post-session hook，特定事件發生時被觸發的小程式）可能還在收尾，系統卻偶爾已在另一個執行器上恢復該工作階段；現在必定會等待掛鉤完全結束才允許接續。

iTerm2 特定字型下 Clawd 吉祥物排版修復，五官不再歪斜

在 iTerm2 終端機中看見的 Clawd 吉祥物變得更加工整可愛。過去在某些特定的字型與字級大小設定下，終端機渲染文字圖形時會產生微小字元寬度偏差，導致 Clawd 的眼睛左右不對稱、雙腳高度參差不齊；這次更新微調了字元輸出對齊方式，確保在各種字型大小下都能呈現端正勻稱的吉祥物樣貌。

宛如繪圖軟體微調了像素網格對齊，讓小寵物的五官與腳爪在任何螢幕縮放下都工整對稱。

工作階段摘要設定 400 字上限，單字邊界截斷防膨脹

像書籍封底的內容簡介設有嚴格的字數限制，超過篇幅時會在最後一個完整單詞處乾淨收尾，不再讓冗長文字溢出封面。

工作階段（session）的摘要功能不再無限膨脹。過去無論是系統自動產生的摘要，還是手動輸入 /recap 產生的回顧，偶爾會失控生成落落長的冗長篇幅；現在摘要文字被嚴格限制在最多 400 個字元內，並在單字邊界截斷，不從單字中間切開。

工作階段計數器改由背景寫入，縮短啟動等待時間

每次啟動 Claude Code 時的速度變得更加輕快。過去在啟動階段，系統會先停在前台等待工作階段計數器（session counter）完成磁碟寫入，稍微拖慢了進入對話畫面的時間；現在這項寫入作業已全面移至背景非同步執行，不再阻礙主流程的啟動作業。

就像超市入口讓顧客直接進門，門邊的人流計數器則在背景累加人數，不必等店員先寫完紀錄才放行。

自動模式暫存 Monitor 放行規則，指令審查更嚴謹安全

像機場開啟全面自動安檢警戒時，即使平時持有免檢通行證的內部維護人員，隨身裝備也必須一律放進 X 光機接受完整掃描。

自動模式（auto mode，讓 Claude 不逐一問你就自己執行的模式）的安全防護進一步提升。在自動模式運作期間，原本設定的 Monitor 允許規則會被暫時擱置，所有監控指令將與一般 Bash 指令一視同仁，接受相同標準的安全審查，避免指令繞過防護。

雲端平台自動模式分類器標準統一，依嚴重程度精準評分

自動模式（auto mode，讓 Claude 不逐一問你就執行的模式）在各雲端平台看齊官方規格。在 Bedrock、Vertex AI、Foundry 以及停用遙測的環境中，系統分類器現在採用與官方 Claude API 完全相同的預設配置，包含依據嚴重程度進行評分（severity-scored）的判斷機制，確保風險判定一致且可靠。

如同教育主管機關讓每所學校都採用同一份評量標準，不會因為校區不同而換一套分級方式。

自動模式 Git 狀態檢查升級，無視隱藏未追蹤檔案設定

像倉庫盤點時即使設定檔勾選了「隱藏無條碼紙箱」，稽查員依然會徹底檢查庫房角落，絕不草率判定倉庫為完全淨空。

自動模式（auto mode）執行 Git 狀態檢查時更加嚴密。過去如果專案的 Git 設定中包含 status.showUntrackedFiles=no，系統會被該設定矇蔽，誤以為工作目錄沒有任何未追蹤檔案而回報乾淨狀態；現在系統已修正檢查邏輯，不再漏看任何未追蹤檔案。

/goal 任務停泊於背景工作時，自動定時回報進度

如同把車輛送進保養廠大修時，專員會在 30 分鐘後、以及隨後每隔一段時間主動發簡訊回報進度，而不是等車主親自回廠詢問。

使用 /goal 指令設定長程目標時，若工作階段因為等待長時間運行的背景工作而進入閒置狀態，系統現在會在 30 分鐘後自動甦醒並進行進度檢查與回報，隨後依序在 1 小時與 2 小時再次檢查，不必等使用者手動切回視窗觸發。

/usage 支援團隊額度花費列，未消費時清楚標記 0%

查看額度消耗時，團隊方案的使用者現在能掌握更清楚的資訊。輸入 /usage 指令時，系統現在會為 Team 與 Enterprise 方案成員顯示專屬的使用額度（usage-credits）花費列；在尚未產生任何花費之前，該列會明確標示為 0% 的上限狀態，方便管理者與成員清楚了解當前的配額起點。

這好比公司發放專屬公務油卡時，儀表板一開始就清楚列出總額度與已使用 0% 的進度條，讓持卡人在出發前就心中有數。

print/SDK 模式接收 SIGTERM 乾淨結束，不留偽造拒絕紀錄

在列印（print）或 SDK 模式下結束處理程序時，對話歷史不再殘留多餘的干擾紀錄。過去收到 SIGTERM 終止訊號時，系統會在歷史紀錄中寫入回合中斷與偽造的工具拒絕紀錄；現在系統結束時不再寫入這些多餘資訊，同時正在執行的指令依然會被正常終止，處理程序也維持以代碼 143 退出。

好比辦公室收到下班通知時員工直接關機離席，出勤簿上標記正常打卡下班，不會憑空補記一筆拒絕處理公文的違規紀錄。

斜線指令打錯時精確報錯，不再盲目執行模糊比對

像在電視遙控器輸入未知頻道號碼時，螢幕會提示查無此頻道，而不會自作主張跳轉到號碼相近的冷門節目。

輸入斜線指令時不再因為手滑而誤跑其他指令。過去若不小心打錯斜線指令，或輸入了當前工作階段（session）無法使用的指令並按下 Enter，系統會自動挑選最接近的模糊比對結果執行；現在系統會直接回報找不到該指令，不過正規的指令前綴與別名依然可以正常執行。

遠端遙控在終端機關閉後數秒內，迅速標記為離線狀態

使用遠端遙控（Remote Control）管理對話時，線上狀態的同步變得更即時。當你在本機結束命令列介面（CLI）或直接關閉終端機視窗時，連線狀態會迅速更新。遠端系統現在會在數秒鐘之內將該工作階段（session）標記為離線，不再讓介面長時間停留在連線中的假象。

這就像通訊軟體在手機關機時，頭像旁的線上綠燈會在幾秒內轉為離線灰燈，不讓遠端的使用者誤以為對方仍在線上等待。

跨工作階段訊息超載時前端拒絕，不再假裝送出卻默默丟棄

跨工作階段（session）傳送訊息時，資料收發的可靠度大幅提升。過去如果短時間內密集送出大量突發訊息，導致數量超出接收端收件匣所能承載的上限，系統會表面回報發送成功、背地裡卻把超出的訊息悄悄丟棄；現在 SendMessage 會在最前線直接拒絕超量的發送請求並回傳錯誤，讓你能即時掌握傳輸狀況。

像工廠的零件暫存架已滿時，管理員會先拒絕接收新零件，而不會先登記入庫再默默丟掉。

提示詞邊框標籤與頁尾右緣對齊，終端介面排版更工整

如同排版精良的雜誌頁面，頁首章節標籤、內文邊界與頁尾資訊全都沿著同一條垂直輔助線切齊，整體版面俐落清爽。

終端機輸入介面的排版細節更加協調。提示詞邊框上的工作階段標題標籤，現在與頁尾右側邊界精準對齊；同時，頁尾右側的各項狀態指標（包含目標指示器、工作階段狀態、背景代理狀態）以及文字截斷提示，也全部採用與提示詞主區域一致的右側邊界寬度。

VS Code 支援螢幕報讀器，逐字稿朗讀與回合標題導覽

VS Code 擴充套件的無障礙支援迎來重大改進。現在逐字稿（transcript，完整對話歷史紀錄）具備更完善的朗讀能力。擴充套件全面支援螢幕報讀器（screen reader）。當 Claude 回覆訊息、跳出權限請求、發生錯誤或狀態改變時，系統都會提供即時語音朗讀通知。此外，報讀器使用者還能透過各對話回合標題快速跳轉導覽。

像能朗讀的文件閱讀器，會即時讀出新內容與提示，也讓你依章節標題跳到想聽的位置。

ANTHROPIC_DEFAULT_MODEL sets session defaults while preserving /model picks

Like a radio with a favorite preset that powers on to your station, yet lets you tune to another channel and remembers it after a reboot.

The new ANTHROPIC_DEFAULT_MODEL environment variable (a value supplied before the program starts) sets the model for new sessions. With zsh, add this to ~/.zshrc in your home directory, then open a new terminal before starting Claude Code:

export ANTHROPIC_DEFAULT_MODEL=sonnet

sonnet is the default-model alias to enter; use opus for Opus, or a full supported model name. A /model selection during a conversation still overrides the default and persists after restarts, unlike the model-locking ANTHROPIC_MODEL.

SendMessage adds notify_when_idle for one-shot cross-session notices

Cross-session SendMessage on macOS and Linux now includes a notify_when_idle option. When you run multiple Claude Code sessions on the same machine, one session can ask another to send a single notice the next time it becomes idle. It is an opt-in, one-shot mechanism that eliminates the need to poll the target session in a busy loop.

Like asking a coworker in the next office to knock on your door when they finish, saving you from peeking into their room every few minutes.

macOS sandbox enforces wildcard read-deny rules and blocks rename bypasses

Like a vault pass marked with a strict restriction against reading ledgers: even if a guest is allowed into the archive room or renames the denied file, the denial remains absolute.

On macOS, sandbox wildcard read-deny rules (such as **/.env) now take precedence inside allowed read regions. They cover the full contents of matched directories, and access cannot be bypassed simply by renaming the denied file.

Session utilities, MCP logs, and skills hot-reload survive deleted working directories

Background tasks and utilities no longer break when a session's directory is deleted from underneath it. Since 2.1.229, removing the active working directory broke clipboard copying, background housekeeping, background sessions, and local MCP (Model Context Protocol) logs, while triggering errors on every skill change in SDK and VS Code sessions. The runtime now handles missing working directories smoothly without failing.

Like a worker whose folding table is packed away: their clipboard, walkie-talkie, and toolbelt continue to function normally without a hitch.

Fullscreen renderer falls back to classic mode if startup fails

The fullscreen renderer now recovers gracefully from startup failures. Previously, if the fullscreen renderer failed to initialize a single time, the application became permanently broken and crashed on every subsequent launch. It now falls back to the classic terminal renderer instead of exiting, keeping your session operational.

Like a stage projector failing to boot: the lighting system immediately switches back to classic spotlights so the show goes on.

/model picker scrolls within terminal bounds and highlights only newest release

Like a digital menu board in a dessert parlor that scrolls smoothly when items exceed screen height, while highlighting only the single newest flavor of the season.

The /model picker now fits cleanly inside your terminal window. If the list of available models is taller than the terminal, it renders only what fits and lets you scroll through the rest. Furthermore, the highlight style is now reserved exclusively for the newest model release rather than arbitrary items.

SendMessage fixes malformed closing tags causing summary text rejections

Cross-session messaging now parses malformed payload tags reliably. Previously, when calling SendMessage, a broken closing tag could accidentally displace the message body into the summary parameter, causing the request to be rejected. The parser now isolates the text correctly regardless of imperfect tag formatting.

Like a clinic registration desk that keeps a patient's description in the description field despite a malformed closing label, instead of putting it in the summary box and rejecting the registration.

Subprocess startup failures are handled cleanly without unhandled rejections

Like a delivery dispatcher handling a scooter that failed to start calmly, rather than letting the entire dispatch office crash in confusion.

Subprocess startup failures no longer trigger unhandled promise rejections. In version 2.1.234, trying to launch a command like powershell.exe on WSL with Windows interop disabled caused unhandled runtime crashes. The process manager now catches and handles these startup errors cleanly.

Fullscreen mode fixes delayed messages, prompt blank bands, and pane repainting

Fullscreen mode received several screen-drawing and layout fixes. Resizing the terminal window sometimes caused newly submitted messages to remain invisible until the subsequent UI tick. In addition, clearing multi-line prompts could leave an empty blank band above the input area, and resizing panes away and back left views unpainted. These visual rendering issues have all been resolved.

Like a clean blackboard wiping down without stray chalk marks, updating text instantly without lag when the frame is adjusted.

Managed-settings prompt ensures visibility before capturing approval keystrokes

Like a formal contract where the clerk must place the document directly in front of you, rather than keeping it hidden while treating your doorbell press as a signature.

A dangerous security issue with managed settings prompts has been fixed. Previously, the startup prompt asking for approval of managed configurations could fail to display on screen while still recording your very first keystroke as consent. The prompt now reliably renders before processing user input.

tmux tab titles stop jumping by updating only when text actually changes

Terminal tab titles inside tmux (especially via iTerm tmux integration) no longer jump jittery across updates. The title string used to be rewritten continuously on a 960ms animation loop, creating visible flicker on the tab bar. It is now written only when the title text itself changes.

Like a meeting room door display that updates only when the title text changes, rather than flickering its backlight every second.

Clear errors when cloud environments list is empty or malformed

Fetching cloud environments now returns descriptive diagnostics if the response is empty or damaged. Previously, when the cloud environment endpoint returned an empty list or malformed data, the CLI presented an opaque, unhelpful error message. It now explains the failure clearly so you can diagnose configuration issues quickly.

Like a building directory that clearly says "no tenants listed" or "directory data is malformed", rather than displaying an inscrutable failure code.

Remote Control stops auto-selecting fallback models on Fable 5 prompt timeout

Like a dining order where the waiter waits for you to return to the table, rather than automatically switching to a fallback dish after 60 seconds of absence.

When using Remote Control, the initial usage-credits confirmation prompt for Fable 5 no longer automatically picks a fallback model after 60 seconds of inactivity. It now remains open until you explicitly respond.

Spinner tips and background loops recover from malformed guest-pass cache

Spinner tips now appear reliably while waiting for responses. Previously, if the cached guest-pass reward in ~/.claude.json was malformed, the system entered a repeated background error loop and failed to render loading tips completely. The cache reader now handles corrupted data gracefully.

Like a navigation app that skips a corrupted saved route and keeps showing the next instruction instead of repeatedly surfacing an error.

Self-hosted runner sessions await post-session hooks before migrating

Like a car rental return where inspection and cleaning must finish completely before the keys are handed to the next driver, preventing overlapping handoffs.

Self-hosted runner session lifecycle handling is now race-free. When a session is released due to idle, retire, or startup timeout, it used to occasionally resume on a different runner before its post-session hook finished executing. The coordinator now strictly awaits hook completion before migrating the session.

Clawd mascot eyes and feet align neatly across all iTerm2 font sizes

The Clawd mascot in iTerm2 now displays with consistent proportions. At certain terminal font sizes, character cell measurement differences caused Clawd's ASCII eyes and feet to render misaligned and lopsided. Spacing has been adjusted so the mascot appears cleanly balanced across different font configurations.

Like snapping pixel art to an exact grid so an illustrated mascot's eyes and paws stay symmetrical at any zoom level.

Session recaps capped at 400 characters and trimmed at word boundaries

Like a book jacket blurb with a strict character limit that stops at the end of a complete word rather than spilling over the cover.

Session recaps will no longer run away with endless text. Both automatic recaps and manual /recap outputs are now capped at a maximum of 400 characters, neatly truncated at a clean word boundary so that sentences do not cut off mid-word.

Session counter writes in background to boost startup performance

Launching Claude Code is now faster and more responsive. Previously, the CLI blocked startup while waiting to record the session counter to disk. This write operation is now handled in the background, allowing the prompt interface to open without unnecessary disk I/O delay.

Like a supermarket that lets shoppers enter while a doorway counter increments visitor totals in the background, instead of holding the door until a clerk records each arrival.

Auto mode reviews Monitor commands like Bash by shelving allow rules

Like an airport switching to full automated security where even staff with bypass badges must put their bags through the X-ray machine.

Auto mode security has been strengthened. When auto mode is active, existing Monitor allow rules are temporarily set aside, ensuring that Monitor commands undergo the exact same safety review as standard Bash commands.

Auto mode classifier unifies severity scoring across all cloud platforms

Auto mode classification is now standardized across third-party cloud environments. On Bedrock, Vertex AI, Foundry, and setups where telemetry is turned off, the auto mode classifier now adopts the exact same defaults used on the Claude API, including severity-scored safety classification.

Like a school district using the same grading rubric at every campus, rather than changing standards based on location.

Auto mode git status check ignores showUntrackedFiles=no overrides

Like an inventory audit where the auditor inspects all unlabelled boxes in the warehouse regardless of a setting telling the scanner to ignore untracked items.

The git status check in auto mode is now impervious to repository overrides. Previously, a repo configured with status.showUntrackedFiles=no could fool the check into declaring a clean working tree. The inspector now inspects untracked files accurately regardless of local git configuration.

/goal periodically checks in on sessions parked behind background tasks

Like a mechanic messaging you with progress updates after 30 minutes and at regular intervals during a lengthy repair, rather than waiting for you to call in.

When a session running under /goal is parked waiting for long-running background tasks to complete, it now checks in automatically after 30 minutes (and subsequently at 1h and 2h marks) instead of sitting idle until you return.

/usage displays usage-credits rows for Team and Enterprise plans

The /usage command now provides detailed credit consumption views for Team and Enterprise organization members. It displays a dedicated usage-credits row, which clearly shows a capped bar at 0% before any spending occurs, giving teams full clarity over their starting baseline.

Like a corporate gas card dashboard displaying the full allowance along with a clean "0% spent" status before your first trip.

SIGTERM in print/SDK modes exits cleanly without synthetic tool denials

Terminating print or SDK sessions via SIGTERM now produces clean exit logs. The runtime no longer injects synthetic tool denials or interrupted-turn artifacts into the conversation transcript before shutting down. Active commands are still terminated properly, and the process exits with status code 143.

Like clocking out at the end of the shift: your log shows a normal departure rather than claiming you refused to answer work requests.

Slash-command typos report errors directly instead of guessing fuzzy matches

Like punching a typo into a TV remote: the television reports that the channel does not exist, rather than jumping into a random nearby channel.

Typing a slash-command typo or invoking a command not available in the current session now cleanly displays an error on Enter, instead of executing the nearest fuzzy match. Legitimate command prefixes and registered aliases continue to execute as expected.

Remote Control reflects offline status within seconds when CLI exits

Remote Control session status synchronizes much faster when your local client shuts down. Whenever the CLI exits or the terminal window is closed, connection status refreshes immediately. Remote Control now marks the session as offline within seconds instead of lingering as active.

Like a messenger app turning your profile badge from green to grey within seconds of closing your laptop, preventing others from thinking you are still available.

SendMessage rejects inbox overflows up front instead of dropping them silently

Cross-session messaging now guarantees honest feedback when handling sudden bursts. Previously, when rapid bursts exceeded what a destination session's inbox could accommodate, SendMessage reported them as delivered even though messages were dropped. It now rejects excessive messages up front with an error so the caller can back off or retry.

Like a factory parts rack that refuses a new part once it is full, rather than marking it stored and silently throwing it away.

Prompt border title chips and right-aligned footer items align consistently

Like a clean magazine layout where header tags, body margins, and footer notes all align with the same vertical grid line.

The terminal prompt layout has been polished for visual consistency. The session title chip embedded on the prompt border now aligns with the footer's right edge. Furthermore, right-aligned footer items (such as the goal indicator, session state, and background agent status) and truncated notices share a uniform right margin with the prompt box.

VS Code extension adds screen reader announcements and heading navigation

The VS Code extension now provides full screen reader accessibility for the session transcript. Users receive live audible announcements for incoming replies, permission prompts, errors, and status changes. In addition, the transcript incorporates per-turn heading structures so assistive technology users can navigate swiftly from turn to turn.

Like a document reader that announces new content and prompts live, while letting you jump to the spot you want by chapter heading.
