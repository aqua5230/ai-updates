Claude Code 2.1.236

Released: 2026-08-19

Release notes

FEATURE

ANTHROPIC_DEFAULT_MODEL sets session defaults while preserving /model picks

Like a radio with a favorite preset that powers on to your station, yet lets you tune to another channel and remembers it after a reboot.

The new ANTHROPIC_DEFAULT_MODEL environment variable (a value supplied before the program starts) sets the model for new sessions.

With zsh, add this to ~/.zshrc in your home directory, then open a new terminal before starting Claude Code:

export ANTHROPIC_DEFAULT_MODEL=sonnet

sonnet is the default-model alias to enter; use opus for Opus, or a full supported model name.

A /model selection during a conversation still overrides the default and persists after restarts, unlike the model-locking ANTHROPIC_MODEL.

FEATURE

SendMessage adds notify_when_idle for one-shot cross-session notices

Cross-session SendMessage on macOS and Linux now includes a notify_when_idle option.

When you run multiple Claude Code sessions on the same machine, one session can ask another to send a single notice the next time it becomes idle. It is an opt-in, one-shot mechanism that eliminates the need to poll the target session in a busy loop.

Like asking a coworker in the next office to knock on your door when they finish, saving you from peeking into their room every few minutes.
FEATURE

macOS sandbox enforces wildcard read-deny rules and blocks rename bypasses

Like a vault pass marked with a strict restriction against reading ledgers: even if a guest is allowed into the archive room or renames the denied file, the denial remains absolute.

On macOS, sandbox wildcard read-deny rules (such as **/.env) now take precedence inside allowed read regions.

They cover the full contents of matched directories, and access cannot be bypassed simply by renaming the denied file.

BUGFIX

Session utilities, MCP logs, and skills hot-reload survive deleted working directories

Background tasks and utilities no longer break when a session's directory is deleted from underneath it.

Since 2.1.229, removing the active working directory broke clipboard copying, background housekeeping, background sessions, and local MCP (Model Context Protocol) logs, while triggering errors on every skill change in SDK and VS Code sessions. The runtime now handles missing working directories smoothly without failing.

Like a worker whose folding table is packed away: their clipboard, walkie-talkie, and toolbelt continue to function normally without a hitch.
BUGFIX

Fullscreen renderer falls back to classic mode if startup fails

The fullscreen renderer now recovers gracefully from startup failures.

Previously, if the fullscreen renderer failed to initialize a single time, the application became permanently broken and crashed on every subsequent launch. It now falls back to the classic terminal renderer instead of exiting, keeping your session operational.

Like a stage projector failing to boot: the lighting system immediately switches back to classic spotlights so the show goes on.
FEATURE

/model picker scrolls within terminal bounds and highlights only newest release

Like a digital menu board in a dessert parlor that scrolls smoothly when items exceed screen height, while highlighting only the single newest flavor of the season.

The /model picker now fits cleanly inside your terminal window.

If the list of available models is taller than the terminal, it renders only what fits and lets you scroll through the rest. Furthermore, the highlight style is now reserved exclusively for the newest model release rather than arbitrary items.

BUGFIX

SendMessage fixes malformed closing tags causing summary text rejections

Cross-session messaging now parses malformed payload tags reliably.

Previously, when calling SendMessage, a broken closing tag could accidentally displace the message body into the summary parameter, causing the request to be rejected. The parser now isolates the text correctly regardless of imperfect tag formatting.

Like a clinic registration desk that keeps a patient's description in the description field despite a malformed closing label, instead of putting it in the summary box and rejecting the registration.
BUGFIX

Subprocess startup failures are handled cleanly without unhandled rejections

Like a delivery dispatcher handling a scooter that failed to start calmly, rather than letting the entire dispatch office crash in confusion.

Subprocess startup failures no longer trigger unhandled promise rejections.

In version 2.1.234, trying to launch a command like powershell.exe on WSL with Windows interop disabled caused unhandled runtime crashes. The process manager now catches and handles these startup errors cleanly.

BUGFIX

Fullscreen mode fixes delayed messages, prompt blank bands, and pane repainting

Fullscreen mode received several screen-drawing and layout fixes.

Resizing the terminal window sometimes caused newly submitted messages to remain invisible until the subsequent UI tick. In addition, clearing multi-line prompts could leave an empty blank band above the input area, and resizing panes away and back left views unpainted. These visual rendering issues have all been resolved.

Like a clean blackboard wiping down without stray chalk marks, updating text instantly without lag when the frame is adjusted.
BUGFIX

Managed-settings prompt ensures visibility before capturing approval keystrokes

Like a formal contract where the clerk must place the document directly in front of you, rather than keeping it hidden while treating your doorbell press as a signature.

A dangerous security issue with managed settings prompts has been fixed.

Previously, the startup prompt asking for approval of managed configurations could fail to display on screen while still recording your very first keystroke as consent. The prompt now reliably renders before processing user input.

BUGFIX

tmux tab titles stop jumping by updating only when text actually changes

Terminal tab titles inside tmux (especially via iTerm tmux integration) no longer jump jittery across updates.

The title string used to be rewritten continuously on a 960ms animation loop, creating visible flicker on the tab bar. It is now written only when the title text itself changes.

Like a meeting room door display that updates only when the title text changes, rather than flickering its backlight every second.
BUGFIX

Clear errors when cloud environments list is empty or malformed

Fetching cloud environments now returns descriptive diagnostics if the response is empty or damaged.

Previously, when the cloud environment endpoint returned an empty list or malformed data, the CLI presented an opaque, unhelpful error message. It now explains the failure clearly so you can diagnose configuration issues quickly.

Like a building directory that clearly says "no tenants listed" or "directory data is malformed", rather than displaying an inscrutable failure code.
BUGFIX

Remote Control stops auto-selecting fallback models on Fable 5 prompt timeout

Like a dining order where the waiter waits for you to return to the table, rather than automatically switching to a fallback dish after 60 seconds of absence.

When using Remote Control, the initial usage-credits confirmation prompt for Fable 5 no longer automatically picks a fallback model after 60 seconds of inactivity.

It now remains open until you explicitly respond.

BUGFIX

Spinner tips and background loops recover from malformed guest-pass cache

Spinner tips now appear reliably while waiting for responses.

Previously, if the cached guest-pass reward in ~/.claude.json was malformed, the system entered a repeated background error loop and failed to render loading tips completely. The cache reader now handles corrupted data gracefully.

Like a navigation app that skips a corrupted saved route and keeps showing the next instruction instead of repeatedly surfacing an error.
BUGFIX

Self-hosted runner sessions await post-session hooks before migrating

Like a car rental return where inspection and cleaning must finish completely before the keys are handed to the next driver, preventing overlapping handoffs.

Self-hosted runner session lifecycle handling is now race-free.

When a session is released due to idle, retire, or startup timeout, it used to occasionally resume on a different runner before its post-session hook finished executing. The coordinator now strictly awaits hook completion before migrating the session.

BUGFIX

Clawd mascot eyes and feet align neatly across all iTerm2 font sizes

The Clawd mascot in iTerm2 now displays with consistent proportions.

At certain terminal font sizes, character cell measurement differences caused Clawd's ASCII eyes and feet to render misaligned and lopsided. Spacing has been adjusted so the mascot appears cleanly balanced across different font configurations.

Like snapping pixel art to an exact grid so an illustrated mascot's eyes and paws stay symmetrical at any zoom level.
BUGFIX

Session recaps capped at 400 characters and trimmed at word boundaries

Like a book jacket blurb with a strict character limit that stops at the end of a complete word rather than spilling over the cover.

Session recaps will no longer run away with endless text.

Both automatic recaps and manual /recap outputs are now capped at a maximum of 400 characters, neatly truncated at a clean word boundary so that sentences do not cut off mid-word.

PERF

Session counter writes in background to boost startup performance

Launching Claude Code is now faster and more responsive.

Previously, the CLI blocked startup while waiting to record the session counter to disk. This write operation is now handled in the background, allowing the prompt interface to open without unnecessary disk I/O delay.

Like a supermarket that lets shoppers enter while a doorway counter increments visitor totals in the background, instead of holding the door until a clerk records each arrival.
FEATURE

Auto mode reviews Monitor commands like Bash by shelving allow rules

Like an airport switching to full automated security where even staff with bypass badges must put their bags through the X-ray machine.

Auto mode security has been strengthened.

When auto mode is active, existing Monitor allow rules are temporarily set aside, ensuring that Monitor commands undergo the exact same safety review as standard Bash commands.

FEATURE

Auto mode classifier unifies severity scoring across all cloud platforms

Auto mode classification is now standardized across third-party cloud environments.

On Bedrock, Vertex AI, Foundry, and setups where telemetry is turned off, the auto mode classifier now adopts the exact same defaults used on the Claude API, including severity-scored safety classification.

Like a school district using the same grading rubric at every campus, rather than changing standards based on location.
FEATURE

Auto mode git status check ignores showUntrackedFiles=no overrides

Like an inventory audit where the auditor inspects all unlabelled boxes in the warehouse regardless of a setting telling the scanner to ignore untracked items.

The git status check in auto mode is now impervious to repository overrides.

Previously, a repo configured with status.showUntrackedFiles=no could fool the check into declaring a clean working tree. The inspector now inspects untracked files accurately regardless of local git configuration.

FEATURE

/goal periodically checks in on sessions parked behind background tasks

Like a mechanic messaging you with progress updates after 30 minutes and at regular intervals during a lengthy repair, rather than waiting for you to call in.

When a session running under /goal is parked waiting for long-running background tasks to complete, it now checks in automatically after 30 minutes (and subsequently at 1h and 2h marks) instead of sitting idle until you return.

FEATURE

/usage displays usage-credits rows for Team and Enterprise plans

The /usage command now provides detailed credit consumption views for Team and Enterprise organization members.

It displays a dedicated usage-credits row, which clearly shows a capped bar at 0% before any spending occurs, giving teams full clarity over their starting baseline.

Like a corporate gas card dashboard displaying the full allowance along with a clean "0% spent" status before your first trip.
FEATURE

SIGTERM in print/SDK modes exits cleanly without synthetic tool denials

Terminating print or SDK sessions via SIGTERM now produces clean exit logs.

The runtime no longer injects synthetic tool denials or interrupted-turn artifacts into the conversation transcript before shutting down. Active commands are still terminated properly, and the process exits with status code 143.

Like clocking out at the end of the shift: your log shows a normal departure rather than claiming you refused to answer work requests.
FEATURE

Slash-command typos report errors directly instead of guessing fuzzy matches

Like punching a typo into a TV remote: the television reports that the channel does not exist, rather than jumping into a random nearby channel.

Typing a slash-command typo or invoking a command not available in the current session now cleanly displays an error on Enter, instead of executing the nearest fuzzy match.

Legitimate command prefixes and registered aliases continue to execute as expected.

FEATURE

Remote Control reflects offline status within seconds when CLI exits

Remote Control session status synchronizes much faster when your local client shuts down.

Whenever the CLI exits or the terminal window is closed, connection status refreshes immediately. Remote Control now marks the session as offline within seconds instead of lingering as active.

Like a messenger app turning your profile badge from green to grey within seconds of closing your laptop, preventing others from thinking you are still available.
FEATURE

SendMessage rejects inbox overflows up front instead of dropping them silently

Cross-session messaging now guarantees honest feedback when handling sudden bursts.

Previously, when rapid bursts exceeded what a destination session's inbox could accommodate, SendMessage reported them as delivered even though messages were dropped. It now rejects excessive messages up front with an error so the caller can back off or retry.

Like a factory parts rack that refuses a new part once it is full, rather than marking it stored and silently throwing it away.
FEATURE

Prompt border title chips and right-aligned footer items align consistently

Like a clean magazine layout where header tags, body margins, and footer notes all align with the same vertical grid line.

The terminal prompt layout has been polished for visual consistency.

The session title chip embedded on the prompt border now aligns with the footer's right edge. Furthermore, right-aligned footer items (such as the goal indicator, session state, and background agent status) and truncated notices share a uniform right margin with the prompt box.

FEATURE

VS Code extension adds screen reader announcements and heading navigation

The VS Code extension now provides full screen reader accessibility for the session transcript.

Users receive live audible announcements for incoming replies, permission prompts, errors, and status changes. In addition, the transcript incorporates per-turn heading structures so assistive technology users can navigate swiftly from turn to turn.

Like a document reader that announces new content and prompts live, while letting you jump to the spot you want by chapter heading.
