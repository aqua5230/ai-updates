Claude Code 2.1.269

Released: 2026-09-11

Release notes

BUGFIX

Plugin evaluation scoring launched, fixing path display and extraction permissions

Plugin developers can now directly evaluate extension performance, using a new command to run an eval suite against Claude Code and generate scored, reproducible results (including JSON and HTML reports):

claude plugin eval --help              # View plugin evaluation command help

Several plugin security and path issues have also been fixed.

For plugin archives in a session, fixes resolve issues where other local users could read extracted files, extracted files retained world-writable permissions from archives, and stale files survived re-extraction. For plugins enabled by organizations through managed settings, an issue where they failed to load in headless mode has been resolved; Claude Desktop will load them from the next session once Desktop bundles this CLI version. Additionally, headersHelper consent prompts no longer display URL paths that could be misread as hostnames, and relative paths on Windows containing folders starting with @ are no longer misidentified as redacted URLs.

The entire workflow is like periodic inspections at a vehicle testing facility, using dedicated machines to measure brake and emission data item by item and issuing inspection decals to prevent unverified parts from leaving vulnerabilities during assembly.
FEATURE

Skill namespaces align with Claude Desktop, improving Language Server exit workflows

When using skills synced from claude.

ai in cloud sessions, package names are now formatted as anthropic-skills:<name> to match Claude Desktop behavior; bare names can still be used when there are no conflicting items. If the Skill tool is called with an unregistered bare name that uniquely matches a plugin skill, the error message now actively suggests the full name. For plugin LSP language servers running in the background (such as rust-analyzer) that previously remained running at session end if they rejected shutdown parameters, an exit command is now sent even if the shutdown request fails to ensure processes are terminated. Additionally, reading the artifact database and saving it into the session scratchpad no longer stops to ask for working-directory approval.

This is like packing away instruments after a symphony rehearsal, where custom instruments brought by guest musicians are clearly tagged with section numbers, and even if an instrument case latch gets stuck when dispersing, the stage manager thoroughly checks and clears the stage.
FEATURE

Terminal output style switching added, spinner tips recommend focus view

This is like switching filters and camera angles on the fly in a professional photography studio, where the photographer can instantly apply black-and-white or soft-focus color grading, or dim surrounding fixtures right away when focusing on the subject's expression.

The terminal now adds style-switching commands:

/output-style                         # List all available output styles
/output-style [name]                  # Switch to the specified output style

This feature also supports Remote Control, cloud environments, and various headless sessions.

The spinner animation while waiting for responses now suggests /focus to switch to a streamlined view retaining only your prompt, a one-line work summary, and the response. The /diff panel for reviewing file changes now opens fully rendered in one step instead of showing a loading state first. Additionally, an issue where attaching CMYK JPEG images caused decoding failures has been fixed; they are now converted, resized, and attached like regular JPEGs.

FEATURE

Bash file edits show diffs, strengthening pipeline write security restrictions

When commands executed through Bash modify files in the terminal, tool results now directly include a diff of the changed files.

This feature is supported by the managed setting bashEditDiffEnabled. Security checks have also been reinforced for pipeline writes. Previously, when writing files via Bash's tee command, Edit() deny rules and write-path checks could be bypassed; this protection is now fixed, and Bash(tee:*) allow rules no longer cover destinations outside the working directories. Additionally, the Git status told to Claude after compaction is now refreshed to the current status instead of using outdated records from the start of the session.

Construction sign-off is like an itemized invoice at a renovation site, clearly listing which partition wall was removed and which pipe was replaced; if anyone tries to run hidden pipes through an unsigned neighbor's unit without authorization, the inspector can intercept and stop it on the spot.
FEATURE

Permission exclamation marks restrict source scope, telemetry metrics tag repository attributes

This is like dedicated customs clearance procedures in freight shipping, where special clauses apply only to the customs broker that signed them, and shipping containers are clearly stamped with vessel numbers and codes without mixing in anonymous sources.

Telemetry and permission settings receive several adjustments:

# Tag vcs.* repository attributes; commit events include vcs.ref.head.*
export OTEL_METRICS_INCLUDE_REPOSITORY=1
export OTEL_LOG_TOOL_DETAILS=1

Deny or ask permission rules starting with an exclamation mark ! now apply only within the settings source that wrote them without spreading, and a bare ! negation is ignored.

An issue where Read, Edit, and Write calls blocked by path-scoped deny rules were omitted from permission_denials in --output-format stream-json results has been fixed. Additionally, attribution reminders no longer override CLAUDE.md or memory rules against commit and PR attribution; lines set by managed settings still apply, and gRPC endpoints without a scheme correctly name the collector in the approval dialog.

FEATURE

Gateway model discovery customizes timeout, cloud inference adopts session model

Connection flexibility and multitasking stability have improved for users on enterprise model gateways or third-party cloud platforms.

If a gateway's /v1/models endpoint responds slowly, the wait timeout can now be customized via an environment variable (defaulting to 3 seconds).

export CLAUDE_CODE_GATEWAY_MODEL_DISCOVERY_TIMEOUT_MS=10000

Across Bedrock, Vertex, Foundry, and gateway environments where an account cannot access the default Opus model, running /insights now uses the current session model instead, resolving previous direct failures.

When another local process happens to refresh login at the exact same moment, the session still fully loads organization policy limits. Additionally, for desktop sessions using Bedrock, Vertex, or a gateway, turn-end notifications now include contextual text explaining what Claude needs.

This is like the triage window in a hospital emergency room, proactively extending call waiting times during special lab tests, having on-duty doctors take over report interpretation if the attending physician shifts changes, and ensuring simultaneous registrations never overwrite medical records.
BUGFIX

Workflow raises background agent concurrency limits, fixing status reporting and formatting

This scheduling is like heavy container gantry cranes at a modern shipping terminal, where multiple machines move cargo concurrently, the central control room never falsely reports idle slots while cranes are actively hoisting, and equipment specification boards no longer split their borders due to oversized text.

For high-volume concurrent inference demands, an environment variable can now raise the Workflow tool's per-run concurrent background agent limit (configurable from 1 to 256):

export CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS=32

Several background task and display issues have also been resolved.

In remote and headless sessions, an issue where background agents running still mistakenly reported waiting for input has been fixed (set CLAUDE_CODE_BG_TASKS_REPORT_RUNNING=0 to restore the old behavior). Rapidly clicking /fork receipts no longer blocks immediate backgrounding, and sessions started via the SDK or desktop app no longer show unknown statuses in agent lists. Additionally, when resuming background tasks, escape codes, line breaks, and oversized text from on-disk records no longer reach task lists or notifications, and prompt box top borders no longer split into extra lines from line breaks.

BUGFIX

Prompt cache reuse accurately maintained, fixing long-session resumption and compaction stalls

This is like Go players returning to the board after a match pause to resume play, placing stones directly according to earlier game records without knocking over the entire board when the clock chimes.

Responsiveness and caching performance in long conversations have improved significantly.

When a response is cut off at the output limit and automatically resumed, prompt caching on the next turn no longer partially invalidates. Resuming a session after interrupting Claude mid-thought fixes an issue where changed re-sent context hurt cache reuse. Cloud sessions briefly wait for server configuration before the first request, preventing cache misses. Auto-compaction no longer gets permanently stuck on prompt-too-long states when lacking complete earlier exchanges to summarize. Transcript updates no longer re-process the entire conversation to build collapsed tool-use summaries. Additionally, CLAUDE_CODE_RESUME_INTERRUPTED_TURN no longer re-runs turns that failed with API errors over 6 hours ago, and CLAUDE_CODE_RESUME_INTERRUPTED_TURN_MAX_AGE_MS can customize this limit.

BUGFIX

Terminal keyboard protocol compatibility fixed, eliminating stray startup characters

Keyboard interactions and compatibility across terminals have been thoroughly calibrated.

Issues where F1, F2, and F4 failed in kitty-protocol terminals, Delete failed in st, Alt+arrows acted as Escape in rxvt-unicode, and Shift+punctuation typed unshifted keys in WezTerm have all been resolved. Replies to capability queries no longer appear as stray text at startup in certain terminals. Over slow connections like SSH or browser terminals, 22c, color, or version replies are no longer typed into the prompt. Additionally, over SSH or in unrecognized terminals that answer kitty keyboard queries (such as foot and Alacritty 0.16+), Shift+Enter and Ctrl+Shift shortcuts are now fully supported.

The entire calibration is like mechanical microswitches and anti-ghosting circuits on professional gaming keyboards, where signal lines never mistake test voltages for keystrokes and complex key combinations fire instantly.
BUGFIX

Terminal fullscreen resizing prevents blank rows, input cursors render normally

This is like motorized projection screens in an exhibition hall: no matter how wide the screen stretches or retracts, top and bottom borders never turn blank unexpectedly, and pointers and refresh rates match specifications precisely.

Terminal interface layout and cursor rendering have received multiple fixes.

After resizing terminal windows in fullscreen mode, an issue where rows at the top or bottom of transcripts went blank has been fixed. When the terminal's native cursor is enabled, text fields for permission rules, auto-mode rules, add-directory, session renames, and feedback reviews fix missing cursors that obscured typing positions. Additionally, for GNOME Terminal and Konsole versions that do not support synchronized output, Claude Code no longer assumes synchronized output based merely on terminal names, preventing display update anomalies.

BUGFIX

External editor return redraws fixed, eliminating lingering block cursors in fullscreen

Window switching and rendering are now more stable for users accustomed to launching external editors for long-form edits.

Returning from an external editor outside fullscreen mode via Ctrl+G previously caused the interface to be drawn twice; this redraw issue has been corrected. An issue where returning from an external editor in Konsole drew the interface twice has also been resolved. For rxvt-unicode terminals, issues where terminal block cursors showed through beneath the interface after leaving or re-entering fullscreen, or stayed visible after returning from an external editor in fullscreen mode, are now resolved.

The overall transition is like a plein air painter folding a portable sketchpad, where pulling back to a small sketchbook from an outdoor easel never stamps the canvas twice, and unfolding full-sheet paper leaves no stylus cursor stuck in edge shadows.
BUGFIX

External tool server connections fixed, headless session retries retain replies

This connection architecture is like repeater stations along transoceanic submarine cables, where external stations connect immediately when power restores, URL parameter tweaks never trigger blind restarts, and background transmission commands operate independently to completion.

Communication stability in remote and headless sessions receives important fixes.

Resuming remote sessions now connects synced plugin MCP servers properly. In resumed headless sessions, switching models or retrying requests mid-turn no longer loses that turn's replies. When updated configurations only change query parameter ordering in server URLs, MCP servers no longer reconnect unnecessarily. In first-party sessions with telemetry disabled, alwaysLoad servers that finish connecting mid-conversation are immediately usable on the next turn. On Windows, PowerShell tool commands sent to the background no longer terminate when Claude Code exits.

FEATURE

Goal execution adds automatic retry and backoff, review reports post PR comments directly

Process control is now more dependable when executing long-running tasks with advanced commands.

Previously, /goal silently stalled after network drops, API errors, or reaching token limits. It now automatically retries with backoff, or pauses and clearly states why, including waiting until usage limits reset. /ultrareview --post now posts PR comments directly when findings arrive and prints comment links, without needing a second cloud session. In the input prompt, prompt suggestions dropped for text without spaces between words (such as Japanese, Chinese, and Thai) have been restored. Prompt suggestions for CJK text now retain single-word and mixed-script suggestions, dropping meta or evaluative text just like English. Additionally, /btw side questions previously could fabricate tool calls and output; Claude is now instructed not to write them, and any that appear are flagged as unexecuted.

This is like pacing guidance at marathon aid stations, where runners facing exhaustion or dehydration slow their pace and are directed to rest stops, while roadside volunteers report actual course conditions without inventing detour routes.
FEATURE

[VSCode] Subagent map visualizes management, Focus view displays live progress

This is like dynamic work-assignment boards on a construction site, listing each foreman's area of responsibility and progress on individual cards, where supervisors can review work logs or stop specific crews at any time.

The VSCode extension brings visual tools for multi-agent collaboration.

Clicking the agent pill in the footer opens an agent map with dedicated cards for all subagents in the current session, supporting stopping individual agents and reading read-only transcripts. In Focus view, live progress rows for running subagents have been added beneath tool-call groups. An issue where new turns triggered by plain-text prompts (such as scheduled tasks) were mistakenly grouped into the previous turn in Focus view has been fixed. For plan previews, issues where late-loading previews hid comment boxes or displayed older plans have been eliminated, and closed tabs no longer accept orphaned comments. Additionally, when Claude writes documents or messages for someone other than the user, it addresses that audience and names it at the top of the reply.

The VSCode command menu adds two new dialogs: Hooks and Permission rules.

Users can browse rules across user, project, and local settings in visual panels. Hooks can be added, edited, or removed; permission rules can be added or removed. Managed, plugin, and session hooks remain read-only; startup-option, session-only, and managed permission rules remain read-only. The current-file chip in the input box is now removed directly via an X icon, replacing the previous Hide toggle. Context menu and editor title bar items that could not act on the selected tab have been cleaned up and removed. Additionally, screen reader and keyboard accessibility have been upgraded across slash-command menus, @-mention menus, output-style pickers, Send/Stop buttons, permission and question cards, and onboarding checklists, while inserting @-mentions via shortcuts when starting new chat views no longer experiences lag.

The entire operation is like outfitting machinery consoles with standardized safety valve menus and mistake-proofing covers, where maintenance staff can intuitively open or close valves while assistive prompts and key guides are thoroughly in place.

One-off scheduled routines resolve issues where runs occasionally executed a second time after transient server errors. Additionally, routine runs using subagents that were previously treated as finished too early—which could skip retries after real failures or trigger duplicate runs—now have their status determination fully fixed.

This is like anti-jam security flaps on mailbox drop slots, allowing mail to be pulled back and rewritten before postal carriers collect it, while delivery vans never make duplicate trips for the same package due to brief signal glitches.

Plugin rows in Slack access settings no longer show only unlabeled raw IDs, but now display plugin names and link to the managing bundle. [Claude Tag] Threads automatically retry failure notices, fixing table attachments and routine runs

When collaborating with Claude in Slack channels, notifications and formatting render more reliably.

When a failed turn hits brief Slack rate limits, failure notices are no longer dropped to leave threads silent, but are now automatically retried. When tables are posted alongside attached files in the same message, tables are no longer downgraded to raw pipe text, instead posting as normally rendered tables followed by plain file captions. Entering @Claude !restart at the top level of a channel where Claude is not active no longer starts unrelated conversations, replying privately instead that there is nothing to restart. Additionally, scheduled routines in channels can now reply directly in existing threads rather than spamming new top-level messages; timestamps on live progress checklists now display each reader's local time and relative update elapsed time instead of fixed UTC times.
