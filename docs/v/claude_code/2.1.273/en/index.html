Claude Code 2.1.273

Released: 2026-09-15

Release notes

FEATURE

Gateway Hint Headers Introduced for More Precise Enterprise Traffic Routing

To help enterprise gateways tell what each model call is for, requests can now carry their own hint signals.

This is like sticking classification labels and delivery notes onto a package exterior, allowing sorting hubs to separate rush deliveries from bulk freight by barcode without unpacking the boxes.

Claude Code now supports sending five hint headers with requests, covering request class, agent type, previous tool durations, context compaction status, and whether compaction was completed, making it easier for backend gateways to analyze traffic and route requests. To enable these headers when sending requests, simply set CLAUDE_CODE_GATEWAY_HINT_HEADERS=1. When managing model calls via custom gateways on internal networks, this setting helps enterprise systems accurately track the purpose and state of each invocation.

FEATURE

Remote Control Adds Session Forking to Launch Independent Background Sessions

When you want to test an alternative direction on mobile, you can now fork the conversation directly.

This is like opening an independent bypass lane alongside a main road, allowing vehicles to peel off and explore new paths while traffic on the original lane continues undisturbed.

After launching Remote Control with claude --remote-control or /remote-control, you can tap fork directly in the Claude app, and your computer will automatically spawn an independent background session to continue execution. When debugging remotely from your phone on the go, this lets you preserve current progress while testing new approaches in parallel.

FEATURE

Proactive Disconnection Alerts for External Tools and Commands for Expired Logins

When an external tool drops mid-session, you are no longer left guessing.

When using MCP (Model Context Protocol, a protocol connecting AI to external tools), if a tool server disconnects mid-session and automatic reconnection gives up, the terminal proactively displays a notification pointing you to the /mcp command. Additionally, if an MCP server's login credentials expire mid-session, the error message clearly explains how to re-authenticate.

This is like an external monitor cable slipping loose in the office: instead of pretending everything works normally, the system immediately pops up an alert prompting you to check the port.
FEATURE

Cloud Platforms Default Auto Mode to Local Classifier with Switch Available

Running auto mode on cloud-hosted platforms is now more responsive.

Across Bedrock, Vertex AI, and Foundry, auto mode currently defaults to using the local classifier to identify commands. If organizations need to switch to the cloud platform's server-side classifier, they can set CLAUDE_CODE_AUTO_MODE_SERVER=1.

This is like filtering parts instantly using local sensors right at the factory door, eliminating the round-trip latency of sending data back to a remote headquarters server for evaluation every time.
FEATURE

Telemetry Metrics Complete Tool Names and Problem Reports Filter Private Data

For performance checks, plugin login, and issue reports, this release separates the data that should be kept from the data that should be hidden.

When enabling OTEL_LOG_TOOL_DETAILS=1 to track performance, cost and token metrics become more complete. Logs now include the real names of agents, skills, plugins, and MCP servers. Signing in with a Claude account now also requests access to your claude.ai plugins. When running /bug and /feedback to report issues, submitted reports retain only behavioral parameters from the last API request—such as model name, system prompt, and tools list—while automatically omitting request metadata and CLAUDE_CODE_EXTRA_BODY fields.

This filtering mechanism is like filling out a warranty survey where the system automatically blacks out confidential details, sending only failure codes back to the manufacturer.
BUGFIX

Disabled Skills Move to Trash and Enterprise Management Rules Take Precedence

After a company turns off skills or rolls out managed rules, Claude Code should not keep using old permissions.

When an organization turns off skills in claude.ai, previously synced skills no longer remain in sessions and instead move directly to the recoverable trash. Furthermore, allowManagedMcpServersOnly, deniedMcpServers, and disableClaudeAiConnectors rules configured via Mobile Device Management (MDM) or managed-settings.json are no longer ignored even when server-managed settings coexist, ensuring security controls take full effect.

This revocation workflow is like a company reclaiming software access permissions: the computer immediately moves the application into the recycle bin, and central headquarters policies always override custom departmental preferences.
FEATURE

Security Boundary Protections Reinforced with Stricter Command Prompts and Path Access

Unreadable Bash commands, memory paths outside the working directory, and macOS file paths each return to the right permission handling.

This is like strictly verifying visitor badges at a campus gate: regardless of what jacket someone puts on or whether they take a side shortcut, entry is granted only after confirming valid clearance.

When permissions.blockReadsOutsideWorkingDirectories is enabled, Bash commands that the permission checker cannot fully analyze no longer skip confirmation prompts, and a flaw where a subshell in bypass mode hid a dangerous rm command has been fixed; memory directories specified by project settings outside the working directory are no longer loaded into the prompt, recalled, indexed, or used for memory extraction. On macOS, dragged-in screenshots or files reported under a secondary path are no longer denied due to symlink resolution issues. Previous over-blocking on unanalyzable commands has been reverted, restoring confirmation prompts for commands like time -p make build.

FEATURE

Sub-Agent States Delivered Reliably and Long-Session Scheduling Runs Smoother

When background sub-agents are mid-run, the important part is that results do not disappear and scheduling does not run in the wrong place.

This is like auxiliary conveyor belts on a factory production line: even when individual workpieces are moved to a back packing area, overall progress reports and handoff manifests remain orderly and clear.

If a streamed reply omits token usage or carries no model ID, sub-agents and background agents are no longer marked as failed with lost results. When outputting via the SDK or --output-format stream-json, remaining messages and final reports from a sub-agent are no longer dropped even if it moves to the background mid-run. /tui no longer hangs on restart due to an agent-team member that has already finished. When .claude/scheduled_tasks.json is copied to a new worktree, scheduled tasks no longer run in the wrong session. Hook progress and sub-agent updates in long sessions no longer re-process the entire conversation history on every update.

BUGFIX

Thinking History Preserved Accurately and Context Usage Metering Avoids Premature Triggers

In long conversations, thinking history and context usage both need to be preserved accurately.

Running /login, /upgrade, or /extra-usage no longer discards previous thinking history from the conversation, avoiding forced full prompt-cache rewrites on subsequent requests. The context meter and auto-compact no longer count advisor-tool turns at twice their actual size, fixing an issue where compaction triggered prematurely halfway through the window. Remote Control clients connected to Claude Desktop, VS Code, or JetBrains sessions are no longer refused when querying context window usage. The compaction status line spinner no longer displays duplicate ellipses.

This protection mechanism is like a page counter in a pocket notebook: it precisely measures the thickness of every summary, and won't tear out preceding draft pages during page turns just because an ID was temporarily checked.
FEATURE

Artifacts Publishing Re-sends Automatically and Databases Support Single-Field Updates

Artifact publishing, page reads, and database updates now make it less likely that you have to redo work after getting stuck.

This is like posting sticky notes on a cloud collaboration whiteboard: making an edit requires only peeling off a specific field tag rather than wiping and redrawing the entire board.

In cloud or Remote Control sessions, the Artifact tool no longer pauses unnecessarily for approval when auto mode uploads chat attachments. Database updates can now remove a single field without rewriting the entire document, and publishing requests whose connections drop after reaching the server are re-sent safely to avoid failures or duplicate versions. When encountering unsupported file types, the terminal displays a clean single-line error while informing Claude of supported formats; reading a page clearly explains the database rules and capabilities for that page, and operations no longer trigger false-positive plugin suggestions.

FEATURE

Cloud Gateway Auth Errors Provide Specific Guidance with Clearer Certificate and Proxy Diagnostics

Diagnostic messages now pinpoint specific causes during cloud platform and network connection issues.

When encountering 401 or 403 errors on Bedrock, Vertex AI, or Foundry, or 403 errors on Claude app gateways, messages no longer blindly prompt to run /login; instead, they clearly specify which credential to refresh or guide you to contact your gateway administrator. When a cloud session cannot be created due to an expired or revoked login, the prompt correctly directs you to run /login. In-session SSL certificate and proxy connection errors now list error codes and remediation steps, such as pointing to NODE_EXTRA_CA_CERTS for untrusted corporate certificates.

This experience is like a building access card failing at the gate: the screen clearly displays whether the card is demagnetized or requires administrator clearance, rather than blindly asking everyone to line up again for queue tickets.
FEATURE

GitHub Workflow Errors Pinpoint Causes with Clearer Pull Request Diagnostics

When a GitHub workflow only shows a generic error code, it can leave you stuck outside the real login, SAML, or webhook problem.

Running /install-github-app no longer misreports SAML single sign-on blocks as missing administrator permissions, and cloud sessions encountering IP allowlists, suspended app installations, or SAML restrictions directly show the specific cause. When running /autofix-pr, failures with gh pr view display native GitHub CLI errors (such as sign-in or rate limits), while webhook delivery failures state the specific reason. Running /web-setup with a refused GitHub token lists likely causes and fixes, and connection failures clearly point out proxy or TLS certificate issues.

These diagnostic reports are like a package held up at customs: the inspection slip clearly checks whether an identity affidavit is missing or clearance quotas are exhausted, showing you at a glance which document needs filing.
BUGFIX

Exclamation Marks Allowed in Shell Mode and Repository Exclude Stubs No Longer Linger

You are in shell mode, you type ! grep …, and the leading exclamation mark vanishes — that one is fixed.

When already in shell mode, the main prompt no longer drops a leading ! exclamation mark, so you can type negated commands. The other fix: during long-running sessions, if a repository's .git directory has been deleted or moved away, Claude Code no longer recreates a stub .git/info/exclude file in its place.

Both fixes are like an over-eager assistant finally learning to leave things alone: the note you wrote keeps every character, and the folder you moved away stays moved.
FEATURE

VS Code Hides Disabled Feedback and Windows Error Banner Eliminated

VS Code feedback entry points should stay hidden when disabled, and Windows should not show fake errors after a turn completes.

If an organization has disabled product feedback, the "Report a problem" option in VS Code along with /bug and /feedback commands will no longer open a report form. On Windows, a red exit banner showing error code 4294967295 no longer pops up at the top of the screen after completed turns. Furthermore, when adding mapped network drives via --add-dir, the system strengthens network permission checks for Universal Naming Convention (UNC) paths.

This overall behavior is like hiding disabled feedback boxes on a dashboard: once tasks finish, the system quietly returns to standby without flashing glaring red warning indicators.
FEATURE

Web Routine Management Updated with Confirmation Dialog for Unsaved Changes

Routine pages now ask first before throwing away the name, prompt, or edits you typed.

This is like setting recurring events in an online calendar: navigating away from the edit window actively prompts you to confirm discarding drafts, while placing manual run buttons and run history side by side on the same dashboard.

After an administrator removes and re-adds an organization connector, routines no longer lose access permissions or erroneously invoke old connectors. When a routine name, prompt, or edit has been entered on the New routine page or Edit routine dialog, closing prompts a "Discard unsaved changes?" confirmation. The detail page has also been redesigned: breadcrumbs now include a menu and rename option, the on/off switch and Run now button are integrated at the top, and run history is displayed alongside routine settings.

FEATURE

Web Environment Setup Made More Reliable with Direct Routing to Configuration

Before new users enter the web version, environment creation, privacy settings, and first-run guidance now take fewer detours.

When creating a self-hosted environment from organization settings, a server error that left half-created environments behind has been fixed. The administrator "Share cloud sessions" setting has been moved under Data and privacy, allowing Data and privacy admins to manage it directly. New users on Mac and Windows without a configured cloud environment no longer see a mandatory full-page desktop app download screen when visiting the web version, heading straight to setup instead.

The new onboarding flow is like a new hire bypassing promotional brochures and walking straight into the office, while administrators centrally manage all external sharing settings from a dedicated privacy console.
BUGFIX

Claude Tag Watches Public Slack Channels with Thread and Memory Fixes

If Claude Tag in Slack goes silent, restarts work, or leaves out memory, teams have a hard time trusting it to take over collaboration.

Like a sharp project assistant who proactively monitors incident announcement channels and stays focused in individual discussion threads, Claude never scraps in-progress drafts just because someone chimes in elsewhere.

Claude now proactively watches related public channels (such as incident channels a conversation depends on) without needing manual mentions; replying in an older thread no longer restarts in-progress tasks or loses unpushed work. Scheduled tasks in organization-shared private channels now continue running reliably in their original threads. Reinstalling the app under Enterprise Grid when the grid is disconnected but one of its workspaces stays connected no longer causes Claude to go silent within minutes, and adding channel managers is now supported on Enterprise Grid shared channels, channels where Claude has not yet been used, and legacy private channels. The admin Memory page now lists channel memory created by Claude, allowing administrators to review, edit, and delete it at any time.

BUGFIX

Cloud Service Connectivity Reinforced with AWS and Authentication Fixes

Connections should not break midway just because an account was freshly authorized, an AWS endpoint has no region, or a third party returns a lowercase auth type.

After an account token refreshes, messages are no longer dropped with false notices claiming an environment could not be found. AWS connections fully support region-less endpoints such as Budgets, Savings Plans, WAF Classic, and Import/Export, and Global Accelerator requests now sign properly; if a request cannot be signed due to hostnames lacking a region, the system clearly explains the cause and remediation. When third-party providers return lowercase token types for OAuth client-credentials and JWT-bearer connections, requests now standardize on the standard Bearer scheme.

This connectivity mechanism is like an international communications switchboard that reliably parses diverse standard protocols, never dropping in-transit telegrams when refreshing transit passes.
BUGFIX

Code Review Precision Improved with Dependency Notes and Comment Delivery Fixes

In code review, few things hurt more than a small change getting a full re-review, or retrying comments only to duplicate or miss them.

This is like a senior editor reviewing revisions: focusing exclusively on newly amended passages and detailing upstream and downstream impacts in margin notes, without rejecting an entire manuscript for full review just because an author uses different casing conventions.

When merging a base branch into a pull request whose prior review noted "Additional findings," the system runs a lighter follow-up review instead of a full re-review; repositories whose owner or name contains a capital letter now skip empty or content-identical pushes. REVIEW.md files are no longer ignored in their entirety due to @-mentions, multiline code spans, or backticked HTML tags. Instead, only lines that link to changed files are withheld. Suggested fixes now state what dependent code must keep working, and review comments for secondary affected locations use full sentences. Retrying /ultrareview --post ensures findings comments post exactly once while naming the reviewed commit.
