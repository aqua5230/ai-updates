Claude Code 2.1.332

發布日期：2026-11-25

繁體中文

新功能

斜線選單新增 MCP 伺服器技能（測試版）

想直接取用外部服務內建的專屬指令，現在不用手動複製貼上。MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器提供的技能已進入測試版，會直接列在 / 選單裡。 這些技能在 / 選單裡會顯示成 server:skill 格式，讓你一眼認出它來自哪台伺服器。你自己原本建立的其他技能則會保留原本的名字，不會被改名。

就像廚房裡各家品牌的香料罐都貼上產地標籤，架上原本的自製醬料照舊叫原本的名字，拿取時一眼就能分清楚。
新功能

載入技能前可透過 hook 攔截內嵌指令

替 Claude 掛上外部技能或自訂指令，最怕它一載入就自動跑起裡面的終端機指令。現在新增了 PreSkillShellCommand 這個 hook（特定事件發生時會被觸發的小程式）事件，能在載入當下直接拒絕執行內嵌的 shell 指令。 如果你同時有 2.1.331 或更舊的版本，設定檔裡寫到這個事件時，啟動當下會先跳出提醒對話框。

好比活動場館在特約廠商進場搭台前先檢查工具箱，不合規定的機具當場擋在門外，不讓它直接開機運作。
新功能

跨工作階段訊息支援一律傳送與模型提醒

開著多個工作階段同步跑任務，現在各視窗之間的訊息放行與模型切換更好掌控。 遇到來自其他工作階段的暫留訊息詢問時，現在選項裡多了一個「Always deliver」，選下去就能直接放行。 如果被標記的訊息讓目前的工作階段停在不同模型上，終端機最底下會一直留著一行提醒，直到你用 /model 重新選好模型為止。

跟把常用分機設成免確認直接轉接一樣，若這通電話還在錯的窗口上，桌上就一直貼著便條提醒你換線。
新功能

給管理員的 OpenTelemetry 遙測調整

給使用 OpenTelemetry 追蹤紀錄的管理員與開發者，這一版調整了四項回報行為。 開啟回應紀錄時，Claude 透過一般訊息工具或 Cowork 訊息工具送出的文字現在會多記一筆回應事件。未開啟回應紀錄（OTEL_LOG_ASSISTANT_RESPONSES=1）的話，工具輸入紀錄只會留下文字長度，不再存下全文。 桌面版 Code 分頁的工作階段預設服務名稱改為 claude-code-desktop。若過濾條件原本寫死 claude-code 記得更新，或設 OTEL_SERVICE_NAME 維持舊名。 帳號沒啟用的內建 MCP 伺服器，啟動時不會再誤報連線失敗事件。

新功能

VS Code 與桌面版新增工作階段保存提醒

在編輯器寫程式跑長對話，或是回頭接續昨天的進度時，最怕有內容沒存好卻不知道。 在 VS Code 與桌面版的 Code 分頁裡，當工作階段有部分內容無法存檔時，畫面會跳出警告，並告訴你怎麼用 /compact 把內容保存下來。 接續舊的工作階段時，如果更早之前的訊息沒有載入，介面也會像終端機版一樣先顯示通知，讓你心裡有數。

彷彿寫到最後幾頁發現筆記本裝訂鬆脫，編輯器先提醒你怎麼裝訂保存，翻回前面缺頁時也會夾張書籤提示。
新功能

啟動頁標頭直接顯示網安驗證方案層級

擁有 Cyber Verification Program（網路安全驗證方案）資格的帳號，現在一打開程式就能確認自己的方案狀態。 只要用 claude.ai 帳號登入，而且你的方案層級適用目前選用的模型，啟動畫面頂端的模型名稱旁邊就會直接標出你的驗證層級。

如同參加展覽時把可通行的展區等級直接印在名牌旁，站上入口一眼就能確認資格。
問題修復

修正登入無法存檔卻誤報成功

執行 claude auth login 登入 claude.ai 時，過去就算登入資料沒存進去，畫面仍會印出 Login successful. 讓你誤以為成功。這個問題已經修好，現在存檔失敗會回傳結束碼 1，並提示要檢查的項目，例如殘留的鎖定檔或磁碟已滿。

問題修復

用 `@` 提及或讀取檔案不再卡死或靜默漏讀

讀檔或用 @ 帶入資料不再那麼容易凍結或靜默漏掉內容。 讀取、@ 提及或壓縮遇到無人寫入的具名管線（例如被鎖住的密鑰管理工具掛載的 .env）時，不會再無限期卡住，超過 20 秒就會失敗結束。 提示詞或管線輸入裡若出現 @ 後面接著極長的無斷行字串（例如內嵌字型的壓縮 CSS），現在也不會凍結。 用 @ 提及副檔名文字檔時，若連前 2,000 行都超過讀取上限，不會再悄悄略過，現在會直接告訴 Claude 檔案大小與讀取方式。

新功能

對話壓縮失敗與代理大小限制恢復更穩定

長對話就算碰到壓縮卡關或代理伺服器大小限制，現在也能接續跑下去。 自動壓縮連續失敗時，若在對話長度上限前再壓一次就能接續對話，回合不會再直接卡死並跳出「Prompt is too long」。 壓縮摘要一直超過輸出上限時，連續三次被截斷後，最後一次嘗試會主動要求產出更短的摘要。 週額度還有很多空間的訂閱者，閒置自動壓縮不會再被跳過。 透過有請求大小限制的代理或閘道器傳送長對話，導致每則訊息與 /compact 都回傳 413 錯誤時，現在的恢復能力也改善了。

問題修復

Hook 凍結、超長日誌截斷與 hook 詢問理由顯示

掛了 hook 之後遇到的幾種凍結與日誌溢位問題，這版一次清掉。 權限規則或 hook 條件含多個萬用字元並比對長指令時，不會再凍結。 hook 持續不斷印出輸出造成的凍結與記憶體暴衝，在多數情況下不再卡住與耗盡記憶體。 對話回合中或 /compact 後，若 hook 擋下動作或執行失敗，並夾帶超大日誌，不會再造成凍結與脈絡溢位；超過約 50,000 字元的文字現在會自動縮短。 在終端機執行 Read、Grep、Glob、Edit 或 Write 的詢問畫面時，PreToolUse hook 要求確認的理由現在會正常顯示出來。

問題修復

MCP 伺服器斷線重連、指令與凍結修復

外接 MCP 伺服器碰上狂印輸出、斷線或指令漏判的狀況已經改善。 本機 MCP 伺服器狂印標準輸出時，終端機不會再凍結也不會無視 Ctrl+C。 使用 SSE 串流的 MCP 伺服器若事件串流中斷後換新端點或沒恢復，不再卡死或拒絕所有工具呼叫。 Remote Control 工作階段重開後，本機 MCP 伺服器不會再看到新的工作階段 ID。 MCP 伺服器回傳的任務 ID 上限從 128 字元放寬到 1,024 字元，不再出現「malformed task handle」錯誤。 執行 /mcp reconnect all 與 /mcp disable all 時，不會再把帳號未啟用的內建伺服器算進去。

問題修復

修正重寫大檔後開啟回溯點的長時間凍結

把受追蹤的大檔案整個重寫過後，過去只要想點開先前的回溯點查看紀錄，終端機就會僵住很久沒有反應。這個問題已經修好，現在重寫大檔案之後再開啟回溯點，不會再發生長時間凍結。

問題修復

遠端控制的工作階段與額度狀態回報更準確

從桌面版、VS Code 或 Agent SDK 查看 Remote Control 工作階段，燈號狀態現在跟實況一致。 當工作階段其實正在等對話框或 MCP 伺服器的提問回應時，不再錯誤顯示成執行中。 用量額度重設過後，Remote Control、IDE 與 SDK 用戶端也不會再繼續回報已達上限。 由桌面版或 VS Code 託管的工作階段在執行 /compact 期間，狀態不再顯示成閒置。

問題修復

接續工作階段與設定檔存檔更可靠

切換工作環境或從當機後接續對話，規則重複與漏訊息的問題都解掉了。 你可以用 EnterWorktree 把工作階段移進 .claude/worktrees 底下的 worktree（讓同一個專案平行開多份副本的功能）。移進去之後，或在裡面接續工作時，多數情況下不會再重複把 CLAUDE.md 和規則檔送給模型。 在 Bedrock、Google Cloud Agent Platform、Foundry 等第三方供應商遇到當機或強制終止後，重開對話不會再漏掉最後幾則訊息。 把空白工作階段移至背景時，不再跳出「Couldn't load transcript from file」失敗。 有其他工作階段正在存檔時，~/.claude.json 不會再被誤判為毀損。

問題修復

雲端與桌面版工作階段完成狀態不再誤判

背景任務還在跑、或剛拒絕權限請求時，畫面上顯示的進度現在不會再跟實際情況對不上。 在無頭模式（沒有視覺介面或終端機視窗的執行模式）與雲端工作階段裡啟動前景分支的 Agent 呼叫時，不會再於分支剛啟動的瞬間就回報已完成。 於重啟後的 claude.ai 對話拒絕權限提示時，摘要列不再把根本沒執行的工具呼叫算成已完成。 在 Claude 桌面版收到背景任務的回報後，原本顯示「需要輸入」的狀態也不會再莫名消失。

新功能

Linux 版軟連結差異與剪貼簿套件提示

Linux 用戶在檔案差異與剪貼簿貼圖上多了兩項實用修補。 透過 symlink（指向另一個檔案位置的捷徑）讀過檔案之後，Bash 的編輯差異不會再把沒改動過的符號連結標成已修改。 用 Ctrl+V 從剪貼簿讀取圖片失敗時，現在提示訊息會直接寫出該安裝的套件名稱，提醒你裝 wl-clipboard 或 xclip。

像抄寫員不會把沒動過的捷徑標籤誤記成有修改，貼圖失敗時也會直接報出缺哪個工具。
新功能

讀取 `/stats` 與 `/usage` 紀錄不再卡頓

累積大量對話紀錄後，查看用量與統計資料的速度和流暢度都改善了。 對話紀錄檔包含許多損壞行時，接續工作階段與執行 /stats 不再凍結好幾秒。 /stats 讀取大型工作階段紀錄檔時，包括關閉對話框之後，鍵盤延遲好幾秒的問題已經修好。開啟除錯紀錄時若語言伺服器狂噴標準錯誤輸出，也不再卡鍵。 最近的工作階段很多時，執行 /usage 的尖峰記憶體用量與執行速度也一併獲得改善。

問題修復

模型受限或停用時的備援與切換更順暢

當指定模型被雲端拒絕或不在可用清單裡，現在會自動往下找替代模型，不會直接卡死失敗。 --fallback-model 若填了像 sonnet 這類系列名稱，就算 availableModels 只允許舊版，也不會再被直接捨棄。 availableModels 清單未強制執行時，若雲端拒絕預設模型、且清單裡沒列出它或同系列舊版，工作階段也不會直接失敗。 用 --model default 或選 Default 時，若該模型無法使用，會自動改用較舊的模型而不直接報錯。在自動模式下，只會切到自動模式支援的模型。 Bedrock 與 Google Cloud Agent Platform 啟動時的模型升級建議，也不再列出被 availableModels 排除的模型。

問題修復

雲端平台的模型降級與區域選擇修復

透過企業雲端平台或閘道器呼叫模型，不再因為區域或設定檔差異卡死。 在 Google Cloud Agent Platform 與 Foundry 使用強制執行的舊模型清單時，若首選被拒，只要清單照新到舊排列，就會自動降級到同系列的下一個。 在 Bedrock、Agent Platform 與 Foundry 後方的閘道器若用自訂字句拒絕 opus，現在會降級到有回應的舊模型。 在 Bedrock 執行子代理時，若帳號在父代理的區域沒有對應設定檔，會改用該模型自己的設定檔，即使位在跨區域也沒問題。 在 Bedrock Mantle 上，別名 sonnet 不再誤指成 Haiku 4.5，現在代表 Sonnet 5 而非 Sonnet 5.5。未啟用 Sonnet 5 的帳號會收到錯誤，需先啟用。

新功能

Foundry 預設改用 Sonnet 5.5 並退役舊模型

使用 Microsoft Foundry 服務的讀者，這版更新調整了預設模型與降級規則。 Foundry 的預設模型已改為 Sonnet 5.5，請部署 claude-sonnet-5-5，或把 ANTHROPIC_DEFAULT_SONNET_MODEL 設成你已部署的模型。 Claude Sonnet 4、Opus 4 與 Opus 4.1 在 Foundry 上已被列為退役模型。自動降級不會再退到這幾個版本，若釘選使用也會跳出已退役警告。 管理員清單擋掉 sonnet、opus 或 haiku 對應的版本時，Foundry 會改用內建或對應名稱底下允許的最新版本，不會跳出該模型系列。

新功能

Agent Platform 與 Foundry 調整別名與區域

使用雲端平台預設模型別名的用戶，接下來呼叫 sonnet 或 opus 時會對應到更新的模型版本。 Google Cloud Agent Platform 與 Microsoft Foundry 上的 sonnet 別名已改為 Sonnet 5.5。Foundry 的 opus 別名也改為 Opus 5.5，而 Amazon Bedrock 上的 sonnet 則維持在 Sonnet 4.5。 Agent Platform 上的 sonnet 與背景請求現在會讀取 VERTEX_REGION_CLAUDE_5_5_SONNET 環境變數；若只設了 4_5 的變數，則會改走 CLOUD_ML_REGION 或 us-east5。

比方說公車路線編號沒改，但跑這條線的車隊已經換成新車款，只有個別分站還留著舊車型。
新功能

部分雲端平台切到 Sonnet 5 預設開自動模式

在 Bedrock Mantle、Agent Platform 或 Foundry 寫程式，常會從終端機或 VS Code 切換模型。切到 Sonnet 5 或 5.5 時如果沒設定模式，現在會直接以自動模式啟動。 如果想關閉這個自動切換行為，只要在設定檔加上以下設定：

{
  "disableAutoMode": "disable"
}

像開上剛鋪好的高速公路，只要沒先挑駕駛模式，發動時就會預設幫你打開輔助駕駛，想自己踩油門再把開關關掉。
新功能

Claude 閘道器改用 Sonnet 5.5 當次選模型

透過 Claude 應用閘道器連線若因政策沒開放 Opus 4.6，現在預設挑到的候補模型已經升級。 閘道器內建的模型清單裡，Sonnet 5.5 已取代 Sonnet 4.5 成為第二個模型。政策不允許使用 Opus 4.6 時，Claude 桌面版現在會直接以 Sonnet 5.5 啟動。

如同飯店原本安排的標準房型滿房時，櫃檯端出的第二順位房型已換成新整修好的樓層。
新功能

SDK 與無頭指令中途傳入訊息改計為使用者

給串接 SDK 或用 claude -p 開發自動化流程的開發者：在雲端環境或關閉遙測、拿不到功能開關的狀況下，從 Opus 4.8 起，對話中途傳進去的訊息會直接算成使用者本人發的訊息。 如果程式轉送的不是使用者自己打的字，記得替這段轉送文字加上系統合成的標記。

把這想成總機幫忙轉達訊息，現在一律視同客戶本人親口交代；若是機器自動補上的通知，得另外蓋個代發印章。
問題修復

終端機中斷快捷鍵與按鍵解除綁定修復

在終端機想按快捷鍵喊停或清掉設定，卻遇上沒反應或反效果的狀況已經修好。 在提示列按 Ctrl+C 停掉背景代理時，若該代理還有未讀的子代理回報，不會再錯把 Ctrl+C 當成展開新回合，連按兩下也能正常離開。 在大型或速度較慢的 Git 儲存庫等待檔案差異比對時，按 Esc 現在能立刻停掉 Bash 指令，不會卡住下一則訊息。 在 keybindings.json 解除組合鍵綁定時，就算綁定寫 alt 而解除寫 meta（或反過來寫），第一個按鍵也不會再傻傻等第二鍵。

問題修復

修正 `/install-github-app` 返回誤勾選項

執行 /install-github-app 設定 GitHub 整合時，過去只要按 Esc 退回上一步，畫面上原本選過的工作流程又會被重新打勾。這個問題已經修好，現在按 Esc 返回不會再自動重複勾選。

新功能

終端機點按語音聽寫延長時限並新增停止原因

習慣用語音口述長段需求的話，這版拉長了終端機點按模式的錄音待機時間，也不再丟失長文。 過去口述超過 10,000 字元後文字會遺失的問題已經修好。 待機門檻從原本的 15 秒沒新詞或最長 2 分鐘，拉長成 60 秒沒新詞或最長 10 分鐘。時間到時已辨識的文字會保留在輸入框不送出，下次再點一下就能接著往下講。 送出提示詞時麥克風會自動停止；若是你動手編輯文字、被面板遮住、斷線或獨立錄音程式中斷，它也會停下來並說明原因。

想像請速記員等你邊想邊唸，以前停頓一會兒他就闔上本子，現在能多等你一陣子，真的收不到音也會提醒你。
新功能

API 回應異常與額度誤報的錯誤顯示更清楚

If you type and send a message while a command is running and press Esc before Claude replies, the message is no longer lost—it starts a new turn, and pressing Esc a second time stops it. Fixed an issue where Code Mode sometimes kept waiting for minutes on a command that had already been stopped. Inline shell commands inside a typed slash command no longer get skipped after a background script's output arrives. Resuming a paused workflow no longer waits for minutes while other background work is running.

FEATURE

Code Mode Background Script Timeouts, Subagents, and Resume Notices

Code Mode background scripts and claude -p sessions now handle resumption and timeout limits more clearly. Claude is now explicitly notified when a slow command moves to the background and leaves its script with empty output, as well as of the time limit on background commands in claude -p and the Agent SDK. Subagents in Code Mode no longer fail with "Agent stalled" and lose their command when a script runs for more than 10 minutes. In Agent SDK and claude -p sessions, resuming after stopping while a script was running no longer drops Claude's last reply. When resuming a Code Mode session, Claude is now told up front that its earlier script variables are gone.

BUGFIX

Grep Search Accuracy Fixes and Faster Windows Glob

Edge-case misreads in Grep searches are fixed, and Glob searches on Windows now run faster. The Grep tool's -o flag no longer misses an empty match at the end of a file without a trailing newline. Using multiline mode on non-UTF-8 files no longer adds blank lines or misnumbers lines, and -A and -B now work properly alongside a -C value of 0. On Windows machines with 6 or more CPUs, Glob walks large local folders in parallel for speed, and if stopped by a time limit, it still lists what it has found.

Just as checking a file no longer misses the corners of the last page, searching a large warehouse now sends multiple teams to rummage in parallel and hand over the list of what they found when time runs out.
BUGFIX

Mod Turn Interruption Display and Prompt Hint Adjustments

For those building or using mods: this release adjusts two details of how mods interact with the terminal. When interrupting a turn while a mod's step execution hook is waiting, the screen no longer displays "user-cancel" as an error and instead shows "Interrupted" normally. When the status line at the bottom of fullscreen mode already has a label on its right, the prompt content passed to a mod now omits the hint for selected text.

BUGFIX

Fixed Web Search Errors from Empty or Duplicate Domain Lists

When letting Claude search the web, you no longer have to worry about a minor rule oversight stalling the whole run. Previously, if the allowed or blocked domain list was empty or contained duplicate URLs, starting a web search would immediately throw an API error; that issue is now fixed.

FEATURE

Improved Startup Stability on Windows Company PCs

Silent crashes shortly after launching Claude Code on some company-issued Windows PCs have been improved. Previously, in these environments it could exit shortly after starting without printing any message; this release improves startup stability.

FEATURE

Shorter Fullscreen `/context` Output and Unit Labels

When checking usage stats in a shorter terminal window, you no longer have to keep scrolling up and down to find the total. Running /context in fullscreen now produces shorter output so the total is less likely to scroll off-screen, and the legend names its unit only once.

FEATURE

Refuse Invalid Rules in `/permissions` and Show the Reason

Entering a rule in /permissions that would be skipped on the next startup is now blocked on the spot with an explanation. For example, an invalid rule like rm -rf without a tool name used to be silently skipped on the next restart after being saved, but the interface now refuses it and shows the reason.

PERF

Lower Memory Use for Long Resumes and Multi-Tool Startups

Whether opening long conversations or connecting lots of MCP tools, this release saves more memory in the background. Resuming a very long conversation history now consumes less memory than before. Memory usage at startup is also lower when connecting to MCP servers that list many tools. Initial memory usage at the start of a conversation in claude -p or SDK-hosted sessions has been improved as well.

FEATURE

Desktop App Skips Certain Custom Settings When Using a Gateway

When the Code tab in Claude Desktop connects to the Anthropic API with a gateway address configured, it skips two types of local settings. In your custom settings, model IDs for default, side-request, alias, and subagent use are skipped directly if they do not start with claude. Bringing your own stationery into an exam hall works the same way: when the hall requires standard gear, any ruler that does not fit the approved size gets left at the door.

Crossing guards face a similar call with an unfamiliar pass—previously they kept everyone on the sidewalk, whereas now they turn back to ask whether you want to let it through.

When opening /feedback drafts in the terminal, the cursor now starts on "Not now", above separate rows to send the report alone or with the transcript.
