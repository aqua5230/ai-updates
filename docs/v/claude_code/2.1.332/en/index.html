Claude Code 2.1.332

Released: 2026-11-25

Release notes

FEATURE

Slash Menu Adds MCP Server Skills (Beta)

To use built-in commands from external services directly, you no longer need to copy and paste them by hand. Skills from MCP (Model Context Protocol, a protocol for connecting AI to external tools) servers are now in beta and appear right in the / menu. These skills appear in the / menu as server:skill so you can tell at a glance which server each one comes from. Other skills you created yourself keep their original names without being renamed.

Like spice jars in a kitchen where each brand gets an origin label, the house-made sauces already on the shelf keep their original names so you can tell them apart at a glance.
FEATURE

Block Inline Commands Before Loading Skills via Hook

When attaching external skills or custom commands to Claude, the biggest worry is having their terminal commands run automatically as soon as they load. A new PreSkillShellCommand hook (a small program triggered by specific events) event can now refuse inline shell commands right as a skill or command loads. If you also use version 2.1.331 or older, a settings file that names this event will open a reminder dialog at startup.

Picture an event venue inspecting toolboxes before outside contractors set up their booths, turning non-compliant gear away at the door before it can power on.
FEATURE

Cross-Session Messages Support Always Deliver and Model Reminders

When running tasks across multiple open sessions at once, it is now easier to manage message delivery and model switches between windows. When prompted about held messages from another session, the options now include "Always deliver", which lets the message through right away. If a flagged message leaves your current session on a different model, a reminder line stays at the bottom of the terminal until you pick a model with /model.

Think of setting a frequent extension to transfer without confirmation, while keeping a sticky note on your desk whenever the call is still on the wrong line to remind you to switch.
FEATURE

OpenTelemetry Telemetry Adjustments for Admins

For admins and developers using OpenTelemetry tracking, this release adjusts four reporting behaviors. When response logging is on, text Claude sends through the general message tool or Cowork's message tool now records an extra response event. When response logging (OTEL_LOG_ASSISTANT_RESPONSES=1) is off, tool input logs record only the text length instead of the full text. The default service name for desktop Code tab sessions is now claude-code-desktop. Update any filters keyed on claude-code, or set OTEL_SERVICE_NAME to keep the old name. Built-in MCP servers that are not enabled for your account no longer falsely report a connection failure event at startup.

FEATURE

VS Code and Desktop Add Session Save Reminders

When running long coding conversations in your editor or picking up yesterday's progress, the last thing you want is unsaved content slipping past unnoticed. In VS Code and Desktop's Code tab, when part of a session cannot be saved, a warning appears explaining how to preserve it with /compact. When resuming an older session, if earlier messages were not loaded, the interface now shows a notice just like the terminal version so you know what to expect.

A notebook whose binding loosens on the final pages gets a similar save reminder from the editor, plus a bookmark tucked into the front whenever earlier pages are missing.
FEATURE

Startup Header Shows Cyber Verification Program Tier

Accounts enrolled in the Cyber Verification Program can now confirm their tier status as soon as they open the app. When you are signed in with a claude.ai account and your tier applies to the currently selected model, your verification tier appears right beside the model name at the top of the startup screen.

At an exhibition, it works like printing your zone access level right beside your name on your badge so anyone at the entrance can verify your eligibility at a glance.
BUGFIX

Fix Login Falsely Reporting Success When Saving Fails

Previously, running claude auth login to sign in to claude.ai still printed Login successful. even when the login data could not be saved. That is now fixed: a save failure exits with code 1 and lists what to check, such as a leftover lock file or a full disk.

BUGFIX

File Reads and @ Mentions No Longer Freeze or Silently Drop Content

Reading files or bringing in data with @ is less likely to freeze or silently drop content. When reading, @-mentioning, or compacting hits a named pipe that nothing writes to (such as a .env mounted by a locked secrets manager), it no longer hangs indefinitely and now fails after 20 seconds. Prompts or piped input containing an @ followed by a very long unbroken string (such as minified CSS with an embedded font) no longer freeze either. When an @-mentioned text file with an extension exceeds the read limit even in its first 2,000 lines, it is no longer silently skipped; Claude is now told the file size and how to read it.

FEATURE

More Reliable Recovery for Compaction Failures and Proxy Size Limits

Long conversations can now keep going even when they hit a compaction stall or a proxy server size limit. When auto-compaction fails repeatedly, if one more compaction before the conversation length limit can keep the conversation going, the turn no longer stalls with "Prompt is too long". When a compaction summary keeps exceeding the output limit, after three cut-off replies, the final attempt now explicitly asks for a shorter summary. Idle auto-compaction is no longer skipped for subscribers who still have plenty of room under their weekly limit. Recovery is also improved when sending a long conversation through a proxy or gateway with a request size limit causes every message and /compact to fail with a 413 error.

BUGFIX

Hook Freezes, Oversized Log Truncation, and Prompt Reasons

This release clears up several freezes and log overflow issues that occur when hooks are attached. Checking a permission rule or hook condition with multiple wildcards against a long command no longer freezes. Freezes and runaway memory use caused by a hook printing output nonstop no longer hang or exhaust memory in most cases. During a conversation turn or after /compact, if a hook blocks an action or fails with a massive log, it no longer causes a freeze or context overflow; text over about 50,000 characters is now automatically shortened. On terminal prompts for Read, Grep, Glob, Edit, or Write, a PreToolUse hook's reason for asking for confirmation now displays properly.

BUGFIX

MCP Server Reconnect, Command, and Freeze Fixes

Issues with external MCP servers flooding output, disconnecting, or misjudging commands have been improved. When a local MCP server floods its standard output, the terminal no longer freezes or ignores Ctrl+C. MCP servers using SSE streaming no longer hang or refuse all tool calls if their event stream cuts off and returns on a new endpoint or fails to recover. After a Remote Control session restarts, local MCP servers no longer see a new session ID. The task ID limit returned by MCP servers has been raised from 128 to 1,024 characters, eliminating the "malformed task handle" error. Running /mcp reconnect all and /mcp disable all no longer counts built-in servers that aren't enabled for your account.

BUGFIX

Fix Long Freeze When Opening Rewind Points After Rewriting Large Files

After a large tracked file was completely rewritten, trying to open a previous rewind point to view its history used to make the terminal freeze for a long time without responding. That issue is now fixed, so opening a rewind point after rewriting a large file no longer causes a long freeze.

BUGFIX

More Accurate Remote Control Session and Usage Status Reporting

When viewing Remote Control sessions from the desktop app, VS Code, or the Agent SDK, status indicators now match reality. Sessions no longer falsely show as running when they are actually waiting on a dialog or a question from an MCP server. Remote Control, IDE, and SDK clients no longer keep reporting that the usage limit is reached after it has already reset. Sessions hosted by the desktop app or VS Code no longer show as idle while /compact is running.

BUGFIX

More Reliable Session Resumption and Config Saving

Issues with duplicated rules and missing messages when switching environments or resuming after a crash have been resolved. You can use EnterWorktree to move a session into a worktree (a feature that lets you open multiple parallel copies of the same project) under .claude/worktrees. After moving into it, or when resuming work there, CLAUDE.md and rules files are in most cases no longer sent to the model a second time. After a crash or forced kill on third-party providers such as Bedrock, Google Cloud Agent Platform, and Foundry, reopening a conversation no longer drops the last few messages. Moving an empty session to the background no longer fails with "Couldn't load transcript from file". ~/.claude.json is no longer mistakenly reported as corrupted when another session is in the middle of saving it.

BUGFIX

Cloud and Desktop Session Completion Statuses Are No Longer Misread

When background tasks are still running or a permission request was just declined, the progress shown on screen no longer mismatches what is actually happening. When starting a foreground fork's Agent call in headless mode (a run mode without a visual interface or terminal window) or a cloud session, it no longer reports as finished the moment the fork starts. When you decline a permission prompt in a restarted claude.ai chat, the summary line no longer counts tool calls that never ran as completed. In Claude Desktop, a session's "needs input" status no longer disappears inexplicably after receiving a background task's report.

FEATURE

Linux Symlink Diff and Clipboard Package Prompt Fixes

Linux users get two practical fixes for file diffs and pasting images from the clipboard. After reading a file through a symlink (a shortcut pointing to another file location), the Bash edit diff no longer marks an unchanged symbolic link as modified. When reading an image from the clipboard with Ctrl+V fails, the prompt message now names the package to install, reminding you to install wl-clipboard or xclip.

A scribe won't mark an untouched shortcut label as edited, and when pasting an image fails, they'll call out the exact missing tool.
FEATURE

Reading `/stats` and `/usage` Records No Longer Lags

Speed and smoothness when checking usage and statistics after accumulating many conversation records have been improved. Resuming a session and running /stats no longer freezes for several seconds when a transcript file contains many damaged lines. The issue where keys lagged for several seconds while /stats read large session transcripts, including after closing the dialog, has been fixed. Keys also no longer lag when debug logging is on while a language server floods its standard error output. Peak memory usage and execution speed when running /usage on machines with many recent sessions have also been improved.

BUGFIX

Smoother Fallbacks and Switching When Models Are Restricted or Unavailable

When a specified model is refused by the cloud or isn't on the available list, it now automatically steps down to a substitute model instead of failing outright. If --fallback-model is given a family name like sonnet, it is no longer dropped even when availableModels only allows an older version. When the availableModels list is not enforced, a session no longer fails outright if the cloud refuses the default model and the list names neither it nor an older version in the same family. When using --model default or picking Default, if that model is unavailable, it automatically switches to an older model instead of stopping with an error. In auto mode, it only switches to a model that auto mode supports. The start-up model upgrade offer on Bedrock and Google Cloud Agent Platform also no longer names models excluded by availableModels.

BUGFIX

Model Step-Down and Region Selection Fixes on Cloud Platforms

Calling models through enterprise cloud platforms or gateways no longer gets stuck due to region or profile differences. When using an enforced list of older models on Google Cloud Agent Platform and Foundry, if the first choice is refused, it automatically steps down to the next one in the same family as long as the list is ordered newest first. Behind a gateway on Bedrock, Agent Platform, and Foundry, if the gateway refuses opus in its own words, it now steps down to an older model that answers. When running subagents on Bedrock, if your account has no matching profile in the parent agent's region, it uses the model's own profile instead, even across regions. On Bedrock Mantle, the sonnet alias no longer resolves to Haiku 4.5 and now represents Sonnet 5 rather than Sonnet 5.5. Accounts without Sonnet 5 enabled will get an error and need to enable it first.

FEATURE

Foundry Switches Default to Sonnet 5.5 and Retires Older Models

For readers using Microsoft Foundry, this update adjusts the default model and step-down rules. Foundry's default model has changed to Sonnet 5.5; deploy claude-sonnet-5-5 or set ANTHROPIC_DEFAULT_SONNET_MODEL to a model you have deployed. Claude Sonnet 4, Opus 4, and Opus 4.1 are now marked as retired on Foundry. Automatic step-downs no longer fall back to these versions, and pinning one shows a retired warning. When an admin's list blocks the version sonnet, opus, or haiku points to, Foundry uses the newest allowed version under a built-in or mapped name without leaving that model family.

FEATURE

Updated model aliases and regions on Agent Platform and Foundry

If you use default cloud platform model aliases, calling sonnet or opus now points to newer model versions. The sonnet alias on Google Cloud Agent Platform and Microsoft Foundry now points to Sonnet 5.5. Foundry's opus alias also switches to Opus 5.5, while sonnet on Amazon Bedrock stays on Sonnet 4.5. On Agent Platform, sonnet and background requests now read the VERTEX_REGION_CLAUDE_5_5_SONNET environment variable; if only the 4_5 variable is set, they fall back to CLOUD_ML_REGION or us-east5.

A bus route keeps its number, while the fleet running it switches to newer buses and individual stops still keep the old model.
FEATURE

Some cloud platforms default to auto mode on Sonnet 5

When coding on Bedrock Mantle, Agent Platform, or Foundry, you often switch models from the terminal or VS Code. If no mode is set when switching to Sonnet 5 or 5.5, sessions now start in auto mode. To turn off this automatic switch, add the following setting to your configuration file:

{
  "disableAutoMode": "disable"
}

Imagine pulling onto a newly paved highway: unless you pick a driving mode first, driver assist turns on at startup, and you can flip the switch off when you want to work the pedal yourself.
FEATURE

Claude gateway switches fallback model to Sonnet 5.5

When connecting through the Claude apps gateway without Opus 4.6 allowed by policy, the default fallback model has been upgraded. In the gateway's built-in model list, Sonnet 5.5 replaces Sonnet 4.5 as the second model. When policy does not allow Opus 4.6, Claude Desktop now starts directly on Sonnet 5.5.

Suppose a hotel's standard room is booked out: the second-choice room the front desk offers now comes from a newly renovated floor.
FEATURE

SDK and headless mid-turn messages now count as user input

For developers integrating the SDK or automating with claude -p: in cloud environments or with telemetry off where feature flags cannot be fetched, messages sent mid-turn now count as coming from the user starting with Opus 4.8. If your program relays text that the user did not type themselves, remember to add a synthetic marker to that relayed text.

Consider a switchboard operator passing along a message: it now counts as spoken by the customer directly, while any machine-generated notice needs a separate proxy stamp.
BUGFIX

Terminal interrupt shortcuts and key unbinding fixes

Issues where pressing terminal shortcuts to stop work or clear bindings did nothing or backfired are now fixed. When pressing Ctrl+C at the prompt to stop a background agent that still has an unread subagent report, Ctrl+C no longer starts a new turn by mistake, and pressing it twice exits normally. While waiting for a file diff in large or slow Git repositories, pressing Esc now stops a Bash command immediately without holding up the next message. When unbinding a chord in keybindings.json, even if it was bound as alt and unbound as meta (or the reverse), the first key no longer sits waiting for a second key.

BUGFIX

Fixed `/install-github-app` re-checking options on back

When running /install-github-app to set up GitHub integration, pressing Esc to go back a step used to re-check workflows you had previously selected. This is now fixed, so going back with Esc no longer checks them again automatically.

FEATURE

Extended timeout and stop reasons for terminal tap voice dictation

If you dictate long prompts by voice, this release extends the standby time for terminal tap mode and stops dropping long text. An issue where dictated text beyond 10,000 characters was lost is now fixed. The standby threshold increases from 15 seconds without new words or 2 minutes maximum to 60 seconds without new words or 10 minutes maximum. When time runs out, recognized text stays in the input box unsent so your next tap picks up where you left off. The microphone stops automatically when you send the prompt; it also stops and explains why if you edit the text, a panel covers it, the connection drops, or a separate recorder program is interrupted.

Imagine a stenographer waiting while you think and speak: they used to close their pad after a short pause, but now wait longer and alert you if they truly stop receiving audio.
FEATURE

Clearer error display for broken API responses and false quota alerts

Cryptic raw error dumps mid-conversation and normal replies flashing red by mistake have both been cleaned up. When a non-streaming retry hits a corrupted or interrupted response, the screen no longer prints raw "JSON Parse error" or "The operation was aborted." text. Replies that happen to start with "You've used" or "You've hit your" are no longer misread as red usage limit errors. When a proxy or gateway cuts off or corrupts a compressed response, the turn now ends in plain words instead of printing raw errors like "ZlibError fetching".

FEATURE

macOS computer use updates safety rules and Screen Recording setup

When letting Claude operate your screen on a Mac, this release adjusts the permission setup flow and safety rules. When setting up Screen Recording permission, the permission prompt can now restart Claude Code directly and resume your existing chat without starting over manually. Before Claude actually begins operating the computer, this feature now takes up less conversation context. Stopping anytime with Esc is more reliable: even when the Claude Code window or an app you allowed is in front, an Esc meant for that app's popup now stops computer use directly. The macOS version has updated to newer safety rules, so some actions may be refused and typing may become slower.

FEATURE

Mac version reserves `computer-use` as a skill name

If computer use is turned on for your Mac and you happened to write a skill or slash command with the same name, you will now need to rename it. computer-use is now a reserved skill name. On Macs with computer use enabled, custom skills or commands with that name stop loading, and a start-up notice appears reminding you to rename it.

Once a phone maker reserves "Camera" exclusively for the built-in app, any custom shortcut with the same name needs a new name to avoid a clash.
BUGFIX

Credential and Helper Commands Now Time Out

Calling an external helper command for an API key or AWS credentials no longer stalls your connection. Fixed a rare hang when a helper command, such as an API key helper, ran past its time limit. awsCredentialExport, which exports credentials, now times out after 10 minutes instead of waiting forever.

Sending a courier across the street for a pickup now comes with a ten-minute timer; if they are not back when it rings, you close the order instead of waiting by the door.
BUGFIX

Fullscreen Selection, History Picker, and Image Path Fixes

Several glitches with fullscreen text selection, history search, and pasted image paths in the terminal are now fixed. Selecting text in fullscreen no longer pushes the footer's right-hand label onto a second row, which used to shift the text under the mouse and copy the wrong line. When pressing Ctrl+R in fullscreen to search past prompts, stale or repeated rows no longer appear if multiple entries share a timestamp. Pasted links and relative paths ending in an image filename no longer show up late or swallow an Enter pressed right after.

BUGFIX

Plugin Install, Cache Cleanup, and Reload Prompt Fixes

Managing plugins on your machine is smoother when a download is interrupted or a file is briefly locked. When a downloaded plugin cannot be copied into place, temp_* folders no longer pile up inside ~/.claude/plugins/cache. When hitting a plugin "not cached" error, the message now points to /reload-plugins instead of /plugin. When running claude plugin marketplace add on Windows, it now waits and tries again in some cases if another program, such as an antivirus scanner, briefly holds the downloaded files.

BUGFIX

Effort Level Kept Across Environments and Model Switches

Your preferred response depth now stays with you whether you adjust it on mobile or web, or start a session with flags. --effort is no longer ignored when starting an interactive session with --environment while CLAUDE_CODE_EFFORT_LEVEL is set to the same level. Switching models from the Claude mobile app or claude.ai now keeps the effort level saved for your previous model when none is saved for the new one.

Logging into a new computer works much the same way: your preferred font size and desktop settings carry right over untouched.
BUGFIX

Self-Hosted Runner Git Config Compatibility Fixes

Two snags with Git setup and version checks on self-hosted runners are now resolved. Under Anthropic-managed Git, self-hosted runner sessions no longer fail their first clone when the machine's Git config contains an includeIf "gitdir:" or "onbranch:" section (Git 2.44 to 2.46). When running --configure-git, a hung git --version check is no longer misreported as Git missing from PATH.

FEATURE

Self-Hosted Runner Tokens Add `oat02-` Prefix

If you maintain proxy filtering rules or log scrubbers, take note of a change to CLAUDE_CODE_OAUTH_TOKEN (the access string used to verify identity). Its prefix can now end in oat02- as well as oat01-. If your proxy rules or log scrubbers only match oat01-, update them accordingly and mask the entire value.

Highway toll lanes face the same issue when a new plate prefix rolls out: both the gate scanners and billing masks have to add it so nothing slips through.
FEATURE

Self-Hosted Runner Setup Now Hides Environment Key

Running the initialization flow in a macOS or Linux terminal no longer risks exposing sensitive strings to anyone nearby. When running claude self-hosted-runner setup with no arguments, it now asks for the environment key in the terminal before Claude starts and hides what you paste.

Typing a PIN at an ATM works the same way, showing only asterisks on screen so passersby cannot peek at the real string.
BUGFIX

Fix NotebookEdit Corrupting Cells on Type Change

Editing cell blocks in a notebook previously could save an invalid file. This is now fixed: when NotebookEdit changes a cell's type, turning a cell with attachments into a code cell is refused.

BUGFIX

Fix Long Design System READMEs Losing File Lists

After moving a design system from standalone Claude Design, a long README previously lost its list of files to load when Claude started a deck or design. This is now fixed so the file list in long READMEs stays intact.

BUGFIX

Fix Reused IDs and Revived Tasks on Bulk Edits

Deleting or updating several tasks at once previously caused task IDs to be reused, deleted tasks to come back, and the TaskGet tool to list completed tasks as blockers. These issues are now fixed.

FEATURE

Code Mode Tool Search, Input Guards, and File Confirmation

Calling tools and handling output files in Code Mode now include input checks and modification confirmations. Tool inputs containing a list of over 4,096 items are no longer silently skipped. Very large typed arrays in tool inputs no longer cause freezes and now result in the call being refused directly. Because a cut-off description can lead to misuse, tool search now displays longer MCP tool descriptions in full whenever space allows. Claude now confirms before discarding worktree changes, reads artifact files before publishing them, and updates an existing artifact instead of creating a second one.

BUGFIX

Code Mode Command Interruption, Waiting, and Workflow Resume Fixes

Running commands or pausing workflows in Code Mode no longer stalls for several minutes for no reason. If you type and send a message while a command is running and press Esc before Claude replies, the message is no longer lost—it starts a new turn, and pressing Esc a second time stops it. Fixed an issue where Code Mode sometimes kept waiting for minutes on a command that had already been stopped. Inline shell commands inside a typed slash command no longer get skipped after a background script's output arrives. Resuming a paused workflow no longer waits for minutes while other background work is running.

FEATURE

Code Mode Background Script Timeouts, Subagents, and Resume Notices

Code Mode background scripts and claude -p sessions now handle resumption and timeout limits more clearly. Claude is now explicitly notified when a slow command moves to the background and leaves its script with empty output, as well as of the time limit on background commands in claude -p and the Agent SDK. Subagents in Code Mode no longer fail with "Agent stalled" and lose their command when a script runs for more than 10 minutes. In Agent SDK and claude -p sessions, resuming after stopping while a script was running no longer drops Claude's last reply. When resuming a Code Mode session, Claude is now told up front that its earlier script variables are gone.

BUGFIX

Grep Search Accuracy Fixes and Faster Windows Glob

Edge-case misreads in Grep searches are fixed, and Glob searches on Windows now run faster. The Grep tool's -o flag no longer misses an empty match at the end of a file without a trailing newline. Using multiline mode on non-UTF-8 files no longer adds blank lines or misnumbers lines, and -A and -B now work properly alongside a -C value of 0. On Windows machines with 6 or more CPUs, Glob walks large local folders in parallel for speed, and if stopped by a time limit, it still lists what it has found.

Just as checking a file no longer misses the corners of the last page, searching a large warehouse now sends multiple teams to rummage in parallel and hand over the list of what they found when time runs out.
BUGFIX

Mod Turn Interruption Display and Prompt Hint Adjustments

For those building or using mods: this release adjusts two details of how mods interact with the terminal. When interrupting a turn while a mod's step execution hook is waiting, the screen no longer displays "user-cancel" as an error and instead shows "Interrupted" normally. When the status line at the bottom of fullscreen mode already has a label on its right, the prompt content passed to a mod now omits the hint for selected text.

BUGFIX

Fixed Web Search Errors from Empty or Duplicate Domain Lists

When letting Claude search the web, you no longer have to worry about a minor rule oversight stalling the whole run. Previously, if the allowed or blocked domain list was empty or contained duplicate URLs, starting a web search would immediately throw an API error; that issue is now fixed.

FEATURE

Improved Startup Stability on Windows Company PCs

Silent crashes shortly after launching Claude Code on some company-issued Windows PCs have been improved. Previously, in these environments it could exit shortly after starting without printing any message; this release improves startup stability.

FEATURE

Shorter Fullscreen `/context` Output and Unit Labels

When checking usage stats in a shorter terminal window, you no longer have to keep scrolling up and down to find the total. Running /context in fullscreen now produces shorter output so the total is less likely to scroll off-screen, and the legend names its unit only once.

FEATURE

Refuse Invalid Rules in `/permissions` and Show the Reason

Entering a rule in /permissions that would be skipped on the next startup is now blocked on the spot with an explanation. For example, an invalid rule like rm -rf without a tool name used to be silently skipped on the next restart after being saved, but the interface now refuses it and shows the reason.

PERF

Lower Memory Use for Long Resumes and Multi-Tool Startups

Whether opening long conversations or connecting lots of MCP tools, this release saves more memory in the background. Resuming a very long conversation history now consumes less memory than before. Memory usage at startup is also lower when connecting to MCP servers that list many tools. Initial memory usage at the start of a conversation in claude -p or SDK-hosted sessions has been improved as well.

FEATURE

Desktop App Skips Certain Custom Settings When Using a Gateway

When the Code tab in Claude Desktop connects to the Anthropic API with a gateway address configured, it skips two types of local settings. In your custom settings, model IDs for default, side-request, alias, and subagent use are skipped directly if they do not start with claude. If CLAUDE_CODE_AUTO_COMPACT_WINDOW in your settings is set below 200K alongside a gateway address, it is also ignored; use the /autocompact command to adjust it instead.

Bringing your own stationery into an exam hall works the same way: when the hall requires standard gear, any ruler that does not fit the approved size gets left at the door.
FEATURE

Desktop App and VS Code Plan Mode Now Ask for Approval

Plan mode in the desktop app's Code tab and VS Code no longer blocks every command it cannot evaluate. Previously in plan mode, whenever an automatic safety check could not determine whether a command was safe, it refused the command outright. Now, if you entered plan mode from "Manual" or "Accept edits" mode, it prompts for your approval instead.

Crossing guards face a similar call with an unfamiliar pass—previously they kept everyone on the sidewalk, whereas now they turn back to ask whether you want to let it through.
FEATURE

Destructive Prompts and Feedback Default to Safer Choices

Accidentally deleting or submitting data from tapping too fast is frustrating, so the default focus on two confirmation screens is now more conservative. On destructive questions that clear data, such as running /clear from an agent's view, pressing PgUp or Home now jumps to "No". When opening /feedback drafts in the terminal, the cursor now starts on "Not now", above separate rows to send the report alone or with the transcript.

Important forms use that same safeguard by resting the cursor on cancel or defer first, so a slip of the finger will not wipe or submit your data right away.
FEATURE

Cloud Schedules Renamed to "cloud scheduled task"

The labels shown when opening /schedule, permission prompts, or the cloud option in /loop have been unified. Text that previously said "routine" or "cloud schedule" now consistently reads "cloud scheduled task". If you are used to typing /routines to pull up the list, the existing /routines command still works.

An office building renaming different floor-by-floor booking slips under one shared title works much like this, while the old shortcut signposts still get you there.
BUGFIX

[VSCode] Diff Notifications and Line-Copying Fixes

Notifications and text selection are now more accurate when viewing and copying Claude's proposed code diffs in VS Code. Closing an unapplied proposed diff tab now notifies you about unapplied edits in more cases, while a split copy of an already answered diff no longer triggers duplicate notifications. Using "Copy deleted line" and "Copy changed line" in the diff view no longer copies a different line, and double-clicking near the bottom no longer copies unasked.

Proofreading a manuscript follows the same rule: reminders only pop up for unconfirmed edits, and pointing to a line copies that exact line instead of grabbing the wrong one or triggering by accident.
BUGFIX

[VSCode] `/rewind` Restoration and Compacted History Fixes

Rewinding progress in the editor sidebar or continuing a compacted long conversation no longer gets stuck spinning or shows fake prompt entries. Restoring a conversation with /rewind in the sidebar now shows a warning if it would stop a self-paced /loop. When Claude's process hangs at startup, the Rewind view no longer stays stuck spinning on "Checking code changes…". After reloading, resuming, or forking a compacted conversation, the compaction summary no longer appears as your own prompt or shows up in Rewind and prompt history.

FEATURE

[VSCode] Manage Plugins List Shows Installed Versions

Checking which version of an extension you have installed no longer requires clicking into each one. Opening "Manage plugins" in VS Code now shows the current version number directly next to each row.

BUGFIX

[VSCode] `/model` Picker Navigation and Screen Reader Fixes

VS Code's /model picker now behaves properly for keyboard navigation, Tab completion, and screen readers. Right after opening the model picker, the up and down arrow keys no longer start from the wrong row, and screen readers now announce the highlighted model when opened via /model or the command menu. Completing /model with Tab no longer accidentally switches the model, and the model picker no longer closes right away when nothing is running.

BUGFIX

[VSCode] Chat Panel Display, High Contrast, and Tool Count Fixes

Clicking to expand thinking steps, viewing long URLs, or using High Contrast mode in the chat sidebar now behaves cleanly. Clicking a "Thinking" row no longer makes the view jump away, and opening a menu over certain banners no longer shifts the chat. The blocked microphone tooltip is no longer cut off, long URLs in Web Fetch no longer overflow their rows, and usage bars no longer look full in High Contrast mode. In long sessions, an agent's tool call count no longer shrinks; it now shows how many calls are listed.

BUGFIX

[VSCode] Sign-In, Logout Status, and Error Display Fixes

Feedback in the editor is now much clearer when switching accounts or when authentication fails. Triggering a second logout in the same window while the first is still running no longer falsely reports success, and the error screen when logout fails now includes a "Show logs" button. A sign-in failure without an error message no longer returns silently to the sign-in screen, and old authentication errors no longer stay on screen after you sign in again in that tab.

BUGFIX

[VSCode] Background Completion Notices and Hidden Panel Alerts Fixed

When you minimize the window to the side while waiting for a job to finish, you no longer have to worry about missing key messages. When Claude is idle, the chat now reliably pops up a completion notice after a background command, agent, workflow, or monitor finishes. A hidden panel's notice now names which session is waiting for you, a question cut off when Claude's process ends no longer leaves only a red dot, and the display order of Hebrew and Arabic questions has been fixed.

BUGFIX

[VSCode] Conversation Read/Write, Renaming, and Queue Order Fixed

Session renaming, saving on NTFS drives, and post-reopen message order in VS Code are all fixed. In VS Code 1.101 and 1.102 on Windows 11 24H2 and later, forking a conversation, opening and saving memories, or creating project output styles on NTFS drives no longer fails. A session rename that cannot be saved no longer reverts silently, and screen readers can now read out a session's status, which session is open, and which groups are collapsed. After reopening a conversation, queued messages waiting to be sent and attached files no longer appear in reverse order.

BUGFIX

[VSCode] Web Fetch Status Dot and Error Message Display Fixed

The Web Fetch status dot and thinking block error display in VS Code conversation history have been fixed. When Web Fetch gets an error from a site or hits a redirect that wasn't followed, it no longer lights up a success dot next to "Fetched from". When a question ends in an error and its stored result has no text, it no longer always shows a generic "Something went wrong". Redacted thinking blocks now display normally instead of showing as "Unsupported content type".

BUGFIX

[VSCode] Fix Ignoring `spinnerVerbs` Setting

Changing the spinnerVerbs loading prompt verbs in your settings file used to be completely ignored by VS Code. As long as they come from Claude Code user or managed settings, they now apply properly in VS Code.

BUGFIX

[VSCode] Fix Mod Layout Width and Right-to-Left Punctuation

Layout glitches when extension mods display right-to-left text and draw block borders in VS Code are fixed. Previously, punctuation landed on the wrong side when a mod output right-to-left text, and a mod's band or pane filled only part of its width when the panel font lacked box-drawing characters; both issues are now fixed.

FEATURE

[VSCode] Tab Closing, File Links, and Plain-Text Wrapping Improved

Closing conversation views, clicking path links, and viewing single-line output in the editor are now much smoother. After closing the last Claude tab, an empty, locked editor pane no longer stays beside it. Most links pointing to files without an extension, to folders, or with a line and column number now jump properly when clicked instead of doing nothing. Commands and one-line output opened in a plain text tab now wrap automatically.

BUGFIX

[VSCode] IME Underline and Up/Down Draft Recall Fixed

Composing with an input method or browsing old drafts with the Up and Down keys in the VS Code message box no longer gets tangled up. When composing text with an input method, the composing word in the input box now shows its underline properly. Holding the Up key to recall an earlier prompt no longer overwrites an unsent draft directly, and pressing Down after adding a new line to or clearing the recalled prompt properly switches back to the original message.

PERF

[VSCode] Faster Panel Opening, Long Sessions, and Large Workspaces

Opening the Claude panel in VS Code, loading long sessions, and streaming replies in real time are all faster. Reading diagnostics is also faster when a very large workspace is open.

FEATURE

[VSCode] Longer Voice Dictation Timeout and Stop Reason

When dictating notes as you think and pausing for a few seconds, you no longer have to keep reopening the microphone. The auto-stop idle limit has been extended from 15 seconds without recognized speech or 2 minutes max to 60 seconds or 10 minutes max, so the microphone can stay on longer. When the microphone stops sending audio or the panel stays hidden, voice dictation now stops automatically and shows why.

Keeping a speakerphone open to take notes, you are less likely to get hung up on the moment things go quiet, and when no sound comes through at all, it chimes to let you know.
