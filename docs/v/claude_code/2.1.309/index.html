Claude Code 2.1.309

發布日期：2026-10-22

繁體中文

新功能

ultrareview 嚴格檢查工作區信任，未獲授權立即中斷

當你在終端機使用 claude ultrareview 進行進階程式碼審查時，工具現在會主動確認目前工作區是否值得信任。在一般終端機下它會跳出確認提問，若沒有互動終端或在自動化環境則會直接拒絕執行。在自動化腳本中，你必須加入不帶參數的 --trust-workspace 旗標（需放在 PR 編號或基準分支後面）。或者設定環境變數（執行時讀取的設定值）CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1。

好比大樓警衛室只讓登記過的訪客上樓，以前審查員可能直接走進私人辦公室，現在必須先刷卡確認訪客名單，未登記者一律在門外擋下。

當你在持續整合伺服器上排程跑深度審查，卻發現指令中斷時，可按上述位置補上信任旗標，通過工作區信任檢查。

新功能

/claude-api 技能換裝多代理人架構，預設啟用動態工作流程

當你透過 /claude-api 技能規劃雲端代理人團隊時，背後生成團隊的底層範本已經升級。以往工具會採用舊有的協調員架構（coordinator）。現在改以 multiagent_20261001 架構建立 Managed Agents（由平台託管的代理人）子團隊，並預設開啟動態工作流程。

宛如專案工作室調整團隊編制，以前沿用舊的組織方式，現在改用新的團隊組織方式。

當你需要為多步驟任務設計多個助理分工時，直接呼叫 /claude-api，產出的代理人團隊就會採用這套架構，動態工作流程也已預設開啟。

新功能

sed -i 採用標準指令確認，修改內容不再交由 /rewind 復原

在對話中要求 Claude 直接批次替換檔案文字時，sed -i 指令的執行與確認流程有了調整。以前這類就地修改指令會跳出模擬的檔案編輯預覽，現在它改為顯示標準的 Bash 執行提示，並依照輸入的原文直接運行。與其他透過 Bash 進行的修改一樣，執行過後的檔案變更不會再被 /rewind 指令復原。

跟在便條紙上動筆塗改一樣，以前動筆前會先在旁邊墊一張描圖紙給你看預覽，現在直接按指令在紙上落筆。

如果你打算在大量程式碼中批次取代變數名稱，執行前請確認修改內容，因為 /rewind 不會復原這類修改。

問題修復

補強沙盒隔離防線，嚴格限制設定檔與捷徑路徑寫入

當你在 macOS 與 Linux 上啟用沙盒執行指令時，多項環境隔離與檔案寫入的防護邊界獲得了修正。沙盒內的 Bash 指令以前會在執行前於沙盒外載入 Shell 啟動檔，現在不會在隔離環境外偷跑。當目錄透過符號連結（指向真實位置的捷徑檔）連接時，macOS 的 denyWrite 規則現在會確實比對目標的真實位置，設定檔儲存庫的防寫限制也不會被捷徑繞過。沙盒指令與自動核准的修改不再能更動由 --mcp-config 指定的 MCP（讓 AI 連接外部工具的協定）設定檔。在 Linux 環境中，背景指令即使存活超過原本的工作階段，沙盒禁止寫入的防線也不再提早解除。若沙盒處於啟用但無法運作的狀態，排除於沙盒外的指令在寫入允許清單的路徑前會主動跳出確認，並直接拒絕未隔離的備援操作。

問題修復

終端機強化指令審核，嚴防重導向與目錄切換繞過授權

當 Claude 在終端機執行複合指令或刪除檔案時，幾處曾會漏掉權限提示或錯誤信任狀態的盲點已全數修復。Bash 權限檢查以前會盲目信任由指令設定的變數，即使該指令的輸出重導向根本無法開啟；現在不會再誤判為成功。當指令在執行 git 前先變更目錄，若 cd 被包裝或帶有前綴，Bash 檢查現在會像一般 cd 一樣確實跳出確認提示。當複合指令包含子 Shell 時，Edit(path) 阻擋規則現在能確實攔截指向該路徑的重導向寫入。在 Windows 上，若 Set-Location 或 cd 目標為當前目錄但帶有額外參數，PowerShell 權限檢查不再自動放行，而是會跳出核准詢問。桌面應用程式與 VS Code 在略過權限模式下若遇到危險的 rm 與 rmdir 指令，現在會直接拒絕並附上改寫建議，避免無人值守的工作階段卡在確認畫面。

新功能

收緊工作樹隔離防護，Git 操作提速並預先載入物件

當你啟用隔離環境讓多個對話平行處理不同任務時，版本控制與工作目錄的邊界防護有了重要改善。工作樹（Git 讓同一專案平行開多份副本的功能）隔離的工作階段中，先前部分帶有語系前綴、原本應被隔離守衛拒絕的指令會被放行，現在已修正；zsh 下原本會漏網的算術運算指令也會被阻擋。由 Claude Code 建立的工作樹與分支簽出，現在會像其他 Git 操作一樣主動忽略替換參照（replace refs）。Windows 上多項內部 Git 指令變快；在所有平台上，這些指令的錯誤訊息都改以英文顯示，不受 Git 語言設定影響。在一般複製品或設定了 Bash 沙盒的部分複製品中，建立與重複使用工作樹時不再隨選抓取物件；這類部分複製品會先抓取物件，再建立或重複使用工作樹。

新功能

/claude-api 擴充雲端追蹤支援，查核即時文件並開放授權令牌

當你請 /claude-api 技能協助配置雲端服務與鏈路追蹤時，多項說明準確度與追蹤設定已獲得改善。技能說明不再誤稱 ant beta:worker poll --on-work 會傳遞追蹤上下文。修正 C# 追蹤配置遺漏雲端平台客戶端跨度（spans）的瑕疵。修正原本聲稱 AWS 上的 Claude Platform 請求跨度無法加入呼叫端追蹤的錯誤說法。要求加入 OpenTelemetry 時，技能現在會在 SDK 追蹤之外同時主動提供 API 追蹤選項。技能在回覆功能不受支援前，會先連線查核最新即時官方文件。服務帳號金鑰與工作負載身分同盟的授權令牌（用來驗證身分的數位令牌），現在已可用於管理 OpenTelemetry 的輸出目的地。

問題修復

技能命名支援目錄前綴區隔，資料圖表導入新版對比標準

當你在專案中載入多組外掛或自訂技能時，技能重複衝突與檔案讀取例外處理已得到修復。透過 --add-dir 載入的技能若與既有技能同名，以前會無法使用，現在會自動加上前綴顯示為 <folder>:<name>。在終端機 Shell 變更檔案後，/verify 與 /code-review 不再發生找不到巢狀套件自身技能的問題。從 claude.ai 同步的外掛與技能，在遭遇磁碟讀取錯誤時不會再於工作階段中途莫名被整組移除。內建的 dataviz 資料視覺化技能正式支援 APCA 文字對比度演算標準（在需要符合 AA 規範處仍維持 WCAG 2 比例），調色盤驗證腳本新增 apca(text, background) 函式，並能指引圖表著色區塊內的標籤該搭配白色或接近黑色。

問題修復

修正對話送出與檢視快捷鍵，工具預覽文字妥善處理表情符號

當你在終端機快速輸入文字與切換畫面時，快捷鍵的觸發反應與對話紀錄排版獲得了修正。以前在模型回覆開始前按下 ctrl+enter 立即送出，訊息只會進入排隊；若在提示詞掛鉤（特定事件發生時被觸發的小程式）執行期間按下，還會重啟掛鉤並將訊息留在等待佇列，現在已徹底修正。在 ! 開頭的 Shell 模式下，綁定快捷鍵的斜線指令不再錯誤地被丟進系統 Shell 中執行。按下 ctrl+o 時，來自其他代理人與工作階段中等待投遞的訊息，現在會完整標記為等待狀態並顯示在紀錄下方。工具輸出的長預覽文字若剛好截斷在表情符號中間，以往會導致工作階段紀錄損毀而無法被 jq 解析，現在已修正截斷處理。

問題修復

隊友代理人繼承工具限制，自架執行器接軌中斷操作

當你啟動分割視窗的隊友代理人或在自架伺服器上執行任務時，跨代理人設定傳遞與狀態銜接更為一致。分割視窗中的隊友代理人現在會確實繼承隊長在指令列指定的工具禁用規則與 --tools 限制。透過 /rename 重新命名的工作階段，在 VS Code 視窗重新載入或非互動式 --resume 恢復後，不會再以隨機產生的名稱顯示給其他對話。若該回合透過 /code-review --fix、子代理人或 Shell 指令修改了已納入檢查點的檔案，/rewind 清單不再誤顯示「沒有程式碼變更」。在自架執行器環境中，若首個提示詞仍在子代理人中運作，--startup-timeout-min 不會誤殺工作階段，但凍結的行程仍會被停止。當工作階段轉移到新的自架執行器時，Claude 現在能清楚看見被中斷的工具呼叫，並將其標記為結果未知。

問題修復

修復 PowerShell 掛鉤阻擋機制，別名模型自動解析

當你在工作流程中設定自訂掛鉤（特定事件發生時被觸發的小程式）以攔截工具或步驟時，Windows 與模組載入的相容性獲得了提升。在 PowerShell 中運行的掛鉤程式若以代碼 2 結束，以往無法成功阻擋操作，現在已能正確攔截。在未安裝 Git for Windows 的 Windows 環境中，指定使用 PowerShell 的工具前置與權限請求掛鉤也不再因缺少該工具而直接失守放行。自訂模組的 turn.step 掛鉤中若以別名（例如 haiku）指定模型，以前每次請求都會失敗，現在會正確解析出對應模型。當掛鉤模組因巢狀過深而無法載入時，錯誤訊息現在會明確點名出問題的檔案路徑，不再只印出簡略的堆疊溢位提示。

問題修復

大型說明檔避免重複壓縮，成品發布與權限不再頻繁卡關

當對話中包含大量說明文件或正在發布網頁成品時，對話壓縮與成品更新流程不再反覆打擾。讀取受大型巢狀 CLAUDE.md 管轄的檔案後，工作階段以前會陷入反覆壓縮對話的循環；現在若巢狀說明檔超出容量上限，工具只會載入檔案開頭部分。發布或更新成品時，以往部分包含特定縮減程式碼（minified scripts）或未被預先讀取的常見頁面會遭到拒絕，現在已能正常發布。在同一個回合中，若對話曾觸發過內容壓縮，Claude 以前會在後續每次更新成品時不斷重複要求授權，這個問題現在已經修復。

問題修復

桌面工作階段維持連線，遠端狀態列與停用工具不再錯亂

當你透過桌面應用程式或遠端控制操作 Claude Code 時，帳號狀態與背景連線的穩定度得到了改善。在列印模式與 SDK 工作階段中，已經停用的 MCP（讓 AI 連接外部工具的協定）伺服器，以前會在後續跳出權限提示時被意外重新連線，現在已維持關閉。在由 Claude 桌面應用程式託管的工作階段中，網路連線重新整理時對話訊息偶爾遺失的問題已經排除。當同一台電腦上的終端機登入了不同帳號或組織時，桌面應用程式中的工作階段以前會遺失部分功能，現在不會再因此缺少功能。針對非 Git 儲存庫的普通資料夾，claude remote-control 的狀態列（顯示在終端機最底下的狀態列）不再將分支名稱錯誤顯示為 HEAD。

問題修復

隱私設定即時同步，意見回饋與 GitHub 標記精確呈現

當你在終端機檢查隱私設定或向官方回報問題時，回傳的訊息說明與對外發布內容更加清晰。輸入 /privacy-settings 時，以前可能顯示過期的「協助改善我們的 AI 模型」開關狀態；現在會即時呈現最新設定，無法取得設定時也會明確告知。當你所屬的組織未開放意見回饋時，送出 /feedback 不再只顯示含糊的「請稍後再試」，而是會顯示伺服器提供的具體原因並指引回報錯誤的管道。含有大量紀錄的超大 /feedback 報告在傳送失敗時，現在會自動改為排除對話紀錄後重新送出，不再直接報錯中斷。在發布 Pull Request、議題或留言時，Claude 不會再將角色名稱或佔位符寫成 @ 標籤，避免意外通知到無關的 GitHub 使用者。

問題修復

磁碟空間滿載提供清理指引，修復串流逾時與工具安裝彈窗

當底層系統空間不足或身處特定雲端環境時，錯誤提示與連線等待機制變得更為實用。在共用 /proc 的 Linux 沙盒中，讀取工具讀取特定 PDF 頁面範圍不再誤報檔案不存在。在 Amazon Bedrock 將 ANTHROPIC_BEDROCK_BASE_URL 設為預設端點時，細粒度串流不會再被錯誤關閉。透過僅發送保持連線訊號（keepalive pings）的閘道連線時，等待 API 回覆提示不再閃爍，非 Anthropic 後端會等待 45 秒。在未安裝 Xcode，也未安裝 Command Line Tools（命令列開發工具）的 Mac 上，啟動 Claude Code 不再每次跳出安裝視窗。磁碟滿載導致 Bash 指令中斷時，會說明原因並點名應釋放空間的資料夾；暫存空間已滿時啟動也會顯示清楚訊息而非晦澀代碼。

問題修復

VS Code 聊天面板長訊息支援摺疊，快取損壞自動修復

當你在 VS Code 側邊面板中使用 Claude Code 時，幾處版面繪製與快取異常已經獲得排除。當編輯器因快取（把算過或查過的結果暫存起來直接用）了不完整的檔案而導致 Claude 面板一片空白時，擴充套件現在會自行恢復，或明確提示問題原因與手動解決方法。像 /goal 這類過長的斜線指令提示詞，現在會像其他長訊息一樣自動摺疊在展開按鈕後方，即使把聊天面板調窄，長訊息也不會撐破版面。輸入框上方標示來自特定外掛的提示標籤，不再錯誤遮擋斜線指令與 @ 標註的選單。貼上複製的 LaTeX 數學公式時，不再產生多餘的空白清單項目、空白段落或程式碼區塊，編號清單也不會再被強制從 1 重新起算。

問題修復

VS Code 編輯等待時間縮短，憑證警告提示與空紀錄修復

當你在 VS Code 中編修程式碼或發出語音指令時，操作延遲與背景紀錄邏輯獲得了調整。聽寫或套件自身請求的憑證（確認連線對象身分的證明）驗證失敗時，例如經過會檢查加密流量的代理伺服器，日誌現在會提供處理指引。每次開啟新對話卻未發送訊息時，歷史紀錄不再被空工作階段塞滿。若在 ~/.claude/keybindings.json 的 Chat 區段將 "ctrl+j" 設為 null，在聊天輸入框按下 Ctrl+J 不再強制換行，改交由 VS Code 與作業系統處理。當組織不接受意見回饋時，錯誤提示不再只回傳 HTTP 狀態碼，會顯示具體原因。聊天面板中的編輯與寫入速度加快，每次編輯後等待偵測新問題的時間從原本的 1 至 1.5 秒縮短為多數情況下的 0.75 秒。

問題修復

雲端工作階段修正環境變數引號，管理介面與變更清單明朗化

當你在瀏覽器管理雲端工作階段與連線設定時，表單填寫與文件顯示體驗有了改善。在例行表單中新增連接器時，清單在載入期間不再誤報沒有可用的連接器。雲端環境編輯器不再打亂變數順序，當數值同時包含單引號與雙引號時，也不會再多餘地自動補上反斜線。管理設定中的自架環境對話框獲得調整，標題、分頁標籤與按鈕在滾動時會固定在可視範圍，只有中間內容會捲動。雲端工作階段中的閱讀文件工具列不再顯示跳脫後的 JSON 原始碼，而是會呈現易讀的排版內容。變更面板現在會主動標明目前是僅列出已推送的提交，還是僅顯示 Claude 的檔案修改。

新功能

Slack 標註草稿正確轉發頻道，審核按鈕支援重啟對話

FEATURE

ultrareview Enforces Workspace Trust Checks, Halting Immediately Without Authorization

When you run advanced code reviews in the terminal using claude ultrareview, the tool now actively verifies whether the current workspace is trusted. In a standard terminal, it prompts for confirmation, but it directly refuses execution if there is no interactive terminal or inside an automated environment. In automated scripts, you must include the --trust-workspace flag with no arguments (placed after the PR number or base branch). Alternatively, you can set the environment variable (configuration values read at runtime) CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1.

Picture a building security desk that only allows registered visitors upstairs: where reviewers could previously walk straight into private offices, they must now badge in against the visitor log, and anyone unlisted is stopped at the door.

When a scheduled in-depth review on a continuous integration server stops unexpectedly, add the trust flag in the position described above to pass the workspace trust check.

FEATURE

/claude-api Skill Adopts Multi-Agent Architecture, Enabling Dynamic Workflows by Default

When you design cloud agent teams through the /claude-api skill, the underlying template generating those teams has been upgraded. Previously, the tool relied on the legacy coordinator architecture. It now builds Managed Agents (agents hosted by the platform) subteams using the multiagent_20261001 architecture, with dynamic workflows enabled by default.

A project studio reorganizes its staffing: where it previously relied on an older organizational setup, it now adopts a new team structure.

When you need to delegate multi-step tasks across multiple assistants, call /claude-api directly, and the generated agent team will use this architecture with dynamic workflows turned on by default.

FEATURE

sed -i Adopts Standard Command Prompts, Leaving Edits Outside /rewind Restoration

When you ask Claude to batch-replace file text in a conversation, the execution and confirmation flow for the sed -i command has been adjusted. Previously, this in-place modification command displayed a simulated file edit preview. It now displays a standard Bash execution prompt and runs directly with the verbatim input. Like other modifications made through Bash, resulting file changes will no longer be restored by the /rewind command.

Think of writing corrections on a notepad: where you once placed tracing paper over the page to preview changes, you now put pen directly to paper as instructed.

If you plan to batch-replace variable names across extensive code, verify your changes before running, because /rewind will not undo these modifications.

BUGFIX

Sandbox Isolation Hardened with Stricter Write Limits on Configs and Symlinks

When you enable sandboxing to run commands on macOS and Linux, several protection boundaries for environment isolation and file writes have been fixed. Bash commands inside the sandbox previously loaded Shell startup files outside the sandbox before execution. They no longer run outside the isolated environment. When directories are connected via symlinks (shortcut files pointing to real locations), macOS denyWrite rules now accurately match the real target location, preventing shortcuts from bypassing write restrictions on configuration repositories. Sandboxed commands and auto-approved modifications can no longer alter MCP (Model Context Protocol, enabling AI to connect with external tools) configuration files specified by --mcp-config. In Linux environments, even if background commands outlive their original session, write-prohibition boundaries in the sandbox are no longer lifted prematurely. If the sandbox is enabled but non-functional, commands exempted from the sandbox will prompt for confirmation before writing to allowlisted paths, while un-isolated fallback operations are rejected outright.

BUGFIX

Terminal Strengthens Command Auditing, Blocking Redirection and Directory Changes Bypasses

When Claude runs compound commands or deletes files in the terminal, several blind spots that previously missed permission prompts or falsely trusted state have been fixed. Bash permission checks previously blindly trusted variables set by a command even if output redirection failed to open. They no longer misjudge such executions as successful. When a command changes directories before running git, Bash checks now properly prompt for confirmation if cd is wrapped or prefixed, matching standard cd behavior. When compound commands contain subshells, Edit(path) blocking rules now reliably intercept redirection writes targeting that path. On Windows, if Set-Location or cd targets the current directory with extra arguments, PowerShell permission checks no longer auto-approve the command, prompting for confirmation instead. When dangerous rm and rmdir commands run in bypass permissions mode, the desktop app and VS Code now reject them directly with rewrite suggestions, preventing unattended sessions from stalling on confirmation prompts.

FEATURE

Worktree Isolation Guard Tightened, Accelerating Git Operations and Pre-fetching Objects

When you enable isolated environments so multiple conversations can handle different tasks in parallel, boundary protections for version control and working directories have improved significantly. Inside sessions isolated by worktrees (Git features that maintain parallel copies of the same project), commands with locale prefixes that should have been rejected by the isolation guard previously slipped through, but this is now fixed. Arithmetic commands under zsh that previously went unnoticed are also blocked. Worktrees and branch checkouts created by Claude Code now actively ignore replace references, matching other Git operations. Multiple internal Git commands are faster on Windows. Across all platforms, error messages from these commands are now displayed in English, regardless of Git locale settings. In standard clones or partial clones configured with Bash sandboxing, creating and reusing worktrees no longer fetches objects on demand. Such partial clones now pre-fetch objects before creating or reusing a worktree.
