Claude Code 2.1.309

Released: 2026-10-22

Release notes

FEATURE

ultrareview Enforces Workspace Trust Checks, Halting Immediately Without Authorization

When you run advanced code reviews in the terminal using claude ultrareview, the tool now actively verifies whether the current workspace is trusted. In a standard terminal, it prompts for confirmation, but it directly refuses execution if there is no interactive terminal or inside an automated environment. In automated scripts, you must include the --trust-workspace flag with no arguments (placed after the PR number or base branch). Alternatively, you can set the environment variable (configuration values read at runtime) CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1.

Picture a building security desk that only allows registered visitors upstairs: where reviewers could previously walk straight into private offices, they must now badge in against the visitor log, and anyone unlisted is stopped at the door.

When a scheduled in-depth review on a continuous integration server stops unexpectedly, add the trust flag in the position described above to pass the workspace trust check.

FEATURE

/claude-api Skill Adopts Multi-Agent Architecture, Enabling Dynamic Workflows by Default

When you design cloud agent teams through the /claude-api skill, the underlying template generating those teams has been upgraded. Previously, the tool relied on the legacy coordinator architecture. It now builds Managed Agents (agents hosted by the platform) subteams using the multiagent_20261001 architecture, with dynamic workflows enabled by default.

A project studio reorganizes its staffing: where it previously relied on an older organizational setup, it now adopts a new team structure.

When you need to delegate multi-step tasks across multiple assistants, call /claude-api directly, and the generated agent team will use this architecture with dynamic workflows turned on by default.

FEATURE

sed -i Adopts Standard Command Prompts, Leaving Edits Outside /rewind Restoration

When you ask Claude to batch-replace file text in a conversation, the execution and confirmation flow for the sed -i command has been adjusted. Previously, this in-place modification command displayed a simulated file edit preview. It now displays a standard Bash execution prompt and runs directly with the verbatim input. Like other modifications made through Bash, resulting file changes will no longer be restored by the /rewind command.

Think of writing corrections on a notepad: where you once placed tracing paper over the page to preview changes, you now put pen directly to paper as instructed.

If you plan to batch-replace variable names across extensive code, verify your changes before running, because /rewind will not undo these modifications.

BUGFIX

Sandbox Isolation Hardened with Stricter Write Limits on Configs and Symlinks

When you enable sandboxing to run commands on macOS and Linux, several protection boundaries for environment isolation and file writes have been fixed. Bash commands inside the sandbox previously loaded Shell startup files outside the sandbox before execution. They no longer run outside the isolated environment. When directories are connected via symlinks (shortcut files pointing to real locations), macOS denyWrite rules now accurately match the real target location, preventing shortcuts from bypassing write restrictions on configuration repositories. Sandboxed commands and auto-approved modifications can no longer alter MCP (Model Context Protocol, enabling AI to connect with external tools) configuration files specified by --mcp-config. In Linux environments, even if background commands outlive their original session, write-prohibition boundaries in the sandbox are no longer lifted prematurely. If the sandbox is enabled but non-functional, commands exempted from the sandbox will prompt for confirmation before writing to allowlisted paths, while un-isolated fallback operations are rejected outright.

BUGFIX

Terminal Strengthens Command Auditing, Blocking Redirection and Directory Changes Bypasses

When Claude runs compound commands or deletes files in the terminal, several blind spots that previously missed permission prompts or falsely trusted state have been fixed. Bash permission checks previously blindly trusted variables set by a command even if output redirection failed to open. They no longer misjudge such executions as successful. When a command changes directories before running git, Bash checks now properly prompt for confirmation if cd is wrapped or prefixed, matching standard cd behavior. When compound commands contain subshells, Edit(path) blocking rules now reliably intercept redirection writes targeting that path. On Windows, if Set-Location or cd targets the current directory with extra arguments, PowerShell permission checks no longer auto-approve the command, prompting for confirmation instead. When dangerous rm and rmdir commands run in bypass permissions mode, the desktop app and VS Code now reject them directly with rewrite suggestions, preventing unattended sessions from stalling on confirmation prompts.

FEATURE

Worktree Isolation Guard Tightened, Accelerating Git Operations and Pre-fetching Objects

When you enable isolated environments so multiple conversations can handle different tasks in parallel, boundary protections for version control and working directories have improved significantly. Inside sessions isolated by worktrees (Git features that maintain parallel copies of the same project), commands with locale prefixes that should have been rejected by the isolation guard previously slipped through, but this is now fixed. Arithmetic commands under zsh that previously went unnoticed are also blocked. Worktrees and branch checkouts created by Claude Code now actively ignore replace references, matching other Git operations. Multiple internal Git commands are faster on Windows. Across all platforms, error messages from these commands are now displayed in English, regardless of Git locale settings. In standard clones or partial clones configured with Bash sandboxing, creating and reusing worktrees no longer fetches objects on demand. Such partial clones now pre-fetch objects before creating or reusing a worktree.

FEATURE

/claude-api Expands Cloud Tracing Support, Verifying Live Docs and Enabling Auth Tokens

When you ask the /claude-api skill to configure cloud services and distributed tracing, several documentation accuracies and tracing settings have been improved. The skill description no longer mistakenly claims that ant beta:worker poll --on-work propagates trace context. It fixes an issue in C# tracing setups where cloud platform client spans were omitted. It corrects the inaccurate claim that Claude Platform request spans on AWS cannot join caller traces. When asked to add OpenTelemetry, the skill now proactively provides API tracing options alongside SDK tracing. Before responding that a feature is unsupported, the skill now connects online to verify against current official documentation. Service account keys and authorization tokens (digital credentials used for identity verification) from workload identity federation can now be used to manage OpenTelemetry export destinations.

BUGFIX

Skill Names Support Directory Prefixes, Introducing Modern Contrast Standards to Dataviz

When you load multiple plugins or custom skills into a project, duplicate skill collisions and file-read exception handling have been resolved. If a skill loaded via --add-dir shares the same name as an existing skill, it was previously unusable. It is now automatically prefixed as <folder>:<name>. After modifying files in the terminal Shell, /verify and /code-review no longer encounter issues locating skills belonging to nested packages. Plugins and skills synced from claude.ai are no longer removed entirely mid-session when encountering disk read errors. The built-in dataviz skill officially supports the APCA text contrast algorithm standard (while maintaining WCAG 2 ratios where AA compliance is required). Its palette verification script introduces the apca(text, background) function and guides whether labels inside shaded chart regions should pair with white or near-black.

BUGFIX

Shortcut Keys for Sending and Viewing Fixed, with Better Emoji Handling in Tool Previews

When you quickly type text and switch views in the terminal, shortcut responsiveness and transcript formatting have been fixed. Previously, pressing ctrl+enter to send immediately before the model began responding merely queued the message. If pressed while prompt hooks (small programs triggered by specific events) were executing, it restarted the hook and left the message stranded in the queue, which is now resolved. In Shell mode prefixed with !, slash commands bound to shortcuts are no longer erroneously forwarded to the system Shell for execution. When pressing ctrl+o, pending messages awaiting delivery from other agents and sessions are now fully flagged as pending and displayed at the bottom of the log. If long preview text from tool output was truncated in the middle of an emoji, it previously corrupted the session transcript and prevented jq from parsing it, which has now been fixed.

BUGFIX

Teammate Agents Inherit Tool Restrictions, Bridging Interrupted Operations on Self-Hosted Runners

When you launch split-pane teammate agents or run tasks on self-hosted servers, cross-agent configuration propagation and state transitions are more consistent. Teammate agents in split panes now properly inherit tool disablement rules and --tools restrictions specified on the command line by the lead agent. Sessions renamed via /rename no longer revert to randomly generated names when viewed from other conversations after a VS Code window reload or a non-interactive --resume. If a turn modifies checkpointed files through /code-review --fix, subagents, or Shell commands, the /rewind list no longer erroneously displays 'no code changes'. In self-hosted runner environments, --startup-timeout-min will not terminate the session prematurely if the initial prompt is still active in a subagent, though frozen processes are still stopped. When a session transitions to a new self-hosted runner, Claude can now clearly see interrupted tool calls and mark them as having an unknown result.

BUGFIX

PowerShell Hook Blocking Fixed, Aliased Models Automatically Resolve

When configuring custom hooks (small programs triggered when specific events occur) in your workflow to intercept tools or steps, compatibility with Windows and module loading has improved. Hook programs running in PowerShell that exit with code 2 previously failed to block operations, but now intercept them correctly. On Windows environments where Git for Windows is not installed, pre-tool and permission-request hooks specifying PowerShell no longer fail open simply due to the missing tool. If a model is specified by an alias (such as haiku) in the turn.step hook of a custom module, requests that previously failed every time now correctly resolve the corresponding model. When a hook module fails to load due to excessive nesting, error messages now explicitly identify the problematic file path instead of printing a terse stack overflow notice.

BUGFIX

Large Instruction Files Avoid Repeated Compaction, Artifact Publishing and Permissions No Longer Stall

When conversations involve extensive documentation or web artifacts are being published, conversation compaction and artifact update flows no longer cause repeated interruptions. After reading files governed by a large nested CLAUDE.md, sessions previously fell into loops of repeatedly compacting conversations. If a nested instructions file exceeds the size limit, the tool now loads only the initial portion of the file. When publishing or updating artifacts, certain common pages containing specific minified scripts or pages that were not preread previously faced rejection, but can now be published normally. If a conversation triggered content compaction within the same turn, Claude previously asked for permission repeatedly on every subsequent artifact update, an issue that is now fixed.

BUGFIX

Desktop Sessions Stay Connected, Remote Status Line and Disabled Tools No Longer Misbehave

When operating Claude Code through the desktop app or remote control, the stability of account status and background connections has improved. In print mode and SDK sessions, disabled MCP (a protocol that connects AI to external tools) servers previously reconnected unexpectedly when permission prompts appeared later, but now remain closed. In sessions hosted by the Claude desktop app, an issue where conversation messages were occasionally lost during network refreshes has been eliminated. When terminals on the same computer are logged into different accounts or organizations, sessions inside the desktop app previously lost certain features, but will no longer miss capabilities as a result. For standard folders that are not Git repositories, the status line (the bar displayed at the bottom of the terminal) of claude remote-control no longer mistakenly shows the branch name as HEAD.

BUGFIX

Privacy Settings Sync in Real Time, Feedback and GitHub Mentions Render Accurately

When checking privacy settings in the terminal or reporting issues to the team, returned explanations and public content are much clearer. Running /privacy-settings previously might have displayed an outdated toggle state for helping improve AI models, but now displays current settings in real time and clearly states when settings cannot be retrieved. When feedback is not enabled for your organization, submitting /feedback no longer merely displays a vague request to try again later, instead presenting the specific reason provided by the server and directing you to bug-reporting channels. When an oversized /feedback report containing extensive logs fails to transmit, it now automatically retries after excluding conversation transcripts, rather than aborting directly with an error. When publishing pull requests, issues, or comments, Claude no longer formats role names or placeholders as @ mentions, preventing unintended notifications to unrelated GitHub users.

BUGFIX

Full Disk Space Provides Cleanup Guidance, Streaming Timeouts and Tool Installation Popups Fixed

When the underlying system is low on space or running in specific cloud environments, error prompts and connection waiting mechanisms are more practical. Inside Linux sandboxes sharing /proc, the read tool no longer falsely reports that files do not exist when reading specific PDF page ranges. When Amazon Bedrock configures ANTHROPIC_BEDROCK_BASE_URL as the default endpoint, fine-grained streaming is no longer mistakenly disabled. When connecting through gateways that only send keepalive pings, the prompt waiting for API responses no longer flickers, and non-Anthropic backends wait for 45 seconds. On a Mac with neither Xcode nor Command Line Tools (developer tools for the command line) installed, launching Claude Code no longer triggers an installation popup every time. When Bash commands abort because the disk is full, the tool explains the reason and names the folder where space should be freed. Starting up when temporary storage is full also displays a clear message rather than cryptic codes.

BUGFIX

VS Code Chat Panel Supports Collapsing Long Messages, Corrupted Cache Automatically Recovers

When using Claude Code in the VS Code side panel, several layout rendering and caching anomalies have been resolved. When the editor caches an incomplete file and causes the Claude panel to go completely blank, the extension now recovers on its own or clearly explains the cause and manual resolution. Lengthy slash command prompts such as /goal now automatically collapse behind an expand button just like other long messages, and narrowing the chat panel will no longer cause long messages to break the layout. Hint tags above the input box indicating specific plugins no longer mistakenly obscure menus for slash commands or @ mentions. Pasting copied LaTeX mathematical formulas no longer creates superfluous empty list items, blank paragraphs, or code blocks, and numbered lists are no longer forced to restart from 1.

BUGFIX

VS Code Edit Wait Time Shortened, Certificate Warning Guidance and Empty Logs Fixed

When editing code or issuing voice commands in VS Code, operational latency and background logging logic have been adjusted. When certificate verification (checking digital proof of the connection target's identity) fails for dictation or extension requests, such as when passing through a proxy that inspects encrypted traffic, logs now provide troubleshooting guidance. Opening a new conversation without sending a message no longer clutters history with empty sessions. If "ctrl+j" is set to null in the Chat section of ~/.claude/keybindings.json, pressing Ctrl+J in the chat input box no longer forces a newline, deferring handling to VS Code and the operating system. When an organization does not accept feedback, error prompts no longer return only an HTTP status code, displaying the specific reason instead. Editing and writing in the chat panel are faster, reducing the wait time to detect new problems after each edit from 1 to 1.5 seconds down to 0.75 seconds in most cases.

BUGFIX

Cloud Sessions Fix Environment Variable Quotes, Admin Interface and Changes List Clarified

When managing cloud sessions and connection settings in the browser, the experience for filling out forms and viewing documents has improved. When adding connectors in routine forms, the list no longer falsely claims that no connectors are available while loading. The cloud environment editor no longer scrambles variable order, nor does it insert redundant backslashes when values contain both single and double quotes. The self-hosted environment dialog in administrative settings has been adjusted so that headers, tabs, and buttons stay pinned in view while scrolling, leaving only the middle content scrollable. The document-reading toolbar in cloud sessions no longer displays escaped raw JSON, rendering cleanly formatted content instead. The changes panel now explicitly clarifies whether it is listing only pushed commits or displaying only file modifications made by Claude.

FEATURE

Slack Channel Drafts Dispatch Correctly, Review Buttons Support Restarting Sessions

When your team collaborates with Claude inside Slack channels, the reliability of message dispatching and interactive cards has significantly improved. Drafts approved in a channel were previously at risk of being mistakenly posted by Claude into direct messages. Posts without a specified channel are now rejected outright, ensuring content is delivered to the designated channel. When clicking approve or reject on a review card, if the underlying session has stopped, your action now automatically restarts that session to proceed. After workspaces are migrated to a different Claude organization (including unshared channels on Enterprise Grid), Claude no longer misses unmentioned discussion messages in channels. Before posting replies to a thread, Claude now reads the latest comments just posted by others, preventing disjointed responses. If the admin Slack settings page fails to load, it no longer falsely reports that no workspace is connected, instead displaying an error message alongside a retry button.

FEATURE

Pull Request Review Check Marks Automatically Backfilled, Manual Stops Promptly Close Checks

When waiting for automated code reviews on GitHub pull requests, check status updates are now more accurate. When a review finishes successfully but earlier attempts to create the check status failed, the tool on its final retry now reliably backfills the completed check mark, preventing the pull request from hanging in a state with no check results. If new code is pushed during an ongoing review and queued up behind it, typing @claude review stop to halt the review manually previously still allowed queued reviews to start. Queued checks are now closed immediately with the specific cancellation reason noted.

Just as an official document approval system automatically applies a final approval stamp once sign-off is complete, any case recalled midway is immediately marked with the withdrawal reason to prevent review progress from remaining in limbo.
