Claude Code 2.1.274

Released: 2026-09-17

Release notes

FEATURE

Critical Memory Warnings Alert in Real Time, Background Commands No Longer Stop Prematurely

When system memory is running critically low, the terminal now displays a visible warning with guided steps to free memory or restart safely.

Background commands that were previously stopped after idling for thirty minutes under mild memory pressure now only stop when memory is critically low, with the debug log clearly recording the reason.

This is like a coolant temperature warning light on a car dashboard: a red light alerts the driver for inspection only when the radiator is truly overheating, rather than stalling the engine randomly during normal driving.
FEATURE

MCP Connection Protocol Upgrades and Flexible Startup Wait Time Configuration

The boarding gate announces a final boarding cutoff, departing promptly once time is up while luggage arriving later is sent on the next flight.

Non-interactive mode can now set the maximum wait time for connecting MCP (Model Context Protocol) servers during the first turn via CLAUDE_CODE_MCP_STARTUP_WAIT_MS.

When using --strict-mcp-config with an empty --mcp-config, the first turn no longer gets held up waiting to time out on incidental servers. In streaming JSON sessions, deferred tool search tools no longer stall first-turn startup. Environments such as Bedrock, Vertex, and Foundry now adopt the v2 client and the latest protocol negotiation by default. Invalid SDK server entries in configuration files are skipped with a warning.

BUGFIX

Clear Reporting for MCP Tool Permissions and Safe Masking of Sensitive Variables

When calling external extension tools, if a request is refused by the server due to insufficient permissions, the error message now clearly names the missing permissions and points to /mcp re-authentication instead of misreporting an expired sign-in.

Connection error logs and the login tool description no longer leak resolved secret strings from environment variables. Servers using legacy HTTP and SSE protocols now connect properly even when returning error codes. Streamable tool calls are no longer bound to a fixed timeout and won't time out early. Prompts and resources update immediately when a server sends list-changed notifications.

This is like customs returning a package with a clear checklist of missing documents and counter guidance while proactively redacting personal information, rather than mistaking missing paperwork for an expired passport.
FEATURE

OpenTelemetry Telemetry Logging Upgrades for More Transparent Request Tracing

This is like upgrading the indexing labels on a flight recorder: every conversation and request precisely logs its flight number and fuel metrics, making post-flight review crystal clear.

System telemetry now adds an effort attribute to LLM request traces.

Through the new managed settings resolved event, administrators can clearly track configuration sources and policy status, and setting the environment variable OTEL_LOG_MANAGED_SETTINGS=1 automatically redacts sensitive setting values and digests in logs. When exporting raw request bodies to local files, the newly generated index.jsonl file and event attributes accurately link each model response to its corresponding request file and transcript message.

FEATURE

Configurable Timeout for Enterprise Apps Gateway and Graceful Shutdown for In-Flight Requests

The Claude apps gateway now supports adding store.connect_timeout_seconds in its configuration to lengthen the database connection timeout.

If the database connection experiences a slight delay during boot, the gateway actively retries the connection up to three times, and clearly points to the configuration location if unreachable. When the server receives a shutdown signal, it no longer forcefully cuts open streams, instead waiting up to twenty-five seconds for in-flight requests to complete transmission smoothly.

This is like a restaurant at closing time not abruptly turning off the lights to rush customers out, but rather leaving ample time for the last seated guests to finish their meal gracefully.
FEATURE

Enhanced Gateway Load Warnings and Streamlined Spend Limit Checks

The Claude apps gateway now issues an active load warning when open connections exceed two hundred and fifty-six, and includes identity information in telemetry data.

Under high load, the spend-limit check is simplified from four database round trips to one, effectively reducing timeout risks; if the database drops a connection during the check, the system properly handles the exception. When a user triggers sign-in rate limits at /login, the interface clearly explains the refusal reason, while gateway logs flag which limit was hit and suggest which setting to change.

The entire management is like a smart queuing system in a bank lobby: dispatching extra counters when crowds surge and merging multi-step verification into a single teller visit.
BUGFIX

Smart Transcript Self-Healing and Uninterrupted Goal and Hook Sessions

When a stenographer compiles meeting notes, torn pages are automatically mended, overly long content is summarized for key points, and established goals are never lost.

When a corrupted transcript leads to tool call errors, sessions attempt to self-heal or provide a hint to use /rewind to end retry loops.

Long-running tasks driven by hooks automatically compact the conversation when context overflows again after previous compaction. For instance, an active /goal will not lose its ongoing objective when resuming a compacted session. Ordered lists entered in messages are no longer forcefully renumbered. Stop prompt hooks that trigger repeatedly now display with a concise label.

BUGFIX

Subagent Parameters Preserved and Accurate Transcript and Progress Display

When managing agents using the claude agents command, launch parameters such as --model, --effort, and permission modes are no longer lost after an auto-update relaunch.

On Bedrock, Vertex, and Foundry platforms, subagents configured with the Opus model correctly recognize and retain their model settings. Messages sent by a subagent to the main session remain fully preserved in the desktop transcript after a relaunch, and a subagent's concise progress summary is no longer accidentally overwritten by a runaway multi-paragraph reply.

This is like a dispatched specialist's badge and task list: regardless of shift changes or re-registration, their equipped tools and briefing summaries remain intact.
FEATURE

Smoother Background Task Resumption and Notification Batching to Save Model Turns

In headless mode and SDK sessions, multiple background tasks finishing concurrently are now handled in a single model call rather than sending individual requests one by one.

Resuming an interrupted background agent avoids leaving behind incomplete batched tool calls, and resuming work with CLAUDE_CODE_RESUME_INTERRUPTED_TURN properly reports previously unfinished background tasks. Status notifications when background agents wait on tasks are more accurate. Script output and exit status from the Monitor tool are delivered merged into a single notification.

This is like a laboratory machine feeding multiple collected samples into an analyzer all at once, eliminating the wait time of repeatedly powering the device on and off.
PERF

Plugin Management Performance Upgrades and Elimination of Redundant Configuration Reloads

When plugin policy is centrally managed remotely, the system no longer frequently rewrites the manifest file on startup, preventing the desktop version from repeatedly reloading plugins across all open sessions.

After plugins reload, terminal commands only re-source the profile if executable directories changed, effectively eliminating command execution stalls. Standalone plugin directories no longer mistakenly inherit version numbers from enclosing Git repositories; plugins loaded from archive files avoid stale extracted files after multiple reloads; and repository clones retain Git LFS pointers by default to save bandwidth.

This is like installing a new accessory in a toolbox: only inventorying compartments when a tool's location changes, without needing to unpack and check the entire box every time.
FEATURE

Smoother Artifact Operations and Overwrite Protection for Team Collaboration and Publishing

When multiple people collaborate on cloud blueprints, the system checks the latest online version before submitting modifications, preventing newly published drafts from accidentally overwriting teammates' work.

The Artifact tool now ensures the session reads the latest content before updating, eliminating the dilemma where an approved update is subsequently refused.

In team collaboration and cloud environments, reading a teammate's artifact is no longer misjudged as disabled network access. If not signed in to a cloud account, the terminal clearly notifies on the first attempt and stops futile retries sooner. Publishing based on an older version is proactively intercepted with the newer page provided to merge, and new versions published remotely in local environments no longer interrupt current conversation turns.

BUGFIX

Stricter Command Permission Checks and Fixes for Worktree Isolation and Edit Previews

When executing terminal commands involving special variable assignments or loops, the system now properly triggers permission prompts.

In worktree-isolated sessions, potentially dangerous operations with nested shell expansions are directly refused. In files containing multi-byte characters, the preview position in Edit permission prompts no longer drifts from the actual modification location. Furthermore, the system performs stricter safety checks before removing an agent worktree containing submodule checkouts to prevent data loss.

This is like a construction site strictly verifying every special operations permit and inspecting each fastener before dismantling temporary scaffolding.
BUGFIX

Click-to-Expand Fullscreen Messages and Fixes for Question Previews and File Links

In fullscreen mode, collapsed teammate and agent messages now support click-to-expand for full reading.

Clickable links pointing to local file paths in the terminal have been corrected to adhere to the file:// protocol standard, opening files smoothly when clicked inside terminals like VS Code. In AskUserQuestion preview mode, entered notes attach accurately to the currently highlighted option, and pressing Enter to submit no longer drops the selected item. Launching inside editor terminals on Linux under Wayland no longer unexpectedly opens extra blank editor windows.

This is like an exhibition tablet guide: clicking a summary instantly expands full details, and note fields precisely lock onto checked items when completing a survey.
FEATURE

Accurate Slash Command Guidance and Leaner Code Review Execution

Error hints in desktop sessions now suggest slash commands such as /usage-credits instead of invalid command-line flags.

When organization policy disables fast mode, entering /fast on in non-interactive environments explicitly reports that it has been disabled. The /schedule command preserves prompt message roles when saving routines. The /status command correctly displays failure details for the API key helper and unifies terminology for related features under cloud sessions. The /code-review command switches to leaner inline review prompts, avoiding spawning excessive review subagents for standard models.

The entire operation is like updating a car dashboard: every switch and warning light falls neatly into place, clearly reflecting the current driving mode.
FEATURE

Fluid Language Server Diagnostics and Reliable Persistence for Self-Hosted Runners

When a language server publishes project-wide diagnostics across thousands of files, the system no longer causes noticeable per-turn slowdowns.

Self-hosted runners now keep retrying upon transient failures during token refreshes, and actively fetch new tokens following authentication errors, preventing sessions from frequently breaking. The runner skips read-only repositories refused by the git host during access checks rather than failing session startup. The first turn of a cloud session no longer misses tools from connecting MCP servers.

This is like an automated factory running smoothly when handling massive parts inventories, promptly swiping access passes again if a security sensor briefly misreads.
FEATURE

[VSCode] Resuming Steps Across Window Reloads and Managing Memories and Instructions from Customize Menu

This is like clipping notes to an office desk: even if the computer restarts after power-off, halfway-completed documents resume accurately, and reference materials in drawers remain accessible at any time.

After reloading the window in VS Code, the system automatically continues interrupted steps with a label in chat, and messages sent while running a tool are no longer lost upon reload.

The Customize menu adds Memory and Instructions entries to view auto-memory toggles and edit instruction files. A new claudeCode.lockEditorGroups setting prevents the extension from locking editor groups, resolving unintended layout splitting when reopening tabs or starting new sessions.

FEATURE

[VSCode] Conflict-Free Settings Writes and Immediate Focus on New Tab Shortcut

When opening a new tab via shortcut in VS Code, the input box automatically gains focus so you can type immediately without clicking.

Overlapping settings writes from the extension now include safeguards to prevent ~/.claude/settings.json corruption or dropped settings. Asking side questions with /btw right after starting a conversation no longer mistakenly displays another session's history. The brief freeze when first querying global gitignore files is resolved, with standard XDG config paths supported. Sign-in and sign-out states in terminals reflect immediately after changing configuration directories in environment variables.

This is like neatly slotting documents back into a binder: turning to a fresh page finds the pen tip already poised at the first line.
BUGFIX

[VSCode] Full Diffs Display and Fixes for Accessibility and High Contrast Themes

Edit diff boxes in chat now fit the exact number of rows displayed, no longer getting cut off at the bottom under wrapped lines or specific panel widths.

Under High Contrast themes, inline code and code blocks are once again clearly readable. Screen readers now clearly announce message senders (such as "You" or "Claude") along with the names of executed tools. The plan review card supports scrolling through comments, preventing the feedback button from being obstructed. Plugin management and MCP dialogs now support full keyboard navigation. Session names no longer shift horizontally when typing queries in the session picker.

The entire interface upgrade is like adding appropriate typography and audio guidance to a document, ensuring comfortable browsing regardless of assistive tools used.
FEATURE

[Claude Code on the web] Flexible Cloud Branch Diffing and More Stable Git Operations and Authentication

When reviewing engineering blueprints in the cloud, you can select any version for comparison at any time, and reissuing temporary passes never delays on-site work.

In the diff view for cloud sessions on the web, a new branch picker lets you freely compare changes against any branch instead of being restricted to the base branch.

When GitHub token renewals briefly fail, git operations no longer throw service unavailable errors; and after credentials refresh, commits no longer experience temporary signing errors. Sessions marked as read no longer revert back to an unread status.

FEATURE

[Claude Code on the web] Improved Routine Reliability and Long-Term Retry for Disconnected Accounts

Editing a routine no longer triggers unintended double firing or automatically re-enables a paused routine.

When saving a routine fails to link with GitHub due to repository trigger limits, the toast message explicitly details the failure cause. When the owner's GitHub connection is lost, the routine skips the current run and continues retrying for up to seventy-two hours instead of disabling the routine on the first failed check. When subscription pauses place a routine on hold, the notice clearly guides users to manually re-enable it after restoring the subscription.

This is like an automated garden sprinkler system: when the water pipe is temporarily dry, it periodically re-attempts supply rather than scrapping the entire setup.
FEATURE

[Claude Tag] Upfront Channel Guest Permissions and Prompt Bot Mention Wakeups

This is like an office building's smart front-desk concierge: not only pre-registering guest access tiers, but also springing into action immediately upon hearing calls from assistants in other departments.

A Guests setting has been added to Claude Tag admin settings, allowing administrators to specify access rules upfront when adding channels.

When other Slack apps or bots mention @Claude, Claude wakes up and replies properly even after days of channel inactivity; and mentions during new channel creation are delivered smoothly once Claude joins. Significant follow-up updates sent minutes later are posted as new notification replies instead of silently editing previous messages. Monitoring for cross-workspace shared channels and environment name displays have also been resolved.

BUGFIX

[Claude Tag] Fixed Single-Channel Search and Optimized Live Progress Checklist Layout

When searching for messages within a single Slack channel, search failures are resolved and matching results are returned accurately.

When stopped by a safety filter, the system explicitly explains the reason and no longer cancels running background work. Email addresses in replies no longer show a redundant mailto: prefix. In busy threads, live progress checklists are capped at two thousand characters and updated at most every fifteen minutes, while automatically updating older checklist links. Editing a Slack canvas in specific channels no longer repeatedly appends redundant guest notes.

The entire update is like replacing a bulletin board with a clean dynamic checklist: searches are precise and the layout remains tidy without clutter.

[Code Review] Clear and Plain Review Findings with Error Retries and Link Guidance

When senior reviewers provide feedback, they state affected parties, error locations, and fix methods upfront with crystal clarity.

Automated Code Review now posts each finding using short, plain sentences, allowing developers to understand issues at a glance.

When GitHub or internal services experience transient startup errors, the system automatically waits and retries to prevent unexpected interruptions. Upon re-review, resolved threads close normally without staying open due to appended lower-severity notes. If a review is skipped due to organization limits, check-run cards and comments directly link to the admin page for prompt resolution.
