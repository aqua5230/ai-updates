記憶體緊繃即時示警，背景指令不再提早中斷

當電腦記憶體（RAM，負責暫存執行中程式的空間）吃緊時，終端機會直接跳出明顯警示，並附上釋放記憶體或安全重啟的引導步驟。以前在一般記憶體壓力下閒置三十分鐘就會被停止的背景指令，現在只有在記憶體極度不足時才會停下，除錯日誌也會清楚記錄停用原因。

這就像汽車儀表板上的水溫警示燈，只有在水箱真正過熱時才會亮起紅燈提醒駕駛檢修，平常行駛不會隨意強制熄火。

MCP 連線協定全面升級，啟動等待時間靈活設定

登機門廣播最後登機時限，時間一到準點出發，後續抵達的行李再由下一班次送達。

非互動模式現在能透過 CLAUDE_CODE_MCP_STARTUP_WAIT_MS 設定首輪等待 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器連線的上限時間。搭配空的 --mcp-config 使用 --strict-mcp-config 時，首輪不再因無關伺服器苦等逾時。在串流 JSON 的工作階段中，延後搜尋的工具不再卡住首輪啟動。Bedrock、Vertex 與 Foundry 等安裝環境預設改採第二版用戶端與最新協定交涉。設定檔中無效的 SDK 伺服器項目會直接跳過並發出警告。

MCP 工具權限清晰回報，敏感變數安全隱藏

呼叫外部擴充工具時，若因權限不足遭伺服器拒絕，錯誤訊息現在會明確列出缺少的權限項目並提示使用 /mcp 重新驗證，不再誤報為登入過期。連線錯誤日誌與登入工具說明中，不再洩漏環境變數解析後的機密字串。使用傳統 HTTP 與 SSE 協定的伺服器回傳錯誤代碼時已能正確連線。可串流的工具呼叫不再受限於固定時間而提早逾時。當伺服器推送清單變更時，提示詞與資源項目會即時更新。

這如同海關退件時清楚附上補件清單與櫃檯指引，並主動遮蓋個人個資，不再把缺少證件誤判為護照失效。

OpenTelemetry 遙測記錄升級，請求溯源更透明

這就像為飛行記錄器升級標籤索引，每次對話與請求都精準記錄航程編號與油耗數據，事後調閱一清二楚。

系統遙測（telemetry，收集軟體運作數據以利分析的機制）現在於大型語言模型請求追蹤中新增了 effort 思考程度屬性。透過新增的受管設定解析事件，管理者能清楚掌握設定來源與策略狀態，設定環境變數 OTEL_LOG_MANAGED_SETTINGS=1，即可在記錄中自動遮蔽敏感的設定值與摘要。當你將原始請求內容輸出至本機檔案時，新產生的 index.jsonl 索引檔與關聯識別碼能將每次模型回覆精確連結至對應的請求檔案與對話訊息。

企業網關連線逾時可調，關機等待請求消化

管理 Claude 企業應用的應用程式網關（Gateway，負責轉發與管理連線的中繼伺服器）現在支援在設定中加入 store.connect_timeout_seconds，用以延長資料庫連線逾時秒數。開機時若資料庫連線稍有延遲，網關會主動重試連線最多三次，無法連線時也會明確指出設定位置。當伺服器收到關機訊號時，不再強制切斷進行中的連線，會最多等待二十五秒讓處理中的請求順利傳輸完成。

這好比餐廳打烊前不再直接熄燈趕客，而是留出充裕時間讓最後入座的客人優雅用餐完畢。

網關負載警示強化，額度檢查省時省力

企業應用網關現在會在連線數量超過二百五十六筆時主動發出負載警示，並於遙測資料中納入身分識別資訊。在高承載狀態下，花費用量檢查從原本的四次資料庫往返簡化為一次，有效減少逾時風險；若在檢查期間資料庫連線中斷，系統也能妥善捕捉異常。當使用者在 /login 觸發登入頻率限制時，介面會清楚說明拒絕原因，伺服器日誌也會同步標記觸發的規則與建議修改的設定項。

整套控管猶如銀行大廳的智慧叫號系統，人潮湧現時主動調度窗口，將多道審核程序併為單次臨櫃辦理。

對話記錄智慧修復，目標與掛鉤工作階段不中斷

速記員整理會議紀錄時，若發現紙頁破損會自動黏合，內容過長時主動提煉重點，絕不遺漏既定目標。

當對話記錄損毀導致工具呼叫錯誤時，工作階段會嘗試自我修復，或提示使用 /rewind 結束重試迴圈。由掛鉤（hook，特定事件發生時被觸發的小程式）驅動的長任務，在篇幅再次超出上限時會自動壓縮對話。例如執行中的 /goal 在接續已壓縮的工作階段時，不會遺失進行中的目標。對話中輸入的自訂編號清單不再被強制重新排序。阻擋對話的掛鉤重複觸發時改以精簡標籤呈現。

子代理參數完整保留，對話紀錄與進度精確呈現

使用 claude agents 指令管理代理時，自動更新重啟後不會再遺失 --model、--effort 或權限模式等啟動參數。在 Bedrock、Vertex 與 Foundry 平台上，指定 Opus 模型的子代理能正確辨識並保留模型設定。子代理回傳給主工作階段的訊息，在桌面版重啟後依然完整保留在對話記錄中；子代理的精簡進度摘要也不會再被冗長的多段回覆意外覆蓋。

這猶如外派專員的識別證與工作清單，無論換班或重新登記，身上配備的工具與簡報摘要都確實保留。

背景任務接續更流暢，通知彙整省下模型輪次

在無頭模式（headless，沒有終端機視窗的背景執行模式）與 SDK 工作階段中，多個同時完成的背景任務現在會合併為單次模型呼叫處理，不再逐一分次發送請求。恢復執行被中斷的背景代理時，不會殘留不完整的批次工具呼叫；使用 CLAUDE_CODE_RESUME_INTERRUPTED_TURN 接續工作時，也能正確回報先前未完成的背景任務。背景代理等待任務時的狀態通知更加準確。監視工具的腳本輸出與結束狀態合併為單一通知送達。

這宛如檢驗機將採集的多組樣本一次送入分析儀，省去反覆開關機器的等待時間。

外掛管理效能升級，設定載入不再頻繁重讀

外掛套件（Plugin，擴充系統功能的附加模組）原則由遠端集中管理時，系統啟動時不再頻繁重寫清單檔案，避免桌面版重複重新載入所有工作階段的外掛。外掛重新載入後，執行終端機指令時只有在執行檔目錄變更時才會重新讀取設定檔，有效消除指令執行時的停頓。獨立外掛目錄不再錯誤繼承外部的 Git 版本號；從壓縮檔載入的外掛在多次重載後不會讀取到舊解壓檔案；複製套件庫時預設保留大檔案指標以節省頻寬。

這好比在工具箱安裝新配件時，只在工具位置改變時清點收納格，平時不必整箱翻開重對。

成果工件讀寫更順暢，團隊協作與發布防覆蓋

多人共用雲端設計圖時，系統在送出修改前先確認線上最新版本，避免後發布的圖稿意外覆蓋隊友心血。

成果工件（Artifact，由 AI 產生的獨立檔案或程式碼成果）工具現在於更新前會先確保工作階段讀取最新內容，不再出現確認更新後又被拒絕的窘境。在團隊協作與雲端環境中，讀取隊友工件不再被誤判為網路連線關閉。若尚未登入雲端帳號，首次執行即會明確告知並減少無效重試。發布舊版本時會主動攔截並提供最新頁面以便合併；本機環境中遠端發布的新版本也不會無故打斷目前對話。

指令權限把關更嚴密，工作樹隔離與編輯預覽修正

執行包含特殊變數指派或迴圈的終端機指令時，系統現在會正確觸發權限確認提示。在工作樹（worktree，Git 讓同一專案平行開多份副本的功能）隔離的工作階段中，帶有巢狀指令擴展的潛在危險操作會被直接拒絕。在包含多位元組字元（例如中文字）的檔案中，檔案編輯權限提示中的預覽位置不再與實際修改處產生偏差。此外，在移除包含子模組簽出的代理工作樹前，系統會執行更嚴謹的安全檢查以防資料遺失。

這好比施工現場嚴格核實每張特種作業操作證，拆除臨時鷹架前必須逐一檢查固定扣件。

全螢幕訊息點擊展開，問答預覽與檔案連結修復

在全螢幕模式下，原本摺疊的隊友與代理訊息現在支援點擊展開完整閱讀。終端機中指向本機檔案路徑的可點擊連結，已修正為符合 file:// 協定標準，在 VS Code 等終端機中點擊即可順利開啟檔案。在互動問答工具的預覽模式下，輸入的備註文字會精準附加在當前反白的選項上，按下 Enter 送出時也不會遺失選取的項目。在 Linux Wayland 環境的編輯器終端機中啟動時，不再異常開啟額外的空白編輯器視窗。

這就像展覽館的導覽平板，點選摘要直接展開詳情，填寫問卷時備註欄位精準鎖定勾選的項目。

斜線指令提示精準對齊，程式碼審查更輕量

桌面版工作階段中的錯誤提示現在會引導使用 /usage-credits 等斜線指令，不再推薦無效的命令列參數。當組織政策禁用快速模式時，非互動環境輸入 /fast on 會明確告知已被停用。/schedule 儲存例行排程時能完整保留提示詞角色。/status 指令會正確顯示金鑰輔助程式的失敗細節，並將相關雲端功能統一標示為雲端工作階段。/code-review 改為使用輕量化的內嵌提示詞，不再為一般模型繁衍過多審查子代理。

整套操作猶如汽車儀表板更新，各項開關與警示燈號各就其位，清楚反映目前的行車模式。

語言伺服器診斷不卡頓，自託管執行器穩定續航

若是語言伺服器（LSP，在背景分析程式碼語法與錯誤的工具）對數千個檔案發布專案診斷時，系統不再於每一輪對話產生明顯延遲。自託管 Runner 執行器在更新 token（驗證身分的授權令牌）遇到短期失敗時會持續重試，遇到授權錯誤時也會主動重新取得憑證，不再讓工作階段頻繁中斷。在程式碼託管平台存取檢查被拒絕的唯讀套件庫，執行器會主動略過而非直接導致啟動失敗。雲端工作階段首輪對話也不會遺漏連線中的 MCP 工具。

這好比自動化工廠在面對龐大零件清單時穩定運行，遇到門禁感應不良也會即刻重刷通行證。

[VSCode] 視窗重載接續執行，自訂選單管理記憶與指示

這就像在辦公桌上夾好工作便條，即使下班斷電重啟電腦，進行到一半的公文也能精準接續，抽屜裡的參考資料隨時都能查閱。

在 VS Code 中重新載入視窗後，系統會自動接續中斷的步驟並於對話中加上標籤；執行工具期間送出的訊息也不會再因重新載入而遺失。自訂選單中新增了記憶與指示管理項目，方便檢視自動記憶開關與編輯指示檔案。透過新增的 claudeCode.lockEditorGroups 設定，可防止擴充套件鎖定編輯器分組，解決重新開啟分頁或建立新工作階段時版面意外分割的問題。

[VSCode] 設定寫入防衝突，快捷鍵開啟分頁即刻輸入

在 VS Code 中使用快捷鍵開啟新分頁時，輸入框會自動取得焦點，無需手動點擊即可直接打字。擴充套件並行寫入設定時增加防護，避免 ~/.claude/settings.json 損毀或遺漏設定項。新對話剛建立時使用 /btw 提問，不再錯誤顯示其他工作階段的歷史問答。首次查詢全域忽略檔案時的短暫卡頓已消除，並支援標準的 XDG 設定路徑。在環境變數設定中修改設定目錄後，終端機內的登入與登出狀態會即時反映。

這好比在資料夾中抽換文件時精確歸位，翻開新活頁紙時筆尖已在第一行待命。

[VSCode] 差異比對完整呈現，無障礙與高對比主題修復

對話中的檔案修改差異比對框現在會完全貼合內容行數，即使在長行折行或特殊面板寬度下也不再被底部截斷。在高對比主題下，行內代碼與程式碼區塊已恢復清晰可讀。螢幕報讀軟體現在會清楚朗讀訊息發送者（例如「You」或「Claude」）與執行的工具名稱。計畫審查卡片支援留言清單捲動，不再遮擋意見回饋按鈕。外掛管理與 MCP 對話框支援完整鍵盤操作。工作階段選擇器在搜尋時名稱不再橫向晃動。

整套介面升級猶如為文件加上合適的字級與語音導覽，無論使用哪種閱讀輔助工具都能舒適瀏覽。

[網頁版] 雲端分支靈活比對，Git 操作與認證更穩定

在雲端檢視工程藍圖時，你隨時能挑選任意版本進行對照，換發臨時通行證時也不會耽誤現場施工。

網頁版雲端工作階段的差異比對檢視中，新增了分支選擇器，讓你自由比對變更與任何分支的差異，不再受限於基準分支。當 GitHub 的 token（用於存取服務的授權令牌）短期更新失敗時，Git 操作不再直接跳出服務不可用的錯誤；認證憑證重新整理後，程式碼提交也不會再出現短暫的簽章失敗。標記已讀的工作階段不會再跳回未讀狀態。

[網頁版] 例行排程穩定度提升，連線異常支援長效重試

編輯例行排程（Routine，在雲端定時或依事件觸發的自動化任務）時，不再發生意外觸發兩次或自動重新啟用已暫停排程的狀況。儲存排程若因達到觸發上限等原因無法連結 GitHub，提示訊息會具體指出失敗原因。當擁有者的 GitHub 連線遺失時，排程會跳過當次執行並持續重試長達七十二小時，不再於首次檢查失敗時直接關閉排程。當訂閱暫停導致排程擱置時，通知會清楚引導在恢復訂閱後手動重新開啟排程。

這好比花園的自動定時灑水器，水管暫時缺水時會定時再次嘗試供水，不會直接整組報廢。

[Claude Tag] 頻道訪客權限預先設定，機器人標記即時喚醒

這好比辦公大樓的智慧值班管家，不僅能預先登記訪客通行等級，聽到其他部門助理呼叫時也會立刻起身應對。

在 Claude Tag 管理設定中新增了訪客權限選項，讓管理員在新增頻道時預先指定存取規範。當其他 Slack 應用程式或機器人標記 @Claude 時，即使頻道閒置多日也能正確喚醒並回覆；新頻道建立時的標記訊息也會在加入後順利送達。隔數分鐘後發送的重要後續更新會發布為新的通知訊息，不再靜默修改舊訊息。跨工作區共享頻道監控與環境名稱顯示也已修正。

[Claude Tag] 單一頻道搜尋修復，即時進度清單排版最佳化

在 Slack 單一頻道內搜尋訊息時，已修復搜尋失敗的問題並能正確回傳符合的結果。當觸發安全過濾機制而停止時，系統會明確告知原因且不再取消執行中的背景工作。回覆中的電子郵件地址不再顯示多餘的 mailto: 前綴。在熱門討論串中，即時進度檢查清單限制於二千字以內並最多每十五分鐘更新一次，同時自動更新舊的清單連結。在特定頻道編輯 Slack 畫布時，不再反覆附加多餘的訪客註記。

整套更新如同為公佈欄換上乾淨的動態清單，搜尋精準且版面整潔不洗版。

[Code Review] 審查意見直白易懂，錯誤重試與連結指引完善

資深審查專家提出修改建議時，開門見山點出受影響對象、出錯位置與修復方法，溝通清楚明瞭。

自動代碼審查（Code Review）現在以簡短平實的語句發布每條審查結果，讓開發者一眼看懂問題所在。當 GitHub 或內部服務啟動時短暫異常時，系統會自動等待並重試，避免審查意外中斷。重新審查時，已修復的討論串會正常關閉，不再因附加次要備註而維持開啟。若因組織配額限制跳過審查，狀態卡片與留言會直接附上管理頁面連結以利排除限制。

English

Critical Memory Warnings Alert in Real Time, Background Commands No Longer Stop Prematurely

When system memory is running critically low, the terminal now displays a visible warning with guided steps to free memory or restart safely. Background commands that were previously stopped after idling for thirty minutes under mild memory pressure now only stop when memory is critically low, with the debug log clearly recording the reason.

This is like a coolant temperature warning light on a car dashboard: a red light alerts the driver for inspection only when the radiator is truly overheating, rather than stalling the engine randomly during normal driving.

MCP Connection Protocol Upgrades and Flexible Startup Wait Time Configuration

The boarding gate announces a final boarding cutoff, departing promptly once time is up while luggage arriving later is sent on the next flight.

Non-interactive mode can now set the maximum wait time for connecting MCP (Model Context Protocol) servers during the first turn via CLAUDE_CODE_MCP_STARTUP_WAIT_MS. When using --strict-mcp-config with an empty --mcp-config, the first turn no longer gets held up waiting to time out on incidental servers. In streaming JSON sessions, deferred tool search tools no longer stall first-turn startup. Environments such as Bedrock, Vertex, and Foundry now adopt the v2 client and the latest protocol negotiation by default. Invalid SDK server entries in configuration files are skipped with a warning.

Clear Reporting for MCP Tool Permissions and Safe Masking of Sensitive Variables

When calling external extension tools, if a request is refused by the server due to insufficient permissions, the error message now clearly names the missing permissions and points to /mcp re-authentication instead of misreporting an expired sign-in. Connection error logs and the login tool description no longer leak resolved secret strings from environment variables. Servers using legacy HTTP and SSE protocols now connect properly even when returning error codes. Streamable tool calls are no longer bound to a fixed timeout and won't time out early. Prompts and resources update immediately when a server sends list-changed notifications.

This is like customs returning a package with a clear checklist of missing documents and counter guidance while proactively redacting personal information, rather than mistaking missing paperwork for an expired passport.

OpenTelemetry Telemetry Logging Upgrades for More Transparent Request Tracing

This is like upgrading the indexing labels on a flight recorder: every conversation and request precisely logs its flight number and fuel metrics, making post-flight review crystal clear.

System telemetry now adds an effort attribute to LLM request traces. Through the new managed settings resolved event, administrators can clearly track configuration sources and policy status, and setting the environment variable OTEL_LOG_MANAGED_SETTINGS=1 automatically redacts sensitive setting values and digests in logs. When exporting raw request bodies to local files, the newly generated index.jsonl file and event attributes accurately link each model response to its corresponding request file and transcript message.

Configurable Timeout for Enterprise Apps Gateway and Graceful Shutdown for In-Flight Requests

The Claude apps gateway now supports adding store.connect_timeout_seconds in its configuration to lengthen the database connection timeout. If the database connection experiences a slight delay during boot, the gateway actively retries the connection up to three times, and clearly points to the configuration location if unreachable. When the server receives a shutdown signal, it no longer forcefully cuts open streams, instead waiting up to twenty-five seconds for in-flight requests to complete transmission smoothly.

This is like a restaurant at closing time not abruptly turning off the lights to rush customers out, but rather leaving ample time for the last seated guests to finish their meal gracefully.

Enhanced Gateway Load Warnings and Streamlined Spend Limit Checks

The Claude apps gateway now issues an active load warning when open connections exceed two hundred and fifty-six, and includes identity information in telemetry data. Under high load, the spend-limit check is simplified from four database round trips to one, effectively reducing timeout risks; if the database drops a connection during the check, the system properly handles the exception. When a user triggers sign-in rate limits at /login, the interface clearly explains the refusal reason, while gateway logs flag which limit was hit and suggest which setting to change.

The entire management is like a smart queuing system in a bank lobby: dispatching extra counters when crowds surge and merging multi-step verification into a single teller visit.

Long-running tasks driven by hooks automatically compact the conversation when context overflows again after previous compaction. For instance, an active /goal will not lose its ongoing objective when resuming a compacted session. Ordered lists entered in messages are no longer forcefully renumbered. Stop prompt hooks that trigger repeatedly now display with a concise label.
