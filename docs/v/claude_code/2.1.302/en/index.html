Claude Code 2.1.302

Released: 2026-10-16

Release notes

FEATURE

Auto mode classifier supports custom models, extra-long conversations no longer rejected outright

When you enable auto mode (a mode that lets Claude execute tools autonomously without asking each time) to handle heavy and complex tasks, you can now customize the model used by the local safety classifier. Through the environment variable CLAUDE_CODE_AUTO_MODE_MODEL, you can specify the model for the client-side classifier while the server-side model remains unchanged. When a conversation is too long and exceeds the scope of server-side safety checks, it is now compacted first instead of rejecting tool calls outright.

A quality inspector at a restaurant kitchen pass previously turned away an entire table whenever an order ticket was too long, but now consolidates the order first while the head chef can designate a review assistant.

An issue where most auto mode classifier block events failed to record classifier_category has been fixed. Another issue where newly added attributes crowded out tool_use_id, tool_source, and tool_parameters when OTEL_LOGRECORD_ATTRIBUTE_COUNT_LIMIT was set low has also been resolved.

FEATURE

/config adds idle compaction toggle, stopping midway no longer reports length error

When you leave a conversation window idle for too long, you might notice that Claude automatically reorganizes earlier message history. The /config settings menu now includes an "Idle compaction" option so you can freely enable or disable automatic idle compaction, and the notice displayed after reorganization finishes now explains how to turn it off. Previously, if you stopped generation midway while a conversation was being compacted, the screen would throw a "Prompt is too long" error; this issue has now been resolved.

Think of a plant greenhouse equipped with scheduled misting: forcing a pause mid-spray previously triggered a pipeline overpressure alarm, but the control panel now adds a shutoff switch with guidance and accurately records settings even for custom nutrient tanks.

If your gateway uses prefixed Opus 4 or 4.1 names (such as anthropic/claude-opus-4-1), running /autocompact and /effort has also been corrected to save to the proper model.

BUGFIX

Chrome extension instructions share cache, dynamic tool loading no longer misses

When you start a new conversation, operating instructions for Claude in Chrome can now be read from a shared prompt cache. Claude adjusted the placement of these instructions within the system prompt so that new conversations can share the existing cache.

Picture a central restaurant kitchen moving popular stock to a shared prep station: where every new dish previously required simmering broth from scratch and grabbing fresh spices mid-cook risked spilling ingredients, every chef can now immediately access ready-made base stock.

Tools added dynamically midway through a session will no longer suffer cache misses, even after being reloaded via ToolSearch or undergoing conversation compaction.

FEATURE

Claude Design shows sunset date notices, cloud failures route to dedicated settings

If you regularly use UI design commands in your terminal, you will now see more accurate timelines and guidance notices during related operations. When you enter /design-sync or /design-login, the screen adds a notice explaining that the standalone web version of Claude Design is scheduled to shut down on December 14, 2026.

Consider a ferry terminal posting advance signs to announce that an old waiting room will soon close: where ticketing issues on floating island ferry routes previously misdirected passengers back to landside counters, the sign now directly provides an online management URL and an exact date.

When executing /design consent and /design revoke fails in a cloud session, the error message now points you to claude.ai/design/settings instead of recommending unusable login commands.

BUGFIX

Plugin loading speed noticeably improved, config writing and command compatibility fixed

When you have many plugins installed for a project, launching Claude Code now comes with noticeably shorter wait times. The system has reduced filesystem calls when reading plugin commands and agent files, an improvement that is especially noticeable on Windows. Previously, when executing subcommands like claude plugin, the process would occasionally exit before configuration file writes finished, causing lost changes or leaving behind .tmp temporary files; it now ensures writes complete before exiting. When Git defaults to the reftable reference format, the marketplace no longer repeatedly re-downloads entire repositories on every refresh, nor do newly installed plugins display an unknown version. PowerShell tools can now smoothly invoke commands under a plugin's bin/ directory, piping into formatting commands when search results are empty no longer throws errors, and failures when querying builtin plugins correctly point to /plugin.

BUGFIX

MCP protocol compatibility upgraded, desktop re-authentication guidance made more accurate

When using external tools in the desktop app, you will now receive guidance that perfectly matches your current interface if re-authentication or reconnection is required. Previously, when desktop Claude needed to reconnect to an MCP (Model Context Protocol, a protocol that connects AI to external tools) server, it misdirected you to check web settings or run the /mcp command, even though neither option existed in that environment; this guidance has now been corrected.

Just as pairing an environmental sensor with smart home appliances previously dropped the entire connection when optional parameters were missing while prompting users toward nonexistent buttons, omitting non-core values now maintains normal operation while offering accurate indicator light guidance.

Meanwhile, when an external server negotiates protocol version 2026-07-28 without providing optional fields such as resultType, ttlMs, or cacheScope, the tool list no longer goes blank, and tool calls no longer fail completely.

FEATURE

Forked subagents enabled by default, background execution rules aligned across interfaces

When using Claude in the desktop app, VS Code, or programmatically, rules for handling multiple tasks in parallel are now unified with the terminal. Forked subagents (subagent_type: "fork") are now enabled by default in claude -p, the Agent SDK, desktop, and VS Code; to disable them, set CLAUDE_CODE_FORK_SUBAGENT=0, while claude mcp serve does not offer them. Subagents in main conversations on desktop and VS Code now always run in the background rather than being decided by the model, whereas agent calls initiated by subagents run in the foreground by default. An issue in the viewer where scrolling long lists or collapsing groups resulted in highlighted blank lines has been fixed, and the bottom ← for agents hint text now automatically hides 10 seconds after a session opens, leaving only a count of pending agents.

FEATURE

Third-party cloud headless mode permissions default to default, switching providers no longer errors

When calling Claude on enterprise cloud platforms via the CLI or SDKs, switching provider channels midway through a session will no longer stall. Previously, switching to Vertex AI or Bedrock in the middle of a session frequently failed due to mismatched input parameters (diagnostics: Extra inputs are not permitted); this compatibility issue is now resolved. On third-party providers, if no permission mode is specified and telemetry is disabled or the setup is a fresh install, claude -p and Agent SDK sessions will start with default, requiring an explicit --permission-mode auto to maintain automatic approvals. When reopening background sessions from other folders that lack a model gateway, the system now specifically explains why the connection failed instead of vaguely reporting that you are not logged in.

FEATURE

Concurrency limits added for prompt and agent hooks, executing at most 12 per event

When your automation workflow sets up many custom interception commands for the same event, you can keep track of which are currently executing and which are still waiting. Prompt and agent hooks (small programs triggered by specific events) now have a concurrency limit: at most 12 can run concurrently for the same event, with remaining hooks waiting their turn. This limit is calculated on a per-event basis.

A car wash arranges cleaning bays for incoming batches of vehicles: at most 12 cars can now be washed simultaneously in the same batch, while remaining vehicles wait at the entrance until a bay clears for the next one in line.
BUGFIX

Windows external drive writes no longer rejected, Git orphaned files and fetch fixed

When working on projects across different operating systems or specialized disk formats, file modifications and version control will now run much more smoothly. On Windows, if a project is located on an exFAT or FAT32 partition—including sessions started with the --plugin-dir flag—file writes that were previously rejected by the system or triggered frequent confirmation prompts have had their permission misjudgments fixed. In Git 2.56 or newer, if a directory retains an orphaned .git file pointing to a nonexistent path, the worktree (a Git feature for maintaining multiple copies of the same project in parallel) isolation mechanism no longer refuses to create or restore worktrees. For self-hosted runners that reuse checkout directories formatted with reftable, running git fetch to retrieve data will no longer fail due to object errors.

Like filing engineering blueprints into a nonstandard binder that previously rejected entire folders over mismatched loose-leaf rings or leftover scrap labels, the system now cleanly recognizes divider pockets and properly stores documents.
BUGFIX

Wrapped terminal hyperlinks are fully clickable, and emojis no longer break table layouts

When you browse long URLs or text containing icons output by Claude in the terminal, visual presentation and click experiences are now much cleaner. Previously, when an extra-long URL wrapped in backticks wrapped across lines, only the first line was clickable in terminals that support hyperlinks. Now, the entire URL is consolidated into a single clickable link. When a link started inside an emoji, the wrap width counted an extra character cell, causing that emoji to be hidden in question previews and turning tables into lists. These issues are now fixed.

A vintage printing press receives a fine kerning tune-up: previously, hitting a special emblem stamp misaligned an entire table row and splitting a long address across two lines left only half a barcode readable, whereas now the layout stays neatly aligned and barcodes scan on contact.
BUGFIX

Cloud session costs no longer reset during accumulation, and credit plans skip extra suggestions

When you monitor account quota consumption or continue projects in the cloud, usage and cost tracking are now more precise. If your subscription plan charges for specific models solely via extra credits, Claude automatically skips follow-up prompt suggestions after answering the query and deducting credits, preventing silent credit consumption in the background. Meanwhile, when a cloud session resumes in a new process, previously accumulated costs and usage no longer reset to zero.

An automated parking garage gate upgrades its billing software: previously, rebooting the system wiped earlier parking hours back to zero and hourly premium spots automatically pushed unneeded add-ons, whereas now billing tracks every cent without omission and spending remains crystal clear.
BUGFIX

Read tool sets image size limit, directly rejecting sources over 128 MB

When you ask Claude to read local images, the source size determines whether it loads. Previously, the Read tool (a utility for inspecting file contents) loaded image files of any size, or pipes and devices named like images, entirely into memory. Now, image sources exceeding 128 MB are rejected from loading.

BUGFIX

Artifact publishing supports empty modifications, and version conflict retry logic is fixed

When you have Claude dynamically generate or modify display artifacts in conversation, the publishing flow is no longer interrupted by minor glitches. When publishing an artifact (a standalone display panel or code file), the system no longer fails if Claude transmits an empty list of modifications. Meanwhile, if a newer version of an artifact was already created elsewhere while an update was being submitted, Claude no longer blindly retries in an erroneous manner upon rejection, but follows the proper retry mechanism to update content.

Submitting revised blueprints to a municipal office follows new intake protocols: previously, attaching the original diagram without textual edits triggered an outright rejection, and having someone else register a newer revision first led to frantic, blind resubmissions, but now zero-change submissions are accepted cleanly and version conflicts trigger a proper re-review.
FEATURE

Prompt message redirects to GitHub when organizations disable the feedback command

When using the terminal in a corporate or enterprise-managed team environment and looking to share suggestions about tool features, notice the prompt shown by the feedback command. When your organization's administrative policy disables the /feedback command, the on-screen message now directs you to GitHub issues (a page used to submit bug reports), instead of asking you to contact an internal organization admin.

When an apartment complex decommissions its resident suggestion box, a replacement notice posts a different forwarding address: whereas the notice once pointed to the building manager's office, it now points directly to an issue submission form so residents know exactly where to deliver feedback.
BUGFIX

Remote Control clearly marks offline status, and help remains accessible while logged out

When managing sessions across devices through Remote Control, connection status is now clear at a glance. If your computer goes offline during a remote connection, the subagent panel in the interface no longer spins indefinitely, but clearly shows that the Remote Control connection has dropped.

Piloting an aerial drone mirrors this communication flow: previously, losing the base station signal left the controller screen stuck forever on a loading spinner, and operating without an account hid all manual instructions, but now disconnections prompt an explicit alert and help documents stay readable without signing in.

Meanwhile, if you run claude remote-control --help without being logged in to an account, the system now prints complete command usage and exits cleanly, instead of hanging unresponsive.

BUGFIX

[VSCode] Browser connection status calibrated, and unclosed code block streaming fixed

When viewing Claude's responses while connecting peripheral tools inside the VS Code editor, visual display and connection status are now more accurate. Previously, even when unable to connect to any browser with the Claude extension installed, the @browser banner at the top mistakenly reported "Browser connected". Now, connection status is calibrated to reflect actual conditions. When an MCP server URL contains a query string, completing login authorization from the panel no longer opens a broken authentication webpage. If a list item contained an unclosed code block, a rendering glitch where subsequent text briefly displayed as plain text before abruptly snapping into code during streamed generation has now been completely fixed.

Status indicators on a server room monitoring panel demonstrate this visual fidelity: previously, the panel falsely signaled a successful link without connecting to external instruments and live captions flickered erratically upon encountering unclosed tags, whereas now connection lights faithfully reflect reality and streamed text renders without a hitch.
BUGFIX

[Cloud sessions] Unstarted routine reasons now visible, with status determination and duplicate executions fixed

When configuring automated routines in the cloud to run reports or analyses, task execution histories are now more dependable. On the routine management page, if the previous run failed to start properly, a prominent banner at the top now details the specific reason, such as the organization reaching its concurrent cloud session limit. Previously, unexpected interruptions in a cloud session caused the task status to be misrecorded as completed. If a task was archived before starting, it was erroneously displayed as canceled. Now, these edge cases are properly marked as failed. Meanwhile, when a scheduled task fails midway, the system no longer takes it upon itself to restart from scratch an hour or more later, preventing duplicate reports or repeated billing charges.

Operating an automated factory dispatch board reflects this strict accounting: previously, machine crashes were falsely recorded as on-time completions, unstarted work orders pulled from the queue were marked as canceled, and mid-shift power cuts triggered quiet reruns that wasted raw materials, whereas now malfunction causes are crystal clear and status reports remain strictly accurate.
BUGFIX

[Cloud sessions] History rewind and cross-device sync fixed, with precise launch failure messages

When collaborating with teams in cloud sessions through a browser, multiple operations and interface sync mechanisms are now smoother. When clicking "Rewind to here" inside a session, previously only the latest message worked while all others failed, but now every historical checkpoint rewinds smoothly. Self-hosted runners require Claude Code v2.1.246 or later. When a pull request encounters merge conflicts, the status line no longer briefly flashes back to a ready state during GitHub re-reviews. When a GitHub repository is renamed or moved, issues where the diff view missed modifications or failed to load have been resolved. Meanwhile, messages sent from another device now appear instantly on open pages without requiring a manual refresh. If a session fails to launch, error messages now explicitly indicate "Connection lost" or a server error instead of staying vague.

BUGFIX

[Claude Tag] Slack message formatting and image attachments fixed, preventing premature direct message drops

When tagging Claude for assistance in Slack channels or direct messages, conversation formatting and file-sharing experiences are now much more reliable. Images uploaded to Slack in formats such as HEIC, SVG, TIFF, and BMP now pass properly to Claude as working files instead of getting lost. When Claude answers a question by editing an earlier message, the "is thinking…" indicator below the tag clears properly rather than lingering permanently. URLs inside code blocks attached under list steps are no longer wrapped in superfluous angle brackets, allowing copied commands to be pasted directly. Hyperlinks in responses no longer absorb trailing bold markers, italics, or full-width punctuation into the URL and break formatting. When a direct message encounters a delay in a single Slack lookup, the system now proactively retries first, rather than immediately replying that direct messages are unavailable and discarding the request. In Slack Enterprise Grid, direct messages run in whichever connected workspace where you most recently opened Claude.

FEATURE

[Claude Tag] Admin Interface Reorganized into Four Tabs, Accelerating Repository and Channel Search

When administrators adjust Claude authorization scopes and connection channels in the admin console, permissions are now neatly organized. The Claude Tag admin interface has been reorganized into four tabs: Bundles, Connectors, Skills and plugins, and Channels, making permission categories clear at a glance. Repository search performance has noticeably improved, now covering up to 100 connected GitHub accounts and searching private repositories beyond the first 5,000 indexed by GitHub App installations. In the add location feature, manually entering or pasting a channel name immediately displays that channel without waiting for the organization's full channel list to load. The "Add > Domain" option on workspace or channel pages is ready as soon as the current page finishes loading, without waiting for all channels to load.

A modern logistics dispatch console mirrors this upgrade: where staff once waited for a full warehouse inventory count before selecting a shelf, dedicated tabs now surface the matching storage rack immediately upon entering an item code, notably improving dispatch efficiency.
FEATURE

[Claude Tag] Channel Manager Role Granted Automatic Permissions, Shared-Host Connectors Displayed Independently

When enterprises strictly control Claude usage permissions across different team roles, configuration rules for administrator roles and external tools are now thoroughly clarified. In organizations with restricted role permissions, newly appointed channel managers previously could lose access to Claude in Slack. The manager role now automatically includes access authorization for Claude Tag. The roles page in organization settings has also been tidied up, consolidating roles created for channel managers into a collapsible section beneath existing organization roles for a much cleaner layout. If multiple MCP servers share the same host address, the admin console no longer mistakenly merges them into a single connector, displaying each server independently instead. When a channel reaches its monthly spend cap, the system notice no longer mistakenly claims that channel managers can increase quotas, instead clearly identifying organization owners with a link to the usage page.

Department store administration reorganizes vendor registries in a similar way: floor managers assigned to new counters previously lost register privileges and brands sharing a warehouse were lumped into a single booth, but supervisory roles now activate access automatically, each brand is listed independently, and spending approval contacts are clearly identified.
FEATURE

[Code Review] Setup Automatically Restores After Connecting GitHub, Reopening Directly to Repository Selection

When configuring Code Review workflows in the admin console, redirecting mid-process for authorization no longer loses your initial progress. Previously, leaving the setup workflow to connect a GitHub account prevented the admin console from automatically restoring progress upon return, often requiring a fresh start. This redirection interruption is now resolved, reopening directly to the repository selection screen upon return so you can smoothly resume setup.

Travelers completing an immigration entry form experience the same relief: previously, redirecting to verify identity wiped all entered details upon return, but the system now faithfully preserves form progress and reopens directly at the destination selection step.
