Claude Code 2.1.302

發布日期：2026-10-16

繁體中文

新功能

自動模式分類器支援自訂模型，超長對話不再一律拒絕

當你開啟自動模式（auto mode，讓 Claude 不逐一詢問就自主執行工具的模式）處理繁重複雜的任務時，現在能自訂本機安全分類器使用的模型。透過環境變數 CLAUDE_CODE_AUTO_MODE_MODEL，可指定用戶端分類器的模型，伺服器端模型不變。對話太長而超出伺服器端安全檢查範圍時，現在會先壓縮，不再一律拒絕工具呼叫。

宛若餐廳出餐口的品管員，以前點單太長就整桌退單，現在先整併菜單，主廚也能指定審查助手。

多數自動模式分類器阻擋事件漏記 classifier_category 已修復；OTEL_LOGRECORD_ATTRIBUTE_COUNT_LIMIT 較低時，新增屬性擠掉 tool_use_id、tool_source、tool_parameters 的問題也已修復。

新功能

/config 新增閒置壓縮開關，中途停止不報長度錯誤

平時讓對話視窗閒置太久時，你可能會發現 Claude 自動整理了先前的發言紀錄。現在 /config 設定選單新增了「Idle compaction」選項，方便你自由開啟或關閉閒置自動壓縮；整理結束後的提示也會主動說明關閉方式。以前若在對話正在整理壓縮時中途停止回答，畫面會跳出提示詞過長（Prompt is too long）的錯誤；現在這個問題已經修好。

好比植物溫室裝了定時微霧噴灑，以前灑水途中硬按暫停會觸發管線超壓警報，現在不僅在控制箱加上開關與關閉說明，面對特殊規格的養液槽也能精準記錄設定。

若你的閘道使用了帶有前綴的 Opus 4 或 4.1 名稱（例如 anthropic/claude-opus-4-1），執行 /autocompact 與 /effort 也已修正為儲存至正確模型。

問題修復

Chrome 擴充指令共享快取，動態工具載入不再漏命中

當你開啟新的對話時，Claude in Chrome 的操作指引現在能從共用提示詞快取讀取。Claude 調整了這些指引在系統提示詞中的擺放位置，讓新對話能共用既有的快取（cache，把算過或查過的結果暫存起來直接用）。

如同餐廳中央廚房把常用高湯移至共用檯面，以前每開一鍋新料理就要重新熬煮，途中拿取新香料還會打翻備料，現在每位廚師都能即時取用現成底料。

在工作階段中途動態加入的工具，即使經過 ToolSearch 再次載入或對話壓縮，也不會再發生快取未命中的問題。

新功能

Claude Design 提示服務退場時間，雲端失敗導向專屬設定

若你平時習慣在終端機使用介面設計指令，現在執行相關操作時會看見更準確的時程與導引提示。當你輸入 /design-sync 或 /design-login 時，畫面會新增提示，說明獨立網頁版 Claude Design 預計於 2026 年 12 月 14 日關閉服務。

猶如渡輪碼頭提前立牌預告舊候船室即將停用，以前在離島浮動船班上遇到票券問題還被誤導回陸上窗口，現在告示直接附上線上管理網址與確切日期。

在雲端工作階段執行 /design consent 與 /design revoke 失敗時，提示訊息也已改為指引至 claude.ai/design/settings，不再建議無法使用的登入指令。

問題修復

外掛程式載入速度明顯提升，設定寫入與指令相容性修復

當你為專案安裝了大量外掛程式時，現在啟動 Claude Code 會感覺到等待時間明顯縮短。系統減少了讀取外掛指令與代理檔案時的檔案系統呼叫次數，這項改進在 Windows 環境尤其有感。以前執行 claude plugin 等子指令時，程式偶爾會在設定檔寫入完成前提早退出，導致變更遺失或殘留 .tmp 暫存檔，現在已確保寫入完成才結束。當 Git 預設採用 reftable 引用格式時，市集不再每次重整都重複下載整個倉庫，新裝外掛也不會顯示版本未知。PowerShell 工具現在能順利呼叫外掛 bin/ 目錄下的指令，搜尋為空時串接格式化指令不再噴錯，查詢內建外掛失敗時也正確指引至 /plugin。

問題修復

MCP 協定相容性升級，電腦版重新授權引導更準確

當你在桌面應用程式中使用外部工具，若需要重新授權或連線，現在會得到完全符合當前介面的操作指引。以前桌面版 Claude 在需要重新連接 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器時，會誤導你去翻找網頁版設定或打 /mcp 指令，即使該環境根本沒有這些選項；現在這項引導已修正。

比方替智慧家電配對環境感測器，以前感測模組少了選填參數就整組斷線，螢幕還提示你去按根本不存在的按鈕，現在缺漏非核心數值照常運作並給出準確燈號指引。

同時，當外部伺服器協商使用 2026-07-28 協定版本，但未提供 resultType、ttlMs 或 cacheScope 等非必要欄位時，工具清單不再一片空白，呼叫工具也不會全數失敗。

新功能

分叉子代理預設開啟，背景執行規則跨介面對齊

在桌面應用程式、VS Code 或是透過程式呼叫 Claude 時，分頭處理多項任務的規則現在與終端機統一。分叉子代理（subagent_type: "fork"）在 claude -p、Agent SDK、桌面版與 VS Code 改為預設開啟，若要關閉可設 CLAUDE_CODE_FORK_SUBAGENT=0，claude mcp serve 則不提供。桌面版與 VS Code 主對話的子代理現在固定在背景執行，不再由模型決定；子代理發起的代理呼叫則預設在前景執行。檢視畫面中捲動長清單或摺疊分組後內容反白空行的問題已經修復，底部的 ← for agents 提示文字也會在工作階段開啟 10 秒後自動隱藏，僅保留等待處理的代理數量計數。

新功能

第三方雲端無頭模式權限預設為 default，切換通道不再報錯

平時在企業雲端平台透過指令或程式庫呼叫 Claude 時，中途切換供應商通道不再卡關。以前在工作階段進行到一半時切換至 Vertex AI 或 Bedrock，請求容易因輸入參數不符（diagnostics: Extra inputs are not permitted）而失敗，這項相容性問題現已修復。在第三方供應商上，若未指定權限模式，且關閉遙測或屬於全新安裝，claude -p 與 Agent SDK 工作階段會以 default 啟動，若要維持自動授權需明確加上 --permission-mode auto。從其他資料夾重新開啟背景工作階段若缺少模型閘道，系統現在會具體說明無法連線的原因，不再含糊顯示未登入。

新功能

提示詞與代理掛鉤加入並行上限，同事件最多執行 12 個

當你的自動化工作流替同一事件設定了許多自訂攔截指令時，可以留意哪些正在執行、哪些仍在等待。提示詞與代理掛鉤（hook，特定事件發生時被觸發的小程式）現在有了並行上限：同一事件最多同時執行 12 個，其餘掛鉤等待輪到自己。這個數量是按每個事件計算。

洗車場替每批進場車輛安排清洗位置；現在同一批最多有 12 輛同時清洗，其餘車輛先在入口等待，有位置才輪到下一輛。
問題修復

Windows 外接磁碟寫入不再遭拒，Git 孤立檔案與抓取修復

當你在不同作業系統或特殊磁碟格式下編寫專案時，現在檔案修改與版本控制會順暢許多。在 Windows 環境中，若專案位於 exFAT 或 FAT32 格式的磁碟槽上，包含加上 --plugin-dir 參數啟動的工作階段，以前每次寫入檔案都會遭到系統拒絕或頻繁彈出確認，現在這項權限誤判已經修好。在 Git 2.56 或更新版本中，若目錄殘留了指向不存在路徑的孤立 .git 檔案，工作樹（worktree，Git 讓同一專案平行開多份副本的功能）隔離機制不再拒絕建立或復原工作樹。對於自架執行器（self-hosted runner），若重複使用 reftable 格式的簽出目錄，git fetch 抓取資料時不再因物件錯誤而中斷。

像在特殊規格的檔案夾內整理工程圖紙，以前遇到活頁扣環不同或殘留廢棄標籤便整本拒收，現在能順暢辨識夾層並落實歸檔。
問題修復

終端機超連結折行完整可點，表情符號不再破壞表格排版

當你在終端機瀏覽 Claude 輸出的長網址或包含圖示的文字時，現在視覺呈現與點擊體驗都更加俐落。以前包裹在反引號內的超長網址若跨行折行，在支援超連結的終端機裡往往只有第一行可以點擊；現在整段網址已整合成一個完整的點擊連結。連結起點落在表情符號（emoji）內時，折行寬度會多算一個字元欄位，造成該表情符號在問題預覽中被隱藏，並讓表格變成清單；這些問題已修復。

恰如老式鉛字排版機完成了字距微調，以前遇到特殊圖案印章就讓整行表格破版走位，長網址切成兩行也只能掃出半張條碼，現在版面工整對齊且條碼隨點即通。
問題修復

雲端工作階段費用累計不歸零，點數方案跳過額外建議

當你關注帳戶的額度消耗或在雲端持續進行專案時，現在用量與成本統計變得更加精準。如果你的訂閱方案針對特定模型僅能以額外點數計費，Claude 在回覆該次提問並扣除點數後，會自動跳過後續的提示建議，避免在背景悄悄消耗你的用量點數。同時，雲端工作階段在新的行程中恢復時，先前累積的費用與用量不再歸零。

正如智慧停車場的計費閘門，以前系統重開機就會把前段停車時數歸零重算，遇到以時計費的特殊車位還會自動推銷非必要服務，現在費用結算分文不漏且消費透明清楚。
問題修復

讀取工具設下圖片大小上限，超過 128 MB 直接拒載

當你請 Claude 讀取本機圖片時，來源大小會影響它是否載入。以前讀取工具（Read tool，用來查看檔案內容的工具）會把任何大小的圖片檔，或名稱像圖片的管道、裝置，整份載入記憶體。現在超過 128 MB 的圖片來源會被拒絕載入。

問題修復

成果物發布支援空修改，版本衝突重試邏輯修復

當你讓 Claude 在對話中動態生成或即時修改展示成果物時，發布過程不再因為小意外而中斷。成果物（artifact，獨立生成的展示面板或程式碼檔案）在發布時，若 Claude 傳送了空的修改清單，系統不再判定失敗。同時，若某份成果物在送出更新的過程中已由其他地方產生了更新的版本，遭到退件後 Claude 也不會再以錯誤的方式盲目重試，而是會遵循正確的重試機制更新內容。

好比向機關送審修訂藍圖，以前就算只是附上原圖無文字修改也會被拒收，遇到他人搶先登記新版次時還會胡亂重複遞件，現在既能順利接收無修改發布，遇版本衝突時也能按規範重新審查。
新功能

組織停用回饋指令時，提示訊息改為引導至 GitHub

當你在公司或企業受管的團隊環境下使用終端機，若想對工具功能提出建言，可以留意回饋指令顯示的提示。當所屬組織的管理政策關閉了 /feedback 指令時，畫面上的訊息現在會引導你前往 GitHub issues（用來提交問題的頁面），不再要求你聯絡內部組織管理員。

比方公寓大樓的住戶意見箱停用後，公告改貼另一個收件地址；以前公告指向管理室，現在則指向問題回報表單，住戶照著新的指引就知道該往哪裡提交。
問題修復

Remote Control 離線明確標示，未登入仍可查詢說明

當你透過遠端操控（Remote Control）跨裝置管理工作階段時，現在連線狀態一目了然。如果你的電腦在遠端連線期間離線，介面中的子代理面板不再無止境轉圈等待，而是會明確顯示 Remote Control 連線已中斷。

跟操作空拍無人機一樣，以前主機訊號中斷時遙控螢幕只會永久卡在載入圖示，未登入帳號時也看不到指令說明；現在斷線會顯示中斷提示，未登入仍可查看指令說明。

同時，若你在尚未登入帳號的狀態下執行 claude remote-control --help，系統現在會正常印出完整的指令用法並順利退出，不再異常無反應。

問題修復

[VSCode] 瀏覽器連線狀態校正，未閉合程式碼串流修復

當你在 VS Code 編輯器中一邊檢視 Claude 的回答一邊連接周邊工具時，現在畫面顯示與連線狀態都更為精準。以前即使根本無法連線到任何安裝了 Claude 擴充功能的瀏覽器，頂部的 @browser 橫幅仍會誤報「Browser connected」；現在連線狀態已校正為真實情況。當 MCP 伺服器的網址中帶有查詢字串（query string）時，從面板進行登入授權不再開啟損壞的驗證網頁。在清單項目中若包含尚未閉合的程式碼區塊，答案串流生成時後續文字一度先顯示為純文字再突兀跳成程式碼的渲染問題，現在也已徹底修正。

恰如機房監控面板的指示燈號，以前沒連上外接儀器就謊報連線成功，即時字幕遇到未結束的標籤還會閃爍跳動，現在連線燈號忠實反映現狀，文字串流輸出也流暢無瑕。
問題修復

[Cloud sessions] 排程任務未啟動原因上線，狀態判定與重複執行修復

當你在雲端設定例行排程任務（routine）讓系統自動跑報表或分析時，現在任務的執行履歷更加可靠。在 routine 的管理頁面上，若上次執行未能順利啟動，頂部現在會以醒目橫幅具體說明原因，例如組織已達到同時並行雲端工作階段的上限。以前如果雲端工作階段發生非預期中斷，任務狀態會被誤記為已完成。若在啟動前就遭封存，則會錯誤顯示為已取消。現在這些異常情境均已正確改標記為失敗。同時，當排程任務中途失敗時，系統不會再於一小時或更久之後自作主張從頭重跑，避免重複寄送報告或造成重覆扣款。

猶如無人工廠的排程派工看板，以前遇到機台當機卻謊報準時完工，未動工就被撤除的工單也標成取消，中途斷電還會悄悄重做造成原料浪費，現在故障原因一目了然且狀態精確無誤。
問題修復

[Cloud sessions] 歷史倒轉與跨裝置同步修復，啟動失敗精確提示原因

當你透過瀏覽器進入雲端工作階段與團隊協作時，現在多項操作與介面同步修復得更加平穩。在工作階段中點擊歷史倒轉（Rewind to here）時，以前只有最新一則訊息有效、其餘皆會失敗，現在所有歷史節點都能順暢倒轉；若使用自架執行器則需搭配 Claude Code v2.1.246 或更新版本。當 Pull Request 發生合併衝突時，狀態列不再於 GitHub 重新複查期間短暫跳回準備就緒狀態。當 GitHub 儲存庫被重新命名或移動位置後，差異檢視（diff view）遺漏修改或載入失敗的問題已排除。同時，從另一台裝置傳送的訊息現在會即時出現在已開啟的頁面上，不必再手動重新整理網頁。若工作階段啟動失敗，錯誤訊息改為明確顯示連線中斷（Connection lost）或伺服器錯誤，不再含糊籠統。

問題修復

[Claude Tag] Slack 訊息格式與圖片附件修復，私訊不再輕易中斷

當你在 Slack 頻道或私訊中標記 Claude 協助工作時，現在對話格式與傳檔體驗都更加健全。在 Slack 中上傳 HEIC、SVG、TIFF 與 BMP 等格式的圖片，現在會作為工作檔案正常傳遞給 Claude，不再遺失。當 Claude 透過編輯舊訊息回答問題後，標記下方的「is thinking…」提示會正確消除，不再永久殘留。程式碼區塊內附在清單步驟下的網址不再被多餘的角括號包裹，複製指令可直接貼上使用。回覆中的超連結也不會再把後方的粗體、斜體符號或全形標點符號吃進網址內而造成破版。私訊遇到單次 Slack 查詢延遲時，系統現在會先主動重試，不再直接回覆私訊暫不可用並丟棄訊息。在 Slack Enterprise Grid 中，私訊會在你最近開啟 Claude 的那個已連接工作區執行。

新功能

[Claude Tag] 後台管理介面重整為四大分頁，儲存庫與頻道搜尋加速

管理者在後台調整 Claude 的授權範圍與連線通道時，各項權限現在被整理得井井有條。Claude Tag 後台管理介面重新梳理為四大分頁：Bundles、Connectors、Skills and plugins 以及 Channels，各項權限歸類一目了然。儲存庫搜尋效能明顯提升，現在最多可涵蓋 100 個已連結的 GitHub 帳號，並能搜尋超過 GitHub App 安裝前 5,000 個以外的私人儲存庫。在新增位置功能中，手動輸入或貼上頻道名稱時，系統能立即顯示該頻道，不必再苦等組織的完整頻道清單全數載入。工作區或頻道頁面中的「Add > Domain」選項，只要當前頁面載入完成便立即可用，不必苦等所有頻道載入完畢。

彷彿現代化物流倉儲的調度中控台，以前調閱貨架非得等全場庫存盤點完畢才能點選，現在分頁權責分明，輸入貨號隨即顯示對應料架，調度效率明顯提高。
新功能

[Claude Tag] 頻道管理員角色自動賦權，共用主機連接器獨立顯示

當企業針對不同團隊角色嚴格管控 Claude 的使用權限時，管理員身分與外部工具的設定規則現在徹底釐清。在限制角色權限的組織中，新任命的頻道管理員先前可能會失去在 Slack 使用 Claude 的權限；現在管理員角色已自動涵蓋 Claude Tag 的存取授權。組織設定中的角色頁面也進行了整理，為頻道管理員建立的角色現在會集中收納在組織既有角色下方的摺疊區塊中，版面乾淨許多。若多個 MCP 伺服器共用同一個主機位址，後台不再將其錯誤合併為單一連接器，改由每個伺服器各自獨立顯示。當頻道達到每月支出上限時，系統提示不再誤稱頻道管理員能調高額度，而是明確標明組織擁有者並附上用量頁面連結。

宛如百貨商場重新整頓專櫃廠商登錄簿，以前店長調派專櫃竟失去收銀權限，共用倉庫的品牌全擠在同一個櫃位，現在主管職務自動開通授權，各品牌獨立列管且額度審批窗口一清二楚。
新功能

[Code Review] 連接 GitHub 後自動恢復設定，重開直接回到選庫畫面

在後台設定程式碼審查（Code Review）流程時，中途跳轉授權不再弄丟原本的進度。以前在設定流程中如果中途離開頁面去連接 GitHub 帳號，返回管理後台時系統無法自動恢復進度，常常需要重新開始；現在這項跳轉中斷問題已經修復，返回後會直接重新開啟在儲存庫挑選畫面，讓你順利接續完成設定。

FEATURE

Auto mode classifier supports custom models, extra-long conversations no longer rejected outright

When you enable auto mode (a mode that lets Claude execute tools autonomously without asking each time) to handle heavy and complex tasks, you can now customize the model used by the local safety classifier. Through the environment variable CLAUDE_CODE_AUTO_MODE_MODEL, you can specify the model for the client-side classifier while the server-side model remains unchanged. When a conversation is too long and exceeds the scope of server-side safety checks, it is now compacted first instead of rejecting tool calls outright.

A quality inspector at a restaurant kitchen pass previously turned away an entire table whenever an order ticket was too long, but now consolidates the order first while the head chef can designate a review assistant.

An issue where most auto mode classifier block events failed to record classifier_category has been fixed. Another issue where newly added attributes crowded out tool_use_id, tool_source, and tool_parameters when OTEL_LOGRECORD_ATTRIBUTE_COUNT_LIMIT was set low has also been resolved.

FEATURE

/config adds idle compaction toggle, stopping midway no longer reports length error

When you leave a conversation window idle for too long, you might notice that Claude automatically reorganizes earlier message history. The /config settings menu now includes an "Idle compaction" option so you can freely enable or disable automatic idle compaction, and the notice displayed after reorganization finishes now explains how to turn it off. Previously, if you stopped generation midway while a conversation was being compacted, the screen would throw a "Prompt is too long" error; this issue has now been resolved.

Think of a plant greenhouse equipped with scheduled misting: forcing a pause mid-spray previously triggered a pipeline overpressure alarm, but the control panel now adds a shutoff switch with guidance and accurately records settings even for custom nutrient tanks.

If your gateway uses prefixed Opus 4 or 4.1 names (such as anthropic/claude-opus-4-1), running /autocompact and /effort has also been corrected to save to the proper model.

Tools added dynamically midway through a session will no longer suffer cache misses, even after being reloaded via ToolSearch or undergoing conversation compaction.
