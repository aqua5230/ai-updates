Claude Code 2.1.326

Released: 2026-11-16

Release notes

FEATURE

Agent teams can now use Code Mode

With multi-agent collaboration in agent teams enabled, you can now turn on Code Mode at the same time. If you already had Code Mode turned on, any session you start with agent teams will now launch directly in Code Mode without needing to switch manually.

Picture a mountaineering team tuning their radio channels before heading out: previously, two pieces of gear could not be switched on together, but now flipping the switch on the way out puts everyone straight onto the same channel.
FEATURE

Code Mode permission checks and prompt updates

When using Code Mode in auto mode, if a skill or slash command has an inline ! command that needs approval, Claude is now asked to run it instead of failing to load. Background subagents also no longer fail when preloading these skills. Permission checks for sandboxed commands have been tightened as well, so more commands now ask first or are refused outright. When Code Mode cannot be turned on, the message now explains what you can do. The $ shell helper also refuses certain inputs with an error without running anything.

FEATURE

Code Mode mod layout and folder safeguards

For those building Code Mode mods (custom extensions): the box component now supports horizontal scrolling, the text component adds max-lines and clipping options, and wrapped text no longer drops lines when truncated. Mods can now also call tools like Bash and Read through the Code Mode interface as expected. For general users, editing files in a session's mods folder now triggers prompts more often. Sandboxed commands can also write to fewer folders. If you are prompted on every edit, simply remove any links inside pointing to unreadable or network paths.

FEATURE

Default to auto mode when no mode is set

For organizations using the Claude Code + Cowork HIPAA configuration, terminal and VS Code sessions now start in auto mode by default. To turn off this default behavior, simply add disableAutoMode. If no mode is set and the organization's policy has not loaded yet, sessions also start in auto mode instead of falling back to Manual mode. Once settings finish loading, sessions that start in auto mode by default switch to the server-managed default mode; they only fall back to Manual mode if both settings and policy fail to load, or if the policy requires it.

Before a hotel receives a guest's special room-type memo, the front desk checks them in using the standard room process; once the memo arrives or the connection fails, they switch back to manual confirmation as required.
BUGFIX

Auto mode classifier and usage billing fixes

For organizations using the Claude Code + Cowork HIPAA configuration on a direct Anthropic API connection, actions are now checked by the server-side classifier, just like other organizations. An issue where stale settings from an older version could leave auto mode stuck on the local classifier—which counts toward usage—has also been fixed, so it no longer wastes your usage.

It is like handing review procedures previously logged in a personal ledger back to headquarters for unified inspection, while clearing out misrecorded rules left over from an earlier version.
FEATURE

Auto mode tightens wildcard allow rules

Some shell commands that previously ran directly in auto mode are now blocked. Wildcard allow rules that do not name a program or that start with $HOME are now ignored by auto mode, leaving the safety check to decide whether to allow them. Wildcard rules whose program path uses Windows backslashes are now also evaluated by the safety check and may be blocked, while exact-match rules still allow calls directly. Rules starting with .\ are planned to be restored later.

Customs officers no longer wave through blank declaration forms with no item name filled in; only packages with the exact item name clearly written can pass straight through.
BUGFIX

Managed settings updates for Claude Desktop and SDK

For teams and developers using managed settings: in Claude Desktop's Code tab, the subagent model specified in managed settings now overrides your personal setting, just like in the terminal. However, if those managed settings also specify a provider or gateway, it will not override. If the environment list under autoMode in managed settings omits "$defaults", it now replaces all built-in entries in Claude Desktop and Agent SDK apps as well. To keep the default protections, remember to add "$defaults" or copy the sensitive-target entries yourself.

A head office's team rules used to still defer to an employee's own settings or default list at the desktop branch, but now they override personal practices and replace the whole set there too.
FEATURE

Clearer warnings for settings write failures and syntax errors

If --allowedTools, --disallowedTools, or --tools contains an incomplete rule at startup, a warning now appears. When adding rules or folders via /permissions, a main-conversation tool prompt, or /add-dir, if the settings file cannot be written, the terminal no longer acts as if it were saved and instead issues a warning naming the file. When a settings file is saved with an error mid-session, a warning now names the file as well. If a settings file or .mcp.json has a JSON syntax error, the error message now points directly to the line and column.

BUGFIX

Fix crashes from managed setting key names and deep nesting

Previously, certain key names in managed settings could prevent Claude Code from starting or unexpectedly affect other managed settings files. This has been fixed, and managed settings now load normally. Values nested thousands of levels deep in settings files used to cause crashes or intermittent failures; now any value past 64 levels is dropped with a warning.

Like unwrapping a multi-layered gift box, the rule now rejects and flags anything that hasn't reached the bottom by layer 64, instead of prying it open until the whole table collapses.
FEATURE

OpenTelemetry telemetry updates for admins

For administrators managing OpenTelemetry telemetry data: a new environment variable OTEL_RESOURCE_INCLUDE_HOST (off by default) is now available. When enabled, telemetry resource attributes also include the host name and host ID. If a PreToolUse hook (a small program triggered by specific events) in managed settings directly refuses a tool call, it now reliably leaves both a decision event and a denial record. Cowork cloud sessions now wait until the first turn of conversation before sending an organization's telemetry data. Sessions that receive no messages send nothing, so counts may decrease.

Put another way, a shop now logs a visitor only when someone actually steps in to ask a question, instead of counting people who just push the door open for a quick look and leave.
FEATURE

Show reasons when hooks fail or block actions

When a Node or Python hook crashes, it previously printed only the first line of its stack trace; now the error is shown directly, and pressing Ctrl+O reveals up to 10,000 characters of output. If a PreToolUse hook returns exit code 127, the error message now reminds you that its check may not have run at all. Status colors in the transcript are also easier to tell apart: failed or timed-out hooks now appear in red, hooks that stop Claude appear in yellow, and the reason is listed right underneath.

FEATURE

Changes to hook input rewrites, blocking scope, and HTTP rules

When multiple PreToolUse hooks respond to the same tool call, rewritten input parameters now stay in effect in more cases. A hook's blocking decision now applies in more cases; if a hook previously always printed "decision": "block", it may start actually blocking calls after this update. Hooks from managed settings also have updated rules for how allowedHttpHookUrls and httpHookAllowedEnvVars apply. HTTP hooks now ignore Content-Length and Transfer-Encoding in their header settings, calculating the length from the request body instead.

FEATURE

Monitor points to error log file when timing out with no events

When using Monitor to watch a background process and it times out with no events, if the underlying command wrote errors to stderr, Claude is now proactively informed and given the path to the file holding the output.

FEATURE

Applying and explaining managed-mcp.json added mid-session

When an administrator adds managed-mcp.json while a session is in progress, MCP (a protocol that connects AI to external tools) servers stop loading. An explanatory message now appears on screen to tell you why the servers stopped. Settings added mid-session like this may now take effect at the next check, though you still need to restart any currently open sessions for them to apply in full.

When a school swaps its textbook list mid-semester, the next class gets an announcement explaining why the old books were dropped, though enrolled classes still need a fresh schedule to switch over completely.
BUGFIX

Fixes for /mcp connection status, canceling waits, and error hints

When you open /mcp in the terminal and a local stdio MCP server fails to start, the reason is now shown instead of leaving a blank screen. While a server is reconnecting, pressing Esc or pressing Ctrl+C twice closes the wait screen while the reconnect continues in the background. Enabling a slow server also shows progress, and pressing Enter a second time no longer disables it by mistake. When you make a configuration mistake with claude mcp add-json, it no longer replies with a generic invalid input message and instead points out what to change.

BUGFIX

Fixes for background MCP questions, copying links, and form navigation

When a background MCP task pops up a question, pressing Ctrl+C twice actually leaves the question to be answered later, so the hint text no longer mistakenly says "cancel". Pressing c to copy an MCP sign-in URL no longer leaves an extra c character in the paste field. When filling out an MCP server's input form, you can now use Tab and Shift+Tab to move between fields, and clearing a required field no longer leaves its checkmark behind.

BUGFIX

Fixes for mixed-up parallel MCP calls and tool search loading

When multiple MCP tools are called in parallel and two long results arrive in the same millisecond, reading one no longer picks up the other call's result. Searching for a tool by its exact name previously occasionally loaded a tool from a different MCP server; that is now fixed, though you may be asked to confirm again during the process. When two servers have very similar names, prompts no longer disappear unexpectedly. MCP tools that support multiple argument format branches previously showed Claude only the first format, whereas values like 42 can now be passed properly to a branch that accepts numbers.

Sorting mail at a busy post office counter used to put items in the wrong cubby whenever two large parcels arrived at once or recipients had similar names, whereas now every package lands in its proper slot.
FEATURE

Better error reporting for MCP auth failures and cloud disconnects

For MCP servers without a stored OAuth refresh token (an authorization credential), a failed headersHelper or one skipped in an untrusted folder previously caused other sessions to lose that server too. This is now fixed so other sessions are no longer affected. For developers integrating the SDK: if a tool call arrives right after the host removes an MCP server, it no longer mistakenly reconnects or asks for authentication. Claude is now notified if a remote MCP question is declined and the tool fails, or if a tool becomes unavailable after a cloud worker is replaced. If a cloud session is cut off after sending a call through its proxy, Claude is also told that the outcome is unknown.

FEATURE

Blocking tools from writing sign-in files and system device files

Security restrictions protecting sign-in credentials have been tightened. Claude's file tools now refuse writes to sign-in credential files such as .credentials.json. The Bash permission check is also stricter, prompting you first before more commands can touch Claude Code's sign-in credential files. Certain device and process files are now also blocked from file tools so the agent cannot read or write them freely.

Think of it as putting a lock on the drawer holding your passport and ID, so routine paperwork stays out and anyone reaching inside has to ask you face to face first.
FEATURE

Stricter permission checks for Bash, copy/move, and oversized commands

The Bash permission check now asks first for more commands and refuses them when no one can answer; some Bash commands on macOS that previously ran directly now ask or are refused as well. Some cp and mv commands now ask you before running. Even in bypass permissions mode, certain tool calls still require approval and are denied if no one answers. When a command has values too long for the Bash permission check to finish reading, it now asks first as well, and blocks the command if a deny rule may apply or no one can answer.

BUGFIX

Fix Bash file operation misreads and false danger warnings

Copying a file with cp used to be refused entirely whenever the source file was covered by an Edit deny rule; that is now fixed. grep in Bash also no longer silently skips some plain-text files. Transcripts used to mislabel file-deleting or overwriting commands like find -delete, cat a > b, or sort -o as a search or a read, and now categorize them properly. Some commands without rm that Claude Code cannot read reliably will no longer trigger the misleading "Dangerous rm operation" warning.

FEATURE

Tighter prompts and function limits for the PowerShell tool

The PowerShell tool commonly used on Windows now asks before running more commands; unattended runs refuse them unless an allow rule, auto mode, or bypass permissions mode allows them. Some commands now ask for confirmation even in bypass permissions mode, or get refused outright. Malformed PowerShell commands are also denied. If a command defines a function with the same name as a built-in command, it is now blocked as well so Claude can rename it and try again.

In a workshop where wrenches cannot share a label with power drills, risky moves still require a second check even if you hold an inspection-exempt pass.
FEATURE

Disable j and k keys in the macOS computer use permissions panel

When granting permissions and picking items to enable for computer use on macOS, pressing j and k no longer moves the cursor. Use the arrow keys or Ctrl+P and Ctrl+N to move up and down instead.

FEATURE

Restrict home folder writes and strengthen Bash sandbox isolation

Bash sandbox protections on macOS, Linux, and WSL are now tighter. Within the same session, the sandbox keeps its state in some cases until you run /sandbox or /cd; during that time, Bash may ask first. Sandboxed commands on macOS, Linux, and WSL no longer write to some sensitive home folders by default; if needed, specific paths can be allowed via allowWrite under filesystem in the sandbox section of user or managed settings. When auto-allow is off, command lines that set environment variables also prompt first, while unattended runs may refuse them.

Workers inside a temporary work zone cannot step into the home study without an entry pass, and the fence is never casually taken down mid-job.
FEATURE

Sandbox updates for .git, new folders, and /rewind

After a sandboxed command finishes, the Bash sandbox now sets aside any unexpected entries that appear in the repository's .git folder. On Linux and WSL, if a folder specified by --add-dir does not exist yet, the sandbox creates it before each command, so commands that meant to create that folder themselves may fail, skip, or write inside it instead. When the sandbox is on in macOS, Linux, and WSL, running /rewind leaves some files untouched and reports them as skipped.

FEATURE

Sandbox changes for rewritten permissions and claude mcp serve

For developers writing permission hooks or integrating the SDK: commands originally checked as sandboxed now stay in the sandbox even if rewritten during approval; the approver must explicitly add the setting to disable the sandbox to allow bypassing it. Running claude mcp serve now ignores excludedCommands under the sandbox settings block.

BUGFIX

Fix Linux sandbox symlink startup and leftover lock files

On Linux, if the home or config directory points into /net through a symlink (a shortcut file pointing to another location) and sandbox settings deny reading it, commands used to fail to start. That issue is fixed, and commands now start normally. When a sandboxed command is stopped partway through, empty placeholder files like .git/config.lock no longer get left behind in the project. Linux sandbox instructions for Claude are also clearer, explaining that a started server is only reachable from the same command.

FEATURE

Explain why features are disabled by provider or environment variables

Previously, entering certain commands only showed "Unknown command" without explaining why they were unavailable. Now when you enter one of these disabled commands, the terminal no longer bluntly replies "Unknown command" and instead tells you why it is off, such as your sign-in method, provider, or an environment variable like DISABLE_TELEMETRY. To see all disabled features at a glance, /status also adds a row that specifically states what turned them off.

At a vending machine where pressing a drink button does nothing, it used to only flash a red light; now the screen spells out which circuit switch was turned off.
BUGFIX

Fix account and key detection in /login and /status

Choosing to sign in with a Console account in /login used to accidentally overwrite your existing Claude subscription login if you signed in with your Claude plan in the browser; that is now fixed. When an approved ANTHROPIC_API_KEY is still active, /login no longer ends on just "Login successful" and instead reminds you that requests still use this key. After turning on the API key in /config, the screen no longer stays stuck on "Not logged in". The not-logged-in prompt, /login, and /status now also name an unused ANTHROPIC_API_KEY.

BUGFIX

Fix logout credential cleanup and agent resume sign-in attribution

/logout and claude auth logout in the terminal now retry revoking the login, and if the server does not confirm, they tell you where to revoke it manually. When only a Console profile's login credentials are stored on a drive that does not support folder timestamps, claude auth logout no longer leaves credentials behind, and token refresh no longer fails along with it. When resuming a past conversation from agent view, if the background service does not have the terminal's API key or token, it no longer mistakenly sends requests under the background service's own sign-in.

FEATURE

Auth timeout retries and clearer certificate and block error messages

When sending a model request in Claude Desktop's Code tab, a single 401 authentication error now triggers one automatic retry instead of failing right away. When a network block page returns HTTP 403 and triggers forceLoginOrgUUID or forceRemoteSettingsRefresh errors, it no longer mistakenly tells you to sign in again. When a certificate signature cannot be verified, Desktop's Code tab no longer blames the internet connection. On CERT_SIGNATURE_FAILURE errors, it also notes that a root certificate renewal may be the cause and points to what IT can adjust.

FEATURE

/login paste safeguards and sign-in flow improvements

When pasting a sign-in code in claude auth login, the screen now shows what you pasted so you can fix mistakes before pressing Enter. After submitting in /login and claude setup-token, it also shows "Finishing sign-in…". If you paste a verification code or web address at a sign-in prompt by mistake, it tells you what to paste instead without dismissing the prompt. /login now uses a standard text field with rejection reasons listed right below it, and short windows scroll the field into view. When the API refuses a Console sign-in, the error message now tells you to run /login instead of pointing to an admin setting.

Entering a PIN at a bank ATM used to eject your card on a mistake, but now it keeps you on the same screen, highlights which field is wrong, and lets you proceed once fixed.
FEATURE

Command and gateway sign-in screens aligned with /login

Running /design-login, /install-github-app, and MCP sign-in now gives you the same smooth experience as /login. The first two also mask the pasted sign-in code for privacy. On the Claude apps gateway sign-in screens, the sign-in address is now a clickable link, and pressing c quickly copies it.

BUGFIX

Key-handling fixes for first run, sign-in, and sign-out

While first-run sign-in waits for the browser or a pasted code, pressing Esc now goes back one screen instead of doing nothing. After running /logout in fullscreen mode, the screen now keeps the logged-out message visible instead of exiting blank. After quitting a sign-in or setup step with Ctrl+C or Ctrl+D, the shell prompt is no longer drawn over the last screen. Pressing Ctrl+C twice during the first-run theme choice or at a background session's startup question no longer does nothing or freezes the terminal.

/privacy-settings toggle and multi-account save fixes

When declining updated terms in /privacy-settings or at startup, keys pressed while saving no longer overwrite your OFF choice. A quick double press on the toggle no longer saves the opposite of what the screen shows. Pressing keys after Esc no longer changes your setting either, and failed saves now notify you clearly. If you switch accounts in another terminal, /privacy-settings no longer saves to the wrong account, and picking OFF right after ON no longer wrongly shows it as enabled.

Usage limit menu safeguards and budget reset notices

Pressing Backspace and Enter right as the spend limit menu opens no longer silently clears your monthly limit. The usage limit menu also no longer pops up while you are typing and wipes your draft. After a usage limit resets, an upgrade hint no longer appears under old limit messages. When a team's pooled budget runs out, the message now states when the budget resets. When /usage-credits is refused and you have billing access yourself, the screen now points you to the usage settings page instead of always saying the request was sent to your admin.

FEATURE

Login changes while waiting on limits and /usage order

With "Continue automatically at usage limit" enabled, switching accounts or signing out during the wait now makes Claude Code show a notice and stop immediately without sending any requests. For subscribers running /usage in fullscreen mode, plan limit bars now appear before session cost. If you want to see cost first, run /cost instead. After a reply billed to usage credits finishes, Claude Code no longer sends an automatic session recap; you can still run /recap manually when needed.

FEATURE

Remote Control live streaming and connection updates

With Remote Control enabled, session replies from claude remote-control, Claude Desktop, and VS Code now stream to your phone or browser as they are written. You no longer have to wait for the full response to finish. When connecting through a proxy, Remote Control now sends requests over a CONNECT tunnel, and stops with an error if the proxy refuses CONNECT. Remote session debug logs generated under --verbose are now saved to ~/.claude/child-logs/.

Following a live text play-by-play of a sports match means each line typed at the venue pops up on your phone right away instead of waiting for a post-game press release.
BUGFIX

Remote Control status, QR code, and Stop fixes

Remote Control sessions no longer disconnect mid-reply when the server is briefly unavailable. In short terminal windows such as 80×24, the /remote-control QR code is no longer cut off either. While background subagents are still running, your phone no longer wrongly shows the session as idle, and pressing Stop on your phone or the web ends the subagents too. Status is no longer inverted when waiting on a prompt that can only be answered in the terminal or when turning on Remote Control while a tool is running. Pressing Stop during a restart also prevents the reply from resuming on its own afterward.

FEATURE

Cloud and remote file upload retries, preservation, and notification masking

On Linux with no feature flags loaded, re-sending a file with the same name in Remote Control or cloud sessions no longer overwrites Claude's edited copy; the old copy moves to a .kept- folder, or the new file is not saved. When Claude sends files from cloud or Remote Control sessions and a proxy responds with HTTP 502, 504, or 520 to 524, it now retries once instead of failing immediately. Push notifications from Remote Control and cloud sessions also have stronger secret masking. When requesting Chrome extension access from a terminal session over Remote Control, claude.ai still names the site clearly even if it is already allowed.

BUGFIX

Fixes for file-sending key checks in claude.ai and Cowork

Fixed an issue where sending a file in a claude.ai chat or Cowork task could still fail to send even after you clicked "Send it" at the secret key check. When a plugin file contains a Word, Excel, or other compressed file, the interface no longer prompts repeatedly just because of the format, and instead reads the contents first to check for keys.

FEATURE

Tighter self-hosted runner permissions and built-in gh api updates

Fixed an infinite loop when using claude self-hosted-runner where it kept requesting new tokens nonstop if the machine's clock ran ahead and made a refreshed token look expired. Under --trust-workspace false, self-hosted runners now ignore more repository settings; put any needed settings in user or organization managed settings instead. If gh is missing in Linux and macOS sessions, a built-in gh api is now provided via Anthropic by default, using your GitHub sign-in if you are logged in. To turn this default off, run with --use-anthropic-gh false.

BUGFIX

Faster cloud stop and remote "always allow" saving updates

Fixed an issue where pressing Stop in cloud or self-hosted runner sessions could occasionally hang waiting for slow MCP servers to connect before actually stopping, so it now aborts faster. Adjusted how "always allow" choices are saved when answering permission requests through Remote Control or on self-hosted runners.

BUGFIX

Updates to /autofix-pr, /teleport, and cross-machine messaging

When /autofix-pr hits a cloud session that cannot be stopped, it no longer falsely reports the run as cancelled and instead includes a link to the session so you can stop it manually. Opening /teleport in narrow terminals no longer hides sessions from the list. If you switch to an API key, auth token, profile, or workload identity while keeping an older claude.ai login saved, Claude now refuses to send messages to a session on another machine.

BUGFIX

Fixes for artifact publishing permissions, access labels, and link display

Files in a background session's temporary folder are no longer refused when publishing artifacts. The terminal also properly prints the link after Claude publishes or updates an artifact. Fixed an issue in some cloud sessions where subagents still received artifact tools even when Artifact was explicitly listed in disallowedTools. Anyone with access to the folder can open a just-published artifact, and Claude no longer mistakenly calls it private.

BUGFIX

Fixes for worktree setup progress and exit counts

When opening a worktree (a Git feature that lets you keep parallel copies of the same project) with claude --worktree, slow setup now shows progress. The screen no longer stays blank while you wait. Some worktree sessions now skip certain plugin settings, and the screen clearly lists what was skipped.

FEATURE

Worktree subagent branch safety and cleanup limits

Subagents isolated in a worktree are now blocked from running git commands in Bash that could rewrite shared branches in any repository; regular sessions are unaffected. As long as a background subagent or shell command might still be running in a worktree, ExitWorktree refuses to remove it unless Claude explicitly passes discard_changes. Creating a worktree, using /teleport, or running IDE checkouts now invokes git with a stricter PATH, so custom git filters or helpers may need their full path.

Writers drafting in separate rooms are not allowed to alter everyone's shared master index directly, and checking out while someone is still inside will not tear down and clear the room.
BUGFIX

Fixes for background session gateway retention and process mis-kills

An LLM gateway exported in your terminal previously got lost in background runs after a crash, after reopening from another folder, or when the background service lacked it; sessions now stop before sending any model request instead of connecting to the wrong place. Fixed an issue where the background service's process cleanup could mistakenly kill your own process (such as your SSH login) if a process ID on its list had been reused by another user's process. Opening, stopping, or removing the older session that a background session resumed no longer kills the background session and loses its request. If a permission check errors out in non-interactive runs or background agents, the message now names the cause.

FEATURE

Background flags and --bare key restrictions

If a --bare session uses an unapproved API key, most setups now refuse moving it to the background. Running claude --bare --bg when the background service lacks that key also exits with an error. Because --bg and --worktree --tmux never read the initialize request, passing --await-initialize alongside them is now refused at startup instead of running with missing fields.

Sending a parcel to an unmanned pickup locker while still checking "sign in person" now makes the counter flag the contradiction and turn it away, rather than shipping it out with missing details.
