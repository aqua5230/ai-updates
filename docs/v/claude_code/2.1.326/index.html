Claude Code 2.1.326

發布日期：2026-11-16

繁體中文

新功能

agent teams 可用 Code Mode

開了多代理協作的 agent teams 後，現在也能同時打開 Code Mode 了。如果你原本就已經開啟 Code Mode，之後只要啟動帶有 agent teams 的工作階段，就會直接從 Code Mode 起步，不必再手動切換。

就像登山隊出門前先調好對講機頻道，以前兩項裝備不能同時開，現在出門時開關一拉就直接進到同一個頻道。
新功能

Code Mode 權限檢查與提示更新

在 auto mode 下使用 Code Mode，若技能或斜線指令內嵌 ! 指令需要核准，現在會改請 Claude 執行，不再直接載入失敗。 背景子代理預先載入這類技能時也不再出錯。沙盒指令的權限檢查同步收緊，更多指令會先詢問或直接拒絕。 無法開啟 Code Mode 時，畫面會說明可採取的做法。$ Shell 輔助工具也會直接擋下部分輸入並報錯，不會執行任何動作。

新功能

Code Mode 擴充模組排版與資料夾把關

給開發 Code Mode mod（擴充模組）的人：區塊元件新增水平捲動支援，文字元件加入最大行數與裁切選項，文字換行截斷時也不再漏行。 模組現在也能正常透過 Code Mode 介面呼叫 Bash 與 Read 等工具。 一般使用者在工作階段的 mods 資料夾改檔案時，現在會更常跳出詢問。沙盒指令可寫入的資料夾也變少了。若每次編輯都一直被問，只要刪掉裡面連往無法讀取或網路路徑的連結就好。

新功能

未指定模式時改為預設進 auto mode

套用 Claude Code + Cowork HIPAA 設定的組織，終端機與 VS Code 工作階段現在預設進入 auto mode。想關閉這個預設行為，只要加上 disableAutoMode 即可。 若尚未設定模式且組織政策還沒載入，工作階段也會先採 auto mode，不再退回手動模式。 等設定載入完成後，預設採 auto mode 的工作階段會改套用伺服器管理的預設模式；若設定與政策都載入失敗，或政策要求改回，才會退成手動模式。

飯店還沒收到旅客的特殊房型備忘前，櫃檯先按標準房流程安排入住；等備忘單送到或連線失敗時，再照規定改回人工確認。
問題修復

Auto mode 分類器與用量計費修正

套用 Claude Code + Cowork HIPAA 設定的組織，只要是直連 Anthropic API，現在會跟其他組織一樣改由伺服器端分類器檢查動作。 先前因為舊版殘留設定，auto mode 有時會卡在計入使用量的本機分類器，這個問題也已經修好，不會再白白消耗你的用量。

好比把原本記在個人帳本上的審核手續，交回總部統一查驗，舊版留下的誤記規則也一併清掉。
新功能

Auto mode 收緊萬用字元放行規則

過去在 auto mode 能直接跑過的一些 Shell 指令，現在會被擋下。 沒寫明程式名稱或以 $HOME 開頭的萬用字元放行規則，auto mode 現在會略過不採信，改由安全檢查決定是否放行。 程式路徑使用 Windows 反斜線的萬用字元規則，現在也會經過安全判斷而可能被攔截，只有精確比對的規則仍會直接放行。以 .\ 開頭的規則，官方後續計畫恢復放行。

海關人員不再看到沒填品名的空白申報單就免驗放行，只有把確切品名寫清楚的包裹才能直接過關。
問題修復

組織管理設定在桌面版與 SDK 的套用調整

給採用組織管理設定的團隊與開發者：在 Claude Desktop 的 Code 分頁，管理設定指定的子代理模型現在會蓋過個人設定，跟終端機版相同。不過若管理設定本身也指定了供應商或閘道，就不會覆蓋。 若管理設定裡 autoMode 的 environment 清單沒寫 "$defaults"，現在在 Claude Desktop 與 Agent SDK 應用程式也會取代所有內建項目。想保留預設保護，記得加上 "$defaults" 或自行複製敏感目標項目。

總公司訂好的團隊守則，以前進到桌面分部還會照員工自己的設定或預設清單走，現在一樣直接蓋過個人做法並整套替換。
新功能

設定檔寫入失敗與語法錯誤改為明確警告

啟動時若 --allowedTools、--disallowedTools 或 --tools 裡有不完整的規則，現在會跳出警告。 在 /permissions、主對話工具提示或 /add-dir 新增規則與資料夾時，若設定檔無法寫入，終端機不會再裝作已存檔，而是直接點名檔案發出警告。 工作階段中途存到有錯的設定檔時，現在也會點名提示。設定檔或 .mcp.json 若有 JSON 語法錯誤，錯誤訊息會直接指出第幾行第幾欄。

問題修復

修正管理設定鍵名與過深巢狀導致當機

組織管理設定裡只要出現特定鍵名，過去會讓 Claude Code 無法啟動，或意外影響其他管理設定檔。這個問題已經修好，管理設定現在能正常載入。 設定檔裡若出現巢狀深達數千層的數值，過去會造成當機或時靈時不靈；現在超過 64 層的值會直接捨棄並跳出警告。

跟拆多層禮物盒一樣，規定拆到第六十四層還沒見底就直接退件提醒，不再硬拆到整張桌子垮掉。
新功能

管理員的 OpenTelemetry 遙測記錄調整

給管理 OpenTelemetry 遙測資料的管理員：現在多了環境變數 OTEL_RESOURCE_INCLUDE_HOST（預設關閉）。開啟後，遙測資源屬性就會一併附上主機名稱與主機識別資訊。 組織管理設定裡的 PreToolUse hook（掛鉤，特定事件發生時被觸發的小程式）若直接拒絕工具呼叫，現在也會確實留下決策事件與拒絕紀錄。 Cowork 雲端工作階段現在會等到第一輪對話才送出組織的遙測資料。沒有收到任何訊息的工作階段不會送出資料，因此計數可能下降。

換個方式看，店裡改成真的有人進門問話才記一次來客，只推門看一眼就走的不再算進統計。
新功能

Hook 執行失敗與擋下動作時顯示原因

Node 或 Python 寫的 hook 若當掉，過去只會印出錯誤追蹤的第一行；現在會直接顯示錯誤，按下 Ctrl+O 還能看到最多 10,000 字元的輸出。 PreToolUse hook 若回傳結束碼 127，錯誤訊息也會直接提醒檢查可能根本沒跑起來。 對話紀錄裡的狀態顏色也更好辨認：失敗或逾時的 hook 改成紅色顯示，擋下 Claude 執行的改成黃色，並把原因直接列在下方。

新功能

Hook 改寫輸入、阻擋範圍與 HTTP 規則變更

多個 PreToolUse hook 同時回應同一次工具呼叫，改寫後的輸入參數現在在更多情況下都能保留生效。 Hook 回傳的阻擋決定現在適用更多情況；如果某支 hook 原本每次都固定印出 "decision": "block"，更新後可能會開始真的擋下呼叫。 來自管理設定的 hook，也調整了 allowedHttpHookUrls 與 httpHookAllowedEnvVars 的套用規則。HTTP hook 現在會忽略標頭設定裡的 Content-Length 與 Transfer-Encoding，改依請求內容計算長度。

新功能

Monitor 逾時無事件時會指出錯誤紀錄檔

用 Monitor 監看背景程序卻等到逾時都沒事件，若背後的指令其實把錯誤印到了標準錯誤輸出，現在會主動告訴 Claude 這件事，並附上存放輸出的檔案路徑。

新功能

中途加入 managed-mcp.json 的套用與說明

管理員在工作階段進行途中新增 managed-mcp.json，MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器會停止載入。現在畫面上會出現說明訊息，告訴你為什麼伺服器停了下來。 這種中途加入的設定現在有機會在下一次檢查時就開始生效；不過要讓設定完整套用，還是得重開目前開啟中的工作階段。

學校期中臨時更換書單時，下一堂課就會先發公告讓大家知道為何舊書停用，但修課中的班級還得重新開一次課程表才會整套換新。
問題修復

/mcp 連線狀態、取消等待與錯誤提示修復

在終端機開啟 /mcp，本機標準輸出入 MCP 伺服器若啟動失敗，現在會顯示原因，不再只留一片空白。 伺服器重新連線期間，按 Esc 或連按兩次 Ctrl+C 可以先關閉等待畫面，重連會留在背景繼續跑。啟用慢速伺服器時也會顯示進度，再按一次 Enter 也不會誤關掉。 使用 claude mcp add-json 寫錯設定時，不再只回泛用的無效輸入訊息，而是直接指出該修改哪裡。

問題修復

MCP 背景提問、複製連結與表單操作修復

背景 MCP 任務跳出問題後，連按兩次 Ctrl+C 其實只是把問題留待稍後回答，現在提示文字不再誤寫成取消。 按 c 複製 MCP 登入網址時，貼上欄位裡不會再多出一個 c 字元。 填寫 MCP 伺服器的輸入表單時，現在可以用 Tab 與 Shift+Tab 在欄位間切換，把必填欄清空後也不會還留著勾選記號。

問題修復

MCP 平行呼叫錯置與工具搜尋載入修復

同時呼叫多個 MCP 工具，若兩筆較長的結果在同一個毫秒抵達，過去會讀到另一通呼叫的結果，現在已經修好。 用精確名稱找工具時，過去偶爾會載入別台 MCP 伺服器的工具；現在已經修好，過程可能會再請你確認一次。兩台伺服器名稱很像時，提示詞也不會再突然消失。 支援多種參數格式分支的 MCP 工具，過去只給 Claude 看第一種格式，現在像 42 這類數值也能正確交給接收數字的分支。

在忙線的郵局櫃檯分信時，以前兩包大件同時到或收件人名字很像就容易塞錯格，現在每件包裹都能準確歸位。
新功能

MCP 驗證失敗與雲端斷線的錯誤回報改善

沒有儲存 OAuth 更新用 token（授權令牌）的 MCP 伺服器，過去若 headersHelper 失敗或在未信任資料夾沒執行，會害其他工作階段也少掉這台伺服器。這個問題已經修好，其他工作階段不會再被波及。 給串接 SDK 的開發者：主機剛移除某台 MCP 伺服器後若收到工具呼叫，不再錯誤重連或要求驗證。 遠端 MCP 的提問被拒後工具失敗，或雲端工作單元換掉後工具不可用，現在都會通知 Claude。雲端工作階段經 Proxy 送出呼叫後若被切斷，也會告訴 Claude 結果未知。

新功能

禁止工具誤寫登入檔與系統裝置檔案

保護登入憑證的安全限制收緊了。Claude 的檔案工具現在會直接拒絕寫入 .credentials.json 這類登入憑證檔。 Bash 權限檢查也提高警戒，更多指令想碰觸 Claude Code 的登入憑證檔前，都會先跳出來問你。 部分裝置檔與行程檔現在也列為檔案工具的拒絕存取對象，不會讓代理隨意讀寫。

把這想成幫放護照與身分證的抽屜加裝鎖頭，一般文書整理進不去，想伸手拿也得先當面問過你。
新功能

Bash、複製搬移與超長指令的權限把關更嚴

Bash 權限檢查現在會先詢問更多指令，無人能回應時就直接拒絕；macOS 上部分過去直接放行的 Bash 指令也改為詢問或拒絕。 部分 cp 與 mv 指令現在執行前也會先問過你。即使切到略過權限模式，部分工具呼叫仍會要求核准，無人回應就拒絕。 遇到指令值太長、Bash 權限檢查來不及讀完的情況，現在也會先詢問；若可能觸及拒絕規則或無人回應，就會直接攔下。

問題修復

修正 Bash 檔案操作誤判與誤報危險提示

用 cp 複製檔案，過去只要來源檔受 Edit 拒絕規則限制就會整筆被拒，現在已經修好。Bash 裡的 grep 也不再默默漏掉部分純文字檔。 對話紀錄過去會把 find -delete、cat a > b 或 sort -o 這類刪寫檔指令誤記成搜尋或讀取，現在不再歸錯類。 有些不含 rm 但 Claude Code 讀不太準的指令，也不會再誤跳「Dangerous rm operation」的誤導警告了。

新功能

PowerShell 工具收緊詢問條件與函式限制

Windows 常用到的 PowerShell 工具，現在在更多指令執行前會先問你；無人看守的執行除非有放行規則、auto mode 或略過權限模式允許，否則會直接拒絕。 部分指令現在甚至連略過權限模式都會要求詢問，或直接拒絕。語法有誤的 PowerShell 指令也會直接被拒。 若指令裡定義的函式與內建指令撞名，現在同樣會被擋下，讓 Claude 改名後再試。

打個比方，工場規定扳手不能跟電鑽貼同一個名字，碰到危險動作就算領過免檢證照樣要複驗。
新功能

macOS 電腦操作權限面板停用 j 與 k 鍵

替電腦操作功能在 macOS 上授權、挑選要開的項目，現在按 j 和 k 不會再移動游標。要上下切換，改用方向鍵或 Ctrl+P、Ctrl+N 即可。

新功能

Bash 沙盒限縮家目錄寫入並強化隔離

macOS、Linux 與 WSL 的 Bash 沙盒保護現在更嚴密了。同一個工作階段裡，沙盒在部分情況下會先維持狀態，直到你跑 /sandbox 或 /cd；期間 Bash 可能會先詢問。 沙盒指令在 macOS、Linux 與 WSL 預設不再寫入部分敏感家目錄資料夾；真有需要，可在使用者或管理設定檔的 sandbox 區塊透過 filesystem 的 allowWrite 放行部分路徑。 關閉自動放行時，碰到設定環境變數的指令列也會先詢問，無人看守的執行則可能直接拒絕。

沙盒像替工人圍起臨時施工區，沒有開通行證就不能踏進住家書房，中途也不會隨便拆掉圍籬。
新功能

沙盒調整 .git、新增目錄與 /rewind 行為

沙盒內的指令跑完後，若儲存庫的 .git 資料夾出現預期外的項目，Bash 沙盒現在會把它另外移開。 在 Linux 與 WSL，若 --add-dir 指定的資料夾還不存在，沙盒會在每次指令前先建好，因此原本打算自己建該資料夾的指令可能失敗、略過或改寫進裡面。 在 macOS、Linux 與 WSL 開啟沙盒時，執行 /rewind 會保留部分檔案不動，並回報這些檔案已被略過。

新功能

權限改寫與 claude mcp serve 的沙盒調整

給寫權限 hook 或串接 SDK 的開發者：原本受沙盒檢查的指令，就算在核准過程中被改寫，現在仍會留在沙盒裡執行；核准端必須主動加上停用沙盒的設定才會放行。 執行 claude mcp serve 時，現在會忽略 sandbox 設定區塊底下的 excludedCommands。

問題修復

修正 Linux 沙盒捷徑啟動與殘留鎖定檔

在 Linux 上，家目錄或設定目錄若透過 symlink（符號連結，指向另一個位置的捷徑檔）連進 /net，又被沙盒禁止讀取，過去會啟動失敗。這個問題已經修好，指令現在能正常啟動。 沙盒指令執行到一半被中止時，專案裡偶爾會留下 .git/config.lock 這類空白佔位檔，現在也不會再殘留。 Linux 沙盒給 Claude 的指引也更明確，會說明啟動的伺服器只能從同一道指令連線。

新功能

功能被供應商或環境變數停用時會說原因

以前輸入某些指令只會看到「Unknown command」，看不出它為什麼不能用。 現在輸入這類被停用的指令時，終端機不會再冷冷回你「Unknown command」，而是會直接告訴你停用原因，例如登入方式、供應商，或 DISABLE_TELEMETRY 這類環境變數。 想一次看清哪些功能被關掉，輸入 /status 也會多出一列，專門標明是什麼原因停用了它們。

去自動販賣機按飲料沒反應時，以前只亮紅燈，現在螢幕會直接寫明是哪條電路被開關關掉。
問題修復

修正 /login 與 /status 的帳號金鑰判斷

在 /login 選擇用 Console 主控台帳號登入，若瀏覽器裡改用 Claude 訂閱方案登入，過去會不小心蓋掉原本的訂閱登入狀態，現在已經修好。 當核准使用的 ANTHROPIC_API_KEY 還在生效時，/login 不會再只顯示「Login successful」，而是會提醒請求仍在使用這把金鑰。 在 /config 開啟 API 金鑰後，畫面不會再卡在「Not logged in」。未登入提示、/login 與 /status 現在也都會點名尚未使用的 ANTHROPIC_API_KEY。

問題修復

登出清除憑證與代理恢復的帳號歸屬修復

終端機裡的 /logout 與 claude auth logout 現在會重試撤銷登入，若伺服器沒確認，也會告訴你去哪裡手動撤銷。 當只有 Console 主控台設定檔的登入憑證放在不支援資料夾時間戳記的磁碟上時，claude auth logout 不會再漏刪憑證，token 刷新也不會跟著失敗。 從代理檢視恢復舊對話時，若背景服務沒有終端機的 API 金鑰或 token，現在不再誤用背景服務自己的登入身分送出請求。

修正 /model 的 Default 選項顯示與切換

打開 /model 選單時，過去已存的模型常只顯示「Default (recommended)」，看不出方案預設究竟是什麼。現在 Default 會直接寫明你方案的預設模型名稱，在終端機選取它就能切回該預設模型。

新功能

/update-config 與 /doctor 輸出調整

長工作階段裡打字、串流輸出與調整視窗大小的反應都更流暢，讀寫檔案後的回應速度也更快，Windows 使用者感受尤其明顯。 工作階段閒置時喚醒電腦的頻率降低了，閒置時的 CPU 用量也跟著下降。 Windows 每個工作階段第一道 Bash 指令的啟動速度加快約 1 秒；在 git 儲存庫執行 /compact 後，第一則訊息的回應也更快了。

把辦公室電梯感應器重調過之後，沒人搭時不再空轉，人一踩進去關門起步也比以前快了半拍。

在 ! 殼層模式下，沒帶斜線的檔名現在也能按 Tab 自動補齊，遇到空白或特殊字元時路徑還會自動加上引號。 在輸入框按住 Esc 清完文字後不會再順手開出 Rewind，也不會誤取消待執行的 /loop。若再按一次 Esc 已不會清除輸入，畫面的提醒文字也會跟著消失。 排隊中的訊息底下現在改標「Queued」，看起來不再像是你打的訊息本身。

回覆串流掉字、捲動回看與記憶體配置修復

畫面繪製遇到單次記憶體配置失敗時，整個工作階段不會再直接結束閃退。 回覆剛開始串流時，對話紀錄不會再漏掉幾行或讓輸入框往上跳；串流進行中，長清單或程式碼區塊也不再少一行或跳動。 在傳統渲染器下，較長的排隊訊息不再於串流期間蓋住 Claude 的回覆，也不會從捲動紀錄中被抹掉。

修正切換模型閃白、長檔卡頓與轉圈跳動

在 /model 挑完模型不再畫面全白吃按鍵，用 /model <alias> 與 /effort <level> 切換時輸入框也不再短暫消失並漏接文字。 權限提示與 Ctrl+O 紀錄要顯示新建的長檔案時，或是遇到極長的 Bash、PowerShell 指令時，不會再讓工作階段凍結卡住好幾秒。 回覆結束與工具呼叫串流完成時，提示文字、「Reading 1 file…」與輸入框也不再閃爍或上下跳動。

全螢幕捲動定位、搜尋卡頓與提示框顯示改善

在全螢幕模式往上捲動或回答 Edit、Write 提示後回覆完成時，文字不再亂跳，調整視窗大小也不會跑位或跳輪次。 長工作階段在搜尋或往回跳很遠時不再整片變白，快速捲動中途也不會卡死。 頂端固定的提問框串流時不再誤顯示舊問題，往上拖曳反白複製回覆時也不會連它一起複製進去。輸入框邊框現在還會直接標出長提示共有幾行落在視野之外。

TUI 切換說明、滑鼠亂碼與預覽捲動修復

長對話跑 /tui default 或另個視窗改 tui 設定時，畫面不再錯亂。若無法切回傳統渲染器，Claude Code 會直接指出是什麼設定鎖住了全螢幕。 新帳號第一個工作階段現在會跟後續使用同一種渲染器；離開全螢幕模式後，終端機也不會再被輸入一堆滑鼠跳脫字元。 在全螢幕模式下看 claude --resume 的工作階段預覽時，內容不再亂碼且能正常捲動。

全螢幕工具計時、標題與指令輸出顯示修復

在全螢幕往上捲看舊訊息時，若有權限提示或問題在等你，畫面現在會發出提醒。工具群組標題也會正確顯示正在跑的呼叫，不再寫成已完成或排隊中的那一筆。 已完成的工具群組不再把搜尋或列目錄也計為殼層指令，工具計時器也不會把等權限或排隊時間算進去。 執行多行殼層指令時不再塞滿整個全螢幕；點開收合中的執行中指令列，現在也看得到即時輸出與計時器。

改善指令即時輸出、跳到底部鈕與 Ctrl+O 提示

執行 ! 殼層指令時，開頭 3 秒鐘現在就會看到輸出，不再先空白一片。 全螢幕模式底下還有回覆內容時，跳到底部的按鈕不會再提早消失；矮視窗上方顯示問卷或通知時，輸入框也不會被擠不見。 全螢幕下打開 Ctrl+O 紀錄時，不再錯誤提示按 Ctrl+B 將指令放背景（該鍵在全螢幕是往上翻頁），並會清楚標出 Claude 還在工作中。

在高度較矮的全螢幕視窗裡，Ctrl+R 搜尋、模型選擇器、計畫核准、問題預覽、背景殼層輸出與 /plugin 安裝選項過去容易被切掉，現在都能完整顯示。 在窄終端機裡，/context 網格與「Credit balance too low」、「Waiting for API response」等 API 錯誤與重試通知不再被裁斷或錯亂。連「esc to interrupt」與「Interrupted」提示也能完整對齊顯示。

自訂狀態列隨視窗縮放更新且不閃爍

自訂 status line（顯示在終端機最底下的狀態列）在按 Ctrl+C、進入 ! 殼層模式或貼圖時，不再突然消失或讓畫面跳動。 縮放終端機、執行 /cd 或 /rename 後，它會即時跟上新的寬度、資料夾與工作階段名稱，不再抱著舊資料不放。 狀態列旁的「esc to interrupt」提示也不再缺席；而當 Esc 其實是操作面板或頁尾項目時，它則會識相收起來。

修正中日韓粗體、Windows 路徑與寬表格排版

Claude 回覆裡的 Windows 路徑，在 .claude 或 _build 等資料夾前不再漏掉反斜線。日、中、韓文粗體若以標點開頭或結尾，也不再直接露出 ** 符號。 計畫與子代理提示裡的寬表格不再散掉、長格旁的短字不再被腰斬，畫成標籤與數值清單時也不會冒出多餘字詞與空行。 指令與工具輸出裡的 JSON 清單末項和靠右對齊數字會保持縮排；差異比較裡的「No newline at end of file」也不再被算成一行程式碼而害後面行號全歪掉。

對話框與 ? 清單統一按鍵提示順序並適應窄視窗，/hooks 與 /permissions 深層畫面也標明 Esc 返回。許多對話框的錯誤、警告與確認統一以 ✘、⚠、✔ 開頭，狀態列也更整齊。 /add-dir、/export 等多個設定與回報輸入框統一外觀且長字會換行，被拒的內容能原地修改。長選單與 /、@ 選單也會標明上下還有幾列隱藏項目。 更多清單支援頭尾循環移動，斜線指令勾選清單支援 Home 與 End，/permissions 搜不到東西時也會主動說明。

新功能

拉桿調整與各介面文字、間距細節改善

整理了 /plugin、/mcp、登入、設定、代理檢視、/teleport、Remote Control 與 claude --help 等處的介面文字。/btw、/help 與設定錯誤等對話框的對齊與間距也一起微調。 /autocompact 與 /scroll-speed 改用新版拉桿，能顯示每個數值、支援 Home、End 與全螢幕滑鼠點擊，也適合窄終端機。 /config、/memory 與 auto mode 設定裡的開關狀態，現在統一顯示為 on 與 off。

問題修復

管線分頁按鍵、SSH 複製與全域設定套用修復

把 claude --help 導進分頁器（如 claude --help | less）閱讀時，方向鍵與 q 鍵現在能正常操作了。 透過 SSH 連線執行 /copy 與 /export 時，不再一律誤報已複製到剪貼簿。Pro 與 Max 用戶的對話分享詢問在發下一則訊息、/clear 或 /resume 後也會自動收起。 思考力度提示不再於每次權限對話後重跳，上下文警告也不再遮掉額度上限通知。/config 的減少動態效果與顯示提示改為全域套用，不再只影響目前資料夾。

問題修復

claude logs 疊字與 /ide、/status 修復

在非全螢幕模式下按下 Ctrl+Z，暫停訊息不再直接疊印在輸入框上面。執行 claude logs 時，輸出也不再蓋掉並混雜原本終端機裡的畫面。 在 /ide 出現Connect to your IDE automatically?問題時，按 Esc 現在能順利退出，不必連按兩次 Ctrl+C 把整個程式關掉。 執行 /status 查看狀態時，安裝相關的警告訊息不再重複顯示兩次。

問題修復

PR 狀態標章、折行網址點擊與筆記本編輯修復

切換分支後，頁尾 PR 標章不再停留上一支分支的內容；先跑 fetch 或 pull 後，「Pushed to」摘要也不會寫錯分支名。若 gh 拒絕執行且隱藏退出碼，畫面不再誤報「Merged PR」或「Closed PR」。 在不認得但支援連結的終端機裡，跨行折疊的網址以及 Rex 終端機裡的帶標籤連結現在都可以點擊了。 長單行訊息不再誤顯示「(0 lines hidden)」，會如實標示隱藏了多少文字。編輯筆記本漏寫類型或刪格時工具列不再不見，在最頂端插入儲存格也不會顯示 @undefined。

新功能

VS Code 新增關閉下一句提問建議的設定

在 VS Code 請 Claude 改程式時，如果覺得輸入框旁一直跳出「下一句可以問什麼」的提示有點干擾，現在多了一個專屬設定可以關掉它。 只要打開 VS Code 的 settings.json，加入下面這行就能關閉：

{
  "claudeCode.promptSuggestions": false
}

在紙上寫大綱時如果覺得旁邊有人不斷代擬下一句反而分心，只要把提醒紙條收起來就能安靜照自己步調寫。
問題修復

修正 VS Code 分支對話倒回程式碼誤刪檔案

在 VS Code 分支對話點選「Rewind code to here」退回某一步時，過去偶爾會多倒退一輪並刪掉那一輪建好的檔案。這個問題已經修好，現在會準確停在你選定的那一輪。

問題修復

VS Code 編輯加速與沙盒、記憶資料夾修復

在 VS Code 關閉沙盒時，沙盒對話框不會再偷偷於家目錄與專案的 .git 資料夾建立空白檔案與資料夾。 記憶資料夾若有 symlink 迴圈，不再漏列項目或讓記憶體暴漲；遇到具名管線也不再卡死。指令執行中的即時輸出遇到一次讀取失敗後，不會再直接停擺。 如果編輯器原本就沒在未開啟分頁的檔案回報新問題，Edit 與 Write 現在不會再枯等問題檢查，改檔更快。

問題修復

VS Code 登入保存、貼碼提醒與額度按鈕修復

在部分網路環境下，VS Code 已儲存的登入狀態不再莫名遺失。使用 Console 主控台登入但沒有 API 金鑰時，每次打開面板或視窗也不再閃過一下登入畫面。 不小心貼進驗證碼、網址或其他登入嘗試的碼時，登入流程不會直接中斷，面板會改為告訴你應該貼上哪一種碼。 Team 與 Enterprise 成員在工作階段中重新登入後，用量上限橫幅上的「Request more」按鈕不會再每次按下去只跳回來卻什麼都沒送出。

問題修復

VS Code 的 /ide 切換、產出物連結與高對比修復

第二個工作階段執行 /ide 時，不再默默被第一個搶走連線而斷開。現在會由最新的連線勝出，被替換掉的工作階段也會告訴你怎麼切回來。 在 bash、zsh、fish 與 Git Bash 用「Open in Terminal」卻啟動失敗時，現在會說明原因並附上安裝指南連結。發佈產出物後，面板也會顯示「Open artifact」連結。 對話面板失焦時，「attach selected text」提示不再被下一句建議蓋住；高對比主題的按鈕邊框與淺色高對比歡迎圖示也修好了。

新功能

VS Code 即時輸出樣式與擴充錯誤紀錄調整

在 VS Code 聊天面板執行指令時，即時輸出現在換成跟指令卡片「OUT」那一列一致的樣式，閱讀起來更統一。 給編輯器本身遙測收集參考的細節也做了調整：事件監聽、檢視與啟動階段發生的擴充功能錯誤文字，現在不會再混進編輯器自己的錯誤遙測裡。

FEATURE

Agent teams can now use Code Mode

With multi-agent collaboration in agent teams enabled, you can now turn on Code Mode at the same time. If you already had Code Mode turned on, any session you start with agent teams will now launch directly in Code Mode without needing to switch manually.

Picture a mountaineering team tuning their radio channels before heading out: previously, two pieces of gear could not be switched on together, but now flipping the switch on the way out puts everyone straight onto the same channel.
FEATURE

Code Mode permission checks and prompt updates

When using Code Mode in auto mode, if a skill or slash command has an inline ! command that needs approval, Claude is now asked to run it instead of failing to load. Background subagents also no longer fail when preloading these skills. Permission checks for sandboxed commands have been tightened as well, so more commands now ask first or are refused outright. When Code Mode cannot be turned on, the message now explains what you can do. The $ shell helper also refuses certain inputs with an error without running anything.

FEATURE

Code Mode mod layout and folder safeguards

For those building Code Mode mods (custom extensions): the box component now supports horizontal scrolling, the text component adds max-lines and clipping options, and wrapped text no longer drops lines when truncated. Mods can now also call tools like Bash and Read through the Code Mode interface as expected. For general users, editing files in a session's mods folder now triggers prompts more often. Sandboxed commands can also write to fewer folders. If you are prompted on every edit, simply remove any links inside pointing to unreadable or network paths.

FEATURE

Default to auto mode when no mode is set

For organizations using the Claude Code + Cowork HIPAA configuration, terminal and VS Code sessions now start in auto mode by default. To turn off this default behavior, simply add disableAutoMode. If no mode is set and the organization's policy has not loaded yet, sessions also start in auto mode instead of falling back to Manual mode. Once settings finish loading, sessions that start in auto mode by default switch to the server-managed default mode; they only fall back to Manual mode if both settings and policy fail to load, or if the policy requires it.

Before a hotel receives a guest's special room-type memo, the front desk checks them in using the standard room process; once the memo arrives or the connection fails, they switch back to manual confirmation as required.
BUGFIX

Auto mode classifier and usage billing fixes

For organizations using the Claude Code + Cowork HIPAA configuration on a direct Anthropic API connection, actions are now checked by the server-side classifier, just like other organizations. An issue where stale settings from an older version could leave auto mode stuck on the local classifier—which counts toward usage—has also been fixed, so it no longer wastes your usage.

It is like handing review procedures previously logged in a personal ledger back to headquarters for unified inspection, while clearing out misrecorded rules left over from an earlier version.
FEATURE

Auto mode tightens wildcard allow rules

Some shell commands that previously ran directly in auto mode are now blocked. Wildcard allow rules that do not name a program or that start with $HOME are now ignored by auto mode, leaving the safety check to decide whether to allow them. Wildcard rules whose program path uses Windows backslashes are now also evaluated by the safety check and may be blocked, while exact-match rules still allow calls directly. Rules starting with .\ are planned to be restored later.

Customs officers no longer wave through blank declaration forms with no item name filled in; only packages with the exact item name clearly written can pass straight through.
BUGFIX

Managed settings updates for Claude Desktop and SDK

For teams and developers using managed settings: in Claude Desktop's Code tab, the subagent model specified in managed settings now overrides your personal setting, just like in the terminal. However, if those managed settings also specify a provider or gateway, it will not override. If the environment list under autoMode in managed settings omits "$defaults", it now replaces all built-in entries in Claude Desktop and Agent SDK apps as well. To keep the default protections, remember to add "$defaults" or copy the sensitive-target entries yourself.

A head office's team rules used to still defer to an employee's own settings or default list at the desktop branch, but now they override personal practices and replace the whole set there too.
FEATURE

Clearer warnings for settings write failures and syntax errors

If --allowedTools, --disallowedTools, or --tools contains an incomplete rule at startup, a warning now appears. When adding rules or folders via /permissions, a main-conversation tool prompt, or /add-dir, if the settings file cannot be written, the terminal no longer acts as if it were saved and instead issues a warning naming the file. When a settings file is saved with an error mid-session, a warning now names the file as well. If a settings file or .mcp.json has a JSON syntax error, the error message now points directly to the line and column.

BUGFIX

Fix crashes from managed setting key names and deep nesting

Previously, certain key names in managed settings could prevent Claude Code from starting or unexpectedly affect other managed settings files. This has been fixed, and managed settings now load normally. Values nested thousands of levels deep in settings files used to cause crashes or intermittent failures; now any value past 64 levels is dropped with a warning.

Like unwrapping a multi-layered gift box, the rule now rejects and flags anything that hasn't reached the bottom by layer 64, instead of prying it open until the whole table collapses.
FEATURE

OpenTelemetry telemetry updates for admins

For administrators managing OpenTelemetry telemetry data: a new environment variable OTEL_RESOURCE_INCLUDE_HOST (off by default) is now available. When enabled, telemetry resource attributes also include the host name and host ID. If a PreToolUse hook (a small program triggered by specific events) in managed settings directly refuses a tool call, it now reliably leaves both a decision event and a denial record. Cowork cloud sessions now wait until the first turn of conversation before sending an organization's telemetry data. Sessions that receive no messages send nothing, so counts may decrease.

Put another way, a shop now logs a visitor only when someone actually steps in to ask a question, instead of counting people who just push the door open for a quick look and leave.

Show reasons when hooks fail or block actions

When a Node or Python hook crashes, it previously printed only the first line of its stack trace; now the error is shown directly, and pressing Ctrl+O reveals up to 10,000 characters of output. If a PreToolUse hook returns exit code 127, the error message now reminds you that its check may not have run at all. Status colors in the transcript are also easier to tell apart: failed or timed-out hooks now appear in red, hooks that stop Claude appear in yellow, and the reason is listed right underneath.

FEATURE

Changes to hook input rewrites, blocking scope, and HTTP rules

When multiple PreToolUse hooks respond to the same tool call, rewritten input parameters now stay in effect in more cases. A hook's blocking decision now applies in more cases; if a hook previously always printed "decision": "block", it may start actually blocking calls after this update. Hooks from managed settings also have updated rules for how allowedHttpHookUrls and httpHookAllowedEnvVars apply. HTTP hooks now ignore Content-Length and Transfer-Encoding in their header settings, calculating the length from the request body instead.

FEATURE

When using Monitor to watch a background process and it times out with no events, if the underlying command wrote errors to stderr, Claude is now proactively informed and given the path to the file holding the output.

For developers integrating the SDK: if a tool call arrives right after the host removes an MCP server, it no longer mistakenly reconnects or asks for authentication. Claude is now notified if a remote MCP question is declined and the tool fails, or if a tool becomes unavailable after a cloud worker is replaced. Some commands without rm that Claude Code cannot read reliably will no longer trigger the misleading "Dangerous rm operation" warning.

If a command defines a function with the same name as a built-in command, it is now blocked as well so Claude can rename it and try again.

When "Open in Terminal" fails to start in bash, zsh, fish, or Git Bash, a notice now explains why and links to the install guide. After publishing an artifact, the panel also shows an "Open artifact" link. While the chat panel is unfocused, the "attach selected text" hint is no longer hidden by the prompt suggestion; button borders in high-contrast themes and the welcome art in Light High Contrast are also fixed.

FEATURE

VS Code Live Output Style and Extension Error Logging Updates

When running a command in the VS Code chat panel, the live output now matches the style of the command card's "OUT" row, making it more consistent to read. Details for the editor's own telemetry collection have also been adjusted: extension error text from event listeners, views, and activation no longer mixes into the editor's own error telemetry.
