VS Code 對話可收起工具細節

你在 VS Code 裡跟 Claude 對話，想看回答卻被一串工具操作淹沒時，現在可以切到 Focus view（焦點檢視，把每回合的工具活動收在可展開摘要裡）。聊天選單、Ctrl+Alt+F，或「Claude Code: Toggle Focus view」指令都能切換；摘要仍會顯示哪個工具正在執行。它像把廚房做菜的過程合起來，只把菜單留在桌上：要追查時再掀開，平常不必被鍋碗瓢盆擋住。

沙盒保住憑證，也撐住大型上傳

Linux 或 WSL 裡的沙盒（sandbox，把程式限制在隔離範圍內執行）現在可把憑證檔設成 mode: "mask"。裡頭的命令讀到的是替身檔，連 extract 正規表達式（用符號匹配字串的語法）挑出的片段也能替換；資料要送出沙盒時，代理才換回真值。macOS 沒有這種遮罩能力，會改成拒絕讀取。另一方面，經過沙盒代理的大型上傳不再因 TLS 錯誤失敗。像寄件櫃檯先給你一張遮住關鍵欄位的影本，真正交件時才由櫃員換入原件。

外掛與提示詞先做相容性體檢

準備發布外掛或調整 API 提示詞時，現在多了兩道早期提醒。claude plugin validate 會警告：市集或外掛名稱若不符合 Claude Desktop 的受管理市集同步規則，之後會被拒絕。claude-api skill 也新增 prompt-audit 子指令，會檢查提示詞與工具說明是否還沿用為舊模型寫的模式。這像送印前先讓校稿機檢查店名能不能掛上招牌、文案格式能不能被新版印刷機讀到；問題在上架前看見，而不是同步失敗後才猜原因。

Bash 與 PowerShell 的權限檢查補洞

命令看似只是條件判斷，裡面卻藏了另一道指令時，權限檢查現在不會再放過它。先前 zsh 能在 Bash 工具的 [[ ]] 正規表達式條件裡執行隱藏命令，避開確認；這類命令現在都會要求權限。Windows 的 PowerShell 若路徑含引號，檢查也曾處理錯誤，現在同樣會請你核准。門禁像是終於會翻開包包夾層檢查，而不是只看外袋標籤；路徑裡有特殊字元，也不會讓它看錯證件。

思考切換與 MCP 連線不再偷偷回復

工作階段一開始關掉 thinking（思考模式，讓模型保留更多推理過程的開關）後，再把它打開，現在會確實影響這一整段對話。連線中的 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器若被停用，也不會悄悄自己恢復。另一個修正針對 claude -p：透過 --mcp-config 加入的伺服器會在第一回合前連好，不再讓模型把本該執行的工具呼叫原樣印成文字。這就像關掉一台設備後，控制台不會趁你轉身又把它接回電源。

重送提示詞、SDK 工具與搜尋都更可靠

你按 Esc 撤回提示詞後又送一次，先前用 @ 指名的檔案不會再無聲消失。開發者若用 SDK 的 MCP 工具，工具名稱剛好是 JavaScript 內建物件屬性，例如 constructor，準備 API 請求時也不會崩潰。至於關閉 thinking 後以 xhigh 或 max effort（投入更多推理資源的等級）跑 WebSearch，原本會收到 400 錯誤，現在可正常搜尋。像重新遞一份附檔申請書、讓窗口正確辨認罕見姓氏，最後也讓高難度查詢真的送進資料庫。

額度訊息與 Windows 的 AWS 登入說清楚

Team 或 Enterprise 用戶碰到 spend limit（支出上限）時，訊息終於會指向自己的個人上限，而不是錯怪組織的月上限。Windows 的桌面受管理工作階段裡，使用 AWS SSO 命名設定檔登入 Bedrock 時，若電腦碰巧有多餘的 HOME 環境變數（啟動程式前預先給它的設定值），也不會再登入失敗。前者像信用卡通知終於指出是你的卡刷到上限；後者則像門禁不再被一張放錯抽屜的地址便條帶錯路。

自動續接與重新驗證少了意外

若你明確設 CLAUDE_CODE_RESUME_INTERRUPTED_TURN=0，被打斷回合的自動續接現在真的會關掉；其他代表關閉的 falsy 值也會被尊重。電腦睡醒時，兩個 Claude Code 行程偶爾會同時更新同一個 MCP 連接器或 WIF OAuth token（用來證明登入身分的授權令牌），互相踩到而逼你重登；現在避免了這場競跑。像在交接簿寫下「不要自動續辦」後，值班人員不會照樣替你開案；兩人也不會同時搶著換同一把門鎖。

工作階段名稱與外掛狀態不再失聯

你在 Claude Code Desktop 或 claude.ai 改工作階段名稱，CLI 現在也會更新，而且不論從哪個介面改都會先整理名稱格式。非互動工作階段（沒有終端機視窗、直接執行的模式）裡，外掛或組織派發的 skill（技能，告訴 Claude 如何處理特定工作的指示）若剛好叫 /help、/feedback 等終端機內建名，也能叫得動。外掛重載完成後，「Plugins changed」通知也會自動消失。像同一份行程表在手機、網頁與櫃檯都用同名，活動結束的提醒則會自行撤牌。

Vim 模式記得複製內容，也更懂返回時機

用 Vim mode（Vim 模式，用鍵盤指令編輯文字的操作方式）編寫提示詞時，yank register（暫存複製文字的位置）不會再因為開過對話框、搜尋歷史或看逐字稿就被清空。另一個小但重要的修正是：你一路 undo 回空白提示詞後，第一次按左箭頭會先準備「再按一次才回代理畫面」的確認，而不是立刻跳走。像剪貼簿不會因為你翻了幾頁文件就倒空；走到門口也會先亮警示燈，免得你按錯一步就離開編輯桌。

自動模式的權限判斷更省快取，也看得見用量

Google Vertex AI 上的 Claude 4.5 世代以上模型，tool search（工具搜尋，讓模型找可用工具的功能）重新可用。自動模式處理平行工具呼叫的權限判斷時，會更有效率地使用快取（把算過的結果暫存起來直接用）；切換模式剛好碰上尚未完成的檢查，也會重新問你，而不套用過期結果。同一段對話前綴會重複用於判斷，因而降低 prompt-cache 成本。Stats 面板則把快取 token 納入總數，分開列出輸入、輸出、快取讀取與寫入。就像收費停車場重用已驗過的車牌資料，並把每種計費清楚印在收據上。

沒有共同歷史的 /ultrareview 會先說明

你用 /ultrareview 比對目前儲存庫與基準分支，兩者若沒有共同 Git 歷史，錯誤訊息現在更能指出下一步。完全沒有分支的 checkout（簽出副本，Git 目前取出的工作版本）會立刻被拒絕，並建議先建立分支；已是完整副本的情況，也不會再亂建議 git fetch --unshallow。這像地圖導航發現起點根本沒有接上道路時，會叫你先選一條路，而不是硬叫你去挖一條其實已經挖好的隧道。

Windows 啟動不再為查時間叫出 PowerShell

Windows 啟動 Claude Code 時，程式要讀取行程建立時間，現在直接呼叫原生的 kernel32，不再為這件事另外啟動 PowerShell。若公司的 endpoint security（端點安全工具，監看電腦程式行為的防護軟體）會攔住 powershell.exe，也就不會再跳出不必要的詢問。這不是少查資料，而是改走 Windows 自己的服務窗口；像大樓住戶查電錶，不必每次都叫外包技師進門，因此保全也不用反覆放行。

背景工作改為保留成果，是否開 PR 看任務

背景工作階段完成任務後，現在會 commit 並 push，讓做出的工作有地方可保存；但 draft PR（草稿合併請求，尚未準備合併的程式碼提案）只在任務本身要求時才開。它也會遵守你專案的 CLAUDE.md Git 指示，最後一定回報成果放在哪裡。這項行為會影響協作流程：把背景工作想成代你整理檔案的同事，他會把成品歸檔並告知位置，卻不會未經任務要求就送出一份請人審核的提案。

外掛安裝會重試，裝好可立即啟用

輸入 /plugin install 找不到外掛時，它會先刷新過期的市集目錄並重試，再告訴你真的找不到。從 /plugin 裝好的外掛，只要安全，現在會立刻啟用，不必一律再輸入 /reload-plugins。外掛也可把 skills 路徑寫成 "." 代表根目錄；根層 SKILL.md 驗證失敗時，錯誤訊息會明說應該使用外掛根目錄。像店員先更新庫存再說缺貨，新買的零件能直接裝上，而說明書放在盒子最上層也能被正確找到。

工作階段種類、表情與 /fork 各有新提示

想知道眼前工作階段是否還在你手上，/status 現在會標示它是 interactive，還是背景工作且為 attached 或 unattended。打表情符號時，常見替代短碼 :thumbsup:、:thumbsdown:、:love: 也會補全。至於用 /fork 分出新工作階段，它會替自己建立一份工作樹（worktree，Git 讓同一專案平行開多份副本的功能），不再直接在原工作階段的簽出副本裡工作。像看班表就知道誰值班、通訊軟體聽得懂不同簡寫，而分派的新同事也會拿到自己的桌面。

瀏覽器、快速模式與 Monitor 都會交代收尾

Claude in Chrome 完成工作、不再需要自己開的分頁後，會把那些分頁關掉。快速模式（fast mode，優先加快回應的模式）若在工作階段中途用完 usage credits（可用額度），串流回應會直接說明，不再沉默失敗。Monitor 裡的 watch（持續觀察命令輸出的功能）若結束前沒有任何輸出，也會明說「沒有輸出」，不再只寫含糊的「stream ended」。像助理借用幾張參考頁後會收好，預算耗盡會當面告知，巡邏員空手回來也會說他整趟沒看到事。

Gateway 驗證更嚴格，過期權限提醒不再重複

Gateway 收到 model 欄位不是字串時，現在會直接回 400 錯誤，不會照單全收再往後端轉送。這讓資料格式錯誤在入口就被擋下。另一邊，auto-mode 分類呼叫還排隊時如果權限模式改了，核准提示不會再反覆顯示那條變更通知。像郵局櫃檯看到地址欄塞進一張照片就當場退件，而不是把怪資料一路送到分揀中心；公告貼過一次，也不會每次排隊都重新貼滿牆。

VS Code chats can fold away tool details

When a VS Code chat answer is buried under a long trail of tool activity, switch to Focus view. It folds each turn's activity into an expandable summary while still showing which tool is currently running. Toggle it from the chat menu, with Ctrl+Alt+F, or through the “Claude Code: Toggle Focus view” command. It is like closing the kitchen doors while keeping the menu on the table: open them when you need to inspect the cooking, but do not let the pots block dinner.

The sandbox protects credentials and handles large uploads

On Linux and WSL, sandboxed commands can now read a masked stand-in for a credential file when it uses mode: "mask". The stand-in can cover the whole file or regions selected by an extract regex, while the sandbox proxy restores the real value only on egress. macOS falls back to denying the read. Large uploads through that proxy also no longer fail with TLS errors. Think of a shipping desk handing you a redacted copy, then having the clerk insert the real details only when the package leaves.

Plugins and prompts get a compatibility checkup

Before publishing a plugin or revising API prompts, there are now two earlier warnings. claude plugin validate flags marketplace or plugin names that Claude Desktop's managed marketplace sync would reject. The claude-api skill also adds prompt-audit, which looks for prompt and tool-description patterns written for older models. It is like checking whether a shop sign and its artwork fit the printer before sending them to press, instead of discovering the problem after distribution fails.

Permission checks close Bash and PowerShell gaps

A command that looks like a condition but hides another command inside it can no longer slip past permission checks. zsh previously could execute hidden commands in Bash tool [[ ]] regex conditionals without prompting; affected commands now require permission. On Windows, PowerShell checks also now correctly ask for approval when a path contains quote characters. It is like security finally checking a bag's inner pocket rather than just its label, even when the ID includes unusual punctuation.

Thinking and MCP connections stop quietly reverting

If a session began with thinking off, turning it on now affects the rest of that session as intended. An MCP server disabled while it is connecting also no longer silently comes back. Another fix targets claude -p: servers supplied with --mcp-config connect before the first turn, so the model does not print its tool calls as literal text instead of using them. It is like a control panel that no longer reconnects a machine after you deliberately unplugged it.

Resent prompts, SDK tools, and search are more reliable

When you retract a prompt with Esc and submit it again, files mentioned with @ no longer vanish silently. SDK MCP tools whose names match built-in object properties such as constructor also stop crashing while an API request is prepared. And WebSearch at xhigh or max effort with thinking disabled no longer returns a 400 error. It is like resubmitting an application with its attachments intact, having the clerk recognize an unusual surname, and finally letting a difficult query reach the archive.

Spend-limit messages and AWS sign-in on Windows are corrected

When Team or Enterprise users hit a spend limit, the message now correctly points to their individual limit instead of blaming the organization's monthly limit. In desktop-managed Windows sessions, Bedrock authentication with an AWS SSO named profile no longer fails merely because the machine has a stray HOME environment variable. One is like a credit-card alert naming the card that hit its limit; the other is like a security desk no longer following an address note left in the wrong drawer.

Auto-resume and re-authentication avoid surprises

Setting CLAUDE_CODE_RESUME_INTERRUPTED_TURN=0 now truly disables automatic resumption of an interrupted turn; other falsy values are honored too. After waking from sleep, two Claude Code processes could rarely refresh the same MCP connector or WIF OAuth token at once, forcing another sign-in. That race is avoided now. It is like a handover note saying “do not reopen automatically” finally being followed, while two staff members stop trying to replace the same lock at once.

Session names and plugin status stay in sync

Rename a session in Claude Code Desktop or claude.ai and the CLI now follows, with names sanitized from every rename surface. In non-interactive sessions, plugin- or organization-delivered skills that happen to be named like terminal built-ins such as /help and /feedback can now be invoked. The “Plugins changed” notification also clears after plugins reload. It is like one itinerary keeping the same clean title on your phone, the web, and the desk, while a finished alert takes itself down.

Vim mode keeps yanks and knows when to return

In Vim mode, the yank register no longer empties just because you opened a dialog, searched history, or viewed the transcript. There is also a small but important navigation fix: after undoing back to an empty prompt, the first left-arrow press arms the “press again to return to the agent view” confirmation instead of immediately taking you away. It is like a clipboard that does not empty when you browse papers, plus a warning light at the door before you leave the desk.

Auto-mode permissions reuse cache, and usage is visible

Tool search is available again on Google Vertex AI for Claude 4.5-generation and newer models. In auto mode, permission checks for parallel tool calls use the cache more efficiently; if you switch modes while a check is pending, it reliably asks again instead of applying a stale result. Reusing the cached conversation prefix also reduces prompt-cache costs. The Stats panel now includes cache tokens in totals and breaks them down by input, output, cache read, and cache write. It is like a paid car park reusing a verified plate record and printing every kind of charge on the receipt.

/ultrareview explains missing shared history up front

When /ultrareview compares a repository with a base that shares no Git history, its errors now point to the useful next step. A checkout with no branches is refused up front with advice to create one, while a complete clone is no longer incorrectly told to run git fetch --unshallow. It is like a map noticing that the starting point is not connected to any road, telling you to choose a road first rather than ordering you to dig a tunnel that already exists.

Windows startup no longer launches PowerShell just to read times

When Claude Code starts on Windows, it now reads process creation times through the native kernel32 call rather than spawning PowerShell for the job. Endpoint security tools that gate powershell.exe therefore stop prompting unnecessarily. The same information is still read; it simply uses Windows' own service counter instead. It is like checking a building meter without calling an outside technician through the lobby every time.

Background work preserves results and opens PRs only when asked

Background sessions now commit and push to preserve their work. They open a draft PR only when the task calls for one, follow the repository's CLAUDE.md Git instructions, and always finish by reporting where the work lives. This changes a collaboration habit: picture a colleague filing the finished work and telling you where it is, without sending a review request unless that was part of the assignment.

Plugin installs retry and can activate immediately

If /plugin install cannot find a plugin, it now refreshes a stale marketplace catalog and retries before saying it is unavailable. Plugins installed through /plugin activate immediately when safe instead of always requiring /reload-plugins. A plugin may also use "." as its skills path; if root-level SKILL.md validation fails, the message tells you to use the plugin root. It is like a clerk updating stock before declaring an item absent, then fitting a safe new part straight away and finding its manual at the top of the box.

Session types, emoji, and /fork get clearer behavior

/status now says whether a session is interactive or a background job that is attached or unattended. Emoji completion also accepts common alternate shortcodes such as :thumbsup:, :thumbsdown:, and :love:. And a session created with /fork receives its own worktree rather than working in the original session's checkout. It is like a roster showing who is on duty, a messenger understanding several familiar abbreviations, and a newly assigned colleague receiving a desk of their own.

Browser, fast mode, and Monitor all report their endings

Claude in Chrome now closes tabs it opened once it no longer needs them. If fast mode runs out of usage credits mid-session, the stream reports that fact instead of failing silently. And when a Monitor watch exits without producing output, it says so rather than merely reporting “stream ended.” It is like an assistant closing borrowed reference pages, telling you directly when the budget is gone, and a patrol officer reporting that nothing happened during the round.

Gateway validation tightens and stale permission notices disappear

When Gateway receives a non-string model field, it now rejects it with a 400 rather than forwarding it onward. That stops malformed data at the entrance. Separately, approval prompts no longer repeat the notice about a permission-mode change while an auto-mode classifier call was queued. It is like a post-office counter returning a photo placed in the address field instead of sending it to sorting, while a notice posted once does not cover the wall again for every person in line.

思考切换与 MCP 连接不再偷偷恢复

工作阶段一开始关掉 thinking（思考模式，让模型保留更多推理过程的开关）后，再把它打开，现在会确实影响这一整段对话。连线中的 MCP（Model Context Protocol，让 AI 连接外部工具的协议）服务器若被停用，也不会悄悄自己恢复。另一个修正针对 claude -p：通过 --mcp-config 加入的服务器会在第一回合前连好，不再让模型把本该执行的工具调用原样印成文字。这就像关掉一台设备后，控制台不会趁你转身又把它接回电源。

重送提示词、SDK 工具与搜索都更可靠

你按 Esc 撤回提示词后又送一次，先前用 @ 指名的文件不会再无声消失。开发者若用 SDK 的 MCP 工具，工具名称刚好是 JavaScript 内建对象属性，例如 constructor，准备 API 请求时也不会崩溃。至于关闭 thinking 后以 xhigh 或 max effort（投入更多推理资源的等级）跑 WebSearch，原本会收到 400 错误，现在可正常搜索。像重新递一份附档申请书、让窗口正确辨认罕见姓氏，最后也让高难度查询真的送进资料库。

额度消息与 Windows 的 AWS 登录说清楚

Team 或 Enterprise 用户碰到 spend limit（支出上限）时，消息终于会指向自己的个人上限，而不是错怪组织的月上限。Windows 的桌面受管理工作阶段里，使用 AWS SSO 命名配置文件登录 Bedrock 时，若电脑碰巧有多余的 HOME 环境变量（启动程序前预先给它的设置值），也不会再登录失败。前者像信用卡通知终于指出是你的卡刷到上限；后者则像门禁不再被一张放错抽屉的地址便条带错路。

自动续接与重新验证少了意外

若你明确设 CLAUDE_CODE_RESUME_INTERRUPTED_TURN=0，被打断回合的自动续接现在真的会关掉；其他代表关闭的 falsy 值也会被尊重。电脑睡醒时，两个 Claude Code 进程偶尔会同时更新同一个 MCP 连接器或 WIF OAuth token（用来证明登录身份的授权令牌），互相踩到而逼你重登；现在避免了这场竞跑。像在交接簿写下“不要自动续办”后，值班人员不会照样替你开案；两人也不会同时抢着换同一把门锁。

工作阶段名称与插件状态不再失联

你在 Claude Code Desktop 或 claude.ai 改工作阶段名称，CLI 现在也会更新，而且不论从哪个界面改都会先整理名称格式。非交互工作阶段（没有终端窗口、直接执行的模式）里，插件或组织派发的 skill（技能，告诉 Claude 如何处理特定工作的指示）若刚好叫 /help、/feedback 等终端内建名，也能叫得动。插件重载完成后，“Plugins changed”通知也会自动消失。像同一份行程表在手机、网页与柜台都用同名，活动结束的提醒则会自行撤牌。

Vim 模式记得复制内容，也更懂返回时机

用 Vim mode（Vim 模式，用键盘命令编辑文字的操作方式）编写提示词时，yank register（暂存复制文字的位置）不会再因为开过对话框、搜索历史或看逐字稿就被清空。另一个小但重要的修正是：你一路 undo 回空白提示词后，第一次按左箭头会先准备“再按一次才回代理画面”的确认，而不是立刻跳走。像剪贴板不会因为你翻了几页文件就倒空；走到门口也会先亮警示灯，免得你按错一步就离开编辑桌。

自动模式的权限判断更省缓存，也看得见用量

Google Vertex AI 上的 Claude 4.5 世代以上模型，tool search（工具搜索，让模型找可用工具的功能）重新可用。自动模式处理并行工具调用的权限判断时，会更有效率地使用缓存（把算过的结果暂存起来直接用）；切换模式刚好碰上尚未完成的检查，也会重新问你，而不套用过期结果。同一段对话前缀会重复用于判断，因而降低 prompt-cache 成本。Stats 面板则把缓存 token 纳入总数，分开列出输入、输出、缓存读取与写入。就像收费停车场重用已验过的车牌资料，并把每种计费清楚印在收据上。

没有共同历史的 /ultrareview 会先说明

你用 /ultrareview 比对目前仓库与基准分支，两者若没有共同 Git 历史，错误消息现在更能指出下一步。完全没有分支的 checkout（签出副本，Git 当前取出的工作版本）会立刻被拒绝，并建议先建立分支；已是完整副本的情况，也不会再乱建议 git fetch --unshallow。这像地图导航发现起点根本没有接上道路时，会叫你先选一条路，而不是硬叫你去挖一条其实已经挖好的隧道。

Windows 启动不再为查时间叫出 PowerShell

Windows 启动 Claude Code 时，程序要读取进程建立时间，现在直接调用原生的 kernel32，不再为这件事另外启动 PowerShell。若公司的 endpoint security（端点安全工具，监看电脑程序行为的防护软件）会拦住 powershell.exe，也就不会再跳出不必要的询问。这不是少查资料，而是改走 Windows 自己的服务窗口；像大楼住户查电表，不必每次都叫外包技师进门，因此保全也不用反复放行。

后台工作改为保留成果，是否开 PR 看任务

后台工作阶段完成任务后，现在会 commit 并 push，让做出的工作有地方可保存；但 draft PR（草稿合并请求，尚未准备合并的代码提案）只在任务本身要求时才开。它也会遵守你项目的 CLAUDE.md Git 指示，最后一定汇报成果放在哪里。这项行为会影响协作流程：把后台工作想成代你整理文件的同事，他会把成品归档并告知位置，却不会未经任务要求就送出一份请人审核的提案。

插件安装会重试，装好可立即启用

输入 /plugin install 找不到插件时，它会先刷新过期的市场目录并重试，再告诉你真的找不到。从 /plugin 装好的插件，只要安全，现在会立刻启用，不必一律再输入 /reload-plugins。插件也可把 skills 路径写成 "." 代表根目录；根层 SKILL.md 验证失败时，错误消息会明说应该使用插件根目录。像店员先更新库存再说缺货，新买的零件能直接装上，而说明书放在盒子最上层也能被正确找到。

工作阶段种类、表情与 /fork 各有新提示

想知道眼前工作阶段是否还在你手上，/status 现在会标示它是 interactive，还是后台工作且为 attached 或 unattended。打表情符号时，常见替代短码 :thumbsup:、:thumbsdown:、:love: 也会补全。至于用 /fork 分出新工作阶段，它会替自己建立一份工作树（worktree，Git 让同一个项目平行开多份副本的功能），不再直接在原工作阶段的签出副本里工作。像看班表就知道谁值班、通信软件听得懂不同简写，而分派的新同事也会拿到自己的桌面。

浏览器、快速模式与 Monitor 都会交代收尾

Claude in Chrome 完成工作、不再需要自己开的分页后，会把那些分页关掉。快速模式（fast mode，优先加快回应的模式）若在工作阶段中途用完 usage credits（可用额度），串流回应会直接说明，不再沉默失败。Monitor 里的 watch（持续观察命令输出的功能）若结束前没有任何输出，也会明说“没有输出”，不再只写含糊的“stream ended”。像助理借用几张参考页后会收好，预算耗尽会当面告知，巡逻员空手回来也会说他整趟没看到事。

Gateway 验证更严格，过期权限提醒不再重复

Gateway 收到 model 字段不是字符串时，现在会直接回 400 错误，不会照单全收再往后端转送。这让资料格式错误在入口就被挡下。另一边，auto-mode 分类调用还排队时如果权限模式改了，批准提示不会再反复显示那条变更通知。像邮局柜台看到地址栏塞进一张照片就当场退件，而不是把怪资料一路送到分拣中心；公告贴过一次，也不会每次排队都重新贴满墙。

サンドボックスが認証情報を守り、大きなアップロードも支える

Linux と WSL では、認証情報ファイルに mode: "mask" を指定すると、サンドボックス内のコマンドは代替コピーを読むようになった。ファイル全体だけでなく、extract 正規表現で選んだ箇所も隠せる。外へ送る時だけサンドボックスプロキシが本物の値へ差し替える。macOS ではこの方式を使えないため読み取りを拒否する。さらに、そのプロキシ経由の大容量アップロードは TLS エラーで失敗しなくなった。配送窓口が伏せ字の控えを渡し、発送時だけ係員が本票を差し込むようなものだ。

プラグインとプロンプトを先に互換性診断できる

プラグインを公開したり API のプロンプトを直したりする前に、二つの早期警告を使えるようになった。claude plugin validate は、Claude Desktop の管理対象マーケットプレイス同期で拒否される名前を警告する。claude-api skill には、古いモデル向けの書き方がプロンプトやツール説明に残っていないか調べる prompt-audit 子コマンドも加わった。印刷に出す前に、店名の看板と原稿が新しい印刷機に通るか校正するようなものだ。

Bash と PowerShell の権限確認の穴を塞いだ

条件式に見せかけて別のコマンドを隠す抜け道を、権限確認が見逃さなくなった。以前は zsh が Bash ツールの [[ ]] 正規表現条件の中で隠しコマンドを実行し、確認を回避できたが、該当するコマンドは今後許可を求める。Windows では、引用符を含むパスを PowerShell が誤って処理していた問題も直り、同じく承認を求める。入館口が袋の表札だけでなく内ポケットまで確認し、記号入りの身分証でも見間違えないようなものだ。

思考設定と MCP 接続が勝手に戻らなくなった

セッション開始時に thinking をオフにしていても、後からオンにすれば残りの会話にきちんと反映される。接続中の MCP サーバーを無効にした場合も、黙って元に戻らない。claude -p では --mcp-config で渡したサーバーが最初のターン前に接続され、本来実行すべきツール呼び出しを文字として出力しなくなった。意図して電源を抜いた機器を、操作盤が勝手につなぎ直さないようなものだ。

再送信したプロンプト、SDK ツール、検索が安定した

利用上限の案内と Windows の AWS ログインを正した

Team や Enterprise の利用者が spend limit に達した時、表示は組織の月間上限を誤って責めず、本人の個別上限を正しく指す。Windows のデスクトップ管理セッションで AWS SSO の名前付きプロファイルを使って Bedrock に認証する場合も、不要な HOME 環境変数があるだけで失敗しなくなった。前者はカード利用通知が上限に達したカードを正しく示すようなもの、後者は受付が引き出しに紛れた住所メモに惑わされないようなものだ。

自動再開と再認証の不意打ちを減らした

CLAUDE_CODE_RESUME_INTERRUPTED_TURN=0 を設定すれば、中断したターンの自動再開は本当に無効になる。ほかの falsy 値もオフとして尊重される。スリープ復帰時には、二つの Claude Code プロセスが同じ MCP コネクタや WIF OAuth token を同時に更新し、再ログインを強いることがまれにあったが、この競合を避けるようになった。引き継ぎメモの「自動で再開しない」を守り、二人が同じ鍵を同時に交換しなくなるようなものだ。

セッション名とプラグイン状態が連携した

Claude Code Desktop や claude.ai でセッション名を変えると、CLI の名前も更新される。どの画面から変更しても名前は整えられる。非対話セッションでは、プラグインや組織配布の skill が /help や /feedback のような端末組み込み名と重なっていても呼び出せるようになった。プラグインを再読み込みすれば「Plugins changed」の通知も消える。スマホ、Web、受付で同じ予定表の題名を共有し、終わった案内札が自分で下がるようなものだ。

Vim モードがヤンクを覚え、戻るタイミングも正した

Vim mode では、ダイアログを開いたり履歴検索や逐語録表示をしたりしても yank register が空にならない。空のプロンプトまで undo した後も、最初の左矢印で即座にエージェント画面へ戻るのではなく、「もう一度押すと戻る」という確認が有効になる。書類をめくってもクリップボードが空にならず、机を離れる前に出口の警告灯が点くようなものだ。

自動モードの権限判定がキャッシュを節約し、利用量も見える

Google Vertex AI では Claude 4.5 世代以降のモデルで tool search が再び使える。自動モードの並列ツール呼び出しに対する権限確認はキャッシュをより効率的に使い、確認待ちの間にモードを変えた場合も古い結果を適用せず、確実に再確認する。同じ会話の先頭部分を再利用して prompt-cache のコストも下げる。Stats パネルはキャッシュ token を合計に含め、入力、出力、キャッシュ読み取り、書き込みを分けて示す。有料駐車場が確認済みのナンバーを再利用し、料金の内訳を領収書に明記するようなものだ。

共通履歴のない /ultrareview は先に理由を示す

/ultrareview で現在のリポジトリとベースに共通の Git 履歴がない時、エラーが次にすべきことを示すようになった。ブランチのない checkout は最初に拒否され、まずブランチを作るよう案内される。完全な clone には git fetch --unshallow を誤って勧めない。地図が出発地点を道路につながっていないと見つけ、既にあるトンネルを掘れと言う代わりに、まず道路を選ぶよう教える感じだ。

Windows 起動時に時刻取得だけで PowerShell を呼ばなくなった

Windows で Claude Code を起動する時、プロセス作成時刻は PowerShell を起動して読むのではなく、ネイティブの kernel32 呼び出しで取得する。powershell.exe を監視する endpoint security ツールも不要な確認を出さなくなる。情報を読まなくなったのではなく、Windows 自身の窓口を使うだけだ。建物のメーター確認のたびに外部の技師をロビーへ通さなくてよくなるようなものだ。

バックグラウンド作業は成果を残し、PR は必要な時だけ開く

バックグラウンドセッションは作業を残すために commit と push を行うようになった。draft PR を開くのはタスクが求める時だけで、リポジトリの CLAUDE.md にある Git 指示に従い、最後には成果物の場所を必ず報告する。これは協業の振る舞いを変える。作業を片付けて保管場所を知らせる同僚だが、依頼にないレビュー依頼までは送らない、と考えると分かりやすい。

プラグイン導入は再試行し、入れたらすぐ有効にできる

/plugin install がプラグインを見つけられない場合、古いマーケットプレイスカタログを更新して再試行してから、見つからないと告げる。/plugin で入れたプラグインは安全ならすぐ有効になり、常に /reload-plugins を要しない。skills のパスには "." も使え、ルートの SKILL.md の検証が失敗した場合はプラグインルートを使うようエラーが案内する。在庫を更新してから品切れと言い、安全な新部品をすぐ取り付け、箱の上にある説明書も見つける店員のようなものだ。

セッション種別、絵文字、/fork の挙動が分かりやすくなった

/status はセッションが interactive なのか、attached または unattended のバックグラウンドジョブなのかを示す。絵文字補完は :thumbsup:、:thumbsdown:、:love: などのよく使う別名も受け付ける。/fork で作ったセッションは元の checkout で作業せず、自分用の worktree を持つ。当番表で担当が分かり、メッセンジャーが複数の略記を理解し、新任の同僚にも自分の机が渡るようなものだ。

ブラウザー、fast mode、Monitor が終わり方を明確に伝える

Claude in Chrome は、自分で開いたタブが不要になると閉じるようになった。fast mode の利用中に usage credits が尽きた場合も、黙って失敗せずストリームで知らせる。Monitor の watch が出力なしで終了した時も、「stream ended」とだけ言わず、出力がなかったと明示する。助手が借りた参考ページを閉じ、予算切れを直接伝え、巡回員が何もなかったことも報告するようなものだ。

Gateway の検証を厳しくし、古い権限通知を繰り返さない

Gateway は model フィールドが文字列でない場合、後方へ転送せず 400 で拒否する。形式の壊れたデータを入口で止められる。また、auto-mode の分類呼び出しが待ち行列にある間に権限モードが変わっても、承認プロンプトがその通知を繰り返し表示しない。郵便局の窓口が住所欄に写真を入れた郵便をその場で返し、同じ掲示を列の一人ごとに壁へ貼り直さないようなものだ。

VS Code에서 Claude와 대화할 때 답변이 긴 도구 작업 기록에 묻힌다면 Focus view로 바꿀 수 있다. 턴마다 도구 활동을 펼칠 수 있는 요약으로 접되, 지금 실행 중인 도구는 계속 보여 준다. 채팅 메뉴, Ctrl+Alt+F, 또는 “Claude Code: Toggle Focus view” 명령으로 전환한다. 주방의 조리 과정은 문 뒤로 접어 두고 식탁에는 메뉴만 남기는 것과 같다. 확인할 때만 문을 열면 된다.

샌드박스가 자격 증명을 지키고 큰 업로드도 처리한다

Linux와 WSL에서는 자격 증명 파일에 mode: "mask"를 지정하면 샌드박스 안의 명령이 대체 사본을 읽는다. 파일 전체뿐 아니라 extract 정규식으로 고른 부분도 가릴 수 있고, 밖으로 보낼 때만 샌드박스 프록시가 실제 값으로 바꾼다. macOS에서는 이 방식 대신 읽기를 거부한다. 또한 그 프록시를 거치는 큰 업로드가 TLS 오류로 실패하지 않게 됐다. 배송 창구가 가려진 사본을 주고 발송 순간에만 직원이 진짜 정보를 넣는 것과 같다.

플러그인과 프롬프트를 먼저 호환성 점검할 수 있다

플러그인을 배포하거나 API 프롬프트를 고치기 전에 두 가지 조기 경고를 쓸 수 있다. claude plugin validate는 Claude Desktop의 관리형 마켓플레이스 동기화가 거부할 마켓플레이스나 플러그인 이름을 알린다. claude-api skill에는 예전 모델을 위해 쓴 프롬프트와 도구 설명 패턴을 살피는 prompt-audit 하위 명령도 추가됐다. 인쇄를 맡기기 전에 가게 간판과 원고가 새 인쇄기에 맞는지 교정하는 것과 같다.

Bash와 PowerShell 권한 확인의 빈틈을 막았다

조건식처럼 보이지만 안에 다른 명령을 숨긴 경우도 이제 권한 확인을 피할 수 없다. 이전에는 zsh가 Bash 도구의 [[ ]] 정규식 조건 안에서 숨은 명령을 실행해 확인을 우회할 수 있었지만, 해당 명령은 이제 권한을 요구한다. Windows에서는 경로에 따옴표가 있을 때 PowerShell 검사가 잘못 처리하던 문제도 고쳐져 승인받는다. 출입구가 가방 겉면만 보지 않고 안주머니까지 확인하며, 기호가 든 신분증도 잘못 읽지 않는 것과 같다.

사고 설정과 MCP 연결이 몰래 되돌아가지 않는다

세션을 시작할 때 thinking을 껐더라도 나중에 켜면 이제 남은 대화에 제대로 반영된다. 연결 중인 MCP 서버를 비활성화해도 몰래 다시 켜지지 않는다. claude -p에서는 --mcp-config로 넣은 서버가 첫 턴 전에 연결되어, 모델이 실행할 도구 호출을 글자 그대로 출력하지 않는다. 일부러 전원을 뽑은 장비를 조작반이 뒤에서 다시 연결하지 않는 것과 같다.

다시 보낸 프롬프트, SDK 도구, 검색이 더 안정됐다

Esc로 프롬프트를 거둔 뒤 다시 보내도 @로 지정한 파일이 조용히 사라지지 않는다. SDK의 MCP 도구 이름이 constructor처럼 내장 객체 속성과 같아도 API 요청을 준비하다 충돌하지 않는다. thinking을 끈 채 xhigh 또는 max effort로 WebSearch를 실행할 때 나던 400 오류도 고쳐졌다. 첨부 서류를 그대로 다시 내고, 창구가 드문 성을 제대로 알아보며, 어려운 검색도 자료실까지 들어가는 것과 같다.

사용 한도 안내와 Windows의 AWS 로그인을 바로잡았다

Team 또는 Enterprise 사용자가 spend limit에 닿으면 이제 메시지가 조직의 월 한도를 잘못 탓하지 않고 개인 한도를 가리킨다. Windows의 데스크톱 관리 세션에서 AWS SSO 이름 프로필로 Bedrock에 인증할 때도, 남아 있는 HOME 환경 변수 하나 때문에 실패하지 않는다. 전자는 카드 한도 알림이 어느 카드의 한도인지 제대로 알려 주는 일이고, 후자는 경비 데스크가 서랍에 잘못 든 주소 메모를 따라가지 않는 일과 같다.

자동 재개와 재인증의 뜻밖의 문제를 줄였다

CLAUDE_CODE_RESUME_INTERRUPTED_TURN=0을 설정하면 중단된 턴의 자동 재개가 이제 실제로 꺼진다. 다른 falsy 값도 꺼짐으로 존중한다. 잠에서 깰 때 두 Claude Code 프로세스가 같은 MCP 커넥터나 WIF OAuth token을 동시에 갱신해 다시 로그인해야 했던 드문 경쟁도 피한다. 인수인계장에 ‘자동 재개하지 말 것’이라고 쓰면 당직자가 그대로 따르고, 두 사람이 같은 자물쇠를 동시에 바꾸려 들지 않는 것과 같다.

세션 이름과 플러그인 상태가 동기화된다

Claude Code Desktop이나 claude.ai에서 세션 이름을 바꾸면 CLI에도 반영되고, 어느 화면에서 바꿔도 이름 형식을 정리한다. 비대화형 세션에서는 플러그인이나 조직이 배포한 skill 이름이 /help, /feedback 같은 터미널 내장 이름과 겹쳐도 호출할 수 있다. 플러그인을 다시 불러온 뒤에는 “Plugins changed” 알림도 사라진다. 휴대폰, 웹, 안내 데스크의 일정표가 같은 깔끔한 제목을 쓰고 끝난 알림판은 스스로 내려가는 것과 같다.

Vim 모드가 복사 내용을 기억하고 돌아갈 때를 안다

Vim mode에서는 대화 상자를 열거나 기록을 검색하고 대화 기록을 봐도 yank register가 비워지지 않는다. 빈 프롬프트까지 undo한 뒤에도 왼쪽 화살표를 처음 누르면 바로 에이전트 화면으로 가지 않고 ‘한 번 더 누르면 돌아감’ 확인이 준비된다. 서류를 몇 장 넘긴다고 클립보드가 비지 않고, 책상을 떠나기 전 출구 경고등이 켜지는 것과 같다.

자동 모드 권한 판단이 캐시를 아끼고 사용량도 보인다

Google Vertex AI에서는 Claude 4.5 세대 이상 모델에서 tool search를 다시 쓸 수 있다. 자동 모드의 병렬 도구 호출 권한 확인은 캐시를 더 효율적으로 쓰며, 확인이 기다리는 동안 모드를 바꾸면 오래된 결과를 적용하지 않고 다시 묻는다. 같은 대화 앞부분을 재사용해 prompt-cache 비용도 줄인다. Stats 패널은 캐시 token을 합계에 넣고 입력, 출력, 캐시 읽기, 쓰기를 나눠 보여 준다. 유료 주차장이 이미 확인한 차량 번호를 재사용하고 영수증에 모든 요금 항목을 적는 것과 같다.

공통 기록이 없는 /ultrareview가 먼저 이유를 알려 준다

/ultrareview가 현재 저장소와 기준 사이에 공통 Git 기록을 찾지 못하면, 오류가 이제 다음 할 일을 알려 준다. 브랜치가 없는 checkout은 처음부터 거절하고 브랜치를 만들라고 안내한다. 이미 완전한 clone에는 git fetch --unshallow을 잘못 권하지 않는다. 지도가 출발점이 어느 길에도 연결되지 않았음을 보고, 이미 있는 터널을 다시 파라고 하는 대신 먼저 길을 고르라고 알려 주는 것과 같다.

Windows 시작 시 시간 확인만 하려고 PowerShell을 띄우지 않는다

Windows에서 Claude Code를 시작할 때 프로세스 생성 시간은 이제 PowerShell을 따로 띄우지 않고 네이티브 kernel32 호출로 읽는다. powershell.exe를 막는 endpoint security 도구도 불필요한 확인을 띄우지 않는다. 정보를 덜 읽는 것이 아니라 Windows 자체 창구를 쓰는 것이다. 건물 계량기를 확인할 때마다 외부 기사를 로비로 들일 필요가 없어지는 것과 같다.

백그라운드 작업은 결과를 남기고 PR은 필요할 때만 연다

백그라운드 세션은 작업을 보존하기 위해 commit과 push를 하도록 바뀌었다. draft PR은 작업에서 요구할 때만 열며, 저장소의 CLAUDE.md Git 지시를 따르고 마지막에는 결과물이 있는 곳을 반드시 알린다. 협업 방식에 영향을 주는 변화다. 일을 정리해 보관하고 위치는 알려 주지만, 요청하지 않은 검토 요청까지 보내지는 않는 동료와 같다.

플러그인 설치는 다시 시도하고 곧바로 활성화할 수 있다

/plugin install이 플러그인을 찾지 못하면 오래된 마켓플레이스 목록을 새로고침하고 다시 시도한 뒤에야 없다고 알린다. /plugin으로 설치한 플러그인은 안전하면 곧바로 활성화되어 늘 /reload-plugins를 할 필요가 없다. 플러그인의 skills 경로에는 "."도 쓸 수 있고, 루트 SKILL.md 검증이 실패하면 오류가 플러그인 루트를 쓰라고 안내한다. 점원이 재고를 갱신한 뒤 품절을 말하고, 안전한 새 부품은 바로 달며, 상자 맨 위의 설명서도 찾는 것과 같다.

세션 종류, 이모지, /fork의 동작이 더 분명해졌다

/status는 세션이 interactive인지, attached 또는 unattended 상태의 백그라운드 작업인지 보여 준다. 이모지 자동 완성도 :thumbsup:, :thumbsdown:, :love: 같은 흔한 다른 짧은 코드도 받는다. /fork로 만든 세션은 원래 checkout에서 일하지 않고 자기 worktree를 받는다. 근무표로 담당자를 알 수 있고 메신저가 여러 약어를 알아들으며, 새 동료도 자기 책상을 받는 것과 같다.

브라우저, fast mode, Monitor가 끝난 상황을 분명히 알린다

Claude in Chrome은 자신이 연 탭이 더는 필요 없으면 닫는다. fast mode를 쓰다가 세션 중간에 usage credits가 소진돼도 조용히 실패하지 않고 스트림에 알린다. Monitor의 watch가 아무 출력 없이 끝나면 ‘stream ended’라고만 하지 않고 출력이 없었다고 밝힌다. 조수가 빌린 참고 페이지를 닫고, 예산이 떨어지면 직접 알리며, 순찰자가 아무 일도 없었다고 보고하는 것과 같다.

Gateway 검증을 엄격히 하고 오래된 권한 알림을 반복하지 않는다

Gateway는 model 필드가 문자열이 아니면 뒤로 넘기지 않고 400 오류로 거절한다. 형식이 잘못된 자료를 입구에서 막는 셈이다. 또 auto-mode 분류 호출이 대기 중일 때 권한 모드가 바뀌어도 승인 안내가 그 변경 알림을 반복하지 않는다. 우체국 창구가 주소 칸에 사진을 넣은 우편물을 그 자리에서 돌려보내고, 같은 공지를 줄 선 사람마다 벽에 다시 붙이지 않는 것과 같다.
