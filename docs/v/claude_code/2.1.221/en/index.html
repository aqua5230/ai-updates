Claude Code 2.1.221

Released: 2026-08-04

Release notes

FEATURE

VS Code chats can fold away tool details

When a VS Code chat answer is buried under a long trail of tool activity, switch to Focus view.

It folds each turn's activity into an expandable summary while still showing which tool is currently running. Toggle it from the chat menu, with Ctrl+Alt+F, or through the “Claude Code: Toggle Focus view” command. It is like closing the kitchen doors while keeping the menu on the table: open them when you need to inspect the cooking, but do not let the pots block dinner.

FEATURE

The sandbox protects credentials and handles large uploads

On Linux and WSL, sandboxed commands can now read a masked stand-in for a credential file when it uses mode: "mask".

The stand-in can cover the whole file or regions selected by an extract regex, while the sandbox proxy restores the real value only on egress. macOS falls back to denying the read. Large uploads through that proxy also no longer fail with TLS errors. Think of a shipping desk handing you a redacted copy, then having the clerk insert the real details only when the package leaves.

FEATURE

Plugins and prompts get a compatibility checkup

Before publishing a plugin or revising API prompts, there are now two earlier warnings.

claude plugin validate flags marketplace or plugin names that Claude Desktop's managed marketplace sync would reject. The claude-api skill also adds prompt-audit, which looks for prompt and tool-description patterns written for older models. It is like checking whether a shop sign and its artwork fit the printer before sending them to press, instead of discovering the problem after distribution fails.

BUGFIX

Permission checks close Bash and PowerShell gaps

A command that looks like a condition but hides another command inside it can no longer slip past permission checks.

zsh previously could execute hidden commands in Bash tool [[ ]] regex conditionals without prompting; affected commands now require permission. On Windows, PowerShell checks also now correctly ask for approval when a path contains quote characters. It is like security finally checking a bag's inner pocket rather than just its label, even when the ID includes unusual punctuation.

BUGFIX

Thinking and MCP connections stop quietly reverting

If a session began with thinking off, turning it on now affects the rest of that session as intended.

An MCP server disabled while it is connecting also no longer silently comes back. Another fix targets claude -p: servers supplied with --mcp-config connect before the first turn, so the model does not print its tool calls as literal text instead of using them. It is like a control panel that no longer reconnects a machine after you deliberately unplugged it.

BUGFIX

Resent prompts, SDK tools, and search are more reliable

When you retract a prompt with Esc and submit it again, files mentioned with @ no longer vanish silently.

SDK MCP tools whose names match built-in object properties such as constructor also stop crashing while an API request is prepared. And WebSearch at xhigh or max effort with thinking disabled no longer returns a 400 error. It is like resubmitting an application with its attachments intact, having the clerk recognize an unusual surname, and finally letting a difficult query reach the archive.

BUGFIX

Spend-limit messages and AWS sign-in on Windows are corrected

When Team or Enterprise users hit a spend limit, the message now correctly points to their individual limit instead of blaming the organization's monthly limit.

In desktop-managed Windows sessions, Bedrock authentication with an AWS SSO named profile no longer fails merely because the machine has a stray HOME environment variable. One is like a credit-card alert naming the card that hit its limit; the other is like a security desk no longer following an address note left in the wrong drawer.

BUGFIX

Auto-resume and re-authentication avoid surprises

Setting CLAUDE_CODE_RESUME_INTERRUPTED_TURN=0 now truly disables automatic resumption of an interrupted turn; other falsy values are honored too.

After waking from sleep, two Claude Code processes could rarely refresh the same MCP connector or WIF OAuth token at once, forcing another sign-in. That race is avoided now. It is like a handover note saying “do not reopen automatically” finally being followed, while two staff members stop trying to replace the same lock at once.

BUGFIX

Session names and plugin status stay in sync

Rename a session in Claude Code Desktop or claude.

ai and the CLI now follows, with names sanitized from every rename surface. In non-interactive sessions, plugin- or organization-delivered skills that happen to be named like terminal built-ins such as /help and /feedback can now be invoked. The “Plugins changed” notification also clears after plugins reload. It is like one itinerary keeping the same clean title on your phone, the web, and the desk, while a finished alert takes itself down.

BUGFIX

Vim mode keeps yanks and knows when to return

In Vim mode, the yank register no longer empties just because you opened a dialog, searched history, or viewed the transcript.

There is also a small but important navigation fix: after undoing back to an empty prompt, the first left-arrow press arms the “press again to return to the agent view” confirmation instead of immediately taking you away. It is like a clipboard that does not empty when you browse papers, plus a warning light at the door before you leave the desk.

FEATURE

Auto-mode permissions reuse cache, and usage is visible

Tool search is available again on Google Vertex AI for Claude 4.

5-generation and newer models. In auto mode, permission checks for parallel tool calls use the cache more efficiently; if you switch modes while a check is pending, it reliably asks again instead of applying a stale result. Reusing the cached conversation prefix also reduces prompt-cache costs. The Stats panel now includes cache tokens in totals and breaks them down by input, output, cache read, and cache write. It is like a paid car park reusing a verified plate record and printing every kind of charge on the receipt.

FEATURE

/ultrareview explains missing shared history up front

When /ultrareview compares a repository with a base that shares no Git history, its errors now point to the useful next step.

A checkout with no branches is refused up front with advice to create one, while a complete clone is no longer incorrectly told to run git fetch --unshallow. It is like a map noticing that the starting point is not connected to any road, telling you to choose a road first rather than ordering you to dig a tunnel that already exists.

PERF

Windows startup no longer launches PowerShell just to read times

When Claude Code starts on Windows, it now reads process creation times through the native kernel32 call rather than spawning PowerShell for the job.

Endpoint security tools that gate powershell.exe therefore stop prompting unnecessarily. The same information is still read; it simply uses Windows' own service counter instead. It is like checking a building meter without calling an outside technician through the lobby every time.

FEATURE

Background work preserves results and opens PRs only when asked

Background sessions now commit and push to preserve their work.

They open a draft PR only when the task calls for one, follow the repository's CLAUDE.md Git instructions, and always finish by reporting where the work lives. This changes a collaboration habit: picture a colleague filing the finished work and telling you where it is, without sending a review request unless that was part of the assignment.

FEATURE

Plugin installs retry and can activate immediately

If /plugin install cannot find a plugin, it now refreshes a stale marketplace catalog and retries before saying it is unavailable.

Plugins installed through /plugin activate immediately when safe instead of always requiring /reload-plugins. A plugin may also use "." as its skills path; if root-level SKILL.md validation fails, the message tells you to use the plugin root. It is like a clerk updating stock before declaring an item absent, then fitting a safe new part straight away and finding its manual at the top of the box.

FEATURE

Session types, emoji, and /fork get clearer behavior

/status now says whether a session is interactive or a background job that is attached or unattended.

Emoji completion also accepts common alternate shortcodes such as :thumbsup:, :thumbsdown:, and :love:. And a session created with /fork receives its own worktree rather than working in the original session's checkout. It is like a roster showing who is on duty, a messenger understanding several familiar abbreviations, and a newly assigned colleague receiving a desk of their own.

FEATURE

Browser, fast mode, and Monitor all report their endings

Claude in Chrome now closes tabs it opened once it no longer needs them.

If fast mode runs out of usage credits mid-session, the stream reports that fact instead of failing silently. And when a Monitor watch exits without producing output, it says so rather than merely reporting “stream ended.” It is like an assistant closing borrowed reference pages, telling you directly when the budget is gone, and a patrol officer reporting that nothing happened during the round.

FEATURE

Gateway validation tightens and stale permission notices disappear

When Gateway receives a non-string model field, it now rejects it with a 400 rather than forwarding it onward.

That stops malformed data at the entrance. Separately, approval prompts no longer repeat the notice about a permission-mode change while an auto-mode classifier call was queued. It is like a post-office counter returning a photo placed in the address field instead of sending it to sorting, while a notice posted once does not cover the wall again for every person in line.
