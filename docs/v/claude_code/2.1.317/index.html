Claude Code 2.1.317

發布日期：2026-11-03

繁體中文

新功能

外寄帳號郵件前新增確認，防堵終端機工具洩漏個資

當你請 Claude 透過終端機執行指令或抓取網頁時，工具呼叫可能會夾帶個人敏感資訊。現在不管是網頁瀏覽還是命令列工具，只要即將把你的帳號電子郵件傳送到外部網路，終端機都會先彈出提示詢問你是否放行。

像寄出重要信件前櫃檯人員會逐頁翻開附件，以前只要你按下了寄送鍵，信件就直接投遞出去；現在一旦發現收件清單含有你的私人地址，櫃檯便會先停下來請你確認。

這防止了腳本或第三方套件在未經授權的情況下，悄悄把你的聯絡信箱回傳給外部伺服器。

新功能

Agent SDK 掛鉤新增阻擋選項，回呼失敗即刻中斷動作

開發者在撰寫代理程式的自動化流程時，常需要設定檢查點來攔截危險動作。Agent SDK 的 hook（特定事件發生時被觸發的掛鉤程式）回呼函式現在支援 onFailure: "block" 設定。當回呼執行失敗或拋出錯誤時，會主動阻擋接下來的操作，不再放任動作繼續執行。

就像智慧門禁的感應器故障時自動上鎖，以前警報線路一旦斷訊，閘門反而會因為程式沒有中斷而直接放行；現在只要安全檢驗沒有順利跑完，整道關卡便會立刻卡死。

這確保了前置安全性檢查出狀況時，未經驗證的變更不會被貿然套用。

問題修復

自動模式健全檢查機制，修復子代理空白與雲端卡關

當你切換到自動模式放手讓 Claude 獨立處理工作時，畫面卡住或無故中斷常讓人摸不著頭緒。現在當安全檢查對子代理的工具呼叫沒有回應時，主畫面會主動跳出通知，不再留下一片空白。自訂模型閘道若對伺服器端安全檢查回傳 403 或 422 錯誤碼，自動模式不會再每輪都報錯中斷；搭配 apiKeyHelper 的 403 處理則維持原樣。在雲端工作階段裡，當 Artifact 工具上傳資料、寫入資料庫或透過 outputs 資料夾儲存檔案時，自動模式會順暢執行，不再突然停下來等待手動批准。

問題修復

排程任務加強連接器預警，修復下次執行時間與循環喚醒

依賴定時排程或背景循環來自動化工作時，任務的狀態顯示與連結設定至關重要。使用 /schedule 建立雲端排程任務時，如果任務被掛上了未要求的連接器，終端機會主動跳出警示並附上移除指引。建立或更新排程後的結果清單，現在也會正常顯示下次執行時間與對應連結，不再莫名缺漏。過去若在全域關閉了排程功能，已儲存的任務會無法列出或刪除，現在隨時都能正常清理。另一方面，當 Claude 在請求中遺漏部分欄位時，/loop 的自主節奏喚醒排程有時會遺失，這個排程中斷的問題也已完成修復。

問題修復

OpenTelemetry 補齊方案屬性，修正代理傳輸卡死與重試

企業在集中監控終端機呼叫紀錄時，遙測資料的完整度與傳輸穩定性直接影響維運品質。OpenTelemetry 的指標、事件與追蹤跨度（span）中，現在補上了 anthropic.plan、anthropic.seat_type、anthropic.provider 與 anthropic.custom_base_url 四項屬性。透過代理伺服器匯出遙測資料到 HTTPS 端點時，先前若有另一筆匯出還在進行，新啟動的匯出從未送出，這個問題已修好，這類匯出現在會正常送出。如果代理伺服器阻擋了 HTTP 端點並回傳 403，也不會再對該代理狂發大量連線嘗試。遇到完全無回應的代理伺服器，請求會在 10 秒後超時，或依照 OTEL_EXPORTER_OTLP_TIMEOUT 的設定最多等待 30 秒，不再無止境掛起。

新功能

應用程式閘道新增費用報表，釐清配額顯示與長提示詞錯誤

團隊管理者在後台盤點成員的使用開銷時，需要精確掌握不同部門與日期的花費明細。Claude 應用程式閘道新增管理 API GET /v1/organizations/analytics/cost，支援查詢指定日期區間的總支出，並可按開發者、每日或身分識別群組分類。設定了 admin: 的閘道會將開發者群組資料保留 admin.identity_retention_days 天供報表統計。當群組共享預算用完時，statusLine（顯示在終端機最底下的狀態列）與 /usage 過去會誤將個人額度標示為 100% 耗盡，目前已改正。閘道也不再隱藏 Amazon Bedrock 的輸入過長錯誤，使對話能順利觸發自動壓縮；遇上必要閘道連線失敗時，啟動提示會指明網路或 TLS 憑證問題，不再誤導為登入異常。

新功能

隔離巢狀管線識別碼，自架環境支援舊版對話紀錄共用

在自動化測試機或雲端環境中以管線呼叫 Claude 時，巢狀執行的子程序容易干擾外層對話。過去在雲端或自架執行器的工作階段中執行 claude -p，程式會共用外層的識別碼，導致子指令直接寫入父層對話紀錄，重啟時甚至接錯歷史對話，子程序還會產生自己的標題送給父層。現在這些識別碼干擾已經各自獨立隔開。如果你在自架環境仍需要舊版行為，可以在執行器將環境變數 CLAUDE_CODE_DISABLE_NESTED_SESSION_ID 設為 1，讓內層的 claude -p 繼續沿用當前工作階段的識別碼與對話逐字紀錄。

問題修復

自架執行器連線重建機制，修復狀態遺失與轉移異常

將任務派發到自建伺服器執行時，伺服器波動或網路斷線容易讓長時間運作的任務功虧一簣。自架執行器遇到 501 或 529 以外的 5xx 伺服器錯誤時，輪詢與工作階段會立即建立全新連線，不再重複沿用失效舊連線；心跳檢測若無回應，也會直接重開連線，不再徒勞輪詢閒置通道。在計畫等待批准時重啟，過去容易遺失對話紀錄，目前該問題已獲修復。當工作階段遷移到新執行器時，即使中斷輪次超過 CLAUDE_CODE_RESUME_INTERRUPTED_TURN_MAX_AGE_MS，Claude 依然能看見中斷的工具呼叫；先前已關閉的外部工具伺服器，也不會在轉移機器後莫名被重啟。

問題修復

Claude 桌面版 Code 分頁強化，修復外部工具斷線與思考深度

在電腦桌面版切換到 Code 分頁工作時，專案設定與延伸工具的載入順序經常影響產出效果。桌面應用程式的 Code 分頁現在會在工作階段尚未載入機構遠端託管設定時跳出提示，並在載入完成後再次通知。專案若預先設定了 effortLevel（思考深度等級），過去由應用程式預先啟動再帶入專案的工作階段會忽略該設定，現在已能正確套用。在部分桌面工作階段中，專案與本機端的 MCP（讓 AI 連接外部工具的協定）伺服器在對話第一輪結束後就自動斷線的問題，也已經順利修復。

問題修復

釐清身分驗證與憑證錯誤，修復令牌儲存與網路阻擋提示

在公司內網或嚴格控管的網域登入工具時，模糊的連線報錯常讓人分不清是帳號還是網路出問題。現在遇到區域或網路被阻擋的 HTTP 403 錯誤時，錯誤訊息會清楚說明遭到封鎖，不再誤報為登入失敗。在 TLS 流量審查代理伺服器更新憑證存放區的根憑證後，API 請求不會再因為找不到本機簽發憑證而中斷。微軟 Foundry 載入 Azure 憑證失敗時，也會明確標記為 cloud_credential_error 並提醒檢查或重新整理。執行 claude auth status 時，程式先前會在慢速 token（授權令牌）寫入前過早結束而導致下次被登出，這項儲存時機問題也已經修正。

問題修復

補正雙重授權提示路徑，修復權限模式升級與免問選項

當 Claude 同步執行多項操作請求授權時，清楚的提示資訊是保護檔案安全的第一道防線。在 claude.ai 與行動裝置應用程式上，如果同時跳出兩個授權提示，第二個提示過去會遺失檔案路徑與指令內容，現在已能完整顯示。在 Remote Control 與 SDK 主機環境下，擴充模組（mod）觸發的工具呼叫先前會錯誤提供「不再詢問」選項，目前已移除此非預期選項以確保審核嚴謹。背景工作階段在進行規格升級或除役時，剛變更的權限模式有時會意外丟失，這項同步問題也已修復完畢。

問題修復

恢復對話自動帶回啟動參數，修復檔案重複通知與標題遺失

結束終端機並重新回到先前的工作進度時，對話狀態的延續能省下重複說明的時間。退出程式時顯示的恢復對話提示，現在會主動把最初啟動時帶上的旗標（例如 --chrome --debug）排在 --resume 前方，方便直接複製。恢復工作階段後，Claude 不會再收到它早已知曉的重複檔案變更通知。如果先前對話曾因工具被關閉而呼叫失敗，恢復後也不會再持續停用該內建工具。雲端與 SDK 工作階段在產生對話標題期間若收到新訊息或中斷指令，標題也不再無故丟失。

問題修復

改善外掛同步與無頭模式記憶體，擴充開發完成主動提議分享

在專案中安裝多個自訂技能與外掛程式時，背景同步與載入效率直接影響啟動體驗。在 headless（沒有終端機視覺介面的執行模式）中掛載大量註冊指令的外掛時，先前會佔用過高記憶體並拖慢啟動速度，現在載入流程已獲得改善。從 claude.ai 同步技能若遇上磁碟無法寫入，程式不會再每 10 分鐘重複下載或遺失技能。雲端工作階段中若同步的外掛包含相同伺服器，運作中的連接器也不會再被誤報為失敗或需要驗證。內建的 plugin-authoring 技能在確認你編寫的擴充模組運作正常後，會主動詢問一次是否需要協助分享。

問題修復

管線寫入失敗改回傳代碼 1，修復啟動設定監聽與訊號重複

自動化腳本在後台長時間運作時，任何靜默失敗或未釋放的程序都會累積成維運隱患。執行 claude -p 時若因硬碟空間或配額額度耗盡，導致對話紀錄或 ~/.claude.json 寫入失敗，程式現在會印出錯誤訊息並以結束代碼 1 退出，不再誤報為成功代碼 0。在包含 --setting-sources 等跳過清理機制的環境上，過期的歷史紀錄檔現在會確實執行清理。程式剛啟動首秒內對設定檔所做的修改，現在會即時生效，不必等待下一次檔案異動。中止 Shell 指令時，子行程過去有時會收到兩次 SIGTERM 終止訊號而跳過自身的清理流程，該問題目前也已獲得解決。

問題修復

團隊協作通訊與模式同步，修復終端清除輸入誤殺背景代理

讓多位 AI 代理在後台分頭協作專案時，訊息投遞與執行模式的同步十分關鍵。透過 SendMessage 發送訊息給執行中的背景代理時，代理正在跑的指令會移入背景且不中斷，讓新訊息能更早送達。在命令列按下 Ctrl+C 清除輸入框文字時，先前會誤將所有背景代理一併中止，現在不再影響背景任務。在 tmux 或 iTerm2 分割視窗中啟動的團隊成員，會正確跟隨主控工作階段採用手動模式，不再擅自進入自動模式。隊友延遲送達的訊息不會再重建已刪除的收件匣，重啟的隊友也不會因先前的關閉審核被剔除，退出時對外掛監聽程序更會略過多餘的背景執行確認。

問題修復

團隊新手導引刪除防呆，杜絕誤刪近期檔案與虛假成功提示

當你整理專案文件並要求 Claude 刪除團隊指引時，模糊指令可能導致意外刪除重要檔案。過去如果在輸入指令時要求刪除 /team-onboarding 導引卻沒有指明具體名稱，Claude 會擅自刪除最新更新過的那份檔案，現在已修正此危險行為。如果伺服器拒絕了刪除請求，Claude 也不會再假稱該檔案已被刪除，而是會誠實回報刪除失敗。

宛如交代助理銷毀公文卻沒說清檔號，以前對方會擅自挑最新那份拿去碎紙，機器拒絕還謊稱已辦妥；現在不再亂挑，而且失敗會誠實回報。
問題修復

對話壓縮保留歷史摘要，修正快取環境變數與子代理思考深度

當對話長度接近上限觸發自動壓縮時，內容精簡的完整度直接關係到後續回答的精確度。在超長對話中，即使自動壓縮機制需要縮減自身的請求長度，也不會再遺失前段對話的摘要紀錄。若專案的 CLAUDE.md 內容龐大且在發送後發生異動，壓縮後也不會再跳出提示過長的錯誤。停用 prompt cache（把算過或查過的結果暫存起來直接用）的環境變數 DISABLE_PROMPT_CACHING_OPUS 與 DISABLE_PROMPT_CACHING_SONNET，現在對帶有 [1m]、跨區域或無日期後綴的模型名稱都能確實生效。採用與主對話不同模型的子代理或隊友，則會改用該模型專屬的思考深度等級或預設值，不再盲目繼承主工作階段設定。

問題修復

讀取未變更檔案恢復回傳內文，修復搜尋超時與文件頁數計算

請 Claude 閱讀專案程式碼或翻閱本機文件時，工具回傳的資料完整度決定了判斷的準確性。讀取工具（Read tool）先前在重複查看未變更檔案時僅回傳簡短存根，現在已移除該機制，重新讀取皆會傳回完整內容。搜尋工具在達到時間上限時，先前會把 Grep 和 Glob 的部分結果誤當成全部結果，現已修正為正確標記。在 PDF 自身後設資料異常時，Read 工具與 @ 標記過去會少算頁數，該問題也已排除。當個人成品累積超過 200 個時，/artifacts 與工具共享清單先前會顯示為空，現在皆能正常列出。設定為空的 AWS_BEARER_TOKEN_BEDROCK 會在 stdio MCP 伺服器中直接取消設定，使伺服器能順利取用主機既有的 AWS 憑證。

問題修復

遠端控制新增分支自動編號，修復重啟無回應與停用提示

透過遠端連線管理多個對話分支時，清晰的狀態回饋能讓切換操作井然有序。當全域設定 disableRemoteControl 停用遠端控制時，輸入 /remote-control 不再顯示未知的指令錯誤，而是明確告知該功能已被設定關閉。重啟 claude remote-control 後，若你在上一則訊息送出後一分鐘內又傳了下一則給閒置的工作階段，那則訊息過去有時沒人回應，現在已修好。而在建立對話分支且應用程式未自訂名稱時，長標題會保留結尾的 (fork) 標記。若對話是由 claude remote-control 啟動，原名稱的分支在再次複製時會自動命名為第二分支，方便快速辨識演變歷程。

新功能

PR 對話支援跨頁搜尋，改善螢幕報讀與 Slack 卡片呈現

在日常團隊協作中調用輔助工具時，介面反饋的流暢度會直接影響操作專注度。在累積大量工作階段的專案中執行 claude --from-pr 時，若關聯的對話落在第一頁之後，過去會誤報找不到對話，現在已支援跨頁檢索。螢幕閱讀器模式在子代理執行時，先前每次數值變動都會反覆朗讀耗時與 token（AI 處理與計費的文字單位），現在已消除這類多餘報讀。在 Slack 貼上成品連結時，卡片改以簡潔按鈕呈現並直接在 Claude 中開啟，不再擠入側邊欄。送出 /feedback 報告期間不會再多餘顯示按 Enter 確認的提示，/design-sync 遇到設計系統遷移時也會在建置前提前停止並說明。

問題修復

Windows 磁碟工作目錄辨識改進，修復 260 字元路徑限制

在 Windows 系統上處理深層資料夾或特殊磁區時，路徑長度與格式常常是工具呼叫出錯的元兇。在部分原生路徑查詢失敗的 Windows 磁碟區上，過去所有的工具呼叫都會被拒絕執行，現在工作目錄檢查已改為比對資料夾本體識別碼，不再卡死。針對非透過桌面版啟動的工作階段，暫存草稿區與其他暫存路徑過去會隨著專案路徑累加變長，導致複製進來的儲存庫輕易撞上 260 個字元的路徑長度上限，目前路徑結構已調整縮短，避免了複製與寫入時的路徑長度報錯。

跟快遞核對送件地址一樣，以前地圖查不到路名就整批拒送，轉運標籤還越貼越長以致寫不下；現在改認建築代號放行，並精簡中繼標籤避免退件。
問題修復

FEATURE

Confirmation Added Before Sending Account Email, Preventing Terminal Tools from Leaking Personal Information

When you ask Claude to execute commands or fetch web pages through the terminal, tool calls might carry sensitive personal information. Now, whether using web browsing or command-line tools, whenever an action is about to send your account email address to an external network, the terminal will first pop up a prompt asking whether to allow it.

Picture a counter clerk flipping through attachments before dispatching important mail: previously, as soon as you pressed the send button, the letter was sent straight out; now, if the recipient list is found to contain your private address, the counter pauses first to ask for your confirmation.

This prevents scripts or third-party packages from quietly sending your contact email back to external servers without authorization.

FEATURE

Agent SDK Hooks Add Block Option to Halt Actions Immediately on Callback Failure

When developers write automated workflows for agents, they often need to set checkpoints to intercept dangerous actions. Agent SDK hook (small programs triggered when specific events occur) callbacks now support the onFailure: "block" setting. When a callback fails to execute or throws an error, it proactively blocks subsequent operations instead of letting the action keep running.

Think of a smart access control system that locks down automatically when its sensor malfunctions: previously, if the alarm line lost signal, the gate would let people straight through because the process was not interrupted; now, as long as the safety inspection does not complete smoothly, the entire barrier jams immediately.

This ensures that when issues arise during pre-execution security checks, unverified changes are not applied recklessly.

BUGFIX

Auto Mode Health Check Mechanism Fixes Subagent Blank Views and Cloud Stalls

When you switch to auto mode to let Claude handle tasks independently, frozen screens or unexpected interruptions often cause confusion. Now, when a safety check has no answer for a subagent's tool call, the main view actively displays a notice instead of leaving a blank screen. If a custom model gateway returns a 403 or 422 error code to a server-side safety check, auto mode no longer fails with errors every turn; 403 handling with an apiKeyHelper remains unchanged. In cloud sessions, when the Artifact tool uploads data, writes to a database, or saves files through the outputs folder, auto mode runs smoothly without suddenly pausing to wait for manual approval.

BUGFIX

Scheduled Tasks Add Connector Warnings, Fixing Next Run Times and Loop Wakeups

When relying on scheduled runs or background loops for automation, task status displays and link settings are essential. When using /schedule to create a cloud scheduled task, if the task is attached to connectors you did not request, the terminal proactively displays a warning along with instructions on how to remove them. The results list after creating or updating a schedule now properly displays the next run time and corresponding link, no longer leaving them missing. Previously, if scheduled tasks were disabled globally, stored tasks could not be listed or deleted, but they can now be cleaned up normally at any time. In addition, when Claude omits certain fields from a request, self-paced /loop wakeup schedules were sometimes lost; this scheduling interruption issue has also been resolved.

BUGFIX

OpenTelemetry Adds Plan Attributes, Fixing Proxy Export Hangs and Retries

When enterprises centrally monitor terminal call records, the completeness of telemetry data and transmission stability directly affect operational quality. Four attributes—anthropic.plan, anthropic.seat_type, anthropic.provider, and anthropic.custom_base_url—have now been added to OpenTelemetry metrics, events, and spans. When exporting telemetry data to an HTTPS endpoint through a proxy, a newly initiated export that started while another export was still in progress was previously never sent; this issue is fixed, and such exports are now sent normally. If a proxy server blocks an HTTP endpoint and returns a 403 error, a flood of connection attempts will no longer be fired at that proxy. When encountering a proxy server that never answers, requests time out after 10 seconds, or wait up to 30 seconds according to OTEL_EXPORTER_OTLP_TIMEOUT, no longer hanging indefinitely.

FEATURE

Apps Gateway Adds Cost Reports, Clarifying Quota Displays and Long Prompt Errors

When team managers review member spending in the admin console, they need precise visibility into expense breakdowns across departments and dates. The Claude apps gateway has added an admin API, GET /v1/organizations/analytics/cost, which supports querying past spend over a date range in total, per developer, per day, or by identity provider group. Gateways with admin: configured will retain developer group data for admin.identity_retention_days days for report aggregation. When a group's pooled budget runs out, the status line (the bar shown at the bottom of the terminal) and /usage previously mistakenly marked a developer's personal quota as 100% exhausted, which has now been fixed. The gateway also no longer hides Amazon Bedrock's "Input is too long." error, allowing conversations to trigger automatic compaction smoothly; when a required gateway connection fails, the startup prompt points to network or TLS certificate issues instead of misleadingly indicating a sign-in failure.

FEATURE

Isolating Nested Pipeline Identifiers While Supporting Legacy Session Sharing on Self-Hosted Runners

When invoking Claude via pipelines on automated test runners or in cloud environments, nested subprocesses can easily interfere with the outer conversation. Previously, running claude -p inside a cloud or self-hosted runner session shared the outer session's ID, causing child commands to write directly into the parent transcript, resume the wrong conversation upon restart, and generate their own titles to send to the parent. These identifier conflicts are now isolated independently. If you still need the legacy behavior in a self-hosted environment, you can set the environment variable CLAUDE_CODE_DISABLE_NESTED_SESSION_ID to 1 on the runner, allowing inner claude -p runs to continue using the current session's ID and transcript.

Self-Hosted Runner Connection Rebuilding Mechanism Fixes Lost State and Migration Anomalies

When dispatching tasks to run on self-hosted servers, server fluctuations or network drops can easily ruin long-running jobs. When self-hosted runners encounter a 5xx server error other than 501 or 529, polling and sessions immediately open a brand-new connection instead of repeatedly reusing the failed one; if a heartbeat receives no answer, connections are reopened directly rather than fruitlessly polling idle channels. Restarting while a plan waited for approval previously led to lost conversation history, which has now been fixed. When a session migrates to a new runner, Claude can still see the interrupted tool call even if the interrupted turn is older than CLAUDE_CODE_RESUME_INTERRUPTED_TURN_MAX_AGE_MS; previously disabled external tool servers will also no longer unexpectedly turn back on after moving between machines.
