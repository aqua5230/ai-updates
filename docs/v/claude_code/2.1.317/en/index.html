Claude Code 2.1.317

Released: 2026-11-03

Release notes

FEATURE

Confirmation Added Before Sending Account Email, Preventing Terminal Tools from Leaking Personal Information

When you ask Claude to execute commands or fetch web pages through the terminal, tool calls might carry sensitive personal information. Now, whether using web browsing or command-line tools, whenever an action is about to send your account email address to an external network, the terminal will first pop up a prompt asking whether to allow it.

Picture a counter clerk flipping through attachments before dispatching important mail: previously, as soon as you pressed the send button, the letter was sent straight out; now, if the recipient list is found to contain your private address, the counter pauses first to ask for your confirmation.

This prevents scripts or third-party packages from quietly sending your contact email back to external servers without authorization.

FEATURE

Agent SDK Hooks Add Block Option to Halt Actions Immediately on Callback Failure

When developers write automated workflows for agents, they often need to set checkpoints to intercept dangerous actions. Agent SDK hook (small programs triggered when specific events occur) callbacks now support the onFailure: "block" setting. When a callback fails to execute or throws an error, it proactively blocks subsequent operations instead of letting the action keep running.

Think of a smart access control system that locks down automatically when its sensor malfunctions: previously, if the alarm line lost signal, the gate would let people straight through because the process was not interrupted; now, as long as the safety inspection does not complete smoothly, the entire barrier jams immediately.

This ensures that when issues arise during pre-execution security checks, unverified changes are not applied recklessly.

BUGFIX

Auto Mode Health Check Mechanism Fixes Subagent Blank Views and Cloud Stalls

When you switch to auto mode to let Claude handle tasks independently, frozen screens or unexpected interruptions often cause confusion. Now, when a safety check has no answer for a subagent's tool call, the main view actively displays a notice instead of leaving a blank screen. If a custom model gateway returns a 403 or 422 error code to a server-side safety check, auto mode no longer fails with errors every turn; 403 handling with an apiKeyHelper remains unchanged. In cloud sessions, when the Artifact tool uploads data, writes to a database, or saves files through the outputs folder, auto mode runs smoothly without suddenly pausing to wait for manual approval.

BUGFIX

Scheduled Tasks Add Connector Warnings, Fixing Next Run Times and Loop Wakeups

When relying on scheduled runs or background loops for automation, task status displays and link settings are essential. When using /schedule to create a cloud scheduled task, if the task is attached to connectors you did not request, the terminal proactively displays a warning along with instructions on how to remove them. The results list after creating or updating a schedule now properly displays the next run time and corresponding link, no longer leaving them missing. Previously, if scheduled tasks were disabled globally, stored tasks could not be listed or deleted, but they can now be cleaned up normally at any time. In addition, when Claude omits certain fields from a request, self-paced /loop wakeup schedules were sometimes lost; this scheduling interruption issue has also been resolved.

BUGFIX

OpenTelemetry Adds Plan Attributes, Fixing Proxy Export Hangs and Retries

When enterprises centrally monitor terminal call records, the completeness of telemetry data and transmission stability directly affect operational quality. Four attributes—anthropic.plan, anthropic.seat_type, anthropic.provider, and anthropic.custom_base_url—have now been added to OpenTelemetry metrics, events, and spans. When exporting telemetry data to an HTTPS endpoint through a proxy, a newly initiated export that started while another export was still in progress was previously never sent; this issue is fixed, and such exports are now sent normally. If a proxy server blocks an HTTP endpoint and returns a 403 error, a flood of connection attempts will no longer be fired at that proxy. When encountering a proxy server that never answers, requests time out after 10 seconds, or wait up to 30 seconds according to OTEL_EXPORTER_OTLP_TIMEOUT, no longer hanging indefinitely.

FEATURE

Apps Gateway Adds Cost Reports, Clarifying Quota Displays and Long Prompt Errors

When team managers review member spending in the admin console, they need precise visibility into expense breakdowns across departments and dates. The Claude apps gateway has added an admin API, GET /v1/organizations/analytics/cost, which supports querying past spend over a date range in total, per developer, per day, or by identity provider group. Gateways with admin: configured will retain developer group data for admin.identity_retention_days days for report aggregation. When a group's pooled budget runs out, the status line (the bar shown at the bottom of the terminal) and /usage previously mistakenly marked a developer's personal quota as 100% exhausted, which has now been fixed. The gateway also no longer hides Amazon Bedrock's "Input is too long." error, allowing conversations to trigger automatic compaction smoothly; when a required gateway connection fails, the startup prompt points to network or TLS certificate issues instead of misleadingly indicating a sign-in failure.

FEATURE

Isolating Nested Pipeline Identifiers While Supporting Legacy Session Sharing on Self-Hosted Runners

When invoking Claude via pipelines on automated test runners or in cloud environments, nested subprocesses can easily interfere with the outer conversation. Previously, running claude -p inside a cloud or self-hosted runner session shared the outer session's ID, causing child commands to write directly into the parent transcript, resume the wrong conversation upon restart, and generate their own titles to send to the parent. These identifier conflicts are now isolated independently. If you still need the legacy behavior in a self-hosted environment, you can set the environment variable CLAUDE_CODE_DISABLE_NESTED_SESSION_ID to 1 on the runner, allowing inner claude -p runs to continue using the current session's ID and transcript.

BUGFIX

Self-Hosted Runner Connection Rebuilding Mechanism Fixes Lost State and Migration Anomalies

When dispatching tasks to run on self-hosted servers, server fluctuations or network drops can easily ruin long-running jobs. When self-hosted runners encounter a 5xx server error other than 501 or 529, polling and sessions immediately open a brand-new connection instead of repeatedly reusing the failed one; if a heartbeat receives no answer, connections are reopened directly rather than fruitlessly polling idle channels. Restarting while a plan waited for approval previously led to lost conversation history, which has now been fixed. When a session migrates to a new runner, Claude can still see the interrupted tool call even if the interrupted turn is older than CLAUDE_CODE_RESUME_INTERRUPTED_TURN_MAX_AGE_MS; previously disabled external tool servers will also no longer unexpectedly turn back on after moving between machines.

BUGFIX

Claude Desktop Code Tab Enhancements Fix External Tool Disconnections and Thinking Depth

When switching to the Code tab in the desktop app, the loading order of project settings and extension tools often affects results. The desktop app's Code tab now displays a notice when an organization's remote managed settings have not loaded for a session, and notifies again once they finish loading. If a project pre-configures effortLevel (thinking depth level), sessions started ahead of time by an app and then opened in the project previously ignored the setting, but it is now correctly applied. In some desktop sessions, an issue where project and local MCP (a protocol allowing AI to connect to external tools) servers disconnected automatically after the first turn has also been successfully fixed.

BUGFIX

Clarifying Authentication and Credential Errors, Fixing Token Storage and Network Block Notices

When logging into tools on a corporate intranet or strictly managed domain, vague connection errors often make it hard to tell whether an account or network issue is at fault. Now, when encountering an HTTP 403 error caused by a regional or network block, the error message clearly explains the block instead of incorrectly reporting a sign-in failure. After a TLS-inspecting proxy updates root certificates in the certificate store, API requests will no longer fail with "unable to get local issuer certificate". When Microsoft Foundry fails to load Azure credentials, it now explicitly flags the issue as cloud_credential_error and prompts you to check or refresh them. When running claude auth status, the program previously exited prematurely before a slow token (an authorization credential) refresh was saved, which could sign you out on the next run; this storage timing issue has also been corrected.

BUGFIX

Restoring Paths in Simultaneous Permission Prompts and Fixing Permission Mode Upgrades

When Claude runs multiple operations simultaneously and requests authorization, clear prompt details serve as the first line of defense for protecting file safety. On claude.ai and mobile apps, if two permission prompts pop up at the same time, the second prompt previously lost its file path and command content, but it now displays them completely. In Remote Control and SDK host environments, tool calls triggered by mods (extension modules) previously offered a "don't ask again" option by mistake. This unexpected option has now been removed to ensure rigorous review. When background sessions undergo specification upgrades or retirement, freshly changed permission modes sometimes went missing unexpectedly, and this synchronization problem has also been resolved.

BUGFIX

Preserving Launch Flags on Session Resumption and Fixing Duplicate File Notifications

When exiting the terminal and returning to prior work progress, continuing session state saves time spent repeating explanations. The "Resume this session with" hint shown upon exiting now proactively places the flags you launched with (for example --chrome --debug) ahead of --resume for easy copying. After resuming a session, Claude will no longer receive duplicate notifications about file changes it already knew about. If an earlier conversation had a tool call fail because the tool was turned off, that built-in tool will no longer remain disabled after resuming. If cloud and SDK sessions receive a new message or Stop command while generating a conversation title, titles will no longer be lost for no reason.

BUGFIX

Optimizing Plugin Sync and Headless Memory While Offering Mod Sharing Upon Completion

When installing multiple custom skills and plugins in a project, background sync and loading efficiency directly impact the startup experience. In headless mode (an execution mode without a terminal visual interface), loading many plugins that register commands previously consumed excessive memory and slowed down startup, but the loading process has now been improved. If syncing skills from claude.ai encounters a disk that cannot be written to, the program will no longer repeatedly download them every 10 minutes or lose skills. If a synced plugin contains the same server during cloud sessions, working connectors will no longer be mistakenly reported as failed or needing authorization. After confirming that a mod you built works properly, the built-in plugin-authoring skill will proactively offer once to help share the mod.

BUGFIX

Returning Exit Code 1 on Pipeline Write Failures and Fixing Duplicate Signals

When automated scripts run in the background for extended periods, any silent failure or unreleased process builds up operational risks. When running claude -p, if exhausted disk space or quota causes writes to transcripts or ~/.claude.json to fail, the program now prints an error message and exits with code 1 rather than mistakenly reporting success with exit code 0. On environments where some runs skip cleanup mechanisms, such as those using --setting-sources, expired transcript files are now reliably cleaned up. Modifications made to settings files within the first second or so after startup now take effect immediately without waiting for another file change. When stopping a shell command, child processes previously sometimes received the SIGTERM signal twice and skipped their own cleanup routines, an issue that has now been resolved.

BUGFIX

Synchronizing Team Agent Communication and Modes While Preventing Input Clears from Halting Agents

When having multiple AI agents collaborate on projects in the background, message delivery and execution mode synchronization are critical. When sending a message to a running background agent via SendMessage, the command currently running moves to the background without being stopped, allowing new messages to arrive earlier. When pressing Ctrl+C at the command line to clear typed text, it previously stopped all background agents by mistake, but it now no longer affects background tasks. Teammates started in tmux or iTerm2 panes will correctly follow the lead session in using manual mode rather than entering auto mode on their own. Delayed messages from teammates will no longer recreate deleted inboxes, restarted teammates will not be removed due to earlier shutdown approvals, and exit will skip the redundant "Background work is running" prompt for plugin monitors.

BUGFIX

Guarding Team Onboarding Guide Deletion Against Accidental Removal and False Success Prompts

When organizing project documents and asking Claude to delete team guides, ambiguous instructions could lead to accidental deletion of important files. Previously, when asked to delete a /team-onboarding guide without specifying a concrete name, Claude took the liberty of deleting the most recently updated file, a dangerous behavior that has now been corrected. If the server refuses a deletion request, Claude will no longer falsely claim that the file was deleted, but will instead honestly report that the deletion failed.

Imagine instructing an assistant to destroy an official document without specifying the file number: previously, they would take the liberty of picking the most recently updated copy for the shredder and falsely claim it was done when the machine refused; now they no longer pick arbitrarily, and failures are reported honestly.
BUGFIX

Retaining Conversation Compaction Summaries While Correcting Cache Variables and Subagent Effort

When conversation length nears the limit and triggers automatic compaction, the thoroughness of content streamlining directly affects the accuracy of subsequent answers. In very long conversations, even when the automatic compaction mechanism must shorten its own request length, it will no longer lose summaries of earlier conversation history. If a project has a massive CLAUDE.md that changed after being sent, a "Prompt is too long" error will no longer appear after compaction. The environment variables DISABLE_PROMPT_CACHING_OPUS and DISABLE_PROMPT_CACHING_SONNET that disable prompt caching now reliably take effect on model names with [1m], cross-region variants, or undated suffixes. Subagents or teammates using a different model from the main conversation will switch to that model's dedicated effort level or default value instead of blindly inheriting the main session's setting.

BUGFIX

Restoring Full Content for Unchanged File Reads and Fixing Search Timeout Marking

When asking Claude to read project code or browse local documents, the completeness of data returned by tools determines the accuracy of its judgments. The Read tool previously returned only a short stub when re-reading unchanged files, but this mechanism has been removed and reading an unchanged file now returns full content. When a search hits its time limit, search tools previously mistook partial Grep and Glob results for complete results, which has now been fixed with proper markings. When a PDF's own metadata was abnormal, the Read tool and @-mentions previously undercounted its pages, an issue that has now been eliminated. When you accumulate 200 or more of your own artifacts, /artifacts and the tool's shared list previously showed up empty, but they now display normally. An AWS_BEARER_TOKEN_BEDROCK configured as empty will now be directly unset in stdio MCP servers, enabling the server to smoothly access the machine's existing AWS credentials.

BUGFIX

Adding Automatic Fork Numbering in Remote Control and Fixing Restart Unresponsiveness

When managing multiple conversation forks over remote connections, clear status feedback keeps switching operations orderly. When the global setting disableRemoteControl disables Remote Control, entering /remote-control no longer returns an "Unknown command" error, but clearly indicates that the feature has been turned off by configuration. After restarting claude remote-control, if you send another message to an idle session within one minute of your previous message, that message previously sometimes went unanswered, which has now been fixed. When creating conversation forks and the application does not set a custom name, long titles will retain their trailing (fork) tag. For sessions started with claude remote-control, forking a branch already named with a fork suffix automatically names it with (fork 2) to easily track evolutionary history.

FEATURE

Supporting Multi-Page PR Session Searches and Improving Screen Reader Announcements

When invoking auxiliary tools in daily team collaboration, smooth interface feedback directly affects operational focus. When running claude --from-pr in projects with many sessions, if the linked conversation fell beyond the first page, it previously mistakenly reported "No conversations found", but multi-page retrieval is now supported. In screen reader mode while a subagent runs, the system previously repeatedly read out elapsed time and tokens (units of text AI processes and bills for) on every update, but these redundant announcements have now been eliminated. When pasting artifact links in Slack, cards now present a simpler button to open directly in Claude rather than squeezing into the side panel. While sending a /feedback report, the prompt showing "Enter to confirm" is no longer shown unnecessarily. When encountering a design system migration, /design-sync will also stop early before building and explain the situation.

BUGFIX

Windows Working Directory Detection Improved and 260-Character Path Limit Fixed

When handling deep folders or special volumes on Windows systems, path length and formatting often cause tool calls to fail. On some Windows volumes where native path lookup fails, every tool call was previously refused, but the working-directory check now compares the folder's identity instead of stalling. For sessions not started by Claude Desktop, the session scratchpad and other temporary paths previously grew with the project path length, causing cloned repositories to hit the 260-character path limit; the path structure has now been shortened to prevent path length errors during cloning and writing.

Just as a courier checking delivery addresses once refused an entire shipment when a map lookup failed and stacked transfer labels until they ran out of room, the service now identifies the building code instead and trims intermediate tags to prevent returns.
BUGFIX

VS Code Extension Fixes Dropped Messages in Forked Chats, Timeout Restarts, and Deep Thinking

When discussing code directly with Claude in VS Code, message completeness is essential for contextual reasoning. When forking conversations in the extension, only one of the tool calls run in parallel was previously kept, and trailing messages kept by automatic compaction were often lost, leaving responses without context; message loss has now been eliminated. When Claude does not finish starting in time, the extension now automatically attempts to start Claude once more before showing an error, preventing lost messages. The interface no longer mistakenly opens the sign-in screen when a request is blocked for its region or network. Even when telemetry collection is turned off, the ultrathink command now reliably raises effort for its turn and displays its rainbow animation.

FEATURE

VS Code Panel Fonts Scale with Settings and File Links Open in a Separate Editor Group

When fine-tuning the reading view and font size in the editor sidebar, overall visual layout determines the comfort of reviewing code. When chat.fontSize is raised in settings, attachment chips, menus, banners, and dialogs in the Claude panel now scale up simultaneously instead of staying small in the corner. When clicking a file link in a chat tab, the file now opens in another separate editor group instead of abruptly replacing the current chat screen. In the Account panel, the typographical issue where the second word of a plan name was mistakenly displayed in lowercase has also been corrected to the proper casing.

BUGFIX

Cloud Sessions Add Link Cards, Improve Admin Interface and Secret Overwrite Protection

When interacting with remote servers in cloud environments, popup external links and organizational settings require rigorous protection and clear presentation. When an MCP (a protocol connecting AI to external tools) server asks to open a webpage, cloud sessions now proactively display a link card so you can freely open or decline the link instead of letting the request go unseen in the background. The organization environment dialog in admin settings now uses a compact layout where each section opens from a row, and unsaved input prompts for confirmation before closing. If you add a network secret for a host that already has one, the form directly refuses and points to the existing secret to prevent accidental overwrites. Newly scheduled tasks also automatically populate with the default environment selected by the organization administrator instead of enforcing the official hosted default.
