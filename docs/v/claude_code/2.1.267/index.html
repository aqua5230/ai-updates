思考深度設定全面設限，自訂技能前言設定正式生效

想讓 Claude 深入推理又擔心 token（AI 處理與計費的文字單位）消耗過量，現在能透過 maxEffortLevel 設定為思考深度加上緊箍咒。

這宛如在跑車油門踏板下方加裝限速卡榫，無論開在哪條公路上都能限制最高轉速，駕駛依舊能輕踩慢行，自訂路線的定速指示也不會被車廠出廠預設忽略。

以前在 Bedrock、Vertex 與 Foundry 等不同雲端平台上，很難全面鎖定努力程度上限。現在無論在最外層或 modelSettings 針對個別模型指定，都能統一設限，且日常仍可自由選擇更低的努力等級：

{
  "maxEffortLevel": "medium",
  "modelSettings": {
    "claude-opus-4-7": {
      "maxEffortLevel": "low"
    }
  }
}

此外，自訂指令、技能或子代理在 YAML 前言中指定的 effort: 數值，先前在 Opus 4.7、Opus 4.8 與 Fable 5 等固定預設等級的模型上會失效，如今已修復並能正確生效。

系統提示詞支援即時重算，調校文案免重啟對話

正在反覆微調提示詞（prompt）卻苦於每次改動都得開新對話，新的 --system-prompt-snapshot off 旗標正是為此而生。當你在打磨自訂提示詞內容時，系統預設會沿用工作階段初次錄製的提示詞快照，導致你在外側修改了檔案文字，當前的對話依然讀取舊版內容。現在只要在啟動 Claude 時帶上這個選項，每一次發出提問都會重新讀取並渲染最新的系統提示詞，讓文案調校的測試過程變得更加靈活迅速。

整套流程好似在排練室試穿戲服，每次出場都當場換上最新修改的布料剪裁，不必每修一針就得解散劇組重新開演。

外部工具異動保全推論思考，切換模型快取不漏接

當你請 Claude 呼叫外部工具或中途切換模型時，先前辛苦推導的思考脈絡不再無端消失。

這好比多位專家在會議室白板上記錄解題推導，中途就算外聘顧問進出或更換麥克風，也不會突然把整面黑板的心算擦掉重抄。

以往 MCP（讓 AI 連接外部工具的協定）伺服器重送模型已載入的工具、內建工具重繪，或工具因斷線升級而消失時，清單重寫往往會丟失先前的思考內容；如今推論皆能妥善保留。在未開啟工具搜尋的工作階段中，外掛動態加入也會改以延遲定義傳遞，避免破壞快取（把算過結果暫存起來直接用）複用。透過 /model 切換模型時不再重發全部工具定義；commit 與 PR 的歸屬文字改以對話附註送達，並會在切換模型時更新，且 claude.ai 連接器工具在工作階段更動時也能保住推論記憶。

恢復工作階段沿用工具描述，背景任務不破壞提示快取

重新打開先前未完成的工作階段時，最怕背景暫存全部失效導致推論延遲。以前從對話分岔出的背景工作單元若把 EnterWorktree 這個工作樹（Git 讓同一專案平行開多份副本的功能）工具加進對話的工具清單，便會破壞快取重用機制。現在恢復工作階段時，不會再因 MCP（讓 AI 連接外部工具的協定）重連時間差而改寫工具清單或丟失思考，首回合執行工具時也能直接重播既有描述而非重新渲染。此外，從 -p 印出模式切換至互動模式時系統提示詞前綴保持一致。透過 --system-prompt 或 --append-system-prompt 啟動的子代理與工作階段，也會一次記錄提示詞與工具定義，不再每次重新渲染。

延續同一個會議記錄思維，這就像隔天回到會議室復工時，直接對照昨天蓋印封存的會議底稿接續討論，不會因為助手分頭跑腿或翻開備份記錄就擅自撕掉前言。

工件發布支援斷線自動重試，明確指出損壞字元行數與欄位

發布工件（artifact，在獨立視窗展示的成果文件）若中途網路斷線或遇到格式錯誤，現在不再只回傳不明原因的失敗代碼。在過去，如果上傳檔案時連線中斷，Claude Code 往往只能回報未知結果；如今只要判定傳輸未完成，就會自動重試 1 次以確保順利送達。當頁面檔案並非有效的 UTF-8 編碼，或是包含代表損毀的替換字元（U+FFFD）時，錯誤訊息也不再模糊帶過，而是會具體標示出需要修正的行數與欄位。若工件發布遭到拒絕，畫面亦會清楚解釋被拒原因以及具體的應對處置方法。

這套防護有如印刷廠送件作業，遇到斷線能自動重發一次，內容包含損壞字元時會明確指出第幾行第幾列，被拒絕出版時也會清楚說明退件原因與修改方針。

遠端操控憑證過期自動續期，及時同步桌面與編輯器權限

在遠端電腦透過 claude remote-control 連線工作時，長時間掛機最怕憑證失效讓所有連線瞬間中斷。

這如同在長效監控哨所配置專用通信機，遇到月度密碼過期會自行向總部換約重連而不斷線，新加入的聯絡終端也能即時掌握目前的防衛等級。

以往遠端伺服器憑證在大約 30 天過期後，主機行程會直接退出並切斷所有掛載的工作階段；現在主機端會自動重新註冊憑證並持續保持運作。同時，新加入 Claude Desktop 或 VS Code 工作階段的遠端操控客戶端，之前常停留在過期的舊權限模式直到手動變更，如今一連上就能立刻呈現即時且正確的權限狀態。

企業受管設定嚴密把關，雲端憑證逾期精確回報

在由公司統一控管規則的企業環境中，雲端排程與登入驗證具備更嚴密的防護。受管設定要求沙箱時 Cowork 雲端排程啟動失敗已修復；allowedHttpHookUrls、httpHookAllowedEnvVars 與 allowedChannelPlugins 讀取失敗時一律不予放行。在 Claude Desktop 下 AWS 或 Google Cloud 憑證過期不再盲目重試 10 次，改為提示重新認證；強制閘道登入框按 Esc 即可關閉。自建執行端會回報 --use-anthropic-git-proxy 並對使用舊代理的工作階段提出警示，轉發身分遇 429 限制不再轉移上游以落實每人配額。

整體防護宛若金融大樓的安全閘道，條文讀取不清時一律從嚴封鎖，身分過期不再盲目空轉十次，限制也確實落實到每位個別訪客頭上。

終端機按鍵與滾動修復，輸入文字不再延遲跳格

在手機或終端機全螢幕下操作各項指令，文字輸入與介面捲動現在更加乾淨俐落。

這恰似把老舊放映機的齒輪重新校準，打字輸入不再因為背景動畫轉動而延遲跳格，切換視窗或滑動閱覽時畫面資訊也穩定呈現。

以前在代理人檢視中重新連線至 tmux 或 ssh 工作階段後，Shift+Enter 換行與 Option+Backspace 刪除單詞等快捷鍵會失效，如今已完全修復。行動端設備執行 /context 等本機指令時輸出空白的問題已獲解決，在全螢幕向上滾動時，對話頂端也能正常顯示淡色的上一則提問提示。此外，/diff 程式碼差異面板不再先閃爍零個檔案變更與載入轉圈才定格，無改動時的空白提示也已置中對齊，打字時按鍵更不會被載入動畫卡住延遲。

恢復大容量歷史對話不掉內容，用量警示燈號穩定顯示

恢復先前對話或載入超過 5 MB 的超大歷史紀錄時，整個還原過程變得更乾淨迅速。以前在包含大量 Bash 工具呼叫的對話中執行 --resume，首次渲染畫面常需等待；現在首次渲染更快。當工作階段的對話紀錄超過 5 MB 時，先前重新載入對話容易漏失平行工具呼叫與掛鉤（特定事件發生時被觸發的小程式）輸出，如今資料都能完整重現。透過 -p --resume 執行 /compact 壓縮或其他斜線指令後，對話中也不會再多生出一筆多餘的接續提示。如果工作階段中因切換不同模型或模式而回傳不同的額度週期，用量上限警示也不會再忽明忽暗地閃爍。

整個載入流程好比翻開厚重的歷史卷宗，即使檔案超過 5 MB 且包含多條平行批註也能完整讀取，恢復作業時不再無故多插一張空白備忘頁。

終端指令回傳白話說明，市集路徑防護與沙箱複製指引

讓 Claude 在自動模式或沙箱環境執行工作時，工具的引導說明與安全把關變得更親切嚴謹。以往執行終端命令時，Claude 常只是機械式複誦指令；現在更新了 Bash 工具說明指引，引導它用大白話解釋命令的作用。在沙箱內若遇到 pbcopy 等剪貼簿指令執行失敗，Claude 會主動建議改用內建的 /copy 指令。工作流程中帶有龐大輸出結構的 agent() 呼叫，在自動模式下不再直接被拒，而是交由安全分類器審查。在 macOS 與 Linux 上，外掛市集路徑帶有反斜線可繞過邊界檢查的漏洞已堵死；claude agents 的 @ 選單也能即時列出工作階段開啟後新建立的儲存庫。

這如同給領航員換上更清晰的作業指南，執行指令時會用白話解釋步驟，遇到封閉環境複製失敗時也會主動推薦替代指令。

[VSCode] 差異檢視跟隨編輯器主題，修復截圖貼上與多語系文字

在 VS Code 裡與 Claude 對話，程式碼差異對照面板現在能完美貼合你的編輯器主題。

體驗改善有如為繪圖板換上具備自動調色的多功能畫布，不管是貼上圖片、選用高對比深淺外觀，或是處理帶有空格的檔名，筆觸都精準無誤。

過去對話框中的變更區塊總是強制以深色佈景顯示，現在會同步套用當前啟用的色彩主題與高對比模式。在 WSL2 或 WSLg 環境下貼上螢幕截圖時，不再把原始圖片位元組塞進輸入框，而是直接轉成附件或自動略過；同時修復了混合由右至左語系與英文時文字順序錯亂的問題。在檔案修改方面，採 Windows（CRLF）換行格式的檔案在確認套用變更時不再噴出找不到字串的錯誤，且使用 @ 提及檔案時也不會漏掉路徑帶有空格的檔案。

[VSCode] 遠端工作階段清單載入修復，排除循環歷史與行程空轉

開啟含有大量捷徑或龐大專案的遠端主機時，VS Code 擴充套件不再因循環紀錄或檔案搜尋而把 CPU 衝上 100%。過去當對話存檔中包含循環的父層關聯時，進行對話分支、編輯歷史訊息或執行倒轉操作會導致外掛主機直接卡死在 100% CPU，現已修復。透過 Remote-SSH 連線且工作區資料夾僅存在於遠端電腦時，工作階段清單介面過去會載入失敗，目前已能正常顯示。此外，在超大型專案或含有密集符號連結（指向另一個位置的捷徑檔）的工作環境中檢視檔案時，背景搜尋工具 ripgrep 行程失控狂飆的問題也獲得了解決。

承接同一個工作環境的平穩運作，這好似為巡檢機具加裝轉速調節器，遇到跨主機遠端連線或大量捷徑檔案時不再失控空轉。

[Claude Code on the web] 企業版 GitHub 授權自動換新，調度本人帳號備援呼叫

透過網頁版 Claude Code 操作 GitHub 企業伺服器時，逾期的 token（授權令牌，用於身分認證）現在會自動換新。

這宛如在雲端工作台配置全天候秘書，遇到通行權杖逾期會自動換發，即使所屬單位未安裝官方擴充套件，也能直接採用你本人的帳號順暢銜接。

先前在 GitHub Enterprise Server 的工作階段中，只要個人認證憑證到期，介面就會誤標為帳號已斷線；如今在進行拉取請求（PR）或討論議題操作時，系統會自動在背景刷新授權並保持連線。另外，在尚未安裝 Claude GitHub App 的組織架構下，執行 gh 命令或呼叫 API 原先會直接報錯，現在會直接改用你已綁定的 GitHub 帳號發送請求，若尚未登入也會明確提示。

[Claude Tag] 預設連線支援切換自訂通道，額度耗盡清楚指引儲值

負責管理 Claude Tag 團隊連線的管理者，現在不必刪除重來就能將預設通道切換至自訂連接器。在後台設定預設連線表單時，新加入的「Use a custom connector」連結允許你中途直接轉向自訂通道。當團隊組織的用量額度耗盡時，Claude 過去只會冰冷回報 API 拒絕了無效請求，現在會具體說明額度已用完並指引儲值方法。在頻道頂層發布訊息後，成員在討論串內要求編輯或刪除該則貼文時，指令不再被誤判為對話糾錯，而是確實轉交給當初發文的工作階段處理。此外，管理審查介面的工具存取授權請求點擊「Connect」時，之前常跳出授權失敗或誤報授權包已刪除的問題也已修正。

整個調整就像在團隊客服總機後台增加切換自訂外線的捷徑，額度用盡時明確告知儲值途徑，留言串內的修改請求也能準確遞交給當初發文的專員。

Universal Thinking Depth Limits with maxEffortLevel, Frontmatter Effort Settings Now Effective

If you want Claude to reason deeply without burning through excessive tokens, you can now cap its thinking depth with the maxEffortLevel setting.

This is like installing a speed limiter stop beneath a sports car's accelerator pedal: it caps maximum RPM on any highway while still letting the driver cruise gently, ensuring custom cruise-control instructions along the route are no longer overridden by factory defaults.

Previously across cloud providers like Bedrock, Vertex, and Foundry, it was difficult to uniformly lock effort level caps. Now, whether configured at the top level or per model under modelSettings, limits apply consistently while still allowing you to pick a lower effort level during daily use:

{
  "maxEffortLevel": "medium",
  "modelSettings": {
    "claude-opus-4-7": {
      "maxEffortLevel": "low"
    }
  }
}

Additionally, effort: values specified in YAML frontmatter for custom commands, skills, or subagents previously failed on models with pinned default effort levels (such as Opus 4.7, Opus 4.8, and Fable 5); this has now been fixed to take effect properly.

Real-Time System Prompt Re-Rendering Without Restarting Conversations

If you are iterating on prompt text and tired of starting a new conversation for every tweak, the new --system-prompt-snapshot off flag is built for you. When polishing custom prompt content, the system by default reuses the prompt snapshot recorded at session start, causing active conversations to keep reading stale content even after you edit external files. Now, by passing this flag when launching Claude, every request will reload and render the latest system prompt fresh, making prompt experimentation much faster and more flexible.

The entire workflow is like trying on costumes in a rehearsal hall: actors step onto the stage wearing the latest fabric adjustments on the spot, rather than dismissing the entire cast to restart the show after every stitch.

Reasoning Preserved Across Tool Changes, Cache Reuse Holds on Model Switches

When Claude invokes external tools or switches models mid-session, previously accumulated reasoning context no longer vanishes unexpectedly.

This is like experts solving equations across a conference room whiteboard: even if guest consultants walk in and out or microphones get swapped, no one suddenly wipes the entire board clean to start over.

Previously, when an MCP server re-sent definitions, a built-in tool re-rendered, or a tool disappeared due to disconnections or upgrades, rewriting the tool list discarded earlier thinking; reasoning is now safely preserved. In sessions without ToolSearch, dynamically added plugin tools are now passed as deferred definitions to prevent breaking prompt-cache reuse. Switching models via /model no longer re-sends every tool definition; commit and PR attribution text now arrives as a conversation note that updates on model changes, and reasoning memory is also retained when claude.ai connector tools change across session resumes.

Resumed Sessions Reuse Tool Descriptions, Background Tasks Preserve Prompt Cache

When reopening unfinished sessions, cache invalidation causing inference delays is a major pain point. Previously, when a background worker forked from a conversation added EnterWorktree to the conversation's tool block, it broke prompt-cache reuse. Now when resuming a session, tool lists are no longer rewritten and thinking is no longer dropped due to MCP reconnection timing differences; turns executing tools on the first step also replay recorded descriptions directly instead of re-rendering them. Additionally, the system prompt prefix remains consistent when resuming a print-mode (-p) conversation interactively. Subagents and sessions launched with --system-prompt or --append-system-prompt now record prompt and tool definitions once instead of re-rendering them.

Continuing the meeting records analogy, this is like resuming work in the conference room the next day with yesterday's stamped and sealed minutes, without tearing off the preface just because assistants ran errands or opened backup logs.

Artifact Publishing Adds Auto-Retry on Disconnects, Pinpoints Corrupted Character Locations

When publishing artifacts, network drops or formatting errors no longer return vague failure codes. Previously, if a connection was cut off mid-upload, Claude Code often reported an unknown outcome; now, whenever it detects that an upload never completed, it automatically retries once to ensure delivery. When a page file is not valid UTF-8 or contains replacement characters (U+FFFD) indicating corruption, error messages no longer gloss over the issue, instead explicitly naming the line and column to fix. If an artifact publish is refused, the screen also clearly explains the reason along with actionable remediation steps.

This protection is like submitting print jobs to a press: it automatically retries once if transmission drops, pinpoints exact row and column numbers if corrupted characters appear, and provides clear rejection reasons and revision instructions if publishing is turned down.

Automatic Renewal for Expired Remote Control Credentials, Real-Time Desktop and Editor Permission Sync

When working on a remote machine via claude remote-control, long-running sessions no longer suffer sudden drops from expired credentials.

This is like equipping an outpost with a dedicated communicator that automatically renews its monthly passcode with headquarters without dropping the link, while newly connected terminals instantly reflect current defense levels.

Previously, when server credentials expired after about 30 days, the host process exited and dropped all attached sessions; now the host automatically re-registers and keeps running. Meanwhile, Remote Control clients joining a Claude Desktop or VS Code session previously remained on stale permission modes until changed manually, but now immediately reflect accurate, up-to-date permission states upon connecting.

Strict Enterprise Managed Settings Enforcement, Accurate Cloud Credential Expiration Reporting

In enterprise environments governed by centralized policies, cloud scheduling and login authentication now receive tighter safeguards. Startup failures for Cowork cloud scheduled tasks in organizations requiring sandboxing are now fixed; unreadable allowedHttpHookUrls, httpHookAllowedEnvVars, and allowedChannelPlugins settings now admit nothing rather than everything. Under Claude Desktop, expired AWS or Google Cloud credentials no longer blindly retry 10 times, prompting for re-authentication instead; pressing Esc now closes the mandatory gateway login dialog. Self-hosted runners now report --use-anthropic-git-proxy and warn sessions cloning via the legacy proxy, while forward_user_identity passes 429 rate limits directly to developers rather than failing over upstreams to enforce per-user quotas.

The overall defense resembles security turnstiles in a financial building: unreadable rules strictly deny entry, expired badges no longer trigger ten pointless retry spins, and limits are enforced on every individual visitor.

Terminal Keystroke and Scrolling Fixes, Jitter-Free Responsive Text Input

Operating commands across mobile clients or fullscreen terminals is now much smoother for text input and interface scrolling.

This is like recalibrating the gears of a classic projector: typing input no longer lags behind background animations, and screen details remain steady when switching windows or scrolling.

Previously inside agent views, reconnecting to tmux or ssh sessions broke shortcuts like Shift+Enter for newlines and Option+Backspace for word deletion; these are now fully fixed. Blank outputs when running local commands like /context on mobile devices have been resolved, and scrolling up in fullscreen mode now reliably shows the dim last-prompt header at the top. Additionally, the /diff code difference panel no longer flashes "0 files changed" with a spinner before settling, its empty state is centered, and keystrokes are no longer delayed by loading animations.

Restoring Large Conversation Transcripts Without Data Loss, Stable Usage Warnings

Resuming previous conversations and loading massive transcripts over 5 MB is now cleaner and faster. Previously, running --resume on sessions with many Bash tool calls caused noticeable delays on first render; first-render time is now shorter. When a session transcript exceeds 5 MB, reloading used to drop parallel tool calls and their hook output; all of it now comes back intact. Running /compact or other slash commands via -p --resume no longer inserts an extra spurious continuation prompt. If switching models or modes within a session returns varying quota windows, usage-limit warnings no longer flicker on and off.

The entire loading process is like opening a heavy historical archive: even files exceeding 5 MB with parallel marginal notes load completely, without inserting an unneeded blank memo page upon resumption.

Plain-Language Terminal Command Descriptions, Marketplace Path Containment and Sandbox Copy Guidance

When running Claude in auto mode or sandboxed environments, tool descriptions and security checks are now clearer and stricter. Previously when executing terminal commands, Claude often mechanically echoed the command; updated Bash tool guidance now steers it to explain what commands do in plain words. Inside the sandbox, if clipboard commands like pbcopy fail, Claude proactively suggests using the built-in /copy command. In workflows, agent() calls with large output schemas are no longer flatly refused in auto mode, routing to the safety classifier for review instead. On macOS and Linux, a case where a marketplace entry path containing a backslash could bypass the containment check has been closed, and the claude agents @ menu now lists repositories created after session start.

This is like giving a navigator clearer operational guidelines: explaining steps in plain terms when issuing commands, and recommending alternative commands when copy operations fail inside closed quarters.

[VSCode] Diff View Adapts to Editor Themes, Fixes for Screenshot Pasting and Multilingual Text

When chatting with Claude in VS Code, code diff panels now align with your active editor theme.

The upgrade is like outfitting a graphics tablet with an auto-adjusting color canvas: whether pasting images, choosing high-contrast dark or light themes, or handling filenames with spaces, every stroke remains precise.

Previously, chat diff blocks always rendered with a dark theme; they now follow the active VS Code color theme, including high contrast. Pasting screenshots on WSL2 or WSLg no longer inserts raw bytes into the chat input, instead attaching the image or ignoring the paste if unavailable; typing mixed right-to-left and English text in the wrong order has also been fixed. For file edits, accepting changes in diff view on files with Windows (CRLF) line endings no longer fails with "String not found in file", and @-mentions no longer drop files with spaces in their paths.

[VSCode] Remote Session List Loading Fixes, Eliminating Cyclic Loops and Runaway Processes

When connecting to remote hosts with symlink-heavy or massive codebases, the VS Code extension no longer spikes CPU to 100% over cyclic transcripts or file searches. Previously, when saved transcripts contained cyclic parent links, forking, editing earlier messages, or rewinding caused the extension host to hang at 100% CPU; this is now fixed. In windows connected over Remote-SSH where the workspace folder exists only on the remote host, the sessions list view previously failed to load and now renders properly. Additionally, runaway background ripgrep processes when viewing files in large or symlink-heavy workspaces have been resolved.

Continuing the smooth operation of this workspace, this is like adding a speed governor to inspection machinery, preventing uncontrolled spinning during cross-host remote connections or encounters with heavy shortcuts.

[Claude Code on the web] Automatic Token Refresh for GitHub Enterprise, Personal Account Fallback for API Calls

When working with GitHub Enterprise Server via Claude Code on the web, expired tokens now refresh automatically.

This is like assigning a 24/7 assistant to your cloud workbench: when access tokens expire, they are renewed automatically, and work carries on under your personal account even if the organization lacks the official app.

Previously in GitHub Enterprise Server sessions, expired authentication credentials caused the interface to report the GitHub account as disconnected; PR and issue operations now automatically refresh tokens in the background to stay connected. Additionally, in organizations without the Claude GitHub App installed, running gh commands or making GitHub API calls previously threw errors, but now routes through your connected GitHub account and explicitly notes when none is connected.

[Claude Tag] Preset Connections Support Switching to Custom Channels, Clear Guidance on Depleted Credits

Administrators managing Claude Tag team connections can now switch preset connections to custom connectors without starting over. When configuring preset connection forms in admin settings, a newly added "Use a custom connector" link lets you pivot directly to custom channels. When an organization runs out of usage credits, Claude previously replied with a generic message stating the API rejected an invalid request; it now explicitly explains credits are exhausted and details how to add more. After Claude posts a message at a channel's top level, thread requests to edit or delete that post are no longer treated as conversational corrections, routing properly to the session that originally posted it. Additionally, clicking **Connect** on Tool access requests under Admin settings > Review requests previously failed with "Authorization failed" or showed the access bundle as deleted; this has now been resolved.

The overall update is like adding a shortcut to switch to custom outside lines in a team switchboard: clearly guiding top-ups when credit runs out and routing thread edit requests to the original dispatcher.
