Claude Code 2.1.295

發布日期：2026-10-08

繁體中文

問題修復

掛鉤阻擋失敗動作，修正重新載入時的防護漏洞

當你加上自訂掛鉤（hook，特定事件發生時被觸發的小程式）時，啟動失敗也能阻擋動作。

命令與 HTTP 掛鉤支援 onFailure: "block"，啟動失敗、逾時或傳回非預期結束碼就阻擋後續動作。深層巢狀工具輸入不再被截斷而漏掉防護。外掛掛鉤背景工作單元重新啟動、模組重新載入期間，原本會繞過另一模組帶有 .catch 的防護掛鉤的呼叫，現在會被拒絕。非同步掛鉤分多行印出的 JSON 也能正確讀取；雲端工作階段不再因 session.receive 掛鉤先請求權限而卡住。工具執行後若遭外掛拒絕，Claude 與你會得知工具已執行，但結果被攔截。

大樓門禁重開機時，以前可能漏查另一道關卡，現在這類通行會被拒絕。
問題修復

外掛市集安裝與驗證補上警告，誤刪問題修好

管理擴充工具時最怕設定檔載入失敗卻毫無動靜。

執行 claude plugin install、enable、disable 或新增市集時，若要寫入的設定檔無法載入，會發出警告。在 /plugin 錯誤分頁按 Enter，不再未經確認就移除市集及其外掛。新增市集若名稱無法用於安裝外掛，會直接拒絕；新增或重新整理含大型 Git 子模組的市集時，只抓取含外掛檔案的子模組。子模組是儲存庫內連結的另一份儲存庫。claude plugin validate 遇到 README 缺少安裝指令，會印出可貼上的建議，不影響結束碼，即使使用 --strict 也一樣。掛鉤模組因頂層 var 重新綁定遭拒時，錯誤會指出行號、原因與修法。

逛軟體商店時，以前按 Enter 可能誤刪商店與已裝商品，現在會先問你。
新功能

模組介面按鈕更豐富，通知優先權與編寫引導升級

開發或使用自訂介面模組時，資訊排版與提醒層級現在更有彈性。

模組現在可透過 $.ui.notify 發送符合系統設定的原生桌面通知，並明確標記發送來源。按鈕元件支援放入文字子節點，方便在單一可點擊按鈕內呈現標籤或次要細節。由所屬組織發布的彈出提示（toast）會排在其他模組前面優先顯示。內建的外掛編寫技能在沒有終端機的工作階段中不再要求執行指令，並僅在被詢問時才解說分享流程；Workflow（工作流程工具）拒絕 scriptPath 時，會提示改用 script 行內傳入腳本，這種方式可在沒有 Read 讀取工具的工作階段使用。

問題修復

外掛熱重載補上漏接存檔，不再反覆跳出確認詢問

在修改擴充模組並即時查看效果時，漏接存檔可能讓你仍看到舊版本。

熱重載（hot reload，修改程式碼後不重啟即時生效的技術）已修好兩種漏接：/reload-plugins 或工作階段啟動正在讀取模組檔案時存檔，以及上次重載後幾毫秒內再次存檔。重載詢問直接放行但未選答案後，不再每回合重複出現；SDK 宿主若在回答前關閉詢問，詢問最多會出現三次，不再整個工作階段都關閉熱重載。外掛選項命名為 constructor 或 prototype 時，不再一直讀到預設值，編輯後也能重新載入。加入大型介面的外掛，在外掛掛鉤背景工作單元停滯時，不再使另一個外掛被卸載。

問題修復

外掛設定變更嚴格受檢，提示詞歷程不再殘留無效內容

透過外掛管控對話設定或改寫輸入時，設定與記錄應該反映外掛的決定。

使用 /model、/fast、/output-style 或在 /config 切換自動更新管道，會先詢問 config.set 掛鉤（特定事件觸發的小程式），再儲存設定。prompt.submit 掛鉤改寫或捨棄輸入後，提示詞歷程與對話記錄中的待發送提示詞紀錄，不再保存改寫或捨棄前的原始輸入。claude plugin test 不再錯誤放行會移除工具呼叫、工具結果或思考區塊的 session.append 掛鉤，這些區塊在真實工作階段會保留。-p 與 SDK 工作階段不再把產生的型別檔寫入 --plugin-dir 外掛資料夾，只寫到正在開發模組的位置。掛鉤模組程式碼巢狀數千層時，載入或驗證失敗並只顯示堆疊溢位訊息的問題也已修好。

問題修復

Windows 外掛載入與安裝紀錄修正，快取誤判修好

在 Windows 環境或多個連線環境間使用外掛時，可能遇到路徑與管理歸屬判斷錯誤。

VS Code 在 Windows 上因磁碟代號大小寫不同而無法載入專案範圍外掛的問題已修好。Windows 的 plugin install、uninstall 在專案或本機範圍操作時，也不再因 C: 與 c: 這類差異漏掉安裝紀錄或新增重複紀錄。長時間運作的工作階段，在另一個工作階段同步 claude.ai 外掛更新後，掛鉤不再錯報「Plugin directory does not exist」。託管設定會列出或啟用外掛的機器上，遭竄改的伺服器託管設定快取（把查過的資料暫存起來直接用）將個人外掛誤判為組織管理外掛的問題也已修好。

新功能

企業閘道支援串流逾時控制，模型清單也限制備援轉送

企業透過閘道轉送雲端模型請求時，可以限制等待與模型去向。

timeouts.upstream_ttfb_ms 可設定 Bedrock、Vertex、Foundry 等上游的串流開始等待毫秒數，逾時就切換備援（主通道失敗時接手的替代方案）或回傳 502。每個上游可設 models 清單，只轉送列出的模型，備援轉送也受限制；每個項目中的一個 * 可作萬用字元。Amazon Bedrock 位於 AWS 美國地理區域以外時，未列於 models: 的模型請求原本會被 AWS 拒絕；閘道現在會嘗試你自己的區域，若仍遭拒，會指出需加入的模型。背景請求優先使用 Haiku 4.5，閘道未提供時才退回工作階段原本的模型。

物流中心以前改走備用線可能漏查貨物名單，現在換線也得照名單分派。
新功能

企業閘道強化登入強制導向，審計紀錄精準串聯雲端請求

如果企業需要集中管控員工的登入管道與使用軌跡，可以設定登入去向並比對請求紀錄。

沒有託管設定的機器，可在使用者設定加入 forceLoginMethod: "gateway" 與 forceLoginGatewayUrl，讓 /login 開啟指定閘道。模型推論的審計紀錄新增 upstream_request_id，成功回應標頭加入 request-id，方便對照雲端上游、閘道日誌與 Claude Code 遙測。機器已設定 OpenTelemetry（收集監控資料的標準），或工作階段已登入閘道時，登入驗證事件能正確匯出。若遇到內附 Claude Desktop 結構定義尚不認識的 desktop 原則鍵，閘道會帶著警告啟動並提供該設定，不必為這類新桌面設定升級閘道。

問題修復

企業閘道改用 AWS CountTokens，花費上限與 Fable 選單修正

管理員查看閘道用量時，工作階段移出群組後不再殘留舊群組與花費上限。

Amazon Bedrock 閘道改用 AWS CountTokens API 計算權杖（token，AI 處理與計費的文字單位），取代向模型請求單一權杖的方式，供 /context 與大檔讀取使用；需授予 bedrock:CountTokens 權限。PostgreSQL 資料庫處於唯讀狀態時，每 30 秒記錄警告，說明哪些操作失敗及如何復原。CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC 不再隱藏 /usage 與狀態列的閘道花費上限，花費上限請求會送往目前工作階段登入的閘道。已登入閘道的工作階段，availableModels 中的 Fable 模型現在會顯示於 /model 選單，以內建列取代同模型的 modelPicker 列。

新功能

基礎工具參數解析更寬容，權限受限模式嚴格受控

讓 AI 執行命令或讀取檔案時，參數小差異不再直接卡住工具。

Bash（執行終端機命令的工具）收到 command_description 而非 description 時不再失敗；Read 收到空的 pages 參數會視為未填。Grep 搜尋支援附帶 -l、-c、-r 旗標，不再因此呼叫失敗。--tools 與 --restricted 的限制會套用到啟動後才註冊的內建工具，已棄用的工具名稱也不再繞過呼叫者的工具集合。Bash 對萬用字元迴圈的權限檢查已修正。無法取得功能旗標（控制功能是否開啟的開關）時，Claude 3 Opus、Claude 3.x Sonnet 工作階段不再被提供它們會拒絕的工具搜尋。

新功能

百萬上下文請求智慧降級，檔案變更偵測不再誤判已讀

當處理龐大程式碼庫或超長上下文時，系統與模型之間的溝通更加穩健。

使用標記百萬上下文（[1m]）的模型時，若雲端平台拒絕該測試旗標，系統會自動移除旗標並重新發送請求，避免整批請求直接失敗。在檔案讀寫方面，即使檔案修改時間未更新但內容已變動，或是終端機指令未印出內容，編輯工具都不會誤以為檔案已經完整讀取過。大型檔案上傳失敗且未提供原因時，Claude 得到的說明已改善，會回報失敗而不縮小檔案。xhigh 與 max 思考力度下，網路搜尋及 agent 掛鉤（特定事件觸發的小程式）評估耗時過長的問題已修好。

新功能

外部工具採用退避重連，長時間斷線後可再連線

在無頭模式（headless，沒有終端機視窗的執行模式）或 SDK 程式整合中連接遠端工具時，斷線後不再一直離線。

遠端 MCP（讓 AI 連接外部工具的協定）伺服器中斷超過 15 秒後無法重連的問題已修好；反覆連上就斷線時，重連間隔會逐步拉長，最多 30 秒。伺服器錯誤回覆含網路錯誤名稱，不再使連線被誤切斷；分頁指標重複也不再反覆索取同頁。等待資源清單時按中斷鍵，能結束回合而無需等逾時。WebSocket 傳輸收到超過 16 MiB 的訊息，不再解析並會關閉連線，與其他傳輸方式的上限一致。

猶如撥打客服專線，以前接通就斷線仍急著重撥，現在會拉長間隔再試。
新功能

外部工具檔案型別精準辨識，工具說明長度上限放寬

透過外部工具回傳程式碼、樣式或圖示檔案時，檔案格式現在能正確保留。

以前 MCP（讓 AI 連接外部工具的協定）工具回傳的 CSS、JavaScript、XML 容易被存成 .bin，使 Read 拒絕讀取；現在這些檔案及字型、圖示都有對應副檔名。工具搜尋載入的說明上限由 2,048 放寬至 16,384 字元。claude mcp serve 的背景 Bash 結果會指出輸出檔名，工具說明也修正了原本承諾會收到、實際卻永遠不會到達的通知。不取得功能旗標的安裝中，claude.ai 連接器預設協商 MCP 協定版本 2026-07-28；功能旗標是控制功能是否開啟的開關，可用 MCP_PROTOCOL_NEGOTIATION=legacy 退出這項協商變更。

問題修復

MCP 工具背景任務狀態透明，非互動模式不再多餘警示

當你將耗時較長的 MCP（讓 AI 連接外部工具的協定）工具呼叫放到背景執行時，任務動態的同步變得更加清晰。

如果你在任務面板或連線客戶端中手動中止了執行中的 MCP 工具，Claude 會得知工具已停止。工具轉移到背景時所跳出的系統通知，現在會顯示完整的任務識別碼以利辨識。在自動化無人值守的非互動工作階段中，若任務完全不需要使用特定 MCP 伺服器，不再跳出多餘的登入驗證提示；無頭模式（沒有終端機視窗的執行模式）與 SDK 工作階段中，延遲完成的登入或重連，不再把 setMcpServers() 設定的 MCP 伺服器誤列為使用者自己的伺服器。

問題修復

子代理工作環境資訊修正，訊息傳遞與技能預載修好

讓子代理（分頭執行子任務的 AI 助理）在獨立工作樹工作時，不再混入主工作階段的 Git 分支、狀態與近期提交。

工作樹是同專案的平行副本。Workflow 子代理的技能結果回給呼叫者；代理夥伴首次 SendMessage 不再因工具未載入而失敗。工作階段遭終止後第二次恢復時，也會提醒 Claude 可用 SendMessage 恢復背景子代理。名為 worker 的自訂代理，不再於自動模式拒絕通知及任務詳情活動清單中誤顯示為「Agent」。Skill 工具先於回應串流結束時，allowed-tools 與 effort 不再遺失；兩欄指定可用工具與思考力度，避免 -p 的 Bash 指令遭拒。子代理從 skills 最多預載 32 個技能、各一次，有 Skill 工具仍可呼叫其餘技能。

新功能

背景任務取消操作分清楚，服務停止時告知收尾

按 ← 將工作移到背景、還在等工具完成時，停止與繼續工作的操作有不同結果。

停止回合會顯示「Backgrounding cancelled」；輸入文字取消背景化，Claude 則繼續在前景工作。CLAUDE_AUTO_BACKGROUND_TASKS 不再於子代理後方仍有編輯或命令排隊時搶先背景化，避免後方呼叫過早開始。macOS 或未安裝服務的 Linux 上，claude agents 與背景服務一起停止時，執行中的工作階段約一分鐘後停止並顯示通知；期間再次執行 claude agents 可避免停止。兩者退出時不再意外啟動新服務，拖延關機或重啟中斷的工作階段。恢復時也不再誤告知 Claude 未完成的背景工作流程可能遭 TaskStop 停止。

新功能

循環排程快捷鍵明確分工，無人看守重試支援時間上限

使用 /loop 定時檢查時，離開連線畫面與停止循環是兩件事。

連接背景工作階段，在閒置提示字元按兩次 Ctrl+C 只會離開連線，待執行的喚醒仍保留；按 Esc 才停止循環，取消待執行喚醒也會顯示通知。用 ← 移到背景的自定步調 /loop，Esc 無法停止的問題已修好。若下次喚醒在程序停止期間到期，循環會停止；現在工作階段會顯示通知，Claude 也會得知。無人看守的重試模式 CLAUDE_CODE_RETRY_WATCHDOG 可用 CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS 環境變數（啟動程式前提供的設定），限制遇到 429 用量限制或 529 伺服器超載時的最長等待毫秒數。

問題修復

對話倒帶歷程嚴格同步，環境變數與排程狀態精確還原

使用 /rewind 倒帶對話或分支出新主題時，不會再遺失提示詞或誤重啟已停止的任務。

倒帶後送出的提示詞，在工作階段移到背景或遭終止後恢復時不再遺失，被刪除的回合也不再重現。已停止的排程不再於倒帶後恢復時重啟；對話壓縮後按 Esc 或倒帶，再恢復工作階段時遺失排程的問題也已修好。剛按 ← 後，用 ↑ 或 Esc 將待發送訊息拉回輸入框，提示詞歷程會保留它。執行 /resume 或 /branch 後，SessionStart 掛鉤（啟動工作階段時觸發的小程式）寫入 CLAUDE_ENV_FILE 環境檔案的變數能傳給 Bash 工具；未變更的非同步啟動掛鉤上下文，也不再於每次恢復時重複加入對話。

新功能

終端機支援狀態通訊協定，管線輸出與文字複製更乾淨

與 Claude 互動或將輸出交給其他程式時，狀態與回覆不該漏掉。

支援程式狀態協定 OSC 7501 的終端機，能在分頁或狀態列顯示 Claude 正在工作、等你輸入或已完成。/copy 可選取引言文字，複製時不帶 >。管線（將輸出接給另一個程式）中緊接淡色字的粗體字，不再被畫成淡色。背景工作階段的命令與掛鉤不再繼承 FORCE_COLOR=3，避免 Claude 讀到顏色跳脫碼。claude -p 若因背景工作開啟新回合，每回合回覆會在回合結束時印出，不再丟失早先回覆。最後回合結束後仍保持開啟時，只有標準錯誤輸出 stderr 連到終端機，才會印出正在等待什麼的說明。

問題修復

終端機游標定位修復，連結安全性與介面互動改善

在終端機打字、貼上特殊字元或點擊超連結時，游標與連結顯示不該誤導你。

從 macOS 剪貼簿將帶重音標記的文字貼到提示字元中間，游標不再多跳一格。vim（以按鍵指令編輯文字的模式）的 ~ 不再把游標移過行尾，使後續 x 刪除指令無效；3~ 也不再跨入下一行。回覆或代理夥伴訊息中的原始終端機超連結位元組，不再被畫成隱藏位址的可點連結；文字網址也不再被殘留的顏色或隱藏樣式遮住，包括表格換行與問題預覽。/model 的 Max 思考力度會正確標示只適用目前工作階段。/tui 無法重新啟動 Claude Code 時，無訊息退出或顯示原始系統錯誤的問題也已修好。

問題修復

終端機超長回覆凍結修好，語法高亮與排版定位修正

當 Claude 產生數萬行回覆或逐漸加深的巢狀引言時，終端機曾卡到難以操作。

FEATURE

Hooks Block Failed Actions and Close Shielding Gaps During Reloads

When you add custom hooks (small programs triggered by specific events), startup failures can now block actions.

Command and HTTP hooks support onFailure: "block", blocking subsequent actions if they fail to start, time out, or return an unexpected exit code. Deeply nested tool inputs are no longer truncated to bypass protections. During plugin hook worker restarts and module reloads, calls that previously bypassed another module's shielding hook with .catch are now rejected. Multi-line JSON printed by async hooks is parsed correctly, and cloud sessions no longer hang when a session.receive hook requests permissions upfront. If a tool execution is rejected by a plugin after running, both Claude and you are informed that the tool executed but its output was intercepted.

Like a building access system that used to miss a second checkpoint during reboots, such entry requests are now rejected.
BUGFIX

Plugin Marketplace Adds Install Warnings and Fixes Accidental Deletion

When managing extensions, silent configuration load failures can cause unexpected issues.

Running claude plugin install, enable, disable, or adding a marketplace now issues a warning if the target configuration file fails to load. Pressing Enter on the /plugin error tab no longer removes the marketplace and its plugins without confirmation. Adding a marketplace is rejected if its name cannot be used to install plugins; adding or refreshing marketplaces with large Git submodules now fetches only submodules containing plugin files. Submodules are separate repositories nested inside a repository. When claude plugin validate finds a README missing install instructions, it prints pasteable suggestions without affecting the exit code, even when using --strict. When a hook module is rejected due to top-level var rebinding, the error message indicates the line number, reason, and remediation.

Picture browsing an app store where pressing Enter used to delete the store and installed items; it now asks for confirmation first.

Richer Module UI Buttons with Upgraded Notification Priorities and Authoring Guidance

When building or using custom UI modules, layout and alerting options are now more flexible.

Modules can now deliver native desktop notifications via $.ui.notify respecting system preferences and clearly attributing the source. Button components support text child nodes, allowing labels or secondary details to be rendered within a single clickable button. Toast popups published by your organization are prioritized ahead of other modules. The built-in plugin authoring skill no longer prompts to run commands in sessions without a terminal and only explains sharing flows when asked. When Workflow (a workflow tool) rejects scriptPath, it prompts you to use script to pass inline scripts instead, which works in sessions without Read tools.

When modifying extension modules and inspecting changes in real time, missed file saves can leave you looking at outdated code.

Hot reload (applying code changes immediately without restarting) has fixed two missed save cases: saving files while /reload-plugins or session startup is reading module files, and saving again within milliseconds of the previous reload. Reload prompts allowed without an explicit selection no longer recur every turn. If an SDK host dismisses prompts before answering, the prompt appears up to three times rather than disabling hot reload for the entire session. Plugin options named constructor or prototype no longer continuously read default values and reload cleanly after edits. Plugins with large UI surfaces no longer cause another plugin to unload when a plugin hook worker stalls.

When enterprises route cloud model requests through a gateway, they can constrain wait times and model destinations.

In the input box, Ctrl+Shift+Tab, Cmd+Shift+Tab, and Alt+Shift+Tab no longer accidentally toggle permission modes, and Ctrl+Tab no longer unintentionally accepts suggested prompts. When two Claude windows are visible simultaneously, keyboard focus no longer jumps back and forth to send text to the wrong conversation.

BUGFIX

[Cloud sessions] Reconnection History Displays in Batches, Missing Responses After Unarchiving Fixed

Running long-running tasks or schedules in Cloud sessions brings noticeable improvements to reconnection and configuration.

An issue where sending messages immediately after unarchiving sometimes produced no response due to container (an isolated environment for running tasks) startup failures is resolved, and legacy routine schedules reliably load pre-saved prompts. When reconnecting after brief network drops, missed conversation history renders on screen as a single batch rather than slowly crawling line by line. The default height of the install script input field in cloud environment settings has been increased, expanding automatically with content while supporting manual drag-resizing.

Reviewing a missed broadcast recording previously required waiting for frames to catch up one by one, but missed activity now displays all at once.
BUGFIX

[Claude Tag] Slack Collaboration Card Expiration Extended, Channel Relays and Restarts Fixed

When collaborating with @Claude in Slack team channels, several adjustments have been made to confirmation cards and notifications.

Setting confirmation cards now remain active for 30 minutes, up from 10 minutes. Notifications for Enterprise Grid (Slack's enterprise plan for multiple workspaces) cross-workspace shared channels applying organization defaults now trigger at most once a month, only when someone mentions Claude. Forked thread continuation cards now render proper channel links and member mentions instead of raw Slack markup. The spinning indicator no longer persists after confirming an @Claude !restart, and @Claude mentions from other apps or bots are no longer dropped after a busy channel stops reading unmentioned messages. When adding channel managers moves members into Custom roles (custom permission roles) and potentially removes other permissions, admins are prompted for confirmation beforehand.

FEATURE

Self-Hosted Large Repository Fetches No Longer Abort, Code Review Lingering Issues Accurately Reported

When running tasks or automated code reviews in self-hosted enterprise environments, large projects previously encountered issues with timeout limits or oversized rules files.

An issue where large Git repository fetches aborted while the server was actively reporting progress has been resolved; the CLAUDE_RUNNER_FETCH_SERVER_PROGRESS_CAP_MS environment variable (configuration provided before starting a program) allows adjusting or disabling this timeout. The runner no longer passes CCR_AUTO_MODE_ALLOW, CCR_AUTO_MODE_ENVIRONMENT, or CCR_AUTO_MODE_SOFT_DENY into the session environment. During re-reviews where previously detected issues remain unresolved, review comments accurately report the remaining count rather than falsely claiming zero issues. An issue where code review skipped rules when a pull request modified a large CLAUDE.md project rules file has also been fixed.
