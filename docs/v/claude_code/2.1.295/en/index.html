Claude Code 2.1.295

Released: 2026-10-08

Release notes

FEATURE

Hooks Block Failed Actions and Close Shielding Gaps During Reloads

When you add custom hooks (small programs triggered by specific events), startup failures can now block actions.

Command and HTTP hooks support onFailure: "block", blocking subsequent actions if they fail to start, time out, or return an unexpected exit code. Deeply nested tool inputs are no longer truncated to bypass protections. During plugin hook worker restarts and module reloads, calls that previously bypassed another module's shielding hook with .catch are now rejected. Multi-line JSON printed by async hooks is parsed correctly, and cloud sessions no longer hang when a session.receive hook requests permissions upfront. If a tool execution is rejected by a plugin after running, both Claude and you are informed that the tool executed but its output was intercepted.

Like a building access system that used to miss a second checkpoint during reboots, such entry requests are now rejected.
BUGFIX

Plugin Marketplace Adds Install Warnings and Fixes Accidental Deletion

When managing extensions, silent configuration load failures can cause unexpected issues.

Running claude plugin install, enable, disable, or adding a marketplace now issues a warning if the target configuration file fails to load. Pressing Enter on the /plugin error tab no longer removes the marketplace and its plugins without confirmation. Adding a marketplace is rejected if its name cannot be used to install plugins; adding or refreshing marketplaces with large Git submodules now fetches only submodules containing plugin files. Submodules are separate repositories nested inside a repository. When claude plugin validate finds a README missing install instructions, it prints pasteable suggestions without affecting the exit code, even when using --strict. When a hook module is rejected due to top-level var rebinding, the error message indicates the line number, reason, and remediation.

Picture browsing an app store where pressing Enter used to delete the store and installed items; it now asks for confirmation first.
FEATURE

Richer Module UI Buttons with Upgraded Notification Priorities and Authoring Guidance

When building or using custom UI modules, layout and alerting options are now more flexible.

Modules can now deliver native desktop notifications via $.ui.notify respecting system preferences and clearly attributing the source. Button components support text child nodes, allowing labels or secondary details to be rendered within a single clickable button. Toast popups published by your organization are prioritized ahead of other modules. The built-in plugin authoring skill no longer prompts to run commands in sessions without a terminal and only explains sharing flows when asked. When Workflow (a workflow tool) rejects scriptPath, it prompts you to use script to pass inline scripts instead, which works in sessions without Read tools.

BUGFIX

Plugin Hot Reload Captures Missed Saves and Stops Repeated Confirmation Prompts

When modifying extension modules and inspecting changes in real time, missed file saves can leave you looking at outdated code.

Hot reload (applying code changes immediately without restarting) has fixed two missed save cases: saving files while /reload-plugins or session startup is reading module files, and saving again within milliseconds of the previous reload. Reload prompts allowed without an explicit selection no longer recur every turn. If an SDK host dismisses prompts before answering, the prompt appears up to three times rather than disabling hot reload for the entire session. Plugin options named constructor or prototype no longer continuously read default values and reload cleanly after edits. Plugins with large UI surfaces no longer cause another plugin to unload when a plugin hook worker stalls.

BUGFIX

Plugin Config Changes Strictly Inspected and Prompt History Cleared of Invalid Entries

When managing session settings or rewriting inputs via plugins, configs and histories should reflect plugin decisions.

Using /model, /fast, /output-style, or toggling auto-update channels in /config now consults config.set hooks (small programs triggered by specific events) before persisting settings. After a prompt.submit hook rewrites or discards input, prompt history and session pending prompt logs no longer retain the original input prior to rewriting or discarding. claude plugin test no longer erroneously passes session.append hooks that strip tool calls, tool results, or thinking blocks, which are preserved in real sessions. Headless -p and SDK sessions no longer write generated type definitions to the --plugin-dir folder, writing only to the module location under active development. An issue where hook module code nested thousands of levels deep failed loading or validation with only a stack overflow error has also been fixed.

BUGFIX

Windows Plugin Loading and Install Records Fixed Along with Cache Misclassification

When using plugins on Windows or across multiple connection environments, path and governance misclassifications can arise.

An issue where VS Code on Windows failed to load project-scoped plugins due to drive letter casing mismatches has been fixed. Windows operations with plugin install and uninstall in project or local scopes no longer drop install records or add duplicates because of C: versus c: differences. In long-running sessions, hooks no longer falsely report "Plugin directory does not exist" after another session syncs claude.ai plugin updates. On machines where managed configurations list or enable plugins, a bug where a tampered server-managed config cache misclassified personal plugins as organization-managed plugins has also been resolved.

FEATURE

Enterprise Gateway Adds Streaming Timeouts and Restricts Fallback Forwarding by Model List

When enterprises route cloud model requests through a gateway, they can constrain wait times and model destinations.

timeouts.upstream_ttfb_ms configures the time-to-first-byte waiting threshold in milliseconds for upstreams like Bedrock, Vertex, and Foundry, switching to fallbacks or returning a 502 on timeout. Each upstream can define a models list to route only listed models, which also constrains fallback routing; a single * in each entry acts as a wildcard. When Amazon Bedrock is located outside AWS US regions, model requests not listed under models: were previously rejected by AWS; the gateway now tries your own region and, if still rejected, identifies which model needs to be added. Background requests prioritize Haiku 4.5, falling back to the session's original model only when the gateway does not provide it.

Think of a logistics center that used to overlook cargo manifests when switching to backup routes; line changes must now dispatch strictly according to the manifest.
FEATURE

Enterprise Gateway Enforces Login Redirection and Links Audit Logs to Cloud Requests

Enterprises needing centralized governance over employee login channels and usage trails can configure login destinations and correlate request logs.

Machines without managed configurations can add forceLoginMethod: "gateway" and forceLoginGatewayUrl in user settings to direct /login to the designated gateway. Model inference audit logs now include upstream_request_id, and successful response headers append request-id to facilitate cross-referencing between cloud upstreams, gateway logs, and Claude Code telemetry. When a machine has OpenTelemetry (a standard for collecting monitoring data) configured or a session is logged into the gateway, login authentication events are properly exported. If the gateway encounters desktop policy keys not yet recognized by the bundled Claude Desktop schema, it starts with a warning and serves the configuration without requiring a gateway upgrade for new desktop settings.

BUGFIX

Enterprise Gateway Adopts AWS CountTokens and Fixes Spend Limits and Fable Menus

When administrators review gateway usage, sessions moved out of a group no longer retain stale groups or spend limits.

The Amazon Bedrock gateway now uses the AWS CountTokens API to calculate tokens (text units used for AI processing and billing) instead of requesting a single token from the model, serving /context and large file reads; this requires granting bedrock:CountTokens permissions. When the PostgreSQL database enters a read-only state, warnings are logged every 30 seconds detailing failed operations and remediation steps. CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC no longer hides gateway spend limits from /usage and the status line, and spend limit requests are routed to the gateway logged into by the current session. For sessions logged into a gateway, Fable models in availableModels are now displayed in the /model menu, replacing modelPicker rows with built-in rows for the same model.

FEATURE

Core Tool Parameter Parsing Loosened and Restricted Modes Strictly Controlled

When having AI execute commands or read files, minor parameter differences no longer break tool invocations.

Bash (a tool for running terminal commands) no longer fails when receiving command_description instead of description; Read treats an empty pages parameter as unset. Grep searches now support appending -l, -c, and -r flags without causing call failures. Restrictions from --tools and --restricted apply to built-in tools registered after startup, and deprecated tool names no longer bypass caller toolsets. Bash permission checks for wildcard loops have been fixed. When feature flags (switches controlling whether features are enabled) cannot be retrieved, Claude 3 Opus and Claude 3.x Sonnet sessions are no longer offered tool searches they would otherwise reject.

FEATURE

Smart Fallback for 1-Million Context Requests and Accurate File Change Detection

Communication between the system and models is more resilient when handling massive codebases or very long contexts.

When using models tagged with 1-million context ([1m]), if the cloud platform rejects the test flag, the system automatically removes the flag and resends the request so the entire batch does not immediately fail. For file reading and writing, editor tools no longer assume a file has been read in its entirety if the modified timestamp remains unchanged despite content updates, or if a terminal command produces no output. When large file uploads fail without a specified reason, the explanation given to Claude is improved, reporting failure rather than shrinking the file. Issues where web searches and agent hooks (small programs triggered by specific events) took excessively long to evaluate under xhigh and max thinking efforts have been fixed.

FEATURE

Backoff Reconnection for External Tools and Recovery from Extended Disconnects

Connecting to remote tools in headless mode (an execution mode without a terminal window) or SDK integrations no longer remains permanently offline after a disconnection.

An issue where remote MCP (a protocol connecting AI to external tools) servers failed to reconnect after disconnecting for over 15 seconds has been fixed. When connections drop repeatedly right after connecting, reconnection intervals now back off progressively up to 30 seconds. Server error responses containing network error names no longer mistakenly terminate connections, and duplicate pagination cursors no longer fetch the same page repeatedly. Pressing interrupt while awaiting resource lists now terminates the turn without waiting for timeouts. WebSocket transports receiving messages over 16 MiB now skip parsing and close the connection, matching limits on other transports.

Dialing a customer service hotline now spaces out retries instead of rushing to redial whenever a call drops right after connecting.
FEATURE

Precise File Type Detection for External Tools and Expanded Tool Description Limits

File formats are now preserved correctly when returning code, style, or icon files through external tools.

Previously, CSS, JavaScript, and XML returned by MCP (a protocol connecting AI to external tools) tools were often saved as .bin, causing Read to reject them; now these files as well as fonts and icons receive matching extensions. The description limit loaded by tool search has been expanded from 2,048 to 16,384 characters. Background Bash results in claude mcp serve now state the output filename, and tool descriptions have been corrected to remove promises of notifications that never arrive. In installations that do not fetch feature flags, the claude.ai connector negotiates MCP protocol version 2026-07-28 by default. Feature flags are switches controlling whether capabilities are enabled, and you can opt out of this negotiation change using MCP_PROTOCOL_NEGOTIATION=legacy.

BUGFIX

Transparent Background Task Status for MCP Tools and Reduced Prompts in Non-Interactive Mode

Synchronization of task activity is clearer when running long-running MCP (a protocol connecting AI to external tools) tool calls in the background.

If you manually abort a running MCP tool from the task popover or connected client, Claude learns that the tool has stopped. System notifications displayed when tools move to the background now show the full task ID for easy identification. In automated, unattended non-interactive sessions, unnecessary authentication prompts no longer appear when tasks do not require specific MCP servers. In headless mode (an execution mode without a terminal window) and SDK sessions, delayed logins or reconnections no longer mistakenly list MCP servers configured via setMcpServers() as user-provided servers.

BUGFIX

Fixed Subagent Work Environments, Message Passing, and Skill Preloading

When subagents (AI assistants running subtasks in parallel) work in separate worktrees, they no longer mix in Git branches, status, and recent commits from the primary session.

A worktree is a parallel copy of the same project. Workflow subagent skill results now return to callers, and initial SendMessage calls between peer agents no longer fail due to unloaded tools. When resuming a terminated session for a second time, Claude is also reminded to use SendMessage to resume background subagents. Custom agents named worker no longer mistakenly appear as "Agent" in auto-mode rejection notices and task detail activity lists. When the Skill tool finishes before the response stream ends, allowed-tools and effort are no longer lost; these fields specify allowed tools and thinking effort, preventing -p Bash commands from being rejected. Subagents preload up to 32 skills once each from skills, and can still invoke remaining skills when the Skill tool is available.

FEATURE

Distinct Background Task Cancellation Actions and Clear Cleanup Notices on Service Stop

When pressing ← to background work while waiting for tools to finish, stopping versus continuing work now yields distinct outcomes.

Stopping a turn displays "Backgrounding cancelled", while typing input cancels backgrounding and lets Claude continue in the foreground. CLAUDE_AUTO_BACKGROUND_TASKS no longer eagerly backgrounds tasks when edits or commands remain queued behind a subagent, preventing subsequent calls from starting prematurely. On macOS or Linux without installed services, when claude agents stops alongside the background service, active sessions stop after roughly one minute with a notification; running claude agents again during this window prevents the shutdown. Exiting both no longer inadvertently starts a new service, which previously delayed shutdown or restarted interrupted sessions. Resuming also no longer mistakenly informs Claude that incomplete background workflows may be stopped by TaskStop.

FEATURE

Distinct Shortcuts for Loop Scheduling and Max Wait Times for Unattended Retries

When using /loop for scheduled checks, disconnecting from the session and stopping the loop are separate actions.

In a connected background session, pressing Ctrl+C twice at an idle prompt only disconnects the client while preserving pending wakeups; pressing Esc stops the loop and notifies you of cancelled wakeups. An issue where Esc could not stop self-paced /loop tasks moved to the background with ← has been fixed. If the next wakeup expires while the process is stopped, the loop terminates; sessions now display a notification and Claude is informed. Unattended retry mode CLAUDE_CODE_RETRY_WATCHDOG can use the CLAUDE_CODE_RETRY_WATCHDOG_MAX_WAIT_MS environment variable (configuration provided before starting a program) to cap maximum wait milliseconds upon encountering 429 rate limits or 529 server overloads.

BUGFIX

Strict Dialogue Rewind History Sync and Accurate Restoration of Variables and Schedules

Prompts are no longer lost and stopped tasks are not accidentally restarted when using /rewind to rewind conversations or branch into new topics.

Prompts submitted after rewinding are preserved when sessions move to the background or resume after termination, and deleted turns no longer reappear. Stopped schedules no longer restart upon resuming after a rewind, and an issue where schedules were lost when resuming after conversation compaction followed by Esc or rewind has been fixed. Using ↑ or Esc immediately after pressing ← to pull a pending message back into the input box preserves it in prompt history. After running /resume or /branch, variables written to the CLAUDE_ENV_FILE environment file by SessionStart hooks (small programs triggered on session start) are passed to the Bash tool. Unchanged async startup hook context is also no longer repeatedly added to the conversation across resumes.

FEATURE

Terminal Support for Status Protocols and Cleaner Pipeline Output and Text Copying

Status and responses are no longer missed when interacting with Claude or piping output to other programs.

Terminals supporting the application status protocol OSC 7501 can display in tabs or status lines whether Claude is working, awaiting input, or finished. /copy allows selecting blockquote text, copying it without >. Bold text directly following dim text in pipelines (passing output to another program) is no longer rendered dim. Commands and hooks in background sessions no longer inherit FORCE_COLOR=3, preventing Claude from reading ANSI color escape codes. When claude -p opens new turns due to background tasks, each turn's response prints when the turn ends, preventing earlier responses from being lost. When remaining open after the final turn ends, explanations of what is being awaited only print if standard error stderr is connected to a terminal.

BUGFIX

Fixed Terminal Cursor Positioning, Safer Links, and Improved Interface Interactions

Cursor and link displays no longer mislead you when typing, pasting special characters, or clicking hyperlinks in the terminal.

Pasting text with accented characters from the macOS clipboard into the middle of the prompt no longer moves the cursor an extra cell. In vim (a mode for editing text using keyboard commands), ~ no longer advances the cursor past the end of the line to break subsequent x delete commands, and 3~ no longer spans across to the next line. Raw terminal hyperlink bytes in responses or peer agent messages are no longer rendered as clickable links with hidden URLs, and plaintext URLs are no longer obscured by lingering colors or hidden styling, including table line wraps and question previews. The Max thinking effort in /model is properly labeled as applying only to the current session. Silent exits or raw system errors when /tui fails to restart Claude Code have also been fixed.

BUGFIX

Terminal Freezes on Ultra-Long Responses Fixed, Syntax Highlighting and Layout Alignment Corrected

When Claude generated tens of thousands of lines of output or progressively deepening nested blockquotes, the terminal could become completely unresponsive.

Freezes caused by tens of thousands of lines of output, Ctrl+C failures, and multi-second pauses with gigabytes of memory usage from blockquotes deepening every few lines have been fixed. Syntax highlighting (using colors to distinguish code) stalling for seconds to minutes on ultra-long lines, large blocks of consecutive blank lines, unclosed strings, or heredocs is also fixed; a heredoc is a syntax for defining multi-line text blocks. Text containing tabs or bidirectional control characters is no longer clipped at screen edges or overlapping adjacent lines. Tab stops are now calculated from the start of the text, and short outputs with Windows CRLF line endings are no longer collapsed into a single line.

When typesetting, extra-long manuscripts or increasingly deep blockquotes used to stall the layout engine, but these hang scenarios are now resolved.
BUGFIX

Remote Control File Transfer Limits Relaxed, macOS Privacy Prompt False Triggers Fixed

When using Remote Control to manage sessions from other devices or running background tasks on macOS, unexpected rejections and permission prompts could occur.

An issue where sending more than 256 files at once remotely was rejected with 'could not be vouched for' has been fixed. False warnings reporting that push notifications were not sent when claude remote-control just received a mobile message, had not used the /config toggle, or was started from inside Claude Code are now resolved. When Remote Control, claude.ai, and desktop interfaces await permission confirmation, they display the MCP tool's server and human-readable name instead of internal identifiers. File counting when launched in the macOS home directory or any directory above it no longer triggers false data access prompts for other applications. Background sessions restarted alongside updates no longer occasionally fall outside the stable application bundle and re-trigger folder permission prompts.

BUGFIX

Chrome URL Rule Protections Fixed, Auto-Mode Switching and Cache Cleanup Improved

Several unexpected behaviors when configuring URL block rules, Auto-Mode, or performing disk cleanup have been resolved.

The Chrome extension's host:80 blocking rule now correctly applies to standard HTTP pages on that host. After removing disableAutoMode, desktop and SDK programmatic integrations can switch back to Auto-Mode without restarting. Temporary files left in ~/.claude/seed-admin after interrupted /ultrareview uploads are now removed by retention-based cleanup. When an advisor model saved by /advisor is no longer available, the panel opens to 'No advisor', and occasional startup failures loading managed settings after login refreshes are fixed. The rate_limit_event warning in headless mode (an execution mode without a terminal window) clarifies whether the account has additional usage enabled.

FEATURE

Artifact Background Clarity Improved, Permission Confirmations Streamlined Without Telemetry

Viewing interactive Artifacts (standalone web pages or previews of generated programs) generated by Claude offers a smoother visual and operational experience.

Artifact pages without custom background colors now render on a pure white background instead of the previous grayish off-white. In environments with diagnostic telemetry disabled, Artifact tool permission prompts are streamlined to the same five core questions as standard setups, avoiding repetitive interruptions when reading others' artifacts or modifying data. Scheduled and Run now routine jobs in telemetry-disabled installations can now publish new private artifacts or update your own artifacts without prompting.

BUGFIX

[VSCode] Click-to-Open Files in Chat Supported, Forked Sessions and Shortcuts Fixed

When collaborating with Claude in VS Code, file navigation and multi-window switching no longer interfere with each other.

Files sent by Claude are listed on dedicated lines in the chat; clicking a filename opens it in the editor with a description beneath it, remaining visible in focused views. An issue where using 'Fork conversation from here' or rewind failed to restore after background agent activity or the panel's own status bar, returning 'Message not found in session', has been resolved. In the input box, Ctrl+Shift+Tab, Cmd+Shift+Tab, and Alt+Shift+Tab no longer accidentally toggle permission modes, and Ctrl+Tab no longer unintentionally accepts suggested prompts. When two Claude windows are visible simultaneously, keyboard focus no longer jumps back and forth to send text to the wrong conversation.

BUGFIX

[Cloud sessions] Reconnection History Displays in Batches, Missing Responses After Unarchiving Fixed

Running long-running tasks or schedules in Cloud sessions brings noticeable improvements to reconnection and configuration.

An issue where sending messages immediately after unarchiving sometimes produced no response due to container (an isolated environment for running tasks) startup failures is resolved, and legacy routine schedules reliably load pre-saved prompts. When reconnecting after brief network drops, missed conversation history renders on screen as a single batch rather than slowly crawling line by line. The default height of the install script input field in cloud environment settings has been increased, expanding automatically with content while supporting manual drag-resizing.

Reviewing a missed broadcast recording previously required waiting for frames to catch up one by one, but missed activity now displays all at once.
BUGFIX

[Claude Tag] Slack Collaboration Card Expiration Extended, Channel Relays and Restarts Fixed

When collaborating with @Claude in Slack team channels, several adjustments have been made to confirmation cards and notifications.

Setting confirmation cards now remain active for 30 minutes, up from 10 minutes. Notifications for Enterprise Grid (Slack's enterprise plan for multiple workspaces) cross-workspace shared channels applying organization defaults now trigger at most once a month, only when someone mentions Claude. Forked thread continuation cards now render proper channel links and member mentions instead of raw Slack markup. The spinning indicator no longer persists after confirming an @Claude !restart, and @Claude mentions from other apps or bots are no longer dropped after a busy channel stops reading unmentioned messages. When adding channel managers moves members into Custom roles (custom permission roles) and potentially removes other permissions, admins are prompted for confirmation beforehand.

FEATURE

Self-Hosted Large Repository Fetches No Longer Abort, Code Review Lingering Issues Accurately Reported

When running tasks or automated code reviews in self-hosted enterprise environments, large projects previously encountered issues with timeout limits or oversized rules files.

An issue where large Git repository fetches aborted while the server was actively reporting progress has been resolved; the CLAUDE_RUNNER_FETCH_SERVER_PROGRESS_CAP_MS environment variable (configuration provided before starting a program) allows adjusting or disabling this timeout. The runner no longer passes CCR_AUTO_MODE_ALLOW, CCR_AUTO_MODE_ENVIRONMENT, or CCR_AUTO_MODE_SOFT_DENY into the session environment. During re-reviews where previously detected issues remain unresolved, review comments accurately report the remaining count rather than falsely claiming zero issues. An issue where code review skipped rules when a pull request modified a large CLAUDE.md project rules file has also been fixed.
