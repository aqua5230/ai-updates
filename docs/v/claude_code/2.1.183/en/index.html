Claude Code 2.1.183

Released: 2026-06-19

Release notes

FEATURE

Auto mode gets safety nets against destructive commands

Claude will no longer execute destructive Git commands unless you explicitly ask it to discard your local work.

The system will now actively block destructive Git commands (like git reset --hard and git clean -fd that irreversibly delete files). It also refuses to run git commit --amend unless the agent itself made that specific commit during the current session. For infrastructure-as-code tools like Terraform or Pulumi, running a destroy command is now strictly forbidden unless you specifically name the target stack. Additionally, scheduled tasks and Webhook triggers used to be incorrectly interpreted as your keyboard inputs, sometimes accidentally 'approving' an AI action on your behalf; this dangerous loophole has been firmly closed. It's like putting a safety guard on a lawnmower: unless you explicitly flip the switch and point at a specific patch of dirt, it absolutely refuses to shred your prized rose bushes, and a stray bird landing on the handle can no longer accidentally start the engine.

BUGFIX

Agent teams are tougher, and search/output glitches are gone

Team-based AI collaboration just got a lot more dependable.

Previously, spawning a teammate in a tmux pane (a terminal multiplexer) could fail if your shell initialization was slow, and keystrokes you typed on the main screen would bizarrely leak into the new teammate's window; these chaotic overlaps are now fixed. Also, if a teammate dispatched a background task to a subagent, that task used to be ruthlessly killed the moment the teammate finished its turn—now it survives to completion. On the cognitive side, subagents using WebSearch no longer return totally blank results, and if the AI spins its wheels generating a "thinking block" but fails to produce actual visible output, it won't just silently give up anymore—it will re-prompt the model once to produce visible output. Finally, we squashed the annoying 400 Extra inputs are not permitted errors that plagued subagent spawns on certain configurations. It's like a busy factory floor: previously, a slow-booting new robot would jam the assembly line, and any chore handed to an intern was immediately thrown in the trash the moment their manager clocked out for the day. Now, handoffs are flawless, and the interns faithfully finish their tasks even after their boss goes home.

BUGFIX

Settings and UI cleaned up, squash screen-corrupting bugs

The interface is now noticeably cleaner and more intuitive.

The settings menu (/config) makes sense now: you can hit Enter or Space to toggle switches, and pressing Esc actually saves and closes instead of reverting all your changes. You can also run /config --help to easily look up shorthand keys. We've scrubbed the constant 'setup issues' nag from the startup logo; if you want a system health check, just run /doctor. You'll now get clear warnings if you request a deprecated model or one that automatically updates to a newer version. We also squashed a ton of screen-corrupting bugs: the total UI meltdown (merged text and duplicated spinners) in Windows Terminal under heavy subagent loads is fixed, your cursor won't get stranded above the prompt in vim mode anymore, the noisy 'PostToolUse' timing lines cluttering focus mode are gone, and user-level skills won't infinitely duplicate themselves in your autocomplete list. Finally, headless environments (running without a screen) will no longer crash by exposing fake auth-stub tools to the AI when an MCP server demands authentication. It's like thoroughly decluttering your workstation: broken buttons now work predictably, phantom alarms have been silenced, and the flickering monitor that scrambled your spreadsheets has finally been replaced, leaving you with a distraction-free space.
