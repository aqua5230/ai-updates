對話分身自動掛名，跑腿小幫手分家

你請 Claude 改報告磨了半小時，它摸熟你的想法了，這時又想順便生一版簡報。插話問，討論會變大雜燴；開新對話，它又什麼都不記得，得重講半小時。這正是打「/fork」的時刻（原意是叉子，因為它像樹枝分岔，從目前對話分出一條新枝）。打下去，Claude 把聊到現在的內容整份複製給分身，成為獨立的「背景工作階段」（background session，丟到背景自己繼續跑、不用你盯著），帶著全部記憶去做簡報；你留在原地改報告。分身就像交出去的外送單：在「claude agents」清單自成一列，沒取名字就自動拿你交代的那句話當名字，一眼認出誰是誰。「查一下這個詞」這種要等答案才能繼續的小事，交給「/subtask」（子任務）。它是原本「/fork」順便叫出的內建子代理（subagent），這次分了家——就像外送平台把「叫外送」跟「請店內夥計跑腿」分成兩顆按鈕，你再也不會按錯。

刪掉的對話找得回來，分身做完會回報

派出去的分身，現在更難搞丟、也更會回報。昨天手滑刪掉的對話，今天又想接著用？在代理畫面輸入「/resume」（恢復），過去的工作階段都會列出來讓你挑——連從清單手動刪掉的都找得回來，選了就丟回背景接著跑，像取消的外送單還能重新派送。兩個會讓分身出狀況的毛病修好了：以前分身碰上寫入失敗，會失去跟主線對話的保護；剛停掉的分身重開，偶爾也不吭聲就失敗——現在重開要嘛直接成功，要嘛講清楚原因、讓你強制重開。你中途點開一個還在開機的分身，也不再對著空白畫面乾等，會先看到整理好的對話紀錄。分身做完事而你正閒著時，左下角提示字會跳「N done」（N 件完成）閃一下提醒你。就像每位外送員送達都會回報，你不用一直開門張望。

auto-mode 加裝煞車，失控前先喊停

你是否曾遇過自動模式（auto-mode）失控？當 Claude 陷入瘋狂搜尋或無限開啟子代理（subagent）的迴圈時，荷包可能瞬間大失血。現在系統加裝了跳電保護。單一工作階段（session）的網頁搜尋與子代理數量預設限制在 200 次，一旦超標就強制中斷，打「/clear」可重新計數。如果遇上運行超過 2 分鐘的 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）指令，也會自動移到背景執行，不讓畫面卡死。若要回復乾淨的預設值，這正是你輸入「claude auto-mode reset」的時刻，系統會先詢問確認，加上「--yes」就能直接跳過。像家裡裝了無熔絲開關，一個插座短路只會跳開它，不會燒毀整棟房子。

危險指令與掛鉤失效的漏洞補齊

把鑰匙交給管家，最怕他擅自開鎖或把外人帶進家門。以前在規劃模式下，像 touch 或 rm 這種修改檔案的危險指令有時會沒問你就自己跑掉，現在已被牢牢鎖上。當你建立工作樹（worktree，Git 讓同一專案平行開多份副本的功能）時，以前會跟著連結亂跑。現在若專案藏了指向外部的符號連結（symlink，指向另一位置的捷徑檔），系統會直接擋住，防止檔案被寫到專案外。此外，當掛鉤（hook，特定事件被觸發的小程式）要求中斷時，即使工具失敗也不會再漏掉指令。甚至在收到終端終止訊號時，系統也會把背景子行程清乾淨。像保全系統補上了沒鎖好的後門，該阻擋的動作這次真的擋得住。

「/ultrareview」四個卡關一次修掉

想要進行程式碼審查，卻發現指令老是聽不懂你的意思？這次「/ultrareview」一口氣修復了四個讓你卡關的地方。以前你輸入「#123」或貼上 PR 連結時，系統常常認不出來直接報錯，現在各種寫法都吃得下去。當你指定只存在於遠端的分支時，系統也會主動去 origin 抓取，打錯字還會幫你猜最接近的名字。在「/clear」後重開的工作階段（session，工作階段為原定譯法）中，原本會被跳過的計費確認現已補回。而在桌面版應用程式遇到非 Git 儲存庫錯誤時，提示也會改為引導你切換資料夾。就像客服專線終於聽懂你的話，不再轉錯部門或忘記收費。

終端機操作卡頓與跑版修好了

當你在終端機裡手忙腳亂地輸入指令，卻常碰上畫面卡頓或文字折行跑版？這批修正專門治這些介面上的小疙瘩。在 Windows 上被原則擋住 PowerShell 5.1 時，後台守護行程（daemon）現改用第七版啟動。用「!」在 shell 模式輸入含路徑的指令時，不會再因為自動完成選單開著而失效。在代理畫面按 Ctrl+J 也終於能正常換行。此外，像是計畫核准對話框提示被長路徑擠爛、全螢幕縮放時歡迎畫面沒跟著變寬，以及窄版 diff 畫面行號消失等排版問題，也全部調整完畢。就像幫家裡卡卡的門鎖上了油，開關終於順了。

幾種讓工作階段開不起來的毛病修好了

你正在處理緊急任務，工作階段卻無預警卡死在啟動畫面？這些阻礙對話開機的疑難雜症已經被清除了。如果你的專案設定了特殊的傳輸安全性憑證（如 mTLS 或額外的 CA 憑證包），雲端代管工作階段現在會忽略這些設定並跳出警告，但保證讓你順利開機。以前如果先讀取了檔案的局部內容，在恢復工作階段（session，工作階段為原定譯法）時若編輯該檔會被誤判而擋下，這問題已修好。另外，使用繼續參數重啟後若呼叫 ExitWorktree 也會正常執行。就像大樓保全認識了更多款門禁卡，不再因為格式不同就把你鎖在門外。

遙測回報與搜尋擷取的可靠度修好了

你在背景傳送監控指標或抓取網頁資料時，是否常被斷斷續續的網路錯誤打斷？這批修正提高了遙測與搜尋的可靠度。當 OpenTelemetry 匯出遇到不吃分段傳輸的 Azure 監控伺服器時，現改用傳統相容模式發送，避免被 411 拒絕。在無頭模式（headless，沒有終端機視窗／視覺介面的執行模式）下若設定了 TRACEPARENT，事件紀錄也不會再漏掉追蹤編號。而當網頁搜尋工具因流量過大回傳 API 錯誤或遭遇限流時，系統會自動在背景以漸進拉長等待的方式重試。就像客服學會分清答錄機和忙線音，遇到忙線會等一下再撥，不再直接放棄。

換模型與傳訊更即時，講話變輕量

呼叫 AI 總是花大把冤枉錢，而且中途換模型還要等下一輪才生效？這批更新讓傳送指令更即時且省錢。現在提示詞快取（prompt caching，把重複提問暫存以節省成本的功能）在 Bedrock 或自訂代理端點也終於支援了。當多個代理互相對話時，訊息本體不會在歷史紀錄中重複塞兩次，節省你的 token（AI 處理與計費的文字單位）花費。在無頭模式下，當你想切換模型，這正是打「set_model」的時刻，指令會直接在下個往返當下生效。像外送軟體分清「正在送餐」與「等你確認付款」，狀態會顯示「需要輸入」，再也不會讓你乾等。

介面用詞與規則微調收尾

你想回頭查看先前的旁支對話，卻發現面板早就關掉了？這次更新針對介面用詞和核心規則進行了微調。現在，當你想要回頭翻看之前的問答時，這正是打「/btw」的時刻，它會直接幫你重開最近一次的側邊提問面板。此外，子代理預設將直接繼承主工作階段（session，工作階段為原定譯法）的權限設定。企業版的強登入限制也同步延伸至 VS Code 插件與 SDK 等各個角落。而 tmux 在舊版本下不支援同步輸出的說明也已更正。就像把說明書上印反的按鈕名稱重新校正，使用時才不會一頭霧水。

連線疑難雜症再修一輪

當你建立起複雜的多代理合作小隊，卻常在連線中途遭遇各種斷線或顯示空白？這批修復清理了剩餘的連線頑疾。在遠端控制（Remote Control）中途加入的客戶端，不會再看到空空如也的畫面。在串流（streaming）模式下重啟工作階段時，控制請求也不再無故消失。同時，代理小隊重新初始化時，正在關閉的隊友也不會向隊長重複發送空閒狀態。此外，修復了局部讀取後 @ 提及失效，以及退出代碼 143 造成逾時誤判等問題。就像大樓的許多零星小故障，技師一次巡完徹底解決。

Conversation copies name themselves, and the helper gets its own lane

You have spent half an hour revising a report with Claude, and it now understands your thinking. Then you want it to make a slide deck too. Ask in the same conversation and the discussion becomes a jumble; start a new one and Claude remembers nothing, so you must explain it all again for half an hour. That is when to use /fork: named after a fork in a tree, it branches off from the current conversation. Run it and Claude gives a copy everything discussed so far as an independent background session, which makes the slide deck with all that context while you keep revising the report. The copy is like a delivery order you hand off: it gets its own row in claude agents, and if unnamed, takes your prompt as its name so you can tell them apart. For a small job such as “look up this term,” where you need the answer before continuing, use /subtask. It is the built-in subagent that /fork used to launch along the way, but they now have separate homes—like a delivery app splitting “order delivery” and “ask the shop assistant to run an errand” into two buttons, so you no longer press the wrong one.

Deleted sessions can come back, and copies report when they're done

The copy you sent out is now harder to lose and better at reporting back. Did you accidentally delete a conversation yesterday and want to continue it today? Type /resume in the agent view and you can choose from past sessions — including ones manually removed from the list — then send it back to the background to keep running, like re-dispatching a cancelled delivery order. Two bugs that could disrupt a copy are fixed: after a state write failure, it used to lose its protection tied to the parent conversation; reopening a just-stopped copy also sometimes failed without a word. Now reopening either succeeds or explains why it cannot and lets you force a restart. Open a copy that is still booting and, instead of staring at a blank screen, you first see the formatted transcript. When a copy finishes while you have nothing to answer, the footer briefly pulses N done to alert you. Like every courier reporting a delivery, you no longer need to keep watching the door.

Auto-mode gets brakes that stop runaway loops before they spiral

Have you ever watched auto-mode run wild? When Claude spirals into endless searches or subagent loops, your budget can vanish instantly. Now there is a breaker in place. A session is capped at 200 WebSearch calls and 200 subagent spawns by default, with /clear resetting the counter. Any MCP (Model Context Protocol) call running past 2 minutes automatically moves to the background so your window does not freeze. If you want to wipe the slate clean, that is when to run claude auto-mode reset (adding --yes skips the confirmation prompt). It is like adding a surge protector to your home—a single faulty plug trips the switch instead of burning down the house.

Holes that let risky commands slip through without asking are patched

Handing your keys to a helper is risky if they unlock doors without asking. Under plan mode, file-modifying commands like touch or rm sometimes ran without permission; they are now locked down. When you create a worktree (Git's feature for parallel copies), Claude will no longer write files outside your folder by following a symlink (a shortcut file pointing elsewhere). In addition, when a hook (a script triggered by events) requests a halt, infrastructure errors will no longer swallow the command. Even if a process receives SIGTERM, the CLI kills the whole process tree. It is like a security system patching unlocked back doors—what should be blocked actually is.

Four `/ultrareview` snags fixed in one pass

Need a code review but the command keeps failing to understand you? Four /ultrareview snags are now fixed in one go. It now accepts #123, PR 123, or a full PR link instead of throwing errors. Specifying a remote-only branch automatically triggers a fetch from origin, and typos will get suggestions for the closest match. In a fresh session after /clear, the billing confirmation is no longer skipped. Finally, if you run into repository errors on Claude Desktop, the app will guide you to switch folders. It is like a customer hotline that stopped dropping calls, transferring you to the wrong desk, or forgetting to bill you.

Terminal input glitches and layout jank are fixed

Are terminal glitches and broken layouts slowing down your typing? This batch smooths out those interface friction points. On Windows, if policies block PowerShell 5.1, the daemon prefers PowerShell 7. In shell mode (!), path autocomplete will no longer freeze commands containing file paths. Keyboards with extended reporting can now use Ctrl+J for newlines correctly. Layout bugs like truncated text in the approval dialog, static panels on window resizing, and missing markers in narrow diff views are all patched. It is like oiling a few sticky door locks—everything finally moves smoothly.

A few reasons sessions failed to start are fixed

Are you rushing a task only to have your session freeze right at startup? A few bugs preventing conversations from launching are now gone. Cloud-managed sessions that used to crash due to project certs like mTLS or custom CA bundles will now ignore those settings with a warning and start anyway. We fixed an error where editing a file previously read in chunks would block you on resuming. Also, calling ExitWorktree after picking up a session with resume parameters works fine now. It is like building security learning to accept different ID card styles instead of locking you out.

Telemetry export and web search reliability fixed

Do network drops and fetch errors interrupt your metrics exports and web searches? We have hardened telemetry and web tools. OpenTelemetry HTTP exports to Azure Monitor will use compatible settings to avoid chunked transfer rejections. Under headless mode (running without terminal windows), OTLP logs will not lose trace IDs when TRACEPARENT is set. If web search hits an overloaded server or rate limits, the tool now retries with backoff instead of giving up with an API error text. It is like an agent waiting for a line to clear and calling back later, instead of reporting a busy signal as the final answer.

Lighter inter-agent talk and faster mid-turn model swaps

Are you spending too much on AI tokens, or waiting until the next turn just to switch models? We have made communications faster and lighter. Prompt caching (saving past prompts to reduce costs) now works across gateways like Bedrock or custom base URLs. In multi-agent systems, messages are no longer duplicated in histories, saving your token budget. Under headless mode, when you need to swap models, that is when to send a set_model request, which changes the model on the spot instead of waiting for the next turn. It is like a delivery app distinguishing between "out for delivery" and "waiting for approval," so you are never left guessing.

UI wording and rule adjustments

Did you close your side-question panel only to realize you still need the answers? This batch polishes the UI text and permissions. When you want to review previous side discussions, that is when to type /btw, which reopens your most recent exchange on the side panel. In addition, subagents now inherit the parent session's permissions directly. Enterprise sign-in rules now apply to VS Code extensions and the SDK, not just the terminal. A tmux sync warning was also corrected. It is like correcting a typo in a device manual—getting the details straight ensures a smooth setup.

Another round of connection and syncing fixes

Are remote controllers and teammates losing connection or showing blank grids mid-run? We have cleared a batch of connectivity bugs. Remote Control clients joining a running session will no longer see an empty workflow grid. In streaming mode, restarting a session won't drop control requests that were prematurely marked complete. Teammate agents won't spam leaders with duplicate idle alerts when teams are initialized again. Small bugs like failing @-mentions after offset reads and exit code 143 timeout alerts are also resolved. It is like a technician fixing scattered minor bugs in a building all at once.
