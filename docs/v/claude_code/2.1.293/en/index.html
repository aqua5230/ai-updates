Claude Code 2.1.293

Released: 2026-10-07

Release notes

FEATURE

Claude Haiku 5.5 Launches with Million-Token Context and New Pricing

When you need to process large volumes of text quickly, the default lightweight model in the official API gets an upgrade.

The new claude-haiku-5-5 offers a 1M context window (the amount of text the model can hold in a single pass). Input and output cost $0.10 and $0.50 per million tokens (the units of text the AI processes and bills by), while prompts over 100K are billed at $0.50 and $2.50.

Think of a small delivery truck whose cargo bed can hold a million units of data, and billing depends on how much you load in: once a prompt exceeds a hundred thousand units, a different set of input and output rates applies.
BUGFIX

Agent List Display Stabilized, Authorization and Names No Longer Distorted

When running multiple background sessions, the agent list and bottom-bar information now correctly reflect the current state.

Previously, when the system briefly couldn't read the session folder (for example, because too many files were open), the agent count in the bottom bar would vanish and the list would be wiped out by placeholders. Now read errors no longer scramble the interface. Custom agents named worker are no longer mislabeled as Agent at startup, and the detail dialog title keeps the original type after they finish. claude agents previously offered an option to skip permission checks, but if the consent existed only in .claude/settings.local.json or a --settings file, background sessions would ignore that option; now consent is asked for first, and sessions that still ignore the option keep showing a short notice.

Picture checking a field staff schedule board: previously a stuck folder would make a whole row of names disappear and print the wrong badge; now name tags stay correct, and permission changes get a clearly posted reminder note.
FEATURE

Subagent Types Precisely Identified, Tool Disable Scope No Longer Misjudged

When monitoring multiple subagents or custom tool lists through scripts, status notifications and tool determinations become clearer.

subagentStatusLine (the data providing subagent status) adds an agentType field so scripts can tell custom agent types apart. Previously, after the host, permission rules, or a --tools list removed SendMessage, Claude could still be asked to use it to resume subagents or send messages; this is now fixed, including for resumed sessions. Subagents and --agent sessions are also no longer told the entire session has a built-in tool disabled just because their own tool list doesn't include it.

Like issuing dedicated ID badges to a task force: previously, when one member happened to have no scissors at hand, the broadcast mistakenly announced a company-wide ban; now it distinguishes who lacks a listed tool, and no one is asked to use an extension line that has been removed.
BUGFIX

Background-Switch Logic Fixed, Drafts and Queued Messages No Longer Lost

When you press the left arrow ← key mid-run to switch a session to the background, unsent text and pending-question states are no longer accidentally interrupted.

Previously, as long as the input box held unsent text, or the screen was waiting for you to answer a question, pressing ← would still switch to the background after 10 seconds. Now the background switch is automatically canceled in these situations. When a queued message cannot be transferred to the background, the system stays in place and explains why, instead of losing the message. If a permission confirmation appears right after you press ←, pressing Esc, or choosing No without feedback, also stops that turn as expected.

It works like handing tasks off at a counter: previously, if you were mid-sentence or reaching for your ID, the clerk would wait a few seconds and then pull down the shutter anyway; now, with a draft or question in hand, this closing is canceled instead of forcing the conversation into the back room.
BUGFIX

More Flexible Plugin Tool Declaration, Test and Hook Mechanisms Fixed

When developing custom modules or plugins, tool registration and testing flows are more reliable.

$.tool.register supports isDeferred; setting it to false lists the tool schema directly in the prompt without going through tool search. When the plugin hook (a small program triggered by specific events) worker process restarts, a module's classic.* event hooks are no longer dropped, avoiding a situation where only settings hooks respond alone. Modules calling $.session.append used to make claude plugin test fail; tests can now read back the appended records via mock.session. On Macs with Docker Desktop installed, symlinks (shortcut files pointing to another location) under ~/.docker/bin used to make claude plugin eval reject every execution granted Bash permission. This bug is fixed, and the rejection message now indicates which part of the credential store (where login proofs are kept) holds the link.

BUGFIX

Remote-Control Streaming Smoother, Notification and History Upload Fixes

When conversing through remote control or cloud environments, long replies display and background status behave more normally.

Previously, in long conversations text would occasionally freeze in a block and then suddenly pop out; it now displays smoothly word by word. After credentials are restored, the system no longer re-uploads the history from the start of the session. When launched via the claude remote-control command, push notifications no longer falsely report that remote control is not enabled.

Imagine setting up a clear live broadcast line: previously, long content tended to jam into one big packet dumped out all at once, and reconnecting would replay the opening remarks; now words arrive smoothly, and the connection indicator stays accurate at all times.
FEATURE

Chrome Browser Control Strengthened, Tabs and Switching No Longer Disconnect

When having Claude drive the Chrome browser to fetch web pages, tab responsiveness and connection prompts become friendlier.

When the browser is slow to report tabs, page operations are rejected less often. Typing the /tui command in a session started with --chrome no longer accidentally cuts the browser connection, and the --no-chrome parameter is respected. When a cloud session can't find a browser and multiple organizations exist, the prompt explains that the extension must sign in to the same organization and how to switch.

Like asking an assistant to operate your computer: previously, when tab information came back slowly, operations were easily refused; now such refusals are rarer, and switching view modes doesn't kick the browser connection off.
BUGFIX

Code Review Upload Fixed, Failure Reasons Listed Explicitly

When uploading projects with code review or /ultrareview, file checks and error guidance are clearer.

Previously on Linux, sandboxed command execution could wrongly reject some repositories because a config file "couldn't be parsed"—for example, when the repository sat inside another checked-out copy of the project. This read problem is now fixed. When a split index file is rejected, the system no longer suggests a fix that could leave Git unable to read the index. In Code Review's add-repository dialog, repositories that can't be added are now listed one by one, each with its reason (such as missing GitHub write permission).

Picture a parcel entering a smart security scanner: previously, multi-layer packaging would trigger a mistaken rejection, and the rejection slip came with wrong advice on how to open it; now the inspection flow works properly, and rejections list each missing travel document one by one.
BUGFIX

Skill Description Delivery Fixed, Idle Sync Interval Extended

When you had just edited a custom skill's description on the web, Claude in the terminal sometimes couldn't read the change.

After editing a skill description synced from claude.ai, you no longer sometimes need to start a new conversation or type /clear for the model to pick up the revised description. When no session is in use, the background sync that checks for skill changes now runs about every 40 minutes instead of every 10 minutes.

Think of an office updating its work manual: previously, after a clause was changed, you sometimes had to swap in a fresh meeting notebook for colleagues to read it; now that obstacle is gone, and the interval for checking manual changes while nobody is on duty has been stretched out.
BUGFIX

Clipboard and Keyboard Fixes, Menu Adjustments No Longer Wrap Around

When pasting text in the terminal, setting shortcuts, or picking model parameters, input detection is more accurate.

Pasted text whose first and last words matched used to be treated as typed by hand. After pasting a skill name, an accent mark typed or pasted right after it that merged into the last letter could make the skill name count as manual input; both issues are fixed. In the /model menu, using the left and right arrows to adjust thinking depth no longer wraps past the highest or lowest value, avoiding accidentally saving Low as the default. Previously, when sending a report via /feedback, pressing Ctrl+O or Ctrl+Z jumped back to the draft list, making it impossible to cancel sending; this is now fixed. keybindings.json accepts a single space key " ", and shows a warning for extra spaces like "ctrl+ k".

Like a typewriter whose paper feed and key mechanism have been recalibrated: previously a whole pasted passage was mistaken for keystroke-by-keystroke typing, and a dial turned to its limit would jump back to the start; those misjudgments and jumps are now corrected.
BUGFIX

Vim Mode Editing Fixes with Precise Cursor Alignment for Indentation and Line Deletion

For users accustomed to editing commands with Vim mode enabled in the terminal, indentation and deletion operations are now more intuitive.

Previously, pressing >> or << to indent on blank lines caused the cursor to drift past the end of the line, preventing a subsequent x from deleting characters. The cursor now remains in the correct position. After deleting an entire line in Visual mode using V followed by d, the cursor lands on the first non-blank character, and pressing . correctly repeats the operation on that line.

Much like calibrating a drafting ruler, indenting on a blank line previously made the cursor slide off the page and left it without a landing point after whole-line deletions; now the cursor consistently lands on a character every time, and repeating operations takes effect immediately.
BUGFIX

Background Maintenance and Cleanup Command Fixes Prevent Terminating Unrelated Processes

Process management and cleanup commands are now more reliable during routine maintenance and file cleanup.

Running claude logs, claude stop, claude kill, claude rm, claude daemon status, claude daemon stop, or claude daemon uninstall no longer causes unexpected logouts when login credentials are near expiration or already expired. When encountering files or directories that cannot be deleted, claude purge previously exited silently or hung in the terminal; it now finishes deleting the remaining items, lists failures, and exits with code 1. On Windows, stopping the status line, hooks, or commands no longer terminates unrelated programs that happen to share the same process ID.

Just as a cleaning crew no longer halts entirely when a single drawer is jammed or mistakenly escorts out visitors from next door, it clears the remaining areas and leaves a checklist of pending items.
FEATURE

Single-File Bash View Commands Load Rules, Diff Notices Indicate Background Changes

Project rule triggering and change tracking are more comprehensive when Claude inspects files or edits code through terminal commands.

Previously, viewing a single file through the Bash tool with cat, head, tail, sed -n, or grep instead of the Read tool missed path-specific rules and nested CLAUDE.md files. These single-file viewing commands now correctly load their dedicated rules. Diff notices for Bash edits also explicitly note that listed files were modified while the command was running (which may include writes from other background processes).

Consider an inspector entering a storage room through a side door: where area guidelines were once missed, they are now retrieved reliably, and the inspection report clarifies that changes occurred during the operation, potentially reflecting work left by other shifts.
FEATURE

Artifact Packages Pin Exact Versions, Publishing Paths No Longer Flash Error Strings

When Claude creates artifacts (web pages you can preview directly or standalone code components), external libraries are used and publication logs are displayed.

Claude now pins external libraries to exact versions released at least two weeks prior during artifact creation. An issue where the log line briefly displayed Artifact("(unprintable path)") while an artifact was being published and streamed is also fixed.

In the manner of an artisan building showroom prototypes, the bill of materials now specifies exact component versions released at least two weeks earlier, and delivery manifests no longer briefly flash unreadable address strings mid-transit.
FEATURE

Enterprise Policies Load Early with Automatic Retry on Timeout for Smoother Startup

Startup performance and policy configuration are smoother when using Claude in enterprise or team organizational environments.

The system now fetches organizational policies and managed settings earlier, automatically retrying stalled requests after 3 seconds. This reduces frustrating delays caused by sluggish connections. An issue where the application gateway refused to start when desktop policies configured Claude Desktop's built-in browser keys (such as builtinBrowserEnabled) has been resolved.

Resembling a smart access gate in a corporate office that syncs badge credentials early with headquarters and retries after a 3-second reader delay, turnstiles that previously refused to start due to specific policy keys now boot smoothly.
FEATURE

Memory Compaction Avoids Duplicate Work, Prompt Messaging Reverts to Established Design

Claude tracks historical progress and permission notifications more reliably during long conversations or automated tasks.

Previously, triggering context compaction (a mechanism that condenses long transcripts to free up space) could cause Claude to misjudge tasks finished before compaction as just completed, leading to duplicate work or reverted progress. This timeline confusion has now been fixed. A change to auto-mode rejection messages has been reverted, no longer telling Claude that a rejection covers the entire outcome rather than a single command. When cloud container restarts lose pending /loop wakeups or scheduled tasks, notifications are no longer sent to Claude, allowing the session to stay dormant.

View it as an executive assistant summarizing meeting notes: condensing older minutes previously caused confusion over when tasks were finished and even triggered duplicate efforts, but this chronological misjudgment is now corrected.
BUGFIX

External Tool Connections Fix Memory Leaks, Sorting and Polling Loads Optimized

Memory consumption and server load are more balanced when projects connect multiple external tools or run at scale in self-hosted environments.

Previously, HTTP MCP (a protocol connecting AI to external tools) connections retained every sent request until closed. This caused a memory leak (where data no longer needed continues occupying memory), which is now resolved. In the list of agents and MCP servers provided to the model, names with non-ASCII characters are sorted after ASCII names. OpenTelemetry (a tool for collecting application runtime telemetry) claude_code.at_mention log entries now emit at most 100 agent events and 100 MCP resource events per prompt read. Self-hosted environments replaced fixed 5-second polling with a 4–6 second jitter interval, preventing multiple instances in the same environment from sending requests simultaneously.

An analogy is a dispatch counter at a logistics hub where processed receipts no longer clutter the desks and rosters are neatly indexed; truck fleets now stagger their check-in times instead of crowding through the gates in the same second.
BUGFIX

[Claude Tag] Slack Cross-Grid Channels Fixed, Executions Run Without Mid-Task Interruptions

Message routing and permission updates are smoother when collaborating with Claude or running routine tasks in Slack channels.

In Enterprise Grid shared channels across multiple workspaces, Claude no longer erroneously reports that a workspace is unconfigured upon encountering an unconnected workspace tag. When administrators update connectors, plugins, skills, or rules mid-task, Claude avoids abrupt interruptions and instead applies changes after finishing the current task. Triggering routine tasks in threads with notes now reliably executes and reports back within the thread. When Claude joins announcement channels where only administrators can post, it joins quietly without posting an unprompted introduction.

A dependable assistant assigned to a project room once misidentified department liaisons and abruptly stopped work when managers updated policies; now, it finishes current tasks before adopting new rules and enters announcement channels quietly without causing distractions.
FEATURE

[Claude Tag] Admin Console Rules Relaxed, Connector Status Rendered Accurately

Administrators managing Claude Tag permissions and connectors in the admin console now have greater configuration flexibility.

The channel rule limit for individual workspaces and organization-wide pages has been raised from 20 to 50 rules, allowing more granular policies. The management page now proactively lists unconnected Enterprise Grids with a Connect button for direct linking. In admin settings, the Add a connector dialog (the modal for adding connectors) in access sets previously marked all Google connectors as connected following a single Google login; this display bug is now fixed.

Envision an admin console expanding its electrical breaker capacity with substantially more slots and dedicated switches for unconnected cross-zone circuits; the plug installation panel no longer illuminates every Google indicator simply because one socket was plugged in.
