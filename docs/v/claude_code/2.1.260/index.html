全螢幕比對面板上線，終端機畫面清爽不殘留

就像在工作桌旁加裝一面可隨時收折的雙面鏡，一邊對話一邊就能看到最新改動的模樣。在全螢幕模式下寫程式，現在可以輸入 /diff 開啟或關閉側邊的比對面板，即時查看 Claude 編輯時尚未提交的變更。當終端機畫面太滿時，按下 ctrl+l 或 cmd+k 就能清空畫面，想查閱歷史訊息只要往上捲動即可。此外，在全螢幕下按 Ctrl+Z 暫停不會再把外層 shell 畫面錯位畫在暫停介面上，國旗圖示、組合表情符號與重音字母在換行或行末最後兩格時也不會再破版或留下殘影。

無頭模式支援顧問指令，遙控操作更省資源

透過桌面端 App、Remote Control 或以 -p 參數執行的無頭模式（headless，沒有終端機視窗／視覺介面的執行模式）工作階段，現在能直接使用純文字形式的顧問指令。你可以輸入 /advisor、/advisor <model>、/advisor off 三種文字形式。同時，無頭環境也新增了 /reload-plugins 來重新載入外掛，因此會出現在 Claude Code Desktop 與 SDK 指令清單。如果遠端輸入了不存在的模型名稱，系統會在當下直接報錯拒絕，避免等到下一則訊息才崩潰。非互動模式（-p / SDK）工作階段的閒置時處理器用量改善。這有如幫遠端遙控器補齊實體按鍵與省電待機功能，指令輸入錯誤時也會立刻亮燈示警。

Fable 5.1 快取全面升級，百萬脈絡壓縮不逾時

輸入 /cost，或查看 status line（狀態列）的 prompt_cache 欄位時，快取未命中會標出原因，例如 tool definitions、system prompt 變更，或閒置超過 TTL。Claude Fable 5.1 先前沒把工具結果後的脈絡納入提示詞快取，所以每輪 tool-call 曾當未快取輸入重送；現在會納入。中途改 /effort 不再讓快取失效。上列 model: fable 代理不會再忽略綁定上的 [1m] 而默默改用 200K。組織若能用 Fable 5.1，/model 選單會顯示它；先前只能打上列完整指令。Opus 與 Fable 工作階段會在接近 100 萬 token（文字單位）上限前壓縮，極大脈絡時救援壓縮不再 10 分鐘超時。

權限規則精準解析括號，路徑比對嚴防破口

路徑含括號的 Edit、Write 或 Read 權限規則，以前曾被當成無效丟掉，或被 Bash 沙盒忽略，唯讀資料夾因此可寫。若出現未閉合中括號等無法編譯的正規表達式（regex，用符號比對字串的語法），所有檔案編輯都會報 Invalid regular expression。現在此類拒絕規則會退回保護其字面路徑。若在括號後誤加多餘文字（例如 Bash(ls) x），系統會直接回報設定無效而非默默忽略。Windows 例 Edit(C:\dir\(name)\**) 裡的 \( 會被讀成跳脫括號而非路徑分隔，錯誤訊息會建議明確寫法。此外，Glob 與 Grep 工具現在會先確認權限，才回報路徑是否存在。食譜寫「高湯（雞骨或蔬菜）」時，括號裡的替代食材不該讓整份菜單從廚房消失。

企業憑證無礙登入，受控檔案免重複核准

公司人事系統裡正式員工與舊外包是兩組帳號，不該被舊的那組卡住；公佈欄上已核准的內規也不必每次再簽一次。企業身分登入與伺服器託管設定在這次更新中變得更加清晰穩定。當公司的根憑證授權單位僅安裝在作業系統憑證庫時，AWS Bedrock 的模型偵測、token（AI 處理與計費的文字單位）計算與 AWS SSO/STS 呼叫不再因找不到發行憑證而失敗。使用 claude.ai 企業版或團隊版的成員，即使殘留先前 /login 留下的 API 金鑰，也能正常載入託管設定；輸入 /status 時會明確標示哪一組憑證正在生效、哪一組未被使用。伺服器下發的受控 CLAUDE.md，鍵名為 claudeMd，不再觸發安全核准對話框。掛鉤（hook，特定事件發生時被觸發的小程式）、Shell 指令、沙盒與不安全的 env 設定仍須核准。

閘道支援桌面政策，自動阻擋巢狀欄位拼錯

閘道支援下列鍵：

userPluginMarketplacesEnabled  # Desktop 鍵
userPluginUploadsEnabled  # Desktop 鍵

身分提供者若須再要 openid 才會在更新時給識別令牌，可設定 oidc.scope_on_refresh。更新失敗日誌也會具名失敗步驟。Bedrock 被中斷的請求改用 AWS 免費 CountTokens API 計算輸入 token，需授予 IAM bedrock:CountTokens，而非改送只含一個 token 的請求。兩把 Desktop 鍵寫在 desktop 政策區塊。orgPluginSettings 改以清單格式傳送，供 Claude Desktop 1.15200.0 起讀取；舊版忽略。若 desktop 政策在 MCP（外部工具協定）的 managedMcpServers 或 orgPluginSettings 巢狀物件拼錯欄位，啟動時會拒絕並指出該欄位。欄位名拼錯就送不出，會標出錯格。

外掛載入不再卡死模型，瀏覽器連線更穩固

外掛掛鉤（hook，特定事件發生時被觸發的小程式）或組織外掛市集載入失敗時，切換模型不再把整段工作階段鎖死；每次切換都會重新檢查並標註拒絕原因。由 SDK 提供的 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器不再於第一輪對話缺席，例如 Desktop connectors。雲端託管的 claude.ai 工作階段在增減連接器時，Claude in Chrome 工具不再於中途跳出 Not connected。若組織管理員關閉此功能，--chrome、/chrome 與瀏覽器工具會一併停用。從網址市集安裝外掛時，若主機應用程式（例如 Claude Desktop）把市集存成目錄，先前會失敗並出現：

marketplace entry path does not stay inside the marketplace directory

這就像音響擴大機更換訊號源時，即使某個外接插頭鬆脫，也不會導致整台機器永久死鎖而無法切換頻道。

代理團隊通知精準送達，結構化輸出提早防呆

在大型專案團隊中，各工種之間的傳令與交接必須精準到位，才不會因為聯絡簿被洗掉或回報送錯辦公室而造成混亂。當子代理透過 SendMessage 喚醒另一個代理時，對方完成後的通知現在會正確送回給發起喚醒的子代理，不再誤送到主工作階段。代理團隊在 API 長時間重試等待時（例如處於 CLAUDE_CODE_RETRY_WATCHDOG），對話紀錄不會再被重試通知擠掉而洗白。執行工作流時，如果子代理正在進行長時間的脈絡壓縮，不會再被誤判為停滯而遭粗暴重啟。結構化輸出方面，Workflow 的 agent({schema}) 若遇到永遠無法滿足的 JSON Schema，會事先拒絕；達到重試上限時也會附上最後一次驗證錯誤。子代理啟動的背景指令取消了 1 小時限制，會執行到自己結束或被停止為止，並對齊主工作階段。

背景工作階段防幽靈重影，工作樹安全清點防手滑

移至背景的工作階段不會再於 ListAgents 出現同名的 interactive 幽靈分身，檢視器也不再收到它的 SendMessage。多個工作階段共用同一個專案目錄時偶發的輸出交換錯誤也已修復。刪除帶有未推送提交的工作樹（worktree，Git 讓同一專案平行開多份副本的功能）背景工作階段時，第一次會報出分支名稱與提交數量，再執行一次刪除才會丟掉該工作樹。以 -p --resume 或 --continue 接續若遺失 Git 詮釋資料，失敗一次後會跳過工作樹繼續執行。自託管 runner 若設定了 --kill-session-after-min，遇到純粹等待使用者輸入的暫停狀態時會和平釋放，不會強制終止並報錯。就像管理共用辦公區的臨時座位，分身不會重疊登記；桌上還有未歸檔文件會先清點，等候主人回覆也不會被直接清空。

歷史回溯確實驗證備份，GitLab 連結不再誤指 GitHub

當你想透過 /rewind 或 --rewind-files 回溯專案狀態時，系統現在有了更嚴格的確認機制。若檢查點備份檔案遺失導致實際上未還原任何內容，系統不會再虛報成功；回溯後也不會殘留舊回合的讀取紀錄，避免外部修改檔案後發生誤判或重複塞入整個檔案。在遠端或桌面 App 工作階段中發布產出物時，不會再無故多彈出一個瀏覽器分頁，協作工作階段中產出物工具首次呼叫的參數驗證錯誤也已修正。針對使用 GitLab 的開發者，巢狀子群組的專案現在能被正確辨識為 GitLab 存放庫，終端機顯示的議題編號連結（例如 owner/repo#123）也會精確連往 gitlab.com 而非誤連至 GitHub。這就像在記事本上按復原鍵，系統會確實檢查底稿存檔，不再假裝已經還原，也不會把隔壁頁的筆記目錄給搞混。

技能精準保留選取行數，雲端審查等候更寬裕

在編輯器裡呼叫專屬助理就像用螢光筆標出重點交給專家，選取的行數會原封不動交到對方手中。IDE 選取的行數在觸發技能（skill）或斜線指令時不會再遺失，Claude 能收到 N lines selected 這句脈絡。受控設定的 skillOverrides 若以內建技能別名為鍵（例如用 checkup 覆寫 /doctor）已能正常生效，Skill(name) 拒絕規則也完整涵蓋了 <目錄>:名稱 形式的巢狀技能。內建的 claude-api 技能範例已更新 Go、Java 與 C# 程式碼至最新世代模型識別碼，並說明較便宜的 worker 或子代理模型也應採用新世代模型。雲端審查指令 /ultrareview 與 claude ultrareview 的等候時間上限從 30 分鐘延長至 45 分鐘。

VS Code 頁尾顯示努力程度，回應重試不留殘影

VS Code 擴充套件在介面顯示與工作階段管理上變得更加俐落。底部的模型標籤現在會直接顯示目前選擇的努力程度，切換模型後數值不再停留在舊狀態，且標籤尺寸已恢復為原本的緊湊大小。工作階段清單的狀態篩選選單中，新增了 Open 與 Closed 兩個選項，方便你快速分類與尋找專案。此外，Claude Code 對 dropped response 重試後，畫面不再留下半截訊息、空白工具卡或多餘的 Thought for 行。就像把儀表板重新擦拭乾淨，開關檔位一目了然，重試後也不會留下半截殘缺的草稿。

VS Code 智慧切換開啟分頁，遠端設定即時套用

在 VS Code 中操作多個分頁與遠端控制時的體驗更加順暢。在歷史工作階段選擇器中點選已在其他分頁開啟的工作階段時，編輯器會直接切換到該分頁，不再重複載入同一份對話。在分頁畫面重新整理期間執行重新命名（Rename）指令，系統現在會確實套用新名稱，不再無聲失效。新開啟工作階段時若自動啟動 Remote Control，歡迎畫面不會再莫名消失。此外，若在分頁剛啟動的當下切換「為所有工作階段啟用 Remote Control」，該設定現在能正確套用到正在初始化的分頁中。好比辦公桌上的文件夾標籤與切換器，翻閱已打開的卷宗會直接引導至該分頁，新開的檔案盒也不會因為剛啟動就漏接全域開關。

Headless mode supports advisor commands, making remote operations more resource-efficient

Fable 5.1 caching fully upgraded, 1M context compaction no longer times out

A long text is like a labeled filing cabinet—as long as the contents don't change, there's no need to unpack the entire box to recalculate.

prompt_cache  # status line field
model: fable  # agent setting
ANTHROPIC_DEFAULT_FABLE_MODEL  # pin

When running /cost or checking the prompt_cache field in the status line, cache misses now indicate the likely cause, such as changes to tool definitions, system prompt modifications, or idling past the TTL. Claude Fable 5.1 previously did not include the context attached after tool results in prompt caching, causing it to be re-sent as uncached input on every tool-call turn; it is now included. Changing /effort mid-session no longer invalidates the prompt cache. The model: fable agents listed above will no longer ignore the [1m] tag on pins and silently fall back to 200K. If an organization has access to Fable 5.1, the /model picker now displays it; previously it had to be typed as the full command above. Opus and Fable sessions now compact shortly before reaching the 1M token limit, and recovery compaction on very large contexts no longer times out at 10 minutes.

Permission rules accurately parse parentheses, tightening path matching against loopholes

Permission rules for Edit, Write, or Read whose paths contain parentheses were previously dropped as invalid or ignored by the Bash sandbox, leaving read-only folders writable. If an uncompilable regex pattern appears, such as an unclosed bracket, every file edit fails with Invalid regular expression. Deny rules of this kind now fall back to guarding their literal paths. If extra text is mistakenly appended after the closing parenthesis, such as Bash(ls) x, the system now directly reports an invalid setting instead of silently ignoring it. For Windows examples like Edit(C:\dir\(name)\**) where \( is read as an escaped parenthesis rather than a path separator, the error message now suggests an unambiguous spelling. In addition, the Glob and Grep tools now check permissions before reporting whether a path exists. When a recipe specifies "broth (chicken or vegetable)," the alternative ingredients in parentheses should not make the entire menu disappear from the kitchen.

Enterprise credentials log in smoothly, managed files bypass repeated approvals

In a corporate HR system, full-time employees and former contractors have separate accounts and shouldn't get blocked by the old ones, just as approved internal rules on the bulletin board don't need to be re-signed every time. Enterprise identity login and server-managed settings are clearer and more stable in this update. When a corporate root CA is installed only in the OS certificate store, AWS Bedrock model discovery, token counting, and AWS SSO/STS calls no longer fail due to missing issuer certificates. Members using claude.ai Enterprise or Team plans can now load managed settings normally even if a leftover API key from an earlier /login remains; running /status clearly marks which credential is in effect and which is unused. Server-managed CLAUDE.md files under the key claudeMd no longer trigger the security approval dialog. Hooks, shell commands, sandbox settings, and unsafe env configurations still require approval.

Gateway supports Desktop policies, automatically blocking misspelled nested fields

The gateway now supports the following keys:

oidc.scope_on_refresh  # scope key
userPluginMarketplacesEnabled  # Desktop key
userPluginUploadsEnabled  # Desktop key
orgPluginSettings  # list format

For identity providers that only return an ID token on refresh when requested for openid again, oidc.scope_on_refresh can be configured. Refresh failure logs also name the step that failed. Aborted requests on Bedrock now use AWS's free CountTokens API to count input tokens—requiring IAM bedrock:CountTokens—instead of sending a request containing only a single token. The two Desktop keys are placed in the desktop policy block. orgPluginSettings is now sent in list format for Claude Desktop 1.15200.0 and later to read; older versions ignore it. If a desktop policy misspells a field in a nested object under managedMcpServers or orgPluginSettings, startup is refused and the exact field is identified. If a field name is misspelled, it cannot be submitted, and the incorrect entry will be marked.

Plugin loading no longer freezes model switching, browser connection stabilizes

When a plugin hook or organization plugin marketplace fails to load, switching models no longer locks the entire session; each switch now re-checks and states the reason for refusal. SDK-provided MCP servers, such as Desktop connectors, no longer miss the first turn of conversation. When adding or removing connectors in cloud-hosted claude.ai sessions, Claude in Chrome tools no longer fail mid-task with Not connected. If an organization admin turns off this feature, --chrome, /chrome, and browser tools are disabled altogether. When installing plugins from a URL marketplace where the host application (such as Claude Desktop) stores the marketplace as a directory, it previously failed with:

This is like switching input sources on an audio amplifier: even if an external plug comes loose, the entire device will not permanently freeze and prevent changing channels.

Agent team notifications route accurately, structured output adds early safeguards

In a large project team, handoffs and messages between different roles must be delivered accurately to prevent confusion from a wiped contact book or reports sent to the wrong office. When a subagent wakes another agent via SendMessage, the completion notification is now correctly sent back to the subagent that initiated the wake-up, rather than mistakenly delivered to the main session. During long API retry waits (such as under CLAUDE_CODE_RETRY_WATCHDOG), agent team transcripts are no longer evicted or wiped blank by retry notices. When running workflows, if a subagent is undergoing long context compaction, it is no longer misidentified as stalled and abruptly restarted. For structured output, Workflow's agent({schema}) now rejects unsatisfiable JSON Schemas up front, and errors hitting the retry limit will include the last validation failure. The 1-hour time limit on background commands started by subagents has been removed; they now run until they exit or are stopped, matching the main session.

Background sessions prevent ghost twins, worktree deletions safely guard unpushed commits

Sessions moved to the background no longer appear in ListAgents as a phantom interactive twin with the same name, and the viewer will no longer receive its SendMessage deliveries. Intermittent output swap errors when multiple sessions share the same project directory have also been fixed. When deleting a background session whose worktree has unpushed commits, the first attempt reports the branch name and commit count, and deleting again discards the worktree. Resuming with -p --resume or --continue when Git metadata is lost will fail once, then proceed without the worktree. If a self-hosted runner is configured with --kill-session-after-min, encountering a paused state that is purely waiting for user input will release the session peacefully instead of killing it and reporting a failure. Just like managing hot desks in a shared office: duplicate identities are never registered twice, desks with unfiled documents are inventoried first, and waiting for an owner's reply won't trigger an immediate wipe.

History rewind verifies backups reliably, GitLab links no longer point to GitHub

When rewinding project state via /rewind or --rewind-files, the system now includes stricter verification mechanisms. If checkpoint backup files are missing and nothing is actually restored, the system no longer falsely reports success, nor does it leave stale file-read tracking from rewound turns—preventing misjudgments or full-file re-injections after external edits. Publishing an artifact in a remote or desktop app session no longer opens an unnecessary extra browser tab, and parameter validation errors on the first artifact tool call in collaboration sessions have been resolved. For developers using GitLab, projects in nested subgroups are now properly recognized as GitLab repositories, and issue reference links in the terminal (such as owner/repo#123) link accurately to gitlab.com rather than mistakenly to GitHub. Like pressing undo in a notebook: the system verifies the draft backup instead of pretending it restored, without mixing up the note catalog on adjacent pages.

Skills preserve selected line counts accurately, cloud review wait window extended

Calling a dedicated assistant in your editor is like highlighting key sections for an expert—the exact lines you selected reach their hands untouched. IDE line selections are no longer lost when triggering a skill or slash command, allowing Claude to receive the N lines selected context. Managed skillOverrides entries keyed on a bundled skill's alias—such as overriding /doctor with checkup—now apply properly, and Skill(name) deny rules fully cover nested skills written in the <dir>:name format. The bundled claude-api skill examples have updated their Go, Java, and C# code to current-generation model IDs, clarifying that cheaper worker or subagent models should also use current-generation models. The maximum wait time for cloud review commands /ultrareview and claude ultrareview has been extended from 30 minutes to 45 minutes.

VS Code footer displays effort level, retrying responses leaves no artifacts

The VS Code extension brings cleaner interface rendering and session management. The model pill in the footer now directly displays the currently selected effort level, no longer retaining a stale value after switching models, and pill dimensions have returned to their earlier compact size. In the session list's status filter menu, Open and Closed options have been added for faster project categorization and searching. In addition, after Claude Code retries a dropped response, the screen no longer leaves behind half-finished messages, empty tool cards, or an extra Thought for line. Just like wiping the dashboard clean so gear settings are clear at a glance, with no half-written drafts left behind after a retry.

VS Code smartly switches open tabs, remote settings apply immediately

Working across multiple tabs and Remote Control in VS Code is now smoother. Selecting a session from the session history picker that is already open in another tab directly switches to that tab instead of loading the same conversation a second time. Executing the Rename command while a tab view is reloading now reliably applies the new name instead of silently doing nothing. When opening a new session where Remote Control starts automatically, the welcome screen no longer inexplicably disappears. Furthermore, toggling "Enable Remote Control for all sessions" right as a tab is launching now properly applies to the initializing tab. Like folder tabs and switchers on a desk: looking up an already opened file directs you straight to that tab, and a newly opened file box won't miss the global switch just because it was starting up.
