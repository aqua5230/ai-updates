Claude Code 2.1.260

Released: 2026-09-03

Release notes

FEATURE

Fullscreen diff panel launches, keeping the terminal screen clean without artifacts

Like mounting a foldable two-way mirror beside your desk so you can see the latest changes while having a conversation.

When coding in fullscreen mode, you can now enter /diff to toggle a side-by-side diff panel and inspect uncommitted changes in real time as Claude edits.

When the terminal screen gets crowded, pressing ctrl+l or cmd+k clears the transcript view, and you can scroll up to view earlier messages. In addition, pressing Ctrl+Z in fullscreen to pause no longer misrenders the outer shell screen onto the paused interface, and flag icons, joined emoji, or accented letters will no longer break layout or leave stale artifacts when wrapping or falling in the terminal's last two columns.

FEATURE

Headless mode supports advisor commands, making remote operations more resource-efficient

Sessions running in headless mode via the desktop app, Remote Control, or the -p flag can now directly use text-based advisor commands.

You can enter three text forms: /advisor, /advisor <model>, and /advisor off. At the same time, headless environments add /reload-plugins to reload plugins, making it available in the Claude Code Desktop and SDK command lists. If an invalid model name is entered remotely, the system now refuses it with an error immediately instead of crashing on the next message. Idle CPU usage has also improved for non-interactive (-p / SDK) sessions.

This is like equipping a remote control with physical buttons and a power-saving standby mode, while flashing a warning light instantly whenever an invalid command is entered.
FEATURE

Fable 5.1 caching fully upgraded, 1M context compaction no longer times out

A long text is like a labeled filing cabinet—as long as the contents don't change, there's no need to unpack the entire box to recalculate.
prompt_cache  # status line field
model: fable  # agent setting
ANTHROPIC_DEFAULT_FABLE_MODEL  # pin
/model claude-fable-5-1  # full command

When running /cost or checking the prompt_cache field in the status line, cache misses now indicate the likely cause, such as changes to tool definitions, system prompt modifications, or idling past the TTL.

Claude Fable 5.1 previously did not include the context attached after tool results in prompt caching, causing it to be re-sent as uncached input on every tool-call turn; it is now included. Changing /effort mid-session no longer invalidates the prompt cache. The model: fable agents listed above will no longer ignore the [1m] tag on pins and silently fall back to 200K. If an organization has access to Fable 5.1, the /model picker now displays it; previously it had to be typed as the full command above. Opus and Fable sessions now compact shortly before reaching the 1M token limit, and recovery compaction on very large contexts no longer times out at 10 minutes.

FEATURE

Permission rules accurately parse parentheses, tightening path matching against loopholes

Permission rules for Edit, Write, or Read whose paths contain parentheses were previously dropped as invalid or ignored by the Bash sandbox, leaving read-only folders writable.

If an uncompilable regex pattern appears, such as an unclosed bracket, every file edit fails with Invalid regular expression. Deny rules of this kind now fall back to guarding their literal paths. If extra text is mistakenly appended after the closing parenthesis, such as Bash(ls) x, the system now directly reports an invalid setting instead of silently ignoring it. For Windows examples like Edit(C:\dir\(name)\**) where \( is read as an escaped parenthesis rather than a path separator, the error message now suggests an unambiguous spelling. In addition, the Glob and Grep tools now check permissions before reporting whether a path exists.

When a recipe specifies "broth (chicken or vegetable)," the alternative ingredients in parentheses should not make the entire menu disappear from the kitchen.
FEATURE

Manual commands run outside the sandbox, accurately intercepting hidden substitutions

Commands you enter at the terminal prompt starting with an exclamation mark ! will run outside the sandbox even when strict sandbox mode sandbox.allowUnsandboxedCommands: false is enabled, just like typing directly into your own terminal.

{"sandbox":{"allowUnsandboxedCommands":false}}
permissions.blockReadsOutsideWorkingDirectories
REPORTTIME
REPORTMEMORY
DIRSTACKSIZE

The previous change applying Read() deny rules to Bash arguments—which denied npm run build under a Read(./**/build/**) rule in every mode and prompted for cd … && grep even in auto mode—has been reverted and no longer behaves this way.

On macOS, enabling the blocking key listed above no longer prevents sandboxed Git from reading the user's git config, and worktree-isolated subagents can now access their own checkout directories. If zsh hides a command substitution inside assignments to the three parameters listed above, it now prompts for approval.

Steps typed by hand on your own workbench should execute directly, while extra instructions smuggled into work order notes must ask for permission first.
FEATURE

Enterprise credentials log in smoothly, managed files bypass repeated approvals

In a corporate HR system, full-time employees and former contractors have separate accounts and shouldn't get blocked by the old ones, just as approved internal rules on the bulletin board don't need to be re-signed every time.

Enterprise identity login and server-managed settings are clearer and more stable in this update.

When a corporate root CA is installed only in the OS certificate store, AWS Bedrock model discovery, token counting, and AWS SSO/STS calls no longer fail due to missing issuer certificates. Members using claude.ai Enterprise or Team plans can now load managed settings normally even if a leftover API key from an earlier /login remains; running /status clearly marks which credential is in effect and which is unused. Server-managed CLAUDE.md files under the key claudeMd no longer trigger the security approval dialog. Hooks, shell commands, sandbox settings, and unsafe env configurations still require approval.

FEATURE

Gateway supports Desktop policies, automatically blocking misspelled nested fields

The gateway now supports the following keys:

oidc.scope_on_refresh  # scope key
userPluginMarketplacesEnabled  # Desktop key
userPluginUploadsEnabled  # Desktop key
orgPluginSettings  # list format

For identity providers that only return an ID token on refresh when requested for openid again, oidc.scope_on_refresh can be configured.

Refresh failure logs also name the step that failed. Aborted requests on Bedrock now use AWS's free CountTokens API to count input tokens—requiring IAM bedrock:CountTokens—instead of sending a request containing only a single token. The two Desktop keys are placed in the desktop policy block. orgPluginSettings is now sent in list format for Claude Desktop 1.15200.0 and later to read; older versions ignore it. If a desktop policy misspells a field in a nested object under managedMcpServers or orgPluginSettings, startup is refused and the exact field is identified.

If a field name is misspelled, it cannot be submitted, and the incorrect entry will be marked.
FEATURE

Plugin loading no longer freezes model switching, browser connection stabilizes

When a plugin hook or organization plugin marketplace fails to load, switching models no longer locks the entire session; each switch now re-checks and states the reason for refusal.

SDK-provided MCP servers, such as Desktop connectors, no longer miss the first turn of conversation. When adding or removing connectors in cloud-hosted claude.ai sessions, Claude in Chrome tools no longer fail mid-task with Not connected. If an organization admin turns off this feature, --chrome, /chrome, and browser tools are disabled altogether. When installing plugins from a URL marketplace where the host application (such as Claude Desktop) stores the marketplace as a directory, it previously failed with:

marketplace entry path does not stay inside the marketplace directory

This is like switching input sources on an audio amplifier: even if an external plug comes loose, the entire device will not permanently freeze and prevent changing channels.
FEATURE

Agent team notifications route accurately, structured output adds early safeguards

In a large project team, handoffs and messages between different roles must be delivered accurately to prevent confusion from a wiped contact book or reports sent to the wrong office.

When a subagent wakes another agent via SendMessage, the completion notification is now correctly sent back to the subagent that initiated the wake-up, rather than mistakenly delivered to the main session.

During long API retry waits (such as under CLAUDE_CODE_RETRY_WATCHDOG), agent team transcripts are no longer evicted or wiped blank by retry notices. When running workflows, if a subagent is undergoing long context compaction, it is no longer misidentified as stalled and abruptly restarted. For structured output, Workflow's agent({schema}) now rejects unsatisfiable JSON Schemas up front, and errors hitting the retry limit will include the last validation failure. The 1-hour time limit on background commands started by subagents has been removed; they now run until they exit or are stopped, matching the main session.

FEATURE

Background sessions prevent ghost twins, worktree deletions safely guard unpushed commits

Sessions moved to the background no longer appear in ListAgents as a phantom interactive twin with the same name, and the viewer will no longer receive its SendMessage deliveries.

Intermittent output swap errors when multiple sessions share the same project directory have also been fixed. When deleting a background session whose worktree has unpushed commits, the first attempt reports the branch name and commit count, and deleting again discards the worktree. Resuming with -p --resume or --continue when Git metadata is lost will fail once, then proceed without the worktree. If a self-hosted runner is configured with --kill-session-after-min, encountering a paused state that is purely waiting for user input will release the session peacefully instead of killing it and reporting a failure.

Just like managing hot desks in a shared office: duplicate identities are never registered twice, desks with unfiled documents are inventoried first, and waiting for an owner's reply won't trigger an immediate wipe.
BUGFIX

History rewind verifies backups reliably, GitLab links no longer point to GitHub

When rewinding project state via /rewind or --rewind-files, the system now includes stricter verification mechanisms.

If checkpoint backup files are missing and nothing is actually restored, the system no longer falsely reports success, nor does it leave stale file-read tracking from rewound turns—preventing misjudgments or full-file re-injections after external edits. Publishing an artifact in a remote or desktop app session no longer opens an unnecessary extra browser tab, and parameter validation errors on the first artifact tool call in collaboration sessions have been resolved. For developers using GitLab, projects in nested subgroups are now properly recognized as GitLab repositories, and issue reference links in the terminal (such as owner/repo#123) link accurately to gitlab.com rather than mistakenly to GitHub.

Like pressing undo in a notebook: the system verifies the draft backup instead of pretending it restored, without mixing up the note catalog on adjacent pages.
FEATURE

Skills preserve selected line counts accurately, cloud review wait window extended

Calling a dedicated assistant in your editor is like highlighting key sections for an expert—the exact lines you selected reach their hands untouched.

IDE line selections are no longer lost when triggering a skill or slash command, allowing Claude to receive the N lines selected context.

Managed skillOverrides entries keyed on a bundled skill's alias—such as overriding /doctor with checkup—now apply properly, and Skill(name) deny rules fully cover nested skills written in the <dir>:name format. The bundled claude-api skill examples have updated their Go, Java, and C# code to current-generation model IDs, clarifying that cheaper worker or subagent models should also use current-generation models. The maximum wait time for cloud review commands /ultrareview and claude ultrareview has been extended from 30 minutes to 45 minutes.

FEATURE

VS Code footer displays effort level, retrying responses leaves no artifacts

The VS Code extension brings cleaner interface rendering and session management.

The model pill in the footer now directly displays the currently selected effort level, no longer retaining a stale value after switching models, and pill dimensions have returned to their earlier compact size. In the session list's status filter menu, Open and Closed options have been added for faster project categorization and searching. In addition, after Claude Code retries a dropped response, the screen no longer leaves behind half-finished messages, empty tool cards, or an extra Thought for line.

Just like wiping the dashboard clean so gear settings are clear at a glance, with no half-written drafts left behind after a retry.
FEATURE

VS Code smartly switches open tabs, remote settings apply immediately

Working across multiple tabs and Remote Control in VS Code is now smoother.

Selecting a session from the session history picker that is already open in another tab directly switches to that tab instead of loading the same conversation a second time. Executing the Rename command while a tab view is reloading now reliably applies the new name instead of silently doing nothing. When opening a new session where Remote Control starts automatically, the welcome screen no longer inexplicably disappears. Furthermore, toggling "Enable Remote Control for all sessions" right as a tab is launching now properly applies to the initializing tab.

Like folder tabs and switchers on a desk: looking up an already opened file directs you straight to that tab, and a newly opened file box won't miss the global switch just because it was starting up.
