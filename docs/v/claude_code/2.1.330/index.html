Claude Code 2.1.330

發布日期：2026-11-20

繁體中文

新功能

企業帳號登入直接套用組織設定

在公司使用由 Anthropic Enterprise Admin Console 管理的帳號，現在可以直接登入 Claude Code。只要執行 claude auth login，Claude Code 就會套用組織的設定，並走組織指定的雲端供應商或閘道連線。

就像拿公司門禁卡刷進辦公室後，電腦自動連上內網並套用部門印表機設定，不用自己逐項重填。
新功能

內建 easel 模組可直接畫圖表與指標結果

想把對話裡的數據或外部工具的統計畫成圖表來看，現在不必自己另外寫程式。macOS 與 Linux 上的 Pro、Max 方案，以及有開放的 Team 與 Enterprise 方案，新增了內建模組 easel。 只要向 Claude 要求畫圖，或查看 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）指標結果時，easel 就會直接把圖表畫在下方。想關掉自動畫圖，進 /config 調整就行。

想像請咖啡店店員算帳時順手把每月銷量畫成折線圖貼在明細下面，想只看純數字也能隨時關掉。
新功能

登入網址變短，需要時也能印出完整連結

以前在終端機執行 /login、claude auth login 或 claude setup-token，印出的 claude.ai 登入連結常常長到換好幾行。現在這三個指令顯示的登入網址變短許多，複製起來比較乾脆。 遇到短連結出錯，或是腳本需要從網址裡抓參數時，執行指令前加上環境變數 CLAUDE_CODE_FULL_SIGN_IN_LINK=1 就會改印完整網址：CLAUDE_CODE_FULL_SIGN_IN_LINK=1 claude auth login。

跟把長網址縮成短連結方便傳給朋友一樣，平常挑好按的短版，要拆開看參數時再換回完整原址。
新功能

自架執行器新增 --start-dir 指定工作目錄

大型程式碼庫裡常包著好幾個子專案，想請 Claude 從其中一個資料夾開工，可以加上 --start-dir 參數，或設定環境變數 SELF_HOSTED_RUNNER_START_DIR。 指定起點後，設定與 hook（掛鉤，特定事件發生時被觸發的小程式）依然照原本方式載入，不會因此漏掉。

好比進大型商場只去其中一間專櫃逛，櫃位動線縮小了，但商場原本的廣播與門禁規矩照舊有效。
新功能

外掛儲存庫範圍與存取遭拒新增提醒

在雲端或自架執行器的工作階段裡裝外掛卻沒成功，以前常常搞不清楚問題出在哪裡。現在只要外掛市集的儲存庫不屬於該工作階段的範圍而抓不到時，畫面會主動顯示通知。 自架執行器若遇到 Anthropic 託管的 Git 拒絕存取某個外掛自己的儲存庫，通知還會點出外掛名稱，並告訴你接下來該怎麼處理。

把這想成去圖書館調閱特藏資料失敗時，櫃檯現在不只說調不到，還會寫清楚是哪一本書缺授權以及要找誰申請。
新功能

外掛 JSON 安裝結果補上指令錯誤與輸出欄位

給串接安裝結果的開發者：用自動化腳本跑 claude plugin install --json 裝外掛，過去不容易從結果判斷外掛自帶的安裝指令有沒有出事。 現在回傳結果會標示安裝指令是否曾把訊息寫進標準錯誤輸出，以及是否出錯、被強制終止或執行逾時。

如快遞簽收單多印了「配送逾時」與「曾開箱註記」兩欄，不用拆包裹就能從單據先判斷狀況。
問題修復

自架執行器 /metrics 補上派工耗時與輪詢修正

給負責監控自架執行器的維運人員：/metrics 端點新增了兩項計時指標，方便追蹤派工後的等待時間，也順帶修好一項容易誤導的舊數值。 由協調器啟動的執行器現在會記錄從發出工單到註冊完成的秒數；為特定工作階段啟動的執行器，則會記錄從工單發出到接手第一個工作階段的秒數。另外，從未成功輪詢時，距上次成功輪詢的秒數過去會誤顯示為 0，這個問題已修好。

問題修復

長對話壓縮與網頁抓取不再卡住數分鐘

跑完一整段長對話或剛喚醒電腦，終端機有時會突然動彈不得好幾分鐘，這批問題現在都修好了。 壓縮過長的對話紀錄後，Claude Code 不會再緊接著凍結好幾分鐘。 用 WebFetch 抓取某些網頁時，工作階段不會再卡住數分鐘，也不會莫名回傳空白結果。 在 Linux 與 WSL 上休眠兩分鐘以上再送出第一句提問時，不會再對已經斷掉的連線傻等三分鐘。

問題修復

ExitWorktree 不再誤刪其他工作階段的副本

平行開好幾個終端機跑任務，以前退出時有時會誤刪別處正在用的工作區。現在執行 ExitWorktree 或從退出對話框離開，不會再誤刪其他工作階段正使用的 worktree（工作樹，Git 平行開多份專案副本的功能）。

問題修復

並行存檔與磁碟滿時的備份問題修正

同時開著多個視窗或指令操作，本地紀錄與備份不再互相踩掉。 好幾個 Claude Code 行程同時儲存使用者設定時，改動不會再莫名遺失。 同時執行多道 claude plugin 指令時，已安裝清單裡的外掛不會再不見。 多筆任務更新同時寫入時，任務之間的相依關係與中繼資料不會再丟失。 硬碟空間滿了的時候，~/.claude.json 不完整的備份不會再被保留下來，也不會把原本完好的舊備份擠掉。

問題修復

接續對話與 claude -p 寫檔失敗處理更可靠

拿指令接續上次進度或寫自動化管線，遇到異常狀況不再無聲失敗或開出空白對話。 最後一筆儲存訊息的時間戳缺漏或無效時，--continue 與 --resume 不會再開出空的工作階段或直接失敗。 透過 claude -p --continue 執行時，SessionStart 掛鉤寫入的環境變數不再遺失。 把 claude -p 的輸出寫入滿載磁碟的檔案時，現在會印出錯誤並回傳狀態碼 1，不再默默以狀態碼 0 結束；不過若遇到已滿的 NFS 遠端掛載目錄，仍可能偵測不到。

問題修復

MCP 工具結構與子代理共用連線等問題修正

工作階段同時掛載多個 MCP 工具或子代理，先前常碰到的異常報錯與連線中斷問題現在都有解了。 當許多 MCP 工具帶著會被 API 拒絕的輸入結構時，對話回合不會再因「JSON schema is invalid」失敗，工作階段檔案也不會膨脹好幾 MB。 子代理各自宣告使用同一個 MCP 伺服器時，其中一個結束不會再把伺服器關掉，其他子代理與主工作階段仍可繼續用。 企業允許或拒絕清單排除了內建畫圖工具 easel 時，它仍會維持封鎖。不過每次啟動時，不會再跳出「MCP server blocked by enterprise policy: easel」的警告。

新功能

Linux 大型忽略資料夾不再拖慢 Bash 指令

讀取較慢的程式碼庫如果塞了像 node_modules 這類龐大的排除目錄，跑命令時常得乾等好幾秒。在 Linux 上這還會讓該工作階段後續完全不顯示檔案差異，現在這個問題已經修好。

新功能

Windows 搜尋與 Bash 加速，磁碟錯誤說清楚

在 Windows 電腦開工作階段搜尋或跑指令，現在順手許多，碰到無法驗證的磁碟機也不會只看到一頭霧水的錯誤。 沒有自訂啟動檔的電腦上，若 Git Bash 啟動花上 10 到 60 秒，同一工作階段剩下的 Bash 指令不會再跟著變慢。 Grep 與 Glob 搜尋本機路徑時，內建 ripgrep 不再每次都另開主控台，速度因此加快。 工作階段資料夾位在無法驗證的磁碟機上時，錯誤訊息現在會說明原因，並告訴你重試有沒有幫助。

問題修復

檔案復原與權限附註、打字內容不再弄丟

剛改完檔案、在批准視窗補充說明或正專心打字，手邊的紀錄與文字現在都能好好留著。 修改檔案的回合剛結束，兩筆排隊提問或疊加技能接著一起執行時，/rewind 不會再誤還原成更早的版本。 批准權限提示時順手附上的文字與圖片，即使核准後的指令或工具接著失敗，附帶內容也不會被丟掉。 在全螢幕模式下收到規劃內容時，你原本打到一半還沒送出的後半段文字會完整保留。

問題修復

claude.ai 連結器在提及與移除檢查的修復

在終端機裡搭配 claude.ai 連結器工作，以前容易在提及資源、共用網址或檢查連線時卡關。 在終端機輸入框用 @ 提及來自 claude.ai 連結器與外掛伺服器的 MCP 資源時，資源現在會正常附加上去。 兩個名稱不同的 claude.ai 連結器就算共用同一個伺服器網址，也不會再被漏掉。 在 /mcp 檢查「Connect on claude.ai」時，只要 claude.ai 已有對應伺服器網址但少了查詢參數的連結器，不會再誤報未連線。 用 claude mcp remove 移除 claude.ai 連結器時，現在會明確提示改到 /mcp 關閉或到 claude.ai 上刪除。

問題修復

Chrome 短暫斷線後會正常恢復連線狀態

瀏覽器明明開著也已經登入，過去只要出現短暫的連線問題，Claude in Chrome 就會一直停在「not connected」狀態。這個問題已經修好，不會再卡在未連線畫面。

問題修復

切換或指定模型後，系統提示與備援不再跑錯

不管是在啟動時鎖定模型、對話途中切換，或開出多層子代理，模型指令與備援現在會跟著對齊。 在 Amazon Bedrock Mantle 未選模型直接開啟終端機工作階段時，不會再忽略已鎖定的 Opus 模型，宣布切換備援後也不會繼續呼叫不可用的預設模型。 在 /context 之後、送出第一則訊息前更換模型，系統提示不會再留著舊模型的指示。 在回合中途換模型時，Claude 偶爾會對提交署名提醒回話而提早結束回合，這情況已修好；不過若由組織管理設定強制加上拉取請求署名行，仍可能發生。 在 opusplan 或 haiku 的計畫模式下，子代理再開出的下層代理與分岔不會再錯用計畫模式模型。

新功能

Code Mode 減少卡頓，補上圖片檢視指引

在 Code Mode 跑長腳本或處理大量檔案，畫面卡住與誤會報錯的情況少了許多。 有路徑範圍規則或讀取拒絕規則的專案裡，腳本一次讀完數百個檔案後不再停頓好一陣子。 子代理的腳本呼叫數千次工具後，終端機卡住的時間變短許多。 按下 Esc 中斷後，被停下的指令下方會顯示「Interrupted」，不再出現一片紅字錯誤。現在 Claude 在這個模式下也知道怎麼檢視圖片和 PDF 了。

問題修復

Code Mode 圖表工具與快取還原問題修復

在 Code Mode 搭配工具、自動模式或壓縮對話使用，幾個狀態與資源追蹤的錯誤已經修好。 Claude 在此模式呼叫內建圖表工具不會再失敗；在自動模式與略過權限模式下，腳本裡的 MCP 工具要求結束回合時也會正常生效。 在自動模式下，腳本載入技能後若有模組附加註記，先前的思考與提示詞快取（cache，把算過的結果暫存起來直接用）不會再被清掉重寫。 按下 Esc 與執行 /compact 後，腳本讀過的檔案會正確還原；在 Claude 首次回覆前查 /context，系統工具數量也不再少算。

問題修復

背景子代理停止與 MCP 任務追蹤問題修復

把任務或代理丟到背景繼續跑，停止訊號與權限狀態現在能正確跟上。 被停掉的背景子代理不會再自己跑回來；在應用程式或 SDK 啟動的工作階段裡，就算代理剛好快完成才被停止，Claude 也不會再繼續傻等它。 背景工作階段在核准計畫後重新喚醒時，不會再退回先前的權限模式。 把工作階段切到背景時，正在跑的 MCP 任務不會再被誤報成已停止，背景工作階段也能接著追蹤任務進度；但若該伺服器使用標準輸入輸出或自訂標頭，則不支援。

新功能

遠端控制的終端機紀錄與手機狀態顯示更準確

在手機或網頁跟電腦終端機兩邊切換著看同一場對話，畫面上的提示與按鈕狀態現在對得起來。 從手機或網頁按下停止來結束背景代理時，終端機上出現的紀錄通知不會再偽裝成是你自己打字送出的訊息。 在對話進行到一半才開啟遠端控制時，手機應用程式不會再把 Diff 與拉取請求按鈕藏起來，也不會把早已停止的工作階段顯示成正在運作。

問題修復

語言伺服器卡住時 Esc 可中斷，啟動中也不撞車

編輯程式碼依靠的語言伺服器反應慢半拍或正在啟動，現在不用整段乾等或直接報錯。 當 LSP 工具呼叫卡在遲遲不回的語言伺服器時，按下 Esc 就能直接中斷等待。另外，語言伺服器還在啟動期間同時湧入多筆呼叫與編輯時，工具呼叫與診斷資訊也不會再跟著失敗。

新功能

/mcp 與 /plugin 分類與重連錯誤顯示優化

打開 /mcp 或 /plugin 整理外掛與外部工具伺服器，找來源跟查錯都省事多了。 /mcp 不再把外掛伺服器全都算成內建。外掛帶來的會列在「Plugin MCPs」底下，--mcp-config 與內建伺服器歸在「Other MCPs」，個別頁面也會標明所屬外掛。 在 /mcp 與 /plugin 按下重連後，若伺服器依然失敗或需要登入，頁面會停在原處直接秀出原因。全螢幕開啟 /plugin 時，有錯誤的外掛頁面一開始就會先顯示錯誤內容。

新功能

/config 與 /resume 等指令顯示與搜尋優化

平常切換設定、翻舊紀錄或看使用統計，幾個不順手的小毛病都整理好了。 在 /config 搜尋設定時，開頭符合輸入字的項目大多會排在最前面，打「effort」能找到 Model，打「dark」或「light」能找到 Theme。在 24 列高的全螢幕視窗裡，專案指示選擇器也會完整秀出全部四個選項，不再只剩一個。 打開 /resume 清單時，那些你只開了 /model 之類畫面就離開的空工作階段不會再混在裡面。 /stats 統計新活動時改以你所在的本地時區計算天數，不再用 UTC 時區切日。

新功能

/ultrareview 切錯資料夾會喊停，額度不足先提醒

執行 /ultrareview 做深度審查前，現在會幫你把目標專案跟花費額度兩邊都顧好。 要是終端機的殼層已經切進另一個程式碼庫，/ultrareview 不會再審錯程式碼或莫名失敗，而是直接停下來並報出兩邊的資料夾名稱。在 Team 與 Enterprise 方案上，如果本月剩餘花費上限低於一次審查的常見費用，費用確認視窗也會清楚告訴你還剩多少額度。

好比送洗衣服前店員不只再三核對單號，還會先提醒儲值卡餘額快不夠付這趟洗衣費。
問題修復

Grep 與 Read 等檔案讀取和格式錯誤修復

拿工具搜尋文字或讀取文件，幾種特定格式造成的誤判與漏字都修好了。 未開啟多行模式卻在搜尋規則裡放進換行符號時，Grep 不再誤報找不到相符內容，而是直接回報被拒絕的規則。 帶有位元組順序記號存檔的 Jupyter 筆記本，現在能被 Read 與 NotebookEdit 工具正常讀取，不再誤判為無效 JSON。 CLAUDE.md 與記憶檔裡只要含有 HTML 註解，裡頭的參考式連結定義不會再被漏掉。用 Read 指定頁碼範圍讀取跨頁掃描檔時，每頁也不會再同時重複顯示左右兩半。

問題修復

執行中的監控器不再把舊對話留在記憶體

開啟監控器持續盯著背景進度，過去它會把先前的對話內容一直佔在記憶體裡，直到監控結束才放掉。這個問題已經修好，執行中的監控器不會再這樣佔住先前對話。

問題修復

Claude Desktop 大 PDF 誤報修正

聊了一長串對話後，再加入超過上下文視窗大小的 PDF，回合過去可能會以「Prompt is too long」結束。這個問題發生在透過第三方供應商使用 Claude Desktop 的部分工作階段，排程任務除外，現在已修好。

問題修復

同名代理設定檔不再受檔案搜尋順序影響

同時存了兩份名字一樣的使用者或專案代理設定，到底會套用哪一份常常令人摸不著頭緒。過去這取決於檔案搜尋列出的先後順序，這個問題已經修好，不會再跟著搜尋順序飄移。

問題修復

無日誌檔時 claude daemon logs 不再卡死

問題修復

VS Code 複製指令與快捷鍵按鍵失靈修復

寫程式到一半想貼上一段指令、按住按鍵或順手用鍵盤移動游標，卻突然卡住或誤送出半截訊息，這幾個編輯器操作上的小毛病都修好了。 從程式碼區塊複製指令再貼到終端機時，尾巴不會再多帶一個換行符號害指令直接跑起來。按住 Enter 不放時，也不會再把打到一半的訊息或斜線指令提早送出去。 在問題卡按下 Enter 會正確選取當下聚焦的選項，不會誤送之前的答案。選過「Other」之後方向鍵也能繼續用，重新打開已回答的問題卡時也會停在你上次選的那一項。 在 macOS 上，重新命名框與對話框的 Cmd+A、C、V、X 與 Z 恢復正常。訊息框裡的 Ctrl+F 與 Ctrl+P 也能順利移動游標。

問題修復

VS Code 誤觸復原與拖曳關窗等問題修復

在 VS Code 畫面按鍵或滑鼠操作手快一點，不再莫名刪掉東西或把對話框弄不見。 長按 Enter 選 /rewind 不再未經確認就還原檔案。連點兩下 Remove 或 Delete，也不會跳過確認就刪掉記憶、MCP 伺服器或外掛市集。 反白選取對話框裡的文字不小心拖過視窗邊緣時，對話框不會再直接關閉並弄丟打好的內容；在計畫預覽裡快速連點兩下單字後，Add Comment 按鈕也不會再跟著消失。

新功能

VS Code 特殊符號路徑與選取行數不再算錯

把資料夾或程式段落指定給 Claude 看，傳過去的變動狀態與行數範圍現在對得上。 在 macOS 與 Linux 上，只要檔案路徑裡含有 #、? 或 %20（例如 C# 資料夾），未儲存的修改與新增問題不會再被漏掉。 整行選取文字時，選取標籤、@ 提及與傳給 Claude 的內容都不會再多算一行，檔案連結也不會再漏掉範圍的最後一行。

新功能

VS Code 分岔對話不再重跑排程與舊提問

在 VS Code 分出新對話線或清空畫面重新開始，舊設定與排程不再偷跑或沒提醒。 在面板裡分岔出去的對話，重新載入視窗後不會再自己重新執行先前還沒回覆的舊提問，也不會把原本對話的 /loop 排程再多跑一遍。 執行 /clear 清空後，如果當下工作階段仍在運作卻還沒套用新信任資料夾的 CLAUDE.md 與設定，現在會明確給出提示。

問題修復

VS Code 顧問訊息與側邊欄狀態等排版修復

VS Code 的側邊欄與聊天視窗裡，幾處容易看不見狀態、排版被切掉或提示太籠統的地方都修好了。 顧問呼叫不會再顯示成「Unsupported content type」，工作階段清單也會正常標出側邊欄聊天工作階段的狀態。 編輯筆記本儲存格列過長的字不會再被切斷，窄面板裡的權限規則不再擠成一團，問題卡上的標記變清楚，拒絕信任提示後選單也不會再把聊天畫面推歪。 登入遭到暫停的帳號時，畫面現在會顯示暫停通知與申訴連結，不再只給一個籠統的失敗訊息。

Now, except for skills configured with context: fork, running a skill with a model setting keeps subagents, forks, compaction, and /recap on the session's original model so they don't drift away.

Hiring a foreign-language tutor for a lesson used to force the household butler, accountant, and secretary to switch languages too, while now all those helpers stick to your usual language except in separately isolated classes.
FEATURE

Subagent model fallbacks and Bedrock regions carry over

When a subagent's designated model is temporarily unavailable and switches to a fallback model, any downstream agents it spawned previously could revert to different settings. Now a subagent's fallback model carries forward: any model-less agents and forked conversations it subsequently starts will run on that fallback model, and any further agents they launch will inherit its Bedrock region.

FEATURE

Self-hosted runner Bash records diffs on demand, with full-log option

After a terminal command finishes, there is no need to compute change details if nothing downstream uses them, though text transcripts may miss that section as a result. On self-hosted runners, Bash commands now skip computing the file diff whenever no subsequent feature needs it. If your organization's audit requires keeping every file diff, you can set bashEditDiffEnabled to true in managed settings. Once enabled, every command includes the full diff as before.

Convenience store registers used to print a long itemized receipt for every purchase, whereas now they skip printing when nobody needs to reconcile it and only print every receipt when reimbursement rules require a record.
FEATURE

Self-hosted runners halt startup when checkout hook exits 108

When a code-pulling script has already reported that it cannot continue, having the coordinator blindly retry the task on the next machine only wastes time. While a self-hosted runner prepares a session, if the repository checkout hook exits with status code 108, session startup now stops immediately without trying other runners.

FEATURE

Prompt hooks accept model aliases like haiku

When configuring prompt hooks, the model field now accepts model aliases such as haiku or sonnet.

FEATURE

/design-sync fallback uses only project Storybook

When running /design-sync and building the reference Storybook, it now only reads the version already installed in the project. This fallback build no longer uses versions outside the project.

FEATURE

Subagent progress summaries use fewer tokens via short notes on gateways

Running several background helpers from the command line to tackle tasks in parallel used to mean rereading the entire conversation history for every progress update, driving up usage on your bill. Now, when you sign in to a terminal session through a Claude apps gateway, subagent progress summaries are compiled from short notes only, using far fewer tokens (the text units AI processes and bills by).

FEATURE

VS Code adds /fork to branch after the last reply

Halfway through discussing architecture with Claude in VS Code, want to keep that shared context and open a separate branch to try another approach without repasting background info? That is the exact moment to run /fork. Typing /fork in a conversation branches off a new, independent conversation right after the last reply.

Saving a presentation as a new copy before editing a second version keeps the original file untouched in its folder, so any changes in the new version won't disrupt earlier progress.
FEATURE

VS Code adds /workflows to view the running agent map

Handing several agents different workflows to run in the background and want to see at a glance what is running right now? Type /workflows in VS Code to open the agent map directly and list the workflows currently running.
