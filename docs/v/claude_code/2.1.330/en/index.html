Claude Code 2.1.330

Released: 2026-11-20

Release notes

FEATURE

Enterprise account sign-in automatically applies organization settings

If you use an account at work managed by Anthropic Enterprise Admin Console, you can now sign in directly to Claude Code. Once you run claude auth login, Claude Code applies your organization's settings and routes connections through its designated cloud provider or gateway.

Think of tapping your company badge at the office door and having your laptop automatically join the internal network and load the department printer settings, without re-entering anything yourself.
FEATURE

Built-in easel module draws charts and metric results directly

When you want to turn numbers from a conversation or stats from external tools into a chart, you no longer need to write separate code yourself. Pro and Max plans on macOS and Linux, along with Team and Enterprise plans where available, now include the built-in easel module. Whenever you ask Claude to draw a chart or view MCP (a protocol that lets AI connect to external tools) metric results, easel renders the chart directly underneath. To turn off automatic charts, adjust the setting in /config.

Picture asking a coffee shop clerk to tally the bills and having them sketch a monthly sales line chart right below the receipt, which you can turn off whenever you only want plain numbers.
FEATURE

Sign-in URLs are shorter, with an option to print the full link

Previously, running /login, claude auth login, or claude setup-token in the terminal often printed a claude.ai sign-in link long enough to wrap across several lines. The sign-in URLs shown by these three commands are now much shorter and cleaner to copy. If the short link throws an error or a script needs to parse parameters from the URL, prepend the environment variable CLAUDE_CODE_FULL_SIGN_IN_LINK=1 before the command to print the full URL instead: CLAUDE_CODE_FULL_SIGN_IN_LINK=1 claude auth login.

Like shortening a long URL before sending it to a friend: you use the compact version most of the time and switch back to the full address only when you need to inspect its parameters.
FEATURE

Self-hosted runner adds --start-dir to set the working directory

Large repositories often contain several subprojects; to have Claude start in one specific folder, pass the --start-dir flag or set the SELF_HOSTED_RUNNER_START_DIR environment variable. Even with a starting directory set, settings and hooks (small programs triggered by specific events) still load the same way as before without getting skipped.

Imagine walking into a large mall to visit just one boutique; your path stays inside that shop, yet the mall's intercom announcements and entry rules still apply as usual.
FEATURE

Notices added for plugin repository scope and denied access

When installing a plugin failed during a cloud or self-hosted runner session, it used to be hard to tell what went wrong. Now a notice appears automatically whenever a plugin marketplace cannot be fetched because its repository is outside the session's scope. On a self-hosted runner, if Anthropic-managed Git refuses access to a plugin's own repository, the notice also names the plugin and tells you what to do next.

Treat this like requesting special-collection materials at a library and having the desk not only say they cannot fetch them, but also name which book lacks permission and who to ask for access.
FEATURE

Plugin JSON install output adds command error and stderr fields

For developers parsing install results: when using automated scripts with claude plugin install --json to install plugins, it used to be hard to tell from the output whether a plugin's own install command ran into trouble. The returned output now indicates whether the install command wrote to stderr, and whether it exited with an error, was killed, or timed out.

A delivery receipt with "delivery timed out" and "box opened" fields added lets you tell what happened from the slip alone without opening the package.
BUGFIX

Self-hosted runner /metrics adds dispatch timing and fixes poll age

For operators monitoring self-hosted runners: the /metrics endpoint now includes two timing metrics to track wait times after dispatch, along with a fix for a misleading legacy value. Runners spawned by an orchestrator now record the seconds from work order issuance to registration completion, while runners started for a specific session record the seconds from work order issuance to taking over their first session. Also, the seconds since the last successful poll previously misreported as 0 when a runner had never polled successfully, and that issue is now fixed.

BUGFIX

Long conversation compaction and WebFetch no longer freeze for minutes

Cases where the terminal suddenly froze for several minutes after a long conversation or waking your computer are now fixed. After compacting an overly long conversation history, Claude Code no longer freezes for several minutes immediately afterward. Fetching certain pages with WebFetch no longer stalls the session for minutes or unexpectedly returns an empty result. On Linux and WSL, sending the first prompt after sleeping for two minutes or more no longer waits three minutes on a connection that has already died.

BUGFIX

ExitWorktree no longer deletes another session's copy

When running tasks across several terminals in parallel, exiting used to occasionally delete a workspace still in use elsewhere. Running ExitWorktree or leaving from the exit dialog no longer deletes a worktree (a Git feature for keeping parallel copies of a project) that another session is actively using.

BUGFIX

Fixes for concurrent saves and full-disk backups

Running multiple windows or commands at the same time no longer causes local records and backups to overwrite one another. When several Claude Code processes save user settings simultaneously, changes are no longer lost. Running multiple claude plugin commands at the same time no longer causes plugins to vanish from the installed list. When multiple task updates are written at the same time, task dependencies and metadata are no longer lost. When the disk is full, incomplete backups of ~/.claude.json are no longer kept or allowed to displace intact older backups.

BUGFIX

More reliable session resuming and claude -p write-failure handling

When you use commands to pick up where you left off or build automation pipelines, unexpected conditions no longer cause silent failures or blank sessions. When the last saved message has a missing or invalid timestamp, --continue and --resume no longer open an empty session or fail outright. When running via claude -p --continue, environment variables written by a SessionStart hook are no longer lost. When writing claude -p output to a file on a full disk, it now prints an error and exits with status code 1 instead of silently exiting with status code 0; however, a full remote NFS mount may still go undetected.

BUGFIX

Fixes for MCP tool schemas and shared subagent connections

Unexpected errors and dropped connections when a session loads multiple MCP tools or subagents at once are now resolved. When many MCP tools carry input schemas that the API rejects, turns no longer fail with "JSON schema is invalid", and session files no longer bloat by several megabytes. When subagents each declare the same MCP server, one finishing no longer shuts the server down, so other subagents and the main session can keep using it. When an enterprise allowlist or denylist excludes the built-in chart tool easel, it still stays blocked. However, the "MCP server blocked by enterprise policy: easel" warning no longer appears at every startup.

FEATURE

Large ignored folders on Linux no longer slow down Bash commands

In slower repositories packed with large ignored directories like node_modules, running commands often meant waiting for seconds. On Linux, this also stopped file diffs from showing for the rest of the session, and that issue is now fixed.

FEATURE

Faster Windows search and Bash, plus clearer drive errors

Running searches or commands in a Windows session is now much smoother, and hitting an unverifiable drive no longer leaves you with a confusing error. On machines without custom startup files, if Git Bash takes 10 to 60 seconds to start, the remaining Bash commands in the same session no longer slow down along with it. When Grep and Glob search local paths, the built-in ripgrep no longer opens a separate console each time, making searches faster. When a session folder sits on a drive that cannot be verified, the error message now explains why and tells you whether retrying can help.

BUGFIX

File rewinds, permission notes, and typed text stay intact

Whether you just edited a file, added notes in an approval prompt, or were in the middle of typing, your history and text now stay safely preserved. Right after a turn that modified a file, when two queued prompts or stacked skills run together, /rewind no longer mistakenly restores an earlier version. Text and images attached when approving a permission prompt are no longer dropped even if the approved command or tool subsequently fails. When a plan arrives in fullscreen mode, the rest of the text you were halfway through typing and had not sent yet is preserved in full.

BUGFIX

Fixes for claude.ai connector mentions, removal, and checks

Working with claude.ai connectors in the terminal used to hit snags when mentioning resources, sharing URLs, or checking connections. When you @-mention MCP resources from claude.ai connectors and plugin servers in the terminal prompt box, those resources are now attached properly. Two claude.ai connectors with different names are no longer dropped even when they share the same server URL. During the "Connect on claude.ai" check in /mcp, as long as claude.ai has a connector at the matching server URL without its query parameters, it no longer falsely reports as not connected. When removing a claude.ai connector with claude mcp remove, it now clearly tells you to turn it off in /mcp or delete it on claude.ai instead.

BUGFIX

Chrome restores connection status after brief disconnects

Even when your browser was open and signed in, a brief connection issue used to leave Claude in Chrome stuck in the "not connected" state. That issue is now fixed, so it no longer gets stuck on the disconnected screen.

BUGFIX

System prompts and fallbacks stay aligned after model switches

Whether you pin a model at startup, switch mid-conversation, or spin up nested subagents, model instructions and fallbacks now stay aligned. When starting a terminal session on Amazon Bedrock Mantle with no model selected, a pinned Opus model is no longer ignored, and it no longer keeps calling an unavailable default model after announcing a fallback. When you switch models after /context and before sending the first message, the system prompt no longer keeps the old model's instructions. When switching models mid-turn, Claude occasionally replied to its commit attribution reminder and ended the turn early, which is now fixed; however, this can still happen if managed organization settings enforce a pull request attribution line. In plan mode under opusplan or haiku, subagents and forks spawned by a subagent no longer mistakenly run on the plan-mode model.

FEATURE

Less freezing in Code Mode, plus image viewing guidance

Running long scripts or handling large batches of files in Code Mode now comes with far fewer screen freezes and misleading errors. In projects with path-scoped rules or Read deny rules, scripts no longer pause for a long stretch after reading hundreds of files at once. After a subagent's script makes thousands of tool calls, the terminal freezes for far less time. After pressing Esc to interrupt, "Interrupted" now appears under the stopped command instead of a wall of red error text. Claude now also knows how to view images and PDFs in this mode.

BUGFIX

Fixes for Code Mode chart tool and cache restoration

Several state and resource tracking bugs when using Code Mode with tools, auto mode, or compacted conversations are now fixed. Calling the built-in chart tool in this mode no longer fails; in auto mode and bypass permissions mode, an MCP tool's request from a script to end the turn now takes effect properly. In auto mode, if a mod adds a note after a script loads a skill, earlier thinking and the prompt cache are no longer cleared and rewritten. After pressing Esc and running /compact, files read by a script are restored properly; checking /context before Claude's first reply no longer undercounts system tools.

BUGFIX

Background Subagent Stop and MCP Task Tracking Fixes

When you send tasks or agents to run in the background, stop signals and permission states now stay in sync. Stopped background subagents no longer start back up on their own. In sessions started by an app or the SDK, Claude no longer keeps waiting for a background agent that was stopped just as it finished. Background sessions no longer fall back to their previous permission mode when waking up after approving a plan. When you move a session to the background, a running MCP task is no longer falsely reported as stopped, and the background session can continue following its progress, except when the server uses stdio or sets custom headers.

FEATURE

More Accurate Terminal Logs and Mobile Status for Remote Control

When switching between your phone or the web and your computer's terminal in the same conversation, on-screen prompts and button states now match up. When you tap Stop from a phone or the web to end a background agent, the log note shown in the terminal no longer looks as if you typed and sent it yourself. When you turn on Remote Control mid-conversation, the mobile apps no longer hide the Diff and pull request buttons, or show an already stopped session as working.

BUGFIX

Esc Cancels Stalled Language Server Calls; Startup Failures Also Fixed

When the language server you rely on for editing is slow to respond or still starting up, you no longer have to wait indefinitely or hit immediate errors. When an LSP tool call hangs on an unresponsive language server, pressing Esc immediately cancels the wait. In addition, when multiple calls and edits arrive while a language server is still starting, tool calls and diagnostics no longer fail together.

FEATURE

Better Grouping and Reconnect Error Display in /mcp and /plugin

Opening /mcp or /plugin to manage plugins and external tool servers now makes finding sources and checking errors much easier. /mcp no longer lists all plugin servers as built-in. Those provided by plugins appear under "Plugin MCPs", --mcp-config and built-in servers go under "Other MCPs", and each server's page names its plugin. After clicking Reconnect in /mcp and /plugin, if a server still fails or requires sign-in, the page stays open and shows the cause right away. When opening /plugin in fullscreen mode, a plugin page with errors now starts by showing those errors.

FEATURE

Improved Display and Search for /config, /resume, and /stats

Several minor friction points when toggling settings, browsing past sessions, or checking usage stats have been cleaned up. When searching settings in /config, most items whose names start with what you type appear first; typing "effort" finds Model, and typing "dark" or "light" finds Theme. In a 24-row fullscreen window, the Project instructions picker now displays all four choices instead of only one. When opening the /resume list, empty sessions where you only opened a screen such as /model and left are no longer mixed in. /stats now counts days for new activity in your local time zone instead of splitting days by UTC.

FEATURE

/ultrareview Stops on Wrong Folder and Warns on Low Spend Limit

Before running /ultrareview for a deep review, both your target project and spending budget are now checked upfront. If your terminal shell has moved into another repository, /ultrareview no longer reviews the wrong code or fails inexplicably; instead, it stops and names both folders. On Team and Enterprise plans, if your remaining monthly spend limit is less than what a review usually costs, the cost confirmation dialog also clearly tells you how much limit is left.

Before taking in your laundry, the clerk double-checks the ticket number and warns you if your prepaid card balance is running too low to cover the wash.
BUGFIX

Grep, Read, and File Format Parsing Fixes

Several misdetections and dropped items caused by specific formats when searching text or reading files have been fixed. When a line break is included in a search pattern without multiline mode enabled, Grep no longer falsely reports no matches and instead reports the rejected pattern directly. Jupyter notebooks saved with a byte order mark can now be read properly by the Read and NotebookEdit tools instead of being flagged as invalid JSON. Link reference definitions inside CLAUDE.md and memory files are no longer dropped when the file contains an HTML comment. When using Read with a page range on a scanned two-page spread, each page no longer shows both halves duplicated together.

BUGFIX

Running Monitors No Longer Keep Earlier Conversations in Memory

When you start a Monitor to watch background progress, it used to hold earlier conversation content in memory until the monitor ended. This issue is fixed, so running Monitors no longer keep earlier conversations in memory like that.

BUGFIX

Fix for False Prompt Length Errors on Large PDFs in Claude Desktop

After a long conversation, adding a PDF larger than the context window could end the turn with "Prompt is too long". This happened in some Claude Desktop sessions on third-party providers, other than scheduled tasks, and is now fixed.

BUGFIX

Same-Name Agent Files No Longer Depend on File Search Order

When two user or project agent files declare the same name, it was often unclear which one would take effect. Previously, the choice depended on the order the file search listed them; this is now fixed so it no longer drifts with search order.

BUGFIX

claude daemon logs no longer hangs when no log file exists

Running claude daemon logs inside a Git repository folder previously hung indefinitely whenever no log file existed yet. This is fixed, and the command no longer waits forever.

BUGFIX

Fixes for Edit hook commands, diagrams, and layout rendering

When editing settings, reading conversation layouts, or viewing diagram artifacts, text could occasionally vanish, styles could go missing, or edits could get blocked—this batch of display and editing bugs is now fixed. Within the same Markdown paragraph, if a backslash before an emoji appears further down after bold or italic text, the one or two characters immediately following that formatted text are no longer hidden. When editing certain valid hook commands in Claude settings files, the Edit tool no longer refuses the change. Mermaid diagrams in HTML artifacts now preserve their original line breaks and stereotypes (annotations in class diagrams indicating a class's role) instead of dropping them.

BUGFIX

WebFetch now honors /effort when a gateway blocks the small model

When summarizing web pages with WebFetch, if the gateway refused the small fast model, your /effort thinking level was previously ignored. This is fixed, and WebFetch now follows your /effort setting in that situation as well.

BUGFIX

Fast mode billing supported for claude -p on Google Cloud

When running claude -p on Google Cloud Agent Platform with the model coming from ANTHROPIC_MODEL or a settings file, --settings '{"fastMode":true}' was previously ignored. Fast mode now takes effect and bills at the fast mode rate.

BUGFIX

forceLoginOrgUUID no longer blocks startup on temporary disconnects

When forceLoginOrgUUID was set to enforce logging into a specific organization, a single temporary server error or dropped connection previously caused startup to be refused. This is fixed, so a one-off transient issue no longer locks you out.

BUGFIX

Commands like /design-login now show an appeal link for on-hold accounts

When an account was on hold, running /install-github-app or /design-login previously showed only a generic failure message with no clue where to go next. This is fixed, and it now displays the on-hold notice and an appeal link.

BUGFIX

Self-hosted runners no longer lose work state on handoffs and restarts

When a long task hits a machine restart, mid-run handoff, or startup hang, losing prior progress and cache is the worst-case scenario—handoff and continuity bugs across these cases are now fixed. When a failure report is lost or a session is returned to the same runner, the runner no longer ignores it until exit. In sessions with telemetry off, tool calls no longer vanish without a result after a new runner takes over a permission prompt. Prompt cache and earlier thinking are now preserved when the list of repositories a restart cannot prepare changes. Resumed large repositories with --push-outcome-on-release set no longer drop previously pushed work. Sessions are no longer falsely shown as working when Claude Code hangs on every start and --startup-timeout-min is set between 2 and about 6.

BUGFIX

pkill -f no longer kills itself on Linux self-hosted runners

Trying to clean up background processes by keyword in the terminal only to accidentally shut down your own working environment is a nerve-wracking hazard that is finally gone. Previously, running pkill -f in a Linux self-hosted runner session could kill its own shell with exit code 144 or even take down the runner; when using a pkill that supports --ignore-ancestors, it no longer kills itself.

BUGFIX

Scheduled tasks on self-hosted runners can now notify owners with telemetry off

Setting up a scheduled job only to receive no reminder afterward—only to find out it was because telemetry was off or a third-party provider was used—is now fixed. Previously, scheduled tasks on self-hosted runners had no tool available to notify their owner when telemetry was disabled or a third-party provider was used; a notification tool is now available in these environments.

FEATURE

Self-hosted runner spawn-runner hooks now start in parallel

Having free slots on a machine to take new tasks only to get stalled behind a slow startup script is a bottleneck many operators have hit. Previously, a single slow spawn-runner hook could hold up the entire self-hosted runner orchestrator; now, as long as slots remain free, the orchestrator polls every 4 to 6 seconds to claim sessions. New spawn-runner hooks can also launch without waiting for earlier ones to finish, with a default limit of 4 concurrent hooks per orchestrator, adjustable via --hook-concurrency. If your hook cannot run alongside another, just set it to 1.

Airport security lanes no longer wait for the traveler ahead to pack up their laptop before waving the next person through, calling people forward and screening them in parallel whenever a spot opens.
FEATURE

Clearer startup checks and 403 log messages for self-hosted runners

When a machine stops running in the middle of the night, opening the log file only to find a confusing error message takes the most time to troubleshoot. When hitting a 403 error such as one blocked by an IP allowlist, most log lines now start with the reason returned by the server instead of mislogging it as a secret or token (authorization credential) error, so anyone with keyword alerts should update their matching text. The warn mode for repository settings no longer stops at the first finding; it reports up to 50 findings per session and says so if it stops early. Runners started on a full disk no longer grab sessions and fail them—unless started from a work order, they wait for space first and exit with status code 1 only after a full minute with no task. When missing Git credentials cause startup to fail, the error now explains whom to ask for help and what to do if the repository is wrong. Sessions on Amazon Bedrock or Google Cloud Agent Platform also notify you when they start on a fallback default model because your account refused the original default.

BUGFIX

Skipped scheduled task notice now tells you to start with --resume

After a scheduled task is skipped, the old notice often misled people into thinking typing /resume inside a running session would recover it, only for the task to still not run. This is fixed, and the notice now clearly states to start Claude Code with --resume.

BUGFIX

claude plugin validate no longer falsely flags hooks as invalid

When checking plugin modules with AbovePrompt or AbovePromptList hooks, claude plugin validate used to falsely warn that those hooks never run in VS Code. This issue is fixed, and validation no longer raises this false warning.

BUGFIX

/design-sync no longer mistakenly deletes files renamed right after upload

When running /design-sync to sync design files, if Claude Design stored a newly uploaded file under a different name, the sync tool used to delete it. This issue is fixed, and newly uploaded files are no longer mistakenly deleted.

BUGFIX

Automatic retry restored when generation limit is set too high

For developers integrating with models: when sending a request, if the single-generation limit is higher than what the model or gateway accepts, you no longer need to resend it yourself. Version 2.1.329 removed this automatic retry mechanism, and this release restores it.

PERF

Faster file diffing

Checking what changed in a file no longer takes as long.

FEATURE

macOS sandbox deny-list errors now name long lists and how to shorten them

When setting too many sandbox deny rules on macOS exceeded the limit, it used to only report an error without telling you which list was too long. The error message now names the overly long lists directly and explains how to shorten them.

FEATURE

Recurring scheduled tasks and /loop limit extended to 30 days

When letting Claude periodically inspect your project or check status in the background, it used to stop after running for more than 7 days. Now, as long as the session stays open, recurring scheduled tasks and /loop can run continuously for up to 30 days, and they tell you in advance when the task will end. If you created scheduled tasks before this update, they still keep their original 7-day limit.

An automatic plant waterer gets its maximum schedule extended from a week to a month, with the end date shown on the screen in advance, while the older potted plants still wrap up after seven days as before.
FEATURE

More high-risk rm delete commands now require approval

Accidentally letting an AI run a delete command that wipes out an entire project or home directory has always been one of the scariest mishaps. Now, more rm commands targeting the root directory, home directory, a top-level folder, or the current working folder require your approval before running. If such a command runs in an unattended environment where nobody can reply to confirm, Claude Code refuses to execute it outright.

A dual-key lock now sits on the switch next to a building's main power supply, so nobody can press it when no one is on site to approve and sign off.
FEATURE

deniedMcpServers now hides only the named connector

When a company or individual wanted to block a claude.ai connector in settings via deniedMcpServers, blocking by name used to hide other connectors under the same server URL as well. Now, configuring by name hides only the specific connector you named, while other connectors at the same URL remain visible. If you truly want to block all connectors under that URL at once, deny the full URL directly in settings instead.

Building security used to block every coworker from a visitor's company whenever that visitor was blacklisted, but now it turns away only that person; to refuse the entire company, you block its business registration number directly.
FEATURE

claude --teleport prints commands in some setups

When you run claude --teleport in certain setups, it no longer switches branches for you and instead prints the Git commands so you can run them yourself. If you run it with the -p flag, the command exits with status code 1 until the branch switch is complete.

A rental car agency hands you printed lane-change instructions to handle on your own, and without manual confirmation, it won't let you pull out until you are in the designated lane.
FEATURE

Unrecognized models with sonnet or haiku use shorter prompts

When you enter a custom model name on a self-hosted gateway or third-party platform, any name containing "sonnet" or "haiku" used to receive the long system prompt even if Claude Code did not recognize the full name. Now those unrecognized names get the more concise system prompt, just like any other unknown model. If you want every model to receive the full system prompt, set the environment variable CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0.

At a café counter, ordering an unfamiliar custom drink with "latte" in its name used to get you the full elaborate presentation, whereas now it comes in a standard simple cup unless you specifically ask for the full setup.
FEATURE

Non-forking skills keep subagent and compaction models unchanged

When you specify a model setting inside a custom skill file, invoking that skill previously switched any spawned subagents, forked conversations, compaction, and /recap to that model as well. Now, except for skills configured with context: fork, running a skill with a model setting keeps subagents, forks, compaction, and /recap on the session's original model so they don't drift away.

Hiring a foreign-language tutor for a lesson used to force the household butler, accountant, and secretary to switch languages too, while now all those helpers stick to your usual language except in separately isolated classes.
FEATURE

Subagent model fallbacks and Bedrock regions carry over

When a subagent's designated model is temporarily unavailable and switches to a fallback model, any downstream agents it spawned previously could revert to different settings. Now a subagent's fallback model carries forward: any model-less agents and forked conversations it subsequently starts will run on that fallback model, and any further agents they launch will inherit its Bedrock region.

FEATURE

Self-hosted runner Bash records diffs on demand, with full-log option

After a terminal command finishes, there is no need to compute change details if nothing downstream uses them, though text transcripts may miss that section as a result. On self-hosted runners, Bash commands now skip computing the file diff whenever no subsequent feature needs it. If your organization's audit requires keeping every file diff, you can set bashEditDiffEnabled to true in managed settings. Once enabled, every command includes the full diff as before.

Convenience store registers used to print a long itemized receipt for every purchase, whereas now they skip printing when nobody needs to reconcile it and only print every receipt when reimbursement rules require a record.
FEATURE

Self-hosted runners halt startup when checkout hook exits 108

When a code-pulling script has already reported that it cannot continue, having the coordinator blindly retry the task on the next machine only wastes time. While a self-hosted runner prepares a session, if the repository checkout hook exits with status code 108, session startup now stops immediately without trying other runners.

FEATURE

Prompt hooks accept model aliases like haiku

When configuring prompt hooks, the model field now accepts model aliases such as haiku or sonnet.

FEATURE

/design-sync fallback uses only project Storybook

When running /design-sync and building the reference Storybook, it now only reads the version already installed in the project. This fallback build no longer uses versions outside the project.

FEATURE

Subagent progress summaries use fewer tokens via short notes on gateways

Running several background helpers from the command line to tackle tasks in parallel used to mean rereading the entire conversation history for every progress update, driving up usage on your bill. Now, when you sign in to a terminal session through a Claude apps gateway, subagent progress summaries are compiled from short notes only, using far fewer tokens (the text units AI processes and bills by).

FEATURE

VS Code adds /fork to branch after the last reply

Halfway through discussing architecture with Claude in VS Code, want to keep that shared context and open a separate branch to try another approach without repasting background info? That is the exact moment to run /fork. Typing /fork in a conversation branches off a new, independent conversation right after the last reply.

Saving a presentation as a new copy before editing a second version keeps the original file untouched in its folder, so any changes in the new version won't disrupt earlier progress.
FEATURE

VS Code adds /workflows to view the running agent map

Handing several agents different workflows to run in the background and want to see at a glance what is running right now? Type /workflows in VS Code to open the agent map directly and list the workflows currently running.

Opening a subway map works the same way: instead of clicking into every conversation thread to dig through logs, one map shows which lines are currently in service.
FEATURE

VS Code adds setting to stop Esc from interrupting Claude

Used to tapping Esc in the editor to dismiss popups or clear a selection, only to accidentally stop a running Claude? You can now turn off VS Code's claudeCode.escapeStopsClaude setting so Escape does not stop Claude.

BUGFIX

VS Code adds setting to unpin prompts so they scroll away

When reading a long Claude reply, having your original prompt pinned to the top of the screen takes up valuable reading space. You can now use VS Code's claudeCode.pinPrompt setting to let your prompt message scroll away with the page. Great for screens where you want the entire layout dedicated to reading long text.

FEATURE

VS Code adds threshold setting for context usage indicator

Find it distracting when VS Code's context usage indicator pops up after just a few lines of conversation? You can now use the claudeCode.contextUsageThreshold setting to choose how much context must be used before the indicator appears. Open VS Code's settings.json and set claudeCode.contextUsageThreshold to your preferred display threshold.

Your phone does not rush to flash red low-battery text at 90%—you can set how much power is left before the alert lights up, sparing you from staring anxiously at a progress bar right after startup.
FEATURE

VS Code Open in Side Bar command adds prompt argument

Want to bind a frequent prompt to a keyboard shortcut or your own extension so one press opens the side bar with the prompt filled in? VS Code's "Open in Side Bar" command now has a prompt argument. Pass prompt when calling this command from a keybinding or extension to open the side bar with your specified prompt.

FEATURE

VS Code session group menu adds Move up and Move down

Have several session groups open at once and want to move your most-checked one higher up so it is easier to find? The session group menu now includes Move up and Move down options, letting you reorder groups with a click.

FEATURE

VS Code proposed change buttons and tab focus stay in place

When coding in VS Code while reviewing changes proposed by Claude, buttons and keyboard focus no longer jump around. Sending prompts in a connected terminal session no longer makes VS Code repeatedly switch away and steal focus into the terminal; a slow-loading Claude tab also no longer steals keyboard focus while you are typing in another file. After dragging a proposed diff window into a new window, the Accept and Reject buttons finally work properly. "Accept Proposed Changes" and "Reject Proposed Changes" also now appear only on the proposed diff view, instead of covering the chat, terminal tab, or other files.

BUGFIX

VS Code fixes command copying and broken key shortcuts

These editor interaction glitches—getting stuck or accidentally sending half-written messages when pasting a command, holding a key, or moving the cursor with the keyboard mid-coding—are now fixed. Copying a command from a code block and pasting it into the terminal no longer includes a trailing newline that immediately runs the command. Holding down Enter also no longer sends a half-written message or a typed slash command prematurely. Pressing Enter on a question card now selects the currently focused option instead of sending an earlier answer. Arrow keys continue working after picking "Other", and reopening an answered question card lands on your previous pick. On macOS, Cmd+A, C, V, X, and Z in the rename box and dialogs work again. Ctrl+F and Ctrl+P in the message box also move the cursor smoothly.

BUGFIX

VS Code fixes accidental rewind and drag-to-close dialog bugs

Moving quickly with keys or the mouse in VS Code no longer unexpectedly deletes items or makes dialogs vanish. Holding Enter on /rewind no longer restores files without confirmation. Double-clicking Remove or Delete also no longer skips confirmation to delete a memory, MCP server, or plugin marketplace. Accidentally dragging a text selection past the edge of a dialog no longer closes the dialog and loses typed text; the Add Comment button in the plan preview also no longer disappears after a fast double click on a word.

FEATURE

VS Code fixes special-character paths and selection line counts

When pointing Claude to a folder or code snippet, the change status and line ranges passed along now match up. On macOS and Linux, unsaved changes and new problems are no longer missed when a file path contains #, ?, or %20 (such as a C# folder). When selecting whole lines of text, the selection chip, @-mentions, and what is sent to Claude no longer count one line too many, and file links no longer leave out the last line of a range.

FEATURE

VS Code forked conversations no longer re-run schedules or old prompts

When you branch off a new conversation or clear the screen to start over in VS Code, old settings and schedules no longer run unexpectedly or go without notice. Conversations forked in the panel no longer re-run an old, unanswered prompt by themselves after a window reload, nor do they run the original conversation's /loop schedules a second time. After running /clear, if the current session is still running without applying CLAUDE.md and settings from a newly trusted folder, a clear notice is now shown.

BUGFIX

VS Code fixes for advisor messages, sidebar status, and layout

Several issues in VS Code's sidebar and chat window—where status was hidden, layouts were cut off, or notices were too vague—have been fixed. Advisor calls no longer show as "Unsupported content type", and the session list now properly displays the status for the sidebar chat's session. Long lines in the Edit Notebook Cell row are no longer cut off, permission rules no longer crowd together in a narrow panel, marks on question cards are clearer, and menus no longer shift the chat view out of place after a declined trust prompt. When signing in to an account on hold, the screen now shows the on-hold notice and appeal link instead of just a generic failure message.
