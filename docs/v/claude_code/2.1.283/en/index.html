Claude Code 2.1.283

Released: 2026-09-25

Release notes

FEATURE

Enterprise Gateway Adds Model List Matching and Load Testing

Organizations running an internal gateway to centrally manage AI requests now have finer control options.

Enabling CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 attaches x-claude-code-prompt-id to headers sent to the gateway, making it easy to trace all requests originating from the same prompt. A new availableModelsMatch setting only permits exact matching model versions when set to "exact", preventing unreviewed new versions from going live directly. Meanwhile, deniedModels blocks specific models even if they are allowed in availableModels. The gateway also adds a load_test_mode load-testing mode that returns mock responses immediately after signing requests without forwarding them upstream, and upstream providers now officially support Amazon Bedrock Mantle endpoints.

FEATURE

Prompt Audit Tool Automatically Checks Outdated Configurations

After upgrading to a new model, you can now run /doctor prompt-audit or /checkup prompt-audit to check whether configuration files in your project are outdated.

This tool thoroughly scans project CLAUDE.md files, skills, custom agents, and commands to catch stale prompt patterns written for older models. In the audit report, broken paths, outdated commands, and conflicting instruction files are prioritized at the top, while officially supported thinking keywords are preserved intact.

Think of a home inspector walking through a house with a tape measure to check the finishes, flagging worn-out pipes on a repair list while leaving compliant and sound structures untouched.
FEATURE

Plugin Validation Enhances Path Checks and Lists Marketplace Removal Cascades

Command validation and reporting are now clearer during plugin development.

claude plugin validate fails when encountering names in marketplace.json that cannot be installed, or when paths for outputStyles, themes, monitors, or lspServers are missing or extend outside the directory. When loading via --plugin-dir fails, plugin_errors entries in the stream-json system/init message now indicate the unloaded directory under path. claude plugin details lists MCP (Model Context Protocol) servers declared in plugin.json. claude plugin marketplace remove lists plugins that will be removed alongside the target. claude plugin eval refuses to run and reports the version when Git is below 2.31.

BUGFIX

Corrupted Installed Plugin Lists Are Automatically Backed Up and Container Cache Loading Is Fixed

After moving home or configuration directories inside dev containers, user-installed plugins and marketplaces will no longer fail to load due to stale cache locations.

If installed_plugins.json contains entries with invalid IDs, it can now still be reloaded; if it contains records unparseable by the current version, claude plugin commands identify the entry and explain how to restore it without overwriting the file. Only when the entire file is unreadable will its contents be preserved in an adjacent file before rebuilding, with claude plugin list reporting its location. Unversioned plugins recover to their originally installed revision upon cache loss. When two plugin IDs differ only by case, uninstalling one that lacks an enabledPlugins entry in scope will no longer accidentally delete the other plugin along with its options and secrets. If a plugin hosting a skill fails to load, the Skill tool now explains that the plugin could not load rather than misreporting that the skill is not installed.

BUGFIX

MCP Servers Receive Real-Time Background Progress Updates and Transient Disconnection Fixes

When connecting to MCP servers, connection reliability and background progress notifications are now significantly improved.

Long-running tools moved to the background now continuously deliver progress notifications to the background tasks view instead of silently dropping them. If a stateless remote MCP server temporarily returns HTTP 404—such as during a proxy redeployment—the bug where it remained marked connected but unusable for the rest of the session has been fixed. Stdio MCP servers that are still starting when a session ends are now properly shut down. For servers without a valid URL, /mcp no longer presents invalid login options, and claude mcp add, add-json, and remove no longer falsely report success when writing to user or local configuration files fails.

FEATURE

MCP Tool List Supports Pagination and Automatically Persists Returned Images

Managing external tools and viewing execution results now offer better presentation and file integration.

Running /mcp to inspect MCP tools displays more items per screen, supports mouse wheel scrolling and page navigation keys, and marks organization-blocked tools with a warning icon. Images returned by MCP tools are now automatically saved as physical files, making them easy to open directly via commands or file-reading tools. When running /context to inspect context size, server instructions are broken into a dedicated row and counted toward the total context size. Enabling OTEL_LOG_TOOL_CONTENT=1 includes outputs from MCP tools, WebFetch, and WebSearch in tool.output telemetry events. The post-authorization success page also features a centered layout, dark mode, and updated artwork.

FEATURE

Terminal Lists Add Mouse Navigation and Unified Selection Actions

Navigating lists during terminal tasks and commands is now much smoother.

/tasks displays status icons and full task details, keeps headers and key hints pinned when multiple tasks exist, and supports page navigation keys, mouse wheel scrolling, and clicks. Menus including /help, /hooks, /copy, /chrome, /memory, /ide, /release-notes, /rewind, /diff, /remote-env, and /plugin also support mouse and page navigation. When searching /skills or /artifacts, list pointers dim appropriately, and truncated messages from other sessions in fullscreen mode can be clicked to expand. Markdown links in Warp terminal can now be clicked to open. /rewind and /diff now use shared select:* actions while retaining messageSelector:* and diff:* bindings, and the /workflows execution list adopts a half-height layout with a pinned header.

BUGFIX

Custom Keybindings Add Spelling Checks and Fix Rapid Typing Delays

Key responsiveness and configuration validation are now more accurate when customizing shortcuts or typing rapid command sequences.

If a modifier key is misspelled as an invalid name like ctl+k in keybindings.json, the system now logs a warning in debug logs with correction suggestions. When rapidly pressing or pre-typing keystrokes over SSH or terminal multiplexers, input is no longer processed against stale state. The built-in shortcuts guide corrects the chord timeout to three seconds and no longer calls cmd an alias for meta. Rebinding or unbinding footer:openSelected in keybindings.json no longer leaves a lingering "Enter to view" prompt at the bottom, and terminal suggestions appear less frequently after being ignored twenty consecutive times, resuming their original cadence once accepted.

BUGFIX

Vim Mode Fixes Cursor Placement for Extra-Long Prompts and Action Repeats

For users editing long prompts with Vim mode in the terminal, cursor positioning and action replay bugs have been resolved.

Previously, loading an extra-long prompt exceeding 10,000 characters in normal mode often positioned the cursor past the end of the text; it now lands cleanly within the text boundaries. Repeating actions with . no longer drops Shift+Enter linebreaks, places the cursor inside accented characters, or replays older edits after 3J or a Visual-mode J on the final line. Pressing V to select an entire line followed by p to paste now positions the cursor on the first non-whitespace character. Whitespace indentation handling when joining lines with J, as well as cursor movement when joining on the last line, are now fixed to match native Vim.

FEATURE

Sandbox Configuration Adds Granular Fault Tolerance and Prevents Protected Directory Deletion

File permission safeguards and configuration fault tolerance are strengthened under sandbox protection.

When using PowerShell tools on Windows, an issue where cmd /c rd, rmdir, del, or erase could bypass protections to delete drive roots, home directories, or folders rejected by Remove-Item has been fixed. If centrally managed sandbox settings contain an invalid nested field, only that invalid entry is blocked while all valid sandbox rules continue to apply normally. Launching from subdirectories of a Git repository no longer misidentifies auto-memory note writes as sensitive files, and Git operations inside the sandbox no longer prompt credential helpers to store temporary proxy authentication credentials.

BUGFIX

Git Worktrees Fix Certificate Verification and Optimize Runner Workflows

When deploying tasks with worktrees or self-hosted runners, Git credentials and automation workflows are safer.

Passing CA certificates to Git through the GIT_CONFIG_COUNT environment variable no longer interrupts worktree checkouts due to certificate verification failures, such as when downloading Git LFS files. In self-hosted runner environments, lifecycle hooks executing Git commands skip repository Git LFS pre-push hooks and ignore system-level writable hook paths; they also no longer sign commits if --configure-git is not used. The runner's own Git now consistently verifies routes to Anthropic Git, and warning messages clearly state where GIT_SSL_CAINFO and GIT_SSL_NO_VERIFY take effect.

BUGFIX

Model Fallback Retries Original Configuration and Fixes Quota Display

When switching models or checking usage quotas, displayed information and fallback mechanisms are more accurate.

With telemetry disabled, weekly Fable quotas now display correctly in /usage and the VS Code usage meter. When using /model, model IDs for Sonnet 4.6 or Sonnet 5 with dates or -v1:0 suffixes no longer incorrectly accept the [1m] option that should be rejected, and specifying the default Haiku model correctly displays the corresponding model version and pricing. When Opus already has a 1M context window, Opus options and the Default model name no longer display "(1M context)", while the actual window size remains unchanged. When model fallback occurs, dynamic workflows no longer lock all subagents onto the fallback model and instead retry the originally configured model. If Haiku is the primary session model, DISABLE_PROMPT_CACHING_HAIKU also takes effect.

FEATURE

Connection Warmup Reduces Latency and Startup Modules Load Lazily

When starting conversations and sending the first prompt, wait times are noticeably shorter.

Reusing pre-established connections significantly reduces first-request latency, and the compilation step runs concurrently during initial response generation rather than waiting until streaming ends. When using claude -p or Claude Code Remote, unnecessary interactive interfaces are no longer preloaded, and rule classifiers and artifact tools now load lazily on first use. For first-time claude.ai accounts where artifact features are unconfirmed, prompting no longer waits up to 1.5 seconds, deferring the wait to the first message if necessary. When sorted artifact database queries return a full page, they clarify that this is only one page and explain how to retrieve subsequent items. Automatically started artifact watchers shut down after three and a half hours of inactivity, restarting when artifacts are published or watched again.

FEATURE

Remote Control Supports Telemetry-Free Mode and Displays Live Compaction Tokens

When using remote control or waiting for long sessions to undergo background context compaction, displays are clearer and smoother.

Paid plan users disabling telemetry via DISABLE_TELEMETRY or DO_NOT_TRACK can now still enable remote control normally, and running /remote-control in narrower terminal windows no longer truncates mobile QR scanning prompts with awkward line wraps. When overly long conversations trigger context compaction, the spinner starts a timer at compaction onset and dynamically counts tokens consumed during summary generation, replacing the previous static percentage progress bar.

FEATURE

System Prompts Support Mixed Files and Skill Naming Limits Are Lifted

When customizing system prompts and managing skill permission rules, configuration is more flexible.

In launch flags, --system-prompt and --append-system-prompt now permit passing both inline text and file arguments simultaneously, placing file prompt contents before text arguments automatically. Skill(anthropic-skills:<name>) disable rules now also block that skill when delivered as an extension by Claude Desktop, while Skill(skill:<name>) disable rules match against skill aliases and display names. Prior reserved name restrictions on claude-ai have been lifted: identically named skills, commands, workflows, and MCP server skills and prompts can all be reloaded, while Skill(claude-ai:*) continues to operate under standard prefix rules.

FEATURE

Third-Party Platforms Default to Auto Mode and Review Prompts Add Warnings

When operating through third-party cloud platforms or executing automated workflows, default permissions and state retention are refined.

Without explicitly configured permission modes, interactive sessions on third-party platforms or with telemetry disabled now default directly to auto mode, though users can still override this default via settings. Before launching /ultrareview code reviews, the startup prompt warns that reviewing local branches may upload uncommitted changes from tracked files. In accessible environments, screen readers no longer misread quoted commands and paths as built-in dialog text. When SDK turns end early, deferred tool calls or completed results are no longer lost, and pending approval prompts are preserved across background worker restarts. Usage information for non-streaming fallbacks is likewise retained.

BUGFIX

VS Code Fixes Web Session Sync and Input Field Cursor Misalignment

Resuming cross-platform sessions in the editor or pasting long prompts is now much smoother.

Sessions sent from the web app to VS Code no longer drop messages sent while Claude is working, nor do web sessions vanish from the list and open empty chats when older versions leave blank local copies behind. After reopening sessions, turns are no longer split incorrectly if Claude receives a message mid-turn (such as during auto-continue). Reloading also no longer displays rewound turns or shows only pre-compaction messages after compaction. When automatic permission mode switching fails, the switch continually retries until it succeeds, preventing the indicator from showing a mismatch with the active mode. Agent icon alignment in narrow panels and cursor drift when pasting multiline text ending with newlines into long prompts have also both been resolved.

FEATURE

Cloud Sessions Support Read-Only Repositories and Prevent Duplicate Steps

When running background tasks and schedules in cloud environments, multi-repo integration and restart stability are improved.

Adding private repositories to running cloud sessions now only requires read permissions on the GitHub account rather than forcing push access. When server restarts trigger automatic recovery, completed steps are no longer re-executed, preventing duplicate comments or pushes. When creating new recurring schedules in the cloud, default execution times are set a few minutes past the hour, and the UI notes that schedules set on the hour may start a few minutes late. Initial conversational words also stream smoothly in cloud environments.

BUGFIX

Slack Mentions Support Restricted Channel Searches and Fix Duplicate Replies

When invoking Claude via mentions in Slack, permission management and connection settings are more comprehensive.

Administrators can now configure search restrictions by organization, workspace, or channel, allowing Claude to search only added public channels, while a new back button returns directly to the thread after completing account authorization. For channels with rule-bound permissions, settings pages now correctly show all active extensions and connectors, and searches no longer miss items when a GitHub App installation selects a large number of repositories. When new messages arrive mid-response, the system no longer sends duplicate answers. Schedules no longer stop when legacy private channel IDs change, and non-guest members joining channels configured as Channel only no longer interrupt all conversations when Slack delays identity confirmation.

FEATURE

Code Review Requests Auto-Retry, Waiving Charges for Unverified Timeouts

When submitting branch changes on GitHub and invoking @claude review for assistance, failed requests or timeout interruptions no longer stall without a response.

When GitHub fails to return a pull request, the review request retries once; if it fails again, it posts an explanatory comment. If a code review is aborted due to reaching its time limit without completing any verification, the review is marked incomplete, incurs no charge, and automatically retries once.

When placing a courier delivery, if the system cannot locate the order, it checks once more and leaves a message if still unfound; if delivery times out before any package is verified, it is marked incomplete at no charge and retried once.
