Claude Code 2.1.318

Released: 2026-11-04

Release notes

FEATURE

Login Expiration Added to Status Checks with Ten-Day Advance Warnings

When running commands on servers or background schedules, sudden credential expiration often interrupts automated jobs without warning. Running claude auth status now displays the loginExpiresAt sign-in expiration date. When executing claude -p, the JSON output also adds a credential_expires_at field. When a stored claude.ai sign-in has 10 days or fewer remaining, claude -p text output prints a one-line warning to stderr. If a login has already reached its time limit, the terminal no longer throws an unclear error, but explicitly states that the credentials have expired. During claude -p runs, it specifically names claude auth login and claude setup-token to sign in again.

Much like a text reminder from a front desk before a rental pass expires, where an expired card previously failed at the scanner without warning, it now reminds you ten days early to renew and clearly states which counter to visit if expired.
FEATURE

Custom Extensions Support Lightweight Forking and Preserve User Turns for Submit Hooks

When asking Claude to write extensions, permission tracking and execution models are now more clearly defined. Claude Code now keeps a record of your answer when asking to turn on the extensions (mods) it writes in the current session. When authoring extensions that use $.model.fork for side jobs, an effort reasoning option is now available. Side jobs can be specified to run at low effort regardless of how high the main session setting is, and the returned results report the effort actually sent. Content attached at prompt.submit hooks (small programs triggered by specific events) now stays in the user's turn rather than going out as a system message.

Picture a head chef assigning an assistant to peel potatoes, where there is no need for master-level precision cuts as long as the assistant processes them quickly through a streamlined workflow and brings them back to the same prep table.
FEATURE

Apps Gateway Adds Cross-Account Roles with Refined Log Warnings and Proxy Hints

When maintaining an internal gateway, enterprises often need to attribute AI usage costs from each engineer to separate cloud accounts. The Claude apps gateway adds an assume_role setting on mantle upstreams, supporting switches to another AWS account role to attribute cloud spending. When a Google access token from a federation (external_account) credentials file is about to expire, the gateway logs an advance warning. Log hints for listen.trusted_proxies have also been improved to remind you to list only reverse proxies that add the connecting address to X-Forwarded-For themselves. When AWS CountTokens fails on Amazon Bedrock, the warning clarifies that Claude Code counts tokens itself, pointing to IAM permissions only when AWS explicitly denies access. While past logs could make it look like a gateway failure, they now directly state the division of responsibility and troubleshooting direction.

FEATURE

Network Home File Locking Hardened to Prevent Dropped Settings and Cleared Logins

On server clusters in universities or companies, multiple hosts often share the same network home directory. Previously, when configuration files could not be updated on a shared home directory, running /logout or claude mcp remove falsely reported success while settings were silently dropped, an issue that is now resolved. When another host signs in again to the same account and organization, running jobs no longer unexpectedly exit with a not logged in error. claude mcp add and remove now wait for the file lock and exit 1 if it cannot be obtained, though saves from another job can still replace a saved server. When network storage runs out of space, the stored login is no longer replaced by an empty file. Across network file systems, ~/.claude.json, settings files, and login credentials are far less prone to being deleted or replaced by older copies. If a configuration file is reported missing, the system checks again to avoid missing MCP (Model Context Protocol, a protocol for connecting AI to external tools) servers.

FEATURE

Terminal Configuration Files Gain Corruption Protection Without Overwrites in Non-Interactive Mode

When a local configuration file is accidentally corrupted, blind automatic repairs often erase valuable personal settings. When launched in non-interactive mode, if ~/.claude.json contains invalid JSON syntax, it is no longer forcibly replaced with defaults; startup fails directly, explains how to restore the file, and leaves the original file intact. When the configuration file is empty with no backup, it is no longer misreported as corrupted, but treated like a first-time launch instead. Printed restore commands no longer point to empty or truncated backups, nor do they fail on read-only files. During retention cleanup in environments that only run claude -p, a fresh backup is created before deleting the last valid one. For unattended tasks (claude -p, SDK apps), ~/.claude.json is no longer rewritten on every run when its contents have not changed at all.

FEATURE

Self-Hosted Runners Provide Spawn Reasons with Updated Log Formats and Argument Hints

When setting up dedicated self-hosted runners, managing schedules and diagnosing connection states requires clearer information. The orchestrator's spawn-runner hook environment now adds the CLAUDE_RUNNER_SPAWN_REASON environment variable. This records why Anthropic sent the request, remaining unset when none was provided. If --release-idle-session-min is passed as the final argument at startup with no value, or if its value contains only whitespace characters, a startup warning is actively displayed. Orchestrator log formats have also been updated. The ok session=… message now prints to stdout at every log level, appending reason=… after jti=…. Meanwhile, nack session=… appends reason=… after retryable=…, requiring corresponding adjustments for automated scripts that match against legacy keywords.

FEATURE

Cloud Sessions Support Starting Without Repositories with Improved Browser Paths and Log Fetching

When running temporary tests or automated scripts in cloud sessions, configuration options are now more flexible. Starting a session in an Anthropic-hosted cloud environment now includes a No repository option, allowing conversations to begin directly without picking a code repository. Cloud sessions now include the usual Chrome alias names, enabling tools other than Playwright to locate the built-in Chromium browser through google-chrome and CHROME_PATH. When a cloud environment has been deleted and the input box is hidden, the prompt card adds a New session button. Running gh run view --log and gh api now retrieves GitHub Actions execution logs directly rather than getting stuck on unreachable redirects. Most Create PR failures now display a specific reason or a GitHub link, and connector search results actively inform Claude that results cover only part of the directory.

FEATURE

Remote Control Accelerates Sleep Reconnection While Naming Missing Folders and Parallel Checkouts

When connecting to other hosts to write code via Remote Control, computer sleep often disrupts connections or causes disordered states. Remote sessions now reconnect significantly faster after a pause or sleep. Following a failed connection, /remote-control no longer mislabels that session as available. When a session's working folder is missing, rather than emitting a misleading error, the error message now explicitly names the missing folder. When a fork of a terminal fork is created without an assigned title, the default name is cleanly labeled in the format of Name (fork 2). If side-by-side checkouts of the same repository exist in the same environment, menu listings no longer look identical, instead displaying their respective folder names for clear identification.

BUGFIX

Editor Extension Halts Pointless Restart Loops While Fixing Error Banners and Sign-In Prompts

Using Claude Code in VS Code previously risked wasting background resources when organization settings blocked sign-in. Previously, when a window's sign-in was refused by organization settings, the extension kept launching a new Claude Code process in the background every minute, an endless wake-up issue that is now fixed. When a long word appears in the chat panel's error banner, layout overflow no longer pushes the close button out of view. When a sign-in status check fails, the sign-in screen now directly displays what Claude Code actually printed in the terminal, making troubleshooting account permissions or network issues far more intuitive.

Think of a building access scanner failing to read a badge, where the terminal no longer attempts to swipe every minute and set off alarms, instead displaying the failure reason directly on the screen at once.
FEATURE

Background Subagents Prevent Cache Expiration and Resumed Workflows Avoid Re-Execution

When dispatching subagents to run heavy builds or tests in the background, long-running cache states now have better safeguards. Across all cloud providers, if a background subagent runs a shell command for more than 3 minutes, it automatically moves the command to the background so the prompt cache (temporarily saving calculated or retrieved results for direct reuse) does not expire from waiting too long. On Bedrock, Vertex, Foundry, or in environments with telemetry turned off, if the cache has not warmed up, subagent progress summaries can now wait up to 5 minutes for a pending response. When a message is flagged and "Switch models when a message is flagged" is set to "Ask each time", subagents stop and wait rather than switching models on their own. When workflows are resumed after reaching a usage limit, they no longer re-run already finished agents. While a background subagent is running, the screen no longer repeatedly pops up the "Now using usage credits" notice about every 30 seconds.

BUGFIX

Session Restarts Preserve Execution Directories, Securing Message Queues and Environment Variables

When experiencing network drops or service restarts, sessions on cloud runners and self-hosted runners now restore more accurately to their pre-interruption state. A shell command approved after a restart now runs in the target folder where it was originally requested instead of mistakenly falling back to the session's start folder. If that folder cannot be entered, it is not run. If an approved connector tool becomes unavailable after a restart, the system now proactively notifies Claude. When a cloud service temporarily refuses uploads for several minutes, conversation turns are no longer stopped halfway through. Variables written to CLAUDE_ENV_FILE by a Setup hook (a script triggered by specific events) now properly reach the Bash tool. After restarting from an API error, the system no longer re-sends an older failed message ahead of queued newer messages. Restarting immediately after reading a large image or retrying a tool call will also no longer drop the interrupted conversation turn.

BUGFIX

Headless Mode Accurately Reports Failures, While Stop Command Cancels Subsequent Messages

When using headless mode (running without a terminal window or visual interface) or integrating via an SDK, programs must accurately track execution success or failure. When custom slash commands fail or can only be invoked by Claude, running them in claude -p and Agent SDK sessions no longer prints blank output, but instead outputs error information. When a mod hooks turn.step, if an API error cuts off a reply midway or execution is actively stopped, sessions are no longer mistakenly reported as finishing successfully. When a message is sent immediately after switching models, issuing a Stop command now properly cancels or stops that message instead of allowing it to continue running in the background. When an idle non-interactive session exits, previously deleted session transcripts are no longer re-created with their last prompt.

FEATURE

Denial Rules Extend to Official Servers, While Plugin Token Refreshes Prevent Sign-Outs

When connecting external tools or extension marketplaces, tool validation and security denial rules receive several critical fixes. URL entries in deniedMcpServers now also block Anthropic-provided servers whose upstream URL matches, as well as connectors assigned dedicated URLs in cloud sessions or on self-hosted runners. When a call is made before a tool finishes loading, the error message now returns that tool's input schema. Running /mcp in cloud sessions no longer counts tools the model cannot use, and each row in the list clearly indicates how many tools are actually available. If a stdio server exits during the version probe, it is no longer re-probed on every start, and a server dying within 3 seconds for its own reason is also pinned to the legacy handshake for 7 days. Inconsistencies when validating custom marketplace file names have been fixed, and plugin commands now only exit after token (authorization credential) refreshes are completely saved, preventing unexpected sign-outs on the next launch.

FEATURE

Automated Cleanup Preserves Active Binaries, While Updates Retry Immediately on Network Drops

When running background daemons or self-hosted nodes over long periods, software upgrades could previously delete active main executables by mistake. During auto-updates or older version cleanups, the system previously removed binaries of still-running processes, causing remote-control hosts, background daemons, and self-hosted runners to fail when starting new sessions with a spawn ENOENT error. The cleanup mechanism now properly identifies running processes and keeps them intact. Even if a process was started by another user account, such as a process left behind by sudo claude, it is no longer treated as dead and will not have its binary deleted. Auto-update reliability has also been improved. If a brief network failure occurs while verifying release information for a new version, it is now retried immediately instead of waiting for the next check cycle.

A warehouse cleaning crew first cross-checks duty badges before clearing equipment: as long as any worker remains on duty, their toolbox will not be thrown out as trash, even if they switched shifts or belong to a different department.
BUGFIX

Resuming Conversations Preserves History, While Idle Compaction Guarantees Accurate Summaries

When discussing a project with Claude over extended periods, preserving conversation history and slimming memory usage are vital. A regression introduced in 2.1.314 has been resolved: when a malformed tool call ran out of retries, using the --continue flag sometimes lost the earlier conversation history. When a session triggers auto-compaction due to inactivity, the system no longer mistakes an ordinary reply for a summary, ensuring that only genuine conversation summaries are kept after replacement. A temporary compatibility fix introduced in version 2.1.288 has been removed. When resuming conversations created in 2.1.286 or earlier, leftover thinking blocks can now be dropped directly rather than forcibly kept.

Rebinding a thick volume of meeting records works the same way: where missing pages once led to tossing the entire binder, the process now preserves original details and condenses them into a faithful summary during idle archiving.
BUGFIX

macOS Terminal Memory Leak Resolved, Stabilizing Git Commits with Native Bash

When running batches of commands with Claude on a Mac, terminal performance and stability have received targeted improvements. An issue in macOS environments where running numerous Bash commands caused memory to climb continuously and stalled the session has been resolved. When the terminal's Bash tool invokes macOS's built-in /bin/bash, the reliability of git commits and pull request creation is improved. While the background shell details dialog remains open, the elapsed runtime inside the window now updates in real time instead of freezing.

Clearing scratch paper from an office desk follows the same principle: previously, every errand assigned to an assistant left piles of unfiled receipts until the desk overflowed, but tasks are now filed away immediately to keep the work surface clear.
FEATURE

Permission Prompts Prevent Accidental Keystrokes, Enabling Risk Assessment by Default for Managed Agents

When granting tools permission to run commands, typing too quickly or encountering slight delays in prompt popups previously led to accidental dangerous actions. Keystrokes typed right after sending a message or before a slow prompt appeared no longer inadvertently answer subsequent permission prompts. Rule details, built-in rules, and delete confirmation views in /permissions now use the standard dialog. Pressing Ctrl+C twice there now goes back or cancels instead of quitting the entire program. When configuring Managed Agents via /claude-api managed-agents-onboard, built-in tools for new agents and MCP tools in quickstart templates now receive the auto permission policy by default, aligning with Claude Console safety standards. To grant complete clearance, users can explicitly specify running without asking.

BUGFIX

Damaged Certificate Stores No Longer Block Connections, Isolating Multi-Account Logins

Enterprise environments often customize security certificates or require all team members to bind to a specific organization UUID. When the certificate store (where the system stores root certificates) pointed to by the NODE_EXTRA_CA_CERTS environment variable is empty, not PEM format, or starts with a damaged certificate, every connection previously failed outright. Readable root certificates are now loaded while skipping corrupted sections, accompanied by a warning on standard error. On machines enforcing the forceLoginOrgUUID policy, tokens generated by setup-token that belong to permitted organizations are no longer rejected at startup. Sessions are also no longer mistakenly refused at startup by an allowedProviders list that another login on the same machine previously stored.

FEATURE

Mobile Syncs Execution Status Accurately, Eliminating Duplicate Push Notifications

When checking ongoing cloud tasks from a mobile phone on the go, conversation statuses and real-time push notifications are now far more accurate. In the iPhone app, if a cloud session was cut off at a tool call or after removing a rejected image or document, the screen previously showed a still-running turn as finished. The interface now tracks actual execution progress closely. When Claude leaves the status field out of a PushNotification call, duplicate notifications are no longer dispatched. Notice banners have also been refined: guidance that previously instructed users to "press 2"—which only works in a terminal—now says "try again" so mobile and web users are not confused.

Delivery tracking in a food app works on the same premise: while a meal is still cooking or in transit, it does not prematurely display a delivery checkmark, nor does it fire duplicate push notifications along the route.
FEATURE

IDE Terminals Cease Auto-Installing Extensions, While Oversized Images Report Actual Pixel Limits

Across integrated development environments and routine conversation interfaces, several commands and notifications have been streamlined. When launched directly from an integrated development environment (IDE) terminal, Claude Code no longer automatically installs or updates the editor extension. To install it, run /ide from an external terminal or manage it directly from the editor's extensions view. Selecting "Ask your admin for more usage" in the usage limit menu now sends the request in one step. When sending more than 20 images in a single request and encountering an oversized file, the error message no longer rigidly claims the limit is 2000px, but displays the API's actual pixel limit. Running /design revoke to revoke design permissions no longer falsely reports success when the backend request fails with a 404 error.

BUGFIX

Keyboard focus fixed in tag management; Code Review analytics page automatically retries on network failures

The admin console and project review dashboard offer a more reliable experience when facing unstable network connections or using assistive technology. In Claude Tag admin setup, keyboard focus and screen reader announcements have been fixed; pressing Escape in the connect form now only closes the current form and no longer also closes the outer Add dialog. The Code Review analytics page now automatically retries loading once after a server or network failure; if loading still fails, it displays a Try again banner instead of previously blank, invalid cards.

Pushing a small drawer back into a filing cabinet does not slam the outer door shut; similarly, a card reader automatically retries once after a connection timeout, prompting to try again only if that fails rather than leaving the whole screen blank and frozen.
