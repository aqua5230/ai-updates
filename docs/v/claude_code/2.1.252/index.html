zh-TW

Mac 上的 Bash 指令不再因為目錄搬家而失敗

你每天把車停回同一格車位，某天開進去卻發現那整層改成別的用途，警衛攔著你說這裡停不了。在部分 Mac 上，跑 Bash 指令（在終端機裡直接下給電腦的文字命令）會突然失敗，畫面丟出一句 task output swap refused (tasks dir moved or linked)。癥結在存放任務輸出的 tasks 目錄：它如果被移動過，或被換成一個指向別處的連結，Claude 就認不得這個位置，於是拒絕把跑完的結果放回去，整條指令跟著失敗。這次修掉了這個情況，目錄搬過家也好、改成連結也好，指令都能照常跑完。

新專案按下「always allow」，這次真的記得住

你在一個新專案裡按下「always allow」（總是允許），想省掉之後每次都被問一次的麻煩，結果下一次做同樣的動作，同一個確認又跳出來。問題在於這個決定要寫進專案裡的 .claude/settings.local.json，而當專案還沒有這個檔案時，你的選擇沒有地方落腳，按了跟沒按一樣。現在即使專案裡還沒有這個檔案，「always allow」也存得住，同一件事不會再問你第二次。你在櫃台留了口信，那裡卻連一本留言簿都還沒擺出來，話說完就跟著散掉。

連線變差時，遠端工作階段不再做完了還停在原地

山上的工程隊已經把電塔修好，回報的無線電卻卡在半路，指揮中心盯著沒動靜的畫面乾等好幾分鐘。由 Claude Desktop 或 VS Code 主持的 Remote Control（從另一台裝置接手操作同一段對話）碰過一樣的狀況：當連往 claude.ai 的連線變差時，工具明明已經跑完，畫面卻要停上好幾分鐘才有反應。做完的消息傳不回來，你這頭只能等，也分不清它是還在跑，還是已經掛掉。這次把這個情形修掉，連線不穩的時候，工具一結束就會反映到畫面上。

背景任務吐出的巨量錯誤，不再把對話撐爆

背景任務失敗的時候，會把錯誤內容整包送回對話裡給你看。偏偏有些失敗吐出來的量大得驚人，磁碟塞滿時 git 報的錯就是一個例子。這種通知一塞進對話，整包內容就會超過 API 請求的大小上限，也就是一次能送出去的資料量天花板，於是對話直接卡死在那裡。現在超大的失敗輸出不會再把請求撐破，任務失敗照樣通知你，對話也還走得下去。先前就像一台超過限高的貨車開進涵洞，車頭卡在入口，後面整排車跟著動不了。

en

Bash commands stop failing when the tasks directory has moved

You drive to the same parking spot you use every day and find the whole level turned over to something else, with an attendant waving you off: nothing can be parked here. On some Macs, Bash commands would suddenly fail with task output swap refused (tasks dir moved or linked). The sticking point was the tasks directory where command output is parked: if that directory had been moved, or replaced with a link pointing somewhere else, Claude no longer recognized the spot, refused to swap the finished output back in, and the whole command went down with it. That case is now fixed, so the command runs to the end whether the directory moved house or turned into a link.

"Always allow" now sticks in a project that has no local settings file yet

You hit "always allow" in a fresh project to stop being asked the same thing every time, and the very next time you do that action, the same prompt shows up again. The decision has to be written into the project's .claude/settings.local.json, and when the project does not have that file yet, your choice had nowhere to land, so clicking it changed nothing. Now "always allow" sticks even in a project without that file, and the same question stays away. You leave a message at the front desk, but no message book has been put out there yet, so the words scatter the moment they are said.

Remote Control sessions stop stalling after a tool finishes on a weak connection

The crew up the mountain has already fixed the tower, but their radio report gets stuck halfway down, and the control room stares at a frozen screen for minutes. Remote Control sessions hosted by Claude Desktop or VS Code ran into the same thing: when the connection to claude.ai was degraded, a tool had actually finished, yet the session sat still for minutes before anything moved. The news of completion never made it back, so you waited without knowing whether it was still working or had died. That stall is now fixed, and on a shaky connection the session reacts as soon as the tool ends.

Huge failure output from background tasks no longer bursts the conversation

When a background task fails, the error output is sent back into the conversation for you to read. Some failures produce a staggering amount of it; git errors on a full disk are one example. Once such a notification was packed into the conversation, the whole thing went past the API request size limit, the ceiling on how much data can be sent in one go, and the conversation was stuck there. Very large failure output no longer bursts the request, so a failed task still notifies you and the conversation keeps going. It was like a truck taller than the underpass driving in: the cab wedged at the mouth, and every car behind it stopped moving too.

一部の Mac で tasks ディレクトリの移動によるコマンド失敗が直る

毎日停めている駐車枠へ車を入れようとすると、その階全体が別の用途に変わっており、係員に「ここには停められない」と止められる。一部の Mac で、Bash コマンド（端末に文字で直接打ち込む命令）が突然失敗し、task output swap refused (tasks dir moved or linked) と表示されることがあった。原因は、実行結果を置いておく tasks ディレクトリにある。このディレクトリが移動されていたり、別の場所を指すリンクに置き換えられていたりすると、Claude はその場所を認識できず、走り終えた結果を戻すことを拒み、コマンド全体が失敗していた。今回この状況が修正され、ディレクトリが引っ越していてもリンクになっていても、コマンドは最後まで走る。

設定ファイルがまだないプロジェクトでも「always allow」が保存される

新しいプロジェクトで「always allow」（常に許可）を押し、毎回聞かれる手間を省いたつもりでも、次に同じ操作をすると同じ確認がまた出てきた。この決定はプロジェクト内の .claude/settings.local.json に書き込まれる必要があり、そのファイルがまだないプロジェクトでは、選んだ内容に落ち着き先がなく、押しても押さなくても同じだった。今後はそのファイルがないプロジェクトでも「always allow」が保存され、同じことを二度聞かれない。受付に伝言を残しても、そこにはまだ伝言帳が一冊も置かれておらず、言った端から言葉が散っていく状態だった。

接続が悪いとき、ツール完了後も止まっていたリモート操作が直る

山の工事隊はすでに鉄塔を直し終えているのに、報告の無線が途中で止まり、指令室は動かない画面を数分間見つめて待つ。Claude Desktop や VS Code がホストする Remote Control（別の端末から同じ対話を引き継いで操作する仕組み）でも同じことが起きていた。claude.ai への接続が悪化しているとき、ツールは実際には終わっているのに、画面は数分間止まったままだった。終わったという知らせが戻らないため、まだ動いているのか落ちたのかも分からず待つしかなかった。今回この停止が修正され、接続が不安定でもツールが終わればすぐ画面に反映される。

バックグラウンドタスクの巨大なエラー出力が対話を溢れさせなくなる

バックグラウンドタスクが失敗すると、そのエラー出力がまとめて対話に送り返される。ところが失敗によっては出力量が桁違いに大きく、ディスクが一杯のときの git のエラーがその一例である。こうした通知が対話に入り込むと、全体が API リクエストのサイズ上限、つまり一度に送れるデータ量の天井を超えてしまい、対話がそこで止まっていた。今後は巨大な失敗出力がリクエストを破裂させることはなく、タスクの失敗は通知されたうえで対話も続けられる。以前は、制限高さを超えたトラックがガード下へ入り込むようなもので、入口で車体がつかえ、後ろの車も一台残らず動けなくなっていた。

일부 Mac에서 tasks 디렉터리가 옮겨져 명령이 실패하던 문제를 고침

매일 대던 주차 칸에 차를 넣으려는데 그 층 전체가 다른 용도로 바뀌어 있고, 직원이 여기에는 댈 수 없다며 막아선다.일부 Mac에서 Bash 명령이 갑자기 실패하며 task output swap refused (tasks dir moved or linked)라는 문구가 떴다. Bash 명령은 터미널에 글자로 직접 입력하는 명령이다. 원인은 실행 결과를 넣어 두는 tasks 디렉터리에 있다. 이 디렉터리가 옮겨졌거나 다른 곳을 가리키는 링크로 바뀌어 있으면 Claude가 그 자리를 알아보지 못해 끝난 결과를 되돌려 놓기를 거부했고, 명령 전체가 함께 실패했다. 이번에 이 상황이 고쳐져서 디렉터리가 이사를 했든 링크로 바뀌었든 명령은 끝까지 돌아간다.

설정 파일이 아직 없는 프로젝트에서도 「always allow」가 저장된다

새 프로젝트에서 「always allow」(항상 허용)를 눌러 매번 묻는 번거로움을 없앴다고 생각해도, 다음에 같은 동작을 하면 같은 확인이 또 떴다. 이 결정은 프로젝트 안의 .claude/settings.local.json에 기록되어야 하는데, 그 파일이 아직 없는 프로젝트에서는 고른 내용이 앉을 자리가 없어 눌러도 누르지 않은 것과 같았다. 이제는 그 파일이 없는 프로젝트에서도 「always allow」가 저장되어 같은 것을 두 번 묻지 않는다. 안내 창구에 말을 남겨도 그곳에 방명록이 아직 한 권도 놓여 있지 않아 말이 나온 순간 흩어지던 셈이다.

연결이 나쁠 때 도구가 끝난 뒤에도 멈춰 있던 원격 세션을 고침

산 위의 공사팀은 이미 철탑을 고쳤는데 보고 무전이 중간에 걸려, 지휘실은 움직이지 않는 화면을 몇 분씩 바라보며 기다린다.Claude Desktop이나 VS Code가 호스트하는 Remote Control(다른 기기에서 같은 대화를 이어받아 조작하는 방식)에서도 같은 일이 있었다. claude.ai로 가는 연결이 나빠졌을 때, 도구는 실제로 끝났는데도 화면은 몇 분 동안 멈춰 있었다. 끝났다는 소식이 돌아오지 않으니 아직 도는 중인지 죽은 것인지도 모른 채 기다릴 수밖에 없었다. 이번에 이 멈춤이 고쳐져 연결이 불안정해도 도구가 끝나는 즉시 화면에 반영된다.

백그라운드 작업이 쏟아낸 거대한 오류가 더 이상 대화를 터뜨리지 않는다

백그라운드 작업이 실패하면 그 오류 출력이 통째로 대화에 되돌아와 표시된다. 그런데 실패에 따라 출력량이 엄청나게 큰 경우가 있고, 디스크가 꽉 찼을 때의 git 오류가 그 예다. 이런 알림이 대화에 들어가면 전체가 API 요청 크기 상한, 곧 한 번에 보낼 수 있는 데이터 양의 천장을 넘어 대화가 거기서 멈췄다. 이제는 아주 큰 실패 출력이 요청을 터뜨리지 않아, 작업 실패는 그대로 알려 주면서 대화도 계속 이어진다. 예전에는 높이 제한을 넘긴 트럭이 굴다리로 들어가는 것과 같아서, 입구에 차체가 걸리고 뒤따르던 차들도 함께 멈춰 섰다.
