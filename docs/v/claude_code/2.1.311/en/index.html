Claude Code 2.1.311

Released: 2026-10-26

Release notes

FEATURE

Self-Hosted Runner Supports Keeping Idle Sessions and Skips Rate-Limited Read-Only Repositories on Startup

When running automation tasks via a runner on a self-hosted server, your host often still has unfinished processes left behind.

Consider renting a conference room for a cross-departmental meeting: previously, whenever the projector connection glitched, the entire room was immediately cancelled and locked by the system; now, the room skips the faulty projector and opens as usual, and if a discussion group stays behind to organize notes at the whiteboard after the meeting ends, access control will not immediately turn off the lights and lock the doors.

If you run tasks using self-hosted-runner, two new options, --hold-idle-file and --max-hold-min, are now available. When your host reports processes left running from earlier, an idle session (an ongoing interactive connection) is preserved. In addition, when an added read-only repository encountered rate limiting during startup in the past—such as receiving an HTTP 429 error or a Git wrapper exiting with code 75—the entire session failed to start. Now, the self-hosted runner automatically skips the rate-limited read-only repository, allowing the main session to open smoothly.

FEATURE

Typing ultrathink in Terminal Enables Extra-High Thinking Effort with Dynamic Mid-Turn Boosts

When facing particularly thorny architecture refactoring or algorithm debugging, you might want the model to spend more time thinking deeply.

A driver climbing an uphill slope downshifts and steps on the gas: previously, the cruise control setting could not be altered once set before departure, leaving the car to crawl slowly on steep hills; now, pressing the pedal mid-drive instantly injects power, and the dashboard boost light illuminates only when actual extra power is being delivered.

Typing ultrathink in the interactive terminal allows Opus 5.5, Sonnet 5.5, Haiku 5.5, and Fable 5.1 models on Anthropic's API to think deeply at extra-high effort (xhigh effort). Even if Claude has already started answering, typing ultrathink midway raises the thinking depth for the rest of that turn's computation. The rainbow text effect has also been adjusted in tandem. The colorful effect appears only where the keyword can genuinely raise thinking effort; if mentioned inside quotes or as part of a file path, the interface keeps normal text color.

BUGFIX

Prompt Cache Misses from Thinking Effort Add Warnings, Usage List Fully Reveals Consumption

When switching between different models to plan tasks or review code, cache misses can consume valuable quota without you noticing.

Utility bills that break down every detail offer a clear parallel: previously, sudden power spikes caused by swapping in specialized appliances were entirely hidden, leaving people wondering where their quota went; now, the meter proactively warns of power loss when switching to devices with different specifications, and the bill prints out large expenses.

When adjusting thinking effort in plan mode, if the plan model differs from the current session model, the /effort command now proactively warns about a prompt cache miss so you can assess additional costs. The /usage command has also updated its display, faithfully listing large prompt cache misses that were previously omitted. When running /code-review, Claude prioritizes thinking effort and uses the maximum level only when explicitly requested. In addition, model names have dropped the [1m] suffix where it had no practical effect, though the legacy format remains accepted.

FEATURE

Conversations Past 200K Tokens Auto-Compact, Memory Reading and Summary Checks Improved

During extended conversations or when working on large projects, lengthy conversation histories easily trigger context limits.

Imagine a library organizing mountains of research notes: in the past, once notes filled a fixed number of pages, you were simply refused from turning the page, and obsolete drafts might even resurface; now, librarians proactively bind and condense bulky materials so you can keep writing, rechecking whether key summaries are properly included before binding.

In standard-context sessions, when a single request exceeded 200,000 tokens (text units for AI processing and billing), the tool previously halted directly and prompted that "Usage credits required for 1M context". Now, the tool proactively compacts the conversation history, organizing context for you and continuing execution directly without stalling midway. This automatic compaction mechanism also fixes a file state reading error. If MEMORY.md or CLAUDE.md was edited earlier in the session, the model previously saw stale, unupdated content right after automatic compaction; this issue has now been resolved. Additionally, when the model's compaction reply misses summary content, the tool requests the summary once more from the model before replacing the existing conversation, ensuring conversation history continues smoothly.

BUGFIX

Disable Compaction Setting Strictly Enforced, Rewind Confirmation Clarifies Removing Later Messages

Some teams must preserve the original context of every conversation step due to audit requirements or troubleshooting needs.

Courtroom trial records requiring verbatim archiving present an identical principle: previously, even when ordered to record proceedings entirely, some clerks would take it upon themselves to summarize main points; now, whenever a prohibition badge is placed, all members and menus are strictly barred from condensing text, and retrieving records clearly states that subsequent notes are being removed.

When the DISABLE_COMPACT environment variable is set, agent teammates no longer automatically compact history. Entering /rewind to open the rewind menu also no longer offers "Summarize from here" or "Summarize up to here" options. DISABLE_COMPACT in configuration files and module environments can now only turn compaction off, not re-enable it. When running /rewind, the confirmation screen has been corrected to state that subsequent messages will be removed, rather than incorrectly claiming the conversation "will be forked"; the warning message has also corrected the claim that manual and Bash edits are never affected by a code restore.

BUGFIX

Subagents Support Connecting Tools Dynamically, Fixing Repeated Hook Triggers and Cleanup

When the main agent breaks subtasks down into background parallel execution, background agents often require dedicated directories and tool support.

Dispatching a project task force to an independent meeting room mirrors this setup: previously, if the coordinator stepped out early, the whiteboard was wiped clean, while the punch clock by the door rang twice every minute; now, support tools arriving late are properly received, and the room is never cleared out early before the team finishes work.

After a subagent starts, if it encounters an MCP (Model Context Protocol, an open standard connecting AI to external tools) server that takes longer to connect, it can now properly use those tools once connection completes. An isolated worktree (Git's mechanism to run multiple parallel copies of the same project) used by a subagent is no longer deleted prematurely while a background subagent is still working in it. SubagentStop hooks (small programs triggered by specific events) now fire only once upon completion instead of repeating twice a minute. Background agents waiting for terminal wakeups no longer mistakenly start a new main conversation turn. When cloud or background sessions restart, completed skills no longer run a second time.

BUGFIX

Agent Teams Retain Task Lists on Reconnection, Keybinding Aligns Exit Behavior

When collaborating with multi-agent teams, reconnecting after interruptions relies on the system completely preserving pending tasks.

Scheduling around a whiteboard with a project team illustrates the problem: previously, when reconvening in the office after lunch, all task sticky notes on the whiteboard were wiped clean, and progress from a new branch was even pasted back onto the old board; now, the whiteboard remains intact upon returning, and identical notes are not repeatedly handed over during conversations.

In agent team sessions, reconnecting via --resume, --continue, /resume, or --session-id, as well as running /clear or recovering from a crash, no longer empties the task list. Running /branch also no longer mistakenly writes progress to the original session's list. In an individual agent's chat tab, pressing the up arrow key ↑ when a message is waiting to be sent now properly recalls history rather than sending a duplicate message. In agent view, pressing Ctrl+D twice on an empty input now exits, matching the behavior of the main prompt.

FEATURE

Remote Control Promptly Reports Blocked Connections, Cloud Collaboration Retains Tools Across Restarts

When working remotely from a mobile phone or terminal outside the office, connection reliability and message attribution are critical.

Directing base camp operations remotely over a satellite phone follows the same pattern: previously, whenever a relay line was blocked, the signal stalled silently on connecting for several minutes, while dispatches sent by an assistant were stamped with your personal seal; now, blocked lines are reported immediately, full disks or excess attachments explain their causes, and equipment remains intact after restarting the system.

If Remote Control is blocked by a network proxy, it no longer stays on "Connecting" for two minutes. In mobile apps, messages that Claude sends to a cloud or Remote Control session are no longer mistakenly attributed to you. When attachments are omitted because the disk is full or exceed 20 files, the system now explains the reason. In Cowork cloud sessions, hanging fetching and searching now time out after 300 seconds; restarts no longer lose tools due to specifying an agent. Loading a compacted session via /teleport or claude --teleport now warns that local copies omit messages prior to summarization.

FEATURE

Background Daemon Restarts Scheduled Sessions on Crash, Accurately Guiding Recovery and Respawn

When delegating heavy workloads to background services, sudden silent terminations of background processes are a major concern.

Night watch patrol systems in a commercial high-rise face a comparable scenario: previously, the control console advised flipping a switch that had long been removed, blindly spinning up generators even when no records were found; now, abnormal interruptions during scheduled patrols trigger automatic restarts, and the system offers clear guidance on resuming shift duties.

When a background session is pinned, connected, or has scheduled tasks or wake-ups configured, it now automatically restarts if it crashes between turns. When the background service does not respond, the error prompt now suggests running claude daemon stop --any and explains that it terminates all background sessions, rather than recommending a disabled command. Running claude respawn <id> now checks whether that ID exists beforehand, preventing the background service from launching needlessly when no matching session is found. Messages shown when a background process exits no longer promise an impossible restart and explain how to resume the session. When opening a background session from a terminal supporting hyperlinks, status line (the bar displayed at the bottom of the terminal) links can now be clicked normally.

BUGFIX

MCP Accurately Maps Project Paths, Fixing Cleared Auth and Remote Status Displays

When managing external custom tools across projects, inaccurate configuration paths and connection states increase debugging overhead.

Visitor access control in an office tower operates under the same reality: previously, registering equipment in a branch caused the system to mistake a sub-cubicle for an independent enterprise, and meeting rooms requiring no badges were erroneously flagged with red lights after keycard resets; now, configuration paths trace back accurately to their parent projects, and pass issuance statuses are faithfully displayed.

When running claude mcp add, claude mcp remove, or /mcp in a repository subdirectory, settings map to the project entry in ~/.claude.json rather than incorrectly pointing to the current subdirectory. claude mcp list and claude mcp get no longer print duplicate error codes when connections fail. In /mcp, a remote MCP (Model Context Protocol, an open standard connecting AI to external tools) server that requires no sign-in no longer reports failure after "Clear authentication". A remote server to which no credentials were sent also no longer falsely shows "authenticated".

BUGFIX

Interrupting Claude Takes Effect Immediately During Downloads, Plugin Directory Recognition and Skill Caching Optimized

When asking the model to fetch external data or load extension plugins, unresponsive pauses or misidentified directories disrupt development rhythm.

Like borrowing multiple reference books from a library, pressing cancel used to force you to wait at the counter until delivery timed out if just one book was in transit, and returning a box of books was even logged as a single volume; now canceling stops the wait immediately, and book lists checked within ten minutes can be retrieved directly.

When an external tool server has not answered a resource read or a skill is still downloading, pressing interrupt now takes effect immediately instead of waiting for a connection timeout. When using --plugin-dir to specify a folder containing multiple plugins, an empty .mcp.json at the top level is no longer mistakenly loaded as a single plugin. In addition, sessions that set CLAUDE_CODE_SYNC_SKILLS with feature-flag fetching off now directly reuse a claude.ai skills list fetched by another session on the machine within 10 minutes, saving the time of frequent re-queries.

BUGFIX

Massive File Changes No Longer Stall or Underreport, Ultra-Long Lists and Diff Preview Fixed

When project configuration specifications are complex or a single edit touches thousands of lines, the rendering efficiency of file editing tools directly impacts workflow fluidity.

Picture a text editor proofreading an ultra-long scroll: encountering continuous, lengthy entries used to freeze the entire machine for seconds, and statistics would even absurdly show zero after replacing thousands of lines of text at once; now flipping through a wide scroll does not miscount lines, nor does a comparison window suddenly pop up when there are no text changes.

When modifying thousands of lines in a single file, the Write and Edit tools no longer stall for up to 5 seconds or falsely report that 0 lines changed. Long freezes at startup and after reading or writing files when CLAUDE.md holds an extremely long list item have been fixed. When previewing lines wider than the terminal, the Write tool no longer skips rows or miscounts hidden lines. In fullscreen-width terminals, the diff pane no longer pops up automatically after an edit if there is nothing to compare.

BUGFIX

Shell Command Timeouts Retain Partial Output, Sandbox Conflicts and Environment Descriptions Corrected

When running time-consuming build tasks or background scripts on the command line, command execution status and permission boundaries serve as the basis for judging progress.

Operating long-running machinery inside a security containment room used to mean that once the timer rang, unfinished parts on the workbench were cleared away without a trace, and the alarm at the door repeated the exact same rules to veteran workers every single morning; now parts already machined are kept when time is up, and overlapping containment room paths no longer cause deadlocks.

When a shell command reaches its timeout limit, the result now retains and displays the output so far, and states that the command is still running in the background. On Linux, the error where the sandbox tool bwrap failed to create files when --plugin-dir was also an added directory and blocking reads outside working directories was enabled has been resolved. The Bash tool description no longer claims that the working directory permanently persists between calls, and the environment block no longer names an unexecuted shell (such as labeling fish when using zsh). Warnings for settings file permission rules are now shown once per user until the rule changes.

Much like a design agency delivering project deliverables, interactive prototypes and formal contracts used to be handed over in the exact same binder without URL hashes jumping when switching chapters; now interactive diagrams are crafted into clickable presentation web pages, while long-form prose is organized into documents easy to circulate and revise.

In the past, when guiding readers through different views, Claude mistakenly stated that the browser address bar stayed the same, and this explanation has now been updated to reflect the correct routing behavior.

FEATURE

Deep Thinking on Cloud Platforms Protected from Idle Disconnection, Non-Retry Flags Respected to Prevent Hangs

When invoking external models in enterprise cloud environments, complex network proxies and long computations often pose connection challenges.

Watching a long-distance convoy navigate a cross-border highway, checkpoints used to assume trucks had broken down whenever cargo required detailed audits, repeatedly requeueing freight already denied customs clearance; now active running signals are properly recognized, and connection drops point out which toll gate should be inspected first.

On Google Vertex AI, Microsoft Foundry, and AWS platforms, endpoints send thinking progress updates, so they are no longer misjudged as idle and cut off. When typing commands, pasting text, or selecting files in the terminal, having characters swallowed by the interface interrupts your train of thought.

Organizing a manual on a typewriter used to mean that pasting an image path caused the typewriter to impulsively clip the text and paste a photograph, print brackets while omitting backslashes, or even fail to locate files noted as exceptions in the index; now original text is preserved intact, and misclicks on a scrollbar can be cancelled simply by moving away.

A lone backslash inside quotes or brackets, like "\" or (\), no longer disappears from replies. When pasting text containing an image path, such as ! open /tmp/shot.png, it no longer mistakenly attaches the image and drops the path text. When typing @ to select files, negation rules in .ignore and .rgignore are now supported, correctly selecting re-included files. While the prompt contains text, the feedback draft card no longer displays shortcut keys to prevent key conflicts. Clicks on scrollbars in fullscreen lists now trigger only upon releasing the mouse button, allowing you to cancel by moving away.

Handling mail dispatch in a registry office, special seal stamps used to cause errors during system filing, and automated messengers forwarding documents frequently ignored notices posted right at the doorway; now special characters are escaped and packaged using standard codes, and the recipient's intake guidelines are reviewed before delivery.

Issues where claude -p and SDK sessions saved transcript messages out of order or retained retracted messages have been resolved. When scheduling automated tasks in a cloud-hosted environment, organizational member turnover should not permanently lock automated workflows.

Renting automated slots in a shared server room, a manager temporarily leaving and later rejoining the company previously left earlier scheduled machines permanently locked, and failed key regenerations gave no feedback on the console; now returning to the team allows machines to be re-enabled, and naming equipment triggers checks that intercept duplicate tags.

In Anthropic-hosted environments, when the owner of an automated routine leaves the organization and rejoins, the routine no longer remains locked, and the owner can now turn it back on. When deleting or regenerating a routine's API token (authorization token) fails, the screen now displays an error toast even if the edit dialog has already closed. When bringing AI tagging into team messaging apps for collaboration, understanding invocation frequency across skills helps optimize workflows.

Claude Tag analytics has added a Skills view showing how often Claude runs each attached skill in Slack channels and which go unused, with Usage links provided in admin settings. Routine inspection tasks that run in a new session can now end directly without posting a throwaway message to the channel if there is nothing to report. In admin settings, private Slack channels visible to your account now show a lock icon instead of the # symbol.

FEATURE

[Code Review] Automatic retry on transient server faults, clear closure when retries fail

When relying on automated review bots during pull requests, occasional cloud connection hiccups can stall the inspection process.

Submitting assignments through an online portal, brief network drops previously led the system to immediately register a failed submission, leaving students uncertain whether to keep waiting or retry manually; now line faults trigger one automatic reconnect with clear status updates, and a failure to parse the material triggers a definitive notice to stop waiting.

Code review sessions that fail to start due to transient server faults are now retried once automatically, and the check run clearly indicates that a retry is in progress. If the model still cannot analyze a change during the automatic retry, the check run explicitly states that no further automatic review will start, preventing teams from waiting indefinitely without updates.
