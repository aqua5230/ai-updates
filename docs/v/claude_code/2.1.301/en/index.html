Claude Code 2.1.301

Released: 2026-10-15

Release notes

FEATURE

Unattended Retry Mode Adds Configurable Usage Limit Wait Threshold

When leaving Claude running extensive tasks in the background overnight, hitting usage limits and idling mid-job is a constant worry. Previously, with unattended retry mode enabled (CLAUDE_CODE_RETRY_WATCHDOG, a background watchdog that automatically retries on errors), hitting a usage limit caused the process to wait indefinitely, even if the reset time was hours away. The new CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS environment variable decisively terminates the request whenever the reset wait time exceeds your configured millisecond threshold.

Think of taking a queue number: if the counter display says the next batch will take several hours, you pack up and leave rather than waiting around outside all night.
FEATURE

Vim Mode Adds Bracket Matching and Key State Switching

For Vim users accustomed to navigating code quickly with terminal shortcuts, handling now feels closer to the native editor. Vim mode introduces the % motion to jump between matching brackets, which also pairs with d, c, and y for delete, change, or yank operations. Previously, pressing Esc on heavily loaded machines could get stuck in INSERT (the state for typing text) without switching. Free-text fields in prompt inputs now support NORMAL (the navigation state for motions and commands). Pressing Esc now drops back to normal mode first, and only cancels when pressed again in normal mode, preventing your typed answer from being wiped out.

Like shifting a manual transmission, depressing the clutch previously got stuck in neutral at times, but gear changes now lock in cleanly, and downshifting no longer resets engine RPM to zero by mistake.
FEATURE

OpenTelemetry Tracing Guidance and Expanded Tool Decision Event Attributes

Observability logs now record more detail when tracking why Claude invokes tools in enterprise dashboards. Configuration guidance for OpenTelemetry (an open-source standard for tracking execution traces across systems) is now included in the claude-api skill, covering how to configure export destinations with the ant tool. The tool_decision event adds classifier_verdict and permission_mode fields, helping administrators distinguish classifier decisions in auto mode (the setting allowing Claude to execute autonomously) from existing permission rules. When OTEL_LOG_TOOL_DETAILS=1 is enabled, tool_decision events where the classifier blocks an action also record the triggered built-in rule name in classifier_category.

Picture reviewing a lab report: whereas tests previously only showed positive or negative marks, you can now separate automated instrument readings from manual reviews, complete with specific item names when abnormalities occur.
FEATURE

Mod Extensions Add Multi-Line Input and Standardized Return States

Interface and flow control become more precise when authoring a Mod (modules that extend Claude's capabilities). The Input component adds a rows prop for multi-line terminal input, submitting on Enter and inserting newlines on Shift+Enter or backslash. Calling $.model.fork before the initial response finishes in claude -p or cloud sessions no longer throws nothing-to-fork. Prompt tree lists now support Markdown with up to 48 lines across desktop, mobile, and VS Code, while staying at 12 lines in the terminal. The .catch handler on a hook (small programs triggered by specific events) now runs only on thrown exceptions or timeouts, and events generated by internal calls are no longer forwarded back to the hook itself. The $.env.set method for setting or unsetting environment variables now returns {} on successful operations, and { deny } with a reason when writes are skipped.

FEATURE

Model Switching Flow and Long Conversation Auto-Summarization Improvements

Switching mid-conversation to a model with a smaller context window is now much smoother when transferring long dialogs. A context window represents the maximum text volume a model can read at once. When conversations run too long, the original model is asked to summarize them first, resolving an issue where quota was deducted for summarization without asking. When using fable or best aliases through the Anthropic API, organizations without access to the latest Fable release will automatically fall back to the prior version and retry once. Non-Bedrock custom model names that include application-inference-profile no longer mistakenly run awsAuthRefresh and delay hooks. When connecting through a gateway, differing model names returned by the server will no longer cause repeated conversation compression using an unselected model.

A passenger transfers from a long-haul coach to a compact shuttle: luggage was previously repacked for an unapproved fee, but permission is now requested first while the original driver streamlines the cargo, and the transit station avoids mixing up fleet numbers that forced endless re-transfers.
BUGFIX

Skill Parameter Hydration Performance and Plugin Permission Attribution Fixes

Invoking commands and confirming permissions is now cleaner and more transparent when projects install numerous custom skills or plugins. Previously, skills (playbooks expanding domain knowledge and commands) and commands with too many or excessively long parameter names stuttered for seconds during invocation. Hydration is now limited to the first 64 names with a maximum of 64 characters each. An issue where skills, commands, and hooks consumed excessive memory while hydrating numerous placeholders has been resolved. The skill catalog no longer vanishes from the model after running /rewind to roll back conversations, and documentation in /claude-api mistakenly claiming the Claude platform on AWS lacks CMEK external key endpoint support has been corrected. When a plugin or skill hook triggers an ask prompt for decisions, the confirmation dialog now clearly labels which plugin or skill originated the hook.

Imagine consulting a parts inventory ledger: having too many entry fields previously jammed the entire clipboard, but specification indexes are now capped to compact entries, and retrieved tools clearly display ownership labels for their parent toolbox.
BUGFIX

Account Login and Credential Refresh Fixes

Error messages are clearer when login refresh fails, and running quick commands will no longer cause accidental logouts if they terminate mid-refresh. Previously, when disk space filled up completely, the system failed to refresh login credentials and instead displayed a confusing "Please run /login" error message. It now identifies the exact disk that is out of space and explicitly prompts you to remove files to free up room. When running quick commands like claude auth status or claude plugin list, if the command exited while refreshing a token (an authorization ticket used to verify identity), it previously triggered refresh timeouts and unexpected logouts. These login refresh timeouts and accidental sign-outs are now fixed.

Consider updating a signature seal at a bank counter: dried ink previously led to false claims that your seal was invalid, and quick passbook checks froze accounts on the spot, but low ink now prompts an immediate refill request and quick balance inquiries no longer get you kicked out.
BUGFIX

Artifact Publishing Updates and Mobile Layout Rendering Fixes

Updating content and previewing on phones is now more reliable when asking Claude to produce standalone web pages or document artifacts. In environments configured with PreToolUse hooks that intercept edits or writes, updating artifacts previously met with outright rejection. Claude now edits the file normally before republishing, instead of attempting to modify files directly inside the publishing call. In the mobile app, text on Claude-generated web pages previously bled above the sticky header during scrolling. The top header band now renders solid background fill, preventing scrolled content from showing through.

A display case protects an exhibition poster: updating the print previously involved defacing the surface on-site and drawing security guards, but staff now remove the sheet to touch it up before reframing, and the top frame solidly covers the page beneath as people walk past.
BUGFIX

File Reading, Search Tools, and Git Operation Fixes

Underlying inspection tools report results more faithfully and safely when auditing source code or comparing version diffs. When search processes crashed unexpectedly, search tools like Grep and Glob previously returned empty results. They now properly throw errors to report the search failure. The Read tool no longer mistakenly ingests binary files such as .xlsm, .parquet, .epub, and .heic as plain text. When exiting Claude Code, Git worktrees (capabilities allowing parallel copies of the same project) created via WorktreeCreate hooks are no longer silently deleted if unpushed commits remain. In Git repositories using the reftable format, the /diff command no longer misses conflicted cherry-pick or revert operations if underlying inspections time out or fail.

Just as strict auditing protocols govern an archive room, equipment crashes no longer falsely report missing records, illustrated volumes are not forced into plain text transcripts, and unfiled document crates require in-person sign-off before leaving the floor.
BUGFIX

Workflow Automation and Background Command Execution Fixes

Background steps and permission controls are significantly more dependable when orchestrating multi-agent or scripted project automations. When workflow agents encountered framework notes indicating missing user authorization in task descriptions, they previously skipped steps while falsely reporting success, an issue that is now fixed. After running Bash cd to change directories within the same session, reading, editing, or re-running workflow scripts no longer prompts unexpected permission requests or fails with rejections. Tool calls interrupted by incoming mid-turn messages during permission evaluation are no longer falsely reported to the model as user rejections. On Windows, output files from terminated background PowerShell commands that previously missed the trailing [killed] indicator now append it properly.

Much like an automated factory conveyor belt, notes once led stations to skip assembly steps while marking items passed and station handoffs triggered outright refusal, but every procedure now executes faithfully while mid-process halts receive clear cancellation stamps.
BUGFIX

Fixes for Terminal Text Artifacts, Table Layout, and Dark Theme Colors

When opening a terminal to run commands, character boundaries and color gradations on screen are now cleaner and easier to read. In environments such as MATE Terminal on RHEL 8 that use older versions of VTE (terminal emulator core component, versions below 0.53), fixes resolve >0q obscuring folder trust prompts and >4m noise appearing upon exit. A bug where leftover GOK text appeared in front of the prompt upon launching certain iTerm2 versions has been fixed. Markdown tables containing only a header row previously failed to render completely when their width exceeded the terminal (including tables appearing in plan approval cards), but they now draw properly. Under dark ANSI themes and 16-color terminals, text inside filled boxes remains dimmed, but it is no longer dimmed under selections and search highlights, and list descriptions are also correctly dimmed like secondary text.

Old computer displays finally receive proper calibration: boot-up static previously scrambled text and wide tables disappeared broken, but every character now aligns neatly with sharp contrast against dark backgrounds.
FEATURE

Optimizations for Session Compaction, Prompts, and Subagent Progress Updates

When engaging in lengthy conversations or dispatching subtasks, the interface no longer freezes briefly from heavy data loads. A brief UI stutter caused by rebuilding visible message history when running /compact or automatic compaction in fullscreen mode has now been fixed. During long-running subagent (an agent that independently performs a specific subtask) tasks, progress history now updates incrementally instead of recalculating the entire trail on every render. When resuming a previous session, the compaction prompt bar no longer offers a Ctrl+O shortcut that fails to load history, but instead clearly explains the path where earlier messages are stored, and this prompt now displays properly in fullscreen mode as well. When you interrupt a response midway, a prompt that previously appeared immediately suggesting /clear to clear conversations and save tokens no longer pops up right away to cause disruption. Tokens are units of text used for AI processing and billing.

Reading a serialized novel is much smoother now: rather than rebinding all earlier chapters with every page turn and causing a jam, the reader simply turns to the newest page, with each new volume clearly noting where the previous book is archived.
BUGFIX

Fixes for Self-Hosted Runner Session Retries and Repository Attachment

When integrating team chat apps and using self-hosted runners, session launch and teardown become significantly more reliable. A fix resolves an issue where sessions launched from Slack failed to find or mount repositories when managed settings restricted MCP (Model Context Protocol, a protocol that connects AI to external tools) servers. If specific tools must be disabled, deniedMcpServers can be configured in settings. A bug has been fixed where unrelated environment settings or session failure messages citing missing Git reference wording caused sessions to be misidentified as having a deleted source branch, preventing retries. If a terminating session fails or is rejected while releasing resources, logs no longer promise retries. Repeated failures now display the failure count.

Automated fleet depots operate with dependable entry gates: security limits previously blocked vehicles from locating parking bays and repair tickets citing specific codes mistakenly marked entire cars as scrapped, but now parking proceeds smoothly and abnormal check-ins record exact failure counts.
BUGFIX

VS Code Extension Support for Mathematical Formulas and Panel Performance Fixes

Formulas render more cleanly and conversation interactions feel smoother when discussing problems with Claude in the VS Code panel. Claude's responses now support LaTeX mathematical formulas, including standalone paragraph $$, multiline \[ … \], and inline $…$ or \(…\) syntax. In VS Code and JetBrains panels, a "Get more usage" link has been added to the usage limit banner for Pro and Max plans. A fix resolves a vicious cycle where a conversation that crashed or froze the panel was forcefully reopened every time the window reloaded. Panel slowdowns during extended thinking have been resolved by no longer reparsing the entire thinking text on every update. When certain language servers report issues, they no longer display [object Object], correctly showing rule identifiers instead (such as MD013). Environments without dictation, such as non-claude.ai logins or remote windows, no longer load the native audio module to check microphone permissions.

Classroom blackboards move straight into the editor: equations stay neatly typeset, and no derivation freezes the workspace in a vicious cycle no matter how long it takes.
