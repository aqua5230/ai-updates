Claude Code 2.1.277

Released: 2026-09-18

Release notes

FEATURE

Added AGENTS.md Support for Project Instructions, Automatically Loaded When No Custom File Exists

When working on projects following common standards, Claude Code now automatically reads AGENTS.md as guidance whenever there is no CLAUDE.md in the root directory.

This is like a patrol officer visiting a residence: if no custom notice is posted on the door, they consult the standard community guidelines instead.

You can customize the instruction file to read under "Project instructions" in /config. This feature is not yet available on Bedrock, Vertex, or Foundry.

FEATURE

Enhanced Forward Proxy Support for App Gateways, Adding Custom Headers and Proxy-Side Hostname Resolution

For enterprise Claude apps gateways whose only egress is a forward proxy, setting CLAUDE_GATEWAY_PROXY_IS_EGRESS_BOUNDARY=1 now hands the proxy the hostname for every outbound request instead of resolving it locally.

An optional headers: map has been added to upstream configurations to send static headers to a custom proxy running in front of a provider. When a proxy is configured, the telemetry relay no longer ignores collector hosts or domains listed in NO_PROXY. Loopback connection error messages now clearly suggest setting CLAUDE_GATEWAY_ALLOW_LOOPBACK.

This is like a multinational corporation's central mailroom: all outbound mail passes addresses directly to dedicated external couriers for sorting, while internal documents are routed directly to specific departments according to an exemption list.
FEATURE

Real-Time Background Task Update Notices, Preventing Session Crashes from Language Server Exits

When checking task progress, panels such as /tasks now display a line notifying you that an update is waiting if a background task finishes while the panel is open.

Background sessions started with claude --bg no longer unexpectedly exit when a plugin's LSP server exits or closes its stdin. The deprecated TaskOutput tool has been officially removed; Claude now reads background task output files using the Read tool, and the taskOutputMaxChars setting along with the TASK_MAX_OUTPUT_LENGTH environment variable no longer have any effect.

This is like a kitchen order notification light: if a new dish is ready while the front staff is reviewing order boards, it lights up immediately, and clearing away dirty plates in the back does not interrupt front-of-house operations.
FEATURE

Immediate Error Exits for Headless Sessions, Accelerating Startup and Accurately Accumulating Costs

When invoked via automated scripts or the SDK, sessions in headless mode no longer hang indefinitely after encountering an internal error; they now clearly report the error and exit with status code 1.

Resuming earlier sessions no longer resets cost and token usage totals to zero, as headless sessions properly save their cumulative totals at exit. The first turn in SDK and headless modes no longer waits on per-directory lookups for CLAUDE.md, speeding up startup. Standalone claude -p runs outside an SDK or IDE have removed the background Haiku auto-title request.

This is like an automated logistics conveyor belt: if a sorting module malfunctions, it immediately flashes a red light, halts, and reports an error, while restarting faithfully accumulates the weight of previously transported goods.
BUGFIX

Subagent Results Clearly Indented Under Headers, Fixing Collaborative Caching and Message Ordering

When collaborating across multiple agents, subagent results are now returned to the main agent under a dedicated header with indented formatting, preventing output from being mistaken for the session's own instructions.

Resumed subagents and teammates no longer re-render loaded MCP definitions, preserving the prompt caching mechanism. Agent messages arriving mid-turn now appear precisely where they arrived rather than below the command execution row. Fast typing or pasting in claude agents dispatch input no longer produces scrambled text. Pressing Enter on a selected agent panel row now functions properly. Script-computed prompts in cloud workflows are now clearly framed with their source.

This is like a cross-departmental project meeting: field assistants' investigation reports are submitted in dedicated covers with indented records, ensuring they are not confused with the host's agenda while preserving existing meeting minutes.
FEATURE

Plugin Installation Corruption Prevention, Accurately Recording Marketplace Versions with Update Prompts

When managing extensions, running claude plugin install to reinstall a plugin version currently in use by a session or another program leaves unchanged copies alone instead of corrupting the installed copy; if a newer version exists in the marketplace, the command now proactively notifies you and suggests claude plugin update.

Plugins installed from the official marketplace now correctly record their Git commit hash in installed_plugins.json, and updating a pinned-commit plugin updates this record accordingly. A malformed entry in enterprise marketplace rules no longer silently disables the entire marketplace policy. Plugin reload previews no longer keep unpacked archive files until exit, nor do they overwrite the fallback download cache.

This is like library collection maintenance: books currently borrowed by patrons remain untouched if there is no revised edition, and a few erroneous entries on a procurement list do not shut down the entire library's acquisition policy.
FEATURE

Cleaned Plugin Panel Display, Preventing Skill Management Crashes from Reserved Object Property Names

When browsing installed plugins on the Installed tab, error messages such as failed plugin updates now strip terminal control characters, ensuring clean, readable text.

The /plugin and /skills interfaces no longer crash when a skill or legacy command is named after built-in Object properties like constructor or toString. When every install in a multi-select operation fails, the panel now shows an explicit failure notice instead of closing silently. Removing uninstalled plugins no longer leaves orphaned "failed to load" rows in the interface. MCP servers listed separately from their plugins now clearly indicate which plugin they belong to.

This is like an app store management dashboard: even if an extension is named using a reserved word, the list remains neatly arranged and clearly marks which parent package each plugin belongs to.
BUGFIX

Comprehensive Fixes for File and Search Tools, Accurately Reporting System Resource and Match Errors

When searches cannot start because the system is out of processes, memory, or file handles, the Grep and Glob tools now return explicit errors instead of incorrectly reporting no matches.

Writing to an existing directory path with the Write tool now reports a clear error instead of treating it as declined permission. When matching fails on very large edits containing non-ASCII text or backslashes, the Edit tool now properly reports that the string was not found instead of throwing a regular expression too large error. The Edit tool also fixed an issue where an escaped backslash followed by uXXXX text was mistakenly treated as a \uXXXX escape sequence, which could cause edits of non-ASCII characters to accidentally overwrite escaped backslashes. Escaped control characters in paths are now handled as literal text. Reading PDF pages on Windows when working folder paths are long (about 120 characters or more) has also been resolved.

This is like a warehouse retrieval system showing an equipment malfunction during a power outage rather than reporting zero stock, and avoiding misinterpreting codes when transcribing special serial numbers.
FEATURE

Rate-Limited Artifact Publishes Support Retries, Dedicated Tool Accurately Reads Artifact Links

Previously, when Claude hit a rate limit while publishing, it was told to stop retrying even though nothing had been published.

If publishing an artifact hits rate limits, Claude is now clearly informed that nothing was published along with guidance on when to retry, rather than being told to give up completely. When conversations include claude.ai artifact links and the Artifact tool is available, Claude prioritizes reading content with the dedicated Artifact tool instead of using the generic WebFetch tool. Permission prompts for the Artifact tool are now more concise, listing pages and artifacts by title or file name while grouping relevant links after the explanatory text.

This is like a parcel locker when full: it clearly informs the courier that the package has not yet been deposited and suggests the next delivery window, while the delivery slip concisely lists package names and pickup barcodes.
FEATURE

Compound Bash Commands Fully Evaluated Under Sandbox, Dangerous Deletions Prompt Safety Guards

With the sandbox on (the guard that runs commands in an isolated area), some commands were slipping out of it entirely when they should not have.

When sandboxing is enabled, $TMPDIR no longer expands to an empty string in Bash commands executed outside the sandbox. Under the sandbox.excludedCommands exemption setting, every part of a compound command must match the rule to be exempt from the sandbox, preventing a partial match from bypassing sandboxing entirely. When a command involves high-risk rm deletions, the permission prompt explicitly names the flagged command and suggests adding a ${VAR:?} guard so headless runs can recover. Sandbox prompt instructions on cloud platforms now adopt first-party wording that clearly defines task permission boundaries.

This is like a heavy machinery safety gate in a factory: it opens only when the entire sequence of safety sensors is cleared, and triggering high-risk switches requires pressing dual two-hand safety confirmation buttons.
BUGFIX

Full Cache Preservation on Resumed Sessions, Reliably Loading Attachments and Worktree Skills

Picking an old conversation back up with --resume could previously crash it, or make every request after it fail.

Resuming an earlier session whose history contains plain-string assistant messages or empty text blocks alongside other content no longer causes request failures or crashes. When continuing sessions after /clear, --continue, or --resume, startup hook output no longer causes the first message fragment to be missed, preventing full prompt cache misses. Conversation attachments are no longer re-rendered after a resume or relaunch, fully preserving extended thinking and prompt cache status. Opening worktree sessions with --worktree now reliably loads main project skills even when .claude/skills is untracked by version control. A crash when resuming transcripts containing incomplete hook summaries has also been resolved.

This is like a vintage gramophone resuming record playback: even if silent gaps or commentary bookmarks are inserted between audio tracks, the needle tracks accurately without degrading the master tape's audio quality.
BUGFIX

Fault Tolerance for Malformed Configuration Files, Preventing Launch and Plugin Management Freezes

A single malformed value in ~/.claude.json used to be enough to make Claude Code hang or crash on launch.

Interactive startup no longer hangs or throws errors for users when customApiKeyResponses or theme values are corrupted. Opening /mcp or the /plugin manage panel with a malformed claudeAiMcpEverConnected field no longer triggers type error crashes. Remote Control session bookkeeping now functions properly even when encountering malformed placeholder records.

This is like a smart speaker reading a memory card: even if it encounters a few corrupted playlist preferences, it still boots smoothly into the main menu without disrupting everyday operations.
BUGFIX

Conflict-Free Multi-Version Logins, Tolerant Update Checks and Automatic Staging Cache Cleanup

Unexpected logouts, stalled or misleading updates: this group fixes problems you can hit while signing in and updating.

Running older and newer versions locally no longer causes unexpected account logouts. If a proxy returns an invalid version number, update checks no longer error every 30 minutes; when a minimum or maximum version is set, claude update no longer hangs; a malformed minimumVersion is now ignored. Installations managed via winget or apk no longer falsely report being up to date when version lookups fail. Failed auto-updates now proactively clean up ~/.cache/claude/staging, leaving no large staged downloads behind. Errors following revoked logins now lead with /login, and Console sign-in displays the server's error message when API key creation is refused.

This is like a commercial building access control system: swiping old and new badges across different readers does not invalidate either, and update failures automatically empty temporary lockers of discarded packages.
FEATURE

Automatic Sanitization for Invisible Prompt Characters, Ensuring Inputs During Processing Are Not Dropped

If you like to type your next message while Claude is still busy, that habit no longer costs you.

Messages typed while Claude is actively working are now properly processed rather than being ignored by the model. When prompts are entered, invisible Unicode formatting and tag characters are automatically stripped, displaying the cleaned prompt for your review before sending. Loading prompts containing terminal color codes from history or an external editor no longer triggers unrecoverable interface crashes.

This is like an automated mail sorting machine at the post office: it flattens envelopes and filters out invisible watermark impurities before letters enter sorting bins, without dropping incoming queued packages while processing previous mail.
FEATURE

Stable Terminal Rendering Enhancements, Real-Time Feedback on Fullscreen Text Copying

Crashing right after launch on slow machines and, in rare cases, a screen that stops updating: neither happens anymore.

Launching sessions under heavy system load no longer crashes with unrecoverable interface errors when the initial spinner appears. A rare issue where the screen could stop updating for the rest of the session after an internal rendering error has been eliminated, ensuring continuous live updates. In the fullscreen /resume session picker and other panels covering the prompt area, drag-selecting text with the mouse now reliably displays the copied notice. Startup overflow lines under the logo now concisely show how many notices are hidden.

This is like a high-resolution airport departure board: turning on power during crowded peak hours does not result in a black screen crash, and selecting flight codes with a mouse instantly triggers a copied notification.
FEATURE

Smarter Code Review Command Guidance, Persistent Model Listings with Clear Refusal Explanations

When running the code review command /ultrareview with nothing to review, the interface now explains the context and offers a command to review your latest commit, while the first commit in a new repository is reviewed in full; in non-interactive sessions, it explicitly refuses when the repository lacks a base branch or shared history.

On the Anthropic API, Fable now always appears in the /model list, appearing greyed out only when disabled by organization settings. In Cowork cloud sessions, WebFetch and WebSearch now clearly inform Claude of the exact reason when requests are refused, such as a used-up fetch budget or admin policy restrictions. An issue on Windows where out-of-memory errors immediately following Claude's reply prevented tool calls from executing has also been resolved.

This is like an editor-in-chief at a newspaper: when there are no new submissions on the desk, they proactively suggest reviewing the latest column, and clearly state reasons when access permissions are insufficient.
FEATURE

[VSCode] Panel Menu Supports Quick Logout, Comprehensively Managing Background Tasks and Usage Metrics

If you use Claude Code in VS Code, this release adds new actions such as signing out, stopping background tasks, and copying responses.

A "Sign out" row has been added to the panel menu, along with support for typing /logout in the command menu. The agent map now includes background shells and running tasks, each equipped with a Stop button, and can be opened directly with /tasks. A Copy response button is now available beside AI responses, alongside a typed /copy command. A one-time notice appears when inactive sessions are archived automatically, and an "Unarchive all" action has been added to the Archived sessions group. In environments where plan limits do not apply, the Account & usage dialog and session manager now display costs and token usage.

This is like an office's advanced smart control console: it lists management controls for background printers and shredders alike, while sending a helpful notification whenever document folders are automatically archived.
FEATURE

[VSCode] Intuitive Settings and Feature Menus, Persisting Effort Levels and Fast Mode

Preferences you set in VS Code could previously vanish after a restart.

Clicking the "General config" menu item now opens settings directly, and typing commands such as /mcp, /hooks, /memory, and /rewind directly opens their respective dialogs. Effort levels adjusted via the slider now persist across sessions on models that already had a level saved with /effort. The mode picker no longer misses the Auto option when saved model settings use differently-cased aliases like "Sonnet". Toggling fast mode with /fast is now correctly saved as the default, remaining active after restarts.

This is like a custom dial on a professional camera: it securely stores shortcut menus and aperture settings in internal memory, preserving your familiar shooting mode even after powering back on.
FEATURE

[Claude Code on the Web] Tiered Cloud Environment Management, Supporting Organization Sharing and Network Safeguards

When a Team or Enterprise plan shares cloud environments, the hard part is telling which ones are yours and which ones everyone uses.

On Team and Enterprise plans, the cloud environment picker is now divided into Personal and Organization sections, allowing admins to share personal environments with the entire organization. Organization environments open as read-only summaries by default on the Code tab to prevent unauthorized modifications, while editing is consolidated under Admin settings → Cloud environments. Cloud environments saved with Custom network access and no domains no longer silently revert to Trusted mode, and the dialog now requires at least one domain. The admin setting label has been renamed to "Cloud sessions", removing the redundant read-only Mobile row beneath it.

This is like conference room access control in a shared office space: private rooms can be upgraded to all-hands meeting rooms, while the authority to alter room layouts remains strictly reserved for building management.
BUGFIX

[Claude Tag] Fixed Cross-Channel Routine Reads, Upgraded Credential Forms and Network Logs

For teams using Claude Tag in Slack, this group of fixes centers on routines and access credentials.

Routines created in a Slack channel on an Enterprise Grid org-wide install can now properly read other public channels in their workspace when running. Links on credential presets in Claude Tag access bundles now open each vendor's dedicated credential-setup page instead of generic API documentation. Admins can now point the Pylon credential preset at Pylon's EU host. Google Cloud credential forms in access bundles now explain why a key file is refused, the website and scopes stay locked, and pasted keys are preserved when a replacement is rejected. The network events log in admin settings fixed missing response statuses for connections using AWS signing, client certificates, or a custom CA.

This is like a digital pass application desk at an international business center: application forms direct you precisely to dedicated embassy visa pages, and retain filled-in fields when submissions fail so they can be easily corrected and re-submitted.
