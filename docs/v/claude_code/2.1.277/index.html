Claude Code 2.1.277

發布日期：2026-09-18

繁體中文

專案指示新增 AGENTS.md 支援，無專屬設定時自動代入

當你接手遵循通用標準的專案時，只要根目錄中沒有 CLAUDE.md，Claude Code 現在會自動讀取 AGENTS.md 作為指引。

這就像巡邏員查訪住戶，若門口沒貼專屬公告，便主動借閱通用的社區規章。

你可以在 /config 的「Project instructions」項目下自訂要讀取的指示檔案。這項功能目前尚未套用至 Bedrock、Vertex 或 Foundry 平台。

應用網關轉發代理強化，支援自訂標頭並改由代理解析主機名稱

針對僅透過正向代理連線的企業應用網關，現在可設定 CLAUDE_GATEWAY_PROXY_IS_EGRESS_BOUNDARY=1，讓所有對外請求直接交由代理伺服器解析主機名稱，不再於本機自行解析。上游配置新增選填的 headers: 對應表，可向模型供應商前端的自建代理傳送靜態標頭。設定代理時，遙測（telemetry，收集軟體運作數據以利分析的機制）轉發器不再忽略 NO_PROXY 名單中的主機或網域。本機回送連線錯誤訊息現在會明確提示設定 CLAUDE_GATEWAY_ALLOW_LOOPBACK。

這好比跨國企業的郵務總收發處，所有對外信件直接將收件地址交給專屬外務快遞分揀，內部公文則依照豁免清單直送特定部門。

背景任務即時提示更新，工作階段不再因語言伺服器中斷

檢視執行進度時，若背景任務在此期間處理完畢，/tasks 等面板會即時出現提示行，告知有等待檢視的最新進展。以 claude --bg 啟動的背景工作階段，不再因為外掛的語言伺服器（LSP，在背景分析程式碼語法的輔助工具）結束或關閉標準輸入而異常退出。舊版的 TaskOutput 工具已正式移除，Claude 改用 Read 工具讀取背景任務輸出檔，taskOutputMaxChars 設定與 TASK_MAX_OUTPUT_LENGTH 環境變數不再生效。

這如同後台的廚房出餐通知燈，當外場翻閱點餐板時若有新菜餚出爐會即刻亮燈，打烊清理部分餐盤也不會影響前台營業。

無頭工作階段錯誤即時退出，啟動加速且精準累計費用

透過自動化腳本或 SDK 呼叫時，在無頭模式（headless，沒有終端機視覺介面的執行模式）下的工作階段若遭遇內部錯誤，不再無限期卡住，現在會清楚回報錯誤並以狀態代碼 1 退出。接續執行先前的工作階段時，花費用量與權杖計量不再從零起算，無頭工作階段會在結束時妥善儲存總計數據。SDK 與無頭模式的首輪對話不再等待逐層搜尋目錄下的 CLAUDE.md，加快了啟動速度。在 SDK 或 IDE 之外單獨執行的 claude -p 移除了背景生成標題的 Haiku 請求。

這就像自動化物流傳送帶，一旦分揀模組故障便立即亮紅燈停機報錯，重新啟動時也會忠實累加已搬運的貨物重量。

子代理結果清晰標註縮排，協同快取與訊息排序修復

多個代理同時協同分工時，子代理的執行結果現在會加上專屬標題與縮排後傳回主工作階段，避免回傳內容被誤認為主對話的指令。接續執行的子代理與隊友不再重新渲染已載入的 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）定義。這項改進妥善保護了快取（暫存提示詞以加快反應）機制。對話中途抵達的代理訊息會精準顯示在抵達位置，而非排在指令列下方。在 claude agents 指令中快速輸入不再產生亂碼。代理面板中按下 Enter 鍵能正常選取。雲端工作流程中的腳本提示詞現在明確標註來源。

這好比跨部門專案會議，外派助理的調查報告均附上專用簽呈封套並縮排記錄，既不會與主持人的議程混淆，也保留了既有的會議記錄。

外掛安裝防損毀，市集版本精確記錄並支援更新提示

管理擴充套件時，執行 claude plugin install 重新安裝正在被某個工作階段或其他程式使用的外掛版本，若版本未變更會保留原樣，不再損毀已安裝的副本；若市集有新版本，指令會主動提示並建議改用 claude plugin update。官方市集安裝的外掛現在會在 installed_plugins.json 中正確記錄 Git 提交雜湊，更新固定版本的套件時也會同步刷新紀錄。企業市集規則中若存在格式錯誤的項目，系統不再默默關閉整套市集控管策略。外掛重載預覽不再於結束前持續佔用解壓暫存檔，也不會覆寫備援下載快取（暫存安裝檔的空間）。

這就像圖書館的館藏維護，讀者正在借閱的圖書若無修訂版就原地保留，採購清單中少數有誤的書目也不會導致全館進書政策停擺。

外掛面板顯示淨化，特殊名稱不再造成技能管理閃退

開啟外掛分頁瀏覽已安裝清單時，更新失敗等錯誤訊息現在會自動清除終端機控制字元，確保文字清晰可讀。當技能或舊指令命名為 constructor 或 toString 等特殊屬性名稱時，/plugin 與 /skills 介面不再發生閃退。多選安裝全數失敗時會明確顯示失敗通知，不再無聲關閉面板。移除已解除安裝的外掛後，介面不會再殘留「載入失敗」的無效列。獨立列出的 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器現在會清楚標示所屬的外掛名稱。

這好比應用程式市集的管理面板，即便擴充模組使用了保留字命名，清單依然整齊陳列並清楚標註每個外掛的母套件歸屬。

檔案與搜尋工具全面除錯，精確回報系統資源與比對錯誤

當系統耗盡行程、記憶體或檔案控制代碼導致搜尋無法啟動時，Grep 與 Glob 工具現在會明確報錯，不再誤報為找不到項目。使用 Write 工具寫入既有資料夾路徑時，會明確回報錯誤，不再誤判為權限被拒絕。Edit 工具在處理包含反斜線或非 ASCII 字元的超大文字時，比對失敗會正確顯示找不到字串，不再拋出正規表達式（用符號比對文字的語法）過大的錯誤。Edit 工具也修復了將反斜線後接 uXXXX 文字誤當作 \uXXXX 跳脫處理的問題，可能導致非 ASCII 字元的編輯意外覆蓋跳脫反斜線序列。路徑中的轉義序列會作為文字處理。Windows 環境下工作目錄長度約 120 個字元以上時讀取 PDF 頁面失敗的問題也已修復。

這好比倉庫檢索系統在電力中斷時直接顯示設備異常，而不是回報庫存為零，抄寫特殊編號時也不會誤判代碼。

成果工件發布支援限流重試，專屬工具精確讀取連結

以前 Claude 發布內容撞上頻率限制，會被告知別再重試，但其實東西還沒發出去。發布成果工件（Artifact，AI 產生的獨立檔案或程式碼成果）若觸發頻率限制，系統會清楚告知 Claude 本次尚未發布成功並提示重試時間，不再要求它直接放棄。當對話中包含 claude.ai 工件連結且 Artifact 工具可用時，Claude 會優先使用專屬的工件工具讀取內容，而非使用泛用的 WebFetch 網頁擷取工具。工件工具的權限確認提示語句現在更為簡短，清楚列出頁面與工件的標題或檔名，並將相關連結統一整理在說明文字後方。

這宛如快遞櫃在收件櫃位滿載時，清楚告知外送員包裹暫未入櫃並提示下一梯次投遞時間，派件單上也精簡列出包裹名稱與取件條碼。

Bash 沙盒複合指令全面受檢，刪除操作主動提示安全防護

開著沙盒（把指令關在隔離區裡跑的防護）時，有些指令其實不該整條溜出去。啟用沙盒時，在沙盒外執行的 Bash 指令中 $TMPDIR 變數不再被展開為空字串。在 sandbox.excludedCommands 豁免設定中，複合指令必須所有子指令都符合規則才能豁免於沙盒，防止部分符合就整條跳出防護。當指令涉及高風險的 rm 刪除操作時，確認提示會具體點出違規指令並建議加上 ${VAR:?} 安全防護變數，讓無頭模式（headless，沒有終端機視覺介面的背景運作模式）也能順利復原。雲端環境上的沙盒提示詞採用官方標準用語，明確規範任務權限邊界。

這好比工廠重型機具的操作防護門，只有在整串安全感應器全數通過時才允許開啟，啟動危險開關時也必須按下雙手安全確認鍵。

工作階段接續完整保留快取，附件與平行副本技能正常載入

用 --resume 接回舊對話，以前可能當機，或之後每次請求都失敗。接續執行先前的工作階段時，對話歷史若包含純文字助理訊息或空白文字區塊，不再導致請求失敗或崩潰。在 /clear、--continue 或 --resume 接續對話時，若啟動掛鉤（hook，特定事件發生時被觸發的小程式）印出輸出，系統不再遺失首條訊息片段。這項修正避免了快取（暫存提示詞的機制）完全失效。對話附件在重啟後不會被重新渲染，完整保留了思考過程與快取狀態。使用 --worktree 開啟平行副本工作階段時，即使 .claude/skills 未被版控追蹤，也能順利載入主專案技能。歷史紀錄中包含不完整掛鉤摘要的崩潰問題也已修復。

這好比老牌留聲機在接續播放唱片時，即使音軌間穿插靜音段落或插入解說書籤，磁頭依然精準循軌而不破壞母帶音質。

設定檔格式異常安全容錯，啟動與外掛管理不再卡死

~/.claude.json 裡只要有一個值格式不對，以前就可能讓 Claude Code 一開就卡住或當掉。使用者在啟動時即便 customApiKeyResponses 或 theme 主題設定值損毀，互動介面也不會卡死或拋出錯誤。開啟 /mcp 工具管理或 /plugin manage 外掛面板時，若 claudeAiMcpEverConnected 欄位格式異常，不會再引發型別錯誤崩潰。遠端控制工作階段的紀錄簿在遇到格式不正確的佔位紀錄時也能正常運作。

這好比智慧音響在讀取記憶卡時，即便遇到幾行毀損的播放清單偏好，依然能平穩開機進入主選單，不影響各項功能操作。

多版本並行登入不衝突，更新檢查容錯並自動清理快取

莫名被登出、更新時卡住或誤報，這組修的都是登入與更新時會撞到的問題。當本機同時執行新舊版本時，不再發生帳號無預警被登出的問題。代理伺服器回傳無效版本號時，更新檢查不再每 30 分鐘報錯；有設定最低或最高版本時，claude update 不再卡住；格式錯誤的 minimumVersion 現在會被忽略。透過 winget 或 apk 安裝時，若查詢版本失敗不再誤報為最新版本。自動更新失敗後會主動清理 ~/.cache/claude/staging，不再殘留龐大的快取（暫存檔案的空間）。撤銷登入時會提示執行 /login，在主控台登入若伺服器拒絕建立 API 金鑰，也會顯示伺服器錯誤訊息。

這就像商務大樓的門禁系統，新舊識別證在不同刷卡機讀取不會互相註銷，更新失敗時也會自動清空暫存箱的廢棄包裹。

提示詞字元自動過濾清洗，運算中輸入訊息不遺漏

Claude 還在忙時你就先打好下一句，這個習慣現在不會再吃虧。當你在 Claude 仍在運算處理時預先鍵入訊息，這些訊息現在會被妥善排程處理，不再被模型遺漏忽視。輸入提示詞時，系統會主動過濾並清除不可見的 Unicode 格式與標籤字元，並在送出前展示清理後的文字供你確認。從歷史紀錄調出或自外部編輯器載入包含終端機顏色代碼的提示詞時，不再觸發無法復原的介面錯誤崩潰。

這如同郵局的自動分信機，在信件送入分揀槽前先撫平紙張並濾除隱形水印雜質，在處理前一封郵件時也不會漏掉排隊中的新包裹。

終端機渲染效能穩定提升，全螢幕文字選取複製即時回饋

慢電腦上剛啟動就當掉、少數情況下畫面停住不動，這兩件事不會再發生。在電腦高負載時啟動工作階段，介面不再因為首次顯示旋轉載入圖示而崩潰退出。內部渲染錯誤後螢幕可能停止刷新的問題已排除，確保畫面在整個工作階段期間持續即時更新。在全螢幕的 /resume 工作階段選擇器與其他覆蓋輸入區的面板中，透過滑鼠拖曳選取文字後，已能正常顯示已複製的提示通知。啟動時商標下方的過長通知提示行，改為以隱藏 N 則通知的簡明文字呈現。

這宛如機場大廳的高解析航班看板，即使人潮擁擠時開啟電源也不會黑屏當機，滑鼠選取航班代碼時也會即時彈出複製完成的提示。

審查指令指引更智慧，模型清單常駐並精確回報拒絕原因

執行程式碼審查指令 /ultrareview 時，若無待審變更，介面會說明情境並提供審查最新提交紀錄的指令，對新套件庫的首個提交也會完整審查；非互動環境中若無基礎分支或共同歷史則會明確拒絕。在 Anthropic API 模式下，/model 清單一律會顯示 Fable 模型，僅在組織停用時反灰。在 Cowork 雲端工作階段中，WebFetch 網頁擷取與 WebSearch 搜尋工具在請求被拒時會明確告知 Claude 具體原因，例如額度用盡或管理員策略限制。Windows 上回覆後因記憶體不足導致工具呼叫未執行的問題也已修復。

這好比報社的審稿總監，桌面沒有新投稿時會主動提議複審最新專欄，調閱權限不足時也會標明原因。

[VSCode] 面板選單支援快速登出，背景任務與用量統計全面納管

在 VS Code 裡用 Claude Code 的人，這版多了登出、停止背景任務、複製回應等幾項新操作。面板選單中新增了「Sign out」登出選項，並支援在指令列鍵入 /logout 快速登出。代理地圖中現在納入了背景終端機與執行中的背景任務，每項任務均配備停止按鈕，並可透過 /tasks 指令直接開啟檢視。AI 回覆訊息旁新增了複製按鈕，亦可鍵入 /copy 複製完整回覆。閒置的工作階段被自動封存時會彈出單次提示，封存分組中也新增了全部解除封存按鈕。在不適用方案上限的環境中，帳戶用量對話框與工作階段管理器現在會顯示花費與 token（AI 處理與計費的文字單位）使用量。

這就像辦公室的高級智慧中控台，將正在背景運作的印表機與碎紙機一併列出管理按鈕，並在公文夾自動歸檔時發出貼心通知。

[VSCode] 設定與功能選單直覺開啟，思考程度與快速模式持久保存

在 VS Code 裡設好的偏好，以前重開後可能就不見了。點選「General config」選單項目現在會直接開啟設定頁面，鍵入 /mcp、/hooks（掛鉤，特定事件發生時被觸發的小程式）、/memory、/rewind 等指令也能直接叫出對應的設定對話框。透過思考程度滑桿設定的數值，現在會跨工作階段持續保存，不再遺失先前以 /effort 儲存的等級。以不同大小寫別名（例如「Sonnet」）儲存模型時，模式選擇器不再遺漏自動模式選項。執行 /fast 指令切換的快速模式已能正確儲存為預設值，重新啟動後依然生效。

這宛如專業相機的自訂轉盤，將快捷選單與光圈設定精準儲存在機身記憶體中，重新開機後依然維持你最熟悉的拍攝模式。

[網頁版] 雲端環境分層管理，支援組織共用與嚴謹網路限制

在 Team 或 Enterprise 方案裡共用雲端環境，最怕分不清哪個是自己的、哪個大家都在用。在 Team 與 Enterprise 企業方案中，雲端環境選擇器現在劃分為個人與組織兩個專屬區塊，管理員可直接將個人建立的環境共享給整個組織。組織共用環境在 Code 分頁中預設以唯讀摘要呈現，防止非管理員誤觸修改，編輯功能統一移至管理員設定的雲端環境專區。設定為自訂網路存取但未填寫任何網域的雲端環境，不再無聲還原為受信任模式，儲存時會主動要求至少填入一個網域。管理員設定中的標籤已重新命名為「Cloud sessions」（雲端工作階段），並移除了下方多餘的唯讀行動裝置列。

這就像共用辦公空間的會議室門禁權限，個人專用室可升級為全員會議室，並將調整格局的權限嚴格保留給大樓管委會。
