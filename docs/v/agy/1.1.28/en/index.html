Antigravity 1.1.28

Released: 2026-09-09

Release notes

FEATURE

Automatic extended retries on temporary 503 errors keep sessions uninterrupted

When asking AI to perform long multi-step tasks, the biggest worry is hitting brief congestion on remote model servers.

Much like a card reader briefly disconnecting at a busy bakery checkout, where the clerk does not immediately return your items and show you out the door, but asks you to wait a moment and tap again until the connection recovers.

Previously, whenever encountering a transient model API error like 503 Unavailable, the entire ongoing session was forced to terminate. Now, when encountering such temporary situations, the agent significantly extends the retry period using exponential backoff (waiting longer between retries as failed attempts increase). Even during brief service fluctuations, your session will no longer be casually interrupted.

FEATURE

Local credentials speed up sign-in identity checks and account switching clears stale business data

Launching the tool or switching accounts is now ready promptly every time.

Previously, opening the CLI or completing browser authorization required sending a network request to verify your identity; if the lookup ran into issues, the entire sign-in process would freeze and halt, and the plan tier shown at startup often flickered and disappeared. Now, data is read directly from stored credentials (login identity proofs stored locally), so lookup failures no longer block sign-in completion, and the on-screen plan tier remains stably displayed. If you switch from a business account with a selected project to a personal account, old business project and license details are now thoroughly cleared, preventing project access errors caused by leftover stale data.

This is like showing a stamped membership card directly from your wallet at the gate without ticket staff calling headquarters every time, and handing over a regular visitor pass while returning the VIP badge so outdated passes will not block the entrance.
FEATURE

Smoother headless automation with prompt exits and clear error reporting

Chaining commands into automated workflows demands clean execution and explicit feedback.

Much like a logistics delivery fleet consolidating cargo overnight, departing immediately once loading is complete and leaving clear labels and receipts along the way without idling on-site because no one is there to sign.

When running in headless mode with the -p flag, the CLI now exits promptly once the final answer is delivered. Running background tasks and scheduled timers are waited on subject to --print-timeout, while persistent daemon tasks like development servers continue running without being forcefully terminated. Each turn cuts up to 200 ms of idle latency and skips generating conversation titles that nobody would see. Non-interactive implementation plan reviews now pass automatically. If --print-timeout expires mid-turn, it returns the partial output and exits successfully with a warning on stderr, while manual Ctrl+C interrupts still exit with a non-zero code. Fatal errors add a stable error: marker on stderr, noting potential truncation and explaining why previous runs ended silently.

FEATURE

URL fetching asks for permission first and tool approval prompts explain reasons clearly

Security guardrails are much clearer when having AI fetch data or invoke local tools.

The default permission for fetching URLs has changed from always allowed to asking first, requesting approval before reading a URL unless pre-authorized. Tool approval prompts have also been revamped to specify exactly what is being approved—such as asking Run this command?, Allow access to this URL?, or Allow calling this tool?. The shortcut for editing commands is only offered when approving a command, preventing interface confusion. When the reason for approval is not obvious, a Reason: line is attached below explaining why, such as a hook flagging the action or a file belonging to a different project.

This is like installing a smart intercom at the front door: visitors must ring first, the screen clearly displays their identity and purpose, and notes any guard inspection reasons so you never press the door release blindly.
FEATURE

Model name resolutions are logged for traceable audit trails

When specifying model names in the terminal, the actual underlying resolution is now crystal clear.

Much like filling a prescription at a pharmacy where an out-of-stock brand-name drug is substituted with an equivalent generic, with the replacement record and rationale clearly noted on the receipt and label.

The CLI tool has enhanced its auditability for model selection. Whenever a model name you specify resolves behind the scenes to a different model, the logs faithfully record the specific conversion process. Whether resolving an alias to an official name, switching to a different reasoning variant via the --effort flag, or replacing a deprecated saved model, everything leaves a clear trail in the logs. This removes any guesswork about which version is running behind the scenes, allowing you to trace the active model at any time.

BUGFIX

Plugin reinstalls cleanly replace directories and MCP relative paths resolve accurately

Managing plugins and bundled tools no longer leaves annoying leftover files behind.

Previously, reinstalling a plugin left old files that were already deleted from the source inside the directory; now, installation replaces the managed plugin directory exactly, and attempting to install from the plugin's own installed directory is directly rejected to prevent corruption. Uninstalling a plugin also no longer leaves leftover enabled or disabled entries in config.json. Meanwhile, if MCP servers defined by plugins use relative paths or leave the working directory unset, they previously resolved against the wrong location; they now consistently resolve against the plugin's own directory, ensuring bundled scripts run properly.

Just like swapping a camera lens kit: mounting a new set completely removes old glass, detaching it cleans up stale button mappings from the control menu, and dedicated kit filters align accurately against the lens mount.
BUGFIX

Subagents reliably discover tools at startup and release queued messages upon completion

Dispatching subagents for complex multi-tasking now offers more reliable tool discovery and state transitions.

Previously, a startup race condition meant subagents could fail to find tools if external tool servers were still initializing. Now, MCP servers ensure initialization finishes so subagents can always find their tools. Additionally, especially in very large conversations, subagents sometimes appeared stuck in a running state after finishing; this caused incorrect status reporting and left messages queued for idle delivery stuck until restarting the application. Both issues are now resolved, so subagents properly transition their state and deliver queued messages on schedule once tasks finish.

Like assigning an intern assistant on the factory floor: they are only sent to fetch tools after equipment warms up, and they report shift handovers immediately upon finishing tasks rather than pretending to stay busy and stalling dispatch orders in the mailroom.
BUGFIX

Terminal commands release internal state promptly to cut memory usage in long sessions

Running continuous commands in the same session no longer leads to runaway memory bloat.

Previously, the tool suffered from a memory leak where every executed terminal command retained its internal state in memory for the rest of the session. As a result, running many commands in extended sessions caused memory usage to surge continuously. This fix thoroughly clears residual state once commands finish, significantly reducing memory consumption in long sessions that run many commands.

Much like wiping down a kitchen countertop immediately after each dish instead of piling up used plates and pots until closing time, keeping the workspace neat and uncluttered even during a full day of service.
