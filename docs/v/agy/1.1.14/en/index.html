Antigravity 1.1.14

Released: 2026-08-18

Release notes

FEATURE

Returning sign-in points straight to your last method

Returning to an enterprise account no longer starts with guessing which route to take.

You are offered one Continue with ... choice named after the method you used last time.

It is like an e-reader remembering the chapter where you stopped and taking you there when you reopen it.

You still choose how to sign in; the entry point now begins with a known direction instead of a row of possibilities.

FEATURE

MCP servers can supply their OAuth client identity details

When connecting a tool to an MCP server, you may previously have needed to supply a client ID yourself or arrange dynamic client registration.

A server that implements OAuth client ID metadata documents can now provide those identity details.

It is like an exhibition wall listing venue details that a guide device can read directly instead of making visitors fill them in.

Such servers no longer require a manually supplied client ID or dynamic client registration.

FEATURE

Context and usage panels fit terminal and scroll

Opening /context in the terminal now gives you a scrollable panel sized to the terminal.

/usage uses the same sizing.

Think of an expandable document rack that adjusts to the desk: when its visible area is not enough, the documents are not cut off; you scroll down to see more.

Both panels therefore adapt to the terminal, and /context lets you view what extends beyond the screen. This does not claim new context, usage data, or commands.

FEATURE

One switch decides what a markdown agent inherits

When defining an agent in Markdown, one inheritCustomizations switch now decides whether it adopts your skills, rules, plugins, subagents, and MCP servers.

Each kind previously had defaults that could silently disagree.

It is like replacing five light switches facing different directions with one main switch for whether a room keeps your arrangement.

Built-in skills, rules, and plugins also remain when an agent sets inherit_user to false, because that setting only opts out of personal customizations, not CLI-supplied ones.

FEATURE

Outside-workspace access is read-only; cycle mode governs writes

When an agent needs to view files outside your workspace, that access setting now grants read access only.

Writes are automatically approved according to the cycle mode setting.

It is like a reading room handing you material from outside its shelves to examine, while marking it still follows a separate borrowing rule.

Reading and writing are no longer bundled under one outside-workspace permission: the first is read-only and the second is assigned to cycle mode.

BUGFIX

Language-server failures are reported instead of looking successful

If the language server, a background service that helps the program understand language content, fails during startup or while the CLI is running, the failure now prints in the terminal and the process exits non-zero.

It previously left silently while reporting success.

It is like a broken cash register that no longer closes its door and stamps the ledger “completed,” but writes the fault on the counter.

The terminal output and exit status can now show the failure; this does not claim to repair the language server itself.

BUGFIX

Terminals without OSC 8 support get readable sign-in links

If your terminal cannot parse OSC 8 hyperlinks, the sign-in URL and other links could previously render as garbled text.

The program now detects such terminals, including GNU screen, and gives plain text instead.

It is like replacing an invitation written with an unreadable code with a note that writes out the address.

The change concerns links in terminals that do not support OSC 8; it does not say supported terminals lose their hyperlink format.

BUGFIX

Enter no longer submits prompt while path suggestions load

When the path-suggestion popup was still loading, pressing Enter used to swallow the key: the prompt was sent, then results opened on top of it.

That ordering error is now fixed.

It is like a menu in the same input field still loading when a key submits its content first, then the menu results cover what was just sent.

The fix covers the popup's loading state and the overlap caused by the swallowed Enter key. Results no longer open over the prompt.

BUGFIX

Reopened artifact lists keep each earlier review status

When reopening the artifact list, a list of code or documents produced in a conversation, every earlier artifact is no longer marked approved.

Items left unreviewed, commented on, or rejected in the previous turn keep their actual status.

It is like reopening a graded workbook where blank, annotated, and returned pages stay in their places instead of receiving one “approved” stamp.

The list therefore reflects the previous review result rather than rewriting every old item because you reopened it.

BUGFIX

One malformed MCP entry no longer takes down other servers

If one entry in an MCP configuration is malformed, it previously could bring down every other server too.

That error is now logged and skipped, while the remaining servers still load.

It is like a conductor putting aside one unreadable sheet of music so the other players can still take the stage.

The bad entry is not made correct and its server is not promised to load; the change is that one error no longer topples the rest.

BUGFIX

Long conversations can revert or branch past the SQL-variable limit

After a conversation grows long, reverting to earlier content or opening a branch could fail with too many SQL variables.

SQL is a language for querying databases, and that message means too many query variables were involved.

It is like trying to retrieve a passage from a huge stack of index cards or make a new copy, while the old method jams too many cards into one query slot.

Long-conversation reverts and branches no longer fail with that error. This fix concerns those two actions, not titles or history truncation.

BUGFIX

Long-conversation titles no longer jump to old messages after truncation

After a long conversation's history was truncated, its title could jump to an unrelated older message.

The fix protects the checkpoint, a marker that remembers a progress position, from which the title is derived, so the title keeps its correct source.

It is like putting away early pages of an overgrown notebook: the cover title used to read an old bookmark, but the bookmark that determines the title is now protected.

History truncation therefore no longer sends the title to an unrelated old message. This fix concerns title sourcing, not reverting, branching, or SQL-variable errors.

BUGFIX

A multi-line paste no longer sends one prompt per line

Pasting multiple lines into a terminal that does not honor bracketed paste used to submit one prompt for each line.

The pasted block is no longer submitted line by line.

It is like placing a stack of papers in a mail slot that once delivered every sheet as a separate letter, but now recognizes this paste as one stack.

The fix applies where the terminal does not honor bracketed paste; it does not claim to change terminals that do.
