Antigravity 1.1.14

發布日期：2026-08-18

繁體中文

回訪登入少走岔路，直接看見上次方法

公司帳號又要登入時，畫面不必再讓你猜該選哪條路。回來的使用者現在會看到一個 Continue with ... 選項，名稱就是自己上次採用的登入方式。

這像閱讀器記住你上次停下閱讀的章節，重新打開時會先帶你回到那一章。

你仍是在選登入方式，只是入口先對準已知方向，少了在多個選項間來回找的步驟。選項也會直接點出那個方法名稱。

連 MCP 伺服器時，登入身分資料可自動接手

要把工具接到 MCP（讓 AI 連接外部工具的協定）伺服器時，原本可能得自己交出 client ID，或替它辦動態註冊。現在伺服器若有實作 OAuth client ID metadata 文件，就能提供這份登入身分資料。

像展覽牆列出場館資料，讀得懂格式的導覽機可直接讀取，不必由遊客補填。

因此，符合這段規格的伺服器不再要求手動提供 client ID 或動態 client 註冊；沒有實作這段規格的伺服器，更新內容沒有承諾改變。

內容與用量面板跟著終端機大小，可捲動查看

在終端機裡打開 /context 想看內容時，面板現在能捲動，也會依終端機尺寸調整。/usage 的尺寸也採相同作法。

像可伸縮的文件架會跟著桌面大小收放；架子看得到的範圍不夠時，文件沒有被裁掉，而是往下捲動查看。

因此兩個面板都跟著眼前終端機調整，/context 還能查看超出畫面的部分。這項變更沒有宣稱增加內容、用量資料或新的指令。

代理程式繼承個人自訂，改用一個總開關決定

你在 Markdown 寫代理程式時，現在可用 inheritCustomizations 一個開關決定它是否採用你的 skills、rules、plugins、subagents 與 MCP servers。先前各種類各自有預設值，彼此還會默默不一致。

這像把五把各自方向不同的燈開關，換成一個總開關來決定整間房是否沿用你的佈置。

內建的 skills、rules、plugins 也不會因代理程式把 inherit_user 設為 false 而消失，因為 false 原本只表示不採用你的個人自訂，不是退出 CLI 隨附的內容。

工作區外存取改成唯讀，寫入照循環模式處理

需要讓代理程式查看工作區外的檔案時，這個存取設定現在只授予讀取權。寫入則依 cycle mode 設定自動核准。

這像借閱室把館外資料交給你翻閱，但要在上面動筆，仍按另一套借閱規則處理。

讀取與寫入不再由同一句「允許工作區外存取」混在一起；前者限為唯讀，後者明確交給 cycle mode。這是既有設定權限的調整，並非宣告可任意寫進工作區外位置。

語言伺服器失敗不再假裝成功，終端機會說明

CLI 啟動時或正在運作時，語言伺服器（替程式理解語言內容的背景服務）若失敗，現在會把失敗印在終端機，並以非零狀態結束。過去它會安靜離開，卻回報成功。

這像店裡的收銀機壞了，門不再悄悄關上並在帳上蓋「交易完成」，而是把故障寫在櫃檯上。

它不會再安靜離開卻報成成功。你因此能從終端機和結束狀態辨認失敗；更新內容沒有表示會自動修好語言伺服器本身。

不懂 OSC 8 的終端機，也能看清登入連結

若你的終端機不會解析 OSC 8 hyperlinks，登入 URL 和其他連結先前可能顯示成亂碼。現在程式會偵測這種終端機，例如 GNU screen，改給純文字。

這像對方看不懂附有暗號的邀請卡時，改遞上一張把地址完整寫出的紙條。

改變的是連結在不支援 OSC 8 的終端機裡的呈現方式；支援該格式的終端機，原始更新沒有說要改成純文字。

路徑建議還在載入，Enter 不會先送出提示

剛叫出路徑建議視窗，結果還在載入時按 Enter，先前 Enter 會被吃掉：提示送出後，結果又在提示上方彈開。現在不再發生這個順序錯亂。

像同一個輸入欄的選單尚未載入完，按鍵卻先把內容送出，接著選單結果又蓋到剛送出的內容上。

修正針對路徑建議彈出視窗仍在載入的狀態，以及 Enter 被吞掉後造成的送出與結果重疊。結果不會在提示上方再開一次。

重開產物清單，舊項目的審核狀態不再全變通過

重開 artifact list（對話產生的程式碼或文件清單）時，先前每個 artifact 不會再一律被標為 approved。上一輪尚未審核、留下評論、或被拒絕的項目，現在會保留原本狀態。

這像把上次批改過的作業本重新翻開，空白、註記與退回的頁面仍各自留在原位，不會全部蓋成「通過」。

因此清單反映的是前一輪實際審查結果，而非重開動作替所有舊項目改寫狀態。

一筆壞 MCP 設定不再拖垮其他伺服器

MCP（讓 AI 連接外部工具的協定）設定裡若有一筆格式不正確，過去可能連其他伺服器都無法啟動。現在這筆錯誤會被記錄並略過，剩下的伺服器仍會載入。

像樂團名單裡有一張看不懂的譜，指揮先把那張放到一旁，其他樂手照常上台。

錯誤會留下紀錄，但不擋住其他載入。它沒有把壞設定變正確，也沒有保證那台伺服器會載入；改變的是單一錯誤不再帶倒其餘伺服器。

長對話回退或分支，不再被 SQL 變數上限擋住

對話拉得很長後，想回退到先前內容或另開分支，過去可能因 too many SQL variables 而失敗。這是 SQL（用來查詢資料庫的語言）變數過多造成的錯誤訊息。

像要從一大疊索引卡找回某段記錄或另開一份副本，舊作法把太多卡一次塞進查詢格，因而卡住。

現在長對話的回退與分支不會再被這個錯誤擋下；這張卡只說這兩個操作，沒有涵蓋標題或歷史截斷的修正。

歷史截斷後，長對話標題不再跳到舊訊息

長對話的歷史被截斷後，標題先前可能跳到無關的舊訊息。修正會保護標題所依據的 checkpoint（用來記住某個進度位置的標記），讓標題仍從正確來源取得。

像整理一本太厚的筆記時收起前段頁面，封面標題原本誤讀了舊書籤；現在真正用來決定標題的書籤受到保護。

因此歷史截斷不會把標題帶往不相干的舊訊息。這張卡只處理標題來源錯置，沒有涵蓋回退、分支或 SQL 變數錯誤。

貼上多行文字時，不會一行送出一個提示

在不支援 bracketed paste 的終端機貼上多行文字時，先前每一行都可能被當成一個提示送出。現在整段貼上不再逐行提交。

這像把一疊紙交給收件櫃，過去它把每張都當成獨立信件投遞，現在能把這次貼上的內容當成同一疊。

修正的條件是終端機不遵守 bracketed paste；更新內容沒有宣稱改變支援該機制的終端機行為了。

English

Returning sign-in points straight to your last method

Returning to an enterprise account no longer starts with guessing which route to take. You are offered one Continue with ... choice named after the method you used last time.

It is like an e-reader remembering the chapter where you stopped and taking you there when you reopen it.

You still choose how to sign in; the entry point now begins with a known direction instead of a row of possibilities.

MCP servers can supply their OAuth client identity details

When connecting a tool to an MCP server, you may previously have needed to supply a client ID yourself or arrange dynamic client registration. A server that implements OAuth client ID metadata documents can now provide those identity details.

It is like an exhibition wall listing venue details that a guide device can read directly instead of making visitors fill them in.

Such servers no longer require a manually supplied client ID or dynamic client registration.

Context and usage panels fit terminal and scroll

Opening /context in the terminal now gives you a scrollable panel sized to the terminal. /usage uses the same sizing.

Think of an expandable document rack that adjusts to the desk: when its visible area is not enough, the documents are not cut off; you scroll down to see more.

Both panels therefore adapt to the terminal, and /context lets you view what extends beyond the screen. This does not claim new context, usage data, or commands.

One switch decides what a markdown agent inherits

When defining an agent in Markdown, one inheritCustomizations switch now decides whether it adopts your skills, rules, plugins, subagents, and MCP servers. Each kind previously had defaults that could silently disagree.

It is like replacing five light switches facing different directions with one main switch for whether a room keeps your arrangement.

Built-in skills, rules, and plugins also remain when an agent sets inherit_user to false, because that setting only opts out of personal customizations, not CLI-supplied ones.

Outside-workspace access is read-only; cycle mode governs writes

When an agent needs to view files outside your workspace, that access setting now grants read access only. Writes are automatically approved according to the cycle mode setting.

It is like a reading room handing you material from outside its shelves to examine, while marking it still follows a separate borrowing rule.

Reading and writing are no longer bundled under one outside-workspace permission: the first is read-only and the second is assigned to cycle mode.

Language-server failures are reported instead of looking successful

If the language server, a background service that helps the program understand language content, fails during startup or while the CLI is running, the failure now prints in the terminal and the process exits non-zero. It previously left silently while reporting success.

It is like a broken cash register that no longer closes its door and stamps the ledger “completed,” but writes the fault on the counter.

The terminal output and exit status can now show the failure; this does not claim to repair the language server itself.

Terminals without OSC 8 support get readable sign-in links

If your terminal cannot parse OSC 8 hyperlinks, the sign-in URL and other links could previously render as garbled text. The program now detects such terminals, including GNU screen, and gives plain text instead.

It is like replacing an invitation written with an unreadable code with a note that writes out the address.

The change concerns links in terminals that do not support OSC 8; it does not say supported terminals lose their hyperlink format.

Enter no longer submits prompt while path suggestions load

When the path-suggestion popup was still loading, pressing Enter used to swallow the key: the prompt was sent, then results opened on top of it. That ordering error is now fixed.

It is like a menu in the same input field still loading when a key submits its content first, then the menu results cover what was just sent.

The fix covers the popup's loading state and the overlap caused by the swallowed Enter key. Results no longer open over the prompt.

Reopened artifact lists keep each earlier review status

When reopening the artifact list, a list of code or documents produced in a conversation, every earlier artifact is no longer marked approved. Items left unreviewed, commented on, or rejected in the previous turn keep their actual status.

It is like reopening a graded workbook where blank, annotated, and returned pages stay in their places instead of receiving one “approved” stamp.

The list therefore reflects the previous review result rather than rewriting every old item because you reopened it.

One malformed MCP entry no longer takes down other servers

If one entry in an MCP configuration is malformed, it previously could bring down every other server too. That error is now logged and skipped, while the remaining servers still load.

It is like a conductor putting aside one unreadable sheet of music so the other players can still take the stage.

The bad entry is not made correct and its server is not promised to load; the change is that one error no longer topples the rest.

Long conversations can revert or branch past the SQL-variable limit

After a conversation grows long, reverting to earlier content or opening a branch could fail with too many SQL variables. SQL is a language for querying databases, and that message means too many query variables were involved.

It is like trying to retrieve a passage from a huge stack of index cards or make a new copy, while the old method jams too many cards into one query slot.

Long-conversation reverts and branches no longer fail with that error. This fix concerns those two actions, not titles or history truncation.

Long-conversation titles no longer jump to old messages after truncation

After a long conversation's history was truncated, its title could jump to an unrelated older message. The fix protects the checkpoint, a marker that remembers a progress position, from which the title is derived, so the title keeps its correct source.

It is like putting away early pages of an overgrown notebook: the cover title used to read an old bookmark, but the bookmark that determines the title is now protected.

History truncation therefore no longer sends the title to an unrelated old message. This fix concerns title sourcing, not reverting, branching, or SQL-variable errors.

A multi-line paste no longer sends one prompt per line

Pasting multiple lines into a terminal that does not honor bracketed paste used to submit one prompt for each line. The pasted block is no longer submitted line by line.

It is like placing a stack of papers in a mail slot that once delivered every sheet as a separate letter, but now recognizes this paste as one stack.

The fix applies where the terminal does not honor bracketed paste; it does not claim to change terminals that do.
