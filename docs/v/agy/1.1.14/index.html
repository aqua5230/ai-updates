回訪登入少走岔路，直接看見上次方法

公司帳號又要登入時，畫面不必再讓你猜該選哪條路。回來的使用者現在會看到一個 Continue with ... 選項，名稱就是自己上次採用的登入方式。⟦這像閱讀器記住你上次停下閱讀的章節，重新打開時會先帶你回到那一章。⟧你仍是在選登入方式，只是入口先對準已知方向，少了在多個選項間來回找的步驟。選項也會直接點出那個方法名稱。

連 MCP 伺服器時，登入身分資料可自動接手

要把工具接到 MCP（讓 AI 連接外部工具的協定）伺服器時，原本可能得自己交出 client ID，或替它辦動態註冊。現在伺服器若有實作 OAuth client ID metadata 文件，就能提供這份登入身分資料。⟦像展覽牆列出場館資料，讀得懂格式的導覽機可直接讀取，不必由遊客補填。⟧因此，符合這段規格的伺服器不再要求手動提供 client ID 或動態 client 註冊；沒有實作這段規格的伺服器，更新內容沒有承諾改變。

內容與用量面板跟著終端機大小，可捲動查看

在終端機裡打開 /context 想看內容時，面板現在能捲動，也會依終端機尺寸調整。/usage 的尺寸也採相同作法。⟦像可伸縮的文件架會跟著桌面大小收放；架子看得到的範圍不夠時，文件沒有被裁掉，而是往下捲動查看。⟧因此兩個面板都跟著眼前終端機調整，/context 還能查看超出畫面的部分。這項變更沒有宣稱增加內容、用量資料或新的指令。

代理程式繼承個人自訂，改用一個總開關決定

你在 Markdown 寫代理程式時，現在可用 inheritCustomizations 一個開關決定它是否採用你的 skills、rules、plugins、subagents 與 MCP servers。先前各種類各自有預設值，彼此還會默默不一致。⟦這像把五把各自方向不同的燈開關，換成一個總開關來決定整間房是否沿用你的佈置。⟧內建的 skills、rules、plugins 也不會因代理程式把 inherit_user 設為 false 而消失，因為 false 原本只表示不採用你的個人自訂，不是退出 CLI 隨附的內容。

工作區外存取改成唯讀，寫入照循環模式處理

需要讓代理程式查看工作區外的檔案時，這個存取設定現在只授予讀取權。寫入則依 cycle mode 設定自動核准。⟦這像借閱室把館外資料交給你翻閱，但要在上面動筆，仍按另一套借閱規則處理。⟧讀取與寫入不再由同一句「允許工作區外存取」混在一起；前者限為唯讀，後者明確交給 cycle mode。這是既有設定權限的調整，並非宣告可任意寫進工作區外位置。

語言伺服器失敗不再假裝成功，終端機會說明

CLI 啟動時或正在運作時，語言伺服器（替程式理解語言內容的背景服務）若失敗，現在會把失敗印在終端機，並以非零狀態結束。過去它會安靜離開，卻回報成功。⟦這像店裡的收銀機壞了，門不再悄悄關上並在帳上蓋「交易完成」，而是把故障寫在櫃檯上。⟧它不會再安靜離開卻報成成功。你因此能從終端機和結束狀態辨認失敗；更新內容沒有表示會自動修好語言伺服器本身。

不懂 OSC 8 的終端機，也能看清登入連結

若你的終端機不會解析 OSC 8 hyperlinks，登入 URL 和其他連結先前可能顯示成亂碼。現在程式會偵測這種終端機，例如 GNU screen，改給純文字。⟦這像對方看不懂附有暗號的邀請卡時，改遞上一張把地址完整寫出的紙條。⟧改變的是連結在不支援 OSC 8 的終端機裡的呈現方式；支援該格式的終端機，原始更新沒有說要改成純文字。

路徑建議還在載入，Enter 不會先送出提示

剛叫出路徑建議視窗，結果還在載入時按 Enter，先前 Enter 會被吃掉：提示送出後，結果又在提示上方彈開。現在不再發生這個順序錯亂。⟦像同一個輸入欄的選單尚未載入完，按鍵卻先把內容送出，接著選單結果又蓋到剛送出的內容上。⟧修正針對路徑建議彈出視窗仍在載入的狀態，以及 Enter 被吞掉後造成的送出與結果重疊。結果不會在提示上方再開一次。

重開產物清單，舊項目的審核狀態不再全變通過

重開 artifact list（對話產生的程式碼或文件清單）時，先前每個 artifact 不會再一律被標為 approved。上一輪尚未審核、留下評論、或被拒絕的項目，現在會保留原本狀態。⟦這像把上次批改過的作業本重新翻開，空白、註記與退回的頁面仍各自留在原位，不會全部蓋成「通過」。⟧因此清單反映的是前一輪實際審查結果，而非重開動作替所有舊項目改寫狀態。

一筆壞 MCP 設定不再拖垮其他伺服器

MCP（讓 AI 連接外部工具的協定）設定裡若有一筆格式不正確，過去可能連其他伺服器都無法啟動。現在這筆錯誤會被記錄並略過，剩下的伺服器仍會載入。⟦像樂團名單裡有一張看不懂的譜，指揮先把那張放到一旁，其他樂手照常上台。⟧錯誤會留下紀錄，但不擋住其他載入。它沒有把壞設定變正確，也沒有保證那台伺服器會載入；改變的是單一錯誤不再帶倒其餘伺服器。

長對話回退或分支，不再被 SQL 變數上限擋住

對話拉得很長後，想回退到先前內容或另開分支，過去可能因 too many SQL variables 而失敗。這是 SQL（用來查詢資料庫的語言）變數過多造成的錯誤訊息。⟦像要從一大疊索引卡找回某段記錄或另開一份副本，舊作法把太多卡一次塞進查詢格，因而卡住。⟧現在長對話的回退與分支不會再被這個錯誤擋下；這張卡只說這兩個操作，沒有涵蓋標題或歷史截斷的修正。

歷史截斷後，長對話標題不再跳到舊訊息

長對話的歷史被截斷後，標題先前可能跳到無關的舊訊息。修正會保護標題所依據的 checkpoint（用來記住某個進度位置的標記），讓標題仍從正確來源取得。⟦像整理一本太厚的筆記時收起前段頁面，封面標題原本誤讀了舊書籤；現在真正用來決定標題的書籤受到保護。⟧因此歷史截斷不會把標題帶往不相干的舊訊息。這張卡只處理標題來源錯置，沒有涵蓋回退、分支或 SQL 變數錯誤。

貼上多行文字時，不會一行送出一個提示

在不支援 bracketed paste 的終端機貼上多行文字時，先前每一行都可能被當成一個提示送出。現在整段貼上不再逐行提交。⟦這像把一疊紙交給收件櫃，過去它把每張都當成獨立信件投遞，現在能把這次貼上的內容當成同一疊。⟧修正的條件是終端機不遵守 bracketed paste；更新內容沒有宣稱改變支援該機制的終端機行為了。

Returning sign-in points straight to your last method

Returning to an enterprise account no longer starts with guessing which route to take. You are offered one Continue with ... choice named after the method you used last time. ⟦It is like an e-reader remembering the chapter where you stopped and taking you there when you reopen it.⟧ You still choose how to sign in; the entry point now begins with a known direction instead of a row of possibilities.

MCP servers can supply their OAuth client identity details

When connecting a tool to an MCP server, you may previously have needed to supply a client ID yourself or arrange dynamic client registration. A server that implements OAuth client ID metadata documents can now provide those identity details. ⟦It is like an exhibition wall listing venue details that a guide device can read directly instead of making visitors fill them in.⟧ Such servers no longer require a manually supplied client ID or dynamic client registration.

Context and usage panels fit terminal and scroll

Opening /context in the terminal now gives you a scrollable panel sized to the terminal. /usage uses the same sizing. ⟦Think of an expandable document rack that adjusts to the desk: when its visible area is not enough, the documents are not cut off; you scroll down to see more.⟧ Both panels therefore adapt to the terminal, and /context lets you view what extends beyond the screen. This does not claim new context, usage data, or commands.

One switch decides what a markdown agent inherits

When defining an agent in Markdown, one inheritCustomizations switch now decides whether it adopts your skills, rules, plugins, subagents, and MCP servers. Each kind previously had defaults that could silently disagree. ⟦It is like replacing five light switches facing different directions with one main switch for whether a room keeps your arrangement.⟧ Built-in skills, rules, and plugins also remain when an agent sets inherit_user to false, because that setting only opts out of personal customizations, not CLI-supplied ones.

Outside-workspace access is read-only; cycle mode governs writes

When an agent needs to view files outside your workspace, that access setting now grants read access only. Writes are automatically approved according to the cycle mode setting. ⟦It is like a reading room handing you material from outside its shelves to examine, while marking it still follows a separate borrowing rule.⟧ Reading and writing are no longer bundled under one outside-workspace permission: the first is read-only and the second is assigned to cycle mode.

Language-server failures are reported instead of looking successful

If the language server, a background service that helps the program understand language content, fails during startup or while the CLI is running, the failure now prints in the terminal and the process exits non-zero. It previously left silently while reporting success. ⟦It is like a broken cash register that no longer closes its door and stamps the ledger “completed,” but writes the fault on the counter.⟧ The terminal output and exit status can now show the failure; this does not claim to repair the language server itself.

Terminals without OSC 8 support get readable sign-in links

If your terminal cannot parse OSC 8 hyperlinks, the sign-in URL and other links could previously render as garbled text. The program now detects such terminals, including GNU screen, and gives plain text instead. ⟦It is like replacing an invitation written with an unreadable code with a note that writes out the address.⟧ The change concerns links in terminals that do not support OSC 8; it does not say supported terminals lose their hyperlink format.

Enter no longer submits prompt while path suggestions load

When the path-suggestion popup was still loading, pressing Enter used to swallow the key: the prompt was sent, then results opened on top of it. That ordering error is now fixed. ⟦It is like a menu in the same input field still loading when a key submits its content first, then the menu results cover what was just sent.⟧ The fix covers the popup's loading state and the overlap caused by the swallowed Enter key. Results no longer open over the prompt.

Reopened artifact lists keep each earlier review status

When reopening the artifact list, a list of code or documents produced in a conversation, every earlier artifact is no longer marked approved. Items left unreviewed, commented on, or rejected in the previous turn keep their actual status. ⟦It is like reopening a graded workbook where blank, annotated, and returned pages stay in their places instead of receiving one “approved” stamp.⟧ The list therefore reflects the previous review result rather than rewriting every old item because you reopened it.

One malformed MCP entry no longer takes down other servers

If one entry in an MCP configuration is malformed, it previously could bring down every other server too. That error is now logged and skipped, while the remaining servers still load. ⟦It is like a conductor putting aside one unreadable sheet of music so the other players can still take the stage.⟧ The bad entry is not made correct and its server is not promised to load; the change is that one error no longer topples the rest.

Long conversations can revert or branch past the SQL-variable limit

After a conversation grows long, reverting to earlier content or opening a branch could fail with too many SQL variables. SQL is a language for querying databases, and that message means too many query variables were involved. ⟦It is like trying to retrieve a passage from a huge stack of index cards or make a new copy, while the old method jams too many cards into one query slot.⟧ Long-conversation reverts and branches no longer fail with that error. This fix concerns those two actions, not titles or history truncation.

Long-conversation titles no longer jump to old messages after truncation

After a long conversation's history was truncated, its title could jump to an unrelated older message. The fix protects the checkpoint, a marker that remembers a progress position, from which the title is derived, so the title keeps its correct source. ⟦It is like putting away early pages of an overgrown notebook: the cover title used to read an old bookmark, but the bookmark that determines the title is now protected.⟧ History truncation therefore no longer sends the title to an unrelated old message. This fix concerns title sourcing, not reverting, branching, or SQL-variable errors.

A multi-line paste no longer sends one prompt per line

Pasting multiple lines into a terminal that does not honor bracketed paste used to submit one prompt for each line. The pasted block is no longer submitted line by line. ⟦It is like placing a stack of papers in a mail slot that once delivered every sheet as a separate letter, but now recognizes this paste as one stack.⟧ The fix applies where the terminal does not honor bracketed paste; it does not claim to change terminals that do.

MCP サーバー接続時に OAuth のクライアント情報を受け取れる

ツールを MCP サーバーへつなぐ際、以前は client ID を手で渡すか、動的な client 登録を行う必要があった。サーバーが OAuth client ID metadata 文書を実装していれば、今はそのログイン用の身元情報を渡せる。⟦展示の壁に会場情報が書かれ、形式を読める案内機が直接読めるため、来場者が書き足さなくてよいようなものだ。⟧この部分の規格を実装したサーバーでは、手動の client ID や動的 client 登録が不要になる。

コンテキストと使用量のパネルが端末に収まり、スクロールできる

端末で /context を開くと、パネルはスクロールでき、端末の大きさに合わせて表示される。/usage も同じ大きさに調整される。⟦伸縮する書類棚が机の大きさに合わせて収まるようなものだ。見える範囲が足りない場合、書類を切り取るのではなく下へスクロールして続きを見る。⟧両パネルは目の前の端末に合わせて調整され、/context では画面外の部分も見られる。内容や使用量の情報、指令を増やすものではない。

Markdown エージェントが引き継ぐ個人設定を一つのスイッチで決める

Markdown でエージェントを定義する際、inheritCustomizations 一つのスイッチで、自分の skills、rules、plugins、subagents、MCP servers を採用するか決められるようになった。以前は種類ごとの既定値が黙って食い違うことがあった。⟦向きの違う五つの照明スイッチを、部屋の配置を引き継ぐか決める主電源へ替えるようなものだ。⟧inherit_user を false にしても、CLI 付属の skills、rules、plugins は消えない。false は個人の自作設定だけを外す意味だからである。

ワークスペース外は読み取り専用になり、書き込みは cycle mode に従う

エージェントにワークスペース外のファイルを見せる必要がある場合、このアクセス設定が与えるのは読み取り権限だけになった。書き込みは cycle mode の設定に従って自動承認される。⟦閲覧室が館外の資料を読むために渡しても、書き込む場合は別の貸し出し規則に従うようなものだ。⟧読み取りと書き込みを一つのワークスペース外アクセスで混ぜず、前者は読み取り専用、後者は cycle mode に任せる。

言語サーバーの失敗を成功のように黙って終えなくなった

CLI の起動時または実行中に、言語サーバー（プログラムが言語内容を理解するのを助けるバックグラウンドサービス）が失敗すると、今は端末に失敗が表示され、プロセスは非ゼロで終了する。以前は黙って終了しながら成功を報告していた。⟦壊れたレジが静かに店を閉めて帳簿へ「完了」と押す代わりに、故障をカウンターへ掲げるようなものだ。⟧端末出力と終了状態で失敗を見分けられる。

OSC 8 を読めない端末でもサインインリンクを読める

端末が OSC 8 hyperlinks を解析できない場合、サインイン URL や他のリンクは以前、文字化けとして表示されることがあった。今は GNU screen などを検出し、代わりにプレーンテキストを渡す。⟦暗号付きの招待状を読めない相手へ、住所をそのまま書いたメモを渡すようなものだ。⟧変更は OSC 8 非対応端末でのリンク表示に関するものであり、対応端末をプレーンテキストへ変えるとは書かれていない。

パス候補の読み込み中に Enter がプロンプトを送らなくなった

パス候補のポップアップがまだ読み込み中に Enter を押すと、以前はキーが飲み込まれた。プロンプトを送信した後で、結果がその上に開いていた。今はこの順序の乱れが直った。⟦同じ入力欄のメニューがまだ読み込み中なのに、キーが先に内容を送信し、その後でメニューの結果が送信した内容に重なるようなものだ。⟧修正対象はパス候補ポップアップの読み込み中の状態と、Enter が飲み込まれて起きた送信と結果の重なりである。結果はプロンプトの上に再び開かない。

再び開いた成果物一覧が過去の審査状態を保つ

会話で作られたコードや文書の一覧である artifact list を開き直しても、以前の artifact がすべて approved になることはなくなった。前のターンで未審査、コメント付き、拒否だった項目は本来の状態を保つ。⟦採点済みのノートを開き直したとき、空白、注記、差し戻しのページがそれぞれ残り、すべてに「合格」の印が押されないようなものだ。⟧一覧は開き直した操作ではなく、前回の実際の審査結果を示す。

壊れた MCP 設定一件が他のサーバーまで止めなくなった

MCP 設定の一件が壊れていると、以前は他のすべてのサーバーまで止まることがあった。今はそのエラーを記録して飛ばし、残りのサーバーは読み込まれる。⟦指揮者が読めない楽譜一枚を脇へ置き、他の演奏者は舞台に立てるようなものだ。⟧壊れた設定を正しくするわけでも、そのサーバーを読み込む保証でもない。一件の誤りが残りを倒さない点が変わった。

長い会話の戻しや分岐が SQL 変数の上限で止まらなくなった

会話が長くなった後、以前の内容へ戻したり分岐を作ったりすると、too many SQL variables で失敗することがあった。SQL（データベースを問い合わせるための言語）の変数が多すぎるというエラーである。⟦大量の索引カードからある記録を戻したり別の束を作ったりする際、古い方法では一度の照会枠にカードを詰め込みすぎて止まるようなものだ。⟧長い会話の戻しと分岐は、このエラーで失敗しなくなった。この修正は題名や履歴の切り詰めを扱わない。

履歴の切り詰め後、長い会話の題名が古いメッセージへ飛ばなくなった

長い会話の履歴が切り詰められた後、題名が無関係な古いメッセージへ飛ぶことがあった。修正では、題名の基になる checkpoint（進行位置を覚えるための印）を保護し、題名が正しい出所から得られるようにする。⟦厚くなりすぎたノートの前半をしまう際、表紙の題名が古いしおりを読んでいたが、題名を決めるしおりを保護するようなものだ。⟧履歴の切り詰めで題名が無関係な古いメッセージへ飛ばなくなる。この修正は題名の出所だけを扱い、戻し、分岐、SQL 変数のエラーは扱わない。

複数行の貼り付けが一行ごとのプロンプト送信にならない

bracketed paste を尊重しない端末で複数行を貼り付けると、以前は一行ごとに一つのプロンプトとして送信されていた。今は貼り付けたまとまりを行ごとに送らない。⟦郵便受けへ紙の束を入れたら、以前は一枚ずつ別の手紙として配っていたのが、今回は一束だと扱えるようなものだ。⟧修正は bracketed paste を尊重しない端末が条件であり、対応端末の挙動を変えるとは書かれていない。

다시 로그인할 때 지난번 방법으로 바로 간다

회사 계정에 다시 로그인할 때 어느 길을 골라야 할지 추측할 일이 줄었다. 다시 온 사용자에게는 지난번 쓴 방법 이름이 붙은 Continue with ... 선택지가 하나 제시된다. ⟦전자책 리더가 지난번 멈춘 장을 기억했다가 다시 열면 그곳으로 데려가는 것과 같다.⟧로그인 방법을 고르는 일은 같지만, 이미 아는 입구에서 시작한다.

MCP 서버 연결 때 OAuth 클라이언트 정보가 이어진다

도구를 MCP 서버에 연결할 때 예전에는 client ID를 직접 주거나 동적 client 등록을 해야 할 수 있었다. 서버가 OAuth client ID metadata 문서를 구현했다면 이제 로그인 신원 정보를 제공할 수 있다. ⟦전시장 벽에 장소 정보가 적혀 있어 형식을 읽는 안내 기기가 방문객에게 채우라고 하지 않고 바로 읽는 모습과 같다.⟧이 부분의 규격을 구현한 서버는 수동 client ID나 동적 client 등록을 요구하지 않는다.

컨텍스트와 사용량 패널이 터미널 크기에 맞고 스크롤된다

터미널에서 /context를 열면 패널을 스크롤할 수 있고 터미널 크기에 맞춘다. /usage도 같은 방식으로 크기가 맞춰진다. ⟦늘어나는 서류함이 책상 크기에 맞춰 접히는 모습과 같다. 보이는 범위가 모자라면 서류를 잘라 내는 대신 아래로 스크롤해 더 본다.⟧두 패널은 눈앞의 터미널에 맞고, /context에서는 화면 밖으로 이어진 부분도 볼 수 있다. 내용, 사용량 정보, 명령을 늘린다는 뜻은 아니다.

마크다운 에이전트가 물려받을 개인 설정을 한 스위치로 정한다

마크다운으로 에이전트를 정의할 때 inheritCustomizations 하나로 자신의 skills, rules, plugins, subagents, MCP servers를 받아들일지 정할 수 있다. 예전에는 종류마다 기본값이 달라 조용히 충돌할 수 있었다. ⟦방향이 제각각인 다섯 개 조명 스위치를 방의 배치를 따를지 정하는 주 스위치 하나로 바꾸는 모습과 같다.⟧inherit_user를 false로 둬도 CLI에 들어 있는 skills, rules, plugins는 사라지지 않는다. false는 개인 사용자 지정만 빼려던 뜻이기 때문이다.

작업 공간 밖 접근은 읽기 전용이며 쓰기는 cycle mode를 따른다

에이전트가 작업 공간 밖 파일을 볼 필요가 있을 때 이 접근 설정은 이제 읽기 권한만 준다. 쓰기는 cycle mode 설정에 따라 자동 승인된다. ⟦열람실이 밖의 자료를 읽으라고 건네도, 거기에 글을 쓰는 일은 별도 대출 규칙을 따르는 모습과 같다.⟧읽기와 쓰기를 작업 공간 밖 접근 하나로 묶지 않고, 앞은 읽기 전용이며 뒤는 cycle mode가 맡는다.

언어 서버 실패를 성공한 듯 조용히 끝내지 않는다

CLI가 시작할 때나 실행 중 언어 서버, 즉 프로그램이 언어 내용을 이해하도록 돕는 백그라운드 서비스가 실패하면 이제 터미널에 실패가 찍히고 프로세스가 0이 아닌 상태로 끝난다. 예전에는 조용히 나가면서 성공을 보고했다. ⟦고장 난 계산대가 조용히 문을 닫고 장부에 완료 도장을 찍는 대신, 고장을 카운터에 적어 두는 모습과 같다.⟧터미널 출력과 종료 상태로 실패를 알아볼 수 있다.

OSC 8을 읽지 못하는 터미널에서도 로그인 링크를 볼 수 있다

터미널이 OSC 8 hyperlinks를 해석하지 못하면 로그인 URL과 다른 링크가 예전에는 깨진 글자로 보일 수 있었다. 이제 프로그램은 GNU screen 같은 터미널을 감지해 일반 텍스트를 준다. ⟦암호가 든 초대장을 읽지 못하는 사람에게 주소를 그대로 쓴 쪽지를 건네는 모습과 같다.⟧변경은 OSC 8을 지원하지 않는 터미널의 링크 표시에 관한 것이며 지원하는 터미널까지 일반 텍스트로 바꾼다는 뜻은 아니다.

경로 추천을 불러오는 동안 Enter가 프롬프트를 보내지 않는다

경로 추천 팝업이 아직 불러오는 중에 Enter를 누르면 예전에는 키가 삼켜졌다. 프롬프트가 전송된 뒤 결과가 그 위로 열렸다. 이제 이 순서 꼬임이 고쳐졌다. ⟦같은 입력칸의 메뉴가 아직 로딩 중인데 키가 먼저 내용을 보내고, 뒤이어 메뉴 결과가 방금 보낸 내용 위를 덮는 모습과 같다.⟧수정 대상은 경로 추천 팝업의 로딩 상태와 Enter가 삼켜져 생긴 전송 및 결과 겹침이다. 결과는 프롬프트 위에 다시 열리지 않는다.

다시 연 산출물 목록이 이전 검토 상태를 지킨다

대화에서 만든 코드나 문서 목록인 artifact list를 다시 열어도 이전 artifact가 모두 approved로 표시되지 않는다. 지난 차례에 미검토, 댓글 있음, 거절이었던 항목은 실제 상태를 유지한다. ⟦채점한 공책을 다시 펼쳤을 때 빈 페이지, 주석, 반려된 페이지가 제자리에 남고 모두에게 통과 도장이 찍히지 않는 모습과 같다.⟧목록은 다시 여는 행동이 아니라 지난 검토 결과를 보여 준다.

잘못된 MCP 항목 하나가 다른 서버까지 멈추게 하지 않는다

MCP 설정의 한 항목 형식이 잘못되면 예전에는 다른 모든 서버까지 멈출 수 있었다. 이제 그 오류를 기록하고 건너뛰며 나머지 서버는 계속 불러온다. ⟦지휘자가 읽을 수 없는 악보 한 장을 옆에 두고 다른 연주자는 무대에 서게 하는 모습과 같다.⟧잘못된 설정을 고치거나 그 서버가 불러와진다고 보장하는 것은 아니다. 한 오류가 나머지를 넘어뜨리지 않는 점이 바뀌었다.

긴 대화의 되돌리기와 분기가 SQL 변수 한도에 막히지 않는다

대화가 길어진 뒤 이전 내용으로 되돌리거나 분기를 열면 too many SQL variables로 실패할 수 있었다. SQL은 데이터베이스를 조회하는 언어이며, 이 메시지는 조회 변수 수가 너무 많다는 뜻이다. ⟦많은 색인 카드에서 한 기록을 되찾거나 새 묶음을 만들 때, 예전 방식이 조회 칸 하나에 카드를 너무 많이 넣어 멈추는 모습과 같다.⟧긴 대화의 되돌리기와 분기는 이제 이 오류로 실패하지 않는다. 이 수정은 제목이나 기록 절단을 다루지 않는다.

기록이 잘린 뒤 긴 대화의 제목이 옛 메시지로 뛰지 않는다

긴 대화의 기록이 잘린 뒤 제목이 관계없는 옛 메시지로 뛸 수 있었다. 수정은 제목이 얻어지는 checkpoint, 즉 진행 위치를 기억하는 표지를 보호해 제목이 올바른 출처를 계속 쓰게 한다. ⟦너무 두꺼운 공책의 앞쪽 페이지를 정리할 때 표지 제목이 옛 책갈피를 잘못 읽던 것을, 제목을 정하는 책갈피는 보호하는 모습과 같다.⟧기록 절단이 제목을 관계없는 옛 메시지로 보내지 않는다. 이 수정은 제목 출처만 다루며 되돌리기, 분기, SQL 변수 오류는 다루지 않는다.

여러 줄 붙여넣기가 줄마다 프롬프트를 보내지 않는다

bracketed paste를 따르지 않는 터미널에 여러 줄을 붙여넣으면 예전에는 줄마다 프롬프트 하나로 전송됐다. 이제 붙여넣은 덩어리를 줄별로 보내지 않는다. ⟦우편함에 종이 한 묶음을 넣었는데 예전에는 매 장을 따로 편지로 배달하던 것이, 이제는 한 묶음으로 알아보는 모습과 같다.⟧수정은 bracketed paste를 따르지 않는 터미널에 해당하며 이를 지원하는 터미널을 바꾼다는 뜻은 아니다.
