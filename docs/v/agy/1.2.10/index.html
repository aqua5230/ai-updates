Antigravity 1.2.10

發布日期：2026-09-24

繁體中文

新功能

/config 新增中等詳細程度，摘要工具呼叫並保留指令回覆

當你交辦複雜任務給助理時，既不想被整頁的工具呼叫與思考細節洗版，又希望能看清執行了哪些指令與最終產出。

在 /config 設定選單中，現在新增了介於 high 與 low 之間的 medium 詳細程度（Verbosity，控制終端機輸出多寡的設定）選項。切換到這個模式後，助理會把一連串相關的工具呼叫與思考過程，整合成像是 Explored N files 這樣的簡短摘要。所有實際跑過的指令與產生的文字回覆，依然會完整顯示在畫面上。Verbosity 設定本身以及底下的每個選項，現在都附上了說明文字，清楚標示各選項會顯示與隱藏哪些內容。

好比閱讀晨會的重點簡報，後台密集的資料調度被濃縮成一行要點，關鍵結論與交辦指令依然完整呈現。
新功能

成品檢視器圖表渲染加速，多工器環境自動切換文字圖表

在終端機裡開啟圖表或數學公式時，畫面載入與按鍵操作現在更俐落。

在支援 Kitty 圖片協定的終端機中，成品檢視器（artifact viewer，瀏覽產出圖表與文件的介面）會在背景預先渲染產物，打開瞬間就能看見 Mermaid 圖表與 LaTeX 算式。圖片改以較小尺寸一次上傳，使用 Ctrl+= 與 Ctrl+- 縮放不再閃爍。檢視器頁尾將置頂與置底提示整併為 g/G top/bottom，m 鍵會清楚標示切換模式（包含 diagram、LaTeX、ASCII 或 raw），並修復箭頭符號過早折行的問題。在 tmux 或 GNU screen 內若圖片無法傳入，系統會自動備援降級為 ASCII 純文字圖表避免留白，有設定穿透者仍可用 CLI_GRAPHICS=kitty 強制開啟圖片模式。

問題修復

終端機沙盒降低繞過頻率，失敗步驟標記與 Esc 鍵行為修整

讓助理在終端機裡自動執行各項指令時，安全防護與按鍵操作現在更符合直覺。

終端機沙盒（sandbox，在隔離環境中執行指令以確保安全的機制）現在經過改善，助理要求跳出沙盒確認的頻率明顯降低。助理現在清楚知道沙盒內的指令可以直接讀寫自己的 artifact 與 scratch 資料夾，而且就算前面某個指令曾需要跳出沙盒，接下來的指令依然會優先在沙盒內嘗試。執行結束且回傳非零退出碼的指令，其步驟標題已從原先的 Errored 正式改為 Failed。當終端機跳出建議下拉選單時，按下 Esc 鍵現在會先關閉選單，按第二下 Esc 才會中斷助理執行，避免選字時不小心誤按中斷。

新功能

自訂設定檔改為僅掃描當前目錄，巢狀項目需透過 include_only 指定

當你在專案中自訂技能、規則或外掛目錄時，現在設定檔的載入行為變得更精確可預測。

在 skills.json、rules.json、agents.json 與 plugins.json 這類自訂設定檔（customization，用於擴充助理能力與行為的設定）中，填入目錄路徑時現在只會載入直接位於該目錄下的第一層項目，行為與預設的 .agents/skills/ 資料夾一致，不再自動遞迴載入所有子目錄中的內容。如果你想要引入深層子目錄裡的特定巢狀項目，必須在設定項目中透過 include_only 明確列出路徑，例如：

{"path": "shared_skills", "include_only": ["category/my-skill"]}

就像打開收納盒只拿取最上層的物件，若要翻出深層隔袋裡的工具，就得在領取清單上明確標出該項目的名稱。
問題修復

無頭模式串流中斷回傳錯誤退出碼，JSON 輸出保留部分回覆

把命令列工具放進自動化腳本跑任務時，最怕遇到程式半途出錯卻假裝成功。

在以 -p 或 --prompt 執行的無頭模式（headless，沒有終端機畫面的自動執行模式）下，以前若串流輸出中途因模型或助理出錯中斷，程式仍會帶著代表成功的代碼 0 結束。現在這類異常會正確改以退出碼 3 結束並印出 AGY_ERROR 錯誤行，JSON 錯誤輸出中也會保留出錯前已生成的局部內容，多輪 stream-json 工作階段則維持發出警告並繼續執行。

問題修復

舊版遠端控制升級後不再重複當機，自動取消廢棄服務

以前使用舊版 Remote Control 安裝腳本設定的機器，在升級版本後常會陷入不斷崩潰重啟的無窮迴圈。

現在當命令列工具被該已廢棄的舊版背景服務啟動時，會自動取消註冊該背景服務，並提示改用 remote-control start 指令啟動，徹底解決升級後反覆當機重開的問題。

問題修復

子代理工作樹檔案不再誤當成品，隔離存放避免殘留元資料

呼叫背景助手平行處理程式碼時，專案目錄不再被莫名其妙的說明檔弄亂。

以前在 Git 工作樹（worktree，讓同一專案平行開多份副本的功能）中寫入一般檔案時，系統會誤以為那是產物，強制要求附帶描述並留下 .metadata.json 檔案。現在子代理的工作樹統一移至資料目錄下的 worktrees/ 資料夾，這個問題已經修好。

English

FEATURE

/config Adds Medium Verbosity to Summarize Tool Calls While Keeping Commands and Responses Visible

When delegating complex tasks to an agent, you might want to avoid being flooded with pages of tool calls and thought details while still clearly tracking executed commands and final responses.

The /config settings menu now introduces a medium verbosity option between high and low. In this mode, the agent groups a series of related tool calls and thought processes into concise summaries like Explored N files. All executed commands and resulting text responses remain fully visible on the screen. The Verbosity setting and each individual option beneath it now include descriptive text clearly outlining what is shown or hidden.

Picture reading a morning briefing: intensive background data operations are condensed into a single takeaway, while key conclusions and assigned instructions remain fully visible.
FEATURE

Artifact Viewer Accelerates Diagram Rendering and Falls Back to Text Diagrams in Multiplexers

Viewing diagrams or math formulas in the terminal is now smoother across loading and key interactions.

On terminals supporting the Kitty graphics protocol, the artifact viewer pre-renders artifacts in the background so Mermaid diagrams and LaTeX formulas appear instantly upon opening. Images are uploaded once at a smaller size, eliminating flickering when zooming with Ctrl+= and Ctrl+-. The viewer footer combines the separate top and bottom hints into g/G top/bottom, labels the m key with the active switch target (including diagram, LaTeX, ASCII, or raw), and fixes hints containing arrow symbols wrapping too early. Inside tmux or GNU screen where images cannot reach the terminal, the system automatically falls back to ASCII text diagrams to prevent blank gaps, while setups with passthrough can still force image mode using CLI_GRAPHICS=kitty.

FEATURE

Terminal Sandbox Reduces Bypass Requests with Refined Failed Step Labels and Esc Key Handling

Running commands automatically with an agent in the terminal is now safer and more intuitive.

With improvements to the terminal sandbox, the agent requests to bypass the sandbox significantly less often. The agent now recognizes that sandboxed commands can directly read and write its own artifact and scratch directories, and it continues to prioritize the sandbox for subsequent commands even after an earlier command required a bypass. For commands that finish execution with a non-zero exit code, the step title is formally updated from Errored to Failed. When the suggestions dropdown is open in the terminal, pressing Esc now closes the dropdown first, requiring a second Esc press to interrupt the agent and preventing accidental cancellation during autocomplete.

FEATURE

Customization Configs Now Scan Top-Level Directories Only, Requiring Nested Items via include_only

Loading behavior for customization files is now more precise and predictable when defining skills, rules, or plugins directories in a project.

In customization files such as skills.json, rules.json, agents.json, and plugins.json, directory entries now load only first-level items located directly inside that directory—matching the behavior of the default .agents/skills/ directory—rather than recursively scanning every subdirectory. To include a specific nested item within a deeper subdirectory, you must explicitly specify its path via include_only, for example:

{"path": "shared_skills", "include_only": ["category/my-skill"]}

Think of opening a storage box and picking only top-level items: retrieving a tool tucked away in a deep inner pouch requires explicitly naming it on the retrieval list.
BUGFIX

Headless Mode Streaming Errors Now Return Exit Code 3 While JSON Output Retains Partial Responses

When running the CLI in automation scripts, silent failures that masquerade as success are a major pitfall.

In headless mode executed with -p or --prompt, streaming outputs interrupted by model or agent errors previously exited with code 0 indicating success. Such failures now properly exit with code 3 and print an AGY_ERROR line, while JSON error output preserves the partial response generated prior to the failure, and multi-turn stream-json sessions continue to warn and proceed.

BUGFIX

Upgraded Legacy Remote Control Installations No Longer Crash Loop and Unregister Deprecated Services

Machines configured with legacy Remote Control installer scripts previously fell into infinite crash loops after upgrading.

When the CLI is launched by that deprecated background service, it now automatically unregisters the background service and prompts switching to the remote-control start command, completely resolving crash loops after upgrades.

BUGFIX

Subagent Worktree Files Are No Longer Mistaken for Artifacts to Prevent Metadata Residue

When invoking background agents to work on code in parallel, project directories will no longer be cluttered with unexpected metadata files.

Previously, writing standard files inside a Git worktree caused the system to mistake them for artifacts, demanding descriptions and leaving .metadata.json files behind. Subagent worktrees now reside under a unified worktrees/ folder in the app data directory, resolving this issue.
