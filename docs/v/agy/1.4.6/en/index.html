Antigravity 1.4.6

Released: 2026-10-23

Release notes

FEATURE

Plugin List Adds MCP Server Configuration Row, Updating Variables Without Disabling and Re-enabling

When fine-tuning connection keys or server parameters after installing plugins in your terminal, there is no longer a need to disable and re-enable them. Entering /plugin to view the list of installed plugins now displays a Configure MCP servers... option beneath every entry.

Picture tweaking an individual knob on a stage audio rack, where changing parameters once required pulling the main power plug to restart the entire system; now the panel clearly marks which lines still need adjustment, and after turning the knob, new settings take effect immediately.

If a plugin still has empty variables, the list marks them with ⚠ needs setup as a reminder to fill them in; each server shows ✓ configured for ready ones and lists specific missing variable names for incomplete ones. After saving, enabled plugins automatically restart their corresponding MCP (a protocol connecting AI to external tools) servers to apply new values immediately.

FEATURE

Terminal Sandbox Protects More Credentials by Default, Requiring Explicit Authorization for Docker and Kubernetes Access

When running commands inside sandbox environments, locally stored sensitive credentials now receive stricter default isolation safeguards. Sandboxed commands no longer allow reading or modifying ~/.docker, ~/.kube, or ~/_netrc by default unless you grant explicit authorization.

Much like living rules in a rented studio, private documents inside drawers were previously left open for anyone to rummage through; now important compartments are locked directly, and no one may browse them without the owner's explicit permission.

In the past, sandbox environments permitted writes to ~/.docker and ~/.kube by default. Consequently, any sandboxed command requiring Docker registry (a repository storing container images) credentials or Kubernetes cluster credentials must now obtain your explicit authorization before proceeding.

FEATURE

Conversation Compaction Preserves Uploaded Images and PDFs, Keeping Attachments Accessible After History Pruning

When facing long conversations with accumulated messages, you no longer need to worry about previously uploaded files disappearing during manual or automatic conversation compaction. Whether the system automatically triggers history compaction or you manually enter /compact in the terminal, the conversation summary completely preserves your previously uploaded images, PDFs, and various attachment files.

Leafing through a bound case file where past records were condensed into outlines, crime scene photos and attachments clipped inside once got tucked away into storage boxes; now all reference documents remain pinned directly to the front page of the summary, ready for checking details at any review.

This ensures the AI can still clearly inspect these attached files and continue answering questions regarding details within them, even after older exchanges are condensed and consolidated.

FEATURE

Authorization Scope Extends Across Main Conversation and Subagents, Eliminating Repeated Confirmations for the Same Operation

When delegating complex tasks to subagents (independent AI assistants helping divide work in the background), frequent authorization prompts often interrupt your workflow. Now, after choosing to allow an operation for the entire conversation, that permission applies directly across the entire main conversation and all of its subagents, regardless of whether you approved it from the main thread or a subagent's prompt.

Holding a single project pass to access a research facility, bringing in a new assistant previously required security guards to call a manager for fresh sign-offs; now once the main project clears access, all supporting teams share that authorization to begin work immediately.

This saves you from repeated approval prompts when subagents perform the same operation, keeping distributed work uninterrupted.

FEATURE

Status Line Displays Specific Waiting Progress with Dynamic Countdown for Model Retries

When submitting complex tasks and waiting for responses, the terminal no longer leaves you with a vague in-progress label. The status line (the status bar displayed at the very bottom of the terminal) now specifically lists the exact step the AI is waiting on, replacing previous generic activity indicators. Whether it is initializing an MCP (a protocol connecting AI to external tools) server or automatically retrying when a model is temporarily unavailable, you can monitor current status in real time. During retry scenarios, the status line directly shows a dynamic countdown in seconds alongside the attempt count, such as Model unavailable (attempt 2/10), retrying in 12s.

Flight display boards in an airport departure lounge once showed only a vague processing notice during flight delays, leaving passengers to stare helplessly at screens; now the board clearly states that a gate is being scheduled alongside an exact countdown.
FEATURE

`/diff` Highlights Word-Level Inline Changes with Clear Visibility Across All Color Themes

When you want to see exactly which words were altered before and after code or text modifications, the diff view now pinpoints the core of every change with precision. Simply entering /diff in the terminal to inspect modifications highlights the exact words that changed right within the modified line across all color themes.

Using a highlighter to proofread contract drafts, circling replaced words once helped focus attention on actual modifications; now the diff view flags those focal points for you so you can inspect exactly which words were swapped within each modified line.
FEATURE

Plugin Validation Adds Help Flag, Thoroughly Verifying Config Structures and Skill Files

When troubleshooting configuration file structures while developing custom plugins, more detailed validation tooling is now available. Running the plugin validation command in the terminal now supports --help to inspect parameter documentation and performs comprehensive verification across settings:

agy plugin validate --help

It inspects configuration details for context providers, catching missing label or command entries, invalid or duplicate trigger words, unknown fields, and missing executable script files. For skill configuration, if a skills entry declared in plugin.json does not exist or lacks SKILL.md, the validation tool issues a warning and reports in detail all SKILL.md files skipped by the loader, including skill files brought in via plugin.json or skills.json.

A factory inspector examining a boxed model kit once only checked the total part count printed on the packaging; now the inspector cross-checks the instruction manual step by step to catch missing assembly steps and mismatched components, listing even the unmounted modules that were skipped.
BUGFIX

Terminal Cursor Resolves Offsets for Full-Width Characters and Line Wraps, Aligning Up and Down Arrow Keys Accurately

When typing Chinese, Japanese, Korean, or emoji, the terminal cursor now stays accurately positioned at the insertion point. Previously, entering full-width CJK (Chinese, Japanese, and Korean) characters, emoji, tab characters, special whitespace, or wrapped text in the command prompt, as well as in the settings, permission amendment, plugin setup, feedback, hooks, or artifact search boxes, often caused the cursor to drift from the insertion point and made up and down arrow keys jump to the wrong line. This issue has been resolved, and both the cursor and arrow keys now land on the correct text positions.

BUGFIX

Three Fixes for Command Execution, File Edit Prompts, and Enterprise Login Issues

When calling tools to execute commands, reverting changes outside your workspace, or preparing to work after a restart, you might have occasionally encountered unexpected errors or forced re-logins. When tool calls included a large reasoning signature (data returned by models alongside tool calls), commands occasionally failed to launch with argument list too long; this issue has been resolved. When the prompt shows an extra choice, such as for edits outside the workspace in accept-edits mode, the warning banner Esc disabled during file edits previously named the wrong reject key; it now names the correct one. When enterprise accounts on macOS and Windows had login credentials exceeding the system keychain size limit, their login state was previously lost upon restarting; this issue has been resolved, and login status now persists properly across restarts.
