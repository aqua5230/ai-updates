Antigravity 1.3.4

Released: 2026-10-13

Release notes

FEATURE

Complete Plugin and Agent Listings with Structured Output Support

When you have installed many extensions and want to inventory which tools and dedicated assistants are currently active all at once, the information is often incomplete.

Like checking an orchestra roster that previously listed only permanent musicians and missed guest sections, the roster now records every visiting performer and individual section member under their official name.

Running agy plugin list now adds a --json flag to output structured data for easy programmatic parsing. The command no longer displays only manually imported packages, but completely lists all plugins installed from the marketplace along with their version numbers and enabled status. When typing /plugin in a chat to view plugin details, the agent list below previously omitted subagents declared at the root of agents.json. This issue is now fixed, and all loaded agents are fully displayed by name instead of only grabbing directory names.

FEATURE

Model Switching Omits Thinking Parameters and Automatically Filters Unauthorized Options

When switching chat models or tuning reasoning depth, users often got stuck due to missing parameters or selecting invalid options.

Think of ordering steak at a restaurant: previously, leaving out the doneness level prevented placing an order, but now the chef serves a recommended doneness automatically, and unavailable cuts are removed from the menu board in advance.

When specifying a model with --model or /model, you can now enter just the base model name without being required to add the --effort flag. The system automatically applies a default thinking effort (the server default, or otherwise medium or lowest in order) without throwing an error and halting. If logged in through a Google Cloud pay-as-you-go commercial account, the menu proactively hides third-party models that the project has no permission to access. In addition, an error where thinking budgets conflicted with thinking effort when using Application Default Credentials (ADC, a mechanism allowing local environments to directly obtain cloud authorization) has also been fixed.

FEATURE

Remote Control Settings Panel Opened for Adjustments with Instant Permission Deletion Sync

When checking terminal progress via a mobile browser while away, users often ran into dilemmas where preference options could not be changed or revoked rules remained in effect.

Picture managing a central server room from a tablet: previously the panel only displayed settings without allowing modifications, but now adjusting climate control or revoking visitor access immediately syncs the configuration files on the physical host.

The settings panel for browser Remote Control (a feature allowing users to operate terminal sessions through a web interface) is now officially open. The window directly lists active items such as project and global permissions, queued messages, AI quotas, telemetry data, and artifact reviews. Starting via agy remote-control serve loads settings.json, and changes made on the web page are immediately written back to the local machine. Previously, "always allow" rules approved in the browser remained in effect even after being removed in the rule editor or on the /permissions tab. Rules are now stored exclusively in the shared config.json, becoming invalid immediately upon removal.

BUGFIX

Command Flag Errors No Longer Run Silently, Returning Explicit Warnings and Exit Codes

When launching tools from the command line, accidentally mistyping an agent name or combining contradictory flags could easily cause confusion because the system did not clearly intervene.

A station ticket turnstile illustrates this shift: where passenger cards with errors were once quietly let through, automated gates now instantly flash red, intercept entry, and list valid ticket types, while staffed booths sound a warning before taking further action.

When specifying an agent using --agent with a misspelled name, the system previously fell back silently to the default agent. In headless mode (an execution mode without a visual terminal interface) combined with -p, encountering an unmatched name now exits directly with status code 1 and lists all available agents. Under the same condition in a standard interactive window, the system now displays an Agent Not Found warning before falling back to the default agent. When mixing --print with --prompt-interactive, the exit code after reporting the conflict has also been changed from 0 (which originally indicated success) to exit code 2.

BUGFIX

Model Request Failure Retry Intervals Shortened to Eliminate Idling During Unstable Connections

When connections to AI servers are unstable or requests fail repeatedly, the terminal previously often became unresponsive.

During consecutive model request failures, the system previously waited up to 4 minutes between automatic retries, leaving the entire session stalled for extended periods. This issue has now been resolved, and the upper limit for wait intervals between automatic retries has been shortened to at most 30 seconds, reducing idle waiting time during connection abnormalities.

BUGFIX

Remote MCP Login Credentials Stabilized to Prevent Forced Logout on Transient Network Drops

When using remote plugins that require web authorization, the biggest frustration was being forcibly logged out over minor network fluctuations.

When connecting to a remote MCP (Model Context Protocol, a protocol allowing AI to connect to external tools) server that uses OAuth authentication, the system previously cleared login credentials whenever it encountered brief network interruptions, timeouts, or server errors. Now credentials are cleared only when the authorization server definitively rejects authentication, so brief disconnections no longer require logging in again.

BUGFIX

Diff Command No Longer Falsely Reports No Changes When Repositories Enable Color Output

When attempting to review code modification progress during a conversation, the terminal sometimes displayed blank output even when modifications were present.

When entering /diff to inspect changes in a Git, Mercurial, or Jujutsu repository, if version control was configured to force color output (such as color.ui = always), the system previously misinterpreted the output and displayed No uncommitted changes. This issue has now been resolved, so the command properly reads and displays all uncommitted file modifications even when color formatting is enabled in the environment.

BUGFIX

Conversation History Search Automatically Fallbacks on Timeout Without Freezing the List

When typing in the input box to reference an earlier conversation, slow searches often froze the cursor in place and prevented selection.

When entering @conversation: in the terminal to search for past conversations, if the conversation lookup was slow, the menu previously stayed stuck on the Fetching matches for ... loading screen. This issue has now been resolved: after waiting more than 2 seconds, the menu automatically falls back to showing locally stored conversation history, eliminating the need to wait indefinitely.

BUGFIX

Incomplete Media Files Rejected Directly to Prevent Cascading Conversation Failures

When having an agent analyze media files in a project folder, an incompletely downloaded file could ruin the entire subsequent conversation.

When an agent read a WebM media file that was incomplete or contained only header information, the system previously attached the file to the session, causing every subsequent conversation request to fail with an error. This issue has now been resolved: the system directly refuses to load such incomplete files and no longer brings corrupted attachments into the conversation, ensuring subsequent operations proceed normally.

Fixed requests failing with `thinking_budget and thinking_level are not supported together` when signed in with Application Default Credentials and using a model that has a thinking level.

Fixed "Always allow" rules approved from a Remote Control browser session still applying after you removed them in the browser's rules editor or the shared tab of `/permissions`; these rules are now saved only to the shared `config.json`.
