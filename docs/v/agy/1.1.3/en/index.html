Antigravity 1.1.3

Released: 2026-07-16

Release notes

BUGFIX

A dedicated code search command, plus fixes for garbled formatting and intrusive errors

You can now quickly dig through your entire project's code using the new /codesearch (or /cs) command.

It interprets your queries as regular expressions (regex, an advanced syntax for pattern matching) by default, but you can use -F for strictly literal matches and filter specific files using f: globs. Visually, the interface has grown smarter: it now draws a clear indicator line to show exactly where earlier conversation history was squeezed down (context-compaction, the feature that folds old memories to save space); extra padding spaces around inline code have been stripped away; and shell commands containing dollar signs will no longer be mistaken for math formulas. Also, when an eligibility error occurs, the message and verification URL now sit politely inline in your input loop, rather than pushing your whole screen upwards. It's like getting a new bookshelf that comes with a powerful cataloging system to pinpoint any book, neatly tucks annoying notification slips into the pages, and smooths out the awkward gaps between the books.

FEATURE

Startup and discovery speeds skyrocket, cutting out redundant file reads

You no longer have to stare at a stalling screen while Antigravity (Google's terminal AI assistant) warms up.

Previously, during bring-up, the CLI would completely block your interactive startup while it laboriously scanned your file system to discover skills (settings providing extra capabilities); it now loads them asynchronously (letting the main interface start instantly while loading happens in the background), drastically cutting down startup latency. Moreover, when the system hunts for customizations like skills, rules, agents, or hooks, it now consolidates these directory walks and caches (temporarily saving results for instant reuse) its filesystem lookups, eliminating redundant I/O reads. It also fixed a minor hiccup where customization rules were loaded twice if the directory was reached via a symlink (a file pointing to another location). It's like driving your car: instead of a full-body security sweep every time you turn the key, you can just start the engine and go, and your GPS remembers the routes so it doesn't have to recalculate at every intersection.

FEATURE

No more CPU spikes on huge chats, and mouse copying works smoothly

Your computer will no longer choke on massive conversations when using no-flickering mode (a display mode that prevents the terminal screen from flashing on every update).

Previously, as the chat grew, every single screen refresh would rebuild the conversation index (the internal map of the chat) larger and larger, causing high CPU usage and unbounded rendering costs. This index rebuild is now idempotent (meaning it converges to a stable state no matter how many times it runs), keeping system load stable. Row math in this mode was also corrected so the status line stays neatly inside your viewport, and dismissing an artifact (a standalone document preview generated by the system) detail view will no longer leave ghost comments on the screen. Even better, it now supports copy-on-select: dragging to highlight text and simply releasing the mouse instantly copies the clean text (stripped of ANSI terminal color codes) to your clipboard, hiding the virtual scrollbar so it doesn't interfere. It's like working on a mile-long scroll — previously, your assistant would recount the entire scroll every time you added a stroke; now, they only process what's needed. And when you want to trace a section, circling it instantly gives you a clean photocopy, while the scroll handles tuck themselves away.

BUGFIX

Tighter permissions for headless runs, and no more login loops on Linux

When running tasks in the background, the system no longer makes unauthorized decisions.

Previously in headless runs (modes without a terminal window, like -p), tools requiring permission either hung or auto-approved; the CLI now soft-denies them and prints a stderr notice showing the allow-rule needed to permit them. In "always-proceed" mode, outside-of-workspace file writes are no longer incorrectly auto-approved. Linux users are saved from login loops caused by slow OS keyring reads; the CLI now bypasses the keyring if no D-Bus session bus is present, skips it for an hour after a timeout, and extends timeout windows. Like sending a robot to a warehouse: encountering a locked door, it reports the key it needs; if the guard is slow, it waits longer instead of triggering alarms.

BUGFIX

Timeout limits on runaway servers save conversations from sudden death

When you ask the AI to invoke an external tool, it will no longer get dragged down by unresponsive servers.

Previously, if your MCP (Model Context Protocol, a standard connecting AI to external tools) server simply never responded, the agent would freeze like a statue and hang indefinitely; the system now actively bounds connection attempts, tool-listing requests, and per-tool-call attempts with strict timeouts, allowing it to gracefully give up and move on. Furthermore, certain tool calls used to catastrophically break the conversation by corrupting the history (the underlying memory of the chat), which blocked all further responses and killed the session instantly; this fatal bug has been fully squashed. It's like sending an assistant to fetch a document — they used to stand there forever if the room was empty and lose their walkie-talkie; now you've given them a strict timeout rule, so they come back if nobody answers, and keep their radio perfectly safe.
