Antigravity 1.2.14

發布日期：2026-09-30

繁體中文

新功能

設定選單新增排隊選項，可隨時插話打斷對話

當你看到助理正朝錯誤方向執行長任務時，現在可以直接插話叫停。

跟看著助手搬錯箱子時直接出聲喊停一樣，以前只能等他把整批貨搬完才能交代新指令，現在一開口就能立刻打斷他。

你可以在 /config 選單找到 Queued Messages 選項。保持預設的 Queue 會把補充訊息暫存到當前輪次結束，切換成 Send Immediately 則能立即中斷助理。這項偏好也能直接寫入全域設定檔 settings.json，修正了以往寫入該設定卻被系統忽略的問題：

{"queuedMessages": "send-immediately"}
新功能

Linux 容器環境支援遠端控制，沒有 systemd 使用者服務管理員也能背景啟動

當你在輕量 Docker 環境裡想要連線操作時，過去常因底層缺少自動託管機制而直接碰壁卡關。

彷彿在沒有自動排班系統的小型倉庫裡改由工人手動輪值，雖然當機時不會自動重啟、開機也不會自動執行，但依然能把手邊的工作順利跑起來。

在沒有 systemd 使用者服務管理員（替個人帳號管理背景服務的程式）的 Linux 機器上執行 remote-control start 時，現在會直接將常駐程式以背景行程啟動，並警告該行程當機後不會自動重啟且開機時不會自動載入。你隨時能輸入 remote-control status 查詢其行程識別碼（PID），需要結束時輸入 remote-control stop 即可將其關閉。

新功能

長對話載入更快，缺步歷程不再覆寫舊進度

當你接續聊了很久的繁重工作階段，或是中途遇上當機想接回紀錄時，整個流程順暢且安心許多。

如同翻開厚重日記時直接跳到最新的書籤頁，不必每次都從第一頁逐字掃描，就算中間曾掉了一頁，後續記錄也絕不會錯位覆蓋。

重啟擁有數千步驟的對話時，命令列介面不再預先逐步掃描，載入速度明顯加快。歷程若曾因當機或寫入中斷而出現遺漏步驟，恢復時不會再隱藏最新內容，更不會讓新訊息意外覆寫舊紀錄。自動產生的對話標題現在也會將首則訊息附加的圖片與檔案納入考量，純傳截圖或檔案的請求也能擁有具體的標題。

新功能

帳號違規遭封鎖時，登入錯誤提示附上申訴連結

早上一開工卻被擋在門外，畫面上只寫著因違反服務條款（Terms of Service）遭到停權，常讓人不知道該去哪裡詢問。

以前遇到帳號受阻只能看見失敗提示，摸不清該找誰處理；現在登入失敗的錯誤訊息裡會直接附上申訴連結，讓你能立刻點擊網址提交說明。

就像門禁卡突然失效時，感應機不再只發出逼逼警告聲，而是直接在螢幕上顯示管理室的服務電話與分機。
新功能

`--json-schema` 啟動時嚴格檢查，根層級非物件立即報錯

當你為指令傳入結構描述時，若格式有誤或檔案遺失，系統在啟動階段就會立即攔截。

好比海關在登機門前嚴格核對護照格式，發現拿的是白紙、寫錯代碼或缺件就當場拒絕通行，而不是放行登機後才引發混亂。

參數 --json-schema 不再將純文字、單獨型態名稱（如 string）或不存在的結構描述檔默默當成字串型態處理。現在只要輸入上述無效內容，或是根層級不是物件（"type": "object"）的結構描述，程式在啟動時就會直接輸出錯誤訊息並以結束代碼 1 中斷退出。

問題修復

輸入提示不再游標偏離，表情符號與特殊文字換行不割裂

在終端機輸入特殊字元或在多重視窗中作業時，游標位置與文字折行現在能精準對齊。

就像使用排版工具編輯圖文，以前遇到複雜貼圖或組合文字時游標會飄到半空中、換行還會把圖案切成兩半，現在游標與字元邊界都緊緊貼合。

修復了在提示列輸入 ⚠️ 或 👩‍💻 等表情符號，以及天城文（Devanagari）與泰文等組合字元時游標尾端偏離的問題，特別是在 tmux 環境下更是如此。當文字過長自動折行時，也不會再將這類特殊字元拆散切成兩行顯示。

問題修復

檢視管線裝置與損毀影音不再卡死，事前攔截並清楚提示

當助理嘗試讀取特殊系統檔案或不完整的影音錄影時，對話不會再陷入無止境的等待或報錯。

宛如播放器遇到未下載完成的影片或特殊資料通道時直接提示檔案損毀，而不是整台機器當機轉圈圈。

以前助理若嘗試檢視管線（pipe）、通訊端或裝置檔等特殊檔案，流程很容易直接卡死。檢視未錄製完整的 MP4、MOV 或 M4A 影音檔時，對話也會陷入無效引數（INVALID_ARGUMENT）錯誤而無法繼續。現在遇到這兩類檔案時，系統會在讀取前直接攔截並給出明確的提示訊息。

English

FEATURE

Settings Menu Adds Queue Option to Interrupt Conversations Anytime

When you see your assistant heading in the wrong direction during a long task, you can now speak up and stop it directly.

Think of calling out to stop a helper carrying the wrong box: previously you had to wait until the entire shipment was moved to issue new instructions, but now you can interrupt immediately.

You can find the Queued Messages option in the /config menu. Keeping the default Queue buffers follow-up messages until the current turn ends, while switching to Send Immediately interrupts the assistant right away. This preference can also be written directly to the global configuration file settings.json, fixing an issue where writing this setting previously got ignored by the system:

{"queuedMessages": "send-immediately"}
FEATURE

Remote Control Now Supported in Linux Containers, Starting in Background Without systemd User Service Manager

When you want to connect and operate inside a lightweight Docker environment, you previously hit a wall because the underlying system lacked an automated hosting mechanism.

Picture running a small warehouse without an automated scheduling system by having workers take manual shifts: although it will not automatically restart on crashes or launch on boot, it still keeps your current work running smoothly.

When running remote-control start on Linux machines without a systemd user service manager (a program that manages background services for a user account), the daemon now starts directly as a background process, warning that the process will not restart on crash or launch on boot. You can enter remote-control status anytime to check its process ID (PID), and enter remote-control stop whenever you need to shut it down.

FEATURE

Long Conversations Load Faster, and Histories with Missing Steps No Longer Overwrite Old Progress

When you resume a heavy, long-running session or reconnect to your history after a crash, the entire workflow is noticeably smoother and safer.

A reader opening a thick journal jumps straight to the newest bookmarked page without scanning word-by-word from the start, ensuring later entries never misalign or overwrite old notes even if a page went missing.

When restarting conversations with thousands of steps, the command-line interface no longer pre-scans step-by-step, significantly speeding up load times. If history was missing steps due to crashes or interrupted writes, resuming will no longer hide the latest content, nor will new messages accidentally overwrite old records. Auto-generated conversation titles now also factor in images and files attached to the first message, giving concrete titles to requests that only include screenshots or files.

FEATURE

Login Error Prompts Include Appeal Links When Accounts Are Blocked for Violations

Starting your morning only to find yourself locked out, with a screen stating your account has been suspended for violating the Terms of Service, often leaves you wondering where to turn.

Previously, encountering a blocked account only showed a generic failure message with no clear contact point; now, login failure error messages directly include an appeal link, letting you click the URL immediately to submit an explanation.

Instead of merely beeping when an access card fails, a card reader now displays the management office phone number and extension directly on its screen.
FEATURE

`--json-schema` Strictly Validated at Startup, Failing Immediately If Root Level Is Not an Object

When you pass a schema to a command, the system now intercepts formatting errors or missing files right at startup.

Customs officers strictly check passport formats at the boarding gate, turning away blank paper, mistyped codes, or missing documents on the spot rather than causing chaos after boarding.

The --json-schema parameter no longer silently treats plain text, bare type names (such as string), or non-existent schema files as string types. Supplying any of these invalid inputs, or a schema whose root level is not an object ("type": "object"), now causes the program to output an error message at startup and exit immediately with exit code 1.

BUGFIX

Prompt Input Eliminates Cursor Drift, Keeping Emojis and Complex Characters Intact Across Line Wraps

When entering special characters in the terminal or working across multiplexed windows, cursor positioning and text wrapping now align precisely.

Like laying out text and graphics in a publishing tool where complex stickers previously floated the cursor into mid-air and line breaks sliced graphics in half, the cursor and character boundaries now fit tightly together.

Fixed trailing cursor drift when entering emojis such as ⚠️ or 👩‍💻, as well as combining characters like Devanagari and Thai in the prompt line, especially inside tmux environments. When long text wraps automatically, it will also no longer split these special characters across two lines.

BUGFIX

Inspecting Pipe Devices and Corrupted Media No Longer Hangs, Intercepting Early with Clear Prompts

When the assistant attempts to read special system files or incomplete audiovisual recordings, conversations no longer get trapped in endless waiting or error states.

A media player encountering an incomplete video download or a special data stream alerts you to file corruption directly instead of freezing the entire machine with a spinning wheel.

Previously, if the assistant tried to inspect special files such as pipes, sockets, or device files, the process easily hung completely. Inspecting incompletely recorded MP4, MOV, or M4A media files also threw INVALID_ARGUMENT errors that blocked the conversation from continuing. When encountering either type of file, the system now intercepts before reading and provides a clear prompt.
