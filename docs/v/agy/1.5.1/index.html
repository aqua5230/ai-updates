Antigravity 1.5.1

發布日期：2026-11-05

繁體中文

新功能

agy acp 開放帳號所有可用模型，支援任何 ACP 客戶端

在偏好的程式碼編輯器中透過 agy acp 串接模型時，挑選清單不再受工具種類限制。

如同走進連鎖咖啡廳，以前只有旗艦店的機台能點選特調飲品，其他分店只能選基本美式；現在只要登入同一個會員帳號，每台點餐螢幕都會列出帳號可選的所有品項。

過去只有少數列在固定名單上的編輯器，才能挑選 Gemini 以外的模型，其他串接的用戶端都無法選用。現在這項限制已經移除。只要是你帳號有權限使用的模型，agy acp 都會完整提供給每一個連接的 ACP 客戶端。

新功能

遠端代理模式的分頁標籤重新命名，清楚區分介面與遠端設定

只要加上 --remote-agent 參數開啟遠端工作階段，並輸入 /config 調整選項，畫面上方的分頁名稱便有了更精確的標記。

好比音響擴大機上的旋鈕標籤，以前只印著「本機」與「遠端」，讓人摸不清到底在調螢幕還是外接喇叭；現在直接改印「顯示面板」與「外接音箱」，看字面就知道在調整哪一部份。

以往這類工作階段裡的設定分頁標為 Local 與 Remote，容易讓人混淆各自掌管的範圍。現在分頁正式改為 TUI 與 Remote Agent，清楚表明一邊用來設定終端機介面，另一邊專門調整遠端代理。兩個分頁底下的所有設定項目本身都維持不變。

新功能

終端指令退出後縮短等待，背景程序佔用時 1 秒內接續

請代理在終端機執行指令時，若指令啟動了持續在背景運作的程序，對話流程切換得更即時。

跟交響樂團的樂章銜接一樣，以前指揮剛放下指揮棒，只要後方定音鼓的餘音還沒徹底消散，整個樂團就要在台上乾等；現在只要主要樂器停奏，指揮便能立刻帶領大家進入下一段旋律。

以前終端機指令雖然已經執行完畢退出，但只要它衍生的背景程序仍佔用著輸出通道，代理會原地等待 5 秒才繼續往下走。現在這項等待已縮短至至多約 1 秒，讓代理能迅速接續執行後續任務。

新功能

子代理等待回應時標明工具名稱，精確掌握卡住原因

委派子代理執行任務的多工過程中，輸入框上方的狀態提示能直接看出它需要你做什麼。

就像診所診間外的叫號燈，以前只亮著含糊的「處理中」，病患在門外完全不知道該不該進去；現在燈號會直接改亮「等待驗光」，大家一看就知道接下來要配合哪個檢查項目。

以往在輸入框上方的子代理狀態列中，如果子代理卡住並等待你的輸入，狀態只會籠統顯示為 Blocked · Processing...，讓人無法判斷它究竟是在運算還是等候回應。現在狀態會直接列出卡住它的工具名稱，例如顯示為 Blocked · AskQuestion，清楚指出它正等著你回答問題。

新功能

終端沙盒限縮外掛真實令牌替換範圍，防止網址反射外洩

終端機沙盒環境內運行的各類外掛程式，連線授權資訊的防護機制多了一道防線。

彷彿持代驗憑條領取機密文件，以前只要任何收件欄填上代號，系統都會換成正式印鑑，容易被回寄外洩；現在只准在指定的授權欄位換上真實印鑑，其他地方一律不予替換。

在外掛程式發出請求時，真實的授權令牌（token，用來向第三方服務驗證身分的憑證令牌）現在只會在網路請求的 Authorization 標頭中替換代用標記。這能防止惡意指令把代用標記刻意塞在網址或自訂標頭中，避免外部網站將替換後的真實令牌反射回傳而導致憑證外流。

問題修復

修復 agy acp 工作階段狀態同步，提示取消與表單不再卡死

透過 ACP 協定與編輯器長時間協同作業時，多項工作階段的中斷與通知問題已獲得修正。

有如郵政窗口的叫號系統，以前只要前一位民眾中途抽單，常常導致下一位號碼連帶作廢，舊表單還留在櫃檯；現在中途取消會確實結案，後續叫號與表單關閉都井然有序。

以前若在提示執行時關閉、重新載入或恢復工作階段，原本的提示會無限懸掛，現在會正式標示為已取消。手動取消提示也不再連帶中止隨後送出的下一道指令。 通知的傳遞順序也已校正，session/update 不會再晚於 session/prompt 回應才抵達。權限請求與提問表單若已在其他地方完成回答，或所屬提示已經結束，現在都會自動關閉，不再殘留於畫面上阻礙後續提示。

問題修復

修復 Windows 檔案編輯換行符號錯誤，改善非 ASCII 亂碼與行程釋放

Windows 使用者在終端操作時，檔案換行格式、文字編碼與外部工具殘留行程等問題已獲得修復。 針對採用 CRLF 換行符號的檔案，以前編輯常因找不到目標文字（target content not found）而中斷。現在會精準比對換行符號，新增的行數也會沿用檔案原本的換行格式。 當代理執行的指令輸出包含非 ASCII 字元時，以前容易顯示亂碼或直接報錯。現在會自動以 UTF-8 模式（PYTHONUTF8=1）執行 Python，並將 PowerShell 的輸出編碼切換為 UTF-8。若你自己已設定 PYTHONUTF8，就以你的設定為準。 透過標準輸入運行的 MCP 伺服器（Model Context Protocol，讓 AI 連接外部工具的協定）停止後，其子行程也不會再殘留背景，解決外掛目錄因檔案被佔用而無法升級的困擾。

問題修復

企業登入與雲端憑證環境下，外掛市集與指令恢復正常運作

依賴企業模型閘道或應用程式預設憑證（AGY_ADC_AUTH）登入的環境下，外掛管理功能現在能正常使用。以前在這類驗證環境下執行 agy plugin 指令，會遇到功能不可用且外掛市集完全空白的情況。現在這個問題已經修好，能正常列出外掛市集並執行各項外掛指令。

問題修復

browser 代理移出對話清單，回歸專屬子代理定位

開啟新對話挑選要互動的代理時，選單不再顯示專供內部呼叫的工具。以前內建的 browser 代理會誤列在對話啟動清單中；但它本質上是設計給主代理在背景調用的子代理。現在它已從一般對話選單中移除，並維持原有的子代理運作方式。

問題修復

GNU screen 內複製功能修復，文字精準送入剪貼簿

習慣在 GNU screen 終端環境中操作的使用者，剪貼簿現在能精確接收複製內容。以前在 GNU screen 內使用選取即複製或輸入 /copy 時，文字常常無法順利送入剪貼簿，選取較長文字時終端機畫面還會殘留多餘的雜亂字元。現在這個問題已經修好，複製內容會正確進入剪貼簿且畫面維持乾淨。

English

FEATURE

agy acp Opens All Account Models to Any ACP Client

When connecting models through agy acp in your preferred code editor, the selection list is no longer limited by the type of tool.

Picture walking into a chain coffee shop: previously, only ordering kiosks at flagship locations let you select specialty drinks, while other branches offered only a basic Americano; now, as long as you log into the same membership account, every ordering screen lists all items available to that account.

In the past, only a small number of editors on a fixed list could choose models other than Gemini, while other connected clients could not use them. This restriction has now been removed. As long as a model is available to your account, agy acp provides it completely to every connected ACP client.

FEATURE

Tabs in Remote Agent Mode Renamed to Clearly Distinguish UI and Agent Settings

Whenever you start a remote session with the --remote-agent flag and enter /config to adjust options, the tab names at the top of the screen have more precise labels.

Think of knob labels on an audio amplifier: previously, they were only printed with "Local" and "Remote," leaving you unsure whether you were tuning the screen or external speakers; now they are printed as "Display Panel" and "External Speakers," making it clear from the text alone which part is being adjusted.

Previously, the configuration tabs in these sessions were labeled Local and Remote, making it easy to confuse the scope governed by each. The tabs are now officially changed to TUI and Remote Agent, making it clear that one configures the terminal interface and the other specifically adjusts the remote agent. All settings under both tabs remain unchanged.

FEATURE

Reduced Wait After Terminal Command Exits, Resuming Within 1 Second When Background Processes Hold Output

When asking the agent to run commands in the terminal, if a command launches a process that continues running in the background, the conversation switches more promptly.

Like the transition between movements in a symphony orchestra: previously, as soon as the conductor lowered the baton, if the reverberation of the timpani in the back had not completely died down, the entire orchestra had to wait idly on stage; now, as soon as the main instruments stop playing, the conductor can immediately lead everyone into the next melody.

Previously, even though a terminal command had finished executing and exited, as long as a background process it spawned still held the output channel open, the agent would wait in place for 5 seconds before moving forward. This wait has now been shortened to at most about 1 second, allowing the agent to swiftly move on to subsequent tasks.

FEATURE

Subagents Waiting for Input Name Tool Directly to Pinpoint Causes of Pauses

During multitasking where subagents are delegated tasks, the status prompt above the input box directly reveals what it needs from you.

Consider a call light outside a clinic exam room: previously, it only lit up with a vague "Processing," leaving patients outside unsure whether to enter; now the indicator directly switches to "Waiting for Optometry," so everyone knows at a glance which examination item to follow.

Previously, in the subagent status row above the prompt, if a subagent was blocked waiting on your input, the status only vaguely displayed Blocked · Processing..., making it impossible to tell whether it was computing or waiting for a reply. The status now directly names the tool blocking it, such as displaying Blocked · AskQuestion, clearly indicating that it is waiting for you to answer a question.

FEATURE

Terminal Sandbox Restricts Real Plugin Token Replacement to Prevent Leakage via URL Reflection

For various plugins running in the terminal sandbox environment, an extra line of defense has been added to protect connection authorization details.

Imagine claiming confidential documents with a temporary voucher: previously, whenever a code was entered in any recipient field, the system replaced it with an official seal, risking leaks if returned; now the real seal is applied only in the designated authorization field, with replacements prohibited everywhere else.

When a plugin issues a request, real authorization tokens (credentials used to verify identity with third-party services) now replace stand-in markers only in a network request's Authorization header. This prevents malicious commands from deliberately stuffing stand-in markers into URLs or custom headers, avoiding credential leaks caused by external websites reflecting back the replaced real tokens.

BUGFIX

Fixed agy acp Session State Sync So Prompt Cancellations and Forms No Longer Hang

When collaborating with editors over the ACP protocol for extended periods, several session interruption and notification issues have been resolved.

A post office counter queue provides an apt comparison: previously, if the person ahead withdrew their application midway, the next ticket was often invalidated along with it while the old form sat on the counter; now midway cancellations close cleanly, keeping subsequent calling and form dismissals in good order.

Previously, closing, reloading, or resuming a session while a prompt was running left the original prompt hanging indefinitely, but it is now officially marked as cancelled. Manually cancelling a prompt also no longer stops the next command sent right after it. The delivery order of notifications has also been calibrated so that session/update no longer arrives after the session/prompt reply. Permission requests and question forms now close automatically if they are answered elsewhere or their prompt ends, rather than lingering on screen and blocking subsequent prompts.

BUGFIX

Fixed Windows File Editing Line Ending Errors, Non-ASCII Garbled Text, and Process Cleanups

For Windows users operating in the terminal, issues with file line ending formats, text encoding, and leftover external tool processes have been resolved. Previously, editing files that use CRLF line endings often aborted because target content could not be found (target content not found). Edits now accurately match whichever line endings the file uses, and newly inserted lines preserve the file's original line ending format. When command output run by the agent contains non-ASCII characters, it previously tended to display garbled text or throw errors. Python is now automatically run in UTF-8 mode (PYTHONUTF8=1), and PowerShell's output encoding is switched to UTF-8. If you have set PYTHONUTF8 yourself, your setting takes precedence. After stdio MCP servers (Model Context Protocol, an open standard for connecting AI to external tools) stop, their child processes no longer linger in the background. This resolves the issue where plugin directories could not be upgraded because files were in use.

BUGFIX

Plugin Marketplaces and Commands Restored Under Enterprise Login and Cloud Credential Environments

In environments that rely on an enterprise model gateway or Application Default Credentials (AGY_ADC_AUTH) for sign-in, plugin management features now work normally. Previously, running agy plugin commands in these authentication environments resulted in unavailable features and a completely empty plugin marketplace. This issue has now been resolved, properly listing plugin marketplaces and executing various plugin commands.

BUGFIX

browser Agent Removed from Conversation List to Retain Dedicated Subagent Role

When starting a new conversation and picking an agent to interact with, the menu no longer displays tools intended strictly for internal calls. Previously, the built-in browser agent was mistakenly listed among agents available to start a conversation with; however, it is fundamentally designed as a subagent invoked by the primary agent in the background. It has now been removed from the standard conversation menu while retaining its original operation as a subagent.

BUGFIX

Fixed Copying Inside GNU screen So Text Accurately Reaches Clipboard

For users accustomed to working inside the GNU screen terminal environment, the clipboard now accurately receives copied content. Previously, using copy-on-select or entering /copy inside GNU screen often failed to deliver text to the clipboard, and selecting longer text left stray clutter characters on the terminal screen. This issue has now been resolved: copied text properly reaches the clipboard, and the screen stays clean.
