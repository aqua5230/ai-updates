Antigravity 1.5.2

發布日期：2026-11-06

繁體中文

新功能

遠端代理支援雲端擴充技能，放寬專案大檔上傳限制

如果你習慣透過 --remote-agent 在遠端主機執行代理任務，常需要搭配外掛技能或上傳規格書等參考資料。現在透過 /plugin 連線的雲端擴充套件技能，已經正式支援遠端代理工作階段。這些技能會直接顯示在斜線選單中，在訊息開頭輸入就能直接呼叫。輸入 /skills 會依套件分組列在遠端代理技能清單，輸入 /skills reload 即可重新整理。

跟出海科考的探險船連線一樣，以前通訊受限，既無法調用總部的專家工具箱，傳送高解析海圖還會被中斷；現在遠端船隻能隨時掛載雲端技能，大型觀測檔也能順暢送達。

從 /projects 新增 PDF、二進位檔案或大於約 8 MB 的檔案到遠端專案時，過去容易上傳失敗，現在都能順利完成上傳。

新功能

macOS 的 Option 快捷鍵開箱即用，免額外修改終端機設定

在 Mac 上使用命令列時，想按下 alt+m 等組合鍵往往會遇到按鍵無反應或打出特殊符號的困擾。macOS 版本的 Option 組合鍵預設行為迎來更新。以前在終端機裡按 Option 鍵快捷鍵時，若沒有事先把 Option 鍵設定為 Alt 鍵，按下後可能毫無反應，或者直接打出 µ 等特殊字元；現在這些快捷鍵開箱就能直接生效，不再需要手動修改終端機偏好設定。

像使用新買的遊戲鍵盤一樣，以前得先自行修改按鍵映射才能讓特殊功能鍵生效，現在接上主機就能直接辨識預設捷徑。

如果你仍偏好原有的輸入行為，把環境變數 AGY_CLI_MAC_OPTION_AS_ALT=0 這個設定設為 0，就會回到舊行為，終端機便維持舊有的按鍵對應規則。

新功能

跳過權限模式增設安全防線，保護高風險指令並排除子代理停頓

當你啟用 --dangerously-skip-permissions 參數跑自動化任務時，高風險操作與工作區邊界有了更清楚的防線。

類似拿著快速通行證進出廠區，以前只要出示證件就能進入所有庫房；現在特定管制區與管理規定仍需查驗，但一般走道上的隨行助理不再被警衛無端攔下盤查。

該模式不再自動放行內建清單中的受保護指令，這些指令會恢復一般審核，其餘指令仍照常免詢問執行。若企業管理員要求工作區外的指令或檔案存取必須經過審查，--dangerously-skip-permissions 與設為自動放行的外掛代理都不會跳過；無頭模式（headless，沒有終端機視覺介面的執行模式）則會直接拒絕此類請求。子代理在此模式下存取工作區外檔案時，先前會卡頓約 60 秒、卡在檔案權限上，現在讀寫均可直接通行，搭配 -p 也不再停頓，自訂的明確拒絕規則仍維持有效。

新功能

存取工作區外的檔案改為單一授權，不再一次開放全部目錄

碰到代理需要讀取工作區外部的特定設定檔時，提示視窗不再要求你交出整個外部目錄的控制權。代理請求存取工作區外的檔案時，確認提示會明確顯示 Allow access to this file?。你可以針對當前指定的單一路徑，選擇在本次對話中永遠允許或拒絕，或將設定直接寫進 settings.json；系統不會再因為單一檔案的請求，就一口氣開放工作區外所有檔案的存取權限。

好比向大樓管理員借鑰匙，以前只要借用單一辦公室，就得把整棟大樓的門禁全面解鎖；現在管理員只會精準發放你指名那間會議室的感應卡，離開後其餘房間依然安全上鎖。

這讓你在引用公用設定或全域工具時，既能放心放行特定文件，又不必擔心整個硬碟門戶大開。

問題修復

修復指令選單與多任務循環錯誤，並強化遠端連線重試機制

日常切換各類執行模式與操控通道時，幾處影響操作流暢度的小毛病現在都已獲得改善。 使用 agy -p 執行單次輸出時，不再於背景發送模型請求來生成終端機根本不會顯示的對話標題，省下多餘的模型等待與消耗。 建立遠端控制連線時，若在建立初期遇上短暫的網路波動或伺服器抖動，會主動重新嘗試連線，不再直接中斷離開。 代理執行出錯當下若剛好有排隊中的訊息，先前會陷入連續瘋狂重試的迴圈，現在這些排隊訊息會暫停並等待你的下一道指令。 在 agy acp 工作階段中，斜線選單修正為列出當前工作階段代理的指令與技能，自訂代理的專屬工具也能正常顯示，不再誤列預設代理的選項。 以前在這些情境下容易遇到連線驟斷或無效重試，現在各類執行模式都能穩定收尾。

新功能

擴充套件防範惡意路徑穿越，阻擋符號連結並放寬欄位驗證

從外部下載社群擴充套件或開啟陌生的專案儲存庫時，外掛的檔案操作與載入範圍受到更嚴密的防護。

如同租借公共置物櫃，以前可能藉由暗道打通鄰近隔間；現在置物櫃加裝防護鋼板，嚴禁穿透到其他櫃位，標籤格式不符也只會貼上警告而非直接退件。

agy plugin 的各項指令會拒絕不安全的套件名稱並回報 invalid plugin name，且禁止寫入套件資料夾外或透過符號連結（symlink，指向另一個位置的捷徑檔）寫入，防止惡意套件覆寫 mcp_config.json 等設定檔。工作區內的 .agents/plugins.json 與 .agents/skills.json 限制僅能從工作區或儲存庫內部載入，以絕對路徑、../ 或捷徑指向外部的項目一律略過。而 agy plugin validate 遇到未知欄位時改為發出警告並略過，其餘擴充設定照常檢查。

問題修復

MCP 協定修復 OAuth 重新連線錯誤，並完整傳遞工具自訂參數

透過 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）連接伺服器並使用 OAuth 登入時，授權流程與工具溝通現在更加可靠。

宛如在線上商城完成多步驟結帳，以前只要分頁在中途重新整理，先前建立的付款金鑰就會失效；現在重整後仍能沿用原本的交易憑證，填寫的寄送備註也能完整送達系統。

過去登入採用 OAuth 的 MCP 伺服器時，若因 /mcp 重新載入或開啟新對話而重新連線，常會跳出 Invalid PKCE code_verifier 錯誤；現在原本打開的登入連結依然有效。若 MCP 工具宣告了 explanation、toolSummary、toolAction 或 waitForPreviousTools 參數，先前呼叫常漏傳這些引數，現在模型發送的數值都能確實送達工具。

問題修復

修復中日語音輸入字元間距，全形英文字詞空格不再遺失

使用中文或日文進行語音輸入時，即時聽寫草稿的字元間隔現在顯示得更加自然。以前在最終辨識結果送達前，中文與日文的即時草稿會在每個字元之間硬塞一個空格，而全形英文字詞彼此之間的正常空格反而會無故消失。這個問題已經修復，現在草稿能維持連續排版，全形英文字詞間的空格也能正確保留。

English

FEATURE

Remote agents support cloud plugin skills, lifting upload limits on large project files

If you often run agent tasks on remote hosts with --remote-agent, you frequently need plugin skills or have to upload reference materials like specification documents. Cloud plugin skills connected via /plugin are now officially supported in remote agent sessions. These skills appear directly in the / menu and can be called by typing them at the start of a message. Running /skills lists them grouped by plugin under Remote agent skills, and running /skills reload refreshes the list.

Much like staying in touch with an offshore research expedition, where limited communications once blocked access to headquarters' specialist toolkits and broke transfers of high-resolution nautical charts, the remote vessel can now attach cloud skills anytime and large observation files arrive smoothly.

When adding PDFs, binary files, or files larger than about 8 MB from /projects to a remote project, uploads previously failed often, but now complete successfully.

FEATURE

macOS Option-key shortcuts work out of the box without extra terminal configuration

When using the command line on a Mac, pressing key combinations such as alt+m often led to no response or typed unexpected special characters. The default behavior for Option-key combinations on macOS has been updated. Previously, when pressing Option-key shortcuts in your terminal without configuring Option to act as Alt beforehand, pressing them did nothing or directly typed special characters such as µ; now these shortcuts work right out of the box without manually changing terminal preferences.

Picture plugging in a newly bought gaming keyboard: previously, you had to reconfigure key mappings yourself before special function keys worked, but now connecting it to the computer immediately recognizes default shortcuts.

If you still prefer the original input behavior, setting the environment variable AGY_CLI_MAC_OPTION_AS_ALT=0 will return to the old behavior, keeping your terminal's previous key mapping rules.

FEATURE

Permission-skipping mode adds safety guardrails, protecting high-risk commands and resolving subagent stalls

When you enable --dangerously-skip-permissions to run automated tasks, high-risk operations and workspace boundaries have clearer guardrails.

Think of how a fast pass works in a factory facility: previously, flashing your badge opened every storeroom, but now restricted zones and governance policies still require verification while accompanying assistants in common corridors are no longer needlessly stopped by guards.

The mode no longer automatically approves commands on the built-in protected list, which now return to normal review, while other commands continue to run without asking. If enterprise administrators require commands or file access outside the workspace to be reviewed, neither --dangerously-skip-permissions nor plugin agents set to auto-allow will bypass those checks. In addition, headless mode (running without a terminal visual interface) now directly denies such requests. When subagents accessed files outside the workspace in this mode, they previously stalled for about 60 seconds on file permissions; both reads and writes now proceed directly without prompting, runs with -p no longer pause, and custom explicit deny rules remain in effect.

FEATURE

File access outside the workspace switches to single-path authorization, ending broad directory exposure

When an agent needs to read a specific configuration file outside the workspace, the prompt window no longer asks you to surrender control over the entire external directory. When an agent requests access to a file outside the workspace, the confirmation prompt clearly displays Allow access to this file?. You can choose to always allow or deny that single path for the current conversation, or write the setting directly into settings.json; the system will no longer open access to all files outside the workspace just because of a single file request.

Consider borrowing keys from a building manager: whereas requesting a single office once required opening up access across the entire building, the manager now issues a keycard solely for your designated conference room, leaving all other rooms securely locked.

When referencing shared configurations or global tools, this lets you confidently approve specific documents without worrying about leaving your entire hard drive wide open.

BUGFIX

Fixed command menus and queued message retry loops, and strengthened remote connection retries

Several small issues that affected operational smoothness when switching across execution modes and control channels have now been resolved. Running single outputs with agy -p no longer makes a background model request to generate a conversation title that the terminal never shows, saving redundant model waits and resource usage. When establishing Remote Control connections, encountering brief network fluctuations or server jitter during initial setup now triggers automatic retries instead of immediately dropping the connection. If messages were queued at the moment the agent encountered an error, the agent previously entered a rapid retry loop, but those queued messages now pause and wait for your next command. In agy acp sessions, the / menu has been corrected to list the commands and skills of the agent running the session, properly displaying custom agents' dedicated tools instead of mistakenly listing the default agent's options. Where sudden disconnections or futile retry loops once occurred in these scenarios, various execution modes now conclude cleanly and reliably.

FEATURE

Plugins guard against malicious path traversal, blocking symbolic links and relaxing field validation

When downloading community plugins from external sources or opening unfamiliar repositories, plugin file operations and loading boundaries are now more tightly protected.

Public storage lockers provide a useful parallel: where hidden passages might once have broken through adjacent compartments, lockers now feature steel reinforcement plates that strictly prevent breaches into neighboring units, while nonconforming label formats merely receive a warning rather than outright rejection.

Commands under agy plugin reject unsafe plugin names with invalid plugin name, and refuse to write outside the plugins folder or through symbolic links (shortcut files pointing to another location), preventing malicious plugins from overwriting configuration files such as mcp_config.json. Items listed in a workspace's .agents/plugins.json or .agents/skills.json are restricted to load only from within the workspace or repository root, and entries pointing externally via absolute paths, ../, or shortcuts are skipped. In addition, when agy plugin validate encounters unknown fields, it now emits a warning and skips them while checking remaining extension settings normally.

BUGFIX

MCP protocol fixes OAuth reconnection errors and delivers custom tool parameters intact

When connecting to servers via MCP (Model Context Protocol, an open standard connecting AI models to external tools) and signing in with OAuth, authorization workflows and tool communications are now significantly more reliable.

Imagine completing a multi-step checkout at an online storefront: previously, refreshing the tab midway invalidated the established payment key; now the original transaction credentials remain valid after a refresh, and custom shipping notes reliably reach the system.

When signing in to an MCP server that uses OAuth, if a reconnection occurred due to /mcp reloading servers or starting a new turn, an Invalid PKCE code_verifier error previously appeared; now the originally opened sign-in link remains valid. Furthermore, if an MCP tool declared its own explanation, toolSummary, toolAction, or waitForPreviousTools parameters, calls previously omitted these arguments, but values sent by the model now reach the tool intact.

BUGFIX

Fixed Chinese and Japanese voice dictation character spacing, preserving spaces between fullwidth Latin words

When using voice dictation in Chinese or Japanese, character spacing in live dictation drafts now appears much more natural. Previously, before the final transcript arrived, live drafts in Chinese and Japanese inserted an unwanted space between every character, while normal spaces between fullwidth Latin words vanished without cause. This issue has been resolved: drafts now maintain continuous typography, and spaces between fullwidth Latin words are correctly preserved.
