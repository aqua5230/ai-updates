Antigravity 1.5.5

Released: 2026-11-11

Release notes

FEATURE

Preview /swarm supports multi-agent collaboration to advance tasks through a shared board

When facing large architecture refactors or cross-module investigations, relying on a single conversation often means waiting in line as the AI executes step by step. You can now enter /swarm <task> to launch the preview swarm mode. The primary agent becomes a coordinator that adds multiple worker agents, each in its own independent session, working on tasks in parallel through a shared message board. Worker agents can be forked from an existing member's conversation and freely use any model from the /model picker. When a model runs out of quota, worker agents pause instead of repeatedly retrying. If the entire swarm stalls, a monitor agent alerts the coordinator. Because each worker agent operates independently and consumes quota, it is specifically marked as (Preview & Quota Heavy) in the slash menu.

Just as an R&D project assigns multiple teams to investigate separately, previously progress halted whenever one person got stuck; now each team syncs updates on a bulletin board, stays on standby when materials run low, and an overseer alerts the lead manager if all work stalls.
FEATURE

Track Swarm progress with full-screen board and status row, featuring shortcut keys for live monitoring

When multiple agents run simultaneously in the background, keeping track of every member's updates and progress is essential. While a swarm runs, a ● Swarm(<title>) row appears in the active-items tray below the prompt, displaying the latest message and total post count, and marking Done when finished. You can press Enter on that row to open the /swarm board full-screen board, or press alt+x to dismiss the row (rebindable as swarm.dismiss). You can also press alt+s at any time to bring up the board (rebindable as swarm.board). The board is divided into a roster (showing each member's state and model), a posts feed, and a Markdown preview pane, supporting full navigation keys:

tab / shift+tab # Move between panes
z               # Zoom the focused pane
enter           # Show or hide the selected message
[ / ]           # Step up and down through posts
p               # Filter posts to a specific member and mentions
o               # Open a member's subagent details
f               # Follow new posts automatically
esc             # Back out to the previous screen

Picture a situation room monitoring multiple field missions: operators once stared at terminal lines blindly guessing what was happening; now a split screen displays personnel status alongside report details, and a handy dashboard opens quickly for tracking.
FEATURE

Add environment variable to disable bundled ripgrep and avoid endpoint protection blocks

When searching code on machines subject to corporate security policies, antivirus software often blocks temporary executables extracted by tools as threats. A new environment variable, ANTIGRAVITY_DISABLE_EMBEDDED_RIPGREP, is now available. Setting it to true stops the command-line tool from extracting and executing the bundled ripgrep search utility. This setting is specifically designed for situations where endpoint security software blocks embedded tools. Once enabled, searches use a ripgrep installed on your system PATH or fall back to the built-in search mechanism.

Think of bringing a specialized toolkit into a restricted facility: security once confiscated newly unpacked personal gear and halted operations; now technicians may check out pre-approved resident equipment instead of unsealing fresh tools.
FEATURE

Support Gemini 4 Carbon via Application Default Credentials across Low, Medium, and High tiers

If you sign in to your development environment with Google Cloud credentials and want to try another model, you now have a new option. When signing in with Application Default Credentials (AGY_ADC_AUTH), Gemini 4 Carbon appears in both the /model picker and the --model startup parameter across Low, Medium, and High tiers. To specify one, select it from the menu or pass --model with the corresponding tier name at launch.

A professional repair shop adds three wrenches of different sizes to its tool cabinet: previously, accessing the cabinet through this credential channel offered only the original tools; now three extra options are available, letting technicians choose whichever fits.
BUGFIX

Enforce encrypted connections for enterprise model gateways and fix Gemini request fields

Enterprises commonly set up dedicated gateways to forward AI requests to enforce data governance and audit transmitted content. When configuring a remote enterprise model gateway URL, the CLI now strictly requires an encrypted https:// connection. Unless the gateway runs on the same machine (such as localhost, 127.0.0.0/8, or ::1), configuring an unencrypted http:// URL is rejected with an error rather than sending prompts in plain text. In the past, sending Gemini-format requests to enterprise gateways included a non-standard sessionId field, causing gateways that strictly validate request formats to reject every request. This formatting issue has been fixed.

Consider a secure courier dispatch system for sensitive documents: unsealed postcards were once permitted and irregular envelope stamps caused outright rejections; now remote dispatches mandate sealed certified mail while letter codes follow standard specifications.
BUGFIX

Import Claude Code plugins with automatic command and hook conversion for full compatibility

When migrating Claude Code plugins, command and hook formats often fail to load due to environment differences. Previously, running agy plugin import converted commands into skills that failed to load or were all named SKILL. Now each command is named after its folder, and agy plugin validate no longer warns about leftover commands/ directories. Previously, copying hooks/hooks.json directly caused hooks (small programs triggered by specific events) to be skipped. During conversion, tool names are now mapped to built-in tools with a 60-second timeout applied, while items with no equivalent are listed as warnings in the summary.

Like fitting a replacement adapter: mismatched pins previously caused the entire setup to fail; now legacy pins automatically convert into standard sockets, and unmapped lines are flagged with clear warnings.
BUGFIX

Headless mode automatically shuts down after execution and forces exit on 30-second timeout

When invoking the CLI in headless mode (an execution mode without a visual interface) within automation scripts, stuck background tasks often halt the entire schedule. Previously, after completing a task and printing results with agy -p, the program sometimes never exited if a background task such as conversation title generation got stuck. The CLI now finishes its shutdown procedure within 30 seconds. This issue has been fixed.

BUGFIX

Store /teamwork run state in app data directory to prevent mutual overwrites

When launching multiple team collaborations in parallel under the same project directory, mixing state files can easily trigger conflicts. Previously, running /teamwork wrote run state into the .agents/teamwork/ folder in your working directory, causing two runs in the same workspace to overwrite each other. Each run now stores its state in an isolated folder under the CLI's app data directory. This issue has been fixed.

BUGFIX

Terminal file links display relative paths to identify locations without clickable support

When working over SSH connections or in traditional terminals, screens often cannot directly open clickable hyperlinks. Previously, file links in agent responses showed only the file name, making file locations impossible to identify in terminals that cannot open clickable links (such as Terminal.app, screen, or over SSH). Labels now explicitly display the path relative to your working directory, relative to ~/, or the absolute path. This issue has been fixed.

BUGFIX

Subagents and workers fully retain uncommitted changes, supporting isolated copies for large directories

When asking subagents or swarm workers to modify code separately, failing to sync uncommitted changes causes confusion. Previously, when subagents and swarm workers obtained copies of a Git repository, they only started from the last commit, causing all uncommitted work to be lost. Now their worktree (a Git feature that opens multiple parallel copies of the same project) fully includes all staged, unstaged, and untracked changes. Even if a project is not under version control, the CLI can provide workers with an isolated workspace folder, supporting limits up to 100,000 entries and 4 GiB in size. This issue has been fixed.
