Antigravity 1.1.17

Released: 2026-08-21

Release notes

FEATURE

One execution route makes agent behavior more consistent

When an agent handles the same job through different entry points, differing results are a nuisance.

Its execution harness now follows one path, so every starting point goes through the same process.

It is like routing trains from scattered platforms onto one main line, where the dispatch rules finally match.

Tool behavior is therefore more consistent. Hooks, small programs triggered by particular events, use that route too. Prompts, the instructions you give the agent, do as well. The same work should vary less just because you began it differently.

BUGFIX

Slash commands no longer vanish

When you want the teamwork preview but its command has vanished from the list, it can seem as though the feature does not exist.

It is like a familiar button falling off a remote: the device remains, but you cannot tell it what to do.

/teamwork-preview and some other slash commands, commands you call by typing /, no longer disappear for some users. When you need them, they should remain in the list so you can call their features as before.

BUGFIX

Enter opens active work even while typing in Vim mode

While typing a command in Vim insert mode, the state where text goes directly into the prompt, you might want to inspect work that is still running.

Enter previously would not open it.

It was like writing in a notebook while the lit-up to-do item beside it could not be opened; the button was visible but out of reach.

Now Enter opens an active background task, work that keeps running behind your current action. It also opens a subagent, an agent assigned work by another agent. You can inspect that work without first leaving insert mode.

BUGFIX

Ogg audio and video files can now be attached

When you give a recorded audio or video file to the model, the AI that reads files and responds, it is baffling to have a supported extension rejected.

It was like putting the same overly general shipping label on packages with different contents, leaving the receiving desk to send them back.

You can now attach .ogg, .opus, and .ogv files. They had all been sent as the generic application/ogg type, which made the model reject them; that attachment problem is fixed. Your Ogg audio and video no longer get stopped by that file-type label on the way in.
