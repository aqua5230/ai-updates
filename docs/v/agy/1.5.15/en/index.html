Antigravity 1.5.15

Released: 2026-11-23

Release notes

FEATURE

/context shows auto-compaction threshold

As a conversation grows longer and nears the model limit, you might wonder when cleanup will trigger. /context now adds an auto-compaction threshold row under the capacity header. The AGY_CLI_AUTO_COMPACT_OVERRIDE environment variable (a setting read when a program starts) now also supports all eligible models. To time conversation compaction yourself, set this variable to specify how many token (the text units AI processes and bills by) trigger it, up to the model's context window size. You can pass an exact count like 700000, a shorthand like 800K or 0.5M, or a percentage like 80%. Once set, you can see the active override in both /context and /model.

Picture setting an eighty-percent-full alarm for a warehouse: instead of scrambling to clear space only when it is nearly packed, you can choose how full it gets before tidying up early, and the dashboard shows your current threshold.
BUGFIX

Orchestrator thinking effort and /btw fixed

When Orchestrator is enabled to run planning and execution separately, unset roles and newly selected model families previously defaulted to the family's highest thinking level. Now the default Effort for Planner and Executor in the Orchestrator row of /model is high. If high is unavailable, it still falls back to that family's highest level. Your "orchestrator" choices saved in settings.json remain unchanged. When asking side questions with /btw in these conversations, it previously dropped the plan-and-execute split, and now inherits your configured Planner and Executor models and Effort.

Hiring an architect and a construction crew used to mean running at max brainpower from day one and losing the original team whenever you asked a quick side question; now it starts in a high gear by default, and any quick interruption is still handled by that same split team.
FEATURE

Local conversations kept by default

Previously, each time you launched the CLI, it only kept the 500 most recent local conversations and deleted older records on startup. Now all saved conversations are kept in ~/.gemini/antigravity-cli/conversations by default, with no automatic pruning of older ones.

FEATURE

Remote Control project picker and environment switching

Opening the home screen or new-conversation panes in the Remote Control browser view to find a project no longer requires clicking through a three-item Recent group and nested submenus. The project picker is now a flat, scrollable list sorted by recency that you can simply scroll through. When remote environments are available, the This Computer / Remote picker appears ahead of the project picker. It filters projects by environment and remembers the last project you used in each one. You can also open local GitHub projects remotely right from Clone from This Computer.

Think of organizing your phone contacts: instead of stuffing frequent contacts into three fixed slots behind nested menus, they are now laid out flat by most recent call, and switching between work and personal accounts still remembers who you last looked up.
FEATURE

Remote Control queued-messages card shows waiting tasks

When you send a new message to the agent from the browser view after the main reply finishes while background work is still running, the screen previously only showed Sends after agent finishes working. Now the queued-messages card header shows Waiting on ..., listing the active subagent count and the titles of up to two non-daemon (a small program that runs persistently in the background) background tasks or timers. Meanwhile, persistent background tasks such as dev servers do not hold up the queue, and pressing Send Now still sends your message right away.

Waiting in line at a bank counter used to show a sign that only said "Please wait," whereas now it shows how many tellers are busy ahead of you and which two documents are still pending; the air conditioner humming nearby does not count, and urgent requests still go through immediately.
FEATURE

Remote Control permission prompts bold target scope

Before granting the agent permission to touch files or run commands, uniform text across options makes it easy to miss what you are actually allowing. Permission prompts in the Remote Control browser view now bold the target folder path, command pattern, or domain inside "always allow" option labels. As you edit the target in the prompt, the bolding updates live so the scope a rule grants stands out at a glance.

FEATURE

Higher text contrast in tokyo night

When using the tokyo night color scheme, expanded thoughts, tool output, and dimmed hints previously blended too easily into agent responses. Adjusted text contrast now keeps those sections clearly distinct from the agent's main replies while remaining easy to read.

BUGFIX

/config terminal warnings and truncated descriptions fixed

Opening /config in a Windows terminal to check Rendering Mode previously often showed false warnings or cut-off descriptions. When TERM was unset in Windows PowerShell or Command Prompt consoles, it used to falsely warn ⚠ terminal does not support alt screen. That false warning is now fixed. Rendering Mode warnings such as ⚠ alt screen unavailable — run ssh -t also used to run right into the setting description in dim text. It would also say terminal "unknown" when the terminal name was unavailable, and cut off multi-line setting descriptions past three lines; all of these display issues are now fixed.

BUGFIX

agy acp editor loading and turn state fixed

When connecting an editor to the agent through agy acp, conversations often failed to finish loading history, attachments broke commands, or turns ended before work was done. Loading long conversations now waits for history replay to finish instead of cutting off after 2 seconds. Attaching to a running session preserves active permission and question prompts, and a missing session ID now returns error code -32002 instead of -32603. Leading slash commands or skills such as /plan or /compact are no longer skipped when files, selections, images, or links are attached ahead of them. Empty 0-byte files are preserved, and web URLs or line-range resource links are no longer treated as local paths. If subagents or non-daemon tasks are still running when the main reply finishes, the turn now stays open across background wake-ups until they finish and reports the combined token usage. Persistent tasks such as dev servers still end the turn right away. When interrupting or canceling a turn, in-progress tool calls no longer stay stuck open in the editor. Failed tool calls that produced no command or diff output now include error messages as well.

BUGFIX

Remote Control split terminal tabs no longer reload

When splitting a terminal pane side by side from the side panel in the Remote Control browser view, the screen previously reloaded and lost your scroll position and focus, which no longer happens. Adding new split panes now keeps the oldest pane as the group's lead pane and tab title. When a terminal exits at the same time another terminal opens, the view also automatically moves off the exited tab.

BUGFIX

Remote Control Long-Chat Load Older Messages Button No Longer Jumps

The keyboard- and screen-reader-focusable Load older messages button at the top of long conversations in the Remote Control web view used to disrupt interaction. On mobile, it used to clip against the title bar, and focusing or clicking it would scroll the view back to the bottom of the conversation. These issues are now fixed, and pressing Esc dismisses the button instead of accidentally closing the outer mobile drawer.
