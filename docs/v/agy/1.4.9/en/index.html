Antigravity 1.4.9

Released: 2026-10-28

Release notes

FEATURE

Terminal Paste Shortcuts and Image Dragging Support, Even over Remote SSH Connections

When you want the AI to analyze screenshots or design drafts, you no longer need to manually enter full file paths.

Just as you share photos in a messaging chat, where dragging an image into the terminal used to leave only a file path, you can now insert images directly into the conversation, even reaching remote connections accurately.

As long as only an image is in the clipboard, pressing your terminal's own paste shortcut (such as Cmd+V on Mac or Ctrl+Shift+V on other systems) pastes the image directly. Dragging image files straight into the prompt attaches them as files instead of inserting their paths. Image pasting operates normally even over SSH connections with X11 or Wayland forwarding enabled. When the clipboard contains no attachable media, pressing paste displays a No image or video found in the clipboard message. If the environment lacks a clipboard utility, the notice explicitly names the package to install, such as wl-clipboard on Wayland.

FEATURE

Plugin Discover Tab Groups by Marketplace Sections, with New Name and Logo Checks for Validation

Whether looking for terminal extensions or preparing to publish your own plugin, you can now align directly with official marketplace standards.

Picture browsing a department store where every product was once lumped into a single sprawling roster; items are now arranged across dedicated sections, while incoming storefronts have their signboards and name formats strictly checked.

Entering /plugin in the terminal to open the Discover tab presents plugins grouped by official marketplace sections rather than one flat list, with cross-category plugins listed under every relevant section. When testing plugins with agy plugin validate, names not using lowercase kebab-case (such as Neo4j) trigger a warning with suggested valid alternatives, failing under --strict. Validation now checks logos as well, warning if logo is unset, points externally or into bundled-out folders like .github/, or specifies external URLs, with the same checks applied to context provider iconUri values.

FEATURE

Long Diff Lists Explicitly Label Count Units, Distinguishing File Totals from Turn Rows

When browsing through extensive code change records in the terminal, navigation numbers at the bottom of the list clearly display their counting standard.

Think of leafing through a bound anthology where footer numbers previously omitted units and mixed chapter headers with text, making readers suspect missing pages; it now specifies whether it tallies total articles or formatted layout rows including headers.

Under longer /diff change lists, the position indicator previously showed only numeric ranges, leaving it ambiguous whether it referenced files or screen lines. The indicator now explicitly labels counting units according to the view mode, displaying counts like [1-44 of 195 files] in All Changes mode to clearly denote file totals. Switching to Per Turn mode displays [1-44 of 195 rows], since turn headers also count toward row totals. This distinction ensures the indicator no longer conflicts with actual file counts.

FEATURE

Auto Mode Command Review Skips Irrelevant Checks, Eliminating Timeouts in Non-Repository Folders

When using Auto mode to let the AI execute commands that might leave the terminal sandbox, the review process no longer stalls on unexpected timeouts.

A security guard doing neighborhood rounds used to rifle through nonexistent visitor logs in every empty room, running out the patrol clock; now they verify whether the unit is registered with the property board before searching.

When evaluating whether a command leaves the terminal sandbox, the reviewer now first determines whether the working directory belongs to a Git or other version control repository. Previously, the reviewer spent its time budget running git status blindly across all folders, triggering frequent timeouts in regular directories. By bypassing unneeded runs in non-repository folders, timeout rates during command reviews are noticeably reduced.

FEATURE

execute_url Permissions Isolated to Require Separate Approvals for Sensitive Google Services

When permitting AI tools to access public web pages, private accounts and cloud consoles are no longer automatically approved alongside them.

Consider visitor badges at an office building where an entry pass to the public lobby previously granted access all the way into private offices and vaults; general lobby admission is now strictly separated from secure vaults, requiring every suite to verify clearance individually.

When invoking web addresses with execute_url, permission rules now restrict the inherited scope of authorizations. Previously, approving a Google site like www.google.com or cloud.google.com also granted access to sensitive apps under the same domain. Services including mail.google.com, docs.google.com, drive.google.com, accounts.google.com, and console.cloud.google.com are now isolated under separate management. Each sensitive service requires your explicit individual approval rather than inheriting general website access.

BUGFIX

Always-Allow Rules for Multi-Line Commands Now Take Effect, Preventing Repeated Prompts and Unusable Settings

When running multi-line python -c or node -e scripts in the terminal, even if you had chosen to always allow them, the command line previously paused for confirmation on every execution while accumulating unusable entries in your settings. This issue is now resolved, and previously saved multi-line rules apply properly without repeatedly prompting for confirmation.

BUGFIX

Onboarding Screens Adapt to Small Terminals, Keeping Buttons Visible and Enabling Scrolling

When launching the tool for the first time and viewing onboarding screens in a smaller terminal window, the display was often cut off by window boundaries, hiding bottom confirmation buttons from view. Text and links now wrap automatically to fit terminal width. In very narrow terminals, the color preview is automatically cropped or hidden, and the banner only displays when the screen can accommodate it entirely. If step content is still too tall, you can scroll up and down using Shift+↑, Shift+↓, PgUp, or PgDn, while action buttons stay visible throughout.

BUGFIX

Vim Mode Supports Space Targets, Fixing Cursor Misalignment and Lingering Incomplete Commands

When using Vim editing mode in the terminal, pressing commands like r, f, F, t, and T followed by a space previously canceled the action. Combinations such as r<space>, f<space>, and df<space> now work properly. With the cursor on an empty last line, commands no longer mistakenly apply to the line above. After submitting a prompt, half-typed operators (such as a solitary d) no longer carry over into the next conversation turn.

BUGFIX

Hidden Characters Stripped Around Wrapped Code, Eliminating Boxes and Stale Artifacts in Terminals

When agent replies included wrapped code, invisible special characters (U+FFF9 and U+FFFA) previously leaked into the terminal, causing some terminals or terminal multiplexers to render them as unexpected boxes or leave stale characters on screen. This issue has now been resolved, and superfluous boxes or leftover characters no longer appear on screen.

BUGFIX

Persistent Conversation Errors Resolved by Omitting Malformed Images, Mismatched Tools, and Outdated Thinking Blocks

Several failure modes that previously caused subsequent turns to freeze when anomalous images, tool results, or thinking blocks appeared in conversation history have now been resolved. If the AI read a corrupt image or one with text preceding its header (such as a screenshot captured with adb exec-out screencap -p > screenshot.png that mixed in warnings), conversations repeatedly ran into INVALID_MEDIA errors. Such images are now rejected directly with an error indicating where the real header starts, allowing the AI to fix the command. When trimmed history left a tool result without its matching call, conversations previously froze with errors on every turn. Sending requests now actively omits unmatched tool calls and results. When using certain models on a Google Cloud project, if the system prompt, tools, or an earlier message changed after a thinking block, conversations previously failed persistently. Outdated thinking blocks are now dropped rather than rejecting the request.

BUGFIX

Fix Browser Subagent Missing Snapshots by Adding Required DevTools MCP Page ID

When used with Chrome DevTools MCP (Model Context Protocol, a protocol that connects AI to external tools) 1.11 or later, the /browser subagent previously failed to obtain snapshots of the current page at the start of each turn. This happened because the request omitted the page ID required by the new version, causing snapshot capture to fail silently in the background. This issue has now been resolved, with the required page ID added to the request so that the subagent can smoothly retrieve webpage snapshots at the start of each turn.
