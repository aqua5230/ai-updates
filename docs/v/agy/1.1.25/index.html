修正 Markdown 自訂代理相對路徑解析，以定義檔所在目錄為基準

你在自訂代理的 Markdown 定義檔中引用周邊模組時，相對路徑不再因為執行位置不同而迷路。過去在代理定義檔中若使用相對路徑來指定子代理與外掛程式，系統常以當前執行目錄而非定義檔所在位置進行解析，導致檔案找不到；現在相對路徑一律以該代理定義檔所在的資料夾為基準正確解析。這宛如依據建築平面圖找房間，說明書上的「走廊左側第三間」一律以這棟大樓的入口為基準計算，不會因為你站在不同大門外就指錯方位。

MCP OAuth 支援逾千字超長授權碼，身分驗證不再受阻

透過外部授權伺服器綁定帳號時，長序號不再卡死登入流程。使用 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）進行 OAuth 登入驗證時，如果授權伺服器回傳長度超過 1024 個字元的授權碼，過去系統會因長度限制而判定失敗；現在這項門檻限制已經修復，長度超過 1024 字元的授權碼也能順利通過驗證並完成服務連接。如同大樓門禁閘門升級了感應容量，過去訪客通行證條碼超過特定字數就會讀取失敗，現在遇到長條碼也能順暢感應通關。

修正 Windows 技能面板路徑比對，全域與工作區技能正確歸類

在 Windows 系統上檢視已安裝的擴充技能時，面板清單中的分類與層級變得更加精準。過去在 Windows 環境開啟 /skills 面板時，由於主機路徑分隔符號（反斜線 \）的比對問題，導致全域技能與工作區技能經常被錯誤分類；現在路徑比對與分組邏輯已完成修正，所有技能都會依其實際路徑正確歸類到所屬群組。猶如圖書館檔案室校正了索書號的辨識標籤，不再因為標籤上的斜線方向不同，就把總館的常備書籍誤標成分館專屬藏書。

排除執行期重複授權與崩潰隱患，強化 `/boost` 與摘要處理穩定度

長時間執行多代理協作或重啟工作階段時，幾項影響執行階段與系統設定的底層問題已獲得修正。過去在重新載入工作階段與呼叫子代理時，設定檔會不斷累積重複的授權項目，現在已修正此累積現象。針對加速執行，改善了工作者工具配置以解決 /boost 在執行期失敗的問題。同時修復了背景摘要更新在軌跡關閉後因嘗試讀取快取步驟（暫存的歷史步驟）而引發的空指標嚴重崩潰。這如同替工廠的自動化流水線做全面檢修，清除了多餘的重複通行許可並校準機具，還避免了抄表員在產線停機後誤查暫存紀錄而造成跳電。

加固 Remote Control 反向通道路由，遠端連線傳輸更安全

從外部裝置遠端連線操控開發環境時，網路傳輸通道現在變得更加牢固。這彷彿在總部與外勤特派員之間鋪設了加固的加密專用通道，並重新校準了路由方向，確保指令與數據往返時不會繞遠路或在中途受干擾。Antigravity 提供的 Remote Control（讓使用者從遠端裝置操控本機對話的功能）依靠反向通道路由來轉發通訊；這次更新全面加固了反向通道路由的處理機制，大幅提升遠端連線時的連線穩定性與路由安全性。

モデルカタログに Gemini 3.8 Flash が追加、API キー接続時の軽快な選択肢が拡充

公式 API キーで直接接続する開発者向けに、モデル一覧へ新たな選択肢が加わった。これは工具箱に高回転の軽量電動ドライバーを追加したようなもので、専用バッテリーを装着するだけで、素早い応答と軽快なペースが求められる組み立て作業にいつでも対応できる。環境変数に GEMINI_API_KEY を設定して接続すると、モデルカタログに最新の Gemini 3.8 Flash モデルが表示される。日常的なコードの検索や素早い編集を行う際、メニューから直接このモデルを指定して、より柔軟にモデルを使い分けることができる。

Markdown 定義のカスタムエージェントが周辺リソースをデフォルト継承、スキルやルールを即座に利用可能

Markdown ファイルでカスタムエージェントを作成する際、デフォルトエージェントと完全に同一のリソース構成を利用できるようになった。以前のカスタムエージェントは環境内に存在するスキル、ルール、サブエージェント（subagents、特定タスクを分担する補助エージェント）を自動で引き継がず、基本的な能力一式が不足しがちだった。現在はすべての周辺スキル、ルール、サブエージェントがデフォルトで継承され、追加設定なしで環境リソースを直接呼び出せる。これは新しく着任したアシスタントがオフィスに入ると、チーム共通の道具箱や業務規程、協力スタッフの名簿がすでに机の上に揃っていて、ゼロから申請する必要がない状態に似ている。

Markdown 定義カスタムエージェントの相対パス解決を修正、定義ファイルの配置ディレクトリを基準に解決

カスタムエージェントの Markdown 定義ファイルから関連モジュールを参照する際、実行場所の違いによって相対パスを見失う問題が解消された。従来のエージェント定義ファイルで相対パスを用いてサブエージェントやプラグインを指定すると、定義ファイルの場所ではなく現在の実行ディレクトリを基準に解決され、ファイルが見つからない事態が発生していた。現在は相対パスが該当エージェント定義ファイルのあるディレクトリを基準として正しく解決される。これはフロアマップに従って部屋を探す際、案内書の「廊下左手の3番目の部屋」という表記がその建物の入口を基準に計算され、自分が別の門の外に立っているからといって方角を誤らずに済むようなものだ。

MCP の OAuth 認証で 1024 文字超の長い認可コードに対応、ログインの失敗を解消

外部認証サーバーを通じてアカウントを連携する際、長いコードによってログイン処理が停止する問題が解消された。MCP（外部ツールと AI を接続するプロトコル）で OAuth 認証を行う際、認可サーバーから 1024 文字を超える認可コードが返されると、従来の長さ制限により認証が失敗していた。今回の修正によって制限が解消され、1024 文字を超える認可コードでも正常に検証を通過してサービスへ接続できるようになった。ビルのセキュリティゲートが読み取り容量を拡張し、以前は文字数が多すぎてエラーになっていた来訪者パスのバーコードも、スムーズに読み取って通過できるようになった状態と同じだ。

Windows 環境のスキルパネルにおけるパス照合を修正、グローバルとワークスペースのスキルを正しく分類

Windows 上でインストール済みスキルを確認する際、パネル一覧での分類と階層表示が正確になった。以前の Windows 環境で /skills パネルを開くと、パス区切り文字（バックスラッシュ \）の照合問題によって、グローバルスキルとワークスペーススキルが誤って分類されることがあった。現在はパス照合とグループ化のロジックが修正され、すべてのスキルが実際のパスに基づいて正しいグループへ分類される。これは図書館の書庫で請求記号の読み取り処理を是正し、記号内のスラッシュの向きが違うだけで本館の所蔵本を分館専用本と誤認しなくなった状態に似ている。

実行時の重複権限蓄積とクラッシュを解消、`/boost` と要約処理の安定性を強化

マルチエージェントの協調動作やセッションの再読み込みを長時間行う際、ランタイムや設定に影響していた複数の根本的な問題が修正された。従来はセッションの再読み込みやサブエージェントの呼び出しを繰り返すと設定ファイルに重複した権限許可が蓄積していたが、この蓄積が解消された。高速実行についてはワーカーツールの構成を改善し、実行時に /boost が失敗する問題を解決した。さらに、軌跡の終了後にバックグラウンドの要約更新がキャッシュされたステップを読み込もうとして発生していた深刻な nil ポインタクラッシュも修正された。これは工場の自動化ラインを総点検し、重複した通行証を整理して機械を調整しつつ、ライン停止後に記録係が一時データを参照して停電を引き起こす事態を防いだようなものだ。

Remote Control のリバーストンネルルーティングを強化、リモート接続の安全性を向上

外部端末から開発環境へリモート接続して操作する際、ネットワークの通信経路がより強固になった。これは本部と現場の特派員との間に暗号化された専用経路を整備し、ルーティングの向きを再調整して、送受信される指示やデータが遠回りしたり妨害されたりしないようにした状態に似ている。Antigravity が提供する Remote Control（リモート端末からローカルの対話を操作する機能）は、リバーストンネルルーティングを用いて通信を転送している。今回の更新ではこのルーティング機構が全面的に強化され、リモート接続時の安定性と安全性が大幅に向上した。

`/resume`에 디렉터리별 그룹 보기 추가, 단축키로 대화 목록을 깔끔하게 전환

여러 프로젝트 폴더를 오가며 작업할 때, 지난 대화 기록에서 이전 논의를 찾아내는 방식이 한층 더 깔끔해졌다. 서랍 속에 한데 섞여 있던 서류를 프로젝트 폴더별로 정리해 두고, 단축키 한 번으로 펼침 목록과 바인더 그룹을 자유롭게 오가는 것과 같다. /resume 명령어로 지난 대화를 선택할 때 자유롭게 활성화할 수 있는 워크스페이스 그룹 보기가 추가되었다. Ctrl+F 단축키를 누르면 기본 펼침 대화 목록과 디렉터리별로 그룹화된 보기 사이를 즉시 전환하여 특정 프로젝트의 이전 기록을 빠르게 찾을 수 있다.

모델 카탈로그에 Gemini 3.8 Flash 추가, API 키 연결 시 가벼운 선택지 제공

공식 API 키로 직접 연결하는 개발자를 위해 모델 목록에 새로운 선택지가 추가되었다. 공구함에 고속 경량 전동 드라이버를 하나 더 마련해 둔 것과 같아서, 전용 배터리만 연결하면 빠른 반응과 경쾌한 템포가 필요한 조립 작업에 언제든 꺼내 쓸 수 있다. 환경에 GEMINI_API_KEY를 설정하여 연결하면 모델 카탈로그에 최신 Gemini 3.8 Flash 모델이 표시된다. 일상적인 코드 조회나 빠른 편집을 진행할 때 메뉴에서 이 모델을 직접 지정하여 한층 유연하게 모델을 운용할 수 있다.

Markdown 커스텀 에이전트의 기본 환경 리소스 상속 지원, 스킬과 규칙 바로 사용

Markdown 파일로 커스텀 에이전트를 작성할 때 기본 에이전트와 동일한 리소스 구성을 그대로 활용할 수 있게 되었다. 이전에는 커스텀 에이전트가 환경 내에 존재하는 스킬, 규칙, 서브에이전트(subagents, 특정 작업을 분담하는 보조 에이전트)를 자동으로 이어받지 않아 기본 역량이 부족해지기 쉬웠다. 이제는 주변의 모든 스킬, 규칙, 서브에이전트를 기본으로 상속받아 별도 설정 없이도 환경 리소스를 즉시 호출할 수 있다. 새로 입사한 비서가 사무실에 들어섰을 때 팀의 공용 도구함과 업무 지침서, 보조 인력 명단이 책상 위에 이미 갖춰져 있어 일일이 신청할 필요가 없는 것과 같다.

Markdown 커스텀 에이전트의 상대 경로 해석 수정, 정의 파일 디렉터리 기준으로 변경

커스텀 에이전트의 Markdown 정의 파일에서 주변 모듈을 참조할 때 실행 위치에 따라 상대 경로를 잘못 찾는 문제가 해결되었다. 기존에는 에이전트 정의 파일에서 상대 경로로 서브에이전트나 플러그인을 지정하면 정의 파일 위치 대신 현재 실행 디렉터리를 기준으로 경로를 해석하여 파일을 찾지 못하는 경우가 발생했다. 이제 상대 경로가 해당 에이전트 정의 파일이 위치한 디렉터리를 기준으로 올바르게 해석된다. 건물 평면도를 보고 방을 찾을 때 안내서의 "복도 왼쪽 세 번째 방"이라는 설명이 건물 입구를 기준으로 계산되어, 다른 출입문 바깥에 서 있다고 해서 방향이 어긋나지 않는 것과 같다.

MCP OAuth 1024자 초과 긴 인증 코드 지원, 인증 실패 문제 해결

외부 인증 서버를 통해 계정을 연동할 때 긴 문자열 때문에 로그인 과정이 막히는 현상이 사라졌다. MCP(AI가 외부 도구와 연결되도록 돕는 프로토콜)로 OAuth 인증을 진행할 때 인증 서버가 1024자를 초과하는 긴 인증 코드를 반환하면 기존에는 길이 제한으로 인해 실패로 처리되었다. 이번 수정으로 해당 제한이 해결되어 1024자가 넘는 인증 코드도 정상적으로 검증을 마치고 서비스 연동을 완료할 수 있다. 건물 출입 게이트의 인식 용량을 늘려, 예전에는 글자 수가 길어 인식에 실패하던 방문증 바코드도 막힘없이 통과시키는 것과 같다.

Windows 스킬 패널의 경로 매칭 수정, 전역 및 워크스페이스 스킬 정상 분류

Windows 환경에서 설치된 스킬을 확인할 때 패널 목록의 분류와 계층 구조가 한층 정확해졌다. 이전에는 Windows에서 /skills 패널을 열었을 때 호스트 경로 구분자(백슬래시 \) 매칭 문제로 인해 전역 스킬과 워크스페이스 스킬이 잘못 분류되는 현상이 자주 발생했다. 이제 경로 매칭 및 그룹화 로직이 수정되어 모든 스킬이 실제 경로에 따라 올바른 그룹으로 정리된다. 도서관 자료실에서 청구기호 인식 라벨을 바로잡아, 라벨의 슬래시 방향이 다르다는 이유로 본관 비치 도서를 분관 전용 도서로 잘못 표시하지 않게 된 것과 같다.

런타임 중복 권한 축적 및 충돌 문제 해결, `/boost` 및 요약 처리 안정성 강화

다중 에이전트 협업을 오래 실행하거나 세션을 다시 불러올 때 런타임과 설정에 영향을 미치던 여러 근본적인 문제가 해결되었다. 기존에는 세션 재로드 및 서브에이전트 호출 시 설정 파일에 중복된 권한 허용 항목이 계속 누적되는 현상이 있었으나 이를 바로잡았다. 빠른 실행을 위해 워커 도구 구성을 개선함으로써 /boost가 런타임에 실패하던 문제를 해결했다. 아울러 실행 궤적이 닫힌 후 백그라운드 요약 업데이트가 캐시된 단계를 읽으려다 발생하던 심각한 nil 포인터 비정상 종료도 수정되었다。공장의 자동화 생산 라인을 총점검하여 불필요한 중복 출입증을 정리하고 기계를 조율하는 한편, 라인이 멈춘 뒤 검침원이 임시 기록을 잘못 확인하여 정전이 발생하는 상황을 방지한 것과 같다.

Remote Control 역방향 터널 라우팅 강화, 원격 연결 전송 보안 향상

외부 기기에서 원격으로 연결하여 개발 환경을 제어할 때 네트워크 전송 통로가 한층 더 견고해졌다. 본부와 현장 특파원 사이에 암호화된 전용 통로를 구축하고 라우팅 방향을 재조정하여, 오가는 명령과 데이터가 우회하거나 도중에 방해받지 않도록 보장한 것과 같다. Antigravity가 제공하는 Remote Control(원격 기기에서 로컬 대화를 제어하는 기능)은 역방향 터널 라우팅을 통해 통신을 전달한다. 이번 업데이트에서는 역방향 터널 라우팅 처리 메커니즘을 전면 강화하여 원격 연결 시의 연결 안정성과 라우팅 보안을 대폭 향상했다.
