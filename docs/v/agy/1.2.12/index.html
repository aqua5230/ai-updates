Antigravity 1.2.12

發布日期：2026-09-27

繁體中文

效能優化

全螢幕捲動效能升級，長對話與檢視器不再卡頓

當你在全螢幕模式下翻閱篇幅很長的對話紀錄，或是打開產出物檢視器查閱內容時，快速滑動滾輪與觸控板變得十分滑順。

以前手指快速滾動時，每一次細微的滾輪訊號都會立即觸發畫面重新繪製，不僅容易造成畫面卡頓，還會佔用大量處理器（CPU，電腦負責運算的核心）資源。現在系統會先將短時間內連續觸發的滑動事件合併整理，再一次性更新畫面，既降低了運算負擔，也消除了操作延遲。

如同收發室把同一時間寄達的零散信件整批捆好一次遞交，不必每來一張明信片就專程跑一趟辦公室。
新功能

額度或預算耗盡立即停損，不再空等數分鐘重試

使用金鑰 GEMINI_API_KEY 進行操作時，一旦帳戶額度見底，系統會立即中斷並回報，不再讓你乾等。

以前只要遇到每日配額（quota，平台允許呼叫的使用上限）耗盡、專案或帳單達到支出上限，或是預付餘額扣光，程式仍會花費數分鐘持續重試不可能成功的連線。現在遇到這類確定無法解決的狀況會立刻中止工作階段。至於每分鐘呼叫次數超標這類短暫限制，仍會自動重試。

好比去自動販賣機買飲料，發現卡片餘額不足時機器會立刻提示餘額為零，而不是反覆吞吐卡片空轉好幾分鐘。
問題修復

重新接續長對話瞬間載入，跳過重複動畫不再卡頓

當你打開先前篇幅很長的工作階段繼續提問時，畫面載入的速度變得俐落許多。

以前在 medium 或 low 的詳細程度（verbosity，決定畫面要印出多少除錯與執行細節的設定）下恢復對話時，系統需要花上數秒重播所有歷史紀錄，造成操作延遲。現在先前執行完畢的工具會直接顯示為完成狀態，省去逐條重播動畫的時間。在載入過程中敲擊鍵盤，也不會再重新整理只載入到一半的對話紀錄。

就像翻開已寫好的會議紀錄，大家能直接從結論處接著討論，不必把每位發言者的發言逐字重唸一遍。
問題修復

終端機多工器標題不再亂碼，修復圖片探測干擾

在多窗格環境下啟動工具時，終端機與分頁的名稱終於能正常保留。

以前在 GNU screen、tmux（包含 iTerm2 的 tmux -CC 分頁）或 Zellij 等環境中開啓命令列時，標題每次都會被改成 Ga=q,f=32,... 這類奇怪的字串。這是因為系統啟動時會發送圖片支援的探測訊號，因而干擾了終端機多工器（將終端視窗分割成多個獨立工作區的工具）。現在程式不再主動向多工器發送圖片探測指令。若你確定需要開啟圖片顯示，依然可透過設定 CLI_GRAPHICS=kitty 強制啟用。

彷彿廣播系統取消了開場時刺耳的測試音，螢幕面板上的節目名稱再也不會被測試訊號給干擾覆蓋。
問題修復

Vim 模式多項修正，支援中文字元搜尋與選取復原

偏好使用 Vim 模式編輯指令與文字的讀者，現在輸入非英文字元或選取段落時順手許多。

以前在 r、f、F、t 與 T 指令後輸入 é 或 中 等非 ASCII 字元（非英文字母與標準符號的文字）時會被直接忽略。在可視模式（Visual mode，反白選取文字的模式）下使用 fv 與 fV 會意外跳出選取，無法順利延伸範圍。當執行 D、C 或可視狀態下的 ~、u、U 但沒有變動文字時，以前還會多記一筆空白復原紀錄並清空重做歷程。現在這些編輯問題都已修正完畢。

宛如操作高階文書軟體，跳躍搜尋中文字能精確定位，反白選取時不會無故中斷，就算誤觸沒有作用的按鍵也不會清空復原歷程。

English

PERF

Smoother Full-Screen Scrolling Eliminates Stutter in Long Chats and Artifact Viewer

Rapid scrolling with a mouse wheel or trackpad is now much smoother when browsing lengthy conversation histories or inspecting content in the artifact viewer in full-screen mode.

Previously, every tiny scroll event triggered an immediate screen redraw during fast scrolling, which caused visual stutter and consumed heavy CPU resources. The system now batches scroll events triggered in rapid succession before updating the screen all at once, reducing computational overhead and eliminating lag.

Picture a mailroom bundling scattered letters that arrive at the same time into a single delivery, rather than running to an office for every individual postcard.
FEATURE

Immediate Fail-Fast on Exhausted Quota or Budget Without Minutes of Retrying

When operating with GEMINI_API_KEY, the system now halts immediately and reports the error once your account quota is exhausted, sparing you from waiting idly.

Previously, when hitting daily quotas, project or billing spend limits, or running out of prepaid credits, the application would still spend several minutes retrying connections that could not possibly succeed. The session now terminates immediately upon encountering these permanently unresolvable conditions. Transient restrictions such as exceeding rate limits per minute will still be retried automatically.

A vending machine immediately alerts you to a zero balance when your card lacks sufficient funds, rather than repeatedly ejecting and swallowing the card for minutes.
BUGFIX

Instant Resumption for Long Sessions Skips Replay Animations Without Lag

Loading feels much crisper when reopening a lengthy prior session to continue asking questions.

Previously, resuming a conversation under medium or low verbosity required several seconds to replay entire histories, causing UI lag. Previously completed tools now render directly in their finished state, skipping sequential animation replays. Typing on the keyboard during loading also no longer refreshes a conversation history that has only partially loaded.

Think of opening completed meeting minutes where everyone resumes discussion directly from the conclusion, without reading every attendee's remarks aloud word for word.
BUGFIX

Terminal Multiplexer Titles Preserved Without Mojibake From Graphics Probing

Terminal and tab titles are now properly preserved when launching tools in multi-pane environments.

Previously, opening the command line under GNU screen, tmux (including iTerm2 tmux -CC tabs), or Zellij altered window titles to strange strings like Ga=q,f=32,.... This occurred because the startup sequence sent graphics support probes, which interfered with terminal multiplexers. The program no longer sends graphics probes to multiplexers by default. If you still need image rendering, you can force it on by setting CLI_GRAPHICS=kitty.

Like a broadcast system silencing its harsh opening test tone, the show title on the display panel is no longer scrambled by test signals.
BUGFIX

Multiple Vim Mode Fixes Support Non-ASCII Character Search and Selection Undo

Editing commands and text in Vim mode is now significantly smoother when typing non-English characters or selecting blocks.

Previously, non-ASCII characters such as é or 中 were silently ignored after r, f, F, t, and T commands. Using fv and fV in Visual mode inadvertently exited the selection instead of extending the range. Furthermore, executing D, C, or Visual mode ~, u, and U without modifying text recorded an empty undo entry and wiped the redo history. All of these editing glitches have now been resolved.

Much like working in an advanced text editor, jumping to Chinese characters lands accurately, highlighting text does not abruptly cancel, and hitting ineffective keys will not wipe your redo history.
