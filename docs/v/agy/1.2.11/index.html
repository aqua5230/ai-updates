Antigravity 1.2.11

發布日期：2026-09-25

繁體中文

新功能

模型推理解析度支援分級，旗標與選單皆可自訂力度

當你需要模型處理繁複的架構設計或快速回覆簡短提問時，能自由調配思考深度就顯得格外實用。

Antigravity 改進了不同模型對推理解析度（reasoning effort，模型產生答案前的思考運算深度）的支援，讓支援不同思考力度的模型能更精準切換層級。現在只要在啟動指令加上 --effort 旗標，或在對話中輸入 /effort 與 /model，就能從視覺化量表直接挑選適合的強度。

就像騎變速自行車依路況切換檔位，遇到陡峭山路時切換到高檔全力衝刺，平坦直路則換上輕檔快速巡航。

遇到棘手的重構難題時拉高力度，寫簡短測試或整理資料時調低檔位，思考資源運用更靈活。

新功能

需要設定參數的手動外掛改為預設停用

平時若是習慣直接把擴充套件檔案複製到設定資料夾，要注意這些外掛的啟用方式變了。

以前直接放進 ~/.gemini/config/plugins 目錄的外掛，只要內含需要設定參數的 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器，往往一放進去就嘗試運作；現在它們預設會先保持停用，直到你主動啟用為止。這樣的行為已與透過 /plugin 指令安裝的外掛完全一致。

如同收到需要裝上電池才能運轉的新家電，出廠時預設切在斷電安全檔，一定要先裝妥配件並手動按下開關才會啟動。
問題修復

WezTerm 與 VS Code 終端機不再破圖，圖表改以純文字備援顯示

在 WezTerm 或 VS Code 內建終端機裡查看架構圖或數學公式時，畫面上不再出現一連串令人摸不著頭緒的亂碼方塊。

過去輸出 Mermaid 流程圖或 LaTeX 公式時，終端機被誤判為支援 Kitty 繪圖通訊協定，導致畫面印出整排破圖字元；現在已取消這項假設，改以清晰的 ASCII 純文字備援格式顯示，確保圖表與排版內容都能一目了然。

問題修復

關閉選取即複製後，成品檢視器釋放滑鼠控制並恢復快速鍵

當你在設定中關閉選取自動複製功能時，瀏覽產出的檔案內容不再被強制攔截游標動作。

過去在 /config 裡將 Copy on Select 關閉後，成品檢視器依然會捕捉滑鼠事件，使得終端機原生的選取與複製快速鍵無法使用；現在檢視器已不再佔用滑鼠，終端機本身的複製操作能正常運作，按下 Ctrl+C 也會如期執行中斷或退出。

問題修復

專案自訂代理支援修復，桌面端與無頭模式皆能正常選用

當你在專案目錄下配置專屬的輔助角色時，各個執行環境現在都能順利讀取到這些客製化設定。

以前放在 .agents/agents/ 目錄下的專案自訂代理，容易在桌面應用程式建立的工作區、已信任的工作區、使用 --agent 參數、以 -p 或 --prompt 執行的 headless（無頭模式，沒有終端機視窗的執行模式），以及 /agents 面板中找不到或無法選取；現在這些辨識問題均已修好，無論在哪種模式下都能直接指派自訂代理。

English

FEATURE

Tiered Reasoning Effort Support for Models, Configurable via Flag and Menu

When you need a model to tackle complex architectural designs or quickly answer brief questions, the freedom to adjust thinking depth is especially useful.

Antigravity improves support for reasoning effort across different models, allowing models with varying reasoning capabilities to switch levels more precisely. You can now select the right intensity directly from a visual gauge by adding the --effort flag to startup commands or running /effort and /model during a session.

Like shifting gears on a bicycle to match the terrain, a rider shifts into a higher gear for full power on steep climbs and cruises in a lighter gear on flat roads.

Dial up the effort for tricky refactoring tasks and lower it for short tests or data organization, making your thinking resources far more flexible.

FEATURE

Manually Added Plugins That Need Configuration Now Start Disabled

If you usually copy plugin files directly into the configuration folder, note that these plugins now start up differently.

Previously, plugins placed directly in the ~/.gemini/config/plugins directory would attempt to run immediately if they contained MCP servers requiring configuration parameters; now, they remain disabled by default until you explicitly enable them. This behavior now fully matches plugins installed via the /plugin command.

Picture receiving a new household appliance that requires batteries: it arrives safely switched off by default, starting up only after you install the accessories and manually turn on the power switch.
BUGFIX

No More Garbled Graphics in WezTerm and VS Code, Falling Back to Plain Text Diagrams

When viewing architecture diagrams or mathematical formulas inside WezTerm or the VS Code integrated terminal, you will no longer see confusing rows of corrupted placeholder characters.

Previously, when rendering Mermaid flowcharts or LaTeX formulas, these terminals were incorrectly assumed to support the Kitty graphics protocol, causing rows of broken characters to print on screen. Antigravity has removed this assumption and now displays them in a clear ASCII fallback format, ensuring that both diagrams and formatted content remain readable at a glance.

BUGFIX

Artifact Viewer Releases Mouse Capture When Copy on Select Is Disabled, Restoring Shortcuts

When you disable automatic copy on selection in settings, browsing generated file contents will no longer hijack your cursor actions.

Previously, after turning off Copy on Select in /config, the artifact viewer continued to capture mouse events, preventing the terminal's native selection and copy shortcuts from working. The viewer now releases the mouse so your terminal's built-in copy operations function normally, and pressing Ctrl+C properly interrupts or exits as expected.

BUGFIX

Project Custom Agents Fixed Across Desktop App and Headless Runs

When configuring dedicated assistant roles in your project directory, every execution environment can now smoothly load these custom settings.

Previously, project custom agents located in .agents/agents/ were frequently missing or unselectable in workspaces created in the Desktop App, in trusted workspaces, when specifying --agent, in headless -p or --prompt runs without a terminal window, and within the /agents panel. These discovery issues have all been resolved, allowing you to assign custom agents directly in any mode.
