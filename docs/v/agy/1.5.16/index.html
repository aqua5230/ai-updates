Antigravity 1.5.16

發布日期：2026-11-24

繁體中文

新功能

指令列支援 -r 與 --resume 接續對話

昨天請 AI 改報告到一半關掉終端機，今天想靠對話 ID 接回同一段討論，不用再打完整的參數名稱。這版為 --conversation 加上兩個別名，直接輸入 agy -r <id> 或 agy --resume <id> 就能接續指定對話。

新功能

多步驟任務現在會顯示即時步驟清單

請代理人一口氣處理好幾個動作，盯著空白畫面常會不確定它做到哪裡。在多步驟的互動回合中，輸入框上方的狀態列底下現在會展開即時清單。 只要代理人透過 update_steps 追蹤進度，狀態列就會顯示 N/M steps，若有跳過或失敗的項目也會一併計數。清單最多展開 7 個步驟，項目更多時會用 ⋮ N earlier 與 ⋮ N more 標示前後還有幾項，等全部步驟都完成就會自動收起。

跟去大賣場拿著紙條採買一樣，以前得靠腦袋記住買到第幾樣，現在手邊攤開的清單隨買隨劃掉，東西拿齊了還會自己收進口袋。
新功能

支援 ~/.agents/skills 技能探索

平時換用不同 AI 工具整理資料，最麻煩的是同一套做法得在各家資料夾各複製一份。現在也支援探索放在 ~/.agents/skills 的跨工具 Agent Skills（寫好流程給 AI 照做的擴充包）。 這些技能會直接出現在 /skills 清單與輸入 / 的自動補全裡，代理人執行回合時也能直接取用。如果剛好和 ~/.gemini 裡的技能撞名，仍會優先採用 ~/.gemini 的版本。

以前廚師每換一間廚房，都得把慣用的烹飪刀具重新擺一份；現在放到玄關的共用收納架，進哪間廚房都能順手拿來用，但屋主原本灶台上的那組還是優先。
新功能

執行計時拆開計算並即時更新額度

等代理人處理較長的任務，看著畫面上跳動的秒數或想確認剩餘額度，最怕數字還停在舊狀態。 現在輸入框上方的狀態列會把思考與跑工具分開計時，例如分別顯示 Thinking... 12s 和 Running command... 18s。每當切換階段或換下一個工具，計時就會歸零重算。對話紀錄裡的 Thought for <duration> 標題也只算思考時間，不再把跑工具與串流回覆的時間混進去。 遇到持續一分鐘以上的長回合，模型額度會在代理人串流回覆的過程中定期刷新。回合還沒結束前，輸入 /usage、/quota 或自訂的 statusLine（顯示在終端機最底下的狀態列）指令就能看到最新額度。

就像廚房為洗菜和燉湯分開按碼表，牆上的瓦斯餘量表也會邊煮邊更新，不必等整鍋端上桌才發現快見底。
新功能

全螢幕模式把輸入列固定在終端機底部

開啟 full screen (altscreen) 模式開新對話、瀏覽短對話，或剛按 Ctrl+L 清空畫面，輸入列以前會先出現在終端機上方。隨著訊息進來，輸入列才跟著往下滑。現在這幾種情況下，輸入列都會直接固定在終端機底部。

新功能

Auto 模式放寬工作區外安全寫檔限制

交給預設 Agent Mode 的 Auto 模式處理跨資料夾任務，以前只要寫入或改動工作區外檔案，每次都得先問過你。現在有兩種情況會直接放行。如果檔案位在 Git、Jujutsu 或 Mercurial 等版本控制存放庫（保留歷次修改紀錄的資料夾）內，就會直接處理。如果是只新增內容，例如建立新檔、在尾端附加或插入文字而不替換舊行，一樣不用先問。 不過在存放庫外覆寫或替換舊行，或碰到隱藏路徑、作業系統與開機資料夾，仍會先問。版本控制與 hook（特定事件發生時觸發的小程式）的設定資料如 .git、hooks.json 同樣要先核准，ask 與 deny 規則和組織政策也照舊生效。

在有複寫留底的帳本上補寫新收支，以前會計每次下筆都得先問過你；現在單純補記他能直接寫上去，但想塗改沒有留底的舊帳或翻動封條文件，照樣得先經你點頭。
新功能

停用外掛設定改為保留內建外掛運作

對採用管理員控管設定或 Gemini Enterprise 外掛控管的組織來說，過去開啟 pluginControls.pluginsDisabled 會把內建外掛一併關掉。這版調整後，這項設定會繼續封鎖已安裝、工作區與市集裡的外掛及外掛指令，但會保留內建外掛正常運作。

如果把門口的總電閘分成兩路，以前一拉下來連牆上的緊急指示燈也跟著全暗；現在只會切斷自己外接的延長線與插座，出廠內建的基礎照明照樣亮著。
問題修復

修正指令失敗與逾時狀態燈誤亮綠燈

打開 low、high 詳細度、/thinking 或按 Ctrl+O 展開的對話紀錄，以前常會被綠色圓點誤導，以為步驟都順利跑完。其實裡面可能有執行失敗或逾時的終端機指令，現在這兩種情況都會改亮紅燈，手動取消的指令則維持灰色。

問題修復

修正自填回答時游標消失與輸入法錯位

代理人或子代理發問而你選擇自行打字回答，過去終端機游標會躲到畫面最底下，中、日、韓文等輸入法的組字文字還會跑到別的位置。這個問題已經修好，現在硬體游標會跟著實際編輯位置移動。

問題修復

修正 macOS 經 SSH 跑 agy 重複要求登入

透過 SSH 遠端連進 macOS 執行 agy，過去會繞過你原本在 macOS Keychain（本機保管登入憑證的鑰匙圈）裡的登入狀態，每次都要求重新登入。這個問題已經修好，只要登入 Keychain 處於解鎖狀態，agy 現在會直接沿用；若處於鎖定狀態，就會改用檔案形式儲存 token（登入用的驗證令牌）作為備援。

問題修復

修正 agy acp 轉送子代理請示卡住 60 秒

在 default 或 accept-edits 模式下用 agy acp 連接編輯器，過去子代理或工作流程代理需要工具核准或向你發問，畫面會卡住 60 秒沒反應。現在已經修好，子代理的權限請求、表單提示與提問都會轉送到編輯器，你的回覆也會送回給子代理。

問題修復

修正 /swarm 喚醒通知歸屬錯誤

使用 /swarm 多代理協作，過去留言板的喚醒通知會被記在最後開啟這個群組的成員名下，而非 "system"。這樣一來，針對特定成員的計時器可能提前被取消，工作者的對話壓縮時也容易擠掉協調者的指示。現在通知來源已改回 "system"，不會再發生這兩種連鎖影響。

問題修復

修正語音聽寫無法轉文字與錄音卡住

想在遠端控制網頁版或長對話裡直接開口輸入文字，過去語音聽寫有幾種情況會失靈。 在遠端控制網頁版，語音聽寫原本會直接錄成音訊附件，不會把說話內容轉寫進訊息框，留言框裡的麥克風按鈕還會不見。有時瀏覽器的內容安全政策（限制網頁能存取哪些功能的保護規則）也會擋住麥克風開始收音。現在這些情況已經修好，麥克風能正常收音並把語音轉成文字。 在讀過大檔案或長指令輸出的長對話裡啟動聽寫，以前容易失敗或逾時。在遠端控制網頁版若音訊片段沒有照順序送達，按下停止錄音也會卡住，現在這兩種情況都已解決。

問題修復

修正遠端網頁版大型影音檔開啟失敗

在瀏覽器看遠端對話裡的錄音或影片，以前檔案稍微大一點就會直接被擋下來。只要超過 20 MB 就無法在遠端控制網頁版開啟、播放或下載，畫面還會跳出 File exceeds the 20MB display limit。現在已經修好，最高到 200 MB 的音訊與影片檔都能正常開啟、播放與下載。

問題修復

修正手機遠端網頁返回首頁列表跳回頂端

在行動裝置上滑了半天好不容易找到想看的項目，點進去看一眼再按上一頁，畫面卻又得重頭往下找起。過去在手機的遠端控制網頁版裡，從對話退回首頁時，專案與對話列表會直接重設回最頂端。現在已經修好，回到首頁會保留你原本的捲動位置。

English

FEATURE

CLI supports -r and --resume to resume conversations

If you closed your terminal yesterday while asking AI to revise a report and want to pick up the same conversation by its ID today, you no longer need to type the full flag name. This release adds two aliases for --conversation, so you can run agy -r <id> or agy --resume <id> to resume a specific conversation.

FEATURE

Multi-step tasks now show a live step checklist

When you ask the agent to handle several actions in one go, staring at a blank screen often leaves you guessing how far it has gotten. During multi-step interactive turns, a live checklist now opens under the status line above the prompt. Whenever the agent tracks progress with update_steps, the status line displays N/M steps, along with counts for any skipped or failed items. The checklist shows up to 7 steps, using ⋮ N earlier and ⋮ N more when there are more items before or after, and hides automatically once all steps finish.

Like shopping at a big-box store with a paper list, you no longer have to remember which item you are on—the open list lets you cross things off as you grab them and slips itself into your pocket once you have everything.
FEATURE

Skill discovery now supports ~/.agents/skills

When switching between different AI tools to organize information, the biggest hassle is keeping a separate copy of the same workflow in each tool's folder. Discovery now also supports cross-tool Agent Skills (extension packs with written workflows for AI to follow) placed in ~/.agents/skills. These skills appear directly in the /skills list and / autocomplete, and the agent can use them during its turns. If a name collides with a skill in ~/.gemini, the ~/.gemini version still takes precedence.

Think of a chef who used to set up a fresh set of knives in every kitchen they entered; now the knives sit on a shared entryway rack ready for any kitchen, though the homeowner's own set on the counter still comes first.
FEATURE

Separate elapsed timers and live quota updates

While waiting on a longer task, watching the ticking seconds or checking your remaining quota is frustrating if the numbers are stuck on stale state. The status line above the prompt now times thinking and tool runs separately, showing labels such as Thinking... 12s and Running command... 18s. Whenever the agent switches phases or moves to the next tool, the timer resets to zero. Thought for <duration> headers in the transcript also count only thinking time, without mixing in tool runs and response streaming. For long turns lasting a minute or more, your model quota refreshes periodically while the agent streams its reply. Before the turn even finishes, running /usage, /quota, or custom statusLine (the bar displayed at the very bottom of the terminal) commands shows your latest quota.

Picture a kitchen running separate stopwatches for washing vegetables and simmering soup, while the gas gauge on the wall updates as you cook so you don't wait until the pot hits the table to find out you're running low.
FEATURE

Full-screen mode anchors the prompt bar at the bottom

When you use full screen (altscreen) mode to start a new conversation, view a short one, or clear the screen with Ctrl+L, the prompt bar used to appear near the top of the terminal first. As messages arrived, it would then slide down. In all of these cases, the prompt bar now stays anchored at the bottom of the terminal.

FEATURE

Auto mode relaxes safe file-write limits outside the workspace

When the Auto mode of the default Agent Mode handles tasks across folders, it used to ask for your approval before every write or edit outside the workspace. Two cases now proceed without asking. If the file lives inside a version-controlled repository (a folder that keeps a history of past changes) such as Git, Jujutsu, or Mercurial, it goes right ahead. If the change only adds new content—such as creating a new file, appending at the end, or inserting text without replacing existing lines—it skips the prompt as well. However, overwriting or replacing existing lines outside a repository, or touching hidden paths, OS folders, or startup folders, still asks first. Configuration data for version control and hook (a small program triggered by specific events) setups like .git and hooks.json also require approval, and ask and deny rules plus organization policies remain in effect.

An accountant adding new entries to a carbon-copy ledger used to ask you before every stroke; now plain additions go straight onto the page, while altering unbacked old entries or opening sealed documents still needs your nod.
FEATURE

Disabling plugins now keeps built-in plugins active

For organizations using managed admin settings or Gemini Enterprise plugin controls, enabling pluginControls.pluginsDisabled used to shut off built-in plugins as well. With this update, the setting still blocks installed, workspace, and marketplace plugins and plugin commands, while keeping built-in plugins running normally.

Imagine splitting the main breaker at the door into two circuits: flipping it down used to black out even the emergency wall lights, whereas now it only cuts your own extension cords and outlets while the factory-built lighting stays on.
BUGFIX

Fixed green status dots on failed and timed-out commands

When opening low or high verbosity, /thinking, or transcripts expanded with Ctrl+O, a green dot could mislead you into thinking every step succeeded. In reality, a shell command inside might have failed or timed out; both cases now show a red dot instead, while manually canceled commands stay gray.

BUGFIX

Fixed missing cursor and IME drift on custom answers

When an agent or subagent asked a question and you chose to type a custom answer, the terminal cursor used to hide at the very bottom of the screen and IME composition text for Chinese, Japanese, or Korean would appear in the wrong spot. This is now fixed, so the hardware cursor follows your actual editing position.

BUGFIX

Fixed repeated sign-in prompts for agy over SSH on macOS

Running agy over SSH on macOS used to bypass your existing sign-in state in macOS Keychain (the local store for sign-in credentials) and prompt you to sign in every time. This is now fixed: as long as your login Keychain is not locked, agy reuses it directly, and if it is locked, it falls back to storing your token (an authentication pass used for sign-in) in a file.

BUGFIX

Fix agy acp stalling 60 seconds on subagent prompts

When using agy acp to connect to an editor in default or accept-edits mode, the screen previously stalled for 60 seconds without responding whenever a subagent or workflow agent needed tool approval or asked you a question. This is now fixed: subagent permission requests, form prompts, and questions forward to the editor, and your answers route back to the subagent.

BUGFIX

Fix /swarm wakeup notification attribution

When collaborating with /swarm, board wakeup notifications were previously attributed to whichever member last opened the group instead of "system". As a result, member-scoped timers could be canceled early, and coordinator instructions could be crowded out when a worker's conversation compacted. The notification source is now back to "system", preventing both knock-on effects.

BUGFIX

Fix voice dictation transcription and recording stalls

When trying to speak text directly in the Remote Control browser view or in long conversations, voice dictation previously failed in a few situations. In the Remote Control browser view, voice dictation used to record an audio attachment instead of transcribing speech into the message box, and the microphone button in comment boxes would disappear. Sometimes the browser's content security policy (rules that restrict which features a page can access) also blocked the microphone from starting capture. These issues are now fixed, so the microphone captures audio properly and converts speech to text. Starting dictation in long conversations with large file reads or long command outputs also used to fail or time out. In the Remote Control browser view, pressing stop on a recording could also stall if audio chunks arrived out of order; both cases are now resolved.

BUGFIX

Fix large media files failing to open in Remote Control

When viewing audio or video in remote conversations from a browser, slightly larger files used to be blocked outright. Anything over 20 MB could not be opened, played, or downloaded in the Remote Control browser view, and File exceeds the 20MB display limit appeared on screen. This is now fixed, and audio and video files up to 200 MB can be opened, played, and downloaded normally.

BUGFIX

Fix mobile Remote Control resetting home list to top

On mobile, after scrolling to find an item, tapping into it, and going back, you had to search down from the top all over again. Previously, navigating back from a conversation to the home screen in the mobile Remote Control browser view reset the projects and conversations list to the very top. This is now fixed, and returning to the home screen preserves your scroll position.
