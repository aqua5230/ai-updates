出門在外即使腳下的暫停點突然消失，只要隨身手冊記的是完整全球座標，導航就能照常運作。就算你在一處已被刪除或無法存取的工作目錄中啟動命令列，工具初始化與代理啟動程序也不會再莫名崩潰。以前系統在處理記憶體中的參數架構時，會因目錄失效而找不到相對參照；現在全面改用絕對 URI（統一資源識別碼，以標準格式標記位置的字串）格式，確保各項工具與代理在任何目錄狀態下都能順利初始化。

Smoother `/mcp` Panel Navigation with Clear Arrow and Escape Key Roles

When navigating MCP (protocol connecting AI to external tools) servers and plugins in the /mcp panel, the roles of arrow keys are now clearly divided. Up and down arrow keys strictly move vertically between individual servers and plugins, left and right arrow keys cycle through available actions for the selected item, and pressing Esc exits action mode or closes the panel. It is like navigating a TV menu: up and down keys switch channels, left and right keys adjust audio tracks or video quality, and pressing back cleanly returns to the previous level without accidentally jumping across unrelated fields.

Automatic Deduplication in `/agents` Picker Eliminates Duplicate Agents Across Sources

When contact books across different departments list the exact same person, a smart phone merges them into a single entry rather than cluttering your list with duplicate profiles. When you define agents (assistants that perform specific tasks) with identical names across multiple configuration sources or plugins, opening the /agents picker no longer shows distracting duplicates. Previously during discovery, finding an agent with the same name across different sources or plugins listed every instance in the picker; the menu now automatically deduplicates entries, keeping your selection list clean.

Tool and Agent Initialization Succeeds Even from Deleted Working Directories

Even if your temporary waypoint disappears under your feet while traveling, navigation continues smoothly as long as your guidebook records full global coordinates. Launching the command line from a working directory that has been deleted or is inaccessible will no longer cause tool initialization or agent startup to crash. Previously, parameter schemas held in memory lost relative references when the directory was invalid; switching fully to absolute URI schemes ensures all tools and agents initialize reliably regardless of directory state.

Headless CLI Invocations with Pipes Exit Cleanly Without Hanging

It is like workers shutting off the main water valve before leaving a construction site, ensuring pipes do not stay pressurized and stall subsequent inspections. When running automation scripts in headless mode (background execution without a visual interface) with piped standard output or standard error, invocations no longer hang on exit. Previously, spawned child processes kept the caller's pipes open and prevented the main process from shutting down cleanly; setting FD_CLOEXEC on preserved streams now ensures all pipe resources are fully released on exit.

Lenient `mcp_config.json` Parsing Supports Comments and Trailing Commas

When manually editing tool configurations, you no longer need to worry about quick notes or extra commas breaking your setup. Previously, adding single-line comments //, multi-line comments /* */, or trailing commas in mcp_config.json caused MCP (protocol connecting AI to external tools) configuration parsing to fail; the parser is now more forgiving and reads configurations containing comments and trailing commas smoothly. It is like an understanding form inspector who effortlessly processes notes in margins or accidental punctuation marks without rejecting the entire submission.

Deleting Conversations Thoroughly Cleans Up Orphaned Annotation Files

When clearing old conversations, your local disk space is now kept completely tidy. Previously, deleting a conversation removed the main chat but often left associated annotation files in local storage, gradually accumulating useless orphaned files over time; the deletion logic has been updated to automatically prune matching annotations alongside the conversation. It is like removing an old poster from a wall and scraping off the leftover adhesive tape around the edges, preventing stray scraps from piling up in corners.

Side Questions via `/btw` No Longer Force Goal Progress or Trigger Unintended Tools

While AI is actively working through a major project, you can now safely ask quick side questions without derailment. When running a long-term goal with /goal, asking a side question with /btw (by the way, a command for asking auxiliary questions) previously led to treating the tangent as part of the active goal, forcing unwanted progression and unintended tool calls; their execution states are now decoupled so side questions resolve your query without interrupting the main task. It is like asking a chef cooking an elaborate meal where the salt is: they answer and resume cooking immediately, rather than dumping the entire salt container into the soup.

/mcp 패널에서 MCP(AI가 외부 도구와 연동하기 위한 프로토콜) 서버와 플러그인을 고를 때 방향키의 역할이 명확하게 구분되었다. 상하 방향키는 서버 및 플러그인 항목 간 수직 이동만 담당하고, 좌우 방향키는 선택한 항목의 사용 가능한 동작을 순환 전환하며, Esc 키를 누르면 동작 모드를 빠져나오거나 패널을 닫을 수 있다. 이는 TV 메뉴를 조작할 때 상하 키로 채널을 고르고 좌우 키로 음성이나 화질 옵션을 전환하며 뒤로가기 버튼으로 깔끔하게 이전 단계로 돌아가는 것과 같아서, 잘못 눌러 엉뚱한 항목으로 튀는 일이 없다.

`/agents` 피커 자동 중복 제거, 여러 출처의 동일 에이전트 중복 표시 해소

여러 부서의 연락처에 동일 인물이 등록되어 있어도 스마트폰 주소록은 이를 하나로 합쳐서 보여줄 뿐 같은 사람을 목록에 줄줄이 늘어놓지 않는다. 여러 설정 소스나 플러그인에 같은 이름의 에이전트(agent, 특정 작업을 분담하는 비서)를 정의해 두었더라도 /agents 선택 메뉴를 열었을 때 중복 항목이 나타나지 않는다. 기존에는 탐색 과정에서 출처나 플러그인이 다른 동명 에이전트가 발견되면 피커 목록에 중복으로 나열되었으나, 이제는 자동으로 중복이 제거되어 깔끔한 목록을 유지한다.

작업 디렉터리가 삭제되어도 도구 및 에이전트 초기화 정상 작동

여행 중 발밑의 임시 표지판이 사라지더라도 수첩에 완전한 전역 좌표가 적혀 있으면 내비게이션이 문제없이 길을 안내하는 것과 같다. 삭제되었거나 접근할 수 없는 작업 디렉터리에서 명령줄을 실행하더라도 도구 초기화 및 에이전트 구동 과정이 비정상 종료되지 않는다. 기존에는 메모리 내 매개변수 스키마를 처리할 때 디렉터리 무효화로 인해 상대 경로 참조를 잃어버리는 문제가 있었으나, 절대 URI 스키마 방식을 전면 적용하여 어떤 디렉터리 상태에서도 도구와 에이전트가 안정적으로 초기화된다.

헤드리스 모드 파이프 출력 시 종료 지연 및 멈춤 현상 해결

현장 작업자가 퇴근할 때 수도 밸브를 확실히 잠가 배관에 물이 계속 흘러 후속 점검이 지연되지 않도록 조치하는 것과 같다. 자동화 스크립트를 작성하여 헤드리스 모드(headless, 시각적 화면이 없는 백그라운드 실행 모드)에서 표준 출력이나 표준 에러를 파이프로 전달받을 때 프로세스 종료 시 멈추는 현상이 사라졌다. 기존에는 백그라운드 자식 프로세스가 호출자의 파이프를 계속 점유하여 메인 프로그램이 제때 종료되지 못했으나, 유지되는 스트림에 FD_CLOEXEC 플래그를 설정하여 종료 시 모든 파이프 자원을 완전히 해제한다.

`mcp_config.json` 파싱 유연성 향상, 주석 및 후행 쉼표 허용

도구 설정 파일을 직접 편집할 때 가볍게 적어둔 메모나 실수로 남긴 쉼표 때문에 긴장할 필요가 없어졌다. 기존에는 mcp_config.json 파일에 한 줄 주석 //이나 여러 줄 주석 /* */, 또는 마지막 후행 쉼표가 포함되어 있으면 MCP(AI가 외부 도구와 연동하기 위한 프로토콜) 설정 파싱에 실패했으나, 파서의 오류 허용 범위가 넓어져 주석과 여분의 쉼표가 있어도 정상적으로 읽어 들인다. 이는 융통성 있는 서류 심사관과 같아서, 비고란 옆의 메모나 문장 끝에 잘못 찍힌 쉼표를 보고도 내용을 자연스럽게 파악하여 접수를 거부하지 않는 방식이다.

대화 삭제 시 고립된 주석 파일까지 완전히 정리

오래된 대화 기록을 정리할 때 로컬 디스크 공간이 깔끔하게 정돈된다. 기존에는 대화 기록을 삭제하면 메인 대화만 지워지고 연결된 주석 파일이 로컬 저장소에 그대로 남아 불필요한 고립 파일로 쌓이곤 했으나, 삭제 로직을 보완하여 대화를 지울 때 해당 주석 파일도 함께 자동 정리하도록 개선했다. 이는 벽에 붙은 낡은 포스터를 뗄 때 가장자리에 남은 양면테이프 자국까지 깨끗이 긁어내어 구석에 찌꺼기가 쌓이지 않게 만드는 것과 같다.

목표 실행 중 `/btw` 질문 시 작업 강제 진행 및 의도치 않은 도구 호출 방지

AI가 대규모 작업을 한창 진행하는 도중에도 안심하고 간단한 질문을 던질 수 있게 되었다. /goal 명령어로 장기 목표를 수행하는 도중 /btw(by the way, 다른 질문을 덧붙이는 명령어)로 중간에 질문했을 때, 기존에는 이 대화마저 목표의 일부로 오인하여 억지로 진행을 이어가거나 엉뚱한 도구를 호출하곤 했다. 이제는 두 상태가 완전히 분리되어 질문에는 답변만 제공하고 진행 중인 메인 작업을 전혀 방해하지 않는다. 이는 메인 요리에 집중하는 셰프에게 소금 위치를 물었을 때 셰프가 위치만 알려주고 곧바로 요리에 복귀하며, 국에 소금 한 통을 쏟아붓고 마구 젓지 않는 것과 같다.
