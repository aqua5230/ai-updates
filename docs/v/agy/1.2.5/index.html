Markdown 自訂代理自動注入子代理指引與名冊

在 Markdown 檔案中自訂專案 AI 代理時，現在能讓代理更聰明地分工協作。

好比連鎖餐廳為新進店長準備的交接手冊，只要職責包含調度人力，手冊第一頁就會自動附上當班員工名冊與各崗位指派流程，讓店長一接單就能精準把工作分派給專屬外場或廚房助手。

當你透過 Markdown 格式定義自訂代理，並在工具清單中列入 invoke_subagent 工具時，這項新增機制會自動在該代理的系統提示詞（給予 AI 底層角色的指令設定）中注入目前可用的子代理名冊與詳細使用指引。自訂代理現在能確實依據名單調度所宣告的子代理，不再因為缺乏使用說明而無法分工。

背景任務保留原始命名，通知與清單不再顯示通用代號

將耗時較長的繁重指令丟到背景執行時，隨時掌握各項進度變得更加直覺。以前當你把工作指派至背景執行時，系統往往會將任務名稱替換成自動產生的通用代號，讓人難以一眼辨認哪項工作已經跑完。現在系統改進了背景任務命名機制，任務被移至背景時會完整保留當初給定的專屬名稱。不論是終端機跳出的完成通知，或是隨時查詢的背景任務清單，現在都會清楚呈現原本的任務名稱，方便你精準對照各項作業。

恰如乾洗衣物送交櫃台送洗時，防塵套上始終保留你親筆寫下的送洗衣物標籤，取件通知與待洗清單上都清楚列出那是哪一套衣物，不再只標註一串冰冷隨機的收件流水號。

憑證遭拒時自動登出清除，暫時性網路故障保住工作階段

帳號權限變更或遇上網路波動時，登入狀態的管理現在更加精準可靠。

宛如飯店櫃台的房卡管理，當櫃台確認房客已正式退房結清時，讀卡機會主動清除房卡晶片裡的舊鑰匙以便重新配卡；但若是感應線路短暫繁忙或讀卡機反應延遲，系統絕不會隨意註銷仍在住宿期間的房客權限。

以前當企業帳號被撤銷或失效等情況發生，登入伺服器明確拒絕身分時，過期的登入憑證仍可能殘留在本機。現在命令列工具會自動將你登出並清除過期 token（授權令牌），讓你能乾淨重新登入。與此同時，若是遇上暫時性的網路連線失敗、伺服器錯誤或請求速率限制，系統也絕不會誤刪你的工作階段（session），確保作業不被中斷。

指令遭外部中斷正確標記取消，遠端工作階段同步顯示中斷提示

在終端機執行指令或多端連線操作時，取消與中斷狀態的紀錄現在更加準確。以前當執行中的指令受到外部信號終止（例如整個工作階段在指令運作中途關閉），系統會錯誤將其記錄為結束代碼 0 的成功執行。現在這類指令會正確標記為已取消，並完整保留中斷前所收集到的輸出紀錄。此外，過去只有在本機終端機按下 Esc 鍵時才會跳出 Interrupted 中斷提示，現在只要當前回合確實被取消，包括從已連線的遠端工作階段停止操作，畫面上都會如實顯示中斷提示。

這好比高鐵列車在行駛途中若因外部緊急訊號中途停靠，行車電腦會將該趟行程準確標註為中途取消並保留先前的行駛紀錄，駕駛座與遠端調度螢幕也都會同步亮起醒目的中斷提示燈號。

終端機視窗縮放自動重新折行，對話思考進度框不再卡死凍結

隨意縮放終端機視窗或重載對話時，畫面排版與狀態呈現變得更加順暢。以前在調整終端機視窗大小後，成品檢視器（展示生成檔案與程式碼的預覽介面）中的 Markdown 文字會卡在原始寬度無法自動換行。此外，對話歷史中進行中的思考進度框有時也會永久凍結，例如畫面永遠停留在 Thinking... (31s) 的狀態，即使縮放視窗或重新載入工作階段也無法恢復。現在這兩項介面顯示問題都已修好，文字內容會自動配合新的視窗尺寸重新折行排版，思考框也能如常更新進度。

彷彿電子書閱讀器在切換螢幕寬度時，文章內頁會即時配合新版面重新排版折行，正在載入的進度轉圈圖示也不會因為畫面縮放而卡死在螢幕上。

English

Automatic Subagent Guidance and Roster Injection for Markdown Custom Agents

When customizing project AI agents in Markdown files, agents can now collaborate and divide work more intelligently.

Just like an onboarding handbook prepared by a chain restaurant for a new store manager, where as long as their duties include scheduling staff, the first page automatically includes the on-duty staff roster and station assignment workflows, allowing the manager to accurately dispatch work to dedicated front-of-house staff or kitchen assistants upon receiving orders.

When you define custom agents in Markdown format and include the invoke_subagent tool in their tool list, this new mechanism automatically injects the currently available subagent roster and detailed usage guidance into that agent's system prompt. Custom agents can now reliably delegate to their declared subagents based on the roster, rather than failing to divide work due to missing instructions.

Background Tasks Retain Original Names in Notifications and Lists Instead of Displaying Generic Identifiers

Keeping track of progress is now much more intuitive when sending long-running, heavy commands to run in the background. Previously, when assigning work to run in the background, the system often replaced the task name with an auto-generated generic identifier, making it hard to tell at a glance which job had finished running. The background task naming mechanism has now been improved so that tasks fully retain their originally given custom names when moved to the background. Whether in completion notifications popping up in the terminal or in queryable background task lists, the original task name is now clearly displayed, allowing you to accurately cross-reference each operation.

Just like dropping off dry cleaning at the counter, where the garment bag always keeps the handwritten laundry tag you wrote, and both the pickup notification and pending laundry list clearly specify which outfit it is, rather than only labeling an impersonal, random receipt serial number.

Automatic Sign-Out and Cleanup on Rejected Credentials While Preserving Sessions During Transient Network Failures

Managing sign-in status during account permission changes or network fluctuations is now significantly more accurate and reliable.

Much like room key card management at a hotel front desk, where the card reader proactively clears old keys from the card chip for re-issuance once the front desk confirms a guest has officially checked out and settled their bill, but the system never arbitrarily cancels the access of an actively staying guest if the sensor line is briefly busy or the card reader responds slowly.

Previously, when situations like enterprise account revocations or invalidations occurred and the sign-in server definitively rejected the identity, stale sign-in credentials could still linger locally. The CLI tool now automatically signs you out and clears stale tokens so you can sign in again cleanly. Meanwhile, if transient network connection failures, server errors, or request rate limits occur, the system will never accidentally drop your session, ensuring operations remain uninterrupted.

Commands Terminated by External Signals Correctly Marked as Canceled with Remote Sessions Syncing Interruption Hints

Recording cancellation and interruption states is now more accurate when running commands in the terminal or operating across connected sessions. Previously, when a running command was terminated by an external signal (such as when the entire session shut down mid-run), the system erroneously recorded it as a successful execution with exit code 0. Such commands are now properly marked as canceled while fully preserving the output logs collected before the interruption. In addition, whereas the Interrupted hint previously only appeared when pressing the Esc key locally in the terminal, it now faithfully displays on screen whenever the current turn is actually canceled, including when stopped from a connected remote session.

This is like a high-speed train stopping mid-route due to an external emergency signal: the on-board computer accurately marks that trip as canceled mid-way and preserves prior driving logs, while prominent interruption warning lights illuminate synchronously across both the driver's console and the remote dispatch screen.

Terminal Resizing Automatically Re-wraps Text and Resolves Frozen In-Progress Thinking Frames

Layout and status presentation are now much smoother when freely resizing the terminal window or reloading conversations. Previously, after resizing the terminal window, Markdown text in the artifact viewer remained stuck at its original width without re-wrapping automatically. Furthermore, in-progress thinking frames in conversation history would sometimes freeze permanently—such as staying stuck forever at Thinking... (31s)—without recovering even after resizing the window or reloading the session. Both interface display issues are now resolved: text content automatically re-wraps to fit the new window dimensions, and thinking frames update progress normally.

Just as when switching screen widths on an e-reader, where article pages instantly reflow and re-wrap to match the new layout, and loading progress spinners do not freeze on screen due to screen resizing.
