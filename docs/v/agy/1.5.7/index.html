Antigravity 1.5.7

發布日期：2026-11-13

繁體中文

新功能

代理人預設改為自動模式，嚴格權限優先守護檔案修改

打開終端機請代理人處理工作時，若你還沒儲存過模式設定，啟動方式就會受這次調整影響。尚未儲存模式的工作階段，包含使用 -p 參數的無頭模式（沒有終端機畫面的執行模式），只要環境支援 Auto 就會預設自動啟動，其餘則維持 Default。

相機以前開機預設選一般模式，現在支援自動模式的機型會預設選自動模式，其餘仍選一般模式；改的是開機時先選哪個模式。

若想維持過去習慣，可在 /config 將 Agent Mode 選為 Default，設定會儲存到 settings.json：

{
  "agentMode": ""
}

另外，Tool Permission 的 strict 嚴格權限優先於 Auto 與 accept-edits 模式，修改檔案前依然會主動詢問並等待你同意。

問題修復

終端機長行折行不再卡住，工具群組重繪時步驟持續顯示

在終端機執行會印出大量記錄的指令或呼叫工具時，畫面有時會突然整面卡住。以前如果某個指令印出一整行完全沒有空格的超長字串，會直接引發數秒的介面凍結，連帶讓文字串流與視窗縮放跟著動彈不得。現在文字折行所花費的時間會與該行長度成正比，不再長時間卡死。另外，當一組輸出很長的工具呼叫正在以動畫跳動顯示記號（token，AI 處理文字的計算單位）數量時，代理人的回覆以前會停頓 20 秒以上。現在該工具群組重新繪製時，後續串流的執行步驟依然會持續顯示。以前遇到無空格長文字或工具輸出動畫會卡死畫面，現在介面縮放與步驟串流都能即時反應。

問題修復

背景指令等待密碼或確認提示時，代理人主動接收通知

交辦代理人跑耗時較長的工作時，你可能遇過整個流程突然無聲卡住。以前當移至背景的指令正在等待輸入，例如指令轉入背景前印出密碼或 y/n 確認提示，代理人不會察覺並只會靜默等待。現在只要輸出內容穩定下來，代理人就會收到通知，不再無聲乾等。現在輸出穩定下來後，代理人會收到等待輸入的通知，不再無聲乾等。

問題修復

Windows 版瀏覽器登入同時支援 IPv4 與 IPv6 回傳

在 Windows 系統透過瀏覽器進行帳號登入時，偶爾會碰上網頁跳轉後終端機卻沒有反應的狀況。以前指令列工具的本機登入回呼只監聽 IPv4 或 IPv6 其中一種協定，若瀏覽器透過另一種協定重新導向，登入就無法順利完成。現在本機回呼會同時監聽這兩種協定。以前登入容易因為網路協定不一致而卡在驗證畫面，現在瀏覽器重新導向後便能正常完成登入流程。

問題修復

企業閘道請求 Gemini 4 Carbon 調整參數，排除 HTTP 400 錯誤

當你在企業環境透過模型閘道使用 Gemini 4 Carbon 時，發送請求可能曾遇到連線失敗。以前請求會跳出 HTTP 400 錯誤，提示 Thinking budget is not supported for this model。現在指令列工具會改向 Gemini 4 Carbon 發送思考層級（thinking level），發給閘道的模型識別碼也不再殘留 Low、Medium 或 High 後綴。以前發送請求會被閘道直接退回，現在格式修正後便能正常呼叫。

問題修復

企業安全政策強化審核機制，並恢復無系統沙盒時的自訂規則

在受組織管理政策管制的環境下執行指令或存取檔案時，審核機制迎來了兩項修正。以前若設定了回傳 auto_approve 的 PreToolUse 掛鉤（特定事件發生時被觸發的小程式），或使用 command(*) 萬用允許規則，會意外略過管理員強制要求的審查。現在跳脫終端機沙盒的指令、管理員政策保留審查的指令，以及「一律詢問」政策下讀寫工作區外的操作，一律會向你要求確認。當組織政策要求在終端機沙盒內執行指令，但電腦缺少系統沙盒時，以前會忽略已儲存的允許與拒絕規則，導致每條指令都反覆跳出確認。現在儲存的允許與拒絕規則會正常套用，未列出的指令執行前仍會詢問。以前容易因規則漏洞略過公司審核，或在缺少系統沙盒時被繁瑣提示打擾，現在審查嚴謹且自訂名單正常生效。

問題修復

檢視背景任務詳情時，保留程式碼區塊與反引號格式

當你透過 manage_task 工具查看背景任務的執行狀態時，文字排版可能曾出現錯亂。以前如果任務近期的輸出內容，或是傳送給任務的輸入包含 Markdown 程式碼區塊或連續反引號，任務詳情的排版格式會跑版損毀。這個問題現在已經修好，相關內容會完整保留原有排版。以前閱讀包含程式碼的任務資訊容易版面混亂，現在都能維持工整外觀。

問題修復

遠端操控介面隱藏無效連結，不再顯示無法開啟的網址

使用遠端操控（Remote Control）功能查看代理人回覆時，結尾可能曾出現點不開的連結。以前在部分回覆末端，例如多代理人群組協調員（swarm coordinator）連往群組介面的連結，遠端操控會顯示無法開啟的網址。現在遠端操控會直接略過這些連結。以前在遠端介面常看見無法點擊的網址，現在遠端操控會略過這些無法開啟的連結。

English

FEATURE

Agent defaults to Auto mode while strict permissions protect file edits

When you open the terminal to ask the agent to handle work, if you have not saved a mode setting yet, how it starts is affected by this change. Sessions with no saved mode, including headless mode (an execution mode without a terminal screen) using the -p flag, now start in Auto by default wherever Auto is supported, while the rest stay in Default.

A camera used to select normal mode by default at startup, and now models that support auto mode select auto mode by default while the rest still select normal mode; what changed is which mode is selected at power-on.

To keep the previous behavior, you can set Agent Mode to Default in /config, which saves the setting to settings.json:

{
  "agentMode": ""
}

In addition, strict under Tool Permission takes precedence over Auto and accept-edits modes, so it still asks and waits for your approval before editing files.

BUGFIX

Terminal line wrapping stops freezing and steps keep streaming during tool group redraws

When running commands that print large logs or calling tools in the terminal, the screen could sometimes freeze all at once. Previously, if a command printed a very long line with no spaces at all, it triggered multi-second UI freezes that also stalled text streaming and window resizing. Line wrapping now takes time proportional to the line's length instead of locking up for seconds. Also, while a group of tool calls with long output was animating its token (the unit AI uses to process text) counts, agent replies used to stall for 20 seconds or more. Now, streamed execution steps continue to appear while that tool group re-renders. Where long spaceless text or tool output animations used to freeze the screen, window resizing and step streaming now respond immediately.

BUGFIX

Agent receives notifications when background commands wait for passwords or prompts

When you ask the agent to run a long-running task, you may have seen the whole process suddenly stall in silence. Previously, when a command moved to the background was waiting for input, such as a password or y/n confirmation prompt printed before going to the background, the agent did not notice and just waited silently. Now, once the output settles, the agent receives a notification instead of waiting silently. Once the output settles, the agent is now notified that input is needed rather than waiting in silence.

BUGFIX

Windows browser sign-in supports both IPv4 and IPv6 callbacks

When signing in through a browser on Windows, the terminal would occasionally not respond after the web page redirected. Previously, the CLI's local sign-in callback listened on only IPv4 or IPv6, so if the browser redirected over the other protocol, sign-in could not complete. Now, the local callback listens on both protocols. Sign-in used to get stuck on the verification screen due to protocol mismatches, and now it completes normally after the browser redirects.

BUGFIX

Enterprise gateway requests to Gemini 4 Carbon adjust parameters to prevent HTTP 400 errors

When using Gemini 4 Carbon through a model gateway in an enterprise environment, your requests may have failed to connect. Previously, requests returned an HTTP 400 error with the message Thinking budget is not supported for this model. Now, the CLI sends a thinking level to Gemini 4 Carbon instead, and the model ID sent to the gateway no longer retains a Low, Medium, or High suffix. Requests that used to be rejected directly by the gateway now succeed with the corrected format.

BUGFIX

Enterprise security policies tighten review checks and restore custom rules without an OS sandbox

When running commands or accessing files under organization-managed policies, two fixes have been made to the review mechanism. Previously, a PreToolUse hook (a small program triggered by specific events) returning auto_approve, or a wildcard command(*) allow rule, could accidentally bypass admin-enforced reviews. Now, commands that leave the terminal sandbox, commands held for review by admin policy, and file reads or writes outside the workspace under an "always ask" policy always ask for your approval. When an organization policy requires commands to run inside a terminal sandbox but the machine lacks an OS sandbox, saved allow and deny rules used to be ignored, causing every command to prompt repeatedly. Now, saved allow and deny rules apply normally, while unlisted commands still ask before running. Instead of rule gaps bypassing company reviews or missing OS sandboxes triggering repetitive prompts, reviews are now enforced and custom lists work as expected.

BUGFIX

Background task details preserve code blocks and backtick formatting

When checking a background task's status with the manage_task tool, the text formatting may have been garbled. Previously, if the task's recent output or input sent to the task contained Markdown code blocks or runs of backticks, the task details formatting broke. This issue is now fixed, and the content preserves its original formatting. Where reading task details with code used to look messy, everything now stays cleanly formatted.

BUGFIX

Remote Control hides broken links instead of showing unopenable URLs

When viewing agent replies with Remote Control, unclickable links could sometimes appear at the end. Previously, at the end of some replies, such as a swarm coordinator's link to the swarm UI, Remote Control showed URLs that could not be opened. Remote Control now omits these links. Where unclickable URLs used to show up in the remote interface, Remote Control now skips these unopenable links.
