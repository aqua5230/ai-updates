Antigravity 1.1.11

Released: 2026-08-07

Release notes

FEATURE

Vim editing comes to the prompt

If arrow keys keep breaking your flow while writing a prompt, open /settings, choose Editor Mode, and turn on the off-by-default Vim editing mode.

Vim splits keyboard editing into modes: the prompt now has Normal, Insert, Visual, and Visual Line modes, with a status-line badge. Move with h/j/k/l, or delete, change, and copy with d, c, and y. To keep Vim editing while submitting normally, enable Editor Mode > Insert First: the prompt starts in Insert mode, bare Enter submits, and shift+enter or ctrl+j adds a line. In Normal mode, use ctrl+s or ctrl+enter to submit. Comment boxes in diff and artifact-detail views get the same treatment; a collapsed block moves as one unit. It is like shifting into a familiar gearbox before steering through text.

FEATURE

Print mode stops pretending a command ran

When a script needs account status but not a conversation, print mode can now answer read-only slash commands directly.

-p "/usage", /quota, /credits, /model, /effort, and /skills emit one tab-separated record per line, or structured data with --output-format json or stream-json. No agent turn starts, no quota is spent, and no conversation is left behind. The reverse is now honest too: interactive-only commands such as /clear fail and name the flag or subcommand to use instead. Before, /clear could become ordinary prompt text and the model might claim the context was cleared when nothing happened. It is like a self-service counter that prints available records and points unavailable services to the right desk.

FEATURE

Plugins keep their enabled state through updates

An enabled plugin should not vanish just because its author ships an update.

Plugin enablement now lives only in config.json; the plugin manifest, the file describing a plugin and its defaults, is used once to seed the initial state. If a later release changes its default to "disabled": true, it cannot turn off a plugin you already use. Nor can a default change from off to on move every user's preference at the next update. It is like each apartment keeping its own door lock: the builder supplies a default key at move-in, but later notices from the building do not turn your lock.

FEATURE

Code stays visible and errors say what is wrong

A long line of code clipped at the right edge is frustrating because you cannot tell what you missed.

Artifact detail now wraps long lines in code files instead of cutting them off. When a rate limit or overload calls for a model retry, the client also waits for the delay supplied by the server rather than guessing its own backoff. It is like a server sending a wait-time ticket, and the client retrying only after that time elapses. Another vague failure now gets a name too. Missing a license or IAM role, a role that cloud services use to grant permissions, is shown as a permission failure with a link for troubleshooting, not disguised as a generic run failure.

BUGFIX

Strict permission mode cannot be bypassed by bad allowlists

If you choose request-review or strict permission mode, you expect each command to stay reviewable; an empty-looking allowlist entry should not stamp every command approved.

Entries such as command(time), a comment alone, or empty () tokenize to zero command words, yet once matched everything and silently approved it. They now match nothing, and commands are no longer auto-approved in either review mode. Administrative controls for MCP servers, a protocol that lets AI connect to external tools, also survive startup: a pre-authentication fetch can no longer cache “not applicable” for five minutes and let every server through. The built-in Chrome DevTools MCP server is no longer blocked outright by those controls. It is like a blank address at a post office: it does not automatically send every letter; the real sorting rules still check the destination, and only permitted mail is delivered.

BUGFIX

Pastes, autocomplete, and tool progress stay intact

When you paste a large block as an argument to a slash command, the command needs the text, not merely the [Pasted text #N] label.

It now receives the actual pasted content. After you submit an autocompleted slash command, history stores the complete command name that actually ran, so up-arrow recall does not replay only the prefix you first typed. An alias also needs an exact match before it auto-executes; a partial alias stays in the prompt for you to finish. On the other end, long-running MCP tool calls, where AI connects to external tools through a protocol, report progress again and initialize a task log. It is like a shipment that now carries the real attachment, its receipt, and live tracking rather than an attachment-number sticker.

BUGFIX

Print mode stays quiet and credit checks stop crying zero

When automation runs in print mode, a feedback survey that was turned off no longer springs back on because settings refresh asynchronously.

And if a credit lookup receives an empty response, it no longer treats that absence as a zero balance and shouts “Out of credits.” It is like an account fax missing a page: the app now recognizes missing information rather than declaring the account empty. One misleading switch is also gone. Accounts signed in through a Google Cloud project or application default credentials, login proof a cloud application obtains automatically, no longer see the inapplicable “Use AI Credits” setting. The screen keeps switches you can actually use, not a button that cannot take effect.

Original changelogVim editing comes to the prompt
Added a Vim editing mode, off by default and switched on from `/settings` under `Editor Mode`, bringing modal editing to the prompt with Normal, Insert, Visual and Visual Line modes, a mode badge in the status line and a Vim tab in `/help`, and covering the `h`/`j`/`k`/`l`, `w`/`b`/`e` and `W`/`B`/`E` motions, the `0`/`^`/`$`/`gg`/`G` boundaries, the `f`/`F`/`t`/`T` character searches with their `;` and `,` repeats, the `i`/`a`/`I`/`A` insert entries, the `d`/`c`/`y` operators alongside `x`, `D` and `C` filling the unnamed register for `p`, and the `iw`/`aw`/`iW`/`aW`/`ip`/`ap` text objects.
Added Vim-aware submission so a prompt can be sent without leaving modal editing, through an `Editor Mode > Insert First` toggle that opens the prompt in Insert mode where a bare `Enter` submits and a modified key such as `shift+enter` or `ctrl+j` inserts a newline, `ctrl+s` and `ctrl+enter` keys that submit from Normal mode, an `Enter` binding available as `vim.insert.submit`, and the full set of `vim.*` scopes in `keybindings.json` for remapping any of it.
Added Vim editing to the comment editors in the diff and artifact-detail views, whose footer hints follow the active mode rather than showing one fixed set of bindings, and made a collapsed block behave as a single unit under Vim motions.
