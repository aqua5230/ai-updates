Antigravity 1.5.14

Released: 2026-11-21

Release notes

FEATURE

Stream /thinking live in real time

Curious how the AI reasons step by step before giving an answer? Run /thinking on to stream the model's full thinking live in the transcript while it thinks, or /thinking off to turn it off. Finished thoughts stay expanded without pressing Ctrl+O. This setting is saved as "showThinking" in settings.json and is off by default.

Picture a math class watching a teacher work on the blackboard: previously only the final answer was written up and you had to check your notes for the steps, but now every step stays right on the board whenever you look up.
FEATURE

Add Overview section to /swarm board

When dispatching a group of agents to work on a project in parallel, opening /swarm board in a terminal at least 28 rows tall now shows a live Overview section. It displays the overall goal and task progress in the format Overview · N of M tasks done, along with any blocked count. Below that, up to six workstream threads use status indicators to show whether each background worker is working, in review, waiting on a peer, failed, or done.

A departure board in a train station concourse works the same way: instead of checking progress car by car, you can look up at one summary table to see how many trains are on time, delayed, or stuck on the tracks.
FEATURE

Add plan mode to --remote-agent

If you want to review a remote agent's plan before it edits files or runs commands, --remote-agent sessions now include plan mode. The agent can research and write a plan for your review before making changes or running commands. Press Shift+Tab to switch modes for the current session without changing your saved default, start with --mode plan to enter plan mode right away, or pass --mode when resuming a conversation to override its saved setting. Adjusting Agent Mode (default, accept-edits, plan) on the Remote Agent tab of /config updates the current conversation immediately and saves it as the default for new remote sessions.

Think of taking clothes to a tailor: you can ask them to mark the alterations in chalk first so you can see how they plan to change the fit.
FEATURE

Add RTL direction button to Remote Control file tabs

When viewing notes or plain text files in the Remote Control browser view, right-to-left prose starting with an English word used to snap unexpectedly to left alignment. Now the header of .md, .markdown, and .txt tabs includes a Switch to RTL text direction button so right-to-left text renders cleanly, while code blocks and line numbers stay left-to-right.

Suppose you write a right-to-left letter that includes an English address: previously the whole line got pulled to the left with the English text, whereas pressing the toggle keeps the body aligned cleanly on the right while only the address and numbers read from the left.
FEATURE

Configure both Orchestrator models in /model

On consumer plans in local sessions, opening /model lets you pick both the Planner and Executor models on the Orchestrator row and adjust each one's thinking Effort. Press Tab or Shift+Tab to move between Planner, Executor, and their Effort sliders, then use ← and → to change the selected choice. Your selection is saved under "orchestrator" in settings.json and --settings. The status line (the live bar at the bottom of the terminal) also shows the active planner model next to Orchestrator.

To get the most out of a two-person rowing race, you previously had to row with whatever pairing the organizers assigned; now you can pick who steers the course and who pulls the oars, and even tune how much power each one puts in.
FEATURE

Keep colors and indentation in expanded medium tool groups

When expanding collapsed items in medium verbosity with Ctrl+O or by clicking, the summary header previously dimmed to gray—even red status markers on failed runs. Now the summary header row keeps its original colors, and expanded tool calls are indented behind a │ gutter.

FEATURE

Suggest project folders for outside-workspace prompts on web

When asking an agent to create or edit a file outside the workspace in the Remote Control browser view, permission prompts now offer a broader "always allow" suggestion. They suggest the enclosing repository or project folder first, or the parent folder when there is none, instead of approving only one file at a time. However, sensitive files such as .env or SSH keys and broad folders such as your home directory or /tmp remain limited to that single file. Editing the target path in the prompt also overrides the suggested scope.

When borrowing a room at school for an event, you previously had to sign a separate slip for every microphone; now you are offered the whole club equipment room at once, except for valuables in the safe that still require individual sign-off.
FEATURE

Collapse consecutive subagent launches in browser view

When viewing a conversation in the Remote Control browser view, consecutive subagent launches within a single turn are no longer listed one by one. Adjacent launches collapse into a single Started N subagents row—or Starting N subagents while launching—that you can expand to view and open each subagent.

FEATURE

Allow Auto mode to read outside workspace without asking

When running tasks in the default Agent Mode (Auto mode), viewing files outside the current project folder previously triggered a confirmation prompt unless you enabled Non-Workspace Access in /config. Auto mode now reads files outside the workspace directly without asking. Not all restrictions are lifted, though—writing or editing files outside the workspace still requires your approval. Your ask and deny permission rules, protected config files such as mcp_config.json, other projects' conversations, and organization policies requiring outside-workspace file review all still apply.

Consider borrowing reference books from a neighbor's study: previously you had to ask the owner just to open a book and glance at it, whereas now you can read freely, though picking up a pen to edit the text still requires asking first.
BUGFIX

Fix Windows credential leak via special paths

On Windows, UNC network, device, and NT object paths in workspace permission rules, @ file mentions, plugins, sidecars.json, and custom agents previously posed a security risk. Those paths could trigger a lookup that sent Windows login credentials to a remote host, and are now rejected without being accessed.

BUGFIX

Fix interrupted responses running partial tools and failing validation

When a model response errored out, was canceled, or got cut off partway through, partial tool calls in the incomplete response could still run. Retrying could also resend that broken attempt, causing thinking-signature validation errors in later turns; both issues are now fixed.

BUGFIX

Fix wide table headers and mid-word breaks on narrow terminals

When viewing wide Markdown tables from agent responses on narrow terminals, column headers used to get cut off with … and text columns were squeezed until words broke mid-word. This layout issue is fixed: headers now wrap properly, and column widths keep whole words intact while only breaking long paths and URLs.

BUGFIX

Fix plugin $schema listing errors and name truncation

When a plugin's plugin.json declared an Agent Plugins $schema, /plugin, agy plugin list, agy plugin enable, and agy plugin install used to list the wrong items. Skills, subagents, MCP (a protocol that lets AI connect to external tools) servers, and hooks were all listed incorrectly, such as reading mcp_config.json instead of mcp.json. The bug that misreported hooks.json as hooks (small programs triggered by specific events) named $schema and hooks is now fixed. The agy plugin install summary cutting off subagent names at . is also resolved.

BUGFIX

Fix marketplace plugin install failures and sign-in prompts

When connecting with GEMINI_API_KEY instead of a saved sign-in, running agy plugin install <plugin>@<marketplace> used to fail with an unknown marketplace error. This installation failure is now fixed. When an agent suggested a plugin in its response, it used to include a raw marketplace ID and say The <id> plugin needs you to sign in. Open /plugin to sign in. even if the plugin was not installed. That prompt now reads Open /plugin to install or sign in to this plugin..

BUGFIX

Fix persistent red out-of-credits warning at zero balance

When AI credits were enabled and your credit balance was 0, the status line used to keep showing a red AI: Out of credits warning even while normal model quota was still available. This is now fixed, and the status line only shows AI credits when your balance is greater than 0.

BUGFIX

Fix remote agents listing unsupported local models

When choosing a model with /model in a --remote-agent session, the list used to include options that could not actually run, and picking one threw a confusing error. Now /model labels models unsupported by remote agents as not available for remote agents and omits local custom models. If you send a request with an unsupported model, it now clearly reports this error message:

<model> isn't available for remote conversations yet. Choose another model and try again.
BUGFIX

Fix Esc failing to cancel sends and breaking follow-up messages

Right after submitting a message, while esc to cancel was already shown during pre-send checks, pressing Esc used to fail to stop the send and still ran a full agent turn. Pressing Esc in that window now aborts the send and displays Message not sent: canceled before it was sent. Pressing Esc to cancel while the previous turn was still tearing down used to clear the Interrupted status hint, and an immediate follow-up message would be rejected with executor has not processed the previous input yet. The Interrupted hint now stays visible, and follow-up messages queue until cancellation finishes.

BUGFIX

Fix timed-out or canceled command hooks leaving background processes

When external commands were triggered via hooks.json on Linux and macOS, child processes used to keep running in the background if the hook was canceled mid-run or timed out. This is now fixed, and stopping a command hook terminates its entire process group.

BUGFIX

Fix workflow scripts failing on trailing return statements

When run_workflow ran a Python workflow script ending with a top-level return, it used to fail with workflow syntax error: 'return' outside function. Now a trailing return is evaluated directly as the workflow's result.

BUGFIX

Fix browser Stop and Send Now losing message drafts

In the Remote Control browser view, pressing Stop right after submitting a follow-up message before it finished sending used to drop the entire message. It is now returned to the message box along with its @ mentions, attachments, and review comments, placed after any new text you started typing. Clicking Send Now on a queued message used to clear or overwrite any in-progress draft, attachments, or review comments in the message box. All of those are now preserved, and multiple Send Now clicks are sent in order.

BUGFIX

Fix Comment Count Bugs on Non-Markdown Artifacts

Adding inline comments to code or other non-Markdown artifacts in the side panel of the Remote Control browser view previously caused display and submission errors. The comment count on the Review button stayed at zero, the sidebar and Overview Panel were also missing comment-count badges, and clicking Proceed split them into separate pills. These issues are now fixed.

BUGFIX

Fix iPhone Browser Message Box Alignment

When sending messages in the Remote Control browser view on an iPhone, the message box previously either slid behind the on-screen keyboard or floated in mid-air with a blank gap. This misalignment with the on-screen keyboard is now fixed in conversations, on the home screen, and in side-panel drawers such as subagent tabs.
