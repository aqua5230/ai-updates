Antigravity 1.1.16

發布日期：2026-08-20

zh-TW

MCP 伺服器可用子命令管理

要替 AI 接上外部工具時，MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器設定不必再手改 mcp_config.json。你可用 mcp add、mcp remove、mcp list、mcp enable、mcp disable 管理使用者層級的伺服器，並透過 --type、--env、--header 處理 stdio 與 HTTP 類型。像替配電箱的每個開關貼好標籤；要新增、移除、查看、開啟或停用，都直接操作對應開關，不必拆開牆面重接電線。

`/mcp` 啟停伺服器時保留設定欄位

在 /mcp 面板啟停伺服器時，先前可能讓 mcp_config.json 裡的 enabledTools、timeoutSeconds、url、tools.eager 消失。現在面板編輯時會保留它們，也會保留新版客戶端寫入而它還不認得的欄位。像文書人員更新表格時，只改你指定的勾選欄，不會抹掉其他已填好的資料；連暫時看不懂的新欄位也原樣留下。 因此，較新客戶端寫下的設定經過面板啟停後仍能存活。

大型工作區找檔更快，也會略過忽略清單

專案很大時，在提示列輸入 @ 找檔不必再看著結果慢慢跟上。查找改由內建的 ripgrep 執行，並會等你按鍵停下再查；檔名正好符合查詢的檔案，也會排在只是包含它的資料夾或產生檔之前。這像在倉庫喊出物品名稱，管理員先等你講完，再把標籤完全相同的箱子遞到最前面。而且 .antigravityignore 已列出的檔案不會再出現在 @ 路徑補全裡。

Gemini API Key 也能調推理力度，窄終端機不再擠字

用 Gemini API key 登入後，Gemini 3.6 Flash 與 Gemini 3.7 Flash 終於能用 /effort 調整 reasoning effort（推理力度，模型回答前投入多少思考）。這條登入路徑以前誤說兩個模型不能調，其他登入方式卻早已可調。挑選 /effort 或 /model 時，窄終端機裡時間軸量表下方的推理力度說明若放不下，現在會省略，讓量表保持可讀。旋鈕原本鎖住又貼滿擠在一起的說明，現在能轉動，讀數也看得清楚。

不支援 OSC 8 時，連結不再印出控制碼

若你用的終端機不支援 OSC 8 超連結，例如 Terminal.app，畫面不會再把控制碼原樣印成文字。這類終端機原本無法解讀控制碼，會把它照字面顯示；現在程式先偵測支援情況，避免送出這些控制碼。偵測也延伸到指令輸出與提醒訊息，兩處以前仍不管終端機是否支援就送出超連結。像印刷廠發現讀者沒有隱形墨水閱讀器，便改印可讀文字，不會讓一串標記留在紙上。現在三處都會先辨識是否能處理 OSC 8。

不支援 Kitty 鍵盤協定時，提示列不再累積等號

終端機不支援 Kitty 鍵盤協定（讓終端機辨識鍵盤輸入方式）時，提示列不會再每隔幾秒多出一個 =。原本 renderer（負責畫面顯示的程式部分）會定期重新啟用該協定，但終端機沒有把控制訊號當作協定內容解讀，反而把它印成文字。像每隔幾秒替教室重設投影機的控制訊號，沒有被機器接收，反而一遍遍寫到白板上。現在不支援時，重新啟用協定不會留下等號。

產物檔名有空格時，清單、預覽與標題終於一致

你打開名稱含空格的產物時，清單列、內嵌預覽與詳細標題現在會寫同一個檔名。以前它可能顯示 quarterly%20plan.md，把空格寫成百分比跳脫字元，讀起來像另一個檔案。這像同一部電影在片頭、海報與節目單各處，都一致使用真正的片名。名稱中的空格會正常顯示。因此從清單點進預覽或詳細頁，不必猜眼前的名稱是不是同一份產物。

文字換行後，提示列游標不再走錯位置

在提示列輸入較長文字、內容換到下一行後，游標現在會留在正確位置。先前編輯器算錯換行後的座標，游標看起來可能指著一處，實際插入文字卻落在另一處。像用尺在折過的紙上量位置，折線以前讓刻度接不上；現在尺會沿著紙面繼續量。這在反覆修改長句時尤其容易察覺，也不再誤導你。你在長提示中移動、補字或刪字時，眼睛看到的位置便能對上正在編輯的位置。

MCP 讀取 PDF、音訊等二進位資源不再被丟掉

MCP 伺服器回傳 PDF、音訊或其他非圖片二進位內容時，read_resource 不會再悄悄把它們丟掉。現在每個 blob 都會先卸到磁碟，只有小型文字與圖片資源會直接嵌進回應。像博物館先把每件藏品放進庫房，展板只嵌小幅文字與圖片；大件也不會因此被丟棄。因此大型 PDF、音訊與其他二進位資源能被使用，而非在讀取途中消失。

Workforce Identity Federation 登入不再頻繁失效

使用 Workforce Identity Federation 登入時，不會再因為更新 token（授權令牌，證明登入仍有效的憑據）走錯端點而被登出。問題原本出在更新程序跑到標準登入端點，而不是聯邦登入端點，導致登入狀態大約每小時反覆失效。這像門禁證定時換發有效印章，更新資料卻送到另一棟大樓的發卡機；現在它會送回對應的機器。你用這種聯邦身分登入後，更新授權令牌會留在正確的登入流程中。

內建 skills 會被正確標示與分組

查看 /skills 時，隨 CLI 一起提供的 skills 現在會正確被認成內建項目。以前它們被誤報為非內建，導致 --output-format json 的 builtin 旗標不正確，/skills 面板分組也跟著放錯。像店裡自有品牌商品被貼成外來寄賣品，貨架自然擺錯區；現在標籤與貨架都回到正確位置。若你用 JSON 輸出供其他工具讀取，或直接在面板瀏覽，兩種呈現會對上。

自訂或 SDK 代理也能問 /btw，失敗會顯示真實錯誤

對話進行到一半想岔問一件小事時，/btw 不再因為你正在使用自訂或 SDK 定義的 agent（代理，代替你執行特定任務的 AI 設定）而報 planner 設定錯誤。側問可在任何正在執行的 agent 下運作。若側問本身失敗，畫面也不會一律猜成 model returned an empty response；有自己的錯誤時，會顯示那個錯誤。像問診單可交給不同科別的醫師處理，不會因身分欄位不同退回；若檢查失敗，報告會寫真正的異常。

已完成背景任務不再留在進行中清單

背景任務做完後，狀態列、active-items 清單與 /tasks 面板不會再繼續把它當成進行中。過去任務明明結束，三個位置的資訊卻沒有同步移除，容易讓人以為還要等待。像火車已到站，月台看板卻仍寫著行駛中；現在三塊看板會一同更新。你查看狀態列、active-items 或 /tasks 時，看到的會是仍在背景執行的任務。

壞掉的 settings.json 不會再被預設值覆蓋

如果 settings.json 因格式錯誤而無法解析，CLI 現在拒絕儲存，卻不會把它覆蓋成預設設定。以前只要之後有任何內容被儲存，所有原有設定都可能被默默還原；現在拒絕儲存時，檔案會維持逐位元組相同，狀態列也會點名是哪個檔案。像發現契約有一頁看不懂時，櫃台不再把整份換成空白範本，而是原封放回去讓你手動修好。原有內容不會被抹掉。

父代理沒指定模型時，inherit 子代理仍能啟動

你把子代理的 model 留成 inherit 時，即使父代理本身沒有模型，子代理現在仍能開始工作。舊行為會在啟動時失敗，因為它沒有可繼承的模型。現在會改用預設的快速層級。像接力隊找不到前一棒交來的棒子，不會整隊停在起跑線，而是拿起備用接力棒繼續跑。因此 inherit 的意思仍優先沿用父代理；父代理沒有模型時，才落到預設快速層級。

en

Manage MCP servers with subcommands

When you connect AI to outside tools, MCP (a protocol for connecting AI to external tools) server settings no longer require hand-editing mcp_config.json. Use mcp add, mcp remove, mcp list, mcp enable, and mcp disable for user-level servers; --type, --env, and --header cover stdio and HTTP. It is like labelling every breaker in a panel: add, remove, inspect, enable, or disable a connection at its switch rather than opening a wall to rewire it.

`/mcp` retains configuration fields when toggling servers

When you toggle a server in the /mcp panel, it previously could drop enabledTools, timeoutSeconds, url, and tools.eager from mcp_config.json. The panel now retains them during an edit and also keeps fields written by a newer client that it does not recognize. It is like a clerk updating a form by changing only the box you named, not erasing other completed fields; even a new field the clerk cannot yet read stays untouched. Settings written by a newer client therefore survive a toggle in the panel.

File search is faster in large workspaces and respects ignore rules

In a large project, typing @ to find a file no longer means watching results struggle to catch up. Lookup now uses bundled ripgrep and waits for your keystrokes to pause; an exact filename ranks above a directory or generated artifact that merely contains the query. It is like calling an item name in a warehouse: the clerk waits until you finish speaking, then brings the exactly labelled box to the front. Files listed in .antigravityignore also stop appearing in @ path completion.

Gemini API keys can tune reasoning effort, without cramped picker text

After signing in with a Gemini API key, Gemini 3.6 Flash and Gemini 3.7 Flash can finally have their reasoning effort adjusted with /effort—how much thought a model uses before answering. That sign-in route had wrongly called them unadjustable while other routes allowed it. In narrow terminals, the reasoning-effort description beneath the timeline gauge in /effort and /model is now omitted when it would overflow, keeping the gauge readable. A dial that was locked and crowded by its label can now turn, and its reading remains visible.

Unsupported OSC 8 terminals no longer print raw link controls

If your terminal lacks OSC 8 hyperlinks, such as Terminal.app, control sequences no longer print as literal text. Such terminals originally could not interpret control sequences and displayed them literally; the program now checks support first to avoid sending them. Detection now also covers command output and alert bodies, which had still emitted hyperlinks regardless of support. It is like a printer finding that readers lack an invisible-ink viewer, then using readable ink instead of leaving markings on the page. All three places now check whether OSC 8 can be handled first.

Unsupported Kitty keyboard protocol no longer adds equals signs to prompts

On a terminal without the Kitty keyboard protocol—the way a terminal interprets keyboard input—the prompt no longer gains a = every couple of seconds. The renderer, the part that draws the display, periodically re-armed the protocol, but the terminal printed that control signal as text instead of interpreting it. It is like resetting a classroom projector every few seconds when its control signal is not received and is written onto the whiteboard instead. Re-arming no longer leaves equals signs on unsupported terminals.

Artifact names with spaces now match in list, preview, and header

When an artifact name contains a space, its list row, inline preview, and detail header now spell it the same way. It could previously appear as quarterly%20plan.md, replacing the space with a percent-escape and making it look like another file. It is like one film using its real title in the opening credits, poster, and programme. Moving from list to preview or detail no longer makes you wonder whether it is the same artifact.

Prompt cursor stays aligned after text wraps

After long text wraps in the prompt editor, the cursor now stays in the right place. The editor had miscalculated positions after a wrap, so the cursor could point at one spot while inserted text landed elsewhere. It is like measuring a folded sheet with a ruler: the fold once broke the scale, but now the ruler continues along the paper. When you move, add, or delete text in a long prompt, the visible position matches the edit position.

MCP can now keep PDFs, audio, and other binary resources

When an MCP server returns a PDF, audio file, or other non-image binary content, read_resource no longer silently drops it. Every blob is now offloaded to disk, while only small text and image resources are inlined in the response. It is like a museum placing every object in storage, while its display board embeds only small text and images; larger pieces are not discarded. Large PDFs, audio, and other binary resources remain usable instead of disappearing during reading.

Workforce Identity Federation sign-in stops expiring unexpectedly

With Workforce Identity Federation sign-in, refreshing a token—the credential that keeps a login valid—no longer sends you out through the wrong endpoint. The refresh had gone to the standard sign-in endpoint instead of the federated one, repeatedly invalidating the session roughly every hour. It is like sending a badge for its scheduled validity stamp to the issuing machine in another building; now it returns to the matching machine. Token refresh remains in the correct federated sign-in flow.

Built-in skills are now labelled and grouped correctly

In /skills, skills shipped with the CLI are now correctly identified as built in. They had been reported as not built in, making the builtin flag in --output-format json wrong and placing them in the wrong /skills panel group. It is like a store's own-brand goods being labelled as consignment stock, then shelved in the wrong aisle; labels and shelves now match. JSON output for other tools and the panel view now agree.

Custom and SDK agents can use /btw, with real failure messages

When a small side question occurs to you mid-conversation, /btw no longer fails with a planner configuration error because you are using a custom or SDK-defined agent—an AI setup that performs a particular task for you. Side questions work with whichever agent is running. If one fails, the card no longer blindly says model returned an empty response; when there is its own error, that error is shown. It is like a medical form being handled by doctors in different specialties without being returned for its identity field; if an examination fails, its report gives the real abnormality.

Finished background tasks no longer linger as active

After a background task finishes, the status line, active-items list, and /tasks panel no longer keep calling it active. A task could already be done while all three views failed to remove it, making you think you still had to wait. It is like a train reaching its station while the platform board still says in transit; now all three boards update together. These views show tasks that are still running in the background.

An unreadable settings.json is no longer overwritten with defaults

If settings.json cannot be parsed because its format is broken, the CLI now refuses to save without overwriting it with default settings. Previously, saving anything later could silently revert every existing setting. On a refused save, the file remains byte-for-byte identical and the status line names it. It is like a counter finding an unreadable page in a contract and returning the original for repair instead of replacing the whole document with a blank template.

An inherit subagent starts even when its parent has no model

When a subagent leaves model as inherit, it now starts even if its parent has no model of its own. The old behavior failed because there was nothing to inherit. It now falls back to the default fast tier. A relay team that cannot find the baton from the previous runner does not remain at the start; it picks up a spare baton and keeps running. inherit still prefers the parent model, falling back only when that model is absent.
