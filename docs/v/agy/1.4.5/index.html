Antigravity 1.4.5

發布日期：2026-10-22

繁體中文

新功能

回覆正文與收合思考區塊空行區隔，頂端僅保留標題

閱讀代理人剛生成的回覆時，若思考過程與正文擠成一團，往往會打斷閱讀節奏。

像在會議中翻閱專案報告，以前草稿筆記直接黏在結論上方容易分散焦點；現在頂端只留一張寫著構思時間的簡潔書籤，中間隔出一行空白，正文一目了然，需要時再翻開整份草稿。

現在代理人開始輸出回覆後，收合的思考區塊只會顯示 Thought for … 標題，不再重複列出思考過程的文字片段。收合的思考區塊與正文之間也多了一行空行隔開，文字段落不會再擠在一起。如果你想確認剛才完整的推導邏輯，只要手動展開該區塊，依然能查閱完整的思考內容。

新功能

比對檢視支援折疊搜尋計數，游標樣式與停駐位置對齊

檢閱程式碼變更時，折疊起來的未更動行數常讓搜尋結果變得難以掌握。

好比翻閱厚重的帳冊索引，以前夾在折頁裡的項目算不進筆數，各分冊的標記色塊也不一致；現在標籤直接註記折疊處藏有幾筆帳目，選取欄位也統一換成箭頭符號，翻到當前回合就直接對準第一筆明細。

在 /diff 檔案檢視中以 / 搜尋時，工具現在會計算折疊行內的相符項目，以 match 2/5 · +3 hidden 顯示隱藏數量，f 鍵展開提示也改為 show N hidden matches。介面上，Commit Tree 改用與 All Changes 及 Per Turn 相同的 > 游標與選取色，不再用高亮色塊；切換到 Per Turn 時游標也會直接停在第一個檔案，不必再跳過回合標題。

新功能

循環排程引入偏移時間差，避免整點邊界流量暴增

若有多個背景任務排在整點同時啟動，瞬間湧入的連線很容易讓伺服器塞車。

跟社區大樓安排住戶分流一樣，以前所有單位全擠在整點出門容易在閘門大塞車；現在為每個單位分配固定的前後時間差，整點前後平順出發，需要分秒不差的專車依然能申請在準點出發。

由代理人透過 schedule 工具建立的循環 cron 排程，現在觸發時會依每個排程套用固定的偏移時間，不再剛好卡在整點邊界，有效分散尖峰流量。在一天內多次重複的任務（例如每 30 分鐘或每小時一次），會在各自週期內的特定時間點觸發。每天早上 9:00 等固定時間排程，依然會在預定的該分鐘內執行。若排程需要嚴格對準時刻，代理人也能要求精確時間，而 @every 間隔排程則維持原樣不變。

效能優化

降低閒置與執行資源消耗，長對話與啟動載入更流暢

長時間在終端機開啟工具或處理大型專案時，背景消耗的硬體資源現在明顯下降。 當畫面沒有任何文字變動時，終端機會暫停螢幕重繪，讓閒置時的 CPU 使用率約減少一半。而在模型輸出串流回覆的過程中，工具會略過重複的畫面更新，並降低額度餘額的刷新頻率以節省運算效能。 長篇對話的渲染效能有所改善，重新恢復長對話工作階段時的載入速度也提升。命令列介面啟動並刷新對話摘要時，CPU 開銷也一併降低。 在記憶體管理方面，輸入提示詞與各類文字時改為打字時才動態配置儲存空間，不再預先保留整塊記憶體。閒置時的 CPU 消耗降低，長對話顯示與恢復載入也更快。

問題修復

模型遭安全機制阻擋時停止無止盡重試

遇上模型回覆被內容安全過濾機制阻擋的突發狀況，代理人過去容易陷入停不下來的重試迴圈。以前遇到回應被安全過濾器阻擋時，代理人會在背景靜默重試，甚至可能陷入無止盡的重試迴圈；現在這個問題已經修好，遇到阻擋時不再默默持續重試。

問題修復

外掛設定支援以字串指定技能路徑，避免載入失敗

想載入為其他工具設計的外掛程式時，設定檔格式只要稍有不同就會直接報錯。以前如果外掛的 plugin.json 將 skills 欄位寫成單一路徑字串（例如 "skills": "./skills/"）而非陣列清單，外掛就會載入失敗。現在這個問題已經修好，工具能正確辨識單一路徑字串並完成載入。

問題修復

市集外掛安裝與更新遇網路中斷自動重試一次

從市集安裝或自動更新外掛程式時，偶發的網路震盪容易造成程序中斷。以前下載內容短暫過時或下載中斷時，市集外掛安裝與自動更新可能因校驗碼不符或網路錯誤而失敗；現在命令列介面會自動重試下載一次。

English

FEATURE

Blank line separates response text from collapsed thought block, leaving only the header at the top

When reading a newly generated response from an agent, having the thought process clustered against the main text often breaks your reading flow.

Picture reviewing a project report during a meeting: previously, draft notes stuck directly above the conclusion would distract focus, whereas now only a neat bookmark noting thinking time remains at the top with a blank line in between, keeping the main text clear at a glance while letting you unfold the full draft whenever needed.

Now, once the agent begins outputting a response, the collapsed thought block only displays the Thought for … header instead of repeating text snippets from the thought process. A blank line also separates the collapsed thought block from the main text, so text paragraphs no longer bunch together. If you want to verify the complete reasoning logic behind it, you can still view the full thoughts simply by expanding the block manually.

FEATURE

Diff view supports folded search counts, aligning cursor style and resting position

When reviewing code changes, collapsed unchanged lines often make search results hard to track.

Much like browsing a thick ledger index, items tucked inside folded pages were previously excluded from match counts and marker color blocks across volumes were inconsistent, whereas tabs now directly annotate how many entries are hidden in folds, selection columns uniformly switch to arrow symbols, and turning to the current turn lands straight on the first detail.

When searching with / inside the /diff file view, the tool now counts matches within folded lines, displaying the hidden count as match 2/5 · +3 hidden, and the f key expand hint is now updated to show N hidden matches. On the interface, Commit Tree now uses the same > cursor and selection color as All Changes and Per Turn instead of highlight blocks; when switching to Per Turn, the cursor also rests directly on the first file without needing to skip past turn headers.

FEATURE

Recurring schedules introduce time offsets to prevent traffic spikes on hour boundaries

When multiple background tasks are scheduled to launch at the same time on the hour, an instant surge of connections easily congests the server.

Just as a residential complex staggers departures for its tenants, having every household head out right on the hour previously caused massive gate congestion, but assigning a fixed offset window to each unit now smooths out traffic around the hour while reserved shuttles that require exact timing can still request sharp departure times.

Recurring cron schedules created by an agent via the schedule tool now apply a fixed offset time to each schedule when triggered, no longer landing exactly on hour boundaries and effectively spreading out peak traffic. Tasks that repeat multiple times throughout the day (such as every 30 minutes or once an hour) trigger at specific points within their respective intervals. Fixed-time schedules like 9:00 AM every morning still execute within their scheduled minute. If a schedule requires strict time alignment, the agent can also request exact timing, while @every interval schedules remain unchanged.

PERF

Reduced idle and runtime resource consumption with smoother long conversations and startup loading

When keeping the tool open in the terminal for long periods or working on large projects, background hardware resource consumption has now noticeably decreased. When there are no text changes on screen, the terminal pauses screen repaints, cutting idle CPU usage roughly in half. Meanwhile, while the model streams output, the tool skips redundant screen redraws and lowers the refresh frequency of quota balances to save computing power. Rendering performance for long conversations has improved, and loading speed when resuming long conversation sessions has also increased. When the command-line interface launches and refreshes conversation summaries, CPU overhead is similarly reduced. Regarding memory management, storage space for prompt inputs and various texts is now dynamically allocated during typing instead of pre-allocating entire memory blocks. Idle CPU consumption drops, and long conversation display as well as resumption loading become faster.

BUGFIX

Stop infinite retries when the model is blocked by safety mechanisms

When encountering unexpected situations where a model response was blocked by content safety filters, agents previously tended to get trapped in an endless retry loop. In the past, when a response was blocked by safety filters, the agent would silently retry in the background and could even enter an infinite retry loop; this issue has now been resolved, and it no longer keeps silently retrying when blocked.

BUGFIX

Plugin configuration supports specifying skill paths as strings to prevent loading failures

When trying to load plugins designed for other tools, any slight difference in configuration format would directly trigger an error. Previously, if a plugin's plugin.json specified the skills field as a single path string (such as "skills": "./skills/") instead of an array list, the plugin failed to load. This issue has now been resolved, and the tool correctly recognizes a single path string and completes loading.

BUGFIX

Marketplace plugin installation and updates automatically retry once on network interruption

When installing or automatically updating plugins from the marketplace, occasional network disruptions easily interrupted the process. Previously, when downloaded content was temporarily stale or downloads were interrupted, marketplace plugin installations and automatic updates could fail due to checksum mismatches or network errors; the command-line interface now automatically retries the download once.
