zh-TW

面板視窗不再忽高忽低

從選單列打開面板（popover，浮在其他視窗上的小視窗）時，視窗先跳一下又在兩個高度間來回閃動的問題修好了。它原本像服飾店先按尺寸表猜衣服大小，網頁排好版後再量一次實際尺寸；量到的尺寸本該存下來，供下次優先採用，卻被程式誤認為不是可讀的對照資料而丟掉，於是每次又退回舊的預估值。現在讀寫都接受 Mapping（能用鍵查值的對照資料），已量到的高度會留下來；只有不能回報尺寸的錯誤面板，才繼續使用預估值。測試也改用不是一般 dict 的對照資料，確保這個判斷不會再退回舊路。

日韓語介面不再有空白標籤

日文與韓文介面先前各有 63 個標籤看起來像憑空消失，現在已補上翻譯。檢查原本只核對 489 個文字鍵是否都存在，像倉庫清點到每個紙箱卻沒打開看裡面有沒有東西；因此 loading、no_data、session_title、col_time 與 model_breakdown 雖有鍵名，畫面仍只留下空白。新檢查會拒絕空字串，也會比對 placeholder（顯示時才填入資料的位置）是否和英文一致；少掉或改名都可能在顯示時出錯。帶格式的標記、格式寫法與指令名稱則維持英文，不會被誤譯。

en

Panel windows stop flickering between heights

Opening a panel window from the menu bar no longer makes it snap once and then flicker between two heights. Think of a tailor who first guesses from a size chart, then measures the actual garment after it is laid out. The real measurement should have been saved and used next time, but the app mistook that saved value for unreadable data and threw it away, so it kept falling back to the estimate. Reading and writing now accept a Mapping (key-value data, even when it is not a plain Python dict), preserving measured heights. Only the error panel, which cannot report a measurement, continues to use an estimate. The regression test now uses that non-dict kind of Mapping too.

Japanese and Korean interfaces no longer show blank labels

Japanese and Korean users were each seeing 63 labels vanish into blank space; those translations are now filled in. The old check only confirmed that all 489 text keys existed, like counting every box in a warehouse without opening it to see whether it contains anything. That let loading, no_data, session_title, col_time, and model_breakdown exist as keys yet render blank. New checks reject empty translations and compare every placeholder (a slot filled with data at display time) with English. A missing or renamed placeholder can otherwise fail when the text is formatted. Rich markup, format specifications, and command names remain in English.

ja

パネルの高さが行ったり来たりしなくなった

メニューバーからパネル（popover、ほかのウィンドウの上に浮く小さなウィンドウ）を開いたとき、一度跳ねた後に二つの高さを行き来していた問題が直った。服屋がサイズ表で服の大きさを先に予想し、レイアウト後に実寸を測るようなものだ。本来は実測値を保存して次回に優先するはずが、アプリがその保存値を読めないデータと誤認して捨て、毎回予想値へ戻っていた。今は読み書きとも Mapping（キーで値を引ける対応データ）を受け入れるため、実測した高さが残る。測定を報告できないエラーパネルだけは、引き続き予想値を使う。テストも通常の dict ではない Mapping を使うようになった。

日本語と韓国語の空白ラベルを解消

日本語と韓国語の画面では、それぞれ 63 個のラベルが空白になっていたが、翻訳を補った。以前の検査は 489 個の文字キーがあるかだけを確かめていた。倉庫の箱を数えるだけで、中身を開けて確認しないようなものだ。そのため loading、no_data、session_title、col_time、model_breakdown はキーとして存在しても、画面では空白になっていた。新しい検査は空の翻訳を拒み、placeholder（表示時にデータを入れる場所）が英語版と一致するかも比べる。欠落や名前変更は表示時の書式処理で失敗するおそれがあるためだ。装飾用の記法、書式指定、コマンド名は英語のまま残す。

ko

패널 창 높이가 더는 오락가락하지 않는다

메뉴 막대에서 패널(popover, 다른 창 위에 떠 있는 작은 창)을 열 때 한 번 튄 뒤 두 높이 사이를 오가던 문제가 고쳐졌다. 옷가게가 치수표로 먼저 옷 크기를 짐작하고, 배치가 끝난 뒤 실측하는 모습과 같다. 실측값은 저장돼 다음번에 먼저 써야 했지만, 앱이 저장된 값을 읽을 수 없는 데이터로 잘못 판단해 버리고 매번 추정값으로 돌아갔다. 이제 읽기와 쓰기 모두 Mapping(키로 값을 찾는 대응 데이터)을 받아들여 실측한 높이가 남는다. 측정값을 보낼 수 없는 오류 패널만 계속 추정값을 쓴다. 테스트도 일반 dict가 아닌 Mapping을 사용하도록 바뀌었다.

일본어와 한국어 화면의 빈 라벨을 없앴다

일본어와 한국어 화면에서는 각각 63개 라벨이 빈칸으로 보였는데, 이제 번역을 채웠다. 이전 검사는 489개 문자 키가 있는지만 확인했다. 창고의 상자 수만 세고 안에 물건이 들었는지는 열어보지 않는 것과 같다. 그래서 loading, no_data, session_title, col_time, model_breakdown은 키로 존재해도 화면에서는 빈칸이었다. 새 검사는 빈 번역을 거부하고 placeholder(표시할 때 데이터를 넣는 자리)가 영어와 같은지도 비교한다. 빠지거나 이름이 바뀌면 표시 과정의 형식 처리에서 실패할 수 있기 때문이다. 꾸밈 표기, 형식 지정, 명령 이름은 영어로 남긴다.

原始 CHANGELOG

Original changelog
**The panel window oscillated between two heights.** Opening it snapped the window once, and it kept flicking back and forth afterwards. A panel's height has two sources: `popover_dimensions()` estimates it in Python from a registered base plus per-card adjustments, and the page measures itself for real once it has been laid out and reports the number back. The measurement is meant to win — it is saved to `NSUserDefaults` and read back by `resolve_panel_size()` on the next pass. It never was. `NSUserDefaults.objectForKey_()` hands PyObjC an Objective-C `__NSDictionaryI`, and `isinstance(value, dict)` on that is `False`, so the guard rejected the saved `{classic: 974}` every single time and fell back to the 1004 estimate. The write path had the same guard and therefore discarded every other panel's saved height whenever one was stored. What made this hard to see is that saving worked while loading did not: `defaults read com.lollapalooza.usage` showed the correct 974 sitting on disk the whole time, so the data looked healthy from the outside. The 30-point gap between the two values happens to equal `status_wrap_extra_height`, which is a coincidence worth ignoring — the estimate being wrong is not what caused the loop; the measurement being rejected is. Both guards now accept `collections.abc.Mapping`. The estimate is still used, but only for panels that can never report a measurement — `ErrorPanelView` has no JavaScript bridge, so waiting for one would leave it at the wrong size forever. The regression test substitutes a `MappingProxyType`, which like `NSDictionary` is a `Mapping` that is not a `dict`; a test double built from a plain `dict` passes whether or not the bug is present.
Original changelog
**The Japanese and Korean locales shipped sixty-three blank labels each.** Flagged one version earlier and fixed here. Both locales carried all 489 keys, so `test_every_language_has_the_same_keys` compared key sets, found them identical, and passed — while `loading`, `no_data`, `session_title`, `col_time` and `model_breakdown` rendered as empty space for anyone running the app in either language. A present-but-empty value is invisible to a parity check by construction, which is the same blind spot that let fifty-two Simplified Chinese strings sit in the Traditional Chinese locale until last version. Two assertions now close it: no translated value may be blank, and every value's `{placeholder}` set must match English exactly. The second guards a failure the first cannot see — a translation that drops or renames a placeholder does not look wrong in the file, it raises at `format` time in front of the user. Rich markup (`[dim]`), format specs (`{m:02d}`) and command names were left in English.
