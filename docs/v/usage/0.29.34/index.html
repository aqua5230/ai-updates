zh-TW

選單列數字與供應商標記更容易辨認

把選單列（menu bar，畫面頂端顯示資訊的一條列）想成放在不同牆色前的指示牌：文字和標記得靠粗細與輪廓看清楚，不能只靠原本顏色。百分比維持原有點數，但改為粗體，整條列約增加 5 點；在淺色桌布前也較容易一眼讀到。供應商標記（provider marks，標示服務來源的小圖樣）則改成單色範本影像，會跟著選單列外觀變化：淺色時顯黑，深色時顯白。它們不再倚賴顏色細節，Codex 標記不會在選單列大小縮成模糊一團；也與一向採同樣畫法的 critters 相符。標記大小現在為 14 至 16 點。

程式搬進分區後，也逐項核對啟動清單

整理倉庫，搬盒子進分區後仍得核對出貨清單與新架位，否則開門後才發現找不到貨。散在 repository root 的 77 個模組，歸進 packages（套件，程式的可匯入資料夾）。menubar/、loaders/、wintray/、discussion/、tui/、updates/ 六個資料夾收進 42 個，root 剩 35 個。這只改 import paths（匯入路徑，程式尋找其他程式碼的位置）。行為不變。虛擬環境外的檔案沒搬；狀態列 hooks（掛鉤，特定事件發生時被觸發的小程式）仍留頂層，因為 usage setup 會複製到家目錄，由系統 Python 執行。main.py 以字串載入模組，搜尋找不到；搬走後，字串可能指向空處，測試仍通過，App 卻無法啟動。新增測試讀取 main.py，比對呼叫的模組屬性與內容。

en

Menu bar numbers and provider marks are easier to read

Think of the menu bar as a sign against changing wall colors: both letters and marks need weight and shape, not color alone, to stay readable.Percentages keep their point size but are now bold, making the strip about 5 points taller and easier to read over light wallpaper. Provider marks, the small images that identify a service, are now monochrome template images. They turn black on a light menu bar and white on a dark one. Shape now does the work that color detail once did, so the Codex mark does not collapse into a blur at menu-bar size; the marks also match the critters, which have always been drawn this way. They are now 14 to 16 points tall.

Moved modules now come with a launch-list check

Tidying a warehouse takes more than moving boxes from the doorway into sections: the shipping list must also be checked against each new shelf, or opening day reveals missing stock.The 77 modules that had been loose in the repository root are now grouped into packages, folders that hold related importable code. menubar/, loaders/, wintray/, discussion/, tui/, and updates/ absorbed 42 of them, leaving 35 at the root. Only import paths, where code looks for other code, changed; behavior did not. Files that run outside the virtualenv stayed put: status-line hooks, files called at particular moments, remain at the top level because usage setup copies them to the user's home directory for the system Python. main.py names modules with plain strings, which search cannot find. A moved module could leave one pointing nowhere, while the test suite still passes and the app fails to launch. A new test reads main.py and checks every module attribute it calls against that module's contents.

zh-CN

菜单栏数字与供应商标记更容易辨认

把菜单栏（menu bar，屏幕顶部显示信息的一条栏）想成放在不同墙色前的指示牌：文字和标记得靠粗细与轮廓看清，不能只靠原本颜色。百分比保持原有点数，但改成粗体，整条栏约增加 5 点；在浅色壁纸前也更容易一眼读到。供应商标记（provider marks，标示服务来源的小图样）则改成单色模板图像，会随菜单栏外观变化：浅色时显黑，深色时显白。它们不再依赖颜色细节，Codex 标记不会在菜单栏大小缩成模糊一团；也与一向采用同样画法的 critters 相符。标记大小现在为 14 至 16 点。

程序搬进分区后，也逐项核对启动清单

整理仓库时，光把盒子从门口搬进分区还不够；出货清单也得逐项核对新货架，否则开门后才发现找不到货。原本散在 repository root 的 77 个模块，现在归进 packages（包，把相关程序放进同一个可导入的文件夹）。menubar/、loaders/、wintray/、discussion/、tui/、updates/ 六个文件夹吸收其中 42 个，根目录剩 35 个。这只改 import paths（导入路径，程序寻找其他代码的位置）。行为不变。在虚拟环境外运行的文件也没有搬动。状态栏 hooks（钩子，在特定时机会被调用执行的文件）仍留在顶层，因为 usage setup 会把它们复制到用户主目录，由系统 Python 执行。main.py 用文字指定要加载的模块，搜索找不到这些文字；模块搬走后，文字可能仍指向空处，整套测试仍会通过但 App 无法启动。现在新增测试会读取 main.py，并把它调用的每个模块属性逐一对照该模块内容。

ja

メニューバーの数字と提供元マークを見分けやすく

メニューバー（menu bar、画面上部に情報を表示する細い列）は、壁の色が変わっても読める案内板だと考えるとよい。文字もマークも、元の色だけでなく太さと輪郭で見分けられる必要がある。百分率は同じポイントサイズのまま太字になり、列は約 5 ポイント高くなった。明るい壁紙の上でもひと目で読める。提供元マーク（provider marks、サービスの出所を示す小さな図柄）は単色のテンプレート画像になり、明るいメニューバーでは黒、暗いメニューバーでは白になる。色の細部ではなく形で判別できるため、Codex のマークはメニューバーの大きさでぼやけた塊にならない。従来から同じ方式の critters ともそろい、サイズは 14 から 16 ポイントである。

モジュールの整理と起動リストの照合を一緒に実施

倉庫を整理するなら、箱を入口から区画へ移すだけでは足りない。出荷表も新しい棚の場所と一つずつ照合しなければ、開店後に品物が見つからない。repository root に散らばっていた 77 個のモジュールは、packages（関連する読み込み可能なプログラムをまとめるフォルダ）へ移された。menubar/、loaders/、wintray/、discussion/、tui/、updates/ の六つが 42 個を受け入れ、root には 35 個が残る。変わったのは import paths（ほかのプログラムを探す場所）だけで、動作は変わらない。仮想環境の外で動くファイルは移しておらず、status line hooks（特定の時点で呼び出して実行するファイル）は最上層に残る。usage setup がそれらを利用者のホームディレクトリへコピーし、システム Python で動かすためである。main.py は読み込むモジュールを文字列で指定するため、検索ではその指定を見つけられない。モジュールを移すと文字列が空の場所を指してもテスト一式は通り、App が起動しないおそれがある。新しいテストは main.py を読み、呼び出すすべてのモジュール属性を実際の内容と照合する。

ko

메뉴 막대 숫자와 제공업체 표시를 더 알아보기 쉽게

메뉴 막대(menu bar, 화면 위쪽에 정보를 보여 주는 가는 줄)는 벽 색이 바뀌어도 읽혀야 하는 안내판과 같다. 글자와 표시는 원래 색만이 아니라 굵기와 윤곽으로도 구분되어야 한다.백분율은 같은 포인트 크기를 유지하면서 굵게 바뀌고, 줄 전체는 약 5포인트 높아졌다. 밝은 배경 화면에서도 한눈에 읽기 쉽다. 제공업체 표시(provider marks, 서비스 출처를 알리는 작은 그림)는 단색 템플릿 이미지가 되어 밝은 메뉴 막대에서는 검게, 어두운 메뉴 막대에서는 하얗게 보인다. 이제 색의 세부 사항 대신 모양으로 구분하므로 Codex 표시는 메뉴 막대 크기에서 흐릿한 덩어리가 되지 않는다. 원래 같은 방식으로 그려진 critters와도 맞으며, 크기는 이제 14에서 16포인트이다.

모듈을 정리하고 실행 목록도 하나씩 확인

창고를 정리할 때 상자를 입구에서 구역으로 옮기는 것만으로는 부족하다. 출고 목록도 새 선반 위치와 하나씩 맞춰 보지 않으면 문을 연 뒤 물건을 찾지 못한다.repository root에 흩어져 있던 77개 모듈은 packages(함께 불러올 수 있는 관련 프로그램을 모아 둔 폴더)로 옮겼다. menubar/, loaders/, wintray/, discussion/, tui/, updates/ 여섯 폴더가 그중 42개를 받아 root에는 35개가 남는다. 바뀐 것은 import paths(프로그램이 다른 코드를 찾는 위치)뿐이며 동작은 바뀌지 않는다. 가상 환경 밖에서 실행되는 파일은 옮기지 않았고, status line hooks(특정 시점에 불려 실행되는 파일)는 최상위에 남는다. usage setup이 이를 사용자의 홈 디렉터리로 복사해 시스템 Python에서 실행하기 때문이다. main.py는 불러올 모듈을 일반 문자열로 지정하므로 검색으로는 그 지정을 찾을 수 없다. 모듈을 옮긴 뒤 문자열이 빈 곳을 가리켜도 전체 테스트는 통과하고 App은 실행되지 않을 수 있다. 새 테스트는 main.py를 읽고, 거기서 호출하는 모든 모듈 속성을 실제 모듈 내용과 대조한다.

Original changelog
**The menu bar percentages are now bold.** They were drawn at the menu bar's own point size in regular weight, which left them lighter than everything around them — hard to read at a glance over a light wallpaper. Same size, bold weight; the strip grows by about 5 points.
**The provider marks in the menu bar are now monochrome and follow the menu bar's own appearance.** The color art had to work against whatever wallpaper was behind it, and the Codex mark in particular collapsed into an indistinct blob at menu bar size because its detail came from color rather than shape. The marks are now template images — the system tints them black on a light menu bar and white on a dark one, so they stay legible everywhere, and they match the critters, which have always been drawn this way. They are also 14 to 16 points now.
Original changelog
**The 77 modules that sat loose in the repository root are now grouped into packages.** `menubar/`, `loaders/`, `wintray/`, `discussion/`, `tui/`, and `updates/` absorbed 42 of them; the root is down to 35. Nothing moved that runs outside the virtualenv — the status line hooks are still plain files at the top level, because `usage setup` copies them into the user's home directory to run under the system Python. Behavior is unchanged; only import paths moved.
**A test now guards the modules that `main.py` loads by name.** Those loads are plain strings, so no search finds them and a moved module leaves the string pointing at nothing while the whole suite still passes and the app fails to launch. The test reads `main.py` and checks every attribute it calls on such a module against that module's actual contents.
