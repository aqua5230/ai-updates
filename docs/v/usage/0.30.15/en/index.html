Usage 0.30.15

Released: 2026-09-14

Release notes

FEATURE

HTML reports now feature interactive date filtering, letting recipients explore data instantly without installing an app

When emailing an exported HTML report to teammates or managers, recipients can now freely select the date range they want to inspect right on the page.

It is like sending a client an interactive quote with a mini abacus attached: they nudge a slider at the top, and all totals across the document instantly recalculate.

Previously, the report locked its timeframe at generation time, leaving recipients unable to adjust the view; switching to last week's numbers meant asking you to rerun the command. The new version directly embeds an ~80 KB summary table of "day × tool × model × project" into the page, and every date-dependent section recalculates live in the browser. A sticky date bar at the top provides five shortcut ranges and a custom from/to range. No app or regeneration is required, keeping shared files fully functional. Sections covering a fixed number of days clearly indicate their span, preventing users from assuming the view is broken when switching dates.

FEATURE

Cleaning up transcripts no longer erases usage history, with snapshots persisting totals and costs

Deleting old conversation transcripts to free up disk space no longer wipes out historical reports.

Previously, reports recomputed everything from ~/.claude/projects and ~/.codex/sessions, which grow by roughly 1.9 GB each month, so clearing old files meant erasing history. The new version saves subtotal snapshots across five dimensions—session, date, tool, model, and project—into ~/.usage/usage_snapshot.json, while also recording each session's start time and duration so rankings survive. If a given day's loaded tokens are fewer than in the snapshot, that day is restored from the snapshot. Saved costs are kept as-is rather than repriced against today's prices. In tests across five ranges—today, this week, last 7 days, this month, and all—reports generated with transcripts fully kept versus simulated as completely deleted were byte-identical, except for generation time.

This is like an accounting department summarizing heavy receipts into a ledger: even if expired receipts are later shredded, revenue, expenses, and rankings remain exact.
FEATURE

Report layout reorganized around reading flow, reducing visual noise and optimizing mobile viewing

When opening the usage report, the layout is now rearranged in reading order.

It is like turning an annual report into a table of contents: leading with the overview, stripping redundant charts, tucking details into expandable tabs, and keeping mobile navigation effortless.

The sequence is now summary cards, usage trend, tools, projects, costliest sessions, fixed-span group, calculation details, and Year in Review. The main model section was removed because it duplicated tool numbers; tool rows can expand to reveal models and remain open after switching dates; the project donut chart was removed for repeating ranking data. "Weekly burn trend" is renamed to "Usage trend". Token composition, cache hit rate, and cost confidence are tucked into a collapsed calculation card, while five "fixed range" tags became a single note above their group. Colored bars were replaced with 2px lines along the bottom edge, with only token figures keeping their yellow color. Summary cards are separate rounded boxes that display abbreviated numbers first, followed by exact figures underneath. Section spacing, heading sizes, and horizontal margins are unified, with expandable rows highlighting on hover. On mobile, projects take one line and tools take two lines, session tables scroll horizontally, and the heatmap retains readable grid cells while automatically scrolling to the latest weeks. The opening summary removes the project count, as non-git folders and replayed history inflate the figure.

FEATURE

New daily stacked usage chart and cost confidence, with distinct tool colors eliminating confusion

To provide clear visibility into daily spending and usage pacing across different AIs, the report adds an intuitive daily usage chart.

The chart displays a stacked bar per day colored by tool, featuring a Tokens/Cost toggle in the top-right corner and hover tooltips for daily breakdowns, automatically redrawing when the date range changes. To make each tool instantly recognizable, Grok's color is changed to pink, resolving the issue where its previous green blended into the adjacent Claude green. In addition, the report introduces a "Cost confidence" badge that specifies the exact proportion of usage backed by public pricing versus unpriced usage, explicitly naming models without public rates. The interface also clearly informs readers that reported costs represent API-equivalent values calculated from public price lists rather than subscription bills.

This transparency is like an itemized hotel invoice where each day's expenses are distinguished by colored bars, complete with currency toggles, line-item breakdowns, and clear explanations for estimated unpriced services.
FEATURE

Claude sessions in subdirectories attributed to parent repo via Git, with expanded cache preventing repeated lookups

Launching Claude inside a project subfolder now correctly attributes usage to the same parent project.

Previously, adapters/claude.py handled sessions by taking only the last folder name in the path, causing tests/, docs/, or panels/ to be miscounted as standalone projects. The new version switches to resolve_project_name(), matching Codex, Grok, and Antigravity to determine the git root. To avoid repeated git calls when aggregating folders across multiple tools, the shared cache limit was raised from 256 to 2048 entries. Older dates that can only be replayed from subtotal snapshots retain the folder names recorded at that time.

It is as if a mailroom previously looked only at office door numbers on packages, sorting letters for the same department into different client bins; checking the building's main address finally routes every mail item to the correct project.
BUGFIX

Report fixes layout and chart proportions, calibrating prior-period comparisons and mixed pricing

Several layout and statistical issues in the HTML report have been resolved.

Previous-period comparisons no longer reach before the first day of data, eliminating artificial growth spikes such as ↑2799%. Tool groups mixed with unpriced models no longer hide their entire cost as —, properly displaying Antigravity's previously hidden $166. An issue where .rank-line's display:grid overrode the browser's [hidden] attribute has been fixed, ensuring collapsed rows actually collapse. Adding position:relative to .tokens-cell prevents session ranking bars from piling up in the top-left corner. Expanded model sub-rows now use corrected scaling rather than plotting project share on the total-volume scale, preventing a model accounting for 68.7% of a project from looking three times larger than the project itself.

This is like proofing a ledger's layout: calibrating baseline comparison dates, properly hiding collapsed rows, repositioning overlapping bars, and preventing sub-items from being drawn longer than the total.
