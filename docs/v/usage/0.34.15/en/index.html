Usage 0.34.15

Released: 2026-11-07

Release notes

BUGFIX

Quotas Update Normally over Proxy Networks, Wake-Up URL Queries No Longer Stall Refreshes

When working on certain corporate intranets, you might need to connect to external networks through a proxy server (an intermediary server forwarding outbound requests for a computer). The pre-launch check added in v0.34.14 connected directly to Google, which caused environments behind a proxy to always be judged offline and prevented tools from running. Now, configuring an HTTPS proxy counts as a successful connection and weekly quotas update normally, while setting only NO_PROXY continues to run the check as before.

Think of a building security guard checking visitors who previously only recognized the direct front entrance, treated anyone arriving via shuttle bus as absent, and clogged the gate whenever flipping through the guest registry stalled; now shuttle check-ins are recognized, and registry lookup time counts toward the waiting limit.

If a domain name query hangs when waking from computer sleep, the original 3-second limit now includes the URL lookup time as well, no longer stalling data refreshes.

FEATURE

Auto-Start Window Keeper Now Follows Gemini Quota, Switching Model Groups No Longer Misjudges Timing

When you enable Antigravity's auto-start window keeper feature, the underlying mechanism determines when to trigger a window based on quota status.

Picture a factory dispatching freight trucks: the driver always operates a truck, but dispatchers previously checked the fuel gauge of a sedan on display to schedule trips, leading to departures at the wrong time or no runs at all; now they monitor the truck's fuel level, no longer miscalculating dispatch timing.

This feature always sends messages to a Gemini model, but previously evaluated quota based on whichever model group the card currently displayed. When you selected the Claude, GPT, or Argon model group, the window mechanism would start at the wrong time or never open at all. Now the windowing decision directly tracks Gemini's quota, so whichever model group the interface switches to, it will no longer miss the timing.

BUGFIX

Antigravity Quota Misclassification and Cache Anomalies Fixed, Signing In Again Takes Effect on Next Refresh

When checking Antigravity quotas, anomalies in data classification and local state have now been fixed. When usage reads Google's model list as a fallback (an alternative used when the primary method fails), a Gemini weekly quota close to reset was previously mistaken for a 5-hour quota in its final five hours and jumped into the wrong row, which no longer happens. When Google rejected a sign-in, usage previously kept retrying with the same rejected authorization token (an access credential used to verify identity) for up to an hour. Now after signing in to Antigravity again, the next refresh applies the new credentials directly. If the local quota cache (a file temporarily storing query results) was corrupted, it previously caused the card to disappear permanently. Unreadable files are now automatically moved to ~/.usage/quarantine/ for quarantine, and fresh quotas are fetched.

FEATURE

On Windows, Taskbar Countdown Appears and Clears Promptly with Panel Closed

When using the taskbar icon on Windows to track progress, you can now see the countdown status promptly even without opening the panel.

Just as with an indicator light outside a recording studio, updates to the light lagged behind whenever the studio door stayed closed; now the moment a switch flips, the outside indicator turns on or off in lockstep.

Previously, when a quota happened to fill or reset between two refreshes, as long as the panel (a popover window displaying detailed quotas) remained closed, the taskbar countdown could take up to five minutes to update. This delay has now been fixed, so even if the panel is not kept open, the taskbar countdown appears and clears promptly the moment a quota fills or resets.
