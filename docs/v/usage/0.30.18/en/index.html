Usage 0.30.18

Released: 2026-09-19

Release notes

FEATURE

The HTML report gets a new layout, with chart text up from 9px to 12px

When you open the HTML report generated by usage, each section is now neatly organized inside a consistent dashboard card.

Previously, the entire report was split only by thin divider lines, making it hard to navigate down a long page; now the four summary cards at the top share a single three-row grid, keeping numbers aligned. Body text and numbers uniformly share a sans-serif typeface paired with tabular figures, keeping monospace only for the command line at the top and the [usage]> prefix. The color palette shifted to neutral tones, token counts are no longer amber, and green is reserved exclusively for trends and peaks. Chart text is also larger: axis labels grew from 9px to 12px, legends grew from .7rem to .8rem, and the hour axis alongside the heatmap's month and weekday labels were also enlarged, fixing the previous issue where text was unreadable on ordinary screens.

Think of an exhibition guide that used to separate long passages with a few thin lines and now uses sorted display plaques in bigger print, readable from a step back.
FEATURE

Switching Claude accounts on Windows no longer shows previous quota

Sharing one Windows PC and signing in to different Claude accounts? Claude Code stores retrieved quota in ~/.claude.json and tags the cache (temporary storage for fetched results) with the account name that retrieved it, automatically ignoring the cache whenever the account switches.

Previously, usage did not verify this account tag, and Windows relies primarily on this cache file for Claude quota, causing the tool to keep displaying the previous user's remaining balance after a switch. Now, any cache with a mismatched account is skipped; caches written by older Claude Code versions without account tags continue to be read normally.

Picture a dry cleaner who checks the name on every ticket, so you never walk out with the previous customer's clothes.
FEATURE

Report tests pin session start times to UTC to avoid time zone failures

This one is for developers; as a user you won't notice a difference.

Previously, 6 report tests passed only on machines configured for the UTC time zone, so continuous integration (CI) stayed green while tests consistently failed on Windows machines in UTC+8. This happened because the code converted session start times inline where test fixtures could not freeze the clock; that conversion logic is now separated out so tests can pin the reference time directly to UTC, while the software's functional behavior remains completely unchanged.

An international exam that syncs every clock to GMT grades everyone against the same time, not against each student's wristwatch.
FEATURE

Website visual redesign with larger tap targets and preloaded panel posters

Browsing the usage official website on a mobile phone is now much easier on your fingers.

The homepage feature section now alternates image and text across three rows to present tool quotas, HTML reports, and visual themes, while secondary features are arranged into two-column cards, and the standalone report section is merged into the second row. The pacing section adopts a paper card look, the theme preview frame dynamically fits panel height so shorter panels leave no awkward empty space, and installation instructions moved to the very bottom.

It reads like a redesigned product brochure: main items get prominent spreads, the rest sit in tidy boxes, and the buttons are bigger and harder to miss.

Navigation links, the mobile copy button, and footer links all feature larger tap target areas, and panel previews display a static poster image until fully loaded, with Chinese posters served on Chinese pages.
