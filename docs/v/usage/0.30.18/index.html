Usage 0.30.18

發布日期：2026-09-19

繁體中文

HTML 報表改為儀表板卡片，圖表標籤與字體全面放大

usage 的 HTML 報表這版換了一套長相，圖表文字也放大到一般螢幕看得清楚。

這宛如將連綿漫長的大看板拆解為規格一致的展示卡，外框俐落分明，連同圖表標籤也一併加大，讓參觀者不必貼近螢幕就能看清各項指標。

過去整頁報表只靠細線分段，在長頁面中難以辨識段落分界；現在每個區塊都放進同規格的儀表板卡片中。內文與數字統一採用無襯線字體並搭配等寬數字對齊，等寬字體僅留給最上方的指令與 [usage]> 前綴。色票改採中性色調， token（AI 處理與計費的文字單位）數量不再是土黃色，綠色則專門留給趨勢與峰值。上方四張摘要卡共用同一套三列格線，讓數據俐落切齊。此外，圖表軸標籤從 9px 放大至 12px、圖例從 .7rem 放大至 .8rem，時段軸與熱力圖的月份及星期標籤也同步加大，解決了舊版字級在一般螢幕上難以辨識的困擾。

Windows 切換 Claude 帳號不再顯示舊額度，自動略過不符身分的快取

若是你在 Windows 系統切換 Claude 帳號，查詢到的用量額度現在會即時對應目前登入的身分。 Claude Code 會在 ~/.claude.json 檔案中將額度快取（把查過的結果暫存起來直接用）標註抓取時的帳號名稱，一旦切換帳號就會忽略該筆暫存。過去 usage 讀取資料時未比對帳號標籤，而 Windows 環境下的 Claude 額度主要仰賴這份快取檔案，導致切換帳號後仍持續顯示前一個帳號的剩餘額度。現在只要帳號不符就會主動略過暫存快取；至於舊版 Claude Code 寫入、未附帶帳號標籤的快取，則照舊讀取不受影響。

這做法就像門禁系統在換人感應時重新比對名牌，一旦身分不同便略過櫃檯的暫存資料，不再把前一位訪客的額度誤套給新進人員。

報表測試將工作階段時間固定為 UTC，排除時區差異導致的驗證失敗

跨不同時區執行開發與報表測試，驗證邏輯不再因本機電腦的時差而產生誤判。過去有 6 支報表測試只能在時區為 UTC 的機器上通過，導致持續整合（CI，自動執行程式測試與建置的驗證機制）維持綠燈，但在時區為 UTC+8 的 Windows 電腦上卻固定失敗。問題出在程式先前直接呼叫 .astimezone() 轉換工作階段開始時間，測試環境無法攔截替換該函式。現在該轉換邏輯已獨立抽成 _session_start_text() 輔助函式，測試設定便能像 _entry_date 一樣將時間固定為 UTC，在維持原有功能行為不變的前提下修正了測試環境差異。

此舉如同跨國線上測驗將所有試卷的時間戳記一律對齊標準時區，確保各地評分系統都以同一把尺完成驗證。

官網視覺排版全面翻新，擴大觸控點擊範圍並加入預載海報

usage 官網這版重新排版，手機上也比較好點。

這種整頓好比將型錄重新編排，主力展示採圖文交錯的大版面，其餘項目化為雙欄卡片，並把按鈕與連結範圍全面拓寬以便點按。

首頁功能區改為三排圖文左右交錯呈現，分別介紹各家工具額度、HTML 報表與外觀主題，其餘功能則收納為雙欄卡片，原先獨立的報表專區也一併整併至第二排。進度管家改採紙卡質感呈現，主題預覽外框會隨面板高度自適應縮放，避免較短的面板下方留下多餘空白，安裝說明則移至頁面尾端。導覽列連結、手機複製按鈕與頁尾連結皆擴大了點擊有效範圍，且面板預覽在載入完成前會先顯示靜態海報圖，中文頁面亦對應提供中文海報。

English

HTML reports redesigned as dashboard cards with enlarged chart labels and typography

The usage HTML report gets a new look in this release, with chart text enlarged enough to read on an ordinary screen.

This is like breaking down a continuous, sprawling billboard into uniformly sized display cards with crisp borders, while enlarging chart labels so viewers can clearly read each metric without leaning in close to the screen.

Previously, the entire report relied only on thin rules to separate sections, making division boundaries hard to follow across a long page; now each section sits in a dashboard card of the same specification. Body text and numbers uniformly share a sans-serif typeface paired with tabular figures, with monospace reserved only for the command line at the top and the [usage]> prefix. The color palette adopts neutral tones, token counts are no longer amber, and green is dedicated to trends and peaks. The four summary cards at the top share a single three-row grid, keeping the numbers neatly aligned. In addition, chart axis labels were enlarged from 9px to 12px, legends grew from .7rem to .8rem, and the hour axis alongside the heatmap's month and weekday labels were also enlarged, resolving the issue where older font sizes were unreadable on ordinary screens.

Switching Claude accounts on Windows no longer displays previous quota, automatically skipping mismatched cached data

When switching Claude accounts on Windows, the retrieved usage quota now immediately corresponds to the currently logged-in identity. Claude Code tags the quota cached in ~/.claude.json with the account name that fetched it, ignoring that cached data once the account switches. Previously, usage did not verify the account tag when reading data, and Claude quota on Windows primarily relies on this cache file, causing it to continuously display the remaining quota of the previous account after switching. Now, any cache with a mismatched account is actively skipped; caches written by older versions of Claude Code without account tags are still read as usual without being affected.

This is like an access control system re-verifying name badges when a new person badges in, bypassing the front desk's cached records whenever the identity differs, so a previous visitor's quota is no longer mistakenly assigned to a newcomer.

Report tests pin session start times to UTC, eliminating test failures caused by time zone differences

When running development and report tests across different time zones, verification logic no longer misjudges results due to local clock differences. Previously, 6 report tests passed only on machines set to the UTC time zone, allowing continuous integration (CI) to remain green while consistently failing on Windows machines in UTC+8. The issue occurred because the code previously called .astimezone() inline to convert session start times, preventing test environments from intercepting and replacing the function. That conversion logic has now been extracted into a separate _session_start_text() helper function, enabling test fixtures to pin the time to UTC just like _entry_date, resolving test environment discrepancies while keeping existing functional behavior unchanged.

This is like an international online exam standardizing all test timestamps to a single reference time zone, ensuring scoring systems everywhere grade against the exact same baseline.

Website visual layout completely refreshed with expanded tap targets and preloaded poster images

The usage website has been rearranged, and it is easier to tap on a phone.

This overhaul is like redesigning a product catalog, showcasing main highlights across large alternating image-and-text spreads, organizing remaining items into two-column cards, and broadening button and link tap areas for easier tapping.

The homepage feature section now alternates image and text across three rows to introduce tool quotas, HTML reports, and visual themes, while remaining features are organized into two-column cards, and the previously standalone report section has been merged into the second row. The pacing section now adopts a paper card texture, the theme preview frame dynamically adapts to panel height to avoid leaving extra empty space under shorter panels, and installation instructions have been moved to the end of the page. Navigation bar links, the mobile copy button, and footer links all have enlarged tap target areas, and panel previews display a static poster image until fully loaded, with Chinese pages correspondingly providing Chinese posters.
