zh-TW

Linux 支援狀態列驗證，標準函式庫掛鉤正式納入測試

想在 Linux 環境藉由 usage 掌握 Claude Code 的用量與狀態，過去常因文件未提及而不敢確定是否支援。事實上，負責串接的 hook（事件發生時觸發的自動處理程式）僅依賴 Python 標準函式庫，且 usage setup 在 macOS 與 Windows 上從未設下系統限制，在 Linux 本就能正常運作；過去只是缺少自動化測試驗證，才一直未寫入官方文件。現在 CI 會在 Ubuntu 系統中建立拋棄式 HOME 目錄安裝掛鉤，並傳入真實的 statusLine（終端機底部的即時狀態列）酬載進行驗證。這好比一件出廠就具備防水機能的風衣，過去因說明書未印認證標章讓人不敢在雨天穿出門；直到品管中心在標準測試台噴灑真實水柱，確認它確實防水。

命令列套件登陸 PyPI，免裝桌面版即可在終端機直接試用

套件已以 usage-cli 之名發布至 PyPI，輸入 uvx usage-cli 不用先安裝任何東西，uv 會自行準備 Python 3.13 執行環境，讓 Linux 與 Windows 使用者不必下載 macOS 應用程式，就能體驗 usage status --json、儀表板與報表。執行 uv tool install usage-cli 則可常駐指令；因 usage 名稱在 2016 年已被註冊，套件名稱為 usage-cli，但安裝後 usage 與 usage-cli 指令皆可使用。此途徑僅提供命令列工具，選單列與系統匣應用程式仍維持在 Release 下載。這如同工具出租店提供免押金快借服務，想用扳手不必搬整組工具箱回家，報代號就能直接開工；若順手再登記留用。

依工作目錄精準歸帳，Antigravity 用量不再全數掛在單一專案

像公務採購報帳時，若所有發票都一律蓋上總公司大印，月底的部門支出排行便完全看不出各專案到底花了多少經費；唯有依據出差工單上的工作地點逐筆歸帳，才能精準呈現各專案的真實花費。 Antigravity（agy）的用量現在會準確歸屬至你實際作業的專案中。過去每筆 agy 記錄都固定寫入 "Antigravity" 專案名稱，導致專案用量排行無法看出 token（AI 計費的文字單位）到底花在哪個資料夾。現在記錄會從各工作階段所執行的 shell 指令中自動解析工作目錄，只有在找不到任何指令紀錄時，才會以備援方式退回使用 "Antigravity" 名稱。

en

Claude Code status line is verified on Linux with real test payloads

Linux users looking to track Claude Code usage and metrics through usage previously had to guess whether the integration was supported because it was missing from documentation. In reality, the integration hook relies entirely on the Python standard library, and usage setup never placed an operating system check on the Claude path for macOS or Windows, meaning it already functioned on Linux without issue. It simply lacked test coverage and went undocumented. CI now installs the hook against a throwaway HOME directory on Ubuntu and feeds it a genuine statusLine payload to verify behavior. It is like a jacket manufactured with waterproof fabric that lacked a certified badge in the user manual, leaving customers hesitant to wear it in the rain until the quality-control lab blasted it with actual water jets on a test rig and verified that it was waterproof.

CLI package lands on PyPI for instant terminal access without desktop apps

uvx usage-cli runs without installing anything; uv prepares Python 3.13 on its own so Linux and Windows users can try usage status --json, the dashboard, and reports without downloading the macOS app. The CLI is published to PyPI as usage-cli. Running uv tool install usage-cli keeps the command around; because the name usage was claimed on PyPI in 2016, the distribution is usage-cli, but both usage and usage-cli are installed as commands. This path ships the CLI only — menu bar and system tray apps remain unchanged and come from release downloads. It is like a tool rental counter offering instant on-site borrowing without a deposit, where you can pick up a wrench by its inventory code without purchasing an entire heavy toolbox, and later choose to register and keep that specific wrench in your workshop.

Antigravity usage is attributed to actual project directories instead of a static label

It is like expense reimbursement at a company where stamping every invoice with a generic corporate seal leaves department expense rankings unable to show how much each project spent, until invoices are attributed to the exact work site from travel logs to reflect accurate project costs. Antigravity (agy) token consumption is now accurately attributed to the project you were actually working in. Previously, every agy entry recorded a static "Antigravity" project name, which prevented the project usage ranking from showing which folder the tokens were spent in. Entries now resolve the working directory from the recorded shell commands in each session, falling back to "Antigravity" only when no command is found.

ja

Linux でのステータスライン動作を検証、標準ライブラリのフックを正式テスト

Linux 環境で usage を使って Claude Code の使用量や状態を確認したい場合、以前はドキュメントに記載がなく対応状況が不透明だった。実際には、連携を担う hook（イベント発生時にトリガーされる処理）は Python 標準ライブラリのみに依存しており、usage setup も macOS や Windows で Claude 向けの制限を設けていなかったため、Linux でも以前から問題なく動作していた。単にテストが存在せずドキュメント化されていなかっただけである。現在は CI が Ubuntu 上で使い捨ての HOME ディレクトリを用意してフックをインストールし、実際の statusLine ペイロードを渡して動作を検証するようになった。これは出荷時から撥水性能を備えていたジャケットが、説明書に認定マークがなかったために雨天での着用を躊躇されていたものの、品質管理ラボの試験台で実際に放水テストを行い、撥水性能が確認されたようなものだ。

CLI パッケージが PyPI で公開、デスクトップアプリなしで端末から即時試用可能

パッケージが usage-cli として PyPI で公開され、uvx usage-cli は何もインストールせずに実行でき、uv が Python 3.13 の実行環境を自動で準備する。これにより Linux や Windows ユーザーも macOS アプリをダウンロードすることなく、usage status --json やダッシュボード、各種レポートを試せる。uv tool install usage-cli を実行すればコマンドを常駐させることができる。PyPI では 2016 年に usage が取得済みだったため配信名は usage-cli だが、導入後は usage と usage-cli の両コマンドが利用可能になる。この配布経路は CLI 専用であり、メニューバーやシステムトレイのアプリは従来通り Release からダウンロードする。これは保証金不要のツールレンタル窓口のようなもので、重い工具箱一式を購入しなくても、登録番号を伝えるだけで必要なレンチをその場で手に取って作業でき、気に入ったらそのまま手元に残す手続きを取れる仕組みである。

実際の作業ディレクトリに正確に計上、Antigravity の使用量が単一項目に固定されなくなった

企業の経費精算において、すべての領収書に一律で本社全体の印鑑を押していては、月末の支出ランキングでどのプロジェクトにいくら費用がかかったのか把握できない。出張伝票の作業場所に基づいて案件ごとに仕訳して初めて、各プロジェクトの実際の支出が正しく把握できる。 Antigravity（agy）の使用量は、実際に作業していたプロジェクトへ正確に計上されるようになった。以前は agy のすべての記録に固定の "Antigravity" というプロジェクト名が記録されていたため、プロジェクト別の使用量ランキングを見ても token（AI の課金計算に用いられる文字単位）がどのフォルダで消費されたのか分からなかった。現在はセッション内で記録されたシェルコマンドから作業ディレクトリを特定し、コマンドが見つからない場合にのみフォールバックとして "Antigravity" に戻る。

ko

Linux 환경의 상태 표시줄 동작을 검증하고 표준 라이브러리 훅을 공식 테스트한다

Linux 환경에서 usage 를 통해 Claude Code 의 사용량과 상태를 확인하려 할 때, 예전에는 공식 문서에 설명이 없어 지원 여부를 확신하기 어려웠다. 사실 연동을 담당하는 hook(이벤트 발생 시 트리거되는 처리)은 오직 Python 표준 라이브러리에만 의존하며, usage setup 역시 macOS 나 Windows 에서 Claude 경로를 차단한 적이 없어 Linux 에서도 이미 정상 작동하고 있었다. 단지 테스트가 이루어지지 않아 문서에 기록되지 않았을 뿐이다. 이제 CI 는 Ubuntu 환경의 임시 HOME 디렉터리에 훅을 설치하고 실제 statusLine 페이로드를 전달하여 동작을 검증한다. 마치 출고 당시부터 방수 기능을 갖춘 재킷이 설명서에 인증 표시가 없어 비 오는 날 입기를 망설였으나, 품질 관리 연구소의 시험대에서 실제 물줄기를 분사하는 테스트를 통과해 방수 기능이 확인된 것과 같다.

CLI 패키지가 PyPI에 출시되어 데스크톱 앱 없이 터미널에서 즉시 사용한다

패키지가 PyPI 에 usage-cli 로 배포되었으며, uvx usage-cli는 아무것도 설치하지 않고 실행되며 uv가 Python 3.13 실행 환경을 알아서 준비한다. 이를 통해 Linux 와 Windows 사용자도 macOS 앱을 다운로드할 필요 없이 usage status --json, 대시보드 및 보고서를 바로 체험할 수 있다. uv tool install usage-cli 를 실행하면 명령어를 시스템에 상주시킬 수 있다. PyPI 에서 usage 이름이 2016 년에 이미 선점되어 배포명은 usage-cli 이지만, 설치 후에는 usage 와 usage-cli 명령어가 둘 다 등록된다. 이 경로는 CLI 전용이며, 메뉴 모음 및 시스템 트레이 앱은 기존처럼 Release 다운로드를 통해 제공된다. 공구 대여소에서 보증금 없이 즉석 대여 서비스를 제공하여, 무거운 공구 세트를 통째로 집에 사 들일 필요 없이 식별 코드만 대고 스패너 하나를 바로 집어 들어 작업한 뒤 마음에 들면 장기 보관용으로 등록하는 것과 같다.

실제 작업 디렉터리에 정확히 귀속되어 Antigravity 사용량이 단일 프로젝트로 묶이지 않는다

기업의 경비 정산에서 모든 영수증에 본사 직인만 일괄 날인하면 월말 부서별 지출 순위에서 각 프로젝트가 비용을 얼마나 썼는지 알 수 없으며, 출장 일지의 작업 위치를 바탕으로 건별로 귀속시켜야 각 프로젝트의 실제 지출이 명확히 드러나는 것과 같다. 이제 Antigravity(agy) 사용량은 실제로 작업 중이던 프로젝트에 정확하게 귀속된다. 기존에는 모든 agy 기록에 고정된 "Antigravity" 라는 프로젝트 이름이 저장되어, 프로젝트별 사용량 순위에서 token(AI 요금 부과의 기준이 되는 텍스트 단위)이 어느 폴더에서 소모되었는지 확인할 수 없었다. 이제는 세션에 기록된 셸 명령어에서 작업 디렉터리를 분석하여 반영하며, 명령어를 찾을 수 없는 경우에만 대체 수단으로 "Antigravity"로 되돌아간다.
