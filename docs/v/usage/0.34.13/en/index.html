Usage 0.34.13

Released: 2026-11-06

Release notes

FEATURE

Choose quota alert thresholds directly from the menu

When asking AI to help revise a report, you can choose alert percentages from the menu to get an early warning that your quota is running low.

The oven used to have only an alert switch; now you can choose the mark where it rings. Setting the alert mark below the current reading does not make it ring retroactively—it waits until the next actual crossing.

“Usage Alert Notifications” is now a submenu on macOS and in the Windows tray (the area that groups icons for background apps). It includes an on/off switch and checkmarks for 50/70/80/90/95%. A newly added threshold below current usage waits until the next actual crossing before notifying you. If macOS notification permission is off, the menu explains this and offers an item that opens Notification settings directly. Previously, alerts could look enabled even though notifications could not arrive; now the menu shows where permission is missing.

FEATURE

The classic panel puts quota percentages and red alerts first

When you open usage to check how much quota remains, percentages and alerts are what you need to find first. The classic panel now tones down card titles and project numbers so percentages and red alerts stand out, and removes the color bar on the left of each card. With four or more quota cards, the compact layout also tightens the projects card and footer, instead of shrinking only the quota cards themselves. In the Traditional Chinese, Simplified Chinese, Japanese and Korean interfaces, the “Session” label now reads “5 hours,” directly stating the time span this field represents.

Think of tidying a household bill covered in colorful labels: the title, reference number and amount due used to compete for attention. Now the decorations are put away and secondary details toned down, leaving your attention on the numbers you need to check.
BUGFIX

Older Codex readings no longer carry a warning symbol

Seeing “updated … ago” beside your Codex quota does not, by itself, mean something went wrong with the reading.

A station used to put fault warnings even on timetables published at regular intervals, confusing passengers. Now normal update times stay as notes, and a warning appears only when data was due but could not be obtained.

Codex has no live report, so a slightly older reading is normal. Across all panel themes and in the Claude Code side pane, usage now shows this label in muted text without the ⚠ symbol. You can still see how long ago the data was updated; it is simply no longer treated as a problem. Antigravity keeps its warning because an old value there means a fetch failed. Both may show older numbers, but the reasons differ, and the display now treats them separately.

FEATURE

Beginner mode skips terms you already use yourself

If you already discuss PRs or commits in your messages, repeated explanations of those terms can feel unnecessary.

A tutor used to explain words repeatedly just by following a vocabulary list; now the tutor notices words the student uses independently. But asking what a word means still counts as seeking help, rather than proof that the student has learned it.

Beginner mode now skips terms that appear in your own messages. For example, PR (a request for others to review and merge changes) no longer returns as a hint. The same rule applies to commit (saving a set of changes as a version record). But asking “What is launchd?” does not count as already knowing how to use the term, so you can still receive an explanation. If you do not actually understand a skipped term, you can mark it as not understood in the history pane to bring it back into the hints.

BUGFIX

Quota reminders no longer mix up accounts or repeat warnings

Switching Claude accounts and then receiving a quota reminder for the previous account can make it hard to tell how much you have left. Previously, after switching accounts with /login, a new session (the running period of this conversation) reused the last known numbers until its first reply. The status line hook (a small program triggered by specific events) now records which conversation observed those numbers. Quota reminders ignore readings from other conversations, avoiding attributing the previous account’s quota to you. Antigravity’s reset time can drift by up to a minute between readings, which previously made it look like a new quota window. The same warning now no longer repeats within one conversation.

An attendant used to hand the previous guest’s bill to a new guest and deliver the same payment reminder again. Now the attendant checks the recipient first and recognizes notices already delivered.
BUGFIX

usage self-repair and switch states no longer clash

Keeping different versions of usage on your computer, or letting another tool manage the Claude status line, could previously cause self-repair to go wrong. A hook (a small program triggered by specific events) used to be reinstalled whenever its version differed, so two copies of usage could keep replacing it. Now self-repair only upgrades; an older version will not downgrade what a newer version installed. The status-line switch shows as on only when usage’s own hook is in use. Failed installations are stated explicitly, and if the system refuses launch-at-login registration, the reason is shown too. Hooks related to conversation sessions still repair themselves even when another tool manages the Claude status line. If a tool’s quota numbers have not updated for an hour or more, the reminder also explains that the quota window may have reset. You can tell whether a switch failed to take effect or the numbers in front of you are outdated.

BUGFIX

Muse quota checks use fewer model calls and stop with the app if stuck

Even refreshing a quota card used to spend a model call, meaning that checking usage itself added to usage. With Muse 1.4.13 or later, usage now reads quota results from muse usage --json. This query runs no model, so the quota card no longer calls a model on every refresh. Older Muse versions, or quota windows with no reading yet, still use a fallback: the original one-line muse exec check. Saving model calls depends on the version and available readings; the old method has not been removed in every situation. If a muse usage check gets stuck, quitting the app stops it too.

Checking the water bill used to require turning on the tap for a test; now you can read the water meter directly. The old method is used only when the meter cannot yet be read, and any stuck test is shut off when you leave.
FEATURE

Conversation handoffs mark only successful changes as done

When handing work over to the next conversation, a major concern is a handoff saying something is done when the files were never successfully changed. Session (the running period of this conversation) handoffs now mark only successful changes as done. These include commits (saving changes as a version record) and edits. If a commit is blocked by a pre-commit hook (a small checking program triggered before saving a version), or an edit fails, it is no longer recorded as completed. Commands run with ! in a shell (a program that accepts and runs text commands) are also no longer treated as your last request.

Shift handover records used to count a repair request as a completed repair and mistake an operating note beside it for a customer request. Now only successful work goes in the completed column, and operating notes no longer pass for customer requests.
