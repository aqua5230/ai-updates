zh-TW

Homebrew 安裝後，設定狀態列不再走錯路

你用 Homebrew 安裝 Usage，卻看到「跑 python3 main.py --setup」時，現在不會再被帶進死巷。Homebrew（macOS 的套件安裝工具）裝的是應用程式，沒有原始碼資料夾；以前畫面下方的提示仍叫你照原始碼使用者的方式跑指令。你若翻進應用程式包裡執行 main.py，還會撞上看似無關的 ImportError，因為它必須由 py2app（把 Python 程式包成 macOS App 的工具）隨附的解譯器啟動。現在兩種提示都改指向「Set Up Status Line」按鈕，按一下就能設定顯示在終端機最底下的狀態列；直接誤跑內附的 main.py 時，也會明說為何不能這樣開。像買了組裝好的咖啡機，說明書不再叫你拆機找零件，而是帶你按面板上的設定鍵。

en

Homebrew installs now point you to the right status-line setup

If you installed Usage through Homebrew and saw python3 main.py --setup, that instruction no longer sends you down a dead end. Homebrew installs an app, not a source-code folder, but the footer once gave cask users the directions meant for people who cloned the repository. Digging into the app bundle and running its main.py only produced a misleading ImportError, because it needs the interpreter packaged by py2app. Both messages now point to the “Set Up Status Line” button, which does the job in one click for every type of install. And if the bundled main.py is launched directly, it explains why it cannot run that way. It is like buying an assembled coffee machine: the manual now points to its setup button instead of telling you to open the casing and hunt for parts.

zh-CN

Homebrew 安装后，设置状态栏不再走错路

你用 Homebrew 安装 Usage，却看到「运行 python3 main.py --setup」时，现在不会再被带进死胡同。Homebrew（macOS 的软件包安装工具）装的是应用，没有源代码文件夹；以前界面下方的提示仍叫你按源代码用户的方式运行命令。你若翻进应用程序包里执行 main.py，还会撞上看似无关的 ImportError，因为它必须由 py2app（把 Python 程序打包成 macOS App 的工具）自带的解释器启动。现在两种提示都改为指向「Set Up Status Line」按钮，点一下就能设置显示在终端机最底下的状态栏；直接误运行内附的 main.py 时，也会说明为何不能这样打开。像买了组装好的咖啡机，说明书不再叫你拆机找零件，而是带你按面板上的设置键。

ja

Homebrew版でも、ステータスラインの設定で迷わない

Homebrew で Usage を入れたのに python3 main.py --setup と表示されても、もう行き止まりへ誘導されない。Homebrew が入れるのはアプリであり、ソースコードのフォルダではない。しかし以前は、画面下の案内がリポジトリを複製した人向けの手順のままであった。アプリのバンドル内にある main.py を直接動かすと、py2app（Python プログラムを macOS App にまとめる仕組み）が同梱したインタープリタで起動すべきため、関係なさそうな ImportError にぶつかっていた。今はどちらの案内も「Set Up Status Line」ボタンを指し、どの導入方法でも一度の操作で端末最下部のステータスラインを設定できる。内蔵の main.py を直接起動した場合も、なぜ動かないかを説明して終了する。組み立て済みのコーヒーメーカーで、説明書が分解して部品を探せではなく、操作パネルの設定ボタンを押せと案内するようなものである。

ko

Homebrew 설치 후 상태 표시줄 설정에서 더는 길을 잃지 않는다

Homebrew로 Usage를 설치한 뒤 python3 main.py --setup이라는 안내를 봐도 이제 막다른 길로 들어가지 않는다. Homebrew는 소스 코드 폴더가 아니라 앱을 설치하지만, 예전 화면 아래 안내는 저장소를 복제한 사람용 명령을 그대로 보여 주었다. 앱 번들 안의 main.py를 직접 실행하면 py2app(Python 프로그램을 macOS App으로 묶는 도구)가 함께 넣은 인터프리터로 시작해야 하므로, 엉뚱해 보이는 ImportError를 만났다. 이제 두 안내 모두 “Set Up Status Line” 버튼을 가리키며, 어떤 설치 방식이든 한 번 눌러 터미널 맨 아래 상태 표시줄을 설정할 수 있다. 내장된 main.py를 직접 실행해도 왜 그 방식으로는 작동하지 않는지 설명하고 끝난다. 조립된 커피 머신의 설명서가 뚜껑을 열어 부품을 찾으라 하지 않고, 조작판의 설정 버튼을 누르라고 알려 주는 것과 같다.

原始 CHANGELOG

Original changelog
**The app told Homebrew users to run a command that cannot work.** With no status file on disk, the popover footer said `Run python3 main.py --setup and open Claude Code once` — an instruction written for people who cloned the repo. Someone who installed the cask has no repo, so the natural next move is to look inside the bundle, and `main.py` really is in there: py2app copies it to `Contents/Resources/`. Running that copy with the system `python3` dies on `ImportError: cannot import name 'packaged_resource_path' from 'i18n'`, which points at the wrong thing entirely. The modules `main.py` imports are compiled into `lib/python313.zip`, and only the bundle's own interpreter has that on `sys.path`; with the real `i18n.py` unreachable, an unrelated PyPI package also named `i18n` in the user's site-packages answers the import instead. Both footer messages now name the "Set Up Status Line" button, which does the same job in one click and exists in every install regardless of how it was obtained. The bundled `main.py` additionally exits with an explanation when it is started without py2app's `RESOURCEPATH`, so the dead end says what it is instead of raising. (#92, reported by @kyang-06)
