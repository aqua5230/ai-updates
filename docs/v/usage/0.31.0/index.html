Usage 0.31.0

發布日期：2026-09-27

繁體中文

新功能

新增手繪筆記主題，額度化身方格紙半圓儀表

平常盯著制式數據介面覺得單調時，現在能換上更有手感的新樣式來掌握用量。

這次新增的手繪筆記（Sketchbook）面板主題，將方格紙質感搬上螢幕。介面把每個額度（quota，各家服務分配的使用上限）畫成帶指針的半圓儀表，並以深墨色大字搭配代表色螢光筆底線標示百分比。既有的 50% 與 80% 警示配色與固定的 80% 記號完全保留，macOS 與 Windows 都支援，讓面板總數來到 15 款。

好比隨手翻開手繪帳本，以前只見到整排冷冰冰的規格數據，現在每筆紀錄都像用麥克筆畫上刻度與底線，一眼就能看清進度。
新功能

Windows 面板完整顯示，底部操作按鈕不再被切掉

在直向高度較矮的高解析度螢幕上使用 Windows 版，再也不必煩惱底部按鈕被擠出畫面外。

以前面板仰賴 pywebview（負責在桌面呈現網頁介面的工具庫）回報的尺寸，容易算錯空間，導致「立即更新」與「結束」按鈕被切掉。現在面板直接向 Windows 讀取目標螢幕扣掉工作列後的可用範圍，縮放比例與視窗大小也改用同一個螢幕計算，視窗底邊絕不超過工作列。即使縮到最小可讀比例仍放不下，面板也會自動轉成可以捲動瀏覽。

如同依照牆面高度調整的展示架，以前只顧著展開而把底層按鈕擠到地板下，現在先扣除邊界空間並支援捲動，讓所有操作隨時都能點得到。
新功能

Antigravity 跨天對話每輪各自計日，日期分佈更精準

如果你習慣讓同一個 AI 對話跨好幾天持續進行，用量圖表現在能如實呈現每天的真實消耗。

從 Antigravity CLI 1.1.18 開始，系統不再把每輪對話時間存在原本的位置，導致跨天交談的每一輪用量全被歸到對話開始的第一天。現在程式改從對話的 steps（記錄每一步互動細節的資料表）讀取每輪時間。系統同時會主動重建一次本機快取（cache，把算過的結果暫存起來直接用的機制），讓過去受影響的歷史日期全部重新計算校正。

跟逐日核銷費用的記帳本一樣，以前跨天出差只要寫在同一張申請單，所有花費全被算在出發第一天；現在改依每張明細的確切時間分別記帳，舊帳目也一併重新整理歸位。
問題修復

修正 macOS 摺紙主題抖動，面板縮放不再反覆拉扯

在 Mac 上選用摺紙風格面板時，介面不再因為尺寸計算打架而產生惱人的微小震顫。

以前 macOS 上的面板高度與自動縮放機制會反覆互相觸發，導致 Origami（摺紙主題）介面持續抖動。現在程式在單純調整縮放時會保留足夠的高度空間，同時確保內容增減時依然能正常縮小。開發團隊也補上了瀏覽器回歸測試（browser regression，用自動化腳本驗證既有功能未被改壞的測試），涵蓋自動調整的穩定性與內容切換。

就像相機自動對焦找到穩定焦距，以前視窗與縮放比例互相干擾導致畫面不斷抽搐，現在設定好適當緩衝，既能隨內容靈活伸縮又不再無故晃動。

English

FEATURE

New Sketchbook Theme Turns Quotas into Grid-Paper Semicircle Gauges

If you find standard data interfaces monotonous, you can now switch to a more tactile style to track your usage.

The newly added Sketchbook popover theme brings a graph paper texture to your screen. The interface renders each quota as a semicircle gauge with a needle, displaying large dark-ink percentages with highlighter underlines in each service’s representative color. Existing warning color schemes for 50% and 80% as well as the fixed 80% mark are fully retained across macOS and Windows, bringing the total number of popover themes to 15.

Picture opening a hand-drawn ledger: where there used to be rows of cold metric figures, every entry is now marked with clear dial scales and highlighter underlines, making progress visible at a glance.
FEATURE

Full Windows Popover Display Prevents Bottom Action Buttons from Being Clipped

When using the Windows version on high-resolution displays with shorter vertical heights, you no longer have to worry about bottom buttons being pushed offscreen.

Previously, the popover relied on dimensions reported by pywebview (a library that renders web interfaces on the desktop), which often miscalculated space and cut off the "Update Now" and "Quit" buttons. Now, the popover directly queries Windows for the available area on the target display excluding the taskbar, and both the scale factor and window size are calculated from that same display so the bottom edge never exceeds the taskbar. Even if content cannot fit at the minimum readable scale, the popover automatically switches to a scrollable view.

Think of a display rack tailored to wall height: instead of expanding blindly and pushing lower shelves under the floor, it accounts for boundary margins first and supports scrolling so every control stays within reach.
FEATURE

Antigravity Multi-Day Chats Track Turns Daily for Accurate Date Distribution

If you regularly keep the same AI conversation running over multiple days, usage charts now accurately reflect daily consumption.

Starting with Antigravity CLI 1.1.18, the system no longer stores turn timestamps in their original location, which previously caused all usage across multi-day chats to be attributed to the first day. The application now reads individual turn timestamps from conversation steps (a table recording details for each interaction step). The system also proactively rebuilds the local cache once, recalculating and correcting all affected historical dates.

Like a daily expense ledger where multi-day business trips used to dump every receipt onto the departure date on a single claim, expenses are now booked by the exact time of each item while older records are reconciled into place.
BUGFIX

Fix macOS Origami Theme Jitter to Stop Popover Scaling Conflicts

When selecting the origami-style popover on a Mac, the interface no longer suffers from annoying micro-jitters caused by competing size calculations.

Previously on macOS, popover height and automatic scaling repeatedly triggered each other, causing the Origami theme interface to jitter continuously. Now, the application preserves sufficient height headroom during pure scale adjustments while ensuring it can still shrink properly as content changes. The development team also added browser regression tests (automated scripts that verify existing features remain unbroken), covering auto-fit stability and content switching.

Just as camera autofocus locks onto a stable focal length, where window sizing and scale factors once interfered and caused constant screen twitching, proper buffer spacing now allows smooth resizing with content without unprovoked shaking.
