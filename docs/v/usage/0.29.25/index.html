zh-TW

Antigravity 也有額度狀態列，開關會自己補齊

你若同時用 Claude Code 和 Antigravity CLI，面板的狀態列（status line，顯示在終端機最底下）開關，現在也會把額度顯示裝到後者；未裝 Antigravity 不建資料夾或檔案。macOS 把掛鉤（hook，事件觸發的小程式）放進 ~/.gemini/antigravity-cli/，由內建 /usr/bin/python3 執行，因此不依賴 App 的虛擬環境。像在兩台車上加同款儀表板：原來那台會先備份，關掉開關時再還原。新腳本會留著，免得正在啟動的 CLI 撞上刪檔，整個工作階段都出錯。已開啟者會在啟動時補裝遺失檔案、更新不同版本腳本；關掉就不會再裝。用 pip 或 uv 安裝也會帶上此掛鉤，Windows 系統匣等非 macOS 平台不碰 Antigravity 設定，避免寫入 /usr/bin/python3。

短暫高用量不再被判成 Heavy

剛送出一則內容很多的訊息，狀態卻立刻把你標成 Heavy，現在不會這麼快下結論。先前 burn rate（用量燃燒率，把 token 除以經過時間算出的速度）最短拿一分鐘來算；單則訊息的快取（cache，把算過或查過的結果暫存起來直接用）建立 token（AI 處理與計費的文字單位）就可能把數字推得很高。現在最短觀察時間改成五分鐘，跟 burn_rate.py 原本用來預估的下限一致。這像用車速表判斷你是否超速：不能只看起步那一下的猛踩，得看一小段路。它不是把用量藏起來，而是少讓短暫尖峰替你貼上重度使用者標籤。

兩個選單開關並排，少一條多餘分隔線

打開選單想調整兩個開關時，現在它們會排在同一組，中間那條分隔線拿掉了。兩者原本都是單純的開／關選項，線條卻像在菜單上把同類配菜切成兩區，讓人以為它們有不同身分或用途。畫面沒有增加新控制項，也沒有改掉任何一個開關能做的事；只是讓排列跟實際關係一致。你看到兩個並列開關，就知道它們同樣是可獨立啟用或停用的選項，不必猜那條線暗示了什麼差別。

en

Antigravity gets the quota status line, and its switch keeps it current

If you use both Claude Code and the Antigravity CLI, the panel's existing status line (the readout at the bottom of a terminal) switch now puts the same quota display on Antigravity too. Machines without Antigravity remain untouched: no folder or file is created. On macOS it places a hook (a small program triggered by an event) in ~/.gemini/antigravity-cli/ and runs it with built-in /usr/bin/python3, independent of the app's virtual environment. Think of fitting matching dashboards to two cars: your existing dashboard is backed up first and restored when you turn the switch off. The new script stays behind so a CLI already starting does not collide with its deletion and show an error for its whole session. Startup replaces a missing or outdated script only while the switch is on. pip and uv installs now include it; non-macOS platforms leave Antigravity settings alone, avoiding /usr/bin/python3 on Windows.

A brief burst no longer marks you Heavy

After you send one especially large message, the status display will no longer rush to label you Heavy. Burn rate (the pace calculated by dividing tokens, units of AI text processing and billing, by elapsed time) used to use a span as short as one minute. Cache creation from one message could therefore push the rate high on its own. The shortest span is now five minutes, matching the forecasting floor already used by burn_rate.py. It is like judging speed from a car's gauge: you cannot call someone a speeder from one hard press at the starting line; you need a short stretch of road. Usage is not hidden; a brief spike is simply less likely to attach a heavy-user label.

Two menu toggles now sit together without a misleading divider

When you open the menu to adjust its two toggles, they now appear as one group, with the separator between them removed. Both were always simple on/off controls, but the line was like splitting matching side dishes into separate sections of a menu: it suggested they had different roles. No new control has appeared, and neither toggle does anything different. The layout now matches their actual relationship. Seeing two switches side by side tells you they are both options you can turn on or off independently, without making you guess what distinction the divider was meant to signal.

zh-CN

Antigravity 也有额度状态栏，开关会自己补齐

如果你同时用 Claude Code 和 Antigravity CLI，面板里原来那个状态栏（status line，显示在终端最底下）开关，现在也会把相同的额度显示装到后者；没装 Antigravity 的电脑完全不会多出文件夹或文件。它在 macOS 会把挂钩（hook，特定事件发生时被触发的小程序）放进 ~/.gemini/antigravity-cli/，用内置的 /usr/bin/python3 执行，因此不依赖应用的虚拟环境。像在两辆车上加同款仪表板：你原来设的那台会先备份，关掉开关时再还原。新脚本则刻意留着，免得正在启动的 CLI 撞上删文件，整段会话都显示错误。已经开着开关的人也会在启动时补装丢失文件、更新不同版本的脚本；关掉就不会再装。用 pip 或 uv 安装也会带上此挂钩，Windows 等非 macOS 平台则不碰 Antigravity 设置，避免写入 /usr/bin/python3。

短暂高用量不再被判成 Heavy

刚发出一则内容很多的消息，状态却立刻把你标成 Heavy，现在不会这么快下结论。此前 burn rate（用量燃烧率，把 token 除以经过时间算出的速度）最短拿一分钟来算；单条消息的缓存（cache，把算过或查过的结果暂存起来直接用）创建 token（AI 处理与计费的文字单位）就可能把数字推得很高。现在最短观察时间改成五分钟，和 burn_rate.py 原本用于预测的下限一致。这像用车速表判断你是否超速：不能只看起步那一下猛踩，得看一小段路。它不是把用量藏起来，而是少让短暂尖峰替你贴上重度用户标签。

两个菜单开关并排，少一条多余分隔线

打开菜单想调整两个开关时，现在它们会排在同一组，中间那条分隔线拿掉了。两者原本都是单纯的开／关选项，线条却像在菜单上把同类配菜切成两区，让人以为它们有不同身份或用途。画面没有增加新控制项，也没有改掉任何一个开关能做的事；只是让排列和实际关系一致。你看到两个并列开关，就知道它们同样是可独立启用或停用的选项，不必猜那条线暗示了什么差别。

ja

Antigravity にも利用枠のステータス行が加わり、スイッチが最新状態を保つ

Claude Code と Antigravity CLI を併用しているなら、パネルにあったステータス行（status line、端末の最下部に表示される情報欄）のスイッチで、Antigravity にも同じ利用枠表示を付けられるようになった。Antigravity がない端末には、フォルダもファイルも新設しない。macOS ではフック（hook、特定の出来事で起動する小さなプログラム）を ~/.gemini/antigravity-cli/ に置き、内蔵の /usr/bin/python3 で動かすため、アプリの仮想環境に頼らない。同じ計器盤を二台の車へ付けるようなものだ。元からある表示は先に控えを取り、スイッチを切れば戻す。新しいスクリプトは、起動中の CLI と削除処理がぶつかり一回のセッションずっとエラーになるのを避けるため残す。起動時はスイッチがオンの場合だけ、欠けたものを入れ直し古いものを更新する。pip と uv の導入にも含まれ、Windows など macOS 以外では設定を触らない。

短い急増だけで Heavy 判定にならない

内容の多いメッセージを一つ送っただけで、表示がすぐ Heavy と判定することはなくなった。burn rate（使用速度、token を経過時間で割って求める値）は、以前は最短一分で計算していた。キャッシュ（cache、計算済みや取得済みの結果を一時保存して再利用する仕組み）を作る token（AI が処理・課金する文字の単位）が一通だけに多く含まれると、それだけで値が高くなり得たためである。最短の観察時間は五分になり、burn_rate.py の予測で既に使う下限とそろった。車の速度計で速度違反を決めるなら、発進時に一度強く踏んだ瞬間だけでは足りず、少し道を走って見るようなものだ。使用量を隠す変更ではなく、短い山だけで重い利用者の札を付けにくくする変更である。

二つのメニュー切替が、紛らわしい区切り線なしで並ぶ

メニューを開いて二つの切替を調整する時、二つは一つの組として並び、間にあった区切り線はなくなった。どちらも元から単純なオン／オフの操作なのに、線があることで役割が違うように見えていた。同じ付け合わせをメニューの別の欄へ分けて載せるようなものだ。新しい操作は増えず、どちらかの切替でできることも変わらない。見た目を実際の関係に合わせただけである。横に並ぶ二つのスイッチを見れば、どちらも個別にオンまたはオフにできる選択肢だと分かり、線が何の違いを示すのか考えずに済む。

ko

Antigravity에도 사용량 상태 줄이 생기고, 스위치가 최신 상태를 유지한다

Claude Code와 Antigravity CLI를 함께 쓴다면, 패널에 있던 상태 줄(status line, 터미널 맨 아래에 표시되는 정보 줄) 스위치가 이제 Antigravity에도 같은 사용량 표시를 붙인다. Antigravity가 없는 컴퓨터에는 폴더나 파일도 새로 만들지 않는다. macOS에서는 훅(hook, 특정 일이 일어날 때 실행되는 작은 프로그램)을 ~/.gemini/antigravity-cli/에 두고 내장 /usr/bin/python3로 실행하므로 앱의 가상 환경에 기대지 않는다. 두 대의 차에 같은 계기판을 다는 셈이다. 기존에 쓰던 상태 줄은 먼저 백업하고, 스위치를 끄면 복원한다. 새 스크립트는 이미 시작 중인 CLI가 파일 삭제와 맞부딪혀 한 작업 세션 내내 오류를 보이는 일을 피하려고 남겨 둔다. 스위치가 켜진 경우에만 시작할 때 빠진 파일을 다시 설치하고 오래된 스크립트를 갱신한다. pip와 uv 설치에도 이 훅이 포함되며, Windows 같은 macOS 이외 플랫폼에서는 Antigravity 설정을 건드리지 않는다.

짧은 급증만으로 Heavy 판정을 받지 않는다

내용이 많은 메시지 하나를 보낸 직후 표시가 곧바로 Heavy라고 판단하는 일이 줄어든다. burn rate(사용 속도, token을 지난 시간으로 나눠 계산한 값)는 예전에는 짧게는 1분만 놓고 계산했다. 캐시(cache, 계산하거나 찾은 결과를 잠시 저장해 다시 쓰는 기능)를 만드는 token(AI가 처리하고 요금을 매기는 글자 단위)이 한 메시지에 많이 들어가면 그 하나만으로도 값이 높아질 수 있었다. 이제 가장 짧은 관찰 시간은 5분이며, burn_rate.py의 예측 하한과 같다. 자동차 속도계로 과속을 판정할 때 출발선에서 한 번 세게 밟은 순간만 보고 정할 수는 없고, 짧은 구간은 달려 봐야 하는 것과 같다. 사용량을 숨기는 변경이 아니라, 잠깐의 솟음만으로 과다 사용자 꼬리표가 붙는 일을 줄이는 변경이다.

두 메뉴 스위치가 헷갈리는 구분선 없이 나란히 놓인다

메뉴를 열어 두 스위치를 조절할 때, 이제 둘은 한 묶음으로 놓이고 사이에 있던 구분선은 사라진다. 둘 다 원래 단순한 켜기／끄기 선택지인데도 선이 있어서 서로 다른 역할처럼 보였다. 같은 곁들임 음식을 메뉴의 다른 칸에 나눠 놓는 것과 같다. 새 조작 항목이 생긴 것도 아니고 어느 한 스위치가 하는 일이 바뀐 것도 아니다. 배열만 실제 관계에 맞췄다. 나란한 두 스위치를 보면 둘 다 따로 켜거나 끌 수 있는 선택지임을 알 수 있고, 구분선이 무엇을 뜻하는지 추측할 필요가 없다.

Original changelog
**The status line switch now covers the Antigravity CLI too.** The panel's single switch has always installed Claude Code's status line; it now mirrors the same quota display onto Antigravity when its CLI is installed. The hook is copied to `~/.gemini/antigravity-cli/` and runs under macOS's built-in `/usr/bin/python3`, so it stays stdlib-only and independent of the app's virtual environment. A status line you configured yourself is backed up to a sidecar file first and restored when the switch is turned off; the deployed script is deliberately left behind, because deleting it races with any CLI that is starting and would leave that session showing a status line error for its whole lifetime. A machine without the Antigravity CLI is untouched — no directory and no file is created, and the switch keeps working for Claude Code exactly as before.
**Startup self-healing keeps the Antigravity status line current.** Installing it only on the switch's rising edge would have hidden the feature from everyone whose switch was already on, and would have frozen the deployed script at whatever version first installed it. Self-heal now reinstalls it when it is missing and re-copies it when its bytes differ from the bundled source, both gated on the switch being on — so turning the switch off keeps it off. The Antigravity branch is isolated from the rest of self-heal and only records a log entry when the install actually succeeds.
**`pip` and `uv` installs ship the Antigravity hook.** `usage_statusline_agy` was missing from `py-modules`, so a non-bundle install could not resolve the script and the switch silently did nothing for Antigravity.
**Non-macOS platforms no longer touch Antigravity's settings.** The Windows tray shares the same toggle, and `~/.gemini/antigravity-cli/settings.json` expands there too, so a Windows user with the CLI would have had `/usr/bin/python3` written into their configuration. The sync is now a no-op off macOS.
