zh-TW

遮蔽專案名稱全面生效，圖表與匯出檔案不洩密

「遮蔽專案名稱」現在會套用至整份匯出 usage 報表，分享時不再只是把名稱藏在畫面上。過去匯出的 HTML 報表雖然在畫面上隱藏了專案名稱，檔案內部卻仍夾帶未遮蔽的資料集，等於只在螢幕遮住卻沒從檔案拿掉；現在未遮蔽的副本已自匯出檔完全移除。過去圓餅圖圖例與專案名稱深入分析都仍顯示真實專案名稱；現在兩者也一併納入遮蔽，分析文字改為 Project N，對齊專案表格既有的編號。這像拿黑筆塗黑公文上的機密名稱，以前只塗了複寫紙表面、底層仍夾著原稿；現在則在寄出前把原始底稿徹底抽除。若你曾分享過舊版產生的遮蔽報表，請將那些檔案視為未遮蔽處理。

本機檔案限擁有者，隔離目錄明確設定存取模式

在共用辦公室存放私人物品，不只要把置物箱上鎖，放箱子的儲藏室大門也得加鎖，同棟樓的其他帳號才翻看不到內容。 usage 現在為本機建立的檔案與目錄全面套用僅限擁有者的存取權限。以往存放在 ~/.usage/、~/.usage-reports/ 與 ~/Library/Logs/usage/ 底下的附件、匯出報表與紀錄檔，權限曾允許同部電腦的其他本機帳號讀取；現在新建立的檔案權限一律設為 0600，所屬目錄則設為 0700。匯入附件時也不再複製來源檔案原有的權限。此外，過去移入隔離目錄的檔案雖保有擁有者權限，但目錄本身並未限制；現在該隔離目錄在建立時也會設定明確的存取模式。

超長行設上限，深層巢狀改列無效行

JSONL（每行各放一筆 JSON 資料的檔案格式）歷史檔案中的異常大行，不再會耗盡記憶體、拖垮整個讀取流程。usage 現在以 64 MiB 為上限來讀取每行資料，這個數值是根據實測真實環境中 23 MB 的最大記錄所設定；一旦單行資料超過此上限，程式會直接略過它並繼續運作。遇到層層巢狀過深而引發遞迴錯誤（RecursionError）的 JSON 內容，也會直接當成無效行處理。這像包裹分揀線入口設了兩道檢查：尺寸過大的貨物，以及包裝層數深到難以檢查的貨物，都直接撥到旁道，讓其他包裹繼續前進。這能防止超過 64 MiB 或因巢狀過深引發 RecursionError 的歷史資料中斷讀取流程。

en

Masking project names covers the full exported file, charts, and insights

The "mask project names" option now applies to the entire exported usage report, rather than merely hiding names on screen when you share it. Previously, an exported HTML report still carried the unmasked dataset alongside the masked one, hiding project names on screen without actually removing them from the file; that unmasked copy is now completely dropped from exports. Previously, both the donut legend and project-naming insights still showed real project names; both are now covered by the mask, with insights displaying Project N to match the numbering in the project table. It is like redacting confidential names on a document: earlier releases only blacked out the top carbon copy while leaving the original underneath, but the source sheet is now completely removed before delivery. If you shared a masked report generated by an earlier version, treat those files as unmasked.

Local files are owner-only; the quarantine directory gets an explicit access mode

When storing personal items in a shared building, locking individual storage bins is not enough; the storage room door itself must be secured so other tenants in the building cannot browse the contents. usage now creates local files and directories with owner-only access permissions. Attachments, exported reports, and logs under ~/.usage/, ~/.usage-reports/, and ~/Library/Logs/usage/ were previously created with permissions that let other local accounts on the same machine read them; new files are now 0600 and their directories 0700. Importing attachments also stops copying the source file's existing permissions. Additionally, while files moved into the quarantine directory already kept owner-only permissions, the quarantine directory itself now receives an explicit access mode upon creation.

Oversized JSONL lines are capped; deep nesting is treated as invalid

An oversized line in a JSONL (a file format with one JSON record per line) history file will no longer exhaust memory or derail reading. Lines are now read against a 64 MiB ceiling, which was set from a measured real-world maximum of 23 MB; whenever a line exceeds this threshold, it is skipped so processing can continue. Deeply nested JSON structures that raise a recursion error (RecursionError) are likewise treated as invalid lines. It is like a parcel sorting line with two screening checks: items that are too large or wrapped in layers too deep to inspect are sent directly down a side lane, while the rest keeps moving. This ensures history files containing oversized lines or deeply nested JSON that raises RecursionError cannot derail your usage history.

zh-CN

遮蔽项目名称全面生效，图表与导出文件不泄密

“遮蔽项目名称”现在会应用至整份导出的 usage 报表，分享时不再只是把名称藏在画面上。过去导出的 HTML 报表虽然在画面上隐藏了项目名称，文件内部却仍夹带未遮蔽的数据集，等于只在屏幕遮住却没从文件中去除；现在未遮蔽的副本已从导出文件中完全移除。过去圆饼图图例与项目名称深入分析都仍显示真实项目名称；现在两者也一并纳入遮蔽，分析文字改为 Project N，对齐项目表格已有的编号。这像拿黑笔涂黑公文上的机密名称，以前只涂了复写纸表面、底层仍夹着原稿；现在则在寄出前把原始底稿彻底抽除。若你曾分享过旧版生成的遮蔽报表，请将那些文件视为未遮蔽处理。

本地文件限所有者，隔离目录明确设置访问模式

在共享办公室存放私人物品，不仅要把储物箱上锁，放箱子的储藏室大门也得加锁，同栋楼的其他账号才翻看不到内容。 usage 现在为本地创建的文件与目录全面应用仅限所有者的访问权限。以往存放在 ~/.usage/、~/.usage-reports/ 与 ~/Library/Logs/usage/ 下的附件、导出报表与日志文件，权限曾允许同台设备的其他本地账号读取；现在新创建的文件权限一律设为 0600，所属目录则设为 0700。导入附件时也不再复制源文件原有的权限。此外，过去移入隔离目录的文件虽保有所有者权限，但目录本身并未限制；现在该隔离目录在创建时也会设置明确的访问模式。

超长行设上限，深层嵌套按无效行处理

JSONL（每行存放一条 JSON 数据的文件格式）历史文件中的异常超长行，不会再耗尽内存、拖垮整个读取过程。usage 现在以 64 MiB 为上限来读取每行数据，该数值是根据实测真实环境中 23 MB 的最大记录所设定；一旦单行数据超过此上限，程序会直接跳过它并继续运行。遇到层层嵌套过深而引发递归错误（RecursionError）的 JSON 内容，也会直接当成无效行处理。这像包裹分拣线入口设了两道检查：尺寸过大的货物，以及包装层数深到难以检查的货物，都直接拨到旁道，让其他包裹继续前进。这能防止超过 64 MiB 或因嵌套过深引发 RecursionError 的历史数据中断读取流程。

ja

プロジェクト名マスクが共有ファイル全体・グラフ・インサイトに適用

「プロジェクト名をマスク」は、書き出した usage レポート全体に適用され、共有時に画面上の名前だけを隠すものではなくなった。以前の HTML レポートは画面上でプロジェクト名を隠しつつもファイル内に元のデータセットを残していたが、現在はマスクされていないコピーが完全に除外される。以前はドーナツグラフの凡例とプロジェクト名のインサイトの両方が実際のプロジェクト名を表示していたが、現在は両方ともマスク対象となり、インサイトの表記はプロジェクト一覧表と揃えた Project N に切り替わる。書類の機密名を黒塗りする際、以前は複写の表面だけを消して原本を下に挟んだままだったのが、送付前に元の原稿を抜き取るようになった形だ。過去の版で書き出したマスク済みレポートを共有したことがある場合は、マスクされていないものとして扱う必要がある。

ローカルファイルは所有者専用、隔離ディレクトリには明示的なモードを設定

共有オフィスに私物を保管する際、収納ボックスに鍵をかけるだけでなく保管室の扉も施錠しなければ、同じ建物の別アカウントに中身を見られてしまう。 usage が作成するローカルファイルとディレクトリに対し、所有者のみがアクセスできる権限が適用されるようになった。これまで ~/.usage/、~/.usage-reports/、~/Library/Logs/usage/ の下にある添付ファイル、書き出しレポート、ログは同一端末の他アカウントからも読み取れる状態だったが、新規ファイルは 0600、ディレクトリは 0700 で作成される。添付ファイルの取り込み時にも元のアクセス権を引き継がなくなった。さらに、隔離ディレクトリへ移動したファイル自体は以前から所有者専用だったが、隔離ディレクトリ自体にも明示的な権限が設定されるようになった。

長大な JSONL 行に上限を設定し、深いネストは無効な行として扱う

JSONL（1行ごとに1件の JSON データを入れるファイル形式）の履歴ファイルに異常に大きな行があっても、メモリを使い果たして読み込み全体が止まることはなくなった。usage は実際の環境で測定された最大値 23 MB をもとに設定された 64 MiB の上限を基準に行を読み込み、上限を超えた行はスキップして処理を継続する。入れ子が深すぎて再帰エラー（RecursionError）を引き起こす JSON も、無効な行としてそのまま安全に処理される。荷物の仕分けラインに二つの検査を設けるようなものだ。大きすぎる荷物や、包みが幾重にもなって調べきれない荷物は脇のレーンに直接回し、ほかの荷物は流し続ける。これにより、上限を超えた行や、入れ子が深すぎて RecursionError になる JSON を含む履歴データがあっても読み込みが中断しない。

ko

프로젝트 이름 마스킹이 공유 파일 전체와 차트 및 인사이트에 적용된다

이제 '프로젝트 이름 마스킹'은 내보낸 usage 보고서 전체에 적용되어, 공유할 때 화면에서만 이름을 가리는 데 그치지 않는다. 이전의 HTML 보고서는 화면에서 프로젝트 이름을 숨기면서도 파일 안에는 가려지지 않은 데이터셋을 그대로 담고 있었으나, 이제는 가려지지 않은 사본이 내보내기 파일에서 완전히 제외된다. 이전에는 도넛 차트 범례와 프로젝트 이름 인사이트가 모두 실제 프로젝트 이름을 계속 표시했으나, 이제는 둘 다 마스킹 대상에 포함되어 인사이트 문구가 프로젝트 표의 번호와 일치하는 Project N 으로 바뀐다. 서류의 기밀 이름을 검게 지울 때, 이전에는 먹지 표면만 칠하고 아래에 원본을 남겨 두었다면 이제는 보내기 전에 원본 종이를 완전히 빼내는 것과 같다. 이전 버전에서 내보낸 마스킹 보고서를 공유한 적이 있다면 해당 파일을 마스킹되지 않은 상태로 취급해야 한다.

로컬 파일은 소유자 전용이고 격리 디렉터리에는 명시적 접근 모드를 설정한다

공유 오피스에 개인 물품을 보관할 때 보관함에 자물쇠를 채우는 것뿐만 아니라 보관실 문까지 잠가야 같은 건물의 다른 계정이 내용을 훔쳐볼 수 없다. usage 가 로컬에 생성하는 파일과 디렉터리에 소유자 전용 접근 권한이 적용된다. 기존에는 ~/.usage/, ~/.usage-reports/, ~/Library/Logs/usage/ 아래의 첨부 파일, 내보낸 보고서, 로그가 같은 기기의 다른 로컬 계정에서도 읽을 수 있는 권한으로 생성되었으나, 이제 새 파일은 0600, 디렉터리는 0700 으로 만들어진다. 첨부 파일을 가져올 때도 원본 파일의 권한을 함께 복사하지 않는다. 아울러 격리 디렉터리로 이동된 파일은 이미 소유자 전용 권한을 유지했으나 디렉터리 자체는 그렇지 못했는데, 이제 격리 디렉터리도 생성될 때 명시적인 모드가 지정된다.

긴 JSONL 행에는 상한을 두고 깊은 중첩은 유효하지 않은 행으로 처리한다

이제 JSONL(한 줄마다 JSON 데이터 한 건을 담는 파일 형식) 기록 파일에 비정상적으로 긴 행이 있어도 메모리가 바닥나 읽기 전체가 멈추지 않는다. usage 는 실제 환경에서 측정된 최댓값 23 MB 를 바탕으로 설정된 64 MiB 상한에 맞춰 각 행을 읽으며, 이 한도를 넘어서는 행은 바로 건너뛰고 처리를 이어간다. 중첩이 지나치게 깊어 재귀 오류(RecursionError)를 일으키는 JSON 데이터 역시 유효하지 않은 행으로 간주하여 처리한다. 화물 분류선 입구에 두 가지 검사를 두는 것과 같다. 너무 큰 화물과 포장이 너무 여러 겹이라 검사하기 어려운 화물은 곁길로 바로 보내고, 나머지는 계속 통과시킨다. 이를 통해 64 MiB를 초과하는 행이나 중첩이 너무 깊어 RecursionError를 일으키는 JSON 데이터가 읽기 과정을 가로막지 않는다.
