Usage 0.29.32

發布日期：2026-08-20

繁體中文

新功能

遮蔽專案名稱全面生效，圖表與匯出檔案不洩密

「遮蔽專案名稱」現在會套用至整份匯出 usage 報表，分享時不再只是把名稱藏在畫面上。

過去匯出的 HTML 報表雖然在畫面上隱藏了專案名稱，檔案內部卻仍夾帶未遮蔽的資料集，等於只在螢幕遮住卻沒從檔案拿掉；現在未遮蔽的副本已自匯出檔完全移除。過去圓餅圖圖例與專案名稱深入分析都仍顯示真實專案名稱；現在兩者也一併納入遮蔽，分析文字改為 Project N，對齊專案表格既有的編號。

這像拿黑筆塗黑公文上的機密名稱，以前只塗了複寫紙表面、底層仍夾著原稿；現在則在寄出前把原始底稿徹底抽除。

若你曾分享過舊版產生的遮蔽報表，請將那些檔案視為未遮蔽處理。

新功能

本機檔案限擁有者，隔離目錄明確設定存取模式

在共用辦公室存放私人物品，不只要把置物箱上鎖，放箱子的儲藏室大門也得加鎖，同棟樓的其他帳號才翻看不到內容。

usage 現在為本機建立的檔案與目錄全面套用僅限擁有者的存取權限。

以往存放在 ~/.usage/、~/.usage-reports/ 與 ~/Library/Logs/usage/ 底下的附件、匯出報表與紀錄檔，權限曾允許同部電腦的其他本機帳號讀取；現在新建立的檔案權限一律設為 0600，所屬目錄則設為 0700。匯入附件時也不再複製來源檔案原有的權限。此外，過去移入隔離目錄的檔案雖保有擁有者權限，但目錄本身並未限制；現在該隔離目錄在建立時也會設定明確的存取模式。

新功能

超長行設上限，深層巢狀改列無效行

JSONL（每行各放一筆 JSON 資料的檔案格式）歷史檔案中的異常大行，不再會耗盡記憶體、拖垮整個讀取流程。

usage 現在以 64 MiB 為上限來讀取每行資料，這個數值是根據實測真實環境中 23 MB 的最大記錄所設定；一旦單行資料超過此上限，程式會直接略過它並繼續運作。遇到層層巢狀過深而引發遞迴錯誤（RecursionError）的 JSON 內容，也會直接當成無效行處理。

這像包裹分揀線入口設了兩道檢查：尺寸過大的貨物，以及包裝層數深到難以檢查的貨物，都直接撥到旁道，讓其他包裹繼續前進。

這能防止超過 64 MiB 或因巢狀過深引發 RecursionError 的歷史資料中斷讀取流程。

English

FEATURE

Masking project names covers the full exported file, charts, and insights

The "mask project names" option now applies to the entire exported usage report, rather than merely hiding names on screen when you share it.

Previously, an exported HTML report still carried the unmasked dataset alongside the masked one, hiding project names on screen without actually removing them from the file; that unmasked copy is now completely dropped from exports. Previously, both the donut legend and project-naming insights still showed real project names; both are now covered by the mask, with insights displaying Project N to match the numbering in the project table.

It is like redacting confidential names on a document: earlier releases only blacked out the top carbon copy while leaving the original underneath, but the source sheet is now completely removed before delivery.

If you shared a masked report generated by an earlier version, treat those files as unmasked.

FEATURE

Local files are owner-only; the quarantine directory gets an explicit access mode

When storing personal items in a shared building, locking individual storage bins is not enough; the storage room door itself must be secured so other tenants in the building cannot browse the contents.

usage now creates local files and directories with owner-only access permissions.

Attachments, exported reports, and logs under ~/.usage/, ~/.usage-reports/, and ~/Library/Logs/usage/ were previously created with permissions that let other local accounts on the same machine read them; new files are now 0600 and their directories 0700. Importing attachments also stops copying the source file's existing permissions. Additionally, while files moved into the quarantine directory already kept owner-only permissions, the quarantine directory itself now receives an explicit access mode upon creation.

FEATURE

Oversized JSONL lines are capped; deep nesting is treated as invalid

An oversized line in a JSONL (a file format with one JSON record per line) history file will no longer exhaust memory or derail reading.

Lines are now read against a 64 MiB ceiling, which was set from a measured real-world maximum of 23 MB; whenever a line exceeds this threshold, it is skipped so processing can continue. Deeply nested JSON structures that raise a recursion error (RecursionError) are likewise treated as invalid lines.

It is like a parcel sorting line with two screening checks: items that are too large or wrapped in layers too deep to inspect are sent directly down a side lane, while the rest keeps moving.

This ensures history files containing oversized lines or deeply nested JSON that raises RecursionError cannot derail your usage history.
