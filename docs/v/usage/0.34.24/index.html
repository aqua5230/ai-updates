Usage 0.34.24

發布日期：2026-11-20

繁體中文

新功能

面板新增「楓紅暮色」主題

想替每天點開的畫面換上夕陽配色，現在共有 17 款造型可挑。進到「⚙ 設定 → 更換面板」就能選到「楓紅暮色」。 這款造型在金色到紫色的夕陽裡飄著楓葉，有的落在卡片後面、有的從前面飄過。卡片本身是能透出天空的半透明紫色玻璃，底部兩角還堆著落葉。macOS 開啟「減少動態效果」後，楓葉會停住不動。

新功能

Muse 退訂後會移除額度卡並加快重查

從前帳號沒有續約，只要沒開新的 Muse 對話，usage 就不會主動重查，一直留著最後存下的舊讀數。一旦過了重置時間，額度卡、Claude Code 的額度提示和通知都會把這份舊資料當成還沒用過。 現在 usage 最多每 5 分鐘重跑一次不呼叫模型的 muse usage --json，平常用過 Muse 後約 5 分鐘內就會更新，不必等 30 分鐘。只要 Muse 回報帳號沒有訂閱額度，usage 就會刪掉舊紀錄、不改用 muse exec 呼叫模型，額度卡也隨之消失；等之後再查到額度，卡片就會重新出現。

從前停訂雜誌後，沒再開新刊就沒人去翻信箱，牆上還掛著上期的剩餘期數；現在會定時探頭看訂戶狀態而不拆封試讀，確認退訂就把牌子收起，續訂再掛回去。
新功能

各工具額度讀數與重置狀態更準確

面板出現舊數字或 --，常讓人分不清額度是已重置還是沒讀到。 Codex 過了重置時間，現在比照 Claude Code 和 Antigravity 顯示 0% 與「已重置」，直到下次報出新讀數。以前這兩欄只顯示 --，像讀不到資料。 Muse 因 5 小時額度用完而拒絕時，現在帶有自己的檢查時間。過去沿用上一筆時間，讓卡片像過期、漏發「已用完」通知，也過早重查。 較新的 Codex Spark 讀數不再蓋掉工作階段紀錄裡的一般讀數。不同額度不再合併，一般額度的拒絕不會再顯得過期。 額度感知模式在「Claude Code 自己的額度」補上「（最後更新於…；之後可能已重置）」，舊讀數不會再像最新的。額度感知 hook（特定事件發生時觸發的小程式）更新到 1.20。 各類額度的時間與狀態分清後，看面板剩餘量不用再靠猜。

問題修復

年度帳本與報表數字不再對不攏

升級後回頭對年度明細與熱力圖，現在不用擔心舊紀錄把數字拖偏。 以前重算若跟每日快照相同，會沿用快照缺少版本的紀錄。這讓 token（AI 處理與計費的文字單位）修正前多算的 Antigravity 日子調不下來，現在只剩從快照重播的日子才沿用存下的版本。 年度報表以前先讀或建快取（把算過的結果暫存起來直接用）才存快照，讓明細跟熱力圖不同步、舊資料留存 6 小時。現在會先存快照，確認過舊帳本重算也略過快取。 帳本鎖被別的程序占住太久時，報表以前改讀磁碟帳本卻漏算這次用量還存進快取。現在會在記憶體補進這些日子，也不快取不完整報表。 建不出帳本鎖資料夾時，usage 不再報錯中斷，改比照打不開鎖檔處理。 明細、熱力圖與當次用量都能真正對齊。

問題修復

修復精簡模式不再用舊 hook 蓋掉新版

之前提示檔或設定項目不見了，usage 修補精簡模式會直接拿 app 內附的腳本硬蓋過去，害你自己裝好的新版 hook 反而被退回舊版。現在只有腳本不見或版本較舊時才會替換，其餘只補回缺漏的部分，做法跟修復續談 hook 一樣。

新功能

匯出與重開報表的表格標示更清楚

整理報表匯出存檔，或是重新打開舊報表核對花費，表格上的資訊現在不會漏掉或寫錯。 遇到花費未知的專案，CSV 匯出會寫成破折號，跟模型列一樣。以前會寫成 0.00 讓人誤以為免費，現在 app 直接匯出或存下報表裡的匯出都改過來了。 用「全部」這類日期捷徑匯出的報表，重新打開會直接還原原本的捷徑和歷史說明，不再變成手動選日期範圍。隱藏專案名稱匯出的報表，重開時日期欄也不會再是空的。 模型表裡 Antigravity 的新 Gemini 4 Neon 模型，以前會列出完整 ID，現在跟其他模型一樣改用簡稱「Neon 4」。 以後把報表匯出來對帳或傳給別人看，花費、日期條件跟模型名稱都不會再走樣。

English

FEATURE

New "Maple Dusk" panel theme

If you want a sunset palette for the panel you open every day, there are now 17 themes to choose from. Go to "⚙ Settings → Switch Panel" to select "Maple Dusk". This theme features maple leaves drifting across a gold-to-violet sunset, with some falling behind the cards and others floating in front. The cards themselves are translucent violet glass that lets the sky show through, with fallen leaves piled in both bottom corners. When macOS "Reduce Motion" is turned on, the leaves stop moving.

FEATURE

Muse removes the quota card after unsubscribing and rechecks faster

Previously, if an account did not renew, usage would not actively recheck as long as no new Muse conversation was opened, keeping the last saved old reading. Once the reset time passed, the quota card, Claude Code's quota prompt, and notifications all treated that old data as unused. Now usage reruns the model-free muse usage --json at most every 5 minutes, so after regular Muse use it updates within about 5 minutes instead of waiting 30 minutes. Whenever Muse reports that the account has no subscription quota, usage deletes the old record without falling back to calling a model with muse exec, and the quota card disappears; once quota is found again later, the card reappears.

Previously, after canceling a magazine subscription, nobody checked the mailbox unless a new issue was opened, leaving the remaining issue count from the last issue hanging on the wall; now someone peeks at the subscriber status on a schedule without unsealing a sample copy, takes down the sign once cancellation is confirmed, and hangs it back up upon renewal.
FEATURE

More accurate quota readings and reset states across tools

When old numbers or -- appear in the panel, it is often hard to tell whether a quota has reset or could not be read. Once Codex passes its reset time, it now matches Claude Code and Antigravity by showing 0% and "Reset" until a new reading is reported. Previously, both fields only showed --, looking like unreadable data. When Muse refuses a request because the 5-hour quota is used up, it now carries its own check time. Previously, it reused the previous entry's time, making the card look stale, skipping the "used up" notification, and rechecking too early. Newer Codex Spark readings no longer overwrite general readings in session logs. Different quotas are no longer merged, so a general-quota refusal no longer looks expired. Quota-aware mode adds "(last updated ...; it may have reset since)" to "Claude Code's own quota", so old readings no longer look current. The quota-aware hook (a small program triggered by specific events) is updated to 1.20. With the timing and status of each quota separated clearly, checking remaining amounts in the panel no longer requires guessing.

BUGFIX

Year ledger and report numbers no longer mismatch

When checking annual details and heatmaps after upgrading, you no longer have to worry about old records skewing the numbers. Previously, if a recount matched the daily snapshot, it kept the snapshot's version-less record. That prevented Antigravity days overcounted before the token (the text unit AI processes and bills for) fix from being lowered, whereas now only days replayed from the snapshot keep the stored versions. Previously, the year report read or built its cache before saving the snapshot, causing the details and heatmap to go out of sync and keeping old data for 6 hours. Now it saves the snapshot first, and verified recounts of outdated ledger days also skip the cache. When another process held the ledger lock for too long, the report previously fell back to reading the ledger on disk, omitted this run's usage, and still saved that to the cache. Now it adds those days in memory and does not cache incomplete reports. When usage cannot create the ledger lock folder, it no longer stops with an error and instead handles it the same way as a lock file it cannot open. Details, heatmaps, and current-run usage now truly align.

BUGFIX

Repairing Token Saver no longer overwrites newer hooks with older ones

Previously, when a prompt file or settings entry was missing, repairing Token Saver in usage overwrote things directly with the scripts bundled in the app, downgrading newer hooks you had installed yourself. Now a script is replaced only when it is missing or older, while everything else only has the missing parts restored, the same way the resume hook is repaired.

FEATURE

Clearer table labels when exporting and reopening reports

Whether exporting reports to save or reopening old reports to check spending, table information will no longer be missing or wrong. For projects with unknown cost, CSV exports now write "—", the same as model rows. Previously they wrote 0.00, making them look free; both direct app exports and exports inside saved reports now fix this. Reports exported with a date shortcut like "All" now reopen with the original shortcut and its history note restored instead of turning into a manual date range. Reports exported with hidden project names also no longer have empty date fields when reopened. In the model table, Antigravity's new Gemini 4 Neon models previously listed their full IDs and now use the short name "Neon 4", like the other models. From now on, when you export reports to reconcile expenses or share with others, costs, date criteria, and model names will no longer be distorted.
