Usage 0.34.22

發布日期：2026-11-16

繁體中文

問題修復

Windows 系統匣提示不列隱藏工具

滑鼠移到 Windows 系統匣圖示上，想看各工具額度卻發現排在後面的不見了。過去即使你在「隱藏區塊」藏起 Claude 和 Codex，提示文字仍會硬塞這兩行，把後面的工具擠出 Windows 的 127 字元上限。現在被隱藏的工具不會再出現。唯一保留的是選為「系統匣顯示來源」的工具，因為圖示上顯示的正是它的數字。

新功能

macOS 深色選單列圖示恢復可見

把 macOS Tahoe 螢幕最上方調成暗色外觀後，原本掛在那裡的幾個工具小標誌是不是直接隱形了？之前 Claude、Codex、Antigravity、Grok 與 Muse 的圖示一律畫成黑色，換成深色背景就整個融進去。現在圖示會跟著選單列的文字顏色走，淺色或深色都能看清楚。

問題修復

5 小時額度與通知不被舊讀數拖累

5 小時窗口照理說各自獨立計算，之前只要遇上過期或重置的舊數字，卡片和通知卻常跟著亂套。 Antigravity 週額度更新失敗、只能沿用舊讀數時，過去整張卡會被標成過期，5 小時的燃燒率、通知與窗口保持功能全都停住。現在只有週額度那一列顯示資料放了多久，5 小時那一列照常運作。 額度通知也不再拿重置前的讀數來判斷。過了重置時間後，舊百分比以前還可能發出「已用完」通知，或把下一個窗口的通知擋掉。現在 macOS 與 Windows 上，過了重置時間的窗口都會安靜結束。

月票過期本來不該影響買單程票進站，以前舊數字一過期卻把單程閘門也鎖住，現在各算各的互不干擾。
問題修復

報表未定價與舊紀錄不再誤標 $0

打開報表看到好幾個專案寫著 $0.00，還有一筆「unknown」排在榜首，很容易誤以為沒花到錢或這項目最燒額度。 只用到未定價模型的專案，現在一律改顯示橫線而不是 $0.00，套用日期篩選後也一樣。 模型 ID 整理前留下的舊 Antigravity 歷史，曾保有像 gemini-3.8-flash-n 這類原始 ID。這讓同個模型在報表被列兩次，數十億個 token（AI 處理與計費的文字單位）也被算成 $0。現在這批紀錄會併回整理後的名稱並計價。 2026 年 8 月以前只存下每日總量的用量沒有專案和工具資料，以前被當成「unknown」以 $0.00 排第一。現在它改成排在最底下灰色的「舊紀錄（只剩總數）」，金額顯示未知，趨勢圖圖例也用同一個名稱，百分比不變。

新功能

狀態列開關與跨帳號用量不再錯亂

在 Windows 點了狀態列沒反應，或是換完帳號發現額度百分比還停在舊帳號那邊。 在 Windows 系統匣切換狀態列或安裝 hook（特定事件發生時觸發的小程式）失敗時，現在會直接跳出錯誤提示，不再悄悄沒反應。 換到沒有 5 小時額度的帳號後，狀態列與額度感知模式不再沿用前一個帳號的 5 小時用量。以前這兩個功能會拿舊帳號數字補缺口，讓原本沒有 5 小時額度的帳號顯示成 99% 已用。現在只會用同一個帳號的資料補窗口，狀態列 hook 已更新為 1.19，額度感知 hook 更新為 1.17。 當你讓 Claude Code 用自己的狀態列、只留 Grok 用 usage 的狀態列時，開關現在會正確顯示為開啟。原本它會顯示關閉，按下去反而重新安裝狀態列，而不是關掉 Grok 那邊。

新功能

新舊模型分組與 Mythos 離線定價對齊

各家模型改名、退場或出新版時，清單跟價目表沒跟著動就容易對不上用量。 Antigravity 將於 2026-11-18 下架 GPT-OSS，它已從 Claude 與 GPT 模型群組拿掉。名稱帶有連字號的 Antigravity 群組模型，現在也對得上你的用量紀錄。 Gemini 4 Carbon 在介面上的顯示名稱調整為「Carbon 4」。 使用 Gemini 4 Argon 與 Orchestrator (Argon) 期間，Antigravity 狀態列會顯示 Argon 額度。原本它只會顯示 Claude 與 GPT 群組或 Gemini 群組。 價目表這邊也補上了 Claude Mythos 5 與 Mythos 5.2 的離線價格，價目表檢查同步涵蓋 Mythos 模型。

新功能

新模型偵測不再重複或漏掉提醒

有時才剛看過新模型登場提示，轉頭用 Codex 又再跳一次；換成 Antigravity 推出新模型卻安安靜靜沒通知。 在額度感知模式下，Codex 模型目錄已經記錄過的模型，第一次實際用到時不再從用量紀錄重複提醒一次。 如果第一次掃描 Antigravity 時裡面的模型都已從其他工具認得，usage 現在會記下已經掃描過。往後有新模型出現就不會被當成第一次掃描的一部分，照樣會發出提醒。

點名冊就像店裡的熟客名單，以前看過的名單還會重複唱名、沒登記到的新分店又漏掉新客人，現在都只為真正第一次上門的新面孔報到。
新功能

NO_PROXY 排除 Google 時離線不誤判

電腦有設 proxy（代理伺服器，轉接網路連線的中繼站），又把 Google 列進不走代理的 NO_PROXY 名單，離線時卻被當成已登出嗎？過去即使 Google 登入主機不經由代理連線，usage 只要看到有設代理就當成有網路，結果在離線時執行 Antigravity CLI，把你標成已登出。現在 Google 登入主機被 NO_PROXY 排除時，離線檢查也會正常運作。

就像櫃檯看到你掛了轉接分機就當作外線暢通，沒管直撥號碼不走總機，斷線時直接誤判你離席；現在走直撥也會正常檢查離線狀態。
問題修復

Codex 額度與分支對話不再錯算重讀

只是特定模型被擋下，主畫面的週用量卻跟著跳成滿格；從對話切出去的子工作階段也每次都被重頭讀過。 當 Codex Spark 或 premium 模型這類獨立額度拒絕請求時，卡片以前會把一般週額度也標成用完。現在只有一般 Codex 額度被拒，才會顯示成 100% 已用。 重開舊的 Codex 對話工作階段後如果被拒，卡片過去會停在那個舊讀數，跳過其他工作階段較新的額度。現在會先取最新的讀數，再套用被拒紀錄。 如果你有從對話分岔出去或交給子代理的工作階段，Codex 的磁碟快取（把算過的結果暫存起來直接用）過去每次存檔都會把它們丟掉。現在不會再漏存，也不用每次重新整理都重寫快取、重讀一次。

新功能

報表產生更快，記憶體不再久佔

歷史紀錄越積越多，點開用量報表不只得等上一陣子，關掉後電腦記憶體還像被咬住一樣降不下來。 以前報表是在選單列或系統匣 app 裡直接產生，會把完整歷史再讀一次，讓 app 多佔約 150 MB 記憶體直到重開才會還。現在改由獨立行程產生報表，這個行程結束後就會釋放記憶體。 報表讀取速度也變快了，Claude Code 紀錄改成只讀一次，已刪除的專案資料夾也不再跑 git。一份大量歷史實測從 47 秒降到 32 秒，數字完全相同。

小店把算帳交給外包會計的工作室：以前厚帳本全攤在店裡櫃檯佔位子，現在帳在外面算完就收工，櫃檯立刻空出來。
新功能

超過 30 天被刪的對話仍算活躍日

每天都在用 Claude Code，回頭看報表的連續天數卻莫名其妙斷在一個月前。Claude Code 預設會在 30 天後刪除對話檔，以前那些日子就被當成沒用過，讓活躍日與連續天數跟著斷掉。現在這兩項都會算進去，熱力圖會用最淺的顏色標示。附錄也改名為「數字怎麼算的」，並在「沒算到的用量」底下把這些日期列出來。

跟紙本打卡單滿一個月就碎掉一樣，以前單子一銷毀就把出勤天數歸零，現在總表上仍用淡色補記一筆，全勤紀錄不會平白中斷。
新功能

斜線指令派工對話在報表顯示正常標題

翻舊紀錄想找先前派出去的任務，畫面上卻冒出「<local-command-caveat>The command below」這串字。過去根本看不出那次在忙什麼，現在用斜線指令開頭的派工對話，報表都會顯示正常的標題。

新功能

5 小時選項改名，工作階段改稱計時器

設定選單裡有個選項排在「登入時啟動」正下方，看名字常讓人以為是第二個開機啟動開關。它負責的是在額度重置後立刻開始 5 小時計時器。原名「Auto-start 5-hour Session」改為「Auto-start 5-hour timer」，名稱中的「工作階段」換成「計時器」。實際行為和你的既有設定都不會改變。

English

BUGFIX

Windows tray tooltip drops hidden tools

Hovering over the Windows tray icon to check each tool's quota used to cut off the tools at the end. Even when you hid Claude and Codex under Hide Sections, the tooltip still crammed in their lines and pushed the last tools past Windows' 127-character limit. Hidden tools are now left out. The only one kept is the tool chosen as Tray Display Source, because the icon shows its number.

FEATURE

macOS dark menu bar icons are visible again

After switching the top bar on macOS Tahoe to a dark appearance, did the small tool icons sitting there seem to vanish? Previously, the Claude, Codex, Antigravity, Grok, and Muse icons were always drawn in black, so they blended right into a dark background. They now follow the menu bar's text color, staying clear in both light and dark modes.

BUGFIX

5-hour quotas and alerts stay unaffected by old readings

Each 5-hour window is supposed to be calculated on its own, yet stale or pre-reset numbers used to throw off both the card and notifications. When Antigravity failed to refresh its weekly quota and had to carry over an old reading, the entire card was marked stale, stopping the 5-hour burn rate, notifications, and the window keeper. Now only the weekly row shows how old the data is, while the 5-hour row keeps working. Quota notifications also stop using readings from before a window reset. Past the reset time, an old percentage could still trigger a "used up" alert or block notifications for the next window. On both macOS and Windows, any window past its reset time now ends quietly.

An expired monthly pass should not stop you from buying a single-ride ticket, yet an expired old number used to lock the single-ride gate as well—now each runs on its own without getting in the way.
BUGFIX

Unpriced and old report entries no longer show $0

Opening the report to find several projects listed at $0.00 and an "unknown" entry at the top makes it easy to think nothing was spent or that it burned the most quota. Projects that use only unpriced models now show "—" instead of $0.00, including after date filtering. Older Antigravity history saved before model IDs were cleaned up kept raw IDs such as gemini-3.8-flash-n. That caused the same model to appear twice in the report and left billions of tokens (the text units AI processes and bills for) priced at $0. Those records are now merged into the clean name and priced. Usage saved only as daily totals before August 2026 has no project or tool data, and it used to rank first as "unknown" at $0.00. It now appears at the bottom as a grey "Old records (totals only)" row with an unknown cost, and the trend legend uses the same name while percentages stay unchanged.

FEATURE

Status line switch and cross-account usage stop mixing up

Clicking the status line in Windows could do nothing, or switching accounts could leave your quota percentage stuck on the old account. When toggling the status line or installing a hook (a small program triggered by specific events) fails in the Windows tray, it now shows an error instead of failing silently. After switching to an account without a 5-hour limit, the status line and quota-aware mode no longer carry over the previous account's 5-hour usage. They used to fill the missing window with numbers from the old account, making an account with no 5-hour limit show 99% used. A missing window is now filled only from the same account, with the status-line hook updated to 1.19 and the quota-aware hook to 1.17. When Claude Code uses its own status line and only Grok uses usage's status line, the switch now correctly shows as on. It previously showed as off, and clicking it reinstalled the status line instead of turning Grok's off.

FEATURE

Model groups and Mythos offline pricing aligned

When models are renamed, retired, or newly released, usage stops matching up if the lists and price table fall behind. GPT-OSS, which Antigravity retires on 2026-11-18, has been removed from the Claude and GPT model group. Antigravity group models with hyphenated names now also match your usage logs. Gemini 4 Carbon now displays in the interface as "Carbon 4". While using Gemini 4 Argon and Orchestrator (Argon), the Antigravity status line shows the Argon quota. Previously, it only showed the Claude and GPT group or the Gemini group. Offline prices for Claude Mythos 5 and Mythos 5.2 have been added to the price table, and the price-table check now covers Mythos models as well.

FEATURE

New model detection stops repeating or missing alerts

Sometimes a new-model alert popped up again right after you used Codex, while an actual new Antigravity model triggered no notification at all. In quota-aware mode, a model already recorded in the Codex catalog is no longer announced a second time from usage logs when you first use it. If every model in the first Antigravity scan was already known from other tools, usage now records that the scan took place. Later new models will no longer be treated as part of that first scan and will still be announced.

Think of the roster as a shop's list of regulars: names already on the list used to get called out twice, while an unregistered new branch missed its new arrivals—now only genuine first-time visitors get announced.
FEATURE

Offline check stays accurate when NO_PROXY excludes Google

Have a proxy (an intermediary server that forwards network connections) configured with Google listed in NO_PROXY to bypass it, only to be marked signed out while offline? Previously, even when Google's sign-in host bypassed the proxy, usage assumed you were online just because a proxy was set, so running the Antigravity CLI offline could mark you as signed out. Now the offline check works properly when NO_PROXY excludes Google's sign-in host.

Picture a front desk assuming your outside line works just because an extension is set to forward, ignoring that direct-dial numbers bypass the switchboard and marking you away when disconnected—now direct lines get checked for offline status properly too.
BUGFIX

Codex quotas and forked sessions stop miscounting or rereading

A block on one specific model used to jump the main weekly usage to full, and child sessions branched off a conversation were reread from scratch every time. When a separate limit such as Codex Spark or a premium model refused a request, the card used to mark the regular weekly quota as exhausted too. Now it only shows 100% used when the regular Codex limit is refused. After a refusal in a reopened old Codex session, the card previously stayed on that old reading and skipped newer quota readings from other sessions. It now picks the newest reading first, then applies the refusal. If you have forked sessions or sessions handed off to subagents, the Codex disk cache used to drop them every time it saved. They are no longer left out, avoiding rewriting the cache and rereading them on every refresh.

FEATURE

Reports build faster without holding onto memory

As history grows, opening the usage report not only took a while, it also left your computer's memory stuck high even after closing it. Previously, the report was built inside the menu bar or tray app, loading the full history a second time and adding about 150 MB of memory that stayed until restart. The report is now built in a separate process that frees the memory as soon as it exits. Report loading is faster too: Claude Code logs are now read once instead of twice, and git no longer runs for deleted project folders. On one large history test, build time dropped from 47 to 32 seconds with identical numbers.

A small shop now hands its bookkeeping to an outside accountant's studio: thick ledgers used to stay spread across the shop counter taking up space, whereas now the books are tallied off-site and the counter clears right away.
FEATURE

Conversations deleted after 30 days still count as active days

You use Claude Code every day, yet the streak in your report mysteriously stops a month ago. Claude Code deletes conversation files after 30 days by default, so those days used to count as unused, breaking both your active days and your streak. Now both are counted, and the heatmap marks them in its lightest shade. The appendix is also renamed to "How the numbers are calculated" and lists those dates under "Usage not included".

Paper timecards used to get shredded after a month, resetting attendance counts to zero when the slips were destroyed, whereas the master sheet now adds a faint mark so a perfect attendance record is not broken for no reason.
FEATURE

Slash-command dispatch conversations show proper titles in the report

When you look through old records to find a task you previously dispatched, text like "<local-command-caveat>The command below" appears on screen. It used to be impossible to tell what that run was doing, whereas dispatch conversations starting with a slash command now display proper titles in the report.

FEATURE

5-hour option renamed, changing Session to timer

In the settings menu, an option sits right below "Launch at login", and its name often made it look like a second startup toggle. What it actually does is start the 5-hour timer right after a quota reset. Originally named "Auto-start 5-hour Session", it is renamed to "Auto-start 5-hour timer", replacing "Session" with "timer" in the name. Actual behavior and your existing settings remain unchanged.
