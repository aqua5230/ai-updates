zh-TW

自癒不再把名字像的自製腳本改成官方指令

郵差看到門牌上有「三號」兩個字就把信投進去，結果那是「二十三號」；現在他會確認整個門牌號碼相符才投。你自己留了一份備份檔叫 usage-terse-mode-backup.py，usage 的自癒功能卻把它認成自家的掛鉤（hook，特定事件發生時被觸發的小程式），悄悄改寫成官方指令。原因是它只拿 usage-terse-mode 這串字去比對，名字含這幾個字就算數。移除那條路徑先修好，要求這串字前後得是路徑分隔符號、引號、空白或字串邊界，並且結尾是 .py。現在遷移邏輯裡另外四處判斷要不要覆蓋掛鉤指令的地方，也都改用同一套嚴格比對。

英文單字不再被當成日文或韓文

語言代碼是拿來標示介面該講哪種語言的短代號，ja 是日文、ko 是韓文。usage 判斷代碼時只看開頭幾個字母就算數，於是 jargon 被讀成日文、koala 被讀成韓文。另外幾種寫法也判錯：zh_TW@variant 因為沒有先去掉 @ 後面那段而掉回英文；zh-HK 不像 zh-TW 那樣接受後面再加細分代碼。再查一輪還發現 zh-Hant 和 zh-Hans 有同樣的開頭比對問題，亂編的 zh-Hantasy 也會被當成繁體中文，而缺了 zh-SG- 這個開頭讓合法的 zh-SG-x-private 掉成英文。這段判斷在四個檔案裡各有一份，現在四份都要求開頭之後有明確邊界。查字典時只憑前兩個字母就翻到某一頁，jar 開頭的字全被歸進同一欄；現在得把整個詞對完才算。

終端機編碼不合就整段訊息不見的問題修好了

電線只要有一小段接觸不良，整條走廊的燈都熄掉；現在那截線路獨立起來，其餘照明不受影響。工作階段開始與送出訊息時各有一個掛鉤，終端機用 cp950 這類非 UTF-8 編碼時，它們寫出 JSON 沒有轉成安全字元，會拋出 UnicodeEncodeError，你整段訊息就此消失。現在輸出一律轉成 ASCII 安全的 JSON，寫入動作也包在 try／except OSError 裡。另一個問題在版本標記：四個讀取器用 split 拆字串，遇到被截斷的一行或無效位元組就卡住，壞掉的腳本因此永遠不被認定需要重裝；現在改用 partition，也一併接住 UnicodeDecodeError。還有精簡模式的附屬檔內容爛掉時，只要掛鉤版本沒變就不會重建，因為判斷方式只是看檔案在不在；現在改成驗證內容本身。

續接提示不再因為一個小錯就整段消失

一台機器只要有一個零件卡住就整台停擺；現在那個零件卡住時會單獨跳掉，機器照跑。續接工作階段時 usage 會給你一段提示，講你上次做到哪。以前這段提示很容易整個不見：讀取標準輸入遇到管線斷掉會拋 OSError，但續接不像精簡模式那樣接住它，一個輸入輸出的小狀況就讓掛鉤當掉而不是正常結束。解析工作階段紀錄只接住 OSError，沒接 UnicodeDecodeError，紀錄裡有無效的 UTF-8 位元組時整段提示就消失，不會像遇到空紀錄那樣退回上一份還能用的舊紀錄。現在這兩種狀況都接住了，續接提示照樣出現。

全部做完的待辦清單會清掉，只回一個標點不算數

上次的事情都做完了，下次續接時提示還在報那些已完成的工作。續接掛鉤只有在新清單非空時才覆蓋舊的，而一次工作階段最後那筆 TodoWrite，也就是把每項都標成完成、留下空清單的那一筆，就被忽略了。現在全部項目標記完成後，清單會被清掉。同一批還修了三件事。健康檢查提醒存去重狀態時碰上磁碟滿了或權限不足，錯誤會往外冒把續接提示一起吞掉；現在用 contextlib.suppress(OSError) 框住。判斷回覆有沒有實質內容時，只要文字裡有標點就算數，ok. 或 /clear 這種短回覆因此被留下；現在要求標點兩側都得有字母或數字。另外，git status 給未追蹤目錄的路徑帶著結尾斜線，取檔名得到空字串被默默丟掉，剛建好還沒提交的資料夾因此沒出現在未提交清單裡。清單上每格都打了勾，整張才收走；旁邊只畫了一撇的那格不算填過。

額度回復的通知回來了，一開啟就超標也會提醒

油表警示燈只要指針稍微晃回來就自己熄掉，等真的加滿油了反而沒有任何提示；而上車時油量本來就見底，它也一聲不吭。額度用完後回復時，usage 應該通知你，實際上這則通知一直沒出現。原因是任何低於 100% 的讀數都會把「曾經用完」這個記號清掉，不管跌幅多小；等到真正的重置被認出來，記號早就被先前的小波動清掉了。那個重置指的是一次夠大的單步下降，用來跟雜訊區分開。現在只有那個重置判斷本身會清掉它。另外，警告門檻以前只能靠跟前一筆讀數比較才跨得過去，所以第一次觀測就已經超過門檻的情況完全不會警告，例如程式在你的工作階段進行到 95% 時才啟動。這不像用完的通知，那個第一次讀到 100% 就一定會發。

系統匣選單不再被一個讀取失敗整個拖垮

Windows 上點開選單列的圖示，整個系統匣選單可能整個壞掉打不開。壞的其實只有一列：畫「開機時啟動」那個勾選框時，程式要去讀登錄檔（registry，Windows 存放系統與程式設定的資料庫）確認狀態，而它只接住找不到檔案這一種錯誤。權限不足時錯誤就往外冒，整份系統匣選單跟著垮。現在它接住所有 OSError，那一列直接顯示為未啟用。同一批也清掉一個沒有作用的設定鍵 StartDelay。launchd.plist(5) 根本不認得它，從加進去那天起就沒起過任何作用。儀表板上一顆燈的線路壞了，整片儀表就黑掉；現在那顆燈只顯示未亮，其他讀數照常。

精簡模式的白話規則也管到子代理貼過來的字

導遊全程用大家聽得懂的話講解，換成當地人代講那段時卻整段原話照搬，聽眾一下子跟丟；現在那段也要用同樣的說法轉述。精簡模式（terse mode）要求把話講白，但這條規則以前只管 Claude 自己寫的句子。子代理的回報、工具的原始輸出被直接引用時，模式的提示裡沒有任何指示，裡面的術語就這樣原封不動貼出來，沒人解釋。現在在既有的「術語第一次出現時要解釋」那條規則後面加了一行，五種語言都加了。

en

Self-heal stops taking over your own script that just looks like a hook

A postman drops the letter off because the plate contains "3", when the address is "23"; now he checks that the whole number matches before posting it. You keep your own backup named usage-terse-mode-backup.py, and usage's self-heal treated it as one of its own hooks and silently rewrote it to the official command. The cause was a plain substring check against a marker like usage-terse-mode: any filename containing those characters counted. The removal path was fixed first, requiring a path separator, quote, whitespace, or string boundary around the marker and a trailing .py. The same precise check is now used at the four remaining call sites in the migration logic that decide whether to overwrite a hook's command.

Plain English words are no longer read as Japanese or Korean

A language code is the short tag that says which language the interface should speak: ja for Japanese, ko for Korean. usage matched those with an unbounded prefix test, so jargon was read as Japanese and koala as Korean. Other forms were misread too: zh_TW@variant fell through to English because the part after @ was not stripped, and zh-HK did not accept further subtags the way zh-TW and zh-Hant did. A second pass found the same unbounded-prefix bug in zh-Hant and zh-Hans, letting a nonsense zh-Hantasy match as Traditional Chinese, and a missing zh-SG- prefix that dropped a legitimate zh-SG-x-private to English. This logic was duplicated across four files; all four now require a boundary after every prefix. Looking a word up by its first two letters alone files everything starting with "jar" in one column; now the whole word has to match.

A non-UTF-8 terminal no longer swallows the whole message

One bad contact in the wiring used to darken the whole corridor; that stretch is now isolated, and the rest of the lights stay on. When a terminal uses a non-UTF-8 encoding such as cp950, usage's hooks wrote JSON without escaping, raised UnicodeEncodeError, and lost your entire message. Output is now forced to ASCII-safe JSON, with the write wrapped in try/except OSError. A second problem sat in the version marker: four readers used split and choked on a truncated line or invalid bytes, so a broken installed script was never recognized as needing reinstalling; they now use partition and also catch UnicodeDecodeError. And when a terse-mode sidecar's content had rotted, it was never rebuilt as long as the hook version was unchanged, because staleness was checked with a plain exists(); it is now checked by validating the sidecar's content.

The resume prompt no longer vanishes over one small failure

One jammed part used to stop the entire machine; now that part trips on its own and the machine keeps running. When you resume a session, usage gives you a prompt saying where you left off, and that prompt used to disappear whole. _read_stdin_utf8() could raise OSError on a broken pipe and, unlike terse mode and the terse reminder, session resume did not catch it, so an I/O hiccup crashed the hook instead of exiting 0. _parse_session() caught OSError but not UnicodeDecodeError, so a session log with invalid UTF-8 bytes made the whole resume prompt vanish instead of falling through to the next older, valid log the way an empty log already did. Both are now caught, and the resume prompt still appears.

A finished todo list gets cleared, and a lone punctuation reply does not count

Everything from last time was finished, yet the next resume prompt kept reporting that work. The resume hook only overwrote its stored todo list when the new one was non-empty, so the last TodoWrite call of a session — the one that marks everything complete, leaving an empty list — was ignored. A todo list is now cleared once every item on it is marked done. Three more fixes landed alongside it. Saving the health-check reminder's dedup state could raise OSError on a full disk or a permissions error, and that exception propagated far enough to swallow the main resume prompt; it is now scoped with contextlib.suppress(OSError). _has_structural_signal treated any punctuation anywhere in the text as a sign of real content, so short replies like ok. or /clear were kept as if they were substantive; it now requires alphanumeric characters on both sides of the mark. And git status's trailing slash on an untracked directory path made basename return an empty string, which was silently dropped, so a brand-new uncommitted folder never appeared in the uncommitted-work summary. Only when every box on the sheet is ticked does the sheet get taken away; a stray stroke beside a box does not count as filled in.

The quota-restored notification is back, and a first reading past the threshold warns

A fuel warning light that goes out the moment the needle twitches back says nothing when the tank is actually refilled, and stays silent when you get in with the tank already low. usage is supposed to tell you when depleted quota comes back, and that notification never fired. Any reading below 100% cleared the "was depleted" flag, regardless of how small the drop was, so by the time a genuine reset was detected — a single-step drop large enough to distinguish a real period rollover from noise — the flag had already been cleared by an earlier, tiny fluctuation. It is now cleared only by that same reset detection. Separately, a warning threshold could only be crossed relative to a previous reading, so quota that was already above the threshold on the very first observation — the app launching mid-session at 95%, for instance — produced no warning at all, unlike the depleted notification, which always fires on a first reading of 100%.

One registry read failure no longer takes down the tray menu

On Windows, clicking the menu bar icon could leave the whole tray menu broken. Only one row was actually at fault: to draw the "launch at login" checkbox, the app reads the registry, the database where Windows keeps system and program settings, and its is_enabled() caught only FileNotFoundError. A registry permission error therefore propagated out and could break the whole tray menu instead of just that one row; it now catches any OSError and reports "not enabled." The same batch removed a dead settings key, StartDelay: launchd.plist(5) does not recognize it, so it had no effect and was doing nothing since it was added. When the wiring behind one dashboard lamp failed, the entire panel went dark; now that lamp simply shows unlit and the other readings stay up.

Terse mode's plain-language rule now covers text pasted from a subagent

A guide explains everything in words the group follows, then quotes a local speaker verbatim for one stretch and loses the group; now that stretch has to be relayed in the same plain words. Terse mode asks for plain language, but the rule used to govern only sentences Claude wrote itself. When a subagent's report or a tool's raw output was quoted directly, the mode's own prompt gave no instruction for it, so jargon inside went unexplained. A line was added after the existing "explain a term on first use" rule, in all five languages.

续接提示不再因为一个小错就整段消失

一台机器只要有一个零件卡住就整台停摆；现在那个零件卡住时会单独跳掉，机器照跑。续接会话时 usage 会给你一段提示，讲你上次做到哪。以前这段提示很容易整个不见：读取标准输入遇到管线断掉会抛 OSError，但续接不像简洁模式那样接住它，一个输入输出的小状况就让挂钩崩掉而不是正常结束。解析会话记录只接住 OSError，没接 UnicodeDecodeError，记录里有无效的 UTF-8 字节时整段提示就消失，不会像遇到空记录那样退回上一份还能用的旧记录。现在这两种状况都接住了，续接提示照样出现。

全部做完的待办清单会清掉，只回一个标点不算数

上次的事情都做完了，下次续接时提示还在报那些已完成的工作。续接挂钩只有在新清单非空时才覆盖旧的，而一次会话最后那笔 TodoWrite，也就是把每项都标成完成、留下空清单的那一笔，就被忽略了。现在全部项目标记完成后，清单会被清掉。同一批还修了三件事。健康检查提醒存自己的去重状态时若碰上磁盘满了或权限不足，那个错误会一路往外冒，把主要的续接提示一起吞掉；现在用 contextlib.suppress(OSError) 框住。判断回复有没有实质内容时，只要文字里有任何标点就算数，于是 ok. 或 /clear 这种短回复被留了下来，现在要求标点两侧都得有字母或数字。另外，git status 给未跟踪目录的路径带着结尾斜线，取文件名得到空字符串被默默丢掉，刚建好还没提交的文件夹因此没出现在未提交清单里。清单上每格都打了勾，整张才收走；旁边只画了一撇的那格不算填过。

额度恢复的通知回来了，一开启就超标也会提醒

油表警示灯只要指针稍微晃回来就自己熄掉，等真的加满油了反而没有任何提示；而上车时油量本来就见底，它也一声不吭。额度用完后恢复时，usage 应该通知你，实际上这则通知一直没出现。原因是任何低于 100% 的读数都会把「曾经用完」这个记号清掉，不管跌幅多小；等到真正的重置被认出来，记号早就被先前的小波动清掉了。那个重置指的是一次够大的单步下降，用来跟噪声区分开。现在只有那个重置判断本身会清掉它。另外，警告门槛以前只能靠跟前一笔读数比较才跨得过去，所以第一次观测就已经超过门槛的情况完全不会警告，例如程序在你的会话进行到 95% 时才启动。这不像用完的通知，那个第一次读到 100% 就一定会发。

系统托盘菜单不再被一个读取失败整个拖垮

简洁模式的白话规则也管到子代理贴过来的字

自己修復が名前の似た自作スクリプトを乗っ取らなくなる

郵便配達が表札に「3」とあるだけで投函してしまうが、実際の住所は「23」だった。今は番地全体が一致することを確かめてから入れる。自分で usage-terse-mode-backup.py というバックアップを置いていると、usage の自己修復がそれを自前のフック（特定の出来事で起動する小さなプログラム）と見なし、黙って公式のコマンドに書き換えていた。原因は usage-terse-mode という目印を単純な部分一致で調べていたことにある。ファイル名にその文字が含まれるだけで該当と判定されていた。削除の経路が先に修正され、目印の前後がパス区切り、引用符、空白、文字列の端のいずれかであり、末尾が .py であることを求めるようになった。移行処理の中でフックのコマンドを上書きするか判断する残り四か所も、今は同じ厳密な判定を使う。

英単語が日本語や韓国語と誤読されなくなる

言語コードとは、画面をどの言語で表示するかを示す短い記号である。ja は日本語、ko は韓国語を指す。usage は先頭の数文字が一致すれば該当と判定していたため、jargon が日本語、koala が韓国語と読まれていた。他の書き方も誤判定していた。zh_TW@variant は @ 以降を先に取り除かないため英語へ落ち、zh-HK は zh-TW のように後ろへ細分の記号を足した形を受け付けなかった。追加調査で zh-Hant と zh-Hans にも同じ先頭一致の不具合が見つかり、でたらめな zh-Hantasy まで繁体字中国語と判定されていた。さらに zh-SG- の前置きが抜けており、正当な zh-SG-x-private が英語へ落ちていた。この判定は四つのファイルに重複しており、今はすべてが前置きの直後に明確な区切りを求める。辞書を最初の二文字だけで引くと、jar で始まる語が同じ欄にまとめられてしまう。今は語全体を照合する。

端末の文字コードが違うだけでメッセージが丸ごと消えなくなる

配線の一か所が接触不良なだけで廊下の照明が全部消えていた。今はその区間が切り離され、残りの明かりは影響を受けない。端末が cp950 のような非 UTF-8 の文字コードを使うと、usage のフックは変換せずに JSON を書き出し、UnicodeEncodeError を投げてメッセージが丸ごと失われていた。現在は出力を必ず ASCII で安全な JSON に変換し、書き込みも try／except OSError で包む。もう一つの問題はバージョン標識にある。四つの読み取り処理が split を使い、途中で切れた行や不正なバイトでつまずくため、壊れた導入済みスクリプトが再インストール対象と認識されなかった。今は partition を使い、UnicodeDecodeError も受け止める。さらに簡潔モードの付随ファイルは中身が壊れても、フックのバージョンが変わらない限り作り直されなかった。存在するかどうかだけで判定していたためで、今は中身そのものを検証する。

再開時の案内が小さな失敗一つで消えなくなる

部品が一つ引っ掛かるだけで機械全体が止まっていた。今はその部品だけが単独で外れ、機械は動き続ける。セッションを再開すると、usage は前回どこまで進んだかを伝える案内を出す。以前はこの案内が丸ごと消えやすかった。標準入力の読み取りはパイプが切れると OSError を投げるが、再開処理は簡潔モードのようにそれを受け止めず、入出力の小さな不調でフックが落ちて正常終了しなかった。セッション記録の解析は OSError は受け止めても UnicodeDecodeError は受け止めず、不正な UTF-8 のバイトを含む記録があると案内全体が消え、空の記録のときのように一つ前の有効な記録へ下がることもなかった。今はどちらも受け止められ、再開の案内はそのまま出る。

すべて終えた作業リストは消え、記号だけの返信は本文と見なされない

前回の作業はすべて終えたはずなのに、次の再開案内が終わった仕事を報告し続けていた。再開フックは新しいリストが空でないときだけ保存済みリストを上書きしていたため、セッション最後の TodoWrite、つまり全項目を完了に印して空のリストを残す呼び出しが無視されていた。今は全項目が完了になった時点でリストが消える。同じ回で三点も直った。健康チェックの重複防止状態を保存する際にディスク不足や権限エラーが起きると、その例外が外まで伝わって主要な再開の案内ごと飲み込んでいた。今は contextlib.suppress(OSError) で囲っている。返信に実質的な内容があるかの判定は、文中のどこかに記号があるだけで内容ありと見なしていたため、ok. や /clear のような短い返信が残っていた。今は記号の両側に英数字があることを求める。また git status が未追跡ディレクトリのパス末尾に付ける斜線のせいでファイル名の取得が空文字となり、黙って捨てられていた。作ったばかりで未コミットのフォルダが一覧に出なかったのはこのためである。用紙のすべての枠にチェックが入って初めて用紙が回収される。枠の脇の走り書きは記入と見なさない。

残量回復の通知が復活し、起動直後に超えていても警告が出る

燃料の警告灯が針の少しの揺り戻しで消えてしまうと、実際に満タンにしても何も知らせず、乗り込んだ時点で既に残り少なくても黙ったままになる。使い切った残量が戻ったとき、usage は通知するはずだったが、その通知はずっと出ていなかった。100% を下回る読み取りは、下げ幅がどれほど小さくても「使い切った」という印を消していたためである。本物のリセットが検出される頃には、つまり雑音と区別できるだけの大きな一段の下降が来る頃には、印は先の小さな揺らぎで既に消えていた。今はそのリセット検出だけが印を消す。また警告のしきい値は前回の読み取りとの比較でしか超えられなかったため、最初の観測時点で既にしきい値を超えている場合、たとえば 95% の時点でアプリが起動した場合には警告が出なかった。100% を最初に読んだ時点で必ず発火する使い切りの通知とは対照的である。

レジストリの読み取り失敗でトレイメニュー全体が落ちなくなる

Windows でメニューバーのアイコンを押すと、トレイメニュー全体が壊れて開かないことがあった。実際に不調なのは一行だけである。「ログイン時に起動」のチェックボックスを描くために、アプリはレジストリ、つまり Windows が設定を保管するデータベースを読みに行くが、その処理はファイルが見つからない場合しか受け止めていなかった。権限のエラーはそのまま外へ伝わり、その一行だけでなくメニュー全体を壊し得た。今はあらゆる OSError を受け止め、その行を「未有効」と表示する。同じ回で効果のない設定キー StartDelay も削除された。launchd.plist(5) はこのキーを認識しないため、追加された日から何の働きもしていなかった。計器盤のランプ一つの配線が壊れただけで盤面全体が暗転していた。今はそのランプが消灯と表示されるだけで、他の数値は出続ける。

簡潔モードの平易な言葉の規則がサブエージェントの引用にも及ぶ

ガイドが終始かみ砕いた言葉で説明していたのに、地元の話し手の一節だけをそのまま引用して聴衆を置き去りにする。今はその一節も同じ平易な言葉で伝え直す。簡潔モードは平易な言葉を求めるが、この規則は以前、Claude 自身が書いた文だけを対象としていた。サブエージェントの報告やツールの生の出力をそのまま引用する場合、モードの指示には何も書かれておらず、その中の専門用語は説明されないまま貼られていた。今回、既存の「用語は初出時に説明する」という規則の後に一行が追加された。五言語すべてに入っている。

ko

자가 복구가 이름만 비슷한 자작 스크립트를 덮어쓰지 않는다

집배원이 문패에 「3」이 있다는 이유로 편지를 넣지만 실제 주소는 「23」이었다. 이제는 번지 전체가 맞는지 확인한 뒤에 넣는다.직접 만들어 둔 usage-terse-mode-backup.py라는 백업 파일을 usage의 자가 복구가 자기 훅(특정 사건이 일어날 때 실행되는 작은 프로그램)으로 여겨 조용히 공식 명령으로 덮어썼다. 원인은 usage-terse-mode라는 표식을 단순 부분 일치로만 검사한 데 있다. 파일 이름에 그 글자가 들어 있기만 하면 해당된다고 판정했다. 제거 경로가 먼저 고쳐져, 표식 앞뒤가 경로 구분자, 따옴표, 공백, 문자열 경계 중 하나이고 끝이 .py여야 한다고 요구한다. 훅 명령을 덮어쓸지 판단하는 이관 로직의 나머지 네 군데도 이제 같은 엄격한 검사를 쓴다.

영어 단어가 일본어나 한국어로 잘못 읽히지 않는다

언어 코드는 화면을 어느 언어로 보여 줄지 나타내는 짧은 기호다. ja는 일본어, ko는 한국어를 가리킨다. usage는 앞 몇 글자만 맞으면 해당된다고 판정해서 jargon이 일본어로, koala가 한국어로 읽혔다. 다른 표기도 잘못 읽혔다. zh_TW@variant는 @ 뒤를 먼저 떼어 내지 않아 영어로 떨어졌고, zh-HK는 zh-TW처럼 뒤에 세부 기호를 더 붙인 형태를 받아들이지 못했다. 다시 살펴보니 zh-Hant와 zh-Hans에도 같은 앞자리 일치 문제가 있어 엉터리인 zh-Hantasy까지 번체 중국어로 판정됐다. 또 zh-SG- 접두가 빠져 정당한 zh-SG-x-private가 영어로 떨어졌다. 이 판정 코드는 네 개 파일에 각각 들어 있었고, 이제 네 곳 모두 접두 뒤에 분명한 경계를 요구한다. 사전을 앞 두 글자만 보고 펼치면 jar로 시작하는 말이 한 칸에 몰린다. 이제는 단어 전체를 맞춰야 한다.

터미널 인코딩이 달라 메시지가 통째로 사라지던 문제를 고침

배선 한 군데가 접촉이 나쁘다는 이유로 복도 조명이 전부 꺼졌다. 이제 그 구간이 따로 분리되어 나머지 불은 영향을 받지 않는다.터미널이 cp950 같은 비 UTF-8 인코딩을 쓰면 usage의 훅이 변환 없이 JSON을 써서 UnicodeEncodeError가 나고 메시지가 통째로 사라졌다. 이제 출력은 반드시 ASCII로 안전한 JSON으로 바꾸고, 쓰기도 try／except OSError로 감싼다. 다른 문제는 버전 표식에 있었다. 네 개의 읽기 처리가 split을 써서 잘린 줄이나 잘못된 바이트에 걸렸고, 망가진 설치본이 재설치 대상으로 인식되지 못했다. 이제는 partition을 쓰고 UnicodeDecodeError도 함께 받아 낸다. 또 간결 모드의 딸림 파일은 내용이 망가져도 훅 버전이 그대로면 다시 만들어지지 않았다. 파일이 있는지만 보고 판단했기 때문이며, 이제는 내용 자체를 검증한다.

이어가기 안내가 작은 실패 하나로 사라지지 않는다

부품 하나가 걸렸다고 기계 전체가 멈췄다. 이제 그 부품만 따로 떨어져 나가고 기계는 계속 돈다.세션을 이어갈 때 usage는 지난번에 어디까지 했는지 알려 주는 안내를 띄운다. 예전에는 이 안내가 통째로 사라지기 쉬웠다. 표준 입력 읽기는 파이프가 끊기면 OSError를 던지는데, 이어가기 처리는 간결 모드처럼 그것을 받아 내지 않아 작은 입출력 문제에도 훅이 죽고 정상 종료하지 못했다. 세션 기록 파싱은 OSError는 받아 냈지만 UnicodeDecodeError는 받지 못해, 잘못된 UTF-8 바이트가 든 기록이 있으면 안내 전체가 사라졌고, 빈 기록일 때처럼 바로 앞의 유효한 기록으로 물러나지도 않았다. 이제는 둘 다 받아 내어 이어가기 안내가 그대로 뜬다.

전부 끝난 할 일 목록은 지워지고, 기호뿐인 답은 본문으로 치지 않는다

지난번 일은 다 끝냈는데도 다음 이어가기 안내가 끝난 작업을 계속 알려 줬다. 이어가기 훅이 새 목록이 비어 있지 않을 때만 저장된 목록을 덮어썼기 때문에, 세션 마지막의 TodoWrite, 곧 모든 항목을 완료로 표시해 빈 목록을 남기는 호출이 무시됐다. 이제 모든 항목이 완료로 표시되면 목록이 지워진다. 같은 회차에 세 가지가 더 고쳐졌다. 건강 점검 알림의 중복 방지 상태를 저장하다 디스크가 꽉 차거나 권한 오류가 나면 그 예외가 바깥까지 번져 주요 이어가기 안내까지 삼켰다. 이제는 contextlib.suppress(OSError)로 감쌌다. 답에 실질적인 내용이 있는지 판단할 때 글 안 어디든 기호가 있기만 하면 내용이 있다고 봐서 ok.나 /clear 같은 짧은 답이 남았다. 이제는 기호 양쪽에 영문자나 숫자가 있어야 한다고 요구한다. 또 git status가 추적되지 않은 디렉터리 경로 끝에 붙이는 빗금 때문에 파일 이름을 얻으면 빈 문자열이 되어 조용히 버려졌다. 막 만들고 커밋하지 않은 폴더가 목록에 나오지 않던 이유가 이것이다. 용지의 모든 칸에 체크가 들어가야 용지를 걷어 간다. 칸 옆에 그은 획 하나는 기입으로 치지 않는다.

잔량 회복 알림이 돌아오고, 켜자마자 기준을 넘었어도 경고한다

연료 경고등이 바늘이 조금 되돌아왔다고 꺼져 버리면, 실제로 가득 채워도 아무 말이 없고 탈 때부터 이미 바닥이어도 조용하다.다 쓴 잔량이 회복되면 usage가 알려 줘야 하는데, 그 알림이 계속 뜨지 않았다. 100% 아래의 어떤 읽기든, 떨어진 폭이 아무리 작아도 「다 썼음」 표시를 지웠기 때문이다. 진짜 초기화가 감지될 무렵, 곧 잡음과 구분될 만큼 큰 한 단계 하락이 올 무렵에는 그 표시가 앞선 작은 흔들림에 이미 지워져 있었다. 이제는 그 초기화 감지만이 표시를 지운다. 또 경고 기준은 이전 읽기와 비교해야만 넘을 수 있어서, 첫 관측 때 이미 기준을 넘은 경우, 예컨대 95%인 시점에 앱이 켜진 경우에는 경고가 전혀 없었다. 처음 100%를 읽으면 반드시 발생하는 소진 알림과는 달랐다.

레지스트리 읽기 실패로 트레이 메뉴 전체가 죽지 않는다

Windows에서 메뉴 막대 아이콘을 눌렀을 때 트레이 메뉴 전체가 망가져 열리지 않는 일이 있었다. 실제로 문제가 있는 것은 한 줄뿐이다. 「로그인 시 실행」 체크박스를 그리려고 앱이 레지스트리, 곧 Windows가 설정을 보관하는 데이터베이스를 읽는데, 그 처리는 파일을 찾지 못한 경우만 받아 냈다. 권한 오류는 그대로 바깥으로 번져 그 한 줄이 아니라 메뉴 전체를 망가뜨릴 수 있었다. 이제는 모든 OSError를 받아 내고 그 줄을 「사용 안 함」으로 표시한다. 같은 회차에 효과 없는 설정 키 StartDelay도 지워졌다. launchd.plist(5)가 이 키를 알아보지 못해, 추가된 날부터 아무 일도 하지 않았다. 계기판 램프 하나의 배선이 망가졌다고 판 전체가 꺼졌다. 이제 그 램프만 꺼짐으로 표시되고 다른 수치는 계속 나온다.

간결 모드의 쉬운 말 규칙이 서브에이전트 인용까지 다룬다

안내인이 내내 알아듣기 쉬운 말로 설명하다가 현지 화자의 한 대목만 그대로 옮겨 읽어 청중을 놓친다. 이제 그 대목도 같은 쉬운 말로 다시 전한다.간결 모드는 쉬운 말을 요구하지만, 이 규칙은 예전에 Claude가 직접 쓴 문장만 다뤘다. 서브에이전트의 보고나 도구의 원본 출력을 그대로 인용할 때는 모드의 지시에 아무 내용이 없어, 그 안의 전문 용어가 설명 없이 붙었다. 이번에 기존의 「용어는 처음 나올 때 설명한다」 규칙 뒤에 한 줄이 추가됐다. 다섯 언어 모두에 들어갔다.

**Language detection no longer misreads plain English words as Japanese or Korean, or a made-up Chinese-script tag as a real one.** The `_normalize_lang` logic — duplicated across four files — matched `ja`/`ko` with an unbounded `startswith`, so `jargon` and `koala` were read as Japanese and Korean; a POSIX `@modifier` suffix wasn't stripped, so `zh_TW@variant` fell through to English; and `zh-HK` didn't accept further BCP 47 subtags the way `zh-TW`/`zh-Hant` did. A second pass found the same unbounded-prefix bug in `zh-Hant`/`zh-Hans` (letting a nonsense `zh-Hantasy` match as Traditional Chinese) and a missing `zh-SG-` prefix (dropping a legitimate `zh-SG-x-private` tag to English). All four duplicated copies now require a boundary after every prefix.
Original changelog
**A non-UTF-8 terminal no longer crashes terse mode or session resume, and a truncated or corrupted version marker no longer wedges self-heal.** The SessionStart/UserPromptSubmit hooks wrote JSON without `ensure_ascii`, so a terminal using an encoding like cp950 raised `UnicodeEncodeError` and lost the entire message; output is now forced to ASCII-safe JSON with the write wrapped in `try`/`except OSError`. The four version-marker readers used `split` and choked on a truncated line or invalid bytes, which meant a broken installed script was never recognized as needing reinstalling; they now use `partition` and also catch `UnicodeDecodeError`. Separately, a stale terse-mode sidecar whose content had rotted was never rebuilt as long as the hook version hadn't changed, because staleness was checked with a plain `exists()`; it's now checked by validating the sidecar's content.
Original changelog
**Session resume's stdin and stdout failures are handled the same way its sibling hooks already were, and a corrupted newest session log falls back to an older one instead of going silent.** `_read_stdin_utf8()` could raise `OSError` on a broken pipe, and unlike terse mode and the terse reminder, session resume didn't catch it — an I/O hiccup crashed the hook instead of exiting 0. Separately, `_parse_session()` caught `OSError` but not `UnicodeDecodeError`, so a session log with invalid UTF-8 bytes made the whole resume prompt disappear instead of falling through to the next older, valid log the way an empty log already did.

**A todo list is now cleared once every item on it is marked done.** The resume hook only overwrote its stored todo list when the new one was non-empty, so the last `TodoWrite` call of a session — the one that marks everything complete, leaving an empty list — was ignored, and the next session's resume prompt kept reporting work that was already finished.
**The health-check reminder's own state write no longer takes the whole resume prompt down with it, a bare punctuation reply is no longer read as a real request, and a newly created but uncommitted directory now shows up in the "not saved yet" list.** Saving the health-check reminder's dedup state could raise `OSError` (a full disk, a permissions error) and that exception propagated out far enough to swallow the main resume prompt along with it; it's now scoped with `contextlib.suppress(OSError)`. Separately, `_has_structural_signal` treated any punctuation anywhere in the text as a sign of real content, so short replies like `ok.` or `/clear` were kept as if they were substantive; it now requires alphanumeric characters on both sides of the mark. And `git status`'s trailing slash on an untracked directory path made `basename` return an empty string, which was silently dropped, so a brand-new uncommitted folder never appeared in the uncommitted-work summary.

**The quota-restored notification fires again, and a warning now fires on the very first reading if quota is already past the threshold.** Any reading below 100% cleared the "was depleted" flag, regardless of how small the drop was, so by the time a genuine reset was detected — a single-step drop large enough to distinguish a real period rollover from noise — the flag had already been cleared by an earlier, tiny fluctuation, and the restored notification never fired. It's now cleared only by that same reset detection. Separately, a warning threshold could only be crossed relative to a previous reading, so quota that was already above the threshold on the very first observation — for instance, the app launching mid-session at 95% — produced no warning at all, unlike the depleted notification, which always fires on a first reading of 100%.
