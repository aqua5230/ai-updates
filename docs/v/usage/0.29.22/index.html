zh-TW

自訂 Codex 資料夾不再變成空白頁

你把 Codex 資料放到另一個地方時，usage 原本可能把它當成不存在，畫面只留空白的 Codex 區塊，還不告訴你原因。問題出在 CODEX_HOME 環境變數（程式啟動前交給它的隱藏設定）：它本來能指定 Codex 資料夾，適合多個帳號或容器化設定，但 usage 裡讀取資料的七個入口仍死盯著預設的 ~/.codex/。像搬家後把新住址寫在信封上，七位送件員卻全往舊址跑。現在它們先交給同一個 codex_paths.codex_home() 幫手確認地址；有 CODEX_HOME 就照它找，沒設才回到 ~/.codex/。因此自訂資料夾的使用者能重新看到 Codex 資料。

en

Custom Codex data folders no longer look empty

If you keep Codex data somewhere other than its default folder, usage could previously treat it as nonexistent: the Codex section appeared empty, with no explanation. The culprit was the CODEX_HOME environment variable, a hidden setting supplied before a program starts. It can point to a Codex data folder for multiple accounts or containerized setups, but seven places in usage that read the data were still hardcoded to ~/.codex/. It was like moving house, updating your address, and having seven delivery drivers continue to visit the old one. They now all ask the same codex_paths.codex_home() helper for directions: use CODEX_HOME when set, otherwise fall back to ~/.codex/. Your custom-folder data can show up again.

自定义 Codex 数据文件夹不再变成空白页

当你把 Codex 数据放到别处，usage 以前可能把它当成不存在，界面只留下空白的 Codex 区块，也不说明原因。问题出在 CODEX_HOME 环境变量（程序启动前交给它的隐藏设置）：它本来可以指定 Codex 数据文件夹，适合多个账号或容器化设置，但 usage 中读取数据的七个入口仍死盯着默认的 ~/.codex/。这像搬家后把新地址写在信封上，七位投递员却全跑去旧址。现在它们先交给同一个 codex_paths.codex_home() 助手确认地址；设了 CODEX_HOME 就按它寻找，没设才回到 ~/.codex/。因此使用自定义文件夹的人又能看到 Codex 数据。

ja

自分で指定した Codex のデータフォルダが空扱いされなくなった

Codex のデータを標準以外の場所に置くと、usage は以前それを存在しないものとして扱い、理由も示さず Codex の欄を空白にしていた。原因は CODEX_HOME 環境変数である。これはプログラム起動前に渡す隠し設定で、複数アカウントやコンテナ化した環境では Codex のデータフォルダを指定できる。しかし usage でデータを読む七つの入口は、なお ~/.codex/ に固定されていた。引っ越して新住所を届けたのに、七人の配達員が皆まだ旧住所へ向かうようなものだった。今は全員が codex_paths.codex_home() に住所を確認し、CODEX_HOME があればそれを使い、なければ ~/.codex/ へ戻る。自分で指定したフォルダのデータも再び表示される。

ko

사용자 지정 Codex 데이터 폴더가 빈 것으로 처리되지 않는다

Codex 데이터를 기본 위치 아닌 다른 곳에 두면, usage는 예전에는 그 데이터를 없는 것으로 여겨 이유 설명 없이 Codex 영역을 빈칸으로 남겼다. 원인은 CODEX_HOME 환경 변수였다. 이는 프로그램을 시작하기 전에 전달하는 숨은 설정으로, 여러 계정이나 컨테이너 환경에서 Codex 데이터 폴더를 지정할 수 있다. 하지만 usage에서 데이터를 읽는 일곱 경로는 여전히 ~/.codex/만 고정해 보고 있었다. 이사 후 새 주소를 알렸는데 일곱 명 배달원이 모두 옛집으로 가는 셈이었다. 이제 모두 codex_paths.codex_home() 도우미에게 주소를 물어본다. CODEX_HOME이 있으면 그곳을 쓰고, 없을 때만 ~/.codex/로 돌아간다. 직접 지정한 폴더의 Codex 데이터도 다시 표시된다.

原始 CHANGELOG

Original changelog
**Codex data was unreadable for anyone with a custom `CODEX_HOME`.** Every path into Codex's local data (`codex_loader.py`, `adapters/codex.py`, `session_hooks.py`, `setup_hook.py`, `fsevents_watch.py`, `menubar_state.py`, `analyzer/subscription.py`) was hardcoded to `~/.codex/...`, so anyone who set the `CODEX_HOME` environment variable — multiple accounts, containerized setups — got an empty Codex section with no explanation. All of them now resolve through a single `codex_paths.codex_home()` helper that honors `CODEX_HOME` and falls back to `~/.codex/` when it's unset.
