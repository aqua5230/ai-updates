Usage 0.34.23

發布日期：2026-11-19

繁體中文

新功能

報表與年度帳本的歷史紀錄更準確

翻開歷史報表核對用量，現在不用擔心數字卡在舊紀錄或被覆蓋。 Antigravity 計數修正前存下的舊日子，token（AI 處理與計費的文字單位）總數偏高，過去因為快照只在新數字不小於舊紀錄時才替換而換不進去。現在快照會記下計數版次，只要當天所有工作階段與其他工具紀錄還在本機，就換成修正數字。年度帳本等快照換好才更新，報表也不再補回舊差額。 報表與背景更新在不同行程同時寫入 year_ledger.json 時，過去會互相蓋掉剛存下或補回的日子。現在帳本旁會建鎖檔，一次只讓一個行程讀取、合併並寫回。別的行程佔鎖超過 10 秒就跳過等下次補，沒拿到鎖不寫入。 「全部」報表過去從有 token 用量的第一天起算，漏掉更早只有活躍紀錄的日子。現在改從最早有用量或活躍紀錄那天開始，日期篩選器也選得到。

新功能

專案分類與報表匯出檔名更清楚

匯出專案排行或翻找幾個月前的報表檔案，標籤和檔名常讓人一頭霧水。 匯出專案 CSV 過去先取前 10 名才挑出只剩總數的舊紀錄，第 10 名專案會被擠掉。現在比照報表畫面先挑出舊紀錄，列在最後一列，再取前 10 名專案。 Codex 找不到工作階段的工作資料夾時，會把專案記成 unknown，過去報表一律當成舊紀錄。現在報表和網頁篩選器會檢查資料是否來自舊帳本，是才標成「舊紀錄（只剩總數）」，其餘無名稱的用量顯示「未知」。 HTML、CSV 和 PNG 匯出檔過去用匯出當天命名，隔幾個月重開看不出資料期間。現在改用涵蓋日期命名，像 usage-report-2026-10-01_2026-11-17.csv，無日期篩選器的報表仍用匯出日。匯出的 HTML 重開時也會停在同一段日期。

新功能

額度讀數時效與提醒不再誤報

看終端機底下的狀態列與額度提示，讀數新舊和警告現在不再亂跳。 Muse 過重置時間若沒重讀，過去把 0% 當真在 macOS 與 Windows 跳「已恢復」通知，現在改等新讀數。 Muse 卡片與狀態列改用伺服器查額度時間判斷過期與年齡，重讀舊額度不再像剛查的。 重置估計提前超過 10 分鐘時（如切換額度來源），只要用量停在已警告程度，額度感知模式就不重複警告。 Claude Code 替各時段分開記讀取時間，五小時額度不再顯示週額度舊時間。狀態列 hook（特定事件發生時觸發的小程式）升到 1.21，額度感知為 1.19。 Codex 替各額度保留最新拒絕只套用到對應時段，Codex Spark 較晚被拒時，不再藏起一般額度拒絕。

問題修復

只裝 Grok CLI 開啟狀態列不再報錯

電腦裡只裝了 Grok CLI，開關狀態列卻一直跳出失敗訊息？Grok 狀態列當時已經裝好了，只是 usage 找不到 Claude Code 或 Codex 就跟著回報錯誤。現在只要 Grok 狀態列設定完成，就會回報成功。

問題修復

修復續談 hook 會保留較新的腳本

續談用的提示檔不見了，想跑修復卻怕蓋掉後來裝好的新版程式。現在修復續談 hook 時，usage 只會把遺失的提示檔補回來，已安裝的較新腳本會原封不動留在原地。

新功能

新的 Codex 模型只會公告一次

同一個對話裡，某個模型先出現在用量紀錄、後來又進到 Codex 模型清單，過去 usage 總共發出兩次通知。現在 usage 會沿用第一次的紀錄並保留首次出現的時間，不再重複公告。

新功能

GPT-6.2 Sol 與 Astra 離線也有價

無法下載價目表時，Codex 新的 GPT-6.2 模型花費過去會被算成 $0。現在內建的備援價目表已經收錄它們的單價，斷線也能照常計費：Sol 每百萬 token 輸入 $2、輸出 $10，Astra 則是輸入 $8、輸出 $40。

問題修復

精簡模式不限制創作且誠實交代驗證

開啟精簡模式省字數，過去常連帶綁住創作內容或讓回覆過度簡略。 「不用比喻、表情符號、裝飾性表格」這幾條規定現在只管 Claude 自己的回覆。你請它寫的文章、貼文或簡報不用遵守，要它寫一篇滿是比喻的貼文也不會再跟精簡模式衝突。 改檔或跑指令後，短回覆不能再把沒驗證的事說成做完了。Claude 現在會交代驗證了什麼，沒測過或只做一部分會直說，也會把沒驗證的假設與還沒解決的風險寫完整。如果你的 CLAUDE.md 有教學規則、你要求用比喻或說看不懂，這些都優先於精簡；「不要自創縮寫」也拿掉了「縮寫省不到 token」這句沒有證據的說法。

就像請秘書平時用條列快報進度，他自己的工作匯報會力求精短、沒確認完的事也老實標出來，但替你代筆的活動致詞稿仍會保留比喻和圖表。

English

FEATURE

More accurate history in reports and the year ledger

When checking past usage in historical reports, you no longer have to worry about numbers getting stuck on old records or overwritten. Old Antigravity days saved before the counting fix had inflated token (text units AI processes and bills by) totals, which could not be replaced before because the snapshot only swapped in a new number when it was at least as large as the old one. Now the snapshot records the counting version and swaps in the corrected number as long as all sessions and other tool records from that day are still on disk. The year ledger waits until the snapshot finishes replacing the day before updating, and reports no longer add back the old difference. When a report and a background update ran in separate processes and wrote to year_ledger.json at the same time, they could overwrite days the other had just saved or backfilled. Now a lock file is created next to the ledger so only one process at a time can read, merge, and write it back. If another process holds the lock for more than 10 seconds, this update is skipped for later, and nothing is written without the lock. The "All-time" report used to start from the first day with token usage, leaving out earlier days that only had activity records. It now starts from the earliest day with either usage or activity records, and the date picker can select that day too.

FEATURE

Clearer project labels and report export file names

Exporting project rankings or digging up report files from months ago used to leave you guessing at labels and file names. Project CSV exports used to take the top 10 rows before setting aside old total-only records, which pushed out the 10th project. Now, matching the report view, old records are set aside first and placed in the last row before taking the top 10 projects. When Codex cannot find a session's working directory, it records the project as unknown, which reports used to treat as old records across the board. Now the report and web filter check whether the data came from the old ledger: only those rows are labeled "Old records (totals only)", while other unnamed usage shows as "unknown". HTML, CSV, and PNG exports used to be named after the export date, making it hard to tell which period they covered when reopened months later. They are now named after the covered dates, such as usage-report-2026-10-01_2026-11-17.csv, while reports without a date picker still use the export date. Reopening an exported HTML file also stays on those same dates.

FEATURE

Accurate quota reading ages and no more false alerts

Checking the status line at the bottom of your terminal and quota prompts, reading ages and warnings no longer jump around. When Muse passed its reset time without a fresh reading, it used to treat 0% as real and trigger a "restored" notification on macOS and Windows; it now waits for a new reading. The Muse card and status line now use the server's quota check time to judge staleness and age, so re-reading an old quota no longer looks freshly checked. When the reset estimate moves earlier by more than 10 minutes (such as when switching quota sources), quota-aware mode no longer repeats the warning as long as usage stays at an already-warned level. Claude Code now records a separate reading time for each window, so the five-hour quota no longer shows the weekly quota's old timestamp. The status line hook (a small program triggered by specific events) updates to 1.21, and quota-aware updates to 1.19. Codex now keeps the latest rejection for each quota and applies it only to the matching window, so a newer Codex Spark rejection no longer hides a general quota rejection.

BUGFIX

No error when enabling the status line with only Grok CLI installed

Have only the Grok CLI installed and keep getting a failure message when toggling the status line? The Grok status line was actually already installed, but usage reported an error because it could not find Claude Code or Codex. Now it reports success once the Grok status line is set up.

BUGFIX

Repairing the resume hook keeps newer scripts

If your resume prompt file went missing, you might hesitate to run a repair for fear of overwriting a newer script installed later. Now when repairing the resume hook, usage only restores the missing prompt file and leaves any newer installed script untouched.

FEATURE

New Codex models are announced only once

Within the same conversation, if a model appeared in usage logs first and later showed up in the Codex model list, usage used to send two notifications. Now usage reuses the first record and keeps its first-seen time instead of announcing it again.

FEATURE

GPT-6.2 Sol and Astra have offline pricing

When the price table could not be downloaded, Codex's new GPT-6.2 models used to be counted at $0. The built-in fallback price table now includes their rates so billing still works offline: Sol is $2 input and $10 output per million tokens, while Astra is $8 input and $40 output.

BUGFIX

Token Saver unblocks creative writing and reports verification honestly

Turning on Token Saver to save words used to restrict creative writing as well or make replies overly terse. The rules against analogies, emoji, and decorative tables now apply only to Claude's own replies. Articles, posts, or slides you ask it to write do not have to follow them, so asking for a post full of analogies will no longer conflict with Token Saver. After editing files or running commands, short replies can no longer claim unverified work is done. Claude now states what it verified, says plainly when something is untested or only partly done, and writes out unverified assumptions and open risks in full. If your CLAUDE.md has teaching rules, or if you ask for analogies or say you do not follow, those take priority over brevity; the rule against made-up abbreviations also drops the unsupported claim that abbreviations save no tokens.

Think of a secretary who normally gives you bullet-point progress updates: his own work reports stay brief and flag anything unverified, while the event speeches he drafts for you still keep their analogies and charts.

**Antigravity days in the snapshot now show the corrected token totals.** Before this fix, the daily snapshot replaced a saved day only if the new total was at least as large. Antigravity days saved before the token-counting fix were too high, so the smaller corrected totals never replaced them, in reports or in the snapshot file. The snapshot now records which counting version produced each day. It replaces an old Antigravity day only when every session and every other tool's records from that day are still on disk. The year ledger updates that day only after the snapshot has replaced it, and reports no longer add the old difference back from the ledger.
**Generating a report no longer erases days that background updates just saved to the year ledger.** The year ledger was protected only by a lock inside a single process. When the report ran in a separate process, the report and the background updates could write the ledger at the same time, and one write could erase days the other had just saved or backfilled. usage now creates a lock file next to `year_ledger.json`, so only one process at a time can read, merge, and write the ledger. If another process holds the lock for more than 10 seconds, usage skips this update and tries again later. It never writes without the lock.
**All-time reports include earlier Claude Code activity.** The report used to start on the first day with token usage, so it left out earlier days that had activity but no token records. It now starts on the earliest day with either, and the date picker can select that day.
