Usage 0.34.16

發布日期：2026-11-10

繁體中文

新功能

Antigravity 狀態列改為雙排顯示，補上額度重置時刻與剩餘時間

緊盯著邊長受限的終端機視窗趕工時，最怕算不清手邊的呼叫配額何時重置。

走進候車亭看動態看板，以前單排螢幕擠不下完整字樣，抵達時間常最先被裁切；現在改成分層播送，上方列出路線、下方顯示倒數分鐘，小螢幕也能一眼看齊。

Antigravity 的 status line（顯示在終端機最底下的狀態列）現在採用雙排設計，排版樣式比照 Claude Code。第一排固定保留專案與額度視窗，第二排則放模型與上下文視窗（模型一次可處理的內容容量）。在 5 小時和每週額度的百分比旁，會直接印出重置時刻與剩餘時間，例如 18:37(2h30m left)，意思是 18:37 重置、還剩 2 小時 30 分鐘。即使終端機只有 80 格寬，重置時間依然放得下，不再被優先省略。

新功能

精簡模式兼顧文字可讀性，縮短回覆依然讀一遍就懂

請 AI 簡明扼要回答問題時，最常遇到文字被過度壓縮而難以理解的窘境。

報社主編濃縮長篇通訊，以前為了塞進有限版面猛砍連接詞，讀者讀起來反而滿頭問號；現在改寫時要求句型完整且詞語自然，篇幅變短卻依然一讀就通。

精簡模式（terse mode，縮減回覆長度的輸出模式）現在替回覆品質設下底線，要求讀者讀一遍就能看懂。這套指示要求語句採用常見的慣用搭配詞，動詞必須盡量靠近主詞，並強制保留「因為」與「所以」等關鍵連接詞。這項改進依據一項最新研究：逼迫 AI 寫短，正是其文字變得晦澀難懂的原因之一。

新功能

Codex 子代理用量重新計入，獨立統計不再整份略過

指揮背景代理分頭處理繁重任務之後，翻開用量報告卻可能發現統計數據對不上。

工讀生協助分裝包裹，以前簽收單雖寫著總部抬頭卻漏貼明細，會計對不上總帳便整批退件；現在獨立開立單據從零計算，派工產生的開銷全部如實入帳。

由 spawn_agent 啟動的子代理執行緒會複製父層工作階段的開頭標頭，卻不再複製父層的 token（計量 AI 處理與計費的文字單位）事件。過去 usage 因為無法將它對齊父對話，會將整份紀錄檔直接略過。現在這類子代理紀錄已改為從零開始統計。在發現此問題的電腦上，先前大約少算了 0.4% 的 Codex token 用量。

新功能

Fable 5.2 補上離線價格備援，圖表統一顯示簡稱

遇到網路斷線或離線工作的場合，查看模型支出報表常會因為缺乏即時價目而留下空白。

便利商店刷條碼結帳，以前連不上總部系統就直接顯示無此商品，發票品名也印得落落長；現在機台內建離線公定價，收據上更統一印出簡潔的商品代號。

針對 Fable 5.2 模型，系統現在內建了離線價格設定。價目表無法下載時，Fable 5.2 的費用也不再顯示為缺漏。各類用量表格與統計圖表也統一將其名稱標示為簡潔的 Fable 5.2。

English

FEATURE

Antigravity status line switches to two lines, adding quota reset times and time remaining

When rushing through work while watching a space-constrained terminal window, the worst feeling is losing track of when active call quotas reset.

Think of checking a dynamic display at a bus shelter: where a single-row screen once could not fit all text and cut off arrival times first, a tiered broadcast now lists routes on top and countdown minutes below, letting small screens show everything at a glance.

Antigravity's status line (the status display at the bottom of the terminal) now uses a two-line layout modeled after Claude Code. The first line keeps project and quota windows, while the second line holds the model and context window (the amount of content a model can process at once). Next to the 5-hour and weekly percentages, it prints the reset clock time and time left, such as 18:37(2h30m left), meaning it resets at 18:37 with 2 hours and 30 minutes left. Even if the terminal is only 80 columns wide, reset times still fit and are no longer dropped first.

FEATURE

Terse mode preserves readability, keeping shortened replies clear in one pass

When asking an AI for concise answers, users often encounter text compressed so heavily that it becomes hard to understand.

Picture a newspaper editor condensing long dispatches: where conjunctions were once aggressively cut to fit limited space and left readers puzzled, rewrites now require complete sentence structures and natural phrasing so shortened copy remains clear in one pass.

Terse mode (an output mode that shortens reply length) now sets a quality floor, requiring that readers understand each reply in one pass. These instructions require common word pairings, keep the verb as close as possible to its subject, and mandate preserving key connecting words such as "because" and "so". This improvement follows a recent study: pressuring AI to be brief is itself one reason its text becomes obscure and hard to understand.

FEATURE

Codex subagent usage is counted again, tracked independently instead of skipping whole files

After directing background agents to handle heavy tasks in parallel, opening a usage report might reveal figures that fail to match.

An intern helps pack parcels: while receipt slips once showed headquarters headers but omitted itemized details, prompting accounting to reject whole batches when totals failed to match, independent invoices are now issued from scratch so all dispatch expenses are recorded faithfully.

A subagent thread launched by spawn_agent copies the header of the parent session, but no longer copies the parent's token (the text unit used to measure AI processing and billing) events. Previously, because usage could not match it to the parent conversation, it skipped the entire log file. These subagent records are now counted from zero instead. On the machine where this issue was found, about 0.4% of Codex token usage had previously gone uncounted.

FEATURE

Fable 5.2 adds an offline price fallback, displaying a short name across charts

When working offline or experiencing a network disconnection, reviewing model spending reports often left blanks because real-time pricing was unavailable.

At a convenience store barcode checkout, losing connection to headquarters once prompted registers to display items as missing while printing overly long names on receipts; machines now embed offline list prices and consistently print concise product codes instead.

For the Fable 5.2 model, the system now includes built-in offline pricing. When the price table cannot be downloaded, costs for Fable 5.2 no longer show as missing. Usage tables and charts also consistently display its name as the concise Fable 5.2.
