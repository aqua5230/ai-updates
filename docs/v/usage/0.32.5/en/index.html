Usage 0.32.5

Released: 2026-10-06

Release notes

FEATURE

Status bar displays cache invalidation reasons, documentation removes countdown details

When using Claude Code in the terminal, you might want to know why a cache was invalidated.

Now, the status bar displays the reason within 10 minutes after a prompt cache invalidation, such as "Cache: 62% Just invalidated: Tools changed". It covers all 17 reasons—including model switches, thinking effort, fast mode, tool or system prompt changes, and idle timeouts—and supports five languages, hiding the reason when unknown; when the window is too narrow, the reason is prioritized for hiding.

Picture paying at a restaurant: previously, an expired discount silently reverted to full price, but now the receipt prints whether items changed or time ran out, making the reason clear at a glance.

This feature requires Claude Code 2.1.260 or higher. The status bar hook upgrades to version 1.9 and will automatically update on the next launch. Documentation also removes the obsolete countdown timers that are no longer displayed.

FEATURE

Automatically compare tool formats before release to track upstream structure changes in real time

As AI tools update frequently, parsers reading underlying data often silently break due to official revisions.

The newly added scripts/check_upstream.py development script now validates real files on this machine one by one before releasing a new version. The check covers Claude status lines and conversation logs, Codex sessions and new database versions like state_6.sqlite, Grok logs, and monitored Statuspage components. For Antigravity, it verifies whether conversation databases and quota caches are operating normally. This tool also compares installed hook copies to detect cases where source files were modified without bumping version numbers, clearly reporting OK, NEW, BROKEN, or NO_DATA for each check.

Much like a factory aligning parts against molds before shipping, where developers previously waited for user bug reports after specs broke, format changes are now caught automatically prior to release.
BUGFIX

Side panel borders save more vertical space, fixing background tasks and plugin validation

When viewing the Claude Code side panel on small screens or split windows, every line of vertical space is precious.

Section titles and counts are now moved to the top edge of each border, saving one line per section while still allowing sections to be collapsed by clicking their titles.

Think of a storage box moving category labels from inside compartments to the top border: previously labels occupied an entire line, but aligning them with the border now lets limited screen space display more lines of information.

When fewer than four background tasks were listed, a newly completed task was previously sometimes omitted, but the list now displays them reliably. The panel's own tests pass again on Claude Code 2.1.289, and running claude plugin validate no longer errors on state contract declarations.
