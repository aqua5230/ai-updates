Usage 0.29.35

Released: 2026-08-23

Release notes

FEATURE

Migration paints migration routes across a dusk sky

Open Migration, fourteenth visual theme, and a dusk sky appears with a latitude-and-longitude grid.

Three V-shaped flocks cross it at different speeds, with moving wings.

It works like an open field guide: grid establishes place, then flying birds draw each journey for you.

Route labels such as ROUTE. 7 identify those journeys. This follows illustrated field-guide approach of Lepidoptera panel, using migration as scene this time.

FEATURE

README galleries are rebuilt to complete missing themes and hide real data

Five READMEs were like practice sheets filled with different sample data: photos missed themes, failed to line up, and old images were hand-captured from a real machine, carrying real project names and dollar amounts onto public pages.

It is like reprinting five practice sheets with one set of sample data: layouts line up without printing real project names and dollar amounts in public version.

Headings claimed thirteen images but showed ten: stained_glass and origami had never been photographed, catppuccin only in Chinese, and old images predated Antigravity card. scripts/make_panel_shots.py now rebuilds shots from same synthetic payload used by website. Since galleries put three pictures in each row, a shorter panel pushes whole grid out of line, so all shots use tallest panel height; wide HUD world_cup, genuinely 243 pixels shorter, stays out. That leaves twelve images in four even rows. Website still displays all thirteen alone at own size. GitHub strips scripts and iframes from Markdown, so README remains static images.

FEATURE

Website gallery runs all thirteen live panels and switches their language

Theme wall on website moves from ten static screenshots to thirteen real panels you can view directly.

It is like station's live departure board: you can see actual train status, but pressing its buttons will not make train switch tracks.

origami and stained_glass had no image, while catppuccin showed only Chinese, so thirteen themes meant ten visible themes. Website now puts real panel HTML into frame with hand-written demo payload, and gets theme list from panels.all_panels(). When fourteenth panel arrives, running scripts/make_panel_demo.py places it on site without remembering two more photos. Existing applyLang() also passes site language choice to panel, so all five languages change together. Panel is display-only: no native side on web page can answer Switch Panel or Quit buttons. Old screenshots remain in docs/, and READMEs still link to them.

FEATURE

Stained Glass gains counter-rotation like a kaleidoscope

Stained Glass keeps its existing light sweep, but scene now gains another layer of motion.

When kaleidoscope turns, glass fragments circle in opposite directions and light follows rhythm of refraction; update adds that change to panel.

Layered fragments counter-rotate through kaleidoscopeTurn, while light sweep follows through kaleidoscopeSweep. Existing sunlightSweep remains, as do panel's id and name, so this upgrades existing Stained Glass visually rather than creating another theme.

FEATURE

Seven modules move into packages to avoid a `setup` naming collision at build time

Project root moves out seven more modules and now holds only 28 Python files.

It is like assigning film crew before a shoot: window work goes to set team, menu-bar work to props team, and installation work to logistics team.

panel_window and panel_window_state join panels/; critter_frames joins menubar/; four modules setup_hook, session_hooks, statusline_settings, and login_item install usage into user's system and join new installer/ package. It cannot be called setup: repository root sits on Python's sys.path (list of places Python searches for modules), and a top-level package of that name would shadow import setup used by setuptools and py2app during packaging. Failure surfaces only when packaging, not in test suite. Four modules used to walk upward from __file__ for hook scripts; scripts remain at root to run under system Python, so they now walk up one extra level.

Original changelogSeven modules move into packages to avoid a `setup` naming collision at build time
**Seven more modules moved out of the repository root.** `panel_window` and `panel_window_state` joined `panels/`, `critter_frames` joined `menubar/`, and a new `installer/` package took `setup_hook`, `session_hooks`, `statusline_settings`, and `login_item` — the four modules that install usage into the user's system. The root is down to 28 Python files. The package is named `installer` rather than `setup` because the repository root is on `sys.path` and a top-level `setup` package would shadow the bare `import setup` that setuptools and py2app perform during a build — a failure that only surfaces when packaging, never in the test suite.
