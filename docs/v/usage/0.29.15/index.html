zh-TW

中文、日文、韓文的用量估算不再少算四倍

你拿中文、日文或韓文檔案檢查浪費的用量時，以前看到的數字其實少算了四倍。診斷工具把所有文字都當成四個字元才算一個 token（AI 處理文字量的單位），這套演算法適合 ASCII 文字，卻不適合 CJK 文字：一個中日韓字大約就是一個 token。現在它會把中日韓字逐一計算，其餘文字仍以四個字元估算，所以浪費的 token 與由此算出的費用不會再縮成四分之一。這像秤蔬菜時把每四顆番茄才當一顆，秤重結果當然偏低；秤法改正後，數字才接近實際重量。工具仍在離線運作，沒有為了追求細微的取整誤差加入特定模型的 tokenizer。

壞掉的快取先隔離，留下查問題的線索

某次用量數字看起來不對時，壞掉的快取（把查過結果暫存起來直接用的資料）現在不會立刻被刪光。Antigravity、Codex 與 history 三種快取遇到讀不懂的檔案，仍會重新計算以便繼續使用，但會先把原檔移到 ~/.usage/quarantine/，讓你日後還能檢查出了什麼問題。每個檔名帶毫秒時間戳，第二次故障不會蓋掉第一次；隔離區最多留十個檔案，每個最多 5 MB。這像醫院把破損的檢體先放進證物袋，再重新採樣，而不是直接丟進垃圾桶。只有過期的 schema_version 不會被隔離，因為那是正常升級；每個快取有 32 個分片，一次升版若全送進隔離區，反而會擠掉真正的故障證據。

`--doctor` 會分清楚「缺檔」與「根本用不到」

跑 --doctor 檢查安裝狀態時，看到 forwarder script: [missing] 不必再先以為出錯。以前報告把十四項檢查攤成一張清單，即使你目前的模式根本不用 forwarder script（負責轉送資料的腳本），它也照樣標成 missing。現在結果分成 [core]、[hook] 與 [optional] 三組；不需要轉送腳本的模式會直接寫 [not needed in <state> mode]。這像健康檢查把必做檢驗、加選檢驗和不適用項目分欄，而不是把所有未做項目都標紅。檢查的判斷規則沒有改，改的是報告把情境講清楚的方式；真正缺少目前模式會用到的檔案，仍會顯示為問題。

Windows 的系統匣測試會寫入真實偏好設定

Windows 開發者跑系統匣（Windows 工作列角落放背景程式圖示的區域）測試後，自己的面板偏好曾被悄悄改掉。兩個測試都會呼叫 switch_panel() 切換面板；這個動作接著透過 _save_active_panel_id() 寫入偏好檔，但測試沒有把 prefs.PREFERENCES_FILE 改指向暫存位置，於是實際碰到的是 ~/.claude/usage-preferences.json。換句話說，測試本來該在模型屋裡搬家具，卻走進你的家改了客廳。

四種 README 翻譯都有人守，不再只盯繁中

英文 README 多加一節時，簡體中文、日文和韓文版現在也會被檢查有沒有跟上。原本 check_doc_parity.py 只比對英文與繁中 README，其他三份翻譯沒有自動守門員，只能靠 CLAUDE.md 裡的手動提醒。現在每一種翻譯各自和英文比較，若落後，錯誤訊息會直接點出是哪個檔案。它比的是 ## 標題的數量，不是標題文字本身：譯者仍可用自然的語言改寫標題，不必逐字照翻。這像展覽入口只數每個語言版有沒有同樣多扇展廳門，而不強迫門牌翻成同一串字；少了一扇門才提醒你回頭補。

本機安裝有了腳本，選單列不再默默跑舊版

你剛做完本機 build（編譯完成、可執行的程式版本），標上 release tag 並不會自動換掉 /Applications 裡正在跑的 App。過去這一步只寫在檢查清單，曾讓選單列連續六個版本仍開著舊 build。現在要在本機安裝時，直接執行 scripts/install_local.sh：它先確認 build 存在，印出新舊兩個版本，等待正在執行的 App 結束，再替換檔案，最後核對已安裝版本是否相同。這像買了新燈泡卻只把盒子放在門口；打上標籤不等於已裝進燈座。腳本把拆舊燈、裝新燈和開燈確認串起來，讓本機副本跟著更新。

Usage estimates no longer count CJK text at one quarter of its size

If you use Chinese, Japanese, or Korean files to diagnose waste, the old figures were four times too small. The diagnostic treated every four characters as one token (the unit an AI uses to measure text). That works for ASCII text, but a CJK character is roughly one token. It now counts each CJK codepoint as one token and keeps the four-characters-per-token estimate for everything else, so reported waste and the cost based on it no longer shrink to a quarter of their real estimate. It was like weighing tomatoes but recording only one for every four on the scale. The tool remains offline; it does not add a model-specific tokenizer just to chase tiny rounding differences.

A damaged cache is quarantined instead of erased

When a usage number looks wrong, a damaged cache (stored results reused instead of recomputed) will no longer vanish immediately. Antigravity, Codex, and history caches still recover by recomputing an unreadable file, but first move the original into ~/.usage/quarantine/ so there is something to inspect later. Names include a millisecond timestamp, so a second failure cannot replace the first; the folder holds at most ten files, up to 5 MB each. It is like bagging a damaged lab sample before taking a new one instead of throwing away the only clue. An old schema_version is excluded because it is a normal upgrade. With 32 shards per cache, quarantining an entire version bump would crowd out the evidence from a real failure.

`--doctor` separates a missing file from one you do not need

When you run --doctor to check an installation, forwarder script: [missing] no longer automatically means trouble. The report used to flatten fourteen checks into one list, so it showed a missing forwarder script even in a mode that never uses one. A forwarder script is simply a script that passes data along. Results are now separated into [core], [hook], and [optional]; a mode that does not need the script says [not needed in <state> mode]. It is like a health report separating required tests, elective tests, and tests that do not apply instead of marking every absent test red. The checking logic itself did not change; a file required by the current mode is still reported as missing.

Windows tray tests write to your real preferences

After a Windows developer ran tray tests, their own panel preference changed in silence. The tray is the corner of the Windows taskbar where background-app icons live. Two tests call switch_panel(), which then writes preferences through _save_active_panel_id(). But the tests did not redirect prefs.PREFERENCES_FILE to a temporary location, so they wrote to the real ~/.claude/usage-preferences.json. The tests were meant to rearrange furniture in a model home, yet walked into your living room instead.

Documentation checks now watch all four README translations

When the English README gains a section, the Simplified Chinese, Japanese, and Korean versions are now checked for keeping up too. check_doc_parity.py used to compare English only with Traditional Chinese, leaving the other three translations guarded only by a hand-written reminder in CLAUDE.md. Each translation is now compared with English on its own, and a failure names the file that drifted. The check counts ## headings rather than matching their wording, so translators can still write natural headings instead of copying English word for word. It is like checking that every language edition of an exhibition has the same number of gallery doors, without forcing all the signs to use identical words.

A local-install script keeps the menu bar from quietly running an old build

After you make a local build (a compiled, runnable version of the app), adding a release tag does not replace the copy already running from /Applications. That final step used to live only in a checklist, and the menu bar once kept running a build six versions old. For a local install, run scripts/install_local.sh. It confirms the build exists, prints both versions, waits for the running app to exit, swaps the files, and verifies that the installed version matches. Buying a new light bulb is not the same as putting it in the socket. The script links removing the old bulb, fitting the new one, and checking that the light turns on, so the local copy actually catches up.

中日韓テキストの使用量見積もりが 4 分の 1 にならなくなった

中国語、日本語、韓国語のファイルで無駄な使用量を調べるなら、これまでの数字は実際の見積もりの 4 分の 1 だった。診断はすべての文字を四文字で一 token（AI が文字量を数える単位）としていた。この比率は ASCII 文字には合うが、中日韓の一文字はおよそ一 token である。今後は CJK の各コードポイントを一 token、それ以外を四文字で一 token として数えるため、無駄な token とそこから出す費用が 4 分の 1 に縮むことはない。トマトを量るのに四個ごとに一個だけ記録していた秤を直すようなものだ。道具は引き続きオフラインで動き、わずかな丸め誤差のために特定モデル用 tokenizer は追加しない。

壊れたキャッシュを消さずに隔離して、調査の手掛かりを残す

使用量の数字がおかしく見えたとき、壊れたキャッシュ（調べた結果を一時保存して再利用するデータ）は、もう直ちに消えない。Antigravity、Codex、history の三つのキャッシュは読めないファイルを再計算して復旧するが、その前に元のファイルを ~/.usage/quarantine/ へ移すため、後から原因を調べられる。名前にはミリ秒の時刻が付き、二度目の失敗が一度目を上書きしない。隔離場所は十ファイルまで、各 5 MB までである。壊れた検体を捨てる前に証拠袋へ入れてから採り直すようなものだ。古い schema_version は通常の更新なので隔離しない。各キャッシュに 32 個の断片があるため、更新分を全て入れると本当の故障の証拠を押し出してしまう。

`--doctor` が「不足」と「不要」を区別するようになった

インストール状態を --doctor で調べるとき、forwarder script: [missing] と出ても、すぐに異常だと思わなくてよくなった。以前の報告は十四項目を一つの一覧に並べていたため、現在のモードで使わない forwarder script（データを転送するスクリプト）まで missing と表示していた。これからは結果を [core]、[hook]、[optional] に分け、不要なモードでは [not needed in <state> mode] と明記する。必須検査、任意検査、対象外を分けず、未実施を全て赤字にする健康診断票を直すようなものだ。検査の判定自体は変わらず、今のモードで必要なファイルがない場合は引き続き missing と報告する。

Windows のトレイテストが実際の設定に書き込む

Windows の開発者がシステムトレイ（タスクバーの隅に常駐アプリのアイコンが並ぶ場所）のテストを実行したあと、自分のパネル設定が黙って変わっていた。二つのテストは switch_panel() を呼び、そこから _save_active_panel_id() を通じて設定を書き込む。しかしテストは prefs.PREFERENCES_FILE を一時的な場所へ差し替えておらず、実際の ~/.claude/usage-preferences.json に書き込んでいた。モデルルームの家具を動かすはずの試験が、自宅の居間へ入ってしまったようなものだ。

README の四言語すべてを翻訳漏れチェックの対象にした

英語版 README に節が増えたとき、簡体字中国語、日本語、韓国語版も追いついているか確認されるようになった。check_doc_parity.py は以前、英語と繁体字中国語だけを比べ、残る三翻訳は CLAUDE.md の手作業の注意書きに頼っていた。今後は各翻訳を英語と個別に比べ、ずれた場合はどのファイルかをエラーに表示する。比べるのは ## 見出しの個数であり、見出しの文言そのものではない。翻訳者は英語を一語ずつ写さず、自然な見出しを書ける。各言語版の展示に同じ数の展示室の扉があるかを見るだけで、扉の札まで同じ言葉に強制しないような検査である。

ローカルインストールをスクリプト化し、メニューバーが古い版のまま動くのを防ぐ

ローカル build（コンパイル済みで実行できるアプリの版）を作って release tag を付けても、/Applications で動いているコピーは自動では置き換わらない。この最後の作業は以前チェックリストにしかなく、メニューバーが六版前の build を動かしていたことがある。ローカルへ入れるときは scripts/install_local.sh を実行する。このスクリプトは build の存在を確認し、新旧の版を表示し、実行中の App が終了するのを待ってから入れ替え、インストール済みの版が一致するか確かめる。新しい電球を買って玄関に箱を置くだけでは、灯具は新しくならない。古い電球を外し、新しいものを付け、点灯を確かめるまでを一続きにする作業である。

중국어·일본어·한국어 사용량 추정치가 4분의 1로 줄어들지 않는다

중국어·일본어·한국어 파일로 낭비된 사용량을 점검했다면, 예전 수치는 실제 추정치의 4분의 1에 불과했다. 진단 도구가 모든 문자 네 개를 token(AI가 글자량을 세는 단위) 하나로 계산했기 때문이다. 이 비율은 ASCII 문자에는 맞지만, 한중일 문자 하나는 대략 token 하나다. 이제는 CJK 코드포인트를 하나씩 token 하나로 세고 나머지는 네 글자당 하나로 계산하므로, 낭비된 token과 거기서 계산한 비용이 4분의 1로 줄어들지 않는다. 토마토 네 개를 저울에 올리고 한 개만 적어 두던 계량을 고친 셈이다. 이 도구는 계속 오프라인으로 작동하며, 미세한 반올림 차이 때문에 특정 모델용 tokenizer를 추가하지 않는다.

망가진 캐시는 지우지 않고 격리해 원인을 남긴다

사용량 숫자가 이상해 보일 때, 망가진 캐시(살펴본 결과를 잠시 저장해 다시 쓰는 데이터)를 이제 바로 지우지 않는다. Antigravity, Codex, history의 세 캐시는 읽을 수 없는 파일을 다시 계산해 복구하지만, 먼저 원본을 ~/.usage/quarantine/으로 옮겨 나중에 원인을 살필 수 있게 한다. 이름에 밀리초 시각을 넣어 두 번째 고장이 첫 번째 것을 덮어쓰지 못하게 했고, 격리 장소에는 파일 열 개까지만 두며 파일 하나는 5 MB까지다. 망가진 검체를 버리기 전에 증거 봉투에 넣고 새로 채취하는 것과 같다. 오래된 schema_version은 정상적인 업그레이드라 격리하지 않는다. 캐시마다 조각이 32개이므로 버전 갱신분을 전부 넣으면 진짜 고장의 증거가 밀려난다.

`--doctor`가 없는 파일과 필요 없는 파일을 구분한다

설치 상태를 --doctor로 확인할 때 forwarder script: [missing]가 보여도 곧바로 문제라고 생각할 필요가 없다. 예전 보고서는 열네 가지 검사를 한 목록에 늘어놓아, 현재 모드가 전혀 쓰지 않는 forwarder script(데이터를 넘겨주는 스크립트)도 missing으로 표시했다. 이제 결과를 [core], [hook], [optional]로 나누고, 필요 없는 모드에서는 [not needed in <state> mode]라고 적는다. 필수 검사, 선택 검사, 대상 아님을 나누지 않고 하지 않은 검사를 모두 빨갛게 표시하던 건강검진표를 고치는 셈이다. 검사 기준 자체는 바뀌지 않았으므로, 현재 모드에 필요한 파일이 없으면 계속 missing으로 보고한다.

Windows 트레이 시험이 실제 환경 설정에 쓴다

Windows 개발자가 시스템 트레이(작업 표시줄 구석에서 백그라운드 앱 아이콘을 보여 주는 곳) 시험을 돌린 뒤 자신의 패널 선택이 조용히 바뀌었다. 두 시험은 switch_panel()을 호출하고, 이 동작은 _save_active_panel_id()을 거쳐 환경 설정을 쓴다. 그러나 시험은 prefs.PREFERENCES_FILE을 임시 위치로 돌려놓지 않아 실제 ~/.claude/usage-preferences.json을 건드렸다. 견본 주택의 가구를 옮겨야 할 시험이 자기 집 거실에 들어간 셈이다.

README 네 번역본 모두를 동기화 검사에 넣었다

영문 README에 절이 하나 늘어나면 이제 간체 중국어·일본어·한국어판도 따라왔는지 검사한다. check_doc_parity.py는 예전에는 영문과 번체 중국어만 비교했고, 나머지 세 번역은 CLAUDE.md의 수동 메모에만 기대고 있었다. 이제 각 번역본을 영문과 따로 비교하며, 어긋나면 오류 메시지가 해당 파일을 짚어 준다. 이 검사는 ## 제목의 개수만 세고 제목 문구를 맞추지는 않는다. 번역자는 영어를 한 단어씩 베끼지 않고 자연스러운 제목을 쓸 수 있다. 언어별 전시에 전시실 문이 같은 수만큼 있는지 확인하되, 문패 문구까지 똑같이 강요하지 않는 검사와 같다.

로컬 설치 스크립트로 메뉴 막대가 옛 빌드를 실행하는 일을 막는다

로컬 build(컴파일을 마쳐 실행할 수 있는 앱 버전)를 만들고 release tag를 붙여도 /Applications에서 실행 중인 복사본은 저절로 바뀌지 않는다. 이 마지막 작업은 예전에는 점검표에만 적혀 있었고, 메뉴 막대가 여섯 버전 전 build를 실행한 적도 있다. 로컬에 설치하려면 scripts/install_local.sh를 실행하면 된다. 이 스크립트는 build가 있는지 확인하고 새 버전과 옛 버전을 표시한 뒤, 실행 중인 App이 끝나기를 기다리고 파일을 바꾸며, 설치된 버전이 일치하는지 확인한다. 새 전구를 사서 상자만 현관에 놓는다고 등기구가 바뀌지는 않는다. 낡은 전구를 빼고 새 전구를 끼운 뒤 불이 켜지는지 확인하는 과정을 이어 주는 작업이다.

原始 CHANGELOG

Original changelog
**Token estimates no longer undercount CJK text by a factor of four.** Six places in the waste diagnosis converted characters to tokens with `chars // 4`, which is the ASCII ratio. A CJK character is roughly one token, not a quarter of one, so every figure the diagnosis reported for a Chinese, Japanese or Korean file — wasted tokens and the cost derived from them — came out at a quarter of the truth. This project reads its own `i18n.json`, `CLAUDE.md` and `README.zh-TW.md` often enough to hit this on itself. The estimate now counts CJK codepoints as one token each and everything else at four characters per token. No tokenizer dependency was added: this is an offline tool, and pulling in a model-specific tokenizer to chase rounding-level accuracy is not a trade worth making.
Original changelog
**A corrupt disk cache is preserved instead of being deleted outright.** All three caches — Antigravity, Codex and history — dealt with an unreadable file by removing it and recomputing. That is the right recovery, but it also destroys the only evidence of what went wrong, so a later report of "my numbers look off" has nothing left to inspect. A damaged file is now moved to `~/.usage/quarantine/` first, named with a millisecond timestamp so a second failure cannot overwrite the first, capped at ten files and 5 MB each. A stale `schema_version` is *not* quarantined: that is an ordinary upgrade, and with 32 shards per cache one version bump would flush the whole budget and push the real evidence out. The quarantine helper swallows every error it can hit — it is a side service and must never take the caller down with it.
Original changelog
**`--doctor` no longer reports a missing file that the current mode does not use.** The report listed fourteen checks as one flat list, so `forwarder script: [missing]` read as a fault even when the installed mode never needs that script. It is now grouped into `[core]`, `[hook]` and `[optional]`, and the forwarder line says `[not needed in <state> mode]` when that is the case. None of the check logic changed.
Original changelog
**Two Windows tray tests wrote into the real `~/.claude/usage-preferences.json`.** Both call `switch_panel()`, which persists through `_save_active_panel_id()`, and neither patched `prefs.PREFERENCES_FILE` — so running the suite silently changed the developer's own active panel.
Original changelog
**The documentation parity check covers Simplified Chinese, Japanese and Korean.** `check_doc_parity.py` only compared English against Traditional Chinese, leaving the other three README translations unwatched; `CLAUDE.md` had to carry a note to sync them by hand. Each translation is now compared on its own and the failure message names the file that drifted. The comparison is still a count of `##` headings rather than their text — matching text would force translators to mirror English headings word for word, which is what makes translated docs read badly.
Original changelog
**`scripts/install_local.sh` replaces the hand-typed steps for installing a build locally.** Releasing does not touch `/Applications`: the tag drives CI, and the local copy keeps running whatever was already there. That last step lived only in a checklist, and the menu bar once ran a stale build for six versions before anyone noticed. The script checks the build exists, prints both versions, waits for the running app to exit, swaps it, and verifies the installed version matches.
