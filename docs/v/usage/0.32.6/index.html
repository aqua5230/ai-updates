Usage 0.32.6

發布日期：2026-10-07

繁體中文

新功能

上下文用量依容量變色，側邊面板警示同步

當你跟 AI 進行長篇對話時，往往需要留意用量是否快要超出容量上限。

好比大水庫與小水槽改用不同的警報線，以前側邊面板跟狀態列各自看不同比例，現在兩邊統一套用相同標準，遇到超大容量更會提早亮起黃燈提醒。

上下文視窗現在會依照總容量來判斷顏色。用量達到 50% 或 200K token（AI 處理與計費的文字單位）時會變黃，達到 80% 或 400K token 時則變紅，並以先達到的一項為準。上下文容量為 1M 時，用量大約達到 20% 就會變黃；至於上下文容量為 200K 時，變色門檻則維持不變。Claude Code 側邊面板的警示標準也從原本的 70% 與 85% 改為這套新規則，讓側邊面板與狀態列的顏色完全保持一致。

新功能

精簡模式改用短句回答，嚴格限制各語言長度

如果你習慣讓 AI 給出簡潔俐落的答案，開啟精簡模式時會發現回覆變得乾淨明快。

像專業速記員整理重點，以前回覆容易把好幾件事拖成冗長複句，現在規定每一句只講一個動作，並嚴格卡住字數上限，讀起來輕鬆省力。

精簡模式現在強制一句話只講一件事，一律採用主動語態，並針對同一概念使用一致的詞彙。回覆長度也依照語言設下嚴格上限，中文限制 30 字、日文與韓文限制 40 字，英文則約為 20 個單字。負責這項功能的精簡模式 hook（掛鉤，特定事件發生時被觸發的小程式）版本已升級至 1.7，已安裝的副本會在下次開啟應用程式時自動更新。

新功能

狀態列顯示用量組成，容量吃緊時拆解佔比

把大量程式碼和截圖丟進對話後，一旦看到用量亮起警告，往往很難一眼看出到底是哪類內容在吃容量。

彷彿收納行李超重時跳出的明細清單，以前亮起紅燈你只能瞎猜是哪件物品太重，現在直接標出大件行李數量與雜物佔比，空間不足時還會自動把次要備註收起來。

當上下文（AI 在對話中能參考的內容）用量的數字變黃或變紅時，顯示在終端機最底下的狀態列會主動列出圖片數量，以及讀取檔案與指令輸出的估計佔比，例如 圖片 3 張 · 讀檔與指令輸出 22%。若該比例偏高，會建議你開啟新的對話工作階段。當狀態列空間不足時，這段組成資訊會最先被省略。狀態列 hook（掛鉤，特定事件發生時被觸發的小程式）已升級至 1.14，已安裝的副本會在下次開啟應用程式時更新。

新功能

更新後自動顯示改版重點，提示支援繁體中文

每次應用程式自動升級之後，你往往需要確認剛剛到底改了哪些功能。

如同訂閱的雜誌改版時夾附一張母語重點摘要，以前更新完只能自己找改了什麼，現在一開門就遞上每項只寫一行的繁中清單，斷網時還會貼心留到下次再給。

現在更新後第一次開啟應用程式，畫面會主動跳出這一版的更新內容，而且只會顯示一次。全新安裝的使用者不會看到這項提示；若啟動時沒有網路連線，會在下次開啟時再次嘗試顯示。這項功能同時適用於 macOS 與 Windows 系統。更新提示中每項變更只會列出一行，中文使用者會看到繁體中文說明，其他語言的使用者則會看到英文。由於提示視窗是由你目前安裝的版本所繪製，多語言更新說明會從這版之後的下一版更新提示開始正式生效。

新功能

應用程式程式碼簽章恢復有效，下載後驗證順利通過

如果你在 macOS 上下載應用程式後習慣手動驗證安全性，以前可能會因為簽章失效而無法通過檢查。

像出廠檢驗時重貼封條，以前如果在蓋完印章後又清理暫存碎屑，會弄破標籤導致檢查不過，現在改在徹底清乾淨後才重新壓上鋼印。

現在打包流程在清除位元組碼快取（cache，把編譯結果暫存起來直接用的檔案）後會重新進行數位簽章。下載後的應用程式副本都能順利通過 codesign --verify 驗證，讓程式碼簽章恢復有效。

English

FEATURE

Context usage color adapts to capacity, syncing sidebar panel alerts

During long conversations with AI, you often need to keep an eye on whether usage is nearing capacity limits.

Think of large reservoirs and small basins adopting distinct alert lines: while the sidebar panel and status line previously tracked different thresholds, both now share a unified standard, triggering yellow warnings earlier for extra-large capacities.

The context window now determines its color based on total capacity. Usage turns yellow at 50% or 200K tokens (units of text used for AI processing and billing), and turns red at 80% or 400K tokens, whichever threshold is reached first. With a 1M context window, usage turns yellow at roughly 20%; for a 200K context window, the color thresholds remain unchanged. Claude Code sidebar panel alerts have also switched to these new rules from the previous 70% and 85% marks, keeping colors between the sidebar panel and status line fully consistent.

FEATURE

Concise mode adopts short sentences, strictly capping lengths across languages

If you prefer crisp answers from AI, turning on concise mode makes responses noticeably clear and punchy.

Like a stenographer distilling key points, where answers previously dragged multiple ideas into lengthy compound sentences, every sentence must now convey just one action under strict length caps for effortless reading.

Concise mode now enforces one idea per sentence, strictly adopts the active voice, and applies consistent terms for the same concept. Response length is also capped by language: 30 characters for Chinese, 40 characters for Japanese and Korean, and roughly 20 words for English. The concise mode hook (a small program triggered by a specific event) handling this feature has been upgraded to version 1.7, and installed copies will automatically update on the next application launch.

FEATURE

Status line reveals usage breakdown, detailing proportions under tight capacity

After pasting extensive code and screenshots into a conversation, seeing a usage warning often leaves you wondering which content type is consuming capacity.

Picture an itemized breakdown when luggage exceeds weight limits: instead of guessing which item caused the red alert, big pieces and clutter ratios are explicitly listed, with secondary notes automatically tucked away when space runs tight.

The status line appears at the very bottom of the terminal. When context (the content AI can refer to in a conversation) usage numbers turn yellow or red, the status line actively displays image counts alongside estimated proportions for read files and command output, such as Images 3 · Files & commands 22%. If this percentage is high, it recommends starting a new conversation session. When status line space runs out, this breakdown information is omitted first. The status line hook (a small program triggered by a specific event) has been upgraded to 1.14, and installed copies will update on the next application launch.

FEATURE

Release highlights display automatically upon update, adding Traditional Chinese support

Whenever the application updates automatically, you often want to verify which features changed.

A renewed magazine subscription includes a key summary in your native language: instead of hunting for changes on your own, a single-line Traditional Chinese list greets you immediately, quietly deferred to the next launch if you are offline.

When you launch the application for the first time after an update, a release notes prompt appears on screen and shows only once. Fresh installations will not display this prompt, and if there is no internet connection at startup, it will try again on the next launch. This feature is supported across macOS and Windows. Each change in the update prompt takes only one line; Chinese users see Traditional Chinese descriptions, while other users see English. Because the prompt window is rendered by your currently installed version, multilingual release notes will officially take effect starting with the update prompt in the subsequent release.

FEATURE

Application code signatures restored, passing verification after download

If you manually verify application security after downloading on macOS, invalid signatures may have previously caused checks to fail.

Much like reapplying factory seals during inspection, where clearing residual debris after stamping once tore the seal and failed verification, stamps are now reapplied after thorough cleanup.

The packaging process now performs digital signing again after clearing bytecode caches. Downloaded application copies can now pass codesign --verify verification without issue, restoring valid code signatures.
