Usage 0.33.4

發布日期：2026-10-15

繁體中文

問題修復

Windows 異常結束不再堆積暫存檔，固定重複使用單一資料夾

你在 Windows 上使用 usage 時，若遇到系統關機或程式無預警閃退，硬碟空間常會不知不覺被吃掉。以前每次當掉、強制關閉或隨 Windows 關機，都會在暫存目錄 %TEMP% 留下約 2.5 MB 的 WebView2（微軟讓桌面程式顯示網頁畫面的組件）資料夾。隨著閃退次數增加，這些殘留檔案就會越積越多。現在 usage 改為重複使用 ~/.usage/webview 這一個專屬資料夾，就算異常結束也不會再塞爆暫存區。

如同使用健身房的固定置物櫃，以前每次臨時離開都換鎖霸占一個新櫃子，現在不管來幾次都共用同一個號碼櫃，儲物區不會再堆滿垃圾。
問題修復

離線備用價目表修正 Sonnet 5.5 快取費率，花費不再高估

當 LiteLLM 價目表下載失敗時，你看到的 Sonnet 5.5 花費可能被高估。usage 平常會連線下載 LiteLLM 價目表，只有在下載失敗時才會啟用備用清單。但這張備援表過去仍記載舊費率，把 Sonnet 5.5 讀取快取（把算過的結果暫存起來直接用）的費用算得太貴。現在這份離線價目表已經修正，讀取計價由每百萬 token（AI 處理與計費的文字單位）$0.20 改為 $0.10，不再把 Sonnet 5.5 的離線花費算高。

你拿舊型錄估算採購費用時，以前會因為上頭的單價太高，把預估總額算高；現在手邊的備用型錄更新了，就能按正確的單價估算費用。
問題修復

Claude Code 多視窗與背景代理不再干擾進度，輸入提示穩定保留

你在同專案開多個 Claude Code 視窗或呼叫背景代理時，現在各項操作不再彼此干擾。

跟在共用辦公室工作一樣，以前只要隔壁同事動筆或助理跑腿，櫃檯就把你正在選的便籤收走、甚至塞來隔壁的文件；現在分工清楚，不再錯拿進度。

以前開啟新視窗進行進度交接，常會誤接隔壁仍在跑的對話；現在會跳過其他開著且 10 分鐘內有寫入的工作階段，剛關閉的視窗仍正常交接。背景任務完成通知、以 ! 執行的指令與無參數斜線指令，也不再被當成最近需求。 自 Claude Code 2.1.299 起，背景子代理或隊友開始回合時會誤觸訊號，清空輸入框上方的新手模式名詞；現在只有主對話展開新回合才會清除，挑字不再被中途打斷。

English

BUGFIX

Abnormal Windows Exits No Longer Accumulate Temp Files, Reusing a Dedicated Folder

When using usage on Windows, system shutdowns or unexpected crashes used to quietly eat up disk space. Previously, every crash, forced quit, or Windows shutdown left behind a WebView2 (Microsoft's component for rendering web content in desktop apps) folder of about 2.5 MB in the %TEMP% directory. As crashes piled up, these leftover files continued to accumulate. Now usage reuses a single dedicated ~/.usage/webview folder, so abnormal exits will no longer fill up the temp directory.

Think of having a fixed gym locker: leaving unexpectedly used to mean locking and occupying a new locker every time, but now you reuse the same numbered locker no matter how many times you come, so the storage area never piles up with clutter.
BUGFIX

Offline Fallback Pricing Corrects Sonnet 5.5 Cache Rates, Preventing Cost Overestimation

If downloading the LiteLLM pricing table fails, Sonnet 5.5 costs might be overestimated. usage normally connects to download the LiteLLM pricing table, activating the fallback list only when that download fails. However, this fallback table previously retained outdated rates, pricing Sonnet 5.5 cache reads too expensively. Now this offline price table has been corrected, updating read pricing from $0.20 to $0.10 per million tokens (the text units for AI processing and billing), so Sonnet 5.5 offline expenses are no longer overestimated.

When estimating procurement costs from an old catalog, inflated unit prices previously made the projected total too high, but now that the backup catalog on hand is updated, expenses are calculated using the correct unit prices.
BUGFIX

Claude Code Multi-Window and Background Agents No Longer Interfere with Progress, Keeping Input Hints Stable

When opening multiple Claude Code windows or calling background agents in the same project, operations no longer interfere with one another.

Like working in a shared office, whenever a neighboring colleague started writing or an assistant ran an errand, the front desk used to take away the sticky note you were choosing or even hand you paperwork from next door; now responsibilities are clearly divided, so progress is never mixed up.

Previously, opening a new window for progress handoff often mistakenly attached to an ongoing conversation next door; now, sessions that remain open with writes within 10 minutes are skipped, while recently closed windows still hand off normally. Background task completion notifications, commands run with !, and slash commands without arguments are also no longer treated as recent requests. Since Claude Code 2.1.299, when background subagents or teammates started a turn, they accidentally triggered a signal that cleared Beginner Mode terms above the input box; now, they are cleared only when the main conversation starts a new turn, so selecting words is no longer interrupted midway.
