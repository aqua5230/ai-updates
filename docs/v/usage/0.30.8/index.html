zh-TW

macOS 應用程式套件的文字介面又能開了，字寬表完整打包不閃退

從 macOS 應用程式套件啟動終端文字介面時，畫面不再因缺漏字寬資料而當場閃退。出門施工若只帶工具本體，漏掉夾層裡的零件，到現場就無法開工；整箱連同配件帶齊才不缺件。打包工具 py2app 原本把 rich 列在 includes，只收集靜態引用掃得到的檔案。但 rich/_unicode_data/__init__.py 是在繪圖當下以 import_module() 動態載入各版本 Unicode 字寬表，導致打包出的 app 僅帶了 __init__ 與 _versions，一畫第一張表格就當場崩潰：

usage --tui  # 拋出 ModuleNotFoundError: No module named 'rich._unicode_data.unicode17-0-0'

不經過 rich 渲染的選單列模式不受影響。現在 rich 改列在 packages，整包目錄直接複製而非只收掃得到的片段，文字介面（TUI，終端文字操作畫面）恢復正常。

Fable 5.1 補上離線備援價格，對帳腳本不再整族跳過

Claude Code 2.1.257 起將 Fable 5.1（claude-fable-5-1）設為預設，離線計價缺口如今補齊。先前寫死的備援價目表只有 claude-fable-5，每當下載價目表缺失或過期，Fable 5.1 的每個 token（AI 計費單位）都被算成 $0。它的快取重讀價是 0.25e-6，只有 Fable 5 的四分之一，沿用舊資料也不正確。此缺口過去未被察覺，因 scripts/check_fallback_pricing.py 只比對 opus|sonnet|haiku，不論新舊皆跳過 Fable 家族。現在 Fable 5.1 已補上離線價格，對帳腳本也納入稽核。保險費率表漏記新車的備援費率，斷線時計價直接歸零，查帳員還只抽查舊車；現在費率與稽核皆已補齊。

帶日期模型不再退回新版價格，補齊五款服役中模型

查詢帶日期的舊模型離線價格時，程式不再誤退回到較新版本的便宜價格。公車站牌若只看開頭數字，想搭四號公車的乘客會被載上四之六號新線；現在完整對齊路線才放行。先前 _resolve_model_key 只要鍵名以查詢字串加連字號開頭就算命中。這讓 claude-opus-4-20250514 被解析成 claude-opus-4-6，離線時每百萬 token（AI 計費單位）算 $5 而非真實的 $15，只有真實費用的三分之一。現在查詢自帶版本號時，不再接受追加尾數的候選；無版本號的泛稱如 claude-sonnet 照舊解析得到，同等具體程度取較新版本，具名變體（gpt-5 到 gpt-5-pro）不受影響。表裡原本缺失但仍在服務的五個模型一併補上，並剝除 Bedrock 版本後綴讓查詢正確計價：

claude-opus-4
claude-opus-4-1
claude-opus-4-5
claude-sonnet-4
claude-sonnet-4-5
claude-sonnet-4-5-20250929-v1:0  # 剝除 Bedrock 後綴（v1:0）後正確計價

備援價目表對帳改採解析比對，消除誤報與常態錯誤結束代碼

檢查備援價目表的對帳腳本現在只回報解析失敗的模型，不再給出一份無人能處理的混亂清單。先前 compare_pricing 兩個方向都用字面鍵名相減，但備援價目表本就刻意不帶日期後綴。這讓明明算得出價格的模型（例如 claude-haiku-4-5 與 claude-opus-4-7-20260416）都被報成缺漏。回報的 12 筆缺口有 3 筆是假的，腳本的結束代碼也因此長期為 1，真的缺口混在雜訊裡看不出來。現在兩個方向都改用 _resolve_model_key 判斷。門禁警報若死板比對整串卡號，刻意省略換證日期的合格卡全被誤報成黑名單，警示燈常亮反而掩蓋了真正的闖入者；改採對照解析後才恢復平靜。

用量表格顯示 Opus 5 與 Fable 5.1 簡稱，不再只印原始代號

打開終端機檢視用量表格時，畫面本該為各個模型顯示簡短易讀的名稱，方便一眼掌握用量分佈。但先前簡稱字典 MODEL_SHORT 裡缺少了 Opus 5 與 Fable 5.1 這兩款新條目，導致表格在列出用量時，只能直接印出長串的原始模型代號（raw model IDs），讓整行排版顯得雜亂又難以閱讀。現在用量表格已補齊這兩款模型的對照設定，會端正顯示簡短名稱。手機通訊錄若漏填好友姓名，來電時螢幕只能秀出一長串電話號碼；補上暱稱後，一眼就能認出是誰撥來。

配額提醒提早至用掉一半即發送，單次讀數最多一則通知

你的配額通知現在會提早跳出提醒，且單次讀數絕不連續送出兩則重複通知。Codex 0.153.0 起，五小時視窗剩不到一半就會提醒 Plus 與 Team 使用者。但 usage 先前等到 90% 才提醒，等於被監控的工具比監控端還早出聲。預設門檻在 macOS 與 Windows 一致改為 [50.0, 90.0]，仍可透過 quota_notification_thresholds 自行調整。由於單次讀數可能一口氣跨過兩個門檻，例如 app 在配額已達 95% 時才啟動，或用量單次大跳。此時只有跨過的最高門檻會發送通知，其餘標記為已通知並鎖定，一次觀測絕不冒出兩則重複提醒。河川警戒在水位達一半與九成時各廣播一次，若暴雨讓水位瞬間破九成，警報只響最緊急的紅燈，不重複播送低階警訊。

en

The TUI launches from the macOS app bundle again, packing complete character width tables without crashing

When launching the terminal text user interface from the macOS app bundle, the screen no longer crashes on the spot due to missing character width data. If you head out to a job site carrying only the main tool while leaving the parts in the compartment behind, you cannot start work once you arrive; bringing the whole case along with all accessories ensures nothing is missing. The packaging tool py2app previously listed rich under includes, collecting only files reachable by static import scans. However, rich/_unicode_data/__init__.py dynamically loads per-version Unicode width tables via import_module() at render time, causing the packaged app to carry only __init__ and _versions and crash immediately upon drawing the first table:

usage --tui  # throws ModuleNotFoundError: No module named 'rich._unicode_data.unicode17-0-0'

Menu bar mode, which does not render through rich, is unaffected. rich is now listed under packages so the entire directory is copied directly rather than only scanned fragments, restoring the text user interface (TUI) to normal.

Fable 5.1 gains offline fallback pricing, and the audit script no longer skips the entire family

Claude Code 2.1.257 set Fable 5.1 (claude-fable-5-1) as the default, and the offline pricing gap is now filled. The hard-coded fallback price table previously only contained claude-fable-5, so whenever the downloaded price table was missing or expired, every Fable 5.1 token was costed at $0. Its cache-read price is 0.25e-6, only a quarter of Fable 5's, so inheriting older data would also be incorrect. This gap went unnoticed in the past because scripts/check_fallback_pricing.py only matched opus|sonnet|haiku, skipping the Fable family regardless of whether models were old or new. Now Fable 5.1 has its offline price added, and the audit script includes it in checks. An insurance rate sheet missed fallback rates for new car models, resetting pricing to zero during outages while auditors only sampled old cars; now both the rates and audit coverage are complete.

Dated models no longer fall back to newer version pricing, adding five active models

When querying offline prices for older dated models, the program no longer mistakenly falls back to the cheaper price of a newer version. If a bus stop sign only looks at the leading digit, passengers looking for Bus 4 would be carried onto the newer 4-6 line; now the full route must match before letting them board. Previously, _resolve_model_key counted any key starting with the query string followed by a hyphen as a hit. This caused claude-opus-4-20250514 to resolve to claude-opus-4-6, costing $5 per million tokens offline instead of the actual $15—only one-third of the real cost. When a query carries its own version number, candidates with an appended trailing digit are no longer accepted. Generic names without version numbers like claude-sonnet still resolve as before, picking the newer version among equally specific keys, while named variants (gpt-5 to gpt-5-pro) remain unaffected. Five models still in service that were previously missing from the table have been added, and Bedrock version suffixes are stripped so queries price correctly:

claude-opus-4
claude-opus-4-1
claude-opus-4-5
claude-sonnet-4
claude-sonnet-4-5
claude-sonnet-4-5-20250929-v1:0  # prices correctly after stripping Bedrock suffix (v1:0)

Fallback pricing audit switches to resolution matching, eliminating false positives and persistent error exit codes

The audit script checking fallback pricing tables now only reports models that actually fail to resolve, rather than outputting a confusing list that no one could act on. Previously, compare_pricing diffed raw literal keys in both directions, even though the fallback table deliberately omits date suffixes. This caused models that could calculate prices perfectly well (such as claude-haiku-4-5 and claude-opus-4-7-20260416) to be flagged as missing. Three of the 12 reported gaps were false, keeping the script's exit code at 1 persistently and making real gaps indistinguishable from the noise. Both directions now evaluate models through _resolve_model_key. If an access control alarm rigidly compares full card numbers, valid cards deliberately omitting renewal dates get falsely flagged as blacklisted, and a constantly lit warning light ends up masking real intruders; switching to lookup resolution restores calm.

Usage table displays short names for Opus 5 and Fable 5.1 instead of raw model IDs

When opening the terminal to view usage tables, the screen should display short, readable names for each model to help grasp usage distribution at a glance. However, the short-name dictionary MODEL_SHORT previously lacked entries for Opus 5 and Fable 5.1, forcing the table to print long raw model IDs and making the layout cluttered and difficult to read. The usage table now includes mapping entries for both models, displaying clean short names properly. If a phone contact list misses a friend's name, incoming calls only show a long phone number on the screen; once the nickname is added, you can recognize who is calling at a glance.

Quota warnings fire earlier at 50% usage, sending at most one notification per reading

Your quota alerts now trigger earlier, and a single reading never sends two consecutive duplicate notifications. Starting with Codex 0.153.0, Plus and Team users are warned once less than half of the five-hour window remains. However, usage previously waited until 90% before alerting, meaning the monitored tool warned earlier than the monitor itself. The default threshold is now consistently set to [50.0, 90.0] across macOS and Windows, while remaining customizable via quota_notification_thresholds. A single reading can cross both thresholds at once, such as when the app launches with quota already at 95% or during a single large usage jump. In this situation, only the highest crossed threshold sends a notification while the rest are latched as notified, ensuring one observation never generates two duplicate alerts. A river warning system broadcasts once at half and once at ninety percent water levels; if a torrential storm pushes water past ninety percent instantly, only the most urgent red alert sounds without replaying lower-level warnings.
