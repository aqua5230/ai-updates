Usage 0.34.12

Released: 2026-11-04

Release notes

FEATURE

Quota Checks Support More Installers, with Real-Time Usage and Reset Countdowns

When running multiple AI conversations in the background or using different package managers, quota and usage updates in the menu bar no longer lag behind.

Think of checking real-time heart rate on a sports watch: each step's exertion is settled on the spot instead of waiting until the run is over, and the timer does not reset every time.

The menu bar app starts with a short PATH, so commands installed with nvm, Volta, fnm, mise, asdf, bun or pnpm were often treated as missing, and npm-installed tools could not find node. Now the quota keepers and the Antigravity and Muse quota checks find them reliably. New usage written to the database journal during an Antigravity conversation is counted in real time without waiting for the conversation to finish. A custom Claude Code data folder (CLAUDE_CONFIG_DIR) now syncs in real time instead of lagging by up to 15 minutes. When Codex reports "resets in N seconds", the countdown now starts from the recorded time so refreshing no longer resets the seconds.

FEATURE

Cleaner Installs and Uninstalls Protect Configuration Files from Accidental Edits

When tweaking terminal settings or removing tools, the biggest worry is having personal preferences unexpectedly changed, or even having apps fail to launch due to corrupted config files. Turning off the status line shown at the bottom of the terminal from the menu now keeps it off after a restart. Running usage unsetup or --unsetup turns off the quota reminder hook (a small program triggered by specific events), the side panel, and beginner mode. Uninstalling restores your own status line if you turned it off, while preserving your personal settings. If ~/.claude/settings.json is corrupted, the menu bar app still skips the setup prompt and starts as usual to show usage for each tool. Codex setup no longer accidentally edits config.toml, leaving the file untouched if multi-line instructions contain [tui] and prompting you to manually adjust status_line. Broken curl install scripts and LaunchAgent scripts have both been fixed.

BUGFIX

Reports Align with Local Time and Generation Dates, Fixing Skewed Stats and Crashes

If you want to track daily usage expenses precisely, terminal and HTML reports now faithfully reflect your local schedule. Reset times and session start times in terminal reports now use local time, and daily averages around midnight are no longer calculated using UTC dates. Tables whose records are all zero tokens (units of text processed and billed by AI) no longer crash. The per-minute rate in the blocks view no longer counts cache reads, matching the menu bar. Running usage sessions --sort sessions automatically applies the default sort order instead of crashing. Today, Last 7 days, Last 30 days and This month in the HTML report now count from the day the report was generated instead of the last day with usage, preventing them from showing data from last week. The report also opens properly after switching time zones or when transcripts contain timestamps without a time zone. Menu bar icons update accordingly when the top three tools share equal percentages, and project rankings on daylight saving transition days now correctly include the first hour.
