Windows 狀態列不再永遠空白

Windows 電腦沒裝 Python 時，Claude Code 面板不會再永遠只顯示「--」。安裝程式原本只看 PATH（告訴電腦去哪找程式的搜尋名單）裡有沒有 python 或 py，卻沒確認它能不能跑；Windows 10、11 內建的 App Execution Alias 只是引你去 Microsoft Store 安裝的假 python.exe，也會被誤認。於是 statusLine hook（顯示在終端機最底下狀態列的掛鉤小程式）每次更新都靜悄悄失敗，usage-status.json 沒寫出來，面板便一直空白。現在安裝程式會先用 --version 實測候選程式，不能執行就跳過。像插座看似有孔、裡頭卻沒接電；現在會先試亮測電筆，才把線接上。

en

Windows status line no longer stays blank forever

On a Windows PC without Python, the Claude Code panel will no longer show -- forever. The installer used to trust any python or py found on PATH (the list of places Windows searches for programs) without checking whether it could run. Windows 10 and 11 ship an App Execution Alias: a placeholder python.exe that only sends you to Microsoft Store, yet it was mistaken for Python. The statusLine hook, a small program that updates the bottom status line, then failed silently on every refresh, so usage-status.json was never written. Now each candidate must pass --version first. It is like testing an outlet before plugging in the appliance.

原始 CHANGELOG

Original changelog
**Claude Code panel no longer stays blank forever on Windows**: the installer picked whichever `python`/`py` `shutil.which()` found on `PATH` without checking it actually ran, so on any Windows machine without a real Python install, it silently wired the statusLine hook to Windows' non-functional "App Execution Alias" stub (the placeholder `python.exe`/`python3.exe` that Windows 10/11 ships by default to prompt a Microsoft Store install). The hook then failed silently on every refresh, `usage-status.json` was never written, and the Claude Code panel showed `--` permanently — not a first-run loading state. The installer now actually runs each candidate with `--version` before trusting it, and skips any that don't execute.
