en

Invisible housekeeping: menu bar code gets divided up and size limits get enforced

Nothing new appears in the menu bar in this release; the work is behind the wall. menubar.py had grown to 2,485 lines and crossed 2,000 for the third time. Icon and alert helpers now live in menubar_chrome.py, while state constructors moved to menubar_state.py, bringing the original file down to 2,230 lines. Only file-level functions moved: PyObjC, the bridge between Python and macOS Objective-C, connects controls through AppDelegate method names, so moving one would silently break its control. _popover_size was split into a calculation function with a three-line shell left behind, keeping menubar_state.py testable without the ObjC runtime. CI, the automatic check run on changes, now fails a build when a guarded file exceeds its limit; after a cut, lower the limit rather than raising it to pass. CLAUDE.md's module map also shrank from 24 rows to 12, keeping only warnings that are not obvious from opening each module. It is like reorganizing plumbing: no new fixture appears, but later repairs need not keep breaking through a larger wall.

ko

보이지 않는 정리: 메뉴 막대 코드를 나누고 크기 제한을 자동으로 지킨다

이번 판을 열어도 메뉴 막대에 새 버튼이나 화면이 생기지는 않는다. 벽 안쪽에서 하는 정리다. menubar.py는 2,485줄까지 불어나 세 번째로 2,000줄을 넘겼다. 아이콘과 알림 보조 함수는 menubar_chrome.py로, 상태를 만드는 함수는 menubar_state.py로 옮겨 원래 파일을 2,230줄까지 줄였다. 파일 맨 위에 직접 쓴 함수만 옮겼다. PyObjC는 Python과 macOS의 Objective-C를 잇는 다리이며 AppDelegate 메서드 이름으로 조작 부품을 연결하므로, 그것을 옮기면 해당 부품이 소리 없이 작동을 멈춘다. _popover_size는 계산 함수로 나누고 세 줄짜리 껍데기를 남겨 ObjC 실행 환경 없이도 menubar_state.py를 단위 테스트할 수 있게 했다. CI는 변경 때마다 자동 검사하는 절차로, 대상 파일이 한도를 넘으면 빌드를 실패시킨다. 파일을 나눴다면 한도를 낮추며, 통과하려고 올리지는 않는다. CLAUDE.md의 모듈 지도도 24줄에서 12줄로 줄여 파일을 열면 알 수 있는 설명을 뺐다. 집 배관을 정리하듯 겉모습은 같아도 나중 수리 때 벽을 더 크게 뜯지 않게 한다.

Original changelog
**Nothing changes on screen in this release — it is housekeeping on the menu bar code.** `menubar.py` had reached 2485 lines, creeping past 2000 for the third time after being split apart twice. The icon and alert helpers moved into a new `menubar_chrome.py`, and the state constructors joined `menubar_state.py`, taking the file down to 2230. Only module-level functions moved: PyObjC binds `AppDelegate` methods by selector name, so relocating one would silently stop the matching control from working. `_popover_size` was split rather than moved, because it ends in `NSMakeSize` and `menubar_state.py` has to stay importable without the ObjC runtime for its projections to be unit-testable — the arithmetic moved as `popover_dimensions()` and a three-line shell stayed behind.
**The growth policy behind that cleanup is now enforced by CI rather than by discipline.** `scripts/check_file_size.py` fails the build when a guarded file passes its ceiling. The rule had been written in CLAUDE.md all along; nothing checked it, and the file grew back twice. Lower a ceiling when a cut lands, never raise it to go green.
**CLAUDE.md's module map lists only modules with a gotcha.** Half its rows restated what opening the file would tell you, and three separate rows repeated the same stdlib-only constraint. It went from 24 rows to 12.
