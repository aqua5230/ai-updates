Usage 0.30.6

Released: 2026-08-31

Release notes

FEATURE

Grok CLI gets its own usage status line

A restaurant chain opens a new branch and fits it with the same order board; when the branch closes, the owner's original sign goes back up rather than being left bare.

Grok CLI supports the same command-style status line mechanism as Claude Code, so usage_statusline_grok.py joins the existing install / remove / self-heal flow behind the switch already shared with Claude Code and Antigravity.

Grok's stdin payload carries no rate-limit summary — its documentation says so explicitly — so the script tails ~/.grok/logs/unified.jsonl for creditUsagePercent and currentPeriod.end; when neither can be read the segment is omitted rather than printed as placeholder characters. Only the weekly axis is shown, since Grok has no 5-hour window and reports no cache hit ratio, and neither is estimated.

FEATURE

The status line's second row shows cache hit rate and a countdown

Claude Code 2.

1.251 added a prompt_cache object to the status line hook's stdin JSON, and usage was already storing the whole payload in usage-status.json without reading it. The second row now shows the prompt cache hit rate and a countdown to expiry. A new color_by_pct_inverted() mirrors the thresholds, so a 91% hit rate reads as good instead of borrowing the quota palette's red, and progress_bar() takes an optional color_func, leaving existing callers unchanged. The segment is skipped entirely when caching_observed is not True or the ratio is unavailable, so older Claude Code versions silently omit it; an expired expires_at drops only the countdown and keeps the bar. Narrow terminals degrade in two further steps: the countdown goes first, then the whole segment.

When a dashboard runs out of room it drops the secondary reading first, then the whole cluster, rather than cramming the figures together.
FEATURE

The status line lights up the numbers and dims everything else

Stage lights fall on the speaker while the set and the aisles go dark, so the audience looks where it should.

Empty progress cells, the context window total, and the | separators were pure white and brighter than the figures themselves; they are now grey 240 / dim, leaving usage as the only lit element.

The second row is secondary information, so a cache hit rate of 80% or better takes that row's muted purple and only turns orange below 80% and red below 50% — good news does not need to glow. The same batch reworded the cache countdown. The previous wording was a literal rendering of warm/cold that read as nothing in particular; it now reuses the existing remaining_prefix, giving (59min left) in English alongside the two segments before it. cache_cold_suffix, used in exactly one place, was removed, so five languages no longer need a separate word for it.

FEATURE

A third-party status line with a similar name is no longer taken over

A warehouse keeper hauls off a box because it says "battery", when the label reads "battery tester"; now the whole product name has to match before anything moves.

Hook ownership was decided by the substring test "usage-statusline" in cmd, so someone else's usage-statusline-pro.py was treated as a usage installation: taken over without a backup, and its configuration deleted on uninstall.

The comparison now matches the complete filename, derived from HOOK_TARGET.name and its siblings instead of a hardcoded string, requiring a path separator, quote, whitespace, or string boundary on each side. It deliberately does not compare full paths: the command string shifts with interpreter location, quoting, and Windows backslashes, and a path comparison would stop usage recognizing itself.

FEATURE

The status line's file lock times out instead of hanging

Every message you sent left the status line stalled, because another process was holding the same lock.

_exclusive_lock()'s POSIX branch used a plainly blocking flock(LOCK_EX), while the Windows branch already had a 10-second _LOCK_TIMEOUT_S guard. The POSIX branch now polls with LOCK_EX | LOCK_NB and, on timeout, follows the msvcrt path: the atomic write proceeds without the lock.

If a shared laundry room's door lock only ever waits for the previous user, the queue stops dead; now, after a set wait with no movement, it opens under the safe procedure.
FEATURE

Installed status line copies actually update now

A shop's price board is only reprinted when the master list's revision number changes, so a price that moved without a new revision leaves the shop showing the old figure.

needs_update() compares __version__ in ~/.claude/usage-statusline.py against HOOK_VERSION and skips the copy when they match, so rendering changes that shipped without a version bump never reached an installed copy, silently and with no error.

Both constants were bumped, and a drift test was added: the Token Saver hook had that guard already; the status line was missing it.

FEATURE

The report adds a first-pass rate, compared across models

A team starts tracking not just points but the share of drives that score on the first attempt, and when the same squad tries different plays that number shows which one fits.

The report's usage habits section gained a card measuring what share of your turns this period ran without an interruption and without a blocked tool call, split by model — a quality axis rather than another quota count.

Both signals are structural, read from ~/.claude/projects: interruptedMessageId on user lines, and permission-denial strings inside tool_result content; nothing is inferred semantically. The denominator is user turns rather than assistant messages, because a single exchange emits a dozen assistant messages and would compress every model above 99.5%. Multiple interruptions inside one turn count once. Angle-bracketed internal markers such as <synthetic> are excluded. Interrupted assistant messages are frequently aborted before reaching disk, so unresolvable signals go to an unattributed bucket and are not shown rather than being assigned to a model. The insight line is written only when the spread between the highest and lowest model exceeds 15 points.

FEATURE

The report draws a day-by-day curve and prints properly

The report's header already named the period's peak day, but you had no chart to check it against: daily_trend held 30 days of data that no chart used.

A daily area line now sits above the weekly rollup, marking the highest day and labelling only the period's first and last dates. The stylesheet also gained a @media print block: sections avoid internal page breaks, interactive controls are hidden, shadows and offsets are removed, and colors invert to dark-on-white so a PDF stays readable when the reader is in dark mode.

Turning an exhibition poster into a printed handout swaps the screen's dark ground for dark type on white paper and drops the interactive buttons, so the copy in your hand still reads clearly.
FEATURE

The report's tables, charts, and section rhythm were filled in

A score marked at one dynamic throughout sounds flat; once the loud and soft marks go in, the same notes gain shape.

The five heaviest sessions were the report's only all-text table; the tokens column now carries a thin bar scaled against the largest of the five, colored by the same provider palette the model table uses.

The active-hours chart, previously hour labels alone, now marks its peak value in muted type in the lower right, with no gridlines or Y axis added. The ten sections shared one identical treatment; insights and the heatmap now carry heavier shadows while the recent-work and tools sections are lighter with --faint borders — shadows and borders only, since the persona section holds two cards and a background change would make their height difference conspicuous.

FEATURE

Project and model rows in the report carry share bars

Comparing ten stacked rows previously meant reading the numbers.

Each name now has a 4px solid proportion bar beneath it — solid rather than gradient, so the color is not misread as carrying meaning. The donut's "Other" slice, which used to draw the palette's seventh color and read as nearly the same green as the first, is now a neutral #8b8577, selected inside _donut_svg by a synthetic flag rather than guessed from its index.

When two adjacent shelf categories carry nearly the same spine color, finding a book means checking each one; making the "other" category grey lets the eye skip it at once.
FEATURE

A week still in progress is no longer compared against a complete one

Weighing yourself mid-meal and comparing that against last week's complete record makes the scale say you shed 97% overnight.

The weekly trend measured the current partial week against the previous full one, which on Monday 2026-08-31 produced "W36 ↘ −97%" and the conclusion that this week was 97% lighter.

The final week is now marked in progress when its Sunday falls after date_to (new trend_week_in_progress key, added in all five languages) and shows no percentage, and _trend_summary() compares the last two completed weeks instead.

FEATURE

The Antigravity model name stops mixing two languages, and the menu bar title tightens

A name badge printing the job title in English and then again in another language says the same thing twice; now only the one the reader understands stays.

Antigravity's display_name already ends in an English effort suffix such as (High), and usage appended a localized one after it, naming the same level twice in two languages.

The English suffix is now stripped and only the localized label is kept; when display_name carries no effort field, the stripped suffix becomes the source. The menu bar title tightened up too: the interpunct separator was removed, since the provider icons already separate the figures, and icon spacing was reduced to two spaces. Separately, prompt cache health was documented in all five READMEs under real-time visibility, noting it needs Claude Code 2.1.251 or newer, and the website's description of the AI Tool Update Digest was removed, a report section that no longer exists.

FEATURE

Uninstalling restores Grok's original status line

When a rented flat is handed back, the landlord's original lamp goes back up; a tenant who takes their own lamp and restores nothing leaves the next person with bare wires in the ceiling.

unsetup() handled Claude Code and Codex but skipped Grok, so after --unsetup the user's ~/.grok/config.toml still pointed at a usage script with no supported way back to their own [ui.status_line].

Uninstalling now restores Grok's original status line. The old test exercised only the private _unsetup_grok(), which is why this slipped through; the new one enters through the public unsetup().

FEATURE

Weekly burn trend bars are now CSS gradients

The donut, heatmap, and active-hours chart on the same page were all drawn graphics, while the weekly trend drew its bars with █ characters, looking pasted in from another document.

Those bars are now CSS gradients. The four-column layout and terminal styling are unchanged; the rendering moved into a new ui/report_charts.py.

In an art book where every plate is printed, one page carries a picture assembled from typewriter symbols; that page is now printed the same way as the rest.
FEATURE

The heatmap stops skipping months, and the donut agrees with the table

When a week straddles two months, always deciding by its Monday hands the whole week to the old month it touched for a day; reading the Thursday instead puts the week on the side it actually spent longer in.

A heatmap column's month was taken from its Monday, so a week spanning a month boundary was credited to the old month it barely touched, and a label suppressed by the spacing rule was lost permanently — real output dropped September entirely.

The month is now read from the column's Thursday and compared against the last month actually labelled, so a suppressed month reappears at the next column that satisfies the spacing. Separately, the project donut divided by the sum of by_project[:10] while the table's percentage used total tokens, so one project showed 42.5% in the chart and 36.1% in the table, and the center figure read as a total it was not. The denominator is now summary.total_tokens, with everything not shown (including projects outside the top ten) combined into an "Other" slice reusing the existing report_chart_other string.

FEATURE

Interruptions and denied tools on messages with no model name are no longer dropped

Checking in a delivery, the boxes with no sender written on them are filed under no supplier and never added to the "unknown origin" pile either, so the count comes up short.

A message carrying message.id but no message.model was indexed as an empty string, while the later check tested only model is None.

Those events were therefore neither attributed to a model nor counted as unattributed, undercounting interruptions in the first-pass rate described on the previous card. That is now fixed.

FEATURE

A report with no usage renders a clean empty state

At zero usage the narrative sentence interpolated zeros and placeholders — "---- -- -- was the peak (0/day), main LLM 未知" — above seven sections each saying only "nothing here yet", which is what a new user saw on first open.

When both total_tokens and messages are zero the narrative is now replaced by report_empty_state_hint, a key added in all five languages, and only the header, stat cards, and sponsor section render. Output with data is byte-identical; the untouched full_zh_tw and full_en snapshots are the proof.

A restaurant not yet open for business should not print a menu full of zero-price dishes; a "preparing" sign on the door is enough.
