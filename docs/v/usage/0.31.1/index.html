Usage 0.31.1

發布日期：2026-09-27

繁體中文

新功能

心電圖面板主題登場，用量高低化為即時跳動波形

在日常盯著各家模型額度時，你現在能用醫院監視器風格的畫面掌握消耗狀況。

像看跑車儀表板上的動態轉速表，以前查用量只能盯著單純的數字進度，現在消耗節奏直接化為起伏波形，用量越凶波峰跳得越急。

新加入的心電圖（Heart Monitor）主題採用深色網格背景。每一列額度旁邊都有一條持續捲動的心電圖與等寬大字讀數，當用量越高，波峰會長得越高且跳動得越快。原本的 50% 與 80% 警示及危險配色，以及 80% 記號都完整保留。如果你在系統中開啟了「減少動態效果」，波形動畫就會貼心暫停。這項主題在 macOS 與 Windows 都能使用，讓可選的面板總數增加到 16 款。

新功能

Windows 面板視窗精準貼合內容，放大文字不再冒出多餘捲軸

當你在 Windows 調大文字大小，開啟面板不會再看到擠在邊緣的垂直捲軸。

照片接連放大兩次，若相框只照第一次尺寸做，邊緣仍會被擠住；按最後尺寸做才裝得下。

這是先前視窗問題（[#153]）的後續改進。若 Windows「文字大小」非 100%，會在顯示縮放外疊加 WebView2 縮放倍率（如 125% 乘 109% 達 1.3625）。舊版 GetDpiForWindow 未計入這層放大，使視窗比內容矮約 8% 而冒出捲軸，隱藏卡片也沒用。現在頁面會回報內容高度與 devicePixelRatio（實際顯示倍率），面板依此換算視窗大小、工作區、已存位置與可讀性下限，未回報前則退回顯示縮放。針對 pywebview 呼叫 resize() 與 move() 重複乘上縮放的問題，也依兩者比值補正。

English

FEATURE

Heart Monitor popover theme debuts, turning quota usage into live pulsing waveforms

When keeping an eye on model quotas each day, you can now track consumption with a hospital-monitor style interface.

Picture a dynamic tachometer on a sports car dashboard: while you previously checked usage by staring at plain numeric progress, consumption rhythm is now rendered as an undulating waveform where heavier usage triggers faster, taller peaks.

The newly added Heart Monitor theme features a dark grid background. Next to each quota row is a continuously scrolling ECG trace alongside large monospace readings; as usage rises, the peaks grow taller and pulse faster. The original warning and danger color schemes for 50% and 80%, along with the 80% marker, are fully preserved. If you have "Reduce Motion" enabled in your system settings, the waveform animation pauses automatically. This theme is available on macOS and Windows, bringing the total number of selectable themes to 16.

FEATURE

Windows popover window fits content accurately, eliminating unwanted scrollbars when scaling text

When you increase text size on Windows, opening the popover will no longer display a vertical scrollbar crammed against the edge.

When a photo is enlarged twice in succession, building the frame based only on the first resize still cramps the edges; only sizing it for the final dimensions makes everything fit.

This is a follow-up improvement to a previous window issue ([#153]). If Windows "Text size" is not 100%, WebView2 zoom is compounded on top of display scaling, such as 125% multiplied by 109% reaching 1.3625. The legacy GetDpiForWindow did not account for this extra scaling layer, leaving the window roughly 8% shorter than its content and causing scrollbars to appear even if cards were hidden. The page now reports content height and devicePixelRatio (effective display scale), which the popover uses to calculate window dimensions, workspace, saved positions, and readability floors, falling back to display scale before reporting occurs. To address pywebview redundantly multiplying scaling on resize() and move() calls, values are corrected using the ratio between both scales.
