English

Homebrew install path fixed, and Claude Code no longer crashes on startup after .app hook installs

Homebrew installations will no longer throw errors, and manual App installers don't have to worry about broken config files. Previously, installing usage via Homebrew would fail at the very last step due to a misaligned zip path, throwing a "file not found" error; the path is now fixed, so a simple reinstall works flawlessly. Furthermore, if you dragged the .app to your Mac and clicked "Install Status-Line Hook", it used to accidentally write the path to the app's internal, bundled Python interpreter into your config. Because that internal Python can't run independently outside the bundle, Claude Code would completely panic on startup, throwing errors about missing libraries and refusing to show the status line. It now strictly uses your Mac's built-in system Python. If your config was already corrupted by the old version, don't worry—it automatically repairs itself the next time you launch or re-run the setup. It's like a car dealership handing you a proprietary charging cable that only fits the sockets inside their showroom, leaving you stranded with a dead car at home; now they hand you a universal cable, and if they gave you the wrong one earlier, they'll magically swap it out for the right one.

原始 CHANGELOG

Original changelogHomebrew 安裝不再報錯，Claude Code 啟動不再掛點
**Homebrew install no longer fails**: because the release zip had a single top-level `usage.app` directory, Homebrew would auto-`chdir` into it and then fail to find the file to install, raising `Errno::ENOENT ... usage.app`. The formula's install path is fixed — just reinstall. (Thanks @teddy123434 for reporting #32)
**Claude Code no longer errors on startup after installing the status-line hook from the .app**: installing from the packaged .app used to write the app's bundled Python — which can't run standalone outside the bundle — into the hook config, so Claude Code threw `Could not find platform independent libraries` on startup and the status line wouldn't show. It now always uses the system `/usr/bin/python3`, and any previously corrupted config is repaired automatically on next launch or re-run of setup. (Thanks @teddy123434 for reporting #32)
