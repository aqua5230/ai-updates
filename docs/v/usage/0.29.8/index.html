zh-TW

切換面板不再把視窗送回主螢幕

你把 Usage 的面板（跳出的浮動小視窗）拖到第二台螢幕，換個面板樣式或主題後，它終於不會又跳回主螢幕。以前 Windows 只把主螢幕可用範圍交給程式，程式每次重新定位面板時便拿錯尺，硬把第二台螢幕上的視窗推回去；現在會依面板目前或記住的位置，找出它所在螢幕的可用範圍再定位，所以換樣式後仍留在原處。單螢幕也一併修好：面板切換時會暫留前一種樣式量到的高度，等真正高度測完，不再先用接近全螢幕的假高度把你拖好的位置往上擠。像搬家工人終於先看你住哪一棟，再把家具放回那一棟，而不是一律送回一樓。

en

Panel switching keeps your window on its monitor

After you drag Usage's panel (a small floating pop-up) to a second monitor, switching its style or theme will finally leave it there. Windows had only handed the app the primary display's usable area, so each reposition used the wrong ruler and shoved the panel back onto the primary monitor. It now identifies the usable area for the display containing the panel's current or remembered position. On a single monitor, it also retains the previous style's measured height while the new one is measured, instead of briefly using a near-fullscreen placeholder that pushes your window upward. Like movers checking which building you live in before returning furniture, rather than always dumping it in the lobby.

zh-CN

切换面板不再把窗口送回主屏

你把 Usage 的面板（弹出的浮动小窗口）拖到第二块屏幕后，切换面板样式或主题，它终于不会再跳回主屏。以前 Windows 只把主屏可用范围交给程序，程序每次重新定位面板时便拿错尺子，硬把第二块屏幕上的窗口推回去；现在会按面板当前或记住的位置，找出它所在屏幕的可用范围再定位，因此切换样式后仍留在原处。单屏也一并修好：切换面板时会暂留前一种样式量到的高度，等真正高度测完，不再先用接近全屏的假高度把你拖好的位置往上挤。像搬家工人终于先看你住哪一栋，再把家具放回那一栋，而不是一律送回一楼。

ja

パネルを切り替えてもウィンドウが主モニターへ戻らない

Usage のパネル（画面上に浮かぶ小さなウィンドウ）を二台目のモニターへドラッグした後、パネルの見た目やテーマを切り替えても、主モニターへ戻されなくなった。以前は Windows が主モニターの使える範囲しかアプリに渡さず、パネルを置き直すたびに物差しを取り違えて二台目から押し戻していた。今はパネルの現在位置または記憶した位置があるモニターの範囲を調べて配置するため、切り替え後もその場に残る。一台だけの環境でも、見た目の切り替え中は前の高さを仮に使い、本当の高さを測る前に全画面に近い仮の高さでウィンドウを上へ押しやらない。引っ越し屋が住んでいる棟を確かめて家具を戻し、いつも一階へ運び込まないようなものである。

ko

패널을 바꿔도 창이 주 모니터로 돌아가지 않는다

Usage 패널(화면 위에 떠 있는 작은 창)을 두 번째 모니터로 끌어 놓은 뒤 패널 모양이나 테마를 바꿔도, 이제 주 모니터로 되돌아가지 않는다. 예전에는 Windows가 주 모니터의 사용 가능한 범위만 앱에 알려 주었고, 앱은 패널 위치를 다시 잡을 때마다 엉뚱한 자를 대 두 번째 모니터의 창을 밀어냈다. 이제는 패널의 현재 위치나 기억해 둔 위치가 있는 모니터의 범위를 찾아 배치하므로, 전환 뒤에도 그대로 남는다. 모니터 한 대만 쓸 때도 이전 모양에서 재 둔 높이를 새 높이가 측정될 때까지 임시로 유지해, 거의 전체 화면 크기의 임시 높이가 창을 위로 떠밀지 않는다. 이삿짐센터가 어느 동에 사는지 확인하고 가구를 되돌려 주며, 늘 1층에만 내려놓지 않는 것과 같다.

原始 CHANGELOG

Original changelog
**The Windows panel no longer snaps back to the primary monitor on every panel switch**: dragging the popover onto a second display and then switching panel style (or theme) forced it right back onto the primary monitor. Windows' `SPI_GETWORKAREA` API only ever reports the *primary* monitor's work area, and the window was clamped against that single rectangle on every reposition regardless of which monitor it actually lived on — so a window dragged onto a secondary display got clamped straight back onto the primary one the next time the panel reloaded. Placement now looks up the work area of whichever monitor the window's current (or saved) position falls on via `MonitorFromPoint`/`GetMonitorInfoW`, so a window on a secondary display stays there across panel switches. A related issue on a single monitor is fixed alongside it: switching panels reset the remembered content height to `None`, so the window was briefly clamped against each panel's near-fullscreen placeholder height (`PANEL_HEIGHTS`) before its real height was measured, which could shove a dragged window toward the top of the screen; the previous panel's measured height is now kept as the transitional estimate instead.
