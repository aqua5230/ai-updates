Grok 登上用量報表與互動儀表板，四張對照表同步補齊

平時習慣呼叫 Grok 協作的開發者，現在執行 usage report 或切換至互動儀表板時，終於能將它的用量一併納入統計。

這好比商場服務台早早掛出新專櫃的會員卡，樓層指南與各收銀機名冊卻全漏記，消費者看全館總表時始終找不到它；把各處對照表補齊後才完整歸隊。

先前 macOS 選單列雖有 Grok 的額度卡，讀取器 loaders/grok_loader.py 也能吐出逐次呼叫的 token（AI 處理與計費的文字單位）明細，但轉接層缺少 adapters/grok.py，導致終端機報表與儀表板對它視而不見。這次除了補上轉接器，也同步了四張必須一致的對照表：註冊表的偵測清單、指令列與報表產生器的 AGENT_LOADERS，以及表格介面的 AGENT_SHORT 與 AGENT_LABEL。

報表細分四類 token 並顯示快取命中率，釐清真實消耗

想掌握 AI 的實際消耗，過去報表頂部的「燒掉 Tokens」只把四種不同性質的數字加總成單一數值，根本看不出關鍵細節。

這好比水電帳單只印出一筆總度數，卻把洗澡水、澆花水與管線循環水全混在一起，讓人無法判斷用水習慣是否健康。

本機測試某期 2,565,454,499 個 token（AI 處理與計費的文字單位）裡，高達 93.8% 是讀取快取的舊資料。快取就是把算過或查過的結果暫存起來直接取用；模型真正生成的輸出只佔 0.7%，單看總額毫無意義。現在報表正式拆分為輸入、快取寫入、快取讀取與輸出四類，並計算各工具的快取命中率。算式以快取讀取除以三種輸入脈絡總額，排除掉生成出的輸出。高命中率代表舊脈絡以約十分之一的單價重複取用，五種語言的文案也明確引導此數值象徵體質良好而非無效重複。底層一直都記錄著這四個欄位，先前僅是報表彙整時丟棄，因此不必清理快取或升級資料格式。

一次過關率獨立成報表第三區，頂部 KPI 卡不再重複顯示

你想知道哪款模型最省心、最不需要你回頭反覆插手修正，「一次過關率」現在被拉升成報表第三區的獨立大板塊。這項衡量 AI 能否一次搞定任務的指標早就算好，先前卻埋在第 11 區「使用習慣」的小卡裡，多數人根本捲不到。如今它改排在洞察之後、工具之前，各模型採用排行列版面依過關率由高至低排序，直接回答哪款模型最不用重修，而非單看誰的對話輪次多。頂部關鍵績效指標（KPI，衡量核心表現的量化卡片）也同步移除了重複的一次過關率，解決過去五張卡硬塞在雙欄網格中的難看排版，而且沒有新增任何多國語系文字鍵。

這就像餐廳評鑑把「廚師一試成菜率」從附錄角落拉到首頁專欄，依退菜次數由少到多排列，頂部總覽區便無須再塞入重複的概括數字。

AI 圓桌納入 Codex 的 Astra 預設模型，名單不再寫死

召開 AI 圓桌讓多款模型共同商討問題時，你現在已能指派 Codex 最新的 Astra 模型加入對話。

這如同會議室名單原本寫死只邀三位資深代表，當新任首席代表上任時便被警衛攔在門外；把名冊放寬後，新代表就能直接入席開會。

gpt-6-astra 是 Codex 當前的新預設模型，但圓桌先前的模型白名單寫死了 5.6 版的三款舊變體，導致新旗艦無法登場。這次放行無須更動價目表與報表：LiteLLM 的價格表早已完整收錄該模型的四項實價，報表的顏色分配也只要命中 gpt 前綴就能自動對應，切換選擇毫無阻礙。

「燒掉成本」更名為「API 等值」，移除新台幣換算並以副標說明差額

每次打開報表看到「燒掉成本」這個標籤，往往讓人誤以為自己真的刷卡付出了這筆費用。這項數值僅是依照官方牌價乘出來的假設數字，對於每個月繳固定月費、邊際成本為零的包月使用者來說相當容易引起誤解。現在五種語言統一改名為「API 等值」，先前繁體中文特有的新台幣換算也一併移除，避免將假設數字再乘上匯率二次失真。該數值本身依然保留，供按量計費的 API 使用者參考。另外，由於「燒掉 Tokens」統計了所有代理工具，而「API 等值」僅能計算具備公開牌價的模型，兩張頭條卡的分母並不相同；因此只有在確實出現無牌價用量時，卡片才會顯示副標題說明兩者的差額。

這有如健身房月費會員查看運動手環時，熱量消耗換算出的「外食便當等值金額」僅供參考，若標示成「你今天花掉的餐費」反而會讓人誤以為荷包失血。

Token 組成與快取命中改採排行列，微小比例不再被壓扁

當單一類別佔比超過九成時，傳統的堆疊長條圖就會變成一場排版災難。先前在快取讀取高達 93.8% 的情況下，其餘三種類別被壓成看不見的細縫，長條內的百分比文字甚至重疊成 4.6% 0.1.93.7% 擠在最左側，圖例色塊也缺乏尺寸樣式。輸入、快取寫入與快取讀取都屬於傳入的脈絡，而輸出是生成的文字，性質本不相同。現在改採排行列呈現，四種類別各自擁有獨立的一列與專屬欄位，且長條設有 2% 的最小寬度，讓僅佔 0.7% 的微小產出依然清晰可辨。各工具的快取命中率也套用同款版面依命中率排序，體質最差的工具直接落在最後一列。同時，測試中針對 TypedDict 型別以迴圈變數當鍵遭 mypy 拒絕的問題，也透過 Any 中介變數順利修復。

這好比大合照時體型差距懸殊、名牌全疊成一團，改成單人單列橫條後，每位成員的身形與名次才清晰可辨。

報表資料列改為整列量條，跨區塊數值對齊同一基準線

檢視報表中不同區塊的數據時，數字與量條不再忽左忽右跳動。

這有如試算表裡多張工作表的直欄寬度各吹各的調，數字忽左忽右難以閱讀；重新劃定同一套格線並固定標籤顏色後，整份報表才整齊劃一。

過去排版存在四個獨立缺陷：兩套資料列樣式（.rank-line 與 .tool-row）因欄寬與間距相異，導致數值在各區塊落在不同的水平位置；佔比量條被限制在名稱欄內，只能畫到半列就硬生生中斷；每個區塊層層疊加了區塊、卡片與列框三層多餘邊界；更有兩處區塊缺少欄位表頭。現在資料列改為貫穿整列的進度條，工具區補上了量條元素，且工具的顏色直接綁定代理識別碼（agent id）而非排序位置，避免工具名次互換時發生整批重新塗色的混亂。

報表時間週期與對比標記更明確，移除無刻度的每日折線

追蹤長期消耗趨勢時，報表展示的時間跨度如今更加清晰嚴謹。每週燃燒趨勢區塊移除了原本夾帶的每日折線圖，因該折線既無刻度也無具體數值，不但對不上「每週」的標題，也無法提供任何可化為行動的有效資訊；底下的週次、數值與週增減橫條則維持不變。同時，報表明確講清楚了比較的基準期間，將「較上月」與「較上週」統合成「較前期」；年度統計區塊也正名為「近 53 週」，其週數由程式常數自動傳入，日後常數調整時文案會即時跟上。

這彷彿帳單收據拿掉了沒有刻度與單位的裝飾性波動圖，只保留清楚的每週明細與增減數值，並把對照週期寫得一清二楚。

配額警告文案精簡，完整塞入選單列面板不再被截斷

當你的模型額度即將用盡時，彈出的警告紅字現在能完整顯示於介面之中。先前那行寫死不換行的警語需要 320 到 470 像素寬度，但選單列面板（popover，點擊狀態列圖示展開的小視窗）的文字框僅有 304 至 320 像素，加上卡片外框設定了隱藏溢出內容以維持復古造型，整行紅字因此直接被切斷。實測 13 個面板在 5 種語言下的表現，日文最慘被削掉 81 至 150 像素，英文也只有三個面板能剛好裝下。現在文案在維持原意下全面縮短，左右對決的世界盃面板更提供省略重置時間的超短版本，完美適應每邊僅 151 像素的狹窄空間。

這如同行李吊牌框格尺寸固定，原本冗長的手寫警語硬塞進去只會被切掉後半截；換成精簡標語後，整行提示便完整呈現。

年度帳本不再因版本不合無聲清空，歷史紀錄妥善防護

累積整整一年的 AI 使用紀錄，往後再也不會因為程式升級而無聲無息被歸零蒸發。

這就像圖書館換了新的索書號編碼規則，不能因此把整櫃舊藏書當垃圾直接倒掉，而應先照常上架供人借閱，只有真正碎成紙屑的殘卷才移至隔離室留存。

年度帳本模組原本有四條路徑會直接回傳空帳本，其中最嚴重的便是資料規格版本不符；過去只要開發者微調欄位並調升版號，全球使用者累積的歷史便會靜靜歸零，且毫無備份可救。開發時實測更發現，一次升版就讓本機熱力圖從 119 天驟降至 36 天。現在版本不符時只會記錄警告，依舊逐日解析舊資料；只有在檔案完全無法讀取或結構徹底損毀時，才會先隔離備份至 ~/.usage/quarantine/ 資料夾，周全守護歷史紀錄。

裸倉庫工作樹不再把同專案拆成兩筆，清理後綴並修復歷史

在裸倉庫（沒有工作目錄的 Git 主儲存庫）中建立工作樹時，同一專案往後不再被報表拆成兩筆紀錄。先前專案名稱解析器將工作樹（Git 讓同一專案平行開多份副本的功能）路徑解回主目錄後直接取尾端名稱，讓專案名多帶了 .git。這使純路徑解析的 Claude 回報 obsidian00，其餘三組讀取器卻回報 obsidian00.git；本機實測達 5997 筆對 3732 筆，報表上同一專案被拆成 21.70% 與 10.80% 兩筆。三層架構已同步修復：解析器會去除結尾的 .git，Codex 分片快取升版以重新解析 28 個舊分片，年度帳本則在讀取時將 .git 摺疊併回原專案名。

這恰似同一家分公司只因招牌多印了副檔名，就被會計帳冊當成兩家企業分開記帳；統一歸併後數據才合而為一。

Token 單位進位不再跳級錯誤，四捨五入後自動重新校準

當你的 token 消耗量剛好接近單位級距的邊緣時，報表上的數字與單位現在會正確跳級。

這就像電子磅秤在物體達九百九十九點九五公克時進位，數值跨入整數，單位標籤卻沒跟著切換而秀出「一千點零克」；重新校準級距後，便會準確切換成一公斤。

函式 _fmt_tokens 過去在格式化 token（AI 處理與計費的文字單位）數值時，先根據未縮放的原始值決定單位級距，完成縮放並執行四捨五入後，卻沒有再次檢查數字是否已經滿額進位。這導致 999,950 遭到四捨五入後被印成古怪的 1000.0K，而 999,950,000 也被印成 1000.0M。現在進位後會重新審查級距，確保單位如實躍升。

Grok arrives in usage reports and the interactive dashboard with four synchronized lookup tables

Developers who regularly collaborate with Grok can now finally include its usage in statistics when running usage report or switching to the interactive dashboard.

This is like a mall information desk displaying membership cards for a new boutique while the floor directory and register rosters omit it entirely, leaving shoppers unable to find it on the mall-wide directory until lookup tables everywhere are completed.

While the macOS menu bar previously had a Grok quota card and the loader loaders/grok_loader.py could produce per-call token details, the adapter layer lacked adapters/grok.py, leaving the terminal report and dashboard blind to it. In addition to adding the adapter, this update synchronizes the four lookup tables that must agree: the registry's detector list, AGENT_LOADERS in the CLI and report generator, and AGENT_SHORT and AGENT_LABEL in the table UI.

Reports split tokens into four categories and display cache hit rates to clarify real consumption

To understand actual AI consumption, the headline "tokens burned" at the top of previous reports summed four distinct numbers into a single total, obscuring key details.

This is like a water bill that only prints a single total usage while lumping shower water, garden water, and recirculated pipe water together, making it impossible to judge whether consumption habits are healthy.

In local testing across a period of 2,565,454,499 tokens, as much as 93.8% was cache read while only 0.7% was output the model actually generated, rendering the raw total meaningless. The report now formally breaks down usage into input, cache write, cache read, and output, while calculating cache hit rates for each tool. The formula divides cache read by the sum of the three input contexts, excluding the generated output. A high hit rate indicates that old context is reused at roughly one-tenth the unit price, and the copy across all five languages explicitly frames this metric as a sign of healthy efficiency rather than wasteful repetition. The underlying layer has always recorded all four fields and previous versions merely discarded them during report aggregation, so no cache clearing or data format upgrade is required.

One-pass rate becomes an independent third section in the report, removing duplicates from top KPI cards

For those wanting to know which model requires the least intervention and fewest follow-up fixes, "one-pass rate" has been promoted to a standalone third section in the report. This metric measuring whether AI completes tasks on the first attempt was already computed, but previously sat buried inside a small card under section 11 "usage habits" where most users never scrolled. It is now positioned after Insights and before Tools, with model rows using a ranked layout sorted by pass rate from highest to lowest to directly answer which model needs the fewest revisions rather than just looking at turn count. The top key performance indicator (KPI) cards also removed the duplicate one-pass rate, fixing an awkward layout where five cards were squeezed into a two-column grid without requiring any new i18n localization keys.

This is like a restaurant guide moving the "chef first-try dish success rate" from an appendix corner to a front-page column sorted from fewest dishes sent back to most, eliminating the need to crowd redundant overview numbers into the header.

AI roundtable incorporates Codex's default Astra model as the allowlist is no longer hardcoded

When convening an AI roundtable to deliberate issues across multiple models, you can now assign Codex's latest Astra model to the discussion.

This is like a conference room roster that rigidly invited only three senior delegates, causing security to turn away the newly appointed chief delegate at the door until the list was opened up so the new representative could take a seat.

gpt-6-astra is Codex's current new default model, but the roundtable's previous model allowlist hardcoded three older 5.6 variants, preventing the new flagship from appearing. Enabling it required no changes to pricing tables or reports: LiteLLM's price list already covers the model's four actual prices, and report color assignments match automatically on the gpt prefix, so switching works without another change.

"Cost burned" is renamed to "API equivalent", removing NTD conversion and clarifying gaps via subtitles

Opening the report and seeing the "Cost burned" label often gave the mistaken impression that one had actually paid that amount out of pocket. Because this figure is merely a hypothetical number multiplied out from official list prices, it easily misled subscription users who pay a fixed monthly fee with zero marginal cost. The label is now unified across all five languages as "API equivalent", and the NTD conversion previously unique to Traditional Chinese has been removed to avoid distorting an assumed number a second time through exchange rates. The value itself remains available for pay-as-you-go API users who need it. Furthermore, because "tokens burned" counts all agents while "API equivalent" can only calculate models with published list prices, the two headline cards do not share the same denominator; a subtitle now explains the gap, but only when unpriced usage actually exists.

This is like a monthly gym member looking at a fitness tracker where burned calories are converted into an "equivalent dining-out cost" for reference, which would falsely imply wasted money if labeled as "money spent on meals today."

Token composition and cache hit rates switch to ranked lists, preventing tiny shares from collapsing

When a single category exceeds ninety percent, traditional stacked bar charts turn into a layout disaster. Previously, with cache reads reaching 93.8%, the other three categories collapsed into invisible slivers, in-bar percentage text overlapped into 4.6% 0.1.93.7% at the far left edge, and legend color swatches lacked sizing styles entirely. Input, cache write, and cache read all represent incoming context while output consists of generated text, making them fundamentally distinct in nature. The presentation has now shifted to ranked lines where each of the four categories receives its own row and dedicated columns, with bars given a 2% minimum width to keep even a tiny 0.7% output clearly visible. Per-tool cache hit rates adopt the same layout sorted by hit rate, placing the worst-performing tool on the final row. Meanwhile, a test issue where mypy rejected loop variables used as keys on TypedDict types was resolved cleanly using an Any intermediate variable.

This is like a group photo where huge differences in size cause name tags to pile on top of each other, until switching to individual single-row bars makes every member's stature and standing clear.

Report data rows become full-width bars, aligning values across sections to a shared baseline

When reviewing data across different report sections, numbers and bars no longer jitter unpredictably between left and right.

This is like a spreadsheet where multiple sheets use mismatched column widths that scatter numbers everywhere, until establishing a unified grid and consistent label colors brings the entire report into clean alignment.

The previous layout suffered from four separate defects: two row styles (.rank-line and .tool-row) used differing column widths and gaps that placed numbers at different horizontal positions across sections; share bars were trapped inside the name column and abruptly stopped halfway across the row; every section stacked three redundant borders of section, card, and row frames; and two sections lacked column headers entirely. Data rows are now full-width progress bars, the tools section adds bar elements, and tool colors are keyed directly to the agent ID rather than sort position to avoid repainting every tool whenever rankings shift.

Report timeframes and comparison markers gain clarity, removing scaleless daily line charts

When tracking long-term consumption trends, the report's timeframes are now clearer and more rigorous. The weekly burn trend section dropped its embedded daily line chart because it had no scale or values, failed to match the "weekly" heading, and provided no actionable information, while the week numbers, values, and week-over-week bars below remain unchanged. At the same time, the report clarifies its comparison baseline by unifying "vs. last month" and "vs. last week" into "vs. previous period", while the annual section is renamed "last 53 weeks" with the week count passed from program constants so the copy updates automatically if constants change.

This is like a billing receipt stripping away decorative fluctuation charts lacking scales or units, keeping only clear weekly breakdowns with changes and explicitly stating the comparison period.

Quota warning copy streamlined to fit inside menu bar panels without truncation

When your model quota is running low, the red warning text now displays fully within the interface. Previously, the hardcoded nowrap warning required 320 to 470 pixels of width, but the menu bar panel text box was only 304 to 320 pixels, and because card frames hid overflowing content to preserve a retro aesthetic, the red line was cut off directly. Across 13 panels in 5 languages, Japanese suffered the most by losing 81 to 150 pixels, and English fit in only three panels. The copy is now universally shortened while preserving its original meaning, and the head-to-head World Cup panel provides an ultra-short variant that omits the reset time, fitting neatly into the narrow 151 pixels on each side.

This is like a fixed-size luggage tag where lengthy handwritten warnings get cut off at the edge, but switching to a concise message displays the full reminder cleanly.

Year ledger is no longer silently cleared on version mismatches, safeguarding historical records

A full year of accumulated AI usage history will no longer vanish silently to zero due to software upgrades.

This is like a library adopting new call number rules: it shouldn't discard entire shelves of older books as trash, but keep them on shelves for borrowing while reserving quarantine storage only for scrolls shredded beyond recognition.

The year ledger module previously had four execution paths that returned an empty ledger, the most severe being schema version mismatches; whenever developers tweaked fields and bumped the version, users worldwide quietly lost their entire history with no backups to recover from. Testing during development revealed that a single version bump caused the local heatmap to plunge from 119 days to 36. Version mismatches now merely log a warning and continue parsing older data day by day, moving files into the ~/.usage/quarantine/ directory as isolated backups only when they are genuinely unreadable or structurally corrupted to protect historical records.

Bare repo worktrees no longer split one project into two, cleaning suffixes and repairing history

When creating a worktree from a bare repository, the same project will no longer be split into two separate entries in reports. Previously, the project name resolver resolved worktree paths back to the main directory and took the basename directly, leaving the project name with an unwanted .git suffix. This caused path-only Claude to report obsidian00 while the other three loaders reported obsidian00.git; locally, this amounted to 5997 entries against 3732, splitting the same project in the report into 21.70% and 10.80%. All three architectural layers have been fixed: the resolver strips the trailing .git, the Codex shard cache was bumped to re-parse 28 old shards, and the year ledger folds .git back into the base project name at read time.

This is just like a branch office being logged as two separate businesses in accounting ledgers simply because its sign had a file extension printed on it, until unified consolidation merges the figures back together.

Token units no longer miscalculate tiers on round-up, recalibrating automatically after rounding

When your token consumption nears the boundary of a unit tier, numbers and units on reports will now advance correctly.

This is like a digital scale rounding up at 999.95 grams into a whole number but failing to switch unit labels and showing "1000.0 grams", until recalibrating the tier correctly flips the display to one kilogram.

When formatting token values, the _fmt_tokens function previously selected unit tiers from unscaled raw values, but failed to re-check whether rounding pushed the number across the tier threshold after scaling. This caused 999,950 to be printed as an awkward 1000.0K after rounding, and 999,950,000 as 1000.0M. Unit tiers are now re-evaluated after rounding to ensure units advance properly.
