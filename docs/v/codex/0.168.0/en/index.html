Codex 0.168.0

Released: 2026-11-13

Release notes

FEATURE

Pick a Model Provider for New Chats While Existing Ones Keep Theirs

If you want to switch upcoming work to a different AI model provider (a service that supplies AI computing), you can now browse the list under "Sessions → Model providers" in the sessions menu and set the default for new chats.

Like switching the default dialing line on a phone, future calls go through the new plan, while calls already in progress or reconnected stay on the original line.

After you change the default for new chats, open windows and resumed chats still use their own saved model provider. When you have an active project that should stay on its current model while future chats use another service, you can adjust the default under "Sessions → Model providers" without disrupting it.

FEATURE

Enable Workspace Panes to View a Side Chat Beside the Main One

When you are partway through a main project and want to look something up without switching away from the current screen, this setting comes in handy. Enabling features.tui_workspace lets you display a side conversation beside the main chat. Once enabled, you can drag the center divider to resize the two panes (separate sections split within the screen), or press the leader z shortcut to zoom in on the focused pane.

Picture a desk that used to hold only one open book at a time: adding a movable divider lets you compare two notebooks side by side, sliding the divider adjusts their widths, and you can pull either one closer to focus.

When you are editing a presentation outline in the main chat and want to open a side chat to look things up without switching views, widen the pane to compare them and press leader z afterward to zoom back to the main screen.

FEATURE

Attach Recordings Directly in Chats with Audio-Capable Models

If you have voice notes left after a meeting and want the AI to listen and summarize key points directly, this saves a lot of effort. As long as you choose an audio-capable model, you can attach recordings in Codex chats. During sending, Codex automatically skips recordings that the model has confirmed rejecting on later turns instead of resending them. Codex also calculates space usage based on each clip's duration, allowing more short recordings to stay in context (the range of conversation content the AI currently remembers).

Think of an editor sorting audio tapes on a desk: rejected reels are set aside so they are never resubmitted, while short clips are packed tightly by length to keep more of them on hand.

When you send several short voice memos in batches to an audio-capable model, invalid files will not keep resending, and more short clips can remain in the conversation context together.

FEATURE

Enable Animated GIF Generation and Editing via Config

When making slides or replying to messages, a single static image sometimes cannot explain steps clearly, and a moving visual helps. Enabling features.image_generation_animation lets you ask Codex to generate or edit animated GIFs. When generating or modifying an animation, you can also adjust the frame count (the number of sequential images that make up the animation) and timing controls as needed.

You move from a single illustration to a flipbook, where instead of producing one static picture, you decide how many pages to draw and how long each stays on screen so the sequence comes alive.

Whenever you need to create a demo animation or tweak the playback pacing of an existing GIF, this setting covers it.

FEATURE

Fullscreen tmux Displays Images and Pets on Ghostty and Kitty

If you like running Codex in fullscreen inside an extra terminal management layer, you no longer have to give up viewing images. As long as you use Ghostty or Kitty and enable allow-passthrough all in tmux (a terminal multiplexer tool), fullscreen Codex displays image previews and pets properly.

Turning on this passthrough works like opening the blinds between double-pane glass: previously an extra container layer blocked images and pets on the inside, and opening the path lets them show through to the outer screen.

When you are working in tmux and want to check image previews or keep an eye on pets on screen, adding allow-passthrough all renders everything cleanly in fullscreen.

FEATURE

Terminal Notifications Support osc777 with Longer Command Previews

When you switch to another window while waiting for Codex to report progress or request approval, you can set terminal notifications in your config to tui.notification_method = "osc777", where osc777 is a protocol that lets the terminal send desktop notifications. Approval notifications that need your go-ahead are also clearer. They show longer command previews and clearly distinguish between waiting for terminal input and requesting network access.

A car's center display works similarly: the dashboard used to light up only a generic warning icon, whereas now it spells out the exact category and puts more details on screen.

When a confirmation alert pops up while you are focused on writing an email, you can see the command details and request type right away to decide whether to approve without switching back.

FEATURE

Local History and Resume Lists Filter New Chats by Account

For anyone switching between different ChatGPT accounts on the same computer, keeping each account's records separate matters most when picking up where you left off. Local TUI (terminal text interface) history and resume pickers now filter newly created threads by the currently signed-in ChatGPT account.

Imagine personal work folders on a shared computer: previously you had to sort out which new records belonged to whom, whereas now they are filtered by who is signed in, and switching accounts switches the filter too.

Later, when you switch back to your personal or work account to continue earlier work, opening the history or resume list filters newly created threads by the signed-in ChatGPT account.

FEATURE

Tool-Interrupted Replies Merge Together with Reasoning Summaries Restored

When you review an earlier conversation, nothing is worse than seeing a single reply chopped into pieces by mid-turn tool calls. Now, when a reply is interrupted by tool calls in the TUI, the interface merges the whole answer into a single Markdown (a plain-text format that uses simple symbols to style headings and lists) message. When replaying past conversations, the screen also restores the original reasoning summaries (highlights of the thinking process organized by the AI).

Suppose a speaker pauses mid-talk to check notes, and you typeset the transcript back into one continuous article with the margin notes restored beside it when reviewing later.

Whenever you need to trace how Codex reached a conclusion step by step, the full reply and reasoning summaries appear as a continuous whole on screen.

FEATURE

Long-Running Chats and Save Windows Still Catch Steering Messages

When a task is halfway through and you want to add a quick note to adjust direction, it can sometimes collide with the conversation wrapping up or the moment you switch back to the window. Now, steering messages (supplemental instructions sent before a turn finishes to adjust direction) still reach the running turn even if sent during the final transcript save or after you switch away and return to a long-running chat.

Even as a train pulls into the station or you walk back into a carriage with a radio, the cab's channel stays open so last-minute rerouting cues still get through.

From now on, if Codex is in a long run and you want to nudge its direction, you can send it right away even if you just switched back to the chat window.

FEATURE

Fuzzy Search Gives Filename Matches More Weight

As project folders grow deeper, typing a few characters to find a file often lets parent directory names steal the top spots, forcing you to scroll down several lines. Now, fuzzy file search (a search feature that matches paths using only partial characters) gives filename matches more weight so items matching parent folder names are less likely to crowd out your target file.

Consider searching for goods by item name in a large warehouse: previously a matching aisle name let a whole row of unrelated items crowd the top, whereas now boxes whose own labels match are listed first.

Next time you want to pull up a file quickly and its parent folder happens to share the same word, the search results will more easily keep the filename you want near the top.

FEATURE

Idle local MCP servers on Windows free up file read and write channels

When you have a few spare add-on tools running in the background on your computer, you still want everything else to work normally even when you are not using them. Now idle local MCP (a protocol that connects AI to external tools) servers on Windows yield those resources. Filesystem I/O (file reading and writing operations) stays available to the rest of Codex.

Parked delivery trucks on a shared lane used to block traffic while sitting idle, but now they clear the lane whenever they are not working so other vehicles can keep hauling cargo.

Even with inactive local tools sitting in the background, the rest of Codex can still handle file reads and writes smoothly.

FEATURE

app-server reference adds provider and cloud gateway settings

When connecting Codex to your team's own backend services or cloud models, checking the developer guide is the fastest way to get started. The reference documentation for app-server (the core background service that handles requests) now covers how to list model providers and create custom gateways. It also explains how to update settings for gateways (unified entry points that forward connection requests), AWS Bedrock, and Google Cloud's GCP.

Buying new audio gear now comes with a complete wiring diagram that clearly shows which sound sources you can pick, how to hook up a custom adapter box, and how to adjust each channel's settings later.

Going forward, teams connecting to Bedrock or GCP cloud environments, or setting up an internal model gateway, can look up the exact steps directly in this reference.

FEATURE

Warning points to agents.enabled when features.multi_agent is explicitly set

Anyone who has written features.multi_agent in their config file may see a reminder on screen. Whenever features.multi_agent is explicitly set in the config file, Codex now shows a warning pointing you to agents.enabled if you want to turn off subagent (small helpers that handle work for the main assistant) tools.

At a junction where a new sign has been posted, anyone who previously set their route by the old sign and still follows it now sees a notice telling them to check the other sign to close that lane.

The next time you see this warning, you can follow the prompt and check the agents.enabled setting used to disable subagent tools.

FEATURE

Run Bazel tests locally without BuildBuddy credentials

Open-source contributors submitting code changes to Codex often want to verify on their own machine that tests pass after writing code. Contributors can now run Bazel CI jobs locally without BuildBuddy (a remote testing service used with build systems) credentials. Here, Bazel is the tool for building and testing code, while CI (continuous integration, which automatically runs checks after every change) verifies that the code changes work properly.

Test drivers no longer need to apply for a remote track pass first and can instead pull the car straight into their own garage, start it up, and take a lap to check how it runs.

From now on, contributors helping to patch code can run this test job on their own computer without applying for separate remote credentials.
