Vim 模式加了復原與重做，草稿手滑也不怕

你在 Vim 模式（改用鍵盤符號下指令的編輯方式，名字來自一款老牌文字編輯器）裡改草稿，手滑刪掉一整段附件說明，以前只能重打——現在按 u 就能復原上一步，按 Ctrl+R 則是反悔剛才的復原、重做回去，好比用可擦筆寫稿，寫錯了擦掉重寫，擦太多了再把擦掉的字描回來，紙面痕跡都還在。而且不管草稿裡貼了多少內容、掛了幾個附件，復原跟重做都會保留完整版本，不會漏東漏西，你不用擔心救回來的稿子少了一塊。

外掛市集搬進指令列，查裝移除都在終端機

自動回顧能關掉，貼上偵測開關搬了新家

想關掉自動回顧摘要，或把貼上大量文字的偵測設定搬到新位置，這裡有兩個新設定鍵。Codex 原本會自動生成回顧摘要，如果你只想在打 /recap 時自己叫出來，設定檔加一行：

{"tui": {"auto_recap": false}}

也就是 tui.auto_recap = false，自動摘要關掉，手動 /recap 照樣能用。另一個是貼上偵測（paste burst，短時間內貼上大量文字的辨識機制）設定鍵搬家，改用巢狀寫法：

{"tui": {"disable_paste_burst": true}}

也就是 tui.disable_paste_burst，而舊的頂層寫法目前仍當備援繼續有效，不用急著改。彷彿車上的語音路況提示，能直接在中控台整個關掉、改成按鍵才報路況，開關位置也從儀表板搬進了選單，老車主熟悉的實體按鈕暫時還留著備用。

對話回頭看更清楚，改了什麼、下了什麼指令都留底

回頭捲動 Codex 的終端機介面歷史紀錄時，現在看得到的東西更完整了：程式碼修改會顯示完整的補丁（patch，改動前後對照的差異紀錄），送進背景終端機視窗的輸入內容會留底，個別執行完的指令也各自獨立顯示，不會被吞掉或混成一團。宛如工地的施工日誌，每天不是只寫一句「有動工」，而是附上動工前後的對照照片，還把當天下的每一道工序分開記錄，事後翻查一看就懂哪一步做了什麼。

額度剩不到一半，Plus 跟 Team 會提早跟你說

用 Plus 或 Team 方案的人，額度用得快不快，現在能更早知道。以前要等額度更接近用完才會收到提醒，常常是打到一半才發現要沒了。現在只要在大約五小時一輪的用量視窗裡，額度剩不到一半，就會提早跳出警告，你就有機會提前調整步調，不必臨時改變工作方式。恰似手上剩的洗衣券只剩不到一半時，機台先跳出提醒，讓你有空檔想要不要趕在額度重置前多洗一輪，而不是洗到最後一刻才發現券快用完。

外部連線斷了會自動接回來，未確定的動作先暫停等你看

你透過外部的 app-server（讓其他程式跟 Codex 對話的伺服器介面）連線用 Codex，這條連線如果突然斷掉，就像視訊會議斷線重連，畫面接回來的時候，你正在打的訊息草稿還在、對話紀錄也沒不見，只是原本正在表決的提案先暫停，等你確認才繼續。具體來說，Codex 現在會自動重新連上這個外部 app-server，草稿跟對話轉錄（transcript，逐字紀錄）都完整保留。而斷線當下還不確定有沒有送出、或是還在排隊等處理的動作，會先暫停下來，交給你重新確認過再繼續，不會替你自作主張。

審查跳過該跳的，該顧的紀錄一樣顧著

Codex 的 Guardian（把關風險動作的審查機制）這次分清該管與不管的界線。用 Full Access（完全授權模式）時，遇到只需按確認的動作，Guardian 現在直接跳過審查。換成每個動作都要核准的 User approval mode，Guardian 也不再背景幫提案打分數、預先熱機，但敏感動作檢查與需要你輸入答案的請求，處理方式不變。Guardian 過去審過的紀錄也扛得住考驗：對話被壓縮、程式重啟，或你自己開了分支，紀錄都留得住，仍遵守回捲（rollback，把狀態退回先前某刻）的邊界。子代理（subagent，替它跑某段子任務的分身）的歷史也被隔開，不會混進主線程。宛如社區警衛登記訪客，熟面孔的住戶刷卡就放行、不必每次登記，陌生訪客照樣得留資料才能進去；警衛室的登記簿就算搬家、換班，甚至臨時開了側門，各戶訪客紀錄還是分開保管，不會混成一本。

上下文管理實驗模式預設關閉，開通後才會啟用新工具

Codex 新增了一個預設關閉的實驗設定 features.context_management.experimental_mode，如果你符合資格想試，在設定檔加上：

{"features": {"context_management": {"experimental_mode": true}}}

也就是把這個巢狀設定鍵打開。開啟後，如果你是用 Codex 後端的 ChatGPT Plus、Pro 或 Pro Lite 訂閱、而且帳號被納入資格名單，就會啟用以 token（AI 處理與計費的文字單位）預算管理上下文的機制，外加歷史筆記功能跟 new_context 這個工具。用 API 金鑰（一組用來證明身分、直接呼叫底層服務的密碼字串）登入的工作階段、自訂供應商，以及暫時性的結構化執行緒，則不在開放範圍內，不會啟用這些新機制。有點像新開的試營運方案，只開放給符合資格、事先報名的特定會員試用新設施，臨櫃辦的訪客卡跟外接廠商暫時還用不到。

帳號、路徑、續接紀錄，一批後台細節一次補上

這批修復收攏了幾項後台細節。MCP（Model Context Protocol，讓 AI 連接外部工具的協定）工具的核准記憶改成綁定帳號，換帳號不會沿用另一個帳號核准過的設定；MCP 相對路徑執行檔，在 macOS 上啟動更可靠。對話紀錄壓縮現在併入共享歷史，codex exec resume 依目錄續接也認得壓縮過的紀錄。工作階段的根目錄就算是符號連結（symlink，指到別處的捷徑檔），開執行緒分支照樣正常。app-server 執行緒中繼資料多了可為空值的 model、reasoningEffort 欄位，模型目錄若開放，還能用 request_user_input_async 結構化、非同步發問，不必卡住等你即答。如同寄放行李，寄放單跟存根號碼要對得上才能領回，就算行李轉去別的置物櫃，存根照樣領得到東西，連加保險也能先發通知單，不必現場答。

Vim mode adds undo and redo to safeguard draft edits

When modifying drafts in Vim mode, accidentally deleting a section of attachment notes previously required retyping the whole piece. You can now press u to undo the last action and Ctrl+R to redo, reversing the undo operation. It is like writing with an erasable pen: when you make a mistake, you erase and rewrite, and if you erase too much, you can trace the erased strokes right back on the clean paper. Furthermore, regardless of how much content was pasted or how many attachments were included, undo and redo preserve the complete state without dropping parts of your draft.

The plugin CLI brings remote marketplace browsing, installation, and removal to the terminal

Looking to install plugins to expand Codex with extra capabilities? The plugin CLI now connects directly to remote marketplaces: you can run a command to list available plugins, install a chosen plugin with a single command, or remove it just as easily when no longer needed, all without leaving your terminal. It is like a tool rental shop putting its entire catalog online, allowing you to browse available tools on screen, check them out with a click, and return them when finished without ever flipping through paper lists at the counter.

Automatic recaps can be disabled and paste-burst settings move to nested keys

This release introduces two new configuration keys for managing recap behavior and paste detection. Codex previously generated recap summaries automatically. If you prefer to trigger recaps manually with /recap, add the following line to your configuration file:

{"tui": {"auto_recap": false}}

This sets tui.auto_recap = false, disabling automatic generation while keeping manual /recap invocations available. Additionally, the paste burst detection setting has moved to a nested structure:

{"tui": {"disable_paste_burst": true}}

This introduces tui.disable_paste_burst, while the legacy top-level key continues to work as a fallback so immediate migration is not required. It is like a car audio traffic announcement that can be turned off entirely in favor of an on-demand button, with the toggle relocated from the physical dashboard into a digital menu while the familiar dashboard button still works as a backup.

TUI history displays complete patches, background inputs, and individual commands

Scrolling back through TUI history in Codex now provides a much clearer view of past actions. Code modifications display complete patch diffs, inputs sent to background terminal sessions are fully recorded, and individual completed commands appear distinctly without being omitted or merged together. It is like a construction site log that includes before-and-after photos alongside separated step-by-step records for each task rather than just noting that work occurred, making every past change immediately obvious when reviewed.

Plus and Team plans receive earlier alerts when usage drops below half

Subscribers on Plus and Team plans can now gauge their quota consumption earlier. While warnings were previously triggered only as allowances were nearly exhausted, alerts are now sent as soon as less than half of the allowance remains within an approximately five-hour usage window. This gives you time to pace your prompts without having to abruptly adjust your workflow. It is like a laundry machine displaying an early reminder when fewer than half of your laundry coupons remain, giving you time to plan an extra load before your allowance resets rather than discovering you are out of coupons at the very last moment.

External app-server drops reconnect automatically while pending submissions pause for review

When using Codex through an external app-server connection that suddenly drops, it is like a video conference reconnecting after a network drop, where your draft chat messages and previous chat logs are intact while an ongoing poll is paused until you confirm how to proceed. Codex now automatically reconnects to the external app-server, preserving drafts and conversation transcripts intact. Any submissions that were in-flight or queued when the connection dropped are held in a paused state for user review before proceeding.

Guardian skips unnecessary reviews while preserving history across rollbacks and forks

Guardian reviews in Codex now feature clearer operational boundaries. In Full Access mode, Guardian skips reviews for confirmation-only actions. When running in User approval mode, it stops background proposal scoring and prewarming while preserving existing checks for sensitive actions and user input requests. Furthermore, Guardian review histories now survive compaction, application restarts, and user-created forks while strictly respecting rollback boundaries and isolating subagent history from the main thread. It is like a residential security guard waving recognized residents through without repeated paperwork while still logging outside visitors, keeping visitor logbooks organized and isolated even across desk moves, shift changes, or side-door entries.

Context management experimental mode is disabled by default and enables new tools when activated

Codex introduces the disabled-by-default features.context_management.experimental_mode configuration setting. To try it when eligible, add the following snippet to your configuration file:

{"features": {"context_management": {"experimental_mode": true}}}

When enabled for eligible ChatGPT Plus, Pro, or Pro Lite sessions using the Codex backend, it activates token-budgeted context management, history notes, and the new_context tool. API-key sessions, custom providers, and temporary structured threads remain excluded from these new capabilities. It is like a pilot trial program that grants access to new amenities only to pre-registered eligible members, while day-pass visitors and outside contractors are not included yet.

Refined account scoping, path handling, and session resumes across backend features

This release refines several backend implementation details. Remembered MCP tool approvals are now scoped to the active account so switching accounts will not reuse permissions granted by another user, and relative MCP executable paths launch more reliably on macOS. Rollout compression now incorporates shared histories, allowing codex exec resume to handle compressed rollouts when resuming by working directory, while thread forks operate cleanly with symlinked session roots. Additionally, app-server thread metadata includes nullable model and reasoningEffort fields, and request_user_input_async enables structured asynchronous prompts when supported by the model catalog. It is like checking luggage where the claim ticket must match the account holder to retrieve bags, items remain retrievable even if moved between storage lockers, and additional insurance notices can be sent for later review without requiring an immediate answer on the spot.

Vim モードで元に戻すとやり直しに対応し、下書きの誤操作を防げる

Vim モード（キーボード記号でコマンド操作を行う編集方式で、名称は古くからのテキストエディタに由来）で下書きを編集中に誤って添付ファイルの説明を削除してしまった場合、従来は打ち直すしかなかった。現在は u を押すと直前の操作を元に戻せ、Ctrl+R で元に戻した操作をやり直すことができる。消せるボールペンで原稿を書き、間違えたら消して書き直し、消しすぎたら消した文字をなぞって元通りに戻すような仕組みである。また、下書きに貼り付けた内容の量や添付ファイルの数に関わらず、元に戻す操作ややり直し操作によって完全な状態が維持されるため、復元時にデータが欠落する心配はない。

プラグイン CLI で一覧確認・インストール・削除がターミナル上で完結する

Codex にプラグイン（plugin、追加機能を提供する拡張コンポーネント）を追加したい場合、プラグインの CLI ツールからリモートマーケットプレイスに直接アクセスできるようになった。利用可能な一覧の確認、目的のプラグインのインストール、不要になったプラグインの削除まで、すべてコマンド 1 行で実行でき、ターミナルから離れる必要がない。工具のレンタルステーションが目録全体をオンライン化し、手元の画面で貸出可能な道具を確認してワンクリックで借り出し、使い終わったらボタン 1 つで返却できるようにして、受付で紙の一覧をめくる手間を省いたような仕組みである。

自動要約が無効化可能になり、ペースト検出設定の配置場所が変更される

自動要約の無効化や大量テキストのペースト検出設定の移行に対応する 2 つの新しい設定項目が追加された。Codex は従来、要約を自動生成していたが、手動で /recap を実行した時のみ表示させたい場合は設定ファイルに以下を追加する。

{"tui": {"auto_recap": false}}

すなわち tui.auto_recap = false により自動要約が無効化され、手動での /recap はそのまま利用できる。もう 1 つはペースト検出（paste burst、短時間に大量のテキストが貼り付けられた際の検知機構）の設定キーの変更であり、ネスト構造で記述する。

{"tui": {"disable_paste_burst": true}}

これは tui.disable_paste_burst を意味し、旧来のトップレベル設定もフォールバックとして引き続き有効であるため急いで移行する必要はない。車載の音声交通情報案内を操作パネルでオフにしてボタン操作時のみアナウンスするように変更し、スイッチの場所もダッシュボードから画面メニュー内に移行しつつ従来の物理ボタンも予備として残しているような仕組みである。

対話履歴の表示が詳細化され、変更内容や実行コマンドが記録される

Codex の TUI 履歴をさかのぼって確認する際、表示される情報がより詳細になった。コードの修正箇所は完全な差分（patch、変更前後の差異を示す記録）として表示され、バックグラウンドのターミナルに送信された入力内容も保持され、個別に完了したコマンドも混同されることなく独立して表示される。工事現場の施工日誌において単に作業実施と書くだけでなく、施工前後の対比写真を添付し当日の各工程を個別に記録することで、後から確認した際にどの段階で何が行われたかが一目で分かるような仕組みである。

クォータ残量が半分未満になると Plus および Team ユーザーへ早期通知される

Plus または Team プランの利用者は、クォータの消費ペースをより早い段階で把握できるようになった。従来はクォータが上限近くまで消費されるまで通知が届かず、作業の途中で残量不足に気づくことが多かった。現在はおよそ 5 時間ごとの利用枠において、残量が半分未満になった時点で早期に警告が表示され、作業手順を急に変更することなく計画的に進めることができる。手持ちの洗濯用コインが半分未満になった段階で洗濯機が早めに通知を出し、リセット前にまとめて洗うかを落ち着いて判断できるようにして、最後の瞬間にコイン不足に気づく事態を防ぐような仕組みである。

外部接続が切断されても自動再接続し、未完了のアクションは一時停止して確認を待つ

外部の app-server（他のプログラムが Codex と通信するためのサーバーインターフェース）経由で接続している際に通信が切断された場合、ビデオ通話が切断から復帰した際に下書き中のメッセージや通話記録が残りつつ、採決中の案件のみが一時停止して確認を待つような挙動を示す。具体的には、Codex が外部 app-server に自動再接続し、下書きや会話ログ（transcript、逐語記録）が完全に保持される。切断時に送信完了が未確定だった処理や待機列にあったリクエストは一時停止状態となり、利用者が再確認した上で処理が再開される。

Guardian 審査が必要な箇所に絞り込まれ、履歴の維持と分離が強化される

Codex の Guardian（リスクの高い操作をチェックする審査機構）において管理対象の境界が整理された。Full Access（完全許可モード）では確認のみのアクションに対する審査がスキップされる。各操作の承認を求める User approval mode ではバックグラウンドでの提案スコアリングや事前準備が省略される一方、機密操作の確認やユーザー入力を求める処理は従来通り維持される。過去の審査履歴も対話の圧縮や再起動、ユーザー作成のフォークを越えて保持され、ロールバック（rollback、状態を過去の時点へ戻す処理）の境界も遵守される。またサブエージェント（subagent、特定タスクを分担するエージェント）の履歴も隔離され、メインスレッドに混入することはない。住宅地の警備員が顔見知りの住民をカード認証で通し、見知らぬ来訪者には従来通り記帳を求めるような運用であり、警備日誌は詰所の移転や交代、通用門の増設があっても世帯ごとに分別保管される仕組みに類似している。

コンテキスト管理の実験モードが追加され、有効化で新ツールが利用可能になる

Codex にデフォルトで無効な実験的設定 features.context_management.experimental_mode が追加された。対象ユーザーが試用する場合は設定ファイルに以下を追加する。

{"features": {"context_management": {"experimental_mode": true}}}

Codex バックエンドを使用する対象の ChatGPT Plus、Pro、Pro Lite セッションで有効化すると、token 予算によるコンテキスト管理、履歴メモ、および new_context ツールが有効になる。API キー認証のセッションやカスタムプロバイダー、一時的な構造化スレッドは対象外であり本機能は有効化されない。プレオープン中の施設利用プランのように、事前登録した有資格会員にのみ新設備の試用を開放し、窓口発行のビジターカードや外部委託業者は対象外としているような仕組みである。

アカウント管理・パス解決・セッション再開に関する内部処理が改善

バックエンドの各種詳細仕様が整理された。MCP（Model Context Protocol、AI が外部ツールと接続するための規約）ツールの承認記憶が選択中のアカウントに紐付けられ、アカウント切り替え時に別の設定が引き継がれなくなった。また macOS 上で相対パスの MCP 実行ファイルの起動安定性が向上した。対話圧縮処理が共有履歴にも適用され、codex exec resume でディレクトリ指定による再開時も圧縮済み記録を認識できる。セッションのルートディレクトリがシンボリックリンク（symlink、別位置へのショートカット）であってもスレッド分岐が正常に動作する。app-server のスレッドメタデータに null 許容の model および reasoningEffort フィールドが追加され、モデルカタログが対応していれば request_user_input_async を用いた構造化非同期質問が可能になり、即答を待たずに処理を進められる。手荷物預かり所で預かり証の番号が一致して初めて荷物を受け取れ、保管ロッカーが移動しても預かり証で問題なく引き取れ、追加の保険通知もその場での即答を求めず後から確認できるような仕組みである。

Vim 모드에 실행 취소와 다시 실행이 추가되어 초안 수정 실수를 방지한다

Vim 모드(키보드 기호로 명령을 입력하는 편집 방식으로, 명칭은 오래된 텍스트 편집기에서 유래)에서 초안을 수정하다가 첨부파일 설명을 통째로 지웠을 때 이전에는 다시 작성해야 했다. 이제 u를 누르면 이전 단계로 실행 취소할 수 있고, Ctrl+R을 누르면 실행 취소를 번복해 다시 실행할 수 있다. 지워지는 볼펜으로 글을 쓰다가 잘못 쓰면 지우고 다시 쓰며, 너무 많이 지웠을 때 지워진 글씨를 덧그려 복원하는 것과 같다. 또한 초안에 붙여넣은 내용이나 첨부된 파일이 아무리 많아도 실행 취소와 다시 실행 시 온전한 버전이 보존되므로 내용이 누락될 걱정이 없다.

플러그인 CLI로 마켓플레이스 조회와 설치 및 삭제를 터미널에서 처리한다

Codex에 플러그인(plugin, 추가 기능을 보완하는 확장 구성요소)을 설치하려는 경우, 플러그인 CLI 도구가 원격 마켓플레이스와 직접 연동된다. 설치 가능한 항목을 명령어로 조회하고, 원하는 플러그인을 한 줄 명령으로 설치하며, 불필요한 플러그인을 한 줄 명령으로 제거하는 전 과정을 터미널 안에서 완료할 수 있다. 공구 대여소가 전체 대여 목록을 온라인으로 옮겨, 화면에서 대여 가능한 도구를 확인하고 한 번에 빌린 뒤 사용 후 버튼 하나로 반납할 수 있어 창구에서 종이 장부를 뒤적일 필요가 없는 것과 같다.

자동 요약을 끌 수 있고 붙여넣기 감지 설정 위치가 변경된다

자동 요약 생성을 끄거나 대량 텍스트 붙여넣기 감지 설정을 새 위치로 옮길 수 있는 두 가지 설정 키가 추가되었다. Codex는 기본적으로 요약을 자동 생성했으나 수동으로 /recap을 실행할 때만 불러오고 싶다면 설정 파일에 다음을 추가한다.

{"tui": {"auto_recap": false}}

즉 tui.auto_recap = false로 자동 요약을 끄고 수동 /recap은 그대로 사용할 수 있다. 다른 하나는 붙여넣기 감지(paste burst, 짧은 시간에 대량의 텍스트가 붙여넣어지는 것을 판별하는 메커니즘) 설정 키의 위치 변경이며 중첩 형식으로 작성한다.

{"tui": {"disable_paste_burst": true}}

이는 tui.disable_paste_burst에 해당하며, 기존 최상위 키도 대체 방식으로 계속 작동하므로 급하게 수정할 필요는 없다. 차량 내 음성 교통안내를 센터페시아에서 완전히 끄고 버튼을 누를 때만 안내받도록 변경하며 스위치 위치도 계기판에서 메뉴 내부로 이동시켰으나 기존 물리 버튼을 당분간 예비로 남겨둔 것과 같다.

대화 기록 조회가 개선되어 코드 수정 사항과 실행 명령이 온전히 남는다

Codex 터미널 인터페이스 기록을 거슬러 올라가 확인할 때 제공되는 내용이 훨씬 상세해졌다. 코드 변경 사항은 온전한 패치(patch, 변경 전후의 차이를 대조하는 기록)로 표시되고 백그라운드 터미널 창으로 전송된 입력 내용도 기록되며, 개별 실행 완료된 명령어 역시 누락되거나 뒤섞이지 않고 독립적으로 표시된다. 공사 현장의 시공 일지에 작업 완료라고만 적는 대신 착공 전후 비교 사진을 첨부하고 당일 진행된 각 공정을 개별 기록하여, 나중에 찾아보았을 때 어떤 단계에서 무엇을 처리했는지 한눈에 파악할 수 있는 것과 같다.

사용량이 절반 미만으로 남으면 Plus 및 Team 사용자에게 조기 경고가 전송된다

Plus 또는 Team 요금제 이용자는 한도 소진 속도를 더 일찍 파악할 수 있게 되었다. 이전에는 한도가 거의 다 닳았을 때에야 안내가 표시되어 작업 중간에 소진 사실을 알게 되는 경우가 잦았다. 이제 약 5시간 주기 사용량 구간에서 잔여량이 절반 미만으로 떨어지면 경고가 조기에 표시되어 작업 흐름을 급하게 변경할 필요 없이 미리 계획을 세울 수 있다. 보유한 세탁권이 절반 미만으로 남았을 때 기기에서 먼저 알림을 띄워, 마지막 순간에 세탁권이 부족함을 알게 되는 대신 사용량 초기화 전에 세탁을 더 돌릴지 여유 있게 판단할 수 있는 것과 같다.

외부 연결이 끊겨도 자동 복구되며 불확실한 작업은 확인 대기 상태로 일시 중지된다

외부 app-server(다른 프로그램이 Codex와 대화할 수 있도록 지원하는 서버 인터페이스)를 통해 연결하여 사용하다가 연결이 끊길 때, 화상 회의 연결이 끊겼다가 재접속되었을 때 작성 중이던 메시지 초안과 대화 기록이 유지되고 표결 중이던 안건만 확인을 기다리며 멈춰 있는 것과 같다. 구체적으로 Codex는 외부 app-server에 자동으로 다시 연결하여 초안과 대화 기록(transcript, 대화 전문 기록)을 온전히 보존한다. 연결이 끊긴 시점에 전송 여부가 불확실하거나 대기열에 있던 작업은 일시 중지되어 사용자가 다시 확인한 뒤 진행하도록 대기한다.

Guardian 검토 절차를 간소화하고 이력 보존과 격리를 보장한다

Codex의 Guardian(위험 작업을 점검하는 검토 메커니즘)이 관리 영역을 명확히 구분하도록 개선되었다. Full Access(완전 권한 모드)에서는 단순 확인 작업에 대한 Guardian 검토를 건너뛴다. 매 동작마다 승인이 필요한 User approval mode에서는 백그라운드 제안 점수 산정과 예열 작업이 생략되지만, 민감 작업 점검과 사용자 입력 요청은 기존 방식대로 유지된다. 아울러 이전 검토 기록은 대화 압축이나 재시작, 사용자 생성 포크 후에도 유지되며 롤백(rollback, 이전 상태로 되돌리는 처리) 경계를 준수한다. 서브에이전트(subagent, 특정 하위 작업을 분담하는 보조 에이전트) 이력 역시 격리되어 메인 스레드에 섞이지 않는다. 아파트 경비원이 낯익은 입주민은 카드 확인만으로 통과시키고 낯선 방문객은 인적 사항을 확인하는 것과 같으며, 경비실 기록 대장이 교대나 임시 출입문 개방 시에도 세대별로 분리 보관되어 뒤섞이지 않는 것과 유사하다.

문맥 관리 실험 모드가 추가되어 활성화 시 새로운 도구를 제공한다

Codex에 기본 비활성화 상태인 실험적 설정 features.context_management.experimental_mode가 추가되었다. 자격을 갖춘 사용자가 사용해보려면 설정 파일에 다음을 추가한다.

{"features": {"context_management": {"experimental_mode": true}}}

Codex 백엔드를 사용하는 대상 ChatGPT Plus, Pro, Pro Lite 세션에서 활성화하면 token 예산 기반 문맥 관리와 이력 메모, new_context 도구가 켜진다. API 키로 로그인한 세션이나 커스텀 공급자, 임시 구조화 스레드는 지원 대상에서 제외되어 새 기능이 활성화되지 않는다. 시범 운영 프로그램처럼 사전에 등록한 자격 보유 회원에게만 새 시설 체험을 개방하고, 당일 발급 방문증이나 외부 협력업체는 대상에서 제외하는 것과 같다.

계정 범위와 경로 처리 및 재개 기록 등 백엔드 동작이 전반적으로 개선된다

백엔드 세부 동작이 정리되었다. MCP(Model Context Protocol, AI가 외부 도구와 연결하기 위한 규약) 도구의 승인 기억이 선택된 앱 계정에 종속되도록 변경되어, 계정을 전환해도 다른 계정의 승인 내역이 유지되지 않는다. macOS에서 상대 경로로 지정된 MCP 실행 파일의 실행 안정성이 향상되었다. 롤아웃 압축이 공유 이력에 포함되어 codex exec resume으로 디렉터리 기준 재개 시 압축된 기록을 정상 처리하며, 세션 루트가 심볼릭 링크(symlink, 다른 위치를 가리키는 바로가기)여도 스레드 분기가 정상 작동한다. app-server 스레드 메타데이터에 null을 허용하는 model 및 reasoningEffort 필드가 추가되었고, 모델 카탈로그에서 지원할 경우 request_user_input_async를 통해 구조화된 비동기 질문을 전송할 수 있어 즉답 대기 없이 처리를 이어갈 수 있다. 짐 보관소에서 보관증과 영수증 번호가 맞아야 짐을 찾을 수 있고, 보관함 위치가 바뀌어도 영수증으로 물건을 찾으며 추가 보험 안내도 현장 즉답 없이 확인 가능한 것과 같다.
