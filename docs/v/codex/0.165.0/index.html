Codex 0.165.0

發布日期：2026-10-27

繁體中文

新功能

內建 Google Cloud Vertex AI 提供者，支援 GPT-6.1 Terra 模型

如果你習慣使用 Google Cloud 部署各項服務，現在可以直接透過 Vertex AI 調用模型，不用再自己撰寫複雜的轉接外掛。 設定檔只要加入：

model_provider = "gcp"

就能直接切換為內建的 Google Cloud Vertex AI 提供者。同時，官方模型清單也加入了最新推出的 GPT-6.1 Terra，讓你在挑選模型時有更多元的運算選擇。

宛如到連鎖租車行租賃商務車隊，以前想開特定廠牌還得自己找外包車行簽約，現在官方直接納入特約合作名單，還同步上架了最新款旗艦房車供你自由挑選。

當你著手建置企業內部應用，想把 AI 運算統一收整在既有的 Google Cloud 專案與帳單下，只要在設定檔指定 gcp，就能立刻連接 Vertex AI 資源；需要測試最新模型能力時，也能直接在清單中選用 GPT-6.1 Terra。

新功能

工作階段選擇器支援儲存庫篩選，指令中心依目錄分組

當你同時在多個專案副本間切換工作時，要在落落長的工作階段清單裡找出剛剛開啟的對話往往得費一番工夫。 在搭配 Git 工作樹（讓同一專案平行開多份副本的功能）進行多工處理時，工作階段選擇器現在加入了儲存庫篩選機制，你可以快速過濾出屬於特定專案的工作階段。

好比大型檔案庫整頓借閱卡，以前所有專案的借閱單全塞在同一個抽屜，找紀錄得一張張比對；現在能按專案名稱抽取專屬卡盒，櫃台還會按實體檔案夾分層收納。

代理指令中心也同步支援目錄分組，會將關聯在同一工作樹目錄下的所有紀錄整合在一起，讓跨副本的工作階段瀏覽井然有序。當你一邊在主專案修復問題，另一邊在副本測試新功能時，只要開啟選擇器輸入專案名稱，就能切回目標對話，不再被其他專案的工作階段干擾。

新功能

應用伺服器 API 支援附加對話分支，實驗性拆分子討論串

如果你正在透過應用伺服器介面開發專屬工具，想在同一個對話脈絡下嘗試不同解法時，管理獨立分支往往相當繁瑣。 app-server 的 API 現在加入了實驗性的附加對話分支（從既有對話衍生出附屬子討論串的機制）。這項功能讓應用程式能直接從既有對話拆出分支，既完整保留主線累積的上下文，又不會讓測試過程弄亂原本的紀錄。

恰似在活頁筆記本貼上延伸標籤頁，以前想嘗試第二種草案只能整本重新謄寫，現在直接在關鍵頁面夾入附屬便箋，既保留原有筆記的脈絡，寫壞了也能隨時抽換。

當你需要讓使用者對同一個問題評估多種修改方案時，就能透過這組介面拉出附屬討論串進行推演，讓主線對話隨時維持乾淨。

新功能

支援對話途中調整思考力度，預設開放動態切換

向 AI 提問時如果一開始只隨口聊聊，隨後卻突然碰上需要抽絲剝繭的複雜架構，往往會受限於最初設定的思考程度。 針對有支援的模型，現在已經預設允許在對話途中直接修改思考力度（決定模型在回答前投入多少推理運算的參數）。你不再需要為了讓 AI 想得更深入而特地中斷對話另開新局，交談到一半隨時能依照問題難度靈活增減思考量。

跟下西洋棋時切換思考時限一樣，以前開局選了快棋就只能一路快打到底，現在遇到膠著局面能當場多要幾分鐘長考，解開難題後又能切回節奏，不必把整盤棋推倒重來。

當你原本只是請它解讀一段日常日誌，中途突然想探討分散式鎖的死結原因時，就能當場調高力度，讓模型針對核心邏輯進行深度推理。

新功能

新設定檔預設啟用第二代記憶，支援匯入外部代理記憶

每次建立新的個人設定檔時，如果希望 AI 能記住你的偏好或從其他工具轉移習慣，往往需要不少手動設定。 現在建立全新設定檔時，工具會預設啟用第二代記憶架構（讓工具跨對話保存使用者偏好的機制）。這套架構也同步支援匯入外部代理的記憶資料，能直接讀取其他 AI 工具先前累積的偏好與操作紀錄。

如同搬進全新裝潢的智慧住宅，以前每次換新家都要重新訓練管家認識你的生活作息，現在進門就有現成的智慧管家隨時待命，還能直接把前任管家的備忘手冊整本讀取完畢。

當你從其他開發助理切換到 Codex 時，不用再從頭教它你的排版風格與常用語法，只要把既有的記憶檔匯入，新設定檔就能立刻依循你的慣用模式工作。

問題修復

終端介面在參數錯誤時保持可編輯，新工作階段沿用預設審核者

在終端介面操作工具時，如果遇到執行參數填寫錯誤，偏好設定選單一旦被連帶鎖死，往往會讓人動彈不得。 針對終端使用者介面（以純文字排版的終端機視窗），現在即便執行設定中存在無效參數，偏好設定依然保持可編輯狀態，且修改後能立即生效。新開啟的終端工作階段在未提供明確覆寫時，現在也會確實遵循伺服器的預設審核者規則。

彷彿汽車儀表板的設定選單，以前只要感測器回報異常數值，整個操作面板就跟著卡死無法調整；現在各項控制選項依然能隨意修改並即時生效，新發動的車輛也會主動遵循車隊預設的安全指派。

無論是不慎輸入了無效路徑，或是剛啟動全新的終端對話，介面都不會再無故罷工，各項審核權限也能正常運作。

新功能

中斷與取消時即刻停止背景運算，模型找不到不再盲目重試

當你在操作過程中按下停止或遇到無效請求時，背景程式如果持續空轉或重複嘗試，往往會白白消耗運算資源與等待時間。

有如辦公大樓的撤銷派工機制，以前專案喊停後外包廠商依然繼續趕工，送錯地址的公文還在不斷重複投遞；現在只要前端發出取消通知，所有外派作業與無效配送都會立刻剎車。

第一項改動針對遠端 MCP 工具（讓 AI 連接外部工具的協定）。如果本機端已經取消或不再等待回傳結果，會主動向遠端發送取消通知，避免遠端伺服器徒勞運算。 第二項調整落在代理訊息排隊機制。當你在對話中按鍵中斷執行，或是切換到計畫模式時，已排隊的訊息不會再擅自重啟工作。 第三項改動則是在模型提供者回報找不到指定型號時，工具會立即停止重複嘗試，並完整保留原本的錯誤訊息。 以前遇到操作中斷或設定失效時，背景可能會持續重試或再度喚醒任務，現在各項失效請求都能及時收手。

新功能

市集網址驗證補強防護，防範 Git 連線至未經授權的主機

從擴充市集下載外掛或套件時，工具能否嚴格把關下載來源，攸關整個開發環境的安全。 市集網址的驗證機制現在補上了防護漏洞。以往在比對網址時存在落差，可能導致 Git 最終連線的主機，與安全名單中所允許的主機並不一致。這個驗證漏洞已經補上，Git 不會再連到與允許名單所檢查的不同主機。

猶如社區門禁核對訪客名單，以前警衛登記的地址和訪客實際去的地方可能對不上，現在這個對不上的漏洞已經補上。

這個問題已經修好，安裝市集套件時不會再因網址歧異而誤連至未授權的外部主機。

English

FEATURE

Built-in Google Cloud Vertex AI Provider and Support for GPT-6.1 Terra

If you are used to deploying services on Google Cloud, you can now call models directly through Vertex AI without writing complex adapter plugins yourself. Simply add the following to your configuration file:

model_provider = "gcp"

This directly switches to the built-in Google Cloud Vertex AI provider. At the same time, the official model catalog now includes the newly released GPT-6.1 Terra, giving you more computing options when choosing models.

Picture renting a commercial fleet from a car rental chain. In the past, driving a specific brand required finding and contracting with outside agencies on your own. Now the company directly adds them to its partner roster and puts the latest flagship sedan in the lineup for you to choose from.

When building internal enterprise applications and consolidating AI compute under existing Google Cloud projects and billing, you only need to specify gcp in the configuration file to connect to Vertex AI resources immediately. When you need to test the latest model capabilities, you can also select GPT-6.1 Terra directly from the catalog.

FEATURE

Session Picker Supports Repository Filtering, Agent Command Center Groups by Directory

When juggling work across multiple project copies, locating a recently opened conversation in a long session list often takes considerable effort. When multitasking with Git worktrees (a feature allowing multiple copies of the same project in parallel), the session picker now includes a repository filter, allowing you to quickly filter out sessions belonging to a specific project.

Imagine a large archive reorganizing its checkout slips. Previously, slips from all projects were stuffed into a single drawer, forcing you to check records one by one. Now you can pull out a dedicated card box by project name, and the desk organizes them into tiers by physical folder.

The agent command center now also supports directory grouping, bringing together all records associated with the same worktree directory to keep session navigation across copies neat and orderly. When you are fixing an issue in the main project while testing a new feature in a copy, you can simply open the picker and type the project name to switch back to the target conversation without distraction from other projects' sessions.

FEATURE

App-Server API Supports Experimental Attached Thread Forks

If you are developing custom tools through the app-server interface and want to try different solutions within the same conversational context, managing separate branches can often be cumbersome. The app-server API now includes experimental attached thread forks (a mechanism for branching secondary sub-threads from an existing conversation). This feature allows applications to branch directly off an existing conversation, preserving the full context accumulated in the main thread while preventing experiments from cluttering original records.

Think of attaching extension tabs to a loose-leaf notebook. Previously, trying a second draft meant rewriting the entire notebook from scratch. Now you insert an attached memo directly into key pages, preserving the original context while letting you swap out bad drafts at any time.

When you need users to evaluate multiple revision options for the same issue, you can use this interface to spin off secondary threads for exploration while keeping the primary conversation completely clean.

FEATURE

Support for Adjusting Reasoning Effort Mid-Conversation, Enabled by Default

When asking an AI questions, starting with casual chat and then suddenly running into a complex architecture that demands deep dissection often leaves you constrained by your initial thinking depth. For supported models, changing reasoning effort (the parameter determining how much reasoning computation the model invests before answering) during a conversation is now enabled by default. You no longer need to interrupt the conversation and start a new session just to make the AI think more deeply; you can flexibly adjust the amount of thinking midway based on question complexity.

A chess clock adjustment reflects this transition. Previously, choosing blitz at the opening meant rushing through the entire match. Now, when a stalemate strikes, you can claim a few extra minutes on the spot to think deeply, then switch back to your normal pace once the puzzle is solved without resetting the board.

When you initially ask it to interpret a routine log and suddenly decide to explore the root cause of a distributed lock deadlock midway through, you can increase the effort on the spot to let the model perform deep reasoning on the core logic.

FEATURE

Fresh Profiles Enable Memory v2 by Default with Support for Importing External-Agent Memories

Whenever you create a new profile, having the AI remember your preferences or transfer habits from other tools usually requires considerable manual setup. When creating fresh profiles, the tool now enables memory v2 (a mechanism allowing the tool to preserve user preferences across conversations) by default. This architecture also supports importing external-agent memories, directly reading preferences and operational logs accumulated in other AI tools.

Consider moving into a newly renovated smart home. Previously, each move meant retraining a butler to learn your daily routine. Now, a ready-made smart butler is on standby the moment you enter, capable of reading through your previous butler's entire memo notebook.

When switching from another coding assistant to Codex, you do not need to reteach your formatting style and preferred syntax from scratch; simply import your existing memory files, and the fresh profile will immediately work according to your established habits.

BUGFIX

TUI Preferences Remain Editable on Invalid Settings, Fresh Sessions Honor Default Reviewer

When operating tools in a terminal interface, if execution parameters are entered incorrectly and the preference menu freezes as a result, you are often left stuck. For the terminal user interface (a text-based terminal display), preferences now remain editable and take effect immediately even when invalid parameters exist in execution settings. Fresh terminal sessions also properly honor the server's default approval reviewer rules when no explicit override is provided.

The settings menu on a car dashboard mirrors this behavior. In the past, whenever a sensor reported an abnormal reading, the entire console froze and prevented adjustments. Now control options remain fully editable with immediate effect, and newly started vehicles actively follow default safety assignments set by the fleet.

Whether you accidentally enter an invalid path or just launched a brand new terminal conversation, the interface will no longer freeze without cause, and approval permissions continue to function normally.

FEATURE

Promptly Stop Background Tasks on Interrupt and Cancellation, Stop Blind Retries for Missing Models

When you press stop during an operation or encounter an invalid request, background processes that continue idling or repeatedly retrying waste computing resources and waiting time.

An office building's dispatch cancellation mechanism works in much the same way. Previously, contractors continued rushing work after a project was halted, and misaddressed documents were repeatedly redelivered. Now, once the front desk issues a cancellation notice, all dispatched tasks and invalid deliveries brake immediately.

The first change applies to remote MCP tools (protocols that connect AI to external tools). If the local side has cancelled or no longer waits for returned results, it actively sends a cancellation notice to the remote side, preventing remote servers from wasting compute. The second adjustment targets the agent message queuing mechanism. When you press a key to interrupt execution during a conversation or switch to Plan mode, queued messages will no longer restart work without permission. The third change stops retrying immediately when a model provider reports that a specified model was not found, fully preserving the original error message. Previously, when operations were interrupted or settings failed, background processes might continuously retry or wake tasks back up; now invalid requests cease promptly.

FEATURE

Marketplace URL Validation Strengthened to Prevent Git Connecting to Unauthorized Hosts

When downloading plugins or packages from an extension marketplace, whether a tool strictly verifies download sources is vital to the security of your entire development environment. The marketplace URL validation mechanism has now closed a security gap. In the past, discrepancies during URL matching could cause Git to ultimately connect to a different host from the one permitted on the safe list. This validation gap has been closed, ensuring Git will no longer connect to a host different from the one checked against the allowlist.

Checking visitor logs at a gated community entrance reflects this safeguard. Previously, the address recorded by a guard might not match where a visitor actually went; now this mismatch loophole has been firmly closed.

This issue has been fixed, so installing marketplace packages will no longer inadvertently connect to unauthorized external hosts due to URL discrepancies.
