Codex 0.148.0

Released: 2026-08-18

Release notes

FEATURE

Export full terminal conversations to Markdown

Need to hand a Codex conversation to a teammate? You no longer have to select and copy it piece by piece.

It is like gathering loose notes from a desk into one notebook.

Type /export in the TUI, the text-based interface, to turn the complete conversation into Markdown. Put it on the clipboard for pasting elsewhere, or save it as a new file. Questions, replies, and code that were spread across the screen now have a shareable copy.

FEATURE

Fork, archive, and restore sessions

Halfway through a task, you may want to try another path without losing the original thread.

Run codex exec fork to split off a session, the record of one continuous piece of work.

It is like placing a bookmark at a fork in a novel before following another branch.

The original session remains available while you explore the new one. You can also archive an inactive session from the TUI resume picker and restore it there later.

FEATURE

Write prompts while TUI starts

With the question already in mind, you no longer need to leave the keyboard idle while the TUI initializes: start drafting the prompt, the instruction for AI.

It is like filling out a travel card while a train pulls into the platform, ready to hand over when boarding is prepared.

Startup also shows progress for resuming and forking work. You can tell whether the screen is still preparing, restoring a session, or creating a branch instead of watching an unexplained wait.

FEATURE

See estimated thread credits or cost

In an eligible workspace, you can check an estimate of this thread's credits or cost without leaving the terminal for a billing page.

It is like a taxi showing an estimated fare on its dashboard, roof light, and receipt.

Run /status for the estimate; terminal status lines and titles can show it too. It remains an estimate rather than a final bill, and availability depends on workspace eligibility.

FEATURE

Use Amazon Bedrock as a built-in provider

If your company already runs AI through Amazon Bedrock Runtime on AWS, Codex now includes it as a built-in provider, a source of model connections.

It is like finding a wall socket already installed for an appliance that used to need an adapter.

It supports AWS profiles and regions. It also supports routing for GPT-5.6. That lets it use your existing AWS identity, location, and routing choices rather than requiring another external provider connection.

FEATURE

Hooks can run commands and MCP tools asynchronously

When an event should trigger an automatic follow-up, hooks, small programs triggered by specific events, no longer have to wait for their commands to finish.

They can run commands asynchronously and invoke MCP tools, where MCP is a protocol that connects AI to external tools.

It is like handing a scene change to backstage without making the performance wait for every prop to be set.

A hook can start a command or external tool after an event without tying the same execution path to that wait.

FEATURE

Model and settings changes no longer disrupt a turn

Switching models or updating settings while work was in progress could leave old instructions behind or alter an active turn, one request-and-response processing round.

That no longer happens.

Changing a seasoning packet while soup cooks does not turn ingredients already in the pot into another dish.

You can still change the model and settings, but the current turn is not rewritten midway and stale instructions should not remain in the background to keep affecting later work.

FEATURE

Resumed sessions restore their workspace context

When returning to an earlier session, starting in the wrong folder or losing its approval rules is disruptive.

Resumed sessions now restore the persisted working directory, the folder used for that work, and approval policy, the rules for actions that need consent. Transcript previews are also more accurate.

It is like returning to a paused desk with its label, tools, and access rules put back in place.

The TUI resume choice better shows what you are about to pick up and its original working context.

FEATURE

Reconnect after provider outages and MCP reauthentication

A temporary provider outage, where the source of model service connection has trouble, no longer means the current turn must end there.

Turns reconnect through temporary provider outages. MCP servers, with MCP being the protocol connecting AI to external tools, also recover after OAuth reauthentication, where an existing account authorizes a third-party service.

It is like a tram getting power back after a brief outage without asking passengers to leave and buy tickets again.

Neither recovery requires restarting Codex.

FEATURE

Startup input no longer accidentally activates prompts

Before you can read the TUI, the text-based interface, buffered terminal keystrokes no longer unexpectedly activate prompts or choices on screen.

That prevents a prompt, a question waiting for input or selection, from being triggered before you can read it.

It is like turning on a stereo in the morning without yesterday's remote signal skipping today's first song.

You can inspect the question first, then decide what to enter or select.

FEATURE

Missing authentication shows onboarding

If Codex lacks authentication, the login check that proves identity, it no longer leaves you only at that missing-authentication state.

It shows onboarding, guidance through the steps needed for first use. This connects the missing check to the required first-use steps.

It is like a new phone without a SIM card showing its connection setup instead of only an unusable screen.
FEATURE

Composer and transcript formatting handle pasted text correctly

Pasting text into the composer, the area for writing prompts, can bring CRLF, a two-symbol line-break format used by some text systems.

Wrapped whitespace and long URLs, or web addresses, can also make the display render incorrectly. The composer and transcript, the conversation record display, now handle them correctly.

It is like filing sheets of different sizes without letting folds and long labels bend the pages out of shape.

Pasted special line breaks, wrapped spaces, and long URLs should now stay readable.

FEATURE

Sandbox denies restricted and unreadable paths

A sandbox is an isolated environment that limits what a program can do.

When it meets a denied or unreadable path, it now fails closed: it refuses access when safety cannot be confirmed.

It is like an archive desk withholding a file when it cannot read the collection barcode, rather than guessing the requester may receive it.

This restriction applies across Linux and Windows. A denied or unreadable path is not allowed through; the sandbox keeps the boundary by rejecting it.

FEATURE

Skill-creator guide is more focused

When you create a skill, an instruction guide that teaches Codex a particular way of working, its bundled skill-creator guide is now more focused.

That guide concentrates on creating this kind of instruction.

It is like a hiking map that marks the route to the summit together instead of mixing in other trails.

Use the more focused guide when writing a skill.

FEATURE

Validation rejects unfinished TODO placeholders

Before a skill can pass validation, unfinished TODO placeholders, text left to complete later, can no longer remain in its contents.

Validation, the check that content meets requirements, now rejects those placeholders.

It is like a proofreader returning a “figure pending” mark before printing rather than treating the page as finished.

A skill that passes validation cannot keep unfinished TODO placeholders.
