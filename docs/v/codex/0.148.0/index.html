Codex 0.148.0

發布日期：2026-08-18

zh-TW

整段終端對話可匯出成 Markdown

想把終端機裡和 Codex 討論過的內容交給同事，現在不用再逐段反白複製。這像把散落在桌上的便條紙收進同一本筆記本。在 TUI（文字介面的操作畫面）輸入 /export。完整對話會轉成 Markdown（用符號排出標題、清單等格式的純文字）。你可把結果放進剪貼簿，直接貼到別處；也可另存成新檔案。原本一段段散在畫面裡的提問、回覆和程式碼，會有可保存、可轉交的版本。

工作階段可分岔，也能收起後找回

同一個任務做到一半，想試另一條路又不想毀掉原本脈絡時，可以用 codex exec fork 分出一個工作階段（一次連續工作的上下文紀錄）。這像從小說讀到岔路時，先夾好書籤，再翻到另一條支線。原本的工作階段會留下來，新分支可另行探索。暫時不需要的紀錄也能在 TUI 的 resume picker（挑選要接續哪段工作的清單）歸檔；之後可從同一處還原，再繼續接手。

啟動尚未完成，也能先寫提示詞

問題已經想好時，不必把鍵盤空著等 TUI 初始化完成；現在可先寫下提示詞（交給 AI 的工作要求），把問題先整理成可送出的要求。像列車駛入月台時先填好行程單，乘車準備完成後便能立刻交出。啟動畫面也會顯示接續工作階段與分岔工作的進度。於是你知道畫面仍在準備，還是正在替你恢復哪段工作或建立哪個分支，不會只面對毫無資訊的等待。

可查看工作串的預估額度或費用

在符合資格的工作區，想知道目前這串對話大約用了多少 credits（可用額度）或費用，現在不必離開終端機找帳務頁面。這像計程車把預估車資同時顯示在儀表板、車頂燈和收據上。輸入 /status 可查看估算，終端機最底下的狀態列與終端機標題也會顯示同類資訊。這是預估值，不是承諾的最終帳單；可用與否則取決於你的工作區是否符合資格。

Amazon Bedrock 可直接作為內建供應者

公司已用 AWS 的 Amazon Bedrock Runtime 跑 AI 時，Codex 現在把它列為內建 provider（提供模型連線的服務來源）。像原本得外接的電器，現在插座已經裝在牆上。它支援 AWS profile（AWS 的身分與連線設定）。也支援 region（服務所在區域）。GPT-5.6 的 routing 是把請求送往適合模型的規則，現在也支援。因此可依既有 AWS 身分、區域與路由來使用，而非另行接上一個外部提供者。

掛鉤可非同步跑指令，也能叫用 MCP

要在特定事件發生時自動接一段處理，hooks（掛鉤，特定事件發生時被觸發的小程式）現在不必卡著等自己的指令跑完。它能非同步執行命令，也能叫用 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）工具。像舞台劇把換場交給後台，台上的演出不必等每件道具擺妥。這讓掛鉤可在事件後啟動命令或外部工具，同時不把等待綁死在同一條執行流程上。

切換模型或設定，不再殘留舊指示

一段工作正在進行時切換模型，或更新設定，以前可能留下舊指示，甚至改變進行中的 turn（一次送出要求到得到回應的處理回合）。現在這兩種變動不再造成那些結果。正在煮湯時換一包調味料，不會讓鍋裡已經下過的材料忽然變成另一道菜。你仍可調整模型和設定，但當前回合不會在中途被改寫，過時的指示也不應繼續留在後面，持續影響之後的工作流程。

接回舊工作，目錄與核准規則會一併回來

隔一段時間再接回舊工作階段時，最怕從錯的資料夾開始，或發現先前的核准規則不見了。現在接續後會還原先前保存的 working directory（當時工作的資料夾）。approval policy（哪些動作需先徵得同意的規則）也會回來。逐字稿預覽也更準確。像回到暫停的工作桌，桌牌、工具位置和進出規則都照原樣擺回來。因此在 TUI 選擇接續時，較能辨認將要接手的內容與它原來工作的脈絡。

供應者短暫斷線可重連，MCP 授權後也會恢復

工作進行時 provider（提供模型服務的連線來源）暫時出問題，不再等同這一輪工作必須就此中斷。turn 會嘗試穿過暫時的供應者中斷重新連線。MCP（Model Context Protocol，讓 AI 連接外部工具的協定）伺服器也會恢復。這發生在 OAuth（用既有帳號授權第三方服務的登入方式）重新驗證之後。像電車短暫停電後接回電力，乘客不用先下車再從頭買票。兩種恢復都不需重新啟動 Codex。

啟動時的殘留按鍵不會誤觸提示

看清 TUI（文字介面的操作畫面）之前，終端機先前暫存的按鍵輸入不會再突然啟用畫面上的提示或選項。這可避免某個 prompt（等待你輸入或選擇的詢問）在你讀到內容前就被誤觸。這項修正針對啟動時殘留的終端機輸入。像早晨開啟音響時，昨天留下的遙控器訊號不會替你跳過今天想聽的第一首歌。你能先確認眼前的詢問，再決定要輸入或選哪個選項。

缺少驗證時，會顯示初次設定引導

登入驗證尚未備妥時，Codex 不會只停在缺少 authentication（證明你身分的登入驗證）的狀態。畫面會顯示 onboarding（第一次使用時帶你完成必要步驟的引導）。這是認證缺少時顯示的初次使用引導。它把缺少驗證的情況接到初次使用所需步驟，讓你看得見接下來該完成什麼。像新手機尚未插入 SIM 卡時，螢幕先帶你完成連線設定，而不是只停在不能使用的畫面。

貼上換行文字與長網址，編寫區不再排版錯亂

把別處複製的文字貼進 composer（撰寫提示詞的輸入區）時，CRLF 是某些文字系統用兩個符號表示換行的格式。自動折行產生的空白和很長的 URL（網站位址）也都可能讓畫面看起來怪異。現在編寫區與 transcript（對話紀錄顯示區）會正確處理這些內容。像把不同尺寸的紙張放進同一個資料夾，折痕與長標籤不會把頁面擠歪。貼上含特殊換行、折行空白或長網址的內容時，文字應維持可讀的呈現。

被拒或讀不到的路徑，沙盒會確實擋下

沙盒是一種把程式可做的事圈在安全範圍內的隔離環境。遇到不允許或無法讀取的路徑時，現在採取 fail closed（無法確認安全時先拒絕）的做法。像檔案封存室讀不清取件條碼時，先不交出文件，而不是猜測申請人有權領取。這項限制涵蓋 Linux 和 Windows。換句話說，路徑被拒絕或不可讀時，沙盒不會繼續放行，而是以拒絕來保住限制的邊界。

Skill-creator guide 更聚焦

替 Codex 建立 skill（讓它學會特定工作方法的操作指引）時，內附的 skill-creator guide 現在更聚焦。這份隨工具附上的說明集中於建立這類指引的工作，內容重點就是建立這類操作指引。像登山地圖把前往山頂的路線集中標出，不把其他步道混在同一頁。準備撰寫 skill 時，可參考這份更聚焦的 guide。

未完成 TODO 會被驗證拒絕

準備讓 skill 通過驗證時，未完成的 TODO（提醒日後補做的佔位文字）不能再留在內容裡。validation（檢查內容是否符合要求的程序）現在會拒絕這類佔位文字。這項拒絕針對仍未完成的 TODO 佔位文字。像印刷前的校稿把「待補圖」標記退回，不把它當成已經完成的版面。要通過驗證，skill 內容不能還留著這些未完成 TODO。

en

Export full terminal conversations to Markdown

Need to hand a Codex conversation to a teammate? You no longer have to select and copy it piece by piece. It is like gathering loose notes from a desk into one notebook. Type /export in the TUI, the text-based interface, to turn the complete conversation into Markdown. Put it on the clipboard for pasting elsewhere, or save it as a new file. Questions, replies, and code that were spread across the screen now have a shareable copy.

Fork, archive, and restore sessions

Halfway through a task, you may want to try another path without losing the original thread. Run codex exec fork to split off a session, the record of one continuous piece of work. It is like placing a bookmark at a fork in a novel before following another branch. The original session remains available while you explore the new one. You can also archive an inactive session from the TUI resume picker and restore it there later.

Write prompts while TUI starts

With the question already in mind, you no longer need to leave the keyboard idle while the TUI initializes: start drafting the prompt, the instruction for AI. It is like filling out a travel card while a train pulls into the platform, ready to hand over when boarding is prepared. Startup also shows progress for resuming and forking work. You can tell whether the screen is still preparing, restoring a session, or creating a branch instead of watching an unexplained wait.

See estimated thread credits or cost

In an eligible workspace, you can check an estimate of this thread's credits or cost without leaving the terminal for a billing page. It is like a taxi showing an estimated fare on its dashboard, roof light, and receipt. Run /status for the estimate; terminal status lines and titles can show it too. It remains an estimate rather than a final bill, and availability depends on workspace eligibility.

Use Amazon Bedrock as a built-in provider

If your company already runs AI through Amazon Bedrock Runtime on AWS, Codex now includes it as a built-in provider, a source of model connections. It is like finding a wall socket already installed for an appliance that used to need an adapter. It supports AWS profiles and regions. It also supports routing for GPT-5.6. That lets it use your existing AWS identity, location, and routing choices rather than requiring another external provider connection.

Hooks can run commands and MCP tools asynchronously

When an event should trigger an automatic follow-up, hooks, small programs triggered by specific events, no longer have to wait for their commands to finish. They can run commands asynchronously and invoke MCP tools, where MCP is a protocol that connects AI to external tools. It is like handing a scene change to backstage without making the performance wait for every prop to be set. A hook can start a command or external tool after an event without tying the same execution path to that wait.

Model and settings changes no longer disrupt a turn

Switching models or updating settings while work was in progress could leave old instructions behind or alter an active turn, one request-and-response processing round. That no longer happens. Changing a seasoning packet while soup cooks does not turn ingredients already in the pot into another dish. You can still change the model and settings, but the current turn is not rewritten midway and stale instructions should not remain in the background to keep affecting later work.

Resumed sessions restore their workspace context

When returning to an earlier session, starting in the wrong folder or losing its approval rules is disruptive. Resumed sessions now restore the persisted working directory, the folder used for that work, and approval policy, the rules for actions that need consent. Transcript previews are also more accurate. It is like returning to a paused desk with its label, tools, and access rules put back in place. The TUI resume choice better shows what you are about to pick up and its original working context.

Reconnect after provider outages and MCP reauthentication

A temporary provider outage, where the source of model service connection has trouble, no longer means the current turn must end there. Turns reconnect through temporary provider outages. MCP servers, with MCP being the protocol connecting AI to external tools, also recover after OAuth reauthentication, where an existing account authorizes a third-party service. It is like a tram getting power back after a brief outage without asking passengers to leave and buy tickets again. Neither recovery requires restarting Codex.

Startup input no longer accidentally activates prompts

Before you can read the TUI, the text-based interface, buffered terminal keystrokes no longer unexpectedly activate prompts or choices on screen. That prevents a prompt, a question waiting for input or selection, from being triggered before you can read it. It is like turning on a stereo in the morning without yesterday's remote signal skipping today's first song. You can inspect the question first, then decide what to enter or select.

Missing authentication shows onboarding

If Codex lacks authentication, the login check that proves identity, it no longer leaves you only at that missing-authentication state. It shows onboarding, guidance through the steps needed for first use. This connects the missing check to the required first-use steps. It is like a new phone without a SIM card showing its connection setup instead of only an unusable screen.

Composer and transcript formatting handle pasted text correctly

Pasting text into the composer, the area for writing prompts, can bring CRLF, a two-symbol line-break format used by some text systems. Wrapped whitespace and long URLs, or web addresses, can also make the display render incorrectly. The composer and transcript, the conversation record display, now handle them correctly. It is like filing sheets of different sizes without letting folds and long labels bend the pages out of shape. Pasted special line breaks, wrapped spaces, and long URLs should now stay readable.

Sandbox denies restricted and unreadable paths

A sandbox is an isolated environment that limits what a program can do. When it meets a denied or unreadable path, it now fails closed: it refuses access when safety cannot be confirmed. It is like an archive desk withholding a file when it cannot read the collection barcode, rather than guessing the requester may receive it. This restriction applies across Linux and Windows. A denied or unreadable path is not allowed through; the sandbox keeps the boundary by rejecting it.

Skill-creator guide is more focused

When you create a skill, an instruction guide that teaches Codex a particular way of working, its bundled skill-creator guide is now more focused. That guide concentrates on creating this kind of instruction. It is like a hiking map that marks the route to the summit together instead of mixing in other trails. Use the more focused guide when writing a skill.

Validation rejects unfinished TODO placeholders

Before a skill can pass validation, unfinished TODO placeholders, text left to complete later, can no longer remain in its contents. Validation, the check that content meets requirements, now rejects those placeholders. It is like a proofreader returning a “figure pending” mark before printing rather than treating the page as finished. A skill that passes validation cannot keep unfinished TODO placeholders.
