新增 agents 互動儀表板，集中管理各項任務

同時交辦多個 AI 任務時，現在不用在終端機裡盲目切換。宛如車間牆上的即時派工白板，所有工單一目了然，隨手按個按鍵就能迅速調度。在命令列輸入 codex agents 即可開啟互動式 dashboard（集中查看與操作所有任務的控制面板）。你能在這個畫面中搜尋、啟動、開啟、重新命名以及停止各項任務。如果習慣特定的鍵盤操作，介面也支援自訂快速鍵，讓你用最順手的方式管理所有背景工作。

新增 /cd、/pwd 與 /cwd 指令，在工作階段內切換目錄

在終端機與 Codex 對話時，如果想換到另一個資料夾處理程式碼，現在不必關掉重開。在 TUI（以文字排版的終端機互動介面）的工作階段中，你可以直接輸入 /cd 切換工作目錄，或者用 /pwd 與 /cwd 印出當前所在的路徑。這讓你在同一次交談裡隨時移動工作位置，省去退出對話再重新連線的麻煩。彷彿在圖書館自習時直接抱著課本換到隔壁桌，不必收拾書包重新刷卡入館。

新增 codex queue 指令，將訊息排入指定工作階段

另開終端機想傳話給正在跑的任務時，codex queue 提供了直接插話的管道。正如往同事桌上的待辦匣投遞便條，就算對方正在休息也會被輕拍喚醒，遇上同名同事也能精準投遞。這個新指令可將訊息送進本機或遠端既有的工作階段（保存對話與狀態的執行單元）。排入佇列的訊息現在能確實喚醒閒置中的工作階段；碰上重複的工作階段名稱時，系統能更聰明地辨識目標；同時完整保留貼上文字或延遲執行指令的原有語意，確保工作不失真。

擴充 Vim 編輯模式，支援單字換寫與字元替換

習慣在終端機用 Vim 模式打字的人，編輯提示詞的手感現在更加完整。系統擴充了字元替換功能，也加入多個常用的變更動作。例如你可以用 cw 換掉當前單字，用 c$ 改寫游標到行尾的文字，或者按 cc 清空整行重新輸入。這些快捷動作讓修改輸入內容時更加順手，不必依賴退格鍵逐字倒退。如同雕刻師換上專用雕刀，削掉局部字詞或改動單一筆劃時不必整塊木料重磨。

codex doctor 擴大診斷，全面檢查防護與連線狀態

遇到連線異常或環境卡住時，診斷工具能幫你更快找出病灶。如同診所健檢新增了免疫防禦與血液循環檢查，一次把潛在隱患排查清楚。執行 codex doctor 指令時，檢查範圍現在涵蓋四大關鍵項目：端點防護軟體的阻擋、網路與 proxy（代理伺服器，替你轉發網路請求的中介主機）連線故障、桌面應用程式的運作狀態，以及版本更新伺服器的連線能力。當工具無法正常工作時，你能第一時間釐清是公司安全軟體攔截還是網路設定出錯。

SDK 支援精確設定覆寫，並加入 max 與 ultra 推理選項

透過 SDK（軟體開發套件，讓程式碼直接叫用工具功能的套件庫）呼叫 Codex 的開發者，現在擁有更細緻的控制權。你可以在程式碼中直接傳入精確的 CLI 設定覆寫值，依照當前任務需求微調各項參數。此外，針對需要深度思考的複雜問題，推理力度的選項新加入了 max 與 ultra 兩檔設定，讓模型投入最充足的推理資源來解析難題。宛如賽車手既能精細調校底盤參數，又能在面臨險峻賽道時切換至極限增壓檔位。

接續與分岔對話時，完整還原既有的權限設定檔

接續先前暫停的對話，或從中分岔出新分支時，原本配置的權限規則現在會完整保留。恰如重開暫停的專案時自動配發原本的專屬通行證，不會默默退回一般訪客的備援設定。系統在接續或分岔對話串時，會確實還原當時啟用的 permission profile（權限設定檔）。程式不會再不聲不響退回當前預設值。這確保你在特定安全等級下進行的任務，重開後仍維持相同的授權邊界。

修正子代理重複動作，釐清通知與審核傳遞路徑

讓主代理呼叫子代理分頭做事時，背後的通訊與排程變得更加乾淨。以前子代理有時會不小心重複執行同一個動作，通知訊息與授權核准也可能在介面中傳遞混亂；現在這些問題都已修正。TUI 精準收緊了子代理通知與審核確認的傳遞路徑，確保每個需要你同意的動作都能正確呈現在畫面上。如同機場塔台把每架飛機的到場通知與起飛許可導向正確頻道，也不會對同一架飛機重複下達起飛指令。

WebRTC 即時連線中斷後自動重連，不遺漏待送輸出

透過即時通道接收輸出時，短暫的網路波動不再造成內容遺失。彷彿步話機穿越隧道時計程短暫斷訊，連線接回後會把中斷期間的語音完整補齊而不漏字。負責即時傳輸的 WebRTC（讓瀏覽器與應用程式直接進行影音或資料串流的通訊協定）側邊頻道連線，在遭遇非預期的傳輸中斷時，現在會自動嘗試重新連線。重新連上之後，中斷期間積壓、尚未送出的輸出資料會完整補送，不會被無故丟棄，確保傳輸過程不漏接任何字句。

Windows Terminal 完整保留行內 TUI 歷史紀錄

在 Windows Terminal（微軟推出的現代化命令列終端機）中使用 Codex 的人，回頭翻閱過去的討論紀錄變得更加方便。以前在行內 TUI 模式下互動時，對話內容往往無法留在終端機自帶的 scrollback（向上捲動查看歷史輸出的緩衝區）裡；現在這些行內歷程會完整保留。你可以隨時用滑鼠滾輪往上滑，查看先前的程式碼與回應。像把寫滿筆記的長卷往上捲動，先前的紀錄依然整齊保留在紙頁上方。

設定閒置對話重播上限，防止串流文字佔用記憶體

背景掛著多個任務時，系統不再因為保留太多舊輸出而吃掉記憶體。好似把封存箱設定容量上限，避免暫停工作的舊錄音檔無休止佔滿倉庫空間。針對目前未處於活躍狀態的 TUI 對話串，其 replay buffer（用來重播串流過程的快取緩衝區）現在被設下了明確的儲存上限。這項限制能防止背景對話過度保留落落長的文字串流，大幅減輕記憶體負擔，讓長時間開著多個工作階段的操作更加輕盈穩定。

明確外部貢獻規範，先透過 issue 與設計討論凝聚共識

有意為 Codex 開源專案貢獻程式碼的開發者，現在有了更清晰的協作指引。官方在貢獻規範中明確指出，外部開發者的提案應先透過 GitHub issue 提出並進行架構設計討論，取得共識後再著手實作，而非直接送出 pull request（請求專案管理者合併程式碼的申請）。在動手寫程式前先對齊設計，可避免白費力氣。正像裝修房屋時先與設計師確認藍圖並達成共識，再動工拉管線與砌牆。

補充容器安全文件，揭示 DNS 資料外洩風險與信任極限

在安全容器內執行未受信任的程式碼時，現在有更詳盡的防護風險指引。官方文件深入記錄了 secure devcontainer（用來隔離環境的開發容器）的信任限制。內容特別點出了 DNS 資料外洩的潛在威脅，說明惡意程式可能利用網域名稱查詢將機密資料外洩。這份說明提醒團隊在隔離環境中仍需嚴格審視網路外連政策。好比在隔音嚴密的會議室辦公，若允許隨意對外寄信，信封上的地址查詢仍可能洩漏機密。

后台挂着多个任务时，系统不再因为保留太多旧输出而吃掉内存。好似把封存箱设定容量上限，避免暂停工作的旧录音文件无休止占满仓库空间。针对目前未处于活跃状态的 TUI 对话串，其 replay buffer（用来重播流式过程的缓存缓冲区）现在被设下了明确的存储上限。这项限制能防止后台会话过度保留长长的文本串流，大幅减轻内存负担，让长时间开着多个工作会话的操作更加轻盈稳定。

明确外部贡献规范，先通过 issue 与设计讨论凝聚共识

有意为 Codex 开源项目贡献代码的开发者，现在有了更清晰的协作指引。官方在贡献规范中明确指出，外部开发者的提案应先通过 GitHub issue 提出并进行架构设计讨论，取得共识后再着手实现，而非直接提交 pull request（请求项目维护者合并代码的申请）。动手写代码前先对齐设计，可以避免白费力气。正像装修房屋时先与设计师确认蓝图并达成共识，再动工拉管线与砌墙。

补充容器安全文档，揭示 DNS 数据外泄风险与信任极限

在安全容器内运行未受信任的代码时，现在有更详尽的防护风险指引。官方文档深入记录了 secure devcontainer（用来隔离环境的开发容器）的信任限制。内容特别指出了 DNS 数据外泄的潜在威胁，说明恶意程序可能利用域名查询将机密数据外泄。这份说明提醒团队在隔离环境中仍需严格审视网络外连策略。好比在隔音严密的会议室办公，若允许随意对外寄信，信封上的地址查询仍可能泄露机密。

対話型 agents ダッシュボードでタスクを一元管理

複数の AI タスクを並行して進める際、端末を行き来して迷う必要はもうない。作業場の壁にある指示ボードのように、すべての作業票が一目瞭然で並び、キー操作ひとつで手早く割り振れる。コマンドラインで codex agents と入力すると、対話型のダッシュボードが開く。この画面からタスクの検索、開始、展開、名前の変更、停止をまとめて操作できる。操作用のショートカットキーも好みに応じて割り当てられるため、慣れたキーバインドで各作業を切り盛りできる。

/cd、/pwd、/cwd コマンドで作業ディレクトリを移動

端末で Codex と対話している最中に作業フォルダを移動したくなっても、画面を閉じ直す必要はない。TUI（テキストベースの操作画面）のセッション内で、/cd を入力して作業ディレクトリを切り替えたり、/pwd や /cwd で現在位置を表示したりできる。同じ対話を維持したままフォルダ間を自由に移動できるため、接続し直す手間が省ける。図書館の自習室で荷物をまとめて退館することなく、本を抱えて隣の机へ移るようなものだ。

codex queue でローカルやリモートのセッションへ指示を送信

別のウィンドウから実行中のタスクへ追加入力を送りたいとき、codex queue が直接メッセージを届ける窓口になる。同僚の机のトレイにメモを入れるように、相手が休んでいれば起こし、同姓同名の人がいても正しく届けられる。この新コマンドを使えば、ローカルやリモートにある既存のセッションへ指示を送信できる。キューに入ったメッセージは待機中のセッションを確実に復帰させ、重複したセッション名も適切に見分ける。さらに、貼り付けたテキストや後回しにしたコマンドの意味も崩さずに保持する。

Vim 編集モードを拡充し、単語変更や文字置換に対応

端末で Vim キーバインドを使ってプロンプトを入力する際の操作感が向上した。文字の置換機能が拡充され、実践的な変更モーションも追加されている。例えば cw で単語を書き換え、c$ でカーソル位置から行末までを変更し、cc で行全体を書き直せる。バックスペースキーを連打することなく、使い慣れたキー操作で素早くプロンプトを修正できる。木彫り職人が専用の彫刻刀に持ち替え、木材全体を削り直すことなく単語や行の一部だけを手早く削り整えるようなものだ。

codex doctor がセキュリティソフトやネットワーク障害を診断

接続の不調や環境のトラブルが起きた際、診断機能を使えば原因を素早く特定できる。クリニックの健康診断に免疫機能や血流の検査項目が加わり、隠れた不調を一度に洗い出せるようになったようなものだ。codex doctor を実行した際、エンドポイント保護ツールの干渉、ネットワークやプロキシの通信障害、デスクトップアプリの状態、アップデートサーバーへの接続性の 4 項目を詳しく調べる。ツールが動かないときにセキュリティソフトによる遮断かネットワーク設定の不備かを切り分けられる。

SDK での設定上書きと max・ultra 推論モードに対応

SDK（プログラムから機能を呼び出すための開発キット）を利用する開発者は、動作をより細かく制御できるようになった。コード内から正確な CLI 設定の上書き値を直接渡し、タスクに応じたパラメータ調整を行える。さらに、深い思考を要する難問に対して、思考の深さを示す reasoning effort の選択肢として max と ultra を指定できるようになった。レース車両の足回りを細かく調整しつつ、難関コースで限界突破の過給モードを起動するようなものだ。

対話の再開や分岐時に権限プロファイルを正確に復元

中断していた対話を再開したり、新しいブランチへ分岐したりする際、設定していた権限ルールがそのまま引き継がれるようになった。一時停止した作業へ戻ったとき、専用の通行証がそのまま手渡され、一般来訪者向けの初期設定へ勝手に戻されないようなものだ。スレッドを再開または分岐した際、当時有効だった permission profile（権限プロファイル）が復元される。現在のデフォルト設定へ暗黙のうちに戻ることはない。これにより、特定のセキュリティ基準で進めていた作業の保護範囲を維持できる。

サブエージェントの重複動作を修正し通知や承認経路を整理

メインのエージェントがサブエージェントを呼び出して作業を分担させる際、通信とタスク管理が整理された。以前はサブエージェントが同じ動作を重複して実行したり、通知や承認リクエストの伝達経路が乱れたりすることがあった。今回は重複動作を解消し、TUI におけるサブエージェントの通知や承認要求のルーティングを引き締めた。空港の管制塔が到着通知と離陸許可の要求を正しい無線経路へ流し、同じ航空機に離陸指示を二度出さないようなものだ。

WebRTC サイドバンド切断時に出力を落とさず再接続

リアルタイム通信で出力を受け取る際、一時的な回線の途切れでデータが失われる心配がなくなった。トランシーバーがトンネルで一時的に途切れても、電波が戻った際に保留されていた音声を欠落なく再生するようなものだ。WebRTC（ブラウザやアプリ間でデータ通信を行う規格）を用いたサイドバンド接続は、予期せぬ切断が起きても自動で再接続する。切断中に溜まっていた出力データは破棄されずにそのまま届けられるため、応答内容を取りこぼさない。

Windows Terminal のスクロールバックに対話履歴を保持

Windows Terminal（マイクロソフト製の端末アプリ）で Codex を利用する際、過去のログを振り返りやすくなった。以前はインライン TUI モードで対話すると、端末本来のスクロールバック領域に履歴が残らないことがあった。今回の修正により、インライン履歴が Windows Terminal のスクロールバックに正しく保持されるようになった。マウスホイールで上にスクロールすれば、直前のコードや回答をいつでも確認できる。長い巻物を巻き戻したときに、過去に書き留めた記録が上の余白にそのまま残っているようなものだ。

休止スレッドの再生バッファを制限しメモリ浪費を防止

複数のタスクをバックグラウンドに置いたままでも、古い出力の蓄積によってメモリが無駄に消費される心配がなくなった。保管箱に容量の上限を設け、休止中タスクの録音データが倉庫を圧迫しないようにするようなものだ。非アクティブな TUI スレッドの再生バッファに上限が設定された。これにより、休止中の対話が大量のストリーミング出力を保持し続けるのを防ぎ、メモリ消費を抑えて長時間の作業でも動作を安定させる。

外部からの貢献は PR の前に issue と設計議論を行う方針を明記

Codex のオープンソース開発に参加したい人に向けて、協力手順がより明確になった。外部からの貢献は、いきなり pull request（コードの統合依頼）を出すのではなく、まず issue を立てて設計や方針について議論を交わすべきであると明記された。コードを書く前に設計をすり合わせれば、無駄な手間を避けられる。家のリフォームで壁を壊して工事を始める前に、設計図を広げて建築士と間取りを相談するようなものだ。

安全な開発用コンテナにおける DNS 漏洩リスクと信頼限界を明記

セキュアなコンテナ内で信頼できないコードを実行する際のセキュリティ上の注意点が、ドキュメントに詳しく記載された。secure devcontainer（隔離環境を提供する開発用コンテナ）の信頼限界について解説されている。特に DNS exfiltration、すなわちドメイン名の問い合わせを悪用して機密データを外部へ持ち出すリスクについて言及している。コンテナ内であっても外部への通信ポリシーを厳格に見直す必要があると注意を促す。防音の会議室で作業していても、外部への手紙送付を許せば封筒の宛名検索から秘密が漏れうるようなものだ。

대화형 agents 대시보드로 작업을 한곳에서 관리한다

여러 AI 작업을 동시에 진행할 때 터미널 창을 번거롭게 오갈 필요가 없다. 작업장 벽에 걸린 배차 게시판처럼 모든 작업표가 한눈에 들어오고 단축키로 빠르게 처리하는 모습과 같다.명령줄에서 codex agents를 실행하면 대화형 대시보드가 열린다. 이 화면 안에서 작업을 검색하고 시작하며, 열어보거나 이름을 바꾸고 중지할 수 있다. 원하는 키에 맞게 단축키를 직접 설정하는 기능도 지원해 손에 익은 방식으로 모든 백그라운드 작업을 다룬다.

/cd, /pwd, /cwd 명령어로 세션 내 작업 디렉터리를 이동한다

터미널에서 Codex와 대화하던 중 다른 폴더로 옮겨가 코드를 고치고 싶을 때 더는 창을 껐다 켤 필요가 없다. TUI(글자 기반 조작 화면) 세션 안에서 /cd를 입력해 작업 디렉터리를 이동하거나, /pwd 및 /cwd로 현재 위치한 경로를 확인할 수 있다. 진행 중인 대화를 끊지 않고도 작업 폴더를 자유롭게 오갈 수 있어 세션을 다시 여는 수고를 덜어준다. 도서관 열람실에서 짐을 다 싸서 나갔다 오지 않고 책만 들고 옆자리로 옮겨 앉는 일과 같다.

codex queue로 로컬과 원격 세션에 메시지를 전달한다

다른 창에서 실행 중인 작업에 추가 지시를 보내고 싶을 때 codex queue가 직접 메시지를 건네는 통로가 된다. 동료의 책상 위 서류함에 메모를 넣는 것과 같아서, 쉬고 있던 사람을 깨워주고 이름이 겹치는 사람이 있어도 올바른 상대를 찾아간다.이 명령어를 쓰면 로컬이나 원격에 있는 기존 세션으로 메시지를 보낼 수 있다. 대기열에 들어간 메시지는 멈춰 있던 세션을 깨우고, 중복된 세션 이름도 적절히 가려내며, 붙여넣거나 미뤄둔 명령어의 본래 의미를 왜곡 없이 보존한다.

Vim 편집 모드를 확장해 단어 변경과 글자 대체를 지원한다

터미널에서 Vim 키 바인딩으로 프롬프트를 작성하던 사용자에게 편집 경험이 한층 완전해졌다. 글자 하나를 바꾸는 대체 기능이 늘어났고 다양한 변경 동작이 추가되었다. 이제 cw로 단어를 바꾸고, c$로 커서부터 줄 끝까지 고치며, cc로 현재 줄 전체를 비우고 새로 입력할 수 있다. 백스페이스를 일일이 누르지 않고도 익숙한 키 조합으로 텍스트를 제자리에서 수정한다. 조각가가 전용 조각도로 바꿔 쥐고 나무 전체를 갈아내지 않은 채 필요한 단어나 줄만 깔끔하게 다듬는 일과 같다.

codex doctor가 보안 프로그램과 네트워크 장애를 진단한다

연결에 문제가 생기거나 실행이 막힐 때 내장 진단 도구가 원인을 더 빠르게 짚어준다. 종합 건강검진에 면역 체계와 혈액 순환 검사가 추가되어 숨은 이상을 한 번에 찾아내는 일과 같다.codex doctor 명령어를 실행하면 네 가지 주요 항목을 진단한다. 엔드포인트 보안 프로그램의 차단 여부, 네트워크 및 프록시 장애, 데스크톱 앱 실행 상태, 업데이트 서버 연결 상태를 점검한다. 도구가 제대로 돌지 않을 때 사내 보안 프로그램 문제인지 네트워크 설정 오류인지 즉시 판별할 수 있다.

SDK 설정 덮어쓰기와 max 및 ultra 추론 단계를 지원한다

SDK(프로그램에서 기능을 호출할 수 있게 돕는 개발 도구 모음)를 쓰는 개발자는 동작 방식을 한층 정밀하게 다룰 수 있다. 코드에서 정확한 CLI 설정 덮어쓰기 값을 전달해 작업에 맞춰 세부 옵션을 조정할 수 있다. 아울러 깊은 생각이 필요한 까다로운 문제에 대응할 수 있도록 모델의 추론 강도 옵션에 max와 ultra 단계가 추가되어 충분한 추론 자원을 집중 투입할 수 있다. 경주용 차량의 세부 설정을 조율하면서 험난한 코스를 만났을 때 최고 출력 부스터를 켜는 일과 같다.

대화를 재개하거나 분기할 때 기존 권한 프로필을 복원한다

중단했던 대화를 다시 이어가거나 새 갈래로 분기할 때 기존에 설정해 둔 권한 규칙이 온전히 유지된다. 멈춰 둔 프로젝트를 다시 시작할 때 전용 출입증을 그대로 돌려받고 일반 방문자 기본값으로 조용히 밀려나지 않는 모습과 같다.스레드를 재개하거나 분기하면 당시에 쓰이던 permission profile(권한 프로필)을 그대로 복원한다. 시스템의 현재 기본 설정으로 말없이 되돌아가지 않는다. 이를 통해 특정 보안 등급에서 진행하던 작업의 안전 경계를 변함없이 지킬 수 있다.

서브 에이전트의 중복 동작을 바로잡고 알림과 승인 경로를 정비한다

메인 에이전트가 서브 에이전트를 불러 작업을 나눌 때 내부 소통과 일정 관리가 한층 깔끔해졌다. 예전에는 서브 에이전트가 동일한 동작을 중복으로 실행하거나, 알림과 승인 요청이 인터페이스 내에서 엉뚱하게 전달되곤 했다. 이번 수정으로 중복 실행을 바로잡고 서브 에이전트의 알림 및 승인 요청이 TUI에서 올바른 경로로 전달되도록 정비했다. 공항 관제탑이 도착 알림과 이륙 허가 요청을 올바른 무선 경로로 보내고, 같은 항공기에 이륙 지시를 두 번 내리지 않는 일과 같다.

WebRTC 연결이 끊겨도 대기 중인 출력을 빠뜨리지 않고 다시 연결한다

실시간 채널로 출력을 전달받을 때 일시적인 통신 끊김으로 데이터가 유실되지 않는다. 무전기가 터널을 지나며 잠시 끊겼다가 신호가 돌아왔을 때 밀려 있던 음성을 한 글자도 빠뜨리지 않고 재생해 주는 일과 같다.WebRTC(브라우저나 앱 간에 실시간 데이터 통신을 지원하는 규약) 사이드밴드 연결은 예상치 못한 전송 중단이 발생해도 자동으로 다시 연결된다. 재연결된 뒤 중단 중에 대기하던 출력 데이터를 버리지 않고 모두 보내주므로 응답 내용을 온전히 받아볼 수 있다.

Windows Terminal 스크롤백에 인라인 TUI 대화 기록을 보존한다

Windows Terminal(마이크로소프트의 터미널 프로그램)에서 Codex를 쓰는 사용자는 이전 대화 내용을 확인하기가 훨씬 편해졌다. 예전에는 인라인 TUI 모드로 작업할 때 터미널 자체의 스크롤백 영역에 기록이 남지 않곤 했다. 이제 인라인 TUI 기록이 Windows Terminal의 스크롤백에 온전히 유지된다. 마우스 휠을 위로 올리기만 하면 앞서 주고받은 코드와 답변을 언제든 다시 읽을 수 있다. 메모가 적힌 긴 두루마리를 위로 펼쳤을 때 이전 기록이 종이 위쪽에 고스란히 남아 있는 일과 같다.

비활성 스레드의 재생 버퍼를 제한해 메모리 낭비를 방지한다

백그라운드에 여러 작업을 띄워 두어도 이전 출력을 과도하게 쌓아두느라 메모리를 낭비하지 않는다. 보관 상자에 용량 상한을 두어 멈춰 둔 작업의 녹음 기록이 창고를 무작정 채우지 못하게 막는 일과 같다.비활성 TUI 스레드의 재생 버퍼에 명확한 크기 제한이 적용되었다. 이 제한 덕분에 쉬고 있는 세션이 대량의 스트리밍 출력을 메모리에 계속 붙잡고 있는 현상을 방지해, 여러 세션을 오래 켜두어도 자원을 아끼고 안정적으로 동작한다.

외부 기여는 PR에 앞서 issue와 설계 논의를 거치도록 안내한다

Codex 프로젝트에 코드를 기여하려는 개발자를 위해 협업 안내가 더 명확해졌다. 외부 기여는 곧바로 pull request(코드 병합 요청)를 올리기보다 먼저 issue를 열고 설계와 구현 방향에 대해 논의를 거쳐야 한다고 명시했다. 코드를 작성하기 전에 설계를 먼저 맞추면 헛수고를 피할 수 있다. 집을 고칠 때 벽을 허물고 공사부터 시작하기보다 건축가와 설계도를 먼저 상의하고 합의하는 일과 같다.

보안 개발 컨테이너의 DNS 유출 위험과 신뢰 한계를 문서화했다

보안 컨테이너 안에서 신뢰할 수 없는 코드를 실행할 때 참고할 수 있는 보안 지침이 문서에 상세히 추가되었다. secure devcontainer(격리된 환경을 제공하는 개발용 컨테이너)의 신뢰 한계가 구체적으로 설명되었다. 특히 도메인 주소 조회를 악용해 기밀 데이터를 몰래 빼돌리는 DNS 유출 위험을 짚고 있다. 이 문서는 컨테이너 격리 환경이라도 외부 네트워크 연결 정책을 꼼꼼히 점검해야 함을 일깨워 준다. 방음이 철저한 회의실이라도 외부로 편지를 자유롭게 부칠 수 있다면 봉투에 적힌 주소 조회만으로 비밀이 샐 수 있는 일과 같다.
