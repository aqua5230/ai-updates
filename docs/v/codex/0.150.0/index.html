發布日期：2026-08-26

zh-TW

支援 @ 引用其他任務，並可透過終端機由代理收發與建立任務

在終端機同時推進多項任務時，跨任務調度現在變得像通訊軟體一樣自然。宛如在專案群組裡直接 @ 任務看板，助理就能立刻去翻閱別組進度、建立新工單或遞送留言。你可以用 @ 標記其他 Codex 任務來直接引用其內容；也能在終端機中請代理（agent，自動替你執行任務的 AI 助手）讀取特定任務、建立新任務，或向進行中的任務傳送訊息。這讓多工協作時不必手動複製貼上歷史紀錄。

/copy 新增互動選單，可自選複製全文、獨立程式碼或引用區塊

想從長篇對話中抽出一小段程式碼或重點時，不用再拿滑鼠在終端機裡吃力選取。輸入 /copy 指令後，介面現在會跳出選擇清單。你可以自由挑選要複製整篇完整回覆、各個獨立的程式碼區塊，或是特定的引用區塊。這讓擷取內容變得更加精準俐落。好比便當盒裡將主菜、配菜與白飯各自獨立分格，你可以只夾取需要的那一道菜，不必整盒倒出來挑選。

未命名任務自動生成描述性標題，/rename 主動提供建議名稱

終端機裡開了一堆任務卻常分不清內容的問題，現在有了更省心的解法。如同圖書管理員看一眼未命名卷宗的內文就自動貼上書脊標籤，你要改名時還會主動遞上鉛筆草稿供你修改。未手動命名的終端機任務現在會根據對話自動獲得具描述性的標題；當你想重新命名時，輸入 /rename 指令也會依據當前對話主動建議一段可編輯的標題草稿。這讓你在任務清單中能一眼辨識目標，省去手動打字命名的繁瑣步驟。

終端機 Markdown 連結化身可點擊標籤，未支援環境完整保留網址

閱讀包含超連結的回覆時，終端機畫面變得更加乾淨易讀。在支援超連結的終端機環境下，Markdown 格式的連結會直接顯示為可點擊的簡潔文字標籤；而在不支援點擊的其他終端機中，系統則會完整保留原本可見的網址字串。這樣既能保持排版清爽，又確保在任何環境下都不會遺失網址資訊。正如互動螢幕上可直接點選關鍵字跳轉，而在紙本手冊上則完整印出網址，兼顧了便利與完整。

自訂快捷鍵可循環切換權限模式

你可以把循環切換權限模式的動作綁定到快捷鍵。權限模式（permission mode，決定系統在執行動作時如何處理確認的規則）會隨著這個按鍵依序切換。這像洗衣機的一顆模式旋鈕：每轉一下便換到下一種洗程；同一顆旋鈕只負責選洗程。當工作需要換一種確認方式時，使用你設定的快捷鍵，即可在可用的權限模式間循環切換；想再換一種就繼續按下去。

Vim 模式可用 `.` 重複上一個編輯

Vim 模式裡有多處要做同樣的文字修改時，現在按下 . 就能重複上一個編輯。Vim 模式（以鍵盤指令操作文字的編輯方式）會把剛完成的編輯動作交給 . 重新執行，不必再次逐字輸入相同變更。這像文書軟體的「重複上一個動作」按鈕：上一筆改字完成後，按它便再套用那筆修改；它不負責切換任何工作模式。這是 Vim 模式中的編輯重複功能。

新增 Interrupt 掛鉤，在頂層對話中斷時執行指令或 MCP 處理常式

任務執行途中突然按暫停時，後續的清理與自訂動作現在能自動接手。宛如工廠產線上的緊急停止按鈕，一拍下就會連帶觸發排氣閥與自動斷電程序，確保現場收拾乾淨。系統新增了 Interrupt hook（掛鉤，特定事件發生時被觸發的小程式）。當進行中的頂層對話輪次被中斷時，這項機制可以自動執行命令列指令，或呼叫 MCP（讓 AI 連接外部工具的協定）處理常式進行收尾。這讓中止操作不再只是粗暴中斷，而能妥善保存狀態或釋放佔用的資源。

未受信任專案禁止載入 AGENTS.md，權限變更後持續強制拒絕讀取規則

開啟來源不明的專案時，系統築起了更嚴密的安全防線。未受信任的專案不再能隨意提供專案層級的 AGENTS.md 指示檔，防止惡意專案藉由預先埋設的指令操控 AI 行為。此外，由管理政策所設定的拒絕讀取規則，在使用者中途變更權限後依然會強制生效，不會被意外覆蓋或失效。這確保了敏感檔案在整個操作過程中始終受到保護。正如訪客不能自帶自訂的進出規約交給警衛，且就算換發了臨時通行證，嚴禁閱覽機密檔案的禁令依然牢不可破。

強化診斷日誌敏感資料遮蔽，自動隱藏提供者、權杖更新與認證欄位

匯出診斷日誌排除故障時，機密資訊的外洩風險現在降得更低。系統強化了應用程式伺服器診斷報告中的 credential（登入憑證，證明身分與權限的密鑰資料）遮蔽處理。這次改進精確涵蓋了服務提供者、身分驗證更新以及 attestation（證明裝置與環境合法性的認證欄位）等關鍵資料。當你分享除錯診斷資訊時，這些敏感欄位會被自動遮蓋。恰如對外提供財務報表時，系統自動用黑筆塗掉身分證字號、刷新授權碼與防偽認證碼，確保隱私滴水不漏。

修復遠端 MCP 權杖查詢與必備伺服器啟動，並維持舊版相容性

連接遠端擴充工具時，驗證與啟動流程現在更加穩定順暢。好比連鎖店更新了專用通訊網路，既能精準辨識通行權杖並順利喚醒必備主機，同時依然相容舊款收銀終端機。系統修復了遠端 MCP（讓 AI 連接外部工具的協定）工具的連線問題。程式在查詢遠端 bearer token（驗證存取權限的授權令牌）時不再出錯，也修正了必要伺服器的啟動邏輯。整套調整完整維持了與舊版執行器的相容性，不必擔心升級後舊環境無法運作。

修復 Windows 高權限沙盒建立失敗，支援 Unicode 使用者路徑啟動別名

在 Windows 系統上使用特殊使用者名稱或高權限執行時，環境建立不再卡住。以前當使用者的個人資料夾路徑包含非英文字元（Unicode 字元，如中文或特殊符號）時，啟動別名常會失效。此外，在建立 elevated 管理員高權限沙盒環境時也會遭遇設定錯誤。現在這些路徑與權限問題都已修復，確保在各類系統設定下都能順利啟動隔離環境。就像印刷廠校正排版與裝機流程：標籤上有各種文字都能正確辨識，需要高規格設備的隔離作業區也能順利備妥。

防止 Unix 結束時因已脫離的行程佔用終端機或緩衝區塞滿而卡死

在 Unix 系統（如 macOS 或 Linux 等環境）結束程式時，不再因為背景殘留問題而卡死。以前當已脫離的行程依然佔用終端機，或者輸出緩衝區已被塞滿時，結束程式的流程常會陷入無限等待；現在系統會妥善清理這些狀態並順利退出。這讓每次離開工具時都能乾脆俐落。如同下班關閉辦公室總電源時，即便角落的碎紙機還插著電或出紙匣堆滿紙張，總開關也能順利切斷電源順暢關門。

修復 Amazon Bedrock 模型的對話壓縮錯誤與多代理協同相容性

透過雲端服務租用模型時，長對話與多任務協作變得更穩定。宛如跨國視訊會議的雲端秘書團隊，既能順利把冗長發言濃縮成精華摘要，多位專職助理在同一條線上協同分工時也不再斷線衝突。針對使用 Amazon Bedrock（亞馬遜雲端託管的 AI 模型平台）的使用者，系統修復了長對話的歷史壓縮錯誤；同時也解決了多代理協同作業時的相容性問題。這讓透過雲端模型處理複雜專案時更加流暢。

en

Reference tasks with @ mentions and manage tasks via terminal agents

When running multiple parallel tasks in the terminal, coordinating across workflows is now as natural as using team chat. It is like @-mentioning a project ticket in a group channel so an assistant can immediately inspect another team's progress, open a new task, or drop a memo. You can now use @ mentions to reference other Codex tasks directly in your prompt. You can also ask agents from the terminal to inspect existing tasks, spin up new ones, or dispatch messages to active tasks without manual copy-pasting.

/copy introduces an interactive picker for responses, code blocks, and quotes

When extracting a specific snippet or excerpt from a long reply, you no longer need to drag your mouse across terminal text. Running /copy now opens an interactive picker menu. You can explicitly choose between copying the full response, individual code blocks, or markdown blockquotes. It is like a bento box where main dishes, sides, and rice are neatly partitioned so you can pick out the exact portion you want without dumping the whole container.

Unnamed tasks get automatic titles and /rename suggests conversation-based edits

When juggling multiple background tasks in your terminal, identifying what each task is doing is now effortless. It is like a diligent librarian who glances at an unlabelled folder to affix a descriptive spine label, and offers a pencil draft when you ask to rename it. Unnamed terminal tasks now automatically receive descriptive titles based on context. Furthermore, running /rename inspects your conversation history and suggests an editable title proposal, saving you from having to type names manually.

Clickable Markdown link labels in supported terminals with URLs preserved elsewhere

Reviewing responses that contain hyperlinks is now much cleaner in your terminal. On supported terminals, Markdown links render as tidy, clickable text labels. In environments without hyperlink support, the full visible URLs remain intact so you can still read and copy them easily. It is like a modern touchscreen display where keywords are directly tap-friendly, while a printed guide still prints the full web address alongside them for completeness.

Custom shortcuts cycle permission modes

You can bind cycling through permission modes to a custom shortcut. A permission mode determines how Codex handles confirmation before an action, and the bound key moves through the available modes in sequence. It is like the program dial on a washing machine: each turn advances to the next wash cycle, and that dial has only one job—choosing a cycle. When your work calls for a different confirmation approach, press the shortcut you configured to cycle to it.

Vim mode uses `.` to repeat the last edit

When the same text change is needed in several places in Vim mode, pressing . now repeats your last edit. Vim mode is a keyboard-command way to edit text; . reruns the edit you just completed, so you do not need to type that same change again. It is like a word processor's Repeat Last Action button: after one edit, pressing it applies that edit again, and it does not switch any work mode. This is the editing-repeat feature for Vim mode.

New Interrupt hooks trigger commands or MCP handlers on cancelled turns

When cancelling an active turn midway, automated cleanup and custom actions can now take over immediately. It is like an emergency stop switch on an assembly line that instantly triggers exhaust vents and safe power-down sequences to keep the floor clean. Codex introduces Interrupt hooks. When an active top-level conversation turn is interrupted, these hooks can automatically run shell commands or trigger MCP handlers, allowing your environment to safely persist state or release held resources instead of abruptly terminating.

Block untrusted project AGENTS.md and preserve managed deny-read rules

Opening repositories from unknown sources is now significantly safer. Untrusted projects are no longer allowed to supply project-level AGENTS.md instruction files, preventing malicious repositories from hijacking AI behavior with embedded prompts. Additionally, managed deny-read security rules remain strictly enforced even after interactive permission changes occur during a session. It is like a visitor who cannot bring their own house rules to security, and even after receiving a temporary pass, confidential archive access remains firmly locked.

Enhanced credential redaction for provider, refresh, and attestation diagnostics

Exporting diagnostic reports for troubleshooting is now much safer. Codex has expanded credential redaction across app-server diagnostics. Sensitive data is now automatically masked across provider details, authentication refresh flows, and hardware attestation fields. When you share debug output with maintainers, secret tokens and verification payloads will never leak into log files. It is like preparing an audited statement where an automated marker blacks out personal IDs, refresh codes, and security stamp certificates before export.

Fix remote MCP bearer token lookup and startup while keeping executor compatibility

Connecting to remote tool extensions is now much more dependable. It is like a retail network upgrading its authentication lines to reliably verify access tokens and boot core servers, while remaining fully backwards-compatible with older register hardware. Codex has resolved issues with remote MCP server connections. The system now reliably looks up bearer tokens and initializes required servers without failure, all while maintaining full backwards compatibility with older executor environments.

Fix elevated Windows sandbox setup and launch aliases under Unicode paths

Running Codex on Windows with elevated permissions or special account names is now completely smooth. Previously, if a user profile folder contained non-ASCII Unicode characters (such as accents or non-Latin scripts), launch aliases would often fail. Elevated sandbox environments running with administrator privileges also encountered initialization errors. Both path handling and privilege escalation setups are now resolved. It is like a print shop tuning its typesetting and setup line: labels in different scripts are recognized correctly, and an isolated work bay needing high-spec equipment is prepared without a hitch.

Prevent Unix shutdown hangs caused by detached processes or full buffers

Exiting Codex on Unix systems like macOS or Linux is now fast and reliable. Previously, shutting down could hang indefinitely if detached background processes still held terminal handles or if output buffers were completely full. The shutdown sequence now cleans up detached processes and flushes full buffers properly. It is like locking up an office at the end of the day: even if a paper shredder in the corner is still plugged in or its output tray is full, the master switch reliably cuts power and lets you lock the doors.

Fix Amazon Bedrock conversation compaction and multi-agent compatibility

Running long conversations and multi-agent setups through cloud platforms is now much more reliable. It is like a remote conference team where an assistant cleanly summarizes lengthy meeting records while specialized specialists collaborate on the same call without stepping on each other. For developers using Amazon Bedrock models, Codex has fixed errors during conversation compaction when compressing long context windows. Multi-agent compatibility issues have also been resolved, allowing multiple sub-agents to collaborate smoothly.
