支援 @ 引用其他任務，並可透過終端機由代理收發與建立任務

在終端機同時推進多項任務時，跨任務調度現在變得像通訊軟體一樣自然。宛如在專案群組裡直接 @ 任務看板，助理就能立刻去翻閱別組進度、建立新工單或遞送留言。你可以用 @ 標記其他 Codex 任務來直接引用其內容；也能在終端機中請代理（agent，自動替你執行任務的 AI 助手）讀取特定任務、建立新任務，或向進行中的任務傳送訊息。這讓多工協作時不必手動複製貼上歷史紀錄。

/copy 新增互動選單，可自選複製全文、獨立程式碼或引用區塊

想從長篇對話中抽出一小段程式碼或重點時，不用再拿滑鼠在終端機裡吃力選取。輸入 /copy 指令後，介面現在會跳出選擇清單。你可以自由挑選要複製整篇完整回覆、各個獨立的程式碼區塊，或是特定的引用區塊。這讓擷取內容變得更加精準俐落。好比便當盒裡將主菜、配菜與白飯各自獨立分格，你可以只夾取需要的那一道菜，不必整盒倒出來挑選。

未命名任務自動生成描述性標題，/rename 主動提供建議名稱

終端機裡開了一堆任務卻常分不清內容的問題，現在有了更省心的解法。如同圖書管理員看一眼未命名卷宗的內文就自動貼上書脊標籤，你要改名時還會主動遞上鉛筆草稿供你修改。未手動命名的終端機任務現在會根據對話自動獲得具描述性的標題；當你想重新命名時，輸入 /rename 指令也會依據當前對話主動建議一段可編輯的標題草稿。這讓你在任務清單中能一眼辨識目標，省去手動打字命名的繁瑣步驟。

終端機 Markdown 連結化身可點擊標籤，未支援環境完整保留網址

閱讀包含超連結的回覆時，終端機畫面變得更加乾淨易讀。在支援超連結的終端機環境下，Markdown 格式的連結會直接顯示為可點擊的簡潔文字標籤；而在不支援點擊的其他終端機中，系統則會完整保留原本可見的網址字串。這樣既能保持排版清爽，又確保在任何環境下都不會遺失網址資訊。正如互動螢幕上可直接點選關鍵字跳轉，而在紙本手冊上則完整印出網址，兼顧了便利與完整。

自訂快捷鍵可循環切換權限模式

你可以把循環切換權限模式的動作綁定到快捷鍵。權限模式（permission mode，決定系統在執行動作時如何處理確認的規則）會隨著這個按鍵依序切換。這像洗衣機的一顆模式旋鈕：每轉一下便換到下一種洗程；同一顆旋鈕只負責選洗程。當工作需要換一種確認方式時，使用你設定的快捷鍵，即可在可用的權限模式間循環切換；想再換一種就繼續按下去。

Vim 模式可用 `.` 重複上一個編輯

Vim 模式裡有多處要做同樣的文字修改時，現在按下 . 就能重複上一個編輯。Vim 模式（以鍵盤指令操作文字的編輯方式）會把剛完成的編輯動作交給 . 重新執行，不必再次逐字輸入相同變更。這像文書軟體的「重複上一個動作」按鈕：上一筆改字完成後，按它便再套用那筆修改；它不負責切換任何工作模式。這是 Vim 模式中的編輯重複功能。

新增 Interrupt 掛鉤，在頂層對話中斷時執行指令或 MCP 處理常式

任務執行途中突然按暫停時，後續的清理與自訂動作現在能自動接手。宛如工廠產線上的緊急停止按鈕，一拍下就會連帶觸發排氣閥與自動斷電程序，確保現場收拾乾淨。系統新增了 Interrupt hook（掛鉤，特定事件發生時被觸發的小程式）。當進行中的頂層對話輪次被中斷時，這項機制可以自動執行命令列指令，或呼叫 MCP（讓 AI 連接外部工具的協定）處理常式進行收尾。這讓中止操作不再只是粗暴中斷，而能妥善保存狀態或釋放佔用的資源。

未受信任專案禁止載入 AGENTS.md，權限變更後持續強制拒絕讀取規則

開啟來源不明的專案時，系統築起了更嚴密的安全防線。未受信任的專案不再能隨意提供專案層級的 AGENTS.md 指示檔，防止惡意專案藉由預先埋設的指令操控 AI 行為。此外，由管理政策所設定的拒絕讀取規則，在使用者中途變更權限後依然會強制生效，不會被意外覆蓋或失效。這確保了敏感檔案在整個操作過程中始終受到保護。正如訪客不能自帶自訂的進出規約交給警衛，且就算換發了臨時通行證，嚴禁閱覽機密檔案的禁令依然牢不可破。

強化診斷日誌敏感資料遮蔽，自動隱藏提供者、權杖更新與認證欄位

匯出診斷日誌排除故障時，機密資訊的外洩風險現在降得更低。系統強化了應用程式伺服器診斷報告中的 credential（登入憑證，證明身分與權限的密鑰資料）遮蔽處理。這次改進精確涵蓋了服務提供者、身分驗證更新以及 attestation（證明裝置與環境合法性的認證欄位）等關鍵資料。當你分享除錯診斷資訊時，這些敏感欄位會被自動遮蓋。恰如對外提供財務報表時，系統自動用黑筆塗掉身分證字號、刷新授權碼與防偽認證碼，確保隱私滴水不漏。

修復遠端 MCP 權杖查詢與必備伺服器啟動，並維持舊版相容性

連接遠端擴充工具時，驗證與啟動流程現在更加穩定順暢。好比連鎖店更新了專用通訊網路，既能精準辨識通行權杖並順利喚醒必備主機，同時依然相容舊款收銀終端機。系統修復了遠端 MCP（讓 AI 連接外部工具的協定）工具的連線問題。程式在查詢遠端 bearer token（驗證存取權限的授權令牌）時不再出錯，也修正了必要伺服器的啟動邏輯。整套調整完整維持了與舊版執行器的相容性，不必擔心升級後舊環境無法運作。

修復 Windows 高權限沙盒建立失敗，支援 Unicode 使用者路徑啟動別名

在 Windows 系統上使用特殊使用者名稱或高權限執行時，環境建立不再卡住。以前當使用者的個人資料夾路徑包含非英文字元（Unicode 字元，如中文或特殊符號）時，啟動別名常會失效。此外，在建立 elevated 管理員高權限沙盒環境時也會遭遇設定錯誤。現在這些路徑與權限問題都已修復，確保在各類系統設定下都能順利啟動隔離環境。就像印刷廠校正排版與裝機流程：標籤上有各種文字都能正確辨識，需要高規格設備的隔離作業區也能順利備妥。

防止 Unix 結束時因已脫離的行程佔用終端機或緩衝區塞滿而卡死

在 Unix 系統（如 macOS 或 Linux 等環境）結束程式時，不再因為背景殘留問題而卡死。以前當已脫離的行程依然佔用終端機，或者輸出緩衝區已被塞滿時，結束程式的流程常會陷入無限等待；現在系統會妥善清理這些狀態並順利退出。這讓每次離開工具時都能乾脆俐落。如同下班關閉辦公室總電源時，即便角落的碎紙機還插著電或出紙匣堆滿紙張，總開關也能順利切斷電源順暢關門。

修復 Amazon Bedrock 模型的對話壓縮錯誤與多代理協同相容性

透過雲端服務租用模型時，長對話與多任務協作變得更穩定。宛如跨國視訊會議的雲端秘書團隊，既能順利把冗長發言濃縮成精華摘要，多位專職助理在同一條線上協同分工時也不再斷線衝突。針對使用 Amazon Bedrock（亞馬遜雲端託管的 AI 模型平台）的使用者，系統修復了長對話的歷史壓縮錯誤；同時也解決了多代理協同作業時的相容性問題。這讓透過雲端模型處理複雜專案時更加流暢。

Vim モードで `.` による直前の編集の繰り返しに対応

Vim モードで同じ文字修正を複数箇所に行いたいとき、. を押すと直前の編集を繰り返せるようになった。Vim モードはキーボードのコマンドで文字を編集する方式であり、. は完了したばかりの編集操作をもう一度実行する。文書作成ソフトの「直前の操作を繰り返す」ボタンのようなものだ。一度文字を直した後に押せば同じ修正を適用し、作業モードの切り替えは担当しない。これは Vim モードの編集反復機能である。

中断時にコマンドや MCP ハンドラを実行する Interrupt フックを追加

処理の実行中に停止操作を行った際、後処理や独自の後続処理を自動で走らせることが可能になった。工場の非常停止ボタンを押した瞬間に排気弁が開き、安全停止プログラムが連動して現場を整えるようなものだ。新たな Interrupt フックが追加された。実行中のトップレベル対話が中断された際、指定したシェルコマンドを実行したり、MCP（外部ツールと連携するためのプロトコル）のハンドラを呼び出したりできる。これにより、突然の処理停止時でも状態の保存やリソースの解放を安全に行える。

사용자 지정 단축키로 권한 모드를 순환 전환한다

권한 모드를 순서대로 바꾸는 동작을 원하는 단축키에 연결할 수 있다. 권한 모드는 작업을 실행하기 전에 확인을 어떻게 처리할지 정하는 설정이며, 연결한 키를 누르면 사용할 수 있는 모드를 차례로 이동한다. 세탁기의 코스 선택 다이얼과 같다. 한 번 돌릴 때마다 다음 세탁 코스로 넘어가며, 그 다이얼은 코스를 고르는 일만 맡는다.작업 중 확인 방식을 바꿔야 할 때 설정한 단축키로 전환하면 된다.

Vim 모드에서 `.`으로 직전 편집을 반복한다

Vim 모드에서 같은 글자 수정을 여러 곳에 해야 할 때 이제 .을 누르면 직전 편집을 반복한다. Vim 모드는 키보드 명령으로 글자를 편집하는 방식이며, .은 방금 끝낸 편집 동작을 다시 실행한다. 문서 편집기의 ‘직전 작업 반복’ 버튼과 같다. 한 번 글자를 고친 뒤 누르면 같은 수정을 다시 적용하며, 작업 모드를 바꾸는 일은 맡지 않는다.이는 Vim 모드의 편집 반복 기능이다.

대화 중단 시 명령어와 MCP 핸들러를 실행하는 Interrupt 훅을 추가했다

실행 중인 작업을 중간에 멈추었을 때 뒷정리와 추가 동작을 자동으로 이어받을 수 있게 되었다. 공장 생산 라인의 비상 정지 버튼을 누르면 환기 밸브가 열리고 안전 전원 차단 절차가 함께 작동해 현장을 정돈하는 모습과 같다.새로운 Interrupt 훅이 추가되었다. 진행 중인 최상위 대화 턴이 중단될 때 지정된 셸 명령어를 실행하거나 MCP(외부 도구를 연결하는 표준 규약) 핸들러를 호출할 수 있다. 작업이 갑자기 취소되더라도 상태를 안전하게 저장하고 점유 중인 자원을 정리한다.

신뢰할 수 없는 프로젝트의 AGENTS.md 적용을 차단하고 읽기 거부 규칙을 유지한다

출처가 불분명한 프로젝트를 열 때의 보안 경계가 한층 강화되었다. 신뢰할 수 없는 프로젝트에서는 프로젝트 단위의 AGENTS.md 지침 파일을 불러오지 않도록 차단하여, 저장소에 심어둔 악성 지시문으로 AI 동작을 가로채는 위험을 방지한다. 아울러 관리 정책으로 지정된 읽기 거부 규칙은 사용자가 중간에 권한을 변경하더라도 풀리지 않고 그대로 강제 적용된다. 방문자가 제멋대로 작성한 출입 규칙을 경비원에게 강요할 수 없으며, 임시 출입증을 새로 발급받더라도 기밀문서 열람 금지 구역에는 결코 들어갈 수 없는 일과 같다.

진단 로그의 기밀 가림 처리를 강화해 제공자와 갱신 및 인증 필드를 숨긴다

문제 해결을 위해 진단 로그를 추출할 때 기밀 정보가 밖으로 샐 위험이 크게 줄었다. 앱 서버 진단 출력에서 자격 증명(인증 정보와 접근 암호)에 대한 가림 처리를 한층 강화했다. 서비스 제공자 정보와 인증 갱신 내역, 기기의 정당성을 증명하는 attestation 필드 등의 민감한 정보가 자동으로 숨김 처리된다. 외부 제출용 서류를 뽑을 때 주민등록번호와 갱신용 인증 번호, 위변조 방지 인증 코드를 검은 마커로 꼼꼼히 칠해 가려주는 모습과 같다.

원격 MCP 토큰 조회와 필수 서버 실행을 수정하고 이전 실행기 호환성을 유지한다

원격 확장 도구에 연결할 때의 인증과 서버 구동 과정이 한결 안정적으로 개선되었다. 체인점의 통신망을 업그레이드하여 출입 허가증을 올바르게 인식하고 필수 서버를 켜면서도 구형 결제 단말기와 원활하게 호환되는 일과 같다.원격 MCP(외부 도구를 연결하는 표준 규약) 도구의 통신 오류를 바로잡았다. bearer token(접근 권한을 증명하는 인증 토큰)을 조회할 때 발생하던 문제를 해결하고 필수 서버의 부팅 절차를 정상화했다. 이번 수정은 구버전 실행기와의 호환성을 그대로 유지하도록 구성되었다.

Windows 고권한 샌드박스 설정 오류를 해결하고 유니코드 경로의 실행 별칭을 지원한다

Windows 환경에서 특수 계정명이나 관리자 권한으로 실행할 때 겪던 오류가 깔끔히 해결되었다. 사용자 폴더 경로에 비영문 유니코드(한글이나 특수 문자)가 들어 있으면 실행 별칭이 동작하지 않는 문제가 있었다. 아울러 관리자 권한으로 상승된 샌드박스 환경을 초기화할 때도 설정 오류가 발생하곤 했다. 이번 수정으로 경로 및 권한 처리 문제를 바로잡아 격리 환경을 매끄럽게 띄울 수 있다. 인쇄소가 조판과 설비 준비 과정을 조정해 여러 문자로 된 라벨도 올바르게 읽고, 고사양 장비가 필요한 격리 작업 구역도 문제없이 마련하는 모습과 같다.

백그라운드 프로세스나 버퍼 포화로 인한 Unix 종료 멈춤 현상을 방지한다

macOS나 Linux 같은 Unix 계열 환경에서 프로그램을 종료할 때 화면이 멈추는 일이 사라졌다. 백그라운드로 분리된 프로세스가 터미널을 계속 붙잡고 있거나 출력 버퍼가 가득 차 있으면 종료 절차가 무한 대기에 빠지곤 했다. 이제 비정상적인 상태를 말끔히 정리하고 빠르게 빠져나온다. 퇴근할 때 사무실 메인 전원을 내릴 때 구석의 파쇄기 플러그가 꽂혀 있고 용지함이 꽉 차 있어도 메인 차단기가 깔끔하게 전원을 끄고 문을 잠그는 일과 같다.

Amazon Bedrock 모델의 대화 압축 오류와 다중 에이전트 호환성을 해결했다

클라우드 서비스를 통해 모델을 쓸 때 긴 대화와 다중 작업 협업이 한층 안정적으로 개선되었다. 원격 화상 회의에서 비서 팀이 길어진 회의록을 핵심만 요약해 정리하면서 여러 전문 보조 인력이 같은 회선에서 충돌 없이 분업하는 모습과 같다.Amazon Bedrock(아마존의 클라우드 AI 플랫폼) 모델을 이용할 때 긴 대화 문맥을 압축하는 과정에서 발생하던 오류를 바로잡았다. 아울러 여러 에이전트가 협력해 작업할 때 생기던 호환성 문제도 해결되었다.
