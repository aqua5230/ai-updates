Codex 0.151.0

Released: 2026-08-29

Release notes

FEATURE

Add configurable grace period for optional MCP server tool discovery

It is like a meeting host giving remote guest speakers a brief grace period to join before moving on with the agenda.

When connecting to optional MCP (Model Context Protocol) servers, tool discovery will no longer fail immediately if an external tool takes a moment to respond.

Codex introduces a configurable grace period for discovering tools from optional MCP servers. This gives background or remote servers enough time to complete initialization and register their tools.

FEATURE

Extensions can inspect or replace MCP tool results before reaching the model

Developers who need to sanitize tool outputs or adjust formats can now intercept data directly in the pipeline.

Extensions can now inspect or replace MCP (Model Context Protocol) tool execution results before they are delivered to the model. This allows custom logic to filter out sensitive data or rewrite payload structures before the model processes them.

It is like a copy editor reviewing a reporter's draft before it heads to the printing press, ensuring all published material is properly checked.
FEATURE

Plugin catalogs combine repository configs and report invalid marketplaces

Managing plugin sources across projects is now much more reliable.

Plugin catalogs now combine per-repository configuration into their listings. Furthermore, when a project contains an invalid marketplace, the system reports the issue clearly without hiding the remaining valid plugins. You can troubleshoot broken marketplace links while continuing to use all working extensions.

a mall directory combining each shop’s details into one board, flagging one invalid listing while keeping the other shops visible.
FEATURE

Preserve restored permission profiles in TUI and prevent /cd sandbox weakening

It is like a building security badge that maintains your verified clearance across different floors, ensuring that stepping into an adjacent room never disables door locks.

Security consistency in the terminal interface is now reinforced.

Restored permission profiles are properly preserved across turns in the TUI (terminal user interface). Switching directories using the /cd command is strictly prevented from loosening or bypassing active sandbox restrictions, keeping execution boundaries intact.

FEATURE

Keep tool availability and reasoning effort correct across model switches and fallbacks

Switching models mid-task no longer disrupts tool setups or reasoning levels.

When you manually switch models or trigger a fallback to an alternative model, Codex now keeps tool availability and reasoning effort aligned with the target model. This prevents tools from vanishing unexpectedly and ensures reasoning parameters remain valid for the active provider.

It is like a pit crew changing a race car's tires while instantly recalibrating dashboard telemetry and suspension to match the new setup.
FEATURE

Improve remote sandbox enforcement using actual executor environment details

Running commands in remote environments now benefits from accurate isolation boundaries.

Remote sandbox enforcement now aligns with the executor's actual home directory, operating system, and path conventions. This eliminates authorization discrepancies caused by mismatched path separators, root structures, or platform conventions between local and remote hosts.

It is like a customs border checkpoint inspecting vehicles according to the destination country's road rules rather than the departure location's laws.
FEATURE

Preserve structured MCP tool and resource errors in app-server responses

It is like a medical lab report retaining specific diagnostic codes and reference ranges instead of printing a generic test failure message.

When external services encounter issues, app-server responses now preserve structured MCP (Model Context Protocol) tool and resource errors.

Rather than flattening error responses into plain text strings, the system keeps structured fields intact so client applications and developers can programmatically handle failures and identify root causes.

FEATURE

Count nested subagent token usage toward root goal budgets

Budget tracking across multi-agent workflows is now strictly enforced.

When a primary task delegates work to nested subagents across multiple tiers, token consumption from every child agent is counted toward the root goal budget. This prevents deep subagent branches from silently exceeding the project token allocation.

It is like a general contractor accounting for every subcontractor and specialist on a project, ensuring all labor hours bill against the master construction budget.
FEATURE

Prevent stale Guardian classifications from authorizing actions after permission changes

Security enforcement now reacts instantly whenever authorization rules change.

Previously cached classifications from Guardian (the security component that categorizes action risks) are no longer used after permission states change. The system invalidates stale classification data immediately upon permission updates, ensuring that outdated approvals cannot authorize new actions after permission state changes.

It is like a bank revoking outstanding pre-authorization holds the moment a credit limit is lowered, preventing old approvals from charging against the updated cap.
FEATURE

Add telemetry for escalated stdin reviews and remote executor MCP discovery

a maintenance recorder separately logging escalated stdin review events and MCP discovery events from remote executors.

Observability into security reviews and remote connections is now expanded.

Codex introduces dedicated telemetry tracking for escalated stdin reviews whenever interactive input requires elevated approval. It also logs remote executor MCP (Model Context Protocol) discovery events, giving maintainers clearer visibility into tool registration flows.

BUGFIX

Stabilize Guardian WebSocket and core fixture tests in slow or concurrent CI

Guardian WebSocket connections and core fixture tests now run reliably under high load or network latency.

Guardian WebSocket connections and core test fixtures have been hardened against timing issues. Even when test suites run on slow CI (continuous integration) runners or under heavy concurrency, core fixture tests complete predictably without false alarms.

It is like reinforcing a suspension bridge with dampers so that it stays completely stable through severe storms and rush hour traffic.
