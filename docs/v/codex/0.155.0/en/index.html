Codex 0.155.0

Released: 2026-09-17

Release notes

FEATURE

Experimental Voice Conversations Now Live with Real-Time Transcripts and Microphone Controls

Want to explain your requirements to the AI directly with your voice instead of constantly typing on a keyboard? Codex has introduced experimental /voice conversations on supported builds.

This is like equipping a walkie-talkie with a live subtitle screen and an audio input switch, where speaking immediately displays transcripts on-screen while allowing you to adjust recording states at any time.

You only need to type the /experimental command in a conversation to open the experimental features list and enable this mode. After entering a voice conversation, the terminal screen simultaneously displays live transcripts alongside dedicated microphone controls to toggle audio capture states, keeping spoken communication and written records in sync.

FEATURE

Status Row Displays Live Reasoning Summaries with Completion Timestamps

You no longer need to stare at a blank screen while waiting for the AI to reason about code architecture. The terminal UI status row now displays live reasoning summaries in real time, clearly showing the model's current thinking steps. Once a turn completes successfully, the screen also proactively displays a completion timestamp.

This is like the digital marquee at the front of a high-speed train carriage, showing upcoming stations and train status while in transit, then clearly displaying arrival times upon reaching the destination.

With this improvement, you can stay informed about ongoing computation progress and exact completion times.

FEATURE

Agents Overview Adds Task Hiding, Archiving, and Deletion with Worktree Ownership and Safe Cleanup

Managing multiple background agents and parallel branches is now much more organized. The agents overview page now supports hiding, archiving, and deleting tasks, making it easy to organize completed items or tasks you no longer need to track. In addition, the system includes worktree ownership details and supports confirmed deletion of clean managed worktrees without lingering modifications.

Just like a project manager organizing a Kanban board, you can hide, archive, or remove completed task notes, clearly see who is responsible for each extension workbench, and safely dismantle clean, idle desks.

This keeps parallel branches cleaner and safer when maintaining large projects.

FEATURE

MCP Supports Touch ID on Mac with Reconnect Guidance for Expired OAuth Credentials

Security verification is now faster and more streamlined when connecting external tools via the command line on macOS. On supported Mac models, local terminal UI sessions now support Touch ID verification for MCP (Model Context Protocol) operation requests. Meanwhile, when OAuth credentials on external MCP servers expire, the system accurately reports the error state. If token refresh fails, the interface proactively provides clear reconnection guidance to walk you through login verification.

This is like introducing dual-factor access control to a warehouse: local tool invocations are quickly granted with a fingerprint touch, and when an external contractor's pass expires, the system explains the issue and directs them to the renewal desk rather than abruptly cutting access.
FEATURE

Daemon Supports Configurable Update Schedules with Thread and Goal Recovery After Restarts

Background servers now offer more flexible updates and recovery resilience. You can configure automatic update schedules for the daemon or run codex app-server daemon update at any time to manually check and apply updates. Furthermore, even if the daemon restarts in the background, saved threads and active goals recover automatically without losing workflow context.

Like a 24/7 central HVAC system where building managers can schedule nighttime maintenance or perform manual upgrades, the system immediately restores temperature goals and operational logs across zones upon restarting without interrupting overall service.
FEATURE

Amazon Bedrock Supports Command-Based AWS Credentials with Caching and Auto-Refresh

Cloud credential management is now more automated when invoking models via Amazon Bedrock. The system can now execute configured custom commands directly to obtain AWS credentials and cache them for subsequent use. When credentials near expiration, background processes automatically refresh them based on their lifespan and initiate recovery procedures if authentication anomalies occur.

Like a hotel front desk requesting guest verification from headquarters, the system issues electronic keycards via specified commands, caches them for reuse, renews them before expiration, and retries upon swipe errors.

This eliminates the hassle of manually updating keys frequently.

BUGFIX

Accepted Prompts Preserved on Compaction Failures with Fixes for tmux Resizes and History Viewports

Text and screen states now remain stable during long conversations or frequent window switching. Even if history compaction fails before a turn begins, the system completely preserves accepted prompts to prevent lost input. Additionally, this update fixes missed tmux resize events, transcript viewport restoration issues, and stale history appearing after switching between threads.

Like a secretary's shorthand notebook and display board, new instructions are reliably recorded even if earlier summary compilations fail; when resizing panes or flipping between projects, the display precisely aligns with current progress without leaving outdated drafts from previous pages.
FEATURE

Automatic Approval Reviews Preserve Full Actions and Evidence with Retry Support and Clarified Risk Alerts

Automated review of elevated permissions is now more reliable and fault-tolerant. Automatic approval reviews preserve complete action steps and authorization evidence more reliably during evaluation, providing a solid audit trail. The review process automatically retries upon transient network or server failures, while clearly distinguishing review execution failures from unsafe-action findings to avoid misclassifying system anomalies as security threats.

Like an automated customs e-gate, it preserves full declaration forms and inspection evidence, retries automatically during brief sensor timeouts, and clearly distinguishes card reader network faults from passenger violations instead of mistaking hardware glitches for smuggling.
FEATURE

Account Switching Invalidates Previous Sessions While Clearing Connection Caches and Model Catalogs

Switching between user accounts on the same machine now completely clears sensitive connections and resources from the previous identity. Once account switching completes, the system immediately invalidates all remote-control sessions belonging to the prior identity and clears cached WebSocket connection state and model catalogs, ensuring complete isolation of permissions and data between accounts.

Just like shift workers sharing a workstation, logging out during handoff immediately severs prior remote sessions, clears cached connection states, and wipes access catalogs belonging to the previous employee to prevent identity crossover.
FEATURE

Blocks WSL Sandbox Escapes and Hardens Shell Snapshots Against Credential Leaks

Security safeguards are further enhanced when running scripts or commands in restricted environments. Codex successfully blocks escapes from restricted WSL sandboxes that attempt to launch Windows processes. Meanwhile, the system hardens brokered shell snapshots to prevent confidential credentials from leaking through environment snapshots.

Like building a protective barrier around an isolated lab chamber, it prevents internal programs from bypassing boundaries to the host operating system while locking down brokered shell snapshots to eliminate credential exposure.

This gives you greater peace of mind when testing untrusted code in isolated environments.

FEATURE

Python SDK and Runtime Align with Stable CLI Releases with Matching Versions and Pre-Validated Assets

Package versions and core tools now stay closely synchronized when invoking Codex services via Python. Publishing workflows for the Python SDK and runtime packages are now fully aligned with stable CLI releases, using matching version numbers across both. Before SDK publication, the system rigorously verifies required runtime assets to ensure a complete and ready environment.

Like launching a new product where accessories, software suites, and main hardware share matching release numbers while verifying core components before launch, this ensures an out-of-the-box experience without schedule mismatches.

This effectively prevents mismatched versions or missing asset issues.
