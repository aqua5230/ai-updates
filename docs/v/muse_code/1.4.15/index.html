Muse Code 1.4.15

發布日期：2026-11-13

Original changelog

`muse sessions --json` lists the sessions running on this machine, with who opened each one and whether it can be attached; `muse sessions --watch --json` keeps printing the list as sessions start and end
Several clients connected to the same session host can now drive one session together: each `session/resume` joins as a co-driver instead of refusing `sessionInUse`, submissions run one at a time in order (a busy submit queues unless it asks to steer or replace), and `driveHolder` names the earliest live driver
Send messages to running Muse sessions from the command line, including from the session itself
Session protocol serves `turn/modelAttemptStarted` each time a model attempt starts, before the provider is contacted, so apps can show the model as thinking only once it is working; in the TypeScript SDK, `ViewEvent` and `StaleDroppableMethod` gain `turn/modelAttemptStarted`, so code that matches them exhaustively needs a new case
`ItemKind` gains `subagentInput` — session-protocol clients get one item for each input a session sent to a subagent, when it was queued and when it was delivered, and a delivered subagent result names the row its Finished marker follows, so a client can show those rows in record order on resume
The agent now leaves a notice when it creates a goal or a cron job for you, and `/cron` lists and removes your scheduled jobs
The TypeScript and Python SDKs can now list a session's tasks, skills, and hooks, pause and resume workflows, request a recap, submit feedback, open a side chat, and search stored sessions without raw protocol calls
Session protocol reads of a forked session now report whether it came from a conversation rewind (`forkedFrom.isRewind`)
`muse attach --stdio <SESSION_ID> [-- <serve flags>]` connects a client's stdin and stdout to the host that holds a session, starting the session's own host with those serve flags when none does (except `--trust-workspace`, which a started host does not take), the same way locally and over ssh; it exits 4 when a TUI, `muse exec` or an older muse already holds the session
`muse serve --per-session` serves each connection from a fresh host of its own, which lists its sessions so another client can open and steer them with `muse attach --stdio <id>`; answers and notifications match plain `muse serve`, except that the host keeps running after your input ends (so no `session/closed` arrives) and its own diagnostics go to a log file instead of stderr; it does not take `--trust-workspace`
Settlement is refused only while a live driver holds the session: an attached observer's `turn/unqueue`, `approval/decide`, and `userInput/*` settlement refuse `sessionInUse` (naming how to join the drivers) while another live driver holds, and settle without taking drive once nobody drives, while observing prompts and replaying settled commands stay available
The TypeScript and Python SDK clients can send protocol commands the SDK does not wrap yet with `client.command`, which refuses the commands the SDK manages itself
`muse mcp list` and `muse mcp get` show configured MCP servers with their source, transport, and sign-in status
The TypeScript and Python SDKs can now run a turn in one call with `session.run`, which returns the final answer text, the turn's items, and its token usage, and stops the turn on an abort signal or task cancellation
`muse attach <session-ref>` opens this terminal attached to a session that is already running, as a second driver on the same timeline; unknown, ambiguous, not-running, and not-attachable references refuse with the reason and open no terminal
A client connected to `muse serve` over the session protocol can now list a session's subagents (running and finished) with ids, definition paths, parent, state, and result readiness, instead of parsing parent-stream child records
Sessions served by `muse serve` now remember the recovery mode a client picks when starting or resuming them, and reading a loaded session reports which mode is in effect and where it came from
Session protocol: a delivered subagent input item now carries `deliveredBeforeTurnEnd: true` when the subagent took that input before its parent's turn ended, so a client resuming the session can tell an interrupted turn from a finished one
`muse mcp add` and `muse mcp add-json` save MCP servers to user settings or the project file
`muse mcp remove` deletes MCP servers from user settings or the project file
When a command asks to run outside the sandbox, its approval prompt now offers "Always allow outside the sandbox in this workspace" for that command, so later runs of it there skip the prompt; an older Muse version can't resume a session that showed this choice until it updates
A session's peer-message history index is now a file inside the session folder, so a session folder copied to another machine resumes without rebuilding it
`muse serve` clients can run one model completion with no session, cancel it, and get its text, stop reason, model and token counts
A session protocol `subagent` item now names the subagent whose own session spawned it (`parentSubagentId`), so a client can file a nested subagent under its parent instead of under the root session
After a plan, the reply now says in plain words that nothing has changed yet and that you can reply `go` to start or say what to adjust
Clarified instructions for reading prior reports in Workflow children
Read long text lines in full when they fit the output limit, with byte-range guidance for larger lines
On `muse serve --listen`, only the client driving a session can change its approval mode or permission profile; other connected clients get `drive_required` and can take the drive with `session/resume` once the driving client disconnects
Workflows can read complete results from finished workers
The resume picker preview of a long, compacted chat shows its recent conversation, the same history you see after resuming
Compaction checkpoints keep answered questions and approval choices in a smaller form that holds no answer text; chats whose checkpoint holds one require a compatible app update, and older versions cannot open them
When Esc pauses a goal, the pause notice now stands out, the status bar and one reminder after your next message name `/goal resume`, and `/goal` lists the commands you can use
`/hud` can show the current session ID in the bottom status bar, the same ID `/status` reports
Paging back through a compacted chat over the session protocol now ends at one earlier-conversation item, as reading the chat does, and an older cursor before it answers that the view was truncated
`/feedback` uses the compressed upload that keeps sessions of up to about 760 MiB from the first launch, without waiting for Muse Code to fetch its remote settings
Incoming session messages now reach the client when the session protocol client is on: pending queue rows show the sender, effect label, and body, and delivered messages appear in the transcript, matching the classic client
In the `muse serve` session protocol, a finished workflow now lists its agents in the workflow's own order rather than the order they started, so every client numbers them the same way
Session protocol now streams the model's narration between tool calls as it is written, like final answers; saved chats do not change, so older versions still open them
The resume picker's comfortable view (`ctrl+o`) now explains why workspace status is unavailable — whether the workspace is not trusted, the probe sandbox is unavailable, or the status check failed — instead of silently omitting it; the default dense view is unchanged
Session protocol now marks a streaming message as narration or as the answer from its first word, so clients can show narration as narration while it is written; clients that ignore the mark see no change
The TypeScript and Python SDKs find `muse` on `PATH` when you do not pass a host path to `spawn`, and say what they searched when no host is found
Confirming a conversation rewind now shows "Preparing rewind…" right away, and the action rows stop showing a selection, so it is clear the rewind is underway before the server answers
When a waiting background notice keeps being refused its wake-up, the saved session now notes which hold refused it, so a stalled helper can be traced; an older Muse build cannot open a session holding this note, so update the app to open it (other sessions are unaffected)
Muse Code no longer updates a shared task (its status, plan, or fields) just because the task's own text or agent hints tell agents to; it does the work you asked for, then offers the update and waits for your yes
When you ask Muse Code to empty a directory or clean up files, its final answer now names what it removed and flags anything that looked unrelated to the task, such as another repository or a symlink into one
The TypeScript and Python SDK quickstart and cookbook recipes now teach the high-level client (`MuseClient.spawn`, `startSession`, `session.run`, `turn.cancel()`, `setModel`, `listModels`) instead of raw session protocol calls
A resumed chat whose saved view is damaged heals it from the log; a forked chat, which is not rebuilt, reports `projectionRebuildFailed` right away; health frames coalesce so the client sees the final state once
A loaded chat whose live view fails closed is re-loaded once from its log (weak registry hold, no reopen); a failed re-load announces `projectionRebuildFailed` once
After a `healthy` view-health signal, the client re-reads the view and adopts the turn state, skipping rows it already rendered
When the agent reads an image file, it now also sees the image's width and height in pixels, plus the original size when the image was scaled down, so positions it gives in pixels match the image
When you ask Muse Code to empty a directory or clean up files, it now lists what is there first, deletes what belongs to the task, and asks before deleting anything that looks unrelated, such as another repository, a symlink into one, or data; without your answer it keeps those items and says so
Bug fixes now get a focused failing test for each reported defect, and the regression test also covers the inputs the fix claims to handle beyond the reported one (another position or order, extreme or boundary values, and input rules the request restates), still without new test frameworks or extra full-suite runs
When you tell Muse Code about something the repository cannot show, such as a migration or a deployment that already happened, it now works from what you said, updates repository defaults that still point at the old setup, and remembers it in later turns instead of asking you to repeat it
Session discovery now lists up to 128 local and Claude sessions, up from 64; each machine still makes at most 64 of its live sessions discoverable until a later release raises that limit
Automatic Windows sandbox setup at startup now first explains the two local Windows accounts it creates or updates and what each one runs, then asks Yes or No; No exits without changing anything
When the only thing left is a background job the agent started, the turn now ends instead of the agent polling it; the job's completion or stuck-job notice wakes the agent to finish
When an answer compares many items on short numbers, such as estimates for several funds under several scenarios, Muse can now show them in one wider table that still fits a normal terminal instead of splitting them into narrow tables
The terminal UI now switches between light and dark themes when your terminal does, while a session is running, in terminals that report it (such as Ghostty, kitty and Contour), unless you set a fixed light or dark terminal background in `/theme`
Saved chats can now record that an approval is still being applied, so it settles exactly once after a restart; earlier versions can't open a chat that holds this record, and updating fixes it
When you ask whether something already built behaves correctly, the agent now checks each observation against the source the project follows, fixes only what is wrong, and keeps behavior that is correct, explaining why instead of removing it
When you ask for a 3D web page and the machine has no browser, Muse now installs a headless browser with the system package manager to check the page itself, and says plainly that the page was not run only if that install fails
When the agent reads a file with Windows (CRLF) line endings, it is told so, which makes it less likely to switch the line endings when it rewrites the file
On Windows, the agent is guided to write PowerShell commands such as `Select-String` and `$env:NAME = ...` instead of Unix commands such as `grep` and `export`, which PowerShell does not have
Muse Code keeps closely linked facts in one sentence, so fix and build summaries read as connected sentences instead of one fact per line
While a goal waits on something outside the session that ends at a known time, such as a soak or a cooldown, the agent schedules a one-time wake-up for just after that time instead of only snoozing
Saved chats can now record that the 3D generation service accepted a job, so its job ID is not lost if the call is stopped; earlier versions can't open a chat that holds this record, and updating fixes it
Resuming a session over the session protocol with a `modelId` now records that model the way `muse resume --model` does, and a model the host refuses keeps the session on its saved model instead of failing the resume
MCP servers and hooks now get your proxy settings (`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` and `NO_PROXY`), as other apps do
When more skills are installed than the skills catalog can list, built-in and prompt-named skills keep their full descriptions first and more of the other skills are left out to make room
A Muse build older than this release cannot open a chat in which a newer build resumed the session automatically after a crash and told the agent what was interrupted. Updating the app fixes it; other chats are unaffected
When you ask for a 3D web page in a sentence or two, Muse now checks it in one light pass (a desktop run, one input test, a fix and a final run) instead of its full review rounds, so short requests finish sooner; detailed briefs still get every check
Usage telemetry now trusts the certificate authority file set in `telemetry.ca_bundle`, so it keeps working on networks that re-sign TLS traffic with a company root certificate
Session-protocol clients: view cursors are now minted in the `v9:` spelling; a cursor in an older spelling is refused once with the standard "reopen without a cursor" guidance, and a view cache saved by an older build is rebuilt on first use, so no client silently skips or misreads events
When `muse serve` refuses a request to interrupt, stop, resume, reopen or close a subagent, the refusal now names the exact reason (for example `owner_not_running` or `attempt_history_unavailable`) instead of one general reason
A resumed session's snapshot now carries each Monitor's recent output lines, including the ones already delivered to the model, so a client shows the Monitor's tail right after resuming instead of an empty one
Muse follows your requests more closely: it answers a direct question first, keeps working when you send a question or remark mid-task, does not stop while a change you asked for is still unmade, asks its remaining questions before building on a partial answer, removes extras instead of hiding them when you ask it to simplify, asks you at once when a login only you can renew blocks the task, and no longer works around a download the environment blocks or a package index that fails its certificate check
Muse Spark 1.3 at `max` reasoning effort now gets the same full base instructions as every other model and effort, including the newer answer-style and grounding guidance
Through `muse serve` and the SDKs, stopping a subagent that has already stopped now answers `subagent_already_stopped` instead of `subagent_state_ineligible`, so a client can tell that race from a failed stop
Over the session protocol, a refusal caused by a session log deleted or replaced outside Muse now carries the error reason `session_log_lost` when resuming, sending or steering a message, compacting, renaming, forking, opening a side chat, leaving, controlling a subagent or workflow, or choosing an approval that saves something for later, so a client can recognize it without matching the message
Security: In `muse serve`, subagents and workflow agents now use the same approval mode as the session that started them, so an allow-all session no longer prompts for its subagents and a deny-unmatched session's workflow agents deny instead of asking
Security: Sessions in workspaces the user has not trusted no longer start any MCP servers. Startup withholds every configured server, shows one notice naming the withheld count and reason (project-scope servers are withheld unread, without being listed), and `/mcp` marks each knowable withheld server as "withheld: workspace untrusted". Trusting the workspace starts them on the next session
Security: Sandboxed Linux commands can no longer redirect their own approved network connections to a different local service than the one you approved
Security: A `!` shell command run in a session that `muse serve` hosts can no longer write the folders where Muse keeps its client credentials and settings
Security: In an untrusted workspace, the agent now asks for approval before writing to memory, showing what it wants to save, instead of running silently
Security: Sandboxed Linux commands can no longer redirect another concurrent command's approved network connections to a different local service than the one you approved
Security: A Meta API key after `Bearer` or `Authorization: token`, such as in a printed `curl -H` command or a provider error, is now hidden whole from the model, session logs and error output
Security: When a command running in the sandbox asks to reach a new host, Muse now asks for your approval before looking the hostname up, so a declined host is not looked up; only `localhost` names are still looked up first, to confirm they point at this computer, and a hostname that does not exist now also asks for approval before it fails
Security: A tool call's `shell` argument can now select only bash, zsh or sh (PowerShell or pwsh on Windows); any other value runs the default shell, so an approved command always runs under a shell you expect
Security: On Linux, sandboxed commands and file tools can no longer read sign-in details or settings in `~/.config/muse` and the other settings folders through a second mount of the same filesystem, such as WSL's `/mnt/wslg/distro` or a home folder bind-mounted at a second path; on such a computer a subagent started before updating can lose its work tools when it continues after `/resume`, and a command that walks that second mount reports the settings folders inside it as unreadable
Security: Muse no longer trusts its local session registry folder, or the startup folder of a session's own host, when it sits inside a folder another local user owns; that user could swap in folders of their own, and on a shared Mac change what is inside through folder settings
Security: A session's own host no longer starts through a folder link that another local user owns, even one reached through another link, since they could swap the link and move the host's files
Security: When your data folder's path is too long for its own socket, `muse attach --stdio` and `muse serve --per-session` now start their host under `/tmp/tbh-<uid>-rt` only when that folder is yours, mode 0700, and not a link (they create it when it is missing); otherwise they stop with an error that says how to fix it
Security: `/feedback` now removes more kinds of secrets, such as passwords in connection strings, authorization headers, JWTs and common API key formats, from your note, the recent activity, crash reports, the screen snapshot and the configuration snapshot before upload. Text that follows a secret-looking label, such as `token:` or `password:`, is hidden too, so a note titled "Auth token: refresh loop" is filed as "Auth token: [REDACTED]"
Security: A host that `muse attach --stdio` or `muse serve --per-session` starts now refuses a startup file that something changed after it was written, so another session cannot alter what the host starts with
