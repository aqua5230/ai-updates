Muse Code 1.4.19

Released: 2026-11-21

Release notes

BUGFIX

Claude models can now read images directly

Pasting a screenshot of a report to ask Claude to check the numbers used to fail the entire turn as soon as you sent it. Now Claude models properly receive images from these sources, including images you attach directly, images a tool reads, and existing images inside a resumed session, without interrupting the turn.

Picture bringing an on-site photo to ask a repair technician for help: before, he would reject the whole job as soon as he saw a picture, whereas now he can look at the photo and handle it as usual whether you brought it, an assistant found it, or it was tucked inside an old record.
FEATURE

SDK clients can now receive notifications and disconnect events

For developers integrating the TypeScript and Python SDK (the developer interface for external programs to call this tool), writing code often means tracking messages and connection status from the tool. Now clients can receive every notification, rejected messages, and connection closing events.

FEATURE

More complete session protocol and muse serve control

When connecting an external program to the backend to control tasks, deep background commands used to be impossible to stop, or pausing midway still required waiting for the whole turn to finish. Through the session protocol, a parent session can now stop background commands started by a subagent (an assistant spawned by the main task to work separately) at any depth below it, no longer limited to the direct level. When sending a start request to muse serve, you can now attach a flag to treat the new session as a /clear reset so that SessionStart hooks (small programs triggered when specific events happen) receive the clear source notice. When a goal's turn is still running, a pause or clear command sent through muse serve now goes straight into that turn. The model then stops working on that goal instead of continuing until the turn ends.

FEATURE

Linux sandbox keeps rules for uncreated protected folders

When running commands in a Linux sandbox (an isolated environment that keeps commands from altering files freely), deny rules inside a protected location such as .git still remain even if that folder has not been created yet. This holds even when another sandboxed command in the same workspace cannot see the first one's sandbox records, for example because the two use different runtime directories.

Think of an empty lot in a neighborhood where a utility room has not been built yet: the guard on duty still keeps the no-entry rule for the reserved site, and even if another guard cannot see that guard's patrol log, the rule still holds.
BUGFIX

Invalid single key in tui.keymap no longer resets other shortcuts

When keybinding settings copied across versions include an action that the current build does not have, starting up used to wipe the entire custom key configuration back to defaults. Now, if tui.keymap has a key that maps to no action at startup, the app skips only that key and pops up a notice naming it, while keeping all other custom keys.

Imagine a remote control with an extra button saved for a feature this TV does not have: before, all personal settings on the remote would reset to zero, whereas now that single button is left alone and a sign lights up to show which one it is.
BUGFIX

Fix search tool not finding files by name

When calling the search tool to find files with a specific name, it used to return no results and show only an empty response. That issue is now fixed, and searching for files by name properly lists the matching files.

BUGFIX

muse exec now states the reason when a persistent watch is refused or stopped

After muse exec has already given an answer, trying to open a persistent Monitor (a background watching process) used to start it once and immediately stop it. Now that attempt is refused directly with a reason instead of starting and stopping again. And for a persistent watch closed when a run ends, the stop notice now also states why it stopped.

A diner tries to add an order after the restaurant has closed and cleared the tables: before, the server would take the ticket and immediately send it back, whereas now the request is politely refused on the spot with an explanation, and the closing notice at the end of service also states clearly why orders stopped.
FEATURE

Bundled Linux sandbox reports environment errors when unable to start commands

When preparing to run a command on Linux and even the first step fails to start, a clear prompt is what you need most. When the bundled sandbox cannot start a command, it now directly reports an environment error.

FEATURE

Long sessions and multi-subagent runs use less memory

When many subagents have been opened in the same conversation, memory no longer keeps as many copies of each subagent's start record. Long sessions with many tool steps also use less memory, because watching a task or a run for new records no longer reserves room for a thousand records in advance. Long sessions after conversation compaction (condensing earlier chat messages to free up space) also use less memory, because the subagent view no longer keeps every earlier event.
