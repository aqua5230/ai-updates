Muse Code 1.4.25

發布日期：2026-11-24

繁體中文

新功能

Muse Code 能從圖片生出 3D 模型檔

手上有張產品草圖或物品照片，想轉成 3D 檔案放進簡報或網站卻不會建模嗎？只要你的帳號方案包含 3D 生成功能，現在直接拿一張圖片請 Muse Code 幫忙做 3D 模型，它就會幫你生出 GLB、FBX 或 USDZ 格式的檔案。

就像把物品正面照片交給翻模師傅，不用自己學雕刻工具，師傅就能直接按照片做出立體模型交給你。
問題修復

模型短暫斷線時對話會倒數等候不直接結束

跑工作階段正順手，最怕模型突然短暫連線中斷、整個回合直接卡斷。現在遇到這種短暫斷線時，工作階段不會立刻結束回合，畫面上會出現清楚的倒數計時，撐過這段斷線後繼續往下跑。

好比通話途中車子剛好開進隧道，現在不會立刻掛斷電話，而是先告訴你剩幾秒恢復，出了隧道就接著講。
問題修復

中文或程式碼長對話會在爆窗前及時壓縮

貼進大段程式碼或中日韓文字聊長對話時，工作階段以前容易在還沒觸發壓縮前，就先撞上模型的上下文視窗上限。原因是在沒有提供代管網頁搜尋的請求裡，工作階段會丟棄供應商回報的實際提示長度。現在這項數值不再被丟棄，密集內容的工作階段就能趕在爆窗前完成壓縮。

換成裝箱寄貨時，箱裡早放滿鐵塊，以前店員沒看磅秤就硬塞到撐破，現在會先看準重量提早換大箱。
問題修復

遠端橋接裝置不再取得主機殼層或全開權限

從另一台裝置透過信箱或遠端附加連進來操作時，安全性邊界現在收得更緊。透過這兩種方式橋接進來的裝置，不再能於主機上取得殼層操作權限，也不會拿到 allowAll 權限的工作階段。至於本機端原本的用戶端行為則完全維持不變。

彷彿把營業窗口跟後廚隔開，外部跑腿人員只能在窗口交接，走不進放著爐火與廚具的廚房；店內員工則照常進出。
問題修復

從他處搬移 MCP 伺服器保留環境變數參照

打算把原本在 Claude Code 或 Codex 設定好的 MCP（讓 AI 連接外部工具的協定）伺服器搬來用嗎？以前搬移時遇到 ${VAR} 這類變數參照，代理不是直接略過該伺服器，就是要求你貼上真實密鑰。現在搬移過程會直接把 env、url 和標頭裡的 ${VAR} 參照原封不動留著。

跟搬家時只抄下「水電費自動扣款帳號代號」一樣，不用把銀行卡密碼抄在紙上交給別人，新家照樣能按代號扣款。
問題修復

用規劃技能寫設計文件改為每輪問一題

跟 AI 一起草擬方案，連續被追問往往讓人不知道先答哪個。現在用規劃技能寫設計文件，代理同一輪只會提出一個開放問題，不像以前一次最多問三題。

問題修復

技能開關改用名稱儲存並補強路徑與警告

想固定技能的開關狀態，或自己寫了一份跟內建同名的技能嗎？ 切換開關後，內建技能存為 bundled:<id>，外掛技能存為 plugin:<plugin>:<skill>，並清掉舊設定項目。搬動檔案仍有效；舊版會忽略這類開關。 內建技能路徑改為 bundled://skills/<name>/SKILL.md，不再列出內部套件名；舊的 bundled://muse-core/... 路徑與設定鍵仍可用。 muse exec 啟動時，若你的技能與內建同名，會提醒並附上 bundled:<name> 代碼供開啟內建版。 Windows 專案或使用者 SKILL.md 過大時，警告會列出實際超出容量，不再固定寫超出 1 位元組。

問題修復

外掛獨立開關、異常停用與拒絕內建規則

想單獨關掉內建功能，卻擔心設定出錯或撤銷不掉嗎？ python-env 與 guidance-match-requested-length 已拆為內建外掛，可用 plugins.activation 各自關閉。停用 muse-core 仍關閉兩者，自裝外掛不得用這兩代號。 讀不到設定檔時，外掛在當次執行一律停用，除非專案設定檔點名開啟，避免 hook（事件觸發的小程式）與連線伺服器意外啟動。 已安裝外掛的技能宣告 replaces，警告會點名外掛與該欄位，並忽略該欄位。 用 muse plugins reject 撤銷 foreign-script-guard 等編進執行檔的外掛，若無項可撤銷，會以 builtin-plugin-not-revocable 拒絕，並點名停用開關與環境變數；muse-core 仍報 0 筆成功。

問題修復

Three.js 與 3D 技能不再推薦舊陰影類型

內建的 Three.js 與 3D 視覺技能以前在建立立體場景會推薦一種現行 Three.js 已經棄用的陰影貼圖類型，導致主控台跳出警告。這兩項技能已經更新，現在不會再推薦該舊類型，做出來的場景既能保留柔和陰影，主控台也不會再出現這類警告。

問題修復

恢復工作階段時補齊狀態說明並重啟 MCP

開著多個視窗或曾啟動失敗的舊對話，現在用恢復指令更容易接續。 執行 /resume 列出紀錄時，若有些工作階段正開在另一個 Muse 行程裡而被略過，現在會直接顯示略過了幾個。就算只剩這類工作階段，也不會再誤報 No saved sessions found。 用 muse resume 恢復在啟動階段就中斷的工作階段時，如果當時沒有對話遺失，它現在會直接說明這一點，不再只回報沒有存下紀錄。 先前行程若在 MCP 伺服器啟動到一半時結束，現在恢復該工作階段時會重新啟動那些伺服器，不再讓 MCP 保持停用、進而在有必備伺服器時拒絕執行回合。

問題修復

對話壓縮與重開後保留資料並消除誤報

把長對話壓縮或是關掉工作階段重新開啟後，狀態顯示與資料保留都已經修好。 壓縮時若遇到附帶影片的長訊息，完整文字現在會比照一般長訊息存下來。標註檔名的那一行也會像處理圖片那樣，寫明影片本身沒有被保存。 恢復已完成壓縮的工作階段時，旁邊不再誤出現 runtime closed before context compaction completed 錯誤列。 重新開啟已經壓縮完畢的工作階段時，畫面也不再誤顯示上下文壓縮未完成的訊息。 壓縮工作階段、離開再重新打開後，/workflows 清單裡仍會保留原本的工作流名稱、階段計畫與代理列，不再變成空白。

新功能

背景指令的輸出讀取與引用預覽不再混雜

回頭翻閱背景指令留下的紀錄，指令本文與輸出現在不會混在一起。 即使背景指令一併存下了完整的執行指令，現在依然能正常讀到它另外存下來的輸出內容。 背景指令文字裡原本的引用參考行，現在會完整保留下來不被清掉。 重新接回舊工作階段時，背景指令的預覽內容會把引用的錯誤細節排除在外；較舊的工作階段在協定中也不再把指令文字標成完整的工具輸出。

問題修復

背景指令結束後會補送通知與最終摘要

背景指令已經跑完，你不用再擔心模型漏接結束消息或交出空白結尾。 當背景指令結束後，若把完成通知寫進工作階段時曾失敗一次，下次報告時這則通知依然會送達模型；以前一旦存檔失敗，模型就永遠不會知道指令已經結束。 若背景指令在該回合結束後才完成，而且代理對結果的回覆剛好是空的，它現在會補寫一段簡短的最終摘要，不再毫無回應就結束。

像請同事去列印大批文件，就算第一次沒交回條或忘記在群組留言，下次匯報時進度單照樣會補交到桌上，最後也會附上一句結果說明，不會石沉大海。
問題修復

子代理訊息排隊、背景喚醒與最新回覆修復

交辦給子代理的任務在傳訊、壓縮或重開工作階段後，現在都能正常接上進度。 代理替子代理把訊息排進佇列時，工具結果現在只會說明訊息已排隊，不再顯示容易讓代理誤認成訊息編號的內部追蹤號。 設有目標時，子代理被自身背景工作喚醒並進行壓縮時，不會再存下損壞的檢查點，免得工作階段讀不到子代理或讓 exec 報錯結束。 有後續追問的子代理壓縮自身紀錄並重開工作階段後，讀取結果會回傳最新回答，不再誤判為過期；較早版本存下的工作階段仍會顯示過期。

問題修復

手動停止的子代理一律改為顯示 stopped

在系統裡中斷分派出去的任務後，回頭檢查 /subagents 清單與詳情頁，以前卻會看到令人疑惑的 cancelled 字樣。現在無論是一般或巢狀子代理，只要是由你親手停掉，兩處畫面都會改為顯示 stopped，與實際的工作狀態一致。

問題修復

Shell 指令啟動失敗提醒與結束清理更明確

在 Linux 上，沙盒若因資料夾位置被空檔案（如 ~/.config）佔住而失敗，錯誤會點名該檔案，並提示等其他沙盒指令都結束後刪除重跑。 未安裝 zsh 等原因導致指令無法啟動時，錯誤訊息會直接指出失敗的程式與資料夾，不再只顯示 No such file or directory。 按下 Esc 中斷或逾時後，若無法確認處理程序是否結束，指令仍顯示取消或逾時，另外附上清理未確認的訊息 cleanup not confirmed: <reason>，讓你和模型知道衍生程式可能還在跑。 在 Windows 退出 tbh 或結束 tbh exec 時，未開沙盒的 PowerShell 背景工作階段啟動的程式也會一併結束，不再留在背景。這與 macOS、Linux 原本的處理一致。

問題修復

關閉沙盒時的起始權限提示改寫為使用者範圍

關掉 Shell 沙盒時，工作階段一開始顯示的權限說明以前會寫成指令可以修改主機上的任何檔案。現在這段文字改得更準確，只會說明指令能修改目前這位使用者在這台主機任何位置有權寫入的檔案。

問題修復

修正任務列多餘標籤與工具重試標記

在終端機觀察執行進度或下載檔案時，畫面上終於不會再出現讓人誤判的殘留文字或錯誤圖示。 指令只印出一行空白行時，任務列不會再多出孤零零的 output: 或 status: 字樣。 用 web_fetch 存下 PDF 這類二進位檔案時，回傳結果不再提到這個工具並不接受的提示詞。 被修正並重試的呼叫若重試成功，畫面會改為顯示成功標記；要是重試後的指令本身依然失敗，則會保留失敗標記。

問題修復

Windows 乾淨 worktree 結束後會正確清除

在 Windows 用 --worktree create 建立乾淨的 worktree（讓同一專案平行開多份副本的功能）時，工作階段結束後原本應該自動清掉。但以前清理常會因為 Permission denied 失敗，導致這個工作區被留在原地。這個問題已經修好，現在這類乾淨的工作區會在工作階段結束時正確移除。

問題修復

停寫紀錄時不再新增指定空目錄與離開紀錄

你加上 --no-session-log 跑完後，以前資料夾裡還是會多出幾個用不到的項目。 在 Linux 或 macOS 終端機或執行 exec 時加上這個參數，不會再於資料夾裡建出空的 session-server 和 runtime 資料夾。 用 tbh serve（含 --listen 模式）搭配 --no-session-log 啟動時，不會再把 serve-exit.jsonl 寫進資料夾。它仍會在標準錯誤輸出印出離開原因。

就像退租時說好不留任何雜物，以前房客走後桌上還是會擺幾個空紙箱和一張退房單，現在房間裡乾乾淨淨，只剩門口口頭交代一句離開原因。
問題修復

muse serve 模型判定與目標排程工具啟動

透過 muse serve 提供的工作階段，在模型判斷與啟動檢查上現在更貼近終端機介面。 挑選審核批示用的模型時，muse serve 現在會比照終端機介面從工作階段本身與模型目錄來選，不再一律拿主機的預設模型來審核。 搭配 Meta 模型與模型清單讀取時，muse serve 會按啟動時使用的模型視窗來回報上下文用量（清單沒列出的模型也算），不再誤用預設模型視窗或乾脆不回報。 若 muse serve 工作階段的工具清單指定了內建的目標或排程工具（如 report_progress 或 cron_list），現在能正常啟動，不會再報未知工具名稱錯誤。

問題修復

回溯忙碌的工作階段不會再無限期枯等

想從某個工作階段倒帶回溯時，如果來源工作階段當時太忙、騰不出手來處理，以前畫面會一直乾等下去。這個問題已經修好，現在只要超過請求逾時時間就會直接回報失敗，不會再無止境卡住。

問題修復

正式版不再誤套測試設定而暫停寫入紀錄

在正式發行的軟體版本中，以前若不慎繼承到開發時的實驗參數，程式可能會假裝磁碟空間已滿，或是突然停止記錄工作階段歷史。這項異常已經修復，正式發行版不會再被這些測試設定影響。

問題修復

協定開發者：壓縮後可正確呈現巢狀子代理

給串接工作階段協定的開發者：經過壓縮的工作階段在讀取或恢復後，被裁減的子代理資料現在更能還原階層與狀態。 在壓縮過的工作階段回傳裡，被裁減的子代理會帶上已知的自身識別碼；若是巢狀子代理，已知的父代理識別碼也會附上，讓用戶端能將它排在父代理底下。 當工作階段經過第二次壓縮後，在兩次壓縮之間就已完成的子代理會正確標為已完成，不再誤顯示為執行中。跨越壓縮分界才記錄到啟動的已完成子代理也會被保留，並同樣帶出巢狀子代理的父代關聯。

跟把厚厚的會議紀錄一再濃縮一樣，雖然內文變精簡了，外包團隊的完工狀態與上下級隸屬關係仍會清楚附在後面，不會讓人分不清誰歸誰管。
新功能

協定開發者：分支參數、目標時間與回合數更新

給串接工作階段協定的開發者：工作階段的分支、目標通知與回合統計欄位都有補充。 建立工作階段分支時，現在比照啟動與恢復工作階段，可以傳入新工作階段的模型與設定（屬實驗性欄位）。若模型遭拒或有設定未套用，回應裡也會分別附上拒絕說明與警告訊息。 代理透過目標工具修改目標後，收到的目標變更通知現在會一併帶上該目標的建立時間與更新時間。 列出、讀取或恢復工作階段時，回傳的回合總數現在會把每一輪都算進去，包含失敗的回合、被打斷且撤回的回合，以及仍在執行中的回合。

問題修復

協定開發者：工作區開新工作階段減少掃描外掛

給串接協定的開發者：當專案裡裝了大量擴充套件，每次建立新對話的等待時間現在可以縮短了。系統在整理指示時不再多跑一輪檢查，整體啟動流程少掃描一次已安裝外掛，工作階段能更快進入就緒狀態。

English

FEATURE

Muse Code can generate 3D model files from images

Have a product sketch or photo of an object you want as a 3D file for a slide deck or website, without knowing how to model? As long as your account plan includes 3D generation, you can now hand Muse Code an image and ask for a 3D model, and it will generate a GLB, FBX, or USDZ file for you.

Picture handing a front-facing photo of an object to a mold maker: instead of learning sculpting tools yourself, they build the 3D model straight from the photo and hand it back.
BUGFIX

Sessions wait with a countdown during brief model outages

When a session is running smoothly, nothing disrupts the flow like a brief model connection drop cutting off the whole turn. Now, during a brief outage like that, the session does not end the turn right away; instead, a clear countdown appears on screen so it can ride out the drop and keep going.

Think of driving into a tunnel mid-call: instead of hanging up immediately, the call tells you how many seconds remain until the signal returns and picks right back up once you exit.
BUGFIX

Long code or CJK sessions now compact before overflowing

When pasting large blocks of code or CJK text into a long session, the session previously tended to hit the model's context window limit before compaction could trigger. That happened because, in requests that offered no hosted web search, the session discarded the actual prompt size reported by the provider. Now that value is kept, so sessions with dense content can compact before overflowing the window.

A shipping clerk packing a box full of iron blocks used to keep stuffing until the box burst without checking the scale, whereas now they check the weight first and switch to a larger box in time.
BUGFIX

Remotely bridged devices no longer get a host shell or full permissions

When you connect from another device through the mailbox or remote attach, the security boundary is now tighter. Devices bridged in through either method can no longer get shell access on the host or receive an allowAll session. Local clients, meanwhile, keep their existing behavior unchanged.

Imagine separating a service counter from the back kitchen: outside couriers can only hand items over at the counter and cannot walk into the kitchen with its stoves and utensils, while in-house staff come and go as usual.
BUGFIX

Migrating MCP servers keeps environment variable references intact

Planning to bring over MCP (a protocol that lets AI connect to external tools) servers you already configured in Claude Code or Codex? Previously, when a migration ran into variable references like ${VAR}, the agent either skipped that server or asked you to paste the actual secret. Now the migration leaves ${VAR} references in env, url, and header values intact.

Moving into a new home works the same way if you only write down your utility autopay account code instead of handing someone your bank PIN on paper, so billing still goes through by code at the new place.
BUGFIX

Planning a design doc with the plan skill asks one question per turn

Drafting a proposal with AI can leave you unsure which question to answer first when several arrive at once. Now, when writing a design doc with the plan skill, the agent asks only one open question per turn instead of up to three at a time.

BUGFIX

Skill toggles save by name with cleaner paths and warnings

Want to keep a skill's toggle state consistent, or wrote your own skill with the same name as a built-in one? When you toggle a skill, built-in skills are saved as bundled:<id> and plugin skills as plugin:<plugin>:<skill>, clearing out older entries. Moving the files still works; older versions ignore switches saved this way. Built-in skill paths now use bundled://skills/<name>/SKILL.md instead of naming an internal package; old bundled://muse-core/... paths and settings keys still work. When muse exec starts up and your skill shares a name with a built-in one, it warns you and includes the bundled:<name> ID so you can still open the built-in version. On Windows, when a project or user SKILL.md is too large, the warning now reports how much it actually exceeds the limit instead of always saying 1 byte over.

BUGFIX

Separate plugin toggles, safe fallback, and built-in rejection rules

Want to turn off individual built-in features without worrying about broken settings or unrevocable plugins? python-env and guidance-match-requested-length are now split into separate built-in plugins that you can disable individually via plugins.activation. Turning off muse-core still disables both, and self-installed plugins cannot use either ID. When the settings file cannot be read, plugins stay disabled for that run unless a project settings file enables them by name, preventing hooks (small programs triggered by events) and connected servers from starting unexpectedly. If an installed plugin's skill declares replaces, a warning names both the plugin and that field, and the field is ignored. When you run muse plugins reject on a binary-compiled plugin like foreign-script-guard with nothing to revoke, it now refuses with builtin-plugin-not-revocable and names the disable switch and environment variable; muse-core still reports 0 items succeeded.

BUGFIX

Three.js and 3D skills drop deprecated shadow-map type

The built-in Three.js and 3D visuals skills previously recommended a shadow-map type for 3D scenes that current Three.js has deprecated, triggering console warnings. Both skills have been updated and no longer recommend that old type, so generated scenes keep soft shadows without those console warnings.

BUGFIX

Session resume clarifies status and restarts MCP servers

Older conversations left open across multiple windows or interrupted during startup are now easier to pick up with resume commands. When /resume lists saved logs and skips sessions that are currently open in another Muse process, it now reports how many were skipped. Even if only those sessions exist, it no longer falsely reports No saved sessions found. When muse resume restores a session that stopped during startup and no conversation was lost, it now states that directly instead of only reporting that no log was saved. If the previous process ended while MCP servers were still starting up, resuming that session now restarts those servers instead of leaving MCP disabled and refusing turns when a server is required.

BUGFIX

Data retention and false-error fixes after compaction and session reopening

Status display and data retention are now fixed after compacting a long conversation or closing and reopening a session. When a long message with an attached video is compacted, its full text is now saved just like any other long message. The line that names the file also notes that the video itself was not saved, matching how images are handled. Resuming a session that has already finished compaction no longer shows a false runtime closed before context compaction completed error row beside it. Reopening a session whose compaction has already finished no longer falsely shows a message saying context compaction did not complete. After compacting a session, quitting, and reopening it, /workflows still keeps the original workflow names, phase plan, and agent rows instead of turning into an empty list.

FEATURE

Cleaner output reading and quoted previews for background commands

When you look back at records left by background commands, the command text and its output no longer get mixed together. Even when a background command also saves the full command that was run, its separately saved output can still be read normally. Quoted reference lines in background command text are now preserved in full instead of being stripped out. When reconnecting to an older session, background command previews leave out quoted error details; older sessions also no longer mark command text as full tool output in the session protocol.

BUGFIX

Guaranteed completion notices and final summaries for background commands

Once a background command finishes, you no longer have to worry about the model missing the completion notice or ending with a blank reply. When a background command finishes and saving its completion notice to the session fails once, the notice still reaches the model on the next report; previously, if saving failed, the model would never know the command had ended. If a background command finishes after the turn ends and the agent's reply to the result happens to be empty, it now writes a short final summary instead of ending with no response.

Asking a colleague to print a large batch of documents works the same way: even if they miss handing in the slip the first time or forget to post in the group chat, the progress sheet still lands on your desk at the next check-in, and a brief note on the result is included at the end instead of vanishing without a trace.
BUGFIX

Fixes for subagent message queuing, background wakeups, and latest replies

Tasks delegated to a subagent can now pick up cleanly after messaging, compaction, or reopening a session. When an agent queues a message for a subagent, the tool result now only states that the message was queued and no longer shows an internal tracking number that the agent could mistake for a message ID. When a goal is set, a subagent woken by its own background work and performing compaction no longer saves a broken checkpoint, preventing the session from failing to read the subagent or causing exec to exit with an error. After a subagent with follow-up questions compacts its own history and the session is reopened, reading its result now returns the latest answer instead of falsely marking it as out of date; sessions saved by earlier versions still show as out of date.

BUGFIX

Manually stopped subagents now consistently show stopped

After stopping a delegated task in the system, checking the /subagents list and detail view used to show a confusing cancelled label. Now, whether it is a regular or nested subagent, as long as you stopped it yourself, both views display stopped to match its actual work status.

BUGFIX

Clearer shell startup failure alerts and exit cleanup

On Linux, if the sandbox fails because an empty file such as ~/.config is occupying a needed directory path, the error names that file and tells you to delete it and rerun once all other sandboxed commands have finished. When a command fails to start because zsh is not installed or for similar reasons, the error message now points directly to the failing program and folder instead of only showing No such file or directory. After interrupting with Esc or hitting a timeout, if it cannot be confirmed that the processes have ended, the command still shows as cancelled or timed out and adds cleanup not confirmed: <reason>, letting you and the model know spawned programs may still be running. On Windows, quitting tbh or finishing tbh exec now also terminates programs started by an unsandboxed PowerShell background session instead of leaving them in the background. This matches how macOS and Linux already behave.

BUGFIX

Startup permission note scoped to current user when sandbox is off

When the shell sandbox is turned off, the permission note shown at the start of a session used to state that commands could modify any file on the host. That text is now more accurate, stating only that commands can modify files that the current user has permission to write anywhere on this host.

BUGFIX

Fixes for stray task row labels and tool retry marks

When watching execution progress or downloading files in the terminal, misleading leftover text and wrong icons no longer appear on screen. When a command prints only a blank line, task rows no longer show a stray output: or status: label. When using web_fetch to save a binary file such as a PDF, the returned result no longer mentions a prompt that the tool does not accept. If a corrected and retried call succeeds on retry, the UI switches to a success mark; if the retried command itself still fails, it keeps the failure mark.

BUGFIX

Clean worktrees on Windows now remove properly on exit

On Windows, when creating a clean worktree (a feature that lets you open multiple parallel copies of the same project) with --worktree create, it is supposed to be cleaned up automatically after the session ends. Previously, cleanup often failed with Permission denied, leaving the workspace behind. That issue is now fixed, and clean workspaces like this are properly removed when the session ends.

BUGFIX

No extra empty folders or exit records when session logging is off

After running with --no-session-log, a few unused items used to still show up in your folder. Adding this flag in the Linux or macOS terminal or when running exec no longer creates empty session-server and runtime folders in that directory. When starting tbh serve with --no-session-log, including --listen mode, serve-exit.jsonl is no longer written to the folder. It still prints the exit reason to standard error.

When a tenant moves out after agreeing to leave nothing behind, there used to still be a few empty cardboard boxes and a checkout slip left on the table; now the room is completely empty, with only a quick spoken note at the door explaining why they left.
BUGFIX

muse serve Model Selection and Goal and Cron Tool Startup

Sessions served through muse serve now match the terminal interface more closely for model selection and startup checks. When picking a model for approval reviews, muse serve now selects from the session itself and the model catalog just like the terminal interface, instead of always using the host's default model. When working with a Meta model and reading a model list, muse serve reports context usage against the context window of the model it starts with (including models not on the list), rather than falling back to the default model's window or reporting nothing. If a muse serve session's tool list specifies a built-in goal or cron tool (such as report_progress or cron_list), it now starts normally instead of failing with an unknown tool names error.

BUGFIX

Rewinding a Busy Session No Longer Waits Indefinitely

Previously, when rewinding from a session that was too busy to handle the request, the interface would wait indefinitely. This is now fixed so it fails once the request timeout is reached instead of hanging forever.

BUGFIX

Release Builds No Longer Pause History Writes From Test Settings

In release builds, inheriting experimental development settings by mistake could previously cause the app to simulate a full disk or stop recording session history. This issue is now fixed so release builds are no longer affected by those test settings.

BUGFIX

Protocol Developers: Nested Subagents Display Properly After Compaction

For developers integrating the session protocol: after reading or resuming a compacted session, pruned subagent data now better restores hierarchy and status. In responses for compacted sessions, a pruned subagent now includes its own ID when known, and for a nested subagent, its parent subagent ID is also included when known so clients can display it under its parent. When a session goes through a second compaction, subagents that finished between the two compactions are now accurately marked as finished rather than shown as running. Finished subagents whose spawn was recorded across the compaction boundary are also preserved, along with parent links for nested subagents.

Much like condensing thick meeting minutes over and over, even though the main text gets shorter, the completion status and reporting hierarchy of outsourced teams stay clearly attached at the end so no one loses track of who reports to whom.
FEATURE

Protocol Developers: Fork Parameters, Goal Timestamps, and Turn Counts

For developers integrating the session protocol: session forking, goal notifications, and turn count fields have all been expanded. When forking a session, you can now pass the new session's model and configuration just like when starting or resuming a session (experimental fields). If the model is refused or any settings are not applied, the response also includes a refusal explanation and warning messages. After an agent modifies a goal through goal tools, the goal-changed notification now also includes that goal's created and updated times. When listing, reading, or resuming a session, the returned total turn count now includes every turn, including failed turns, interrupted and withdrawn turns, and turns still running.

BUGFIX

Protocol Developers: Fewer Plugin Scans When Starting Workspace Sessions

For developers integrating the protocol: when a project has many extensions installed, the wait time when starting a new conversation is now shorter. The system no longer runs an extra check while resolving instructions, so the overall startup flow scans installed plugins one time fewer and the session becomes ready sooner.
