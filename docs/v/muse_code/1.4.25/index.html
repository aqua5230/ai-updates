Muse Code 1.4.25

發布日期：2026-11-24

Original changelog

On a compacted `session/read` or `session/resume`, a `prunedSubagents` entry now carries the subagent's own `subagentId` and, for a nested subagent, its parent's `parentSubagentId` when they are known, so a client can show a pruned nested subagent under its parent
`session/fork` takes the new session's `modelId` and `config` like `session/start` and `session/resume`, reports a refused model in `modelIdRefusal` and unapplied settings in `warnings` (experimental members)
When your account includes 3D generation, ask for a 3D model and Muse Code makes a GLB, FBX or USDZ file from an image
With the shell sandbox off, the session-start permission note now says a command can change any file this user can write, anywhere on this host, instead of claiming it can change any file on the host
Turning a skill on or off now saves it in settings under the skill's name (`bundled:<id>` for a built-in skill, `plugin:<plugin>:<skill>` for a plugin skill) and removes that skill's older entries, so the setting keeps working when a skill's files move; an older version ignores switches saved this way
An installed plugin that declares `replaces` on a skill entry now gets a warning naming the plugin and the field, and the field is ignored
The `session/goalChanged` notification now carries the goal's created and updated times after the agent's goal tools change it
`/resume` says how many sessions open in another Muse process it left out, and no longer reports "No saved sessions found" when those are the only ones
Built-in skills show as `bundled://skills/<name>/SKILL.md` instead of naming an internal package; old `bundled://muse-core/...` paths and settings keys keep working
The Python environment skill and the guidance that keeps a requested short answer short are now built-in plugins of their own, `python-env` and `guidance-match-requested-length`, so `plugins.activation` can turn each off by itself; settings that turn `muse-core` off still turn them off, and a plugin you install can no longer take either id
Read saved output of a background command even when its full command is also saved
On Linux, when a sandboxed shell command cannot start because an empty file such as `~/.config` sits where a directory is needed, the error now names that file and says to remove it and run the command again once no sandboxed command is running
Preserve quoted reference lines in background command text
When a long message with a video attached is shortened at compaction, its full text is now saved like any other long message, and the line naming the file says the video was not saved, as it already did for images
Task rows no longer show a stray output: or status: word when a command printed only a blank line
When the settings file cannot be read, plugins are switched off for that run unless a project settings file turns them on by name, so plugins you turned off cannot come back on with their hooks and connected servers
When moving MCP servers over from Claude Code or Codex, the agent now keeps `${VAR}` references in `env`, `url`, and header values instead of leaving the server out or asking you to paste the secret
When a shell command cannot start, for example because `zsh` is not installed, the error now names the program and folder that failed instead of only "No such file or directory"
The bundled Three.js and 3D visuals skills no longer recommend a shadow-map type that current three.js has deprecated, so scenes built from them keep soft shadows without a console warning
Inherited test settings no longer simulate a full disk or pause session history writes in release builds
On Windows, a clean `--worktree create` session worktree is now removed when the session ends instead of being kept after a "Permission denied" cleanup failure
On Linux or macOS, `--no-session-log` in the terminal or `exec` no longer creates empty `session-server` and `runtime` folders in your data folder
When a background command finishes after the turn ends and the agent's reply to its result is empty, the agent now writes a short final summary instead of ending with no answer
When the agent plans a design doc with the plan skill, it asks one open question per turn instead of up to three at once
When the agent queues a message for a subagent, the tool result now says the message was queued for the subagent instead of naming an internal tracking number the agent could mistake for the message's id
When `web_fetch` saves a binary file such as a PDF, its result no longer mentions a prompt the tool does not take
`muse exec` now also says at startup when your own user or project skill has the same name as a built-in skill, and shows the `bundled:<name>` id that still opens the built-in
When a goal is set, a subagent woken by its own background work no longer saves a broken checkpoint as it compacts, which could stop the session from reading the subagent and end an `exec` run with an error
Sessions now ride out a brief model outage inside the turn with a visible countdown instead of ending the turn
After a session is compacted a second time, the `prunedSubagents` list on `session/read` and `session/resume` shows a subagent that finished between the two compactions as finished instead of running, keeps a finished subagent whose spawn was recorded across the cut, and lists the parent of a pruned nested subagent so the nested subagent shows under it
Sessions served by `muse serve` now pick the approval reviewer's model as the TUI does, from the session's model and the model catalog, instead of always reviewing on the host's default model
On Windows, a too-large project or user `SKILL.md` warning now says how far over the limit the file really is, instead of always one byte over
A corrected call shows the success mark when its retry succeeded, and keeps the failure mark when the retried command itself failed
When you stop a shell command (Esc, or it hits its time limit) and its processes cannot be confirmed to have ended, the command still shows as cancelled or timed out, and now also shows `cleanup not confirmed: <reason>`, so you and the model know something it started may still be running
A resumed session whose compaction completed no longer shows a false "runtime closed before context compaction completed" error row beside it
`session/list`, `session/read` and `session/resume` count every turn of a session in `turnCount`, including a turn that failed, one that was interrupted and withdrawn, and one still running
`muse resume` explains when a session stopped during startup and no conversation was lost, instead of only reporting that no log was saved
A rewind no longer waits forever when the session it starts from is too busy to take it; it now fails after the request timeout
In `/subagents` and the subagent detail view, a subagent you stopped now reads `stopped` instead of `cancelled`, matching its work status
Older sessions no longer advertise command text as full tool output in the session protocol
With a Meta model and a model list to read, `muse serve` reports context usage against the window of the model it starts with, including a model the list does not show, instead of the default model's window or none
In `/subagents`, a nested subagent you stopped now reads `stopped` instead of `cancelled`, matching its work status
Reopening a session no longer says context compaction failed to complete when it finished
A `tbh serve` host started with `--no-session-log`, including `--listen`, no longer writes its exit record (`serve-exit.jsonl`) into your data folder; it still prints why it exited on stderr
On Windows, quitting tbh or finishing `tbh exec` now also ends the programs a background PowerShell session started (run without the sandbox), as it already did on macOS and Linux, instead of leaving them running
`muse plugins reject` on a plugin compiled into the binary (such as `foreign-script-guard`) with nothing to revoke now refuses (JSON error code `builtin-plugin-not-revocable`) and names the product gate and the environment variable that switch it off, instead of printing a count-0 rejection that changed nothing; bundled plugins such as `muse-core` keep the count-0 success
When a background command finishes and saving its completion notice to the session fails once, the notice now reaches the model on the next report; before, the model was never told the command had ended
Resuming a session whose earlier process ended while its MCP servers were starting now starts them again, instead of leaving MCP disabled and refusing turns when a server is required
After a subagent with follow-ups compacts its own history and the session is reopened, reading that subagent's result now returns its latest answer instead of saying the result is out of date; sessions saved by earlier versions still say it is out of date
Keep quoted error details out of resumed background command previews
`muse serve` sessions whose `run.toolset` names a goal or cron tool the session provides, such as `report_progress` or `cron_list`, now start instead of failing with an unknown tool names error
Long sessions with dense content, such as code or CJK text, now compact before they overflow the model's context window. The session no longer discards the provider's reported prompt size when the request offered no hosted web search
A device bridged in over the mailbox or remote attach no longer gets a shell or an `allowAll` session on the host; local clients are unchanged
After compacting, quitting and reopening a session, its Workflows stay listed in `/workflows` with their names, phase plan and agent rows instead of an empty list
A session started over the session protocol in a workspace scans the installed plugins one time fewer, so it is ready sooner when many plugins are installed
A new session started over the session protocol in a workspace no longer scans the installed plugins again just to resolve its developer instructions, so it is ready sooner when many plugins are installed
