Muse Code 1.4.22

Released: 2026-11-21

Release notes

BUGFIX

Auto-review no longer saves a separate conversation log

Sessions now take up less disk space. Auto-review no longer saves the reviewer's own conversation as a separate log file. If you want to go back and check how the review made its judgment, you can keep the log by adding this setting to settings.json:

{
  "approval_judge": {
    "child_session_log": "retained"
  }
}

Think of getting dental X-rays: previously the clinic always printed the assistant's verification draft for you to take home, whereas now it skips printing by default unless you ask for a copy.
FEATURE

Untrusted folders now show when project MCP tools are not loaded

When you take over an unfamiliar project folder from someone else and run a command, the tools configured inside may sit completely idle. In an untrusted folder, project MCP (a protocol that lets AI connect to external tools) servers defined in .mcp.json are not loaded by default. Now when you run muse exec, it directly tells you that these project servers were not loaded and how to load them. Running muse mcp list to inspect the list also explains why they were not loaded and how to load them.

Picture opening a spreadsheet sent by a new acquaintance: previously clicking its macro buttons did nothing at all, whereas now a banner pops up at the top explaining why it was blocked and where to click to enable it.
BUGFIX

Side chats opened via the service or SDKs start empty

When you want to branch off into a side topic mid-conversation, opening one used to bring along the entire preceding thread. New side chats opened through muse serve or the TypeScript and Python SDKs (developer toolkits) now start empty instead of showing the content of the original conversation. However, side chats that were already open before this update are unaffected and still show the original conversation turns; as long as they remain open, the session list still counts those turns.

When you step into a breakout room for a private chat mid-discussion, the walls used to be covered with everything just said in the main hall, but now there is a clean whiteboard inside, while rooms opened before the update stay as they were.
BUGFIX

New sessions stop with an error if the log cannot be written

Right after starting a new session and sending your first message, the worst surprise is having the model start running while the log file fails to save. Now, if the session log cannot write this first model request, the turn stops immediately with a retryable storage error instead of calling the model. Once the write succeeds, the request is saved to the log.

At a recording studio starting a new show, the guest used to begin speaking before the tape was even rolling, whereas now the mic only turns on once the recorder confirms it can write—if it cannot, the session pauses and lets you retry.
BUGFIX

Reading and resuming long sessions saves resources and retrieves records

Reading files and continuing conversations in long sessions used to consume extra resources due to repeated reads and copying. For developers integrating with the interface, reading or resuming a long session now requires less processing when requesting only metadata (information describing the session, without conversation content). If the saved history exceeds the read limit, instead of returning only an over-limit result, it can now retrieve pending requests and the last turn. For a session that has never been compacted, reading it again right after resuming no longer reads the entire log file from the start; it only reads what the resume step added. Resuming a long session without a saved checkpoint (a save point that records progress) also uses less memory during startup, because the starting records are no longer copied once for each part that reads them.

BUGFIX

Fix restarting a session dropping the last turn

When the most recent message happens to repeat the instructions or rules of an earlier, finished turn, restarting the session used to drop this final turn completely. This issue has been fixed, so restarting the session now preserves the turn instead of discarding it.

BUGFIX

Fix cancelling a workflow misreporting child tasks as killed

After manually stopping a run midway, the list shows the background jobs that were stopped along with it. Previously, the reported results mistakenly listed a child task's own task as one of that child's killed background tasks. This issue has been fixed, so cancelling a workflow no longer produces this false report.

BUGFIX

Fix Linux sandboxed commands leaving empty placeholder folders

Opening a project directory on Linux would occasionally reveal an unexplained empty placeholder folder. This happened when a sandbox (an isolated, secure environment) command lost its placeholder bookkeeping, leaving the empty folder behind even after the command sharing it had finished. This issue has been fixed, so no empty placeholder folder remains once the command sharing it ends.
