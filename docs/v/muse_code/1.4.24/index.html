Muse Code 1.4.24

發布日期：2026-11-21

Original changelog

`exec --list-models` prints the model IDs your provider offers, one per line, so a mistyped `--model` is recoverable without leaving the terminal
A slow MCP tool call can move to the background with Ctrl+B or when you send another message, and its result joins the conversation when it finishes
The skill and verify reminders are now off by default, so turns end without the verify check's wait and sessions spend fewer tokens on skill suggestions. Turn either back on in `/plugins` or by setting `plugins.skill-reminder.enabled` or `plugins.verify-reminder.enabled` to `true` in `settings.json`
Long command output now reaches the model in the same `<persisted-output>` or `<truncated-output>` block, showing its start and end and the size of the part left out
Long output from file reads, searches and other tools now reaches the model as a short `<persisted-output>` block that names the file holding the full output, or a `<truncated-output>` block when nothing could be saved
Settings, managed skill files and enterprise allow and deny lists accept a built-in skill's `bundled:<id>` name and its older spellings, and a skill named in `allowed_identities` is admitted whatever `allowed_sources` says (an older spelling there names only the built-in skill, never a user skill of that name, while in `denied_identities` it refuses both); name a skill there to keep it available whatever its source. A managed skill file that names one skill twice (two spellings, or a plugin skill's `plugin:<pkg>:<skill>` id beside its path) is kept: matching values apply, and conflicting values turn that skill off with a warning naming both keys. Turning a built-in skill on or off, or resetting it, removes the other spellings of it from that settings file
Resuming a session that ended without a clean exit now shows the abnormal-exit warning even when Muse was started again in between
`muse trace inspect` says when a session log holds no per-lane samples for a request, and still checks the request against its replay
When a shell command runs without a Git directory that was swapped for a symlink, the agent is told which directory moved and how to make it usable again
Background command notices, Monitor events and fetched web pages that had to be cut now name the saved full output in the same `<persisted-output>` block
After a long conversation is compacted, the commands it keeps from earlier work are real commands, not file or log lines that only mention a command word mid-line; commands the agent ran itself are left to the written summary
`muse plugins validate` and `muse plugins install` now say a plugin manifest's `formerUnits` field is ignored (`ignored-former-units`), because only plugins that ship in the product can take over a former plugin's settings; the plugin still installs and its skills and hooks still work
When you name a skill by its short name and only an installed plugin shares that name with a built-in skill, Muse opens the built-in skill instead of asking you to choose
When your own user or project skill has the same name as a built-in skill, the TUI says so at startup and shows the `bundled:<name>` id that still opens the built-in
`muse plugins inspect` lists each built-in skill by the id the skills list uses, such as `bundled:plan`, instead of a plugin-qualified id
Security: Goal cards no longer print raw terminal control sequences hidden in goal text
Security: Writes to `~/.npmrc`, `~/.pypirc`, `~/.docker/config.json` or `~/.kube/config` now ask for approval before Muse changes them
Security: Installed plugin hooks ask for review again when an update changes the code they run, and hooks you approved before this release ask once more
The `run.usage` line of `muse exec --json` now counts every model call of the run; after a context compaction inside the run it counted only the later calls. When exec cannot count the whole run, it leaves the line out and prints a notice to stderr
When a new session's log is deleted while the session starts, the start now stops and says so, instead of writing a new log without the session's permission settings that a later `--session-id` run would pick up
Long sessions that run many Workflows no longer stop saving checkpoints: once a Workflow has ended, its finished subagents drop out of the saved session instead of being carried in every later checkpoint
`muse serve` now applies `-c` overrides such as `-c model_catalog=[]` to the model list it serves, not only when `--preset` is given
A session can still message another local session after an earlier session that messaged it from the same app has closed
Stopping a run or subagent just before its tool calls start, with a `PreToolUse` hook configured, now ends it as cancelled instead of failed with "tool batch ended without result"
A forked session hosted by `muse serve` no longer loses its own earlier turns from what the model sees; from the fork's third turn on, the model was sent the turns inherited from the parent, the fork's first turn and the newest message, but none of the fork's turns in between
In a sandboxed shell under the ProxyOnly network mode, an approved plain-HTTP request to a server that closes on an early client half-close now receives that server's response instead of an empty reply
The web3d skill's page checker takes phone screenshots at device scale 1 on a software renderer, so they time out far less often
Listing sessions no longer hangs when the session index is upgraded in the middle of the request
Starting Muse no longer writes into your earlier sessions' files, so a session that a file-sync tool copies between machines is no longer refused with "the session log was replaced by another file outside Muse"
A terminal or `tbh exec` session started with `--no-session-log`, including a read-only resume, no longer writes the built-in skill and plugin caches into your data folder; it reuses them when they are already there and otherwise keeps a temporary copy that is removed when it exits
On Windows, symbols such as ✓, →, € and —, combining accents, emoji joiners and variation selectors are no longer dropped from what you type or paste into the composer
On Windows, a corrupt session index is now set aside and rebuilt from your session logs, so `/resume` stops scanning every saved session each time it opens and you no longer have to delete the file by hand
On Windows, `--worktree create` now creates the session worktree instead of failing while Git writes the new worktree's `.git` file
On Windows, when the agent tries to read a folder as a file, the listing command it is pointed to now works for folder names with spaces, quotes or non-ASCII characters
Reopening a session no longer leaves out a turn that started while a session checkpoint or a context compaction was being saved
A Workflow agent or an Auto-review reviewer that has stopped responding is now ended 30 seconds after it is cancelled, instead of staying open indefinitely
A command or MCP server that a session starts and leaves running can no longer stop `muse serve` or `muse acp` from indexing history for rewind
A turn waiting on a monitor or background task no longer wakes for an update the model already received
When a turn dies unexpectedly while a tool call is still starting, that tool task now ends as failed instead of staying open forever
Sessions that switch model providers keep working after a crash resume; sessions saved by earlier builds are unchanged
Pressing Esc right after sending a prompt in a long session no longer shows the prompt in the composer and above the status row at the same time
Nested subagents report their true depth in the subagent roster and in subagent items, so a grandchild no longer reads as a direct child
Resuming a session no longer shows a false "runtime closed before context compaction completed" error after a `/compact` whose result could not be saved
When a streaming endpoint answers with no Content-Type header at all, the run now keeps retrying briefly before failing, matching how a transitory proxy rewrite of the header behaves; a page explicitly labelled with a non-SSE content type still fails at once
Stopping a Workflow at the moment it finishes no longer leaves it shown as `unresolved`
`exec --json` lines now carry a unique `id` and the real `recorded_at` time instead of the same placeholder ids and fixed 2026-06-04 times in every run, so scripts can join and time runs from the JSONL output
A `!` command that ends while the session finishes an automatic context compaction in the background no longer fails and loses its output when a tool hook ran for it
When the model service is overloaded (HTTP 503) or times out (HTTP 504), the first retry, and any retry wait the server does not set, now varies a little between sessions, so fewer sessions retry at the same moment and pile onto a service that is already busy
A fork or side chat of a compacted session hosted by `muse serve` now starts from everything the session did after the compaction; a fork could be sent a redundant note restating its delegation settings, and in rarer cases a fork or side chat started without the session's newest turns
After a context compaction in a session that does not write its own session log, a repeated subagent start no longer fails its lookup of the first start
Forked conversations preserve accepted followup turns
Automations that saved a subagent result the app could not finish storing need a newer app version to resume
Large images returned by MCP tools are now resized and re-encoded the same way as images read from files, so a few big tool images no longer make every later request too large
The queue key now keeps command intent when the command trigger is remapped, so a remapped exit or clear during a run acts as the command instead of queueing its text
Preserve exit status and output in notifications for long background commands
When a Workflow subagent's run fails after it has completed model calls, the tokens of those completed calls now count in the Workflow's token total and against a token budget you set
A shell command that fails with sandbox guidance longer than the output limit keeps its saved output and reports that the message was shortened
After a crash, when the session could only reopen from its last checkpoint, the startup notice now lists the tool calls and `!` commands the resume had already cancelled before it fell back to that checkpoint
When a new session's log is deleted while a client starts the session through the session server (`session/start`), the start now stops and says the log was deleted, instead of writing a new log without the session's permission settings
When settings.json cannot be read, skill activation defaults to off for that run instead of silently re-enabling skills the unreadable file had turned off
`/compact` in a session whose latest turn included a pasted image now compacts the conversation instead of refusing it as an invalid target
A full-context fork taken after switching model providers keeps working; forks saved by earlier builds are unchanged
On case-insensitive mounts such as WSL2 DrvFs, Muse's file tools now resolve protected files like `auth.json` and `trust.json` to the file they actually name, so opening the same file through a differently-cased path (for example `MUSE/auth.json`) is denied just like the exact spelling; a sandboxed shell refuses to start when a denied file lives on such a mount, because no path mask can cover the alias
The TUI no longer stops reading keys and drawing while the subagent workspace check waits for a session record to reach a slow disk; on a busy machine this froze the TUI for seconds at a time during turns and subagent runs
A session started with `/new` or `/clear` now saves session checkpoints; before, it saved none, so reopening it after a context compaction read its whole history
When hooks stop a turn on more than one tool call of a batch, a stop on a call that a `PostToolUseFailure` hook corrected with `updatedInput` no longer replaces the stop reason of an earlier call
Auth and trust file locks now sit beside the resolved write destination, so a symlinked auth.json or trust.json shares one lock across every spelling instead of two
A hook from a settings or hooks file that runs when a session starts, resumes, clears, compacts or forks no longer leaves a record in the session log when it exits 0, writes nothing but whitespace to stderr and adds or changes nothing (no context, system message or error); any other run of these hooks is recorded when it ends, and runs of a plugin's hook at these events are recorded as before; plain text that a hook prints to stdout when a session starts, resumes, clears, compacts or forks, or when a subagent starts, becomes context, so that run is recorded
Session logs on disk are smaller, because each model request now writes a shorter trace entry
Starting a new turn in a long session no longer re-reads the records of every earlier turn
A `Stop` hook no longer leaves a record in the session log when it exits 0, writes nothing but whitespace to stderr and adds or changes nothing (it does not keep the turn going, add a system message or fail); any other run of a `Stop` hook is recorded when it ends
