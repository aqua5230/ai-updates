Muse Code 1.4.14

發布日期：2026-11-12

Original changelog

`session/read` shows which connected client currently drives a session (`driveHolder`, the holder's `initialize` name and version; absent when nobody live holds it)
A failed turn's error now carries `requestDenied: true` when the provider refused the request, so session protocol clients can show "Request denied" instead of a generic model failure
Permission profiles can now allow, prompt for, or deny Unix-socket access per path, and a refused Docker socket connection explains the sandbox block with the way out
Startup names the effective approval mode when `--yolo` was requested but a restrictive permission profile took effect
`session/read`, `session/list` and the `session/resume` result show which client last resumed a session over the wire (`resumedByClient`, the resuming connection's `initialize` name and version, recorded durably on the resume marker)
`session/resume` accepts an optional `modelId` that overrides the retained model for that resume — over a stamped label or pin — and recovers an otherwise-unresolved label binding
`session/start` accepts an optional `previousSessionId` that records which session the new one replaces, even when that session no longer exists
Settings-listed models can name a separate background model for reminders and reviews
When the approval judge escalates to you instead of deciding, the approval card now shows the judge's reason as one short line under the command, so a risky request is harder to approve by reflex
`session/list`, `session/read` and the `session/resume` result show which session opened a worker session (`spawnedBy`: the opening session's id plus optional project and thread labels, recorded once when the worker's first session starts)
`session/start` accepts an optional `spawnedBy` (the opening session's id plus optional project and thread labels); the host records it once as the new session's opener and serves it back as `spawnedBy` on `session/list`, `session/read` and `session/resume`
`muse session-message list --json` rows carry `spawnedBy`, the session that opened each listed worker session (its id plus optional project and thread labels), read from the same session index `session/list` serves
An older Muse build cannot open a chat whose permissions were reset because part of its saved permission history was lost or damaged; update the app to open it (other chats are unaffected)
`muse serve --preset` applies the preset's prompts and run settings, accepts presets defined with `-c`, and keeps the preset chosen at startup after login
New features in a project the agent built earlier in the same session no longer start with a failing test, and reported bugs still get a regression test
Inside tmux, Muse now reports its program status (OSC 7501) without waiting for the terminal to answer, so iTerm2's tmux integration (`tmux -CC`) shows whether a session is working, waiting for you, or done; a client that attaches later sees it once the attach resizes the window or the status next changes
Permission profiles that prompt before socket access keep prompting after a session is reopened, and opening such a session requires the latest app version
When an answer compares several things in a table, the detail that does not fit the table now comes as short paragraphs or list items instead of one long block per item
Resume checkpoints of long sessions no longer keep every finished Workflow's child-capacity records, so they stay smaller; opening a session compacted this way needs this app version or later
When Muse Code double-checks its work after giving a final answer, it now reports the result of the check in a sentence or two instead of repeating or extending the answer
Long `/goal` sessions that start sub-agents keep their resume checkpoints small and resume quickly, instead of carrying every step since the first sub-agent started
When you ask for a plan in a file and say what the chat reply should contain, Muse Code saves the plan and replies only as you asked
Overviews, explanations, comparisons, and answers in a format you asked for no longer open with a top-finding line; reports on work Muse Code did still lead with the main finding
When branching a conversation through `muse serve` fails because a session file could not be written, the error now names the step that failed, the kind of path and the operating-system error instead of only `WriteFailed`
`initialize` now refuses a `clientInfo.name` longer than 64 characters, with the same `invalidParams` error a malformed name already gets
Compaction checkpoints keep rejected commands in a smaller form; chats whose checkpoint holds one require a compatible app update, and older versions cannot open them
`/feedback` shows how big the session record is before you agree to attach it, and notes when it will be trimmed
The built-in `browser-game` skill builds games from long design documents with an art-director subagent, which makes the art and ships it in the game folder while the game is built, then runs three critic rounds that play and review the game; short game requests stay light
Apps that show tool activity now see a tool call while a pre-tool hook is still deciding on it, marked as held
When a task gives a reference image, the Blender skill now runs a required critic loop of blind reviews and fixes, as a workflow where available, so renders match the reference more closely
Models that support max reasoning effort now use it by default when you have not chosen an effort, including future models
Reopening a compacted session through `muse serve` (`session/read`, or `session/resume` when it returns inline or snapshot history) now shows the earlier conversation as one collapsed earlierHistory item holding the checkpoint's recent messages, followed by what came after, instead of replaying history from before the checkpoint. Clients that do not know the item kind show its fallback line
Security: Sandboxed Linux commands can no longer rewrite kernel helper settings under `/proc/sys`, even when Muse itself runs as root
A follow-up task sent to a subagent that finished before `muse serve` restarted no longer stops before reaching the model when MCP servers are configured
After a brief disk error interrupts one background save, the next save on the same chat clears it and goes through, instead of being refused until restart
A session waiting on a finished background task now wakes when the task finishes instead of staying stuck until you intervene
When a background context summary fails or is too large to use, Muse Code no longer pays for a new one every turn; it retries only after the conversation has grown well past the failed attempt, including after the session is reopened
Restore resume for older Side chats while preserving their history and permission settings
Preserve active tasks when compacting a conversation more than once
While a storage error lasts, a periodic save that has to be skipped no longer ends the turn when the note recording the skip cannot be written either; the error is logged and the turn goes on
Resuming a session saved by an older version no longer offers Workflow; start a new session to use it
`/new` or `/clear` right after cancelling a run no longer exits with a missing-file error
On Windows, sandboxed shell commands now start in the workspace when it is inside your user folder, so relative paths no longer resolve under the PowerShell install folder
On Windows, Ctrl+V pastes copied text into the prompt in consoles that pass the key to Muse, such as the classic PowerShell window, instead of reporting that no image could be attached
Forking a chat with `muse serve` on Linux works again instead of failing with "file birth time is unavailable"
The `game-3d-visuals` skill now stops its pipeline loop when you ask it to stop, open the file or change course: "open it" opens the file (or says it is not ready yet) instead of waiting for the running stage, and a comment such as "thanks" lets the pipeline continue
Fixed workflow instructions that did not match the current session
A sub-agent started from a `/goal` chat saves its history again when it compacts, so it can be resumed from that point
The built-in `python-env` skill tries a container image, conda channel or prebuilt wheels that the user or the project names before compiling a dependency from source
A chat in which one record of a turn could not be written to disk, even after a retry (for example on a full disk that stayed full), can be forked, side-chatted and rewound again; that turn is left out of the new chat, and Muse says so once
Resumed sessions with a recorded selection keep the model you selected instead of switching to a default
After resuming a compacted session, follow-ups and waits on a subagent no longer fail once a shell command ran after the compaction
Reopening a chat whose saved view fell behind, for example after a cancelled turn, shows its latest turn instead of an older one
A subagent's transcript that a restart cut off reads again as soon as its parent session resumes, with no action on the subagent
Sessions where an older Muse Code (1.4.5 or earlier) recovered an interrupted workflow save context checkpoints again, so compaction is no longer skipped or dropped in them
A forked chat whose saved history has an unreadable part, and where the start of one of its own turns could not be written to disk, no longer refuses every message after it is reopened, forked or side-chatted; that turn is left out, and Muse says so once
A session saves its history again when it compacts after a Workflow's agents were skipped or retried more than 128 times, so it can be resumed from that point
Background work status survives a restart after correcting a missing Workflow name
A session with a lost permission change now refuses to resume when its safe permission reset cannot be enforced, instead of opening with silently dropped Deny rules
A chat in the app or `muse serve` that was closed while a workflow was running saves its history again after it is reopened
When you tell the `game-3d-visuals` skill to stop or exit while its pipeline runs, it now also stops the running background stage (unless you ask it not to call any tools), and a stage that finishes after you stopped no longer starts the next one
Stopping a background task or Monitor from `/tasks` just as it finishes now records the stop right away instead of dropping it after a 30-second wait
A chat in which a reminder for one turn could not be written to disk, even after a retry, can be forked and side-chatted again; that turn is left out of the new chat, and Muse says so once. Rewinding such a chat is still refused
Rewinding past a message you sent while the agent was busy no longer leaves the new branch stuck refusing every message and showing that message as still queued
Resuming a compacted session with `tbh exec --session-id` keeps its subagents, so following up with, waiting on or checking a subagent no longer reports it missing
Keep unknown Workflow result references unchanged
Complete Workflow reports remain readable when their preview is shortened
MCP servers start again when you resume a session after it was compacted, instead of every turn failing with "MCP startup audit failed" or the MCP tools going missing
A forked chat whose copied checkpoint can no longer be replayed (written by an older build, or slightly damaged) opens, forks and side-chats again with its copied history rebuilt; only history that truly cannot be read is left out, and Muse says so once
A Workflow paused just as it finishes now stays paused, instead of also reporting a finished result after the pause
A deactivated Muse Code app now names the server reason instead of telling the user to log in again
`muse serve` refuses to reopen a session whose automated reviewer this host cannot prepare with the `permission_profile_reviewer_unavailable` reason instead of a generic internal error
A chat in which a reminder for one turn could not be written to disk, even after a retry, can be rewound again; that turn is left out of the new chat, and Muse says so once
When a full disk could not save a task link, a monitor line or, in most cases, a named workflow launch, compaction checkpoints now keep working without restarting the chat
Cancelling, force-sealing or stopping a subagent whose own background work is still being killed no longer reports it done early: the result arrives once that work has ended, a cancel that cannot finish yet fails with a typed error naming the task, a stop answers `stopping` until then and is recorded once the jobs are dead
After a resumed session, following up with a subagent started before the conversation was compacted works again instead of failing the subagent with a missing ownership error
A chat in which two different kinds of record could not be written to disk can be forked and side-chatted again; both turns are left out of the new chat, and Muse says so once for each
Restore native MP4 and MOV video reading for supported models
Sessions with an earlier video read keep working when the current model, provider or video setting can't send that video
A denied cross-origin redirect no longer replaces the stored session for an Agent plugin's MCP server, and redirect grants no longer match non-HTTP(S) origins
Reopening a session no longer fails when a turn after a compaction reuses rules or instructions from before it
Background task output now wakes a waiting session instead of staying queued until you intervene
Resuming a session whose worktree was deleted now recreates it on hosts without an enforceable creation sandbox when you already trust the source repository; untrusted repositories still refuse
Built-in skills the model loads on its own now name tools the way the model is offered them, so it calls them by the right name
A session started by another app now takes its title and first-prompt preview from the prompt as it was shown, not the app's wrapper text, so it no longer appears with raw JSON as its name; a session that starts with a skill or image is titled by its display form (its typed form, or [Image 1] for an image-only start)
Saved Workflows can run again from their local script paths on Windows
Agent no longer repeats a question you already answered in the same conversation
Keep recovery guidance intact in long background Workflow results
Preserve the specific failure reason when a subagent fails
A chat reopened on an older build, whose log saved two background-result notices at the same spot, keeps saving compaction checkpoints in the running process instead of refusing them until the next reopen
In the terminal app, resuming a chat whose saved history lost a record after your last permission change (without a permission flag) now reopens it with a reset to the narrower of the default and your surviving profile — or to `:read-only` when the two are crossed — and a warning, instead of refusing it; a resume with no safely-resettable profile is still refused
Resuming a `muse serve` session after Muse Code exited unexpectedly no longer shows the interrupted run's work as still in progress
After a session reopens from a compacted history, retrying an approval decision, a question answer or a queued-message removal returns the original result instead of handling it again
After a crash, `muse serve` no longer asks again about tool calls that were waiting for approval and no longer runs an approved call by itself; the interrupted calls are closed and a call the model makes again gets the normal permission check
Branching a conversation on Windows no longer fails with a write error
When more skills are installed than the startup skill list can show, the agent can still find the ones left out by looking one up with part of its name or description
Plugin MCP servers approved in review can now sign in through `muse serve` as well as `muse mcp login`, instead of being refused as plugin-managed
Retrying a workflow child skip or retry with the same command id after a restart returns its original result; chats whose checkpoint holds such a result require a compatible app update, and older versions cannot open them
Recovered Workflow children release unused capacity reservations, and conflicting attempts get a clear restart error
A resumed coordinator lane whose session takes a moment to redraw now still receives its handover brief and answers, instead of going silent
Reopening a subagent chat keeps replies from earlier work
Tell the main agent to read complete Workflow reports before answering from a shortened preview
A long run no longer fails with "Origin read requires valid checkpoint-suffix or origin-preserved full-replay authority" when a tool result's saved copy has to be re-written after context compaction
A long-running served chat whose earlier checkpoint was saved together with a compaction keeps saving checkpoints instead of refusing every one after a reopen
Very long sessions no longer stall while compacting a conversation too large to summarize at once
A finished background task now wakes a waiting session even when an earlier wake was lost
Work status checks now show a short work ID once instead of repeating the full ID in the header and the status card, and listing background work shows item labels when present (else a short work ID) instead of raw JSON
Preserve background command results in session history after a recording error
A background task that keeps running through several compactions no longer shows as invalid after you reopen the chat
A side chat reopened after it compacted no longer re-reads its whole history each turn, so damage in older history no longer stops it
In the terminal app, resuming a chat whose saved history lost a record with a permission flag (for example --permission-profile or --sandbox-network) now applies your chosen permissions as the `lost_record_reset` commit that drops pre-loss grants (after the reset, or in its place when the reset is not allowed), and one warning that your chosen permissions apply. A pick the retained managed pin refuses, or a reset `:read-only` cannot be shown never wider than both profiles, still refuses with no reset and no warning
Deleting `session-index.db` while Muse Code runs no longer makes the session list fail or crashes the app; the index is rebuilt with fresh files
Opening a side chat over the session protocol no longer intermittently reports the new session is already in use
A parent agent can now read a subagent's whole final answer instead of only its first 512 characters, so it no longer spawns extra agents just to read the rest
Compaction avoids copying preserved user messages into its automatic history notes
A model response whose tool-call signals disagree on the tool name or call id now retries that attempt instead of ending the whole run
After a crash, a resumed client's subagent rows no longer show a recovered child as running, and its child-view composer correctly reports the thread as read-only instead of attempting a send the host rejects
Rewinding to an earlier turn no longer fails after a compaction that ran while a finished background task's result was still waiting to be delivered
A fork or side chat that compacted no longer writes later checkpoints that hide the compaction, so its next resume still starts from the checkpoint
Compaction handoff summaries now preserve operational state-to-action triggers (standing duties with their exact command) verbatim, so a duty like starting a bot once an approval arrives survives context compaction instead of being summarized away
In a session resumed from a checkpoint, running `/goal set` while a turn was running could cancel the new goal turn and then refuse every later message with "Message not sent — saving failed"; the goal turn now starts and later messages go through
Muse is told when the permission mode changes mid-session, so it stops insisting it is still on the launch mode after switching to Unrestricted
Pasting an API key into a logged-out session now shows the contributor models in /model immediately, instead of only after a restart
After context compaction summarizes a skill body away, the skill reminder can offer that skill again instead of treating it as already read for the rest of the session
Resumed and long-running sessions use less memory, because saved copies of session records made mostly of structured data are kept as compact text instead of an expanded in-memory form
Long sessions use less memory, because each saved run event takes less space in memory
Resumed long sessions use less memory, because each run's model instructions and context settings are kept once in memory instead of being copied for every run
Resuming a session with subagents no longer re-reads a subagent's history from before its last compaction
Typing in long sessions with many subagent runs stays responsive, because the subagent tree no longer re-checks every delivered result against every run on each frame
An idle session no longer re-reads the whole session index every two seconds, which removes a constant background disk read on machines with many saved sessions
Resuming a long session that has many subagents and no saved context checkpoint is faster, because checking each subagent log for a checkpoint no longer parses every record
