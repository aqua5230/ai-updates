Muse Code 1.4.14

Released: 2026-11-12

Release notes

FEATURE

Query session connection status with clear labels for active controller and opener

When switching between multiple terminal windows or different tools, it is easy to lose track of which side currently controls a specific conversation.

Picture an electronic sign-in board outside a large conference room that clearly displays on screen who holds the microphone, who handed it off last, and which main meeting assigned this breakout discussion.

Now when reading a session, driveHolder marks which client is driving it in real time. Calling session/read, session/list, or resume results also shows resumedByClient to record who reconnected last. When starting a new conversation via session/start, you can pass previousSessionId to record which old conversation it replaces. If a main conversation opens a background worker, related lists and the muse session-message list --json command also attach a spawnedBy tag, so every row tells you which session opened that background worker.

FEATURE

Permission profiles finely control sockets as approval cards show judgment reasons

When running commands that need access to local services, permission profiles can now allow, prompt, or deny connections to a Unix socket (a local inter-process communication channel) per path.

Think of a customs checkpoint inspection list: where special goods used to only be cleared or held, inspectors can now demand permits item by item and check off reasons on the declaration form when in doubt, preventing rubber-stamp clearance.

If a Docker socket connection is blocked by the sandbox, it directly explains the reason for the block and how to lift it; prompts also persist after restarting a session. In the approval flow, when the approval judge decides to escalate to you for a ruling, the approval card adds a short line of reasoning below the command, reducing the chance of reflexively approving high-risk operations. If --yolo is passed at startup but restricted by a strict profile, the opening lists the mode that actually takes effect. Switching to Unrestricted mode mid-session also syncs in real time, and Linux commands inside the sandbox are prohibited from tampering with kernel settings under /proc/sys.

FEATURE

Automatic safe downgrade on damaged chat permission history prevents unauthorized execution

When history lacks some permission changes due to an interruption, reopening a session no longer silently drops deny rules.

At a bank vault with damaged lock-log paper records, the security system does not drop gate controls; instead, it forces a switch to the highest read-only protection level and refuses entry until permissions are verified.

In the terminal app, if history lost a record after the last change, the system automatically compares the default and the surviving profile, resets by downgrading to the stricter of the two, or falls back directly to read-only mode with a warning, and refuses to resume if it cannot safely reset. Conversations with permission flags such as --permission-profile that lost records instead apply the explicitly specified permissions and invalidate grants from before the damage. Older app versions cannot open conversations whose permissions were reset and require an update to open. In muse serve, if the host cannot prepare the automated reviewer, it clearly reports that the reviewer is unavailable instead of returning a vague internal error.

FEATURE

Resumed chats allow custom model overrides with max reasoning effort on by default

When resuming a previously archived conversation, you can now pass an optional modelId to session/resume to directly override the conversation's originally fixed model setting.

Like swapping in a new audio track on a professional mixing console, performers can assign dedicated effects to individual instruments while letting the main channel deliver maximum resolution by default, and plugging in new gear mid-set lights up the corresponding knobs immediately.

Conversations with a recorded model selection precisely keep your chosen model upon reload instead of jumping back to the default. Models that support maximum reasoning effort will enable maximum reasoning effort by default if no effort is manually specified. Models listed in the settings file can now assign a separate background model for reminders and reviews. If you paste an API key while logged out, the /model menu immediately lists the corresponding models without restarting the tool.

FEATURE

Strict adherence to output format requirements with condensed verification reports

When you specify saving a plan to a file and restrict what the chat reply should contain, the tool now faithfully writes to the file and returns only the agreed chat content.

Following an architectural inspection memo, the main drawings stay uniform, details that do not fit in the table columns move to a sidebar list, and re-inspection sign-off only stamps a brief pass summary at the end instead of reciting the entire contract again.

When you ask for an overview, comparison, or specific format, replies no longer force a top conclusion summary; only reports on the tool's own work lead with the key finding. When comparing multiple items in a table, supplementary details that do not fit in the table are split into short paragraphs or lists. A double-check after giving a final answer states the outcome concisely in a sentence or two without repeating the whole reply. Questions already answered in the same conversation are not asked again; when continuing to build new features in the same session, it no longer starts by throwing a failing test, while reported bugs still get regression tests.

BUGFIX

Game and 3D skills add art direction and multi-round blind reviews for closer renders

When building a game from a complete design document, the built-in browser-game skill now dispatches an art-director subagent (a dedicated helper) to produce assets alongside coding and store them in the game folder, followed by 3 playtest scoring rounds by reviewers.

Inside a miniature animation studio, the art director draws assets while three test groups take turns playing and scoring, and rendering runs multi-round blind reviews against reference sketches while halting immediately the moment the director yells cut.

When a reference image is provided, the Blender skill starts a blind-review and fix loop, running as a workflow where possible, so renders match the example more closely. During a game-3d-visuals skill pipeline run, if you ask it to stop or change course, it halts the background stage; saying "open it" opens the file directly without waiting, while ordinary thank-you phrases let the flow continue normally.

FEATURE

Python skill prioritizes prebuilt packages while skill list supports fuzzy lookup

When installing Python dependencies, the python-env skill now first tries a container image, Conda channel, or wheel (a ready-to-install Python package file) specified by the project or user, avoiding time-consuming compilation from source.

A trip to a hardware supply store works the same way: when ready-made components sit on the shelf, you grab them instead of machining metal in the workshop, and if the catalog cannot fit everything, you call out keywords so the clerk can pull the item from stock.

Built-in skills loaded by the model on its own now call tools using the exact names offered by the model interface, preventing invocation failures from naming mismatches. When the number of installed skills exceeds the startup list display limit, the agent can still look up and load extension skills omitted from the main list using partial keywords from their name or description.

FEATURE

Native MP4 and MOV video reading restored with clearer multimedia session titles

When you pass image or video files to a model for analysis, supported models now resume directly reading native MP4 and MOV videos.

Matching a screening room's projection system, the projector plays the film reel directly whenever it can decode it, switching mid-show to equipment without video support never stalls playback, and the marquee uses the actual movie title rather than customs paperwork.

Even if a video was read earlier, switching later to a model, provider, or setting that does not support video lets the session continue normally without being blocked. When an external app starts a conversation, its title and first-prompt preview directly use the prompt text as shown to the user instead of displaying raw JSON blocks; conversations starting with a skill or image-only input are also named with their display text or [Image 1].

BUGFIX

Deleted worktrees rebuild automatically alongside tmux status and Windows terminal fixes

When you resume a prior session and find its worktree (a Git feature that lets one project keep multiple parallel working copies) was deleted, it automatically recreates that worktree as long as the source repository is already trusted, even on hosts without an enforceable creation sandbox; untrusted repositories still refuse.

Restarting gear at a field station works much the same way: if an existing outpost was accidentally removed, it is rebuilt on the spot as long as the home base is trusted, and console status lights sync immediately to remote monitors.

Inside tmux, the tool proactively broadcasts its running status so external terminals can track progress. On Windows, sandboxed commands inside your user folder properly start in the workspace so relative paths no longer misresolve to the install directory; pressing Ctrl+V in classic consoles pastes text normally, and branching a conversation no longer hits write errors. When running /feedback to report an issue, the screen previews the session record size and notes when it will be trimmed.

BUGFIX

Server mode presets persist across logins with detailed conversation branching errors

When deploying background services with a server architecture, muse serve --preset now fully applies the preset's prompts and runtime environment settings.

Imagine a mail server's dispatch configuration: delivery templates and filtering rules set at boot stay enforced after login, and any failed delivery spells out the exact path and system code where it stalled instead of merely saying send failed.

In addition to supporting custom configs loaded via -c, the preset chosen at startup persists after user login. When branching a conversation via muse serve fails because a session file could not be written, the error message names the specific failed step, path kind, and raw operating-system error code instead of throwing only a vague label. Creating a conversation branch on Linux no longer hits file birth time errors. During connection initialization, a client name exceeding 64 characters is explicitly rejected. If the app is deactivated, it clearly returns the server reason instead of blindly prompting to log in again.

BUGFIX

Safe server crash recovery stops unfinished actions from running on their own

When the server crashes and restarts unexpectedly, any unfinished work from before is now cleaned up safely.

A factory console after a power trip resets and cancels any mid-air machining commands on restart instead of running the equipment on its own, while new handover notes still reach the on-duty operator.

Resuming a session after muse serve exits unexpectedly no longer shows tasks from the interrupted run as still in progress. Tool calls that were waiting for approval before the crash no longer prompt again or run on their own after a restart; interrupted calls are closed out and go through normal approval only if the model invokes them again. When a coordinator lane takes a moment to redraw after waking, its handover brief and answers still arrive reliably instead of going silent. Deleting the session-index.db index file while running no longer breaks the list or crashes the app, and the index is rebuilt from existing files. Opening a side chat over the session protocol also no longer intermittently reports that the session is already in use.

FEATURE

Stronger Workflow crash recovery releases unused capacity reservations

Long-running automated Workflows now handle resumption and resource management more tightly after an interruption.

Automated warehouse rail dispatch works the same way: when a shuttle faults and reboots, it gives back its reserved lane quota, and pressing pause freezes motion immediately so nothing slips out after a stop.

Closing the app or muse serve while a Workflow is running now saves history again once reopened. After correcting a missing Workflow name, background work status survives a restart, and pausing a Workflow right as it finishes keeps its status paused without also reporting completion. Child Workflows recovered after a restart automatically release unused capacity reservations and return a clear restart error on conflicts, while retrying a skip or run with the same command ID returns the original result. Saved Workflows run properly from local script paths on Windows, and older sessions no longer offer Workflow support, so starting a new session is recommended.

FEATURE

Main agent reads full Workflow reports and keeps long-run recovery guidance

When a Workflow produces a long report whose preview is shortened automatically, the main agent is now instructed to read the full report before answering you.

Much like a project lead reviewing a closing deck, the summary slide shows only highlights, yet the full appendix is pulled before making a call and troubleshooting steps stay intact on their own page instead of getting lost in collapsed sections.

Complete Workflow reports remain readable even when their preview is trimmed, and error recovery guidance in long background results stays intact. Unknown Workflow result references are left unchanged, and a mismatch between instructions and the current session has been fixed. If agents in a Workflow are skipped or retried more than 128 times, the session still saves its history after compaction so you can resume from that checkpoint anytime.

BUGFIX

Finished background tasks wake chats immediately with cleaner status IDs

When the main chat is waiting on a long background task, the waiting session now wakes automatically as soon as the task finishes or produces output, without waiting for your manual input.

Once a restaurant kitchen finishes a special order, the pager buzzes so the counter alerts the guest right away instead of making them walk up to ask, and the display board shows only a short pickup number rather than a long internal order barcode.

Even if an earlier wake signal is lost, the completion event still triggers a wake. Stopping a background task or monitor from /tasks right as it finishes now records the stop immediately instead of dropping it after a 30-second wait. Work status checks show a short ID once across the header and card, and listings prefer item labels over raw JSON. Background command results stay in history even after a recording error, and background tasks that keep running across multiple compactions are no longer marked invalid when you reopen the chat.

BUGFIX

Parent agents read full subagent replies and wait for background cleanup

When a parent agent delegates independent work to a subagent, it can now read the subagent's entire final reply directly.

Rather than sending a second assistant just to fetch the back half of a field investigator's notebook, a project manager can read the whole report at once, and a stand-down order closes out only after the field team has actually cleared out.

Previously only the first 512 characters were readable, which often caused parent agents to spawn extra agents just to read the rest. Cancelling, force-sealing, or stopping a subagent that is still cleaning up background work no longer reports done early; cancel waits for background work to finish, and stop explicitly reports that it is stopping in the meantime. Subagent failures preserve the specific error reason, reopening a subagent chat keeps earlier replies, and a client recovered after a crash no longer shows finished subagents as running while marking the composer read-only to prevent rejected sends.

BUGFIX

Subagents stay connected across restarts with lighter goal compaction

In long /goal sessions that dispatch subagents, restart checkpoints no longer carry every minor step from the start, making them smaller and faster to wake.

Compare it to a construction site foreman roster: even if headquarters restarts or the site log is rebound, section leads keep their communication lines and authority intact without hauling every tiny detail from day one in the handover notes.

After a conversation is compacted, sending follow-up tasks to or waiting on previously started subagents no longer reports them missing due to prior shell commands or missing ownership. Subagents started from /goal save properly when self-compacting so they can resume, and subagent transcripts cut off by a restart are reread automatically when the parent chat wakes. With MCP (a protocol that connects AI to external tools) configured, subagents that finished before a server restart can receive follow-up tasks smoothly, and waking a chat with tbh exec --session-id no longer drops subagent links.

BUGFIX

Compaction preserves standing duties verbatim and collapses older history

When a long conversation triggers context compaction, handover summaries now keep standing operational triggers and exact commands verbatim—such as starting a bot once approval arrives—so key instructions are not watered down or overlooked.

A ship's log settles each leg the same way: past voyages are rolled into a single archive scroll, while standard combat procedures are copied word for word into the active manual so nobody has to re-read earlier pages on every turn.

Reopening a compacted session through muse serve neatly folds earlier history into a single collapsed item—clients that do not recognize it display fallback text—followed directly by recent progress instead of replaying from the beginning. Very long sessions no longer stall during compaction, and if a background summary fails or exceeds capacity, the system stops spending quota every turn and waits until the conversation grows noticeably before retrying. If a skill's content is summarized away during compaction, the reminder offers that skill again when needed, and automatic history notes no longer copy preserved user messages repeatedly.

BUGFIX

Checkpoints store rejected commands compactly and keep active tasks

When long-running sessions create restart checkpoints, child capacity records from finished Workflows are no longer kept, keeping checkpoints lighter.

Borrowing from a streamlined archive's filing routine, closed Workflows move out of the daily reference drawer and rejected applications go onto microfilm, saving space while keeping active paperwork intact.

Commands rejected by the user are stored in a compact format in checkpoints, and opening such checkpoints requires updating to a compatible version. Active tasks are preserved across multiple compactions, and sessions whose interrupted Workflows were recovered by an older version resume saving context checkpoints. Reopening a session no longer throws an error when a post-compaction turn reuses rules or instructions from before compaction. Rewriting tool results after context compaction no longer fails permission validation, and compacted forks or side chats no longer have their compacted state hidden by later checkpoints.

BUGFIX

Rewind avoids queued-message locks and approval retries return original results

When you rewind to an earlier conversation turn before a queued message sent while the agent was busy, the new branch no longer gets stuck in a queued state and refuses all further input.

Setting a time machine back to a key junction clears out any mail jammed in transit and pulls original stamped stubs for verification, so switching tracks never locks down the whole station.

Rewinding to an earlier turn also succeeds without error even if context compaction ran while a background task result was still waiting to be delivered. After reloading a session from compacted history, retrying an earlier approval decision, question answer, or queued-message removal returns the original result directly instead of processing it again. In a session resumed from a checkpoint, running /goal set mid-conversation starts the new goal normally, eliminating the save failure that blocked all subsequent messages.

BUGFIX

Fault-tolerant background saves recover cleanly from brief disk errors

When a background save is blocked by a brief disk error, the system now clears the error and completes the write on the next turn without needing a restart.

When a cash register's receipt printer briefly runs out of paper, it logs the skipped print and keeps checking out customers, then resumes printing as soon as a new roll is loaded instead of rebooting the whole register.

If a disk error forces a periodic save to be skipped and even the skip note cannot be written, the conversation continues the current turn after logging the error instead of aborting. Compaction checkpoints continue working even when a full disk prevented saving a task link or monitor. Running /new or /clear right after cancelling a run no longer raises a missing-file error, reopening a chat whose view fell behind shows the latest turn properly, and long-running served chats keep saving checkpoints after a restart without being refused.

FEATURE

Side Chats and Branches Skip Corrupted Turns and Rebuild Readable History

Previously, when a full disk prevented a turn's record from being written, the entire chat would break down.

A photocopier scanning a book with a couple of damp, stuck pages actively skips the unreadable sheets and notes the gaps, letting you bind the remaining complete chapters instead of discarding the entire volume.

Now, these chats can be branched, side-chatted, or rewound again; the system automatically skips turns that cannot be read or failed to write, and clearly notes this once at the start. Even if a chat contains two different failed write records, a missing reminder, or a damaged checkpoint, branching automatically rebuilds a readable history and opens smoothly. Side chats created in older builds now resume properly while preserving their history and permission settings; when reopened after compaction, side chats no longer re-read their entire old history each turn, so damage in older data no longer blocks the current chat.

BUGFIX

MCP Server Login, Post-Compaction Restarts, and Automatic Tool-Call Retries

When connecting external extensions in a chat, review-approved plugin MCP (Model Context Protocol, a protocol that connects AI to external tools) servers can now sign in via muse serve or muse mcp login.

Operators at a switchboard transferring an outside call keep the hold light lit while front-end security checks verify the caller's identity, and even if the call log is archived midway, the dedicated line reconnects automatically upon restart.

When resuming a chat after history compaction, MCP servers restart properly instead of throwing startup audit failures or missing-tool errors. Interfaces showing external tool activity can now see a tool call while a pre-tool hook (a small program triggered when specific events occur) is still evaluating it, marked as held. When a model's tool-call signals disagree on the tool name or call ID, that attempt is automatically retried instead of ending the chat. Denied cross-origin redirects no longer overwrite the stored session, and redirect grants no longer apply to non-HTTP(S) origins. When a model request is denied, it carries a dedicated flag so the interface can display an accurate denial message.

FEATURE

Lower Memory Usage in Long Sessions, Eliminating Typing Jank

Typing in long sessions with multiple subagent tasks no longer suffers from input jank.

Modern warehouses manage space by keeping a single shared copy of each spec manual on main shelves instead of stuffing heavy booklets into every box, and shifting aisle inspections to on-demand spot checks so on-site handling and logging stay agile and smooth.

Previously, every delivered result was checked against every run on each frame; adjusting this comparison keeps typing responsive. Memory usage in long sessions is significantly reduced: structured session records stay in memory as compact text, each run's events take less space, and model instructions and context settings are shared as a single copy. Resuming a session with subagents no longer re-reads their old history from before compaction. Long sessions with many subagents and no saved checkpoints also resume faster because checking each subagent record no longer parses every entry, and idle sessions no longer perform a constant disk-index read every two seconds.
