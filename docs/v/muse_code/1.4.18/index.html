Muse Code 1.4.18

發布日期：2026-11-13

繁體中文

問題修復

目標與驗證提醒預設不再逐次存檔以節省空間

開著長任務反覆檢查進度時，硬碟裡常不知不覺多出一堆細碎紀錄。

好比花園裡的定時灑水器每次巡檢只看當下狀態，以前每巡一回就印一張日報表塞滿信箱，現在預設巡完直接收工，想對帳時再撥開關逐趟留單。

現在工作階段佔用的磁碟空間變少了。負責追蹤目標的 goal-reminder 與負責確認結果的 verify-reminder 兩款提醒外掛，都不再為每次檢查單獨儲存紀錄檔。如果你還想保留這些紀錄，只要打開 settings.json 設定檔，將 plugins.goal-reminder.child_session_log 與 plugins.verify-reminder.child_session_log 設為 "retained" 即可：

{
  "plugins": {
    "goal-reminder": {
      "child_session_log": "retained"
    },
    "verify-reminder": {
      "child_session_log": "retained"
    }
  }
}
問題修復

不看圖的模型遇圖片改註明未附上而不中斷工作階段

你正在用純文字模型整理專案檔案，途中它不小心讀進一張螢幕截圖，或外部工具回傳了一張圖片。過去只要遇到無法看圖的模型，無論是讀取圖片檔還是從 MCP（讓 AI 連接外部工具的協定）工具收到圖片，整個工作階段都會當場中斷。現在這兩種情況不會再弄斷工作階段，執行結果會改為寫明圖片未附上。

想像你把彩色海報遞給只讀文字稿的朗讀員，以前他一看到圖畫就當場停擺，現在他只會平靜告知海報沒夾進來，接著照樣把文字讀完。
問題修復

編輯器裡的代理程式工作階段無法再儲存時會跳出警告

專心在編輯視窗裡接力推進任務時，你怎麼確定對話進度都還存得下來？

恰似拿著拍立得相機不斷按下快門，以前底片匣再也裝不下新照片卻毫無聲響，現在只要畫面存不進去，觀景窗當場就會亮出警訊。

當編輯器裡的代理程式（Agent，能自主執行多步驟任務的 AI 助手）工作階段變得無法再儲存時，畫面上現在會直接發出警告。在你接著下達更多指令或準備離開編輯器前，這個提示會直接通知你工作階段已經無法繼續存檔。

新功能

`muse exec --json --image` 現在也會為圖片標註編號

當你從終端機執行指令並同時傳入多張圖片給 Muse 時，有時會順手加上 --json（一種方便程式讀取的資料格式）參數來接收結果。原本不帶 --json 的 muse exec --image 指令，就已經會在提示詞裡替每張附加圖片標上 [Image #N]。現在只要執行 muse exec --json --image，提示詞一樣會為每張附加圖片加上 [Image #N] 標籤。比方說你一次附上兩張畫面截圖要它處理，加上 --json 後提示詞內依然會出現對應的圖片編號。

如同醫生把多張 X 光片放上燈箱時會在角落標出第一張與第二張，以前改用資料格式送圖會少了這層記號，現在每張圖照樣貼上序號方便指認。
問題修復

第一句話很短時，非英語回覆不再被丟棄重寫

用自己習慣的母語跟工具打招呼時，開場只寫短短幾個字再自然不過。

試想多語導遊帶團時，以前團員只簡短問一句就被誤認成英文團而打掉重講，現在除非你說出常用英語或要求講英文，導遊都會留住原本語言。

現在即使你的第一則訊息很簡短，法文、西班牙文、德文以及其他非英語語言的回答，都不會再被丟棄並重新改寫。Muse 只有在你的訊息使用常見英文單字，或你明確要求使用英文時，才會將工作階段語言設為英文。下次開新對話只先傳一句簡短的法文或西班牙文問候時，產出的回答會完整留下，不會突然被整段撤回重寫。

問題修復

工作階段完成壓縮後，不再於背景重讀整份紀錄

在同一個長對話裡連續推敲好一陣子，工具通常會先幫你把冗長內容精簡收斂。過去工作階段經歷壓縮（將長對話精簡濃縮以騰出空間）之後，工具還會在背景把整份工作階段紀錄重新讀過一遍。現在經過壓縮的工作階段，在壓縮完成後不再於背景重讀整份紀錄檔。

宛如搬新家前已經把厚重舊雜誌精簡成一疊重點剪報，以前搬完家還要把整箱舊刊物再翻閱一遍，現在打包完就專心用這疊剪報，不再回頭翻舊箱子。

English

BUGFIX

Goal and verify reminders no longer save per-check log files by default to conserve space

When running a long task and repeatedly checking progress, small log records often pile up on your drive without you noticing.

A timed garden sprinkler only checks the current state on each round; it used to print a daily report every single pass and stuff the mailbox, whereas now it finishes the round and clocks out by default unless you flip a switch to keep each trip's slip when you want to reconcile later.

Sessions now take up less disk space. Both goal-reminder, which tracks goals, and verify-reminder, which verifies results, no longer save a separate log file for each check. If you still want to keep these logs, open your settings.json file and set plugins.goal-reminder.child_session_log and plugins.verify-reminder.child_session_log to "retained":

{
  "plugins": {
    "goal-reminder": {
      "child_session_log": "retained"
    },
    "verify-reminder": {
      "child_session_log": "retained"
    }
  }
}
BUGFIX

Models that cannot view images now note the image was not attached instead of breaking the session

Suppose you are organizing project files with a text-only model, and it accidentally reads a screenshot or an external tool returns an image. Previously, on any model that could not view images, reading an image file or receiving an image from an MCP (a protocol that lets AI connect to external tools) tool would break the entire session on the spot. Now neither case breaks the session, and the result states that the image was not attached instead.

Imagine handing a color poster to a reader who only reads text scripts; he used to stop cold at the sight of a picture, whereas now he calmly notes that the poster was not included and keeps reading the text.
BUGFIX

Agent sessions in editors warn when the session can no longer be saved

When you are focused on pushing a task forward step by step in an editor window, how can you be sure your conversation progress is still being saved?

Think of snapping away with an instant camera whose film pack can no longer hold another shot without making a sound, whereas now the viewfinder lights up with a warning the moment a frame cannot be saved.

When an Agent (an AI assistant that can autonomously perform multi-step tasks) session in an editor can no longer be saved, a warning now appears on screen. Before you issue more commands or leave the editor, this prompt alerts you directly that the session can no longer be saved.

FEATURE

`muse exec --json --image` now labels images with numbers too

When you run a command from the terminal and pass multiple images to Muse at once, you may also add the --json (a data format designed for programs to read) flag to receive the output. Running muse exec --image without --json already labels each attached image [Image #N] in the prompt. Now, whenever you run muse exec --json --image, the prompt adds the [Image #N] label to each attached image as well. For example, if you attach two screenshots at once for processing, the corresponding image numbers still appear in the prompt even with --json.

Like a doctor placing multiple X-rays on a lightbox and marking the first and second in the corner, sending images in that data format used to leave off those markings, whereas now each image gets its sequence number for easy reference.
BUGFIX

Non-English answers are no longer discarded and rewritten when your first message is short

When greeting a tool in your own native language, starting with just a few words is completely natural.

Picture a multilingual tour guide leading a group: a guest who asked only a brief question used to be mistaken for an English tour and made to start over, whereas now the guide keeps the original language unless you use common English words or ask for English.

Now, even when your first message is short, answers in French, Spanish, German, and other non-English languages are no longer discarded and rewritten. Muse sets English as the session language only when your messages use common English words or you explicitly ask for English. The next time you start a new conversation with just a brief French or Spanish greeting, the generated answer will stay intact instead of being suddenly retracted and rewritten.

BUGFIX

Compacted sessions no longer re-read the whole log in the background

After working back and forth in the same long conversation for a while, the tool usually condenses the lengthy content for you first. Previously, after a session went through compaction (condensing a long conversation to free up space), the tool would still re-read the entire session log in the background. Now, a compacted session no longer re-reads its whole log file in the background after compaction finishes.

Just as someone moving to a new home trims thick old magazines down to a stack of key clippings, they used to flip through the whole box of old issues again after unpacking, whereas now they stick to those clippings once packed and stop digging back into the old box.
