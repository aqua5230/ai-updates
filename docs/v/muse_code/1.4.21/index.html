Muse Code 1.4.21

發布日期：2026-11-21

Original changelog

The TypeScript SDK can cancel or time out `MuseClient.spawn` with a `signal` option, for example `AbortSignal.timeout(10_000)`; a host that never finishes starting is shut down instead of left running
The TypeScript SDK types `command` and `request` from the protocol schema, and a raw connection gains `addNotificationListener` for typed per-method notifications: results are typed, and a call whose params do not match a listed method's type is marked deprecated, ahead of becoming a compile error in a later release; so is a method name that mixes listed and unlisted names, or a generic one on a raw connection (widen it to `string` to keep sending it untyped)
`/resume` now marks sessions that need your input and updates them live
In the TypeScript and Python SDKs, `session.events({ subagents: true })` (Python: `session.events(subagents=True)`) also streams what each sub-agent does, step by step, tagged with the sub-agent it belongs to
Start Muse with `MUSE_SHELL_DROP_META_API_KEY=1` (or `true` or `yes`) to keep your `META_API_KEY` out of commands the agent runs, `!` commands and Monitor commands; a session on an already running Muse server follows that server's setting, and a Muse started by one of those commands gets no key from them
In the TypeScript SDK, `session.reload()` catches up a session the host unloaded while idle, keeping its state, handlers and pending turns instead of starting a new session
The `run.system_prompt_append` setting adds your text after the built-in system prompt instead of replacing it (up to 64 KiB). A session can also set its own value, and it keeps that value when it is resumed or forked
When your session language pin is English and Muse's visible output slips into another script, the harness now retries with a correction restating the pin (up to two corrective retries per response step, then the last attempt is delivered as-is) instead of re-issuing the identical request once
`prompt.surfaces` settings can now also turn off the five context statements that were always kept (workspace root, permission mode, sandbox policy, capability policy and code-mode profile); turning one off changes only what the model is told, never the sandbox, approvals or tool access it describes
When Muse deletes a session, at `session_retention_days` expiry or when it cleans up an empty session, it also removes the saved history that other Muse versions kept for that session, which used to stay on disk
A plugin reminder's instructions file can now be up to 32 KiB instead of 16 KiB; a larger file is still left out with a diagnostic
Muse keeps your session language pin across context compaction: a session that established or requested a language before compacting keeps it on later turns, instead of re-deriving it from the post-compaction messages alone
Prepares saved chats to store an "allow for this session" choice for commands that run on another machine: a version that reads these records refuses one with a field it does not know instead of reading a narrowed permission as a wider one; no chat contains them yet
The session index now caps its write-ahead log at 256 MiB by default, so the log stops growing past that size on always-on machines and listings stay unchanged
The away recap now appears when you come back to a session with just one message, and again after a background result adds new replies, instead of waiting for two more of your messages
The "Worked for" line now also appears after a turn started by a background result, such as a finished background agent, a scheduled task or a goal
On Windows, when a command fails because PowerShell has no Unix command such as `head`, `tail`, `grep` or `wc`, the result names the PowerShell command to use instead, so the agent fixes the command in one step
Chats from automated evaluation runs now keep a record of how each run was set up; earlier versions skip that record, and much older versions may refuse new prompts in such a chat after switching models; updating fixes it
On models other than Muse models, such as Claude, GPT and Gemini, Muse no longer adds an instruction naming the session language to the request or regenerates a reply whose visible text switches language or script; Muse models keep both
Security: A Git directory swapped for a symlink during a session is no longer writable through the link; shell commands run without it
Security: On Linux, the environment of a sandboxed command no longer appears on bubblewrap's command line in the unrestricted network mode, where any process on the machine could read it with `ps`; the command receives the same environment as before
Security: On Windows, where the drive supports file permissions, `auth.json` and `trust.json` are now created so only your account, SYSTEM and Administrators can open them, instead of inheriting the folder's permissions. Each Windows account needs its own config folder (set `XDG_CONFIG_HOME`); if another account can no longer open the file, delete the file and sign in again
After an automatic compaction, `contextUsage` now reports the compacted context instead of the run's summed tokens, so a session-protocol client's context meter drops as soon as the compaction installs
After you pause and resume a Workflow, a rerun agent's conversation now shows the same attempt number as its card (for example `attempt 2/2`) and lists the earlier attempt, instead of `attempt 1/1`
Cancelling a workflow no longer tells the model that an agent which had already finished has no result
Reopening a chat after it compacted no longer marks a finished subagent's kept worktree read-only with a startup warning when the compacted chat still mentions that subagent; it is handled as it would be without compaction
After the disk fills while a message to a subagent is being saved, the session keeps saving checkpoints once the disk frees, instead of skipping them until it is reopened
The agent replies before it starts a background workflow, instead of ending its turn with no answer
A reply that a Monitor event started now keeps its dim source label row when the reply streams in over several seconds, not only when it arrives all at once
Cancelling a whole Workflow now shows "Stopped with the workflow before this agent finished." for each agent that was still running, instead of an empty outcome with no reason
`muse serve` now answers a turn start or steer that takes more than 30 seconds to acknowledge with its real result, instead of an internal error while the turn still runs
In `muse serve`, the model list row for a `--model` choice that no catalog lists now names its provider's profile, like that provider's other rows
The context meter now follows the selected model's limit when switching between cloud models
A session created by a `muse serve` host now records which build created it, so `/export trajectory` for such a session carries `session_build`
After the disk fills while a message to a subagent is being saved, retrying that message no longer makes the session skip every later checkpoint
Reopening a session no longer leaves out a turn that reused the same rules or instructions as a turn from before a mid-session checkpoint
A turn with hundreds of tool calls no longer stops a session's saved view from updating, which left the view unavailable after the session was resumed
In a session log written by an older build, a tool call that had returned its result before a crash keeps that result in the session view instead of having it replaced by the crash notice
When a settings or trust file cannot be used — malformed JSON, a directory in its place, or an unsupported version — the error now ends with a `Recovery:` line naming the file and the next step, instead of leaving the start at a dead end
On Windows, stopping a terminal-mode (`tty`) PowerShell session run without the sandbox, after its shell already exited, now also ends the programs it left running
The resume picker no longer re-reads and re-derives every session row on each refresh when the sessions folder path is not valid UTF-8
On Windows, cancelling a `!` shell command now also stops the programs it started before it shows as cancelled
The TypeScript SDK now reports a `muse serve` exit even when a process it started still holds its output, instead of waiting forever
In the TypeScript and Python SDKs, `session.events()` no longer repeats an event after the SDK fills a gap in delivery (or, in TypeScript, after `session.reload()` replays it), and an event stream now ends when the client closes instead of waiting forever
`/compact` works again in a chat that was started with developer instructions and reopened by a terminal without a `run.developer_prompt` setting, instead of answering that no compactable run is available
The start refusal for an unreadable `settings.json` now names its recovery on the next line (make the file readable with `chmod u+r` or remove it, or move a regular file out of the config directory's place; an absent `settings.json` runs on defaults)
After you pause and resume a workflow, its elapsed time no longer jumps back or restarts at zero, and agents that finished before the pause keep counting and keep their model, tokens and time
Status, usage and MCP cards keep their right border in line when a row holds Arabic text with a lam-alef pair
A named Workflow agent keeps its name after it starts, so editors connected through `muse acp` no longer switch its line to the agent's id
Forking a session after a background monitor wake no longer carries the parent session's startup context into the new session beside its own
`/new` and `/clear` no longer exit to the shell when the previous session is still closing
On Linux, a sandboxed command started without `XDG_RUNTIME_DIR` now finds `/run/user/<uid>` and shares the placeholder registry with commands that use it, so another command of the same user cleaning up at exit no longer lifts its denied path
After the disk fills while a subagent message is settled, closing that subagent no longer makes the session skip every later checkpoint
Stopping a Workflow from the Tasks drawer or `/workflows` now tells the agent you stopped it and not to relaunch it, instead of saying the runtime cancelled it
On Linux, an empty placeholder folder no longer stays behind in your project when two overlapping sandboxed commands block the same missing path
On Linux, a sandboxed command whose `XDG_RUNTIME_DIR` is set but empty now shares the placeholder registry under `/run/user/<uid>` with the other commands of its user, so its exit cleanup no longer lifts a sibling command's denied path
On Linux, memory freed by a compaction or a resume returns to the system within a few seconds instead of about half a minute
Sessions take slightly less disk space: the skill reminder no longer saves a decision record when it finds nothing to suggest, so `muse exec --json` no longer prints that line
An idle session uses less CPU keeping its saved-session list current: each check reads a saved session's file details once instead of three times
A long session keeps less in memory for shell commands and Monitors that have finished
Session logs are a little smaller: a model call and a background reminder no longer write a `scheduled` record, so `muse exec --json` no longer prints that line for them
