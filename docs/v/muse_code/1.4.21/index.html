Muse Code 1.4.21

發布日期：2026-11-21

繁體中文

新功能

/resume 即時標示等你輸入的對話

想接續之前的進度，卻得一個個點開才知道哪個工作階段正停下來等你回覆。現在執行 /resume 開啟清單時，需要你輸入的工作階段會直接加上標記，狀態一有變動也會即時更新。

打開通訊軟體時，以前得逐一點進聊天室才知道誰在等回覆，現在列表上直接亮出標記還會跟著即時刷新。
問題修復

提示詞附加與外掛指示上限調整

想在內建提示外補上自己的指令，或精簡模型看到的背景聲明，這版新增與放寬了幾項控制。 run.system_prompt_append 能把你的文字接在內建系統提示詞後面，上限 64 KiB，不會蓋掉原文。工作階段也能各自設定，恢復或分岔時會繼續保留。 prompt.surfaces 現在還能關掉工作區根目錄、權限模式、沙盒政策、能力政策與程式碼模式這五項固定聲明。關掉只改模型看到的文字，不會動到實際的沙盒（限制指令權限的隔離區）、核准流程或工具權限。 外掛提醒的指示檔上限從 16 KiB 提高到 32 KiB，超出時仍會略過並附上診斷。

以前想改固定交代只能整頁重寫，現在就像在說明書末尾貼便利貼，也能直接劃掉不想讓對方唸出的欄位。
問題修復

語言鎖定留給 Muse 模型並跨壓縮保留

用 Claude、GPT 或 Gemini 等非 Muse 模型對話時，現在不會再被強塞語言鎖定指令。切換成這些外部模型時，就算回覆文字換成別種語言或文字系統，Muse 也不再自動重新生成，只有 Muse 自家模型保留這兩項機制。 在 Muse 模型維持英文鎖定時，如果畫面輸出不小心溜出其他文字系統，以前只會拿同一份請求原封不動重問一次。現在改為附上重申鎖定的修正提示重試，每一步最多修正兩次，超過就把最後一次結果直接交給你。 設定或請求好工作階段語言後，就算中間經過上下文壓縮，Muse 也會把這份鎖定一路留到後續對話，不再只靠壓縮後的訊息重新猜測。

出國請隨行翻譯記錄筆記，以前每換新頁他就得重新猜你想寫哪國字，現在交代過一次就一路記著，偶爾寫偏還會當場拉回來。
新功能

啟動環境變數不讓金鑰流進殼層與監控

跑代理指令或背景監控時，有時不想讓自己的 META_API_KEY 順著執行環境一起被讀到。啟動 Muse 時設定環境變數（傳給程式讀取的背景設定值）MUSE_SHELL_DROP_META_API_KEY=1，或改設 true、yes，都能擋下這把金鑰。設定後，代理執行的指令、! 指令與 Monitor 指令都拿不到 META_API_KEY。 如果連上已經在跑的 Muse 伺服器，工作階段會直接沿用該伺服器的設定。由上述三類指令另外啟動的 Muse，也不會從它們身上拿到這把金鑰。

好比借朋友門禁卡去地下室拿東西，以前得把整串含自家大門鑰匙的鑰匙圈都交出去，現在先把大門鑰匙拔下來再遞過去。
問題修復

Windows 登入與信任檔限制其他帳號存取

多人共用同一台電腦，過去設定資料夾的權限會直接沿用下去，讓同機的別人也有機會打開。只要磁碟支援檔案權限，現在新建的 auth.json 與 trust.json 只會允許你的帳號、SYSTEM 和 Administrators 開啟。 每個 Windows 帳號必須改用自己的設定資料夾，請設定 XDG_CONFIG_HOME 來分開存放。如果其他帳號因此再也打不開原本的檔案，直接刪除該檔並重新登入即可。

就像把存摺和印章從客廳抽屜移進只認自己指紋的小保險箱，其他家人不能再順手打開，但也得各自準備專屬抽屜。
問題修復

修補 Git 符號連結與 Linux 沙盒漏洞

執行殼層與沙盒指令時，現在不能透過被替換的 Git 目錄連結寫入。Linux 沙盒在不限網路模式下，也不再把環境變數暴露在 bubblewrap 的指令列上。 工作階段進行中若把 Git 目錄換成 symlink（符號連結，指向另一個位置的捷徑檔），現在無法透過這個連結寫入，殼層指令會在排除該連結的情況下執行。 在 Linux 開啟不限網路模式的沙盒執行指令時，環境變數以前會直接暴露在 bubblewrap 的指令列上，同機其他程式用 ps 就能讀到。現在指令列不再顯示這些變數，指令本身照舊拿到相同環境。

就像以前把門牌換成假箭頭就能進屋、把密碼貼在信封外頭讓人偷看，現在這兩條漏洞都被封死，只有裡面的人能照常收信。
問題修復

Linux 沙盒多指令並行與路徑清理修復

同一個 Linux 使用者並排執行多個沙盒指令，封鎖路徑與暫存目錄現在會各自守好邊界。 啟動沙盒指令若沒設定 XDG_RUNTIME_DIR，或該變數為空字串，都會去找 /run/user/<uid> 共用同一份佔位登錄表。這樣同使用者的其他指令在結束清理時，就不會誤把別條指令封鎖的路徑一起放行。 當兩個重疊的沙盒指令同時擋下同一個不存在的路徑時，退場後也不會在你的專案裡留下空的佔位資料夾。 以前多指令重疊或缺少環境變數時容易誤解封鎖或遺留空資料夾，這些情況現在都已修好。

新功能

離開回顧與背景任務提示更快出現

把對話擱著去忙別的事，或讓背景任務自己跑完後，過去常得再補傳兩句才看得到進度回顧。 現在只要工作階段裡至少有一則訊息，你回來就會看到離開回顧；背景結果添上新回覆後還會再出現一次，不必再多等自己傳兩則訊息。 由背景代理、排程任務或目標結果啟動的回合結束後，也會顯示「Worked for」耗時行。 若回覆是由 Monitor 事件觸發，就算串流幾秒才輸出完畢，淡色的來源標記列也會留著，不再只有一次整段送達時才顯示。

想像請幫手在廚房燉湯，以前你得連問兩次他才報進度，現在回頭看一眼或他端出新菜，桌邊就會放好進度卡。
問題修復

對話壓縮功能與容量計顯示修復

長對話執行壓縮或換用不同雲端模型，過去常碰到容量計數字不降或壓縮指令失靈。 自動壓縮生效後，工作階段協定的用戶端介面上，容量計現在會立刻降到壓縮後的實際用量，不再一直拿整輪累計的 token（AI 處理與計費的文字單位）來算。在雲端模型之間切換時，容量計的上限也會跟著改用新模型的額度。 帶著開發者指示開始的對話，用沒有設定 run.developer_prompt 的終端機重開後，現在可以正常執行 /compact，不會再回報找不到可壓縮的執行紀錄。 壓縮後的對話若仍提到已結束的子代理人，重開後不會再把它的 worktree（工作樹，Git 讓同一專案平行開多份副本的功能）標為唯讀並跳出警告。現在它會比照未壓縮的對話正常接手。

行李箱把冬衣抽真空壓扁後，以前指針秤還停在壓縮前的舊數字，現在秤面馬上掉回實際重量，換新箱子也會跟著換刻度。
問題修復

Workflow 啟動回覆、計時與名稱修正

啟動或暫停重啟 Workflow，代理人的開場回覆、累計時間和卡片編號過去常對不上。 代理人現在會在啟動背景 Workflow 前先給你一個回覆，不再直接結束回合而留下空白。 暫停並恢復 Workflow 後，經過時間不再倒退或歸零，暫停前已結束的代理人也會繼續累計時間並保留模型與 token 紀錄。重新執行的代理人對話會像卡片一樣標示 attempt 2/2 這類正確的嘗試次數並列出前一輪，不再錯寫成 attempt 1/1。 透過 muse acp 連線的編輯器上，具名的 Workflow 代理人啟動後會留住原本名稱，不會被換成代理人的編號。 以前暫停重啟或用編輯器檢視進度常看到錯亂的數字與代號，這些問題現在都已修好。

問題修復

中止 Workflow 時的狀態與不重啟通知

手動中止整個 Workflow 後，畫面上與送給模型的結束通知過去常少寫關鍵原因。 現在取消進行中的 Workflow 時，對於取消前早就跑完的代理人，不會再誤向模型回報它沒有結果。當時還在跑的代理人，結果會顯示「Stopped with the workflow before this agent finished.」，不再留白。 如果從 Tasks 抽屜或輸入 /workflows 停掉 Workflow，程式會明確告訴代理人是你主動喊停且不要再重新啟動，不再寫成被執行環境取消。 不再把已完成的代理人回報成沒有結果，也會明確告知代理人是你主動停止、不要重新啟動。

問題修復

TypeScript SDK 連線控制與型別升級

給串接 TypeScript SDK 的開發者，這版強化了連線啟動、型別檢查與工作階段接續。 啟動連線支援取消或逾時控制，主機久未完成啟動會直接關閉，不再留在背景空轉。閒置時被主機卸載的工作階段能原地重載，保留狀態、處理函式與待處理對話，不必重開。 指令、請求與原始連線通知監聽已依協定結構加上型別。參數不符已列管方法的型別，或方法名稱混用已列管與未列管名稱，會先標記過時。原始連線上的泛型方法名稱也會如此；這些情況之後將改為編譯錯誤，想不帶型別傳送須放寬為字串型別。 當 muse serve 結束時，就算它啟動的程式還佔著輸出串流，SDK 也會回報結束，不再卡等。

跟寄快遞一樣，以前無人收件只能原地乾等，現在逾時就能撤單，斷線也能憑原本單號原地接續。
問題修復

SDK 事件串流支援子代理人並修正重複

在 TypeScript 與 Python SDK 追蹤代理進度，過去看不到子代理人的個別動作，重連也容易重複收到訊息或卡住。這版更新針對串接這兩種 SDK 的開發者擴充了事件串流功能。 訂閱工作階段事件時現在能開啟子代理人追蹤，串流會逐步送出每個子代理人的動作，並標明這筆事件屬於哪一個子代理人。 補齊遺漏事件或在 TypeScript 端重新載入並重播後，串流不會再重複吐出同一筆事件；用戶端關閉時，事件串流也會跟著結束，不再無限等待。

看多人協作的現場轉播時，以前分不清哪位助手在做什麼、重連還重播舊畫面，現在每個人動作都標清且不重複。
問題修復

muse serve 逾時與清單紀錄修正

用 muse serve 在背景託管對話服務，遇到久候指令或自訂模型過去容易碰到誤報錯誤或資料缺漏。 當開啟回合或調整方向的請求花超過 30 秒才回應時，只要回合還在執行中，muse serve 現在會等著傳回真正的處理結果，不再直接丟出內部錯誤。 在命令列傳入目錄未收錄的 --model 名稱時，模型清單裡那一行現在會像同提供者的其他項目一樣，清楚標出所屬提供者的設定檔名稱。 由 muse serve 主機建立的工作階段現在也會記下建立時的建置版本，之後執行 /export trajectory 匯出紀錄時就能帶有這份版本資訊。

打電話交代遠端櫃檯辦長任務時，以前對方超過期限沒回話就先掛斷報錯，現在願意等到辦完並把結果報回來。
問題修復

設定與信任檔無法讀取改附修復指引

想打開 Muse 卻被擋在門外，只因為裡頭的 JSON 寫壞、版本不合或權限不夠，過去畫面只會留下一條死胡同。 現在遇到這類錯誤時，錯誤訊息末尾會多出一行 Recovery:，點名出問題的檔案與下一步做法；這涵蓋 JSON 格式錯誤、設定位置被資料夾佔用，或不支援的檔案版本。 若是 settings.json 權限不足導致無法啟動，下一行會列出解方：用 chmod u+r 補上權限、刪除該檔，或把佔住設定目錄的檔案移走。如果原本就沒有 settings.json，Muse 會直接套用預設值啟動。

以前車子發不動，儀表板只亮一個紅燈讓你自己猜；現在直接亮出哪顆零件鬆了、拿幾號扳手去轉，照著做就能發動。
問題修復

磁碟寫滿清出空間後恢復儲存檢查點

硬碟空間在儲存或結算子代理人訊息時塞滿，過去可能讓後續檢查點存檔一路停擺。 如果在保存要給子代理人的訊息時磁碟剛好寫滿，只要清出空間，工作階段之後就會繼續正常儲存檢查點，不必等到重開工作階段才恢復。 就算之後重試那則先前寫入失敗的訊息，或在訊息結算時遇上磁碟已滿後再關閉該子代理人，工作階段都不會再跳過後續所有的檢查點。 儲存或結算子代理人訊息時遇上磁碟寫滿，現在清出空間就能接續存檔，後續重試訊息或關閉子代理人也不會讓檢查點停存。

問題修復

工作階段重開、分岔與切換對話修復

聊到一半想另起新線、清掉重來，或把舊紀錄叫回來接續，過去常遇到少了一回合、畫面卡死或直接退回終端機。 重開工作階段時，如果某個回合重複使用了中途檢查點之前的規則或指示，該回合現在不會再被漏掉。即使單一回合呼叫做過上百次工具，工作階段的存檔檢視也會照常更新，不再造成重開後無法查看。 若是讀取舊版建置寫下的工作階段紀錄，崩潰前已經回傳結果的工具呼叫在檢視畫面裡會保留原本結果，不再被換成崩潰通知。 被背景監控喚醒後再分岔出新工作階段時，新對話只會帶入自己的啟動背景，不會把父工作階段的啟動背景也一併帶進來。執行 /new 或 /clear 切換對話時，就算上一個工作階段還沒關完，也不會再直接跳出回到殼層。 以前切換或重開對話常碰上缺頁或閃退，現在對話紀錄與切換過程都能完整接續。

問題修復

跨版本對話紀錄的權限與評估格式相容

不同版本的 Muse 讀取同一份對話存檔，不能因為欄位變動就把權限看寬或擋掉新問題。 這版先替跨機執行指令的「此工作階段允許」選項做好儲存格式準備，目前還沒有任何對話寫入這欄。往後若由不認得新欄位的版本讀取這類紀錄，程式會直接拒讀，避免把原本縮小的權限誤判成更寬的授權。 自動化評估執行產生的對話現在會記錄每次執行的設定方式。較早的版本會略過這份紀錄，而更舊的版本在切換模型後可能會拒絕接受新提示，只要更新 Muse 就能解決。

像新版表格多了一欄限制條件，如果舊印表機認不得那一欄就乾脆拒印，免得把「限本人簽收」印成「誰都能領」。
問題修復

工作階段刪除清理與紀錄檔瘦身

一直開著 Muse 跑任務或反覆執行指令，磁碟裡累積的舊版紀錄與冗餘日誌容易越堆越大。 刪除工作階段、達到 session_retention_days 到期或清理空工作階段，Muse 現在會把其他版本留下的同份歷史一併清掉，不再留在磁碟上。 工作階段索引的預寫日誌（寫入索引前先記下變更的紀錄檔）預設上限設為 256 MiB，讓常開機的機器不會越長越大，清單顯示照舊。 技能提醒若沒有任何建議要給，就不再寫入判斷紀錄；模型呼叫與背景提醒也不再寫入排程紀錄。這讓工作階段更省空間，執行 muse exec --json 時也不會再印出這兩類多餘輸出。 過去常駐執行容易在硬碟留下舊版殘留與空白紀錄，現在容量與輸出都會精簡許多。

新功能

降低閒置、長對話與重開時的資源消耗

掛著對話不動、跑長任務或刷新清單，過去常常默默耗掉多餘的 CPU 與記憶體。 在 Linux 上，壓縮或恢復工作階段所釋放出的記憶體，現在幾秒內就會還給系統，不再得等大約半分鐘。跑得比較久的工作階段，對於已經結束的殼層指令與 Monitor，也會減少記憶體佔用。 工作階段閒置時為了更新已存對話清單，每次檢查現在只會讀取檔案細節一次而不是三次，能降低 CPU 負擔。當工作階段資料夾路徑不是合法的 UTF-8（一種常見的文字編碼格式）時，恢復選擇器每次刷新也不會再重頭重讀並重算每一列。 以前掛著不動或處理舊紀錄常白耗電腦效能，現在能減少 CPU 與記憶體占用，並更快把釋放的記憶體還給系統。

新功能

Windows 缺 Unix 指令改直接給替代名

在 Windows 上讓代理跑命令列工作，PowerShell 本身沒有 head、tail、grep 或 wc 這類 Unix 指令，一叫就出錯。現在遇到這類失敗，回傳結果會直接點名該改用哪一個 PowerShell 指令，讓代理一步就能改對重跑。

新功能

Windows 特定殼層操作補上殘留程式清理

在 Windows 操作 ! 指令或沒開沙盒的終端機模式工作階段，過去按下停止後常還有背景程式在背後繼續跑。 現在在 Windows 取消 ! 殼層指令時，顯示已取消前就會先把該指令啟動的程式一併關掉。若是結束沒有沙盒的終端機模式 tty 的 PowerShell 工作階段，就算裡面的殼層早就退出了，它原本留下的程式現在也會跟著一起結束。

以前關掉廚房總開關，抽油煙機卻還在後面空轉；現在按下停止鈕，它牽出來的所有小馬達都會一起斷電停住。

修正阿拉伯文導致卡片右框線錯位

你可能會打開狀態、用量或 MCP（Model Context Protocol，讓 AI 連接外部工具的協定）資訊欄。只要裡頭出現帶 lam-alef 連字的字句，右側邊界過去就會跟著歪斜。這個排版問題已經修好，現在遇到這類阿拉伯文時，右框線都能整齊對成一條直線。

FEATURE

/resume Marks Chats Waiting for Input Live

When picking up where you left off, you used to have to open each session one by one to see which one had paused for your reply. Now, when you run /resume to open the list, sessions that need your input are marked directly, and their status updates live whenever it changes.

In a messaging app, you used to have to open each chat one by one to see who was waiting for a reply, whereas now the list lights up with a badge and refreshes live.
BUGFIX

Prompt Appending and Plugin Instruction Limit Updates

To add your own instructions alongside the built-in prompt or trim the background statements the model sees, this release adds and relaxes several controls. run.system_prompt_append appends your text after the built-in system prompt, up to 64 KiB, without overwriting the original text. Sessions can also set their own values, which stay intact when resumed or forked. prompt.surfaces can now also turn off five fixed statements: workspace root, permission mode, sandbox policy, capability policy, and code-mode profile. Turning them off changes only the text the model sees, without touching the actual sandbox (an isolated area that restricts command permissions), approval flow, or tool access. The instructions file limit for plugin reminders increases from 16 KiB to 32 KiB, and larger files are still skipped with a diagnostic.

Instead of rewriting an entire page just to tweak standard instructions, you can now stick a note at the end of the manual and cross out any fields you do not want read aloud.
BUGFIX

Language Pinning Kept for Muse Models and Across Compaction

When chatting with non-Muse models such as Claude, GPT, or Gemini, language-pinning instructions are no longer forced into requests. When switching to these external models, even if a reply switches to another language or script, Muse no longer regenerates it automatically; only Muse's own models keep both behaviors. When a Muse model has an English pin and visible output accidentally slips into another script, it used to simply resend the exact same request once. Now it retries with a corrective prompt restating the pin, up to two corrections per step, and delivers the final attempt as-is if it still slips. Once a session language is set or requested, Muse keeps that pin through context compaction into later turns instead of guessing it again solely from the compacted messages.

Think of an interpreter taking notes on a trip abroad: before, they had to guess which language you wanted on every new page, whereas now they remember your choice throughout and correct themselves on the spot if they slip.
FEATURE

Startup Environment Variable Keeps Key Out of Shell and Monitor

When running agent commands or background monitoring, you may not want your META_API_KEY read along with the execution environment. Starting Muse with the environment variable (a background setting passed to a program) MUSE_SHELL_DROP_META_API_KEY=1, or setting it to true or yes, blocks this key. Once set, commands run by the agent, ! commands, and Monitor commands will not receive META_API_KEY. If you connect to an already running Muse server, the session follows that server's setting directly. Any Muse instance started by one of those three command types will not receive the key from them either.

When lending a friend a keycard to grab something from the basement, you used to have to hand over your whole keyring with your front-door key on it, whereas now you take the front-door key off first.
BUGFIX

Windows Sign-In and Trust Files Restrict Other Accounts

When multiple people share the same computer, config folder permissions used to be inherited directly, giving others on the same machine a chance to open them. Where the drive supports file permissions, newly created auth.json and trust.json files now allow only your account, SYSTEM, and Administrators to open them. Each Windows account must use its own config folder by setting XDG_CONFIG_HOME to store files separately. If another account can no longer open the original file as a result, simply delete that file and sign in again.

Moving your bankbook and seal from a living room drawer into a small safe that only recognizes your fingerprint keeps other family members from casually opening them, though everyone now needs their own drawer.
BUGFIX

Fixes for Git Symlink and Linux Sandbox Vulnerabilities

When running shell and sandboxed commands, writing through a swapped Git directory link is no longer allowed. In unrestricted network mode, the Linux sandbox also no longer exposes environment variables on bubblewrap's command line. If a Git directory is swapped for a symlink (a shortcut file pointing to another location) during a session, writing through that link is now blocked, and shell commands run without it. When running sandboxed commands on Linux in unrestricted network mode, environment variables used to appear directly on bubblewrap's command line, where other processes on the same machine could read them with ps. Now the command line no longer shows those variables, while the command itself still receives the same environment.

Before, swapping a door sign for a fake arrow let someone walk right in, and taping a password to the outside of an envelope let others peek; now both holes are sealed so only those inside receive mail as usual.
BUGFIX

Fixes for Concurrent Linux Sandbox Commands and Path Cleanup

When the same Linux user runs multiple sandboxed commands side by side, denied paths and temporary directories now stay within their own boundaries. If a sandboxed command starts without XDG_RUNTIME_DIR set, or with it set to an empty string, it falls back to /run/user/<uid> and shares the same placeholder registry. That way, other commands from the same user cleaning up at exit will not accidentally lift a path denied by another command. When two overlapping sandboxed commands block the same missing path at the same time, they no longer leave an empty placeholder folder behind in your project after exiting. Issues where overlapping commands or missing environment variables could accidentally lift blocks or leave empty folders behind are now fixed.

FEATURE

Away Recap and Background Task Prompts Appear Sooner

After stepping away from a chat or letting a background task finish on its own, you used to have to send two more messages before seeing a progress recap. Now the away recap appears as soon as you return to a session with at least one message, and again after a background result adds new replies, without waiting for two more messages from you. Turns started by a background agent, scheduled task, or goal result now also display the "Worked for" elapsed-time line when they finish. When a reply is triggered by a Monitor event, its dim source label row now stays visible even when the reply streams in over several seconds, instead of appearing only when it arrives all at once.

Picture asking a helper to simmer soup in the kitchen: before, you had to ask twice to get a status update, whereas now a progress card sits by the table as soon as you glance back or they bring out a new dish.
BUGFIX

Fixes for Chat Compaction and Context Meter Display

When compacting long chats or switching between cloud models, the context meter used to stay stuck or the compaction command would fail. After automatic compaction takes effect, the context meter in session-protocol client interfaces now drops immediately to the compacted actual usage instead of continuing to count the summed tokens (the text units AI processes and bills by) from the whole run. When switching between cloud models, the context meter's limit also updates to use the new model's quota. Chats started with developer instructions and reopened in a terminal without run.developer_prompt set can now run /compact normally instead of reporting that no compactable run is available. If a compacted chat still mentions a finished subagent, reopening it no longer marks that subagent's worktree (a Git feature for opening multiple parallel copies of the same project) as read-only with a warning. It is now handled normally just like an uncompacted chat.

After vacuum-sealing winter coats in a suitcase, the dial scale used to stay stuck on the old pre-compression number, whereas now the needle drops to the actual weight right away and switches markings when you change suitcases.
BUGFIX

Fixes for Workflow Startup Replies, Timing, and Names

When starting or pausing and resuming a Workflow, an agent's opening reply, elapsed time, and card attempt numbers used to mismatch. The agent now sends you a reply before starting a background Workflow, instead of ending its turn blank. After pausing and resuming a Workflow, elapsed time no longer jumps back or resets to zero, and agents that finished before the pause continue counting time and keep their model and token records. A rerun agent's conversation now displays the correct attempt count matching its card, such as attempt 2/2, and lists the earlier round instead of wrongly showing attempt 1/1. In editors connected through muse acp, a named Workflow agent keeps its original name after starting instead of being replaced with the agent's ID. Issues where pausing and resuming or viewing progress in an editor showed mismatched numbers and IDs are now fixed.

BUGFIX

Workflow Stop Status and No-Relaunch Notice

Manually stopping an entire Workflow used to leave key reasons missing from both the screen and the completion notice sent to the model. Now, cancelling an active Workflow no longer mistakenly tells the model that an agent that had already finished has no result. Any agent still running at the time shows "Stopped with the workflow before this agent finished." instead of a blank outcome. If you stop a Workflow from the Tasks drawer or by running /workflows, it now tells the agent you stopped it and not to relaunch, rather than saying the runtime cancelled it. Finished agents are no longer reported as having no result, and agents are clearly told you stopped them and not to relaunch.

BUGFIX

TypeScript SDK Connection Control and Type Upgrades

For developers integrating the TypeScript SDK, this release strengthens connection startup, type checking, and session resumption. Starting a connection now supports cancellation or timeouts, shutting down a host that takes too long to start instead of leaving it idling in the background. A session unloaded by the host while idle can reload in place, keeping its state, handlers, and pending turns without starting over. Commands, requests, and raw-connection notification listeners are now typed from the protocol schema. Calls whose parameters do not match a listed method's type, or method names that mix listed and unlisted names, are marked deprecated first. The same applies to generic method names on a raw connection; these will become compile errors later, so widen the name to string to keep sending untyped. When muse serve exits, the SDK reports the exit even if a process it started still holds the output stream, instead of waiting forever.

Just like sending a courier package, if nobody answered before you could only wait around, whereas now you can cancel on timeout and resume with the same tracking number if disconnected.
BUGFIX

Subagent Support and Duplicate Fixes in SDK Event Streams

Tracking agent progress in the TypeScript and Python SDKs previously hid individual subagent actions and could repeat messages or hang on reconnect. This release expands event streaming for developers integrating either SDK. When subscribing to session events, you can now enable subagent tracking so the stream delivers each subagent's actions step by step, tagged with the subagent each event belongs to. After filling in missed events, or after reloading and replaying in TypeScript, the stream no longer emits the same event twice; when the client closes, the event stream ends with it instead of waiting forever.

Watching a live broadcast of a team at work used to leave you guessing which helper did what and replaying old footage on reconnect, whereas now everyone's actions are clearly labeled without repeats.
BUGFIX

muse serve Timeout and Listing Fixes

Hosting conversation services in the background with muse serve previously risked false errors or missing data on slow commands or custom models. When a request to start or steer a turn takes over 30 seconds to respond, muse serve now waits to return the real result as long as the turn is still running, instead of throwing an internal error. When passing a --model name on the command line that is not listed in a catalog, its row in the model list now clearly shows its provider's profile name, just like other entries from that provider. Sessions created by a muse serve host now record the build that created them, so running /export trajectory later includes that build info.

Calling a remote counter with a long task used to mean they hung up with an error once a deadline passed without a reply, whereas now they wait until the job is done and report back.
BUGFIX

Recovery Guidance for Unreadable Settings and Trust Files

Getting locked out of Muse because of broken JSON, an unsupported version, or insufficient permissions used to leave you at a dead end. Now, when such an error occurs, the message ends with a Recovery: line naming the file and the next step; this covers malformed JSON, a directory occupying the config path, or an unsupported file version. If unreadable permissions on settings.json prevent startup, the next line lists the fix: add permissions with chmod u+r, delete the file, or move the file blocking the config directory. If settings.json does not exist at all, Muse starts with defaults.

Previously, when a car wouldn't start, the dashboard only lit a red warning light and left you guessing; now it shows which part is loose and which wrench to grab so you can follow along and get running.
BUGFIX

Checkpoint Saving Resumes After Freeing Full Disk

Running out of disk space while saving or settling a subagent message used to stall all subsequent checkpoint saves. If the disk fills up while saving a message for a subagent, the session now resumes saving checkpoints normally once space is freed, without needing to reopen the session. Even if you later retry that failed message, or close the subagent after hitting a full disk during message settlement, the session no longer skips all later checkpoints. When the disk fills while saving or settling a subagent message, freeing space now lets saving continue, and retrying the message or closing the subagent no longer halts checkpoints.

BUGFIX

Fixes for Session Reopening, Forking, and Switching

Starting a new thread mid-chat, clearing to start over, or pulling up an old log to continue used to drop a turn, freeze the view, or kick you back to the terminal. When reopening a session, a turn that reused rules or instructions from before a mid-session checkpoint is no longer left out. Even if a single turn makes hundreds of tool calls, the session's saved view still updates normally instead of becoming unavailable after reopening. When reading a session log written by an older build, a tool call that had already returned its result before a crash keeps that result in the view instead of being replaced by a crash notice. When forking a new session after a background monitor wake, the new chat only carries its own startup context and no longer pulls in the parent session's startup context as well. Running /new or /clear to switch chats no longer exits to the shell even if the previous session is still closing. Where switching or reopening chats used to hit missing pages or sudden exits, both chat history and switching now continue smoothly.

BUGFIX

Cross-Version Chat Log Permission and Evaluation Compatibility

When different versions of Muse read the same saved chat, field changes must not widen permissions or prevent new prompts from being accepted. This release prepares the storage format for an "allow for this session" choice on commands that run on another machine, though no chats write this field yet. Going forward, if a version that does not recognize the new field reads such a record, it refuses to load it rather than misreading a narrowed permission as a wider grant. Chats generated by automated evaluation runs now record how each run was set up. Earlier versions skip this record, while much older versions may refuse new prompts after switching models, which updating Muse resolves.

Imagine a new form adding a restriction column: if an old printer doesn't recognize that column, it simply refuses to print rather than turning "recipient signature required" into "anyone can pick up."
BUGFIX

Session Deletion Cleanup and Log Trimming

Keeping Muse open for tasks or running commands repeatedly used to pile up old-version history and redundant logs on disk. When deleting a session, reaching session_retention_days expiry, or cleaning up an empty session, Muse now removes the saved history for that session left by other versions as well, instead of leaving it on disk. The session index's write-ahead log (a record of changes saved before updating the index) now defaults to a 256 MiB cap so it stops growing on always-on machines, while listings stay unchanged. Skill reminders no longer save a decision record when they have nothing to suggest, and model calls and background reminders no longer write scheduled records. This saves space for sessions and stops muse exec --json from printing those two extra lines. Where long-running use used to leave old remnants and empty records on disk, both storage and output are now much leaner.

FEATURE

Lower Resource Use When Idle, Long-Running, or Reopening

Leaving a chat idle, running long tasks, or refreshing lists used to quietly burn extra CPU and memory. On Linux, memory freed by compacting or resuming a session now returns to the system within a few seconds instead of about half a minute. Longer-running sessions also keep less in memory for finished shell commands and Monitors. When a session is idle and updating its saved-chat list, each check now reads file details once instead of three times, cutting CPU overhead. When the sessions folder path is not valid UTF-8 (a common text encoding format), the resume picker no longer re-reads and re-derives every row from scratch on each refresh. Where sitting idle or handling old logs used to waste system resources, CPU and memory usage are now lower and freed memory returns to the system faster.

FEATURE

Missing Unix Commands on Windows Now Return PowerShell Alternatives

When you run command-line tasks through an agent on Windows, PowerShell lacks Unix commands like head, tail, grep, or wc, so calling them fails immediately. Now, when this kind of failure happens, the returned result directly names which PowerShell command to use instead, letting the agent fix the command and rerun it in one step.

FEATURE

Leftover Process Cleanup Added for Specific Windows Shell Operations

When running ! commands or unsandboxed terminal-mode sessions on Windows, background programs often kept running after you hit stop. Now, when cancelling a ! shell command on Windows, the programs it started are shut down before it shows as cancelled. When stopping an unsandboxed terminal-mode tty PowerShell session, any programs it left behind now exit along with it, even if the shell inside had already exited.

Shutting off the kitchen's main breaker used to leave the range hood spinning in the background; now, pressing the stop button cuts power to every small motor wired to it and stops them together.
BUGFIX

Fixed Right Border Misalignment Caused by Arabic Text on Cards

You might open the status, usage, or MCP (a protocol for connecting AI to external tools) info cards. Whenever a line inside contained a phrase with a lam-alef ligature, the right border used to shift out of line. That layout issue is now fixed, so the right border stays neatly aligned in a straight line when displaying this kind of Arabic text.
