Muse Code 1.4.17

發布日期：2026-11-13

繁體中文

問題修復

代理遇阻改為先問你，並調整分支建置與表單回傳

當你交辦一串任務給 Muse，遇到下載被擋或建置失敗時，它不再硬撐到最後才回報。

好比請木工到府組裝，缺零件當場問你、舊版做不成換新圖重裁，修到妥當再等你親自按下確認。

只要網路政策拒絕某個步驟所需的下載，Muse 會在執行其他步驟前立刻問你，不再探測其他來源或拖到結案報告才寫出阻礙。當本機檢出版本（checkout）落後且建置失敗時，它會改在最新分支上建置並測試。只要失敗訊息點出解法，Muse 會持續做到套用或提出該解法為止；瀏覽器應用程式的表單也改成等你親自點擊後才回傳結果，不再等待背景步驟。

新功能

代理動到環境設定或背景服務前會先詢問你

請代理幫忙寫一個小工具時，你大概只想讓它在專案裡跑起來，不想整台電腦的設定跟著被改。

就像新來的助理幫你整理辦公桌，如果要換掉常用印章、改大門鑰匙或請人駐點收發室，一定先問過你才敢動手。

當你請 Muse 編譯一個新工具並準備試跑時，只要遇到四種你沒開口要求的改動，它現在都會先問過你再做。這包括把剛產出的程式放進 PATH（系統尋找可執行指令的路徑清單），或是取代、遮蔽原本已經存在的指令。若它需要修改終端機啟動設定檔（shell start-up files），或是在系統安裝背景服務，也一律會先徵求同意。

問題修復

/goal 摘要印出前會移除隱藏控制字元

跑完長任務查看 /goal 摘要時，畫面上呈現的文字有時是由模型產生的。

宛如電視台播出跑馬燈前會先濾掉遙控訊號，不讓訪客提交的文字順手關掉棚內螢幕或亂切頻道。

過去若模型寫出的目標文字夾帶特殊指令，可能讓終端機標題被改掉、整個畫面被清空，甚至游標莫名移動。現在 /goal 摘要在印到畫面前，會先把不可見的終端機控制字元（用來操控游標或清除畫面的隱藏編碼）全數移除，讓模型寫出的目標文字無法干擾終端機畫面。

新功能

舊版程式無法開啟曾連線至其他機器的對話

如果你同時在多台電腦使用 Muse，準備接續先前的跨機工作紀錄前先確認一下版本。比這一版更舊的 Muse 程式，無法開啟較新版曾連線或嘗試連線到另一台機器執行指令的對話。當你在舊版透過編號恢復，或在工作階段選擇器裡點選這類對話時，舊版可能會自行另開一個本機工作階段（session），讀取舊紀錄並改在這台電腦繼續執行。

如同舊款設備讀不懂跨廠連線過的工作單，可能會直接在本地廠房照紀錄開工，結果步驟全對錯了場地。

重新開啟這類對話前請先更新應用程式，因為裡面的工作可能是為另一台機器寫的，其他對話則不受影響。

新功能

長對話視窗容量控管與閒置記憶體歸還調整

對話越聊越長時，Muse 對模型的上下文視窗（模型單次能處理的文字容量上限）與系統記憶體多了三項應對。

就拿書桌桌面來說，桌面快滿時會依剩餘面積挑出剛好的紙張大小，真的放不下就提醒換張新桌，清掉的廢紙也會盡快收走。

當模型有明確的視窗大小時，單輪對話會把向模型請求的輸出量縮減到視窗剩餘空間以內，避開長對話裡多數因請求過大導致的錯誤。 若該輪內容依然塞不進視窗，畫面的提示訊息現在會直接告訴你可以開啟新的工作階段。 當工作階段進入閒置狀態時，先前壓縮對話清出來的記憶體，現在大約半分鐘後就會歸還給系統，不再像以前常常佔住好幾分鐘。

新功能

工作流程壓縮重開與子任務額度計算調整

使用自動化工作流程（workflow）處理多步驟任務時，保存與用量計算有了三項調整。 已儲存的工作流程，就算先經過對話壓縮並重新開啟工作階段，現在依然保留在清單裡供你恢復執行。 若工作流程曾寫入一筆失敗的狀態檢查，舊版應用程式會無法恢復該流程，需要更新應用程式才能接續。 工作流程的 token（AI 處理與計費的文字單位）預算與子任務用量，現在會把子任務的全部工作都算進來，不再只計入第一輪；以前壓縮後找不到流程或只算首輪用量的問題都隨之消除。

新功能

工作階段協定新增子代理停止請求與結果狀態標記

開發串接 Muse 工作階段協定（session protocol）的用戶端時，現在多了三個追蹤與控管子代理的訊號。

想成接力賽場邊的計分板，誰被喊停、誰剛把接力棒交回主將手裡，以及哪筆舊成績已被重跑蓋過，全都照時間點標示。

協定新增實驗性的 subagent/workStop 請求，能像終端機介面本身的停止鈕一樣停掉子代理（主代理派出去分擔任務的助手），讓代理知道這是使用者喊停的。 每當工作階段讀取子代理結果時，用戶端會在該位置收到 subagentResult 項目，附帶畫面看見時的 completed、failed 或 cancelled 狀態，能在父代理讀取處顯示結果。 當子代理在該結果之後又啟動新嘗試，原本 subagent 項目的 result 會帶上 superseded: true，讓用戶端直接從控制狀態判定現況。

新功能

TypeScript 與 Python SDK 新增事件串流與自訂查詢介面

用 TypeScript 或 Python SDK 幫 Muse 寫外掛或用戶端介面時，接取事件流與實驗功能現在多出幾條新路。

彷彿收看賽事文字轉播，主播只推送剛變動的比數行數，不用每球都重傳整場紀錄，想查冷門數據也能透過專用通道直接調閱。

在 TypeScript SDK 中，FoldExtension 的 hook（特定事件發生時被觸發的小程式）現在可監看工作階段彙整時的自訂通知與主機層級事件。 兩個 SDK 都支援用 session.events() 串流輸出每筆新事件對工作階段的變化，方便局部更新畫面。 兩個 SDK 也新增 MuseClient.request 送出未封裝查詢；啟動時若帶入 experimentalApi: true，command 與 request 就會送出實驗性方法。

問題修復

TypeScript 與 Python SDK 修正錯誤原因回報與重試行為

透過 TypeScript 與 Python SDK 串接 Muse Code 時，遇上主機終止或過載的回報與重試方式已經調整。 若呼叫因主機程序（host process）終止而失敗，錯誤原因會附上結束代碼或訊號及錯誤輸出尾段；等待程序結束最久會晚 2 秒回報失敗，且有原因不代表工作階段可恢復。 指令收到帶 retryable: false 的 overloaded 或 backpressured 回應時不再自動重送，沒帶旗標仍會重試。 SDK 主機錯誤訊息所附的相容性連結，現在能正確打開相容性頁面。 submitFeedback 與 submit_feedback 不再為 feedback/submit 加 commandId，遇 backpressured 或 overloaded 也不重送，每次呼叫只送一次。

新功能

muse serve 支援在技能指令中夾帶多段影片

串接 muse serve 開發介面時，現在不用把影片跟技能指令拆成兩趟送出。

假想你把幾段行車紀錄器短片連同檢查清單交給技師，每段影片都照順序貼上編號，對照項目就能一段段看。

當使用者想讓工具依序檢查好幾段操作錄影並套用同一個分析技能時，用戶端只要在單次 turn/start 請求中，將技能項目與多個影片項目一起送出即可。不需另外手動拼字串，每段影片的 [Video #N] 標籤就會像現有的圖片標籤一樣，依序加入該技能的參數當中。

問題修復

工作階段協定改進游標版本控管與異常原因回報

與背景程式互動遇到舊游標或紀錄檔異常時，用戶端透過工作階段協定或 muse serve 收到的訊息不再含糊帶過。 畫面游標（view cursor）現改以 v10: 格式核發，舊格式游標會被拒絕一次並附上標準的「reopen without a cursor」指引。舊版存下的畫面快取（把查過的結果暫存起來直接用）也會在首次使用時重建，免得用戶端漏讀或誤讀事件。 若工作階段紀錄在 Muse 外部被刪除或替換，之後被協定拒絕的子代理中斷、停止、關閉或讀結果操作，會直接說明真正原因，不再誤報為變更無法儲存。 在 muse serve 中，若於恢復對話後歷史紀錄還在重建時送出指令給子代理，即使當下無法存檔，也會回報子代理忙碌中並可重試，不再針對沒執行的指令報成存檔失敗。

問題修復

讀取 settings.json 或 trust.json 失敗時改給明確處置

專案或本機的設定檔讀不到或缺少欄位時，你需要知道該怎麼處理。 若 trust.json 讀不到，muse serve 的信任工作階段會將額外資料夾列為未受信任並照常開啟。 當 settings.json 缺 schema_version 時，會提示補進 "schema_version": 1，不再只報解析錯誤。 若 settings.json 讀不到，hook/list 查詢 hook（特定事件發生時被觸發的小程式）會附讀取錯誤與恢復指引拒絕，不再報成零個。muse resume <id>、muse exec --session-id <id> 以相同錯誤與指引停止續接；全新啟動的 muse、muse exec 仍因權限設定檔而拒絕；不跑 hook 的指令仍附警告照預設值繼續。

問題修復

工作階段清單載入、選擇器焦點與旁支對話標示調整

在清單裡翻找或接續過去的工作階段時，這版修正了三個容易鎖檔、按錯或看混的細節。 工作階段清單現在預設分兩階段執行，清單內容本身不變，但載入長清單時不會一路咬住紀錄檔不放；不過原本就非常龐大的紀錄檔目前還不會因此縮減體積。 恢復工作階段失敗並跳回選擇器時，只要清單列出你剛才點選的那一筆，游標就會立刻選中它，馬上按 Enter 不會再誤開成別的對話。 執行 muse sessions 時，擱置在旁的分支對話現在會標記為所屬對話的分支（sideOf），不再像匿名工作階段一樣並列在旁。過去翻長清單咬住檔案、重試按 Enter 開錯對話，以及找不到分支來源的情況都能避開。

問題修復

恢復與重開工作階段不再因檢查點或設定存檔失敗中斷

重開舊對話接續工作時，這版清掉了四個容易卡關或讓對話消失的狀況。 必須轉進新工作階段來延續的舊對話，即使最新檢查點寫在兩輪之間，恢復時也不再失敗，原本的對話內容會完整留住。 用 --resume、--continue 或 /resume 重開工作階段時，如果先前存下的子代理狀態讀不到，展開的歷史紀錄不再重複列出先前的子代理。 若某一輪的設定當初沒有存成功，下一輪又沿用了相同的規則或指令，現在重開工作階段也不再因此失敗。 分岔出去（forked）的工作階段若在寫入工作區資訊前就已執行過，下次恢復時會自動補認該工作區，讓選擇器列在目前工作區底下，不再因缺漏中繼資料被藏起來。

問題修復

修正任務執行期間的排隊提示、核准卡與輸入列顯示

對話裡有任務正在跑或剛在背景完成時，提示詞送出與畫面顯示都修正了常見錯亂。 排在進行中輪次後面的提示詞，現在會帶著完整文字送進 UserPromptSubmit 的 hook（特定事件發生時被觸發的小程式），不再送出空白內容。 背景任務結束後發出的工作階段訊息，現在都能正常核准。待核准卡片上也會把背景任務的觸發來源與傳送者分開顯示。 從 Tasks 抽屜或使用 /stop all 停掉任務時，你的下一則訊息底下不會再莫名多出第二行輸入提示列。

問題修復

製作瀏覽器遊戲時依你指定的技術堆疊開發

想請 Muse 做一款瀏覽器小遊戲時，這項調整讓它不再只會用最陽春的方式硬寫。

好似拿著指定布料請裁縫師做西裝，對方不再一律用帆布縫製，而是照你挑選的布料裁剪。

當你在對話裡指定要用特定框架來做遊戲，過去它往往還是直接產出純 HTML 檔案。現在只要你在請求中點名想要的技術堆疊（stack，建置應用的工具與框架組合），瀏覽器遊戲就會依你指定的堆疊來開發，不再一律做成純 HTML 檔。

問題修復

內容檢查報告改將草稿專用項目獨立分欄列示

整理網站文章或文件附件並跑一份區分已發布與未發布內容的報告時，過去常怕把草稿素材誤判成廢棄物。代理回報完工前，以前容易把只出現在未發布內容裡的項目寫成「未使用」，或乾脆沒列進去。現在 Muse 會提示代理在宣告完成前重跑一次檢查，將僅供未發布內容使用的項目獨立列在僅限草稿的標題底下，不再誤判或遺漏。

拿專櫃盤點來說，還在後台籌備的新品配件會單獨列成預備清單，既不當作沒用的雜物，也不會被漏寫。
問題修復

讀取截斷的 JPEG 圖片時會直接提示檔案損毀

把下載到一半或複製不全的圖片丟給 Muse 分析時，以前常得等請求送出後才整個被退回。

猶如寄包裹前先檢查外箱，發現箱底早已破洞就在出發前退件，不必花一趟運費送到對方門口才被拒收。

以前讀取一張尾端被截斷的 JPEG 圖片時，工具仍會把這張殘缺的圖檔送給模型，結果整筆請求遭模型拒絕。現在只要讀到檔案尾端不完整的 JPEG，本地就會直接中止並回報「the file may be damaged or invalid」（檔案可能已損毀或無效），不再把壞圖送給模型。

新功能

外掛技能關閉後不會因作者搬移資料夾而重開

如果你曾經關掉某個外掛（plugin，擴充工具功能的套件）裡自己不想要的技能，更新外掛時現在多了一層保障。過去外掛作者一旦搬動了該技能在套件內的資料夾位置，當你更新完外掛，原本關掉的設定就未必能繼續對上。現在即使作者改變資料夾路徑且你完成外掛更新，這項被你關閉的外掛技能依然會維持關閉。

跟退訂電子報一樣，就算發行商後來換了部門並更新架構，你當初關掉的選項依然維持關閉。
新功能

macOS 版改善沙盒內 SSH 連線與鑰匙圈鎖定提示

在 Mac 上使用遠端連線或從 SSH 登入操作 Muse Code 時，這版補齊了兩個會讓人卡在門外的情況。在 macOS 的沙盒（sandbox，限制程式權限的隔離環境）裡執行的終端機指令，現在可以查詢目前的使用者名稱，讓 ssh 像在沙盒外一樣正常運作。當 Mac 在啟動 Muse Code 時無法讀取鑰匙圈（Keychain），例如透過 SSH 遠端連線時，登入畫面現在會說明原因並提示解法：先執行 security unlock-keychain 再重啟 Muse Code，不再只顯示看似登出卻毫無說明的畫面。

就像進大樓刷門禁時，警衛認得出你的員工名字才能接通專線，遇到保險櫃鎖上也會貼紙條寫明解鎖步驟。
問題修復

Windows 版顯示沙盒設定失敗步驟並修正附圖權限錯誤

在 Windows 上啟用沙盒（sandbox，隔離程式執行環境的機制）或在裡頭貼上圖片時，這版把兩個黑箱卡關處改清楚了。當 muse sandbox windows setup 或首次啟動執行的設定失敗時，現在會直接點名失敗的步驟，例如電腦原則拒絕沙盒帳號登入，不再只回報缺少設定標記。在工作階段資料夾不允許建立硬連結（hard link，指向同一份檔案資料的連結）時，例如身處沙盒之中，附加圖片現在也不再跳出「Access is denied」錯誤。

若把沙盒比作體檢站，哪一項被規定擋住就直接寫明項目名稱，不再只給一張缺漏單，夾帶圖片也不再被單一規定卡死。
問題修復

Linux 版修正沙盒併發防護與 Git worktree 執行錯誤

在 Linux 上同時跑多個沙盒（sandbox，隔離權限的環境）指令或切換 Git 分身目錄時，這版修了五個問題。 當 ~/.config 還沒建立時，兩個沙盒指令同時啟動，第二個不再以代碼 125 失敗。 若 Muse 從 git worktree add 建出的 worktree（Git 讓同一專案平行開多份副本的功能）子目錄啟動，指令現在都能執行，不再報錯「Not a directory」。 防止沙盒指令互相拆掉缺失路徑防護的共用鎖，不再存放在會被暫存清理工具半途刪掉的檔案中。 即使沙盒的佔位紀錄被刪掉（例如被 /tmp 清理工具清掉），共用 ~/.config 等缺失路徑的指令先結束時，另一方的防護也不再遺失。 同一工作區啟動另一沙盒指令時，.git 等缺失受保護資料夾內的禁用規則也不再遺失。

BUGFIX

Agent asks you first when blocked, plus branch build and form return updates

When you hand a series of tasks to Muse and a download is blocked or a build fails, it no longer pushes through to the end before reporting back.

A carpenter doing an on-site assembly asks you on the spot if a part is missing, switches to the new blueprint to recut if the old version fails, and fixes things properly before waiting for you to press confirm yourself.

Whenever a network policy refuses a download needed by a step, Muse asks you right away before running other steps, instead of probing other sources or waiting until the final report to mention the block. When your local checkout is behind and its build fails, it builds and tests on the up-to-date branch instead. Whenever the failure output names a fix, Muse keeps working until that fix is applied or offered; browser app forms now also wait for your own click to return their result instead of waiting on a background step.

FEATURE

Agent asks before changing environment settings or background services

When you ask an agent to write a small tool, you probably just want it to run inside your project without changing settings across your whole computer.

Like a new assistant tidying your desk, they would always ask you first before swapping your regular stamp, changing the front door key, or stationing someone in the mailroom.

When you ask Muse to compile a new tool and get ready to test-run it, it now asks you first whenever it hits four kinds of changes you did not request. This includes putting the newly built program on PATH (the list of directories the system searches for executable commands), or replacing or shadowing a command that is already there. If it needs to edit shell start-up files or install a background service on the system, it also always asks for your permission first.

BUGFIX

/goal summary removes hidden control characters before printing

When you check the /goal summary after a long task, the text shown on screen is sometimes generated by the model.

Picture a TV station filtering out remote-control signals before airing a news ticker, so text submitted by a guest cannot turn off studio monitors or switch channels.

Previously, if goal text written by the model carried special sequences, it could change the terminal title, clear the whole screen, or move the cursor unexpectedly. Now, before the /goal summary prints to the screen, all invisible terminal control characters (hidden codes used to move the cursor or clear the screen) are removed, so goal text written by the model cannot interfere with the terminal display.

FEATURE

Older builds cannot open chats that connected to another machine

If you use Muse across multiple computers, check your version before resuming a previous cross-machine work record. A Muse build older than this release cannot open a chat that a newer build connected, or tried to connect, to another machine to run commands there. When you resume such a chat by ID or pick it in the session picker on an older build, that build may start a new local session on its own, read the old log, and continue the work on this computer instead.

An older machine that cannot read a work order linked across plants might start working from the log right on the local floor, running every step at the wrong site.

Update the app before reopening such a chat, because the work inside may have been written for the other machine; other chats are unaffected.

FEATURE

Context window capacity controls and idle memory return updates for long chats

As a conversation grows longer, Muse now handles the model's context window (the maximum amount of text a model can process in one go) and system memory in three ways.

Think of a desk surface: when it is nearly full, you pick a sheet size that fits the remaining space, remind yourself to switch to a new desk if it truly won't fit, and clear away scrap paper promptly.

When a model has a known window size, a turn trims the output it asks for to fit within the room the window has left, avoiding most request-too-large errors in long conversations. If the turn still does not fit in the window, the on-screen message now directly tells you that you can start a new session. When a session becomes idle, the memory freed by a previous compaction is now returned to the system about half a minute later, instead of often holding onto it for minutes.

FEATURE

Workflow compaction resume and child task usage calculation updates

When using automated workflows for multi-step tasks, three adjustments have been made to saving and usage accounting. Saved workflows now remain in the list for you to resume even after a session has been compacted and reopened. If a workflow recorded a failed status check, older app versions cannot resume it and you will need to update the app to continue. Workflow token (the text unit AI processes and bills by) budgets and child task usage now count all of a child's work instead of only its first turn, eliminating the earlier issues of missing workflows after compaction or counting only first-turn usage.

FEATURE

Session protocol adds subagent stop request and result status flags

When building clients that connect to the Muse session protocol, you now have three new signals to track and control subagents.

Imagine a trackside scoreboard at a relay race that marks, at each point in time, who was told to stop, who just handed the baton back to the lead runner, and which old score was overwritten by a rerun.

The protocol adds an experimental subagent/workStop request that stops subagents (assistants dispatched by the main agent to share tasks) just like the terminal UI's own stop button, letting the agent know the user stopped them. Each time a session reads a subagent's result, clients receive a subagentResult item at that point with the completed, failed, or cancelled status seen by the view, so the result can be shown where the parent agent read it. Once the subagent starts a newer attempt after that result, the original subagent item's result carries superseded: true, letting clients determine the current state directly from control state.

FEATURE

TypeScript and Python SDKs add event streaming and custom query APIs

When writing plugins or client UIs for Muse with the TypeScript or Python SDK, you now have several new paths for receiving event streams and experimental features.

It feels like following a live text broadcast where the announcer pushes only the score lines that just changed instead of resending the whole match log on every play, while niche stats can be pulled directly through a dedicated channel.

In the TypeScript SDK, FoldExtension hooks (small programs triggered when specific events occur) can now observe custom notifications during session folds and host-wide events. Both SDKs support session.events() to stream what each new event changed in a session, making incremental view updates easier. Both SDKs also add MuseClient.request for sending unwrapped queries; when spawned with experimentalApi: true, command and request send experimental methods.

BUGFIX

TypeScript and Python SDKs fix error cause reporting and retry behavior

When connecting to Muse Code through the TypeScript and Python SDKs, error reporting and retry handling for host termination or overload have been updated. If a call fails because the host process terminated, the error cause now includes the exit code or signal along with the end of its error output; waiting for the process to exit can delay the failure report by up to 2 seconds, and having a cause does not mean the session can be resumed. Commands that receive an overloaded or backpressured response with retryable: false are no longer resubmitted automatically, while responses without that flag still retry. The compatibility link included in SDK host error messages now opens the compatibility page properly. submitFeedback and submit_feedback no longer attach a commandId to feedback/submit or resubmit after backpressured or overloaded, sending once per call.

FEATURE

muse serve supports attaching multiple videos in skill commands

When integrating with muse serve, you no longer need to send videos and skill instructions in two separate trips.

Suppose you hand a mechanic several dashcam clips along with a checklist, each clip labeled with a number in order so they can inspect them one by one against the items.

When a user wants the tool to inspect several screen recordings in sequence and apply the same analysis skill, the client simply sends the skill part together with multiple video parts in a single turn/start request. Without manually stitching strings together, each video's [Video #N] label is added to the skill's arguments in order, just like existing image labels.

BUGFIX

Session protocol improves cursor versioning and error reporting

When interacting with a background process and encountering an old cursor or a log issue, clients no longer receive vague messages through the session protocol or muse serve. View cursors are now issued in the v10: format, and older cursors are refused once with the standard "reopen without a cursor" guidance. A view cache saved by an older version is also rebuilt on first use so clients do not miss or misread events. If a session log is deleted or replaced outside Muse, any subsequent subagent interrupt, stop, close, or result read that the protocol refuses now states the real reason instead of falsely reporting that the change cannot be saved. In muse serve, if a command is sent to a subagent while its history is still being rebuilt after a resume, it reports that the subagent is busy and can be retried—even when the session cannot be saved—instead of reporting a save failure for a command that never ran.

BUGFIX

Clearer handling when reading settings.json or trust.json fails

When a project or local config file cannot be read or is missing a field, you need to know how to handle it. If trust.json cannot be read, a muse serve trust session marks extra folders as untrusted and opens as usual. When settings.json is missing schema_version, it prompts you to add "schema_version": 1 instead of only reporting a parse error. If settings.json cannot be read, a hook/list query for hooks (small programs triggered by specific events) refuses with the read error and recovery guidance instead of reporting zero hooks. Both muse resume <id> and muse exec --session-id <id> stop resuming with the same error and guidance, while a fresh muse or muse exec start still refuses due to the permission profile, and commands that run no hooks continue on defaults with a warning.

BUGFIX

Improvements to session listing loads, picker focus, and side chat labels

When browsing or resuming past sessions in the list, this release fixes three details that caused file locks, wrong selections, or confusion. Session listings now run in two phases by default: the listing content stays the same, but loading a long list no longer holds the log file open the whole time, though logs that are already very large do not shrink yet. When a session resume fails and returns to the picker, the cursor immediately selects the entry you just clicked as soon as it appears in the list, so pressing Enter right away no longer opens a different conversation. When running muse sessions, a parked side chat is now labeled as a branch of its parent conversation (sideOf) instead of sitting beside it like an anonymous session. Holding files open during long listings, opening the wrong conversation on a quick Enter retry, and losing track of a branch's origin are all avoided.

BUGFIX

Resuming and reopening sessions no longer fails on checkpoints or saved setups

When reopening an old conversation to continue your work, this release clears four issues that could block progress or hide chats. An old conversation that must continue in a new session no longer fails to resume even when its newest checkpoint was written between turns, and the original conversation content is preserved. When reopening a session with --resume, --continue, or /resume, if previously saved subagent state cannot be read, the expanded history no longer lists earlier subagents repeatedly. If a turn's setup failed to save and the next turn reused the same rules or instructions, reopening the session no longer fails. If a forked session ran before its workspace info was recorded, it automatically claims that workspace on its next resume so the picker lists it under the current workspace instead of hiding it for missing metadata.

BUGFIX

Fixes for queued prompts, approval cards, and prompt rows during tasks

When a task is running in a conversation or has just finished in the background, common mix-ups in prompt submission and display are now fixed. A prompt queued behind an active turn now reaches UserPromptSubmit hooks (small programs triggered by specific events) with its full text instead of an empty payload. Session messages sent after a background task finishes can now be approved normally. Pending approval cards also display the background task trigger separately from the sender. Stopping a task from the Tasks drawer or with /stop all no longer unexpectedly adds a second prompt row under your next message.

BUGFIX

Browser games now follow the tech stack you specify

When you ask Muse to build a browser mini-game, this update keeps it from defaulting to the most basic setup.

When you bring your own fabric to a tailor for a suit, they no longer sew everything from canvas and instead cut from the cloth you chose.

When you asked for a specific framework in chat before, it often still generated plain HTML files. Now, as long as you name the stack (the combination of tools and frameworks used to build an app) you want in your request, the browser game is built with that stack instead of always using plain HTML files.

BUGFIX

Content check reports now list draft-only items under their own heading

When organizing site articles or document attachments and running a report that separates published from unpublished content, it used to be easy to mistake draft assets for unused waste. Before reporting completion, agents often marked items that appeared only in unpublished content as "unused" or left them out entirely. Muse now prompts the agent to rerun the check before declaring completion and list items used only by unpublished content under a dedicated draft-only heading, avoiding false positives or omissions.

During a boutique inventory check, new accessories still being prepared in the back room go on their own reserve list so they are neither dismissed as clutter nor left off the count.
BUGFIX

Reading a truncated JPEG image now reports a damaged file directly

When you hand Muse a half-downloaded or incompletely copied image to analyze, you used to have to wait for the request to be sent before the whole thing was rejected.

A clerk who inspects a parcel box before shipping rejects a torn bottom at the counter, sparing you a wasted trip to the recipient's door.

Previously, when reading a JPEG image cut off at the end, the tool still sent the incomplete file to the model, causing the model to reject the entire request. Now, whenever a JPEG with an incomplete end is read, it stops locally and reports "the file may be damaged or invalid" instead of sending the broken image to the model.

FEATURE

Disabled plugin skills stay off even if the author moves their folder

If you have turned off an unwanted skill inside a plugin (a package that extends a tool's features), updating that plugin now comes with extra protection. Previously, if the plugin author moved that skill's folder inside the package, your disabled setting might no longer match after you updated. Now, even if the author changes the folder path and you update the plugin, the skill you turned off stays off.

Unsubscribing from a newsletter works the same way: even if the publisher later moves departments and reorganizes, the option you turned off stays off.
FEATURE

macOS improves sandboxed SSH connections and Keychain lock prompts

When using remote connections or operating Muse Code over SSH on a Mac, this release covers two situations that could leave you locked out. Shell commands running inside the macOS sandbox (an isolated environment that restricts program permissions) can now look up the current user name, allowing ssh to work just like it does outside the sandbox. When a Mac cannot read the Keychain at Muse Code startup, such as over a remote SSH connection, the login screen now explains why and shows the fix: run security unlock-keychain and restart Muse Code, instead of showing a screen that looks logged out with no explanation.

At an office building's security desk, the guard needs to recognize your employee name to patch your call through, and a locked safe needs a note taped to it explaining how to open it.
BUGFIX

Windows Shows Failed Sandbox Setup Steps and Fixes Image Permission Errors

When enabling the sandbox (an isolated environment for running programs) or pasting images inside it on Windows, this release clarifies two opaque roadblocks. When muse sandbox windows setup or the setup run on first start fails, it now names the failed step directly, such as machine policy refusing sign-in for the sandbox account, instead of only reporting a missing setup marker. When the session folder does not allow hard links (entries pointing to the same underlying file data), such as inside a sandbox, attaching an image no longer throws an "Access is denied" error.

If the sandbox is a medical checkpoint, whichever item is blocked by a rule now spells out its name instead of handing back a generic missing-item slip, and bringing along an image is no longer stalled by a single rule.
BUGFIX

Linux Fixes Sandbox Concurrency Protection and Git Worktree Execution Errors

When running multiple sandbox (a permission-isolated environment) commands simultaneously or switching parallel Git directories on Linux, this release fixes five issues. When two sandboxed commands start at the same time while ~/.config does not exist yet, the second no longer fails with exit code 125. If Muse starts from a subdirectory of a worktree (a Git feature for opening multiple parallel copies of the same project) created with git worktree add, commands now run instead of failing with "Not a directory". The shared lock that keeps sandboxed commands from stripping each other's protection for a missing path is no longer stored in a file that a temporary-file cleaner can delete mid-run. Even if the sandbox's placeholder records are deleted (such as by a /tmp cleaner), when one command sharing a missing path like ~/.config finishes first, the other's protection is no longer lost. When another sandboxed command starts in the same workspace, deny rules inside a missing protected folder such as .git are no longer lost either.
