Muse Code 1.4.17

發布日期：2026-11-13

Original changelog

The session protocol gains an experimental `subagent/workStop` request that stops a session's subagents the way the terminal UI's own stop does, so the agent is told the user stopped them
Session-protocol clients get a `subagentResult` item each time a session consumes a subagent's result, at that point in the session, with the result's status (`completed`, `failed` or `cancelled`) when the view saw it, so a client can show each finished subagent where its parent read the result
TypeScript SDK: `FoldExtension` hooks observe custom notifications in the session fold and host-wide events
In the TypeScript and Python SDKs, `session.events()` streams what each incoming event changed in a session, so a client can update its view incrementally
The TypeScript and Python SDKs add `MuseClient.request` for queries the client does not wrap, and `command` and `request` send experimental methods when the client is spawned with `experimentalApi: true`
A `subagent` item's `result` in the session protocol now carries `superseded: true` once the subagent started a newer attempt after that result, so a client can take the subagent's status from its control state
Muse asks you right away, before the other steps, when a network policy refuses a download a step needs, instead of probing other sources or naming the block only in its final report, builds and tests on the up-to-date branch when your checkout is behind and its build fails, keeps working until a fix the failure output names is applied or offered, and makes browser app forms return their result from your own click instead of waiting on a background step
A Muse build older than this release cannot open a chat that a newer build connected, or tried to connect, to another machine to run commands there. When such a chat is resumed by id or chosen in the session picker, that build may instead start a new local chat on its own that reads the old chat's log and continues the work on this machine; update the app before reopening the chat, because that work may have been written for the other machine. Other chats are unaffected
Browser games follow the stack the request names instead of always using plain HTML files
When a turn does not fit the model's context window, the message now says you can start a new session
Session-protocol clients: view cursors are now minted in the `v10:` spelling; a cursor in an older spelling is refused once with the standard "reopen without a cursor" guidance, and a view cache saved by an older build is rebuilt on first use, so no client silently skips or misreads events
Shell commands sandboxed on macOS can look up the current user name, so ssh works as it does outside the sandbox
Session listings now run in two phases by default, so a long listing no longer holds the session log open while it runs; listings are unchanged, and logs that are already very large do not shrink yet
The agent asks before changes you did not request: putting what it built on your PATH, replacing or shadowing a command already there, editing shell start-up files, or installing a background service
`muse serve` clients can send a skill part together with video parts in one `turn/start`; each video's `[Video #N]` label joins the skill's arguments in order, as image labels already do
When you ask for a checker or report that separates published from unpublished content, the agent is now prompted to rerun it and list items used only by unpublished content under their own draft-only heading, instead of calling them unused or leaving them out, before saying it is done
In the TypeScript and Python SDKs, a call that fails because the host process died now says how it ended (exit code or signal, and the end of its error output) in the error's cause; such a call can fail up to 2 seconds later while the SDK waits for that exit, and the cause does not mean the session can be resumed
Security: The `/goal` summary no longer lets goal text written by the model change the terminal title, clear the screen, or move the cursor; invisible terminal control characters are removed before the summary prints
Python and TypeScript SDKs: a command answered `overloaded` or `backpressured` with `retryable: false` is no longer resubmitted automatically; without the flag it still retries
After a resume that fails and reopens the session picker, the session you tried is selected as soon as the picker lists it, so pressing Enter right away no longer opens a different session
A prompt queued behind a running turn now reaches its UserPromptSubmit hooks with its text instead of an empty prompt
A turn on a model with a known context window now trims the output it asks for to the room the window has left, which prevents most request-too-large errors in long conversations
After a session log is deleted or replaced outside Muse, a subagent interrupt, stop, close or result read that the session protocol refuses now says why instead of saying the change can't be saved
The compatibility link in the SDK errors about the Muse Code host now opens the compatibility page instead of a missing page
A session that asks `muse serve` for workspace trust now opens with its extra workspace folders untrusted when `trust.json` cannot be read, instead of failing to open
Resuming a session that has to continue in a new session no longer fails when its newest checkpoint was written between turns; the conversation is kept
Session messages sent after a background task finishes can be approved normally. Pending approval cards show the background task trigger separately from the sender
Keep saved workflows available to resume after compacting and reopening a session
On a Mac where Muse Code cannot use the Keychain at startup, such as over SSH, the login screen now says why and how to fix it (run `security unlock-keychain` and restart Muse Code) instead of looking logged out with no explanation
Reopening a session with `--resume`, `--continue` or `/resume` no longer repeats an earlier subagent in expanded history when its saved subagent state could not be read
On Windows, a failed `muse sandbox windows setup`, or the setup a first start runs, now names the step that failed, such as a sign-in the machine's policy refuses for the sandbox account, instead of only reporting that its setup marker is missing
Older app versions can't resume a workflow that recorded a failed status check; update the app to resume it
When `settings.json` has no `schema_version` (for example, another tool created it), Muse now says to add `"schema_version": 1` instead of reporting a bare parse error
On a `muse serve` session, a command sent to a subagent while its history is still being rebuilt after a resume now answers that the subagent is busy and can be retried, even when the session cannot be saved, instead of reporting a save failure for a command that never ran
Reading a JPEG that is cut off before its end now fails with "the file may be damaged or invalid" instead of sending the broken image to the model, which rejected the request
On Linux, when two sandboxed shell commands start at the same time while `~/.config` does not exist yet, the second no longer fails with exit 125
On Linux, shell commands now run when Muse starts in a subdirectory of a Git worktree created with `git worktree add`, instead of every command failing with a "Not a directory" error
Workflow token budgets and child usage now count all of a child's work, not only its first turn
On Linux, the shared lock that keeps sandboxed commands from removing each other's protection of a missing denied path no longer lives in a file a temp cleaner can delete out from under a running command
On Linux, a sandboxed shell command no longer loses the protection of a missing path such as `~/.config` when another command sharing it finishes first after the sandbox's placeholder records were deleted, for example by a `/tmp` cleaner
A plugin skill you turned off stays off after the plugin's author moves its folder and you update the plugin
Stopping a task from the Tasks drawer or with `/stop all` no longer adds a second prompt row under your next message
On Linux, a sandboxed shell command no longer loses a deny inside a missing protected folder such as `.git` when another sandboxed command starts in the same workspace
Python and TypeScript SDKs: `submitFeedback` / `submit_feedback` no longer attaches a `commandId` to `feedback/submit` or resubmits it after a `backpressured` or `overloaded` answer; each call is one submit, as the wire defines it
Attaching an image no longer fails with "Access is denied" on Windows when the session folder does not allow hard links, for example inside a sandbox
`muse sessions` shows a parked side chat as a side chat of its conversation (`sideOf`) instead of an anonymous session beside it
`muse serve`'s hooks catalog read (`hook/list`) on a `settings.json` nobody could read now refuses with the read error and a recovery line instead of reporting zero hooks, and a resumed start (`muse resume <id>`, `muse exec --session-id <id>`) stops with the same refusal; a fresh `muse` or `muse exec` start keeps its permission-profile refusal, and commands that run no hooks keep continuing on defaults with the one warning
Reopening a session no longer fails when saving a turn's setup failed and the next turn reused the same rules or instructions
A forked session that ran before recording its workspace now takes the workspace on its next resume, so the resume picker lists it under the current workspace instead of hiding it as missing metadata
An idle session now returns the memory a compaction freed to the system about half a minute later, instead of often holding it for minutes
