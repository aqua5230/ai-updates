Muse Code 1.4.23

發布日期：2026-11-21

Original changelog

Context compaction now writes its summary from the same conversation and prompt cache the model was already using, and the summary keeps a list of the messages you sent, with a file holding the full text of any long message it shortens
The TypeScript SDK can refuse to connect to a host whose protocol schema moved by a declared breaking change: pass `refuseDeclaredBreakingSchema: true` when spawning; by default the connection goes ahead and `classifyServedSchema(initializeResult.schema)` names the mismatch's tier
Session protocol completion and shell items can include `terminalRowBeforeItemId` to preserve completion order
The session language guard now also checks the text in todo lists and plan updates, PowerShell and monitor descriptions, user-input questions and options, workflow names and titles, subagent messages, Task descriptions and prompts, memory descriptions and artifact labels, so a slip into another script there is corrected like visible answer text
A Muse build older than this release cannot open a chat while it holds, in the part of the chat the build reads, a message in which a newer build told the agent about a change to the machines the chat runs commands on, or delivered the result of a command on another machine late. Such a chat was connected to another machine before. Updating the app fixes it; other chats are unaffected
Goals accept an honest report when your own settings put a numeric target out of reach, and no longer count an unmentioned test in the workspace as part of the task
The built-in plan, git and test-writing skills give more precise guidance on reusing shared code, reading files at a requested commit or branch, which commits count as yours, and tests a request never mentioned
When a new program leaves open whether to use a local model or a paid hosted service, or which platform it runs on, Muse Code suggests clarifying the requirements first
When the shell sandbox is off, the session-start permission note now tells the agent to run downloaded or generated code as an unprivileged user or inside a full sandbox, because a temporary HOME, working directory or TMPDIR does not contain it
The one notice for a background command still running after 30 minutes now tells the agent, when the task has a time limit, to save its best result where the task asks for it before waiting any longer
Session-message history database files that earlier versions left in session folders are removed in the background, which frees disk space
Muse now removes the saved history that an older Muse version kept for a session once that copy has gone 7 days without a write and no Muse has the session open, which used to stay on disk
After reopening a session that has saved developer instructions with no `run.developer_prompt`, `/compact` measures its token budget on the instructions the turn used instead of falling back to a guess
Keep interrupted command recovery status visible in reopened sessions
`/compact` no longer answers "no compactable run is available" right after a turn in which the conversation was compacted automatically
`/compact` works again on a turn whose request still carries a reminder from an earlier turn, instead of answering that no run can be compacted (forked and side-chat sessions are not covered yet)
The todo reminder no longer gives the agent advice about a todo list it has already updated; the next check reads the current list instead
A long turn with many finished tasks no longer reads those tasks again at each context compaction
Reopening a session that was rewound to the first turn after a compaction, or a branch that starts there, now shows the conversation up to the compaction and the divider, instead of the summary as a prompt and the earlier turns copied below it
A scheduled task that the session accepted after a slow handoff is counted as delivered instead of recorded as skipped, so a repeating task's run count and last-run time stay right
Pausing a workflow now stops a no-deadline (`persistent`) monitor that one of its agents started, so the paused agent reports as cancelled right away instead of waiting until the watched command exits or the session ends
A session resumed over `muse serve` keeps the web-search mode it recorded instead of coming back with web search turned off
`muse exec` now honors `plugins.activation`: a plugin turned off, including `muse-core`, no longer adds its skills to the run
When a session's `developerPrompt` is replaced on resume, subagents started after that now use the new text instead of the text the session started with
`muse serve` no longer refuses a model that `model/list` offers (or accepts one it dropped) when its startup catalog refresh finished before the server installed its catalog
`code_wait` on a backgrounded cell returns the completed result instead of refusing the wait as unknown or already consumed
A shell command that would delete the folder a background command is still running in is now refused, and the refusal names that command and how to stop it
On Linux and macOS, a too-large `SKILL.md` warning now says how far over the limit the file really is, instead of always one byte over
After a run restarts inside a session, the TUI no longer replays the earlier attempt's hook notices, delivery wait and interrupt notice from the re-read history, no longer counts the earlier attempt's output as the new attempt's, and keeps the row of a prompt submitted during that re-read, so an expired hook notice does not reappear, a fresh interrupt notice is not spent by an old terminal, and a stopped automatic compaction is not restarted by the earlier attempt's install
Reopening a session whose automatic compaction finished after your next turn now shows your turns in order above `earlier conversation restored from checkpoint`, instead of moving an earlier turn below it
Muse shows the model's progress text beside its tool calls again on models whose server drops it when reasoning summaries are requested; that session stops asking that model for summaries after the first such response
Resuming a V1 Workflow that started before you compacted the session now explains that Muse reads only the history from that compaction on, instead of saying saved history is missing; such a run still needs a fresh start, and the session stays usable
Reopening a session no longer leaves out a turn that came after a context compaction and reused the same rules or instructions as the compacted turn
When the model service briefly reports that it is overloaded, the first retry now comes after about a second instead of stalling the turn for a full minute
In a `--yolo` session, a question the agent asks while it keeps working now lists its choices in the transcript, so you can see and type an answer without first pressing ctrl+q
Prevent a stalled notice check from withholding a completed CLI run result; warn once when the check times out
A recap requested through the SDKs after a background task, monitor or scheduled task finishes now summarizes that work instead of your earlier message
After a rewind, quitting prints the resume command for the new conversation, and a lost session host names that conversation instead of saying to start again
A malformed or unreadable approval policy file is named by its path in the startup refusal, so the file to fix or delete is clear instead of only a line and column
Closing the `/resume` picker's Ctrl+T transcript preview no longer expands the selected row as if Ctrl+E had been pressed
Reopening a session rewound to the first turn after a compaction (or a branch that starts there) keeps showing the conversation up to the compaction and the divider; the first refresh after the reopen no longer brings the summary back as a prompt with the earlier turns copied below it
The `--reasoning-effort` help in `muse --help` and `muse exec --help` no longer calls the setting Meta-only and names both defaults: high (or Meta's top served tier) and none in interactive sessions on other providers
Resuming a forked session no longer leaves its saved view permanently unavailable when the fork's own log carries a record this build cannot read
While a turn is running, Tab on a slash command such as `/exit`, `/logout`, `/model` or `/usage` runs the command the way Enter does instead of sending its text to the model as a queued message
A finished `bash_input` call's transcript row now names the shell session it acted on (`Sent input to bash`, `Resized terminal bash session`) instead of a generic `tool operation` subject
The refusal for a malformed or unreadable approval policy file now says what to do next: fix the file, or move it aside to start with no saved approval rules
Starting a session worktree whose branch is already checked out in another worktree now fails with a clear message that names the worktree holding it, instead of a generic setup failure that quoted raw Git output
In a workspace you have not trusted, sessions started there (including `muse serve` sessions, and after a resume) now send your user rules file (`~/.claude/CLAUDE.md` or your own config-directory rules) on every turn, not just the first; project rules stay out as before
A workflow recovery that resumes inside a retained session worktree reads that worktree's project MCP configuration again, so user and plugin MCP servers stay available during the recovery instead of all being withheld
`muse plugins validate` and the plugin install report now name the hook file that holds a hook defect (an unsupported event, a malformed handler or an ignored `silent` key) instead of the manifest that points to it, so the reported path is the file to open
After a context compaction, a child agent that finished its work and was then closed is listed as completed instead of failed in the session's earlier-history roster
After you restart a Workflow child with `r`, the agent you are talking to is told which child you restarted and on which attempt it finished, instead of learning it only from the child's own words
After you cancel a Workflow, the agent is told what the children that had already finished found, instead of reporting that nothing came back
`muse trace inspect` no longer reports a byte difference caused by tool names for a request that replays earlier tool calls; sessions recorded by an earlier version still show it
On Windows, sandboxed shell commands in `muse serve` and `muse acp` now run once sandbox setup is complete, instead of failing with "setup has not run", and `muse serve` reports the sandbox as available
The session uptime that `muse export` reports now covers the whole Muse process, including startup and resume, instead of restarting for each session
After a rewind that keeps a background task running, the new conversation no longer lists that task as a running row under the prompt
A subagent whose finish fails no longer writes its diagnostic over the composer while the TUI owns the terminal; the parent conversation shows the same notice a settlement failure shows, and the line still appears on redirected stderr and in the local trace
A running command whose output so far is only blank lines no longer shows the word `tool:` as its output; the row keeps its hint until real output arrives
`-c` settings overrides, MCP servers included, stay applied after `/new` and `/clear` instead of vanishing with the first fresh session
A session worktree created for an id whose branch already exists refuses an explicit `--worktree-base` that is not that branch's tip, naming the branch and the ways on, instead of starting on the branch and dropping the flag
A session hosted by `muse serve` numbers its context-pressure warning under the configured compaction thresholds and context limit, as the terminal does
The suggestion to clarify a new program's requirements first no longer stops a run that has no way to ask a question
`muse exec --json` no longer cuts its output short when many records were still unwritten as the session finished; the lost lines could include a later run's result, and the exit status then came from an earlier run
After you exit while a subagent is still running and later resume the session, the agent is told the subagent was cancelled and the transcript shows its finished row, instead of the subagent silently vanishing
On Windows, stopping a background PowerShell session run without the sandbox and without `tty` now also ends the programs it started, including after its shell already exited
A chat started with `/fork` now shows how long each copied tool call took, instead of 0s
When an OpenAI, Anthropic or OpenRouter endpoint answers a streaming request with a non-SSE page, or a model stream breaks with malformed data, the run now fails fast with the real protocol reason instead of retrying the same broken response until the timeout
In a resumed session, a turn started after the resume that stops unexpectedly or is force-stopped after an interrupt is now closed properly, instead of leaving the session refusing new turns with a "saving failed" message until restart. A turn can still leave the session that way if it was sent while the previous turn was still finishing or just after it ended, was queued behind other input, received a further message before it began, stopped before it began, or was carried over from before the resume
After you replay a finished Workflow, a rerun agent's conversation keeps showing its attempt number (for example `attempt 2/2`) instead of `attempt 1/1`
On Linux, a sandboxed command now finds its placeholder registry once, so a per-user runtime directory that appears while the command is starting no longer leaves one of its denied paths unprotected or refuses another sandboxed command of the same user
Session protocol resume errors no longer claim a repaired log was unchanged
A finished turn on the OpenAI or Anthropic provider is no longer discarded when the provider's usage block has a missing, string-typed, or otherwise odd token count; the answer is kept and the odd count reads as zero, as it already did on the Meta provider
A hook that runs after a tool call, after a batch of tool calls or when a subagent starts no longer leaves a record in the session log when it exits 0, writes nothing but whitespace to stderr, returns no system message, has no error and has no effect, even if it prints to stdout, so sessions with many hooks take less disk; any other run of these hooks is recorded when it ends
A hook that runs when a prompt is submitted no longer leaves a record in the session log when it exits 0, writes nothing but whitespace to stderr and adds or changes nothing (no context, block, rewrite, system message or error), so sessions with many prompt hooks take less disk; any other run of these hooks is recorded as before
Long sessions use less memory, because each event record the live session keeps in memory is smaller
Resuming a long session that was never compacted peaks at less memory, because the decoded copy of its log is released before the session's state is rebuilt
Long sessions use less memory, because the subagent view no longer remembers every event it has shown
A session started in the terminal or with `muse exec` takes less disk: its history for the desktop app is built the first time the desktop app opens the session instead of being written at every turn (until then the desktop app shows no history for a session a terminal still has open)
Long sessions use less memory, because the display no longer carries its journal of earlier turns' task activity into each new turn
