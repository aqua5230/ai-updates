Muse Code 1.4.23

發布日期：2026-11-21

繁體中文

新功能

壓縮摘要共用快取並保留你的提問

長對話要壓縮上下文時，現在會直接沿用模型原本就在跑的對話與提示快取（把算過的內容暫存起來直接用）來寫摘要。 寫好的摘要還會附上一份你送出過的訊息清單。如果有長訊息被縮短，完整原文會另外放進一個檔案裡保留。

編輯雜誌專欄時，以前得把採訪資料抱去另一張桌子重起頭寫導言，長受訪稿也常被剪掉；現在直接拿原本攤在桌上的資料寫大綱，被縮短的長篇內容也會另附一張完整文稿。
新功能

特定跨機紀錄讓舊版 Muse 開不了對話

以前連過其他機器執行指令的對話，若在舊版 Muse 讀取到的範圍內出現特定新版訊息，舊版就會打不開它。這裡說的新版訊息，是指新版告知代理執行指令的機器有變動，或是延後送達另一台機器指令結果的紀錄。 其他沒有這類紀錄的對話完全不受影響，把 Muse 更新到這一版就能正常開啟。

新功能

工作階段語言防護擴大檢查介面文字

在工作階段裡跟代理對話時，待辦清單或選項混入其他書寫文字，現在也會像畫面上的回答一樣被檢查並更正。 這次納進檢查的範圍包含待辦清單、計畫更新、PowerShell 與監看說明，以及向你提問的問題與選項。Workflow 名稱和標題、子代理訊息、Task 說明與提示、記憶描述，還有產出物標籤也都在內。

更換車站指標牌時，月台小標和出口說明以前偶爾會漏掉錯置的外語；現在連每面小指示牌也一併巡過，只要寫偏就當場改回同一套文字。
問題修復

新程式未定規格會先釐清也不卡死

請 Muse Code 動手寫一個新程式，要是沒先交代要用本機模型還是付費代管服務，或是要跑在哪個平台，它現在會建議先跟你釐清需求再往下做。 不過如果這一輪執行環境本來就沒辦法向你提問，這項建議不會把整個執行直接停下來。

找室內設計師畫新家藍圖，沒講清楚要實木還是貼皮地板前，他會先停筆問清楚再買料；但若是寄來的遠距批改單沒留聯絡方式，他也不會就這樣乾等不動。
問題修復

Goals 與內建技能更貼合實際任務範圍

設定任務目標或請代理依內建技能辦事時，它對邊界與進度的判斷現在更準。 當你自己的設定讓 Goals 的數字目標根本達不到時，Goals 會接受誠實回報，也不再把工作區裡你沒提過的測試算進任務裡。 內建的規劃、Git 與寫測試技能給出的指引也更明確，包含怎麼重用共用程式碼、讀取指定提交或分支的檔案、哪些提交才算你的，以及怎麼處理需求裡沒提到的測試。 待辦清單提醒則不再針對代理已經改過的那份清單給建議，下一次檢查會直接讀最新清單。

新功能

權限提醒與未信任工作區規則更嚴謹

打開陌生專案資料夾、關掉沙盒保護，或碰到核准設定檔寫錯無法啟動，這些情況現在都有更明確的提示與防護。 關掉外殼沙盒（隔離執行程式的安全環境）時，工作階段開場的權限提示會提醒代理用無特權使用者或完整沙盒來跑下載與生成的程式。因為暫時的 HOME、工作目錄或 TMPDIR 關不住它們。 遇到格式錯誤或讀不到的核准原則檔，啟動時的拒絕訊息會直接列出檔案路徑而不只報行號欄數。訊息也會告訴你下一步要修好該檔，或先移開好讓它以沒有已存核准規則的狀態啟動。 在還沒信任的工作區開啟工作階段（包含 muse serve 與接續後），現在每一輪都會送出你的個人規則檔。這類檔案例如 ~/.claude/CLAUDE.md 或設定目錄裡的個人規則不再只附在第一輪，而專案規則照舊不載入。

問題修復

/compact 壓縮執行與額度計算修復

想用 /compact 幫長對話瘦身，現在不會動不動被拒或重讀舊任務了。 重開存有開發者指示、但缺少該輪專屬提示紀錄的工作階段後，/compact 會改依該輪實際使用的指示計算 token（AI 處理與計費的文字單位）上限，不再用猜的。 剛經歷過自動壓縮的那一輪結束後，緊接著手動執行 /compact 不會再跳出 "no compactable run is available" 拒絕你。 請求裡還帶著前面輪次留下的提醒時，/compact 也恢復正常運作，不再回覆沒有可壓縮的輪次。不過分支與側邊聊天工作階段目前還不支援。 包含許多已完成任務的長輪次，每次做上下文壓縮時都不會再重頭讀取那些已完成的任務。

問題修復

壓縮後重開工作階段的順序與紀錄修復

對話壓縮過後再去重開或重整畫面，現在顯示的順序和紀錄終於不會亂掉。 把工作階段回溯到壓縮後的第一輪，或是從那裡開出的分支，重開後就算經過第一次畫面重整，也會穩定顯示壓縮前的對話與分隔線。先前會把摘要塞成提問並把舊對話複製在下面的問題已經修好。 若自動壓縮在你送出下一輪之後才完成，重開工作階段時對話輪次會依順序排在 earlier conversation restored from checkpoint 上方。較早的一輪不會再被移到下方。 壓縮後曾沿用同一套規則或指示的那一輪對話，重開工作階段時不會再憑空漏掉。 上下文壓縮之後，先前已經做完工作才被關閉的子代理，在工作階段的早期歷史名單裡會標記為已完成，不再誤判為失敗。

問題修復

回溯與 /fork 分支的接續與紀錄修復

把話題退回早幾輪重新開始，或切出一條支線試新做法，事後常發現工具秒數或背景項目對不上。 回溯對話後退出程式，終端機會印出新對話的接續指令。萬一工作階段主機失聯，也會直接點名這則新對話，不再叫你重頭開始。 回溯時如果還留著背景任務在跑，新的對話輸入框底下不會再把它列成執行中的項目。 接續一個分支工作階段時，就算分支自己的紀錄裡帶有這版讀不懂的項目，已存的檢視畫面也不會從此永遠打不開。 用 /fork 開出的新對話，複製過來的每個工具呼叫現在都會顯示實際花費的秒數，不再一律顯示 0s。

問題修復

接續後部分輪次中止不再卡住

接續對話後才啟動的輪次若意外中止，或在中斷後被強制停止，現在會正常收尾。這類輪次不會再讓工作階段卡在 "saving failed"，拒絕新提問直到重開才放行。 不過仍有幾種情況仍可能讓工作階段卡住：上一輪還在收尾或剛結束時才送出、排在其他輸入後面、開始前又收到新訊息、還沒開始就停掉，或從接續前延續過來的輪次。

問題修復

重啟執行不再重播舊掛鉤與中斷通知

在工作階段裡重啟執行，終端機介面不會再把前一次嘗試的舊紀錄當成這一次來演了。 重讀紀錄時，畫面上不會再重播舊的掛鉤（特定事件發生時被觸發的小程式）通知、送達等待與中斷提醒。它也不會把前一次的輸出算進新的一輪，重讀期間送出的提問列也會好好保留。 這樣一來，過期的掛鉤通知不會又冒出來，新的中斷通知不會被舊終端消耗掉，已經停住的自動壓縮也不會被前一次嘗試的安裝動作重新啟動。

就像舞台劇換場重新開演，以前會把上一場的音效和燈號再放一遍、甚至弄亂這一場的節奏；現在舊帳一筆勾銷，只照新場次的指令走。
問題修復

終端機指令操作與 -c 設定行為修復

在終端機裡邊跑任務邊下指令，或從切換器預覽歷史對話，操作反應順暢不少。 在 --yolo 工作階段裡，代理邊忙邊問你問題時會把選項直接列在對話紀錄中，看得到也能直接輸入回答，不必先按 ctrl+q。 對話還在跑的時候，對 /exit、/logout、/model 或 /usage 這類斜線指令按 Tab 會直接執行。它的反應就跟按 Enter 一樣，不再把指令文字當成排隊訊息送給模型。 關掉 /resume 選擇器的 Ctrl+T 紀錄預覽後，原本選中的那一列不會再像按了 Ctrl+E 一樣展開。 用 -c 覆寫的設定包含 MCP（讓 AI 連接外部工具的協定）伺服器，在 /new 與 /clear 之後仍會生效，不會跟著第一個新工作階段一起消失。

問題修復

對話紀錄裡的指令狀態顯示更清楚

盯著對話捲動區裡一排排執行紀錄，以前常搞不清楚剛才敲的視窗指令送去哪、或只見空白字樣。 重開工作階段之後，先前被中斷指令的復原狀態會繼續留在畫面上給你確認。 執行完畢的 bash_input 呼叫列現在會寫出實際作用的終端機工作階段，不再只顯示籠統的 tool operation。上面會直接標示像是 Sent input to bash 或 Resized terminal bash session 這類說明。 還在跑的指令如果到目前為止只印出空白行，紀錄列不會再拿 tool: 當成輸出，會維持原本的提示直到真正內容送達。

問題修復

背景指令防護與排程任務計數修正

同時開著幾個耗時命令在背後跑，又要小心別誤刪資料夾或漏掉準點執行的紀錄，現在有了對應保護。 只要還有背景指令在某個資料夾裡跑著，想執行會刪掉那個資料夾的指令就會被直接擋下。拒絕訊息還會點名是哪個指令以及怎麼停掉它。 背景指令跑超過 30 分鐘的那次提醒，現在遇到有時限的任務時，會先叫代理把目前最好的結果存到任務指定的位置再繼續等。 用 code_wait 等待一個移到背景執行的程式區塊時，會正常拿到完成的結果，不再當成未知或已被取走而拒絕。 排程任務若在慢速交接後才被工作階段接手，現在會計為已送達而非略過，讓重複任務的執行次數與上次執行時間維持準確。

問題修復

Workflow 暫停監看與恢復設定修復

暫停 Workflow 後，無期限監看也會立刻停止，不再讓代理一直等到指令結束。 暫停 Workflow 時，底下代理啟動的無期限 persistent 監看也會一併停掉。被暫停的代理會立刻回報已取消，不必等到被監看的指令結束或工作階段關閉。 接續在對話壓縮前就啟動的 V1 Workflow 時，會改為說明只讀壓縮後這段紀錄，不再錯報找不到已存歷史。該次執行仍得重新啟動，整個工作階段則能繼續使用。 在保留的工作階段工作樹（Git 讓同一專案平行開多份副本的功能）裡恢復 Workflow 時，會重讀該工作樹的專案 MCP 設定，讓使用者與外掛的 MCP 伺服器保持可用。

問題修復

Workflow 子工作重啟與重播狀態修正

半途按快捷鍵介入或重播跑過的流程，主代理跟介面現在都知道實際跑到第幾次、查出了什麼。 你按 r 重啟 Workflow 的某個子工作後，跟你對話的主代理會直接收到通知，知道你重啟了哪一個子工作以及在第幾次嘗試完成，不必只靠子工作自己口述。 把一個 Workflow 取消掉之後，主代理還是會收到已經做完的子工作查到了什麼結果，不會再回報什麼都沒帶回來。 重播已經結束的 Workflow 時，重跑的代理對話裡會繼續顯示正確的嘗試次數，像是 attempt 2/2，不再錯顯示成 attempt 1/1。

問題修復

子代理接續指示與失敗提示修正

派出子代理分頭辦事後，無論是接續舊對話還是遇到失敗，交接狀態都變得明確。 接續工作階段時如果換掉了開發者指示，之後新啟動的子代理都會改用新內容，不再沿用一開始開啟工作階段時的舊指示。 子代理還在跑你就先離開、之後再接續工作階段時，主代理會被告知子代理已經取消，對話紀錄也會補上結束列，不會再默默消失。 子代理收尾失敗時，診斷訊息不會再直接蓋到終端機介面的輸入框上。父對話會顯示和結算失敗一樣的提示，原本那行仍會留在重新導向的標準錯誤與本機追蹤檔裡。

問題修復

模型連線重試與串流計量容錯修正

連線外部模型偶爾會碰上過載、斷線或回傳怪資料，現在處理得更果斷。 模型服務短暫回報過載時，第一次重試約 1 秒後就會開始，不再讓這一輪白白卡住一整分鐘。 當 OpenAI、Anthropic 或 OpenRouter 端點對串流請求回傳非 SSE 頁面，或資料流因格式錯誤中斷時，這輪會附上真實協定原因快速失敗。它不會再對同一份壞回應重試到逾時。 有些模型一旦被要求給推理摘要，伺服器就會把工具呼叫旁的進度文字丟掉。該工作階段收到第一次這類回應後就會停要摘要，讓進度文字重新顯示。 OpenAI 或 Anthropic 供應商在完成的一輪裡，若使用量區塊裡的 token 計數缺漏、被寫成字串或有其他異常，回答仍會保留。異常計數會比照 Meta 供應商按 0 處理。

新功能

muse serve 搜尋模式與警告計算對齊

經由 muse serve 接續工作階段時，會保留原本記錄好的網頁搜尋模式，不會回來就自動關掉。 啟動時的目錄更新如果比伺服器載入清單早一步完成，muse serve 不再拒絕 model/list 給的模型，也不會誤收已經拿掉的模型。 muse serve 代管的工作階段在計算上下文壓力警告數值時，現在會比照終端機，依照設定好的壓縮門檻與上下文上限來算。

問題修復

muse exec 輸出與指令列說明修復

拿 muse exec 接進自動化腳本跑批次任務，外掛開關、說明和最終輸出的準確度都有改善。 muse exec 現在會遵守 plugins.activation 設定，被關掉的外掛（包含 muse-core 在內）不會再把技能加進執行裡。 muse exec --json 結束時就算工作階段還有大批紀錄來不及寫出，輸出也不會被截斷。這能避免後續執行的結果漏掉，甚至拿前一次的結束狀態碼充數。 指令列執行完畢後，如果通知檢查卡住了也不會再扣住結果不放，檢查逾時只會發出一次警告。 muse --help 和 muse exec --help 裡的 --reasoning-effort 說明不再寫成 Meta 限定。預設推理力度是 high，或 Meta 提供的最高推理力度檔位；其他供應商的互動工作階段則預設為 none。

問題修復

外掛掛鉤路徑與追蹤匯出報告修正

檢查外掛設定、追查工具紀錄或匯出使用數據，現在給出的路徑與時間都貼近實況。 muse plugins validate 與外掛安裝報告遇到掛鉤問題時，會直接點名出錯的那個掛鉤檔而不是指著它的清單檔。無論是不支援的事件、格式錯誤的處理器或被忽略的 silent 鍵，報出來的路徑就是該打開修改的檔案。 在 Linux 和 macOS 上，SKILL.md 檔案過大的警告會報出實際超過上限多少，不再永遠只寫超出 1 位元組。 muse trace inspect 檢查重播舊工具呼叫的請求時，不會再報出由工具名稱造成的位元組差異；不過舊版錄下的工作階段紀錄還是會看到。 muse export 報告的工作階段運行時間現在涵蓋整個 Muse 行程，包含啟動與接續在內，不再每個工作階段重新起算。

問題修復

工作樹分支衝突與基準參數檢查更清楚

準備另開一條工作分支平行寫程式，遇到撞名或基準點對不上時，提示不再含糊帶過。 啟動工作階段工作樹時，要是那個分支已經在別的工作樹被簽出，會直接失敗並點名是哪個工作樹佔著它，不再丟出夾帶原始 Git 訊息的籠統錯誤。 如果用既有分支對應的 ID 建工作樹，你又額外指定了不是該分支末端的 --worktree-base，現在會直接拒絕。它會列出分支名稱與後續做法，不再默默開在該分支上卻把參數丟掉。

跟租共用車位一樣，以前車位早被開走卻只丟一張「停不下」的模糊紙條，甚至擅自把你預約的時段抹掉；現在直接告訴你誰停在裡面，參數對不上也當場講明怎麼改。
問題修復

Windows 與 Linux 沙盒與行程修復

Windows 與 Linux 使用者執行隔離指令或關掉背景 PowerShell，環境銜接與掃尾更完整。 Windows 上的 muse serve 與 muse acp，只要沙盒設定完成就能正常跑沙盒指令，不再報錯 "setup has not run"。而 muse serve 也會正確回報沙盒可用。 同樣在 Windows，在沒開沙盒也沒有 tty 的情況下停止背景 PowerShell 工作階段時，它所啟動的其他程式也會一併結束，就算外殼本身早就先退出了也一樣。 Linux 上的沙盒指令現在只會定位一次佔位登錄位置，就算啟動當下才冒出個人執行期目錄，也不會讓原本禁止的路徑失去保護，或誤擋同一位使用者的其他沙盒指令。

新功能

舊對話歷史清理與延後寫入省硬碟

用久了擔心對話歷史檔把硬碟塞滿，現在舊檔會自動清掉、新檔也改為需要時才建。 舊版本留在工作階段資料夾裡的訊息歷史資料庫檔案，現在會在背景自動清除來騰出空間。 舊版 Muse 為工作階段保存的歷史複本，只要連續 7 天沒有寫入且沒有任何 Muse 開著該工作階段，也會自動從硬碟刪除。 從終端機或 muse exec 開起的工作階段更省空間：給桌面版用的歷史紀錄改在桌面版第一次打開該工作階段時才建立，不再每輪都寫。在此之前，終端機還開著的對話在桌面版不會顯示歷史。

打掃舊儲藏室時，以前搬家留下的舊箱子一放就是好幾年，每次寫筆記還先多複印一份給別間辦公室；現在逾期沒用的舊箱子會自動清掉，複印本也等對方真的來拿才印。
問題修復

無異動的掛鉤空跑不再寫入紀錄檔

掛鉤裝多了，以前就算什麼也沒改動也要寫進工作階段紀錄檔佔空間。 工具呼叫後、整批工具呼叫後或子代理啟動時跑的掛鉤，只要結束碼是 0、標準錯誤只有空白、沒有系統訊息、沒有錯誤也沒有任何效果，就算有印出標準輸出也不再留紀錄。其他情況會在結束時記錄。 送出提問時觸發的掛鉤，結束碼為 0、標準錯誤只有空白，且沒有新增上下文、攔截、改寫、系統訊息或錯誤，才不留紀錄。略過這些無異動紀錄能省下硬碟空間，其餘照舊記錄。

就像大廈警衛巡邏簽到，以前每經過一扇鎖得好好的門也要寫一張長報告；現在一切安好就不必浪費紙張，真有開門或異狀才落筆登記。
新功能

長工作階段與接續執行減少記憶體佔用

一個對話越聊越長，或是打開從沒整理過的龐大舊紀錄，程式吃掉的記憶體量降下來了。 進行中的工作階段保存在記憶體裡的每筆事件紀錄都變小了，長對話更省資源。 接續一個從未壓縮過的長工作階段時，解碼出來的紀錄複本會在重建工作階段狀態前先釋放，記憶體峰值跟著降低。 子代理畫面不再記住它顯示過的每一筆事件。 顯示層也不再把前面各輪的任務活動日誌一路帶進每一輪新對話裡。

跑長途馬拉松時，以前把沿路喝空的紙杯和看過的路標全塞在背包裡；現在邊跑邊把不需要的舊紙屑清掉，步伐自然輕省不少。
問題修復

SDK 連線檢查與工作階段協定更新

開發者把自家工具接上這套引擎時，連線前的版本相容檢查與任務結束後的摘要整理，這版都做了調整。 啟動 TypeScript SDK 連線時，現在可以設定拒絕連上宣告過破壞性協定變動的主機；預設仍會照常連線，並提供方法回報差異的層級。 工作階段協定的完成紀錄與指令列項目可附上順序位置資訊，用來維持完成時的排列順序。 背景任務、監看或排程結束後透過 SDK 要求摘要時，現在會總結那件剛完成的任務，不再誤拿你更早以前的訊息來摘要。 工作階段協定在接續發生錯誤時，不會再把已經修復過的紀錄檔說成未曾修改。

English

FEATURE

Compaction summaries share cache and keep your prompts

When a long conversation needs context compaction, the summary is now written directly from the same conversation and prompt cache the model was already using. The finished summary also includes a list of the messages you sent. If any long message is shortened, its full original text is saved in a separate file.

Picture editing a magazine column: previously, you had to carry interview notes to another desk to write an intro from scratch, and long transcripts often got trimmed; now you draft the outline straight from the material already on your desk, with a full copy attached for any long piece that gets shortened.
FEATURE

Certain cross-machine records block older Muse builds from opening chats

Chats that previously connected to other machines to run commands cannot be opened in an older Muse build if specific newer-build messages appear within the part of the chat it reads. These newer-build messages are records where a newer build told the agent about a change to the machines running commands, or delivered a command result from another machine late. Other chats without such records are completely unaffected, and updating Muse to this release lets them open normally.

FEATURE

Session language guard expands checks to UI text

When talking with the agent in a session, any slip into another script inside todo lists or options is now checked and corrected just like visible answer text. The expanded checks cover todo lists, plan updates, PowerShell and monitor descriptions, and user-input questions and options. Workflow names and titles, subagent messages, Task descriptions and prompts, memory descriptions, and artifact labels are included as well.

Think of replacing train station signs: small platform labels and exit notes used to occasionally slip into a stray foreign language; now every small sign is inspected too and switched back to the same script on the spot whenever it drifts.
BUGFIX

Unspecified new programs clarify requirements first without stalling

When you ask Muse Code to write a new program without specifying whether to use a local model or a paid hosted service, or which platform it runs on, it now suggests clarifying the requirements with you before proceeding. However, if the run environment has no way to ask you a question, this suggestion no longer stops the run outright.

When you hire an interior designer to draft a new home blueprint, he pauses to ask whether you want solid wood or laminate flooring before buying materials; yet if a mailed-in remote markup sheet leaves no contact info, he does not just sit there waiting.
BUGFIX

Goals and built-in skills better match actual task scope

When setting task goals or asking the agent to follow built-in skills, its judgment of boundaries and progress is now more accurate. When your own settings put a numeric target out of reach, Goals accept an honest report and no longer count unmentioned tests in the workspace as part of the task. The built-in plan, Git, and test-writing skills also give clearer guidance, covering how to reuse shared code, read files at a requested commit or branch, determine which commits count as yours, and handle tests not mentioned in the request. Meanwhile, the todo reminder no longer gives advice about a todo list the agent has already updated; the next check reads the latest list instead.

FEATURE

Stricter permission notes and untrusted workspace rules

Opening an unfamiliar project folder, turning off sandbox protection, or hitting a startup failure from a broken approval config now come with clearer prompts and safeguards. When the shell sandbox (an isolated environment for running code) is off, the session-start permission note reminds the agent to run downloaded or generated programs as an unprivileged user or inside a full sandbox. That is because a temporary HOME, working directory, or TMPDIR cannot contain them. When encountering a malformed or unreadable approval policy file, the startup refusal names the file path directly instead of only reporting a line and column number. The message also tells you what to do next: fix the file, or move it aside so it can start with no saved approval rules. When starting a session in a workspace you have not trusted (including muse serve and after a resume), your user rules file is now sent on every turn. Files such as ~/.claude/CLAUDE.md or personal rules in your config directory are no longer attached only on the first turn, while project rules stay out as before.

BUGFIX

/compact execution and token budget fixes

Using /compact to trim long conversations no longer gets rejected unnecessarily or re-reads old tasks. After reopening a session that has saved developer instructions but lacks a turn-specific prompt record, /compact now measures its token (text units AI models process and bill by) budget from the instructions that turn actually used instead of guessing. Right after a turn where automatic compaction occurred, running /compact manually no longer rejects you with "no compactable run is available". When a request still carries a reminder from an earlier turn, /compact also works again instead of replying that no run can be compacted. However, forked and side-chat sessions are not supported yet. Long turns containing many finished tasks no longer re-read those finished tasks from scratch at each context compaction.

BUGFIX

Fixed turn order and records when reopening compacted sessions

Reopening or refreshing the screen after a conversation has been compacted no longer scrambles the displayed order or records. When a session is rewound to the first turn after a compaction, or a branch starts from there, reopening it keeps showing the conversation up to the compaction and the divider even after the first refresh. The previous bug that turned the summary into a prompt and copied earlier turns below it is fixed. If automatic compaction finishes after you send your next turn, reopening the session now lists your turns in order above earlier conversation restored from checkpoint. An earlier turn is no longer moved below it. A turn after compaction that reused the same rules or instructions is no longer dropped when reopening the session. After a context compaction, a child agent that finished its work before being closed is listed as completed in the session's earlier-history roster, instead of being misclassified as failed.

BUGFIX

Fixed resume and log display for rewinds and /fork branches

Rewinding a conversation to an earlier turn or branching off to try a new approach used to leave tool durations or background items out of sync. After rewinding a conversation and quitting, the terminal prints the resume command for the new conversation. If the session host is lost, it also names that new conversation directly instead of telling you to start over. If a background task is still running during a rewind, the new conversation no longer lists it as a running row under the prompt input. When resuming a forked session, its saved view is no longer left permanently unavailable even if the fork's own log contains an entry this build cannot read. In a new chat started with /fork, each copied tool call now shows the actual seconds it took, instead of always showing 0s.

BUGFIX

Aborted post-resume turns no longer lock up sessions

In a resumed session, turns started after the resume that stop unexpectedly or are force-stopped after an interrupt now close properly. Such turns no longer leave the session stuck at "saving failed", refusing new prompts until a restart. However, a few cases can still leave the session stuck: a turn sent while the previous turn was still finishing or just after it ended, queued behind other input, receiving another message before it began, stopped before it began, or carried over from before the resume.

BUGFIX

Restarting a Run No Longer Replays Old Hooks or Interrupt Notices

When a run restarts inside a session, the terminal interface no longer acts out the earlier attempt's old records as if they belonged to this run. When re-reading history, the screen no longer replays old hook (small programs triggered by specific events) notices, delivery waits, and interrupt reminders. It also does not count the earlier attempt's output toward the new round, and the prompt row submitted during that re-read is preserved. As a result, expired hook notices do not reappear, new interrupt notices are not consumed by an old terminal, and an already stopped automatic compaction is not restarted by the earlier attempt's install action.

Like a stage play resetting between acts, it used to replay the previous act's sound cues and lighting, or even disrupt this act's pacing; now the old slate is wiped clean, and it follows only the new act's cues.
BUGFIX

Terminal Command Input and -c Settings Behavior Fixes

Running commands in the terminal while tasks are in progress, or previewing past conversations from the switcher, now responds much more smoothly. In a --yolo session, when the agent asks you a question while staying busy, it lists the choices directly in the transcript so you can see them and type an answer without first pressing ctrl+q. While a conversation is still running, pressing Tab on slash commands such as /exit, /logout, /model, or /usage executes them directly. It behaves just like pressing Enter, instead of sending the command text to the model as a queued message. After closing the /resume picker's Ctrl+T transcript preview, the previously selected row no longer expands as if Ctrl+E had been pressed. Settings overridden with -c, including MCP (a protocol for connecting AI to external tools) servers, remain active after /new and /clear instead of vanishing with the first new session.

BUGFIX

Clearer Command Status in the Conversation Transcript

Looking at rows of execution records in the conversation scrollback, it used to be hard to tell where a just-typed window command went or why only blank text appeared. After reopening a session, the recovery status of previously interrupted commands stays visible on screen for you to confirm. A finished bash_input call row now names the actual terminal session it acted on instead of showing a generic tool operation. It directly displays labels like Sent input to bash or Resized terminal bash session. If a running command has only printed blank lines so far, the transcript row no longer uses tool: as its output and instead keeps its original hint until real content arrives.

BUGFIX

Background Command Safeguards and Scheduled Task Count Fix

When running several long-lived commands in the background at once, you now have safeguards against accidentally deleting folders or missing on-time execution records. As long as a background command is still running inside a folder, any command that would delete that folder is blocked directly. The refusal message also names that command and explains how to stop it. The notice sent once a background command runs past 30 minutes now tells the agent, when facing a time-limited task, to save its best result so far to the task's designated location before waiting any longer. Using code_wait to wait on a code cell moved to the background now returns the completed result normally instead of refusing it as unknown or already consumed. If a scheduled task is accepted by the session only after a slow handoff, it is now counted as delivered rather than skipped, keeping a repeating task's run count and last-run time accurate.

BUGFIX

Workflow Pause Monitoring and Recovery Config Fixes

Pausing a Workflow now immediately stops no-deadline monitoring as well, instead of making the agent wait until the command finishes. When pausing a Workflow, any no-deadline persistent monitor started by its underlying agents is stopped along with it. The paused agent reports as cancelled right away without waiting for the watched command to exit or the session to close. Resuming a V1 Workflow that started before conversation compaction now explains that it reads only the history from that compaction onward, rather than falsely reporting that saved history is missing. That run still needs to be restarted, while the overall session remains usable. When recovering a Workflow inside a retained session worktree (a Git feature that opens multiple parallel copies of the same project), it re-reads that worktree's project MCP configuration so user and plugin MCP servers stay available.

BUGFIX

Workflow Child Restart and Replay Status Fixes

When stepping in mid-run with a shortcut or replaying a finished flow, both the main agent and the interface now know the exact attempt count and what was found. After you restart a Workflow child task with r, the main agent you are talking to receives a direct notice telling it which child task you restarted and on which attempt it finished, rather than relying only on the child task's own words. After cancelling a Workflow, the main agent still receives what the already finished child tasks found, instead of reporting that nothing came back. When replaying a finished Workflow, the rerun agent's conversation continues to show the correct attempt count, such as attempt 2/2, instead of wrongly showing attempt 1/1.

BUGFIX

Subagent Resume Instructions and Failure Notice Fixes

After dispatching subagents to work in parallel, handoff status is now clear whether you resume an old conversation or run into a failure. If developer instructions are replaced when resuming a session, any subagents started afterward use the new content instead of keeping the old instructions from when the session first opened. If you leave while a subagent is still running and resume the session later, the main agent is told the subagent was cancelled and the transcript adds a finished row, instead of the subagent silently disappearing. When a subagent fails to finish, its diagnostic message no longer overwrites the terminal interface's input box. The parent conversation shows the same notice as a settlement failure, while that original line still remains in redirected standard error and the local trace file.

BUGFIX

Model Connection Retries and Streaming Usage Tolerance Fixes

Connecting to external models can occasionally hit overload, dropped streams, or odd payloads, and these cases are now handled more decisively. When the model service briefly reports being overloaded, the first retry starts after about 1 second instead of stalling the turn for a full minute. When an OpenAI, Anthropic, or OpenRouter endpoint replies to a streaming request with a non-SSE page, or a data stream breaks due to malformed data, the turn fails fast with the real protocol reason. It no longer retries the same broken response until the timeout. For some models, once reasoning summaries are requested, the server drops the progress text beside tool calls. After receiving the first such response, that session stops asking for summaries so the progress text appears again. On the OpenAI or Anthropic provider, if a finished turn's usage block has a missing, string-typed, or otherwise abnormal token count, the answer is still kept. Abnormal counts are treated as 0, matching the Meta provider.

FEATURE

muse serve Search Mode and Warning Calculation Alignment

Resuming a session through muse serve preserves the previously recorded web-search mode instead of turning it off upon return. If the startup catalog refresh finishes before the server loads its list, muse serve no longer rejects models offered by model/list, nor does it mistakenly accept models that were removed. When calculating context-pressure warning values, sessions hosted by muse serve now follow the terminal's behavior by computing them from the configured compaction thresholds and context limit.

BUGFIX

muse exec Output and CLI Help Fixes

When integrating muse exec into automation scripts for batch runs, plugin toggles, help text, and final output accuracy are all improved. muse exec now honors the plugins.activation setting, so disabled plugins (including muse-core) no longer add their skills to the run. When muse exec --json finishes, output is no longer truncated even if a large batch of session records has not been written out yet. This prevents losing results from later runs or falling back to an earlier run's exit status code. After a CLI run finishes, a stalled notice check no longer withholds the result, and a check timeout issues only a single warning. The --reasoning-effort help text in muse --help and muse exec --help no longer describes the setting as Meta-only. The default reasoning effort is high, or the highest reasoning-effort tier provided by Meta; interactive sessions on other providers default to none.

BUGFIX

Fixes for Plugin Hook Paths and Trace Export Reports

Checking plugin settings, inspecting tool logs, or exporting usage data now gives paths and times that match reality. When muse plugins validate and the plugin install report hit a hook issue, they now name the specific hook file with the problem instead of pointing to its manifest file. Whether it is an unsupported event, a malformed handler, or an ignored silent key, the reported path is the file to open and fix. On Linux and macOS, the warning for an oversized SKILL.md file now reports how much it actually exceeds the limit, instead of always saying 1 byte over. When muse trace inspect checks a request that replays earlier tool calls, it no longer reports a byte difference caused by tool names; sessions recorded by an earlier version will still show it, though. The session uptime reported by muse export now covers the entire Muse process, including startup and resume, instead of resetting for each session.

BUGFIX

Clearer Worktree Branch Conflict and Base Flag Checks

When you are about to open another working branch to code in parallel, prompts are no longer vague if a name collides or a base point does not match. When starting a session worktree, if that branch is already checked out in another worktree, it now fails directly and names the worktree holding it, instead of throwing a generic error that quotes raw Git output. If you create a worktree for an ID whose branch already exists and you also pass a --worktree-base that is not that branch's tip, it is now rejected outright. It lists the branch name and how to proceed, instead of quietly starting on that branch while dropping the flag.

Renting a shared parking spot used to work the same way: if the spot was already taken, you only got a vague "cannot park" note, or your reserved time slot was silently erased; now it tells you straight out who is parked there, and when your parameters do not match, it explains on the spot how to fix them.
BUGFIX

Windows and Linux Sandbox and Process Fixes

For Windows and Linux users running isolated commands or closing background PowerShell sessions, environment handoff and cleanup are now more thorough. On Windows, muse serve and muse acp can now run sandboxed commands normally once sandbox setup is complete, instead of failing with "setup has not run". muse serve also correctly reports that the sandbox is available. Also on Windows, stopping a background PowerShell session running without the sandbox and without tty now also ends the other programs it started, even if the shell itself already exited earlier. On Linux, a sandboxed command now locates its placeholder registry only once, so even if a per-user runtime directory appears while it is starting up, it will no longer leave denied paths unprotected or mistakenly block other sandboxed commands from the same user.

FEATURE

Old History Cleanup and Deferred Writes Save Disk Space

If you worry that conversation history files will fill up your disk over time, old files are now cleared automatically and new ones are only created when needed. Message history database files left in session folders by earlier versions are now automatically removed in the background to free up space. History copies saved for a session by older Muse versions are also automatically deleted from disk once they go 7 days without a write and no Muse instance has that session open. Sessions started from the terminal or with muse exec use less space: the history for the desktop app is now created only the first time the desktop app opens that session, instead of being written on every turn. Until then, conversations still open in the terminal will not show history in the desktop app.

Cleaning out an old storeroom used to leave boxes from past moves sitting around for years, and every time you wrote a note you printed an extra copy for another office; now unused overdue boxes are cleared out automatically, and extra copies are only printed when the other side actually comes to pick them up.
BUGFIX

No-Op Hook Runs No Longer Write to Session Logs

With many hooks installed, they used to write to the session log and take up space even when they changed nothing. Hooks that run after a tool call, after a batch of tool calls, or when a subagent starts no longer leave a record if they exit with code 0, write only whitespace to stderr, have no system message, have no error, and have no effect, even if they print to stdout. All other cases are recorded when they finish. Hooks triggered when a prompt is submitted are omitted from the log only when they exit with code 0, write only whitespace to stderr, and have no added context, block, rewrite, system message, or error. Skipping these no-op records saves disk space, while everything else is logged as before.

A building security guard on patrol used to write a long report for every locked door passed; now, when everything is fine, no paper is wasted, and a log entry is only written down when a door is opened or something looks off.
FEATURE

Lower Memory Usage for Long Sessions and Resumes

As a conversation grows longer, or when opening a massive old log that was never compacted, the program now uses less memory. Each event record that an active session keeps in memory is now smaller, making long conversations lighter on resources. When resuming a long session that was never compacted, the decoded copy of the log is released before rebuilding the session state, lowering peak memory usage. The subagent view no longer remembers every event it has displayed. The display layer also no longer carries the task activity journal from earlier turns into each new turn.

Running a long marathon used to mean stuffing every empty paper cup and road sign you passed into your backpack; now you clear out unneeded scraps as you run, making every step noticeably lighter.
BUGFIX

SDK Connection Checks and Session Protocol Updates

When developers connect their own tools to this engine, both pre-connection version compatibility checks and post-task summaries have been updated in this release. When starting a TypeScript SDK connection, you can now configure it to refuse connecting to a host that has declared a breaking protocol change; by default it still connects normally and provides a method to report the mismatch tier. Session protocol completion records and shell items can include ordering position information to preserve completion order. When requesting a recap through the SDK after a background task, monitor, or scheduled task finishes, it now summarizes that newly completed task instead of mistakenly summarizing your earlier message. When an error occurs during resume, the session protocol no longer claims that a repaired log file was unchanged.
