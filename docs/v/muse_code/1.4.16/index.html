Muse Code 1.4.16

發布日期：2026-11-13

Original changelog

`session/read` of a subagent session now carries `modelTurnRunning`, which says whether the subagent is still running a model turn, when its parent session is open on the same server
`TurnErrorKind` gains `reasoningReplayRefused` (a chat that cannot continue after a model switch) and `contextOverflow` (a turn that cannot fit the model's context window), both not retryable, so session-protocol clients can tell these two failures apart; existing matches receive them in their catch-all arm
A session protocol `toolCall` item of a shell command now carries a short, display-safe title for the command (`bashTitle`) while Bash titles are on, so a client can label the row without parsing the model's raw text
`muse acp` is on by default, so editors that support the Agent Client Protocol (like Zed) can run Muse as their agent; the surface is experimental and may change in a later release
A `prompt.surfaces` setting turns developer-prompt blocks off by id (with an optional `default`) in global or project settings, and per session through session settings overrides; the five protected blocks stay on for now, and an unknown id is skipped with a startup notice (refused when a session sends it)
TypeScript SDK: `MuseClient.spawn` and `spawnMspConnection` accept a `spawnFn` option, so you can run the handshake and sessions against an in-memory fake host instead of a real `muse` process
Muse now records each session's developer instructions when it starts. When you reopen a session in the terminal (`--resume`, `--continue` or `tbh exec --session-id`) after changing `run.developer_prompt` in your settings, Muse saves the new text and uses it from the next turn. On a session whose developer instructions were set by this release's start or update, a remote send, open, list or poll made while a run is in its first step can wait until that step's checkpoint, never past the call's own deadline; other sessions see no change. Sessions created now cannot be opened by an older build that has this off
Muse checks its work more carefully: it tries other spellings and wider paths before saying something does not exist, finds which copy of the code a report is about before fixing it, reruns named failing tests in the setup they failed in, asks before a change a repository rule forbids or gates, reads the repository's own history and upstream branch, and stops to ask when a network policy blocks a step instead of routing around it
A workflow cancel that `muse serve` refuses now names the exact stop refusal in the error's new `stopRefusal` field, for example `stale_revision`
Muse keeps working when it built a result somewhere other than the screen, tab, page, or file you named, and adds it where you asked instead of offering to
Resuming a session after a crash now shows one notice listing the calls the crash cancelled, joined to the abnormal-exit notice when one prints, or on its own as a warning when it does not
Setting `developerPrompt` to a null or empty value in a session config now opts that session out of Muse's own developer context
Muse now states your session language pin on eligible main runs from the first visible output, deriving the pin deterministically from your own messages in the session (English when your input carries no language signal yet) instead of inferring a language from names, code, or tool output
A session on a host that `muse serve --per-session` or `muse attach --stdio` starts can turn its sandbox off or open its network at `session/start`, within what managed policy allows, when its client opts into the experimental API
On a `muse serve` session that has compacted, forking the conversation, including a subagent that starts from it, no longer fails as a malformed session log when a later turn's instructions are kept only by the compaction checkpoint
A `muse serve` session whose trusted workspace path is a symlink to a folder now starts with the project's custom agents instead of failing with "source root is a symlink"
In `muse serve`, taking back a queued message on a stuck session whose command queue is full now fails after 30 seconds with a busy error you can retry, instead of waiting until the session recovers
Long sessions that start many subagents no longer stop saving checkpoints: a subagent that finished and whose result the main agent already read, for example by waiting for it, now drops out of the saved session once the conversation no longer mentions it, even if nobody closed it
Messages that interrupt a subagent stop showing as queued when its replacement starts
Stop sends its interrupt again when the host says it is busy, so the running turn stops instead of running on
Reinstalling a plugin while a session is using it no longer fails when the only difference is the permissions of the plugin's top folder, which can differ when installs run under different umasks (for example one from a background service and one from a terminal); the copy in use is left alone and replaced at the next install after those sessions end
Body-completion receipts now reach session-protocol clients as dedicated history rows, so a timed-out, steered, or compacted-away tool body keeps its result and expansion state on the client instead of dropping them
The "session log flush degraded" note at the end of a turn no longer goes missing when a checkpoint flushed the session log after a save had failed earlier in the turn
A long session no longer stops with an error that its input plus the requested output exceeds the model's context window: when the window is nearly full, Muse asks the model for a shorter reply instead
A workflow cancel that hits a session storage error is now refused with a reason by `muse serve` instead of failing with an internal error
A message sent or queued while the agent is busy no longer shows "steer failed" and comes back to the input box when the agent is slow to confirm it; it stays queued and is delivered once
Sessions interrupted during startup now reopen normally instead of failing
Session index no longer rewrites itself forever and hangs shutdown when the sessions folder is under a path that is not valid UTF-8
Terminals that show program status (OSC 7501) now return to idle when a scheduled or other background turn completes after one of your turns failed, instead of showing that old error again after every background turn
Resuming the same Workflow preserves the user's token limit
Preserve background agent recovery after compacting and reopening a session
The "session log flush degraded" note at the end of a turn no longer goes missing when a save failed earlier in the turn and the turn then sent a video or settled a tool approval that waited across a restart
Show answers from `/goal resume` without reopening the conversation
Pausing a workflow no longer reports unfinished background work as a missing result
Message approval previews preserve comparison operators and underscores
Forking a resumed session that has a goal no longer fails when the session compacted in the middle of a turn
Compacting a session whose recent turns hold many full-size images, such as screenshots, now saves its checkpoint in most cases instead of skipping it, so the session can resume from that point; the compacted context keeps up to about eight recent full-size images as they are; older images, and a single batch of more than eight, are summarized
Resuming a long session uses less memory, because each tool-task record kept in memory is smaller
Reduce reply display delays after resuming sessions with long subagent histories
Resuming a session with many finished subagents uses less memory and does less work when it first reads each of them, because a finished subagent's tool history is no longer copied into the bookkeeping that tracks subagent attempts
