Muse Code 1.4.12

Released: 2026-10-25

Release notes

FEATURE

Built-in Browser Game Skill Tests Playability and Runs Multi-Round Verification Based on Design Needs

When you want to quickly turn a game concept into a playable web prototype, you can now directly invoke the built-in browser-game skill. It automatically sizes the workload to the request's scale and personally tests the game with real input before handoff.

Picture an independent toy workshop crafting a new action figure: before handoff, the artisan personally presses every joint to check the feel, and for complex mechanisms calls in a fresh tester to verify each item against the manual, fixing issues before packaging and delivery.

When dealing with a long game design document, it runs up to three rounds, with a fresh reviewer testing a copy of the game against a checklist and the brief's rules in each round to fix whatever issues that round uncovers.

BUGFIX

3D Visual Skill Runs Twice as Fast, Triggering Multi-Agent Pipelines Only for Polished Projects

When building three-dimensional scenes or 3D web pages, the biggest worry is having simple models forced through a tedious review process that drags out progress. Now /game-3d-visuals skips the separate visual-plan review by default and runs only one render-versus-reference fix round, cutting execution time roughly in half.

Like a photo studio developing prints, everyday snapshots run straight through the printer, while only film brought in for retouching or fine-art salon portraits gets sent into the darkroom for artisans to color-grade.

The skill no longer intervenes across the board, starting automatically only for tasks requiring polished results (such as providing a reference image, Blender models, or an explicit high-fidelity request). Quick 3D pages and small games are built directly without waiting in a multi-agent pipeline.

BUGFIX

Micro-Edits Skip Upfront Tests, Sharpening Boundaries for Planning Commands and Review Gates

When you only want to change a button color or tweak a single config line, being forced to write a failing test case first often feels unnecessary. Now tiny text, style, or config changes, throwaway prototypes, one-file scripts or pages, and requests for a quick result no longer start by writing a failing test. Other routine fixes run the full test suite once after the last edit, reporting progress on the status line (the status bar displayed at the bottom of the terminal) during long test runs.

Think of a tailor replacing a single button without drafting an entire pattern: while every single stitch used to require a full inspection, small mends are now handed over promptly, and major alterations wait for the client's approval before being delivered.

When entering /plan for a small change, Muse carefully plans out the steps instead of implementing them directly. The skill identifies how the content arrived, reading implement-shaped task text as the planning subject rather than an implementation request. A user review gate also explicitly defers outward-facing actions, pausing execution until post-inspection approval to prevent bounded steps from running ahead into tracker and chat writes.

FEATURE

Enhanced Research Note Guidance Puts Critical Result Details First in Final Reports

When asking an assistant to carry out multi-faceted research, sprawling background investigation notes often drown out the core findings in the final report. The new release strengthens guidance rules to help agents organize research findings and notes into the final report with greater structure.

A veteran editor lays out the morning paper by printing the key figures and headline takeaways right at the top of page one, keeping dozens of pages of interview drafts filed neatly in the back for reference.

In workflow guidance, key details for large results are now consistently placed ahead of lengthy research notes. This allows you to grasp the most substantial findings immediately upon opening the report without wading through large blocks of reference notes to find the point.

FEATURE

Local Port Permissions Configure Independently, Ending Repeated Confirmations for Same-Command Network Requests

When running local web servers or testing APIs inside a sandbox, previous network rules made it difficult to precisely control which local ports were opened. Permission profiles can now open chosen ports to sandboxed commands via network.local_ports, setting each port individually to allow, ask, or deny. Selecting ask prompts on each connection under Linux and once per session under macOS. Loopback entries in network.targets are now rejected and must be migrated to network.local_ports. Older builds cannot open chats that saved local-port rules or managed local-port limits and require an update, though other chats are unaffected.

Security guards at a corporate campus install dedicated gates and issue access cards for individual storerooms; once a courier logs in, subsequent trips during the same run are no longer questioned repeatedly.

After you approve a network request for a non-interactive command once, subsequent requests to the exact same host, port, and protocol no longer prompt for confirmation while that command runs. If a /permissions change fails, it also directly names why the update could not be saved.

BUGFIX

Sandbox Deny Rules Cover Nonexistent Paths, Clearly Explaining Fixes When Writes Are Blocked

Running into a read-only filesystem error inside a sandbox environment often used to leave developers puzzled. When a sandboxed command attempts to write outside the session's writable roots (such as a cache path under the home directory that temporarily stores computed results), the interface no longer just throws a raw filesystem error. Instead, it clearly explains that the sandbox blocked the write and proactively lists remedies: granting access via workspace_roots, running unsandboxed for a single run, or pointing the cache path to the workspace or the /tmp directory.

Strict building management regulates renovations by blocking unauthorized partitions before work begins, offering detour directions when someone heads toward the wrong exit, and clearing away empty boxes if construction halts midway.

Security defenses have also been reinforced: deny rules now fully cover paths that do not exist yet in sandboxed shell commands, blocking creation outright without leaving any trace behind. If a command is killed mid-run, leftover empty placeholder files are cleaned up automatically, preventing them from interfering with the next command that applies the same deny rules.

BUGFIX

Workspace Grants Support Multiple Roots While Sandboxing Version Control Commands

When working on large projects spanning multiple repositories, the security boundaries of file tools and version control commands are critical. Shell commands can now write under every workspace root a client grants with workspaceRoots, no longer restricted to the primary root. Both shell and file tools refuse access to roots that no longer resolve to their recorded locations. An issue where degraded session recovery lost the latest workspace root list has also been fixed.

Consider access control across multiple warehouses: while only the main building used to be guarded, auxiliary facilities are now fully added to the allowlist, and inspection carts operate strictly within an isolated security perimeter.

Sapling commands executed automatically (workspace snapshots and session worktrees) now run entirely inside the sandbox. Session worktrees also refuse to run Sapling in a workspace that has not been trusted yet. Worktree (a feature that lets you open multiple parallel copies of a project) creation and cleanup remain sandboxed inside unprivileged containers. On EdenFS checkouts, sl and hg must go through the launcher with the sandbox disabled to access Eden state. The native sandbox no longer grants access to the Eden filesystem or sockets.

FEATURE

Sandbox Startup Anomalies Alert Promptly, Preventing Interrupted Flows from Leaving Half-Baked Sessions

When launching command-line tools, silent failures in background security defenses make it easy to run dangerous commands without protection. Now, if the configured Bubblewrap path is unusable, startup resumes showing a warning that the sandbox is unavailable. If the configured Linux sandbox helper path is unusable, startup fails with a clear error and halts, rather than silently falling back to unsandboxed mode.

Much like an automobile dashboard running a self-test at ignition, warning lights now illuminate instead of hiding trouble notices, locking the ignition only when encountering faults that must prevent engine start.

If the startup process is interrupted mid-flight, Muse also no longer leaves behind a partially created session.

BUGFIX

Chat Rewinds Handle Edge States, Restoring History Even After Compaction or Save Failures

When you want to abandon a conversational path and step back to previous turns, encountering storage errors or compacted history used to trigger outright refusals. Now the chat rewind feature works smoothly across various edge cases. Rewinding to before a turn that failed, or whose end could not be saved (for example on a full disk), now succeeds instead of being refused. Turns that can never be rewound are clearly shown as unavailable instead of being offered in the options.

An audio cassette deck rewinding past tape splices or noisy segments no longer snags and jams, smoothly skipping over damaged spots to stop precisely where re-recording should begin.

If a conversation has undergone context compaction, or if the preceding turn was still running when a checkpoint was saved, rewinding is no longer refused after you confirm it. Even when the start of a turn could not be written to disk because storage ran out, the chat can still be rewound, and the process automatically leaves out the damaged turn while Muse informs you once.

BUGFIX

Full Disks Halting Turn Writes Isolate Damaged Turns Automatically to Preserve Chat Progress

When disk storage runs out right at the start of writing a turn, restarting the application previously risked losing all subsequent history. Now, whether in the terminal app or in chats opened through the Muse session server, if the start of a turn cannot be written due to a full disk, that turn is safely set aside upon restarting and reported once without losing later checkpoints.

Just as a loose-leaf binder handles an ink-stained page by filing the ruined sheet into an appendix pouch, the entire notebook remains open for reading, copying, and continuing notes as usual.

Even if a chat loses two saves in the same turn (a tool result followed by the next tool call), it can now be reopened cleanly. Such chats can also be forked and can open side chats; the new chat skips the unwritten turn and informs you once. If a forked sub-chat encounters the same write failure itself, reopening also leaves out that turn, reports it once, and allows you to continue execution.

BUGFIX

Explicit Errors and Automatic Recovery for Storage Failures Resume Progress Once Hardware Issues Resolve

When facing disk space shortages or occasional read/write errors, save failures that retry indefinitely can freeze operations. Now, when a reply or subagent result cannot be written, Muse retries briefly and then displays an error explaining why new messages are refused. At this point, running /new, /clear, or other actions that start a new session, configuring a local model, or swapping a provider key immediately displays "saving failed … retrying automatically", allowing you to retry the command once the chat recovers.

A coin-operated machine that jams used to leave buttons completely unresponsive; now it displays an error notice, and once the blockage clears you can continue using it.

When background saving is interrupted by a brief read/write error and never retried, or when a file temporarily cannot be opened or read, saving resumes once the issue clears without requiring a restart. When checkpoint writes are interrupted twice in a row, the chat and reminder helper clean up the half-written file before resuming saving. Tool results and other chat records that failed to save while the disk was full are saved again at the session's next step once sufficient space is available.

BUGFIX

Session Forking Gains Resilience, Accurately Preserving Target Turns Under Heavy Load

Branching an independent exploration from an existing conversation can disrupt thinking if heavy system loads trigger internal errors. Forking and side chats now handle heavy loads without throwing internal errors, and forking from an earlier turn preserves history up to and including that specific turn.

Photocopying borrowed files in a print room used to reject requests after pages were selected; now it binds through the specified page, and high foot traffic no longer triggers false alarms.

Certain compacted sessions and forks of forks may still refuse truncation or forking from later turns, and truncations that retain no turns from an older session are still rejected while that session remains open. Even when a previously full disk prevented a tool call from writing to disk, forking or starting a side chat remains fully supported as long as the tool result landed and a later checkpoint exists. Forking a session over the session protocol also eliminates intermittent false conflict reports claiming the new session is already in use.

BUGFIX

Side Chats Isolate Write Failures, Support Initial Manual Compaction, and Ensure External Tool Compatibility

Opening a side chat to test alternative ideas becomes frustrating when saving failures in the secondary view cascade into the main chat. Now, when a side chat write fails due to full disks or similar faults, the main chat continues saving progress and can still be forked once the issue clears without being dragged down. Side chats also fully preserve the original conversation after saving a checkpoint.

Chopping ingredients on a side cutting board keeps the side prep neat even when scrap piles up, and an accidental spill never fouls the main soup simmering on the primary burner.

Side chat capabilities are also more complete: the first manual compaction now runs smoothly, including after resuming a session. If a project configures MCP (Model Context Protocol, a protocol connecting AI to external tools), entering /side right after resuming a chat no longer blocks subsequent messages from reaching the model. Side chats launched via /side run independently in a lightweight environment without MCP tools.

FEATURE

Failed Context Compaction Preserves Conversations, Resuming Instantly Once Storage Recovers Without Restarts

When conversations grow exceptionally long, background attempts to compact context that fail risk terminating the entire request. Even if compaction fails, Muse preserves the full context so that long requests continue running smoothly without dropping mid-stream.

When a compression bag zipper snags during seasonal wardrobe sorting, the storage trunk keeps holding your clothes in place rather than dumping them outside, letting you resume vacuum sealing the moment the bag is fixed.

This improvement also addresses cascading issues related to storage pressure. Previously, when replies or ordinary tool results failed to write due to a full disk, restarting the software was often required to restore checkpoint saves; now, compaction checkpoints resume working immediately as soon as disk space clears. After a mid-reply compaction, the terminal interface also no longer fires a needless second auto-compaction caused by a stale Blocked pressure reading.

BUGFIX

Workflow Status Remains Transparent with Automatic Model Fallbacks and Clear Interruption Guidance

In multi-agent collaborative workflows, pausing or stopping a step previously caused the interface to surface internal errors. When a workflow pause or stop prevents an agent call from starting, the recovery line and failed row now explain the reason and suggest "Start the Workflow again if it is still needed.", no longer reporting an internal error or asking for a /feedback report.

An assembly line dispatch desk with a technician on leave reassigns tasks to an available specialist with a clear note; during a stoppage, the display board explains how to restart instead of blaring an erroneous plant-wide alarm.

If a requested model is not offered in the current session, the call falls back to the session's model, and the main agent informs you which calls ran on which model. Notifications about a subagent switching models or having a wake-up refused still arrive on the subsequent turn, even if the immediately following turn was cancelled before starting. Leaving a session with stop: true stops the running workflow before handing over, preventing resume prompts from asking about recovery. For workflows that end after a durable fact write fails, the bottom work list displays the failed or cancelled result before clearing after the usual grace period.

BUGFIX

Individual Workflow Calls Can Fail in Isolation, While Persistent Storage Errors Still Halt Runs

When running complex multi-agent workflows, briefly running out of disk space could easily scrap an entire series of tasks. Now, when the startup state of a new agent call cannot be written even after one retry, only that specific call fails with a plain reason, while the rest of the workflow continues running. If another agent's startup state cannot be confirmed as saved, only that invocation aborts; however, if storage has still not recovered, the workflow halts at its next save.

A relay race runner withdrawing unexpectedly used to cancel the entire event, but officials now isolate that single leg; if the track itself remains unusable, the subsequent race still halts.

When a write fails as a background helper session starts, subsequent saves and checkpoints resume once the issue clears. After a full disk cancels a workflow, late-arriving background results no longer freeze checkpoints, and opening a new chat will not retry an unsaved run ending from the previous chat. If a chat fails to save a workflow result and then invokes another tool, it can still be reopened in the same application session following a restart.

FEATURE

Subagents Support Live Transcript Views, Resilient Status Reporting, and Reliable Crash Recovery

When a primary agent dispatches subagents to handle subtasks in parallel, tracking internal progress and live activity is essential. Opening a subagent's detail view now loads the transcript directly from the child's own session and keeps it live while open. When sending notes to a running subagent, once the recipient picks them up, the interface immediately displays a Delivered row confirming delivery.

Field expedition headquarters linking into body cameras maintains a live feed and stamps notes as delivered upon receipt; when a team member loses signal, it honestly reports the disconnect rather than guessing or blindly reissuing dangerous blasting orders.

Error recovery mechanisms are also safer. If a subagent crashes, recovery procedures faithfully report missing tool results as unknown instead of automatically and dangerously rerunning calls. If a subagent stop is interrupted right after taking effect, reopening the session automatically completes the stop record, opening successfully even if writing is blocked and retrying on the subsequent launch.

BUGFIX

Background Tasks Accurately Wake Sessions, Improving Notification Controls and State Watching

When offloading time-consuming builds or tests to the background, sessions must wake the moment those runs finish. Idle sessions now reliably wake when a background task completes; if the session is busy when completion occurs, it wakes as soon as the currently blocking run settles.

A smart timer installed for long-running kitchen baking alerts the chef precisely when the oven finishes, notifying them right after their prep work wraps up if their hands are currently full, and tapping the phone notification immediately shuts off the oven.

Background management and goal modes are also more flexible. Stopping background work directly from notifications now succeeds without reporting that the task was not found. Goal sessions waiting on external work rely on a change watcher instead of appearing hung. Even if a one-time storage error leaves a background task save unconfirmed, periodic session checkpoints continue landing instead of being refused until restart.

BUGFIX

Server Mode Supports Run Presets, Clean Connection Teardown, and Hook Scheduling

When hosting a session server with muse serve, applying preset configurations and managing clean connection exits are core to operational stability. Starting a host now supports --preset to select a run preset, and hooks (small programs triggered by specific events) configured from the command line like -c hooks.… execute reliably instead of being silently dropped.

Front desk checkout at a hotel used to tie up rooms indefinitely whenever a departure notice failed to transmit; now requests resolve at their deadline, and closing down for the night no longer requires re-reading the entire guest registry.

When an accepted reply for session/leave cannot reach the client, it fails at its deadline instead of holding the session until the connection closes. If a timeout occurs, reading that session on the same host reports that it is still stopping until the runtime terminates, after which it can be read again. Replaying the original session/start on an ephemeral host returns the original acknowledgement without recreating the removed session. Leaving a session or shutting down the host no longer rereads the entire chat history.

BUGFIX

Remote Retries Avoid Conflicts, Rebuilding Full History from Logs When Disk Views Break

When operating Muse over remote protocols, dropped connections or damaged disk views often cause out-of-sync session states. Now, after restarting the server, resending turn/start for a completed turn with the same command ID is idempotent (producing the same result when resent), returning the original reply instead of a conflict. When a stale view appears idle, new prompts steer into active background delivery instead of triggering duplicate runs.

Bank wire transfers used to risk errors on reconnecting after a dropped connection, whereas identical transaction IDs now pull up the original receipt; worn passbooks can also be reconciled immediately without requiring an extra visit.

When disk views are damaged, such as a corrupt HEAD.json, resuming rebuilds the full history directly from the session log without requiring reopening. Sessions using a goal continuously save checkpoints to accelerate resume, and history views accurately display completion markers for background terminals. In --no-session-log mode, pending approvals and questions remain readable after launching subagents.

BUGFIX

Cross-Version Session Compatibility and Viewing for Partially Damaged Chat Logs

When team members run different versions or chat logs are unexpectedly damaged, the inability to open files often blocks troubleshooting. Now, if a saved chat log has a missing or unreadable damaged line in the middle, it still opens for reading in apps that support the protocol, provided the chat was never compacted. The interface displays everything readable with a notice at the damaged spot instead of blocking the entire chat, though continuing or forking such a chat is still temporarily refused.

In an archival reading room, a single moth-eaten line once barred access to an entire ancient volume, but staff now insert an advisory slip so readers can view the rest.

When a newer version adds a new field member to durable session records, older builds keep reading them instead of failing entirely over unknown members. Chats containing saved continuations of finished subagents require a compatible version to open. Older builds also cannot open a chat whose permissions were reset because part of its saved permission history was lost or damaged, requiring a Muse update; other chats remain unaffected.

BUGFIX

Terminal Noise Filtering, Keychain Timeout Protection, and Error Deduplication

Working continuously in a terminal environment makes repeated error cascades or exit screen clutter from internal logs especially frustrating. When the same configuration, environment, or step-limit error stops two consecutive dialogue turns with nothing displayed between them, it now appears only once while the session runs. Quitting the text user interface (TUI) also automatically redirects internal cleanup and shutdown diagnostics to the local log file.

Built-in noise suppression inside a sound system automatically filters repeated noise when a needle skips and cuts power quietly at the switch, leaving no harsh shutdown pop in the speakers.

On macOS, if the Keychain stops responding, the program stops waiting after 5 seconds and notes that your login is still saved, and running muse --help no longer waits on the Keychain. When the chosen model is missing from the cache, the background refreshes the model catalog only once. If a /feedback upload fails, the interface also displays the specific reason returned by the server.

BUGFIX

SDK Companion Package Auto-Installation and Setup Deduplication for Faster Session Resumes

When developing Muse applications in Python, missing core dependencies after installation often leaves developers unsure where to look. Now, running pip install muse-code-sdk automatically installs the companion wire-types package, allowing a fresh environment to execute import muse_code. SDK applications also correctly identify a new turn started by Replace as the running turn (activeTurn).

Unboxing flat-pack furniture previously required hunting down missing parts, but tools and screws now arrive bundled together, while repetitive assembly instructions are condensed into a single shared guide that keeps packages lighter and setups faster.

Long sessions store repeated setup blocks once to speed up loading. Messages awaiting replacement or queued during a crash are accurately marked as abandoned when retried. Resumed sessions exit normally after completing their run instead of hanging on earlier tool rejection records. Once a reminder check has reached a decision, it no longer runs repeatedly even when blocked by a Stop or PreToolUse hook (a small program triggered by specific events).
