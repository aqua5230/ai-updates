Muse Code 1.4.12

發布日期：2026-10-25

繁體中文

新功能

內建瀏覽器遊戲技能，依設計需求自動試玩與多輪驗證

當你想把腦中的遊戲點子快速變成可玩的網頁原型時，現在能直接叫用內建的 browser-game 技能。它會依據需求規模自動調整工作份量，並在交付成品前以真實輸入親自試玩遊戲。

好比獨立玩具工坊製作新公仔，交件前師傅會親手按壓關節確認手感，面對複雜機關還會請全新試玩員逐項核對說明書，修正問題後才包裝出貨。

若是遇到長篇的遊戲設計文件，最多進行三輪，每輪由新的審查員試玩副本，對照檢查清單與需求規則，修正該輪發現的問題。

問題修復

3D 視覺技能耗時減半，精緻專案才觸發多代理人管線

建構立體場景或 3D 網頁時，最怕簡單模型也硬塞進繁複的審查流程而拖慢節奏。現在 /game-3d-visuals 預設跳過額外的視覺計畫審查，改為只跑一輪渲染與參考圖對照修復，執行時間縮短約一半。

宛如相館沖印照片，一般生活快照直接過機列印，只有拿出底片精修或指名沙龍質感的作品，才會送進暗房讓師傅分工調色。

這項技能也不再凡事介入，只有遇到需要精緻成果的工作（例如提供參考圖片、Blender 模型，或明確要求高畫質）才會自動啟動。快速建置的 3D 頁面與小型遊戲會直接生成，不必在多代理人管線中空等。

問題修復

微型修改略過前置測試，規劃指令與審查關卡界線更分明

只是想改個按鈕顏色或微調一行設定，如果每次都要先寫一個失敗的測試案例，往往讓人感到多此一舉。現在微小的文字、樣式、設定修改、拋棄式原型、單檔腳本或網頁，或要求快速結果的任務，都不會再強制先寫失敗測試。其他常規修復改在最後一次編輯後跑一次完整測試套件，並在長測試期間於 status line（顯示在終端機最底下的狀態列）回報進度。

就跟裁縫店換顆扣子不必大費周章畫版型一樣，以前動一針就要走完整套驗收，現在小修補俐落交件，大工程在送出門前也一定等客人點頭才寄出。

對小變更輸入 /plan 時，Muse 會認真規劃步驟而非直接實作。這項技能會辨識內容來源，把看似要實作的任務文字當成規劃對象。使用者審查關卡也明確推遲對外操作，在檢視核准前暫停執行，防止步驟超前寫入追蹤器或對話紀錄。

新功能

強化研究筆記整合報告指引，重要成果細節優先排列

當你請助理執行多方調研時，繁雜的背景調查筆記往往會淹沒最終報告中的核心結論。新版強化了引導規則，協助代理人更有條理地把調研成果與筆記整理進最終成果報告中。

好比資深主編排版晨報，讀者最關心的重大數據與頭條結論直接印在頭版最上方，滿滿十幾頁的採訪草稿則整齊收在後頭備查。

在工作流程的指導原則中，產出大型結果的重要細節現在會固定排在冗長的研究筆記之前。這讓你打開報告就能立刻掌握最具分量的關鍵產出，不必再費力翻越整大段的參考筆記才找到重點。

新功能

本機通訊埠權限獨立設定，同指令重複網路請求不再反覆確認

在沙盒裡執行本機網頁伺服器或測試 API 時，以往的網路規則很難精準控制開放哪些本機連接埠。現在權限設定檔能透過 network.local_ports 開放指定連接埠，個別設為 allow、ask 或 deny。Linux 選 ask 每次連線提示，macOS 每個工作階段詢問一次。network.targets 的環回項目現在會遭拒絕，必須遷移至 network.local_ports。舊版無法開啟儲存本機連接埠規則或受管理連接埠限制的對話，須更新；其他對話不受影響。

就像園區警衛換上專用閘門，各庫房個別發卡；送貨員登記一次後，同趟往返不再反覆盤查。

核准非互動式指令的網路請求後，同一指令執行期間，對相同主機、連接埠與協定的後續請求不再重複詢問。若 /permissions 變更失敗，也會直接列出無法儲存的原因。

問題修復

沙盒禁止規則涵蓋未存在路徑，寫入受阻明確提示解法

面對沙盒環境跳出的唯讀檔案系統錯誤，以往常讓人摸不著頭緒。當沙盒指令嘗試寫入工作階段的可寫根目錄之外（例如家目錄下把算過結果暫存起來的快取路徑），介面不再只丟出冰冷的檔案系統錯誤，而是會明確說明受到沙盒阻擋，並主動列出解法：包含透過 workspace_roots 授權、以非沙盒模式單次執行，或是將快取路徑指向工作區或 /tmp 目錄。

如同大樓嚴格管制裝修，未經核准的新增隔間在動工前就被直接擋下，走錯出口時保全會附上通行指引，施工半途中斷也會將空箱清理乾淨。

安全防護也進一步加固：拒絕規則現在完整覆蓋沙盒指令中尚未存在的路徑，徹底封鎖建立行為且不留痕跡。若指令在執行中途被強制終止，殘留的空白佔位檔會自動清理，不再干擾下一個套用相同拒絕規則的指令。

問題修復

工作區授權支援多根目錄，版本控制指令納入沙盒防護

處理跨多個程式庫的大型專案時，檔案工具與版本控制指令的防護邊界至關重要。現在 Shell 指令可寫入用戶端以 workspaceRoots 授權的每個工作區根目錄，不再受限於主目錄；Shell 與檔案工具都會拒絕存取不再指向原位置的根目錄。降級工作階段復原遺失最新目錄清單的問題也已修復。

跟多庫房聯外通道管制一樣，以往只鎖定主倉庫，現在副庫全數列入許可清單，巡檢推車也一律在隔離防護網內作業。

自動執行的 Sapling 指令（快照與工作階段工作樹）全數移入沙盒內執行；工作階段工作樹也會拒絕在尚未信任的工作區執行 Sapling。無特權容器中工作樹（平行開多份副本的功能）的建立與清理都維持沙盒化；EdenFS 簽出中的 sl、hg 必須透過啟動器並停用沙盒，才能存取 Eden 狀態；原生沙盒不再開放 Eden 檔案系統與通訊端。

新功能

沙盒啟動異常即時警示，中斷流程不再殘留半成品

啟動指令列工具時，若背景安全防護失靈卻毫無聲息，很容易在無保護的狀態下執行危險指令。現在若設定的 Bubblewrap 路徑無法使用，啟動時會恢復顯示沙盒不可用的警告；若設定的 Linux 沙盒輔助程式路徑無法使用，則會明確報錯並停止啟動，不再靜默改以非沙盒模式啟動。

恰似汽車發動時的儀表板自我檢測，以前故障通知可能被藏起來，現在該亮的警示燈會亮起，遇到必須阻止發動的故障才鎖住點火。

啟動程序如果在中途意外遭到中斷，Muse 也不會再留下只建立到一半的工作階段。

問題修復

對話倒帶支援邊界狀態，壓縮後與儲存中斷皆可回溯

若想放棄先前的對話走向並回溯到前幾輪，一旦遇到儲存異常或壓縮紀錄，以前常會被整張拒絕。現在對話倒帶（rewind）功能在各種極端邊界狀態下都能順利執行。如果你想倒帶至失敗或結尾未儲存（例如磁碟滿載）的輪次之前，操作已能正常生效；永遠無法倒帶的輪次會直接標記為無法使用，不再出現在選項中。

猶如卡帶錄音機倒帶，碰上磁帶接合處或部分雜音段落不再咬帶卡死，而是順暢跳過損壞點並精確停在想重錄的時間點。

如果對話已經過上下文壓縮，或是儲存檢查點時前一輪仍在執行，確認後倒帶也不會再遭拒絕。即使遇到某一輪開頭因磁碟已滿未能寫入，現在依然能執行倒帶，流程會自動略過該受損輪次並主動提示一次。

問題修復

磁碟滿載中斷單輪寫入，對話自動隔離壞輪以保留進度

磁碟空間偶爾用盡時，若剛好卡在某一輪剛啟動的寫入瞬間，以前重開軟體很容易連帶丟失後續的所有紀錄。現在不論在終端機應用還是透過 Muse 工作階段伺服器開啟的對話，某輪開頭若因磁碟滿載未能寫入，重開後該輪會被安全擱置並提示一次，不會再遺失後續檢查點。

好似活頁筆記本有一張紙沾滿墨水，管理員將污損那頁夾入附錄袋，整本筆記依然能正常翻閱、影印裝訂與接續書寫。

哪怕同一輪中接連遺失工具結果與下一個工具呼叫的兩次儲存，現在也能順利重新開啟對話。這類對話也能進行分岔（fork）並開啟側邊對話，新對話會略過未寫入的輪次並提示一次。分岔子對話自身遇到相同寫入問題，重開後也會略過該輪、提示一次，並能繼續執行。

問題修復

儲存異常具備明確錯誤與自動復原，排除硬體問題即可接續進度

遇上硬碟空間短缺或偶發的讀寫錯誤時，儲存失敗若只會無窮重試，會讓操作卡住。現在回覆或子代理人結果無法寫入時，Muse 短暫重試後會顯示錯誤，說明為何拒收新訊息。此時執行 /new、/clear 或其他建立新工作階段的操作、設定本機模型、更換供應商金鑰，都會立即顯示「saving failed … retrying automatically」，對話復原後可重試原指令。

好比投幣機卡住，以前按鍵沒反應，現在會亮出故障提示，卡住的原因排除後便能繼續使用。

背景儲存被短暫讀寫錯誤中斷而未重試，或檔案暫時無法開啟、讀取，問題排除後都會恢復儲存，不必重啟。檢查點連續兩次寫入中斷時，對話與提醒輔助程式會清理半寫入檔案，再恢復儲存。磁碟滿載時未存下的工具結果與其他對話紀錄，會在工作階段下一步、空間足夠時補存。

問題修復

工作階段分岔更加穩固，精確保留指定輪次並抵抗高負載

想在探索新想法時從舊對話分岔出獨立分支，若負載一高就噴出內部錯誤，會打斷思考。現在分岔（fork）與側邊對話在高負載下不再報出內部錯誤；從較早輪次分岔時，會保留至指定輪次，包含該輪。

跟在影印室調借檔案一樣，以前挑好頁碼卻被拒絕複印，現在會連同指定那頁一起裝訂，人多時也不再無端報警。

部分壓縮過的對話與分岔的分岔，仍可能拒絕截斷或從較晚輪次分岔；舊工作階段仍開啟時，也仍拒絕不保留任何輪次的截斷。 即使過去曾遇上磁碟滿載導致工具呼叫未寫入，只要工具結果已寫入且後續有新檢查點，就能進行分岔或建立側邊對話。透過協定分岔工作階段時，也不會再偶發出現新工作階段已被使用的假性衝突。

問題修復

側邊對話寫入隔離，支援首次手動壓縮並相容外接工具

開啟側邊對話來驗證額外想法時，若副視窗的存檔失敗波及主對話，會讓人十分困擾。現在當側邊對話因磁碟滿載等原因寫入失敗時，主對話依然能持續儲存進度，且待問題排除後依然能正常分岔，不會再被牽連卡死。側邊對話在儲存檢查點後，也能完整保留原本的對話內容。

如同料理時在旁側切菜板切碎配料，副盤即便堆滿碎屑也能就地壓實整理，即使不慎翻落也不會弄髒正在主爐上熬煮的主湯鍋。

側邊對話的功能也更加齊全：現在第一次執行手動壓縮已能順利運作，即使工作階段恢復後也沒問題。若專案配置了 MCP（讓 AI 連接外部工具的協定），剛恢復對話後立刻輸入 /side，不會再阻擋後續訊息送達模型；由 /side 開啟的側邊對話會在不帶 MCP 工具的輕量環境下獨立運行。

新功能

上下文壓縮失敗保全對話，磁碟回穩無需重啟即刻恢復

當對話內容變得非常冗長時，背景如果嘗試壓縮上下文卻不幸失敗，最怕整個請求就此中斷。現在即使壓縮過程遭遇失敗，Muse 依然會保留完整的上下文，讓長篇請求能順暢地繼續執行下去，不再中途斷線。

宛如整理過季衣物時壓縮袋拉鍊卡住，收納箱不會直接把所有衣物丟出門外，而是維持原狀讓你繼續擺放，等袋子修好就能直接抽氣封口。

這項改進也修復了與儲存壓力相關的連鎖問題。過去若因磁碟已滿導致回覆或一般工具結果未能寫入，往往需要重開軟體才能恢復檢查點儲存；現在只要磁碟空間恢復，壓縮檢查點就能立刻接續運作。在回覆中途執行壓縮後，終端機介面也不會再因為過期的阻塞讀數，誤觸第二次無意義的自動壓縮。

問題修復

工作流程狀態清晰透明，缺席模型自動備援且中斷指引明確

在多代理人協同作業的 Workflow（工作流程）中，某個環節暫停或中止，以前介面很容易跳出內部錯誤。現在流程暫停或停止而無法啟動代理人時，復原提示列與失敗項目會說明原因，並建議「若仍需要請重新啟動 Workflow」，不再誤報內部錯誤或要求填寫 /feedback。

恰如產線調度站遇到技師請假，會改派現有師傅並註記；停機時看板也會說明如何重啟，不再誤鳴全廠警報。

若指定模型未在目前工作階段提供，呼叫會改用工作階段的模型，主代理人會告知各次呼叫用了哪個模型。子代理人切換模型或喚醒遭拒的通知，即使下一輪在開始前被取消，再下一輪仍會送達。帶有 stop: true 離開工作階段時會先中止流程，避免恢復時重問復原。寫入失敗而結束的流程，清單列會先顯示失敗或取消結果，再於通常寬限期後移除。

問題修復

工作流程個別呼叫可單獨失敗，持續儲存異常仍會停止流程

執行複雜的多代理人工作流程時，磁碟短暫寫滿很容易導致整串任務直接報銷。現在新代理人呼叫的啟動狀態重試一次仍無法寫入時，只讓該次呼叫失敗並說明原因，其餘 Workflow（工作流程）繼續執行。若是另一代理人的啟動狀態無法確認已存檔，也只中止當次呼叫；但儲存若仍未恢復，流程會在下一次儲存時停止。

好似接力賽有跑者臨時退場，以前整場直接取消，現在先處理該棒；若賽道仍無法使用，後續仍得停賽。

背景輔助工作階段啟動時寫入失敗，問題排除後能恢復儲存與檢查點。磁碟滿載使流程取消後，遲到的背景結果不再卡死檢查點；開啟新對話也不會重試舊對話未存檔的結束動作。流程結果存檔失敗後又呼叫其他工具，對話在重啟後仍能於同一應用程式工作階段中開啟。

新功能

子代理人支援即時記錄檢視，狀態回報與中斷復原更穩固

當主代理人派出子代理人平行處理子任務時，掌握它們的內部進度與即時動態往往是最關鍵的一步。現在點開子代理人的詳細檢視時，Muse 會直接自該子代理人的獨立工作階段載入記錄稿，並在開啟期間維持即時連線更新。當你向執行中的子代理人傳送筆記時，一旦對方成功接收，介面便會立即顯示「已送達」（Delivered）狀態列，確認訊息已交到子代理人手中。

猶如野外探勘指揮部連線隨身攝影機，畫面即時連線並在便籤傳達時打上已送達標記，隊員通訊中斷時誠實回報失聯狀態，絕不擅自猜測或盲目重發危險爆破指令。

異常復原機制也變得更加保險。如果子代理人遭遇當機，復原程序會把遺失的工具結果如實標記為未知，不再危險地自動重新呼叫。若要求停止子代理人的操作在生效瞬間被中斷，下次開啟工作階段時會自動補齊停止紀錄，就算寫入受阻也能照常開啟並於後續重試。

When operating Muse over remote protocols, dropped connections or damaged disk views often cause out-of-sync session states. Now, after restarting the server, resending turn/start for a completed turn with the same command ID is idempotent (producing the same result when resent), returning the original reply instead of a conflict. When a stale view appears idle, new prompts steer into active background delivery instead of triggering duplicate runs.

Bank wire transfers used to risk errors on reconnecting after a dropped connection, whereas identical transaction IDs now pull up the original receipt; worn passbooks can also be reconciled immediately without requiring an extra visit.

When disk views are damaged, such as a corrupt HEAD.json, resuming rebuilds the full history directly from the session log without requiring reopening. Sessions using a goal continuously save checkpoints to accelerate resume, and history views accurately display completion markers for background terminals. In --no-session-log mode, pending approvals and questions remain readable after launching subagents.

BUGFIX

Cross-Version Session Compatibility and Viewing for Partially Damaged Chat Logs

When team members run different versions or chat logs are unexpectedly damaged, the inability to open files often blocks troubleshooting. Now, if a saved chat log has a missing or unreadable damaged line in the middle, it still opens for reading in apps that support the protocol, provided the chat was never compacted. The interface displays everything readable with a notice at the damaged spot instead of blocking the entire chat, though continuing or forking such a chat is still temporarily refused.

In an archival reading room, a single moth-eaten line once barred access to an entire ancient volume, but staff now insert an advisory slip so readers can view the rest.

When a newer version adds a new field member to durable session records, older builds keep reading them instead of failing entirely over unknown members. Chats containing saved continuations of finished subagents require a compatible version to open. Older builds also cannot open a chat whose permissions were reset because part of its saved permission history was lost or damaged, requiring a Muse update; other chats remain unaffected.

BUGFIX

Terminal Noise Filtering, Keychain Timeout Protection, and Error Deduplication

Working continuously in a terminal environment makes repeated error cascades or exit screen clutter from internal logs especially frustrating. When the same configuration, environment, or step-limit error stops two consecutive dialogue turns with nothing displayed between them, it now appears only once while the session runs. Quitting the text user interface (TUI) also automatically redirects internal cleanup and shutdown diagnostics to the local log file.

Built-in noise suppression inside a sound system automatically filters repeated noise when a needle skips and cuts power quietly at the switch, leaving no harsh shutdown pop in the speakers.

On macOS, if the Keychain stops responding, the program stops waiting after 5 seconds and notes that your login is still saved, and running muse --help no longer waits on the Keychain. When the chosen model is missing from the cache, the background refreshes the model catalog only once. If a /feedback upload fails, the interface also displays the specific reason returned by the server.

BUGFIX

SDK Companion Package Auto-Installation and Setup Deduplication for Faster Session Resumes

When developing Muse applications in Python, missing core dependencies after installation often leaves developers unsure where to look. Now, running pip install muse-code-sdk automatically installs the companion wire-types package, allowing a fresh environment to execute import muse_code. SDK applications also correctly identify a new turn started by Replace as the running turn (activeTurn).

Unboxing flat-pack furniture previously required hunting down missing parts, but tools and screws now arrive bundled together, while repetitive assembly instructions are condensed into a single shared guide that keeps packages lighter and setups faster.

Long sessions store repeated setup blocks once to speed up loading. Messages awaiting replacement or queued during a crash are accurately marked as abandoned when retried. Resumed sessions exit normally after completing their run instead of hanging on earlier tool rejection records. Once a reminder check has reached a decision, it no longer runs repeatedly even when blocked by a Stop or PreToolUse hook (a small program triggered by specific events).
